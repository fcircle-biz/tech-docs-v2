# 標準 figure スニペットと差し込み規約

学習ガイドの本文断片（`astro-system/src/chapters/...`）へ画像を差し込む際の正規形と全規約。教材は HTML（Tailwind）なので、指示書が Markdown 記法（`![]()`）でも **HTML の `<figure>` に変換して**差し込む。

## 正規形（コピー元）

```html
<figure class="my-6">
    <img src="/tech-docs-v2/guide/<分類パス>/<slug>/images/<論理名>.<拡張子>"
         alt="<本文に沿った説明的な日本語の代替テキスト>"
         class="w-full max-w-2xl mx-auto rounded-lg border border-slate-200 shadow-sm"
         loading="lazy" decoding="async" />
    <figcaption class="mt-2 text-center text-sm text-slate-600"><キャプション文></figcaption>
</figure>
```

## 各規約

### src（参照パス）
- **base 付き絶対URL** を使う: `/tech-docs-v2/guide/<分類パス>/<slug>/images/<論理名>.<拡張子>`。
- base は `astro.config.mjs` の `base`（現状 `/tech-docs-v2/`）を真実源とする。`_shared` アセット（`/tech-docs-v2/guide/_shared/...`）と同じ規約に統一する。
- 相対パス（`images/...`）でも同ディレクトリ配信で解決はするが、コードベース規約は絶対URL。絶対URLに統一する。

### class（サイズ・体裁）
- `w-full max-w-2xl mx-auto rounded-lg border border-slate-200 shadow-sm`
- `w-full` 単独（カラム全幅）は**大きすぎてバランスが崩れる**。必ず `max-w-2xl`（=672px）で頭打ちにし、`mx-auto` で中央寄せする。
- サイズ調整の目安（ユーザー指定があれば差し替え）: `max-w-xl`=576px（小）/ `max-w-2xl`=672px（既定）/ `max-w-3xl`=768px（大）。
- `border border-slate-200` の枠と `rounded-lg`・`shadow-sm` で本文から浮かせる。

### alt
- 本文の文脈に沿った**内容説明**を日本語で書く（「画像」「図」等の空疎語でなく、何を示す図かを述べる）。
- 例: `alt="ローカル（自分のPC）で記録した変更履歴を push でリモート（GitHub）へ送り、他の人は clone / pull で取得して共有する関係を示した図。"`

### figcaption（キャプション）
- `class="mt-2 text-center text-sm text-slate-600"`。
- 色は **`text-slate-600`** を使う。`_shared/styles.css` のダーク自動補正は `text-*-600〜950` を明色化するため、`text-slate-600` はライト/ダーク両モードで可読になる。`text-slate-400/500` など補正範囲外の薄色は**使わない**（ダークで読みにくくなる）。
- 文言は指示書の「推奨キャプション」をそのまま使う（例 `図1-1 …`）。

### 遅延読込
- `loading="lazy" decoding="async"` を必ず付ける（教材画像は本文中盤以降に多く、初期表示を妨げない）。

### クリック拡大（共通シェルが自動付与・特別なマークアップ不要）
- 本文中の `<img>` は共通シェル（`_shared/main.js` + `_shared/styles.css`）が実行時に自動でラップし、**クリック / Enter / Space で拡大（ライトボックス）表示**になる（`figcaption` はキャプションに流用、背景クリック / ✕ / Esc で閉じる）。同時にブラウザの「画像検索」ボタン表示も抑止する。
- このため figure 側に拡大用の属性・クラスは**不要**。上記の正規形（`max-w-2xl mx-auto` 等）のままでよい（`max-w-*` / `mx-auto` はシェルがラッパーへ移すため、どのサイズでも崩れない）。

### インデント整合（重要・つまずきポイント）
- `<figure>` ブロックは**挿入箇所周辺の既存インデントに正確に合わせる**。
- 章 HTML では、`<section>` 内の要素（多くの本文）と、章ヘッダー直下などコンテンツ直下の要素とで**インデント深さが異なる**。同一スニペットを全箇所へ一括置換すると、浅い箇所だけ一致せず差し込み漏れが起きる。
- 箇所ごとに周辺行のインデントを確認し、それに合わせて差し込む。一括置換に頼らず、漏れがないか figure 数で検証する（`references/placement-and-build.md`）。

## 既存図（Mermaid 等）の扱い

**指示書に「置換」「残置」の明記があればそれに従う。** 明記が無い場合は、差し込み先の周辺にある既存ビジュアル要素（Mermaid 図・比較表・「表示イメージ」ブロック・カード群）と画像を突き合わせ、次で判定する。

| 画像と既存要素の関係 | 対応 |
|---------------------|------|
| 画像が既存要素を**完全に含み、さらに情報を足す**（上位互換） | 既存要素を**コメントアウトして退避**し、その位置に画像を置く（**行ごと消さない**） |
| **まったく別の切り口** | 両方残す（説明 → 画像 → 既存図の順） |
| 画像が既存要素の**要約にすぎない**／既存要素の方が情報量が多い | **画像を差し込まない**。指示書の作成元へ差し戻す（`docs-image-creator` から呼ばれている場合は図案からやり直す） |

- 「同じ流れの図が2つ続く」「同じサンプルの表示イメージが2箇所にある」状態は**必ず解消**する。画像と既存図を機械的に並べない。
- 退避する場合、その要素にしか無い情報（コードのコピーボタン、表の追加列、別 OS の記述など）が失われないか確認する。失われるなら退避せず「両方残す」に倒す。
- 判定に迷う場合は**情報量の多い方を残す**（画像が薄いなら画像を捨てる）。「とりあえず両方残す」は重複の温床なので選ばない。

### コメントアウト退避の書式（置換時の必須手順）

置換と判定した既存要素は、**本文断片（`src/chapters/`）から行ごと削除せず、HTML コメントで囲って残す**。将来画像を差し替える／戻す際の原本になる。

```html
<!-- 【退避】画像 <論理名>.png へ置換（YYYY-MM-DD）。復元する場合はこのコメントを外し、下の figure を削除する。
<div class="mermaid">
flowchart LR
    A["売上"] --&gt; C["利益"]
</div>
-->
<figure class="my-6">
    ...
</figure>
```

**Mermaid を退避するときの必須エスケープ（重要）**

HTML コメントは最初に現れた `-->` で終端する。Mermaid の矢印記法 `-->` はこれに直撃するため、**素のまま囲むとコメントが途中で閉じ、図の残りが本文テキストとして画面に漏れ出す**（実測で確認済み）。退避時は次を機械的に適用する。

**ルールは1つだけ**: 退避するブロック内の**リテラル `-->` をすべて `--&gt;` に置換する**。これだけで下表の全ケースを漏れなく処理できる（`>` だけをエスケープし、ハイフンの本数は変えない）。

| Mermaid の記法 | `-->` を含むか | 退避時の表記 |
|---------------|--------------|------------|
| `-->`（標準の矢印・リポジトリ内 6,408 箇所） | 含む | `--&gt;` |
| `--->`（長い矢印） | 含む | `---&gt;` |
| `-->>`（シーケンス図の破線矢印・12 箇所） | 含む | `--&gt;>` |
| `-.->`（点線矢印・29 箇所） | **含まない**（`-` が連続しない） | **そのまま**（変換不要） |
| `==>`（太線矢印・1 箇所） | 含まない | そのまま |

- ハイフンを削ってはいけない。`-.->` を `-.&gt;` にするような変換は**矢印の種類を壊す**ので禁止。
- HTML コメントは `--!>` でも終端するが、リポジトリ内に出現例は無い。もし現れたら同様に `--!&gt;` とする。
- 置換対象が Mermaid **以外**（比較表・カード群・「表示イメージ」）でも、ブロック内に `-->` が無いことを必ず確認してから囲む。
- 復元時は逆変換する（`--&gt;` → `-->`）。コメント先頭に復元手順を1行書いておくこと。
- 退避コメントは**本文断片にのみ**置く。`docs/` はビルド成果物なので直接編集しない（コメントもビルドで自動的に出力へ運ばれる）。

## 視認性・ダーク規約（CLAUDE.md 準拠）
- 生color指定（`text-[#...]`・`bg-[#...]`）、インライン `style=`、半透明背景（`bg-white/70` 等）は使わない。
- 画像自体が白背景のイラストでも、`<figure>` 側に背景色は付けない（枠 `border-slate-200` のみ）。ダークでは画像自身の地色がそのまま出る（イラスト図版では許容）。
