# codex CLI での画像生成（クロマキー → 透過PNG）

codex CLI に**組み込みの `imagegen` スキル**を使わせて画像を生成する。codex は内部で `image_gen` ツールを呼ぶため、こちら側で API キーやエンドポイントを扱う必要はない。

**本スキルの最終成果物は背景透過（アルファ付き）PNG** だが、**codex には透過ではなくクロマキー（マゼンタ単色背景）で生成させ、透明化は Claude 側で行う**。

## 事前確認

```bash
codex --version                                   # CLI の存在
codex features list | grep image_generation       # "image_generation  stable  true" であること
```

- 未ログイン／フィーチャー無効なら、その旨をユーザーに報告して依頼する（Claude 側で認証フローは行わない）。
- codex 側の imagegen スキル本体は `~/.codex/skills/.system/imagegen/SKILL.md`。

## 再生成を抑える4原則（最重要）

### 原則1: codex に「背景の質」を判定させない

背景の色むら・わずかなグラデーション・近似マゼンタは、**Claude 側の `--auto-key border` が吸収する**。codex がここを不合格にすると、直らない条件を追って上限までリトライする。

→ プロンプトに「**背景の色むら・近似色・わずかなグラデーションは許容。これを理由に作り直さない**」を明記する。

### 原則2: 「指定文字列と完全一致」を合格条件にしない

画像モデルは長い日本語ラベルを短縮する。これは**プロンプトを強めても直らない**。

→ 図案側で**1カード最大14文字程度の短縮ラベルを設計時に確定**する（`illustration-design.md`）。プロンプト側は「意味が変わらない軽微な短縮・助詞の違いは許容」とする。

### 原則3: 画像内に記号を使わない

`―` `—` `–` `〜` `/` は長音や別記号に化ける。区切りが必要なら**改行するか、帯を2つに分ける**。

### 原則4: スタイル参照画像を既定で渡さない

参照画像の陰影・グラデーションを引きずり、フラット塗り指定と衝突して再生成の原因になる（ch04 で codex 自身が指摘）。

→ **既定は参照なし。**構成の粒度は文章で指定する。トーンをそろえたい場合のみ、「**構図の粒度（カード数・文字量）だけを参照し、塗り・陰影・質感は参照しない**」と添えて1枚だけ渡す。

## 生成方式（クロマキー・既定）

1. **codex にクロマキー背景で生成させる** — 背景を `#ff00ff` のベタ塗りにし、`work/<slug>/_raw/` へ保存させる。
2. **アルファ化は Claude 側（本スキル）が行う** — `remove_chroma_key.py` で透明化し、`work/<slug>/` 直下へ最終PNGを書き出す。

| 段階 | 保存先 |
|------|--------|
| クロマキー原版（codex が生成） | `work/<slug>/_raw/<slug>-<NN>-<topic>.png` |
| 透過PNG（本スキルが変換・差し込み対象） | `work/<slug>/<slug>-<NN>-<topic>.png` |

> **透明背景の直接生成（旧「方式①」）は使わない。** 実測で、`image_gen` は「透明背景」の指示を**市松模様（チェッカーボード）として描画**し、ファイルは `mode: RGB`／四隅不透明になった。codex 側で2回リトライしても再現し、3回目には自前スクリプト描画へ逸れた。クロマキー方式は同条件で1回目から通っている。

### キーカラーの選択

- 既定は **`#ff00ff`（マゼンタ）**。教材の技術色がグリーン系でも青系でも干渉しにくい。
- 図版の配色にマゼンタ／ピンクを使う場合のみ `#00ff00`（グリーン）に切り替える。
- 選んだキーカラーは「画像内のどこにも使わない」ことをプロンプトに明記する。

### 変換コマンド

`remove_chroma_key.py` は Pillow を要求するが、システム python には入っていない。**`uv run --with pillow` 経由で実行する**。

```bash
mkdir -p work/<slug>
for f in work/<slug>/_raw/*.png; do
  uv run --quiet --with pillow python "${CODEX_HOME:-$HOME/.codex}/skills/.system/imagegen/scripts/remove_chroma_key.py" \
    --input "$f" --out "work/<slug>/$(basename "$f")" --force \
    --auto-key border --soft-matte --transparent-threshold 12 --opaque-threshold 220 --despill
done
```

- `--force` を付ける（付け忘れると `Output already exists` で**無言でスキップされる**。実測で1枚取りこぼした）。
- 出力の `Key color:` は `#ff00ff` 前後であればよい。**`#f304e9` のような近似色でも正常**。緑や白と判定された場合のみ生成し直し。
- キーカラーのフリンジが残る場合は `--edge-contract 1` を足して1回だけ再実行する。

## 透過の検証（必須）

```bash
uv run --quiet --with pillow python - <<'EOF'
from PIL import Image
import glob, os
for p in sorted(glob.glob("work/<slug>/*.png")):
    if os.path.basename(p).startswith("_check-dark-"): continue
    im = Image.open(p); r = im.convert("RGBA")
    c = [r.getpixel(x)[3] for x in [(0,0),(im.width-1,0),(0,im.height-1),(im.width-1,im.height-1)]]
    h = r.split()[3].histogram(); pct = 100*h[0]/(im.width*im.height)
    ok = "OK " if im.mode=="RGBA" and max(c)==0 and 10<=pct<=60 else "NG "
    print(ok, os.path.basename(p), im.mode, im.size, "四隅", c, "透明率 %.1f%%"%pct)
    bg = Image.new("RGBA", r.size, "#0f172a")
    Image.alpha_composite(bg, r).convert("RGB").save(os.path.join(os.path.dirname(p), "_check-dark-"+os.path.basename(p)))
EOF
```

合格条件: `mode` が `RGBA` ／ 四隅の alpha が 0 ／ 透明率が概ね 10〜60%。同時にダーク合成 `_check-dark-*.png` を作るので、**Read で開いて目視**する（消える文字・線が無いこと）。

`_check-dark-*.png` と `_raw/` は差し込み対象ではない。**`public/` へコピーしない。**

## 実行コマンド（正規形）

長い日本語プロンプトはシェルのクォート事故を起こすため、**ファイルに書いて stdin から渡す**。

```bash
codex exec --sandbox workspace-write --skip-git-repo-check \
  -o <SCRATCH>/codex-last-message.txt - \
  < <SCRATCH>/codex-imagegen-prompt.md \
  > <SCRATCH>/codex-run.log 2>&1
```

- `<SCRATCH>` はセッションのスクラッチパッドディレクトリ（`/tmp` 直書きはしない）。
- `--sandbox workspace-write`: リポジトリ配下（`work/`）へ書けるようにする。
- **`Bash` の `run_in_background: true` で起動**する。

### 完了待ち

画像1枚あたり **約 40〜70 秒**。`Monitor` で codex プロセスの終了を待つ（前景 `sleep` は使わない）。

```bash
# macOS では pgrep -c が使えない。必ず | wc -l で数える
until [ "$(pgrep -f 'codex exec' | wc -l | tr -d ' ')" = "0" ]; do sleep 30; done; echo finished
```

- 画像ファイルの出現を待つだけでは不十分。codex は生成後に自己検証して作り直すことがある。
- **クレジット切れは監視で拾う**: `grep -li "out of credits" <SCRATCH>/run-*.log`。実測で6章分が無音で全滅した。

## プロンプトテンプレート

`<>` を対象章の情報で埋める。**画像ごとの構成は文字列レベルまで書き切る**（`illustration-design.md`）。

```markdown
<技術名> 学習ガイド 第<N>章「<章タイトル>」の**挿絵画像を <枚数> 点生成**してください。

対象章（本文を必ず読んで内容に合わせること）:
- `astro-system/src/chapters/<分類パス>/<slug>/<slug>-learning-material-<NN>.html`

## 生成方法（厳守）

- **組み込みの `image_gen` ツール**で生成する。CLI フォールバック（`scripts/image_gen.py` / `gpt-image-1.5` / `OPENAI_API_KEY`）は使わない。**画像を自前で描画するスクリプトも書かない。**
- **「透明背景」で生成しない。** 透明指定は市松模様として描画されることが確認済み。
- **背景は全面マゼンタ `#ff00ff` のベタ塗り**にする。`#ff00ff` に近いマゼンタ／ピンク系の色を、図版の内部（カード・文字・線）には使わない。
- 画像は **`work/<slug>/_raw/` 配下へ PNG で保存**する（ディレクトリは作成済み）。
- 保存ファイル名は必ず以下の通り:
  1. `work/<slug>/_raw/<slug>-<NN>-<topic1>.png`
  2. `work/<slug>/_raw/<slug>-<NN>-<topic2>.png`
- サイズは **1536 x 1024（横長）**。
- **アルファチャンネルは不要（RGB でよい）。** 透明化は呼び出し側が行うので `remove_chroma_key.py` は実行しない。

## 生成後にすること（これだけ）

1. `file work/<slug>/_raw/*.png` で 1536x1024 の PNG であることを確認する。
2. `view_image` で **1枚につき1回だけ** 内容を見る。
3. 次の**致命的欠陥がある場合に限り**、その画像を **1回だけ** 作り直す。
   - 日本語が判読不能（文字化け・意味のない文字列）
   - 指定と明らかに別の図になっている／主要な要素が欠落している
   - 要素が画面端で見切れている
   - **中身の無い空の枠・灰色のプレースホルダーが残っている**
4. **上記以外はすべて許容し、作り直さない。** とくに次は仕様の範囲内なので**不合格にしない**:
   - 背景マゼンタの**色むら・近似色・わずかなグラデーション**
     （呼び出し側が `--auto-key border` で自動判定して透明化するため問題にならない）
   - カードや帯のわずかな陰影・質感
   - 指定文字列の**軽微な短縮・助詞の違い・折り返し位置の違い**（意味が変わらなければ許容）
5. 1回作り直しても直らない場合は、**それ以上作り直さず**、最も条件に近い版を採用して保存し、
   どこが指定と違うかを報告に書く。

## 背景の要件

- 背景は全面マゼンタ `#ff00ff`。カード・帯・図形の外側はすべてこの色にする。
- 図版の周囲には十分な余白（マゼンタの地）を取り、要素を画面端で見切らせない。
- カード・帯に**ドロップシャドウ・ぼかし・グロー・半透明の重ねを付けない**。
- 白い面が必要な要素は**不透明な白 `#ffffff`** で塗る。
- **マゼンタの地の上に文字・細線を直接置かない。** タイトルも含め、すべての文字は不透明な
  白カードまたは不透明な角丸の帯の中に入れる。

## 共通のビジュアル要件

- クリーンなフラットベクター風の**教育用インフォグラフィック**。角丸カード、細い枠線、明快な矢印、余白たっぷり。
- **日本語**の見やすいゴシック体（Noto Sans JP 風）。文字は大きく、短い語句のみ。
- **画像内に記号を使わない**: `―` `—` `–` `〜` `/` は描かない（長音や別記号に化ける）。
  区切りが必要な箇所は改行するか帯を分ける。丸数字は ①②③ を使う。
- **アイコンは描かない。** カードの中身は指定した日本語テキストだけにする。
- 配色: **<primary.500> を主役**、濃色に <primary.600>、アクセントに <splashStop1>、
  面はごく薄いグレーブルーと不透明な白。過剰な彩色はしない。
- 実在サービスの**ロゴマーク・商標は描かない**。人物は描かない。
```

## トラブルシュート

| 症状 | 対処 |
|------|------|
| 承認待ちで止まる | `--sandbox workspace-write` を付ける |
| 画像が `~/.codex/generated_images/` にしかない | 保存先指定が弱い。「`_raw/` へ**保存**する」「保存ファイル名は必ず以下の通り」を明記して再実行 |
| **同じ章で `image_gen` が3回以上走っている** | 却下条件が厳しすぎる。「生成後にすること」の**許容リスト（背景の色むら・軽微な短縮）が抜けていないか**確認する |
| 日本語ラベルが短縮される | プロンプトでは直らない。**図案側でラベルを14文字以内に詰めて**作り直す |
| タイトルの区切り記号が長音に化ける | 記号を使わない図案に直す（改行・帯の分割） |
| 帯やカードに陰影・グラデーションが残る | **許容してよい**（透明化に影響しない）。気になる場合のみ参照画像を外す |
| カードに空のアイコン枠が残る | 「アイコンは描かない」を明記して1回だけ作り直す |
| `Key color:` が緑・白と判定される | 背景がクロマキーになっていない。しきい値をいじらず生成し直す |
| 変換が無言でスキップされる | `--force` の付け忘れ |
| `ModuleNotFoundError: No module named 'PIL'` | `uv run --quiet --with pillow python …` 経由で実行する |
| `Your workspace is out of credits.` | codex 側のクレジット切れ。リトライで解決しない。**ユーザーに報告して判断を仰ぐ** |

## 複数章を一度に扱う場合

- 章ごとに `codex exec` を**1メッセージ内でまとめてバックグラウンド起動**し、並列実行する。実測で7並列まで問題なく動く。
- **図案設計と最終検収は本体（Opus）が行う。** codex には生成と一次保存までを任せる。
- 章数が多い場合は**2波に分ける**とクレジット切れの被害を局所化できる（実測: 7章＋6章）。
- 全プロセスの終了は `until [ "$(pgrep -f 'codex exec' | wc -l | tr -d ' ')" = "0" ]` で待つ。
