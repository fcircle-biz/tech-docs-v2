Apache Supersetとは

Apache Superset は、データベースに入っているデータを SQL で探索し、チャートとダッシュボードに仕立てて共有するためのオープンソースの BI ツールです。この章では、Superset が何をするツールなのか、なぜ「データを持たない」のか、そして本教材全体で何を学んでいくのかという全体像をつかみます。

本教材の検証環境: Apache Superset 6.1.0

本教材は Apache Superset 6.1.0（2026年5月リリース）で動作確認しています。Superset は更新の速いプロダクトで、画面のラベル・機能フラグの既定値・Docker Compose の構成がバージョンによって変わります。学習中は同じ結果を得るためこのバージョンを推奨します。異なるバージョンを使う場合は、公式ドキュメントも併せて確認してください。

この章で学ぶこと

  • Apache Superset がどんなツールで、誰が開発しているのかを理解する
  • Superset が分析用データを持たず、都度 SQL を発行する仕組みを説明できる
  • Excel や商用 BI ツールとの違いを、向き・不向きの観点で整理できる
  • 接続・データセット・チャート・ダッシュボードという4つの要素の関係をつかむ

1.1 Apache Superset とは何か

Apache Superset（アパッチ・スーパーセット）は、データの探索と可視化のためのオープンソースの BI プラットフォームです。ブラウザで開いて SQL を書き、その結果をグラフにし、複数のグラフを1枚のダッシュボードにまとめてチームに共有する——この一連の作業を1つのツールの中で完結できます。

もともとは民泊サービスの Airbnb 社内で生まれたツールで、その後 Apache ソフトウェア財団へ寄贈され、インキュベータを経て2020年11月にトップレベルプロジェクトへ昇格しました（ASF の公式発表は2021年1月）。ライセンスは Apache License 2.0 で、誰でも無償で利用・改変・自社サーバへの設置ができます。サーバ側は Python（Flask）、画面側は React で作られており、開発は現在も活発に続いています。

「BI ツール」と聞くと Excel の集計表やグラフを思い浮かべるかもしれません。Superset が Excel と決定的に違うのは、データをファイルとして受け渡さない点です。Superset はデータベースに接続し、必要になったタイミングで SQL を発行して結果を描画します。そのため、元データが更新されれば、次にクエリが実行されたタイミングでダッシュボードの数字も更新されます（結果をキャッシュしている場合は、その有効期間中は前回の結果が表示されます。詳しくは第14章）。

SQL で探索できる

内蔵の SQL エディタ「SQL Lab」でクエリを書き、その結果をそのままチャートの材料にできます。

チャートが豊富

折れ線・棒・ピボットテーブル・地図など多数のチャートを、コードを書かずに切り替えられます。

自社環境に置ける

オープンソースなので、社内サーバやクラウド上に自分たちで設置して運用できます。

用語: BI（ビジネスインテリジェンス）とは

業務で貯まったデータを集計・可視化し、意思決定に使える形にすることを BI と呼びます。「先月の売上は目標に届いたか」「どの商品カテゴリが伸びているか」といった問いに、勘ではなくデータで答えるための仕組みです。Superset はその中でも可視化と共有を担当するツールで、データを貯める役割はデータベース側が担います。

1.2 Superset は「データを持たない」

Superset を理解するうえで最も大切な性質が、分析対象のデータを自分の中にコピーして持たないことです。ダッシュボードを開くと、Superset は原則として接続先のデータベースへ SQL を投げ、返ってきた結果を描画します（キャッシュに当たった場合はデータベースへ問い合わせません。後述）。Superset は「データの置き場所」ではなく、データベースの上に載せる可視化レイヤーだと考えてください。

flowchart LR U["利用者のブラウザ"] --> S["Superset
（Webアプリ）"] S -->|SQLを発行| DB[("分析対象のDB
PostgreSQL ／ MySQL ／ DWH など")] DB -->|結果セット| S S --> M[("メタデータDB
チャート・ダッシュボード定義")] S --> C[("キャッシュ
Redis など・任意")]

図には3つのデータベースが登場しますが、役割はまったく違います。混同しやすいところなので、ここで整理しておきましょう。

名前 何が入るか 誰が用意するか
分析対象のDB 売上・在庫・ログなど、実際に分析したい業務データ 本来は自社の既存システム（Superset の外）。学習環境では Superset と同じ Docker Compose 内に用意される
メタデータDB チャート・ダッシュボードの定義、ユーザー、権限、保存クエリ Superset 自身が使う（必須）
キャッシュ 一度実行したクエリ結果の一時保存 任意（第14章で扱う）

なお、本教材の学習環境（第2章の Docker Compose）ではサンプルデータも同じ PostgreSQL コンテナ内の別データベース（examples）に入ります。同じサーバに同居することはあっても、データベースとしては別物である点は変わりません。

「都度 SQL を発行」には例外がある — キャッシュ

Superset は原則としてチャート表示時にデータベースへクエリを発行しますが、データキャッシュ（DATA_CACHE_CONFIG）が有効でキャッシュにヒットした場合は、データベースへ問い合わせずキャッシュされた結果を返します。そのため、キャッシュの有効期間中はデータベースの最新状態と表示内容が一時的に一致しないことがあります。「データを持たない」は分析データを Superset の中に永続的に抱え込まないという意味であり、「一切保持しない」という意味ではありません。キャッシュの設定と有効期限は第14章で扱います。

重要ポイント

ダッシュボードの表示速度は、多くの場合接続先データベースのクエリ処理時間が最も大きな要因になります。そのため、遅いときにまず見直すべきは SQL やテーブル設計です。「重い集計はあらかじめ集計済みテーブルにしておく」という考え方は、本教材を通じて繰り返し出てきます。ただし要因はそれだけではなく、キャッシュの有無・Superset 自身の処理・Web サーバや Celery ワーカーの余力・ネットワーク・1枚のダッシュボードに載せたチャート枚数も影響します（第14章）。

どんなデータベースにつながるのか

Superset は SQLAlchemy という Python のライブラリを経由して接続します。そのため、対応するドライバさえ入れれば PostgreSQL・MySQL・SQL Server・Oracle・SQLite のような一般的な RDBMS から、BigQuery・Snowflake・Trino といった分析基盤まで、幅広く同じ手順で扱えます。接続の具体的な方法は第4章で学びます。

1.3 Excel・商用BIツールとの違い

「Excel で足りているのに、なぜ BI ツールが要るのか」は、最初につまずきやすい疑問です。Excel・Power BI などの商用 BI・Superset を並べて、それぞれが得意な場面を確認しましょう。

観点 Excel 商用BI（Power BI など） Apache Superset
データの持ち方 ファイルにコピーして保持 取り込み（インポート）が中心 持たない。都度 SQL を発行
最新化 手作業で作り直す 更新スケジュールを設定 都度 SQL を実行（キャッシュ有効時はその期間内は前回結果）
共有 ファイルを配布（版が乱立しやすい） サービス上で共有 URL を共有（実体は1つ）
費用 Office ライセンス 利用者ごとのライセンス ソフトは無償。サーバ運用費は必要
必要なスキル 表計算の操作 専用の式（DAX など）と GUI SQL の知識が活きる
導入形態 各自の PC SaaS（クラウド）が中心 自分たちでサーバに設置

Superset が向く場面

  • データがすでにデータベースに入っている
  • 毎日・毎週など、同じ集計を繰り返し見たい
  • 同じ数字を多人数で共有し、版のズレをなくしたい
  • SQL を書ける人がチームにいる
  • ライセンス費用を抑え、自社環境で管理したい

Superset が向かない場面

  • 手元の CSV や Excel を1回だけ集計したい
  • セルに手入力で数字を追記しながら作業したい
  • データベースがなく、接続先を用意できない
  • サーバを運用できる担当者がまったくいない
  • 帳票のように罫線・体裁を精密に整えた印刷物が主目的

「無償」の意味に注意

Superset はソフトウェア自体が無償なだけで、運用は自分たちの仕事になります。サーバの用意、バージョンアップ、バックアップ、障害対応はすべて自前です。商用 BI のライセンス費用と、自社で運用する人的コストを天秤にかけて選ぶものだと理解しておきましょう。運用面の基礎は第14章で扱います。

1.4 Superset を構成する4つの要素

Superset の画面にはたくさんのメニューがありますが、覚えるべき中心概念は4つだけです。この4つは下から順に積み上がる関係になっていて、本教材もこの順番で進みます。

flowchart TD A["Database 接続
どのDBを見るか"] --> B["Dataset
どの表・どのSQLを分析対象にするか"] B --> C["Chart
1つの問いに1つのグラフ"] C --> D["Dashboard
複数のチャートを1枚にまとめる"]
  • Database 接続 — 接続情報（どのサーバのどの DB を、どのユーザーで見るか）。管理者が作ります（第4章）。
  • Dataset（データセット） — 分析の対象範囲。テーブルそのもの、または SQL の結果に名前を付けたもの（第6章）。
  • Chart（チャート） — データセットに対して「何を軸に、何を測るか」を指定した1枚のグラフ（第8章）。
  • Dashboard（ダッシュボード） — チャートを並べて配置し、フィルタで連動させた共有用の画面（第10章）。

ここで押さえておきたいのは、1つのデータセットから何枚でもチャートを作れること、そして1つのチャートを複数のダッシュボードに置けることです。つまり土台であるデータセットを丁寧に作っておくほど、後の作業が楽になります。第6章・第7章でデータセットの整備に2章分を使うのは、このためです。

もう1つの入口: SQL Lab

4つの要素とは別に、SQL Lab という SQL エディタが用意されています（第5章）。データを覗いて確かめたいときや、チャートにする前の試行錯誤はここで行い、良い結果が得られたら「データセットとして保存」してチャート作成へ進む——という流れが定番です。

やってみよう 1-1: 手元の集計作業を4つの要素に当てはめる

環境構築はまだ不要です。Superset を入れる前に、「自分たちのどの作業が Superset に置き換わるのか」を言葉にしておきましょう。この整理が、第6章以降の設計でそのまま効いてきます。

手順

  1. 1 身の回りで「毎月同じ手順で作っている集計表やグラフ」を1つ選ぶ（売上報告、問い合わせ件数、在庫推移など）。
  2. 2 その集計について、次の4つを箇条書きにする。
    (a) 元データはどこにあるか　(b) どの表・どの範囲を見ているか　(c) 何を軸に、何を測っているか　(d) 誰がどの画面で見るか
  3. 3 (a)〜(d) が Superset の Database 接続・Dataset・Chart・Dashboard のどれに対応するか、線でつないでみる。

解答の目安

(a) は Database 接続、(b) は Dataset、(c) は Chart、(d) は Dashboard に対応します。ここで (a) が「担当者の PC にある Excel ファイル」だった場合は要注意です。Superset はデータベースに接続して使うツールなので、まずデータをデータベースへ置くところから検討が必要になります。

理解度確認クイズ

  1. Q1. Superset が「データを持たない」とは、どういう意味ですか？

    回答を表示

    分析対象のデータを Superset 内部にコピーして保存しない、という意味です。チャートやダッシュボードを表示する際に原則として接続先のデータベースへ SQL を発行し、返ってきた結果を描画します。そのため元データが更新されれば、次のクエリ実行時に表示される数字も更新されます。ただしデータキャッシュが有効でキャッシュにヒットした場合は DB へ問い合わせないため、キャッシュの有効期間中は最新値と一致しないことがあります。

  2. Q2. Superset の「メタデータDB」には何が保存されますか？

    回答を表示

    チャートやダッシュボードの定義、ユーザーと権限、保存クエリなど、Superset 自身の設定情報です。売上データのような業務データは入りません。業務データは接続先の「分析対象のDB」にあります。

  3. Q3. Superset の4つの中心概念を、土台になる順に並べてください。

    回答を表示

    Database 接続 → Dataset → Chart → Dashboard の順です。1つのデータセットから複数のチャートを作れ、1つのチャートを複数のダッシュボードに置けるため、下の層ほど丁寧に作る価値があります。

  4. Q4. ダッシュボードの表示が遅いとき、最初に疑うべきなのはどこですか？

    回答を表示

    まず疑うべきは接続先データベースへ発行している SQLです。Superset はキャッシュに当たらない限り都度クエリを実行するため、表示速度はデータベース側の処理時間に大きく依存します。対策としては SQL の見直し、インデックスや集計済みテーブルの用意、そしてキャッシュの利用（第14章）があります。それでも改善しない場合は、1枚に載せたチャート枚数や Superset 側のリソース（ワーカー数・メモリ）も確認します。
