開発者ツールとcurlで通信を観察する

ここまでの章で、HTTPメッセージの構造・メソッド・ステータスコード・ヘッダーといった「知識」を学んできました。この章では、それらを実際の画面とコマンドで自分の目で確かめる方法を身につけます。ブラウザの開発者ツールで通信を観察し、ターミナルの curl コマンドで自分自身がクライアントになってリクエストを送ってみましょう。

この章で学ぶこと

  • 開発者ツールの Network タブで通信一覧と各項目の意味を読める
  • 1件の通信の Headers・Payload・Preview・Response・Timing を確認できる
  • curl コマンドでリクエストを送り、レスポンスやヘッダーを表示できる
  • curl でメソッド・ヘッダー・ボディを指定してAPIを呼び出せる

7.1 開発者ツールの Network タブ

第1章の実習で少しだけ触れた開発者ツールを、ここで本格的に使いこなします。Chrome や Edge では F12 キー（Mac は Option+Command+I）、またはページ上で右クリックして「検証」を選ぶと開きます。上部のタブから Network（ネットワーク）を選ぶと、そのページが発生させた通信が一覧表示されます。

列名 意味
Name リクエスト先のファイル名やパス
Status レスポンスのステータスコード（第5章）
Type 中身の種類（document・xhr・fetch・script・stylesheet・img など）
Size 転送されたデータの大きさ
Time その通信にかかった時間

画面上部には便利なオプションもあります。Preserve log（ログを保持）にチェックを入れると、ページ遷移をまたいでも一覧が消えません。Disable cache（キャッシュを無効化）にチェックを入れると、第6章で学んだキャッシュを使わず毎回サーバーから取得し直します。フィルター欄の Fetch/XHR をクリックすると、画像やCSSを除いたWeb API通信だけに絞り込めます。

開発者ツールを開いたまま操作する

Network タブは、開いている間に発生した通信しか記録しません。ページを開く前に開発者ツールを立ち上げ、Preserve log を有効にしておく習慣をつけましょう。

7.2 1件の通信の詳細を読む

一覧の1行をクリックすると、右側（または下側）に詳細パネルが開きます。ここには第3〜6章で学んだ内容がそのまま表示されており、これまでの知識を実物で確認できる絶好の場所です。

タブ 見られる内容
Headers リクエスト行・ステータス行・リクエスト/レスポンスヘッダー（第3・6章の内容）
Payload 送信したクエリパラメータやリクエストボディ（POST時のJSONなど）
Preview レスポンスボディを整形して見やすく表示（JSONはツリー表示）
Response レスポンスボディをそのままの文字列で表示
Timing DNS・接続・待ち時間・受信時間など、第1章 1.3 で見た各段階の内訳

Web API を呼ぶ通信（Type が xhr や fetch のもの）を選ぶと、Preview タブに JSON がツリー状に表示され、第9〜10章で学ぶ入れ子構造を先取りして目にすることができます。

重要ポイント

Headers タブに表示される内容は、開発者ツール専用の特別な情報ではありません。ブラウザが実際に送受信した HTTP の情報（メソッド・ステータス・ヘッダーなど）を、人間が読める形に整形して表示したものです。ただし HTTP/2・HTTP/3 では、通信路上のデータはテキストではなくバイナリ形式（第3章 3.5）ですし、HTTPS なら暗号化もされています。ネットワーク上を流れるバイト列がそのまま見えているわけではない点に注意しましょう。

7.3 curl の基本

開発者ツールは「ブラウザが行った通信を見る」道具でした。ここからはターミナルの curl（カール）を使い、自分自身がクライアントになってHTTPリクエストを送る方法を学びます。curl は Windows 10以降・macOS に標準で入っているコマンドです。

ターミナル 
# GETリクエストを送り、レスポンスボディだけを表示
curl https://example.com/

# -i : レスポンスヘッダーも含めて表示
curl -i https://example.com/

# -v : 通信の詳細（接続・送受信の生メッセージ）を表示
curl -v https://example.com/

# -I : HEADメソッドで送り、ヘッダーだけ取得（第4章）
curl -I https://example.com/

curl -i を実行すると、HTTP/1.1 200 OK （環境によっては HTTP/2 200。第3章 3.5 のとおり意味は同じ）というステータス行と、第6章で学んだ Content-Type などのヘッダーが、空行を挟んでボディの前に表示されます。第3章で図解した「開始行 → ヘッダー → 空行 → ボディ」という構造が、そのまま目の前に現れます。

Windows の PowerShell に注意

Windows の PowerShell では curl が独自コマンド（Invoke-WebRequest）のエイリアスになっている場合があり、オプションの意味が変わってしまいます。この教材で紹介する curl を確実に使うには、コマンド名を curl.exe と明示的に打ってください。以降の説明では単に curl と表記しますが、Windows の方は curl.exe に読み替えましょう。

7.4 curl でメソッド・ヘッダー・ボディを指定

ここからは第4章で学んだメソッドや、第6章で学んだヘッダーを curl から指定します。よく使うオプションを覚えれば、ブラウザでは送れない POST・PUT・DELETE のリクエストも自由に組み立てられます。

オプション 用途
-X メソッド メソッドを指定（省略時は GET、-d を付けると自動で POST）
-H "名前: 値" リクエストヘッダーを追加
-d データ リクエストボディを指定
--json データ JSONボディ＋Content-Typeを一度に指定（curl 7.82以降）
-L リダイレクト（第5章の3xx）を追いかけて再取得
-o ファイル名 レスポンスボディをファイルに保存
ターミナル（httpbin.org に JSON を POST する） 
# -X POST : POSTメソッドで送信
# -H : Content-Type ヘッダーで「これはJSONです」と伝える
# -d : リクエストボディ本体
curl -X POST https://httpbin.org/post \
  -H "Content-Type: application/json" \
  -d '{"title": "テスト投稿", "userId": 1}'

httpbin.org は、送られてきたリクエストの内容をそのまま JSON にして返してくれる観察用サービスです。上のコマンドを実行すると、レスポンスの json フィールドに、自分が送った title と userId がそのまま含まれているのを確認できます。

Windows でのクォートに注意

行末の \ は macOS・Linux で「次の行に続く」ことを表す記号で、Windows では使えません。Windows ではコマンドを1行にまとめてください。また、コマンドプロンプトはシングルクォート '...' で文字列を囲めないため、ボディ全体をダブルクォートで囲み、内部の " を \" でエスケープします（例: -d "{\"title\": \"test\"}"）。PowerShell でもクォートが崩れる場合は同じ書き方を試してください。

7.5 開発者ツールから「Copy as cURL」で再現する

「ブラウザで動いている通信を、そのまま curl で再現したい」という場面はよくあります。開発者ツールにはそのための便利な機能が用意されています。

flowchart LR A["Networkタブで対象の通信を右クリック"] --> B["Copy を選ぶ"] B --> C["Copy as cURL を選ぶ"] C --> D["ターミナルに貼り付けて実行"]

コピーされたコマンドには、ブラウザが実際に送った User-Agent や Cookie（第8章）まで含めて再現されます。「開発者ツールで見たこの通信を、ターミナルからもう一度送ってみたい」「バグ報告のためにリクエストの再現手順を残したい」というときに重宝します。ただし、コピーした内容にはログイン中の Cookie や Authorization ヘッダーがそのまま含まれるため、他人に共有する前に必ず該当部分を削除・伏せ字にしてください。また Windows 版の Chrome・Edge では「Copy as cURL (cmd)」と「Copy as cURL (bash)」が選べるので、使うターミナルに合わせて選びます。

重要ポイント

開発者ツール（見る）と curl（送る）は対になる道具です。「Networkタブでブラウザの通信を観察する → Copy as cURL で再現する → curl のオプションを1つずつ変えて挙動を確かめる」という往復ができるようになると、通信のトラブルシューティングが格段にやりやすくなります。

やってみよう 7-1: curl で通信を送って観察しよう

ターミナルを開いて、実際に2つのリクエストを送ってみましょう。

手順

  1. 1 ターミナル（Windowsは curl.exe）で curl -v https://example.com/ を実行し、出力を上から順に読む。「接続中」「HTTPリクエストを送信」「HTTPレスポンスを受信」に相当する行を見つける。
  2. 2 7.4の POST コマンドを実行し、レスポンスの json フィールドに自分が送った値が入っていることを確認する。
  3. 3 開発者ツールでどこかのサイトを開き、Networkタブで通信を1件右クリックして「Copy as cURL」を実行、ターミナルに貼り付けて動くか確かめる。

httpbin.org は書き込み系のリクエストを受け取った内容をそのまま返すだけで、実際にはデータを保存しません。何度失敗しても安心して試せます。

理解度確認クイズ

  1. Q1. 開発者ツールの Network タブで、ある行の Status が 404 だったとします。この 404 は何を表す数字で、HTTPメッセージのどこに含まれていますか。

    回答を表示

    レスポンスのステータス行に含まれるステータスコードです（第5章）。404 はクライアントエラー、指定したリソースが見つからなかったことを表します。

  2. Q2. リクエストとして送ったJSONボディを確認したいとき、詳細パネルのどのタブを見ますか。

    回答を表示

    Payload タブです。送信したクエリパラメータやリクエストボディはここに表示されます（レスポンスの中身は Preview / Response タブ）。

  3. Q3. curl でレスポンスヘッダーも含めて確認したいとき、どのオプションを使いますか。

    回答を表示

    -i オプションです。ステータス行とヘッダーが、空行を挟んでボディの前に表示されます。より詳しい通信過程まで見たい場合は -v を使います。

  4. Q4. curl で JSON ボディを POST するとき、なぜ -H "Content-Type: application/json" を付ける必要があるのですか。

    回答を表示

    ボディの中身がJSON形式であることをサーバーに伝えるためです（第6章）。このヘッダーが無いと、サーバーが送られてきたデータの形式を正しく解釈できないことがあります。

  5. Q5. Windows で curl コマンドがうまく動かないとき、まず何を確認・修正すべきですか。

    回答を表示

    PowerShell では curl が独自コマンドのエイリアスになっている場合があるため、curl.exe と明示的に打って本物のcurlを呼び出します。またJSONボディのクォートの崩れにも注意します。
