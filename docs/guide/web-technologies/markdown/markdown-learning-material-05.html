ホーム Markdown 第5章
第5章 所要時間: 約35分

リスト

箇条書きは、情報を整理して伝えるための最も基本的で使用頻度の高い記法です。この章では箇条書きリスト・番号付きリスト・入れ子（ネスト）・タスクリスト（チェックボックス）の書き方と、リストがうまく表示されないときによくある原因を学びます。

この章で学ぶこと

  • 箇条書きリスト（-・*・+ の3種類）の書き方と、記号の後のスペースの重要性が分かる
  • 番号付きリストの書き方と、番号が自動でつけ直される仕組みを理解する
  • リストを入れ子（ネスト）にして、階層のあるメモや手順を書ける
  • タスクリスト（チェックボックス）で TODO やチェックリストを作れる
  • リストが崩れる・認識されないときの、よくある原因と直し方が分かる

5.1 箇条書きリスト

順序を問わない「箇条書き」は、行の先頭に -（ハイフン）、*（アスタリスク）、+（プラス）のいずれかの記号を書くことで作れます。3つとも見た目は同じ「点付きの箇条書き」に変換されますが、この教材では最もシンプルで打ちやすいハイフン（-）を推奨します。

ここで一番大事なルールは、記号のすぐ後ろに半角スペースを1つ入れることです。スペースを忘れると記号がただの文字として表示され、箇条書きとして認識されません（詳しくは5.5節で扱います）。

書いたテキスト（Markdown）

shopping.md 
今日買うもの

- コーヒー豆
- 牛乳
- はちみつ

表示イメージ

今日買うもの

  • コーヒー豆
  • 牛乳
  • はちみつ

* や + でも書けるが、混ぜないよう注意

* や + でも同じ箇条書きになりますが、1つのリストの中で記号を混在させる（例: 1行目が -、2行目が *）と、ツールによっては別々の2つのリストとして扱われ、間に余計な隙間ができることがあります。1つの文書・チームの中では記号を1種類に統一しましょう。

5.2 番号付きリスト

手順のように順番に意味がある場合は、番号付きリストを使います。書き方は「半角数字」＋「半角ピリオド（.）」＋「半角スペース」＋「内容」です。箇条書きと同じく、ピリオドの後のスペースを忘れないようにしましょう。

書いたテキスト（Markdown）

steps.md 
1. 材料を準備する
1. 材料を切る
1. フライパンで炒める
1. お皿に盛り付ける

表示イメージ

  1. 材料を準備する
  2. 材料を切る
  3. フライパンで炒める
  4. お皿に盛り付ける

気づいたでしょうか。書いたテキストは全部「1.」なのに、表示は「1・2・3・4」と自動で連番になっています。これは、Markdown が最初の数字だけを開始番号として使い、あとは自動でカウントアップするという仕組みだからです。

豆知識: 番号を気にしなくてよい理由

すべて 1. と書く癖をつけておくと、後から手順の途中に項目を追加・削除するときに、他の行の番号を書き直す手間がありません。開始番号を1以外にしたい場合は、最初の項目の数字だけ変えれば、そこから連番が始まります（例: 5. から開始）。

5.3 リストの入れ子（ネスト）

リストの中にリストを入れることで、「大分類の下に小分類」のような階層構造を表現できます。これを入れ子（ネスト）と呼びます。内側のリストは、行の先頭を半角スペース2〜4個でインデント（字下げ）することで作れます。

書いたテキスト（Markdown）

region.md 
- 関東
  - 東京都
  - 神奈川県
- 関西
  - 大阪府
  - 京都府

表示イメージ

  • 関東
    • 東京都
    • 神奈川県
  • 関西
    • 大阪府
    • 京都府

インデントの半角スペースの数は、ツールによって最低限必要な数が微妙に異なります（2個で動く場合も、4個必要な場合もあります）。大事なのは同じ文書の中でスペースの数をそろえることと、見た目の幅が同じに見えてもTabキーではなく半角スペースを使うことです。エディタによって Tab の解釈が変わるため、インデントがずれる原因になります。

重要ポイント

箇条書きの中に番号付きリスト、番号付きリストの中に箇条書きを入れることもできます。ただし、階層を深くしすぎる（4段階以上）と読みにくくなるため、2〜3階層までを目安にしましょう。

5.4 タスクリスト（チェックボックス）

GitHub などの一部サービスでは、箇条書きを応用したタスクリスト（チェックボックス付きのリスト）が使えます。- [ ] と書くと未完了のチェックボックス、- [x]（x は半角小文字）と書くと完了済みのチェックボックスになります。TODO リストや作業チェックリストにぴったりの記法です。

書いたテキスト（Markdown）

todo.md 
## 今週のタスク

- [x] キックオフミーティング
- [ ] 資料を作成する
- [ ] レビューを依頼する

表示イメージ

今週のタスク

  • キックオフミーティング
  • 資料を作成する
  • レビューを依頼する

タスクリストは「拡張機能」

タスクリストは Markdown の標準仕様（CommonMark）ではなく、GitHub Flavored Markdown（GFM）と呼ばれる拡張仕様の記法です。GitHub・Qiita・Zenn などでは使えますが、対応していないツールでは [ ] 資料を作成する のようにただの文字として表示されることがあります。方言（フレーバー）については第9章で詳しく扱います。

5.5 リストが崩れる・認識されないときの原因

「リストを書いたのに箇条書きにならない」「入れ子のはずが階層がおかしい」というのは、初心者が最もつまずきやすいポイントです。ほとんどの場合、原因は次の4つのどれかです。

原因 どうなるか 対処法
記号の後にスペースがない ただの文章として表示され、箇条書きにならない - や 1. の直後に半角スペースを1つ入れる
リストの前に空行がない 直前の段落とくっついて、リストとして認識されないことがある リストの前後に空行を1行入れる
インデントのスペース数がバラバラ 入れ子のつもりが親と同じ階層になったり、崩れたりする 文書内でスペースの数（2個や4個など）を統一する
インデントに Tab キーを使っている エディタやツールごとに幅の解釈が変わり、崩れやすい インデントは半角スペースに統一する

次の例で、スペース1つの有無がどれだけ結果を左右するか比べてみましょう。

ng-ok.md 
記号の直後にスペースが無い場合:
-今日の予定

記号の直後にスペースがある場合:
- 今日の予定

困ったときは「プレビューをこまめに確認」

リストの崩れは、書いた文字だけを見ていても原因が分かりにくいことがあります。第2章で学んだプレビュー機能（Ctrl+Shift+V）をこまめに開き、1行書くたびに表示を確認する習慣をつけると、原因を早く見つけられます。

やってみよう 5-1: 買い物リストとタスクリストを作ってみよう

第2章で作成した .md ファイル（または新しく作ったファイル）を使って、この章で学んだリストを実際に書いてプレビューで確認してみましょう。

手順

  1. 1 「買い物リスト」という見出しの下に、買いたいものをハイフン（-）の箇条書きで5つ書き、プレビューで表示を確認する。
  2. 2 そのうち2つの項目を半角スペースでインデントして入れ子にし（例: 「野菜」の下に「にんじん」「玉ねぎ」）、階層になって表示されるか確認する。
  3. 3 「今日のタスク」という見出しの下に - [ ] でタスクを3つ書き、1つだけ - [x] に書き換えてチェックボックスが表示されるか確認する。

理解度確認クイズ

  1. Q1. 箇条書きリストに使える記号を3つ挙げてください。また、この教材で推奨されている記号はどれですか。

    回答を表示

    -（ハイフン）・*（アスタリスク）・+（プラス）の3つです。この教材ではシンプルで打ちやすいハイフン（-）を推奨しています。

  2. Q2. 番号付きリストで、すべての行を「1.」と書いても正しく「1・2・3…」と連番で表示されるのはなぜですか。

    回答を表示

    Markdown は書かれた数字をそのまま使うのではなく、最初の数字だけを開始番号として使い、あとは自動的に1つずつカウントアップして表示する仕組みになっているためです。途中に項目を追加・削除しても、番号を書き直す必要がありません。

  3. Q3. リストを入れ子にしたのに階層がうまく表示されません。まず確認すべきポイントを2つ挙げてください。

    回答を表示

    （例）1つ目は、インデントに使っているのが半角スペースかどうか（Tabキーを使っていないか）。2つ目は、インデントのスペースの数が文書内で統一されているかどうかです。あわせて、リストの記号の後に半角スペースが入っているかも確認しましょう。
