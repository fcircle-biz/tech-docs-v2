Markdownとは

Markdown（マークダウン）は、「#」や「-」などの簡単な記号を添えるだけで、読みやすく整った文書を作れる書き方のルールです。この章では、Markdown が何なのか、なぜ世界中で使われているのか、そしてどんな仕組みできれいに表示されるのか、という全体像をつかみます。

この章で学ぶこと

  • Markdown とは何かを自分の言葉で説明できる
  • Word や HTML と比べたときの Markdown のメリットが分かる
  • Markdown が実際に使われている場所（GitHub・ブログ・チャットなど）を知る
  • 「書いたテキストが HTML に変換されて表示される」という仕組みの全体像をつかむ

1.1 Markdown とは何か

Markdown（マークダウン）は、ふつうのテキスト（文字だけのデータ）に # や - などの簡単な記号を添えることで、「ここは見出し」「ここは箇条書き」といった文書の構造を表現する書き方のルール（記法）です。2004年に John Gruber（ジョン・グルーバー）氏によって考案されました。

このように「文書に印（マーク）を付けて構造を表す言語」をマークアップ言語と呼びます。Markdown はその中でも、覚えることが少なく、書いたままでも読みやすい「軽量マークアップ言語」の代表です。特別なアプリがなくても、メモ帳のようなテキストエディタが1つあれば今日から書き始められます。

シンプルで覚えやすい

使う記号はほんの十数種類。この教材の第3〜8章でほぼ全部を学べてしまう手軽さです。

ただのテキストファイル

中身は文字だけなので軽く、どんな PC でも開けます。変更履歴の管理（Git など）とも相性抜群です。

きれいに変換される

対応サービスに貼るだけで、見出しやリストが整ったきれいなページとして表示されます。

用語: 「マークアップ」と「マークダウン」

Web ページを作る HTML も「マークアップ言語」の一種ですが、タグ（<h1> など）をたくさん書く必要があり、慣れないと大変です。Markdown という名前には、「マークアップ（markup）をもっと簡単に（down）」という遊び心が込められています。名前のとおり、HTML の手軽な代わりとして生まれました。

1.2 書いたもの と 表示されるもの

まずは一目で分かる例を見てみましょう。左があなたが書くテキスト（Markdown）、右がそれを対応サービスで開いたときの表示イメージです。記号がそれぞれ「見出し」「太字」「箇条書き」「リンク」に変身していることに注目してください。

書いたテキスト（Markdown）

profile.md 
# 自己紹介

こんにちは！ **山田 太郎** です。

## 好きなもの

- コーヒー
- 読書
- プログラミング

詳しくは [私のブログ](https://example.com) へ！

表示イメージ

自己紹介

こんにちは！ 山田 太郎 です。

好きなもの

  • コーヒー
  • 読書
  • プログラミング

詳しくは 私のブログ へ！

書く側は記号を数個覚えるだけ。それでも読む側には、整った美しい文書が届きます。この「書きやすさ」と「見やすさ」の両立こそが、Markdown が世界中で愛される理由です。

豆知識: 拡張子は「.md」

Markdown で書いたファイルには、名前の末尾に .md という拡張子を付けるのが一般的です（例: profile.md、README.md）。ファイルの作り方は第2章でじっくり練習します。

1.3 Word や HTML と何が違うのか

「見出しや箇条書きのある文書」を作る方法は、Markdown 以外にもあります。代表的な3つの方法と比べてみると、Markdown の立ち位置がはっきりします。

方法 見出しの書き方の例 特徴
Word などの文書ソフト 文字を選んでメニューから「見出し1」を選ぶ 直感的だが専用アプリが必要。ファイルが重く、共同編集や変更履歴の管理がしづらい。
HTML <h1>自己紹介</h1> Web ページの標準言語で何でもできるが、タグを開いて閉じる書き方は手間で、覚えることも多い。
Markdown # 自己紹介 記号1つで完結。テキストのままでも読みやすく、対応サービスに貼ればきれいに表示される。

Markdown は「Word ほど大げさではなく、HTML ほど難しくない」、ちょうど良いバランスの道具です。もちろん細かいレイアウト調整は苦手ですが、メモ・説明書・記事など「構造のある文章」を素早く書くという用途では最強クラスと言えます。

1.4 Markdown はどこで使われているのか

Markdown は、IT の世界を中心にとても幅広い場所で使われています。「実はあれも Markdown だった」というサービスがきっとあるはずです。

  • GitHub — プロジェクトの説明書である README、Issue（課題）やプルリクエストのコメント
  • 技術記事サービス — Qiita・Zenn などは記事を Markdown で執筆する
  • メモ・ドキュメントアプリ — Notion・Obsidian などは Markdown 記法での入力に対応
  • チャットツール — Slack・Discord・Teams では太字や箇条書きなど一部の記法が使える
  • ブログ・Web サイト作成 — Hugo・Jekyll などのツールは Markdown からサイトを生成する
  • AI チャット — ChatGPT や Claude の回答も Markdown で整形されて表示されている

つまり Markdown を一度覚えれば、開発・執筆・メモ・チームでのやり取りまで、あらゆる場面でそのまま使い回せます。IT エンジニアはもちろん、文書を書くすべての人にとって「一生モノの基礎スキル」です。

1.5 きれいに表示される仕組み

Markdown で書いたテキストは、そのままではただの文字列です。GitHub やエディタのプレビュー機能などの中では、パーサー（変換ツール）が記号を読み取って HTML（Web ページの言語）に変換し、それがきれいに整えられて画面に表示されています。流れを図にすると次のとおりです。

この変換は対応サービスが自動でやってくれるので、書く人は HTML を知らなくてもまったく問題ありません。「記号のルールに従って書けば、あとは機械が良い感じにしてくれる」と覚えておけば十分です。

重要ポイント

Markdown は「書くためのルール」、HTML は「表示するための言語」。あなたは Markdown のルールで書くだけでよく、表示の変換はツールにおまかせ。この役割分担が理解できれば、第1章は合格です。

やってみよう 1-1: 本物の Markdown を見に行こう

インストールなどの準備は第2章で行います。その前に、実際に世の中で使われている Markdown の「変換前」と「変換後」を自分の目で見比べて、イメージをつかんでおきましょう。

手順

  1. 1 ブラウザで GitHub の有名なプロジェクト（例: 「github vscode」で検索して microsoft/vscode）を開き、ページ下部に README がきれいに表示されていることを確認する。
  2. 2 ファイル一覧から README.md をクリックし、表示切り替え（Code / Raw ボタン）で「変換前の生テキスト」を表示して、# や - などの記号を探す。
  3. 3 普段使っているチャットやメモアプリで、**こんにちは** のように入力して太字になるか試してみる（対応していれば、それも Markdown 記法です）。

理解度確認クイズ

  1. Q1. Markdown とはどのようなものか、「記号」という言葉を使って説明してください。

    回答を表示

    ふつうのテキストに「#」や「-」などの簡単な記号を添えて、見出しや箇条書きといった文書の構造を表す書き方のルール（軽量マークアップ言語）です。書いたままでも読みやすく、対応サービスではきれいに変換して表示されます。

  2. Q2. Markdown ファイルに付ける、一般的な拡張子は何ですか？

    回答を表示

    .md です（例: README.md）。markdown の略で、まれに .markdown が使われることもあります。

  3. Q3. Markdown で書いた文書が画面にきれいに表示されるまでの流れを、順番に説明してください。

    回答を表示

    「Markdown でテキストを書く → パーサー（変換ツール）が記号を解釈して HTML に変換する → ブラウザやアプリが整えて表示する」という流れです。変換は対応サービスが自動で行うため、書く人は記号のルールだけ覚えれば大丈夫です。
