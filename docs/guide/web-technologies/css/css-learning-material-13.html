第13章 所要時間: 約35分

CSS変数と保守しやすい書き方

この章では、書いた CSS を後から直しやすく保つための工夫を学びます。同じ色や余白の値をあちこちのセレクタに書いていると、値を変えたくなったときにすべて探して直す必要があり、直し忘れも起こりがちです。カスタムプロパティ（CSS変数）を使えば、値を1箇所にまとめて管理できます。あわせて、クラス名の付け方・スタイルシートの並べ方・よくある失敗の避け方まで、実務でも役立つ整理のコツを身につけましょう。

この章で学ぶこと

  • 同じ値を繰り返し書くことの問題点を説明できる
  • カスタムプロパティ（CSS変数）を :root に定義し、var() で使える
  • 役割に基づいたクラス名の付け方（BEMの考え方を含む）が分かる
  • 保守しやすいスタイルシートの並べ方と、よくある失敗の避け方が分かる
  • Can I use や MDN で、ブラウザの対応状況を確認できる

13.1 同じ値を何度も書く問題

ここまでの章で、色や余白の値を何度も CSS の中に書いてきました。たとえば「テーマ色」を1つ決めたつもりでも、実際には h1・.btn・a:hover など、いくつものセレクタに同じ色コードを書き写していることが多いはずです。

この状態で困るのは、後から色を変えたくなったときです。テーマ色を変更するには、その色コードを使っているすべての箇所を探し出して1つずつ書き換えなければなりません。ファイルが大きくなるほど探す箇所は増え、1つでも直し忘れると、ページの一部だけ古い色が残ってしまい見た目がちぐはぐになります。

style.css（色コードがあちこちに直書き） 
/* 同じ色コードが何箇所にも直書きされている */
h1 { color: #f97316; }
.btn { background-color: #f97316; }
.btn:hover { background-color: #ea580c; }
a { color: #f97316; }
.badge { border: 1px solid #f97316; }

この「同じ値の重複」は、色だけでなく余白のサイズや角丸の大きさなどでも起こります。次の節では、これをCSS変数で解決する方法を見ていきます。

13.2 カスタムプロパティ（CSS変数）

CSS には、値を1箇所で定義して使い回せるカスタムプロパティという仕組みがあります。一般に「CSS変数」と呼ばれます。書き方はシンプルで、:root というセレクタの中に --（ハイフン2つ）で始まる名前を使って値を定義し、使う側では var(変数名) という形で呼び出します。

:root は文書全体（HTML要素とほぼ同じ範囲）を指すセレクタです。ここに変数を定義しておくと、ページのどこからでも参照できる「共通の設定置き場」になります。変数名は自由に付けられますが、必ず -- から始める決まりです。

style.css（CSS変数で一元管理） 
/* :root にテーマ色をまとめて定義する */
:root {
  --main-color: #f97316;
}

/* 使う側は var() で参照するだけ */
h1 { color: var(--main-color); }
.btn { background-color: var(--main-color); }
a { color: var(--main-color); }

こうしておけば、色を変更したいときは --main-color の値を1行直すだけで、それを参照しているすべての箇所に一度に反映されます。関係を図にすると、次のようになります。

flowchart TD A[":root で --main-color を定義"] --> B["h1 が var(--main-color) を参照"] A --> C[".btn が var(--main-color) を参照"] A --> D["a が var(--main-color) を参照"] B --> E["色を変えたいときは
Aの定義を1箇所直すだけでよい"] C --> E D --> E

重要ポイント: ビルドツール不要のブラウザ標準機能

CSS変数は、Sass など一部のツールが持つ「変数機能」とは違い、ブラウザが直接解釈する標準の CSS機能です。ファイルを事前に変換（コンパイル）する必要はなく、この章までに使ってきたのと同じ、ただのテキストファイルとして書くだけで使えます。

13.3 変数の活用例

CSS変数は色だけのものではありません。何度も登場する値であれば、余白のサイズ・角丸の大きさ・フォントの指定など、なんでも変数化できます。よく変数にされる値を整理すると、次のようになります。

  • テーマ色 — --main-color で見出し・ボタン・リンクなどの色を揃える
  • 余白サイズ — --spacing-base で padding・margin の基準値を統一する
  • 角丸 — --radius-base でカード・ボタンの丸みを揃える
  • フォント — --font-main でサイト全体のフォント指定を1箇所にまとめる

変数はページ全体だけでなく、特定のセクションだけ上書きすることもできます。また、var() の第2引数にフォールバック値（変数が定義されていない場合の代わりの値）を指定しておくと安全です。

style.css（上書きとフォールバック） 
:root {
  --accent-color: #f97316;
}

/* このセクションの中だけ変数を上書きする */
.special-section {
  --accent-color: #06b6d4;
}

.btn { background-color: var(--accent-color); }

/* 変数が未定義でも安全なようフォールバック値を指定 */
.badge { color: var(--sub-color, #64748b); }

13.4 クラス名の付け方

クラス名は、見た目ではなく「役割・意味」に基づいて付けるのが基本です。たとえば警告文に赤い文字色を付けるとき、.red-text という名前を付けてしまうと、後で色をオレンジに変更したときにクラス名と見た目が食い違ってしまいます。.error-message のように役割で名付けておけば、見た目を変えても名前はそのまま使えます。単語をつなぐときは、-（ハイフン）でつなぐ書き方が広く使われています。

悪い例（見た目基準）→良い例（役割基準）の順に並べると、たとえば .red-text → .error-message、.big-box → .product-card のように書き換えられます。

中〜大規模なサイトになると、クラス名の付け方をチーム全体で揃えるための「命名手法」が使われます。代表的なものが BEM（Block・Element・Modifier）です。「ブロック（部品）」「エレメント（部品の中の要素）」「モディファイア（見た目の違い）」を、決まった記号でつないで表します。

style.css（BEMの命名例） 
/* ブロック（部品そのもの） */
.card { border-radius: 8px; }

/* エレメント: ブロック__要素名 */
.card__title { font-size: 1.25rem; }

/* モディファイア: ブロック--修飾名 */
.card--featured { border: 2px solid var(--main-color); }

BEM は今すぐ完璧に覚えなくてOK

BEM には細かいルールがいくつもありますが、今の段階では「ブロック・エレメント・モディファイアという3つの単位で名前を分ける考え方がある」と知っておくだけで十分です。詳しいルールは、もう少し規模の大きいサイトを作るようになった次の学習段階で扱います。

13.5 スタイルシートの並べ方

CSS はルールをどんな順番で書いても一応は動きますが、順番が整理されていないファイルは、後から読む人（未来の自分を含む）にとって「どこに何が書いてあるか分からない」ファイルになってしまいます。次の5つのブロックに分けて、上から順に書いていくことをおすすめします。

  • ① リセット・共通設定 — box-sizing の統一など、土台となる設定
  • ② 全体 — body・見出しなど、ページ共通の見た目
  • ③ レイアウト — ページ全体の骨組み（コンテナ・Flexbox・Grid）
  • ④ 部品 — ボタンやカードなど、繰り返し使うパーツ
  • ⑤ メディアクエリ — 画面幅ごとの調整（第11章）

それぞれの区切りに、目立つコメントを入れておくと迷わなくなります。

style.css（並び順の例） 
/* ① リセット・共通設定 */
* { box-sizing: border-box; margin: 0; padding: 0; }
/* ② 全体（body・見出しなど） */
body { font-family: sans-serif; color: var(--text-color); }
/* ③ レイアウト */
.container { max-width: 960px; margin: 0 auto; }
/* ④ 部品（ボタン・カード） */
.btn { padding: 8px 16px; border-radius: 4px; }
/* ⑤ メディアクエリ */
@media (max-width: 600px) {
  .container { padding: 0 16px; }
}

13.6 よくある失敗と回避

CSS は自由度が高い分、書き方が荒れやすい言語でもあります。ここでは、保守性を落としてしまう代表的な4つの失敗パターンと、その回避策をまとめます。

失敗パターン 何が起きるか 回避策
!important の乱用 詳細度を無視して強制的に勝つため、後で上書きするにはさらに強い指定が必要になる セレクタや記述順の見直しで解決できないか、先に検討する
詳細度の上げすぎ セレクタが長く複雑になり、他の場所で再利用・上書きしづらくなる クラスセレクタ1つで当てられるように設計する
インラインスタイルの多用 style="..." がHTML各所に散らばり、CSSファイルを見ても全体像が分からなくなる 見た目の指定はすべてCSSファイル側に書く
使わなくなったルールの放置 HTMLから消したはずのクラス用のCSSが残り続け、ファイルが肥大化する 機能を削除するときは、対応するCSSも一緒に見直す

特に !important と詳細度の上げすぎは、セットで発生しがちです。次のコードを見比べてみましょう。

style.css（悪い例） 
/* 詳細度が高すぎて他から上書きしづらい */
div#main .content ul.list li.item a { color: blue; }

/* !important で無理やり勝たせる（後で上書きしにくくなる） */
.btn { color: red !important; }

!important は最終手段

一度 !important を使うと、次にその値を上書きしたくなったときにも !important が必要になり、際限のない「付け合い」が始まりがちです。使う前に、セレクタの詳細度や記述順を見直せないか考えましょう。

13.7 ブラウザ対応の確認

CSS の機能は今も増え続けていますが、すべてのブラウザ・すべてのバージョンが同じように対応しているとは限りません。新しいプロパティを使う前に「どのブラウザで使えるか」を確認する習慣を付けておくと、公開してから見た目が崩れるトラブルを防げます。

ツール 特徴
Can I use（caniuse.com） 機能名で検索すると、主要ブラウザ×バージョンごとの対応状況が色分け表示される。ざっくり全体像をつかみたいときに便利
MDN のブラウザ互換性表 各プロパティのリファレンスページ末尾に表示される。調べ物のついでに、その場で確認できる

この章で学んだCSS変数の対応状況は？

この章で学んだカスタムプロパティ（CSS変数）は、現在の主要ブラウザであれば問題なく使えます。業務で古いブラウザへの対応が求められる場合だけ、念のため Can I use で確認しておくと安心です。

やってみよう 13-1: 色をCSS変数にまとめてみよう

これまでの章で書いてきた CSS には、同じ色コードをあちこちに書いている箇所があるはずです。それを :root の変数にまとめ直し、1箇所を変えるだけでテーマ色が切り替わることを、実際に手を動かして確認しましょう。

手順

  1. 1 これまでの練習で使っている CSSファイルを開き、繰り返し使っている色コード（メインカラーなど）を探す。
  2. 2 ファイルの先頭に :root { --main-color: 見つけた色コード; } を追加する。
  3. 3 繰り返し出てきた色コードを、1つずつ var(--main-color) に書き換える。
  4. 4 ブラウザで表示を確認し、書き換え前とまったく同じ見た目になっていることを確かめる。
  5. 5 --main-color の値だけを別の色に変えて保存し、変更したすべての箇所が一度に切り替わることを確認する。

まずはメインカラー1つだけを変数にしてみましょう。「値を1箇所変えたら、全部の色が一気に変わった」という体験ができれば、この章の目的は達成です。余裕があれば、余白のサイズも変数化してみましょう。

理解度確認クイズ

  1. Q1. CSS変数（カスタムプロパティ）は、通常どこに定義しますか。また、そこに定義する理由も説明してください。

    回答を表示

    :root セレクタの中に定義するのが一般的です。:root は文書全体を指すため、そこで定義した変数はページのどこからでも var() で参照でき、値を一元管理できるからです。

  2. Q2. var(--sub-color, #64748b) のように第2引数を指定すると、何ができますか。

    回答を表示

    第2引数は「フォールバック値」です。1つ目の変数（--sub-color）が定義されていない場合に、代わりに使われる値を指定できます。変数が未定義でもスタイルが崩れないようにする安全策です。

  3. Q3. クラス名を付けるとき、.red-text ではなく .error-message とすべきなのはなぜですか。

    回答を表示

    クラス名は見た目ではなく役割・意味に基づいて付けるべきだからです。.red-text だと、後で警告色を赤から別の色に変えた際に名前と実際の見た目が食い違ってしまいます。.error-message なら、見た目が変わってもクラス名の意味はそのまま通じます。

  4. Q4. スタイルシートの中で !important を多用すると、どのような問題が起きますか。

    回答を表示

    !important は詳細度の計算を無視して強制的に優先されるため、後から別の場所で上書きしたい場合にさらに強い !important が必要になり、際限のない「付け合い」が起きてスタイルの管理が破綻しやすくなります。使う前にセレクタや記述順の見直しで解決できないか検討すべきです。
