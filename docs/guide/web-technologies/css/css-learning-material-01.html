CSSとは

CSS（シーエスエス）は、HTML で作ったページの「見た目」を指定するための言語です。この章では、CSS が何をしてくれるのか、HTML とどう役割分担しているのか、そして CSS を書くとページがどう変わるのかという全体像をつかみます。まだコードを書く必要はありません。安心して読み進めてください。

この章で学ぶこと

  • CSS とは何かを自分の言葉で説明できる
  • HTML と CSS の役割分担を説明できる
  • CSS で何ができるのか（色・文字・余白・配置・動き）の全体像が分かる
  • 「カスケード」という名前の意味と、CSS の標準の現状を知る

1.1 CSS とは何か

CSS は Cascading Style Sheets（カスケーディング・スタイル・シート）の略で、Webページの見た目を指定するための言語です。文字の色や大きさ、背景、余白、要素の並べ方 — 私たちが「きれいなサイトだな」と感じる部分は、ほぼすべて CSS が担当しています。

HTML だけで作ったページは、実は「読める」けれど「素っ気ない」状態です。見出しは黒く大きく、文字は左端から並び、背景は白 — これはブラウザがあらかじめ持っている最低限のスタイルが適用されているだけだからです。そこに CSS を加えることで、同じ HTML のまま、見た目だけを自由に作り替えられるようになります。

CSS の指示は、いつも「どこに」「何を」「どうする」の3点セットです。たとえば「見出しに（どこに）、文字色を（何を）、オレンジに（どうする）」といった具合です。この形さえ押さえてしまえば、覚えることはプロパティ（指定できる項目）の名前だけ。プログラミングのような複雑な考え方は登場しません。

見た目を自由に決められる

色・文字・余白・並べ方まで、細かく指定できます。デザインの知識がなくても、少しずつ試しながら整えられます。

まとめて一括で変えられる

1つのCSSファイルを直すだけで、サイト内の全ページの見た目を同時に変更できます。修正がとても楽になります。

画面サイズに合わせられる

同じHTMLのまま、PCでは横並び・スマホでは縦積み、といった切り替えができます（第11章で学びます）。

用語: CSS も「プログラミング言語」ではない

CSS には計算や条件分岐といった命令がありません。「この要素はこう見せる」という指定を並べていくだけの言語です。そのため、プログラミング未経験の方でも取り組みやすく、書いた結果がすぐ画面に現れるので、学習の手応えを感じやすいのが特徴です。

1.2 CSS がある場合とない場合

言葉で説明するより、見比べるのが一番です。まったく同じ HTML に対して、CSS を当てていない状態と、少しだけ CSS を当てた状態を並べてみましょう。

profile.html（共通のHTML） 
<h1>山田 太郎</h1>
<p class="job">Webデザイナー</p>
<p>コーヒーと読書が好きです。</p>

CSS なし（ブラウザの標準のまま）

山田 太郎

Webデザイナー

コーヒーと読書が好きです。

CSS あり

山田 太郎

Webデザイナー

コーヒーと読書が好きです。

右側で使った CSS は、次のようなものです。まだ書き方を覚える必要はありません。「どこに { 何を: どうする; }」という形になっていることだけ、雰囲気で眺めてみてください。

style.css 
/* 見出しを中央寄せにして、色を変える */
h1 {
  text-align: center;
  color: #c2410c;
}

/* 肩書きの段落に背景色と丸みを付ける */
.job {
  background-color: #ffedd5;
  border-radius: 9999px;
  text-align: center;
}

HTML はひと文字も変えていないのに、印象がずいぶん変わりました。これが CSS の力です。HTML は「何が書いてあるか」、CSS は「それをどう見せるか」 — この分担を最初に押さえておくと、この先ずっと迷いません。

重要ポイント

CSS を書き換えても、ページの内容（文章そのもの）は変わりません。逆に言えば、見た目を変えたいときに HTML をいじる必要はない、ということです。この「構造と見た目の分離」が、Webの世界で長年守られてきた大原則です。

1.3 HTML・CSS・JavaScript の役割分担

現代のWebページは、3つの技術が協力して作られています。よく「家づくり」にたとえられる関係を、あらためて確認しておきましょう。

技術 役割 家にたとえると
HTML 構造・意味を決める（見出し・段落・画像・リンク） 柱や壁などの骨組み
CSS 見た目を整える（色・文字サイズ・余白・配置） 壁紙や内装のデザイン
JavaScript 動きを付ける（クリックで開閉・入力チェック・通信） 自動ドアや照明などの設備

ブラウザは、この3つを次のような順序で処理してページを組み立てています。CSS が「HTML を読み込んだ後で見た目を決める」立ち位置にいることを、流れで押さえておきましょう。

flowchart TD A["ブラウザが HTMLファイルを読み込む"] --> B["文書の構造を組み立てる（どこが見出しで、どこが段落か）"] B --> C["CSSファイルを読み込む"] C --> D["各要素に、当てはまるスタイルを割り当てる"] D --> E["位置と大きさを計算して画面に描画する"] E --> F["JavaScript があれば動きを追加する"]

ここで大事なのは、CSS は HTML があってはじめて働くという点です。CSS 単体ではページになりません。「HTML で書いた要素に、後から服を着せていくのが CSS」とイメージしておくと分かりやすいでしょう。

よくある勘違い

「見出しを大きくしたいから <h1> を使う」というのは、実は順序が逆です。見出しだから <h1> を使い、大きさは CSS で決めるのが正しい考え方です。見た目のためにタグを選ぶと、検索エンジンや読み上げソフトに正しく内容が伝わらなくなってしまいます。

1.4 CSS で何ができるのか

CSS で指定できる項目（プロパティ）は数百種類ありますが、全部を覚える必要はまったくありません。実際によく使うのは数十個ほどで、それらは次の5つのグループに整理できます。この教材の各章も、おおむねこの順番で進んでいきます。

文字まわり

フォントの種類・大きさ・太さ・行間・文字揃え・下線など。読みやすさを決める土台です。

→ 第5章で学びます

色・背景

文字色・背景色・背景画像・グラデーション。サイトの雰囲気を決める部分です。

→ 第6章で学びます

余白・枠線・サイズ

内側の余白・外側の余白・枠線・幅と高さ。「詰まって見える」を解決する要です。

→ 第7章で学びます

配置・レイアウト

横並び・中央寄せ・段組み・画面サイズ対応。CSS の一番の山場であり、一番おもしろい部分です。

→ 第8〜11章で学びます

装飾・動き

角丸・影・マウスを乗せたときの変化・アニメーション。仕上げの一手間でぐっとプロらしくなります。

→ 第12章で学びます

プロパティの名前は、英語をそのまま使ったものがほとんどです（color は色、font-size は文字サイズ、margin は余白）。暗記しようとせず、「こういうことができたはず」と思い出せる程度で十分です。名前や書式は、必要になったときに調べれば構いません。

調べものは MDN が定番

プロパティの使い方を調べたくなったら、MDN Web Docs（developer.mozilla.org）が定番です。日本語版も充実しており、各プロパティの意味・使用例・ブラウザ対応がまとまっています。検索するときは「css margin mdn」のように「mdn」を付け足すと、目的のページにたどり着きやすくなります。

1.5 「カスケード」という名前の意味と CSS の標準

CSS の頭文字 C は Cascading（カスケーディング＝滝のように流れ落ちる）です。少し不思議な名前ですが、これは 複数のスタイル指定が上から順に重なり、最終的な見た目が決まるという仕組みを表しています。

1つの要素に対して、指定は何段階にも重なります。ブラウザがもともと持っているスタイル、あなたが書いた CSSファイル、HTML の中に直接書いたスタイル — これらが滝のように流れ落ちて合流し、ぶつかったときは決められたルールで勝ち負けが決まります。

flowchart TD A["ブラウザ標準のスタイル（既定の見た目）"] --> D["最終的な見た目"] B["あなたが書いた CSSファイル"] --> D C["HTML内に直接書いたスタイル"] --> D D --> E["競合したときは 詳細度 と 記述順 で決着（第4章）"]

この「重なり」の仕組みこそ、CSS でつまずく人が最も多いポイントです。「書いたのに効かない」の原因はたいていここにあります。第4章でじっくり扱いますので、今は「CSS は重ね塗りされるものだ」というイメージだけ持っておいてください。

CSS の歩みも簡単に押さえておきましょう。仕様は W3C という団体が策定しており、現在は機能ごとの「モジュール」に分かれて継続的に更新されています。

  • 1996年 CSS1 — 文字色や余白など、最低限の装飾が可能になった最初の仕様
  • 1998年 CSS2 — 配置（position）などが加わり、レイアウト表現が広がった
  • 2011年ごろ CSS3 — 角丸・影・アニメーション・メディアクエリなどが登場。以降は仕様全体をまとめて更新せず、機能ごとのモジュール単位で進化する方式に移行
  • 現在 — Flexbox・Grid・カスタムプロパティなどが標準として広く使える状態。「CSS4」という単一のバージョンは存在しない

つまり、いま学ぶべきは「CSS3 まで」といった区切りではなく、現在のブラウザで安定して使える書き方です。この教材で扱う内容は、いずれも主要ブラウザで問題なく動作するものだけを選んでいます。

豆知識: ブラウザごとの差は昔ほど大きくない

かつては「このブラウザでは表示が崩れる」という悩みが日常茶飯事でしたが、現在は主要ブラウザの対応状況がほぼ揃っています。新しい機能を使うときに対応状況を確認したい場合は、Can I use（caniuse.com）というサイトが便利です（第13章で紹介します）。

やってみよう 1-1: CSS を消すとページはどうなる？

エディタの準備は第2章で行います。その前に、いま見ているようなWebページが CSS によってどれだけ支えられているかを、ブラウザだけで体験してみましょう。

手順

  1. 1 好きなWebページ（ニュースサイトなど）をブラウザで開く。
  2. 2 キーボードの F12 キーを押して「開発者ツール」を開く（Mac は Option+Command+I）。画面の右または下に、コードが並んだパネルが現れます。
  3. 3 パネルの中から Styles（スタイル）と書かれた領域を探す。そこに並んでいるのが、その要素に効いている CSS です。
  4. 4 各行の左にあるチェックボックスを外してみる。色が消えたり、配置が崩れたりする様子を観察しましょう（ページを再読み込みすれば元に戻ります）。

意味が分からない記述だらけでも大丈夫です。「見た目はすべて CSS で作られている」ことが実感できれば成功。この開発者ツールは、これから何度も使う一番の相棒になります（第2章で本格的に使い方を学びます）。

理解度確認クイズ

  1. Q1. CSS とはどのようなものか、「HTML」「見た目」という言葉を使って説明してください。

    回答を表示

    HTML で作られたWebページの見た目（色・文字・余白・配置など）を指定するための言語です。HTML が「何が書いてあるか（構造）」を担当し、CSS が「それをどう見せるか」を担当します。

  2. Q2. 「見出しを大きくしたいから <h1> タグを使う」という考え方は、なぜ適切でないのでしょうか。

    回答を表示

    タグは「意味」を表すものであり、大きさは CSS で決めるべきだからです。見た目のためにタグを選ぶと、検索エンジンや読み上げソフトに文書の構造が正しく伝わらなくなります。正しくは「見出しだから <h1> を使い、大きさは CSS で指定する」という順序です。

  3. Q3. CSS の「C」が表す Cascading（カスケーディング）とは、どういう意味でしょうか。

    回答を表示

    「滝のように流れ落ちる」という意味で、ブラウザ標準のスタイル・自分が書いた CSS・HTML内に直接書いたスタイルなど、複数の指定が重なって最終的な見た目が決まる仕組みを表しています。競合したときは詳細度と記述順で決着します（第4章）。

  4. Q4. CSS を書き換えると、ページの文章そのもの（内容）も変わりますか？

    回答を表示

    変わりません。CSS が変えるのは見た目だけです。この「構造と見た目の分離」により、CSSファイル1つを直すだけでサイト全体のデザインを一括変更できるという利点が生まれます。
