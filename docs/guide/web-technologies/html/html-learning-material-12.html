ホーム HTML 第12章
第12章 所要時間: 約50分

実践：プロフィールページを作ろう

いよいよ最終章です。第1章から第11章までで学んだ見出し・段落・リスト・リンク・画像・表・フォーム・セマンティック要素・CSSをすべて使い、自己紹介プロフィールページを1枚、企画から検証・公開まで自力で作りきります。この章はゴールであり、これまでの総復習でもあります。焦らず、順番に手を動かしていきましょう。

この章で学ぶこと

  • 「構成を決める → 骨組みを書く → 中身を入れる → CSSで整える → 検証する」という制作の流れを実践できる
  • これまで学んだタグとCSSを組み合わせて、1枚のプロフィールページを完成させられる
  • 開発者ツールとHTMLバリデータを使い、自分のページの誤りを見つけて直せる
  • GitHub Pagesを使ってページを世界に公開する方法の概要を知る

12.1 総合演習の全体像

この章で作るのは、名前・自己紹介・できること（スキル）・制作物・連絡先をまとめた1枚の自己紹介プロフィールページです。就職活動のポートフォリオや、学習の成果物として実際に使える形を目指します。難しい技術は使いません。ここまでの11章で学んだタグを、正しい場所に、正しい意味で並べていくだけです。

プロが実際にWebページを作るときも、いきなりコードを書き始めることはほとんどありません。次の5つのステップを順番に踏むことで、迷わず・崩れにくいページを組み立てられます。

flowchart TD A["STEP1
構成を決める"] --> B["STEP2
骨組みを書く"] B --> C["STEP3
中身を入れる"] C --> D["STEP4
CSSで整える"] D --> E["STEP5
検証する"] E --> F["公開する（任意）"]

本題に入る前に、この教材でこれまで学んだ主なタグを章ごとに振り返っておきましょう。「あれ、あのタグ何だっけ」となったら、該当の章に戻って復習してからで大丈夫です。

章 主に学んだタグ・属性
第3章 <!DOCTYPE html>・<html>・<head>・<body>
第4章 <h1>〜<h6>・<p>・<strong>・<em>
第5章 <ul>・<ol>・<li>
第6章 <a href="...">
第7章 <img alt="...">・<figure>
第8章 <table>・<tr>・<th>・<td>
第9章 <form>・<input>・<label>
第10章 <header>・<main>・<section>・<footer>
第11章 <link rel="stylesheet">・CSSセレクタとプロパティ

12.2 STEP1: 構成を決める

コードを書く前に、まず「どんな情報を、どんな順番で載せるか」を紙やメモに書き出します。これをワイヤーフレーム（構成の下書き）と呼びます。いきなりエディタを開いて書き始めると、途中で「あれ、何を作っていたんだっけ」と迷子になりがちです。設計図があるだけで、この後の作業がぐっと楽になります。

今回のプロフィールページは、次の5つのブロックで構成します。

ブロック 載せる内容 使う主なタグ
見出し部 名前・ひとことキャッチコピー header / h1
自己紹介 写真・経歴・自己PR文 section / figure / p
できること スキルの箇条書き section / ul
制作物 作った作品の一覧 section / table
連絡先 お問い合わせフォーム・SNSリンク section / form / a

ヒント: 自分なりにブロックを変えてもよい

上の5ブロックは一例です。「趣味」ブロックを足す、「制作物」を「学習履歴」に変える、といったアレンジは自由です。大切なのは、コードを書く前に紙の上で完成イメージを固めるという手順そのものです。

12.3 STEP2: 骨組みを書く

構成が決まったら、まず中身を入れずにタグの骨組みだけを書きます。第3章で学んだ定型（<!DOCTYPE html>〜</html>）と、第10章で学んだセマンティック要素を組み合わせます。

index.html（head部分） 
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>山田 太郎 - プロフィール</title>
  <link rel="stylesheet" href="style.css">
</head>

<meta name="viewport" ...> は、スマートフォンなどの小さな画面でもページが正しい大きさで表示されるようにするための「おまじない」です。定型文としてそのまま書いておけば大丈夫です。

続けて、中身のない「空っぽの箱」を並べてページ全体の骨格を作ります。まだ文字は1文字も入れなくてOKです。

index.html（body部分・骨組みのみ） 
<!-- 中身は空のまま。箱だけ先に置く -->
<body>
  <header></header>
  <main>
    <section id="about"></section>
    <section id="skills"></section>
    <section id="works"></section>
    <section id="contact"></section>
  </main>
  <footer></footer>
</body>
</html>

重要ポイント

各 <section> に付けた id="about" のような属性は、第6章で学んだページ内リンク（<a href="#about">）の飛び先として使えます。骨組みの段階で決めておくと、（発展として）あとでナビゲーションを追加したくなったときにスムーズに作れます。なお本教材では、ナビゲーション自体の作成までは扱いません。

12.4 STEP3: 中身を入れる

骨組みができたら、それぞれの箱に中身を書き込んでいきます。1ブロックずつ、上から順番に進めるのがコツです。全部を一度に埋めようとせず、1つ完成させたらブラウザで確認する、を繰り返しましょう。

(1) 見出し部と自己紹介ブロック — 写真は第7章の <img> と <figure> を使います（本教材では実際の画像は使わず、練習では手元の画像ファイルに置き換えてください）。

index.html（header・aboutセクション） 
<header>
  <h1>山田 太郎</h1>
  <p>Webサイト制作を学び中の初学者です。</p>
</header>

<section id="about">
  <h2>自己紹介</h2>
  <figure>
    <img src="profile.jpg" alt="山田太郎の写真">
    <figcaption>プロフィール写真</figcaption>
  </figure>
  <p>はじめまして。HTMLとCSSを勉強中です。</p>
</section>

(2) できることブロック — 第5章の <ul> でスキルを箇条書きにします。

index.html（skillsセクション） 
<section id="skills">
  <h2>できること</h2>
  <ul>
    <li>HTMLで文書構造を組み立てる</li>
    <li>CSSで見た目を整える</li>
    <li>表やフォームを作成する</li>
  </ul>
</section>

(3) 制作物ブロック — 第8章の <table> で一覧を作ります。

index.html（worksセクション） 
<section id="works">
  <h2>制作物</h2>
  <table>
    <thead>
      <tr><th>作品名</th><th>概要</th></tr>
    </thead>
    <tbody>
      <tr><td>学習ページ</td><td>HTML入門の演習作品</td></tr>
    </tbody>
  </table>
</section>

(4) 連絡先ブロック — 第9章の <form> です。<label for="..."> と id の対応を忘れずに。

index.html（contactセクション） 
<section id="contact">
  <h2>お問い合わせ</h2>
  <form>
    <label for="name">お名前</label>
    <input type="text" id="name" name="name">
    <label for="email">メール</label>
    <input type="email" id="email" name="email">
    <button type="submit">送信</button>
  </form>
  <p>SNS: <a href="https://twitter.com/example">Twitter</a></p>
</section>

よくあるミス

この演習の <form> は、実際に送信先サーバーを用意していないため送信は動作しません。学習用の教材では、フォームは「正しいタグ構造で書けること」を目標にすれば十分です。実際に送信できるフォームを作るには、第9章で触れたサーバー側の仕組みが別途必要になります。

12.5 STEP4: CSSで整える

タグを正しく並べただけの状態は、まだ文字が上から下へ並ぶだけの見た目です。第11章で学んだ外部CSSファイルを使って、色・余白・文字サイズを整えていきます。<head> に置いた <link rel="stylesheet" href="style.css"> がすでに読み込みの準備をしてくれています。

style.css 
/* 基本の見た目を整える */
body {
  font-family: sans-serif;
  color: #333333;
  max-width: 800px;
  margin: 0 auto;
  padding: 20px;
}
h1, h2 {
  color: #2c5282;
}
section {
  margin-bottom: 32px;
}

ここで初めて出てくるプロパティ・書き方もあります。font-family（文字のフォント種類）とmax-width（要素の最大幅）はそれぞれ第11章では扱わなかった新しいプロパティです。また h1, h2 のようにセレクタをカンマで区切ると、複数のセレクタへ同じスタイルをまとめて指定できます（グループセレクタ）。まずは「そういう書き方もある」と知っておけば十分です。

ポイントは、HTMLファイルにはいっさい手を加えないことです。見た目の調整はすべて style.css 側で完結します。これが第1章で学んだ「構造（HTML）と見た目（CSS）の役割分担」の実践です。CSSを保存してブラウザを再読み込みするたびに、少しずつページが整っていく様子を確認してください。

豆知識: 完璧を目指さなくてよい

「レイアウトをきれいに横並びにしたい」と思っても、この教材の範囲（第11章の入口レベルのCSS）ではまだ難しい場合があります。色・余白・文字サイズが整っているだけで十分な完成度です。本格的なレイアウトは、この章の最後で紹介する「次のステップ」で学びます。

12.6 STEP5: 検証する（開発者ツール ＆ バリデータ）

ページが完成したように見えても、タグの閉じ忘れや属性の書き間違いが隠れていることがあります。公開前に2つの方法でチェックする習慣をつけましょう。

ブラウザの開発者ツール

ページ上で右クリック →「検証」（Windowsは F12）で開きます。Elementsタブで実際のタグ構造を確認でき、Consoleタブでは赤字のエラーメッセージが表示されます。CSSの効き具合をその場で試すこともできます。

HTMLバリデータ（validator.w3.org）

W3Cが公式に提供する文法チェッカーです。HTMLファイルをアップロードするか、コードを貼り付けるだけで、タグの閉じ忘れ・属性ミスなどをError（誤り）とWarning（注意）に分けて教えてくれます。

よくあるミスと、それぞれのチェック方法を一覧にまとめました。

よくあるミス 見つけやすい方法
終了タグの閉じ忘れ バリデータのErrorに表示される
alt 属性の書き忘れ バリデータのErrorに表示される
見出しレベルの飛び（h2の次にh4など） 開発者ツールのElementsで階層を目視
同じ id の重複 バリデータのErrorに表示される
CSSが反映されない 開発者ツールのConsoleでファイル読み込みエラーを確認

重要ポイント

エラーが1つも出ないことより、「エラーが出たら自分で読んで直せる」ことのほうが大切です。エラーメッセージには「何行目の、どのタグに問題があるか」が具体的に書かれています。焦らず1つずつ読み解く練習を、この演習を通じて積んでいきましょう。

12.7 公開する: GitHub Pagesの概要

完成したページを自分のPCの中だけに置いておくのはもったいないですよね。GitHub Pages は、GitHub（ソースコードを管理・共有するサービス）が無料で提供している、静的なHTML・CSS・JavaScriptファイルをそのままWeb上に公開できる仕組みです。この教材のサイト自体も、実は同じ仕組みで公開されています。

サーバー用のプログラム知識は不要で、大まかな流れは次のとおりです。

  1. 1. GitHubアカウントを作る — 無料で登録できます
  2. 2. リポジトリ（保管場所）を作り、HTML・CSSファイルを置く（プッシュする）
  3. 3. リポジトリの「Settings」→「Pages」で公開用のブランチを選ぶ
  4. 4. 数分後に「https://ユーザー名.github.io/リポジトリ名/」の形のURLで公開される

今回作ったプロフィールページのようにサーバー側の処理を伴わないページ（静的サイト）であれば、このGitHub Pagesだけで十分に公開できます。実際の操作手順（Gitの使い方）は本教材の範囲外ですが、「自分の作ったHTMLがそのままインターネット上に公開できる」というイメージだけ持ち帰ってください。

公開は必須ではありません

この演習の主目的は「HTMLとCSSでページを組み立てる力を身につけること」です。GitHub Pagesでの公開は任意のステップとして捉えてください。まずは自分のPC上でファイルを完成させ、ダブルクリックしてブラウザで開いて確認できれば、この章の目標は十分に達成できています。

やってみよう 12-1: 自分のプロフィールページを完成させよう

この章で示した手順に沿って、あなた自身のプロフィールページを最初から最後まで作りきってみましょう。テーマは「自己紹介」でなくても構いません（好きな作品の紹介ページなどでもOKです）。

手順

  1. 1 紙かメモ帳に、載せたい情報を5つ以内のブロックに分けて書き出す（STEP1）。
  2. 2 新しいフォルダに index.html と style.css を作り、タグの骨組みだけを書く（STEP2）。
  3. 3 見出し・段落・リスト・表・フォームを、1ブロックずつ中身で埋めていく（STEP3）。1つ書いたらブラウザで保存・再読み込みして確認する。
  4. 4 style.css で色・余白・文字サイズを整える（STEP4）。
  5. 5 開発者ツールでConsoleにエラーが出ていないか、validator.w3.org でHTMLの文法エラーがないかを確認する（STEP5）。
  6. 6 （任意）GitHub Pagesでの公開に挑戦してみる。

完璧なデザインを目指す必要はありません。「見出し・段落・リスト・リンク・画像・表・フォームのうち最低5種類のタグを、意味の通った形で使えているか」を完成の目安にしてください。それができれば、この教材の目標は達成です。

12.8 全タグ チートシート：総復習

この教材で登場した主なタグを、カテゴリごとに一覧にしました。これから実際のページを作るときの早見表として活用してください。

文書の骨組み（第3章）

タグ 用途
<!DOCTYPE html>文書がHTML5系であることの宣言
<html lang="ja">文書全体のルート要素・言語指定
<head>画面に表示されない設定情報の集まり
<meta charset="UTF-8">文字コードの指定（文字化け防止）
<meta name="viewport" ...>スマートフォンで正しい大きさに表示させるおまじない
<title>タブに表示されるページタイトル
<body>画面に表示される内容全体

見出しと文章（第4章）

タグ 用途
<h1>〜<h6>見出し（数字が小さいほど大きな見出し）
<p>段落
<br>強制改行（空要素）
<hr>話題の区切り線（空要素）
<strong> / <em>強い重要性の強調 / 文脈的な強調
<code> / <blockquote>コード表記 / 引用

リスト（第5章）

タグ 用途
<ul> / <ol>箇条書きリスト / 番号付きリスト
<li>リストの各項目
<dl> / <dt> / <dd>説明リスト（用語と説明の対）

リンクとメディア（第6章・第7章）

タグ 用途
<a href="...">リンク（ページ移動・ページ内ジャンプ）
<img src="..." alt="...">画像の表示（空要素・alt必須）
<figure> / <figcaption>キャプション付き画像のまとまり
<video> / <audio>動画・音声の埋め込み

表とフォーム（第8章・第9章）

タグ 用途
<table> / <tr> / <th> / <td>表・行・見出しセル・データセル
<thead> / <tbody>表のグループ化
<caption>表全体のタイトル・説明
colspan / rowspanセルを横方向 / 縦方向に結合する属性
<form>入力を受け付ける全体の枠
<input> / <textarea> / <select>入力部品各種
<label for="...">入力欄の説明ラベル（idと対応）

セマンティック要素とCSS連携（第10章・第11章）

タグ 用途
<header> / <footer>ページ・セクションの導入部 / 締めの部分
<nav> / <main>主要ナビゲーション / ページの主要内容
<section> / <article>意味のあるまとまり / 単独で成立する記事
<aside>補足情報・本筋から離れた関連コンテンツ
<div> / <span>意味を持たない汎用の箱（ブロック / インライン）
<link rel="stylesheet">外部CSSファイルの読み込み

理解度確認クイズ

  1. Q1. この章で紹介した制作の流れ「構成を決める→骨組みを書く→中身を入れる→CSSで整える→検証する」で、いちばん最初にやるべきことは何ですか。またそれをコードを書く前に行う理由を説明してください。

    回答を表示

    最初にやるのは「構成を決める」ことです。載せたい情報をブロックに分けて紙やメモに書き出す（ワイヤーフレーム作成）ことで、途中で迷子にならず、崩れにくいページを効率よく組み立てられるためです。

  2. Q2. ブラウザの開発者ツールとHTMLバリデータ（validator.w3.org）は、それぞれ何を確認するために使いますか。

    回答を表示

    開発者ツールは、実際のタグ構造（Elements）やJavaScript・読み込みのエラー（Console）をブラウザ上でその場で確認するために使います。HTMLバリデータは、HTMLの文法（タグの閉じ忘れや属性ミスなど）を公式のルールに照らして機械的にチェックするために使います。

  3. Q3. GitHub Pagesとはどのようなサービスか、簡潔に説明してください。

    回答を表示

    GitHubが無料で提供している、HTML・CSS・JavaScriptなどの静的ファイルをそのままインターネット上に公開できる仕組みです。サーバー側のプログラム知識がなくても、作ったページを世界に公開できます。

  4. Q4. STEP4「CSSで整える」の段階で、HTMLファイルとCSSファイルのそれぞれに加える変更は何ですか。

    回答を表示

    HTMLファイルにはいっさい手を加えません。見た目の調整（色・余白・文字サイズなど）はすべてCSSファイル側に書きます。これはHTML（構造）とCSS（見た目）の役割分担を実践する重要なポイントです。

お疲れさまでした。次のステップへ

全12章、お疲れさまでした。あなたはすでにHTMLで1枚のページを企画から公開手前まで作りきる力を身につけています。ここからは、さらにWeb制作の世界を広げる3つの方向があります。

  • CSSの本格学習 — Flexbox・Gridによるレイアウト、スマホ対応のレスポンシブデザイン、アニメーションなどを学ぶと、見た目の表現力が大きく広がります。
  • JavaScript — ページに「動き」を付ける言語です。クリックで表示を切り替える、入力内容をチェックするなど、インタラクティブな仕組みを作れるようになります。
  • Webアクセシビリティ・SEO — 誰にとっても使いやすく、検索エンジンにも見つけてもらいやすいページ作りの考え方です。第10章で学んだセマンティックHTMLはその第一歩です。
