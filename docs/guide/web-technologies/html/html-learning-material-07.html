第7章 所要時間: 約40分

画像とメディア

これまでの章では文字だけのページを扱ってきましたが、この章では画像・音声・動画をページに加える方法を学びます。<img> タグの必須属性から、代替テキスト・レイアウトのずれ防止・画像形式の使い分け、そして <audio>・<video>・<iframe> による埋め込み、著作権への配慮まで、視覚要素を扱う上で欠かせない知識を身につけます。

この章で学ぶこと

  • <img> の必須属性 src・alt を正しく書ける
  • 代替テキスト alt の役割を理解し、適切な文言を書ける
  • width・height 属性でレイアウトのずれを防げる
  • 画像形式（JPEG・PNG・GIF・SVG・WebP）を用途に応じて選べる
  • <figure>・<audio>・<video>・<iframe> と著作権への配慮を理解する

7.1 img タグの基本

画像をページに表示するには <img> タグを使います。これまで学んだ <p> や <h1> と大きく違う点があります。それは、HTMLファイルの中に画像データそのものは書き込まれないということです。<img> は「ここに、この場所にある画像ファイルを表示してください」とブラウザに指示する参照（リンク）にすぎません。

また <img> は第3章で学んだ空要素（内容を持たず終了タグが無いタグ）です。<br> と同じ仲間ですね。<img /> のようにスラッシュを付けて書くこともできますが、HTML Living Standard では付けても付けなくても同じ意味になります。

src 属性（必須）

表示したい画像ファイルの場所（パス）を指定します。source（元）の略です。

alt 属性（必須）

画像の内容を説明する代替テキストです。alternative（代わりの）の略です。

空要素

内容を持たないタグなので終了タグ </img> は書きません。

index.html 
<!-- src: 画像ファイルの場所 / alt: 代替テキスト -->
<img src="images/mt-fuji.jpg" alt="夕暮れの富士山">

用語: 属性は必ず両方セットで

ブラウザの文法チェックをすり抜けてしまうことはありますが、仕様上 alt は原則必須です。「画像を置くなら alt も一緒に」を習慣にしましょう。

7.2 代替テキスト alt の役割と書き方

alt 属性は、単なるおまけの属性ではありません。次の3つの場面で重要な役割を果たします。

スクリーンリーダー

視覚に障害のある方が使う読み上げソフトが、画像の代わりに alt のテキストを読み上げます。

読み込み失敗時

パス間違いや通信エラーで画像が表示できないとき、代わりに alt のテキストが表示されます。

検索エンジン（SEO）

検索エンジンは画像の中身を人間のようには理解できないため、alt のテキストを手がかりにします。

書き方のコツは、「その画像が伝えている情報」を簡潔な文章で説明することです。良い例と悪い例を比べてみましょう。

悪い例 良い例 理由
alt="IMG_0231.jpg" alt="ソファで丸くなっている白い猫" ファイル名は画像の内容を説明していない
alt="画像" alt="2024年度 売上グラフ（前年比120%）" 曖昧すぎて内容が伝わらない
alt="画像: 猫の写真です" alt="猫" 「画像」「〜の写真です」は不要（読み上げソフトが自動で伝える）

重要ポイント: 装飾だけの画像は alt=""

区切り線の飾りやアイコンなど、情報を持たない純粋な装飾画像には、空の代替テキスト alt="" を指定します。こうすることでスクリーンリーダーがその画像を読み飛ばし、ユーザーの邪魔をしません。ただし alt 属性自体を省略するのは避けてください。「説明を書き忘れたのか」「意図的に空にしたのか」をスクリーンリーダーなどの支援技術が区別できなくなります。

よくある間違い

alt を丸ごと省略してしまうと、読み込みに失敗したときに何も手がかりが残らず、画面には壊れた画像アイコンだけが表示されます。「面倒だから空欄で」を続けると、視覚障害のある利用者にとってはページの内容が半分も伝わらないことになります。

7.3 width・height 属性とレイアウトのずれ防止

ブラウザは HTML を上から順に読みながらページを組み立てますが、画像ファイルの読み込みには時間がかかります。もし 画像の大きさを事前に知らせていないと、画像が届いた瞬間に周りの文章がガクッと下にずれる、という現象が起こります。これをレイアウトシフトと呼び、Google が重視する表示品質の指標（Core Web Vitals）のひとつにも数えられています。

width・height 未指定

画像の大きさが分からないため、ブラウザは高さ0の場所を確保します。画像が届いた瞬間、下の文章が一気に押し下げられます。

読込前: 見出し → 本文（画像分の隙間なし）
読込後: 見出し → 画像が割り込む → 本文が下にジャンプ

width・height 指定あり

ブラウザは画像の縦横比から表示スペースをあらかじめ確保できます。画像が届いても周りの文章は動きません。

読込前: 見出し → 画像用の空きスペース → 本文
読込後: 見出し → 画像 → 本文（位置そのまま）
index.html 
<!-- 画像の実際のピクセルサイズを指定する -->
<img src="images/mt-fuji.jpg" alt="夕暮れの富士山"
     width="800" height="600">

ここで指定する数値は、画像ファイルが実際に持っているピクセルサイズ（またはそれと同じ縦横比の数値）を書くのが基本です。第11章以降で学ぶ CSS の max-width: 100%（と height: auto）を指定すれば、画面サイズに応じて縮小表示しつつ、レイアウトシフト防止の効果はそのまま活かせます。

よくある間違い

元画像と異なる縦横比の width・height を指定すると、画像が縦や横に引き伸ばされて歪んで表示されます。必ず元画像の縦横比を保った数値を指定しましょう。

7.4 画像形式の使い分けとフォルダ整理

画像ファイルにはいくつかの形式（拡張子）があり、それぞれ得意分野が異なります。目的に合わない形式を選ぶと、無駄にファイルサイズが大きくなったり、画質が劣化したりします。

形式 得意なこと 透過 向いている用途
JPEG（.jpg） 色数の多い写真を高圧縮 × 風景・人物などの写真
PNG（.png） 劣化なしの高画質・透過 ○ スクリーンショット・ロゴ・アイコン
GIF（.gif） 256色までの簡易アニメーション ○（単純） 簡単なアニメーション・古い形式
SVG（.svg） 拡大しても粗くならない図形 ○ ロゴ・アイコン・グラフなどの図形
WebP（.webp） JPEG・PNG より高圧縮・高画質 ○ 写真・イラストなど幅広い用途（近年の主流）

用語: SVG はテキストで書かれた画像

SVG（Scalable Vector Graphics）は、写真のように点（ピクセル）の集まりではなく、座標や図形を記述したテキストデータです。そのため何倍に拡大しても輪郭がギザギザにならず、ロゴやアイコンに最適です。実は SVG も HTML と同じマークアップ言語の仲間です。

画像ファイルが増えてくると、HTMLファイルと同じ場所に置きっぱなしにするとフォルダの中がすぐに散らかります。第2章で学んだフォルダ整理と同じ考え方で、画像専用のフォルダを用意しておきましょう。

フォルダ構成の例

my-website/
├── index.html
├── about.html
└── images/
    ├── mt-fuji.jpg
    ├── logo.svg
    └── profile.png
index.html 
<!-- images フォルダの中の画像を相対パスで指定 -->
<img src="images/mt-fuji.jpg" alt="夕暮れの富士山"
     width="800" height="600">

images/mt-fuji.jpg は、第6章で学んだ相対パスの書き方そのものです。「今いる場所（HTMLファイルの場所）から見て、images フォルダの中の mt-fuji.jpg」という意味になります。ファイル名は半角英数字とハイフンで、スペースや日本語を避けるのが安全です。

7.5 figure・figcaption によるキャプション付き画像

写真集やニュース記事では、画像の下に「◯◯にて撮影」のようなキャプション（説明文）が添えられていることがよくあります。HTML にはこの関係を意味的に表す専用のタグ、<figure> と <figcaption> が用意されています。

<figure> は「画像と、それに関連する説明文をひとまとまりの図として扱う」という意味を持ちます。中に置く <figcaption> がキャプション本文です。1つの <figure> に置けるのは1つの <figcaption> だけですが、置く位置は先頭でも末尾でも構いません。

書いた HTML

index.html 
<figure>
  <img src="images/mt-fuji.jpg"
       alt="夕暮れの富士山"
       width="800" height="600">
  <figcaption>
    河口湖から望む富士山（2024年10月撮影）
  </figcaption>
</figure>

ブラウザでの表示イメージ

河口湖から望む富士山（2024年10月撮影）

右側は画像の代わりにプレースホルダーで示していますが、実際には <img> の部分に写真が表示され、下にキャプションが並びます。なお <figcaption> の既定の文字寄せは左寄せですが、ここでは見やすさのため中央寄せにしています。<figure> と <figcaption> はデフォルトの見た目自体は地味ですが、「この画像とこの説明文はセットである」という意味を検索エンジンやスクリーンリーダーに伝えられる点が価値です。

alt とキャプションは役割が違う

alt は「画像が見えない人・見えない場合の代わりの説明」、figcaption は「画像が見えている人にも表示される補足情報」です。両方書いても内容が重複しないよう、alt は画像そのものの説明、figcaption は撮影場所や出典などの付加情報、と役割分担するとよいでしょう。

7.6 音声・動画・外部コンテンツの埋め込みと著作権

画像だけでなく、音声や動画もタグ1つでページに埋め込めます。ここでは <audio>・<video>・<iframe> の3つを紹介します。

audio・video の例 
<!-- 音声プレイヤーを表示（controls で再生ボタン等を表示） -->
<audio controls>
  <source src="sounds/theme.mp3" type="audio/mpeg">
  お使いのブラウザは音声再生に対応していません。
</audio>

<!-- 動画プレイヤーを表示 -->
<video controls width="640" height="360">
  <source src="movies/intro.mp4" type="video/mp4">
  お使いのブラウザは動画再生に対応していません。
</video>

controls 属性を付けると、再生・停止・音量などのボタンが自動で表示されます。<source> はファイルの場所と形式を示す子要素で、複数書いておくと対応形式が違うブラウザでも再生できます。タグに挟んだ文章（お使いのブラウザは〜）は、<audio>・<video> に対応していない古いブラウザにだけ表示される代替コンテンツです。

YouTube などの動画共有サービスにある動画は、自分のサーバーに置かなくても他のサイトの一部を自分のページに映し出す <iframe>（インラインフレーム）で埋め込めます。

iframe の例 
<!-- YouTube 公式の「埋め込みコード」に含まれる embed URL を使う -->
<iframe src="https://www.youtube.com/embed/xxxxxxxxxxx"
        width="560" height="315"
        title="紹介動画"
        allowfullscreen>
</iframe>

src には、通常の視聴用URL（watch?v=）ではなく、YouTube が提供する埋め込み専用のURL（/embed/）を使います。title 属性は iframe の内容をスクリーンリーダーに伝えるために付けておきましょう。

著作権への配慮

インターネット上の画像・音声・動画には、多くの場合著作権があります。他人が撮影・制作したファイルを無断でダウンロードし、自分のフォルダに保存して <img> や <video> で読み込むことは、著作権侵害にあたる可能性があります。一方 <iframe> による YouTube 埋め込みは、動画の実体が YouTube 側に残ったまま表示されるだけなので、公式が提供する埋め込みコードを使う限りは比較的安全とされています（ただし投稿者が埋め込みを禁止している動画は表示されません）。

ライセンス表記 意味 利用時の注意
CC0 / パブリックドメイン 著作権を放棄・制限なしで自由に利用可 クレジット表記も基本的に不要
CC BY（表示） 作者名を表記すれば利用可 出典・作者名のクレジット表記が必須
全著作権保有 権利者の許可なく利用不可 個別に利用許諾を得る必要がある

学習用の画像を探すときは「フリー素材」「Creative Commons（CC）」といったキーワードで検索し、必ず利用規約（ライセンス）を確認する習慣をつけましょう。

やってみよう 7-1: 画像をページに組み込もう

フリー素材サイトから画像を1枚用意し、正しい alt テキストと figcaption 付きで表示してみましょう。

手順

  1. 1 フリー素材サイト（CC0・商用利用可などのものを選ぶ）から好きな画像を1枚ダウンロードする。
  2. 2 index.html と同じフォルダに images フォルダを作り、その中にダウンロードした画像を保存する。
  3. 3 <figure> の中に、src・alt・width・height を指定した <img> と、<figcaption> を書く。
  4. 4 保存してブラウザで開き、画像とキャプションが表示されることを確認する。試しに src のファイル名をわざと間違えて保存し、alt のテキストが代わりに表示されることも確認してみよう。

alt が表示された瞬間、「画像が読み込めなかったときの保険」としての alt の役割を体感できます。うまく表示されなくても、それも大事な学びです。

理解度確認クイズ

  1. Q1. img 要素の2つの必須属性は何ですか。それぞれの役割も答えてください。

    回答を表示

    src（画像ファイルの場所を指定）と alt（画像の代替テキストを指定）です。src が無いと画像そのものが表示できず、alt が無いと画像が見えない・表示できない場合に内容を伝える手段が失われます。

  2. Q2. 装飾だけの画像（意味を持たない画像）には alt をどう書くべきですか。またその理由も説明してください。

    回答を表示

    alt="" のように空の値を指定します。こうすることでスクリーンリーダーがその画像を読み飛ばし、意味のない説明でユーザーの邪魔をしません。alt 属性自体を省略すると「書き忘れ」と区別できなくなるため避けます。

  3. Q3. img タグに width と height を指定する主な目的は何ですか。

    回答を表示

    画像が読み込まれる前に表示スペースをあらかじめ確保し、画像が届いたときに周囲の文章が下にずれる「レイアウトシフト」を防ぐためです。数値は元画像と同じ縦横比にする必要があります。

  4. Q4. ロゴやアイコンに SVG 形式が向いている理由と、figure・figcaption の役割をそれぞれ説明してください。

    回答を表示

    SVG は座標や図形を記述したテキストデータのため、何倍に拡大してもギザギザにならず画質が劣化しません。figure は画像とその説明文をひとまとまりの図として意味づけるタグで、figcaption はその中に置くキャプション本文です。
