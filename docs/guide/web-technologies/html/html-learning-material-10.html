セマンティックHTMLと文書構造

ここまでで、見出し・段落・リスト・リンク・画像・表・フォームという「意味を持ったタグ」の使い方を学んできました。この章では一歩引いて、ページ全体を、意味のある構造として組み立てる方法を学びます。何にでも使える <div> との付き合い方から、<header> や <main> といった「セマンティック要素」まで、順を追って整理していきます。

この章で学ぶこと

  • <div>・<span> でのグループ化と、ブロック要素・インライン要素の違いを説明できる
  • class 属性と id 属性を正しく使い分けられる
  • セマンティック要素（header・nav・main・section・article・aside・footer）でページ全体を組み立てられる
  • セマンティックにするメリット（読みやすさ・SEO・スクリーンリーダー対応）と、見出しレベルとの関係、よくある誤用を説明できる

10.1 div・span によるグループ化

これまで学んだタグ（<h1>・<p>・<ul> など）は、どれも「これは見出しです」「これは段落です」という意味を持っていました。しかし実際にページを作っていると、「意味は特にないけれど、いくつかの要素をひとまとめにして、まとめて装飾したい」という場面がよく出てきます。そのために用意されているのが <div> と <span> です。

<div>（division＝区分）は、複数の要素をひとつの箱としてまとめるための、意味を持たない汎用コンテナです。<span> は同じ役割を文章の一部分に対して行うためのタグです。どちらも「これ自体に意味はないが、まとめて扱いたい」というときの入れ物、と覚えておきましょう。

card.html 
<!-- div: 複数要素をひとつの箱としてまとめる -->
<div class="profile-card">
  <h3>山田 太郎</h3>
  <p>フロントエンドエンジニア</p>
</div>

<!-- span: 文章の一部分だけをまとめる -->
<p>
  在庫状況：<span class="status-ok">在庫あり</span>です。
</p>

この例の <div> や <span> を全部そのまま消してしまっても、ブラウザに表示される文章そのものは変わりません。これらのタグは「見た目や意味を主張しない、ただの箱」だからです。実際の使い道は、10.3節で学ぶ class 属性と組み合わせて、CSS で装飾したり JavaScript で操作したりする「フック（取っ手）」にすることです。

div・span は「最後の手段」

意味を持ったタグ（見出し・段落・リストなど）で表現できる内容には、必ずそちらを優先してください。<div> や <span> は、「他にふさわしいタグが見当たらないときの、レイアウト・装飾専用の箱」として最後に使うものです。この考え方は10.4節のセマンティック要素にもつながります。

10.2 ブロック要素とインライン要素の違い

<div> と <span> の使い分けは、実は HTML のすべての要素に共通する、もっと大きな分類の一部です。HTML要素は表示のされ方によって、大きくブロック要素とインライン要素の2種類に分けられます。

ブロック要素

横幅いっぱいに広がり、前後で必ず改行される。代表例：div・p・h1〜h6・ul・table・form・section

インライン要素

文章の途中に、中身の幅だけ入り込む。改行はされない。代表例：span・a・strong・em・code・label

言葉だけだと分かりにくいので、実際に箱として並べたイメージを見てみましょう。ブロック要素は積み木のように縦に積み上がり、インライン要素は文章の流れの中に、必要な分だけの幅で収まります。

配置イメージ（ワイヤーフレーム）

ブロック要素1（div・p など） — 横幅いっぱい・前後で改行
ブロック要素2（div・p など） — 上の要素の下に積み上がる span 1 のように文中に span 2 インライン要素が混ざることもできる

もう1点、実務でつまずきやすいポイントがあります。インライン要素には width（幅）や上下の margin（余白）を CSS で指定しても効かないという制約があります。これは第11章で CSS を学ぶときに関わってくる話なので、「ブロックは箱、インラインは文字の一部」という感覚だけ、ここで持っておいてください。

見分け方のコツ

迷ったら「この要素だけで改行されて縦に並ぶか」を考えてみましょう。改行されるならブロック要素、文章の途中に入り込むならインライン要素です。<div> はブロック要素、<span> はインライン要素という対応も、あわせて覚えておくと便利です。

10.3 class・id 属性の使い分け

<div> や <span>（に限らずすべての要素）に「名前」を付けて、CSS や JavaScript から狙い撃ちできるようにする属性が class と id です。似ているようで役割がまったく違うので、ここで整理しておきましょう。

項目 class id
1ページ内での重複 何度でも使える（複数の要素に同じ名前を付けてよい） ページ内で一度だけ（重複は禁止）
1要素に付けられる数 複数OK（半角スペース区切り） 1つだけ
主な用途 共通のデザインパターンを、複数の要素に繰り返し適用する ページ内リンクの飛び先や、JavaScript から特定できる「その1つだけの要素」を指定する
CSSでの書き方 .card { }（ドット） #header { }（シャープ）
index.html 
<!-- class: 同じ見た目を繰り返し使う（複数OK） -->
<div class="card">商品A</div>
<div class="card">商品B</div>
<div class="card highlight">商品C（強調）</div>

<!-- id: ページ内でただ1つの要素を特定する -->
<section id="contact">
  <h2>お問い合わせ</h2>
</section>
<a href="#contact">お問い合わせへ移動</a>

第6章で学んだ「ページ内リンク（<a href="#id名">）」は、まさに id の「一意に特定できる」という性質を利用した機能でした。class 名は product-card のようにケバブケース（小文字とハイフン）で付けるのが一般的です。

重要ポイント

迷ったらまず class を使いましょう。「この要素はページに1つしかなく、それをピンポイントで指し示したい」という明確な理由があるときだけ id を使う、という順番で考えると失敗しません。

10.4 セマンティック要素でページ全体を組み立てる

10.1節で「<div> は最後の手段」と説明しました。実は多くのWebページでは、ページ全体を構成する大きなブロック（ヘッダー・ナビゲーション・本文・footer など）にも、それぞれ意味を持ったタグが用意されています。これらをセマンティック要素（semantic＝意味論的な）と呼びます。

タグ 意味・用途
<header> ページ（または記事・セクション）の導入部分。ロゴ・サイト名・見出しなどをまとめる
<nav> 主要なナビゲーション（メニューリンクの集まり）
<main> そのページ固有のメインコンテンツ。1ページに1つだけ
<section> 見出しを持つ、テーマのまとまり（章・話題の区切り）
<article> それ単体で完結し、他の場所へ再利用・配信できるコンテンツ（記事・投稿・カード）
<aside> 本題から少し外れた補足情報（サイドバー・広告・関連リンク）
<footer> ページ（または記事・セクション）の締めくくり。著作権表示・関連リンクなど

これらのタグを組み合わせて、典型的なブログページの骨組みを組み立てると、次のようなワイヤーフレーム（配置図）になります。図では分かりやすさのため枠線付きの箱で表現していますが、それぞれの箱の位置に対応するタグ名を添えています。

ページレイアウトのワイヤーフレーム

header（サイトロゴ・サイト名）
nav（メインメニュー）

main（このページ固有のメインコンテンツ）

section（トピック1のまとまり）
article（記事その1）
aside（関連記事・広告など補足情報）
footer（著作権表示・お問い合わせ）

この配置を実際の HTML で書くと、次のようになります。<div> がほとんど登場せず、それぞれのタグ名を見ただけで「ここは何のためのブロックか」が一目で分かることに注目してください。

index.html（body抜粋・上部） 
<header>
  <h1>わたしのブログ</h1>
</header>

<nav>
  <ul>
    <li><a href="#">ホーム</a></li>
    <li><a href="#">記事一覧</a></li>
  </ul>
</nav>
index.html（body抜粋・下部） 
<main>
  <article>
    <h2>HTML学習3日目</h2>
    <p>今日はセマンティック要素を学びました。</p>
  </article>
</main>

<aside>
  <h2>関連記事</h2>
</aside>

<footer>
  <p>&copy; 2026 わたしのブログ</p>
</footer>

<section> と <article> は特に混同しやすいので、判断基準を1つ覚えておきましょう。「その部分だけを切り出して、単独で意味が通じる（他のサイトに配信しても成立する）か」を自問してください。YESなら article（ブログ記事・ニュース1本・商品カード1枚など）、NOなら section（ページの中の「特徴」「料金」といった話題のまとまり）です。<header> と <footer> は、ページ全体だけでなく <article> や <section> の中に入れて、記事ごとの見出し・投稿者情報などに使うこともできます（1ページに複数あってもかまいません）。

豆知識: これらもレイアウトを決めるタグではない

セマンティック要素はどれもデフォルトではブロック要素として表示されるだけで、色・余白・横並びといった見た目は付いていません。<nav> を書いただけで自動的にメニューバーの見た目になるわけではなく、実際のレイアウト（横並びにする、背景色を付けるなど）は第11章で学ぶ CSS の仕事です。

10.5 セマンティックにするメリットと見出しレベルとの関係

「タグを変えても画面の見た目はほとんど変わらないのに、なぜわざわざ使い分けるのか」と疑問に思うかもしれません。セマンティックHTMLには、見た目には出てこない3つの大きなメリットがあります。

読みやすさ

コードを見ただけで「ここはナビゲーション」「ここは補足」と構造が分かる。共同開発や半年後の自分にとって、保守しやすいコードになる。

SEO

検索エンジンのクローラーが <main>・<article> を「ページの本題」と判断しやすくなり、検索結果での評価に有利に働く。

スクリーンリーダー対応

視覚に障害のある方が使う読み上げソフトが、<nav>・<main> を「ランドマーク」として認識し、目的の場所へ一気にジャンプできる。

3つ目の「スクリーンリーダー対応」は、アクセシビリティ（accessibility＝利用しやすさ）と呼ばれる分野の一部です。目の見える人が視覚的に「あ、これはメニューだ」とひと目で判断しているのと同じ情報を、セマンティック要素はプログラムにも伝えることができます。<div> ばかりで組んだページでは、この情報がすべて失われてしまいます。

flowchart TD A["body"] --> B["header（ページの導入）"] A --> C["nav（メインナビゲーション）"] A --> D["main（このページ固有の本題・1ページに1つ）"] D --> E["section（トピックのまとまり）"] D --> F["article（単体で完結する記事）"] A --> G["aside（補足情報）"] A --> H["footer（締めくくり）"]

セマンティック要素は、第4章で学んだ見出しレベル（<h1>〜<h6>）とも深く関係しています。<section> や <article> は、原則としてそれぞれ見出し（<h2> など）を1つ持つという前提で設計されています。ページ全体の <h1> を頂点に、各セクションの見出しが <h2>、その中の話題がさらに <h3>…という具合に、タグの入れ子構造と見出しレベルの深さが対応しているのが、正しく整理された文書の姿です。スクリーンリーダーの利用者は、この見出しレベルを一覧表示して目次のように読み上げ順序を選ぶこともできるため、<h1> を複数置くことや、レベルを飛ばすことは情報構造を壊してしまいます。

10.6 よくある誤用

セマンティックHTMLは「使えば使うほど良い」というものではなく、間違った使い方をするとかえって意味を誤解させてしまいます。特に初心者がやりがちな誤用を4つ紹介します。

  • div疲労（divスープ） — ページ全体を <div> ばかりで組んでしまう。<header> や <main> で表現できる箇所は、まずそちらを検討しましょう。
  • <main> を複数使う、または使わない — <main> は1ページに1つだけという決まりがあります。複数の候補（本文とサイドバーの両方など）に付けてしまうと、スクリーンリーダーが「本題はどこ？」と迷ってしまいます。
  • 見出しのない <section> — <section> は「見出しを持つ話題のまとまり」が前提です。見出しを付けられない、単なるデザイン上のグループ化なら <div> の方が適切です。
  • 見た目だけを理由にしたタグ選び — 「大きく太い文字にしたいから見出しタグにする」「枠で囲みたいから <article> にする」のように、見た目を理由にタグを選んでしまう。タグの選択理由は常に「意味」であるべきで、見た目は CSS（第11章）で整えます。

なお、<header> と <footer> は「1ページに1つだけ」という制限がありません。ページ全体用に1つ、さらに各 <article> の中にそれぞれ1つずつ、という使い方も正しい使い方です。「main だけが特別に1つ限定」という点を、混同しないようにしましょう。

よくある勘違い

セマンティック要素を使えば「自動的にアクセシブルになる」わけではありません。あくまでブラウザや支援技術に正しい情報を渡すための土台であり、そのうえで適切な alt 属性（第7章）や label と for の対応（第9章）などを積み重ねて、はじめて使いやすいページになります。

やってみよう 10-1: divだらけのページをセマンティックに書き換えよう

これまでの章で作ったファイルの1つを見直して、セマンティック要素へ置き換える練習をしましょう。

手順

  1. 1 エディタで新しいファイル semantic.html を作成し、これまでどおり <!DOCTYPE html> から書き始める。
  2. 2 <body> の中に、10.4節のコード例を参考にして <header>・<nav>・<main>・<footer> の骨組みを書く。
  3. 3 <main> の中に <article> を1つ置き、自己紹介の見出し（<h2>）と段落（<p>）を入れる。
  4. 4 保存してブラウザで開き、表示は素っ気ないままで良いことを確認する。次にブラウザの「ページのソースを表示」を開き、タグ名だけでどこが何のブロックか判別できるか自分で確かめる。

見た目がほとんど変わらなくても失敗ではありません。セマンティック要素の効果は「見た目」ではなく「意味」に現れる、ということを体感するのがこの実習の目的です。

理解度確認クイズ

  1. Q1. <div> と <span> はそれぞれどのような場面で使うタグですか。ブロック要素・インライン要素という言葉を使って説明してください。

    回答を表示

    <div> は意味を持たないブロック要素で、複数の要素をひとつの箱としてまとめるときに使います。<span> は意味を持たないインライン要素で、文章の一部分だけをまとめるときに使います。どちらも、意味のあるタグで表現できない場合の最後の手段として使います。

  2. Q2. class 属性と id 属性の違いを、1ページ内での重複可否の観点から説明してください。

    回答を表示

    class は1ページ内で何度でも使え、1つの要素に複数付けることもできます。共通のデザインパターンを繰り返し適用する用途に向いています。一方 id はページ内でただ1つの要素にしか付けられず、ページ内リンクの飛び先や JavaScript でその要素だけを特定したいときに使います。

  3. Q3. <main>・<section>・<article> の使い分けを、それぞれの役割にふれながら説明してください。

    回答を表示

    <main> はそのページ固有のメインコンテンツで、1ページに1つだけ使います。<section> は見出しを持つ話題のまとまりで、ページの中の話題ごとの区切りに使います。<article> はそれ単体で意味が通じ、他の場所にも配信できるような完結したコンテンツ（記事・投稿など）に使います。

  4. Q4. セマンティックHTMLにするメリットを2つ以上挙げ、よくある誤用の例を1つ挙げてください。

    回答を表示

    メリット例：コードが読みやすくなる（保守性の向上）、検索エンジンがページの本題を理解しやすくなる（SEO）、スクリーンリーダー利用者がランドマークとして各ブロックへジャンプできる（アクセシビリティ）。よくある誤用例：ページ全体を <div> ばかりで組む「divスープ」、<main> を複数使ってしまう、見出しのない <section> を使う、見た目だけを理由にタグを選ぶ、など。
