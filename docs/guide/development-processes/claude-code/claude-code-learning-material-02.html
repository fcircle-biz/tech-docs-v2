ホーム Claude Code 第2章
第2章 所要時間: 約40分

Claude Codeの仕組み

Claude Code は、一般的なチャット型 AI とは異なる仕組みで動いています。この章では、その内側にある「エージェントループ」「コンテキストウィンドウ」「ツール」「許可（パーミッション）」という4つの概念を1つずつ分解し、Claude Code が実際にどう考え、どう動いているのかを理解します。仕組みを知ることが、次章以降を安心して進めるための土台になります。

この章で学ぶこと

  • Claude Code の中核である「エージェントループ」の5つのステップを説明できる
  • ループの実行中はいつでも介入（コンテキスト追加・割り込み・方向修正）できることを理解する
  • 「コンテキストウィンドウ」が何を保持し、上限に達すると何が起きるかを理解する
  • 「ツール」がエージェントの行動を支える仕組みであることを理解する
  • 許可（パーミッション）の3つのモードの違いを説明できる

2.1 エージェントループ

第1章では、「LLM ＋ ツール ＋ ループ ＝ エージェント」という式を紹介しました。Claude Code は、この「ループ」をエージェントループ（agentic loop）という5つのステップに分解して実行しています。まずは全体の流れを図で見てみましょう。

flowchart TD S1(["① プロンプト入力
あなたが依頼を伝える"]) --> S2 S2["② コンテキスト収集
モデルとやり取りして必要な情報を集める"] S2 -->|"ツール呼び出しが返る"| S3["③ 行動
ファイル編集・コマンド実行など"] S2 -->|"テキストのみが返る"| S4 S3 --> S4{"④ 結果を検証
要求を達成できたか？"} S4 -->|"未達成（ループを継続）"| S2 S4 -->|"達成"| S5(["⑤ 完了
次のプロンプトを待つ"]) U(["あなた"]) -.->|"割り込み・方向修正・
コンテキスト追加（いつでも可能）"| S2 U -.->|"いつでも介入できる"| S3 U -.->|"いつでも介入できる"| S4

図の①〜⑤を、もう少し詳しく見ていきます。

ステップ 内容
① プロンプト入力 あなたが Claude Code に依頼を伝える。
② コンテキスト収集 モデルとやり取りしながら必要な情報を集める。モデルはテキスト、または Claude Code が実行できるツール呼び出しのどちらかを返す。
③ 行動 ツール呼び出しを受けて、ファイルの編集やコマンドの実行など、実際の作業を行う。
④ 結果を検証 行動の結果を確認し、プロンプトで求められたことを達成できているかを判断する。
⑤ 完了 or ループ 達成していれば処理を終えて次のプロンプトを待つ。達成していなければ②に戻り、結果が完全かつ検証可能になるまで繰り返す。

実際の画面では、これらのステップが次のように進んでいきます。

terminal — エージェントループの実例 
$ claude
> ユーザー認証のテストが1件失敗しています。原因を調べて直してください。

● ①依頼を受け取りました。まず状況を確認します。
● ②tests/auth.test.ts と session.ts を読み込んでいます…
● ③トークンの有効期限チェックの条件式を修正しました。
● ④npm test を実行しました（13件中13件が成功）。
● ⑤修正が完了しました。次の指示をお待ちしています。

重要ポイント

④の「結果を検証」が必ず挟まる点が本質です。Claude Code はただ行動するだけでなく、自分の行動結果を確認してから次に進むため、チャット型のAIにはない自己修正力を持っています。

2.2 ループへの介入

エージェントループは「依頼したらあとは待つだけ」の一方通行ではありません。ループが回っているあいだ、あなたは次の3つの方法でいつでもループに関わり、目標へと導くことができます。

コンテキストを追加する

作業の途中で「実はこの制約もある」といった情報を、追加でそのまま伝えられます。

割り込む

違う方向に進み始めていると感じたら、完了を待たずにその場で処理を止められます。

方向修正する

プランや実装の方針を、完了を待たずにその場で軌道修正できます。

本ガイドの進め方

具体的な操作方法（Esc キーでの割り込みなど）は第4章で実際に試します。ここでは「ループの最中はいつでも介入できる」という性質を覚えておいてください。

重要ポイント

この「介入できる」性質こそが、Claude Code を安心して使うための鍵です。第1章の心構え「Claude Code は許可を求める」で触れた「常に主導権はあなたにある」という考え方は、このループへの介入によって支えられています。

2.3 コンテキストウィンドウ

エージェントループが回るあいだ、Claude はやり取りした内容をすべて無制限に記憶しているわけではありません。保持できる範囲には上限があり、それをコンテキストウィンドウと呼びます。

会話、ファイルの内容、コマンドの出力など、Claude がどれだけの情報を保持・参照できるかを決める領域

第1章 1.6 では、これを「Claude の作業記憶（ワーキングメモリ）」と表現しました。まさにこれのことです。おもに次の3つがこの領域を消費します。

会話

これまでのやり取り（あなたの指示と Claude の応答）。

ファイルの内容

読み込んだソースコードやドキュメントの中身。

コマンドの出力

テストの実行やビルドなど、コマンドの実行結果。

コンテキストウィンドウが上限に達すると、Claude Code は会話を圧縮（コンパクト化）します。削除してよい部分・要約すればよい部分を自動的に判断し、扱いやすいサイズまで縮小してから作業を続けます。

本ガイドの進め方

自動圧縮は便利な仕組みですが、要約の過程で細かい情報が失われることもあります。/compact や /clear といった自分で管理するコマンドとあわせて、第7章で詳しく学びます。

2.4 ツール

ツールは、エージェントが実際に動作するための土台です。多くのAIアシスタントは、テキストを受け取ってテキストを返すだけです。Claude Code はツールを持っているからこそ、目的の達成に近づくために「いつ」実行するかを、意味的な理解にもとづいて自分で判断できます。

ツールの種類 何をするか
ファイル読み取り コードベース内のファイルを検索し、内容を読み込む。
ファイル編集 ファイルの内容を書き換える。
コマンド実行（Bash） テストの実行・ビルド・パッケージのインストールなどを行う。
Web検索 最新のドキュメントや情報をインターネットで調べる。

1回のツール呼び出しの中では、実際には次のようなやり取りが行われています。

2.5 許可（パーミッション）の3つのモード

Claude Code がファイルを編集したり、シェルコマンドを実行したりする前に、どこまで確認を挟むかは、次の3つのモードから選べます。

モード ファイルの編集 コマンドの実行
承認モード（既定） 実行前に明示的な許可を求める 実行前に明示的な許可を求める
自動承認モード 確認なしで自動的に編集される 引き続き許可を求める
プランモード 行わない（読み取り専用ツールのみ使用） ファイルを変更するコマンドは実行しない（ls や git log のような読み取り専用の確認コマンドは使われることがある）

プランモードは読み取り専用のツールだけを使い、作業に取りかかる前にまず行動計画を組み立てるためのモードです。ファイルの編集は行わず、ファイルを変更するコマンドの実行も行いません（ls や git log のような読み取り専用の確認コマンドが使われることはあります）。

注意: 確認をすべてスキップする設定もある

設定次第では、確認そのものをすべて省略することもできます。しかし慣れないうちは避けてください。Claude Code にコマンド実行の自由を大きく与えるほど、間違いが実際に起きる前に気づくのが難しくなります。第1章の心構え「Claude Code は間違えることもある」のとおり、要所で確認を挟む姿勢が安全に使いこなす基本です。

本ガイドの進め方

実際にモードを切り替える操作（Shift + Tab）や、それぞれの使いどころは第4章で実践します。プランモードは第5・6章の探索と計画のフェーズでも中心的な役割を果たします。

やってみよう 2-1: エージェントループと許可モードを自分ごとに置き換える

この章で学んだ概念を、まだ Claude Code を使わずに紙の上で整理してみましょう。実際に手を動かすのは次章以降です。

手順

  1. 1 直近で自分が行った小さな修正作業を1つ思い出し、①プロンプト入力〜⑤完了の5ステップに当てはめて書き出してみる。
  2. 2 その作業を Claude Code に任せるとしたら、2.5 の3つのモードのどれを選ぶか、理由も添えて考える。
  3. 3 作業の途中で「割り込み・方向修正・コンテキスト追加」をしたくなりそうな場面がどこかを予想し、メモしておく。

理解度確認クイズ

  1. Q1. エージェントループの④で「要求を達成できていない」と判断された場合、処理はどこに戻りますか。また、それはなぜですか。

    回答を表示

    ②の「コンテキスト収集」に戻ります。検証結果を踏まえて再びモデルとやり取りし、状況に応じたテキストまたはツール呼び出しを新たに得る必要があるためです。これを、結果が完全かつ検証可能になるまで繰り返します。

  2. Q2. コンテキストウィンドウが上限に達すると何が起こりますか。

    回答を表示

    Claude Code が会話を自動的に圧縮（コンパクト化）します。削除してよい部分や要約すればよい部分を自動的に判断し、コンテキストウィンドウを扱いやすいサイズまで縮小してから作業を続けます。

  3. Q3. 許可の3つのモード（承認モード・自動承認モード・プランモード）の違いを説明してください。

    回答を表示

    承認モード（既定）はファイル編集・コマンド実行のどちらも事前に明示的な許可を求めます。自動承認モードはファイル編集を確認なしで行いますが、コマンド実行には引き続き許可が必要です。プランモードは読み取り専用のツールのみを使い、ファイルの編集は行わず、ファイルを変更するコマンドの実行も行わずに作業前の計画を立てます（ls のような読み取り専用の確認コマンドが使われることはあります）。
