第9章 所要時間: 約45分

サブエージェント

Claude Code は、コードベースの探索や調査のような作業を「サブエージェント」に任せることができます。サブエージェントはメインの会話とは別の、独立したコンテキストウィンドウの中で動作し、完了すると要約だけをメインエージェントに返します。この章では、サブエージェントの仕組みを理解し、/agents コマンドで自分専用のサブエージェントを作成・カスタマイズする方法を学びます。

この章で学ぶこと

  • サブエージェントとは何か、メインエージェントとどう違うのかを理解する
  • サブエージェントがコンテキストウィンドウの消費を抑える仕組みを説明できる
  • サブエージェントの定義ファイル（YAMLフロントマター付きMarkdown）の書き方を理解する
  • /agents コマンドで自分用のサブエージェントを作成できる
  • 永続的なメモリと skill キーによるカスタマイズ方法、その注意点を知る

9.1 サブエージェントとは

Claude Code は、タスクをサブエージェントに委任し、タスクを細かく分割して並行して実行させることができます。呼び出す側の会話をメインエージェントと呼ぶと、サブエージェントはメインエージェントとは別に動作する、もう1つの Claude です。その働きは、次のようにまとめられます。

サブエージェントは、タスクを細かく分割して並行して実行するために生成される。それぞれのサブエージェントは、独立したコンテキストウィンドウの中で動作する。

ここでいう「独立したコンテキストウィンドウ」が、本章でいちばん大事なポイントです。メインエージェントが今取り組んでいる主タスクの記憶と、サブエージェントが探索のために読み込んだ大量のファイルやコマンド出力の記憶は、まったく別の場所に置かれます。次の図のように、両者は完全に切り離されています。

flowchart LR subgraph MAIN["メインエージェント（主タスクのコンテキスト）"] U["あなた"] -->|"依頼する"| CC["Claude Code"] end subgraph SUB["サブエージェント（別のコンテキストウィンドウ）"] TASK["探索タスクを実行
（ファイル検索・Web検索など）"] RESULT["大量のツール呼び出し結果"] TASK --> RESULT end CC -->|"タスクを委任する"| TASK RESULT -->|"要約だけを返す"| CC

サブエージェントが作業を終えると、調べた内容を要約だけメインエージェントに返します。探索の途中で読み込んだファイルの中身やコマンドの出力そのものは、サブエージェント側のコンテキストウィンドウに残ったままで、メインエージェントには渡りません。

重要ポイント

サブエージェント＝別のコンテキストウィンドウ＋要約だけを返す。この2点さえ押さえておけば、以降の内容はすべて「この性質をどう活用するか」の話になります。

9.2 なぜサブエージェントが必要か

第7章で見たとおり、コンテキストウィンドウの多くは、コードベースを探索するツール呼び出しや、調べもののための Web 検索によって消費されます。厄介なのは、そうした探索の過程で見つかった内容が、必ずしも今取り組んでいる主タスクに関係があるとは限らないという点です。

たとえば「認証のエンドポイントはどこにありますか」と尋ねたとき、Claude はいくつものファイルを開き、キーワードを検索し、関連しそうなコードを何度も読み込むかもしれません。あなたが本当に知りたいのは「どこにあるか」という一文の答えだけなのに、そこにたどり着くまでの試行錯誤がすべてメインのコンテキストウィンドウに積み上がってしまいます。

観点 サブエージェントを使わない場合 サブエージェントを使う場合
探索のツール呼び出し・Web検索 メインのコンテキストウィンドウに直接積み上がる 別のコンテキストウィンドウで実行される
探索過程の細かいログ すべてメインの記憶に残り続ける 要約だけが返り、メインはきれいなまま
向いている場面 探索の過程そのものも参照したい場合 結果さえ分かればよいタスク（第7章 節約のコツ③）

サブエージェントを使えば、この探索過程をまるごとメインのコンテキストウィンドウの外に追い出せます。結果さえ分かればよいタスクであれば、サブエージェントとの相性は抜群です。

9.3 動作イメージ：ファンアウトで並行実行する

サブエージェントの真価は、複数のタスクを同時に任せられるところにあります。たとえば大きな機能を実装する前に、「認証まわりの実装を調べて」「DBのスキーマを調べて」「関連するテストの有無を調べて」という3つの調査を、それぞれ別のサブエージェントに同時に投げることができます。これをファンアウト（fan-out）と呼びます。

それぞれのサブエージェントは独立したコンテキストウィンドウで並行して動作するため、探索の量が増えても、メインエージェントのコンテキストが圧迫されることはありません。3つの調査が終わると、それぞれの要約だけがメインエージェントに集まります。

flowchart TD CC["メインエージェント"] -->|"タスクA"| S1["サブエージェント1
認証まわりを調査"] CC -->|"タスクB"| S2["サブエージェント2
DB設計を調査"] CC -->|"タスクC"| S3["サブエージェント3
テスト状況を調査"] S1 -->|"要約"| M["メインエージェント
（3つの要約を統合）"] S2 -->|"要約"| M S3 -->|"要約"| M

メインエージェントは、3つの要約を踏まえて次の判断（設計・実装など）に進めます。探索そのものに使った大量のツール呼び出しは、どのサブエージェントのコンテキストウィンドウにも残ったままで、メインの記憶を煩雑にすることはありません。

9.4 定義の形式

サブエージェントは、YAML フロントマターを含む Markdown ファイルとして定義されます。配置場所は、プロジェクト直下の .claude/agents/ ディレクトリです。第8章で見た CLAUDE.md の2階層と同じく、~/.claude/agents/ というユーザーレベルの配置場所もあり、自分のすべてのプロジェクトで共通して使いたいサブエージェントはこちらに置けます。

配置場所 適用範囲
.claude/agents/ プロジェクトレベル。チームで共有する
~/.claude/agents/ ユーザーレベル。自分のすべてのプロジェクトで使える

サブエージェント定義ファイルの配置場所（プロジェクトレベルの例） 

.claude/
└── agents/
    ├── code-reviewer.md
    └── explore.md

各ファイルの先頭には、--- で挟んだ YAML フロントマターを書きます。主なキーは次のとおりです。

キー 役割
name サブエージェントの識別名
description どんな時に呼び出すかの説明。Claude がこれを読んで自動的に判断する
tools 利用できるツールを制限する（例: Read, Grep, Glob）
model 使用するモデルを指定する（例: sonnet）

フロントマターより下の本文には、そのサブエージェント専用のシステムプロンプトを書きます。役割・確認してほしい観点・出力形式などを具体的に書くほど、期待どおりに動いてくれます。実際の定義例を見てみましょう。

.claude/agents/code-reviewer.md 
---
name: code-reviewer
description: 実装が完了しコミット前のタイミングで、変更内容をレビューする専門サブエージェント。
tools: Read, Grep, Glob
model: sonnet
---

あなたは経験豊富なシニアエンジニアです。渡された変更内容を、
まっさらな視点でレビューしてください。

確認する観点:
- 命名・可読性などのコードスタイル
- バグや例外処理の考慮漏れ
- 既存コードとの一貫性

指摘は「重要度: 内容」の形式で簡潔にまとめてください。
自分でファイルを編集しようとしないでください。

この例では、tools を Read, Grep, Glob という読み取り専用のツールだけに絞っています。レビュー担当のサブエージェントは指摘するだけで、ファイルを書き換えるべきではないからです。この考え方は第10章で改めて詳しく扱います。

9.5 /agents で作る

サブエージェントを一から手書きすることもできますが、まずは Claude に生成してもらうのがいちばん簡単です。ターミナルで Claude Code を起動し、次のコマンドを実行してください。

terminal — Claude Code セッション例 
> /agents

● サブエージェントの一覧と管理メニューを表示しています…
● メニューから「Create new agent」を選択してください。

/agents コマンドでサブエージェントを作る手順

  1. 1 ターミナルで /agents を実行し、表示されたメニューから「Create new agent」を選択する
  2. 2 適用範囲を選ぶ（このプロジェクトだけで使うか、すべてのプロジェクトで共通に使うか）
  3. 3 目的を自分の言葉で伝える（どんな役割を担うサブエージェントかを自然文で説明する）
  4. 4 利用できるツールを選択する（読み取り専用に絞るなど、目的に応じて権限を制限できる）
  5. 5 表示色を指定する（ターミナル上でどのサブエージェントが動作しているか一目で分かるようにする）

ポイント: 説明文がそのまま呼び出しの判断材料になる

この手順を進めると、Claude がサブエージェントの名前・説明・システムプロンプトを生成してくれます。ステップ3で伝えた目的の説明は、そのまま description になり、あなたが以降の会話で出す依頼の内容に応じて、Claude がいつそのサブエージェントを呼び出すべきかを自動的に判断する材料になります。

9.6 さらにカスタマイズする

作成したサブエージェントは、次の2つの方法でさらに細かくカスタマイズできます。

永続的なメモリ

会話をまたいでサブエージェントに記憶を保持させます。同じプロジェクトで継続的にそのサブエージェントを使う場合に特に便利です。

skill キーによる事前読み込み

frontmatterに skill キーを追加し、スキル名を列挙することで、起動時にそのスキルを読み込ませます。

注意: skill キーはスキルの内容全体を読み込む

メインの会話で使うスキルは、まず名前と説明だけがコンテキストに読み込まれ、必要だと判断されたときに初めて全内容が読み込まれます（詳しくは第11章）。一方、サブエージェントの skill キーで指定した場合は、これとは異なり、起動時にスキルの内容全体が最初からコンテキストに読み込まれます。多用するとサブエージェント側のコンテキストを圧迫するため、本当に必要なスキルだけを指定しましょう。

スキル（Agent Skills）について

ここで登場した「スキル」自体の作り方や仕様は、本ガイドの範囲外です。詳しくは別ガイド「Claude Skills 入門」で学びます。なお、skill のような設定キーの名称や書き方は、今後変わる可能性があります。最新の情報は公式ドキュメントで確認してください。

9.7 コンテキスト管理との関係（第7章の実践）

ここまで見てきたサブエージェントの仕組みは、第7章「コンテキスト管理」で紹介したコンテキストの容量を節約する3つのコツのうち、③の実践そのものです。

第7章とのつながり

第7章の節約のコツ③「サブエージェントを使う」は、まさに本章の内容です。結果さえ分かればよいタスク（例:「認証のエンドポイントはどこにあるか」）は、サブエージェントに任せることで、探索の過程を丸ごとメインのコンテキストの外に追い出せます。

コンテキストウィンドウをきれいな状態に保つことは、Claude Code で生産性を維持するための最も効果的な方法のひとつです。サブエージェントは、そのための強力な道具です。次章では、この仕組みを使って、コミット前にコードレビューを行う実践的な使い方を学びます。

やってみよう 9-1: 自分専用のサブエージェントを作ってみる

実際に /agents を使って、自分のプロジェクト用のサブエージェントを1つ作ってみましょう。

手順

  1. 1 ターミナルで Claude Code を起動し、/agents を実行して「Create new agent」を選ぶ。
  2. 2 適用範囲を「このプロジェクトのみ」にし、目的として「READMEやコメントの誤字脱字だけを確認する校正担当」のように、具体的な役割を1文で伝える。
  3. 3 生成された .claude/agents/ 配下のファイルを開き、フロントマターの name・description・tools・model と、本文のシステムプロンプトを確認する。
  4. 4 メインの会話でそのサブエージェントを使う依頼をしてみて、動作している間もメインの会話が汚れないことを確認する。

理解度確認クイズ

  1. Q1. サブエージェントとメインエージェントの最大の違いは何ですか？

    回答を表示

    サブエージェントは、メインエージェントとは別の独立したコンテキストウィンドウの中で動作します。メインエージェントと並行して探索などの作業を行い、完了すると調べた内容を要約だけメインエージェントに返します。探索の過程で消費した大量のコンテキストはサブエージェント側に残り、メインエージェントには影響しません。

  2. Q2. サブエージェントはどのような形式のファイルとして定義され、どこに配置しますか？

    回答を表示

    YAMLフロントマターを含むMarkdownファイルとして定義し、.claude/agents/ ディレクトリに配置します。フロントマターには name・description・tools・model などのキーを書き、本文にはそのサブエージェント専用のシステムプロンプトを書きます。

  3. Q3. サブエージェントの skill キーでスキルを事前読み込みする際に、注意すべき点は何ですか？

    回答を表示

    メインの会話で使うスキルは名前と説明だけが先にコンテキストへ読み込まれ、必要になった時点で全内容が読み込まれますが、サブエージェントの skill キーで指定した場合は、これとは異なり起動時にスキルの内容全体がコンテキストに読み込まれます。多用するとサブエージェント側のコンテキストを圧迫する点に注意が必要です。
