MCPで外部ツールとつなぐ

Claude Code が理解できるのは、あなたのコードベースの中身だけではありません。MCP（Model Context Protocol）を使うと、Linear のようなissue管理ツールや社内のデータベースなど、コードベースの外側にある情報や機能にもClaude Codeから手が届くようになります。この章では、MCPサーバーの仕組み・追加方法・スコープ、そして見落としがちな「コンテキストのコスト」までを学びます。

この章で学ぶこと

  • MCP（Model Context Protocol）が何を解決する仕組みかを理解する
  • HTTPサーバーとStdioサーバーの違いを説明できる
  • claude mcp add でサーバーを追加し、/mcp で管理できる
  • スコープ（Local／User／Project）を目的に応じて使い分けられる
  • コンテキストのコストを理解し、必要なサーバーだけを運用できる

11.1 MCPとは何か

Claude Code が理解できるのは、あなたのコードベースの中身だけではありません。MCP（Model Context Protocol）は、Claude Code を外部のツールやデータソースに接続するための仕組みです。

Claude Code を外部のツールやデータソースに接続するための、オープンな標準規格。あなたが何かを尋ねると、Claude はその質問により良く答えるために、いつどのツールを使うべきかを自動的に判断する。

第1章で「エージェント ＝ LLM ＋ ツール ＋ ループ」という式を学びました。ツールは、Claude Code のようなエージェントに、タスクをより効果的にこなすための「行動する力」を与えるものでした。MCPは、この「行動する力」の守備範囲を、あなたのコードベースの外側にまで広げるための仕組みです。

Claude Code は、ネットワーク経由でHTTPサーバーに接続したり、ローカルプロセスとしてStdioサーバーを起動したりして、これらの外部サービスとやり取りします。サーバーの種類については11.5で詳しく見ます。

11.2 MCPが解決する課題

Claude Code はコードベースの中身を深く理解できますが、あなたが実務で扱う情報の多くはコードベースの外側にあります。データベースの中身、Issue管理ツールやチャットツールのような業務アプリ、社外に公開されているリポジトリ――これらはコードを読むだけでは届きません。MCPは、この「コードベースの外側」とのギャップを埋めてくれます。

データベース

業務システムが持つデータの中身を、その場で参照する。

業務アプリ

Linearのissueやチャットの履歴など、チームの情報を取り込む。

公開ドキュメント

ライブラリの最新ドキュメントなど、公開されている情報を調べる。

11.3 具体例: Linear と Context7

実際にどんなことができるのか、2つの代表的なMCPサーバーで見てみましょう。

Linear

プロジェクト管理ツール Linear の MCP サーバーを追加すると、特定のissue（課題）の詳細情報をその場で取り込めます。「このissueの内容を踏まえて実装して」といった依頼ができるようになります。

Context7

ライブラリは頻繁にバージョンアップされ、Claude が知っている情報が古いこともあります。Context7 はライブラリの最新ドキュメントをその場で提供してくれるMCPサーバーです。

11.4 サーバーの追加と管理

MCPサーバーは claude mcp add コマンドで追加します。サーバーの種類（HTTP／Stdio）によって書式が少し異なります。

terminal — MCPサーバーの追加（HTTP） 
# HTTPサーバー（リモート）を追加する例: Linear
claude mcp add --transport http linear https://mcp.linear.app/mcp

# Context7も同様にHTTPサーバーとして追加する
claude mcp add --transport http context7 https://mcp.context7.com/mcp
terminal — MCPサーバーの追加（Stdio） 
# Stdioサーバー（ローカルプロセス）を追加する例
# "--" より後ろが、実際に起動するコマンドになる
claude mcp add my-local-server -- python3 server.py

注意: コマンドの書式は変わる可能性があります

オプションやURLは執筆時点の一例です。実際に追加する際は、対象サービスと claude mcp add の公式ドキュメントで最新の書式を必ず確認してください。

追加したサーバーは、セッション内で /mcp を実行すると管理できます。接続状況の確認・ツールの一覧表示・再接続・サーバーの無効化がその場で行えます。

terminal — /mcp の実行例 
> /mcp
● linear             HTTP    接続済み   ツール 6件
● context7           HTTP    接続済み   ツール 3件
● my-local-server    Stdio   切断      ツール 0件

  Enterキーで詳細を表示（ツール一覧の確認・再接続・無効化）

11.5 サーバーの種類: HTTP と Stdio

MCPサーバーには、大きく分けて2つの種類があります。

観点 HTTPサーバー Stdioサーバー
動作場所 リモート（提供元がホスト） あなたのマシン上のローカルプロセス
接続方法 ネットワーク経由 標準入出力（プロセスとして起動）
典型例 Linear・Context7 のようなクラウドサービス 自作スクリプト・社内限定のローカルツール
向いている場面 チームで同じクラウドサービスに接続したいとき 自分のマシンで完結する処理・機密性の高いデータ

11.6 サーバーのスコープ: Local・User・Project

MCPサーバーは、誰が・どの範囲で使えるかを3つのスコープで設定できます。

flowchart LR A["Local
このプロジェクト × 自分だけ"] -->|全プロジェクトに広げる| B["User
全プロジェクト × 自分だけ"] A -->|チームに共有する| C["Project
このプロジェクト × チーム全員
（.mcp.json をコミット）"]
スコープ 適用範囲 主な用途
Local 現在のプロジェクトで、自分だけ 個人的な試用・実験中のサーバー
User 自分のすべてのプロジェクト 個人でいつも使う共通サーバー
Project .mcp.json をバージョン管理に含め、チーム全員 チームで統一したいサーバー構成

Projectスコープは、プロジェクト直下の .mcp.json にサーバー定義を書き、それをバージョン管理にコミットすることで実現します。mcpServers キーの下に、サーバー名ごとの定義を並べます。

.mcp.json 
{
  "mcpServers": {
    "linear": {
      "type": "http",
      "url": "https://mcp.linear.app/mcp"
    },
    "my-local-server": {
      "command": "python3",
      "args": ["server.py"]
    }
  }
}

HTTPサーバーは type と url を、Stdioサーバーは起動する command と args を指定します。このキー構成もサービスやバージョンによって変わりうるため、実際に設定する際は公式ドキュメントを確認してください。

重要ポイント

チームに共有したいサーバーはProjectスコープ＋.mcp.jsonをコミット。逆にLocal／Userスコープの設定は個人環境向けの情報なので、通常はバージョン管理に含めません。

11.7 コンテキストのコスト

第7章で学んだとおり、コンテキストウィンドウには限りがあります。MCPサーバーは、この限られた資源を静かに消費し続ける存在でもあります。

注意: 使っていなくてもコンテキストを消費する

MCPサーバーは、実際に使っていないときでも、接続している限りツール定義をコンテキストウィンドウに常駐させ続けます。設定するサーバーが多いほど、使えるコンテキストは圧迫されます。

さらに、MCPのツールがコンテキストウィンドウの10%を超えると、Claude Codeは自動的に「ツール検索モード」に切り替わります。必要なツールをその都度探し出す仕組みですが、この状態では動作の信頼性がやや下がることがあります。

対策はシンプルです。/mcp で接続中のサーバーを確認し、実際に使っていないものは無効化しましょう。また、そのツールにCLI版（コマンドラインツール）があるなら、CLIの方が永続的なツール定義を追加しない分、コンテキスト効率が良くなります。

観点 MCPサーバー CLI（コマンドラインツール）
コンテキストへの常駐 接続している間、ツール定義が常に残る 常駐しない。呼び出したときだけ動く
準備 サーバーの起動・接続が必要 インストール済みならすぐ使える
代表例 Linear・Context7 などのMCPサーバー GitHubの gh、AWSの aws

重要ポイント

CLI版がある作業（GitHub操作ならgh、AWS操作ならawsなど）は、MCPサーバーを常駐させるより、その都度CLIを呼び出すほうがコンテキスト効率がよい、という判断基準を持っておきましょう。

11.8 コラム: スキル（Agent Skills）とは

MCPやCLI以外に、Claude Codeにはスキル（Agent Skills）という仕組みもあります。スキルは、名前と説明だけが常にコンテキストに読み込まれ、Claude が「このタスクには必要そうだ」と判断したときにだけ、内容全体を読み込みます。つまり、使わないスキルはコンテキストをほとんど消費しません。

種類 常時コンテキストに載るもの 全内容を読み込むタイミング
MCPサーバー 有効なサーバーの全ツール定義 常時（接続している間ずっと）
CLI なし 実行を指示したとき
スキル（Agent Skills） 名前と説明のみ Claude が必要と判断したとき

スキルの作り方は別ガイドで

スキルの定義方法（SKILL.md の書式など）は、本ガイドの対象外です。詳しくは別ガイド『Claude Skills 入門』で学びます。ここでは「名前と説明だけが常駐する、軽量な仕組み」ということだけ覚えておけば十分です。

やってみよう 11-1: MCPサーバーを棚卸ししてみる

実際にMCPサーバーを追加し、コンテキストのコストまで意識した一連の流れを体験してみましょう。

手順

  1. 1 自分のプロジェクトで claude を起動し、/mcp を実行して、現在接続されているMCPサーバーの一覧と状態を確認する（何も設定していなければ空でも構いません）。
  2. 2 11.4 の例を参考に、Context7 のようなHTTPサーバーを1つ追加してみる（URLや書式は必ず公式ドキュメントで最新のものを確認する）。
  3. 3 追加後、いま使っているライブラリについて「最新のAPIドキュメントを調べて」のように依頼し、Claude Codeがツールを呼び出す様子を観察する。
  4. 4 使い終えたら /mcp からそのサーバーを無効化し、コンテキストを整理する。11.7で学んだ「使っていないサーバーは無効化する」を実践する。

理解度確認クイズ

  1. Q1. HTTPサーバーとStdioサーバーの違いは何ですか？

    回答を表示

    HTTPサーバーはリモートのサービスで、提供元がホストしておりネットワーク経由で接続します。Stdioサーバーは自分のマシン上で動くローカルプロセスで、標準入出力を介して接続します。

  2. Q2. MCPサーバーのスコープ3種と、それぞれの適用範囲を説明してください。

    回答を表示

    Local（現在のプロジェクトで自分だけ）、User（自分のすべてのプロジェクト）、Project（.mcp.json をバージョン管理に含め、チーム全員が自動的に同じサーバーを使える）の3つです。

  3. Q3. MCPのツールがコンテキストウィンドウの10%を超えるとどうなりますか？また、CLI版があるツールについてはどう考えるべきですか？

    回答を表示

    自動的に「ツール検索モード」に切り替わり、必要なツールをその都度探し出すようになりますが、動作の信頼性がやや下がることがあります。CLI版（gh・aws など）がある場合は、MCPサーバーより常駐コストが低いCLIを使うほうがコンテキスト効率がよくなります。
