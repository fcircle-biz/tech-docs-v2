ホーム Claude Code 第14章
第14章 所要時間: 約35分

まとめと次のステップ

ここまで13章にわたって、Claude Code の考え方から日々の使いこなし方までを一つずつ積み上げてきました。最終章となるこの章では、全体像を1枚の表に整理し直し、明日から実践できる習慣とチームへ広げるロードマップを確認したうえで、次に学ぶべき道筋を示します。

この章で学ぶこと

  • 全13章の内容を「章・キーワード・覚えておくこと」の一覧で1枚に振り返られる
  • CLAUDE.md・サブエージェント・MCP が、いずれも「コンテキストの扱い方」の各論であることを説明できる
  • 明日から実践できる5つの習慣を挙げられる
  • 個人利用からチーム導入までのロードマップをイメージできる
  • 次に学ぶべきガイドや公式ドキュメントへの道筋を把握する

14.2 学びの背骨＝コンテキスト

本ガイドには、何度も繰り返し登場した言葉があります。それが「コンテキスト」です。第7章で学んだとおり、コンテキストウィンドウは Claude の作業記憶であり、無限ではありません。実は第8章の CLAUDE.md・第9章のサブエージェント・第11章の MCP は、一見バラバラな機能に見えて、すべて「コンテキストをどう扱うか」という同じ問いへの異なる答えにすぎません。

flowchart TD CTX["第7章: コンテキストウィンドウ
Claudeの作業記憶"] --> C8["第8章: CLAUDE.md
前提を外部ファイル化する"] CTX --> C9["第9章: サブエージェント
探索を別ウィンドウへ逃がす"] CTX --> C11["第11章: MCP
常駐するツール定義を管理する"] C8 --> GOAL["コンテキストを
正しく＆軽く保つ"] C9 --> GOAL C11 --> GOAL

それぞれの章が、コンテキストとどう関わっているかを整理すると次のとおりです。

章 コンテキストとの関わり方
第7章 コンテキスト管理 コンテキストウィンドウの仕組みそのものを学ぶ、すべての土台
第8章 CLAUDE.md 毎回のプロンプトに自動で追加される「前提」を外部ファイル化し、探索のやり直しを防ぐ
第9章 サブエージェント 探索やレビューを別のコンテキストウィンドウへ逃がし、メインには要約だけを残す
第11章 MCP 外部ツールの定義は、使わなくても常駐してコンテキストを消費する。必要なものだけを残す

重要ポイント

CLAUDE.md・サブエージェント・MCP の使い方に迷ったら、「これはコンテキストにとって良い選択か」と自問すると判断しやすくなります。本ガイドの縦串は、最初から最後まで一貫してこの1点でした。

14.3 明日から実践する習慣チェックリスト

知識を実践に落とし込むために、明日からのセッションで意識したい5つの習慣をまとめました。すべてを一度に完璧にこなす必要はありません。まずは1つ、今日から始めてみましょう。

① まずプランモードから始める

新しい依頼を出すときは、Shift + Tab でプランモードに切り替えてから話しかける。コードが実際に書かれる前に、計画の段階で確認・修正できる（第4・5章）。

② 機能の切れ目で /clear する

前の会話が新しい作業にバイアスをかけないよう、別の機能に着手するタイミングでコンテキストをリセットする。続きの作業なら /compact（第7章）。

③ CLAUDE.md を少しずつ育てる

同じ指摘を繰り返していると気づいたら、その場でルールを CLAUDE.md に保存するよう頼む。最初から完璧を目指さない（第8章）。

④ コミット前はサブエージェントにレビューさせる

読み取り専用に絞った code-reviewer サブエージェントに、プッシュ前の変更内容を確認してもらう。メインエージェントの先入観を引きずらない視点が得られる（第6・10章）。

⑤ 毎回必ず実行したいことはフックにする

「編集後は必ずフォーマットする」のような処理は、プロンプトに書くのではなくフックとして設定する。プロンプトは確率的、フックは決定的（第12章）。

14.4 チーム導入ロードマップ

Claude Code は一人で使う分にはすぐに始められますが、チームで力を発揮させるには段階を踏んだ導入が効果的です。次の5段階で、無理なく広げていきましょう。

プランモード・Explore→Plan→Code→Commit"] --> S2["ステップ2: CLAUDE.mdをコミット
プロジェクトの前提をチームで共有（第8章）"] S2 --> S3["ステップ3: サブエージェント定義をチェックイン
.claude/agents/ に配置する（第9・10章）"] S3 --> S4["ステップ4: .mcp.jsonをProjectスコープで共有

チーム全体の決定的な自動化を実現する（第12章）"]

最終段階まで導入が進むと、プロジェクトの構成はおおよそ次のようになります。

チーム導入が完了したプロジェクト構成の例 

myproject/
├── CLAUDE.md              ← 第8章: プロジェクトの前提
├── .claude/
│   ├── agents/            ← 第9・10章: サブエージェント定義
│   │   └── code-reviewer.md
│   └── settings.json      ← 第12章: チーム共有のフック設定

一足飛びに進めない

5段階を一度に導入しようとせず、各ステップがチームに定着してから次に進むと、抵抗が少なく浸透しやすくなります。まずはステップ1〜2から始めるのがおすすめです。

14.6 学習の振り返りクイズ（総合問題）

第1〜13章の内容を横断する、全5問の総合問題です。

  1. Q1. Claude Code が「agentic」であるとはどういうことですか。エージェントループの5ステップも含めて説明してください。

    回答を表示

    Claude Code は、目標を与えられると次に何をすべきかを自分で判断しながら作業を完了まで進める「エージェント」として動作します（第1章）。中核では LLM がループしており、①プロンプト入力 → ②モデルとやり取りしてコンテキストを収集する（テキストかツール呼び出しが返る）→ ③行動する（ファイル編集・コマンド実行）→ ④結果を検証する → ⑤目標を達成していれば終了、していなければ②へ戻る、という5ステップを繰り返します（第2章）。

  2. Q2. Claude Code を安全に使うために、「アクセスできる範囲」と「実行前の確認」にはそれぞれどのような仕組みがありますか。

    回答を表示

    アクセス範囲については、claude を実行したディレクトリと、そのすべてのサブフォルダに限定されます（第3章）。実行前の確認については、既定モードではファイルの変更やコマンド実行の前に必ず確認を求める仕組みがあり、承認モード・自動承認モード・プランモードを Shift + Tab で切り替えられます（第4章）。どちらも「AI に何でも好きにさせない」ための安全装置です。

  3. Q3. Explore → Plan → Code → Commit のワークフローで、コードを書く前にプランモードで計画を立てることには、どんなメリットがありますか。またコミット前にはどのような一手間を挟むとよいですか。

    回答を表示

    プランモードは読み取り専用ツールしか使わないため安全に分析・計画ができ、プラン提示の段階なら「承認・特定箇所の修正・質問」の3つの選択肢で軌道修正できます。コードが実際に書かれる前に方向性を正せるので、後からの手戻りが少なくなります（第5章）。またコミット前には、読み取り専用に権限を絞った code-reviewer サブエージェントにレビューさせるとよいでしょう。メインエージェントの先入観を引きずらない、まっさらな視点でのチェックが得られます（第6・10章）。

  4. Q4. コンテキストウィンドウを節約する3つの工夫を、CLAUDE.md・サブエージェント・MCP のどれと関わるかを含めて説明してください。

    回答を表示

    ①具体的に指示する（曖昧な指示はかえって探索範囲を広げ、長い目で見るとより多くのコンテキストを消費する）、②MCPサーバーを管理する（使っていないサーバーもツール定義が常駐するため、不要なら無効化する。第11章）、③サブエージェントを使う（探索やレビューを別のコンテキストウィンドウに任せ、メインには要約だけを受け取る。第9章）という3つです（第7章）。加えて、セッションをまたいで覚えておいてほしいことを CLAUDE.md に書いておくと、毎回同じ探索を繰り返さずに済みます（第8章）。

  5. Q5. Claude Code が同じ間違いを繰り返す場合、どのように対処すればよいですか。2段階で説明してください。

    回答を表示

    まず、そのルールを CLAUDE.md に保存するよう Claude Code に明示的に依頼します（第8章）。プロンプトでの指示はあくまで確率的で、「たいてい」は守られても「常に」ではありません。それでも繰り返される場合は、フックを使って決定的に強制します。例えば PreToolUse フックで危険な操作や規約違反のコマンドをブロックすれば、例外なく毎回防げます（第12章）。第13章のトラブルシューティングでも、この2段階の対処が案内されています。

全14章、修了おめでとうございます

Claude Code の考え方から、Explore → Plan → Code → Commit の実践ワークフロー、コンテキスト管理、CLAUDE.md・サブエージェント・MCP・フックによるカスタマイズまで、実務で使いこなすための土台はすべて身につきました。あとは実際に手を動かしながら、少しずつ自分のスタイルに育てていくだけです。ここまで学習を続けたあなたなら、きっとうまく使いこなせます。
