ホーム Claude Code 第8章
第8章 所要時間: 約45分

CLAUDE.mdでプロジェクトの記憶を作る

CLAUDE.md は、プロジェクトの情報を Claude Code に継続的に記憶させるための Markdown ファイルです。この章では、CLAUDE.md がどんな課題を解決し、どんな仕組みで働くのかを理解したうえで、自分のプロジェクト用に書き・育て・整理する方法を学びます。

この章で学ぶこと

  • CLAUDE.md がどんな課題を解決するのかを理解する
  • CLAUDE.md の内容がプロンプトに追加される仕組みを理解し、第7章のコンテキスト管理とのつながりを説明できる
  • プロジェクトレベルとユーザーレベルのメモリ階層の違いを説明できる
  • CLAUDE.md を書き育てるための3つのコツを実践できる
  • CLAUDE.md を肥大化させないための考え方を身につける

8.1 CLAUDE.md が解決する課題

第7章では、Claude Code のコンテキストウィンドウ（作業記憶）には限りがあり、セッションが長くなると自動的に圧縮が働くことを学びました。実はセッションをまたいだ記憶にも同じ課題があります。CLAUDE.md ファイルが無い状態で Claude Code を開くと、何が起きるでしょうか。

答えは「毎回まっさらな状態からスタートする」です。そのたびにコードベースを一から探索し直し、どんな依存関係が必要かを調べ、すでにどんな機能が実装されているのかを理解しなければなりません。時には Claude が誤った前提を置いてしまうこともあり、そうなると正しい方向へ導くのがより難しくなります。

CLAUDE.md が無い場合

  • セッションのたびにコードベースを一から探索し直す
  • 依存関係やコーディング規約をそのつど調べ直す
  • 誤った前提を置いてしまい、軌道修正に手間がかかることもある

CLAUDE.md がある場合

  • セッション開始時に自動的に読み込まれる
  • コードベース向けの「オンボーディング資料」として機能する
  • 探索し直す手間が減り、最初から正しい前提で取り組める

8.2 CLAUDE.md とは

CLAUDE.md は、プロジェクトのルートディレクトリに置く Markdown ファイルです。Claude Code はセッションを開始するたびに自動的にこれを読み込みます。いわば、あなたのコードベース向けのオンボーディング資料のようなものだと考えてください。

CLAUDE.md ファイルの内容は、あなたのプロンプトに追加される形で Claude Code に渡される。

ここが CLAUDE.md を理解するうえでもっとも重要なポイントです。CLAUDE.md は特別な記憶領域に保存されて別枠で参照されるわけではありません。毎セッションの開始時に、あなたが送るメッセージの前に丸ごと差し込まれるという、とてもシンプルな仕組みで働いています。

CLAUDE.md

セッション開始時に自動読込

あなたのプロンプトに追加

コンテキストウィンドウを消費（第7章）

第7章とのつながり

CLAUDE.md の内容は魔法のように別枠で保持されるわけではなく、毎回あなたが送るプロンプトに追加されます。つまり CLAUDE.md も第7章で学んだコンテキストウィンドウを消費する存在です。だからこそ、8.6 で説明する「肥大化させない」工夫が重要になります。

8.3 具体例

典型的な CLAUDE.md ファイルは、たとえば次のような内容になります。

CLAUDE.md 
# Project

This is a Next.js 15 app using the App Router, Tailwind, and Drizzle ORM.

# Commands

- Dev server: `pnpm dev`
- Run tests: `pnpm test`
- Lint: `pnpm lint`

# Code Style

- Use 2-space indentation
- Prefer named exports
- All API routes go in app/api/
- Use server actions instead of API routes where possible

いたってシンプルです。これがあれば、Claude Code に React コンポーネントの作成を依頼したときに、スタイリングには Tailwind を使うこと、そしてあなたのコーディング規約に従うことを、すでに理解した状態で対応してくれます。

見出し 書かれている内容
# Project 技術スタックの概要（フレームワーク・スタイリング・ORM など）
# Commands 開発サーバー起動・テスト・Lint など、よく使うコマンド
# Code Style チームのコーディング規約（インデント幅・export の書き方・ファイル配置ルールなど）

8.4 メモリの階層

CLAUDE.md はバージョン管理にコミットすることができますし、そうすべきです。そうすることでチーム全体がその恩恵を受けられます。実は、誰向けのファイルかによって、メモリファイルには階層があります。

ユーザーレベル ~/.claude/CLAUDE.md（自分の設定フォルダ） 自分専用（すべてのプロジェクトに適用） 個人的な好み（例: 説明の詳しさの好みなど）

重要ポイント

プロジェクトレベルの CLAUDE.md はバージョン管理にコミットすべきです。そうすることでチーム全員が同じ前提を Claude Code と共有できます。個人的な好みはユーザーレベルに書き分けましょう。

8.5 CLAUDE.mdを育てる3つのTips

CLAUDE.md は一度書いたら終わりではありません。プロジェクトを進めながら少しずつ育てていくものです。効果的に育てるための3つのコツを紹介します。

1

修正内容はメモリに保存する

Claude に何度も同じ修正を指示している――たとえば「API ルートではなく常にサーバーアクションを使うように」といったことを繰り返し伝えている――と気づいたら、そのルールをメモリに保存するよう明示的に Claude へ依頼しましょう。次にそのプロジェクトを開いたときには、Claude はそれを覚えています。

2

@ 記号でドキュメントを参照させる

Claude に参照してほしいドキュメントがプロジェクト内にある場合は、@ 記号を使ってファイルパスを指定します。

3

最初は CLAUDE.md なしで始める

プロジェクトを始める際は、まず CLAUDE.md ファイルを置かずにスタートすることをおすすめします。そうすることで、どんな点でモデルの軌道修正が頻繁に必要になるかが見えてきます。こうすれば CLAUDE.md をコンパクトに保ち、本当に必要な情報だけに絞り込むことができます。準備が整ったら、/init を実行すれば Claude が代わりに生成してくれます。

Tip② の具体例です。CLAUDE.md 内に次のように書いておくと、必要なときに Claude が README.md を読みに行ってくれます。

CLAUDE.md（抜粋） 
## README.md

Please read if you need more info: @README.md

8.6 アンチパターン: 肥大化させない

8.5 の Tip③ のとおり CLAUDE.md は少しずつ育てていくものですが、育て続けるだけでは肥大化してしまいます。8.2 で確認したとおり、CLAUDE.md はセッションのたびに全文がプロンプトに追加されます。育成と整理はセットで考える必要があります。

注意: CLAUDE.md を肥大化させない

CLAUDE.md が長くなればなるほど、第7章で学んだコンテキストウィンドウをそれだけ多く消費してしまいます。「念のため」で何でも書き込むのではなく、実際に軌道修正が繰り返された内容だけを簡潔な言葉で残しましょう。定期的に読み返し、もう当てはまらない記述や、コードを読めば分かる自明な内容は削除するのがおすすめです。

Claude Code でのセッションが、もどかしいものになるか生産的なものになるかの違いは、多くの場合コンテキストにあります。そして、そのコンテキストを与える手段が CLAUDE.md です。まずは自分たちの技術スタック・好み・よく使うコマンドから書き始め、そこから少しずつ育てていきましょう。

やってみよう 8-1: 自分のプロジェクト用の CLAUDE.md を設計してみる

実際にファイルを作らなくてもかまいません。普段使っている（またはこれから Claude Code を使いたい）プロジェクトを思い浮かべながら、CLAUDE.md に何を書くかを設計してみましょう。

手順

  1. 1 対象のプロジェクトを1つ選び、8.3 の例にならって「# Project」「# Commands」「# Code Style」の3つの見出しで、自分のプロジェクトに当てはまる内容を書き出す。
  2. 2 8.4 を参考に、書いた内容を「チーム全員に関係するもの（プロジェクトレベル）」と「自分だけの好み（ユーザーレベル）」に仕分けし、印を付ける。
  3. 3 書き出した項目の中から、「本当に軌道修正が繰り返されそうなもの」だけに絞り込む。8.6 の考え方に沿って、削っても困らない項目には取り消し線を引いてみる。

理解度確認クイズ

  1. Q1. CLAUDE.md の内容は、Claude Code にどのような形で渡されますか。第7章の内容と関連づけて説明してください。

    回答を表示

    CLAUDE.md の内容はあなたが送るプロンプトに追加される形で渡されます。特別な記憶領域に別枠で保存されるわけではありません。つまり CLAUDE.md も第7章で学んだコンテキストウィンドウを消費する存在であり、内容が長くなるほど消費量も増えます。

  2. Q2. プロジェクトレベルの CLAUDE.md とユーザーレベルの CLAUDE.md の違いを説明してください。

    回答を表示

    プロジェクトレベル（./CLAUDE.md）はリポジトリのルートに置き、チームで共有される。バージョン管理にコミットすべきもので、技術スタックやコマンド、コーディング規約など全員に関係する内容を書く。ユーザーレベル（~/.claude/CLAUDE.md）は自分の設定フォルダに置き、自分が扱うすべてのプロジェクトに適用される個人専用の設定で、個人的な好みを書く。

  3. Q3. 新しいプロジェクトで CLAUDE.md を作るとき、原典が勧める進め方と、内容を肥大化させないための考え方を説明してください。

    回答を表示

    最初は CLAUDE.md なしで始め、Claude への軌道修正が繰り返し必要になった点に気づいてから、/init か手動で作成するのがおすすめです。同じ指摘を繰り返していると気づいたルールは、明示的にメモリへ保存するよう依頼します。CLAUDE.md は毎回全文がプロンプトに追加されるため、念のためで書き込みすぎず、定期的に読み返して不要な記述を整理します。
