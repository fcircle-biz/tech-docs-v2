段階的開示と複数ファイル構成

スキルは、あなたとの会話と Claude のコンテキストウィンドウを共有しています。参照資料やサンプルが増えるほど SKILL.md は肥大化しがちですが、すべてを1ファイルに詰め込むのは得策ではありません。この章では、必要なときだけ詳細を読み込ませる段階的開示（Progressive Disclosure）の考え方と、scripts/・references/・assets/ を使った複数ファイル構成のしかたを学びます。

この章で学ぶこと

  • スキルを1ファイルに詰め込むと生じる2つの問題を説明できる
  • 段階的開示（Progressive Disclosure）の考え方を理解する
  • scripts/・references/・assets/ の役割を区別できる
  • SKILL.md から参照ファイルへ「いつ読むか」を明示してリンクする書き方を書ける
  • SKILL.md の分量の目安（500行）を意識して構成を設計できる

7.1 コンテキストウィンドウを共有しているという事実

スキルは、あなたとの会話と Claude のコンテキストウィンドウを共有しています。Claude がスキルを有効化すると、その SKILL.md の内容がコンテキストに読み込まれます。ここまでは第4章で見た「name と description だけを先に読み、マッチしたら本文を読み込む」という流れの延長です。

しかし実際には、スキルが依存する参照資料・サンプル・ユーティリティスクリプトが必要になる場合もあります。設計ドキュメント、APIの仕様、サンプルコード、テンプレート画像……これらをすべて SKILL.md という1つの Markdown ファイルに詰め込みたくなるかもしれません。

問題1: コンテキストの浪費

2,000行の SKILL.md を用意すると、スキルが有効化されるたびにその全部がコンテキストウィンドウに読み込まれます。実際の依頼で必要なのはごく一部でも、無関係な内容までスペースを占有します。

問題2: メンテナンスの困難さ

指示・参照資料・サンプルコードが1ファイルに混在すると、どこに何が書いてあるかを追いづらくなります。一部を更新するたびに、ファイル全体を読み返す必要が出てきます。

すべてを1ファイルに詰め込むと、コンテキストウィンドウのスペースを大量に消費すること、そしてメンテナンスが大変になることという2つの問題が生じます。

7.2 段階的開示（Progressive Disclosure）という考え方

この2つの問題を解決するのが段階的開示（Progressive Disclosure）です。考え方はシンプルです。必須の指示は SKILL.md に残し、詳細な参照資料は必要なときだけ Claude が読み込む別ファイルに切り出す。これだけです。

「必須の指示」とは、そのスキルが有効になったら常に把握しておいてほしい、コアとなる手順や判断基準のことです。一方「詳細な参照資料」は、特定の状況でだけ必要になる深い情報——たとえばアーキテクチャの詳細、大きなサンプルコード、網羅的な仕様一覧などです。すべての依頼で必要になるわけではないものを、あらかじめ本体から切り離しておきます。

全部をコンテキストへ読み込む"] end subgraph B["段階的開示（分割構成）"] B1["SKILL.md（500行以内）"] --> B2["必要な参照ファイルだけ
そのつど読み込む"] end

左側の1ファイル構成では、スキルが有効になるたびに巨大な本文がまるごと読み込まれます。右側の段階的開示では、SKILL.md 自体は軽量に保たれ、詳細が必要になった場面でだけ追加のファイルが読み込まれます。同じ知識量を持つスキルでも、日常的に消費するコンテキストの量はまったく違います。

7.3 推奨されるディレクトリ構成 — scripts / references / assets

agent skills open standard は、スキルのディレクトリを次のように整理することを推奨しています。

scripts/

実行可能なコード。検証スクリプトやデータ変換ツールなど、読ませるのではなく実行させたい処理を置きます（第8章で詳しく扱います）。

references/

追加のドキュメント。アーキテクチャ解説や仕様一覧など、特定の状況でだけ読んでほしい詳細情報を置きます。

assets/

画像、テンプレート、その他のデータファイル。出力に組み込んだり参照したりする素材を置きます。

複数ファイル構成のスキル（例） 

skill-name/
├── SKILL.md              ← 必須の指示（500行以内が目安）
├── scripts/               ← 実行可能なコード
│   └── validate.py
├── references/            ← 追加のドキュメント
│   └── architecture-guide.md
└── assets/                 ← 画像・テンプレート・データファイル
    └── logo.png

3つのフォルダをすべて用意する必要はありません。スキルの性質に合わせて、必要なものだけ作れば十分です。ドキュメントの参照が中心なら references/ だけ、自動化が中心なら scripts/ だけ、というスキルも珍しくありません。

7.4 SKILL.md から参照ファイルへリンクする

ファイルを分けただけでは、Claude はいつそれを読めばいいか分かりません。SKILL.md の中から、いつ読み込むべきかを明確にした指示とともに補助ファイルへリンクする必要があります。

以下の例では、Claude はシステム設計について質問されたときだけ architecture-guide.md を読み込みます。コンポーネントをどこに追加すべきかを聞かれた場合は、このファイルを一切読み込みません。

SKILL.md（抜粋） 
## アーキテクチャ

システム設計について質問されたときは、
`references/architecture-guide.md` を読み込んでから回答してください。

コンポーネントをどこに追加すべきか聞かれた場合は、
このファイルを読み込む必要はありません。

## テストの規約

新しいテストを書くときは、
`references/testing-guide.md` の規約に従ってください。

ポイントは、リンクを置くだけでなく「どんな依頼のときに読むか」を条件として明示することです。条件が曖昧だと、Claude は必要なときに読み込まなかったり、逆に不要なときまで読み込んでコンテキストを浪費したりします。

重要ポイント: 目次だけを置いているイメージ

段階的開示は、コンテキストウィンドウの中に文書全体を置くのではなく、目次だけを置いているイメージで捉えると理解しやすくなります。目次（SKILL.md）にはどの章にどんな内容があるかが書かれていて、実際に必要になった章（参照ファイル）だけをそのつど開く——普段の資料の使い方と同じです。

7.5 実際の読み込みの流れ

段階的開示を導入すると、Claude の情報収集は次のような多段階の流れになります。

flowchart TD A["Claude がスキルを有効化"] --> B["SKILL.md 本文を読み込む"] B --> C{"依頼の内容は？"} C -->|"システム設計について質問"| D["references/architecture-guide.md を読み込む"] C -->|"コンポーネントの追加場所を質問"| E["architecture-guide.md は読み込まない"]

第4章で見た「name と description だけを先に読み、マッチしたら SKILL.md 本文を読む」という段階に、さらにもう1段階が加わったと考えるとイメージしやすいでしょう。スキル全体の有効化と個々の参照ファイルの読み込みは、それぞれ別のタイミングで判断されます。

目安: SKILL.md は500行以内

SKILL.md は500行以内に収めるのが目安です。それを超えるようであれば、内容を別の参照ファイルに分割すべきかどうかを検討してください。行数はあくまで目安であり、絶対的な上限ではありませんが、「そろそろ分割を考えるタイミング」のサインとして役立ちます。

やってみよう 7-1: 大きくなりそうなスキルを仕分けする

これまでの章で作成・検討してきたスキルの中から、あるいは自分の業務の中から、内容が膨らみそうなスキルを1つ思い浮かべてください。SKILL.md に残す内容と references/（や scripts/）に切り出す内容を仕分けしてみましょう。

手順

  1. 1 そのスキルで扱いたい情報を、思いつく限り箇条書きで洗い出す（手順、判断基準、詳細な仕様、サンプルコードなど）。
  2. 2 それぞれについて「ほぼ毎回必要か」「特定の状況でしか必要ないか」を判定する。前者は SKILL.md に残し、後者は参照ファイル候補にする。
  3. 3 参照ファイル候補を references/xxx.md のようなファイル名に割り振り、SKILL.md に「いつ読み込むか」を明示したリンク文を1〜2行で書いてみる。

ヒント: 迷ったら「この情報がなくても、Claude は8割の依頼に正しく答えられるか？」を基準にしてください。答えが「はい」なら参照ファイル向き、「いいえ」なら SKILL.md に残す情報です。

理解度確認クイズ

  1. Q1. すべての内容を1つの巨大な SKILL.md に詰め込むと、どのような2つの問題が生じますか？

    回答を表示

    ①スキルが有効化されるたびに全内容がコンテキストウィンドウに読み込まれ、スペースを大量に消費すること。②指示・参照資料・サンプルコードが混在し、メンテナンスが大変になること。この2つです。

  2. Q2. 段階的開示（Progressive Disclosure）とは、どのような考え方ですか？

    回答を表示

    必須の指示は SKILL.md に残し、詳細な参照資料は必要なときだけ Claude が読み込む別ファイルに切り出すという考え方です。コンテキストウィンドウの中に文書全体を置くのではなく、目次だけを置いているイメージで捉えられます。

  3. Q3. open standard が推奨する3つのディレクトリ（scripts/・references/・assets/）は、それぞれ何を置く場所ですか？

    回答を表示

    scripts/ は実行可能なコード、references/ は追加のドキュメント、assets/ は画像・テンプレート・その他のデータファイルを置く場所です。

  4. Q4. SKILL.md から参照ファイルへリンクする際、単にファイル名を書くだけでは不十分なのはなぜですか？

    回答を表示

    ファイル名を書くだけでは、Claude は「いつ」そのファイルを読めばいいか判断できません。「システム設計について質問されたときだけ読み込む」のように、読み込むべき条件を明確にした指示とともにリンクする必要があります。
