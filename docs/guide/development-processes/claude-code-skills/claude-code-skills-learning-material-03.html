第3章 所要時間: 約45分

最初のスキルを作る

前章までで、スキルが「何であるか」「どこに置かれるか」を学びました。この章では、実際に手を動かしてパーソナルスキル pr-description をゼロから作ります。PR の説明文を一貫したフォーマットで書くことを Claude に教える、実用的なスキルです。

この章で学ぶこと

  • スキル用ディレクトリを正しい場所・正しい名前で作成できる
  • frontmatter（name・description）と指示本文を持つ SKILL.md を書ける
  • ディレクトリ名とスキル名を一致させる理由を説明できる
  • 作成したファイルが正しく配置されたかを確認できる
  • スキルの変更を反映させるには Claude Code の再起動が必要であることを知る

3.1 今回作るスキル: pr-description

今回のゴールは、PR の説明文を一貫したフォーマットで書く方法を Claude に教える、パーソナルスキルを作ることです。パーソナルスキルなので、ホームディレクトリに置かれ、すべてのプロジェクトで使えます。

作業は次の3ステップだけです。全体の流れを先に確認しておきましょう。

flowchart TD A["ステップ1
ディレクトリを作成する"] --> B["ステップ2
SKILL.mdを作成する"] B --> C["ステップ3
Claude Codeを再起動する"] C --> D["動作確認する"]

1つずつ、コマンドとファイルの中身を確認しながら進めていきます。

3.2 ステップ1: ディレクトリを作る

まず、skills フォルダの中に、スキル用のディレクトリを作成します。ディレクトリ名はスキル名と一致させるのがルールです。

ターミナル 
# パーソナルスキル用のディレクトリを作成する
# ディレクトリ名 "pr-description" はスキル名と一致させる
mkdir -p ~/.claude/skills/pr-description

なぜホームディレクトリなのか

パーソナルスキルは ~/.claude/skills に置きます。ここに置いたスキルは、どのプロジェクトを開いていてもあなたについて回ります。チーム全体で共有したい場合は、第2章で扱ったプロジェクト用の .claude/skills を使います。

3.3 ステップ2: SKILL.md を作る

続いて、そのディレクトリの中に SKILL.md ファイルを作成します。このファイルは、frontmatter のダッシュ（---）で区切られた2つの部分から構成されます。まずは frontmatter 部分から見ていきましょう。

~/.claude/skills/pr-description/SKILL.md（frontmatter部分） 
---
name: pr-description
description: プルリクエストの説明文を作成します。PRを作成するとき、
  PRを書くとき、あるいはユーザーがプルリクエストの変更内容の要約を
  求めたときに使用します。
---

続けて、2つ目の --- の下に、Claude が従うべき指示本文を書きます。

~/.claude/skills/pr-description/SKILL.md（指示本文部分） 
PRの説明文を書くときは：

1. `git diff main...HEAD` を実行して、このブランチの
   すべての変更を確認する
2. 次のフォーマットに沿って説明文を書く

## 概要
このPRが何をするのかを1文で説明します。

## 目的
この変更が必要な理由についての簡単な背景。

## 変更点
- 具体的な変更点を箇条書きで示す
- 関連する変更はまとめる
- 削除・リネームされたファイルがあれば記載する

2つのブロックをつなげたものが、実際に保存する SKILL.md の全体です。--- が2回登場し、上下を分けている点に注目してください。

name はスキルを識別するものです。description は Claude にいつこのスキルを使うべきかを伝えるもので、これがマッチングの判断基準になります。2つ目のダッシュの区切り以降はすべて、スキルが有効化されたときに Claude が従う指示です。

ファイルを保存すると、ディレクトリの構成は次のようになります。 

~/.claude/skills/
└── pr-description/
    └── SKILL.md      ← frontmatter ＋ 指示本文

3.4 ステップ3: Claude Code を再起動する

Claude Code はスキルを起動時にスキャンして読み込みます。そのため、ディレクトリと SKILL.md を作っただけでは、まだ Claude はこのスキルの存在を知りません。

重要: 変更は再起動しないと反映されない

スキルを作成・更新・削除したときは、必ずその後 Claude Code のセッションを再起動してください。再起動するまで、Claude は古い一覧のまま動作し続けます。読み込みの仕組みの詳細は、次の第4章で扱います。

3.5 動作確認: ファイルは正しく作られたか

再起動する前に、まずファイルが正しい場所に正しい名前で作られているかを確認しておきましょう。ls コマンドで中身を一覧表示します。

ターミナル 
# pr-description ディレクトリの中身を確認する
ls ~/.claude/skills/pr-description
# → SKILL.md と表示されればOK

チェックリスト

  • ls ~/.claude/skills/pr-description を実行すると SKILL.md が表示される
  • ディレクトリ名（pr-description）と frontmatter の name の値が一致している
  • SKILL.md の中に --- が2回登場し、frontmatter と指示本文が分かれている
  • 保存後に Claude Code を再起動した

すべて確認できたら、これで pr-description スキルの準備は完了です。実際にスキルが Claude に発見・マッチングされる仕組みと、テストの手順は次の第4章で詳しく見ていきます。

やってみよう 3-1: pr-description スキルを作る

この章で説明した手順どおりに、実際に pr-description スキルを自分の環境に作ってみましょう。

手順

  1. 1 ターミナルで mkdir -p ~/.claude/skills/pr-description を実行し、ディレクトリを作成する。
  2. 2 エディタでそのディレクトリの中に SKILL.md を作成し、3.3 で示した frontmatter と指示本文をそのまま貼り付けて保存する。
  3. 3 ls ~/.claude/skills/pr-description でファイルの存在を確認し、その後 Claude Code を再起動する。

ヒント: SKILL.md をタイプミスした場合は、そのまま編集して保存し直してかまいません。ただし変更を反映させるには、再度 Claude Code を再起動する必要があります。

理解度確認クイズ

  1. Q1. パーソナルスキル用のディレクトリ名は、何と一致させる必要がありますか？

    回答を表示

    スキル名（frontmatter の name の値）と一致させる必要があります。今回の例では、ディレクトリ名も frontmatter の name も pr-description です。

  2. Q2. SKILL.md の name と description は、それぞれ何の役割を担っていますか？

    回答を表示

    name はスキルを識別するものです。description は Claude にいつこのスキルを使うべきかを伝えるもので、リクエストとのマッチングの判断基準になります。

  3. Q3. SKILL.md の2つ目の --- より下に書かれている内容は何ですか？

    回答を表示

    スキルが有効化されたときに Claude が従う指示本文です。今回の例では、git diff main...HEAD を実行することと、## 概要・## 目的・## 変更点 のフォーマットで説明文を書くことが指示されています。

  4. Q4. スキルを作成・更新・削除したあと、何をする必要がありますか？

    回答を表示

    Claude Code を再起動する必要があります。Claude Code はスキルを起動時にスキャンして読み込むため、再起動するまで変更は反映されません。
