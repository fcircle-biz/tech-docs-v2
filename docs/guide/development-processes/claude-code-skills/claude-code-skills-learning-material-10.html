ホーム Claude Code Skills 第10章
第10章 所要時間: 約40分

サブエージェント・フック・MCPとの比較

Claude Code には複数のカスタマイズオプションがあります。前章では CLAUDE.md とスラッシュコマンドとの違いを整理しましたが、この章では残る3つの機能——サブエージェント（subagents）・フック（hooks）・MCPサーバー——とスキルを比較し、Claude Code のカスタマイズ手段を一望します。

この章で学ぶこと

  • スキルとサブエージェントの違い（会話への知識追加 vs 独立コンテキストでの実行）を説明できる
  • スキルとフックの違い（リクエスト駆動 vs イベント駆動）を説明できる
  • MCPサーバーが何を提供する機能で、スキルとどう役割が違うかを理解する
  • 5つのカスタマイズ機能を「起動のきっかけ・実行コンテキスト・主な用途」で比較できる
  • 開発ワークフローの課題に対して、複数の機能を組み合わせて割り当てられる

10.1 「なんでも一つの機能に押し込む」という失敗

Claude Code には、スキル・CLAUDE.md・スラッシュコマンド・サブエージェント・フック・MCPサーバーという複数のカスタマイズオプションがあります。便利な機能が揃っているぶん、誤った選択をすると余計な複雑さを招いてしまいます。第9章では CLAUDE.md とスラッシュコマンドを扱いました。この章では残る3つ、サブエージェント・フック・MCPサーバーを見ていきます。

サブエージェント

独立したコンテキストで作業を委任し、結果だけを受け取りたいとき。

フック

ファイル保存やツール呼び出しといった特定のイベントで、必ず何かを実行したいとき。

MCPサーバー

外部のツールやサービスと連携する能力そのものを、Claude に持たせたいとき。

それぞれが異なる問題を解決するものです。どれをいつ使うべきかを知っておくことで、見当違いのものを作ってしまうのを防げます。

10.2 スキル vs サブエージェント（Subagents）

スキルとサブエージェントは、どちらも「Claude に専門的な振る舞いをさせる」ための機能ですが、どこで実行されるかが根本的に違います。

flowchart LR subgraph S["スキル"] S1["現在の会話"] --> S2["スキルの指示が
既存のコンテキストに加わる"] end subgraph A["サブエージェント"] A1["メインの会話"] --> A2["タスクを委任"] A2 --> A3["別のコンテキストで
独立して作業"] A3 --> A4["結果だけをメインへ返す"] end

スキルは現在の会話に知識を追加します。スキルが有効化されると、その指示が既存のコンテキストに加わり、Claude はそのまま同じ会話の中で作業を続けます。

一方でサブエージェントは別のコンテキストで実行されます。タスクを受け取り、独立して作業を進め、結果を返します。メインの会話からは切り離されています。

サブエージェントを使うべき場面

  • ・別の実行コンテキストにタスクを委任したいとき
  • ・メインの会話とは異なるツールアクセスが必要なとき
  • ・委任した作業とメインのコンテキストを分離したいとき

スキルを使うべき場面

  • ・現在のタスクについて Claude の知識を強化したいとき
  • ・その専門知識が会話全体を通じて当てはまるとき

補足: 組み合わせることもできる

サブエージェントの中でスキルを使わせることも可能です。ただし第11章で扱うとおり、サブエージェントはスキルを自動的には引き継ぎません。カスタムサブエージェントの frontmatter に skills フィールドを明示する必要があります。

10.3 スキル vs フック（Hooks）

フックとスキルの違いは、何が引き金になるかです。フックはイベントに応じて発火します。Claude がファイルを保存するたびにリンターを実行したり、特定のツール呼び出しの前に入力を検証したりする——これはイベント駆動型の仕組みです。

一方でスキルはリクエスト駆動型です。あなたが何を求めているかに基づいて有効化されます。

flowchart TD E1["ファイル保存"] --> H["フック"] E2["特定のツール呼び出し"] --> H H --> H2["決められた処理を
必ず実行（イベント駆動）"] R1["あなたのリクエスト"] --> SK["スキル"] SK --> SK2["リクエストに合致すれば
知識を適用（リクエスト駆動）"]

フックを使うべき場面

  • ・ファイル保存のたびに実行すべき操作
  • ・特定のツール呼び出しの前の検証
  • ・Claude の動作に伴う自動的な副次処理

スキルを使うべき場面

  • ・Claude がリクエストをどう扱うかを左右する知識
  • ・Claude の推論に影響を与えるガイドライン

重要ポイント

フックは「必ず実行される」保証がほしいときの選択肢です。スキルはあくまで description との照合に依存するため、確実性が求められる自動処理（リンター実行など）はフックに任せ、スキルには「判断や知識が必要な作業」を任せるのが基本の使い分けです。

10.4 MCPサーバーとはまったく別のカテゴリ

MCP（Model Context Protocol）サーバーは、外部ツールや連携機能を提供します。社内データベースへの問い合わせ、Slack への投稿、外部 API の呼び出しなど、Claude Code だけでは行えない操作をツールとして追加する仕組みです。

MCPサーバーはスキルとはまったく別のカテゴリです。スキルが「知識・手順」を追加するのに対し、MCPサーバーは「能力・接続先」を追加します。両者は競合するものではなく、組み合わせて使うものです。たとえば「社内issueトラッカーのMCPサーバー」を接続したうえで、「issue起票のフォーマットを定めたスキル」を用意する、といった構成が典型的です。

スキルが追加するもの

「どうやるか」という知識・手順。既存のツールをどう使うべきかを Claude に教える。

MCPサーバーが追加するもの

「何ができるか」という能力・連携先そのもの。Claude が使える新しいツールを増やす。

10.5 5つの機能を並べて比較する

ここまで見てきた機能を、「起動のきっかけ」「実行コンテキスト」「主な用途」の3つの軸で並べてみましょう。

機能 起動のきっかけ 実行コンテキスト 主な用途
CLAUDE.md 常時（すべての会話開始時） メインの会話 常時適用のプロジェクト標準
スキル リクエストとの照合（オンデマンド） メインの会話に知識を追加 タスク固有の専門知識
サブエージェント 明示的な委任 独立した別コンテキスト 分離して任せたい作業
フック イベント（保存・ツール呼び出し等） Claude の動作を外側から制御 イベント駆動の自動処理・検証
MCPサーバー ツールとして呼び出されたとき 外部サービスとの接続 外部ツール・データとの連携

典型的な開発環境では、これらを組み合わせて使います。次の図は、リクエストが来たときに各機能がどう役割分担するかのイメージです。

オンデマンドのタスク専門知識"] A --> D{"独立コンテキストへ
委任したい作業か"} D -->|はい| E["サブエージェント

それぞれが自分の得意分野を担当します。すべてを一つの手法に押し込めるのではなく、組み合わせて使いましょう。話題が関連するときに Claude が自動的に適用すべき知識があるなら、スキルを使う。そして他の機能と組み合わせることで、包括的なカスタマイズを実現してください。

やってみよう 10-1: チームの課題に5つの機能を割り当てる

比較表を頭に入れたところで、実際に自分のチームの状況に当てはめてみましょう。適切な機能を選べるようになると、無理にすべてをスキルへ詰め込むことがなくなります。

手順

  1. 1 自チームの開発ワークフローで感じている課題を3つ書き出す（例: 「PRのレビュー観点がレビュアーごとにバラつく」「デプロイ前チェックを忘れる人がいる」など）。
  2. 2 それぞれの課題に対して、スキル／CLAUDE.md／フック／サブエージェント／MCPのどれで解決するのが最も適切かを、10.5の比較表を根拠に1つずつ割り当てる。
  3. 3 選んだ理由を一言で書く。「なぜスキルではなくフックなのか」を説明できれば、使い分けが身についた証拠です。

ヒント: 迷ったら「必ず実行させたいか（フック）」「独立して任せたいか（サブエージェント）」「外部と繋がりたいか（MCP）」「常時か・オンデマンドか（CLAUDE.md・スキル）」の順に問いかけてください。

理解度確認クイズ

  1. Q1. スキルとサブエージェントの最も本質的な違いは何ですか？

    回答を表示

    スキルは現在の会話に知識を追加し、既存のコンテキストの中で作業を続けます。サブエージェントは別のコンテキストで独立して実行され、タスクを受け取って結果だけをメインの会話に返します。「同じ会話の中で知識を強化するか」「別の実行環境に委任するか」が違いです。

  2. Q2. フックとスキルは、それぞれ何によって起動しますか？

    回答を表示

    フックはイベント駆動型で、ファイルの保存や特定のツール呼び出しといった出来事に応じて発火します。スキルはリクエスト駆動型で、あなたが何を求めているかに基づいて有効化されます。

  3. Q3. MCPサーバーはスキルとどう違いますか？

    回答を表示

    MCPサーバーは外部ツールや連携機能を提供するまったく別のカテゴリの機能です。スキルが「どうやるか」という知識・手順を追加するのに対し、MCPサーバーは「何ができるか」という能力・接続先そのものを追加します。両者は競合せず、組み合わせて使うものです。

  4. Q4. 「デプロイ前チェックを毎回忘れる人がいる」という課題には、スキル・フック・サブエージェントのうちどれが最も適切ですか。理由も含めて答えてください。

    回答を表示

    フックが最も適切です。「必ず実行されてほしい」という確実性が求められる自動処理であり、特定のイベント（デプロイ操作の前など）をきっかけに発火させる用途はフックの得意分野です。スキルはあくまで説明文との照合に依存するため、必ず実行される保証はありません。
