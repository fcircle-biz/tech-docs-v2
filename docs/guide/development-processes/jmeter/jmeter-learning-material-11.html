Test Script Recorderで操作を記録する

HTTP リクエストを1つずつ手で作るのは、画面数が多いシステムでは大変です。JMeter には、ブラウザや curl の操作を「中継」しながら HTTP Request として自動で書き出す HTTP(S) Test Script Recorder があります。この章では記録の仕組みと手順を学び、さらに「記録したままでは使えない」理由と、記録後の整理の進め方を身につけます。

この章で学ぶこと

  • プロキシ（中継役）として通信を記録する仕組みを説明できる
  • Recording テンプレートで記録の準備をし、curl で操作を記録できる
  • ブラウザ（Firefox）を使った記録の設定と、localhost 特有の注意点を理解する
  • HTTPS 記録に証明書が必要な理由を理解し、記録後のスクリプトを整理できる

11.1 レコーディングの仕組み

プロキシとは、通信の「中継役」です。ふつう、ブラウザはサーバーへ直接リクエストを送りますが、プロキシを設定すると、いったんプロキシにリクエストを渡し、プロキシがサーバーへ転送して応答をブラウザへ返します。

JMeter の HTTP(S) Test Script Recorder（HTTP(S) テストスクリプトレコーダー）は、この中継役を JMeter 自身が務める機能です。通信が通り抜けるときに、その内容（URL・メソッド・パラメーター・ヘッダーなど）を読み取って、HTTP Request としてテスト計画に自動で書き出します。

flowchart LR B["ブラウザ または curl"] -->|"1. リクエスト"| P["JMeter プロキシ
ポート 8888"] P -->|"2. 転送"| S["go-httpbin
localhost:8080"] S -->|"3. 応答"| P P -->|"4. 応答を返す"| B P -.->|"記録"| T["テスト計画に
HTTP Request を追加"]

記録で得られるのは、第4章で手作りしたものと同じ HTTP Request サンプラーです。つまり記録は「リクエストを作る作業を省力化する」仕組みであり、記録しただけで完成するわけではありません（11.6 で詳しく扱います）。

11.2 Recording テンプレートで準備する

記録に必要な要素を1つずつ配置するのは手間なので、JMeter のテンプレート機能を使います。メニューの File → Templates... を開き、プルダウンから Recording を選んで Create を押すと、記録用のテスト計画が一式作られます。

作られるツリーは、おおむね次のとおりです（バージョンにより細部は異なります）。 

Test Plan
├─ User Defined Variables
├─ HTTP Request Defaults        ← 接続先の共通設定
├─ HTTP Cookie Manager          ← Cookie の自動管理
├─ Thread Group
│   └─ Recording Controller     ← 記録結果の入れ物
└─ HTTP(S) Test Script Recorder ← 今回の主役
    └─ View Results Tree        ← 記録内容の確認用

次に、HTTP(S) Test Script Recorder を選び、設定を確認します。本ガイドで使う主な項目は次のとおりです。

項目 設定値 説明
Port 8888（既定） プロキシが待ち受けるポート番号。ブラウザや curl にはこの番号を指定する。他のソフトと重なる場合は変更する
Target Controller Test Plan > Thread Group > Recording Controller 記録したリクエストの追加先。テンプレートでは Recording Controller が選ばれている
Grouping Do not group samplers 記録をまとめる方法。操作の区切りごとにグループ化する選択肢もある
URL Patterns to Exclude 画像・CSS・JavaScript などの拡張子（正規表現） 記録しない URL の指定。テンプレートには静的ファイルを除外する既定パターンが入っている
Start / Stop / Restart ボタン プロキシの開始・停止。Start を押すまで何も記録されない

画像・CSS・JavaScript を除外するのは、負荷の本質的な対象が API やページ本体であることが多く、静的ファイルのリクエストが大量に混ざると整理が大変になるからです（静的ファイルも測りたい場合は除外しません）。

もう1つ、テンプレートの HTTP Request Defaults を、本ガイドの共通設定に合わせます。

項目 設定値 説明
Protocol http 練習用サーバーは HTTP
Server Name or IP localhost テンプレートの初期値（example.com など）から書き換える
Port Number 8080 go-httpbin のポート。レコーダーの 8888 とは別物

ヒント: 8888 と 8080 を混同しない

8888 は「JMeter のレコーダーが待ち受ける入口」、8080 は「go-httpbin が待ち受ける入口」です。ブラウザや curl のプロキシ指定には 8888、アクセス先 URL には 8080 を使います。

11.3 まずは curl で記録してみる

ブラウザの設定は環境により挙動が異なるため、最初は curl で記録するのが確実です。curl では -x オプションでプロキシを指定できます。ただし、環境変数 NO_PROXY（no_proxy）に localhost などが設定されていると、-x を指定していても localhost 宛ての通信がプロキシを経由せず、記録されません。社内 PC などではこの設定が入っていることがあるため、本演習では --noproxy "" を付けて、プロキシの除外設定を無効にします。

手順は、(1) go-httpbin を起動しておく、(2) HTTP(S) Test Script Recorder の Start を押す、(3) 別のターミナルから次のコマンドを実行する、の順です。

terminal（macOS / Linux） 
# --noproxy "": NO_PROXY による除外を無効にし、必ずプロキシ（8888）を通す
# 1. クエリ付きの GET を記録
curl --noproxy "" -x http://localhost:8888 "http://localhost:8080/get?name=rec"

# 2. HTML ページを取得する操作を記録
curl --noproxy "" -x http://localhost:8888 "http://localhost:8080/html"

# 3. JSON を POST する操作を記録
curl --noproxy "" -x http://localhost:8888 -X POST "http://localhost:8080/post" \
     -H "Content-Type: application/json" \
     -d '{"user":"alice","item":1}'
コマンドプロンプト（Windows） 
:: --noproxy "": NO_PROXY による除外を無効にし、必ずプロキシ（8888）を通す
:: 1. クエリ付きの GET を記録
curl --noproxy "" -x http://localhost:8888 "http://localhost:8080/get?name=rec"

:: 2. HTML ページを取得する操作を記録
curl --noproxy "" -x http://localhost:8888 "http://localhost:8080/html"

:: 3. JSON を POST する操作を記録（1行で書き、JSON の " を \" にする）
curl --noproxy "" -x http://localhost:8888 -X POST "http://localhost:8080/post" -H "Content-Type: application/json" -d "{\"user\":\"alice\",\"item\":1}"
PowerShell（Windows 標準の 5.1） 
# 0. このウィンドウだけ、NO_PROXY（プロキシの除外設定）を削除する
Remove-Item Env:NO_PROXY -ErrorAction SilentlyContinue

# 1. クエリ付きの GET を記録（curl ではなく curl.exe と書く）
curl.exe -x http://localhost:8888 "http://localhost:8080/get?name=rec"

# 2. HTML ページを取得する操作を記録
curl.exe -x http://localhost:8888 "http://localhost:8080/html"

# 3. JSON を POST する操作を記録（1行で書き、JSON の " を \" にする）
curl.exe -x http://localhost:8888 -X POST "http://localhost:8080/post" -H "Content-Type: application/json" -d '{\"user\":\"alice\",\"item\":1}'

Windows では1行で書き、JSON の二重引用符を \" とエスケープします。PowerShell では curl ではなく curl.exe と書きます（PowerShell の curl は別のコマンドの別名です）。また、Windows PowerShell 5.1 では空の文字列 "" をコマンドの引数として渡せないため、--noproxy "" の代わりに、最初の Remove-Item でそのウィンドウの環境変数 NO_PROXY を削除しています（Windows の環境変数は大文字・小文字を区別しないため、no_proxy も同時に消えます。ウィンドウを閉じれば元に戻ります）。

実行後、Recording Controller の下に /get・/html・/post の HTTP Request が追加されます。リクエストの Name は、URL のパスに通し番号が付いた形（例: /get-1）で自動で付きます（番号の付き方は設定やバージョンで変わることがあります）。記録が終わったら、レコーダーの Stop を押しましょう。

動作確認: 記録できたか

  • curl が JSON などの応答を普通に表示している（プロキシ経由でも応答は届く）。
  • Recording Controller 配下に3つのリクエストが増えている。
  • 記録された /get で始まる名前のリクエストを選ぶと、Path が /get、Parameters に name = rec が入っている。

記録されないときのチェック

レコーダーの Start を押し忘れていないか、curl のプロキシ指定が http://localhost:8888（8080 ではない）になっているか、go-httpbin が起動しているかを確認します。Start 時にポート使用中のエラーが出たら、Port を別の番号（例: 8889）に変え、curl 側も合わせます。また、--noproxy "" を省いたり（PowerShell では Remove-Item Env:NO_PROXY を実行していなかったり）すると、環境変数 NO_PROXY（no_proxy）に localhost が入っている環境では、通信がプロキシを通らず記録されません。

11.4 ブラウザで記録する

実際の画面操作を記録するには、ブラウザのプロキシ設定を JMeter に向けます。公式の手順でも Firefox が使われているため、本ガイドも Firefox で説明します。

  1. 1 Firefox の 設定 → 一般 → ネットワーク設定 → 接続設定... を開く。
  2. 2 手動でプロキシを設定するを選び、HTTP プロキシに localhost、ポートに 8888 を入力する。
  3. 3 「このプロキシーを HTTPS でも使用する」にチェックを入れる。
  4. 4 「プロキシーなしで接続」の欄に localhost と 127.0.0.1 が入っていれば削除する（次の注意参照）。

localhost 宛ての通信はプロキシを通らない（最重要）

ブラウザは既定で、localhost や 127.0.0.1 宛ての通信をプロキシに通さず直接送信します。そのため、設定が正しくても http://localhost:8080 の操作が 1件も記録されません。

Firefox では、アドレスバーに about:config と入力して警告を承諾し、network.proxy.allow_hijacking_localhost を検索して true に切り替えます。あわせて「プロキシーなしで接続」欄から localhost を外します。Chrome 系ブラウザでは別途、プロキシのバイパス設定の変更が必要です。記録が終わったら、ブラウザ設定を元に戻してください。

設定後、レコーダーを Start してから、Firefox で http://localhost:8080/forms/post を開き、フォームに適当な値を入力して送信してみましょう。/links/5 を開いてリンクをたどる操作も記録できます。JMeter 側には GET と POST のリクエストが並びます。

sequenceDiagram participant U as あなた participant F as Firefox participant J as JMeter 8888 participant S as go-httpbin 8080 U->>F: フォームを入力して送信 F->>J: POST /post J->>S: POST /post を転送 S-->>J: 応答 J-->>F: 応答を返す Note over J: HTTP Request として記録

ブラウザで記録すると、アドレスバー入力のたびの favicon 取得など、意図しないリクエストも混ざります。不要なものは 11.6 の手順で削除します。

11.5 HTTPS サイトの記録と証明書

HTTPS の通信は暗号化されているため、中継役の JMeter も、そのままでは中身を読めません。そこで JMeter は、記録時に自分で作った一時的なルート CA 証明書で「サーバーのふりをして通信を復号する」仕組みを使います。ブラウザから見ると、これは正体不明の証明書なので、ブラウザに「この証明書を信頼する」と登録する必要があります。

項目 内容
証明書ファイル <JMETER_HOME>/bin/ApacheJMeterTemporaryRootCA.crt（レコーダーを Start すると生成される）
登録先 ブラウザの証明書（認証局）設定にインポートして信頼させる
有効期限 既定では7日間有効（プロパティ proxy.cert.validity）。期限が切れて作り直された場合は、ブラウザへインポートし直す必要がある
学習後 ブラウザから削除することを推奨

警告: 証明書を信頼させたままにしない

この証明書を信頼したブラウザでは、その証明書の秘密鍵を持つ者が HTTPS 通信を盗み見できる状態になります。記録用の専用プロファイルで行い、作業が終わったら証明書の削除とプロキシ設定の解除を必ず行ってください。

本ガイドの練習先 go-httpbin は http://localhost:8080 であり HTTPS ではないため、この章では証明書のインポート手順までは行いません。実務で HTTPS のテスト環境を記録するときは、公式マニュアルの「Installing the JMeter CA certificate for HTTPS recording」を参照してください。

11.6 記録後の整理

記録直後のスクリプトは、あくまで「ある1回の操作の写し」です。そのまま負荷をかけると、固定値や不要なリクエストのせいで現実と異なる負荷になります。次の手順で整理します。

flowchart TD A["記録直後のスクリプト"] --> B["1. 不要なリクエストを削除"] B --> C["2. 名前を分かりやすく付け直す"] C --> D["3. 接続先を HTTP Request Defaults に集約"] D --> E["4. 固定値を変数化（第8章）"] E --> F["5. 動的な値を相関で抽出（第9章）"] F --> G["6. タイマーとアサーションを追加（第6・7章）"] G --> H["使える状態のスクリプト"]
整理の内容 なぜ必要か 具体例
不要なリクエストの削除 測定対象外の通信が混ざると結果が歪む favicon、広告・解析サービスへの通信
名前の付け直し レポートで何の操作か分かるようにする /post → 注文を送信
接続先の集約 環境が変わっても1か所の修正で済む 各 Request の Server 欄を空にし、Defaults に集約
固定値の変数化 全ユーザーが同じ値だと現実と乖離する ユーザー名を ${user}（CSV）に
動的な値の相関 記録時のトークンやセッション ID は再実行で無効になる JSON Extractor で取り出し ${token} に
タイマーの調整 記録は待ち時間なしで再生され負荷が過大になる Uniform Random Timer を追加

重要ポイント: 記録したまま使わない

記録は「素材集め」です。そのまま実行すると、(1) 毎回同じデータでキャッシュが効いて速く見える、(2) 古いトークンで認証エラーが続出する、(3) 待ち時間なしで過大な負荷になる、といった失敗が起きます。記録 → 整理 → 小さく試すまでを1セットで考えましょう。

やってみよう 11-1: curl で記録して整理する

curl で3つの操作を記録し、整理した上で ch11-recorded.jmx として保存します。

手順

  1. 1 go-httpbin を起動し、JMeter で File → Templates → Recording → Create を実行する。
  2. 2 HTTP Request Defaults を http / localhost / 8080 に設定し、HTTP(S) Test Script Recorder の Port が 8888 であることを確認して Start を押す。
  3. 3 11.3 の3つの curl コマンドを実行し、Stop を押す。
  4. 4 記録された3つのリクエストの名前を「GET 検索」「HTML 取得」「JSON 送信」に変更し、Server Name 欄が Defaults と重複していれば空にする。
  5. 5 ch11-recorded.jmx として保存し、Thread Group に View Results Tree を追加（Add → Listener → View Results Tree）してから、Thread Group を1スレッド・1ループで実行して、その View Results Tree で3件とも成功することを確認する。
ポイント: 記録した POST には Content-Type ヘッダーが記録された HTTP Header Manager が付く場合があります。付いていることも確認しておきましょう。

やってみよう 11-2（任意）: Firefox で /forms/post を送信して記録する

ブラウザ操作の記録を体験します。Firefox が無ければ読み飛ばして構いません。

手順

  1. 1 Firefox のプロキシを localhost:8888 に設定し、about:config で network.proxy.allow_hijacking_localhost を true にする。
  2. 2 レコーダーを Start し、http://localhost:8080/forms/post を開いてフォームを送信する。
  3. 3 GET /forms/post と POST /post が記録されたか、POST の Parameters に入力値が入っているかを確認する。
  4. 4 作業後、Firefox のプロキシ設定と allow_hijacking_localhost を元に戻す。
うまくいかないとき: 何も記録されないなら、まず allow_hijacking_localhost が true か、Start を押したかを確認します。

理解度確認クイズ

  1. Q1. HTTP(S) Test Script Recorder はどのような仕組みで操作を記録しますか？

    回答を表示

    JMeter がプロキシ（中継役）として待ち受け、ブラウザや curl の通信をサーバーへ転送しながら、その内容を HTTP Request としてテスト計画（Target Controller の下）に書き出します。既定のポートは 8888 です。

  2. Q2. Firefox のプロキシを localhost:8888 に設定したのに、http://localhost:8080 の操作が記録されません。原因と対処は？

    回答を表示

    ブラウザは既定で localhost 宛ての通信をプロキシに通さないためです。Firefox の about:config で network.proxy.allow_hijacking_localhost を true にし、「プロキシーなしで接続」欄の localhost も外します。レコーダーの Start 忘れも確認します。

  3. Q3. 記録したスクリプトをそのまま負荷テストに使うと、どんな問題が起きますか？ 整理で行う作業を2つ挙げてください。

    回答を表示

    全ユーザーが同じ固定値を使うため現実と乖離する、記録時のトークンが再実行で無効になる、待ち時間なしで過大な負荷になる、不要なリクエストが混ざる、などの問題が起きます。整理では、固定値の変数化（CSV など）、動的値の相関（JSON Extractor）、タイマーの追加、不要なリクエストの削除、名前の付け直し、接続先の HTTP Request Defaults への集約などを行います。
