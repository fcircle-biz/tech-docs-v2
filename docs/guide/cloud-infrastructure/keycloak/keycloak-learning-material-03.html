ホーム Keycloak 第3章
第3章 所要時間: 約50分

Keycloakを起動して管理コンソールに入る

前章までで「なぜKeycloakが必要か」を理解しました。この章では、いよいよ手を動かします。Dockerを使ってKeycloakを1コマンドで起動し、ブラウザから管理コンソールにログインするところまでを進めます。あわせて、画面の見方と「開発モード」「本番モード」という2つの動かし方の違いも押さえておきましょう。

この章で学ぶこと

  • Dockerを使ってKeycloakを開発モードで起動できる
  • 管理コンソールにadminとしてログインできる
  • 管理コンソール左メニューの主要項目が、それぞれ何をする画面か説明できる
  • 開発モードと本番モードの違いを説明できる

3.1 何をするかの見取り図

この章でやることはシンプルです。Dockerで1つのコマンドを実行するとKeycloakが起動し、あとはブラウザで開くだけです。インストール作業や設定ファイルの用意は必要ありません。全体の流れを先に確認しておきましょう。

図1: 起動から管理コンソールまでの流れ

flowchart TD A["docker run コマンドを実行"] --> B["Keycloakコンテナが起動する"] B --> C["ブラウザで
localhost:8080 を開く"] C --> D["管理コンソール
（Administration Console）"] D --> E["admin / admin でログイン"]

Dockerの基本操作（docker run・docker psなど）にまだ不安がある場合は、先にDocker学習教材の第1〜3章に目を通しておくと、この章がスムーズに進みます。

3.2 事前確認

コマンドを打つ前に、次の2点だけ確認しておきましょう。

事前チェック

  • Dockerが起動しており、docker versionでClientとServerの両方が表示される
  • 8080番ポートを他のアプリが使っていない（他のWebサーバーなどを起動していないか確認）
ターミナル 
# Dockerが正しく動いているか確認する（ClientとServerの両方が表示されればOK）
docker version

3.3 開発モードで起動する

次のコマンドで、Keycloak 26系を開発モードで起動します。ターミナルにそのままコピーして実行してください。

ターミナル 
# Keycloak 26系を開発モードで起動する
docker run --name keycloak -p 8080:8080 \
  -e KC_BOOTSTRAP_ADMIN_USERNAME=admin \
  -e KC_BOOTSTRAP_ADMIN_PASSWORD=admin \
  quay.io/keycloak/keycloak:26.0 start-dev

1行ずつ、何を指定しているのか確認しておきましょう。

オプション 意味
--name keycloak このコンテナに「keycloak」という名前を付ける。後でdocker stop keycloakのように名前で操作できる
-p 8080:8080 パソコンの8080番ポートとコンテナ内の8080番ポートをつなぐ。ブラウザからlocalhost:8080でアクセスできるようになる
-e KC_BOOTSTRAP_ADMIN_USERNAME=admin 最初の管理者ユーザー名をadminに設定する環境変数
-e KC_BOOTSTRAP_ADMIN_PASSWORD=admin 最初の管理者パスワードをadminに設定する環境変数
quay.io/keycloak/keycloak:26.0 使用するイメージ名とバージョン（タグ）。Keycloakの公式イメージはDocker HubではなくQuay.ioで配布されている
start-dev Keycloakを「開発モード」で起動する引数。HTTPS設定などを省略し、素早く試せる状態で起動する

補足: Keycloak 25以前との違い

Keycloak 25以前は、管理者を作る環境変数名がKEYCLOAK_ADMIN / KEYCLOAK_ADMIN_PASSWORDでした。26系からはKC_BOOTSTRAP_ADMIN_USERNAME / KC_BOOTSTRAP_ADMIN_PASSWORDに変更されています。古い記事やドキュメントを参考にするときは、この違いに注意してください。

動作確認

ターミナルに次のような行が流れ、最後にstartedという単語を含む行が出れば起動成功です。

出力結果（例・一部抜粋） 
...
Keycloak 26.0.0 on JVM (powered by Quarkus 3.x) started in 5.4s.
Listening on: http://0.0.0.0:8080

3.4 管理コンソールへのログイン

起動が確認できたら、ブラウザでhttp://localhost:8080/を開いてください。Keycloakのトップページが表示されるので、Administration Consoleのリンクをクリックします。ログイン画面が表示されたら、先ほど環境変数で指定したユーザー名とパスワード——admin / admin——を入力してログインします。

admin / admin はあくまで学習用

今回設定したadmin / adminは、覚えやすさを優先した学習用のパスワードです。実際の業務やインターネットに公開する環境では、このような単純なパスワードを使ってはいけません。本番運用でのパスワード・アクセス制限の考え方は第13章で扱います。

3.5 管理コンソール画面の見方

ログインすると、少し情報量の多い画面が表示されて戸惑うかもしれません。まず覚えておきたいのは2か所だけです。左上のレルム選択と、左側メニューです。

左上には、現在選んでいるレルム（realm）の名前が表示されています。初期状態ではmasterというレルムが選ばれています。レルムが何かは第4章でじっくり扱いますが、ここでは「master は管理専用の特別な区画」とだけ覚えておいてください。

左側メニューには、これから本教材で扱っていく設定項目が並んでいます。それぞれ何をする画面で、どの章で詳しく学ぶかを一覧にしました。

メニュー項目 できること 扱う章
Realm settings レルム（利用者の世界）全体の設定を行う 第4章
Clients Keycloakと連携するアプリ（クライアント）を登録・設定する 第5章
Users 利用者アカウントを作成・管理する 第6章
Groups 利用者をグループにまとめ、権限をまとめて割り当てる 第7章
Realm roles レルム全体で使う役割（ロール）を定義する 第7章
Identity providers Google・GitHubなど外部ログインとの連携を設定する 第12章
User federation 社内のLDAP / Active Directoryにいる利用者をそのまま使う設定 第12章
Sessions 現在ログイン中のセッション一覧を確認する 第10章
Events ログインなどの操作履歴（イベント）を確認する 第13章

今は全部を理解しなくてよい

この段階では、メニューの名前と役割をなんとなく眺めておくだけで十分です。各項目は本教材が進むにつれて、実際に手を動かしながら1つずつ扱っていきます。

3.6 開発モードと本番モードの違い

起動コマンドの最後に付けたstart-devは、Keycloakを開発モードで動かす指定でした。Keycloakにはもう1つ、startという本番モードがあります。この2つは目的も設定もまったく異なります。

項目 開発モード（start-dev） 本番モード（start）
HTTPS 不要。HTTPのままアクセスできる 必須。証明書の設定が必要になる
データベース 組み込みの簡易データベースを自動で使用 PostgreSQLなど外部データベースへの接続が必要
キャッシュ 実質無効な状態で動作する 複数台構成（クラスタ）を見据えて有効化される
想定用途 学習・検証のみ 実運用（本番環境）
コンテナ削除時のデータ docker rmで消える 外部データベース側に残る（設定次第）

開発モードのデータは消えやすい

開発モードでは設定やユーザー情報がコンテナの中に保存されます。--name keycloakを付けたコンテナをdocker rmで削除すると、これまでの設定はすべて失われます。学習を一時中断したいだけなら、docker stop keycloakで止め、再開時にdocker start keycloakを使えば、データを保ったまま続けられます。本番モードでの永続化の考え方は第13章で扱います。

3.7 起動・停止・後片付けのコマンド

この章の最後に、Keycloakコンテナを日常的に操作するためのコマンドをまとめておきます。今すぐすべて実行する必要はありません。困ったときに戻ってくるための一覧として使ってください。

ターミナル 
# 起動中のコンテナを確認する
docker ps

# 起動ログを確認する（-f を付けると継続表示）
docker logs keycloak

# コンテナを停止する（データは保持される）
docker stop keycloak

# 停止したコンテナを再度起動する
docker start keycloak

# コンテナを削除する（開発モードではデータも消える）
docker rm keycloak

3.8 よくあるエラーと対処

うまくいかないときは、次の表を確認してみてください。

症状 原因 対処
ポート8080が使用中で起動に失敗する（port is already allocated） 8080番ポートを別のアプリ（他のKeycloakや別のWebサーバーなど）がすでに使っている -p 8081:8080のように別ポートに変更し、ブラウザはlocalhost:8081を開く
管理コンソールにログインできない（Invalid username or password） 環境変数名がバージョンと合っていない（25以前はKEYCLOAK_ADMIN系） 使用しているイメージのバージョンを確認し、対応する環境変数名を使う。コンテナを削除して作り直す
起動が遅い・ブラウザにまだ何も表示されない 初回起動時はデータベースの初期化などに時間がかかる docker logs keycloakでログを確認し、startedという行が出るまで待つ

やってみよう 3-1: Keycloakを起動して管理コンソールを眺める

実際に手を動かして、この章の内容を体験してみましょう。

手順

  1. 1 3.3節のコマンドをターミナルに入力して実行し、ログにstartedという行が出るまで待つ。
  2. 2 ブラウザでhttp://localhost:8080/を開き、Administration Consoleのリンクをクリックする。
  3. 3 admin / adminでログインする。
  4. 4 左側メニューの各項目（Realm settings・Clients・Usersなど）に順にカーソルを合わせ、3.5節の表と照らし合わせながら眺める（クリックして開かなくてよい）。
  5. 5 確認が終わったらdocker stop keycloakで停止する。次章でもこのコンテナをそのまま使うため、削除はしないこと。

この章のまとめ

  • docker run ... start-devの1コマンドで、KeycloakをDockerの開発モードで起動できた。
  • http://localhost:8080/から管理コンソールを開き、admin / adminでログインできた（学習用のパスワードであり本番では変更が必須）。
  • 管理コンソール左上のレルム選択と、左メニューの主要項目（Realm settings・Clients・Usersなど）がそれぞれ何をする画面か把握した。
  • 開発モード（start-dev）は学習・検証専用で、コンテナを削除するとデータも消える。本番モード（start）との違いは第13章で詳しく扱う。

確認問題

  1. Q1. 起動コマンドの-p 8080:8080オプションは、何と何をつないでいますか。

    回答を表示

    自分のパソコンの8080番ポートと、コンテナ内部の8080番ポートをつないでいます。これにより、ブラウザからhttp://localhost:8080/にアクセスすると、コンテナの中で動いているKeycloakに届くようになります。

  2. Q2. Keycloak 25以前で管理者ユーザーを作成するために使われていた環境変数名を答えてください。26系との違いは何ですか。

    回答を表示

    25以前はKEYCLOAK_ADMIN / KEYCLOAK_ADMIN_PASSWORDという環境変数名でした。26系からはKC_BOOTSTRAP_ADMIN_USERNAME / KC_BOOTSTRAP_ADMIN_PASSWORDに変更されています。

  3. Q3. 開発モードで--name keycloakのコンテナをdocker rm keycloakで削除すると、これまでの設定はどうなりますか。データを消さずに一時停止したいときは、代わりにどのコマンドを使いますか。

    回答を表示

    開発モードでは設定やユーザー情報がコンテナの中に保存されているため、docker rmでコンテナを削除するとこれまでの設定はすべて失われます。一時的に止めるだけならdocker stop keycloakを使い、再開時はdocker start keycloakを実行すれば、データを保ったまま続けられます。
