プロセスとジョブの管理

コマンドを実行するたびに、裏側では「プロセス」というものが生まれて働いています。この章では、いま動いているプロセスを ps や top で確認する方法、1つのターミナルで複数の作業を行き来する「ジョブ制御」、プロセスを安全に終了させる kill の使い方を学びます。最後に、ログアウト後も処理を続ける方法と、Ubuntu の裏側でサービスを管理する systemd にも触れます。

この章で学ぶこと

  • プログラムとプロセスの違い、PIDと親子関係（PPID）を説明できる
  • ps・ps aux・ps -ef で実行中のプロセスを確認できる
  • top でCPU・メモリ使用率をリアルタイムに確認し、並び替えができる
  • &・Ctrl+Z・jobs・bg・fg でフォアグラウンドとバックグラウンドを行き来できる
  • kill・pkill でプロセスを安全に終了でき、nohup と systemd（systemctl status）の役割を理解する

10.1 プログラムとプロセス

第4章・第5章で使った ls や cp のようなコマンドは、ディスクに保存されたプログラム（実行可能なファイル）です。プログラムはただのファイルなので、実行していないときは何もしません。ターミナルでコマンド名を打って Enter を押すと、そのプログラムがメモリに読み込まれ、CPU時間を割り当てられて実際に動き出します。この「実行中の状態」のことを プロセス（process） と呼びます。

カーネルは、生まれたプロセス1つ1つに重ならない番号を割り振ります。これが PID（Process ID、プロセスID）です。プロセスを確認したり終了させたりするときは、名前ではなくこのPIDで指定するのが基本です。また、あるプロセスが別のプロセスを起動すると、起動した側を親プロセス、起動された側を子プロセスと呼び、子プロセスは親のPIDを PPID（Parent PID）として持ちます。たとえばターミナルで ls と打つと、いま使っているシェル（bash）が親となって ls という子プロセスを起動します。

10.2 実行中のプロセスを確認する

動いているプロセスを一覧表示するコマンドが ps（process status）です。オプションによって表示される範囲や項目が変わります。

オプションなしの ps

オプションを付けずに実行すると、いま使っているこの端末に紐づくプロセスだけを、PID・TTY・TIME・CMD の4列で表示します。TTY はどの端末に属しているか、TIME はこれまでに使ったCPU時間の累計（経過時間ではありません）です。

ターミナル 
# 自分の端末に紐づくプロセスを確認する
ps
出力結果（例） 
student@ubuntu:~$ ps
    PID TTY          TIME CMD
   1000 pts/0    00:00:00 bash
   1197 pts/0    00:00:00 ps
student@ubuntu:~$

自分のログインシェル（bash、PID 1000）と、実行した ps 自身（PID 1197）の2行だけが表示されています。

ps aux ― システム全体を詳しく見る

ps aux は、システム上のすべてのユーザーのプロセスを詳しい情報付きで一覧表示します（ハイフン無しの慣用表記です）。

ターミナル 
# システム上の全プロセスを詳しく一覧表示する
ps aux
出力結果（例） 
student@ubuntu:~$ ps aux
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.3  22536 13312 ?        Ss   09:00   0:01 /sbin/init
...（中略: root などほかのユーザーのプロセスが数十〜百行以上続く）...
student     1000  0.0  0.2  18200  5400 pts/0    Ss   09:05   0:00 -bash
student     1522  0.0  0.0  10100  3300 pts/0    R+   10:02   0:00 ps aux
student@ubuntu:~$
列 意味
USER プロセスを実行しているユーザー
PID プロセスID
%CPU CPU使用率（プロセス開始からの平均。直近の値は10.3節の top で見る）
%MEM 物理メモリの使用率
VSZ / RSS 確保している仮想メモリの大きさ／実際に使っている物理メモリの量（単位はKB）
START プロセスが始まった時刻
STAT プロセスの状態（下の説明を参照）
COMMAND 実行されたコマンドと引数

STAT列の主な値: R = 実行中、S = 待機中（スリープ）、T = 停止中、Z = ゾンビ（終了済みだが親が未回収）です。ふだん目にするのはほぼ R と S です。2文字目以降の s はセッションの中心となるプロセス（ログインシェルなど）、+ はフォアグラウンドで動いているものを表します。

ps -ef ― 親子関係が分かる形式

ps -ef は別の書式で全プロセスを表示し、PPID列で親子関係が分かります。スクリプトなどでもよく使われる形式です。

ターミナル 
# 親プロセスのPID(PPID)付きで一覧表示する
ps -ef
出力結果（例） 
student@ubuntu:~$ ps -ef
UID          PID    PPID  C STIME TTY          TIME CMD
root           1       0  0 09:00 ?        00:00:01 /sbin/init
...（中略）...
student     1000     999  0 09:05 pts/0    00:00:00 -bash
student     1650    1000  0 10:05 pts/0    00:00:00 ps -ef
student@ubuntu:~$

最後の行（ps -ef 自身、PID 1650）の PPID が 1000 で、bash のPIDと一致しています。10.1節の親子関係が、そのまま列に表れています。

パイプで絞り込む

第8章で学んだパイプ | を使うと、ps aux の結果から欲しい行だけ絞り込めます。ここでは sleep というプロセスがバックグラウンドで動いているとします（バックグラウンド実行そのものは10.4節で学びます）。

ターミナル 
# 実行中のプロセスからsleepという文字を含む行だけ絞り込む
ps aux | grep sleep
出力結果（例） 
student@ubuntu:~$ ps aux | grep sleep
student     2210  0.0  0.0   2436   604 pts/0    S    10:10   0:00 sleep 300
student     2215  0.0  0.0   7488  1088 pts/0    S+   10:12   0:00 grep --color=auto sleep
student@ubuntu:~$

目的の sleep プロセス（PID 2210）と一緒に、grep 自身の行も表示されています。grep --color=auto sleep というコマンドライン自体に「sleep」という文字が含まれるため一致してしまう、よくある現象です。

やってみよう 10-1: 自分のプロセスを確認する

~/linux-practice/ch10 を作って移動し、ps 系コマンドを試してみましょう。

手順

  1. 1 mkdir -p ~/linux-practice/ch10 && cd ~/linux-practice/ch10 を実行する。
  2. 2 ps を実行し、自分のシェルのPIDを確認する。
  3. 3 ps aux | grep bash と ps -ef | head（第6章の head の復習）をそれぞれ実行し、PPIDの列を眺めてみる。

10.3 top でリアルタイムに監視する

ps は実行した瞬間のスナップショットでしたが、top は画面を占有し、数秒おきに自動更新しながらプロセスの状態を表示し続けます。

ターミナル 
# プロセスの状態をリアルタイムに確認する
top
出力結果（例） 
top - 10:15:32 up  1:15,  1 user,  load average: 0.05, 0.03, 0.01
Tasks: 118 total,   2 running, 116 sleeping,   0 stopped,   0 zombie
%Cpu(s):  0.3 us,  0.3 sy,  0.0 ni, 99.3 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st
MiB Mem :   3915.6 total,   2480.3 free,    410.1 used,   1025.2 buff/cache
MiB Swap:      0.0 total,      0.0 free,      0.0 used.   3505.5 avail Mem

    PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
   1701 student   20   0    9800   3900   3100 R   1.3   0.1   0:00.05 top
   2210 student   20   0    2436    604    520 S   0.0   0.0   0:00.00 sleep
   1000 student   20   0   18200   5400   4600 S   0.0   0.1   0:00.12 bash
...（以下、ほかのプロセスが続く）

上部にはシステム全体の負荷やメモリ状況、下部にはプロセスの一覧が並びます。列の意味は ps aux とほぼ同じです。%Cpu(s) 行の id は CPU が空いている割合です。操作はキーボードで行います。

  • q — top を終了して元のプロンプトに戻る
  • P（大文字） — CPU使用率が高い順に並び替える（既定）
  • M（大文字） — メモリ使用率が高い順に並び替える

top は標準搭載ですが、色分けされたグラフやマウス操作にも対応した htop という見やすい改良版もよく使われます。第11章でパッケージ管理（apt）を学んだあとにインストールします。

10.4 フォアグラウンドとバックグラウンド（ジョブ制御）

これまでのコマンドは、実行すると終わるまでターミナルを占有するフォアグラウンド実行でした。時間のかかる処理を裏で動かしつつ、同じターミナルで別の作業もしたいことがあります。bashにはそのためのジョブ制御という仕組みがあります。ここでは、実際には何もしない sleep（指定した秒数だけ待つだけのコマンド）を使って練習します。

最初からバックグラウンドで実行する（&）

コマンドの末尾に & を付けると、そのコマンドはバックグラウンドで実行され、ターミナルはすぐにプロンプトへ戻ります。

ターミナル 
# sleepコマンドを100秒間バックグラウンドで実行してから、ジョブ一覧を確認する
sleep 100 &
jobs
出力結果（例） 
student@ubuntu:~/linux-practice/ch10$ sleep 100 &
[1] 1234
student@ubuntu:~/linux-practice/ch10$ jobs
[1]+  Running                 sleep 100 &
student@ubuntu:~/linux-practice/ch10$

[1] はジョブ番号（このターミナル内での通し番号）、1234 はPIDです。jobs は、いま抱えているジョブの一覧を確認するコマンドです。

この sleep 100 は100秒たつと自然に終わり、次にEnterを押したときなどに [1]+ Done sleep 100 と表示されます。終わる前に次のジョブを作ると、ジョブ番号は [2] になります。以下の例と同じ番号で試すときは、100秒待つか、この節の後半で学ぶ kill %1 で先に終了させてから進みましょう。

フォアグラウンドで一時停止する（Ctrl+Z）

今度は & を付けずに実行してみましょう。フォアグラウンド実行中はプロンプトが戻らず、他のコマンドを打っても実行されません。ここで Ctrl+Z を押すと、プロセスを終了させずに一時停止できます。

ターミナル 
# フォアグラウンドでsleepを実行する(終わるまで他のコマンドは実行されない)
sleep 100
出力結果（例） 
student@ubuntu:~/linux-practice/ch10$ sleep 100
^Z
[1]+  Stopped                 sleep 100
student@ubuntu:~/linux-practice/ch10$

^Z は Ctrl+Z を押したことを示す画面上の表示です。ジョブは停止中（Stopped）になり、プロンプトが戻ってきます。停止中のプロセスはCPUを使いません。

bg と fg で行き来する

bg は停止中のジョブをバックグラウンドで再開し、fg はバックグラウンドのジョブをフォアグラウンドへ呼び戻します。

ターミナル 
# 停止中のジョブをバックグラウンドで再開してから、フォアグラウンドに呼び戻す
bg
fg
出力結果（例） 
student@ubuntu:~/linux-practice/ch10$ bg
[1]+ sleep 100 &
student@ubuntu:~/linux-practice/ch10$ fg
sleep 100

fg のあとはまたフォアグラウンド実行に戻るため、ターミナルは sleep の終了を待つ状態になります。ここでもう一度 Ctrl+Z を押して停止させたとしましょう。フォアグラウンドに戻さずジョブを終わらせたいときは、次の kill にジョブ番号を渡す方法が便利です。

ターミナル 
# ジョブ番号1を指定してジョブを終了する
kill %1
出力結果（例） 
student@ubuntu:~/linux-practice/ch10$ kill %1
student@ubuntu:~/linux-practice/ch10$
[1]+  Terminated              sleep 100

%1 は「ジョブ番号1」を表します。PIDを調べなくても、jobs で見た番号を使ってそのまま終了できるのが便利な点です。なお、Terminated（終了した）の知らせは bash が次のプロンプトを出すときにまとめて表示するため、上の例のように Enter をもう一度押したあとに現れることがあります。

やってみよう 10-2: sleep でジョブ操作を体験する

図2の状態遷移を、実際に自分の手で一通りたどってみましょう。

手順

  1. 1 sleep 100 & でバックグラウンド実行し、表示されたジョブ番号とPIDを確認する。続けて jobs で状態が Running であることを確認したら、kill %1 で終了させておく（残したままだと手順2のジョブが [2] になり、手順4の kill %1 が別のジョブに当たってしまいます）。
  2. 2 今度は sleep 100 をフォアグラウンドで実行し、Ctrl+Z で一時停止する。
  3. 3 bg でバックグラウンド再開し、jobs で確認する。
  4. 4 fg でフォアグラウンドに戻したあと、kill %1 と打って Enter を押しても実行されないことを確認する（もう一度 Ctrl+Z で止め、jobs で番号を確かめてから kill %番号 で終了させる。最後に jobs で何も残っていないことを確認する）。

10.5 プロセスを終了する

kill は、名前に反して「必ず強制終了させる」コマンドではありません。実際にはプロセスにシグナル（合図）を送るコマンドで、既定では TERM シグナルを送ります。TERMは「終了してください」というお願いで、受け取ったプログラムはファイルの保存などの後片付けをしてから自分で終了できます。

見本: 2210 の部分は、必ず自分の環境で確認した sleep の PID に置き換えてから実行してください。

ターミナル 
# PIDを指定してプロセスにTERMシグナル(既定)を送る（2210 は例。自分の ps aux | grep sleep で確認したPIDに置き換える）
kill 2210

成功すると通常は何も表示されず、そのままプロンプトに戻ります（終了させたのがこの端末のジョブなら、次のプロンプトで Terminated と表示されます）。本当に終了したか確かめたいときは、続けて ps aux | grep sleep をもう一度実行して確認します。

まれに、TERMシグナルを無視するように作られていたり、終了処理の途中で固まったりして、TERMでは終了しないプログラムがあります。その最終手段が KILL シグナル（kill -9 <PID>、あるいは kill -KILL <PID>）です。KILLはプログラム側に断る余地を与えず、カーネルが強制的にプロセスを消します。後片付けができないため、保存し忘れたデータが失われることがあります。まずは既定の kill（TERM）を試し、それでも終了しないときだけ -9 を使いましょう。

どんなシグナルが送れるかは kill -l（エル）で一覧表示できます。

ターミナル 
# 利用できるシグナルの一覧を表示する
kill -l
出力結果（例） 
student@ubuntu:~/linux-practice/ch10$ kill -l
 1) SIGHUP       2) SIGINT       3) SIGQUIT      4) SIGILL       5) SIGTRAP
 6) SIGABRT      7) SIGBUS       8) SIGFPE       9) SIGKILL     10) SIGUSR1
11) SIGSEGV     12) SIGUSR2     13) SIGPIPE     14) SIGALRM     15) SIGTERM
...(以下略、環境により番号が異なる場合があります)
student@ubuntu:~/linux-practice/ch10$

9番の SIGKILL と15番の SIGTERM が、この章で扱った2つのシグナルです。

PIDを調べるのが面倒なときは、pkill でプロセス名を指定して終了できます。同じ名前のプロセスが複数あれば、まとめて対象になります。ただし pkill は、名前の一部が一致するプロセスもすべて対象にします（例: pkill ssh は ssh-agent なども終了させます）。名前が完全に一致するものだけにしたいときは pkill -x sleep のように -x を付けます。

ターミナル 
# プロセス名を指定してまとめて終了させる
pkill sleep

こちらも成功時は何も表示されません。確認したいときは ps aux | grep sleep を再度実行します。

kill は取り扱い注意のコマンドです

①-9（KILL）の多用: kill -9 は後片付けの機会を奪います。「効かないときの最終手段」であって、最初から使うものではありません。
②PIDの打ち間違い: kill 2210 のつもりで kill 2201 のように1文字でも打ち間違えると、自分の別のプロセス（sudo を付けていれば他人やシステムのプロセスまで）を終了させてしまいます。実行前に ps の結果とPIDを必ず見比べましょう。
③システムのプロセスを止める: sudo kill は自分のものではないプロセスも終了できてしまいます。ログの記録やネットワークなど、システムの重要なサービスのプロセスを終了させると、システムが不安定になったり再起動が必要になったりします。sudo を付けたkillは特に慎重に。

10.6 ログアウト後も動かし続ける・システムのサービスを覗く

nohup ― ログアウトしても動かし続ける

ターミナルを閉じたりログアウトしたりすると、そのターミナルで動かしていたプロセスには HUP（ハングアップ）シグナルが送られ、通常はプロセスも一緒に終了します。時間のかかる処理をログアウト後も続けたい場合は、nohup を付けて起動します。HUPシグナルを無視するようになり、標準出力は既定で nohup.out というファイルに書き込まれます。

ターミナル 
# ログアウトしても動作を続けさせる
nohup sleep 300 &
出力結果（例） 
student@ubuntu:~/linux-practice/ch10$ nohup sleep 300 &
[1] 1850
nohup: ignoring input and appending output to 'nohup.out'
student@ubuntu:~/linux-practice/ch10$

「出力を nohup.out に追記します」という案内が表示されます。このターミナルを閉じても、sleep 300 は最後まで動き続けます。

systemd ― バックグラウンドサービスを管理する仕組み

Ubuntu起動時にはPID 1として systemd というプロセスが立ち上がり、cronやsshdなどさまざまなサービス（バックグラウンドで動き続けるプログラム）を管理しています。サービスの状態は systemctl status <サービス名> で確認できます。

ターミナル 
# cronサービスの状態を確認する
systemctl status cron
出力結果（例） 
student@ubuntu:~/linux-practice/ch10$ systemctl status cron
● cron.service - Regular background program processing daemon
     Loaded: loaded (/usr/lib/systemd/system/cron.service; enabled; preset: enabled)
     Active: active (running) since Wed 2026-09-23 09:00:12 JST; 1h 2min ago
   Main PID: 512 (cron)
     Memory: 1.2M
     CGroup: /system.slice/cron.service
             └─512 /usr/sbin/cron -f
...（一部の行と最近のログは省略）
student@ubuntu:~/linux-practice/ch10$

先頭の ● が緑色なら正常に稼働中、Active: active (running) の行で稼働状況とMain PIDが分かります。出力が長い場合はページャー（less と同じ操作感）が開くことがあり、その場合は q で抜けます。WSLのUbuntu 24.04では通常systemdが有効ですが、無効な環境では sudo nano /etc/wsl.conf（第6章の nano・第9章の sudo）で [boot] セクションに systemd=true を追記し、PowerShellで wsl --shutdown してから開き直すと有効になります。

この章のまとめ

  • プログラムは静止したファイル、実行するとプロセスになりカーネルがPIDを割り当てる。起動した側が親プロセス、起動された側が子プロセス（PPID）。
  • ps は自分の端末のプロセスを、ps aux はシステム全体を、ps -ef はPPID付きで一覧表示する。
  • top はプロセスの状態をリアルタイム表示する。PでCPU順、Mでメモリ順に並び替え、qで終了する。
  • 末尾に&を付けるとバックグラウンド実行、Ctrl+Zでフォアグラウンドのジョブを一時停止できる。jobsで確認し、bg・fgで行き来する。
  • kill は既定でTERMシグナルを送る「終了のお願い」。-9（KILL）は応答しないときの最終手段で、乱用やPIDの指定ミスには注意が必要。
  • nohup はログアウト後もプロセスを動かし続け、systemctl status でsystemdが管理するサービスの状態を確認できる。

確認問題

  1. Q1. 「プログラム」と「プロセス」の違いを、PIDという言葉を使って説明してください。

    回答を表示

    プログラムはディスクに保存された、まだ動いていない実行可能ファイルです。プログラムを実行してメモリとCPU時間が割り当てられ、実際に動いている状態がプロセスです。カーネルは生まれたプロセス1つ1つに重ならない番号（PID）を割り振り、確認や終了はこのPIDを使って行います。

  2. Q2. sleep 100 & のあと jobs を実行すると [1]+ Running sleep 100 & と表示されました。この状態から、そのプロセスをフォアグラウンドに戻すには何と入力しますか。

    回答を表示

    fg と入力します。バックグラウンドで動いているジョブ（既定では直近のジョブ）がフォアグラウンドに呼び戻され、以後はそのプロセスが終わるまでターミナルが占有されます。

  3. Q3. kill コマンドが既定で送るシグナルは何ですか。それでプロセスが終了しない場合の最終手段は何で、どのような危険がありますか。

    回答を表示

    既定で送られるのはTERMシグナル（終了のお願い）です。プロセスが応答せず終了しない場合の最終手段は kill -9（KILLシグナル）ですが、プログラムが後片付けをする余地なく強制終了されるため、保存前のデータが失われることがあります。またPIDを打ち間違えると無関係のプロセスを終了させてしまう危険もあります。

  4. Q4. ターミナルを閉じても処理を動かし続けたいとき、どのコマンドを使いますか。標準出力はどこに書き込まれますか。

    回答を表示

    nohup を付けて実行します（例: nohup sleep 300 &）。ログアウト時に送られるHUPシグナルを無視するようになり、ターミナルを閉じても処理が続きます。標準出力を別途リダイレクトしていなければ、既定で nohup.out というファイルに追記されます。
