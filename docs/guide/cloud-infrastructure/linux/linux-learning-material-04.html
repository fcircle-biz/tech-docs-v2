ディレクトリ構造とパス

前章では、コマンドの書式や補完・履歴といった「入力の作法」を学びました。この章では、Linuxのファイルとディレクトリ（フォルダ）が全体としてどのように整理されているかを理解し、「自分が今どこにいるか」を確認しながら目的の場所へ移動する方法を身につけます。最後に、以降すべての章で使う練習用ディレクトリ linux-practice を作成します。

この章で学ぶこと

  • ルート「/」を頂点にした1本のディレクトリツリーの構造と、Windowsとの違いを説明できる
  • /home /etc /var /usr /bin /tmp /root など主要ディレクトリの役割を知る
  • pwd・ls（-l -a -h）で現在地とファイル一覧を確認できる
  • cd で移動し、絶対パスと相対パス（. .. ~）を使い分けられる
  • 練習用ディレクトリ ~/linux-practice を作成し、以降の章の作業場所として使えるようにする

4.1 ツリー構造とルート「/」

Linuxでは、パソコン内のすべてのファイルとディレクトリ（フォルダ）が、「/」（ルートディレクトリ、「スラッシュ」と読む）と呼ばれる1つの頂点から枝分かれする、1本の木（ツリー構造）として管理されています。USBメモリや追加のディスクをつないでも、新しいドライブとして現れるのではなく、このツリーのどこかの枝に「接続（マウント）」される形で取り込まれます。

ルート直下には、用途ごとに決められた名前のディレクトリが並んでいます。これは、第1章で触れたディストリビューションの多くが共通して採用しているLinuxの標準的な配置で、Ubuntuでも同じ考え方が使われています。

図1: ルート「/」から枝分かれするディレクトリツリー（抜粋）

flowchart TD ROOT["/"] --> HOME["/home"] ROOT --> ETC["/etc"] ROOT --> VARD["/var"] ROOT --> USR["/usr"] ROOT --> BIN["/bin"] ROOT --> TMP["/tmp"] ROOT --> ROOTDIR["/root"] HOME --> STUDENT["/home/student
（あなたのホーム）"] USR --> USRBIN["/usr/bin"] BIN -.->|シンボリックリンク| USRBIN

主要なディレクトリの役割を、代表的なものから見ておきましょう。

ディレクトリ 役割
/home 一般ユーザーごとの作業場所。/home/student のように、ユーザー名ごとのディレクトリが並ぶ。自分のファイルはここに置く。
/etc システム全体の設定ファイル置き場。ネットワーク設定やユーザー一覧（/etc/passwd、第9章で扱う）など。
/var 頻繁に中身が変化するデータの置き場。ログ（/var/log）やキャッシュなど。
/usr OSに付属するコマンドやアプリの本体、共有ライブラリなどの置き場。ls などの基本コマンドも、apt で追加したソフトも、ほとんどがここ（/usr/bin など）に入る。
/bin ls・cp など基本コマンドの実体が置かれるとされる場所（Ubuntu 24.04では実体は/usr/bin、詳細は下記）。
/tmp 一時ファイル置き場。再起動などで中身が消えても困らないファイルだけを置く。
/root 管理者ユーザー root 専用のホームディレクトリ（第9章）。一般ユーザーの /home/student とは別物。

Ubuntu 24.04では /bin は /usr/bin への「近道」

上の図で /bin から /usr/bin へ点線を引いたのはこのためです。以前は /bin と /usr/bin は別々のディレクトリでしたが、現在のUbuntuでは /bin は /usr/bin へのシンボリックリンク（Windowsのショートカットに近い仕組み。詳しくは第5章）になっていて、実体は1か所にまとまっています。そのため /bin/ls と /usr/bin/ls は同じファイルを指します。今は「見かけ上2つの名前がある」程度に覚えておけば十分です。

Windowsに慣れていると、この「ドライブ文字がない」という点に違和感があるかもしれません。

Windowsの「C:\」との違い

Windowsでは C:\（Cドライブ）・D:\ のように、ディスクごとに別々の木（ドライブ文字）が存在します。一方Linuxにはドライブ文字という概念がなく、どんなディスクや外部メディアも「/」から始まる1本の木のどこかの枝としてつながります。「Cドライブの中のDドライブ」のような発想はせず、常に「/」を起点に道をたどると考えてください。たとえば WSL では、Windows の C ドライブが /mnt/c という枝としてつながっています（ls /mnt/c で中身を見られます）。

4.2 ホームディレクトリとカレントディレクトリ

ツリーの中で、自分専用の作業場所として割り当てられているのがホームディレクトリです。ユーザー student のホームディレクトリは /home/student で、ターミナルを開くと最初はここに「立って」いる状態になります。このホームディレクトリには、~（チルダ）1文字で表せる特別な近道が用意されています。

そして、ターミナルで「今どこに立っているか」をカレントディレクトリ（作業ディレクトリ）と呼びます。ファイルを操作するコマンドの多くは、パスを省略すると「カレントディレクトリの中の」という意味で解釈されるため、この概念はこれから先ずっと重要になります。カレントディレクトリを確認するコマンドが pwd（print working directory、作業ディレクトリを表示する、の略）です。

見本: 今いる場所を確認します。

ターミナル 
# 今いる場所（カレントディレクトリ）を確認する
pwd
出力結果（例） 
student@ubuntu:~$ pwd
/home/student

~ が実際に何を指しているかは、echo（第3章）で確かめられます。

ターミナル 
# ~ はホームディレクトリの近道（別名）
echo ~
出力結果（例） 
student@ubuntu:~$ echo ~
/home/student

自分の環境ではホームの場所が違うことがある

本ガイドの出力例はユーザー名 student（ホーム /home/student）で統一しています。ただしMultipass（Mac）ではユーザー名が ubuntu 固定で、ホームは /home/ubuntu になります。WSL（Windows）ではプロンプトのホスト名部分が、自分のパソコンの名前（例: DESKTOP-XXXXXXX）になります。表示が違っても、自分の環境の名前に読み替えてください。

4.3 lsでファイル一覧を表示する

ls（list の略）は、第1章でも触れた「今いる場所の中身を一覧表示する」コマンドです。作ったばかりのユーザーのホームディレクトリには、まだ自分で作ったファイルが何もないため、オプションなしの ls では何も表示されません。

ターミナル 
# 今いるディレクトリの中身を一覧表示する
ls
出力結果（例） 
student@ubuntu:~$ ls
student@ubuntu:~$

「何もない」ように見えますが、実は名前が「.」（ドット）で始まるファイルがいくつか存在しています。これらは隠しファイル（ドットファイル）と呼ばれ、シェルの設定ファイルなど「普段は見えなくてよいが、必要になる情報」を置くのに使われる慣習です。隠しファイルも含めて表示するには -a（all）オプションを付けます。

ターミナル 
# 隠しファイルも含めて一覧表示する
ls -a
出力結果（例） 
student@ubuntu:~$ ls -a
.  ..  .bash_history  .bash_logout  .bashrc  .profile

.bashrc はbashの設定ファイル（第11章で編集します）、.profile はログイン時に読み込まれる設定ファイル、.bash_history はこれまで入力したコマンドの履歴（第3章の history コマンドの中身）です。また、一覧の先頭にある . と .. も一種の隠しファイル（正確にはディレクトリへの特殊な参照）で、詳しい意味は4.4節で説明します。環境によっては、.sudo_as_admin_successful（第2章で sudo を使うと作られる空のファイル）や.cache・.sshなども表示されますが、気にしなくて大丈夫です。

さらに詳しい情報が欲しいときは -l（long、長い形式）オプションを使います。オプションは組み合わせて指定でき、-l と -a を続けて書けば -la のように1つにまとめられます（第3章のオプションのまとめ方の復習です）。

ターミナル 
# 詳しい情報 (-l) と隠しファイル (-a) を同時に指定する
ls -la
出力結果（例） 
student@ubuntu:~$ ls -la
total 24
drwxr-x--- 2 student student 4096 Apr  1 10:00 .
drwxr-xr-x 3 root    root    4096 Apr  1 09:45 ..
-rw------- 1 student student  156 Apr  1 10:00 .bash_history
-rw-r--r-- 1 student student  220 Apr  1 09:45 .bash_logout
-rw-r--r-- 1 student student 3771 Apr  1 09:45 .bashrc
-rw-r--r-- 1 student student  807 Apr  1 09:45 .profile

1行ずつの意味を分解すると、次のようになります（.bashrc の行を例に、左から順に8つの情報が並んでいます）。

表示例 項目 意味
- 種類 -=ファイル、d=ディレクトリ、l=シンボリックリンク。
rw-r--r-- 権限 所有者・グループ・その他それぞれの読み書き実行の可否。詳しくは第9章で扱う。
1 リンク数 この実体を指している名前の数。ファイルは通常1。ディレクトリは、親から見た名前と自分の中の「.」で最低2になり、サブディレクトリが1つ増えるごとに（その中の「..」の分）1増える。上の例で ..（/home）が 3 なのは、中に student が1つあるため。
student 所有者 このファイルを持っているユーザー。
student グループ このファイルが属するグループ（第9章）。
3771 サイズ バイト単位のファイルサイズ。-h を付けると読みやすい単位になる（下記）。
Apr 1 09:45 更新日時 最後に中身が変更された日時。
.bashrc 名前 ファイル・ディレクトリの名前。

なお、1行目の total は、一覧にあるファイルが使うディスク容量の合計（1K単位）です。ディレクトリのサイズ 4096 は中身の合計ではなく、ディレクトリ自体の管理情報の大きさです。また、半年以上前に更新されたものは、時刻の代わりに年が表示されます（例: Apr 22 2024）。

バイト数のままだと大きなファイルは読みづらいので、-h（human-readable、人間が読みやすい形式）を付けると、4.0K・3.7K のように K・M・G 単位（1K＝1024バイト）に自動で変換されます。3つのオプションを合わせて -lah と書くのがよく使う組み合わせです。

ターミナル 
# -l -a -h をまとめて指定する（サイズを読みやすい単位にする）
ls -lah
出力結果（例） 
student@ubuntu:~$ ls -lah
total 24K
drwxr-x--- 2 student student 4.0K Apr  1 10:00 .
drwxr-xr-x 3 root    root    4.0K Apr  1 09:45 ..
-rw------- 1 student student  156 Apr  1 10:00 .bash_history
-rw-r--r-- 1 student student  220 Apr  1 09:45 .bash_logout
-rw-r--r-- 1 student student 3.7K Apr  1 09:45 .bashrc
-rw-r--r-- 1 student student  807 Apr  1 09:45 .profile

なお ls は、うしろにパスを指定すると、そこへ移動しなくても中身を確認できます。次のように別のディレクトリを覗いてみましょう。

ターミナル 
# 移動せずに /etc の中身を確認する
ls -l /etc
出力結果（例） 
student@ubuntu:~$ ls -l /etc
total 380
drwxr-xr-x   8 root root  4096 Apr  1 09:40 apt
-rw-r--r--   1 root root  3028 Apr  1 09:40 bash.bashrc
drwxr-xr-x   2 root root  4096 Apr  1 09:40 cron.d
-rw-r--r--   1 root root   756 Apr  1 09:40 hosts
drwxr-xr-x   3 root root  4096 Apr  1 09:40 ssh
...（以下省略。実際には100個以上のファイル・ディレクトリがある）

やってみよう 4-1: 主要ディレクトリを探検する

4.1節で紹介した主要ディレクトリの中身を、実際に ls で覗いてみましょう。何も変更しない、見るだけの実習です。

手順

  1. 1 ls -l /etc を実行し、どんな名前のファイル・ディレクトリが並んでいるか眺める。
  2. 2 ls -lh /var/log を実行し、ログファイルのサイズを確認する。先頭の文字が d の行と - の行、それぞれいくつあるか数えてみる。
  3. 3 ls -a /root を実行してみる。権限がなく中身を見られないはずなので、どんなメッセージが出るか確認する。
  4. 4 /etc と /var/log、どちらに大きいファイルが多かったか、気づいたことを1〜2行でメモする。

Permission denied と出ても慌てない

ls -a /root を実行すると、ls: cannot open directory '/root': Permission denied のようなメッセージが出るはずです。/root は管理者専用のディレクトリなので、一般ユーザーの student からは中身を見られないのが正常な動作です。権限の仕組みは第9章で詳しく学びます。今は「見えない場所もある」ことだけ覚えておけば十分です。

4.4 cdで移動する：絶対パスと相対パス

カレントディレクトリを移動するコマンドが cd（change directory の略）です。うしろに行き先のパス（経路）を指定します。特によく使う書き方を、記号の意味とあわせて先に一覧にしておきます。

書き方 意味
cd 引数なし。ホームディレクトリへ移動する。
cd ~ cd と同じく、ホームディレクトリへ移動する。
cd .. 1つ上（親）のディレクトリへ移動する。
cd - 直前にいたディレクトリへ戻る（行き来をトグルできる）。
cd /etc 指定したパス（ここでは /etc）へ移動する。

実際に順番に試してみましょう。ホームディレクトリからスタートします。

ターミナル 
# 絶対パスで /etc へ移動する
cd /etc
pwd
出力結果（例） 
student@ubuntu:~$ cd /etc
student@ubuntu:/etc$ pwd
/etc

プロンプトの ~ の部分が /etc に変わったことに注目してください。Ubuntuの標準設定では、プロンプトに現在のカレントディレクトリが常に表示されます。続けて、1つ上のディレクトリへ移動してみます。

ターミナル 
# 1つ上（親ディレクトリ）へ移動する
cd ..
pwd
出力結果（例） 
student@ubuntu:/etc$ cd ..
student@ubuntu:/$ pwd
/

/etc の親は / なので、ルートディレクトリに着きました。ここから cd - を使うと、直前にいた /etc に一発で戻れます。

ターミナル 
# 直前にいたディレクトリへ戻る
cd -
出力結果（例） 
student@ubuntu:/$ cd -
/etc
student@ubuntu:/etc$

cd - は移動先のパスを画面に表示してくれる点が、ほかの cd の書き方と違うところです。最後にホームディレクトリへ戻っておきましょう。

ターミナル 
# ホームディレクトリへ戻る（cd 単体でも cd ~ でも同じ）
cd ~
pwd
出力結果（例） 
student@ubuntu:/etc$ cd ~
student@ubuntu:~$ pwd
/home/student

絶対パスと相対パス

ここまでの cd /etc のように、「/」から始まり、今どこにいても同じ場所を指す書き方を絶対パスと呼びます。一方、..（1つ上）や .（自分自身）を使って、「今いる場所」からの道順で書く方法を相対パスと呼びます（cd etc のように名前だけを書く場合も相対パスです）。相対パスは「/」で始まりません。

たとえ話: 待ち合わせ場所の伝え方

絶対パスは「東京駅の丸の内中央口」のように、誰にとっても、どこから出発しても同じ場所を指す伝え方です。相対パスは「ここから2つ目の信号を右」のように、今どこにいるか（現在地）によって指す場所が変わる伝え方です。同じ「2つ目の信号を右」という指示でも、出発点が違えば着く場所はまったく別になります。cd で移動してカレントディレクトリが変わると、同じ相対パスでも行き先が変わる、という点を覚えておきましょう。

図2: 同じ /etc へ、絶対パスと相対パスの2通りでたどり着く

flowchart LR subgraph REL["相対パス: 現在地 /home/student から1段ずつたどる"] direction LR S["/home/student
（現在地）"] -->|"cd ..
1つ上へ"| H["/home"] -->|"cd ..
1つ上へ"| R["/"] -->|"cd etc"| E["/etc"] end subgraph ABS["絶対パス cd /etc: どこにいても / から下る"] direction LR R2["/"] -->|"etc へ"| E2["/etc"] end

. と .. は相対パスを組み立てる部品です。~ と - もあわせて、パスで使う記号をまとめておきます。

記号 意味
. 今いるディレクトリ自身
.. 1つ上（親）のディレクトリ
~ 自分のホームディレクトリの近道。シェルが /home/student に置き換えるので、~/linux-practice は今どこにいても同じ場所を指す（相対パスではない）
- 直前にいたディレクトリ（cdの引数として指定した場合）

絶対パスの例は、この節の最初に試した cd /etc そのものです。今度は同じ /etc へ、相対パスでたどり着いてみましょう。ホームディレクトリまで戻ってから、1つ上へのステップを積み重ねてみます。

ターミナル 
# 相対パス: 1つ上へ2回たどってから etc に入る
cd ~
cd ..
cd ..
cd etc
pwd
出力結果（例） 
student@ubuntu:~$ cd ~
student@ubuntu:~$ cd ..
student@ubuntu:/home$ cd ..
student@ubuntu:/$ cd etc
student@ubuntu:/etc$ pwd
/etc

/home/student から見て、1つ上が /home、さらに1つ上が / です。そこから etc に入れば /etc に着きます。書き方は違っても、絶対パスと相対パスはどちらも同じ場所に着いていることを確認してください。

.. は / でつなげて、1回の cd にまとめられます。../.. は「1つ上の、さらに1つ上」という意味なので、/home/student から cd ../.. を実行すると、一気にルート / まで上がります。

ターミナル 
# ホームに戻ってから、1回の cd で2つ上（ルート）へ移動する
cd ~
cd ../..
pwd
出力結果（例） 
student@ubuntu:/etc$ cd ~
student@ubuntu:~$ cd ../..
student@ubuntu:/$ pwd
/

相対パスがいちばん役立つのは、隣のディレクトリへ移るときです。たとえば /usr/share から、隣にある /usr/bin へは cd ../bin（1つ上の /usr に上がってから bin に入る）で移動できます。たとえば第5章以降で作る ~/linux-practice/ch05 から ~/linux-practice/ch06 へは、cd ../ch06 だけで移動できます（本ガイドの各章では、どこからでも確実に移動できるよう cd ~/linux-practice/ch06 の形で示します）。

ターミナル 
# /usr/share から、隣の /usr/bin へ移動する
cd /usr/share
cd ../bin
pwd
出力結果（例） 
student@ubuntu:/$ cd /usr/share
student@ubuntu:/usr/share$ cd ../bin
student@ubuntu:/usr/bin$ pwd
/usr/bin

最後に、存在しない場所へ移動しようとした場合の挙動も確認しておきましょう。

ターミナル 
# 存在しない場所へ移動しようとするとエラーになる
cd /nothing
出力結果（例） 
student@ubuntu:/usr/bin$ cd /nothing
bash: cd: /nothing: No such file or directory

移動が失敗しても、カレントディレクトリは変わりません（この例では /usr/bin のまま）。タイプミスをしたときによく出るエラーなので、落ち着いてパスを確認しましょう。

4.5 練習用ディレクトリを作る

ここまで学んだ cd・pwd を使って、これから先の章でずっと使う練習専用のディレクトリを作ります。ディレクトリを新しく作るコマンドは mkdir（make directory の略）です。使い方の詳細（複数階層をまとめて作るオプションなど）は第5章で学ぶので、ここではホーム直下に1つ作るだけの最小限の使い方だけを覚えれば十分です。

ターミナル 
# ホームディレクトリに linux-practice フォルダを作る
# （mkdir の詳しい使い方は第5章で学ぶ）
cd ~
mkdir linux-practice
cd linux-practice
pwd
出力結果（例） 
student@ubuntu:/usr/bin$ cd ~
student@ubuntu:~$ mkdir linux-practice
student@ubuntu:~$ cd linux-practice
student@ubuntu:~/linux-practice$ pwd
/home/student/linux-practice

やってみよう 4-2: 相対パスだけで目的地にたどり着く

~/linux-practice を起点に、相対パスだけを使って移動する練習です。手順1で起点へ移動したあとは、/ や ~ で始まる書き方は使わないでください。

手順

  1. 1 cd ~/linux-practice のあと pwd で現在地が /home/student/linux-practice であることを確認する。
  2. 2 そこから /etc へ、cd .. を何回か繰り返し、最後に cd etc として移動する。何回 cd .. すればよいか、実行する前に紙に書いて数えてみる。
  3. 3 pwd で /etc に着いたことを確認する。
  4. 4 cd - を実行すると、~/linux-practice ではなく直前にいた / に戻ることを確認する（cd - で戻れるのは1つ前の場所だけ）。最後に cd ~/linux-practice で練習用ディレクトリに戻っておく。

この章のまとめ

  • Linuxは「/」（ルート）を頂点にした1本のツリー構造。Windowsのようなドライブ文字はない。
  • /home・/etc・/var・/usr・/bin・/tmp・/root にはそれぞれ決まった役割がある。
  • pwdで現在地、ls（-l -a -h）でファイル一覧、cdで移動する。
  • 絶対パスは / から始まり常に同じ場所を指す。相対パスは / で始まらず、今いる場所からの道順で書く（名前や .（自分自身）・..（親）を組み合わせる）。
  • 練習用ディレクトリ ~/linux-practice を作成した。第5章以降はこの中で実習する。

確認問題

  1. Q1. 絶対パスと相対パスの違いを説明してください。

    回答を表示

    絶対パスは「/」（ルート）から始まる道順で、今どこにいても常に同じ場所を指します。相対パスは「/」で始まらず、今いる場所（カレントディレクトリ）からの道順を表すため、現在地が変わると同じ相対パスでも指す場所が変わります。

  2. Q2. cd .. と cd - の違いは何ですか。

    回答を表示

    cd .. は、今いる場所から見て1つ上（親）のディレクトリへ移動します。cd - は階層とは関係なく、直前にいたディレクトリへ戻ります（2回続けて実行すると元の場所と行き来できます）。

  3. Q3. ls だけでは表示されないファイルを表示するには、どのオプションを付ければよいですか。またそのようなファイルは何と呼ばれ、名前にはどんな特徴がありますか。

    回答を表示

    -a オプションを付けます。これらは隠しファイル（ドットファイル）と呼ばれ、名前がドットで始まるという特徴があります（例: .bashrc）。

  4. Q4. Ubuntu 24.04で /bin/ls と /usr/bin/ls が同じファイルを指すのはなぜですか。

    回答を表示

    Ubuntu 24.04では /bin が /usr/bin へのシンボリックリンクになっているためです。見かけ上は2つの名前がありますが、実体は /usr/bin 側の1か所にまとまっています。
