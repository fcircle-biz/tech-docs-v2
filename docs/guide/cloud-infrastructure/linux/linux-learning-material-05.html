ファイルとディレクトリの操作

第4章では、pwd・ls・cd でディレクトリの中を移動し、絶対パスと相対パスでファイルの場所を指定できるようになりました。この章では、いよいよファイルやディレクトリそのものを作成・複製・移動・削除する操作を身につけます。プロジェクト風のフォルダ（docs・src・backup）を実際に組み立てながら、touch・mkdir・cp・mv・rm・rmdir という「ファイル操作の基本コマンド」を一通り体験し、複数のファイルをまとめて扱うワイルドカードや、ファイルへの「参照」であるシンボリックリンクにも触れます。

この章で学ぶこと

  • touch で空ファイルを作成し、mkdir -p で階層ディレクトリを一度に作成できる
  • cp でファイル・ディレクトリをコピーし、上書き確認（-i）の必要性を理解する
  • mv による移動と名前変更が同じ仕組みであることを理解し、使い分けられる
  • ワイルドカード（* ? [ ]）とブレース展開で複数のファイルをまとめて操作できる
  • rm・rmdir でファイル・ディレクトリを削除し、復元できないことを理解して安全に扱える
  • シンボリックリンク（ln -s）の基本的な仕組みを説明できる

5.1 実習の準備 — touch と mkdir でプロジェクトの土台を作る

ファイルをコピーしたり削除したりする前に、まず「操作する対象」が必要です。この章では、架空のプロジェクトを想定した docs（ドキュメント）・src（ソースコード）・backup（バックアップ）という3つのフォルダを自分の手で組み立て、その中で操作を練習します。まずは第4章で作った ~/linux-practice の中に、この章専用のフォルダを作りましょう。

ターミナル 
# 第5章専用の練習フォルダを作って移動する
mkdir -p ~/linux-practice/ch05
cd ~/linux-practice/ch05

touch — 空ファイルの作成と更新日時の更新

touch は、指定した名前のファイルが無ければ中身が空のファイルを新規作成し、既にあれば内容はそのままで更新日時（タイムスタンプ）だけを今の時刻に進めるコマンドです。「とりあえず名前だけのファイルを用意したい」「ビルドツールにファイルが更新されたと知らせたい」といった場面で使います。

ターミナル 
# 空のファイルを新規作成する
touch memo.txt
ls -l memo.txt
出力結果（例） 
student@ubuntu:~/linux-practice/ch05$ touch memo.txt
student@ubuntu:~/linux-practice/ch05$ ls -l memo.txt
-rw-r--r-- 1 student student 0 Sep 23 10:00 memo.txt

先頭の -rw-r--r-- の部分は「誰が読み書きできるか」を表すパーミッションで、環境によっては -rw-rw-r-- と表示されることもあります（詳しくは第9章で学びます）。ここで注目してほしいのは、サイズが 0（中身が空）であることと、末尾に日時が記録されている点です。もう一度 touch を実行すると、内容は空のまま、日時だけが進みます。

ターミナル 
# 同じファイルにもう一度 touch する
touch memo.txt
ls -l memo.txt
出力結果（例） 
-rw-r--r-- 1 student student 0 Sep 23 10:03 memo.txt

mkdir と -p — ディレクトリの作成

mkdir（make directory）は新しいディレクトリを作るコマンドです。ただし、素の mkdir は親ディレクトリが実在する場合しか使えません。試しに、まだ存在しない sample の中に、さらに a/b という2階層を作ろうとしてみましょう。

ターミナル 
# sample がまだ無いのに、sample/a/b を一気に作ろうとする
mkdir sample/a/b
出力結果（例） 
mkdir: cannot create directory 'sample/a/b': No such file or directory

親の sample が存在しないため、その先の a/b を作る場所が無いというエラーです。ここで -p（parents）オプションを付けると、足りない親ディレクトリもまとめて作ってくれます。

ターミナル 
# -p を付けると、足りない親ディレクトリもまとめて作る
mkdir -p sample/a/b
ls -R sample
出力結果（例） 
sample:
a

sample/a:
b

sample/a/b:

ls -R は、ディレクトリの中身をサブディレクトリまで再帰的に一覧表示します。本ガイドで使う Ubuntu には、フォルダを木構造で見やすく表示する tree コマンドは標準で入っていません（インストール方法は第11章で扱います）ので、それまでは ls -R で代用します。

mkdir -p はやり直しても安全

素の mkdir は、既に同じ名前のディレクトリがあるとエラーになります。一方 mkdir -p は「無ければ作る、あれば何もしない」という動きをするため、同じコマンドを何度実行してもエラーになりません。作業手順をスクリプト化するときによく使われる書き方です。

それでは、この章で使うプロジェクト風フォルダを作りましょう。mkdir -p には、複数のパスを空白区切りで並べて渡せます。

ターミナル 
# myproject の中に docs・src・backup をまとめて作る
mkdir -p myproject/docs myproject/src myproject/backup

# docs と src には、練習用のファイルを touch で用意しておく
touch myproject/docs/README.md myproject/docs/notes.txt
touch myproject/src/app.py myproject/src/utils.py
ターミナル 
# 作った構成をサブディレクトリまで一覧表示する
ls -R myproject
出力結果（例） 
myproject:
backup  docs  src

myproject/backup:

myproject/docs:
README.md  notes.txt

myproject/src:
app.py  utils.py

backup はまだ空っぽです。この後の節で、docs と src のファイルをここへコピー・移動していきます。

5.2 ファイルをコピーする（cp）

作業前のファイルを保存しておきたいとき、同じ設定ファイルを別の場所でも使いたいとき——そんなときに使うのが cp（copy）です。cp コピー元 コピー先 という順番で指定します。ここからは myproject の中で作業するので、まず移動しておきましょう。

ターミナル 
# 以降の作業場所 myproject へ移動する
cd ~/linux-practice/ch05/myproject
ターミナル 
# README.md を backup にコピーする（コピー先がディレクトリなら同じ名前で入る）
cp docs/README.md backup/
ls backup
出力結果（例） 
README.md

コピー先にファイル名まで指定すると、コピーしながら別の名前を付けることもできます。

ターミナル 
# コピーしながら名前も変える（コピー先を「ディレクトリ/新しい名前」にする）
cp docs/notes.txt backup/notes-copy.txt
ls backup
出力結果（例） 
README.md  notes-copy.txt

-r — ディレクトリごとコピーする

cp は既定ではファイルしかコピーできません（ディレクトリはコピーの対象外です）。ディレクトリを丸ごとコピーしようとすると、次のように拒否されます。

ターミナル 
# -r を付けずにディレクトリをコピーしようとする
cp src backup
出力結果（例） 
cp: -r not specified; omitting directory 'src'

ディレクトリの中はさらにファイルやディレクトリを含んでいるかもしれないため、うっかり大量のファイルをコピーしてしまわないよう、-r（recursive、再帰的に）を明示的に付ける必要があります。

ターミナル 
# -r を付ければディレクトリごとコピーできる
cp -r src backup
ls backup
ls backup/src
出力結果（例） 
student@ubuntu:~/linux-practice/ch05/myproject$ ls backup
README.md  notes-copy.txt  src
student@ubuntu:~/linux-practice/ch05/myproject$ ls backup/src
app.py  utils.py

backup は既に存在するディレクトリなので、src はその中に（backup/src として）コピーされます。「コピー先が既存のディレクトリなら、その中へ元の名前のまま入る」という動きは、次の 5.3 で学ぶ mv でも共通です。

-i — 上書き前に確認する

cp は既定では、コピー先に同じ名前のファイルがあっても確認なしに上書きします。-i（interactive）を付けると、上書きしてよいか聞いてくれるようになります。

ターミナル 
# 既に backup にある README.md へ、もう一度コピーしてみる
cp -i docs/README.md backup/
出力結果（例） 
cp: overwrite 'backup/README.md'? y

y と入力して Enter を押せば上書き、n なら中止です。-i を付けなければ、この確認なしに黙って上書きされていたことになります。大事なファイルを扱うときの習慣として覚えておきましょう（5.5 節の警告カードで改めてまとめます）。

5.3 ファイルを移動する・名前を変える（mv）

mv（move）は一見 cp に似ていますが、決定的な違いがあります。コピーを作らず、元のファイルをそのまま別の場所・別の名前に付け替えるという点です。つまり実行後もファイルの数は増えません。

図1: cp と mv の違い — ファイルの数に注目

flowchart TD A["cp docs/notes.txt backup/"] --> B["docsに元のファイルが残る"] A --> C["backupに複製ができる
（ファイルが2つになる）"] D["mv docs/notes.txt backup/"] --> E["docsから無くなる"] D --> F["backupに移る
（ファイルは1つのまま）"]

もう1つ重要なのは、「移動」と「名前変更」が同じ mv コマンドで行われるということです。Windows や Mac では「移動」と「名前の変更」は別の操作ですが、Linux では「移動先のパスをどう書くか」が違うだけで、コマンドとしては同じ扱いになります。

使い方 コマンド例 結果
名前変更（リネーム） mv old.txt new.txt 同じ場所で old.txt が new.txt という名前になる
移動 mv file.txt backup/ file.txt が同じ名前のまま backup/file.txt になる
移動しつつ改名 mv file.txt backup/new.txt backup/new.txt という名前で移動する

実際に手を動かして確認しましょう。まずは同じ場所での名前変更です。

ターミナル 
# 同じ場所のまま名前を変える（＝リネーム）
mv docs/notes.txt docs/draft-notes.txt
ls docs
出力結果（例） 
README.md  draft-notes.txt

次に、その名前変更したファイルを backup へ移動します。

ターミナル 
# backup ディレクトリへ移動する（backupは既存ディレクトリなので中へ入る）
mv docs/draft-notes.txt backup/
ls docs
ls backup
出力結果（例） 
student@ubuntu:~/linux-practice/ch05/myproject$ ls docs
README.md
student@ubuntu:~/linux-practice/ch05/myproject$ ls backup
README.md  draft-notes.txt  notes-copy.txt  src

docs から消え、backup に現れました。最後に、mv はディレクトリ自体の名前変更にも使えることを確認しておきましょう。

ターミナル 
# ディレクトリの名前変更も同じ mv でできる
mv backup old-backup
ls
# 名前を元に戻しておく
mv old-backup backup
ls
出力結果（例） 
student@ubuntu:~/linux-practice/ch05/myproject$ ls
docs  old-backup  src
student@ubuntu:~/linux-practice/ch05/myproject$ ls
backup  docs  src

やってみよう 5-1: 自分の手でコピーと移動を練習する

myproject とは別の、自分だけの練習フォルダを使って touch・cp・mv を練習しましょう（この後の節では myproject を引き続き使うので、それとは別の場所で試すのがポイントです）。

手順

  1. 1 mkdir -p ~/linux-practice/ch05/my-practice で自分専用のフォルダを作り、cd で移動する。
  2. 2 touch todo.txt でファイルを作る。
  3. 3 cp todo.txt todo-backup.txt でコピーを作る。
  4. 4 mv todo.txt done.txt で元のファイルの名前を変える。
  5. 5 ls -l を実行し、todo-backup.txt と done.txt の2つが残っていて、todo.txt という名前はもう無いことを確認する。

5.4 まとめて操作する — ワイルドカードとブレース展開

ファイルが数個なら1つずつ cp・mv を打てば済みますが、数十個・数百個になると現実的ではありません。ここで役立つのがワイルドカード（記号でファイル名のパターンを表す仕組み）です。

*（アスタリスク）

0文字以上の任意の文字列に一致。*.txt は a.txt にも report99.txt にも一致する。

?（クエスチョン）

ちょうど1文字に一致。report?.txt は report1.txt に一致するが report10.txt には一致しない。

[ ]（角括弧）

角括弧内に挙げたいずれか1文字に一致。report[12].txt は1か2だけに一致する。

ここで初心者がよく誤解するのが、「* はコマンドが解釈している」という思い込みです。実際には、ls や rm などのコマンドは * という記号の意味をまったく知りません。コマンドを起動する前に、シェル（bash）がディレクトリの中身と照合してファイル名の並びに置き換えてから、コマンドへ渡しているのです。この順番はとても重要なので、図で確認しましょう。

図2: ワイルドカードが展開されてからコマンドに渡るまで

flowchart LR A["入力: ls docs/*.txt"] --> B["シェルが * をディレクトリの中身と照合する"] B --> C["一致した名前に置き換える
report1.txt report2.txt report3.txt"] C --> D["展開後のコマンドを実行
ls docs/report1.txt docs/report2.txt docs/report3.txt"] D --> E["lsコマンド自体は
＊という文字を見ていない"]

まずは、この後の練習で使うファイルをブレース展開で一度に作ってしまいましょう。{1..3} のように範囲を {開始..終了} と書くと、シェルが連番の文字列に展開します。

ターミナル 
cd ~/linux-practice/ch05/myproject/docs
# ブレース展開で report1.txt〜report3.txt を一度に作る
touch report{1..3}.txt
ls
出力結果（例） 
README.md  report1.txt  report2.txt  report3.txt

次に、ワイルドカードをいきなりコマンドで使わず、まず echo で展開結果を確かめる方法を紹介します。echo は受け取った文字をそのまま表示するだけの安全なコマンドなので、「実際に何が渡るか」を rm などで実行する前にリハーサルできます。

ターミナル 
# * が実際に何に展開されるか、実行前に確認する
echo *.txt
出力結果（例） 
report1.txt report2.txt report3.txt
ターミナル 
# ? は「ちょうど1文字」に一致する
echo report?.txt
# [ ] は指定した文字のどれか1文字に一致する
echo report[12].txt
出力結果（例） 
student@ubuntu:~/linux-practice/ch05/myproject/docs$ echo report?.txt
report1.txt report2.txt report3.txt
student@ubuntu:~/linux-practice/ch05/myproject/docs$ echo report[12].txt
report1.txt report2.txt

展開結果が意図どおりだと確認できたので、実際に cp へ渡してみましょう。

ターミナル 
# report1.txt と report2.txt だけを backup にコピーする
cp report[12].txt ../backup/
ls ../backup
出力結果（例） 
README.md  draft-notes.txt  notes-copy.txt  report1.txt  report2.txt  src

一致するファイルが無いとどうなる？

試しに一致するファイルが無いパターンで echo *.xyz のように実行すると、本ガイドの環境では展開できなかった *.xyz という文字列がそのまま表示されます。これをそのまま rm などに渡すと、「*.xyz という名前のファイルは無い」というエラーになります。エラーに表示される *.xyz は「その名前のファイル」ではなく、「一致するファイルが1つも無かった」ことを表しています。実行前に echo や ls で一致するファイルを確かめる習慣をつけましょう。

ブレース展開はファイル名の連番だけでなく、カンマ区切りの候補の列挙にも使えます。{docs,src,backup} のように書くと、それぞれの候補に展開されます。

ターミナル 
cd ..
# ブレース展開はディレクトリ名の列挙にも使える
echo {docs,src,backup}
出力結果（例） 
docs src backup

実はこれ、5.1 で使った mkdir -p myproject/docs myproject/src myproject/backup と同じ並びです。ブレース展開を知っていれば、mkdir -p myproject/{docs,src,backup} の1行でも同じ結果になります。ワイルドカードは「既にあるファイル名との一致」で展開されるのに対し、ブレース展開はファイルの有無に関係なく、書いた候補がそのまま文字列に展開されるという違いも覚えておきましょう。

5.5 ファイル・ディレクトリを削除する（rm・rmdir）

ここまでの cp や mv は、既存のファイルを上書きしない限り、間違えてもコピー元が残っていたり、もう一度 mv すれば元に戻せたりしました。しかし、これから学ぶ rm（remove）は違います。実行する前に、必ず次のカードを読んでください。

rm・cp・mv には「元に戻す」がありません

Windows や Mac の「ゴミ箱」に相当するものが rm にはありません。実行した瞬間にファイルは消え、復元する標準の方法はありません。特に rm -rf（-r で中身ごと、-f で確認なし）は、指定したディレクトリの中身を問答無用で削除する、最も注意が必要な組み合わせです。次のような書き方は本ガイドの実習でも絶対に打たないでください。

  • ・rm -rf / — システム全体を消そうとするコマンド。今日の Ubuntu には誤爆を防ぐ安全装置がありますが、頼ってはいけません。
  • ・rm -rf * — 「今どのディレクトリに居るか」を確認せずに打つと、カレントディレクトリの中身を丸ごと消してしまいます。
  • ・rm -rf ~ /tmp/work — 本来 ~/tmp/work のつもりでも、途中に空白が1つ入るだけで「~（ホームディレクトリ）」と「/tmp/work」という2つの別々の引数としてシェルに渡り、ホームディレクトリごと消えてしまいます。

さらに、5.2〜5.3 で見た cp と mv も、既定では上書き前の確認をしません。大事なファイルを扱うときは -i を付ける、実行前にコマンドをもう一度読み直す、この2つを習慣にしましょう。

削除には rm と rmdir の2つのコマンドがあり、対象と挙動が異なります。

コマンド 対象 中身が残っているディレクトリ
rm ファイル ファイル（複数指定も可） 対象外
rm -r ディレクトリ ディレクトリごと（中身も含む） 確認なしに削除できる
rmdir ディレクトリ 空のディレクトリのみ エラーになり削除できない

まずはファイル1つの削除です。rm は実行すると確認なしに即座に削除します。

ターミナル 
cd ~/linux-practice/ch05/myproject
# ファイルを1つ削除する（確認なしに即座に消える）
rm backup/notes-copy.txt
ls backup
出力結果（例） 
README.md  draft-notes.txt  report1.txt  report2.txt  src

確認なしはやはり怖いので、cp と同じように -i を付けてみましょう。

ターミナル 
# -i を付けると、削除前に確認してくれる
rm -i backup/report1.txt
ls backup
出力結果（例） 
student@ubuntu:~/linux-practice/ch05/myproject$ rm -i backup/report1.txt
rm: remove regular empty file 'backup/report1.txt'? y
student@ubuntu:~/linux-practice/ch05/myproject$ ls backup
README.md  draft-notes.txt  report2.txt  src

続いて、ディレクトリの削除です。rm だけではディレクトリを消せないことを、5.1 で作った sample で確認しましょう。

ターミナル 
cd ~/linux-practice/ch05
# -r を付けずにディレクトリを消そうとする
rm sample
出力結果（例） 
rm: cannot remove 'sample': Is a directory
ターミナル 
# -r を付ければディレクトリごと削除できる（確認なし）
rm -r sample
ls
出力結果（例） 
memo.txt  my-practice  myproject

（my-practice は、やってみよう 5-1 で作ったフォルダです）

最後に rmdir です。rm -r と違い、rmdir は空のディレクトリしか削除できません。中身が残っている docs で試してみましょう。

ターミナル 
cd myproject
# 中身が残っているディレクトリを rmdir で消そうとする
rmdir docs
出力結果（例） 
rmdir: failed to remove 'docs': Directory not empty

一方、空のディレクトリなら問題なく削除できます。rm -r より対象が限られる分、「うっかり中身ごと消す」事故を防げるのが rmdir の利点です。

ターミナル 
# 空のディレクトリなら rmdir で削除できる
mkdir empty-test
rmdir empty-test
ls
出力結果（例） 
backup  docs  src

5.6 シンボリックリンクの紹介（ln -s）

最後に紹介するのは ln -s で作るシンボリックリンクです。Windows の「ショートカット」や Mac の「エイリアス」に近い仕組みで、実体のファイルやディレクトリを指し示すだけの、中身を持たない特別なファイルを作ります。設定ファイルを複数のバージョンから切り替えたり、長いパスに短い別名を付けたりする場面で使われます。本章では、名前だけ覚えておけば十分です。

ターミナル 
# ln -s 参照先 リンク名 の順で、docs を指す docs-link を作る
ln -s docs docs-link
ls -l docs-link
出力結果（例） 
lrwxrwxrwx 1 student student 4 Sep 23 10:40 docs-link -> docs

先頭が l になっている点に注目してください。第4章で見た ls -l の先頭文字は、通常のファイルなら -、ディレクトリなら d でしたが、l（link）はシンボリックリンクを表します。末尾の -> docs が、参照先を示しています。docs-link の中身を見ると、参照先である docs の中身がそのまま見えます。

ターミナル 
# リンク経由で docs の中身を表示する
ls docs-link
出力結果（例） 
README.md  report1.txt  report2.txt  report3.txt

図3: シンボリックリンクの参照関係

flowchart LR L["docs-link
（シンボリックリンク）"] -. 参照する .-> D["docs
（実体のディレクトリ）"] D --> F1["README.md"] D --> F2["report1.txt など"]

リンクを消しても実体は消えない

docs-link はあくまで docs を指す「矢印」なので、リンクだけを rm で削除しても、参照先の docs とその中身はまったく影響を受けません。

ターミナル 
# リンクだけを消しても、参照先の docs は無事
rm docs-link
ls
出力結果（例） 
backup  docs  src

やってみよう 5-2: この章の練習ファイルを整理する

この章で使った myproject を、学んだコマンドで後片付けしてみましょう。「消す前に確認する」という安全な手順を意識してください。

手順

  1. 1 cd ~/linux-practice/ch05/myproject/docs へ移動し、echo report*.txt で削除対象を確認してから、rm -i report*.txt で1つずつ確認しながら削除する（README.md は残す）。
  2. 2 cd .. で myproject に戻り、ls -R backup で中身を確認する。
  3. 3 rm -r backup/src で、バックアップの中に残っている src のコピーだけをまとめて削除する。
  4. 4 最後に ls -R ~/linux-practice/ch05 を実行し、memo.txt・my-practice・myproject（docs・src・backup）がどんな状態になったか確認する。

この章のまとめ

  • touch は空ファイルの作成・更新日時の更新、mkdir -p は足りない親ディレクトリごと一度に作成する。
  • cp はファイルやディレクトリ（-r）をコピーする。既定では上書きを確認しないため、大事なファイルには -i を使う。
  • mv は移動にも名前変更にも使う同じコマンド。移動先が既存のディレクトリなら中へ移動し、存在しないパスを指定すれば名前が変わる。
  • ワイルドカード（* ? [ ]）とブレース展開（{...}）はシェルが実行前に展開する仕組みで、echo で展開結果を事前に確認できる。
  • rm に取り消しは無い。rm -rf は特に危険で、実行前に「今どこにいるか」「何を消そうとしているか」を必ず確認する。
  • シンボリックリンク（ln -s）は元のファイル・ディレクトリを指す「参照」で、リンクを消しても実体は残る。

確認問題

  1. Q1. cp と mv の違いを、実行後にファイルの数がどう変わるかという観点から説明してください。

    回答を表示

    cp はコピー元をそのまま残したうえで複製を作るため、実行後はファイルが2つになる。mv は元の場所から取り除いて新しい場所に付け替えるだけなので、実行後もファイルは1つのままである。

  2. Q2. 中身が残っている docs というディレクトリに対して rmdir docs を実行すると、どうなりますか。理由も含めて答えてください。

    回答を表示

    rmdir: failed to remove 'docs': Directory not empty というエラーになり、削除できない。rmdir は空のディレクトリしか削除できないコマンドで、中身が残っている場合は先にファイルを削除するか、中身ごと消せる rm -r を使う必要がある。

  3. Q3. ワイルドカードを使ったコマンド（例: rm *.log）を実行する前に、まず echo *.log を試すとよいのはなぜですか。

    回答を表示

    * などのワイルドカードは、コマンド自身ではなくシェルが実行前に実際のファイル名の並びへ展開してから渡している。echo で先に展開結果を表示すれば、rm のような取り消せないコマンドに「実際にどのファイルが渡るのか」を安全に確認してから実行できる。

  4. Q4. rm -rf ~ /tmp/work のようにスペースの入れ方を間違えると、なぜ大惨事になりますか。

    回答を表示

    本来 ~/tmp/work という1つのパスのつもりでも、間に空白が入ると ~（ホームディレクトリ）と /tmp/work という2つの別々の引数としてシェルに渡されてしまう。rm -rf は確認なしに両方を中身ごと削除するため、本来消すつもりのなかったホームディレクトリの中身までまとめて消えてしまう。
