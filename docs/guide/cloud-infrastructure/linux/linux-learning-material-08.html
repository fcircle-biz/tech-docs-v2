リダイレクトとパイプ

前章では、grep や cut でデータを加工する方法を学びました。実はコマンドの「入力」と「出力」は、キーボードや画面に固定されているわけではなく、自由に付け替えられます。結果をファイルに保存するリダイレクト、コマンドの結果を別のコマンドへ直接渡すパイプを使えるようになると、これまで学んだコマンドをつなぎ合わせて、より実務的な集計や自動化ができるようになります。

この章で学ぶこと

  • 標準入力・標準出力・標準エラー出力という3本の流れを説明できる
  • > >> < で出力先・入力元を切り替えられる
  • 2> でエラーメッセージだけを分けたり、2>&1 で標準出力とまとめたりできる
  • パイプ（|）でコマンドをつなぎ、tee・xargsを使い分けられる
  • ; && || でコマンドの成功・失敗に応じて処理を続けられる
  • アクセスログをパイプで集計し、結果をファイルに保存できる

8.1 標準入力・標準出力・標準エラー出力

まずこの章専用の作業ディレクトリを作って移動し、わざと存在しないディレクトリを指定してみましょう。

ターミナル 
# 第8章の作業ディレクトリを作って移動する
mkdir -p ~/linux-practice/ch08
cd ~/linux-practice/ch08
# 存在しないディレクトリを指定してみる
ls /nothing
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ ls /nothing
ls: cannot access '/nothing': No such file or directory
student@ubuntu:~/linux-practice/ch08$

画面に出たこのメッセージは、実は ls が出す「もう1種類の出力」です。Linuxのコマンドは実行されるとき、既定で3本の流れ（ストリーム）とつながっています。

標準入力（0）

コマンドが読み込む入力。既定はキーボードです。

標準出力（1）

コマンドの正常な結果。既定は画面です。

標準エラー出力（2）

コマンドのエラーメッセージ。既定は画面です。

図1: コマンドにつながる3本の流れ

flowchart LR KB["キーボードなど
（入力）"] -->|"0: 標準入力"| CMD["コマンド
（例: ls）"] CMD -->|"1: 標準出力
正常な結果"| OUT["画面"] CMD -->|"2: 標準エラー出力
エラーメッセージ"| ERR["画面"]

さきほどの ls /nothing は、標準出力（1）には何も渡さず、標準エラー出力（2）にだけメッセージを渡していました。既定では両方とも同じ画面に表示されるため見た目では区別できませんが、内部的には別々の流れです。この章で学ぶ記号を使うと、それぞれを別の場所に振り分けられます。

「0」「1」「2」という数字の正体

この数字はファイルディスクリプタ番号と呼ばれる、Linuxが入出力を区別するための番号です。厳密な仕組みを覚える必要はなく、「標準入力=0」「標準出力=1」「標準エラー出力=2」という対応だけ覚えておけば、この章のコマンドは十分理解できます。

access.log・sales.csv が無い場合は、この手順で作り直す

第7章のディレクトリが残っていない場合は、次を実行してから進めてください（中身は第7章とまったく同じです）。

ターミナル

cat > ~/linux-practice/ch07/access.log <<'EOF'

192.168.1.11 - - [01/Apr/2026:10:04:10 +0900] "GET /contact.html HTTP/1.1" 200 1536

8.2 リダイレクトで出力先・入力元を変える

標準出力の行き先を画面からファイルに変えることをリダイレクト（redirect）と呼びます。使う記号は >（上書き）と >>（追記）です。

ターミナル 
# echo の出力を画面ではなくファイルに書き込む
echo 1回目 > memo.txt
cat memo.txt
# もう一度 > で書き込むとどうなるか確認する
echo 2回目 > memo.txt
cat memo.txt
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ echo 1回目 > memo.txt
student@ubuntu:~/linux-practice/ch08$ cat memo.txt
1回目
student@ubuntu:~/linux-practice/ch08$ echo 2回目 > memo.txt
student@ubuntu:~/linux-practice/ch08$ cat memo.txt
2回目
student@ubuntu:~/linux-practice/ch08$

「1回目」はどこにも残らず、中身が丸ごと上書きされました。前の内容を残したいときは、末尾に追加する >> を使います。

ターミナル 
# >> は上書きせず末尾に追記する
echo 3回目 >> memo.txt
cat memo.txt
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ echo 3回目 >> memo.txt
student@ubuntu:~/linux-practice/ch08$ cat memo.txt
2回目
3回目
student@ubuntu:~/linux-practice/ch08$

「2回目」が残ったまま「3回目」が追加されました。> と >> が標準出力の行き先を変える記号だったのに対し、標準入力の元を変える記号が < です。前章で tr a-z A-Z < sales.csv を「お決まりの書き方」として使いましたが、ここで仕組みを整理します。

ターミナル 
# ファイル名を引数として渡す場合（ファイル名も表示される）
wc -l ~/linux-practice/ch07/access.log
# < でファイルの中身を標準入力として渡す場合（ファイル名は表示されない）
wc -l < ~/linux-practice/ch07/access.log
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ wc -l ~/linux-practice/ch07/access.log
8 /home/student/linux-practice/ch07/access.log
student@ubuntu:~/linux-practice/ch08$ wc -l < ~/linux-practice/ch07/access.log
8
student@ubuntu:~/linux-practice/ch08$

どちらも行数「8」を数えている点は同じですが、< を使った2つ目はファイル名を表示しません。wc から見ると、< で渡されたデータは「名前の無い、ただの標準入力」に見えるからです。tr のようにファイル名を引数として受け取れないコマンドにファイルの中身を処理させるには、この <（または8.4節で学ぶパイプ）でデータを渡します。

> は既存ファイルを問答無用で上書きする

command > report.txt を実行するとき、report.txt がすでに存在していても確認なしに中身が消えて上書きされます。特に危険なのは sort data.txt > data.txt のように読み込む元とリダイレクト先を同じファイルにしてしまうケースです。シェルは sort を起動する前に、> の準備としてファイルを空にしてしまうため、sort は空っぽのファイルを読むことになり、data.txt の中身がまるごと消えてしまいます。リダイレクト先は必ず別名のファイルにする習慣をつけましょう。うっかり上書きを防ぐ set -o noclobber（既存ファイルへの > を拒否する設定）もあるので、余裕があれば調べてみてください。

8.3 標準エラー出力だけを分ける

> は標準出力（1）だけをリダイレクトし、標準エラー出力（2）には影響しません。エラーメッセージだけを別に扱いたいときは、番号を付けた 2> を使います。8.1節の ls /nothing で試してみましょう。

ターミナル 
# 標準エラー出力だけを error.log に送る
ls /nothing 2> error.log
cat error.log
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ ls /nothing 2> error.log
student@ubuntu:~/linux-practice/ch08$ cat error.log
ls: cannot access '/nothing': No such file or directory
student@ubuntu:~/linux-practice/ch08$

1行目を実行しても画面には何も表示されません。ls /nothing の出力はすべて標準エラー出力だったため、そっくり error.log に移動したからです。エラーメッセージを完全に消したいときは、特殊ファイル /dev/null にリダイレクトします。書き込んだものをすべて消し去る「穴」のような存在で、何を送っても中身は増えません。第7章の find /etc で混ざっていた Permission denied を消してみましょう。

ターミナル 
# 権限エラーのメッセージだけを消して結果を見やすくする
find /etc -name "*.conf" 2>/dev/null

第7章では Permission denied の行が結果に混ざっていましたが、今回はそれが消え、/etc/wsl.conf のような見つかったファイルだけが表示されます。標準出力と標準エラー出力を両方まとめて同じ場所へ送りたいときは 2>&1 を使いますが、書く順序を間違えると意図どおりに動きません。存在するファイルと存在しないファイルを同時に指定して確かめてみましょう。

ターミナル 
# 正しい順序: 先に > でファイルを決め、その後 2>&1 で2番も同じ場所へ
ls memo.txt nothing.txt > result.txt 2>&1
cat result.txt
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ ls memo.txt nothing.txt > result.txt 2>&1
student@ubuntu:~/linux-practice/ch08$ cat result.txt
ls: cannot access 'nothing.txt': No such file or directory
memo.txt
student@ubuntu:~/linux-practice/ch08$

画面には何も表示されず、エラーメッセージと memo.txt（存在するファイル名）の両方が result.txt に入りました。今度は > と 2>&1 の順序を逆にしてみます。

ターミナル 
# 順序を逆にした場合
ls memo.txt nothing.txt 2>&1 > result2.txt
cat result2.txt
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ ls memo.txt nothing.txt 2>&1 > result2.txt
ls: cannot access 'nothing.txt': No such file or directory
student@ubuntu:~/linux-practice/ch08$ cat result2.txt
memo.txt
student@ubuntu:~/linux-practice/ch08$

今度はエラーメッセージが画面に表示され、result2.txt には正常な結果しか入っていません。リダイレクトは左から右へ順番に設定されるためです。2>&1 が先に来ると「2番を、今まさに1番がつながっている画面と同じ場所にする」という意味になり、その後で > result2.txt が1番だけをファイルに切り替えるため、2番は画面につながったまま取り残されます。「まず > でファイルを決め、その後で 2>&1」の順序を覚えておきましょう。bash独自の省略記法 &> を使うと > ファイル 2>&1 と同じ意味を順序を気にせず1つの記号で書けます（例: ls memo.txt nothing.txt &> result3.txt）。

ここまで登場したリダイレクト記号を一覧表にまとめます。

記号 意味
> 標準出力をファイルへ（上書き）
>> 標準出力をファイルへ（追記）
< ファイルの中身を標準入力へ
2> 標準エラー出力だけをファイルへ
2>&1 標準エラー出力を標準出力と同じ場所へ（順序注意）
&> 標準出力・標準エラー出力を両方まとめてファイルへ（上書き）
/dev/null 書き込んだ内容を捨てる特殊ファイル

やってみよう 8-1: リダイレクトを使い分ける

~/linux-practice/ch08 で、この章のリダイレクト記号を実際に動かして確認しましょう。

手順

  1. 1 echo test > a.txt を2回実行し、cat a.txt の中身が1行のままであること（上書きされること）を確認する。
  2. 2 echo test >> a.txt を2回実行し、今度は行数が増えることを確認する。
  3. 3 find /etc -name "*.conf" 2>/dev/null > conf-list.txt を実行し、結果がファイルに保存され画面には何も表示されないことを確認する。

8.4 パイプでコマンドをつなぐ

リダイレクトは「コマンドの出力」と「ファイル」をつなぐ仕組みでした。パイプ（|）は、あるコマンドの標準出力を、ファイルを経由せずそのまま次のコマンドの標準入力へつなぐ仕組みです。第7章の最後で先取りした、次のコマンドを正式に理解しましょう。

図2: パイプでコマンドがつながる様子（sales.csvの商品集計）

flowchart LR A["sales.csv
（9行のデータ）"] -->|"cut -d, -f3
（3列目を取り出す）"| B["item列だけ
item apple banana orange ..."] B -->|"sort
（同じ値を隣に集める）"| C["並べ替え済み
apple apple apple apple
banana banana item orange orange"] C -->|"uniq -c
（隣り合う値を数える）"| D["集計結果
4 apple / 2 banana
1 item / 2 orange"]
ターミナル 
# 3つのコマンドをパイプでつなぎ、商品ごとの件数を集計する
cut -d, -f3 ~/linux-practice/ch07/sales.csv | sort | uniq -c
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ cut -d, -f3 ~/linux-practice/ch07/sales.csv | sort | uniq -c
      4 apple
      2 banana
      1 item
      2 orange
student@ubuntu:~/linux-practice/ch08$

パイプが無ければ、cut の結果を一時ファイルに保存し、それを sort に読ませ、その結果をまた別のファイルに保存して uniq -c に読ませる、という3段階の作業が必要です。パイプはこの一時ファイルへの保存をすべて省略し、コマンドの出力をメモリ上で直接受け渡します。

結果を画面で確認しつつファイルにも保存したいときは、パイプの途中に tee を挟みます。配管のT字継手のように、1つの流れを「画面」と「ファイル」の2方向に分けるコマンドです。

ターミナル 
# 集計結果を画面に表示しつつ、item-count.txt にも保存する
cut -d, -f3 ~/linux-practice/ch07/sales.csv | sort | uniq -c | tee item-count.txt
# 保存されたファイルの中身も確認する
cat item-count.txt
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ cut -d, -f3 ~/linux-practice/ch07/sales.csv | sort | uniq -c | tee item-count.txt
      4 apple
      2 banana
      1 item
      2 orange
student@ubuntu:~/linux-practice/ch08$ cat item-count.txt
      4 apple
      2 banana
      1 item
      2 orange
student@ubuntu:~/linux-practice/ch08$

画面表示と cat item-count.txt の中身が一致しました。> だけを使うと画面表示が消えてファイルにしか残りませんが、tee なら両方を同時に得られます。

最後は xargs です。wc のような多くのコマンドは、ファイル名を標準入力の文字列としてではなく、引数として受け取ります。find の結果をそのままパイプで渡しても、相手のコマンドが「引数」として認識してくれるとは限りません。xargs は、パイプで受け取った文字列を次のコマンドの引数に変換して渡してくれます。

ターミナル 
# xargs練習用に小さなディレクトリとファイルを2つ用意し、まとめて行数を数える
mkdir xargs-demo
echo 1行目です > xargs-demo/a.txt
printf '1行目です\n2行目です\n' > xargs-demo/b.txt
find xargs-demo -name "*.txt" | xargs wc -l
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ find xargs-demo -name "*.txt" | xargs wc -l
 1 xargs-demo/a.txt
 2 xargs-demo/b.txt
 3 total
student@ubuntu:~/linux-practice/ch08$

find が見つけた a.txt・b.txt という文字列を、xargs が wc -l の引数に変換して渡したことで、2つのファイルそれぞれの行数と合計が数えられました。xargs を付けずに find xargs-demo -name "*.txt" | wc -l だけを実行すると、find の出力行数（＝見つかったファイルの個数である2）を数えるだけになり、ファイルの中身は見てくれません。（a.txt と b.txt の表示順は、環境によって入れ替わることがあります）

8.5 コマンドをまとめて実行する

ここまでは1つのコマンドの入出力を扱ってきましたが、複数のコマンドを1行にまとめて実行する方法も見ておきましょう。使う記号は ;・&&・|| の3つで、前のコマンドが成功したか失敗したかによって挙動が変わります。

まず最も単純な ; です。前のコマンドの成功・失敗にかかわらず、次のコマンドを実行します。

ターミナル 
# ; はどちらの結果でも次を実行する
echo 1つ目; echo 2つ目
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ echo 1つ目; echo 2つ目
1つ目
2つ目
student@ubuntu:~/linux-practice/ch08$

次は && です。「かつ」の意味で、左側のコマンドが成功したときだけ右側を実行します。ディレクトリ作成に成功したときだけ、その中へ移動してみましょう。

ターミナル 
# mkdir に成功したときだけ、続けて cd する
mkdir sample && cd sample
cd ..
# 同じディレクトリをもう一度作ろうとすると mkdir が失敗し、cd は実行されない
mkdir sample && cd sample
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ mkdir sample && cd sample
student@ubuntu:~/linux-practice/ch08/sample$ cd ..
student@ubuntu:~/linux-practice/ch08$ mkdir sample && cd sample
mkdir: cannot create directory 'sample': File exists
student@ubuntu:~/linux-practice/ch08$

1回目は mkdir が成功しプロンプトが ch08/sample に変わりましたが、2回目は同じ名前のディレクトリがすでにあるため mkdir が失敗し、cd は実行されずプロンプトも ch08 のままです。こうした「コマンドが成功したか失敗したか」を表す数値を終了ステータスと呼びます。詳しくは第13章で学びます。

最後は || です。「または」の意味で、左側のコマンドが失敗したときだけ右側を実行します。

ターミナル 
# 存在しないディレクトリへの移動に失敗したときだけメッセージを出す
cd nothing || echo "移動できませんでした"
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ cd nothing || echo "移動できませんでした"
bash: cd: nothing: No such file or directory
移動できませんでした
student@ubuntu:~/linux-practice/ch08$

cd nothing が失敗したため || の右側が実行され、メッセージが表示されました。まとめると、; は常に、&&（かつ）は左側が成功したときだけ、||（または）は左側が失敗したときだけ、右側のコマンドを実行します。

8.6 実習: アクセスログを集計してファイルに保存する

この章で学んだリダイレクトとパイプを組み合わせて、第7章で作った ~/linux-practice/ch07/access.log を集計し、結果をファイルに保存しましょう。

access.log が無い場合は、8.1節の手順で作り直してから進めてください。

まずはステータスコード別の件数です。9列目（ステータスコード）を取り出し、並べ替えて数え、件数の多い順に並べます。tee で画面に表示しながら status-count.txt に保存しましょう。

ターミナル 
# ステータスコード別の件数を、画面に表示しつつファイルにも保存する
cut -d' ' -f9 ~/linux-practice/ch07/access.log | sort | uniq -c | sort -rn | tee status-count.txt
出力結果（例） 
student@ubuntu:~/linux-practice/ch08$ cut -d' ' -f9 ~/linux-practice/ch07/access.log | sort | uniq -c | sort -rn | tee status-count.txt
      5 200
      2 404
      1 500
student@ubuntu:~/linux-practice/ch08$

次はアクセス数が多いIPアドレスです。今度は tee ではなく > を使い、結果をファイルにだけ保存してみましょう。

ターミナル 
# アクセス数上位のIPを求め、結果をファイルだけに保存する（画面には出ない）
cut -d' ' -f1 ~/linux-practice/ch07/access.log | sort | uniq -c | sort -rn > top-ip.txt
cat top-ip.txt

cut（列を選ぶ）→sort（隣に集める）→uniq -c（数える）→sort -rn（多い順に並べる）という同じ型のパイプで、対象の列番号を変えるだけで別の集計ができました。この型は実務のログ分析でも頻繁に使われます。

やってみよう 8-2: パイプと集計をもっと使う

~/linux-practice/ch08 で、この章のまとめとして次を試しましょう。

手順

  1. 1 cut -d' ' -f7 ~/linux-practice/ch07/access.log | sort | uniq -c | sort -rn | tee path-count.txt を実行し、パスごとのアクセス数を集計する（/index.html と /about.html がそれぞれ2回で最多のはず）。
  2. 2 find ~/linux-practice/ch08 -maxdepth 1 -name "*.txt" | xargs wc -l を実行し、この章で作ったテキストファイルの行数をまとめて確認する（-maxdepth 1 は、サブディレクトリの中までは探さず ch08 の直下だけを探す指定）。
  3. 3 余裕があれば mkdir ~/linux-practice/ch09 2>/dev/null && echo "ch09を作成しました" || echo "ch09は既にあります" を実行し、2>・&&・|| の組み合わせで結果に応じたメッセージが出せることを確認する（2回目に実行すると別のメッセージになります）。

この章のまとめ

  • コマンドには既定で標準入力（0）・標準出力（1）・標準エラー出力（2）の3本の流れがつながっている。
  • >（上書き）・>>（追記）・<（標準入力へ）でファイルとの入出力を切り替えられる。> は既存ファイルを問答無用で上書きするので注意する。
  • 2>・2>&1・&>・/dev/null で標準エラー出力を分けたり、標準出力とまとめたり、捨てたりできる。> file 2>&1 は順序が重要。
  • パイプ（|）はコマンドの出力を次のコマンドの入力へ直接つなぐ。tee は画面とファイルの両方へ、xargs はパイプの文字列を引数に変換する。
  • ; は常に、&& は成功したときだけ、|| は失敗したときだけ次のコマンドを実行する。
  • cut | sort | uniq -c | sort -rn は「列を選び→隣に集め→数え→多い順に並べる」実務でよく使う集計の型。

確認問題

  1. Q1. sort data.txt > data.txt を実行すると、なぜ data.txt の中身が空になってしまうのですか。

    回答を表示

    シェルは > によるリダイレクト先のファイルを、コマンドが実行される前に開いて空にします。そのため sort が data.txt を読もうとしたときには、すでに中身が空になっており、結果的にファイルの内容が消えてしまいます。読み込む元とリダイレクト先は別のファイルにする必要があります。

  2. Q2. cmd > out.txt 2>&1 と cmd 2>&1 > out.txt は結果が異なります。何が違いますか。

    回答を表示

    リダイレクトは左から右へ順番に設定されます。前者は先に標準出力を out.txt へ向け、その後で標準エラー出力を「標準出力と同じ場所（out.txt）」に向けるため、両方が out.txt に入ります。後者は先に標準エラー出力を「まだ画面を指している標準出力と同じ場所（画面）」に向けてしまい、その後で標準出力だけを out.txt に切り替えるため、標準エラー出力は画面に残ったままになります。

  3. Q3. パイプ（|）とリダイレクト（>）は、どちらも「出力の行き先を変える」点で似ていますが、何が違いますか。

    回答を表示

    リダイレクト（>）はコマンドの出力をファイルにつなぎます。パイプ（|）はコマンドの出力を、ファイルを経由せず別のコマンドの標準入力に直接つなぎます。

  4. Q4. mkdir backup && echo 成功 と mkdir backup || echo 失敗 は、それぞれどんなときに echo 側が実行されますか。

    回答を表示

    && は左側が成功したときだけ右側を実行するので、mkdir backup が成功した（ディレクトリを作れた）ときに echo 成功 が実行されます。|| は左側が失敗したときだけ右側を実行するので、mkdir backup が失敗した（すでに存在するなど）ときに echo 失敗 が実行されます。
