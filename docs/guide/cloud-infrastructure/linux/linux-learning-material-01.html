Linuxとコマンドラインとは

Linux（リナックス）は、世界中のWebサーバーやクラウド、Androidスマートフォンまでを支えているOSです。この章では、OSとは何か、Linuxとはどんなものか、そして「ターミナル」「シェル」「コマンド」がそれぞれ何を指すのかを整理します。まだコマンドは打ちません。第2章で環境を作る前に、まず全体像をつかみましょう。

この章で学ぶこと

  • OSの役割と、Linuxがどこで使われているかを説明できる
  • カーネルとディストリビューションの違いを理解し、Ubuntuの位置づけを知る
  • ターミナル・シェル・コマンドの関係を説明できる
  • GUIと比べたコマンドライン（CLI）の強みと注意点を知る
  • 本ガイドの学習環境と、コードブロックの読み方を理解する

1.1 OSとLinux

パソコンやスマートフォンには、必ず OS（Operating System、オペレーティングシステム）が入っています。OSは、CPU・メモリ・ディスクといったハードウェアと、ブラウザやエディタなどのアプリの間に立つ基本ソフトです。「どのアプリにメモリをどれだけ渡すか」「ファイルをディスクのどこに書き込むか」といった管理を、OSが一手に引き受けています。

代表的なOSには Windows、macOS、そして Linux があります。Linuxは、1991年にフィンランドの大学生だったリーナス・トーバルズ（Linus Torvalds）が作り始めたOSで、次のような特徴があります。

オープンソース

設計図にあたるソースコードが公開されていて、誰でも無料で使え、改良や再配布もできます。世界中の企業や開発者が開発に参加しています。

軽くて安定

画面（GUI）なしでも動かせるため軽く、何か月も止めずに動かし続ける用途に向いています。性能の低い機器でも動きます。

あらゆる場所で動く

サーバーからスマートフォン、家電、スーパーコンピューターまで、形を変えてさまざまな機器で動いています。

普段パソコンでLinuxを見かけることは少ないかもしれませんが、実は身の回りのあちこちで動いています。

  • サーバー・クラウド — Webサイトやアプリのサーバーの多くがLinuxです。AWS・Azure・Google Cloud で借りる仮想マシンも、Linuxを選ぶのが一般的です。
  • スマートフォン — Android は、中心部分にLinux（のカーネル）を使っています。
  • 家電・組込み機器 — 家庭用のWi-Fiルーター、テレビ、カーナビ、ネットワーク機器など。
  • スーパーコンピューター — 世界の性能ランキング上位500台は、すべてLinuxで動いています。
  • 開発環境 — Dockerのコンテナの中身や、Windowsの中でLinuxを動かす WSL もLinuxです。

重要ポイント

作ったWebアプリを公開する先のサーバー、Docker、クラウド……。ITエンジニアとして働くと、ほぼ確実にLinuxを操作する場面が出てきます。しかも、その操作の多くは画面をクリックするのではなく、文字でコマンドを打ち込む方法で行います。本ガイドは、その「コマンドでLinuxを操作する力」を基礎から身につけるための教材です。

1.2 カーネルとディストリビューション

実は「Linux」という言葉は、厳密にはOSの心臓部であるカーネル（kernel）だけを指します。カーネルは、ハードウェアを直接操作し、メモリの割り当て・ファイルの読み書き・プログラムの実行などを管理する、OSの中心部分です。

ただし、カーネルだけでは人間は操作できません。命令を受け付けるシェル、ファイルを一覧表示したりコピーしたりする各種コマンド、ソフトを追加するパッケージ管理の仕組みなども必要です。これらをカーネルとセットにして、すぐ使える形にまとめて配布しているものをディストリビューション（distribution）と呼びます。略して「ディストロ」とも言います。

たとえ話: エンジンと完成車

1.3 ターミナル・シェル・コマンドの関係

コマンドラインを学び始めると、ターミナル・シェル・コマンドという言葉がひんぱんに出てきます。似ているようで役割はまったく違うので、ここで整理しておきましょう。

ターミナル（端末）

文字を入力し、結果を表示する「窓」になるアプリです。Windows Terminal や macOS の「ターミナル」などがあります。自分では命令の意味を解釈しません。

シェル

入力された文字を読み取って解釈し、対応するプログラムを起動する「通訳」です。Ubuntu の標準のシェルは bash（バッシュ）です。

コマンド

実際に仕事をするプログラムです。ls（一覧表示）や cp（コピー）のように、1つ1つが決まった仕事をする小さな道具です。

たとえ話: レストラン

ターミナルは客席の注文用タブレット（注文を入力し、呼び出し状況を表示する画面）、シェルは注文を読み取って担当者に伝えるホール係、コマンドはそれぞれ得意料理を持つ料理人、カーネルはコンロや冷蔵庫を管理する厨房です。お客さん（ユーザー）がコンロに直接触れることはなく、必ずホール係と料理人を通して料理（結果）が届きます。

たとえば、ファイルの一覧を表示する ls コマンドを実行すると、裏側では次のようなやり取りが起きています。

図3: コマンド1行が実行されるまで

第2章で環境を準備したら、実際に次のように ls と入力するだけで、いま居る場所にあるファイルやフォルダの一覧が表示されます（下の例は、第4章以降でファイルやフォルダを作った後の表示です。作ったばかりの環境では何も表示されません）。今は眺めるだけで大丈夫です。

見本: いま居るディレクトリ（フォルダ）の中身を一覧表示するコマンドです。

ターミナル 
# いま居るディレクトリの中身を一覧表示する
ls
出力結果（例） 
student@ubuntu:~$ ls
linux-practice  memo.txt  photos
student@ubuntu:~$

出力例の1行目の student@ubuntu:~$ はプロンプトと呼ばれる「入力待ちの合図」で、その後ろに入力したコマンド（ls）が続いています。2行目が実行結果、3行目は次の入力を待っているプロンプトです。プロンプトの詳しい読み方は第3章で学びます。

1.4 なぜコマンドラインを学ぶのか

Windows や Mac では、アイコンやボタンをマウスで操作する GUI（Graphical User Interface）が当たり前です。これに対して、キーボードで文字の命令を打ち込んで操作する方式を CLI（Command Line Interface）、日本語でコマンドラインと呼びます。GUIがあるのに、わざわざCLIを学ぶ理由は何でしょうか。まずは両者を比べてみます。

観点 GUI（マウス操作） CLI（コマンド操作）
覚えやすさ 画面を見れば分かる。初心者に優しい コマンドを覚える必要がある
繰り返し作業 同じクリックを何度も繰り返す 1行やスクリプトで一気に処理できる
手順の記録・共有 スクリーンショットや文章で説明が必要 コマンドをそのままコピーして共有・再現できる
サーバーの操作 サーバーには画面が無いことが多い 離れた場所のサーバーも手元と同じように操作できる
動作の軽さ 画面の描画にメモリやCPUを使う 文字だけなので軽く、性能の低い機器でも動く

CLIの強みがいちばん分かりやすいのは繰り返し作業です。たとえば「旅行の写真300枚すべてのファイル名の先頭に trip_ を付ける」作業を比べてみましょう。

GUIの場合

OSの一括リネーム機能を使わない場合、1枚ずつ「右クリック → 名前の変更 → 先頭に trip_ を入力 → Enter」を300回繰り返します。途中で打ち間違えたり、1枚飛ばしたりしがちです。

CLIの場合

下の1行を実行するだけです。300枚でも3万枚でも、かかる手間は変わりません。同じ作業が来月も必要なら、この1行を保存しておけば済みます。

見本: 写真のファイル名をまとめて変更する1行です（まだ実行しなくて大丈夫です）。

ターミナル 
# .jpg ファイルすべての名前の先頭に trip_ を付ける
for f in *.jpg; do mv "$f" "trip_$f"; done

この書き方は第13章（シェルスクリプト入門）で学びます。今は「1行で何百回分もの作業を片づけられる」ことだけ覚えておけば十分です。ほかにも、CLIを学ぶ理由には次のようなものがあります。

  • サーバーは画面なしが基本 — GUIを入れないほうが軽く安全なため、サーバーはコマンドで操作するのが普通です。
  • 遠隔操作ができる — SSH（第12章）を使えば、データセンターやクラウドにあるサーバーを手元のターミナルから操作できます。
  • 作業を自動化できる — コマンドを並べたシェルスクリプト（第13章）で、定型作業を自動で実行できます。
  • 開発ツールの多くがCLI前提 — Git、Docker、クラウドの管理ツールなど、エンジニアが日常的に使う道具の多くはコマンドで操作します。

コマンドラインには「元に戻す」がありません

GUIのような確認ダイアログやゴミ箱は基本的に無く、Enterキーを押した瞬間にコマンドが実行されます。特にファイルの削除（第5章の rm）は、実行すると復元できません。本ガイドでは、危険な操作には必ずこの赤いカードで注意を付けます。実行する前にカードを読み、コマンドを見直してから Enter を押す習慣をつけましょう。

1.5 本ガイドの学習環境と進め方

本ガイドでは、利用者が多く情報も豊富な Ubuntu（ウブントゥ）24.04 LTS を使います。「24.04」は2024年4月に公開された版であること、「LTS（Long Term Support）」は長期サポート版で、標準で5年間セキュリティ更新が提供されることを表します。2026年4月には次の LTS である 26.04 も公開されていますが、本ガイドの手順と出力例は 24.04 に合わせています（24.04 の標準サポートは2029年まで続きます）。シェルは Ubuntu 標準の bash を使います。

Ubuntu 用のパソコンを新しく用意する必要はありません。いま使っているパソコンの中で、もう1台 Ubuntu のパソコンを動かすイメージで、次の方法を使います（手順は第2章で解説します）。

Windows の場合: WSL2

WSL2（Windows Subsystem for Linux 2）は、Windows に組み込まれている「Windows の中で Linux を動かす仕組み」です。インストール後は、Windows のスタートメニューから Ubuntu のターミナルをすぐに開けます。

Mac の場合: Multipass

Multipass（マルチパス）は、Ubuntu の開発元である Canonical 社が提供する、Ubuntu の仮想マシンを手軽に作れるツールです。コマンド1つで Ubuntu を起動し、その中に入って操作できます。

Mac のターミナルで直接試さないでください

macOS もLinuxと同じ「UNIX系」のOSなので、Mac の「ターミナル」でも ls などのコマンドが動きます。ただし macOS は Linux ではなく BSD系 のOSで、同じ名前のコマンドでもオプションや出力が違うことがあります。本ガイドの実習は、必ず Multipass で起動した Ubuntu の中で行ってください。

本ガイドの表記ルール

第2章以降は、コマンドを実際に入力しながら進めます。コードブロックなどの読み方をここで確認しておきましょう。

表記 意味
「ターミナル」ブロック そのままコピーして実行できるコマンドです。右上のボタンでコピーできます。貼り付けてすぐ実行できるよう、先頭に $ は付けていません。
「ターミナル（Mac）」「PowerShell（管理者）」ブロック Ubuntu の中ではなく、Mac のターミナルや Windows の PowerShell で実行するコマンドです（主に第2章で使います）。
# で始まる行 コメント（説明文）です。シェルは # 以降を無視するので、コマンドと一緒に貼り付けても問題ありません。
「出力結果（例）」ブロック 実行したときの表示例です。日時やファイルサイズ、ユーザー名などは環境によって変わります。
student@ubuntu:~$ 出力例で使うプロンプトです。ユーザー名を student、コンピューター名を ubuntu として表記しています。実際の画面には、自分の環境のユーザー名とコンピューター名が表示されます（第2章で確認します）。
~/linux-practice 実習用の練習ディレクトリです。第4章で作成し、以降の章の実習はこの中で行います。

読むだけでなく、必ず手を動かす

コマンドは読むだけでは身につきません。第2章以降は、コードブロックのコマンドを必ず自分のターミナルで実行し、「出力結果（例）」と見比べてください。コピーに慣れてきたら、あえて手で打ってみるのも効果的です。打ち間違えてエラーを見ることも、立派な練習になります。

やってみよう 1-1: 第2章に向けて準備する

まだコマンドは打ちません。自分のパソコンを確認して第2章で使う方法を決め、この章の内容を自分の言葉で整理しておきましょう。

手順

  1. 1 自分のパソコンのOSとバージョンを確認する。Windows は「設定 → システム → バージョン情報」で、Windows 11 か、Windows 10 ならバージョン 22H2 以降かを確認します。Mac は画面左上のアップルメニュー →「この Mac について」で、macOS のバージョンとチップ（Apple M シリーズか Intel か）を確認します。
  2. 2 第2章で使う方法を決める（Windows → WSL2、Mac → Multipass）。
  3. 3 身の回りでLinuxが動いているものを3つ挙げてみる。
  4. 4 「ターミナル」「シェル」「コマンド」の違いを、1.3節のレストランのたとえを使って一言ずつ説明してみる。

この章のまとめ

  • OSはハードウェアとアプリの間で資源を管理する基本ソフト。Linuxはオープンソースで、サーバー・クラウド・Android・家電などで広く使われている。
  • 厳密な「Linux」はカーネル（OSの心臓部）。カーネルにシェルやコマンドなどを組み合わせて配布したものがディストリビューションで、Ubuntu は Debian 系の代表格。
  • ターミナル＝入力と表示の窓、シェル＝コマンドを解釈する通訳（bash）、コマンド＝実際に仕事をするプログラム。
  • CLIはサーバー操作・自動化・手順の共有に強い。ただし「元に戻す」が無いので、実行前にコマンドを見直す。
  • 本ガイドは Ubuntu 24.04 LTS（Windows は WSL2、Mac は Multipass）と bash で学ぶ。

確認問題

  1. Q1. 厳密な意味での「Linux」は、OSのどの部分を指しますか。また、ディストリビューションとは何ですか。

    回答を表示

    ハードウェアを直接管理するOSの心臓部であるカーネルを指します。ディストリビューションは、カーネルにシェル・各種コマンド・パッケージ管理の仕組みなどを組み合わせ、すぐ使える形にまとめて配布したものです（例: Ubuntu、Debian、RHEL）。

  2. Q2. ターミナル・シェル・コマンドの役割を、それぞれ説明してください。

    回答を表示

    ターミナルは文字を入力し結果を表示する「窓」となるアプリです。シェルは入力された文字を解釈して、対応するプログラムを起動する「通訳」です（Ubuntu の標準は bash）。コマンドは ls や cp のように、実際に仕事をするプログラムです。

  3. Q3. サーバーの管理でコマンドライン（CLI）が使われる理由を2つ挙げてください。

    回答を表示

    たとえば次のうち2つです。「サーバーは軽さと安全のため画面（GUI）を入れないことが多い」「SSHで離れた場所のサーバーを操作できる」「繰り返し作業をスクリプトで自動化できる」「手順をテキストで正確に共有・再現できる」。

  4. Q4. 本ガイドの「ターミナル」ブロックのコマンドに、先頭の $ が付いていないのはなぜですか。

    回答を表示

    コピーしてそのまま貼り付け、実行できるようにするためです。$ はプロンプト（入力待ちの合図）の一部で、コマンドではありません。一緒に貼り付けると、シェルが $ をコマンドだと思って「command not found」（コマンドが見つからない）というエラーになります。
