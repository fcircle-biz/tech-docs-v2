3つのPrimitive: Choice / Score / Noul

Jev の Question は、Choice・Score・Noul という3種類の Primitive のいずれかで組み立てます。この章では、公式仕様に沿ってそれぞれの criteria の形と返却フィールドの違いを理解し、判断したい内容に応じてどの Primitive を選ぶべきかを判断できるようになります。

この章で学ぶこと

  • Question の共通構造（ID・type・instructions・criteria）を説明できる
  • Choice / Score / Noul の返却フィールドの違いを説明できる
  • 判断内容に応じて3つの Primitive を使い分けられる
  • Noul の 0.5 が「中程度」ではなく「どちらとも言えない」を意味することを理解する

4.1 Question の共通構造

Choice・Score・Noul は見た目も返り値も異なりますが、Question として組み立てるときに必要な要素は共通しています。公式ドキュメントは、どの Primitive でも次の4つの要素で1つの Question が構成されると説明しています。

要素 役割 必須
ID 回答を識別するために自分で決めるキー。例: refund_requested 必須
type choice・score・noul のいずれか 必須
instructions State に対して何を判断してほしいかを書く質問文 必須
criteria 回答として取り得る選択肢・段階の定義 Choice・Score は必須、Noul は任意

この4要素のうち、criteria の形が3つの Primitive で大きく異なります。Choice は「選択肢名 → 説明」のマップ、Score は「低い段階から高い段階の順に並べた配列」、Noul は「省略可能」——この違いを、次の節から順に見ていきます。

4.2 Choice — 選択肢から1つ選ぶ

Choice は、あらかじめ用意した順序を持たない固定の選択肢から1つを選ぶ Primitive です。「どのチームが対応すべきか」「どの言語で書かれたコードか」のように、答えが有限個のカテゴリに分かれる判断に向いています。

Choice の criteria は、選択肢名をキーにしたマップ（辞書）です。それぞれのキーに対して、その選択肢が何を意味するかを説明する文字列を対応させます。

問い合わせ内容から担当部署を振り分ける Question は、次のように書けます。

Choice の Question 例 
{
  "type": "choice",
  "instructions": "この問い合わせは、どの部署が対応すべきですか？",
  "criteria": {
    "billing": "請求・支払い・返金に関する内容",
    "technical": "エラーや不具合、設定方法に関する内容",
    "sales": "見積もりや契約、新規導入に関する内容"
  }
}

返ってくる answer には choice・probabilities・confidence の3つが含まれます。

Choice の回答例（answers.department 相当） 
{
  "type": "choice",
  "choice": "technical",
  "confidence": 0.78,
  "probabilities": { "technical": 0.85, "billing": 0.15, "sales": 0.0 }
}

choice は最も確率の高い選択肢名、probabilities は全選択肢の確率分布（合計は必ず1.0）、confidence は0〜1の確信度です。この数値、実は第1章で見たレスポンス例とまったく同じです。あのとき先取りして見た例は、Choice の典型的な返り値だったのです。

Choice の主な利用例

問い合わせのカテゴリ分類、ユーザー入力の意図（Intent）分類、担当部署の判定、商品カテゴリの分類など、「順序のない固定の選択肢から1つを選ぶ」判断全般に使えます。

4.3 Score — ルーブリックで段階評価する

Score は、あらかじめ定義した段階（ルーブリック）のどこに位置するかを評価する Primitive です。Choice が「並べ替えのできないカテゴリ」を扱うのに対し、Score は弱い→強い、低い→高いという1本の尺度上の位置を扱います。

Score の criteria は、低い段階から高い段階の順に並べた配列です。各段階の番号は配列内の位置（0始まり）で決まり、最小2段階・最大10段階まで指定できます。

バグ報告の重大度を3段階で評価する Question の例です（公式ドキュメントの例）。

Score の Question 例 
{
  "type": "score",
  "instructions": "報告された問題はどれくらい深刻ですか？",
  "criteria": [
    "見た目だけの問題。機能には影響しない",
    "機能が壊れているが、回避策がある",
    "回避策がない、業務を止めてしまう問題"
  ]
}

返ってくる answer には score・legend・probabilities・confidence の4つが含まれます。

Score の回答例（answers.bug_severity 相当） 
{
  "type": "score",
  "score": 1.43,
  "confidence": 0.35,
  "legend": { "0": "見た目だけの問題", "1": "機能が壊れているが回避策あり", "2": "回避策がない問題" },
  "probabilities": { "0": 0.0, "1": 0.57, "2": 0.43 }
}

重要ポイント: score は整数とは限らない

score は、各段階の確率（probabilities）を段階番号で重み付け平均した位置です。上の例では 0 × 0.0 + 1 × 0.57 + 2 × 0.43 = 1.43 となり、レベル1とレベル2の中間に位置しています。設定した段階そのものの値だけでなく、段階と段階の間の小数（例: 1.43 のような値）が返ることがある——これは仕様であり、不具合ではありません。

Score の主な利用例

緊急度、リスクの大きさ、顧客満足度、技術レベル、品質評価など、「弱い〜強い」「低い〜高い」という1本の尺度で捉えられる判断に使えます。

4.4 Noul — 真偽を確率で判定する

Noul は、真偽（Yes / No）を判定する Primitive です。返ってくるのは noul という0〜1の単一の数値だけで、これは「回答が Yes である確率」を表します。1に近いほど強い Yes、0に近いほど強い No です。

criteria は Choice・Score と違い任意（Optional）です。省略した場合は instructions の文だけで判定されます。指定する場合は、true・false それぞれに判定の手がかりとなる説明文を対応させます。

返金要求かどうかを判定する Question の例です。

Noul の Question 例 
{
  "type": "noul",
  "instructions": "顧客は返金を要求していますか？"
}

「先週届いた商品が思っていたのと違ったので、返金してほしいです」という State に対する回答例です。

Noul の回答例（answers.refund_requested 相当） 
{
  "type": "noul",
  "noul": 0.97
}

0.97 は1に非常に近いため、強い Yes——「返金要求である可能性が高い」と読み取れます。多くの実装では、この noul の値をそのまま使わず、しきい値（例: 0.5以上なら Yes 扱い）で真偽値に変換してから使います。

注意: noul の 0.5 は「中程度」ではない

公式ドキュメントは、0.5付近の値について「モデルが Yes と No に同じくらいの確率を与えている（the model gives yes and no similar probability）」と説明しています。Score でいう「中間の強さ」ではなく、「Yes かもしれないし No かもしれない、どちらとも言えない」というモデルの迷いを表す値です。noul は Yes である確率そのものであり、Yes の強さの度合いではありません。

たとえば「この商品、正直ちょっと期待外れでした」という一文だけを State にして同じ Question を投げると、noul: 0.52 のような値が返ることがあります。これは「52%くらいの強さで返金を求めている」という意味ではなく、返金要求と読み取れる根拠も、そうでない根拠も同じくらいあるという、判定そのものの難しさを表しています。

Noul の主な利用例

個人情報を含むか、返金要求か、クレームか、セキュリティリスクを含むかなど、「Yes か No か」という明確な二択の判定に使えます。

4.5 使い分けの指針

ここまで見た3つの Primitive を、「判断したい内容」を軸に整理すると、次のように使い分けられます。

判断したい内容 選ぶ Primitive 返る値
順序のないカテゴリから1つ選びたい（例: 担当部署はどこか） Choice choice・probabilities・confidence
弱い〜強いのスペクトラム上の位置を知りたい（例: 緊急度はどれくらいか） Score score・legend・probabilities・confidence
明確な Yes/No を判定したい（例: 個人情報を含むか） Noul noul

迷ったときは、次のように自問しながら3択に絞り込めます。

flowchart TD A["判断したい内容"] --> B{"順序のないカテゴリから1つ選ぶ？"} B -->|はい| C["Choice"] B -->|いいえ| D{"弱いから強いまでの尺度上の位置を測る？"} D -->|はい| E["Score"] D -->|いいえ| F{"明確なYes/Noを判定する？"} F -->|はい| G["Noul"]

まず「何を1文で聞きたいか」を言葉にし、それから Primitive を選ぶ——この順番を守ることが、次章以降で実際にリクエストを組み立てるときの出発点になります。

やってみよう 4-1: 5つの判断要件に合う Primitive を選ぶ

次の5つの要件それぞれについて、Choice・Score・Noul のどれを使うべきかを考え、criteria の中身まで下書きしてみましょう。「順序のないカテゴリか」「スペクトラム上の位置か」「明確な Yes/No か」の3つの問いが判断の助けになります。

要件

  1. 1 問い合わせの文面が「バグ報告」「機能要望」「使い方の質問」のどれに当たるかを判定したい。
  2. 2 サポートチケットの文章から、顧客がどれくらい強い怒りを感じているかを段階的に評価したい。
  3. 3 レビューコメントにクレジットカード番号やメールアドレスなど、個人情報が含まれているかを判定したい。
  4. 4 問い合わせメッセージが「交換」を求めているのか「返金」を求めているのか、それとも「どちらでもない」のかを判定したい。
  5. 5 デプロイ後の障害報告が、今すぐ対応が必要な緊急事態かどうかを判定したい。

解答の目安

  • 1. Choice — criteria: bug_report／feature_request／how_to_question の3キーにそれぞれ説明文。
  • 2. Score — criteria（低い順の配列）: 「穏やかで中立的な言い回し」→「不満はあるが冷静」→「強い言葉や感嘆符を伴う明確な怒り」。
  • 3. Noul — instructions: 「個人を特定できる情報が含まれていますか？」（criteria は省略可）。
  • 4. Choice — criteria: exchange／refund／neither の3キー。
  • 5. Noul — instructions: 「この障害は今すぐ対応が必要な緊急事態ですか？」。

理解度確認クイズ

  1. Q1. Choice・Score・Noul は、それぞれ何というフィールド名の値を返しますか？

    回答を表示

    Choice は choice・probabilities・confidence。Score は score・legend・probabilities・confidence。Noul は noul のみです。

  2. Q2. ある Noul の Question に noul: 0.5 という結果が返ってきました。これは「そこそこ Yes」という意味でしょうか？正しい解釈を説明してください。

    回答を表示

    誤りです。noul の 0.5 は「Yes である確率も No である確率も同じくらい」、つまりモデルが判定に迷っている状態を表します。中程度の強さの Yesではなく、どちらとも言えないという意味です。

  3. Q3. Score の Question で3段階の criteria（0, 1, 2）を設定したのに、score: 1.43 という小数が返ってきました。これは異常な結果ですか？

    回答を表示

    異常ではありません。score は各段階の確率を段階番号で重み付け平均した位置なので、段階と段階の中間の小数になることがあります（例: 0×0.0 ＋ 1×0.57 ＋ 2×0.43 = 1.43）。整数だけが返ると期待しないでください。

  4. Q4. 「この商品レビューが日本語・英語・その他のどの言語で書かれているか」を判定する場合と、「このコメントは誹謗中傷を含むか」を判定する場合、それぞれどの Primitive を使うべきですか？理由も答えてください。

    回答を表示

    言語判定は Choice（japanese／english／other という順序のない固定の選択肢から1つを選ぶため）。誹謗中傷を含むかは Noul（含む／含まないという明確な Yes/No の判定のため）です。
