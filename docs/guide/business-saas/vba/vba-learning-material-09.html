第9章 所要時間: 約90分

ブックとワークシートの操作

第8章までは、「売上明細」シートという1枚のシートの中で、セルを読み書きし、条件分岐や繰り返しを組み合わせて処理を書いてきました。しかし実際の業務では、集計結果を別のシートに書き出したり、月ごとのバックアップを別ファイルとして残したりと、シートやブックそのものを操作する場面が数多くあります。この章では、Excelの操作対象を1段上の階層である「ブックとワークシート」まで広げ、シートの追加・削除、複数のブックの参照、ブックを開く・保存する・閉じるといった操作をVBAで行えるようになることを目指します。

この章で学ぶこと

  • WorkbookとWorksheetを参照し、シート名・インデックスの違いを説明できる
  • シートの追加・名前変更・コピー・削除をマクロで行える
  • ThisWorkbook・ActiveWorkbook・Workbooks("...")の違いを説明し、使い分けられる
  • ブックを開く・保存する・閉じる処理が書ける
  • シートの存在を事前に確認し、エラーにならない安全な処理が書ける

9.1 オブジェクト階層をもう一度整理する

第1章で、Excelの操作対象は Application（Excel本体）→ Workbook（ブック）→ Worksheet（シート）→ Range（セル）という入れ子構造になっていることを学びました。第8章までは、この構造のうち「シートの中のセル」だけを扱ってきましたが、本章ではいよいよ一段上の「ブックとシート」そのものを操作します。まずは、VBAの命令に繰り返し出てくる「集まり」という考え方を整理しておきましょう。

複数形 ＝ 集まり（コレクション）

Workbooks（開いている全ブック）や Worksheets（ブック内の全シート）のように、末尾に s が付く名前は「同じ種類のものの集まり」を表します。

単数形 ＝ そのうちの1つ

Workbook（1つのブック）や Worksheet（1枚のシート）のように、集まりから取り出した個々のものを指すときは単数形になります。

複数形（集まり） 単数形（1つ） 意味
Workbooks Workbook 開いている全ブック ／ そのうちの1つのブック
Worksheets Worksheet ブック内の全シート ／ そのうちの1枚のシート

この2組の関係を、さくら文具株式会社の「売上管理.xlsm」に当てはめて図にすると、次のようになります。

flowchart TD A["Application
（Excel本体）"] --> B["Workbooks
（開いている全ブックの集まり）"] B --> C["Workbook
（売上管理.xlsm）"] C --> D["Worksheets
（ブック内の全シートの集まり）"] D --> E["Worksheet
（売上明細）"] D --> F["Worksheet
（集計）"] D --> G["Worksheet
（帳票）"] E --> H["Range
（A1、E2:E99など）"]

図の説明: 「集計」は本章で新しく追加するシート、「帳票」は第14章で追加するシートです。VBAでは、まずWorkbooksやWorksheetsという集まりの中から、名前や位置を指定して目的の1つを取り出す、という考え方で対象を指定します。

では、Worksheets という集まりの中から、目的の1枚をどうやって選べばよいのでしょうか。次の9.2で、3つの指定方法を見ていきます。

9.2 ワークシートの参照方法

Worksheets という集まりから1枚のシートを取り出す方法は、大きく3通りあります。それぞれに長所と弱点があるため、状況に応じて使い分けます。

指定方法 書き方の例 長所 弱点
名前で指定 Worksheets("売上明細") コードを読んだだけで対象が分かる シート名を変更されると動かなくなる
位置（インデックス）で指定 Worksheets(1) シート名が分からなくても書ける シートの並べ替えで指す先が変わる
オブジェクト名で指定 Sheet1 表示名（タブの名前）を変えても壊れない コードを読んだだけでは、どのシートか分かりにくい
VBAコードの例 — 3通りの参照方法を比べる 
Sub CompareReferenceMethods()
    ' 名前で指定 — 分かりやすいが、シート名を変更されると壊れる
    Worksheets("売上明細").Range("A1").Value = "名前で指定"
    ' 位置（左から何番目か）で指定 — シートの並べ替えで壊れる
    Worksheets(1).Range("B1").Value = "位置で指定"
    ' オブジェクト名で指定 — 表示名を変えても壊れない
    Sheet1.Range("C1").Value = "オブジェクト名で指定"
End Sub

この例は、「売上明細」シートがブックの1番目にあり、オブジェクトとしての内部名が Sheet1 である場合の書き方です。オブジェクト名は、シートを追加した順にVBAが自動的に割り当てる名前で、VBE（Visual Basic Editor）左側の「プロジェクトエクスプローラー」で確認できます。プロジェクトエクスプローラーには、オブジェクト名とタブに表示されるシート名が並べて表示されており、オブジェクト名はシートのタブ名をあとから変更しても変わりません。実際の値は環境によって異なるため、使う前にVBEで確認してください。

ヒント: WorksheetsとSheetsは別物です

よく似た命令に Sheets があります。Sheets にはワークシートに加えて、グラフシートなどワークシート以外のシートも含まれます。本ガイドで扱うのは表計算用のワークシートだけなので、迷ったら Worksheets を使ってください。

9.3 シートの追加・名前変更・コピー・削除

ここからは、実際に手を動かしながらシートを操作していきます。まずは、これから何度も使う「集計」シートを新しく追加するところから始めましょう。Worksheets.Add は、追加した新しいシートを処理結果として返します（この返ってくる値のことを戻り値（もどりち）と呼びます。詳しくは第10章で学びます）。この戻り値をオブジェクト変数で受け取っておくと、追加した直後に名前を付けたり値を書き込んだりできて便利です。

VBAコードの例 — シートを追加して名前を付ける 
Sub AddSummarySheet()
    Dim ws As Worksheet
    ' 一番右に新しいシートを追加し、その新しいシートを変数に受け取る
    Set ws = ThisWorkbook.Worksheets.Add( _
        After:=ThisWorkbook.Worksheets(ThisWorkbook.Worksheets.Count))
    ws.Name = "集計"                        ' シート名を付ける
    ws.Range("A1").Value = "支店別売上集計"
End Sub

After:= は「このシートの後ろに追加する」という意味の引数です。ThisWorkbook.Worksheets.Count はシートの総数なので、Worksheets(Worksheets.Count) は「今ある一番右のシート」を指します。反対に一番左（先頭）に追加したいときは Before:=Worksheets(1) のように書きます。

既にあるシートを複製したり、順番を入れ替えたりするときは Copy と Move を使います。書き方は追加のときと同じく After:= ／ Before:= で「どこに」を指定します。

VBAコードの例 — シートをコピーして移動する 
Sub CopyAndMoveSheet()
    With ThisWorkbook
        ' 「売上明細」シートを、一番右側にコピーする
        .Worksheets("売上明細").Copy After:=.Worksheets(.Worksheets.Count)
        ' コピーでできた新しいシート（一番右）を、先頭に移動する
        .Worksheets(.Worksheets.Count).Move Before:=.Worksheets(1)
    End With
End Sub

最後に削除です。不要になったシートは Delete で削除できますが、そのままでは通常のExcel操作と同じ確認ダイアログが表示され、マクロの実行がそこで止まってしまいます。

VBAコードの例 — シートを削除する（確認ダイアログを止めて、必ず戻す） 
Sub DeleteSummarySheet()
    ' 削除確認のダイアログを一時的に出さないようにする
    Application.DisplayAlerts = False
    ThisWorkbook.Worksheets("集計").Delete
    ' 設定は必ず元に戻す（戻し忘れると以降の警告がすべて消える）
    Application.DisplayAlerts = True
End Sub

注意: DisplayAlertsは「戻し忘れ」が一番危険です

Application.DisplayAlerts = False にすると、シート削除だけでなく上書き保存など他のすべての確認ダイアログも表示されなくなります。True に戻さないままマクロが終了すると、その後のExcel操作でも警告なしに上書きや削除が実行されてしまい、重大な事故につながります。

必ず False にした直後の処理のあとで True に戻す、とセットで覚えてください。エラーが起きた場合でも確実に戻す方法は、第12章のエラー処理で扱います。

9.4 ブックを参照する — ThisWorkbook / ActiveWorkbook / Workbooks()

ここまではシートの話でしたが、複数のブックを同時に開いて作業することもよくあります。VBAでどのブックを操作対象にするかを指定する方法は、主に3通りあります。

書き方 意味 いつ使うか
ThisWorkbook このマクロのコードが書かれているブック（常に同じ） 自分のブック自身を操作したいとき
ActiveWorkbook 今、一番前に表示されているブック（状況で変わる） 「今、目の前にあるブック」を操作したいとき
Workbooks("ファイル名") 名前を指定して、開いている他のブックを参照する 自分のブックとは別の、特定のブックを操作したいとき

特に注意したいのは ActiveWorkbook です。マクロの実行中に別のブックを開いたり、利用者が他のブックのウィンドウをクリックしたりすると、ActiveWorkbook が指す先はそのつど入れ替わります。

flowchart LR A["ThisWorkbook
（マクロが書かれているブック）"] -->|常に同じブックを指す| B["売上管理.xlsm
（固定）"] C["ActiveWorkbook
（今、最前面にあるブック）"] -->|状況によって指す先が変わる| D["そのとき開いている
いずれかのブック"]

図の説明: ThisWorkbookは、そのマクロが保存されているブックを指し続けます。一方ActiveWorkbookは「今、最前面にあるブック」を指すため、他のブックを開いたり切り替えたりすると指す先が変わります。

重要: 自分のブックを指すときはThisWorkbookを使う

「売上管理.xlsm」自身のシートやセルを操作したいときは、ActiveWorkbook ではなく ThisWorkbook を使うのが実務での基本ルールです。他のブックを開く処理をマクロの中に含めていても、ThisWorkbook を使っておけば、常に自分自身のブックを正しく指し続けます。

注意: ActiveSheetに頼ったコードは危険です

シートを省略して Range("A1").Value = ... のように書くと、VBAは自動的に「今アクティブなシート（ActiveSheet）」に対して処理します。学習中は問題が起きにくくても、実務では利用者が別のシートをクリックしてからボタンを押したり、マクロの途中で別のシートに切り替わったりすることがあり、意図しないシートのデータを書き換えてしまう事故につながります。

対策はシンプルで、常にシートを明示することです。Worksheets("売上明細").Range("A1") のように書けば、どのシートがアクティブであっても常に同じシートのA1を指します。

9.5 ブックを開く・保存する・閉じる

月次の報告では、前年の実績ファイルを参照したり、当月分のバックアップを別ファイルとして残したりする場面があります。ここでは、ブックを開く・保存する・閉じるという3つの基本操作を学びます。

VBAコードの例 — 他のブックを開いて閉じる 
Sub OpenAndCloseWorkbook()
    Dim wb As Workbook
    ' 指定したパスのブックを開き、変数で受け取る（※ "\" はWindows版Excelを前提とした書き方）
    Set wb = Workbooks.Open(ThisWorkbook.Path & "\売上_2026.xlsx")
    ' 必要な処理をした後、保存せずに閉じる
    wb.Close SaveChanges:=False
End Sub

ThisWorkbook.Path は、このブック（売上管理.xlsm）が保存されているフォルダーのパスです。同じフォルダーにある他のファイルを指定したいときは、ThisWorkbook.Path & "\ファイル名" の形でつなげます。Close SaveChanges:=False は「変更を保存せずに閉じる」という意味で、参照だけして内容を変えないブックを閉じるときによく使います。

ヒント: フォルダーの区切り文字は環境によって変わります

\（円記号／バックスラッシュ）はWindows版のフォルダー区切り文字です。Mac版では / が使われます。VBAには、実行環境にあわせた区切り文字をそのまま返す Application.PathSeparator という命令があり、これを使うと環境に依存しない書き方ができます。

ThisWorkbook.Path & Application.PathSeparator & "売上_2026.xlsx"

本ガイドはWindows版Excelを前提としているため、以降のコード例では読みやすさを優先して "\" で統一します。Mac版でも動かしたい場合は、上のように Application.PathSeparator に置き換えてください。

保存には3つの似た命令があり、それぞれ結果が異なります。

命令 動作 保存後、開いているブック
Save 今のファイルに、そのまま上書き保存する 元のブックのまま
SaveAs 新しいファイル名・場所を指定して保存する 保存した新しいファイルに切り替わる
SaveCopyAs 今の内容の「コピー」を別ファイルとして保存する 元のブックが、そのまま開いた状態で続く

バックアップを作る場面では、作業中のブックを切り替えたくないため、多くの場合 SaveCopyAs が適しています。日付をファイル名に含めておくと、いつのバックアップかが一目で分かります。

VBAコードの例 — 日付入りのバックアップを同じフォルダーに保存する 
Sub SaveAsBackup()
    Dim savePath As String
    ' ThisWorkbook.Path は、このブックが保存されているフォルダー（※ "\" はWindows版Excelを前提とした書き方）
    savePath = ThisWorkbook.Path & "\売上管理_" & Format(Date, "yyyymmdd") & ".xlsm"
    ' SaveCopyAs は、今のブックを閉じずに同じ形式のコピーを保存する
    ThisWorkbook.SaveCopyAs savePath
    MsgBox "バックアップを保存しました" & vbCrLf & savePath, vbInformation
End Sub

ヒント: ファイルの存在確認はDir関数で

存在しないファイルを Workbooks.Open しようとすると実行時エラーになります。開く前に Dir(パス) <> "" でファイルの有無を確認しておくと安全です。Dir 関数は、指定したパスのファイルが存在すればそのファイル名を、存在しなければ空文字（""）を返します。

9.6 シートの存在確認と安全な処理

存在しないシート名を Worksheets("...") に指定すると、実行時エラー9（インデックスが有効範囲にありません）が発生し、マクロが強制的に停止します。「集計」シートを使うマクロを毎回安全に動かすには、先にシートが存在するかどうかを確認する必要があります。ここでは、第7章で学んだ If と第8章で学んだ For Each を組み合わせて、この確認を行います。

VBAコードの例 — シートが存在するかを調べる（For EachとIfの応用） 
Sub CheckSummarySheet()
    Dim ws As Worksheet
    Dim found As Boolean          ' 見つかったかどうかを覚えておく箱
    ' ブック内のシートを1枚ずつ調べる
    For Each ws In ThisWorkbook.Worksheets
        If ws.Name = "集計" Then found = True
    Next ws
    If found Then
        MsgBox "「集計」シートは既に存在します"
    Else
        MsgBox "「集計」シートはまだありません", vbExclamation
    End If
End Sub

この考え方を応用すると、「集計シートがあれば内容をクリアし、なければ新規作成する」というどちらの状態でも正しく動くマクロを組み立てられます。処理の流れを図にすると、次のようになります。

flowchart TD A([開始]) --> B{"「集計」シートは
存在するか"} B -->|Yes| C["内容をクリアする"] B -->|No| D["シートを追加して
名前を付ける"] C --> E["見出しを書き込む"] D --> E E --> F([終了])

図の説明: シートが「既にある」場合と「まだない」場合の両方から、最終的に同じ「見出しを書き込む」処理へ合流させるのがポイントです。こうしておけば、マクロを何度実行してもエラーにならず、常に同じ結果になります。

ヒント: シート名は「見た目」だけでは信用しない

「売上明細 」（末尾に半角スペース）や、全角・半角が混ざったシート名は、見た目では区別できないのにVBAからは別の名前として扱われ、エラー9の原因になります。シート名を手入力せず、Debug.Print ws.Name でイミディエイトウィンドウに実際の名前を表示してから、コードにコピー＆ペーストする習慣をつけましょう。

やってみよう 9-1: 「集計」シートを安全に準備する

ここまで学んだ内容を組み合わせて、「集計」シートを何度実行しても壊れないように準備するマクロを作ってみましょう。

手順

  1. 1 「集計」シートが存在すればセルの内容をクリアし、存在しなければ新規作成する PrepareSummarySheet プロシージャを作る（第7章のIf、第8章のFor Each、本章のWorksheets.Addを組み合わせる）。
  2. 2 準備した「集計」シートのA1に「支店別売上集計」、A2に「支店」、B2に「売上金額」という見出しを書き込む。
  3. 3 ブック内の全シート名を Debug.Print で一覧出力する ListSheets プロシージャを作る。
  4. 4 SaveAsBackup を実行し、同じフォルダーに日付入りのバックアップファイルができることを確認する。

実行前 ― ブックの状態

この演習は、下の状態から始めます。ブックに「集計」シートはまだ存在しません（「売上明細」シートには、これまでと同じ10件のデータが入っています）。

ブック内のシートタブ:
[売上明細]
　※「集計」シートはまだ無い

実行するコード

解答例 — PrepareSummarySheetとListSheetsを呼び出す 
Sub Exercise9_1()
    Call PrepareSummarySheet
    Call ListSheets
End Sub

' 「集計」シートがあればクリアし、なければ新規作成して見出しを書き込む
' 準備できたシートを戻り値として返す
Function PrepareSummarySheet() As Worksheet
    Dim ws As Worksheet
    Dim found As Boolean
    For Each ws In ThisWorkbook.Worksheets
        If ws.Name = "集計" Then found = True
    Next ws

    If found Then
        Set ws = ThisWorkbook.Worksheets("集計")
        ws.Cells.Clear
    Else
        Set ws = ThisWorkbook.Worksheets.Add( _
            After:=ThisWorkbook.Worksheets(ThisWorkbook.Worksheets.Count))
        ws.Name = "集計"
    End If

    ws.Range("A1").Value = "支店別売上集計"
    ws.Range("A2").Value = "支店"
    ws.Range("B2").Value = "売上金額"
    Set PrepareSummarySheet = ws
End Function

' ブック内の全シート名をイミディエイトウィンドウに一覧出力する
Sub ListSheets()
    Dim ws As Worksheet
    For Each ws In ThisWorkbook.Worksheets
        Debug.Print ws.Name
    Next ws
End Sub

理解度確認クイズ

  1. Q1. ThisWorkbook と ActiveWorkbook の違いとして正しいものはどれか。

    ア. どちらも常に同じブックを指す
    イ. ThisWorkbookはマクロが書かれているブック、ActiveWorkbookはそのとき前面にあるブック
    ウ. ThisWorkbookは最初に開いたブックを指す

    回答を表示

    正解: イ
    マクロの途中で別のブックを開くと ActiveWorkbook はそちらに移ります。自分のブックのシートを操作したいときは ThisWorkbook を使うのが安全です。

  2. Q2. すでに「集計」という名前のシートがある状態で、別のシートに ws.Name = "集計" を実行するとどうなるか。

    ア. 上書きされて古いシートが消える
    イ. 「集計（2）」という名前が自動で付く
    ウ. 実行時エラー1004（この名前は既に使用されています）になる

    回答を表示

    正解: ウ
    シート名はブック内で一意でなければなりません。名前を付ける前に9.6のように存在確認するか、エラー処理（第12章）で備える必要があります。

  3. Q3. マクロの中でシートを指定せず Range("A1").Value = ... のように書くと、どのシートのA1に値が入るか。またそれの何が危険か。

    回答を表示

    実行した瞬間にアクティブになっているシート（ActiveSheet）のA1に値が入ります。マクロの実行中にアクティブシートが切り替わっていたり、利用者が別のシートを選んでからマクロを実行したりすると、意図しないシートのデータを書き換えてしまう危険があります。対策は、常に Worksheets("シート名").Range("A1") のようにシートを明示することです。

この章のまとめ

  • Workbooks／Worksheets（複数形＝集まり）とWorkbook／Worksheet（単数形＝1つ）は、命名に規則性がある。
  • ワークシートは名前・位置（インデックス）・オブジェクト名の3通りで参照でき、それぞれ長所と弱点が異なる。
  • シートの追加はWorksheets.Add、削除はDeleteで行い、削除時はDisplayAlertsの戻し忘れに注意する。
  • ThisWorkbookは常に同じブック、ActiveWorkbookは状況で変わるブックであり、自分のブックを指すにはThisWorkbookを使う。
  • シートを省略したActiveSheet頼みのコードは、意図しないシートを書き換える事故につながるため避ける。
  • シートの存在確認をしてから処理すれば、実行時エラー9を避けた「何度実行しても壊れない」マクロになる。

次の第10章では、これまで1つのプロシージャの中にまとめて書いてきた処理を、目的ごとの部品に分割する方法を学びます。たとえば支店名からエリアを判定するBranchAreaという関数を自分で作り、売上明細シートのH列に自動入力できるようにします。処理を部品化できるようになると、コードの見通しがよくなり、同じ処理を何度でも再利用できるようになります。
