変数とデータ型

第4章では、SubからEnd Subまでの基本的な書き方や、命令を上から順に実行するというVBAの基本文法を学びました。しかし、ここまでのコード例は "日付" や "こんにちは、VBA！" といった具体的な値を、そのつどコードの中に直接書き込んだものばかりでした。この章では、値をいったん入れておく「箱」——変数——の使い方を学びます。変数を使えるようになると、セルから読み取った値を計算に使い、その結果を必要な場所へ渡す、という実務でもっとも多いパターンのコードが書けるようになります。

この章で学ぶこと

  • 変数の役割を説明し、Dimで宣言して値を出し入れできる
  • 主要なデータ型（Long・Double・String・Boolean・Date・Variant・Object）を使い分けられる
  • Option Explicitを設定し、変数の宣言忘れやタイプミスを実行前に検出できる
  • Constで定数を定義し、コード中に直接書かれた数値（マジックナンバー）を減らせる

5.1 変数とは「名前を付けた箱」

買い物をするときのことを考えてみましょう。「単価480円のノートを12冊買う」場合、頭の中では単価という値と数量という値をいったん覚えておき、それを掛け算しています。VBAにおける変数とは、この「単価」「数量」のように名前を付けた値の入れ物のことです。値をいったん変数という箱に入れておき、必要なときに取り出して計算や表示に使います。

変数を使わなくても、セルの値を直接指定してVBAのコードを書くことはできます。しかし、同じセル参照を何度も書くコードと、意味の分かる名前にいったん入れてから使うコードとでは、読みやすさが大きく変わります。

VBAコードの例 — 変数を使わない場合と使う場合の比較 
' Before: セル参照を式の中に直接書く
Sub ShowAmountBefore()
    MsgBox Range("D2").Value * Range("E2").Value
End Sub

' After: 意味の分かる名前の変数にいったん入れてから使う
'（Dim による宣言は 5.2 で学びます）
Sub ShowAmountAfter()
    Dim unitPrice As Long
    Dim quantity As Long
    unitPrice = Range("D2").Value
    quantity = Range("E2").Value
    MsgBox unitPrice * quantity
End Sub

どちらも同じ結果になりますが、後者はunitPrice * quantityという式を見ただけで「単価と数量を掛けている」と読み取れます。セルの列がずれても、変数名の意味は変わりません。この「セルの値を、名前の付いた箱にいったん受け止めてから使う」という流れを図にすると、次のようになります。

flowchart LR A["セル D2 の値
480"] --> B["変数 unitPrice
（Long型の箱）"] C["セル E2 の値
12"] --> D["変数 quantity
（Long型の箱）"] B --> E["計算
unitPrice × quantity"] D --> E E --> F["計算結果
5760"]

図の説明: セルD2・E2の値は、それぞれ変数unitPrice・quantityという「箱」にいったん入れられます。それ以降の計算は、セルを直接見に行くのではなく変数どうしで行われます。計算結果を実際にセルへ書き戻す方法は、第6章で本格的に学びます。

5.2 宣言と代入 — DimとEqual

変数を使うには、大きく分けて2つの作業があります。まず宣言——「これから使う箱を用意してください」とVBAに伝える作業——を行い、次に代入——その箱に値を入れる作業——を行います。

宣言にはDimというキーワードを使い、Dim 変数名 As データ型の形で書きます。たとえばDim unitPrice As Longと書けば、「Long型（整数）の値を入れる、unitPriceという名前の箱を用意する」という意味になります。宣言した箱に値を入れるには=（イコール）を使い、unitPrice = 480のように書きます。

ここで注意したいのは、この=は数学の「左右が等しい」という意味ではないということです。VBAの=は、「右側の値を計算し、その結果を左側の箱に入れる」という代入の命令です。この違いが分かると、次のような一見不思議な式も自然に読めるようになります。

count = count + 1——数学の等式としては成立しませんが、VBAでは「今のcountの値に1を足し、その結果を再びcountという箱に入れ直す」という意味になり、正しく動作します。数を数えながら処理を繰り返す書き方（第8章）で欠かせない形です。

変数名は自由に付けられますが、読みやすいコードにするための慣習があります。本ガイドでは、意味の分かる英単語を使い、2つ目以降の単語の先頭だけ大文字にするローワーキャメルケース（例: lastRow、unitPrice）を採用します。

注意: 複数の変数をまとめて宣言するときの落とし穴

1行で複数の変数をまとめて宣言したいとき、Dim a, b As Longと書くと、bだけがLong型になり、aは型を指定しなかった扱い（Variant型）になります。VBAではAs データ型が直前の変数1つだけにかかるためです。

意図どおりに両方をLong型にするには、Dim a As Long, b As Longのように変数ごとに型を書きます。慣れないうちは1行1変数で書くほうが安全です。

ヒント: 日本語の変数名も使えます

VBAではDim 単価 As Longのように日本語の変数名も使用できます。ただし、実務のチーム開発では半角英数の変数名が広く使われています。英数字で統一しておくと、他の人が書いたコードと見比べやすいという利点があります。本ガイドでも変数名は英数で統一し、意味は日本語コメントで補います。

ここまでの内容をまとめたコード例を見てみましょう。

VBAコードの例 — 変数を使って金額を計算する 
Option Explicit   ' モジュールの先頭に書く。宣言忘れをエラーにする

Sub UseVariables()
    Dim productName As String   ' 商品名を入れる箱（文字列）
    Dim unitPrice As Long       ' 単価を入れる箱（整数）
    Dim quantity As Long        ' 数量を入れる箱（整数）
    productName = "A4コピー用紙"
    unitPrice = 480
    quantity = 12
    ' 「=」は「右の結果を左の箱に入れる」という意味
    MsgBox productName & " の金額は " & unitPrice * quantity & " 円です"
End Sub

1行目のOption Explicitは、変数の宣言を必須にするおまじないです（詳しくは5.4で説明します）。3つのDim文で商品名・単価・数量それぞれの箱を用意し、続く3行で値を代入しています。最後の行では、文字列をつなげる&演算子を使って、変数の中身をメッセージとして組み立てています。

5.3 主なデータ型と選び方

変数を宣言するときのAs データ型の部分には、何を選べばよいのでしょうか。VBAには多くのデータ型がありますが、大きく2つの種類に分けて考えると理解しやすくなります。

値そのものを入れる型

Long・Double・String・Boolean・Dateなど。数値や文字そのものを箱に入れます。代入は普通の=で行います。

Excelの「もの」を指す型

Worksheet・Rangeなど。値そのものではなく、Excel上の「もの」への参照を入れます。代入にはSetが必要です（第6章）。

実務でまず覚えておきたい7つのデータ型を、表で整理します。

データ型 扱える値 本教材での使用例 ひとこと
Long 整数（約-21億〜21億） 行番号、数量、単価、金額 整数はまずこれを選ぶ
Double 小数を含む数値 消費税率、平均、割合 小数の計算でも安全に扱える
String 文字列 商品名、支店名 値はダブルクォートで囲む
Boolean True または False 条件の判定結果 分岐処理（第7章）でよく使う
Date 日付・時刻 売上日 Format関数で表示形式を整える
Variant どんな種類の値でも入る （型を明示できない場合のみ） 型を省略すると自動でこれになる。動作が遅く、ミスにも気づきにくい
Object シートやセル範囲などの「もの」 Worksheet、Range 値を入れるときSetが必要（第6章）

型を選ぶときの考え方を、フローチャートに整理すると次のようになります。

（Setで代入）"]

図の説明: 入れたい値の種類によって、選ぶデータ型が決まります。迷ったときは、この図をたどれば多くの場合は正しい型にたどり着けます。どれにも当てはまらず判断に迷うときだけ、最後の手段としてVariantを検討します。

注意: 「Integer」は行番号でオーバーフローします

整数を扱う型にはLongのほかにIntegerもあり、名前が短いぶん使いたくなるかもしれません。しかしIntegerが扱えるのは-32,768〜32,767までです。Excelの行番号は最大1,048,576まであるため、32,767行を超えるデータを扱うと突然「オーバーフローしました」（実行時エラー6）が発生します。整数はすべてLongを使う、と決めてしまうのが実務的です。

型を無視して値を入れようとすると、何が起きるのでしょうか。実際に試して確かめてみましょう。

VBAコードの例 — わざと型の合わない値を入れてみる 
Sub TypeErrorSample()
    Dim quantity As Long
    ' 数値の箱に文字を入れようとすると「型が一致しません」（実行時エラー13）
    quantity = "たくさん"
    MsgBox quantity
End Sub

quantityはLong型、つまり数値専用の箱として宣言されています。そこに文字列"たくさん"を代入しようとすると、実行時に「型が一致しません」（実行時エラー13）というメッセージが表示され、処理が止まります。エラーが出ること自体は失敗ではありません。どの行で、なぜ止まったのかを読み取る練習だと考えてください。エラーへの本格的な対処は第12章で学びます。

ヒント: 「もの」を表す型への代入だけは書き方が違います

WorksheetやRangeのような「もの」を表すObject系の型に値を入れるときは、=ではなくSetを使います（例: Set ws = Worksheets("売上明細")）。数値や文字列との違いが分かりにくいところですが、詳しくは第6章でセルやシートを本格的に操作しながら扱います。ここでは「ものを入れるときだけSetが要る」と覚えておけば十分です。

5.4 Option Explicitで宣言を強制する

5.2のコード例で、Subの前に書いたOption Explicitについて、ここで詳しく見ていきます。これは初心者がもっとも恩恵を受ける設定と言ってよいものです。

次のようなコードを考えてみましょう。表の最終行をlastRowという変数に入れ、その後の処理で使うつもりが、変数名を打ち間違えています。

VBAコードの例 — 変数名の打ち間違いによる落とし穴 
Sub CountRows()
    Dim lastRow As Long   ' 正しく宣言した変数
    lastRow = 10
    ' 次の行は "lastRaw" と打ち間違えている
    MsgBox "最終行: " & lastRaw
End Sub

Option Explicitが無い状態でこのコードを実行すると、エラーは出ません。VBAはlastRawを新しい空の変数として黙って作ってしまうため、メッセージボックスには「最終行: 」とだけ表示され、本来出るはずの10が表示されないという静かな間違いが起こります。実行できてしまうため、原因に気づくのは簡単ではありません。

一方、Option Explicitを先頭に書いた状態で同じコードを実行しようとすると、「変数が定義されていません」というエラーが実行前に表示され、lastRawという宣言されていない名前を使っていることにその場で気づけます。

VBEで自動的にOption Explicitを入れる設定

  1. 1 VBE（Visual Basic Editor）のメニューから［ツール］→［オプション］を開く
  2. 2 ［編集］タブを選ぶ
  3. 3 「変数の宣言を強制する」にチェックを入れてOKを押す
  4. 4 以後、新しく追加する標準モジュールの先頭に「Option Explicit」が自動で入る

※ この設定はこれから新しく追加するモジュールに対して効果があります。すでに作成済みのモジュールには自動で追加されないため、先頭の行に手で「Option Explicit」と入力してください。

重要: 新しいブックでは、まずこの設定を確認する

Option Explicitの有無ひとつで、コードを書く体験は大きく変わります。宣言忘れやタイプミスの多くを実行前（コンパイル時）に発見できるため、実行してから「なぜ思った結果にならないのか」を延々と探す時間が減ります。本ガイドの以降のコード例はすべてOption Explicitを前提とします。まだ設定していない場合は、この章のうちに済ませておきましょう。

5.5 定数Constとマジックナンバーの排除

コードの中に0.1や1といった数値を直接書き込むことを、マジックナンバーと呼びます。たとえば消費税率の0.1がコードのあちこちに書かれていると、税率が変わったときにすべての箇所を探して直す必要があり、直し忘れも起こりやすくなります。

このような値には、Constを使って名前を付けておきます。書き方は変数の宣言によく似ていますが、一度入れた値はあとから変更できません。Const 定数名 As データ型 = 値という形で書き、定数名は変数と区別しやすいように大文字とアンダースコア（_）で書く慣習があります（例: TAX_RATE）。実際のコードで見てみましょう。

VBAコードの例 — 定数Constでマジックナンバーをなくす 
Sub UseConstants()
    Const TAX_RATE As Double = 0.1   ' 消費税率。変わってもここだけ直せばよい
    Dim amount As Long               ' 税抜金額
    Dim total As Long                ' 税込金額
    amount = 10000
    ' Int は小数点以下を切り捨てる関数
    total = Int(amount * (1 + TAX_RATE))
    MsgBox "税抜 " & amount & " 円 → 税込 " & total & " 円"
End Sub

Const TAX_RATE As Double = 0.1の1行で税率に名前を付けています。これ以降のコードではTAX_RATEという名前で税率を参照でき、税率が変わったときもこの1行だけを直せばよくなります。total = Int(amount * (1 + TAX_RATE))という式も、ただ数値が並ぶよりずっと意味が読み取りやすくなっています。

変数（Dimで宣言）は途中で値を入れ直せますが、定数（Const）は最初に決めた値のまま変わりません。「実行中に変わってよい値」か「変わってはいけない値」かで、両者を使い分けます。

5.6 セルの値を変数に読み込む

ここまで、変数の宣言・データ型・定数について学びました。最後に、実際の業務でもっともよく使う操作——セルの値を変数に読み込む——を見ておきましょう。5.3で見たデータ型の使い分けが、ここで生きてきます。

「売上明細」シートのA列（日付）とB列（支店）の値を、それぞれ型の合った変数に読み込んでみます。

VBAコードの例 — セルの値を変数に読み込む 
Sub ReadCellToVariable()
    Dim saleDate As Date        ' 日付は Date 型で受ける
    Dim branch As String        ' 支店名は String 型で受ける
    ' 「売上明細」シートの2行目からデータを読み取る
    saleDate = Worksheets("売上明細").Range("A2").Value
    branch = Worksheets("売上明細").Range("B2").Value
    ' Format 関数で日付の見た目を整えて出力する
    Debug.Print Format(saleDate, "yyyy/mm/dd") & " " & branch & "支店"
End Sub

saleDateはDate型、branchはString型で宣言し、セルの値の種類に型を合わせています。Format関数は、日付や数値の見た目を整えて文字列にするための命令で、ここでは日付を「yyyy/mm/dd」の形式に整形しています。実行すると、イミディエイトウィンドウ（第4章でDebug.Printとあわせて確認した画面）に次のように出力されます。

イミディエイトウィンドウの表示例 
2026/04/01 東京支店

型を合わせて受け取ることで、日付は日付として、文字は文字として、Excel側にもVBA側にも意図が正しく伝わります。次章以降、この「セル→変数」の流れは何度も登場します。

やってみよう 5-1: 変数と定数を使って金額を計算する

ここまで学んだDim・データ型・Option Explicit・Constを、実際に手を動かして体験してみましょう。「売上明細」のコピーを使い、必ず練習用のブックで行ってください。

手順

  1. 1 VBEの［ツール］→［オプション］→［編集］タブで「変数の宣言を強制する」にチェックを入れる。新しい標準モジュール M_Practice を挿入し、先頭に Option Explicit が自動で入ることを確認する。
  2. 2 「売上明細」シートの2行目から単価（D2セル）と数量（E2セル）の値を変数に読み込み、金額と税込金額を計算して Debug.Print で出力するマクロを書く。税率は Const で定義すること。
  3. 3 手順2で書いた変数名のどれか1つを、宣言している行か使っている行のどちらかだけでわざと1文字間違え、実行して何が起こるかを確認してから正しく直す。
  4. 4 新しく Dim i As Integer を宣言し、i = 40000 を代入して実行する。「オーバーフローしました」（実行時エラー6）が出ることを確認したら、Integer を Long に直して再実行し、正しく動くことを確かめる。

理解度確認クイズ

  1. Q1. モジュールの先頭に Option Explicit を書く効果はどれか。

    • ア. コードの実行速度が上がる
    • イ. 宣言していない変数を使うとコンパイルエラーになり、タイプミスを早期に発見できる
    • ウ. すべての変数が自動的に Variant 型になる
    回答を表示

    正解: イ
    Option Explicit が無いと、打ち間違えた変数名も「新しい空の変数」として黙って作られてしまい、結果だけが静かに間違います。原因究明がもっとも難しいタイプのバグを未然に防げます。

  2. Q2. Excelの行番号（1〜1,048,576）を入れる変数に適したデータ型はどれか。

    • ア. Integer
    • イ. Long
    • ウ. String
    回答を表示

    正解: イ
    Integer は-32,768〜32,767しか扱えないため、行番号を入れるとオーバーフロー（実行時エラー6）になります。整数は原則 Long を使います。

この章のまとめ

  • 変数は「名前を付けた値の入れ物」で、Dim 変数名 As データ型で宣言し、変数名 = 値で代入する。
  • VBAの=は「右の値を左の箱に入れる」という代入であり、数学の等号とは意味が異なる。
  • 主なデータ型はLong（整数）・Double（小数）・String（文字列）・Boolean（真偽値）・Date（日付）・Variant（何でも入るが非推奨）・Object（もの。代入にはSetが必要）である。
  • 整数はIntegerではなくLongを使う。Integerは32,767を超えるとオーバーフローする。
  • Option Explicitを設定すると、宣言していない変数の使用を実行前にエラーとして検出できる。
  • Constで定数を定義すると、マジックナンバーを排除し、変更を1か所にまとめられる。

次の第6章では、変数に読み込んだ値を使って、RangeやCellsによるセルの本格的な操作——複数セルへの一括書き込みや、最終行の自動判定——を学びます。この章で身につけた「型を意識して値を扱う」という感覚は、次章以降のコードでも土台になります。
