VBAとは何か

毎月おなじ手順でExcelの表を集計し、別のシートに転記し、決まった形の表を作る——そんな作業を「自分の代わりにExcelにやらせる」ための仕組みが VBA です。この章ではコードを書く前に、そもそもマクロとは何か、VBAとはどういう関係なのか、そして VBA を使うと日々の仕事の何が変わるのかという全体像をつかみます。ここで地図を持っておくと、第2章以降で学ぶ一つひとつの文法が「地図のどのあたりの話なのか」が分かるようになります。

この章で学ぶこと

  • マクロとVBAの違いと関係を、自分の言葉で説明できる
  • VBAで自動化できる業務の型を知り、身近な業務に当てはめられる
  • VBAがExcelに命令を伝える仕組みを、おおまかな流れとして理解する
  • VBAの得意・不得意と注意点を把握し、本ガイド全14章の進め方をつかむ

本教材で使う題材について

本ガイドでは全14章を通して、架空の文具卸売会社「さくら文具株式会社」の売上管理業務を題材にします。担当者が毎月手作業で行っている「売上明細」シートの集計・転記・帳票作成を、章を追うごとに少しずつVBAに置き換えていき、第14章では一連の作業をボタン1つで実行できるツールに仕上げます。登場する社名・人名・数値はすべて架空のものです。

使用するファイルは 売上管理.xlsm というブックの「売上明細」シートです。1行目が見出しで、2行目から下に A列＝日付・B列＝支店・C列＝商品名・D列＝単価・E列＝数量 が並んでいます。ここに、第6章では金額（F列）、第7章ではランク（G列）、第10章ではエリア（H列）を、VBAを使って自分の手で追加していきます。

1.1 マクロとVBA — 名前は違うが、深く関係している

Excelの世界では「マクロ」と「VBA」という2つの言葉がよく一緒に出てきます。ほとんど同じ意味で使われることも多いのですが、正確には役割が違います。まずはこの2つを切り分けておきましょう。

マクロ ＝ 作業手順書

「この表を選んで、合計を出して、太字にして、保存する」という一連の操作をまとめて記録したものです。実行すると、記録した手順どおりにExcelが動きます。

VBA ＝ 手順書を書くための言葉

Visual Basic for Applications の略で、マクロの中身を記述するプログラミング言語です。マクロが「文書」なら、VBAは「その文書を書くための日本語や英語」にあたります。

つまり、マクロという成果物を作るために使う言語がVBA、という関係です。「マクロを作る」と言うとき、実際には裏でVBAのコードが書かれています。この関係を図にすると次のようになります。

flowchart LR A["あなたの操作
（記録する）"] --> B["VBAのコード
（言葉で書かれた手順）"] C["あなたが書く
（キーボードで入力）"] --> B B --> D["マクロ
（実行できる手順のまとまり）"] D --> E["Excelが自動で動く"]

図の説明: マクロの中身であるVBAコードは、操作を記録して自動生成する方法（第3章）と、自分でキーボードから書く方法（第4章以降）の2通りで作れます。どちらの道を通っても、最終的にできあがるのは「実行するとExcelが自動で動くマクロ」です。

なぜExcelにプログラミング言語が付いているのか

Excelには、関数・ピボットテーブル・条件付き書式など便利な機能が数多くあります。しかしそれらは「1つの操作」を助ける機能です。実際の業務は「ファイルを開く → 不要な行を消す → 集計する → 別のシートに転記する → 名前を付けて保存する」というように複数の操作の連なりでできています。この「連なり」そのものを保存して繰り返せるようにするために、Excelにはプログラミング言語であるVBAが組み込まれているのです。

ヒント: 「VBA」は Excel 専用ではありません

VBA は Excel だけでなく、Word・Access・PowerPoint・Outlook といった Office 製品に共通して搭載されています。名前の「for Applications（アプリケーションのための）」はここから来ています。本ガイドで Excel VBA を学んでおくと、たとえば Word の差し込み文書作成を自動化したくなったときにも、同じ考え方がそのまま通用します。

1.2 VBAで何ができるのか

VBAでできることは非常に幅広いのですが、実際の業務でよく使われる場面は、次の4つの型に整理できます。自分の仕事のどれが当てはまるかを考えながら読んでみてください。

① 集計する

数千行の明細を条件ごとに合計する、商品カテゴリ別・担当者別に数字をまとめる、といった処理です。関数では追いつかない複雑な条件でも、手順として書けば自動化できます。

② 転記する

あるシートの値を別のシートやブックへ、決められたルールで書き写します。コピー＆ペーストの繰り返しで起きがちな貼り間違い・行ずれをなくせます。

③ 整える

空白行を削除する、表記のゆれを直す、罫線や色を決まった形に整える、印刷範囲を設定する——毎回おなじ「見た目づくり」を一瞬で終わらせます。

④ 出力する

帳票シートを作る、PDFとして保存する、ファイル名に日付を付けて所定のフォルダへ保存する、といった仕上げの処理です。

さくら文具株式会社の担当者が毎月行っている作業を、この4つの型に当てはめると次の表のようになります。本ガイドでは、この一つひとつをどの章で学ぶかもあわせて示します。

型 担当者が毎月している作業 学ぶ章
① 集計する 売上明細を支店別・商品別に集計して合計を出す 第7章・第8章・第11章
② 転記する 集計結果を「集計」シートへ書き写す 第6章・第9章
③ 整える 空白行を削除し、見出しに色を付け、罫線を引く 第6章・第8章
④ 出力する 報告書に当月の日付を付けて保存し、上司に提出する 第9章・第13章・第14章

参考として、VBAのコードが実際にどんな見た目なのかを1つだけ見ておきましょう。今は意味が分からなくてまったく問題ありません。「英語の命令文が、上から順に並んでいる」という雰囲気だけつかんでください。

VBAコードの例 — セルに文字と数式を書き込む 
' 「売上明細」シートに合計欄を作る、という手順のまとまり
Sub 合計欄を作る()
    ' A100 セルに見出しの文字を入れる
    Worksheets("売上明細").Range("A100").Value = "合計"
    ' E100 セルに、E2からE99まで（数量）を合計する数式を入れる
    Worksheets("売上明細").Range("E100").Formula = "=SUM(E2:E99)"
End Sub

1行目の ' で始まる行はコメント（人間向けのメモ）で、Excelは無視します。Sub 合計欄を作る() から End Sub までが1つのマクロで、その間に書かれた命令が上から順番に実行されます。VBAのコードは、このように「どこに」「何を」するかを1行ずつ並べたものだと考えてください。

1.3 VBAを使うと、仕事の何が変わるのか

VBAを学ぶ目的は「プログラミングができるようになること」ではなく、仕事のやり方を変えることです。手作業とVBAでは、同じ結果を出すまでの過程が次のように変わります。

観点 手作業 VBAによる自動化
かかる時間 毎回同じだけかかる（毎月2時間なら年24時間） 作るときだけ時間がかかり、2回目以降は数秒〜数分
ミスの起きやすさ 貼り付け先の行ずれ・消し忘れなど、毎回起こりうる 手順が固定されるため、同じ入力なら常に同じ結果
属人化 やり方が担当者の頭の中にあり、引き継ぎが難しい 手順がコードとして残るため、他の人が読んで引き継げる
担当者の役割 作業そのものに時間を使う 数字を読んで判断することに時間を使える

重要: 「作る時間」も計算に入れる

VBAは万能ではありません。マクロを作るにも時間がかかるため、年に1回しかやらない30分の作業を自動化しても割に合わないこともあります。目安は「繰り返す回数 × 1回あたりの時間」が、作る手間を上回るかどうかです。逆に、毎日・毎週・毎月おこなう定型作業は、多くの場合すぐに元が取れます。

1.4 VBAが動く仕組み

VBAのコードは、Excelとは別のソフトで動いているわけではありません。Excelの内部にVBAを解釈して実行する部分が組み込まれていて、そこがコードを1行ずつ読み取り、Excelの機能を呼び出しています。人が手でリボンやセルを操作する代わりに、コードが同じ操作を代行している、と考えると分かりやすいでしょう。

flowchart TD A["あなた"] --> B["VBE
（コードを書く画面）"] B --> C["VBAコード
（Excelブックの中に保存される）"] C --> D["実行（F5キーやボタン）"] D --> E["Excel本体が命令を受け取る"] E --> F["セル・シート・ブックが変化する"] A -.->|手作業の場合| F

図の説明: VBE（Visual Basic Editor）という専用画面でコードを書くと、そのコードはExcelブックの中に一緒に保存されます。実行するとExcel本体が命令を受け取り、セルやシートが変化します。点線は手作業の場合で、同じ結果に人の手で到達している状態です。

「オブジェクト」という考え方

VBAでExcelに命令を出すときは、操作する対象をはっきり指定します。この操作対象のことを オブジェクト と呼びます。難しそうな言葉ですが、要は「ブック」「シート」「セル」といったExcelの中の“もの”のことです。

  • Workbook — ブック（Excelファイルそのもの）
  • Worksheet — ワークシート（ブックの中の1枚のシート）
  • Range — セル、またはセルの集まり（A1、A1:C10 など）

これらは「ブックの中にシートがあり、シートの中にセルがある」という入れ子の関係になっています。VBAではこの関係を、大きいものから小さいものへ点（.）でつないで表します。住所を「都道府県 → 市区町村 → 番地」と書いていくのと同じ考え方です。

flowchart TD A["Application
（Excel本体）"] --> B["Workbook
（売上管理.xlsm）"] B --> C["Worksheet
（売上明細シート）"] B --> D["Worksheet
（集計シート）"] C --> E["Range
（A1セル）"] C --> F["Range
（E2:E99）"]

図の説明: Excelの操作対象は、Excel本体 → ブック → シート → セルという入れ子構造になっています。VBAでは「どのブックの、どのシートの、どのセルか」を上から順にたどって指定します。この構造は第6章と第9章で本格的に扱います。

1.5 学び始める前に知っておきたい注意点

VBAには、はじめに知っておかないと戸惑いやすい性質がいくつかあります。どれも第2章以降で具体的な対処を学びますが、ここで先に頭に入れておきましょう。

注意: マクロの実行は「元に戻す」ができません

通常のExcel操作は Ctrl + Z で取り消せますが、マクロが行った変更は原則として取り消せません。行を削除するマクロを誤って実行すると、そのデータは戻ってこないということです。

そのため本ガイドでは、必ず練習用にコピーしたブックで試してください。実務のファイルでマクロを試す場合も、事前にバックアップを取ることを習慣にしましょう。

知っておきたいこと 内容 扱う章
保存形式が変わる マクロを含むブックは通常の .xlsx では保存できず、.xlsm（マクロ有効ブック）で保存します 第2章
セキュリティの警告が出る マクロは悪用もできるため、既定では無効化されます。信頼できるファイルのみ有効にします 第2章
エラーは必ず出る 書き間違いや想定外のデータでエラーが出ます。原因を調べる方法を学べば怖くありません 第12章
環境による違いがある Mac版Excelでは一部機能が使えず、Web版Excelではマクロを実行できません 第2章

ヒント: 覚えようとしなくて大丈夫です

VBAの命令は非常にたくさんあり、熟練者でもすべてを暗記してはいません。大切なのは「やりたいことを、どういう手順に分解すればよいか」を考えられることです。個々の命令の書き方は、必要になったときに調べれば十分です。本ガイドも、暗記ではなく「読んで分かる・調べて書ける」状態を目指します。

やってみよう 1-1: 自動化したい作業を書き出す

Excelを開く前に、まず「自分がVBAで楽にしたい作業」を紙かメモ帳に書き出しておきましょう。目的がはっきりしていると、第2章以降の内容が「自分ごと」として頭に入ります。

手順

  1. 1 毎日・毎週・毎月くり返しているExcel作業を3つ書き出す（例: 日報の集計、受注一覧の転記、請求書の印刷）。
  2. 2 それぞれについて「1回にかかる時間」と「月に何回やるか」を書き添える。掛け算した数字が、自動化で浮く時間の目安になります。
  3. 3 1つを選び、その作業を「①集計 ②転記 ③整える ④出力」のどれに当てはまるか分類する。複数にまたがっていてもかまいません。
  4. 4 選んだ作業の手順を、他人に説明するつもりで箇条書きにする。この箇条書きが、そのままVBAで書く手順の下書きになります。第14章まで取っておいてください。

理解度確認クイズ

  1. Q1. 「マクロ」と「VBA」の関係を説明してください。

    回答を表示

    マクロは「一連の操作をまとめて記録し、実行できるようにしたもの」＝成果物です。VBA（Visual Basic for Applications）は、そのマクロの中身を記述するためのプログラミング言語＝道具です。「マクロという文書を、VBAという言葉で書く」という関係になります。

  2. Q2. VBAで自動化するのに向いている作業と、向いていない作業の違いは何ですか？

    回答を表示

    向いているのは手順が決まっていて、繰り返し行う作業です。毎月の集計・転記・帳票作成などが該当します。逆に、年1回しか行わない短時間の作業や、毎回やり方が変わる作業、人の判断が必要な作業は、マクロを作る手間の方が大きくなりがちで向いていません。判断の目安は「繰り返す回数 × 1回あたりの時間」が作る手間を上回るかどうかです。

  3. Q3. マクロを試すときに、練習用のコピーを使うべき理由は何ですか？

    回答を表示

    マクロが行った変更は Ctrl + Z（元に戻す）で取り消せないためです。行の削除や上書きを含むマクロを誤って実行すると、データを元に戻せません。学習中は必ずコピーしたブックで試し、実務のファイルに適用するときも事前にバックアップを取る習慣をつけましょう。

この章のまとめ

  • マクロは記録・実行できる操作のまとまり、VBAはその中身を書くための言語である。
  • VBAでできることは「①集計 ②転記 ③整える ④出力」の4つの型に整理できる。
  • 自動化の効果は「繰り返す回数 × 1回あたりの時間」で見積もる。
  • Excelの操作対象（ブック・シート・セル）はオブジェクトと呼ばれ、入れ子構造になっている。
  • マクロの実行は元に戻せないため、必ず練習用のコピーで試す。

次の第2章では、いよいよExcelを開いて開発環境を整えます。「開発」タブを表示し、コードを書く画面であるVBEを開き、マクロを保存できる形式（.xlsm）でファイルを準備するところまで進みます。
