ホーム Excel VBA 第7章
第7章 所要時間: 約90分

条件分岐

第6章では、VBAで「売上明細」シートのセルを読み書きする方法を学びました。しかし実務では、値を読み書きするだけでなく「その値がいくつなら、どう扱うか」を判断する場面が数多くあります。たとえば売上金額が10万円以上なら「ランクA」、そうでなければ次の条件を確認する——こうした判断をコードに落とし込む仕組みが条件分岐です。この章では「売上明細」シートの2行目、たった1つのセルを対象に、If文とSelect Case文の使い方をじっくり身につけます。複数の行をまとめて処理する繰り返しは、次の第8章で学びます。

この章で学ぶこと

  • If〜Then〜Elseを使って、条件によって処理を切り替えられる
  • 比較演算子と論理演算子（And・Or・Not）を正しく組み合わせて条件式を書ける
  • 3つ以上の分岐をSelect Caseで読みやすく整理できる
  • セルの値を判定して、判定結果や書式を出し分けるマクロが書ける

7.1 条件分岐とは「もし〜なら」

私たちは日常生活で、無意識のうちに「もし〜なら、こうする」という判断を繰り返しています。「雨が降っているなら傘を持つ、降っていないなら持たない」「金額が1万円を超えるなら承認が必要、超えないなら不要」——こうした条件による判断は、プログラムの世界でも同じ形で書くことができます。これを条件分岐と呼びます。

第3章では、操作を記録するだけの記録マクロには「条件によって処理を変える」ことができないという限界があると触れました。記録マクロは、記録したときとまったく同じ手順を繰り返すことしかできず、「金額が10万円以上のときだけ特別な処理をする」といった判断はできなかったのです。この限界を解消するのが、この章で学ぶIf文とSelect Case文です。

Excelの IF関数 — すでに知っている考え方

=IF(F2>=100000,"高額","通常") のように、セルに条件と結果を書く関数です。「条件が成立するなら値1、しないなら値2」という考え方は、これから学ぶVBAのIf文と共通しています。

VBAの If文 — コードで判断する

VBAでは、条件と処理をコードとして複数行にわたって書けます。Excelの関数よりも複雑な判断や、複数の処理をまとめて実行できる点が異なります。

VBAで条件分岐を書くときの基本的な考え方は、次の3つの要素に整理できます。この章を通じて、この3つの組み合わせ方をいろいろな形で学んでいきます。

要素 意味 具体例
条件式 True（真）かFalse（偽）のどちらかに決まる式 amount >= 100000
成立したときの処理 条件式がTrueのときに実行する処理 rank = "A"
成立しなかったときの処理 条件式がFalseのときに実行する処理（省略も可能） rank = "C"

7.2 If 〜 Then 〜 End If の基本形

If文の基本形には、複数行にわたって書く形と、1行で書く形の2種類があります。同じ意味の処理でも書き方が変わるので、まずは見た目の違いを確認しましょう。

複数行のIf文（本ガイドで基本とする書き方） 
If amount >= 100000 Then
    MsgBox "高額取引です"
End If
1行のIf文（End Ifを書かない） 
If amount >= 100000 Then MsgBox "高額取引です"

注意: 複数行なら End If が必須、1行なら End If を書かない

Ifを複数行で書いたときは、必ず対応するEnd Ifが必要です。逆に1行形式で書いたときにEnd Ifを付け足すとエラーになります。「ブロック If に対応する End If がありません」というエラーが出たら、まずIfの数とEnd Ifの数を数えてみましょう。本ガイドでは、読みやすさを優先して複数行の書き方を基本とします。

複数行のIf文では、条件が成立したときに実行される処理を1段字下げ（インデント）して書きます。字下げをそろえることで、「Ifの内側で何が実行されるか」がひと目で分かるようになります。VBEでは多くの場合自動でインデントが調整されますが、崩れてしまったときは手動で整えましょう。

実際に「売上明細」の金額を判定するマクロを見てみましょう。2行目のF列（金額）を読み取り、10万円以上かどうかでメッセージを出し分けます。

CheckAmount — 金額が10万円以上かどうかを判定する 
Sub CheckAmount()
    Dim amount As Double
    ' 「売上明細」の2行目の金額（F列）を読み取る
    amount = Worksheets("売上明細").Range("F2").Value
    ' If の中の「=」ではなく「>=」は比較のための記号
    If amount >= 100000 Then
        MsgBox "高額取引です（" & Format(amount, "#,##0") & " 円）"
    Else
        MsgBox "通常の取引です（" & Format(amount, "#,##0") & " 円）"
    End If
End Sub
実行結果（F2が125,000のとき） 
高額取引です（125,000 円）

F2の値を書き換えてから実行し直し、メッセージが正しく切り替わることを確認してみましょう。10万円ちょうどのときは>=（以上）の条件に含まれるため「高額取引です」になる点にも注目してください。

7.3 Else と ElseIf による多分岐

「どちらでもない場合」を受け止めたいときはElseを使います。さらに3段階以上に分けたいときは、ElseIfを重ねて書きます。「金額が10万円以上ならA、5万円以上ならB、それ以外はC」という3段階の判定を、図で確認してみましょう。

flowchart TD A([開始]) --> B{"金額は10万円以上か？"} B -->|はい| C["ランクA"] B -->|いいえ| D{"5万円以上か？"} D -->|はい| E["ランクB"] D -->|いいえ| F["ランクC"] C --> G([終了]) E --> G F --> G

図の説明: 判定は必ず上から順に進みます。「10万円以上か？」がいいえの場合だけ、次の「5万円以上か？」に進みます。どのルートを通っても、最終的には1つの結果（ランクA・B・Cのいずれか）に落ち着きます。

重要: 上から順に判定され、最初に成立した1つだけが実行される

ElseIfは上から順に評価されます。どこかの条件がTrueになった時点で、そのブロックの処理だけが実行され、それより下のElseIfやElseは確認すらされません。したがって、複数の条件が重なりうる場合は、条件を書く順番が結果を左右します。

この考え方をもとに、「売上明細」の2行目の金額（F列）からランクを判定し、G列に書き込むマクロを作ってみましょう。

RankBySales — 金額に応じてA/B/Cのランクを判定する 
Sub RankBySales()
    Dim ws As Worksheet
    Dim amount As Double, rank As String
    Set ws = Worksheets("売上明細")
    amount = ws.Range("F2").Value
    ' 上から順に判定され、最初に成立した1つだけが実行される
    If amount >= 100000 Then
        rank = "A"
    ElseIf amount >= 50000 Then
        rank = "B"
    Else
        rank = "C"
    End If
    ws.Range("G2").Value = rank      ' G列（ランク）へ書き込む
End Sub

10万円以上を最初に判定している点に注目してください。D2（単価）とE2（数量）の値を書き換えてF2の金額を変化させると、G2の判定は次のように切り替わります。

F2（金額） G2に書き込まれる値
150,000 A
70,000 B
20,000 C

ヒント: 範囲が重なる条件は、狭い方を先に書く

「10万円以上」と「5万円以上」のように範囲が重なる条件をElseIfで並べるときは、必ず範囲の狭い（厳しい）条件を先に書きます。広い条件を先に書いてしまうと、それより厳しい条件は永久に成立しなくなります。RankBySalesで100000以上を先に判定しているのはこのためです。

7.4 比較演算子と論理演算子

If文の条件式では、値を比べるための比較演算子と、複数の条件を組み合わせる論理演算子を使います。まずは比較演算子の一覧です。

演算子 意味 VBAでの例
= 等しい amount = 100000
<> 等しくない amount <> 0
> より大きい（超える） amount > 100000
>= 以上 amount >= 100000
< より小さい（未満） amount < 50000
<= 以下 amount <= 50000

注意: 「=」は代入にも比較にも使われる

rank = "A"は「"A"をrankに代入する」という意味ですが、If rank = "A" ThenのようにIfの条件式の中に書くと「rankが"A"と等しいかどうかを比較する」という意味になります。同じ記号でも文脈によって役割が変わるので注意しましょう。また、「等しくない」を表す記号は、多くの言語で使われる!=ではなく、VBAでは<>である点も間違えやすいところです。

論理演算子で複数の条件を組み合わせる

1つの条件だけでなく、複数の条件を組み合わせたいときは、And（かつ）・Or（または）・Not（〜でない）という論理演算子を使います。AndとOrの結果は、次の真理値表のとおりです。

条件A 条件B A And B A Or B
True True True True
True False False True
False True False True
False False False False

Andは両方の条件が成立したときだけTrueになり、Orはどちらか一方でも成立すればTrueになります。Notは条件の結果を反転させる演算子で、たとえばNot IsEmpty(target.Value)は「空欄でない」という意味になります。

ヒント: 文字列の比較は「見た目が同じ」でも一致しないことがある

セルの値に前後の空白や全角スペースが混ざっていると、If branch = "東京" Thenが成立しないことがあります。見た目には「東京」としか見えなくても、実際には末尾に空白が入っている、といったケースです。前後の空白を取り除くTrim関数を組み合わせたIf Trim(branch) = "東京" Thenという書き方や、全角・半角をそろえるStrConv関数を知っておくと、こうした不一致に対処できます。

7.5 Select Caseで多分岐を整理する

同じ1つの値を何度も比較する場合、If〜ElseIfを重ねると条件の中に同じ変数名が何度も登場して読みにくくなります。そのようなときはSelect Caseを使うと、判定したい値を1回だけ書き、あとはケースを並べるだけで済むため読みやすくなります。書き方には主に4つのパターンがあります。

書き方 意味 例
列挙 複数の値のいずれかに一致する場合 Case "東京", "横浜"
範囲 Toで範囲を指定する場合 Case 50000 To 99999
比較 Isを使って比較演算子で判定する場合 Case Is >= 100000
それ以外 上のどれにも一致しない場合 Case Else

7.3で書いたIf〜ElseIfの考え方は、実はそのままSelect Caseに書き換えられます。支店名からエリアを判定する場合を例に、対応関係を見てみましょう。

flowchart LR subgraph SG1["If ～ ElseIfで書く"] direction TB A1["支店が東京または横浜"] A2["支店が大阪または京都"] A3["それ以外"] end subgraph SG2["Select Caseで書く"] direction TB B1["Case 東京, 横浜"] B2["Case 大阪, 京都"] B3["Case Else"] end A1 -. 同じ判定 .-> B1 A2 -. 同じ判定 .-> B2 A3 -. 同じ判定 .-> B3

図の説明: 左側のIf〜ElseIfで1行ずつ書いていた判定は、右側のSelect Caseでは1つのCaseとして対応します。判定する値（支店）を先頭で1回だけ指定し、あとは値を並べるだけで済むため、条件が増えるほどSelect Caseの読みやすさが際立ちます。

では、この考え方をもとに支店名からエリアを判定するマクロを、Select Caseで書いてみましょう。

JudgeArea — 支店名からエリアを判定する 
Sub JudgeArea()
    Dim branch As String
    branch = Worksheets("売上明細").Range("B2").Value
    ' 同じ1つの値を何度も比べるときは Select Case が読みやすい
    Select Case branch
        Case "東京", "横浜"
            MsgBox branch & "支店は関東エリアです"
        Case "大阪", "京都"
            MsgBox branch & "支店は関西エリアです"
        Case Else
            MsgBox branch & "支店はその他のエリアです"
    End Select
End Sub
実行結果（B2が「東京」のとき） 
東京支店は関東エリアです

Case "東京", "横浜"のようにカンマで区切ると、「東京、または横浜のとき」という意味になります。Select CaseもIfと同じく、上から順に評価され最初に一致したCaseだけが実行される点は変わりません。

7.6 入力チェックに使う判定関数

条件分岐は、値を判定してメッセージを出し分けるだけでなく、「そもそもこのデータは処理してよい状態か」を確かめる場面でもよく使われます。処理の前にデータを確認する、いわば入口の見張りのような役割です。この考え方は、第12章で学ぶエラー処理にもつながっていきます。

関数 判定する内容 例
IsEmpty セルや変数が空欄かどうか IsEmpty(target.Value)
IsNumeric 数値として扱える値かどうか IsNumeric(target.Value)
IsDate 日付として扱える値かどうか IsDate(target.Value)
Like 文字列が指定したパターンに一致するか（あいまい一致） branch Like "東*"

Likeは、"東*"のようにワイルドカード（*や?）を使って、文字列があいまいなパターンに一致するかどうかを調べられます。詳しい書き方は、必要になったときに調べれば十分です。

「売上明細」の2行目の数量（E列）が、空欄でなく、かつ数値として入力されているかを確認するマクロを作ってみましょう。

CheckInput — 数量が正しく入力されているか確認する 
Sub CheckInput()
    Dim target As Range
    Set target = Worksheets("売上明細").Range("E2")   ' 数量のセル
    ' And は「かつ」。両方の条件が成立したときだけ True になる
    If Not IsEmpty(target.Value) And IsNumeric(target.Value) Then
        MsgBox "数量は正しく入力されています"
    Else
        MsgBox "数量が未入力、または数値ではありません", vbExclamation
    End If
End Sub
実行結果（E2が数値のとき） 
数量は正しく入力されています

Not IsEmpty(target.Value) And IsNumeric(target.Value)という2つの条件をAndでつなぐことで、「空欄でなく、かつ数値である」という1つの条件式にしています。反対にE2が空欄だったり「五個」のような文字列だったりすると、Else側のMsgBox "数量が未入力、または数値ではありません", vbExclamationが実行され、警告アイコン付きのメッセージが表示されます。

やってみよう 7-1: 売上明細のランクを判定しよう

この章で学んだIf文とSelect Caseを使って、「売上明細」シートの2行目に対する判定マクロを実際に作り、動かしてみましょう。

手順

  1. 1 「売上明細」の2行目について、金額（F2）を読み取りA/B/CのランクをG2に書き込むマクロ RankBySales を作る（7.3のコード例を参考にしてよい）。
  2. 2 D2（単価）とE2（数量）の値を書き換えて金額を変化させ、A・B・Cの3パターンすべてで正しく判定されることを確認する。
  3. 3 発展: ランクが"A"のときは、G2の文字を赤の太字にする処理を追加する（Range("G2").Font.Color = RGB(192, 0, 0) と Range("G2").Font.Bold = True を使う）。
  4. 4 さらに発展: 支店名（B2）からエリアを判定してH2に書き込む処理を、Select Caseを使って追加する（7.5のJudgeAreaを参考にしてよい）。H列「エリア」は第10章でユーザー定義関数として作り直すので、ここでは2行目だけで試すにとどめます。

理解度確認クイズ

  1. Q1. 次のコードで amount が 60000 のとき、rank に入る値はどれか。

    If amount >= 50000 Then
    rank = "B"
ElseIf amount >= 100000 Then
    rank = "A"
Else
    rank = "C"
End If

    ア. "A"　　イ. "B"　　ウ. "C"

    回答を表示

    正解: イ（"B"）
    ただし、このコードには重大な欠陥があります。amountが150000（15万円）であっても、先にamount >= 50000が成立してしまうため、rankは永久に"A"になりません。ElseIfは上から順に判定され、最初に成立した1つだけが実行されるため、条件は範囲の狭い（厳しい）ものから先に書く必要があります。

  2. Q2. If score >= 80 And score <= 89 Then と同じ意味になる Select Case の書き方はどれか。

    ア. Case 80, 89　　イ. Case 80 To 89　　ウ. Case Is >= 80

    回答を表示

    正解: イ
    Toは範囲を表します。アは「80、または89」という列挙で、その間の81〜88は含まれません。ウは「80以上すべて」という比較で、90以上の値も含んでしまい上限がありません。

この章のまとめ

  • If〜Then〜Elseで条件によって処理を切り替えられる。複数行ではEnd Ifが必須、1行形式では書かない。
  • ElseIfは上から順に評価され、最初に成立した1つだけが実行される。範囲が重なる条件は狭い方を先に書く。
  • 比較演算子（= <> > >= < <=）と論理演算子（And・Or・Not）を組み合わせて条件式を作る。Ifの中の「=」は比較の意味になる。
  • 同じ値を何度も比較するときはSelect Caseが読みやすい。列挙・範囲（To）・比較（Is）・Case Elseの4パターンを使い分ける。
  • IsEmpty・IsNumeric・IsDate・Likeなどの判定関数で、処理の前にデータが想定どおりかを確かめられる。
  • この章では「売上明細」の2行目という1つのセルだけを対象に条件分岐を扱った。複数行をまとめて処理する方法は次の第8章で学ぶ。

次の第8章では、For文やDo Whileといった繰り返し処理を学びます。この章で書いたRankBySalesやJudgeAreaのマクロを、売上明細の全行に対して自動的に繰り返し適用できるようになり、ようやく「実務で使える自動化」に近づきます。
