繰り返し処理

第7章までのコードは、すべて「2行目だけ」を対象に動いていました。しかし本ガイドの「売上明細」シートは10件ですが、実務では数百〜数千件のデータが並びます。1件ずつ手でコードを書き換えるのは現実的ではありません。この章では「同じ処理を、対象を変えながら何度も繰り返す」という、VBAの中でも特に強力な仕組み——繰り返し処理（ループ）を学びます。繰り返しの書き方はいくつかありますが、まずは For ~ Next を確実に身につけてください。表の2行目から最終行までを順に処理する、という業務でいちばん多い形はこれで書けます。For Each ~ Next は、集まりの中身を1つずつ取り出す書き方として、For ~ Next の次に紹介します。Do While / Do Until は、繰り返す回数が事前に決まっていないときに使う補足的な書き方です。まずは For ~ Next を軸に、第7章で覚えた If 文を全データ行へ一気に適用できるようになりましょう。

この章で学ぶこと

  • For ~ Next で、回数の決まった繰り返し処理が書ける
  • For Each ~ Next で、セルやシートなどの集まりを1つずつ処理できる
  • Do While / Do Until で条件による繰り返しが書け、無限ループを避けられる
  • Exit For / Exit Do で、ループを途中で抜けられる
  • 表の最終行までデータ全件を処理する、実務レベルのマクロが書ける

8.1 なぜ繰り返しが必要か

第7章では、金額（F列）が10万円以上かどうかを判定してランク（G列）を付ける If 文を書きました。ただし、あのコードが判定していたのは2行目だけです。「売上明細」シートには、2行目から11行目まで10件のデータが並んでいます（実務ではこれが数百行・数千行になります）。3行目、4行目、5行目……とすべて判定するには、どうすればよいでしょうか。

1つの答えは「同じ If 文を、行番号だけ変えてコピーする」ことです。試しに3行分だけ書いてみると、次のようになります。

繰り返しを使わない場合（非推奨） 
Sub RankWithoutLoop()
    Dim ws As Worksheet
    ' しきい値は第7章で定義した Const RANK_A_THRESHOLD を再利用する想定
    Const RANK_A_THRESHOLD As Long = 100000
    Set ws = Worksheets("売上明細")
    ' 2行目だけを判定（第7章の内容と同じ）
    If ws.Cells(2, "F").Value >= RANK_A_THRESHOLD Then ws.Cells(2, "G").Value = "A"
    ' 3行目も、まったく同じ処理を書く必要がある
    If ws.Cells(3, "F").Value >= RANK_A_THRESHOLD Then ws.Cells(3, "G").Value = "A"
    ' 4行目も……これを、データが続く限り繰り返すことになる
    If ws.Cells(4, "F").Value >= RANK_A_THRESHOLD Then ws.Cells(4, "G").Value = "A"
End Sub

データが500行あれば、この調子で500行分のコードが必要になります。行が増減するたびに書き直しも発生し、まったく実用的ではありません。

繰り返しを使わない場合

同じ処理を、行数の分だけ人力でコピーする必要がある。行数が変わるたびにコードも書き直しになる。

繰り返しを使う場合

「この処理を、行を変えながら最終行まで繰り返して」とVBAに指示するだけで済む。データが増えてもコードは変わらない。

この「同じ処理を、対象だけ変えて何度も行う」ことこそ、コンピュータが最も得意とする作業です。VBAには、この「繰り返し」を指示するための書き方が複数用意されていますが、最初に確実に身につけるべきは For ~ Next です。次の8.2から、まずこの基本形を見ていきましょう。

8.2 For ~ Next の基本

最初に紹介するのは For ~ Next です。「開始の値から終了の値まで、1つずつ数を変えながら繰り返す」という、最も基本的な繰り返し方です。まずは実際に動かして、カウンタの値が変化していく様子を見てみましょう。

For ~ Next の基本形 
Sub CountUp()
    Dim i As Long
    ' i を1から5まで、1つずつ増やしながら繰り返す
    For i = 1 To 5
        Debug.Print i          ' イミディエイトウィンドウに数値を表示
    Next i
End Sub

Debug.Print は、VBEのイミディエイトウィンドウ（表示されていない場合は Ctrl + G）に値を表示する命令です。上のマクロを実行すると、1・2・3・4・5という数値が順番に表示されます。For i = 1 To 5 から Next i までに書かれた処理が、i の値を変えながら5回実行された結果です。

flowchart TD A["i に開始値を入れる"] --> B{"i は終了値以下か"} B -->|Yes| C["ループの中の処理を実行"] C --> D["i に Step の値を足す"] D --> B B -->|No| E["ループを抜けて次の行へ"]

図の説明: For ~ Next は、「終了値以下かどうか」を毎回確認してから処理を実行し、実行後に自動でカウンタを進める、という動作を条件が崩れるまで繰り返します。この「確認 → 実行 → 更新」のサイクルが、繰り返し処理の基本の形です。

ヒント: ループを抜けた直後のカウンタの値に注意

For i = 2 To 10 が最後まで正常に実行されて終わった直後、i の値は 10 ではなく 11 になっています。条件を満たさなくなった時点、つまり「10を超えた」ところまで加算されてからループを抜けるためです。ループが終わったあとに i を使う処理を書くときは、この点を覚えておきましょう。

増分を変える: Step

既定では i は1ずつ増えますが、Step を付けると増え方を変えられます。減らしながら繰り返すことも可能です。

書き方 意味 iに入る値の順番
For i = 1 To 5 1から5まで、1ずつ増える（Step省略時の既定） 1, 2, 3, 4, 5
For i = 2 To 10 Step 2 2から10まで、2ずつ増える 2, 4, 6, 8, 10
For i = 10 To 1 Step -1 10から1まで、1ずつ減る 10, 9, 8, …, 1

Step -1 のように減らしながら回すパターンは、あとで8.6の「行を削除しながら処理する」場面で重要な役割を果たします。ここでは「増分は自由に変えられる」ということだけ覚えておいてください。

8.3 表の最終行まで回す定型パターン

第6章では、End(xlUp) を使ってデータが入っている最終行を求める方法を学びました。この lastRow と For ~ Next を組み合わせると、「2行目から最終行まで、1行ずつ処理する」という、VBAで最もよく使われる形が完成します。

ポイントは、Cells(i, "F") のようにカウンタ変数 i を行番号として使うことです。i が1増えるたびに、参照先のセルも1行下へ移動します。

iの値 参照するセル 対象となる行（例）
2 Cells(2, "F") 2026/04/01・東京・A4コピー用紙
3 Cells(3, "F") 2026/04/01・横浜・付箋セット
… … …
lastRow Cells(lastRow, "F") 最後のデータ行

実際に、単価（D列）×数量（E列）を計算して金額（F列）へ書き込むマクロを見てみましょう。第6章では数式（=D2*E2）としてF列に入れていた計算を、ここではループで計算結果の値そのものとして書き込みます。実行するとF列の数式は値に置き換わるため、以降はD列・E列を直してもF列は自動更新されない点に注意してください。

全行の金額を計算して書き込む — Forの定型パターン 
Sub FillAmount()
    Dim ws As Worksheet
    Dim lastRow As Long, i As Long
    Set ws = Worksheets("売上明細")
    lastRow = ws.Cells(ws.Rows.Count, "A").End(xlUp).Row   ' 最終行を求める
    ' 2行目から最終行まで、i を1ずつ増やしながら繰り返す
    For i = 2 To lastRow
        ' 金額（F列）＝ 単価（D列）× 数量（E列）
        ws.Cells(i, "F").Value = ws.Cells(i, "D").Value * ws.Cells(i, "E").Value
    Next i
    MsgBox lastRow - 1 & " 件の金額を計算しました"
End Sub
実行結果（MsgBoxに表示される文字の例） 
10 件の金額を計算しました

重要: この形を覚えれば、たいていの表は処理できる

lastRow = ws.Cells(ws.Rows.Count, "A").End(xlUp).Row で最終行を求め、For i = 2 To lastRow で1行目（見出し）を飛ばして最終行まで回す——この組み合わせは、以降の章でも繰り返し登場するVBAで最も使う定型文です。まずはこの形を、意味も含めてしっかり覚えておきましょう。

ヒント: 最終行を求めるのはループの「外」で1回だけ

End(xlUp) による最終行の取得を、うっかり For の中に書いてしまうと、ループが回るたびに毎回同じ計算をやり直すことになり、データ量が多いと極端に遅くなります。同様に、ループの中で Select や Activate を使うのも処理が遅くなる原因です（高速化の詳しい話は第11章で扱います）。最終行の取得は、必ずループへ入る前に1回だけ行い、変数に入れておきましょう。

繰り返しの中で条件分岐を使う — 第7章とのつながり

第7章で書いた If 文は、2行目1件だけを判定するものでした。その If 文を、8.3で学んだ For i = 2 To lastRow の中にそのまま入れるだけで、全データ行に同じ判定を適用できます。

繰り返しと条件分岐を組み合わせる — 全行にランクを付ける 
Sub RankAllRows()
    Dim ws As Worksheet, lastRow As Long, i As Long
    ' しきい値は第7章で定義した Const をここでも再利用する
    Const RANK_A_THRESHOLD As Long = 100000
    Const RANK_B_THRESHOLD As Long = 50000
    Set ws = Worksheets("売上明細")
    lastRow = ws.Cells(ws.Rows.Count, "A").End(xlUp).Row
    For i = 2 To lastRow
        ' 第7章の If を、ループの中に入れて全行に適用する
        If ws.Cells(i, "F").Value >= RANK_A_THRESHOLD Then
            ws.Cells(i, "G").Value = "A"
        ElseIf ws.Cells(i, "F").Value >= RANK_B_THRESHOLD Then
            ws.Cells(i, "G").Value = "B"
        Else
            ws.Cells(i, "G").Value = "C"
        End If
    Next i
End Sub

こうして、第7章では1行しか判定できなかった If 文が、繰り返しと組み合わせることで「売上明細」の全行を自動でランク付けできるようになりました。「繰り返し × 条件分岐」は、業務自動化の中核となる組み合わせです。

8.4 For Each ~ Next でコレクションを回す

ここまでの8.2・8.3で学んだ For ~ Next が、繰り返しの基本でした。ここからは、その次に押さえておきたい For Each ~ Next を紹介します。VBAでは、セル範囲やワークシートの集まりのことをコレクションと呼びます。「行番号を数える」のではなく「集まりの中身を1つずつ全部取り出したい」ときは、For Each ~ Next の方が自然に書けます。

For ~ Next ＝ 回数で数える

「2行目から最終行まで」のように、始まりと終わりが数値で分かっているときに向いています。カウンタ変数を自分で用意し、行番号として使います。

For Each ~ Next ＝ 集まりを丸ごと処理

「指定した範囲のセルすべて」のように、コレクションの全部に処理したいときに向いています。行番号を意識する必要がありません。

For Each で取り出した1つ1つの要素を受け取る変数は、要素の型に合わせて宣言します。

対象のコレクション 変数の宣言例 説明
セル範囲（Range） Dim c As Range 範囲内の1つ1つのセルを表す
ワークシート Dim ws As Worksheet ブック内の1つ1つのシートを表す（第9章で使用）
型を限定しない場合 Dim v As Variant どんな型のコレクションにも使える万能型

指定した範囲の数値セルだけを合計する例で、実際の動きを確認しましょう。

For Each でセルを1つずつ取り出して合計する 
Sub SumByForEach()
    Dim c As Range
    Dim total As Double
    ' 指定した範囲のセルを1つずつ c に取り出して繰り返す
    For Each c In Worksheets("売上明細").Range("F2:F1000")
        ' 空欄や文字列を除いて、数値だけを足す
        If IsNumeric(c.Value) And c.Value <> "" Then
            total = total + c.Value
        End If
    Next c
    MsgBox "合計金額: " & Format(total, "#,##0") & " 円"
End Sub

Range("F2:F1000") のように、実際のデータより広めに範囲を指定しても、空欄セルは c.Value <> "" のチェックで、文字列は IsNumeric のチェックで、それぞれ除外されるため問題ありません（空欄のセルは IsNumeric だけでは除外できない点に注意してください）。For Each は「どこからどこまで」を厳密に数えなくてよい分、こうした集計処理と相性が良い書き方です。

8.5 Do While / Do Until と無限ループ

Do While / Do Until は、繰り返す回数が事前に決まっていないときに使う書き方です。行数が分かっている表の処理は、8.2〜8.3で学んだ For ~ Next で書けるので、ここでは「こういう書き方もある」と知っておく程度で十分です。

For も For Each も、「繰り返す回数」や「対象の集まり」があらかじめ決まっている場合に使いました。しかし、「B列が空欄に出会うまで下へ進む」のように、あと何回繰り返すかが事前に分からない場面もあります。そんなときに使うのが Do While と Do Until です。

  • Do While 条件 〜 Loop — 条件がTrue（成立している）の間繰り返す
  • Do Until 条件 〜 Loop — 条件がTrue になるまで繰り返す

この2つは、条件の書き方を逆にすれば同じ動きにできます。「B列が空欄になるまで進む」という同じ要件を、両方の書き方で表すと次のようになります。

flowchart LR subgraph W["Do While（条件がTrueの間まわる）"] W1{"B列が空欄でない"} -->|True| W2["処理を実行"] W2 --> W1 W1 -->|False| W3["ループを抜ける"] end subgraph U["Do Until（条件がTrueになるまでまわる）"] U1{"B列が空欄になった"} -->|False| U2["処理を実行"] U2 --> U1 U1 -->|True| U3["ループを抜ける"] end

図の説明: 左の Do While は「空欄でない」という条件が True の間だけ処理を続けます。右の Do Until は「空欄になった」という条件が True になった時点で止まります。同じ結果を、条件の立て方を反転させることで両方の書き方で表現できます。

実際に「売上明細」から東京支店の明細を探す例で確認してみましょう。何行目まで探せばよいか事前には分からないため、B列（支店）が空欄になる、つまりデータの終わりに達するまで Do Until で1行ずつ下へ進みます。

条件が成立するまで繰り返す — Do Until と Exit Do 
Sub FindTokyo()
    Dim ws As Worksheet
    Dim i As Long
    Set ws = Worksheets("売上明細")
    i = 2
    ' B列が空欄になるまで、1行ずつ下へ進む
    Do Until ws.Cells(i, "B").Value = ""
        If ws.Cells(i, "B").Value = "東京" Then
            MsgBox i & " 行目に東京支店の明細が見つかりました"
            Exit Do                  ' 見つかったらループを抜ける
        End If
        i = i + 1                    ' これを忘れると無限ループになる
    Loop
End Sub

警告: 「空欄になるまで」は、データが1行も欠けていないことが前提

Do Until ws.Cells(i, "B").Value = "" のように空欄セルを終了条件にする書き方は、データが1行も欠けずに連続して並んでいることを前提にしています。データの途中に空白行が1行でもあると、そこで条件が成立してループを抜けてしまい、それより下のデータはまったく処理されません。

たとえば「売上明細」の10件のデータ（2〜11行目）のうち、6行目だけを空欄にしてこのコードを実行すると、i は5行目までしか進めず、7〜11行目の5件はまったく処理されないまま取りこぼされます。

実務では、第6章で学んだ End(xlUp) などで最終行を先に求めてから、8.3で学んだ For ~ Next で回すほうが安全です。For i = 2 To lastRow は行番号を基準に回すため、途中に空白行があってもそこで止まらず、最終行までのすべての行を確実に処理できます。

途中に出てくる Exit Do は、目的のデータが見つかった時点で Do 〜 Loop を強制的に抜ける命令です。これがなければ、東京支店のデータを見つけたあとも、最後の行まで無駄に探し続けてしまいます。Exit Do の考え方は8.6でもう一度詳しく扱います。

警告: 無限ループに注意——止め方を必ず覚えておく

上のコードで、探している支店が2行目に無い場合（＝Exit Do に到達しない場合）に i = i + 1 を消して実行すると、i がずっと2のままなので、条件（B列が空欄になったか）が永遠に成立せず、ループが終わらなくなります。これを無限ループと呼びます。画面が反応しなくなったように見え、初心者はここで強い不安を感じがちです。

落ち着いて、EscキーまたはCtrl + Breakを押してください。実行が強制的に中断され、「中断」ボタンのあるダイアログか、エラーメッセージが表示されます。そこでコードを見直し、条件に関わる値（カウンタなど）をループの中でちゃんと変化させているか確認しましょう。無限ループ自体はよくある失敗であり、慣れれば誰でも数秒で復旧できます。

8.6 Exit For / Exit Do と、繰り返しの注意点

Exit Do と同様に、For ~ Next にも途中で抜けるための命令 Exit For があります。目的のデータが見つかった時点でループを終えれば、残りの行を無駄に調べずに済み、処理が速くなります。

見つかった時点でForループを抜ける — Exit For 
Sub FindFirstHighAmount()
    Dim ws As Worksheet
    Dim lastRow As Long, i As Long
    ' しきい値は第7章で定義した Const RANK_A_THRESHOLD を再利用する想定
    Const RANK_A_THRESHOLD As Long = 100000
    Set ws = Worksheets("売上明細")
    lastRow = ws.Cells(ws.Rows.Count, "A").End(xlUp).Row
    For i = 2 To lastRow
        If ws.Cells(i, "F").Value >= RANK_A_THRESHOLD Then
            MsgBox i & " 行目で初めて10万円以上の金額が見つかりました"
            Exit For              ' 見つかったのでForループを抜ける
        End If
    Next i
End Sub

Exit For は For ループを、Exit Do は Do ループを抜けるという違いだけで、考え方は同じです。「探し物が見つかったら、それ以上探さない」という、人間の自然な振る舞いをコードにしたものだと考えてください。

実務の落とし穴: 行を削除しながらループすると行が飛ぶ

繰り返し処理の中でありがちな失敗が、データ行を削除しながら、上から下へループすることです。行を削除すると、それより下の行はすべて1つずつ繰り上がります。しかしカウンタ i はそれを知らずに単純に+1されるため、繰り上がってきた行が判定を受けずに素通りしてしまいます。

タイミング 5行目 6行目 次にiが指す行
i = 5 で削除する前 削除対象のデータ 次のデータ —
5行目を削除した直後 元6行目のデータが繰り上がる 元7行目のデータが繰り上がる i は 6 へ進む
結果 繰り上がった元6行目のデータ（新5行目）は、iが5を通り過ぎたあとなので判定されずに見逃される

警告: 行を削除するループは、下から上へ回す

この問題を避けるには、For i = lastRow To 2 Step -1 のように、最終行から2行目に向かって、下から上へ処理します。現在の i より下の行を削除しても、まだ処理していない上の行の番号はズレないため、安全に全行をチェックできます。

行の削除・挿入をともなうループでは、必ず処理の向きを意識する習慣をつけましょう。

下から上へ処理して安全に行を削除する 
Sub DeleteEmptyRank()
    Dim ws As Worksheet
    Dim lastRow As Long, i As Long
    Set ws = Worksheets("売上明細")
    lastRow = ws.Cells(ws.Rows.Count, "A").End(xlUp).Row
    ' 下から上へ処理すると、削除しても行がずれない
    For i = lastRow To 2 Step -1
        If ws.Cells(i, "G").Value = "" Then
            ws.Rows(i).Delete            ' G列が空欄の行を削除
        End If
    Next i
End Sub

なお DeleteEmptyRank は「G列（ランク）が空欄の行」を削除するマクロなので、RankAllRows を実行する前に動かすとすべてのデータ行が消えてしまいます。行を削除するマクロは、必ず練習用にコピーしたブックで、削除条件を確かめてから実行してください。

ここまでで、Excelのデータ全件を安全かつ効率よく処理するための土台がそろいました。次の第9章では、この繰り返し処理を使って複数のワークシートを横断的に扱う方法を学びます。

理解度確認クイズ

  1. Q1. For i = 2 To 10 Step 2 のループは何回実行されますか。

    回答を表示

    正解: 5回
    i は 2, 4, 6, 8, 10 と変化するので5回実行されます。Step を省略すると1ずつ増えるため、もし For i = 2 To 10（Stepなし）であれば9回になります。

  2. Q2. Do While 〜 Loop が終わらなくなる原因として最も多いものはどれですか。

    回答を表示

    正解: ループの中で条件に関わる値（カウンタなど）を変化させていない
    条件が変化しないと永久に成立し続け、ループが終わりません。無限ループに陥ったら Ctrl + Break で中断し、「ループの中で条件が変化しているか」を確認しましょう。Loop の書き忘れは構文エラーになりコンパイルの時点で気づけるため、実行時に気づきにくい無限ループの原因としては、条件の更新忘れの方がはるかに多く見られます。

この章のまとめ

  • For ~ Next は、開始値から終了値までカウンタを自動的に変化させながら処理を繰り返す。Step で増分（減分）を変えられる。
  • For i = 2 To lastRow は、表の全データ行を処理するVBAで最もよく使う定型パターン。最終行の取得はループの外で1回だけ行う。
  • For Each ~ Next は、セル範囲やワークシートなどのコレクションを、回数を数えずに1つずつ処理する。
  • Do While / Do Until は、繰り返す回数が事前にわからないときに使う。条件を更新し忘れると無限ループになり、止めるには Escキー / Ctrl + Break を使う。
  • Exit For / Exit Do で、目的のデータが見つかった時点でループを途中終了できる。
  • 行を削除・挿入しながらループするときは、For i = lastRow To 2 Step -1 のように下から上へ処理し、行のズレを防ぐ。
