DAX入門

前章までで、Sales を中心にディメンションがつながったスタースキーマが整いました。ここからは、そのモデルに対して「売上金額はいくつか」「件数は何件か」といった指標そのものを計算する言語、DAX（ダックス）を学びます。DAX は本ガイドの中でもっとも新しい考え方が登場する章で、Excel の数式に慣れているほど戸惑いやすい部分でもあります。特に計算列とメジャーの違いは、最初につまずきやすく、かつ理解できれば以降すべての作業が楽になる本章最大の山場です。焦らず一つずつ確認していきましょう。

この章で学ぶこと

  • DAX とは何かを説明でき、Power Query との役割分担を整理できる
  • 計算列とメジャーの違いを説明し、どちらを使うべきか自分で判断できる
  • SUM・COUNTROWS・DISTINCTCOUNT・DIVIDE など基本の関数でメジャーを作れる
  • CALCULATE で「見る条件」を付け替えるという考え方を理解する

7.1 DAX とは何か

DAX（Data Analysis Expressions）は、Power BI のデータモデルに対して計算を行うための数式言語です。「Excel の数式と似ている」とよく言われ、実際に SUM や IF のように同じ名前の関数もあります。ただし決定的な違いがあります。Excel の数式は1つのセルを対象にしますが、DAX の数式は列全体・テーブル全体を対象にします。SUM(Sales[Amount]) は「特定のセル」ではなく「Sales テーブルの Amount 列すべて」を合計する、という発想の切り替えが最初の関門です。

第4章で学んだ Power Query と、この章で学ぶ DAX は、どちらも「データを加工する」という意味では似て見えますが、担当する工程がまったく違います。混同すると「型を直す作業をDAXでやろうとする」「毎回の絞り込みをPower Queryでやろうとする」といった遠回りをしてしまうため、最初に役割分担を整理しておきます。

観点 Power Query（第4章） DAX（この章）
いつ動くか データを読み込む・更新するとき レポートを表示する・操作するとき
何をするか 行・列・テーブルそのものを整形する 整ったデータに対して計算し、指標を作る
たとえるなら 下ごしらえ（洗う・切る・型をそろえる） 味付け・盛り付け（計算して数値に仕上げる）
代表的な成果物 整形済みのテーブル 計算列・メジャー（次節で解説）

集計する

SUM や COUNTROWS で、合計・件数・平均などの指標を作る。

判定する

IF で、条件に応じて表示する値や文字列を切り替える。

絞り込む

CALCULATE で、今見ている条件を一時的に付け替えて計算する。

名前が同じでも中身は別物

Excel の SUM と DAX の SUM は名前も役割も似ていますが、引数として渡すのは「セル範囲」ではなく「列」です。SUM(Sales[Amount]) のように、テーブル名と列名を角括弧で組み合わせて指定します。この書き方に最初は慣れが必要ですが、本章の例をなぞれば自然に身につきます。

7.2 計算列とメジャーの違い（本章の山場）

DAX で作れる代表的なものが2種類あります。計算列（Calculated Column）とメジャー（Measure）です。どちらも同じ DAX の書き方を使うため見た目は似ていますが、「いつ計算されるか」「どこに保存されるか」がまったく異なります。この違いを理解しないまま進めると、後になって「ファイルが重い」「思った数字にならない」という原因不明のトラブルにつながるため、ここで丁寧に整理します。

まず計算列の例を見てみましょう。Sales テーブルに「税込金額」という新しい列を追加する DAX です。

計算列の例（Sales テーブルに新しい列を追加） 
// Sales の各行に「税込金額」という列を追加する
税込金額 = Sales[Amount] * 1.1

この式は、Sales テーブルの行1件ごとに計算され、その結果が新しい列としてテーブルの中に保存されます。テーブルビューを開くと、まるで最初から入っていたデータのように新しい列が見えるのが計算列です。一方でメジャーは、次のようにテーブルには属さない、独立した計算式として定義します。

観点 計算列（Calculated Column） メジャー（Measure）
計算されるタイミング データの読み込み・更新時に、行ごとに1回計算 レポートを表示・操作するたびにその場で計算
保存先 テーブルの列として、結果を行数分だけ保存する 計算式だけを保存し、結果そのものは保存しない
ファイルサイズへの影響 行数が多いテーブルほど大きくなりやすい 式だけなので、ほぼファイルサイズに影響しない
使いどころ 行ごとに区分・カテゴリを持たせ、スライサーや軸として使いたいとき 合計・件数・平均など、集計して1つの数値にしたいとき（実務での大半はこちら）

行ごとに計算"] --> A2["結果をテーブルの
列として保存"] A2 --> A3["行数分のデータが増え

重要ポイント: 迷ったらメジャー

「売上金額」「受注件数」「平均単価」のように集計して1つの数値を出したいだけなら、ほぼ常にメジャーが正解です。計算列は、集計の結果ではなく「行ごとの新しい属性（区分・分類・フラグなど）」を作りたいときに限って使います。新人のうちは「まず全部メジャーで作ってみて、行ごとの属性が欲しくなったら計算列を検討する」くらいの姿勢で十分です。

7.3 基本の集計関数

ここからは、実際にメジャーとしてよく使う関数を1つずつ確認します。まずは「合計する」「数える」という、集計の基本となる4つの関数です。書き方はどれもシンプルで、関数名(テーブル名[列名]) という形を覚えれば大半に応用できます。

関数 何をする関数か
SUM 指定した数値列の合計を求める
COUNT 指定した列のうち、値が入っている行数を数える
COUNTROWS 列ではなくテーブル全体を指定し、行数そのものを数える
DISTINCTCOUNT 指定した列の重複を除いた、ユニークな値の数を数える

「みらい商事」の売上データで、代表的な3つのメジャーを作ってみましょう。Sales テーブルには1行が1件の売上明細として記録されているため、COUNTROWS(Sales) がそのまま「受注件数」になります。

メジャーの定義（新しいメジャー） 
// 売上金額の合計を求めるメジャー
売上金額 = SUM(Sales[Amount])
// 販売数量の合計を求めるメジャー
販売数量 = SUM(Sales[Quantity])
// 売上明細の行数＝受注件数を数えるメジャー
受注件数 = COUNTROWS(Sales)

続いて COUNT と DISTINCTCOUNT です。両者は「数える」という点で似ていますが、COUNT は値が入っている行の数を、DISTINCTCOUNT は重複を除いたユニークな値の数を数えるという違いがあります。「取引が何件あったか」なら COUNT や COUNTROWS、「顧客が何社あったか」のように同じ値の重複を1つに数えたいときは DISTINCTCOUNT を使います。

メジャーの定義（新しいメジャー） 
// 数量が入力されている売上明細の行数を数える
数量記録件数 = COUNT(Sales[Quantity])
// CustomerID の重複を除き、取引のあった顧客数を数える
顧客数 = DISTINCTCOUNT(Sales[CustomerID])

同じ顧客が何度も注文していても、DISTINCTCOUNT(Sales[CustomerID]) であれば「その顧客は1社」として数えられます。単純に行数を数える COUNTROWS との違いを意識しておきましょう。

7.4 安全な割り算と条件分岐

「平均単価」のように、2つのメジャーを割り算して求める指標もよく使います。ここで新人がほぼ必ずつまずくのがゼロ除算です。もし販売数量が0件のカテゴリがあった場合、[売上金額] / [販売数量] という書き方では計算が破綻し、レポート上にエラーや無限大の表示が出てしまいます。

注意: / による割り算はゼロ除算に弱い

スライサーで期間や地域を絞り込むと、分母となる件数や数量が0になる組み合わせは普通に発生します。単純な / 演算子だけで指標を作ると、絞り込みのたびにエラー表示が出てレポートの信頼性を損ないます。割り算のメジャーは、原則として次の DIVIDE を使いましょう。

DIVIDE 関数は、分子・分母に加えて「分母が0だったときに返す値（省略時は空白）」を指定できる、割り算専用の安全な関数です。

メジャーの定義（安全な割り算） 
// 売上金額 ÷ 販売数量。分母が0なら空白を返す
平均単価 = DIVIDE([売上金額], [販売数量])

ここで [売上金額] や [販売数量] のようにテーブル名を付けずに角括弧だけで書いているのは、すでに定義した別のメジャーを呼び出しているためです。列を参照するときは Sales[Amount] のようにテーブル名が必要ですが、メジャーを参照するときはメジャー名だけで書けます。既存のメジャーを組み合わせて新しいメジャーを作れるのも DAX の便利な特徴です。

もう1つ、条件によって結果を変えたいときは IF を使います。書き方は Excel の IF とほぼ同じで、「条件」「真のときの値」「偽のときの値」の順に指定します。

メジャーの定義（条件分岐） 
// 売上金額が100万円以上なら「達成」、それ以外は「未達」
達成判定 = IF([売上金額] >= 1000000, "達成", "未達")

DIVIDE と IF はどちらもメジャーの中で他のメジャーと組み合わせて使えます。この「小さなメジャーを組み合わせて、少し複雑なメジャーを作る」という積み上げ方に慣れると、DAX 全体の見通しが良くなります。

7.5 CALCULATE 入門

CALCULATE は、DAX の中でもっとも重要でありながら、初心者にとって最初はイメージしづらい関数です。一言で言うと、「今どこを見ているか」という条件（フィルター）を、一時的に付け替えて計算する関数です。この「今どこを見ているか」を専門用語でフィルターコンテキストと呼びますが、本ガイドでは深追いせず、「レポート上でスライサーやページの絞り込みによって、今そのメジャーに効いている条件」という理解で十分です。

たとえば、レポート全体としては全カテゴリの売上を見ているとします。そこから「文具カテゴリだけの売上金額」を、スライサーを使わずにメジャー側で固定して求めたいとき、CALCULATE の出番です。

メジャーの定義（CALCULATE） 
// Category が「文具」の行だけに絞って売上金額を計算する
文具カテゴリ売上 = CALCULATE([売上金額], Products[Category] = "文具")

CALCULATE の第1引数には計算したいメジャーや式（ここでは [売上金額]）、第2引数以降には付け替えたい条件を指定します。第5章で学んだ「フィルターは1側から多側へ流れる」という仕組みのおかげで、Products[Category] = "文具" という条件が Products テーブルから Sales テーブルへ伝わり、文具カテゴリの行だけを対象に SUM が計算されます。

flowchart LR A["売上金額
今の絞り込み条件のまま計算"] -->|CALCULATE で
条件を付け替える| B["文具カテゴリ売上
Category＝文具に固定して再計算"]

今の段階では「そういうものだ」で十分

CALCULATE の正確な動作原理（フィルターコンテキストの評価順序など）は上級者向けの内容で、書籍が1冊書けるほど奥が深いテーマです。新人のうちは「特定の条件に固定した指標を作りたいときに使う関数」という理解でまったく問題ありません。実務で必要になったときに、改めて深く学べば十分間に合います。

7.6 メジャーの作り方と整え方

最後に、ここまで見てきたメジャーを実際に Power BI Desktop 上で作る手順と、見た目を整えるコツを確認します（画面名はバージョンにより多少異なる場合があります）。

  1. 1 「データ」ペインで Sales テーブルを右クリックし、新しいメジャー を選択する。
  2. 2 画面上部の数式バーに 売上金額 = SUM(Sales[Amount]) のように入力し、Enter で確定する。
  3. 3 作成したメジャーを選択した状態でリボンのメジャー ツールタブを開き、書式を通貨や小数に設定し、桁区切りを有効にする。
  4. 4 同じ手順で「受注件数」「平均単価」など、必要なメジャーを追加していく。

メジャーの数が増えてくると、どのテーブルに何のメジャーがあるのか分かりにくくなります。実務では、実データを持たないメジャー専用テーブル（例: _Measures）を1つ作り、すべてのメジャーをそこに移動して整理するという小技がよく使われます。データは1行も入っていない「メジャーの置き場所」を作るイメージです。本ガイドでは名前だけ紹介しますので、余裕があれば試してみてください。

やってみよう 7-1: 3つのメジャーを作りカードで確認する

第5章・第6章で作ったモデルに対して、本章で学んだメジャーを実際に作成し、カードビジュアルで数字を確認しましょう。

手順

  1. 1 Sales テーブルに 売上金額 = SUM(Sales[Amount])、受注件数 = COUNTROWS(Sales)、販売数量 = SUM(Sales[Quantity]) の3つのメジャーを作成する。
  2. 2 続けて 平均単価 = DIVIDE([売上金額], [販売数量]) を作成する。
  3. 3 レポートビューでキャンバスに「カード」ビジュアルを4つ配置し、それぞれに4つのメジャーを1つずつ割り当てる。
  4. 4 売上金額のカードには通貨書式、平均単価のカードには小数1桁の書式を設定し、表示が崩れないか確認する。

理解度確認クイズ

  1. Q1. 計算列とメジャーの違いを、計算されるタイミングと保存先の観点から説明してください。

    回答を表示

    計算列は、データの読み込み・更新時に行ごとに1回だけ計算され、結果がテーブルの列として保存されます。行数が多いほどファイルサイズが増えます。メジャーは、レポートを表示・操作するたびにその場で計算される式で、結果そのものは保存されません。合計・件数・平均のように集計して1つの数値を出したいときはメジャーを使うのが基本です。

  2. Q2. 平均単価を計算するとき、/ 演算子ではなく DIVIDE 関数を使うべき理由は何ですか。

    回答を表示

    スライサーなどで絞り込むと、分母（販売数量など）が0になる組み合わせが発生し得ます。/ 演算子だけで割り算をすると、分母が0のときにエラーや無限大の表示が出てレポートが崩れてしまいます。DIVIDE([売上金額], [販売数量]) のように書けば、分母が0のときに自動的に空白（既定値）を返すため、エラーを起こさずに安全に計算できます。

  3. Q3. CALCULATE はどのような関数ですか。簡単に説明してください。

    回答を表示

    CALCULATE は、今その計算に効いている絞り込み条件（フィルターコンテキスト）を一時的に付け替えて計算する関数です。例えば CALCULATE([売上金額], Products[Category] = "文具") のように書くと、レポート全体の絞り込み状態にかかわらず、常に「文具カテゴリだけ」に固定した売上金額を求められます。
