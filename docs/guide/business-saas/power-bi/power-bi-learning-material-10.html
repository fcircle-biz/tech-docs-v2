ホーム Power BI 第10章
第10章 所要時間: 約60分

Power BI Service

ここまでの章では、作業はすべて Power BI Desktop の中で完結していました。第9章までで仕上げた「みらい商事」の売上レポートも、まだあなたの PC の中にある1つの.pbixファイルにすぎません。この章では、そのレポートを Power BI Service に発行し、ワークスペースという場所でチームと共有し、ダッシュボードやアプリとして配布し、データを最新に保ち続けるところまでの一連の流れを学びます。第1章で触れた「作るのは Desktop、配るのは Service」という一言を、実際に手を動かして体験する章です。

この章で学ぶこと

  • Power BI Desktop から Power BI Service へレポートを発行する流れを説明できる
  • ワークスペースの役割と、管理者・メンバー・共同作成者・ビューアーという4つのロールの違いを理解する
  • セマンティックモデルとレポートが別々に登録される利点、ダッシュボードとレポートの違いを説明できる
  • アプリによる配布の考え方と、データ更新（手動・スケジュール）の仕組みを理解する

10.1 Desktop から Service へ

第1章で整理したとおり、本ガイドでは Power BI Desktop を作る場所、Power BI Service を配る場所として扱ってきました（Service 上でも作成・編集はできますが、学びやすさから Desktop を中心にしています）。レポートが Desktop の中にある間は、自分のパソコンでしか見られません。Desktop 単体には共有・権限管理の機能がないため、チームで共有できるようにするには Service へ発行（Publish）します。

発行の操作自体はとても簡単で、Desktop のリボンにあるホームタブから発行ボタンを押すだけです。ただし、発行には組織のアカウント（会社や学校のメールアドレスで作成したアカウント）でのサインインが必要です。個人用のメールアドレスで作成したアカウントでは、Power BI Service を利用できません。

  1. Desktop でホームタブの発行を選択する
  2. 発行先のワークスペースを一覧から選ぶ（最初は自分の「マイワークスペース」で構わない）
  3. アップロードが完了すると「正常に発行されました」というメッセージが表示される
  4. 表示されたリンクを開くか、ブラウザで Power BI Service にアクセスしてレポートを確認する

発行前

レポートは自分の PC の中の.pbixファイルだけに存在し、他の人は見られません。

発行

発行ボタンを押すと、モデルとレポートがワークスペースへアップロードされます。

発行後

ワークスペースのメンバーが、ブラウザやスマートフォンでレポートを開けるようになります。

発行から利用者に届くまでの道のりを1本の図にすると、次のようになります。本章はこの図の右半分、Service に入ってから先の話です。

flowchart LR A["Power BI Desktop
レポートを作成"] -->|発行| B["Power BI Service
クラウド上のサービス"] B --> C["ワークスペース
チームの作業スペース"] C --> D["レポート／アプリ
共有・配布の形"] D --> E["利用者
ブラウザ・モバイルで閲覧"]

注意: Power BI Service には組織アカウントが必要

個人用の無料メールアドレスでは Power BI Service にサインインできません。会社や学校から発行された Microsoft 365 の組織アカウントを使用してください。名称やサインイン画面の見た目はバージョンにより異なる場合があります。

10.2 ワークスペース

発行先として選んだワークスペースは、Power BI Service の中でレポートやデータを整理する「入れ物」です。サインインすると、最初からマイワークスペースという個人用の場所が1つ用意されています。チームで使うときは、これとは別に共有ワークスペースを作成します。

比較する点 マイワークスペース 共有ワークスペース
目的 個人の作業・動作確認 チームでの共同作業・本番運用
参加できる人 自分だけ 招待されたメンバー全員
ロールの割り当て できない（自分がすべてを行う） 管理者・メンバー・共同作成者・ビューアーを個別に割り当てられる
向いている使い方 個人的な検証・下書き 「みらい商事」の売上分析のような実際の業務データを扱うレポート

重要ポイント: マイワークスペースを本番運用に作り込まない

マイワークスペースは自分専用の場所のため、他の人にロールを割り当てて共同編集する運用には向きません。異動や退職でアカウントが使えなくなると、レポートごと宙に浮いてしまう危険もあります。チームで継続して使うレポートは、最初から共有ワークスペースに置く習慣をつけましょう。

共有ワークスペースでは、メンバーごとにロール（役割）を割り当てます。ロールによってできることが異なり、全員に強い権限を渡す必要はありません。

ロール 主にできること 向いている担当
管理者 ワークスペースの設定変更、メンバーの追加・削除（管理者の追加を含む）、ワークスペース自体の削除 プロジェクトの責任者・情報システム部門の担当者
メンバー アプリの発行、コンテンツの共有、メンバー以下のロールの追加・編集 レポート作成の主担当者
共同作成者 レポートやセマンティックモデルの追加・編集。ただしアプリの発行や他ユーザーの招待はできない レポート作成を手伝うメンバー
ビューアー 発行済みのレポート・ダッシュボードの閲覧のみ。編集はできない レポートを見るだけの現場担当者

ロールの名称や権限の細かい範囲は、Power BI のバージョンや契約プランによって変わることがあります。迷ったときは「まずビューアーから始め、必要になった人だけ引き上げる」という考え方が安全です。

10.3 発行すると何ができるのか

発行が完了すると、ワークスペースの中に2種類の項目が別々に登録されていることに気づくはずです。1つはセマンティックモデル、もう1つはレポートです。

セマンティックモデルとは、第5章・第6章で組み立てたテーブルとリレーション、第7章で作ったメジャーをまとめた、分析の土台そのものです。以前は「データセット」と呼ばれており、Service の画面上ではこの名称が残っている箇所もあります。

レポートとモデルが別項目として登録される最大の利点は、1つのセマンティックモデルから複数のレポートを作れることです。たとえば「みらい商事」のモデルを土台に、経営層向けのサマリーレポートと、営業部向けの詳細分析レポートを別々に用意できます。モデルを1か所で更新すれば、そこから作られたすべてのレポートに同じ数字が反映されるため、レポートごとに集計結果がずれる心配がありません。

flowchart TD M["セマンティックモデル
みらい商事 売上分析"] --> R1["レポートA
経営層向けサマリー"] M --> R2["レポートB
営業部向け詳細分析"] M --> R3["レポートC
店舗別の実績確認用"]

用語: データセットとセマンティックモデル

同じものを指す呼び方が2つあるだけです。「セマンティックモデル」は比較的新しい呼び方で、「データセット」は以前からの呼び方です。ドキュメントや画面によって表記が混在することがあるので、両方とも覚えておくと迷いません。

10.4 ダッシュボードとレポートの違い

第1章のヒントカードでも軽く触れましたが、初心者が混同しやすい用語をもう一度、作り方の違いまで含めて整理しておきましょう。

比較する点 ダッシュボード レポート
ページ数 1ページのみ 複数ページ
作成場所 Power BI Service 上でのみ作成 主に Power BI Desktop で作成して発行
中身 「タイル」と呼ばれる部品を貼り付けたもの ビジュアルを配置したページ
データソース 複数のレポート・複数のセマンティックモデルのタイルを1枚に集約できる 基本的に1つのセマンティックモデルに基づく
対話性 タイルをクリックすると元のレポートへ移動する程度 スライサー・フィルター・ドリルダウンなどで自由に掘り下げられる（第8章・第9章）
向いている使い方 経営層が毎朝ざっと状況を確認する「一覧性」重視 担当者が原因を掘り下げて分析する「深掘り」重視

ダッシュボードのタイルは、レポートを開いてビジュアルにカーソルを合わせたときに表示されるピン留めアイコンから追加します。1つのダッシュボードに、複数のレポートから集めたタイルを並べられる点が、レポート単体との大きな違いです。具体的な手順は本章末の「やってみよう」で実際に試します。

10.5 アプリで配布する

レポートやダッシュボードを見てもらう方法は1つではありません。ここでは代表的な2つの方法、共有リンク（個別共有）とアプリを比較します。

共有リンクは、レポートやダッシュボードの画面右上にある共有から相手を指定して直接送る方法です。手早く試せますが、共有する相手が増えるたびに個別に権限を設定する必要があり、誰にどこまで渡したかを把握しづらくなります。受け取った相手がさらに他の人へ再共有できてしまう設定にも注意が必要です。

アプリは、ワークスペースの内容をひとまとめにパッケージ化し、ナビゲーション付きの1つの画面として配布する仕組みです。対象者（オーディエンス）をグループ単位で指定でき、更新も一括で反映されます。閲覧者はワークスペース自体の編集権限を持たなくてよいため、誤って中身を変更してしまう心配もありません。

比較する点 共有リンク アプリ
配布の単位 レポートやダッシュボードを1点ずつ ワークスペースの内容をまとめて
対象の指定 個人ごとに指定 部署やグループ単位で指定
閲覧者から見える範囲 共有された項目がそのまま見える 整理されたナビゲーションだけを見せられる
更新の手間 増えるたびに共有し直す ワークスペースを更新して再発行すれば一括で反映

アプリを配布するおおまかな流れは次のとおりです。

  1. ワークスペースの右上にあるアプリを発行を選択する
  2. アプリの名前・説明・アイコンなど基本情報を設定する
  3. アプリに含めるレポート・ダッシュボードを選び、ナビゲーションの並び順を決める
  4. 対象者（全社員、または特定の部署のグループなど）を指定する
  5. 発行を押すと、対象者のアプリ一覧に表示されるようになる

10.6 データの更新

レポートを発行して終わりではありません。「みらい商事」の売上データは毎日増えていきます。Service 側のデータを最新の状態に保つ操作が更新（Refresh）です。

手動更新は、ワークスペースでセマンティックモデルの今すぐ更新を選ぶ方法です。その場でデータソースに再接続し、最新のデータを取り込み直します。スケジュール更新は、セマンティックモデルの設定画面であらかじめ更新の頻度と時間帯を決めておく方法で、決めた時刻に自動で更新が実行されます。

これらの更新が必要になるのは、第3章で学んだImportでデータを取り込んでいる場合です。DirectQueryではレポートを開くたびにデータソースへ直接問い合わせるため、この意味でのスケジュール更新は基本的に不要です。

重要ポイント

更新はあくまで「裏側の数字」を新しくするだけの操作です。ビジュアルの配置や色、スライサーの設定といったレポートの見た目は、更新の前後で変わりません。「レポートが壊れた」と感じたら、まず更新が正しく終わっているかを確認しましょう。

ライセンスについて（本章では概要のみ）

Power BI Service を利用するには、無償ライセンス、Pro ライセンス、PPU（Premium Per User）ライセンス、組織が契約する Fabric 容量など、いくつかの提供形態があります。どれを使えるかによって、共有できる相手の範囲やスケジュール更新の回数などが変わります。価格や提供条件は変更されることがあるため、詳細は社内の管理者や公式情報を確認してください。

やってみよう 10-1: レポートを発行してダッシュボードにピン留めする

第8章・第9章で作った「みらい商事」のレポートを Power BI Service に発行し、そこからダッシュボードを作る一連の流れを体験しましょう。

手順

  1. 1 Power BI Desktop で対象の.pbixを開き、ホーム → 発行を選択する。
  2. 2 発行先のワークスペース（共有ワークスペースがあればそれを、なければマイワークスペースでもよい）を選ぶ。
  3. 3 発行が完了したら、表示されたリンクからブラウザで Power BI Service を開き、レポートの各ページを確認する。
  4. 4 カテゴリ別売上の棒グラフなど、任意のビジュアルにカーソルを合わせ、表示されたピン留めアイコンをクリックする。
  5. 5 新しいダッシュボードを選んで名前を付け、タイルとして追加されたことを確認する。
  6. 6 別のページにあるビジュアルも同じダッシュボードにピン留めし、複数レポートの要素を1画面にまとめる感覚をつかむ。

理解度確認クイズ

  1. Q1. セマンティックモデルとレポートが別々に登録されることには、どんな利点がありますか？

    回答を表示

    1つのセマンティックモデルを土台に複数のレポートを作れるため、モデルを1か所で更新すればそこから作られたすべてのレポートに同じ数字が反映され、レポートごとに集計方法がずれる心配がありません。経営層向けの要約レポートと現場向けの詳細レポートを、同じデータから別々に用意できる点も利点です。

  2. Q2. ダッシュボードとレポートは何が違いますか？

    回答を表示

    ダッシュボードは1ページにタイルを貼り付けた「一覧性」重視のまとめ画面で、Power BI Service 上でのみ作成し、複数のレポートやセマンティックモデルからタイルを集められます。レポートは複数ページからなり、スライサーやフィルター、ドリルダウンなどで自由に掘り下げられる分析用の資料で、主に Desktop で作成します。

  3. Q3. レポートを共有リンクではなくアプリで配布するのはなぜですか？

    回答を表示

    アプリはワークスペースの内容をひとまとめにパッケージ化し、対象者をグループ単位で指定して配布できるため、閲覧者ごとに個別共有する手間が減り、更新も一括で反映されます。閲覧者はワークスペース自体の編集権限を持たずに済むため、誤って中身を変更してしまう心配もありません。
