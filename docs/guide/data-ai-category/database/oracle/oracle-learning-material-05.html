表の作成とデータ型

第4章で SQL*Plus と SQL Developer の使い方を覚えたので、この章ではいよいよ自分のデータを入れる「表（テーブル）」を作ります。表の設計図となるデータ型と制約の考え方を学んだあと、実際に部署表（departments）と社員表（employees）を作成してサンプルデータを投入します。ここで作る2つの表は、第6章以降のすべての章で使う共通の教材になりますので、じっくり手を動かして完成させましょう。

この章で学ぶこと

  • 表・行・列・スキーマという言葉を、表計算ソフトとの対応で説明できる
  • VARCHAR2・NUMBER・DATEなど、Oracleの主要なデータ型を用途に応じて選べる
  • CREATE TABLEで制約付きの表を作成し、ALTER TABLE・DROP TABLEで変更・削除できる
  • 主キーの値を自動採番する2つの方法（シーケンスとIDENTITY列）の違いを説明できる

5.1 表・スキーマ・オブジェクトとは

データベースにデータを入れる箱のことを表（テーブル）と呼びます。イメージは表計算ソフトの1枚のシートそのものです。本ガイドではこれから、「会社の社員名簿」に相当する employees 表と、「会社の部署一覧」に相当する departments 表の2枚を作っていきます。この2つの表は、第6章以降のすべての章で繰り返し使う共通の教材です。

表計算ソフトとデータベースの用語は、次のように対応しています。

表計算ソフトの用語 データベースの用語 意味
シート1枚 表（テーブル） 同じ形式のデータをまとめて保管する入れ物
1行分のデータ 行（レコード） 1件分のまとまったデータ（社員1人ぶんなど）
列見出し 列（カラム） 氏名・給与のような項目そのもの

もう1つ覚えておきたいのがスキーマ（1人のユーザーが持つ表やシーケンスなどをまとめた「持ち物一覧」のこと）です。Oracle には「ユーザー名＝スキーマ名」という特徴があり、第3章で作った hr ユーザーで表を作ると、それは自動的に「hr スキーマの表」になります。他人のスキーマの表を見るときは hr.employees のようにスキーマ名で修飾しますが、自分自身のスキーマの表であれば employees だけで参照できます。

用語メモ: 「オブジェクト」とは

Oracle では、表・シーケンス（5.6で学ぶ連番発行の仕組み）・ビュー・索引など、ユーザーが作って管理する部品をまとめてオブジェクトと呼びます。「表はオブジェクトの1種類」と覚えておくと、この先の章で新しい部品が出てきても迷いにくくなります。

5.2 Oracleの主なデータ型

表の列を作るときは、「そこに何を入れるか」を1つずつ決める必要があります。この決まりごとをデータ型と呼びます。紙の申込用紙に「電話番号欄」「金額欄」「日付欄」といった記入欄の種類があるのと同じで、列ごとに入れてよいデータの種類とサイズをあらかじめ決めておくイメージです。

Oracle には多くのデータ型がありますが、初心者がまず覚えるべきものは次の7つです。

データ型 格納するもの 記入例 備考
VARCHAR2(n) 長さが変わる文字列 VARCHAR2(50 CHAR) Oracleの文字列はこれが基本。5.3で詳しく扱う
CHAR(n) 長さが固定の文字列 CHAR(2) 桁数が完全に決まっている場合のみ。基本はVARCHAR2でよい
NUMBER(p, s) 整数・小数を含む数値 NUMBER(2,2) pは全体の桁数、sは小数点以下の桁数
DATE 年月日＋時分秒 DATE '2015-04-01' Oracle特有: 見た目は日付でも時刻まで持つ
TIMESTAMP 年月日＋時分秒＋小数秒 TIMESTAMP(6) DATEよりさらに細かい精度が必要なときに使う
CLOB 長い文章 memo CLOB 商品説明やブログ本文など大容量のテキスト
BLOB 画像・PDFなどのバイナリ photo BLOB ファイルの中身をそのまま格納する

なぜ VARCHAR ではなく VARCHAR2 を使うのか

Oracle には VARCHAR という型名も存在しますが、実際のコードでは必ず VARCHAR2 を使ってください。 Oracle 社自身が「将来のバージョンで VARCHAR の意味を変更する可能性がある」と予告しているためです。本ガイドのサンプルスキーマも、文字列の列はすべて VARCHAR2 で統一します。

DATE は「時刻」まで持っている

他のソフトの「日付」のイメージだと見落としがちですが、Oracle の DATE 型は年月日だけでなく時分秒までを常にセットで持っています。画面の表示形式が年月日だけになっているために気づきにくいだけです。この性質は第8章の日付検索で重要になるので、「DATEには時刻も入っている」とだけ、ここで覚えておいてください。

どの型を選べばよいか迷ったときは、次の流れで考えるとほとんどのケースをカバーできます。

flowchart TD A["入れたいデータは？"] --> B{"文字列？"} B -->|はい・長さが変わる| C["VARCHAR2(n CHAR)"] B -->|はい・長い文章| D["CLOB"] A --> E{"数値？"} E -->|小数がある| F["NUMBER(p,s)"] E -->|整数のみ| G["NUMBER(p)"] A --> H{"日時？"} H -->|秒までで十分| I["DATE"] H -->|もっと細かく| J["TIMESTAMP"]

5.3 文字数か、バイト数か（日本語の落とし穴）

VARCHAR2(10) のように単位を書かずに桁数だけ指定すると、Oracle はこれを「10バイト」という意味で解釈します。本ガイドが前提とする文字コードAL32UTF8（Oracle Database Free の既定の文字コード）では、日本語の1文字がおよそ3バイトを消費します。つまり VARCHAR2(10) には、日本語がたった3文字ほどしか入りません。

これを避けるには、桁数のあとに CHAR を付けてVARCHAR2(10 CHAR) と書きます。こう書けば「10文字」の意味になり、日本語でも英数字でも10文字まで入るようになります。本ガイドのサンプルスキーマの文字列列がすべて CHAR 指定になっているのは、この落とし穴を避けるためです。

実際に、バイト指定の列と文字指定の列を作って違いを確認してみましょう。

moji_test.sql 
-- 3バイト分しか入らない列と、3文字入る列を作って比べる
CREATE TABLE moji_test (
  byte_col VARCHAR2(3),        -- 3バイト分（日本語は1文字しか入らない）
  char_col VARCHAR2(3 CHAR)    -- 3文字（日本語も3文字入る）
);

-- こちらは成功する（3文字なのでchar_colに収まる）
INSERT INTO moji_test (char_col) VALUES ('あいう');

-- こちらはORA-12899（値が大きすぎます）になる
INSERT INTO moji_test (byte_col) VALUES ('あいう');

ORA-12899: 値が大きすぎます

「文字数は制限内のはずなのに、なぜかエラーになる」というときは、まずこのバイト数／文字数の指定漏れを疑ってください。日本語を扱う列には必ず CHAR を付けるクセをつけておくと、日本の現場で最も頻出するこの落とし穴を避けられます。この moji_test 表は5.7で表の変更・削除の練習に再利用するので、このまま残しておきましょう。

5.4 制約 ― データを見張る6つのルール

制約（列や表に設定する「入力ルール」のこと）は、おかしなデータが表に入るのをデータベース自身に見張らせる仕組みです。「入力ミスがないかをアプリ側のプログラムだけでチェックする」よりも、表そのものにルールを埋め込んでおくほうが確実です。アプリにバグがあっても、制約が最後の砦としてデータを守ってくれます。

Oracle でよく使う制約は次の6種類です。

制約 意味 書き方の例 本ガイドでの使用箇所
NOT NULL その列を空欄にできない last_name ... NOT NULL employees.last_name / hire_date
PRIMARY KEY 1行を特定する背番号。重複と空欄を禁止 PRIMARY KEY (employee_id) employees.employee_id / departments.department_id
UNIQUE 値の重複を禁止する（NULLは複数あってもよい） UNIQUE (email) 今回は未使用（重複させたくない列に使う）
FOREIGN KEY 他の表に存在する値しか入れられない FOREIGN KEY (department_id) REFERENCES departments(department_id) employees.department_id → departments.department_id
CHECK 指定した条件を満たす値だけ許す CHECK (salary >= 0) employees.salary
DEFAULT 値を省略したときの初期値 salary NUMBER(8) DEFAULT 0 employees.salary

重要ポイント

たとえば FOREIGN KEY 制約があるおかげで、存在しない部署番号（たとえば99番）を社員データにうっかり入力しても、Oracle が自動的に登録を拒否してくれます。この安心感が、制約を付ける最大のメリットです。

5.5 表を作る: 共通サンプルスキーマを作成する

ここからはハンズオンです。第3章で作った hr ユーザーで FREEPDB1 に接続した状態で、実際に departments 表と employees 表を作っていきましょう。CREATE TABLE の基本形は次のとおりです。

構文（イメージ） 
-- CREATE TABLEの基本形（このまま実行はしない）
CREATE TABLE 表名 (
  列名1  データ型  [制約],
  列名2  データ型  [制約],
  ...
);

まずは部署表 departments です。部署番号を主キーにして、部署名は必須、所在地は未定でもよいので省略可能にします。

departments.sql 
-- 部署表: 会社の部署一覧（表計算ソフトの1枚のシートに相当）
CREATE TABLE departments (
  department_id   NUMBER(4)          NOT NULL,  -- 部署番号
  department_name VARCHAR2(50 CHAR)  NOT NULL,  -- 部署名
  location        VARCHAR2(50 CHAR),            -- 所在地（未定ならNULL）
  CONSTRAINT pk_departments PRIMARY KEY (department_id)
);

続いて社員表 employees です。列が多いので、まずは列と基本的な制約を定義します。主キーや外部キーなど表をまたぐ制約は、あとから ALTER TABLE で追加します。employee_id には5.6で扱うIDENTITY列（自動採番の仕組み）をあらかじめ仕込んでおきます。

employees.sql 
-- 社員表: 会社の社員名簿（まずは列と基本的な制約を定義する）
CREATE TABLE employees (
  employee_id    NUMBER(6) GENERATED BY DEFAULT AS IDENTITY START WITH 111,
  last_name      VARCHAR2(30 CHAR) NOT NULL,   -- 姓
  first_name     VARCHAR2(30 CHAR),            -- 名
  email          VARCHAR2(60 CHAR),            -- メールアドレス
  hire_date      DATE              NOT NULL,   -- 入社日（時刻も持つ）
  job_title      VARCHAR2(40 CHAR),            -- 役職
  salary         NUMBER(8)         DEFAULT 0,  -- 月給（円）
  commission_pct NUMBER(2,2),                  -- 歩合率（0.00〜0.99）
  department_id  NUMBER(4),                    -- 所属部署番号
  manager_id     NUMBER(6)                     -- 上司の社員番号
);

次に ALTER TABLE（表の設計をあとから変更する命令）を使って、主キー・外部キー・チェック制約の3つを追加します。「あとから制約だけを付け足せる」ことも覚えておきましょう。

add_constraints.sql 
-- 主キー制約を追加する（1行を特定する背番号にする）
ALTER TABLE employees ADD CONSTRAINT pk_employees PRIMARY KEY (employee_id);

-- 外部キー制約を追加する（存在しない部署番号を入れられなくする）
ALTER TABLE employees ADD CONSTRAINT fk_emp_dept
  FOREIGN KEY (department_id) REFERENCES departments(department_id);

-- 給与がマイナスにならないようにチェック制約を追加する
ALTER TABLE employees ADD CONSTRAINT ck_emp_salary CHECK (salary >= 0);

表ができたら、DESC（DESCRIBE の略記。第4章で紹介済み）で列構成を確認しておきましょう。

desc_tables.sql 
-- 部署表の構造を確認する（列名・データ型・NULL可否）
DESC departments

-- 社員表の構造を確認する
DESC employees

表の入れ物ができたので、サンプルデータを投入します。まずは部署データ（4件）です。人事部はまだ所在地が決まっていないので NULL（未入力を表す特別な値）にしています。

insert_departments.sql 
-- 部署データ（4件）。人事部はまだ所在地が決まっていないのでNULL
INSERT INTO departments VALUES (10, '営業部', '東京');
INSERT INTO departments VALUES (20, '開発部', '大阪');
INSERT INTO departments VALUES (30, '総務部', '東京');
INSERT INTO departments VALUES (40, '人事部', NULL);
COMMIT;  -- Oracleは自動コミットされないので、これを忘れると保存されない

SELECT column_name, data_type, data_length, nullable
  FROM user_tab_columns
 WHERE table_name = 'EMPLOYEES'
 ORDER BY column_id;

5.6 主キーの自動採番: シーケンスとIDENTITY列

主キーの値を1件ずつ手で数えて入力するのは大変ですし、番号の重複ミスも起きやすくなります。Oracle には主キーを自動的に採番する方法が2つあります。

1つ目はシーケンス（次の番号を発行してくれる「番号札の発券機」のようなオブジェクト）です。CREATE SEQUENCE で独立した部品として作り、シーケンス名.NEXTVAL と書くたびに次の番号が払い出されます。表そのものとは別のオブジェクトなので、複数の表で1つのシーケンスを使い回すこともできます。

2つ目はIDENTITY列（Oracle Database 12c以降で使える、列そのものに採番機能を埋め込む書き方）です。5.5で作った employees.employee_id がこれにあたります。GENERATED ALWAYS AS IDENTITY（常に自動採番。値を指定するとエラーになる）とGENERATED BY DEFAULT AS IDENTITY（値を指定すればそれを使い、省略すれば自動採番する）の2種類があり、本ガイドでは決まった番号のサンプルデータを投入できるように、後者を採用しています。

観点 シーケンス IDENTITY列
定義する場所 独立したオブジェクト（CREATE SEQUENCE） 表の列定義の中（CREATE TABLEの中）
使うときの書き方 明示的に シーケンス名.NEXTVAL と書く INSERTでその列を省略するだけ
複数の表での共有 できる（1つを複数表で使い回せる） できない（その表専用）
本ガイドでの採用 dept_seq（本節で体験用に作成） employees.employee_id

まずはシーケンスを作って動きを確認してみましょう。追加した部署はあとで取り消すので、サンプルデータの4件は変わりません。

dept_seq.sql 
-- 50から始まり10ずつ増える番号札の発券機を作る
CREATE SEQUENCE dept_seq START WITH 50 INCREMENT BY 10;

-- 次の番号を取り出して部署を1件追加してみる
INSERT INTO departments (department_id, department_name, location)
VALUES (dept_seq.NEXTVAL, '広報部', '東京');

-- 動きを確認できたので取り消す（サンプルデータは4件のままにしておく）
ROLLBACK;
-- 注意: ROLLBACKしてもシーケンスの番号は戻らない（50は欠番になり、次のNEXTVALは60になる）

次に、employees のIDENTITY列の動きを確認します。employee_id を指定せずに INSERT すると、自動で番号が割り当てられます。

identity_demo.sql 
-- employee_idを指定せずに追加すると、自動で番号が割り当てられる
INSERT INTO employees (last_name, first_name, hire_date, salary, department_id)
VALUES ('斎藤', '涼', DATE '2025-04-01', 320000, 20);

-- 自動採番された番号を確認する（111が割り当てられる）
SELECT employee_id, last_name FROM employees WHERE last_name = '斎藤';

-- 動きを確認できたので取り消す（サンプルデータは10件のままにしておく）
ROLLBACK;

ROLLBACKしても番号は戻らない

シーケンスもIDENTITY列も、一度払い出した番号をROLLBACKでは戻しません。番号を消費しただけで登録自体を取り消した場合、その番号は二度と使われずに欠番になります。上の例では50が欠番になったため、次に dept_seq.NEXTVAL を呼び出すと60が払い出されます。運用上は問題ありませんが、「なぜ番号が飛んでいるのか」で慌てないよう、この性質を覚えておいてください。シーケンスが払い出す具体的な数字を当てにせず、そのつど NEXTVAL が返す値を使うという考え方が大切です。この dept_seq は第7章でも再び使います。COMMIT と ROLLBACK そのものは第7章で詳しく学びます。

5.7 表を変更・削除する: ALTER TABLEとDROP TABLE

作った表はあとから変更・削除できます。5.3で作った練習用の moji_test 表を使って、ALTER TABLE と DROP TABLE の使い方を練習しましょう（departments と employees はこのあとの章でずっと使うため、練習には使いません）。

ALTER TABLE でできる代表的な変更は次の4つです。

やりたいこと 書き方
列を追加する ALTER TABLE 表名 ADD 列名 データ型
列の定義を変える ALTER TABLE 表名 MODIFY 列名 データ型
列の名前を変える ALTER TABLE 表名 RENAME COLUMN 旧名 TO 新名
列を削除する ALTER TABLE 表名 DROP COLUMN 列名
alter_moji_test.sql 
-- moji_testに列を1つ追加する
ALTER TABLE moji_test ADD memo VARCHAR2(100 CHAR);

-- 列の名前を変更する
ALTER TABLE moji_test RENAME COLUMN memo TO note;

-- 列を削除する
ALTER TABLE moji_test DROP COLUMN note;

表そのものを削除するのが DROP TABLE です。Oracle では削除した表がすぐには消えず、リサイクルビン（削除した表を一時的に保管しておくOracleの「ごみ箱」機能）に入ります。FLASHBACK TABLE ... TO BEFORE DROP で元に戻せますが、完全に消したいときは PURGE を付けます。

drop_flashback.sql 
-- 表を削除する（ごみ箱に入るだけで、まだ完全には消えない）
DROP TABLE moji_test;

-- ごみ箱の中身を確認する
SELECT object_name, original_name FROM user_recyclebin;

-- 削除を取り消して元に戻す
FLASHBACK TABLE moji_test TO BEFORE DROP;

-- 練習が終わったので、今度は完全に削除する（ごみ箱に残さない）
DROP TABLE moji_test PURGE;

ORA-02449: 参照されている表は削除できない

もし DROP TABLE departments; のように、外部キーで参照されている表を削除しようとするとORA-02449になります。どうしても消す必要がある場合は DROP TABLE departments CASCADE CONSTRAINTS; のように CASCADE CONSTRAINTS を付けますが、本ガイドの共通サンプルスキーマでは絶対に実行しないでください。第6章以降の教材データが失われてしまいます。

次の第6章では、この章で作った departments と employees から、いよいよ SELECT 文を使ってデータを取り出していきます。表という「入れ物」ができた今、次はその中身を自由に読み出す番です。

やってみよう 5-1: 部署を仮に追加して制約とROLLBACKを体験する

5.6で体験したROLLBACKの動きを、シーケンスを使わずに自分の手でも確認してみましょう。

  1. 好きな部署名を考え、INSERT INTO departments (department_id, department_name, location) VALUES (99, '好きな部署名', '好きな都市'); を実行する。
  2. SELECT * FROM departments; を実行し、5件になっていることを確認する。
  3. 同じ department_id の99番でもう一度同じ文を実行し、何が起きるかを確認する。
  4. 最後に ROLLBACK; を実行し、部署が4件に戻ることを確認する。

ヒント: 手順3では pk_departments（主キー制約）が重複を検知し、ORA-00001（一意制約違反）で登録を拒否します。COMMITしていない変更はROLLBACKでいつでも取り消せる、という第7章の内容を先取りした安心材料でもあります。

理解度確認クイズ

  1. Q1. 日本語の氏名（最大20文字）を格納する列をOracleで定義するとき、最も適切なのはどれですか。 (a) VARCHAR(20) (b) VARCHAR2(20) (c) VARCHAR2(20 CHAR) (d) CHAR(20)

    回答を表示

    (c)。Oracleでは文字列に VARCHAR2 を使い、日本語を文字数で数えたいので CHAR 指定を付けます。(b) は20バイト＝日本語で約6文字しか入らず、(a) は将来のバージョンで意味が変わる可能性がある型なので使いません。

  2. Q2. DROP TABLE moji_test; を実行した直後に「間違えた」と気づきました。どうすれば元に戻せますか。

    回答を表示

    FLASHBACK TABLE moji_test TO BEFORE DROP; を実行します。削除された表はリサイクルビン（ごみ箱）に入っているため復元できます。ただし DROP TABLE ... PURGE で削除した場合はごみ箱を経由しないため復元できません。

  3. Q3. シーケンスとIDENTITY列の使い分けとして正しい説明はどれですか。

    回答を表示

    シーケンスは表とは独立したオブジェクトで、NEXTVAL を明示的に書いて番号を取り出します。複数の表で使い回すことも可能です。IDENTITY列は特定の表の特定の列に組み込む機能で、INSERT時にその列を省略するだけで自動採番されます。1つの表専用の主キーを自動採番したいだけなら、書き方がシンプルなIDENTITY列が向いています。
