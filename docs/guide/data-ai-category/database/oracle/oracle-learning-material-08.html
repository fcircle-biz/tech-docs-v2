ホーム Oracle 第8章
第8章 所要時間: 約1.5時間

関数とNULL・日付の扱い

第6章で SELECT によるデータの取り出し方を、第7章で INSERT・UPDATE・DELETE による書き換え方を学びました。本章では、取り出した値を「加工する」ための道具である関数を学びます。文字列を整え、数値を丸め、日付を計算する関数を押さえたうえで、本章最大のテーマであるNULL（値が不明という状態）との正しい付き合い方を身につけます。ここで学ぶ NVL や日付関数は、第9章の集計処理で欠かせない道具になります。

この章で学ぶこと

  • 文字列・数値・日付の代表的な関数を使い分けられる
  • NULLの性質（計算に混ぜると結果がNULLになること、Oracleでは空文字列もNULLとして扱われること）を説明し、NVLやCOALESCEで対処できる
  • DATE型が時刻を持つことを踏まえ、TO_CHAR・TO_DATE・TRUNCで正しく日付を扱える
  • CASE式を使って、値を条件によって置き換えられる

本章で登場する主要関数の重要度一覧

本章では多くの関数が登場するため、先に「どれを優先して覚えるべきか」を一覧で示します。各関数は本文中の見出しや表でも同じバッジで示しますので、迷ったらここに戻ってきてください。

関数 用途 重要度 Oracle固有／標準SQL
TO_CHAR 日付・数値を表示用の文字列に変換する 必須 Oracle固有
TO_DATE 文字列をDATE型に変換する 必須 Oracle固有
NVL 値がNULLなら代替値に置き換える 必須 Oracle固有
COALESCE 最初のNULLでない値を返す（3値以上も可） 必須 一般的なSQL/RDBMS
TRUNC 数値を切り捨てる／日付の時刻を切り捨てる 参考 Oracle固有
NULLIF 2つの値が等しければNULLを返す 参考 一般的なSQL/RDBMS
NVL2 NULLかどうかで返す式を丸ごと切り替える 発展 Oracle固有
DECODE 値を検索リストと比較し一致した結果を返す 発展 Oracle固有

「必須」は業務でよく使うので確実に書けるようにしたい関数、「参考」は知っておくと便利な関数、「発展」は今すぐ書けなくても、既存システムのコードを読むときに出会う可能性がある関数です。DECODE は特に、新しく書くコードでは8.7節で学ぶ CASE 式のほうが読みやすいため、まずは「読めれば十分」という位置づけで構いません。

8.1 関数とは何か（自動販売機の比喩）

これまでの章では、表に入っている値をそのまま SELECT で取り出してきました。本章からは、その値を「加工」してから取り出す方法を学びます。この加工をしてくれる部品のことを関数（かんすう）と呼びます。

関数は「自動販売機」に似ています。お金を入れてボタンを押す（＝引数（ひきすう）を渡す）と、対応する商品が出てくる（＝戻り値が返る）。たとえば UPPER という関数に 'oracle' という文字列を渡すと、大文字にした 'ORACLE' という戻り値が返ってきます。中身の仕組みを知らなくても、「何を入れると何が出るか」さえ覚えれば使えるのがポイントです。本章で学ぶのは1行ごとに値を計算する単一行関数で、複数行をまとめて1つの値にする集計関数（COUNT・SUM など）は第9章で学びます。

第6章で紹介した DUAL 表（1行1列だけのダミー表）を思い出しましょう。関数の動きだけを確かめたいときは、わざわざ employees 表を使わなくても DUAL で十分です。本章では「まず DUAL で動きを確認 → 次に employees 表の実データに適用」という流れで進めます。

dual-and-employees.sql 
-- DUAL表を使うと、実際の表が無くても関数の動きだけを試せる
SELECT UPPER('oracle database') AS "大文字変換" FROM dual;

-- 同じ関数を実際の列（employeesのemail）に適用する
SELECT last_name, UPPER(email) AS "メール大文字"
  FROM employees
 ORDER BY employee_id
 FETCH FIRST 3 ROWS ONLY;

8.2 文字列を加工する関数

文字列（VARCHAR2 型の値）を加工する関数はたくさんありますが、まずはよく使う9個を一覧表で押さえましょう。UPPER・LOWER・LENGTH のような関数は他のデータベース製品（PostgreSQLやMySQLなど）でも同じ名前で使えることが多い一般的なSQL/RDBMSの知識です。一方 SUBSTR は製品によって引数の仕様が微妙に異なるOracle固有の書き方なので、他のDBへ移植するときは注意しましょう。

関数 動作 例と結果
UPPER(文字列) すべて大文字に変換する UPPER('sato') → 'SATO'
LOWER(文字列) すべて小文字に変換する LOWER('SATO') → 'sato'
INITCAP(文字列) 単語の先頭だけ大文字にする INITCAP('SATO ICHIRO') → 'Sato Ichiro'
LENGTH(文字列) 文字数を返す LENGTH('佐藤') → 2
SUBSTR(文字列,開始,長さ) Oracle固有 指定位置から指定文字数を切り出す（開始位置は1から） SUBSTR('ORACLE',1,3) → 'ORA'
INSTR(文字列,探す文字) 探す文字列が最初に現れる位置を返す（無ければ0） INSTR('a@b.com','@') → 2
REPLACE(文字列,検索,置換) 一致した部分をすべて置き換える REPLACE('24/04/01','/','-') → '24-04-01'
TRIM(文字列) 前後の空白を取り除く TRIM(' 佐藤 ') → '佐藤'
LPAD / RPAD 指定した長さになるまで左（右）を埋める LPAD('7',3,'0') → '007'

つまずきやすいポイント: 開始位置は1から数える

プログラミング言語によっては先頭を0番目として数えるものがありますが、Oracle の SUBSTR や INSTR は先頭を1番目として数えます。SUBSTR('ORACLE', 1, 3) は「1文字目から3文字」で 'ORA' です。

実データにも適用してみましょう。メールアドレスから @ より後ろ（ドメイン部分）を切り出す例と、社員番号を帳票向けに0埋めする例です。

string-functions-demo.sql 
-- メールアドレスの＠より後ろ（ドメイン部分）を取り出す
SELECT email, SUBSTR(email, INSTR(email, '@') + 1) AS "ドメイン"
  FROM employees
 WHERE email IS NOT NULL
 ORDER BY employee_id;

-- 社員番号を0埋めで6桁の文字列にする（帳票などで桁を揃えたい場合）
SELECT employee_id, LPAD(employee_id, 6, '0') AS "社員番号6桁"
  FROM employees
 ORDER BY employee_id
 FETCH FIRST 3 ROWS ONLY;

8.3 数値を加工する関数

数値（NUMBER 型の値）を加工する関数です。特に ROUND（四捨五入）と TRUNC（切り捨て）は名前が似ていて混同しやすいので、同じ値で比べて違いを確認します。

関数 動作 例と結果
ROUND(数値,桁数) 四捨五入する。桁数省略で整数に。負の桁数なら整数側（十の位など）を丸める ROUND(1234.567,1) → 1234.6
TRUNC(数値,桁数) 参考 Oracle固有 四捨五入せずに指定桁数で切り捨てる TRUNC(1234.567,1) → 1234.5
MOD(m,n) mをnで割った余りを返す MOD(10,3) → 1
ABS(数値) 絶対値（符号を取り除いた値）を返す ABS(-500) → 500
CEIL / FLOOR その値以上（以下）で最も近い整数にする CEIL(1234.1) → 1235

同じ値で比較したあと、歩合が設定されている社員だけを対象に歩合給を四捨五入してみます。歩合率（commission_pct）がNULLの社員をどう扱うかは、8.6節で詳しく取り上げます。

round-trunc-compare.sql 
-- ROUNDとTRUNCの違いを同じ値で比べる（四捨五入か、切り捨てか）
SELECT 1234.567 AS "元の値", ROUND(1234.567,1) AS "四捨五入", TRUNC(1234.567,1) AS "切り捨て",
       CEIL(1234.567) AS "切り上げ整数", MOD(1234,100) AS "割った余り"
  FROM dual;

-- 歩合が設定されている社員だけ、歩合給を1円未満で四捨五入する
SELECT last_name, ROUND(salary * commission_pct) AS "歩合給"
  FROM employees
 WHERE commission_pct IS NOT NULL
 ORDER BY employee_id;

8.4 日付の扱いとDATE型の注意点

Oracle の DATE 型には、他の多くのデータベース製品と違う重要な特徴があります。それは年月日だけでなく時刻（時・分・秒）まで一緒に保存しているという点です。第5章で少し触れたこの事実を、本節でしっかり体験しましょう。

現在日時と日付の加減算 Oracle固有

現在の日時は SYSDATE（DATE 型、秒単位まで）で取得します。関数名は製品ごとに異なり（例: SQL Serverの GETDATE()）、これもOracle固有の名前です。さらに細かい精度やタイムゾーンが必要なら SYSTIMESTAMP を使います。また、DATE 型に数値を足し引きすると「日数」として扱われ、SYSDATE + 1 は24時間後です。

SYSDATE を TO_CHAR なしでそのまま SELECT すると、表示される形式はセッションの NLS_DATE_FORMAT（日付の表示形式を決める設定値）に従うため、実行環境によって見た目の桁や区切り文字が変わる場合があります。そのため、日時を表示するときは TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS') のように書式を明示するのがおすすめです（書式の詳細は8.5節）。

sysdate-and-arithmetic.sql 
-- SYSDATEには時刻も含まれる。+1は「日数」単位で24時間後を意味する
SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD HH24:MI:SS')          AS "現在日時",
       TO_CHAR(SYSDATE + 1, 'YYYY-MM-DD HH24:MI:SS')      AS "24時間後",
       TO_CHAR(SYSTIMESTAMP, 'YYYY-MM-DD HH24:MI:SS.FF')  AS "より精密な時刻"
  FROM dual;

便利な日付関数: MONTHS_BETWEEN・ADD_MONTHS・LAST_DAY Oracle固有

MONTHS_BETWEEN(日付1,日付2) は2つの日付の間の月数、ADD_MONTHS(日付,n) は日付にnか月を加えた日付、LAST_DAY(日付) はその月の最終日を返します。入社日（hire_date）で試してみましょう。

date-functions.sql 
-- 入社日から今日までの勤続月数・勤続年数、1年後の日付、入社月の末日
SELECT last_name,
       TO_CHAR(hire_date, 'YYYY-MM-DD')                 AS "入社日",
       ROUND(MONTHS_BETWEEN(SYSDATE, hire_date))        AS "勤続月数",
       TRUNC(MONTHS_BETWEEN(SYSDATE, hire_date) / 12)   AS "勤続年数",
       TO_CHAR(ADD_MONTHS(hire_date, 12), 'YYYY-MM-DD') AS "入社1年後",
       TO_CHAR(LAST_DAY(hire_date), 'YYYY-MM-DD')       AS "入社月の末日"
  FROM employees
 ORDER BY hire_date
 FETCH FIRST 5 ROWS ONLY;

TRUNCで時刻を切り捨てる: 日付比較の落とし穴 参考 Oracle固有

8.3節では数値を切り捨てる TRUNC を紹介しましたが、TRUNC(日付) のように引数がDATE型のときは、時刻部分を切り捨てて00:00:00にします。このサンプルデータは全員0時0分0秒で登録されているため「＝」でも一致しますが、それはたまたまです。入社時刻まで記録する運用に変われば同じSQLは1件もヒットしなくなるため、時刻を持つかもしれない DATE 列は常に TRUNC か範囲指定で比較するのが安全です。

trunc-and-comparison.sql 
-- このデータは全員0時0分0秒で登録されているため、今は「＝」でも一致する
SELECT COUNT(*) FROM employees WHERE hire_date = DATE '2015-04-01';

-- 安全策1: TRUNCで時刻を切り捨ててから比較する
SELECT COUNT(*) FROM employees WHERE TRUNC(hire_date) = DATE '2015-04-01';

-- 安全策2: 範囲（当日0時から翌日0時未満）で比較する
SELECT COUNT(*) FROM employees
 WHERE hire_date >= DATE '2015-04-01' AND hire_date < DATE '2015-04-02';

注意: DATE列の「＝」比較は時刻に注意

「＝」で日付だけを一致させたいときは、TRUNC か範囲指定を使いましょう。ただし列に関数をかけると索引（インデックス）が効きにくくなる場合があることを、第13章で扱います。

8.5 文字列・数値・日付を変換する関数

ここまで何度も登場した TO_CHAR必須Oracle固有 のように、Oracle には型を変換する3つの代表的な関数があります。「文字列にする」「日付にする」「数値にする」という向きを図で確認しましょう。

flowchart LR A["文字列 '2024-04-01'"] -->|TO_DATE| B["DATE型（時刻を含む）"] B -->|TO_CHAR| C["表示用の文字列"] B -->|TRUNC| D["時刻00:00:00のDATE"] E["文字列 '12345'"] -->|TO_NUMBER| F["NUMBER型"] F -->|TO_CHAR| G["表示用の文字列"]

TO_CHAR や TO_DATE に渡す第2引数は書式モデル（フォーマットモデルとも呼ばれる。日付や数値をどんな形の文字列に変換する／解釈するかを指定する記号の組み合わせ）と呼びます。書式モデルでよく使う記号は YYYY（4桁の西暦）・MM（月01〜12）・DD（日01〜31）・HH24（時00〜23の24時間制）・MI（分00〜59）・SS（秒00〜59）・DAY（曜日のフルスペル）です。数値の書式では、桁区切りの FM999,999,999 のように使います。

to_char-format.sql 
-- 日付と数値を、それぞれ書式を指定して見やすく変換する
SELECT last_name,
       TO_CHAR(hire_date, 'YYYY年MM月DD日') AS "入社日",
       TO_CHAR(hire_date, 'DAY')             AS "曜日",
       TO_CHAR(salary, 'FM999,999,999')      AS "月給"
  FROM employees
 ORDER BY employee_id
 FETCH FIRST 3 ROWS ONLY;

FM（Fill Mode／余白埋め込み抑制の意味）を先頭に付けると、桁数に満たない場合の余分な空白を詰めて表示します。逆に文字列から型を作るには TO_DATE(文字列,書式)必須Oracle固有 や TO_NUMBER(文字列,書式) を使います。

to_date-to_number.sql 
-- TO_DATEで文字列からDATE型を作る（書式を明示する）
SELECT TO_DATE('2024/04/01', 'YYYY/MM/DD') AS "日付変換" FROM dual;

-- TO_NUMBERでカンマ入りの文字列を数値に変換する（書式FMを指定）
SELECT TO_NUMBER('1,234', 'FM9,999') AS "数値変換" FROM dual;

初心者が陥りやすいのが、TO_DATE などを省略して Oracle に「なんとなく」変換させる暗黙変換です。WHERE hire_date = '2015-04-01' のように文字列と直接比較すると、Oracle はセッションの NLS_DATE_FORMAT（NLSはNational Language Support／各国語対応の意味。日付表示形式を決める設定値）に従って自動変換します。この設定は環境によって異なるため、手元では動いても別の環境で失敗する事故につながります。

鉄則: 型変換は省略せず明示する

日付は TO_DATE / TO_CHAR、数値は TO_NUMBER / TO_CHAR で常に明示的に変換しましょう。書式が想定と違うと ORA-01858（数値を期待した箇所に非数値文字があった）や ORA-01861（リテラルが書式文字列と一致しない）になり、数値変換でも変換できない文字列を渡すと ORA-01722（数値が無効です）になります。

8.6 NULLの正体と付き合い方（本章最大の山場）

NULLは「値が無い」ことを表す特別な印です。ここで最初に断言しておきます。NULLは0でも空文字列でもありません。たとえるなら、アンケート用紙の未回答欄です。0点と書いたわけでも「回答なし」という文字を書き込んだわけでもなく、単に何も書かれていない状態。それがNULLです。

(a) NULLを含む計算はすべてNULLになる

歩合の無い社員は commission_pct がNULLです。これを計算に混ぜるとどうなるか見てみましょう。

null-in-calculation.sql 
-- 歩合率(commission_pct)がNULLの社員は、計算結果もNULLになる
SELECT last_name,
       salary,
       commission_pct,
       salary + salary * commission_pct AS "支給額（NULLになる）"
  FROM employees
 ORDER BY employee_id
 FETCH FIRST 5 ROWS ONLY;

歩合の無い佐藤さんの行は、支給額が空欄（NULL）になります。「NULLは0だから給与だけ表示されるはず」は誤りで、NULLが混ざった算術演算の結果は常にNULLになります。ところが第6章で学んだ連結演算子 || だけは例外です。

null-arithmetic-vs-concat.sql 
-- 通常の算術演算はNULLに汚染される
SELECT 100 + NULL AS "計算結果" FROM dual;                -- NULL

-- 連結||はNULLを無視して残りをつなぐ（Oracle独自の挙動）
SELECT 'ABC' || NULL || 'DEF' AS "連結結果" FROM dual;    -- ABCDEF
flowchart TD N["NULL（値が不明という状態）"] --> A["四則演算に混ぜる"] N --> B["文字列を連結する"] N --> C["＝ で比較する"] N --> D["IS NULL で判定する"] A --> A2["結果はNULLになる"] B --> B2["NULLは無視され残りがつながる"] C --> C2["判定できない（常に不明）"] D --> D2["正しく判定できる"] N --> E["NVLで代替値に置き換える"] E --> F["以後の計算にNULLを持ち越さない"]

(b) Oracle特有の挙動: 空文字列もNULLになる Oracle固有

Oracle には、他のデータベース（PostgreSQLやSQL Serverなど）を触った経験がある人ほど驚く挙動があります。空文字列 '' を挿入すると、OracleはそれをNULLとして保存するのです。job_titleに「事務」という値が入っている employee_id=109 を使って確かめてみましょう。

empty-string-is-null.sql 
-- 事前確認: employee_id=109のjob_titleは'事務'（NULLではない）
SELECT employee_id, job_title FROM employees WHERE employee_id = 109;

-- 空文字列 '' を入れてみる
UPDATE employees SET job_title = '' WHERE employee_id = 109;

-- (1)「IS NULL」でヒットする → ''がNULLとして格納された証拠
SELECT employee_id FROM employees WHERE employee_id = 109 AND job_title IS NULL;

-- (2)「= ''」では見つからない（NULLは=で比較できないため）
SELECT employee_id FROM employees WHERE job_title = '';

ROLLBACK;  -- 実験が終わったので基準状態（job_title='事務'）に戻す
実行結果（イメージ） 
SQL> SELECT employee_id FROM employees WHERE employee_id = 109 AND job_title IS NULL;

EMPLOYEE_ID
-----------
       109

SQL> SELECT employee_id FROM employees WHERE job_title = '';

no rows selected

Oracle特有の罠: WHERE 列 = '' は永遠にヒットしない

Oracleでは空文字列がNULLとして扱われるため、「＝ ''」では絶対に一致しません（NULLとの比較は常に「不明」でTRUEになりません）。「未入力かどうか」は必ずIS NULLで判定してください。

(c) NVL・NVL2・COALESCE・NULLIF・DECODEで対処する

NULLの性質が分かったところで、実務で「NULLを手なずける」関数を5つまとめて覚えましょう。すべて同じ重要度ではありません。NVL と COALESCE はよく使うので確実に書けるようにし、NULLIF は知っておくと便利な参考知識、NVL2 と DECODE は既存システムのコードを読むときに出会うことがある発展知識として、まずは「読んで意味が分かる」ことを目標にすれば十分です。

関数 書式 動作 使いどころの例
NVL
必須 Oracle固有 		NVL(値,代替値) 値がNULLなら代替値を返す 歩合率NULLを0として計算する
NVL2
発展 Oracle固有 		NVL2(値,非NULL時,NULL時) NULLかどうかで返す式を丸ごと切り替える 「歩合あり／固定給のみ」のラベル分け
COALESCE
必須 一般的なSQL/RDBMS 		COALESCE(値1,値2,…) 最初のNULLでない値を返す（3つ以上も可） 優先順位のある複数候補から選ぶ
NULLIF
参考 一般的なSQL/RDBMS 		NULLIF(a,b) aとbが等しければNULLを返す 特定の値をNULL扱いに変換したいとき
DECODE
発展 Oracle固有 		DECODE(値,検索1,結果1,…,既定値) 値を検索リストと比較し一致した結果を返す（Oracle独自の古い書き方） 既存システムのコードを読むときに出会うので意味を知っておく。新規はCASE式推奨（8.7節）
nvl-example.sql 
-- NVL: NULLを0に置き換えてから計算する（8.3節の続き）
SELECT last_name,
       NVL(commission_pct, 0)                   AS "歩合率補正",
       salary + salary * NVL(commission_pct, 0) AS "支給額"
  FROM employees
 ORDER BY employee_id
 FETCH FIRST 5 ROWS ONLY;
nvl2-and-nullif.sql 
-- NVL2: NULLかどうかで返す文言そのものを切り替える
SELECT last_name, NVL2(commission_pct, '歩合あり', '固定給のみ') AS "給与形態"
  FROM employees ORDER BY employee_id;

-- NULLIF: 2つの値が等しければNULLを返す（異なればそのまま1つ目を返す）
SELECT NULLIF(10, 10) AS "等しい場合", NULLIF(10, 5) AS "異なる場合" FROM dual;

-- COALESCE: 最初に見つかったNULLでない値を返す（引数は3つ以上も可、NVLとの違い）
SELECT department_name, COALESCE(location, '未定') AS "所在地" FROM departments;
decode-example.sql 
-- DECODE: 値を候補と順番に比較し、一致した結果を返す（Oracle独自の古い書き方）
SELECT last_name,
       DECODE(department_id, 10, '営業部',
                              20, '開発部',
                              30, '総務部',
                              'その他') AS "部署名相当"
  FROM employees
 ORDER BY employee_id
 FETCH FIRST 5 ROWS ONLY;

重要ポイント

NULLは0でも空文字列でもなく「値が不明」という状態です。Oracleでは空文字列もNULLとして格納されます。算術演算はNULLに汚染されますが連結演算子 || だけは無視します。置き換えにはNVL系を、判定には必ずIS NULLを使いましょう。なおDECODEだけはNULL同士を「等しい」とみなす特殊な挙動を持ちます（次節のCASEには無い）。

8.7 CASE式で値を条件分岐する 必須 一般的なSQL/RDBMS

最後に、第6章で学んだCASE式を、ここでは8.6で学んだ DECODE と比べながら整理します。DECODE はOracle独自の古い書き方である一方、CASE は標準SQLでも通用するため、新しく書くコードでは基本的に CASE を使うことをおすすめします。自分で新しくSQLを書くときは CASE だけ使えれば十分ですが、DECODE は長年使われてきた書き方なので、他の人が書いた既存システムのSQLを読むときに出会うことがあります。「書けなくてもよいが読めるようにしておく」というくらいの位置づけで覚えておきましょう。

case-example.sql 
-- 給与帯によって「上級・中堅・一般」のランクを付ける
SELECT last_name,
       TO_CHAR(salary, 'FM999,999') AS "月給",
       CASE
         WHEN salary >= 600000 THEN '上級'
         WHEN salary >= 400000 THEN '中堅'
         ELSE '一般'
       END AS "給与ランク"
  FROM employees
 ORDER BY salary DESC;

これは条件式を自由に書ける形（第6章で学んだ検索CASE式）です。8.6の DECODE の部署名の例のように「1つの値が何であるか」で振り分けるだけなら、第6章で学んだ単純CASE式でも書けます。等号以外の範囲比較（>= など）も書けるのが、DECODE に対する CASE の強みです。

case-vs-decode.sql 
-- 8.6のDECODE例と同じ結果を単純CASE式で書く
SELECT last_name,
       CASE department_id
         WHEN 10 THEN '営業部'
         WHEN 20 THEN '開発部'
         WHEN 30 THEN '総務部'
         ELSE 'その他'
       END AS "部署名相当"
  FROM employees
 ORDER BY employee_id
 FETCH FIRST 5 ROWS ONLY;

やってみよう 8-1: 社員名簿を「読みやすく」加工する

本章で学んだ関数を組み合わせて、NULLがそのまま空欄で残らない社員名簿を作ってみましょう。

  1. departments 表を、所在地（location）が未定の部署は「未定」と表示されるように NVL を使って一覧表示する。
  2. employees 表で、メールアドレスが未登録の社員は「メールなし」と表示し、歩合率がNULLの社員は0%として支給額（salary + salary * 歩合率）を計算する。
  3. MONTHS_BETWEEN で各社員の勤続年数を求め、CASE 式で「新人（3年未満）」「中堅（3年以上10年未満）」「ベテラン（10年以上）」に分類する。
  4. 実行結果を確認し、NULLがどこにも空欄のまま残っていないかをチェックする。

ヒント: 3番の勤続年数は TRUNC(MONTHS_BETWEEN(SYSDATE, hire_date) / 12) でおおよその年数を整数で求め、その値を CASE の条件に使うと書きやすくなります。

理解度確認クイズ

  1. Q1. SELECT 'A' || NULL || 'B' FROM dual; と SELECT 10 + NULL FROM dual; の結果はそれぞれどうなりますか。

    回答を表示

    前者は AB（連結演算子 || はNULLを無視して残りをつなぐため）。後者は NULL（算術演算はNULLに汚染されるため）。この非対称さがOracleのNULL理解でいちばんの勘所です。

  2. Q2. location が未入力の部署について、一覧では「未定」と表示したいとき、どう書けばよいですか。

    回答を表示

    SELECT department_name, NVL(location, '未定') AS "所在地" FROM departments;。NVL は第1引数がNULLのとき第2引数を返します。

  3. Q3. UPDATE employees SET job_title = '' WHERE employee_id = 109; の後、WHERE job_title = '' で検索したら0件でした。なぜでしょうか。またどう書けば見つかりますか。

    回答を表示

    Oracleでは空文字列 '' はNULLとして格納されるためです。NULLとの「＝」比較は常に不明（UNKNOWN）と判定され、TRUEになることはありません。見つけるには WHERE job_title IS NULL を使います。
