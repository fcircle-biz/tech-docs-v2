SELECT文でデータを取り出す

第5章で作成した departments（部署一覧、4件）と employees（社員名簿、10件）に、いよいよ SELECT文（データを"読む"ためのSQL命令）で問いかけてみましょう。本章で身につける書き方は、これ以降のすべての章で土台になります。まずは「必要な行・列だけを取り出す」という基本の型を、じっくり体に覚えさせていきましょう。

この章で学ぶこと

  • SELECT…FROM…WHERE…ORDER BY の4点セットでデータを取り出せる
  • 比較・範囲・部分一致・NULL判定の各条件を書き分けられる
  • 列に別名を付け、|| で文字列を連結して読みやすい結果を作れる
  • DUAL 表の意味を説明でき、取得件数を絞る書き方を使える

6.1 SELECT文の基本形と処理順序 一般的なSQL/RDBMS

SELECT文（データを検索して取り出すSQL命令）は、「住所録の束から条件に合う人だけを探し出し、見やすい順番に並べる」作業だとイメージしてください。基本の形はとてもシンプルです。

select_basic.sql 
-- 社員表の全ての列・全ての行を表示する
SELECT * FROM employees;

-- 必要な列だけを、指定した順番で取り出す
SELECT last_name, department_id, salary FROM employees;

-- 部署番号の重複を除いて一覧する
SELECT DISTINCT department_id FROM employees;

*（アスタリスク）は「全部の列」という意味です。列名を並べれば、その列だけを指定した順番で取り出せます。DISTINCT（重複した行をまとめて1行にする指定）を付けると、同じ値が何度出てきても一覧には1回だけ表示されます。このように必要な列だけを絞り込んで取り出す操作は、データベース理論（関係代数）の用語で射影（しゃえい。表から特定の列だけを取り出す操作）と呼ばれます。対して、必要な行だけを絞り込む操作は選択（せんたく。条件に合う行だけを取り出す操作）と呼ばれ、6.4節で学ぶWHERE句がこれにあたります。用語自体を覚える必要はありませんが、「列を絞る＝射影」「行を絞る＝選択」という区別を意識すると理解が整理しやすくなります。 

SQL> SELECT last_name, department_id, salary FROM employees;

LAST_NAME  DEPARTMENT_ID     SALARY
---------- ------------- ----------
佐藤                  10     650000
鈴木                  10     480000
高橋                  10     380000
田中                  20     620000
伊藤                  20     500000
渡辺                  20     400000
山本                  20     350000
中村                  30     560000
小林                  30     300000
加藤                              280000

10行が選択されました。

列名を指定しない限り、見出し（列名）は自動的に大文字で表示されるのもOracleの特徴です（別名の付け方は次の節で扱います）。社員110番（加藤さん）は未配属のため department_id の欄が空欄になっています。 

SQL> SELECT DISTINCT department_id FROM employees;

DEPARTMENT_ID
-------------

           30
              ← 未配属（NULL）も1つのグループとして数えられる

なお、ORDER BY を指定しないSELECTでは、Oracleが返す行の順序は保証されません。「いつもこの順で返ってくる」と思い込まないようにしましょう。順序を保証する方法は6.5節で学びます。

ここで1つ、初心者が見落としがちな重要な事実があります。SQL文は SELECT → FROM → WHERE → ORDER BY の順に書きますが、Oracleが実際に処理する順番はこれとは異なります。

つまずきポイント: SELECTで付けた別名はWHEREで使えない

WHERE は SELECT より先に評価されます。そのため SELECT salary * 12 AS "年収" … WHERE "年収" > 5000000 のように、まだ存在しない別名を WHERE で使おうとすると ORA-00904（識別子が無効です）というエラーになります。このエラーが出たら「別名をWHEREで使っていないか」を疑いましょう。なお ORDER BY はSELECTより後に評価されるため、別名を使えます。

6.2 列に別名を付ける・計算する・連結する

列名や計算結果には 別名（エイリアス）（結果の見出しに付ける仮の名前）を付けられます。書き方は列の後ろに AS 別名 を続けるだけです。AS は省略もできますが、本ガイドでは分かりやすさのため常に書きます。日本語や空白を含む別名はダブルクォートで囲みます。

用語メモ: ダブルクォートは大文字・小文字をそのまま守る

Oracleは通常、クォートなしで書いた識別子（表名・列名・別名）を自動的にすべて大文字に変換して覚えます。別名をダブルクォートなしで英字で付けた場合（例: AS nenshu）、見出しは自動的に大文字（NENSHU）に変換されます。"氏名" のようにダブルクォートで囲むと、書いたとおりの文字がそのまま見出しになります。日本語や空白を含む別名は、ダブルクォートで囲むのが安全です。囲まなくても動く場合がありますが、数字で始まる別名（例: 24時間後）は囲まないとエラーになるなど例外が多いため、本ガイドでは日本語の別名は必ずダブルクォートで囲みます。

列どうしの四則演算もその場で書けます。たとえば月給の列に12を掛ければ、その場で「年収」を計算できます。文字列をつなげたいときは、Oracleでは ||（縦棒2本。パイプ演算子とも呼びます）を使います。

concat_alias.sql 
-- 姓と名を連結して氏名を作り、月給から年収を計算する
-- Oracleの文字列連結は || （縦棒2本）
SELECT last_name || ' ' || first_name AS "氏名",
       salary                          AS "月給",
       salary * 12                     AS "年収"
  FROM employees
 ORDER BY salary DESC;
氏名           月給       年収
---------- ---------- ----------
佐藤 一郎      650000    7800000
田中 美咲      620000    7440000
中村 由美      560000    6720000
伊藤 大輔      500000    6000000
鈴木 花子      480000    5760000
    :            :            :   （以下5行省略）

10行が選択されました。

見出しが指定したとおり「氏名」「月給」「年収」の日本語になっている点に注目してください。文字列連結の記号は、実はデータベース製品によってばらばらです。他の製品から来た方が最初に戸惑いやすいポイントなので、ここで比べておきましょう。

製品 文字列連結の書き方
Oracle last_name || first_name
PostgreSQL ||（Oracleと同じ）
SQL Server last_name + first_name（+ 演算子）
MySQL CONCAT(last_name, first_name)（関数のみ。既定では || は使えない）

「Oracleの文字列連結は ||」と覚えてください。+ は数値の足し算のための演算子ですが、Oracleは文字列を数値へ暗黙的に変換しようとするため、'123' + '456' のように数値に変換できる文字列であれば計算できてしまいます。一方、'佐藤' + '一郎' のように数値に変換できない文字列に + を使うと ORA-01722（数値が無効です）というエラーになります。文字列をつなげたいときは、常に || を使いましょう。

6.3 DUAL表 —— 表を使わずに計算するための"実験台" Oracle固有

ここまでは表の中身を取り出す例でしたが、「1+1の答えだけ知りたい」「今日の日付だけ確認したい」というように、表とは無関係な計算結果だけが欲しい場面もあります。従来のOracleのSQLは、SELECT に続けて必ず FROM で表名を書く決まりになっていました。

そこでOracleは DUAL表（Oracleがあらかじめ用意している、1行1列だけのダミー表） Oracle固有 という"実験台"を用意しました。FROM dual と書けば、実在する表を持ち出さずに計算式や関数の結果だけを1行で受け取れます。DUAL表という仕組み自体はOracle独自のもので、他のRDBMSには同じ名前の表はありません。MySQLやPostgreSQL、SQL Serverでは、そもそも表を指定せずに SELECT 1 + 1; のように書けます（詳しくは次のコラムで説明します）。

dual_sample.sql 
-- 表を使わずに計算結果だけを見たいときは DUAL 表を使う
SELECT 1 + 1 AS "計算結果" FROM dual;

-- 今日の日付を確認する（SYSDATEは現在の日時を返す関数）
SELECT SYSDATE AS "現在日時" FROM dual;
計算結果
--------
       2

現在日時
---------
31-AUG-26

※ SYSDATEの表示は実行した日によって変わります。また 31-AUG-26 という表示形式はNLS設定（言語・地域の設定）がAMERICANの場合のもので、日本語環境では 26-08-31 のように変わります。表示形式を確実に整えたいときは、第8章で学ぶTO_CHAR関数を使います。

FROMの省略はOracle Database 23aiで導入された機能

MySQLやPostgreSQL、SQL Serverでは以前から SELECT 1 + 1; のように FROM を省略できました。Oracleは長らく FROM の省略を認めていませんでしたが、この機能はOracle Database 23aiで導入され、本ガイドが使用するOracle AI Database 26ai Freeでも引き続き利用できます。そのため SELECT SYSDATE; のようにDUAL表を書かずに済ませられます。とはいえ、既存のシステムやネット上の資料にはDUAL表を使ったSQLが大量にあるため、DUAL表を使った書き方は今でも読み書きできるようにしておく必要があります。本ガイドでも、この先の章を含めてDUAL表を使った書き方を基本として紹介します。

6.4 WHERE句で条件を絞り込む 一般的なSQL/RDBMS

WHERE句（取り出す行を絞り込む条件を書く部分）を使うと、住所録から「東京都に住んでいる人だけ」を探すように、条件に合う行だけを取り出せます。WHERE句に書く「真（正しい）」か「偽（正しくない）」かを判定する条件式は述語（じゅつご、predicate）と呼ばれます。まずは基本の比較演算子です。

演算子 意味
= 等しい
<> 等しくない（!= も使えます）
> ／ >= より大きい／以上
< ／ <= より小さい／以下

比較演算子に加えて、Oracleには「範囲」「候補の中のどれか」「部分一致」を短く書ける専用の書き方があります。文字列はシングルクォート' 'で囲むこと、そしてOracleの文字列比較は大文字・小文字を区別することを覚えておいてください（'SATO' と 'sato' は別物として扱われます）。

where_patterns.sql 
-- 給与が40万以上の社員
SELECT last_name, salary FROM employees WHERE salary >= 400000;

-- 給与が35万以上50万以下の社員（BETWEENは両端を含む）
SELECT last_name, salary FROM employees WHERE salary BETWEEN 350000 AND 500000;

-- 営業部(10)か開発部(20)に所属する社員（INはいずれかに一致）
SELECT last_name, department_id FROM employees WHERE department_id IN (10, 20);

-- 姓が「佐」で始まる社員（%は0文字以上の任意の文字列、_は任意の1文字）
SELECT last_name FROM employees WHERE last_name LIKE '佐%';

LIKE の %（0文字以上の任意の文字列に一致）と _（ちょうど1文字に一致）はセットで覚えましょう。たとえば '東京%' は「東京」で始まる文字列、'東京__' は「東京」の後にちょうど2文字続く文字列に一致します。

続いて、初心者が最も引っかかりやすいNULL（値が「まだ入力されていない」ことを表す特別な印。0でも空文字列でもありません）の判定です。サンプルデータでは、社員110番（加藤さん）が部署未配属（department_id がNULL）、社員109番（小林さん）がメールアドレス未登録（email がNULL）になっています。

null_check.sql 
-- 部署が未定の社員を探す（= NULL では見つからない）
SELECT employee_id, last_name FROM employees WHERE department_id IS NULL;

-- 逆に部署が決まっている社員
SELECT employee_id, last_name FROM employees WHERE department_id IS NOT NULL;

つまずきポイント: WHERE department_id = NULL は常に0件

NULLは「値が不明」という状態であり、「何かと等しい」という比較そのものが成立しません。そのため = NULL は常に「不明（真でも偽でもない）」と判定され、結果は0件になります。NULLを調べるときは必ず IS NULL ／ IS NOT NULL を使う、と丸ごと覚えてください。NULLの詳しい計算上の挙動は第8章で扱います。

最後に、複数の条件を組み合わせる AND（かつ）・OR（または）・NOT（否定）です。ここには算数の「掛け算と足し算」に似た優先順位があります。AND は OR より先に評価されるため、意図と違う組み合わせ方をしてしまうミスが非常によく起こります。

and_or_wrong.sql 
-- 意図：「営業部または開発部」で、かつ「給与40万以上」
-- しかし括弧がないため、ANDが先に評価されてしまう（誤り）
SELECT last_name, department_id, salary
  FROM employees
 WHERE department_id = 10
    OR department_id = 20 AND salary >= 400000;
LAST_NAME  DEPARTMENT_ID     SALARY
---------- ------------- ----------
佐藤                  10     650000  ← 営業部は給与に関係なく全員含まれる
鈴木                  10     480000
高橋                  10     380000  ← 40万未満なのに含まれてしまった！
田中                  20     620000
伊藤                  20     500000
渡辺                  20     400000

6行が選択されました。

department_id = 10 OR (department_id = 20 AND salary >= 400000) という意味で評価されるため、営業部（10）は給与条件を無視してすべて含まれてしまいました。意図どおりにするには、OR側をまとめて括弧で囲む必要があります。

and_or_correct.sql 
-- 括弧でOR側をまとめれば、意図どおりの絞り込みになる（正しい）
SELECT last_name, department_id, salary
  FROM employees
 WHERE (department_id = 10 OR department_id = 20)
   AND salary >= 400000;
LAST_NAME  DEPARTMENT_ID     SALARY
---------- ------------- ----------
佐藤                  10     650000
鈴木                  10     480000
田中                  20     620000
伊藤                  20     500000
渡辺                  20     400000

5行が選択されました。（高橋さん・38万円は正しく除外された）

迷ったら括弧を付ける、を習慣にしてください。括弧は余分に付けても動作は変わりませんが、無くて困ることは頻繁に起こります。

6.5 ORDER BYで並べ替える 一般的なSQL/RDBMS

WHERE を付けずにSELECTしただけでは、Oracleが行をどんな順番で返すかは保証されないと述べました。特定の順番で見たいときは、ORDER BY（並べ替え＝ソートの基準となる列を指定する句）を使います。既定は昇順（ASC、小さい順）で、降順にしたいときは DESC を付けます。複数の列をカンマで並べれば「1つ目の列が同じ値のときは2つ目の列で比べる」という多段階の並べ替えもできます。

order_by_basic.sql 
-- 部署ごとにまとめ、同じ部署の中では給与が高い順に並べる
SELECT department_id, last_name, salary
  FROM employees
 ORDER BY department_id ASC, salary DESC;

NULLを含む列を並べ替えるときは、NULLをどこに置くかを意識する必要があります。Oracleの既定は「NULLは他のどんな値よりも大きい」とみなす扱いです。そのため昇順ではNULLが最後に、降順ではNULLが最初に来るのが既定の動きになります。これは他の製品と異なる場合があるOracle特有の挙動なので、覚えておいてください。明示したいときは NULLS FIRST ／ NULLS LAST を付けます。

nulls_first_last.sql 
-- 歩合率の高い順（降順）。Oracleの既定ではNULLが先頭に来る
SELECT last_name, commission_pct FROM employees ORDER BY commission_pct DESC;

-- NULLを末尾に回したいときは明示的に指定する
SELECT last_name, commission_pct FROM employees
 ORDER BY commission_pct DESC NULLS LAST;
-- ORDER BY commission_pct DESC（既定）
LAST_NAME  COMMISSION_PCT
---------- --------------
佐藤                          ← NULLの8行がまとまって先頭に来る
田中
  :        （中略、NULLが6行続く）
鈴木                     0.10
高橋                     0.05

-- ORDER BY commission_pct DESC NULLS LAST
LAST_NAME  COMMISSION_PCT
---------- --------------
鈴木                     0.10
高橋                     0.05
佐藤                          ← NULLの8行がまとまって末尾に来る
  :        （以下略）

歩合率（commission_pct）が設定されているのは鈴木さんと高橋さんの2名だけで、残り8名はNULLです。「NULLをどちらに寄せたいか」は業務要件次第なので、迷ったら意図を NULLS FIRST ／ NULLS LAST で明示するのが安全です。

6.6 件数を絞る —— FETCH FIRSTとROWNUMの違い

「上位3名だけ見たい」というように、結果の件数そのものを絞り込みたい場面はよくあります。FETCH FIRST n ROWS ONLY 一般的なSQL/RDBMS は標準SQL（ISO/ANSI SQL:2008）に準拠した書き方で、Oracle Database 12c以降で使えるほか、PostgreSQLやSQL Server、DB2など他の主要なRDBMSでも同様に使えます。ORDER BY の直後に書くのが基本の型で、本ガイドでは、まずこちらを使うことを推奨します。

fetch_first.sql 
-- 給与の高い順に上位3名だけ取り出す（12c以降の書き方）
SELECT last_name, salary
  FROM employees
 ORDER BY salary DESC
 FETCH FIRST 3 ROWS ONLY;
LAST_NAME       SALARY
---------- ----------
佐藤              650000
田中              620000
中村              560000

3行が選択されました。

FETCH FIRST は並べ替えを終えたあとの結果に対して「先頭からn件」を切り出すため、「給与が高い順で上位3名」のような要求を、書いたとおり素直に実現できます。他の製品と比べると、MySQLの LIMIT 10 に相当する機能です。

一方、古い資料でよく見かけるのが ROWNUM（取り出された順に1, 2, 3…と振られる、その場限りの通し番号） Oracle固有 です。ROWNUMはOracle独自の仕組みで、他のRDBMSには同じものはありません（たとえばMySQLやPostgreSQLはLIMIT句、SQL ServerはTOP句を使います）。動作原理も独特なので、初心者はあらかじめ落とし穴を知っておくとよいでしょう。

rownum_pitfall.sql 
-- 一見自然だが、常に0件になってしまう例
SELECT last_name FROM employees WHERE ROWNUM > 1;

-- こちらは意図どおり動く（先頭3件を取り出す）
SELECT last_name FROM employees WHERE ROWNUM <= 3;

つまずきポイント: WHERE ROWNUM > 1 はなぜ常に0件なのか

ROWNUMは「行が条件を通過した瞬間」に1から順番に採番されます。最初の候補行を評価するとき、その行にはまだROWNUM=1しか割り当てられていません。ROWNUM > 1 という条件は「1 > 1」となって偽になり、その行は除外されます。ROWNUM=2は「1件目が条件を通過して初めて」割り当てられる番号なので、1件目が毎回除外される以上、2番が振られる行は永遠に現れません。結果として表に何行あっても常に0件になります。

さらに厄介なのは、ROWNUMは ORDER BY より前の段階（表から取り出された直後）で振られるため、ORDER BY salary DESC と WHERE ROWNUM <= 3 を単純に組み合わせても「給与上位3名」にはならず、「並べ替え前にたまたま先頭にあった3件」が返ってしまう点です（Oracleが表を読み出す物理的な順序に依存し、実行のたびに変わる可能性があります）。この問題を避けるには、先に副問合せの中でORDER BY を完了させてから、外側でROWNUM を絞るという2段構えの書き方が必要になります。

重要ポイント

「並べ替えてから件数を絞る」という目的なら、副問合せを書く必要がなく落とし穴も少ない ORDER BY … FETCH FIRST n ROWS ONLY を第一候補にしてください。ROWNUMは、古いコードを読むときに意味を理解できれば十分です。

6.7 CASE式で値を条件分岐させる

CASE式（条件によって返す値を切り替える式）を使うと、「給与が60万円以上なら"上級"、40万円以上なら"中堅"、それ以外は"一般"」というような分類を、SELECT の中でそのまま作れます。表計算ソフトの IF 関数に近い感覚です。書き方には2種類あります。

case_searched.sql 
-- 検索CASE: WHENごとに条件式を書く（上から順に判定される）
SELECT last_name, salary,
       CASE
           WHEN salary >= 600000 THEN '上級'
           WHEN salary >= 400000 THEN '中堅'
           ELSE '一般'
       END AS "給与区分"
  FROM employees
 ORDER BY salary DESC;

WHEN は上から順番に判定され、最初に条件が成立したところで確定します。渡辺さんの給与はちょうど40万円なので salary >= 400000 に一致し「中堅」になります。どのWHEN にも当てはまらない行は ELSE の値になり、ELSE を省略した場合はNULLになる点も覚えておきましょう。

条件式ではなく「1つの列の値がどれに一致するか」で分岐したいだけなら、もっと短く書ける単純CASEが使えます。

case_simple.sql 
-- 単純CASE: 1つの列の値と各候補を照合する
SELECT last_name,
       CASE department_id
           WHEN 10 THEN '営業'
           WHEN 20 THEN '開発'
           WHEN 30 THEN '総務'
           ELSE '未配属'
       END AS "部署略称"
  FROM employees;

単純CASEは CASE 列名 WHEN 値 THEN … の形で「等しいかどうか」しか判定できません。「以上・以下」のような範囲を扱いたい場合は、先に紹介した検索CASE（WHEN 条件式 THEN …）を使う必要があります。

やってみよう 6-1: 条件を組み合わせて社員を探す

本章で学んだ WHERE・ORDER BY・別名・連結を組み合わせて、次の条件に合うSELECT文を自分で書いてみましょう。

  1. 開発部（department_id = 20）に所属し、月給が45万円以上の社員を取り出す。
  2. 結果には、姓と名を連結した氏名を "氏名" という別名で表示する。
  3. 給与が高い順に並べる。

ヒント（解答例）:

exercise_6-1.sql 
SELECT last_name || first_name AS "氏名", salary
  FROM employees
 WHERE department_id = 20
   AND salary >= 450000
 ORDER BY salary DESC;

正しく書けていれば2件——田中美咲さんと伊藤大輔さんだけが返ってきます（渡辺さん・山本さんは45万円未満なので対象外です）。

理解度確認クイズ

  1. Q1. 部署が未配属（department_idが未入力）の社員を探したい。正しいWHERE句は次のどれですか。(a) WHERE department_id = NULL (b) WHERE department_id IS NULL (c) WHERE department_id = ''

    回答を表示

    (b)。NULLは「値が不明」という状態なので、等号では比較できず IS NULL を使う必要があります。(c) の空文字列もOracleではNULL扱いになりますが、比較演算子が等号のままなので、こちらも結果は0件になります（詳細は第8章）。

  2. Q2. SELECT salary * 12 AS "年収" FROM employees WHERE "年収" > 5000000; を実行すると、ORA-00904（識別子が無効です）というエラーになります。理由を説明してください。

    回答を表示

    SQL文はSELECT→FROM→WHERE→ORDER BYの順に書きますが、Oracleが実際に評価する順番はFROM→WHERE→SELECT→ORDER BYです。WHEREはSELECTより先に評価されるため、SELECTで付けた別名「年収」はまだ存在せず使えません。WHERE salary * 12 > 5000000 のように計算式を書き直す必要があります（ORDER BYはSELECTより後に評価されるため、別名を使えます）。

  3. Q3. SELECT * FROM employees WHERE ROWNUM > 1; を実行すると、employees表に10件のデータがあるにもかかわらず常に0件になります。なぜですか。

    回答を表示

    ROWNUMは行が条件を通過した時点で1から順に採番されます。最初の候補行はまだROWNUM=1の段階でROWNUM > 1（1 > 1）を判定されて偽になり除外されます。ROWNUM=2は1件目が条件を通過して初めて割り当てられる番号なので、1件目が毎回除外される以上、2以降の番号を持つ行は決して現れません。結果として常に0件になります。件数を絞りたいときはFETCH FIRST n ROWS ONLYを使うのが安全です。
