Oracle Databaseとは

Oracle Database は、世界中の企業システムで長く使われてきたリレーショナルデータベース管理システム（RDBMS）です。この章では「そもそもデータベースとは何か」という出発点から、Oracle Database の特徴・エディション・他のデータベースとの違いまで、全体像をつかみます。まだ何もインストールしなくて大丈夫です。まずは言葉のイメージを固めましょう。

この章で学ぶこと

  • データベースと RDBMS が何をするものかを、身近な例で説明できる
  • 「SQL」と「Oracle Database」の違いを区別して説明できる
  • 「製品エディション（Free・SE2・EE）」と「クラウドのマネージドサービス」の違いを知り、学習用にどれを選べばよいか判断できる
  • PostgreSQL・SQL Server・MySQL と比べた Oracle の立ち位置を大づかみに説明できる

1.1 データベースとは何か

データベースとは、たくさんのデータを整理して貯めておき、必要なときにすばやく取り出せるようにした「データの保管庫」です。身近な例では、コンビニのレジ（売上データ）、銀行の ATM（口座残高）、通販サイト（商品と注文）、社内の勤怠システム（出退勤の記録）など、私たちが毎日使っているサービスの裏側は、ほぼすべてデータベースが支えています。

イメージとしては「巨大で頑丈な住所録」を思い浮かべてください。名前・住所・電話番号といった項目が決まっていて、行がどんどん増えていく。そこから「東京都に住んでいる人だけ」を短時間で取り出せる（実際の速さはデータ量や索引の有無など環境によって変わります）。これがデータベースの基本的な働きです。

「Excel でも表は作れるのでは？」と思うかもしれません。実際、少量のデータであれば Excel でも十分に役立ちます。しかし、大量のデータを、たくさんの人が同時に、安全に扱うという用途になると、Excel と専用ソフトでは得意・不得意が分かれてきます。この「データベースを管理する専用ソフト」のことを DBMS（Database Management System＝データベース管理システム）と呼びます。

観点 Excel などの表計算 データベース（RDBMS）
大量データの扱い 表計算として設計されており、データ量が増えるほど動作や集計が重くなりやすい 数百万〜数億行規模でも、索引（インデックス）を使って必要な行だけ高速に取り出せる
複数人での同時更新 共同編集の機能はあるが、多人数が同じデータを頻繁に書き換える用途には向きにくい 多数の利用者が同時に読み書きしても、データの整合性が保たれるよう設計されている
処理のまとまりの保証 複数の変更を「まとめて確定／まとめて取り消し」する仕組みは持たない 関連する複数の変更をひとまとまりとして扱い、途中で失敗すれば全体を取り消せる（第12章）
正しさの保証 入力規則を設定しない限り型のチェックが弱く、入力ミスもそのまま保存されやすい 型・制約を設定することで、おかしなデータの登録を防ぎやすい（第5章）
障害からの復旧 ファイルが壊れると、データの復旧が難しいことが多い バックアップとログを組み合わせて復旧できるよう設計されている（第14章）

DBMS の中でも、データを「表（テーブル）」の形で管理し、表どうしを関連づけて扱えるものを RDBMS（Relational Database Management System＝リレーショナルデータベース管理システム）と呼びます。「リレーショナル」は「関連の」という意味で、たとえば「社員の表」と「部署の表」を部署番号でつなげて「営業部の社員一覧」を取り出す、といった使い方ができます。Oracle Database はこの RDBMS の代表格です。

用語メモ: 「SQL」と「Oracle Database」は別のもの

SQL（エスキューエル）は、データベースに指示を出すための言語の名前です。一方 Oracle Database は、その言語を受け付けて実際に動く製品（ソフトウェア）の名前です。「日本語」と「電話機」の関係に似ています。日本語（SQL）は多くの電話機（各社の RDBMS）で通じますが、方言が少しずつ違う、と考えてください。

1.2 Oracle Database とは

Oracle Database は、米 Oracle 社が開発・提供している RDBMS です。1979年に商用の RDBMS として世に出て以来、40年以上にわたり改良が重ねられてきました。日本国内でも、銀行の勘定系システム、通信会社の顧客管理、製造業の生産管理、官公庁のシステムなど、「止まると困る」大規模な基幹システムで数多く採用されています。

「Oracle は高価で企業向け」というイメージがあるかもしれませんが、学習目的であれば心配は不要です。本ガイドで使う Oracle AI Database 26ai Free Oracle固有 は無償で入手・利用できるエディションで、SQL や PL/SQL といった基本的な機能は有償版と共通です（後述のとおり使えるリソース量には上限があり、有償版向けの一部の高度な機能は対象外です）。まずはこれで十分に学べます。

なお、2025年10月に製品名が Oracle Database 23ai から Oracle AI Database 26ai に変わりました。内部のバージョン番号は 23.26.x のままで、23ai に対する機能更新（Release Update）という形で提供されています。書籍やブログでまだ「Oracle Database 23ai Free」という表記を見かけることがありますが、同じもの（の後継バージョン）だと考えて差し支えありません。

高い信頼性

障害対策・バックアップ・復旧の仕組みが充実しており、大規模な基幹システムで長年使われてきた実績があります。

同時実行に強い

「読み取りは書き込みを待たない」という独自の仕組みにより、多人数が同時に使っても待ち時間が生じにくい設計です（第12章）。

PL/SQL が使える

SQL に条件分岐や繰り返しを加えた PL/SQL という言語で、業務ロジックをデータベース側に置けます（第10章・第11章）。

Oracle で使う SQL も、基本的な SELECT 文などは他の RDBMS と共通です。ただし変数・条件分岐・繰り返しといったプログラミング的な書き方は PL/SQL（Procedural Language/SQL）という Oracle 独自の言語になります（第10章で学びます）。まずは共通部分の SQL をしっかり身につければ、他のデータベースにも応用が利きます。

重要ポイント

Oracle を学ぶことは「Oracle だけの知識」を学ぶことではありません。表・SQL・トランザクション・インデックスといった考え方は、どの RDBMS でも共通の土台です。Oracle で身につけた基礎は、PostgreSQL や SQL Server にもそのまま活かせます。

1.3 エディションの違いと学習用の選び方

エディションとは、同じ製品の中で「機能や使える範囲が異なる複数の販売単位」のことです。同じソフトウェアの「無料版・標準版・上位版」のようなものだとイメージしてください。Oracle Database には、用途と規模に応じて複数のエディションが用意されています。中身のソフトウェアは共通で、使える機能とリソースの上限、そして価格が違うと考えると分かりやすいでしょう。

Oracle の製品ラインアップは、大きく分けると「1) 自分でサーバーを用意してインストールし、自分で運用するエディション」と「2) Oracle のクラウド（Oracle Cloud Infrastructure）上で、Oracle が運用を代行してくれるマネージドサービス」の2系統があります。この2つは目的も課金体系も異なるため、区別して理解しておくと迷いにくくなります。

1) 自分で用意して動かす製品エディション Oracle固有

エディション 費用 主な制限・特徴 主な用途
Free（旧 Express Edition / XE） 無償 ユーザーデータ 12GB・メモリ 2GB・CPU 2コアまで。上限を超えると ORA-12954 エラーになりますが、機能自体は豊富に使える 学習・検証・小規模用途（本ガイドで使用）
Standard Edition 2（SE2） 有償 サーバーあたり最大2ソケットまで。高度な機能の一部は非対応 中小規模の業務システム
Enterprise Edition（EE） 有償 上限なし。高可用性・性能・セキュリティの高度な機能を追加購入できる 大規模・ミッションクリティカル（止まると業務や社会に大きな影響が出る、絶対に止められないシステムのこと）な基幹システム

本ガイドでは Oracle AI Database 26ai Free を使います。無償でありながら、SQL・PL/SQL・トランザクション・インデックスといった本ガイドで扱う内容はすべて実行できます。データ量 12GB の制限も、学習で作るサンプルの表であればまったく問題になりません。

2) クラウド上のマネージドサービス 参考

マネージドサービスとは、サーバーの用意・インストール・バックアップ・パッチ適用といった運用作業を、利用者ではなくサービス提供者（ここでは Oracle）が代行してくれる形態のサービスです。Oracle Cloud Infrastructure（OCI）上で提供される Oracle Autonomous AI Database（旧称: Oracle Autonomous Database、2025年10月に改称）がこれにあたります。運用の多くが自動化されており、従量課金（無償枠あり）で利用できます。

「エディション」と「マネージドサービス」は別の軸

Free・SE2・EE は「自分でインストールして動かすソフトウェアの版」であるのに対し、Oracle Autonomous AI Database は「Oracle が代わりに運用してくれるクラウドサービス」です。Oracle のライセンス資料でも、エディション（Free / SE2 / EE などの一覧）とクラウドサービス（Autonomous AI Database などの一覧）は別々の項目として整理されています。「エディションの一種」として覚えてしまうと後で混乱しやすいので、本ガイドでは分けて扱います。本ガイドの学習には、次に説明するローカルの Free エディションを使います。

バージョン名の読み方: 「26ai」とは？

Oracle のバージョンには 11g・12c・19c・23ai・26ai のように数字＋アルファベットが付きます。数字がバージョン番号、末尾の文字はその時代のテーマを表しています（g = grid、c = cloud、ai = artificial intelligence）。23ai は 2024年に登場した世代で、2025年10月に Oracle AI Database 26ai へ名称が変わりました。内部のバージョン番号は 23.26.x のままで、23ai に対する機能更新（Release Update）という形で提供されています。本ガイドは 26ai を前提に解説します。

1.4 他のデータベースとの違い

RDBMS は Oracle だけではありません。よく比較される4製品を並べて、それぞれの立ち位置を確認しておきましょう。今の段階では「なんとなくの住み分け」がつかめれば十分です。

製品 提供元・ライセンス 手続き型言語 よく使われる場面
Oracle Database Oracle 社 / 商用（Free 版は無償） PL/SQL 金融・通信・製造などの大規模基幹システム
PostgreSQL コミュニティ / オープンソース（無償） PL/pgSQL Web サービス、標準 SQL 準拠を重視する用途
SQL Server Microsoft 社 / 商用（無償版あり） T-SQL Windows / .NET 環境の業務システム
MySQL Oracle 社 / オープンソース（無償版あり） SQL/PSM 系 Web アプリケーション、CMS

SQL の書き方も、製品ごとにわずかな「方言」があります。本ガイドで学ぶうちに何度か出てきますので、代表的なものをここで一度眺めておきましょう。今は覚えなくて構いません。「Oracle はここが独特なんだな」という感覚だけ持ってください。

やりたいこと Oracle の書き方 他製品の例 学ぶ章
文字列の型 VARCHAR2 PostgreSQL: varchar / text 第5章
現在日時を取る SYSDATE SQL Server: GETDATE() 第8章
件数を絞る FETCH FIRST 10 ROWS ONLY MySQL: LIMIT 10 第6章
変更を確定する 既定では COMMIT が必要 MySQL / SQL Server: 既定は自動確定 第7章・第12章

最初に知っておくべき注意点

上の表の最終行、「Oracle は通常、データの変更が自動的には確定しない」は初心者が最もつまずくポイントです。INSERT や UPDATE を実行しても、COMMIT と入力するまでは変更が仮の状態にとどまります。ただし、これはクライアントツールや自動コミット設定によって動作が変わる場合があります（例: 一部の GUI ツールは既定で自動コミットを有効にしています）。COMMIT しないまま接続が終わると、その変更は取り消されることがあります。確実に残すには、使っているツールの設定を確認したうえで COMMIT を実行することが基本です。「データを入れたはずなのに無い！」の大半はこれが原因です。第7章でしっかり練習します。

1.5 このガイドの学習ロードマップ

本ガイドは全14章で構成されています。「知る → 作る → 操作する → 深める → 品質と運用を固める」という順に進み、後の章ほど前の章の知識を使います。順番どおりに読み進めることをおすすめします。

第1章・第2章では手を動かす作業はありません。まずは言葉と全体像に慣れることが目的です。実際にインストールして SQL を打ち込むのは第3章からになります。

次の第2章では、Oracle の中身がどんな構造になっているのか（インスタンス・データベース・表領域・スキーマ、そして CDB / PDB）を学びます。ここを理解しておくと、第3章のインストール作業で出てくる用語に迷わなくなります。

やってみよう 1-1: 身の回りのデータベースを探す

インストールはまだ不要です。紙かメモアプリを用意して、次の問いに答えてみましょう。「データベースがどこで働いているか」を意識できるようになると、以降の章の理解が一段と進みます。

  1. 今日あなたが使ったサービス（アプリ・Web サイト・店舗のレジなど）を3つ書き出す。
  2. それぞれについて「どんなデータが保存されていそうか」を、表の列名の形で書き出す（例: 通販サイト → 商品名・価格・在庫数）。
  3. その中で「複数人が同時に書き換えそうなデータ」はどれか、印を付ける。

ヒント: 3番で印が付いたデータこそ、RDBMS が最も得意とする領域です。「在庫数」のように、同時に2人が買おうとしたときに矛盾が起きては困るデータを想像してみてください。この問題への Oracle の答えが、第12章で学ぶトランザクションとロックです。

理解度確認クイズ

  1. Q1. 「SQL」と「Oracle Database」はどう違いますか？

    回答を表示

    SQL はデータベースを操作するための「言語」の名前、Oracle Database はその言語を受け付ける Oracle 社製の「製品（RDBMS）」の名前です。SQL の基本部分は他の RDBMS と共通ですが、Oracle には PL/SQL という独自の手続き型言語があります。

  2. Q2. 学習目的で Oracle Database を導入する場合、どのエディションを選ぶとよいですか。その理由も答えてください。

    回答を表示

    Oracle AI Database 26ai Free（製品エディションの Free）。無償で入手でき、SQL・PL/SQL・トランザクション・インデックスなど学習に必要な機能がひととおり使えるからです。ユーザーデータ 12GB・メモリ 2GB・CPU 2コアという上限はありますが、学習用のサンプルデータでは問題になりません。なお、クラウドの Oracle Autonomous AI Database はエディションではなくマネージドサービスなので、この設問の「エディション」の答えとしては該当しません。

  3. Q3. Oracle でデータを追加したのに、接続し直すとデータが消えていました。最も考えられる原因は何ですか。

    回答を表示

    COMMIT を実行していなかった可能性が高いです。Oracle では INSERT・UPDATE・DELETE による変更は、通常は COMMIT するまで確定しません。ただし、クライアントツールや自動コミット設定によって動作が変わる場合があります。COMMIT しないまま接続が終わると、その変更は取り消されることがあります。使っているツールが自動コミットになっていないか確認したうえで、確実に残すには COMMIT を実行してください（第7章・第12章で詳しく扱います）。
