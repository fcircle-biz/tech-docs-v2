第10章 所要時間: 約2時間

PL/SQL入門

第9章までで、SQL 1文でできることは一通り書けるようになりました。本章では、条件によって処理を分ける・同じ処理を繰り返す・エラーを受け止めて対処するといった、SQL単体ではできない「手続き」の書き方を、Oracle独自の言語 PL/SQL で学びます。ここで身につける書き方は、次の第11章で名前を付けて保存する部品（プロシージャ・ファンクション・トリガー）の土台になります。

この章で学ぶこと

  • PL/SQLのブロック構造（宣言部・実行部・例外処理部）を書ける
  • 変数を宣言して使い、%TYPEで表の定義に追従させられる
  • IF・CASE・LOOP・FORで条件分岐と繰り返しを書ける
  • SELECT INTOとカーソルでSQLの結果をPL/SQLの中で扱い、例外を捕まえて処理できる

10.1 なぜPL/SQLが必要か

これまで書いてきたSQLは、「何が欲しいか」を1文で宣言する言語でした。「営業部の社員を給与の高い順に出して」とお願いすれば、Oracleがその通りの結果を返してくれます。しかし、SQLには次のようなことは書けません。「まず条件を確認し、結果によって処理Aか処理Bを選ぶ」「結果を1件ずつ取り出して、件ごとに違う計算をする」「途中でおかしな値が見つかったら処理を中断し、代わりの対応をする」。これらはすべて「手順」そのものであり、SQLの守備範囲の外にあります。

身近な例で考えてみましょう。SQLは「注文票」です。「らーめん1つ、大盛りで」と欲しい結果だけを伝えます。一方PL/SQLは「レシピ（手順書）」です。「スープを温める→塩加減を確認する→薄ければ調味料を足す→もう一度確認する→盛り付ける」のように、条件による分岐や繰り返しを含む一連の手順を書き下せます。PL/SQL（Procedural Language extensions to SQL / SQLに手続き型の書き方を追加したOracle独自の言語）は、この「レシピを書く力」をOracleに追加するものです。

SQL ＝ 注文票

「欲しい結果」だけを1文で宣言する。手順そのものは書けない（宣言型）。

PL/SQL ＝ レシピ

条件分岐・繰り返しを含む「手順」そのものを書ける（手続き型）。

SQLとPL/SQLでできることの境界線を、表で確認しておきましょう。

やりたいこと SQLだけで PL/SQLなら
給与が40万円以上の社員を出す できる（WHERE句） できる
給与から「高・中・低」を判定して表示する 一部できる（第8章のCASE式） できる（IF文で自由に分岐）
結果を1件ずつ取り出し、件ごとに違う処理をする できない できる（カーソルとループ）
異常な値を見つけたら中断し代替処理をする できない できる（例外処理）

重要ポイント

PL/SQLの処理はOracleサーバーの中でまとめて実行されます。アプリケーションから1文ずつSQLを送るのに比べて通信の往復回数が減るという実務上のメリットもあります。この考え方は第11章の「ストアドプログラム」でさらに活用します。

10.2 PL/SQLブロックの構造

PL/SQLのコードのかたまりをブロックと呼びます。ブロックは次の4つの部分からできています。

部分 省略 書く内容
DECLARE 省略可 これから使う変数の宣言
BEGIN 必須 実際に行う処理（SQL文・IF・LOOPなど）
EXCEPTION 省略可 実行部でエラーが起きたときの受け止め方
END; 必須 ブロックの終わり

名前を付けずにその場だけで実行するブロックを匿名ブロックと呼びます。まずはこの匿名ブロックで書き方に慣れましょう（名前を付けて保存する方法は第11章で学びます）。

flowchart TD A["DECLARE
（変数を用意する・省略可）"] --> B["BEGIN
（処理を書く・必須）"] B --> C{"実行中にエラーが発生した？"} C -->|はい| D["EXCEPTION
（受け止めて処理する・省略可）"] C -->|いいえ| E["END;
（単独の / で実行）"] D --> E

最初に必ずつまずくポイント: 何も表示されない！

PL/SQLで画面に文字を出すには DBMS_OUTPUT.PUT_LINE('...') を使います。ところがSQL*Plusでは、先に SET SERVEROUTPUT ON を実行しておかないと、出力の受け皿が用意されず何も表示されません。エラーにもならず黙って何も出ないため、初心者が最初に必ずつまずく箇所です。SQL Developerでは代わりにDBMS_OUTPUTビュー（第4章）を開いて有効にする必要があります。何も出なかったら「まずSET SERVEROUTPUT ONを打ったか」を疑いましょう。

それでは最初のブロックを実行してみましょう。ブロックの最後には、第4章で確認した単独の /が必要です。

hello_plsql.sql 
-- これを先に実行しないと出力が画面に出ない（SQL*Plusの設定）
SET SERVEROUTPUT ON

BEGIN
  -- 画面に文字を出力する
  DBMS_OUTPUT.PUT_LINE('はじめてのPL/SQL');
END;
/

DECLAREもEXCEPTIONも書かず、BEGINとEND;だけの最小構成です。実行すると「はじめてのPL/SQL」と表示されます。次の節から、このBEGINの中身を少しずつ豊かにしていきます。

10.3 変数を宣言する

変数とは、値を一時的に入れておく「ラベルの付いた箱」です。DECLARE部で、次の書式で宣言します。

構文 
変数名  データ型  [:= 初期値];

-- 例: v_ を付けるのはよくある命名習慣（必須ではない）
v_salary  NUMBER(8)  := 300000;
v_name    VARCHAR2(30 CHAR);

値を入れるときの記号に注意してください。PL/SQLでは代入は :=、比較は =と、はっきり書き分けます。v_salary = 300000;のように書いてしまうと代入にならずエラーになるので気をつけましょう。

変数の型を表の列と手で合わせるのは面倒ですし、あとで列の型が変わったときに直し忘れる原因にもなります。そこで使うのが%TYPEです。employees.salary%TYPEと書くと「employees表のsalary列と同じ型」という意味になり、将来salaryの桁数を変更しても、この変数宣言は直さずに済みます。行まるごとを1つの変数として受け取りたいときはemployees%ROWTYPEを使います（列ごとに変数を用意しなくてよくなります。第11章で活用します）。値を変えたくない場合はCONSTANTを付けます。

type_attribute.sql 
DECLARE
  -- employees.salary と同じ型の変数を宣言する（表定義が変わっても追従する）
  v_salary  employees.salary%TYPE;
  v_name    employees.last_name%TYPE;
BEGIN
  -- 1行だけ取り出して変数に入れる（SELECT INTOは10.6で詳しく学ぶ）
  SELECT last_name, salary INTO v_name, v_salary
    FROM employees WHERE employee_id = 101;
  DBMS_OUTPUT.PUT_LINE(v_name || ' さんの給与は ' || v_salary || ' 円です');
END;
/

用語メモ: SELECT INTO の予告

SELECT 列 INTO 変数 FROM ...は、SQLの結果をPL/SQLの変数に受け渡す書き方です。ここでは「1行だけ取り出す道具」として先に使いましたが、0件や複数件がヒットしたときにどうなるかは重要な注意点があるため、10.6で改めて詳しく扱います。

10.4 条件分岐（IF・CASE）

「条件によって処理を変える」ための基本がIF文です。書式はIF 条件 THEN 処理 ELSIF 条件 THEN 処理 ELSE 処理 END IF;。ELSIFは必要な数だけ重ねられ、どの条件にも当てはまらないときの受け皿として最後にELSEを置けます（省略も可能）。

注意: つづりは「ELSIF」

他の言語のelse ifに引きずられてELSEIFと書いてしまう間違いが非常によくあります。PL/SQLではELSIF（Eの1文字を省略した綴り）が正しい書き方です。

if_elsif.sql 
DECLARE
  v_salary employees.salary%TYPE;
BEGIN
  SELECT salary INTO v_salary FROM employees WHERE employee_id = 103;
  -- ELSEIF ではなく ELSIF と書く点に注意
  IF v_salary >= 600000 THEN
    DBMS_OUTPUT.PUT_LINE('給与ランク: 上級');
  ELSIF v_salary >= 400000 THEN
    DBMS_OUTPUT.PUT_LINE('給与ランク: 中堅');
  ELSE
    DBMS_OUTPUT.PUT_LINE('給与ランク: 一般');
  END IF;
END;
/

同じ判定はCASE文でも書けます。第8章で学んだCASE式は値を返すものでしたが、ここで扱うCASE文は処理を実行するものという違いに注意してください（見た目は似ていますが、式と文は別物です）。

case_statement.sql 
DECLARE
  v_dept employees.department_id%TYPE := 20;
BEGIN
  -- CASE文: 条件に応じて処理(ここではPUT_LINE)を実行する
  CASE
    WHEN v_dept = 10 THEN DBMS_OUTPUT.PUT_LINE('営業部です');
    WHEN v_dept = 20 THEN DBMS_OUTPUT.PUT_LINE('開発部です');
    ELSE DBMS_OUTPUT.PUT_LINE('その他の部署です');
  END CASE;
END;
/

10.5 繰り返し処理（LOOP・WHILE・FOR）

同じ処理を何度も繰り返すための書き方が3種類あります。使い分けの目安を先に表で確認しましょう。

書き方 向いている場面
LOOP ... EXIT WHEN ... END LOOP; 最も基本の形。抜ける条件を好きな場所に書ける
WHILE 条件 LOOP ... END LOOP; 先に条件を判定してから繰り返す（条件が偽なら1回も実行しない）
FOR i IN 1..n LOOP ... END LOOP; 繰り返す回数があらかじめ決まっている（最もよく使う）

基本形のLOOPは、EXIT WHEN 条件;に達するまでずっと繰り返します。EXIT WHENを書き忘れると、永遠に終わらない無限ループになるので注意してください。

basic_loop.sql 
DECLARE
  v_i NUMBER := 1;
BEGIN
  LOOP
    DBMS_OUTPUT.PUT_LINE(v_i || ' 回目の処理');
    v_i := v_i + 1;
    EXIT WHEN v_i > 3;  -- これがないと無限ループになる
  END LOOP;
END;
/

繰り返す回数が最初から決まっているなら、FORループが最も簡潔です。カウンタ変数（下の例のi）はDECLAREで宣言する必要がなく、ループの中でだけ自動的に使えます。

for_loop.sql 
BEGIN
  -- 1から5まで繰り返す（カウンタ変数 i の宣言は不要）
  FOR i IN 1..5 LOOP
    DBMS_OUTPUT.PUT_LINE(i || ' 回目の処理');
  END LOOP;
END;
/

WHILEは「条件を満たす間だけ」繰り返したいときに使います。LOOPとの違いは、条件を先頭で判定するため、最初から条件が偽であれば1回も実行されない点です。

while_loop.sql 
DECLARE
  v_i NUMBER := 1;
BEGIN
  -- v_iが3以下の間だけ繰り返す(先頭で条件判定するのがLOOPとの違い)
  WHILE v_i <= 3 LOOP
    DBMS_OUTPUT.PUT_LINE(v_i || ' 回目の処理');
    v_i := v_i + 1;
  END LOOP;
END;
/

10.6 SELECT INTOと例外処理

10.3で予告したとおり、SELECT INTOには決定的な規則があります。結果が必ずちょうど1行返ることを前提としているという規則です。SQLのSELECTは0件でも複数件でも普通に結果を返しますが、SELECT INTOは違います。

flowchart LR A["SELECT ... INTO 変数"] --> B{"該当した行数"} B -->|ちょうど1行| C["変数に代入されて正常終了"] B -->|0行| D["NO_DATA_FOUND 例外が発生"] B -->|2行以上| E["TOO_MANY_ROWS 例外が発生"]

この「0行」「2行以上」の異常事態を受け止める仕組みが例外処理です。ブロックの最後にEXCEPTION WHEN 例外名 THEN 処理を書きます。NO_DATA_FOUNDとTOO_MANY_ROWSは、Oracleがあらかじめ名前を用意している定義済み例外です。

select_into_exception.sql 
DECLARE
  v_name employees.last_name%TYPE;
BEGIN
  -- 存在しない社員番号を指定してみる
  SELECT last_name INTO v_name FROM employees WHERE employee_id = 9999;
  DBMS_OUTPUT.PUT_LINE(v_name);
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('該当する社員がいません');
  WHEN TOO_MANY_ROWS THEN
    DBMS_OUTPUT.PUT_LINE('複数件見つかりました。条件を見直してください');
END;
/

試しにWHERE employee_id = 9999をWHERE department_id = 20に変えて実行するとどうなるでしょうか。開発部には4名在籍しているため、今度はTOO_MANY_ROWSが発生します。実際に試して確認してみましょう。

想定していないあらゆるエラーを受け止める受け皿として、WHEN OTHERS THENがあります。エラーの詳細はSQLCODE（エラー番号）とSQLERRM（エラーメッセージの文字列）で取得できます。

注意: WHEN OTHERSで握りつぶさない

WHEN OTHERS THEN NULL;のように何もせず終わらせると、本当は何か重大な問題が起きているのに、それに誰も気づけなくなります。WHEN OTHERSを書くときは、必ずDBMS_OUTPUT.PUT_LINE(SQLERRM)などでログを残すか、呼び出し元に再送出しましょう。

自分の業務ルールに合わせて独自のエラーを発生させたいときはRAISE_APPLICATION_ERROR(エラー番号, 'メッセージ')を使います。独自に使えるエラー番号は-20000〜-20999の範囲と決められています。

raise_error.sql 
DECLARE
  v_salary employees.salary%TYPE := -1000;
BEGIN
  IF v_salary < 0 THEN
    -- 独自のエラー番号は -20000 〜 -20999 の範囲で指定する
    RAISE_APPLICATION_ERROR(-20001, '給与にマイナスは指定できません');
  END IF;
END;
/

このブロックを実行すると、ORA-20001というエラー番号とともに指定したメッセージが表示され、処理が中断します。第11章で作るストアドプログラムでは、こうして「入力チェックに失敗したら呼び出し元に伝える」という使い方をします。

10.7 カーソルで複数行を処理する

SELECT INTOは1行専用でした。では「複数行の結果を1件ずつ順番に処理したい」ときはどうするのでしょうか。そこで使うのがカーソルです。カーソルとは、問い合わせ結果のどこまで読んだかを指し示す「しおり」のようなものだとイメージしてください。1件読んでは次へ、1件読んでは次へと、しおりを進めながら処理していきます。

カーソルには書き方が2種類ありますが、初心者はまず「カーソルFORループ」だけ覚えれば十分です。FOR 変数 IN (SELECT文) LOOP ... END LOOP;と書くだけで、しおりを開く・1件ずつ読む・最後に閉じる、という一連の作業をOracleが自動でやってくれます。

cursor_for_loop.sql 
BEGIN
  -- SELECTの結果を1行ずつ r に受け取って繰り返す
  FOR r IN (SELECT last_name, salary FROM employees ORDER BY salary DESC) LOOP
    DBMS_OUTPUT.PUT_LINE(RPAD(r.last_name, 10) || TO_CHAR(r.salary, 'FM999,999') || ' 円');
  END LOOP;
END;
/

rはDECLAREで宣言していないのに、r.last_name・r.salaryのように列名で参照できています。カーソルFORループが、SELECT結果に合わせた%ROWTYPE相当の変数を自動的に用意してくれるためです。

参考までに、もう1つの書き方も見ておきましょう。明示カーソルは、DECLAREでカーソルに名前を付けて定義し、OPEN（開く）・FETCH（1件読む）・CLOSE（閉じる）を自分で書きます。

explicit_cursor.sql 
DECLARE
  -- カーソルに名前(c_emp)を付けて定義する
  CURSOR c_emp IS SELECT last_name FROM employees WHERE department_id = 10;
  v_name employees.last_name%TYPE;
BEGIN
  OPEN c_emp;                     -- しおりを開く
  LOOP
    FETCH c_emp INTO v_name;      -- 1件読む
    EXIT WHEN c_emp%NOTFOUND;     -- 読めなくなったら抜ける
    DBMS_OUTPUT.PUT_LINE(v_name);
  END LOOP;
  CLOSE c_emp;                    -- しおりを閉じる（必須）
END;
/

初心者はカーソルFORループでよい

明示カーソルはOPEN・CLOSEを書き忘れるとリソースが残り続けるなどの落とし穴があります。特別な理由がない限り、初心者は自動で開閉してくれるカーソルFORループを使えば十分です。「こういう書き方もある」と知っておけば、実務でこのスタイルのコードを読むときに困りません。

ここまでで、匿名ブロックの中で変数・条件分岐・繰り返し・SQLの結果の受け取り・例外処理を組み合わせられるようになりました。次の第11章では、この一連の処理に名前を付けて保存し、何度でも呼び出せる部品（プロシージャ・ファンクション）や、表の変更に反応して自動で動くトリガーへと発展させます。

やってみよう 10-1: 部署ごとの人数を判定するブロックを書く

カーソルFORループ・SELECT INTO・IF文・DBMS_OUTPUTを組み合わせて、departmentsの全部署について、所属する社員数から「大所帯」「少人数」「該当者なし」を判定して表示する匿名ブロックを書いてみましょう。

  1. SET SERVEROUTPUT ONを実行しておく（忘れると結果が見えない）。
  2. FOR d IN (SELECT department_id, department_name FROM departments) LOOPで部署を1件ずつ取り出す。
  3. ループの中でSELECT COUNT(*) INTO v_cnt FROM employees WHERE department_id = d.department_id;を実行し、その部署の人数を数える。
  4. IFでv_cnt >= 3なら「大所帯」、v_cnt >= 1なら「少人数」、それ以外は「該当者なし」と判定し、部署名とあわせて表示する。
  5. 実行し、営業部と開発部が「大所帯」、総務部が「少人数」、人事部が「該当者なし」と表示されることを確認する。

ヒント: COUNT(*)は該当が0件でも「0」という値を持つ1行を必ず返すため、SELECT INTOでNO_DATA_FOUNDになる心配はありません。「1部署ずつ処理しながら、その都度別のSQLを実行する」という発想は、SQL単体ではできなかったことを思い出してください。

理解度確認クイズ

  1. Q1. SELECT last_name INTO v_name FROM employees WHERE department_id = 20;を実行すると何が起きますか（開発部には4名在籍しています）。

    回答を表示

    TOO_MANY_ROWS例外が発生します。SELECT INTOはちょうど1行が返ることを前提とするため、2行以上ヒットすると例外になります。1行に絞り込む条件を追加するか、カーソルFORループで1行ずつ処理する必要があります。

  2. Q2. PL/SQLで変数に値を代入する演算子はどれですか。(a) = (b) := (c) ==

    回答を表示

    (b) :=です。=は比較に使う記号で、代入には使えません。この取り違えは初心者の頻出エラーです。

  3. Q3. DBMS_OUTPUT.PUT_LINEを書いて実行したのに、SQL*Plusの画面に何も表示されません。まず何を疑うべきですか。

    回答を表示

    SET SERVEROUTPUT ONを先に実行したかを疑います。これを実行していないと、SQL*Plusは出力の受け皿を用意していないため、エラーも出さずに黙って何も表示しません。SQL Developerの場合はDBMS_OUTPUTビューを開いて対象の接続を有効にする必要があります。
