ホーム SQL Server 第4章
第4章 所要時間: 約60分

SSMSの基本操作

前章で SQL Server と SSMS（SQL Server Management Studio）のインストールが終わりました。この章では、SSMS の画面構成を理解し、オブジェクトエクスプローラーでデータベースを探索し、クエリエディタで T-SQL を実行するという「日々の操作の型」を身につけます。

この章で学ぶこと

  • SSMS の画面（オブジェクトエクスプローラー・クエリエディタ・結果グリッド）の役割を説明できる
  • オブジェクトエクスプローラーでデータベース・テーブル・列を探索できる
  • クエリエディタで T-SQL を実行し、結果を読み・保存できる
  • GO とセミコロンの違い、sqlcmd や VS Code という SSMS 以外の選択肢を理解する

4.1 SSMSの画面構成

SSMS を起動してインスタンスに接続すると、画面は大きく分けて次の4つの領域から構成されます。それぞれの役割を最初に押さえておくと、以降の操作で迷わなくなります。

オブジェクトエクスプローラー（左側）

画面左に常時表示されるツリー表示。サーバーの中にあるデータベース・テーブル・ビューなどの一覧を、フォルダのように展開して確認できます。

クエリエディタ（中央上）

T-SQL を書き込む画面。「新しいクエリ」を開くたびに、このエディタのタブが増えていきます。

結果グリッド（中央下）

SELECT 文を実行した結果が、表形式で表示される領域です。Excel のようにセルをコピーできます。

メッセージタブ（結果グリッドの隣）

影響を受けた行数や、実行時のエラーメッセージが表示されます。結果が0件でも、ここを見れば実行が成功したか分かります。

(左: データベースツリー)"] A --> C["クエリエディタ
(中央上: T-SQLを書く)"] C --> D["結果グリッド
(中央下: 表形式の結果)"] C --> E["メッセージタブ
(中央下: 件数・エラー)"]

用語: インスタンスと接続

SSMS を起動すると最初に「サーバーへの接続」ダイアログが表示されます。第2章で学んだインスタンス（SQL Server 実行単位）に対して、サーバー名（例: localhost）と認証情報を入力して接続します。接続に成功すると、オブジェクトエクスプローラーの一番上にサーバー名が表示されます。

4.2 オブジェクトエクスプローラーで探索する

オブジェクトエクスプローラーはフォルダアイコンの「＋」を1段ずつクリックして展開していく操作が基本です。まずは既定で用意されているシステムデータベースを見てみましょう。

  1. 1 サーバー名の左にある「＋」（または三角アイコン）をクリックして展開する。
  2. 2 「データベース」フォルダを展開すると、System Databases（master・model・msdb・tempdb）が見える。
  3. 3 目的のデータベース（例: 第5章で作成する SampleShop）を展開し、さらに「テーブル」フォルダを展開する。
  4. 4 テーブル名（例: dbo.Customers）を展開すると「列」フォルダがあり、各列名とデータ型が確認できる。

テーブルを右クリックすると、よく使う2つの機能にすぐアクセスできます。

右クリックメニュー できること
上位1000行の選択 クリックするだけで SELECT TOP (1000) * FROM ... が自動生成・実行され、中身をざっと確認できる
テーブルの設計 列名・データ型・NULL許可などを画面上で確認・編集できるデザイン画面が開く

オブジェクトエクスプローラーの内容は、他の人がデータベースを作成・変更しても自動では更新されません。ツリー上部の更新アイコン（）をクリックするか、対象を右クリックして「更新」を選ぶと最新状態に反映されます。

4.3 クエリを実行する

ここからは実際に T-SQL を書いて実行してみましょう。ツールバーの「新しいクエリ」ボタン（または Ctrl+N）をクリックすると、白紙のクエリエディタタブが開きます。

用語: 対象データベースの切り替え

クエリエディタのツールバーには、現在どのデータベースに対してクエリを実行するかを示すドロップダウンがあります。ここで対象を選び直すか、クエリの先頭で USE データベース名; を実行することで、対象データベースを切り替えられます。両者は同じ効果ですが、スクリプトとして保存・共有するなら USE 文を書いておく方が確実です。

次の例では、USE でデータベースを切り替えたうえで、簡単な SELECT 文を実行します。

query.sql 
-- 対象データベースを切り替える
USE master;

-- このインスタンス上のデータベース一覧を確認する
SELECT name, database_id, create_date
FROM sys.databases;

クエリを実行する方法はいくつかあります。目的に応じて使い分けましょう。

操作 方法 用途
F5 「実行」ボタン、または F5 キー エディタ内のすべてのステートメントを実行する
選択範囲の実行 実行したい行をマウスで選択してから F5 複数のクエリを書いたエディタで、一部だけ試したいとき
実行の中止 ツールバーの赤い■（クエリの取り消し）ボタン 実行に時間がかかりすぎている、または誤操作に気づいたとき

注意

何も選択していない状態で F5 を押すと、エディタに書かれたすべての文が上から順に実行されます。UPDATE や DELETE を試し書きしている途中でうっかり F5 を押さないよう、実行前にメッセージタブと選択範囲を確認する癖をつけましょう。

4.4 GO とバッチ

T-SQL のスクリプトでは、文の区切りとしてセミコロン（;）のほかに、GO という単語をよく見かけます。この2つは役割がまったく異なります。

区切り 正体 役割
;（セミコロン） T-SQL 構文の一部 1つのステートメント（命令文）の終わりを示す
GO T-SQL 構文ではない SSMS や sqlcmd が解釈するバッチの区切り

用語: バッチとは

バッチとは、SQL Server にまとめて送信される1つの命令のかたまりです。GO はデータベースエンジンには渡らず、SSMS や sqlcmd がスクリプトを読んで「ここまでを1つのバッチとしてサーバーへ送る」区切りとして使うだけのクライアント側の合図です。そのため GO の後にセミコロンを付けたり、行の途中に置いたりすることはできません。

GO が必要になる代表例が、データベースの作成と切り替えです。同じバッチの中では、作成したばかりのデータベースへすぐには切り替えられません。

batch.sql 
-- 1つ目のバッチ: データベースを作成する
CREATE DATABASE Sample;
GO

-- 2つ目のバッチ: 作成したデータベースへ切り替える
USE Sample;
GO

-- 3つ目のバッチ: 現在の対象データベース名を確認する
SELECT DB_NAME() AS current_db;

逆に、通常の SELECT や INSERT を1文ずつ実行するだけであれば、GO は必須ではありません。「データベース自体を作る・切り替える」「同名オブジェクトを作り直す」といった、SQL Server の内部処理を区切りたい場面で使う、と覚えておけば十分です。

4.5 結果の読み方と保存

SELECT 文を実行すると、既定では結果グリッドに表形式で表示されます。ツールバーのアイコン、または結果ペイン上での右クリックから、表示方法や保存形式を切り替えられます。

操作 内容
グリッド表示 既定の表示方法。列見出しで並べ替え、セルをコピーできる（Ctrl+D）
テキスト表示 結果を等幅フォントの文字列として表示する（Ctrl+T）。ログとして貼り付けたいときに便利
ファイルに結果を保存 結果グリッドを右クリック →「名前を付けて結果を保存」で CSV 形式で書き出せる

メッセージタブには、取得した行数と実行時間が表示されます。「クエリは完了しましたが、行は返されませんでした。」と出た場合は、SELECT 文が0件を返したか、SELECT を含まない文（CREATE や USE）だけを実行したことを意味します。エラーではありません。

重要ポイント: スクリプトの生成

既存のテーブルを右クリック →「テーブルのスクリプト化」→「CREATE 文への」→「新規クエリエディターウィンドウ」を選ぶと、そのテーブルを作り直す CREATE TABLE 文が自動生成されます。他人が作ったテーブルの構造を学ぶときや、同じ構造を別のデータベースに再現したいときに役立ちます（第5章でテーブル作成を学んだ後、ぜひ試してみてください）。

4.6 sqlcmd と VS Code（MSSQL拡張機能）

SSMS は Windows 専用の GUI ツールですが、SQL Server にはコマンドラインや軽量エディタから操作する選択肢もあります。特に macOS / Linux 環境や、自動化スクリプトの中では欠かせません。

sqlcmd は、コマンドラインから T-SQL を実行できる公式ツールです。-S で接続先サーバー、-U／-P でユーザー名・パスワード、-Q で実行する SQL 文を指定します。

terminal — sqlcmd でデータベース一覧を取得 
# sqlcmdでデータベース一覧をコマンドラインから取得する
sqlcmd -S localhost -U sa -P "<パスワード>" \
  -Q "SELECT name FROM sys.databases;"

sqlcmd

CLI 専用ツール。Windows / macOS / Linux 共通で使え、シェルスクリプトへの組み込みやバッチ処理の自動実行に向く。

VS Code + MSSQL拡張機能

Windows / macOS / Linux で動く GUI エディタ。SSMS が使えない環境ではこれが標準的な選択肢になる（かつての Azure Data Studio は2026年2月にサポート終了）。

本ガイドの説明は SSMS を基準に進めますが、これから学ぶクエリはどのツールでも同じように実行できます。GUI に慣れてきたら、sqlcmd もあわせて触れておくと、サーバーに直接ログインして作業する場面でも困りません。

4.7 PostgreSQLとの違い

日常操作の「型」は PostgreSQL とかなり異なります。PostgreSQL の標準ツールは CLI の psql であり、GUI が最初から使いこなせる SQL Server とは前提が逆になっている点に注目しましょう。

PostgreSQL との違い（日々の操作）

観点 SQL Server PostgreSQL
標準ツール SSMS（高機能な GUI が標準） psql（CLI）が標準。GUI は pgAdmin
データベース一覧の確認 オブジェクトエクスプローラー、または SELECT * FROM sys.databases psql のメタコマンド \l
テーブル一覧の確認 オブジェクトエクスプローラー、または SELECT * FROM sys.tables メタコマンド \dt
テーブル定義の確認 テーブルのプロパティ画面、またはストアドプロシージャ sp_help 'テーブル名' メタコマンド \d テーブル名
バッチ区切り GO が必要な場面がある（クライアント側の区切り） GO に相当する概念はなく、セミコロンのみで完結
データベースの切り替え USE データベース名; で同じ接続のまま切り替え メタコマンド \c データベース名 で再接続し直す
結果の既定表示 GUI のグリッド（列幅調整・ソートが可能） CLI のテキスト表（罫線付きの整形テキスト）

特に注意したいのはデータベース切り替えです。SQL Server の USE は接続を保ったまま対象を変えるだけですが、PostgreSQL の \c は文字どおり別のデータベースへ接続をやり直す操作です。この違いは第2章で学んだ「PostgreSQL は1接続につき1データベースしか見えない」という構造に由来します。

やってみよう 4-1: システムデータベースを調べてCSVに保存する

SSMS の基本操作を一通り体験するミニ演習です。オブジェクトエクスプローラーとクエリエディタの両方を使います。

手順

  1. 1 SSMS を起動し、第3章で構築したインスタンスに接続する。
  2. 2 オブジェクトエクスプローラーで「データベース」→「System Databases」を展開し、master・model・msdb・tempdb の4つがあることを目で確認する。
  3. 3 「新しいクエリ」を開き、SELECT name, database_id, create_date FROM sys.databases; を実行する（F5）。
  4. 4 結果グリッドで手順2と同じ4つの既定システムDBが含まれていることを確認する。
  5. 5 結果グリッドを右クリック →「名前を付けて結果を保存」から、CSVファイルとして保存する。

ねらい: 「画面で見る（オブジェクトエクスプローラー）」と「クエリで調べる（sys.databases）」が同じ情報にたどり着くことを体感し、結果をファイルに残す一連の操作に慣れることが目的です。

理解度確認クイズ

  1. Q1. SSMS の「結果グリッド」と「メッセージタブ」は、それぞれ何を表示する場所ですか。

    回答を表示

    結果グリッドは SELECT 文で取得したデータを表形式で表示する場所です。メッセージタブは、影響を受けた行数や実行時間、エラーメッセージなど、データそのものではない実行結果の情報を表示する場所です。

  2. Q2. GO はどのような役割を持ちますか。セミコロンとの違いを踏まえて説明してください。

    回答を表示

    セミコロンは1つのステートメント（命令文）の終わりを示す T-SQL 構文の一部です。一方 GO は T-SQL の構文ではなく、SSMS や sqlcmd がスクリプトを「バッチ」単位に区切ってサーバーへ送るための、クライアント側の合図です。データベースの作成直後に切り替える場合など、バッチをまたぐ必要がある処理で使います。

  3. Q3. SQL Server の USE 文と、PostgreSQL の psql メタコマンド \c は、どちらもデータベースを切り替える操作ですが、動作にどのような違いがありますか。

    回答を表示

    SQL Server の USE は同じ接続を保ったまま対象データベースを変更するだけです。一方 PostgreSQL の \c は、別のデータベースへ改めて接続をやり直す操作になります。これは PostgreSQL では1つの接続が1つのデータベースしか見られない構造になっているためです。
