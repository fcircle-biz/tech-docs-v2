T-SQLプログラミング入門

これまでの章では「1回きりのSELECT文」を書いてきました。この章では、変数・条件分岐・繰り返し・エラー処理といったプログラミング的な書き方を SQL Server の T-SQL でどう実現するかを学びます。さらに、処理をひとまとめにして再利用できるストアドプロシージャやユーザー定義関数、ビューまで、学習用DB SampleShop（Customers / Products / Orders）を題材に体験します。

この章で学ぶこと

  • T-SQL が標準SQLに何を足した言語なのかを説明できる
  • 変数・バッチ（GO区切り）・条件分岐・繰り返しを使ってT-SQLを書ける
  • TRY...CATCHでエラーを捕まえ、内容を確認できる
  • ストアドプロシージャ・ユーザー定義関数・ビューを作成して実行できる
  • T-SQLとPostgreSQLのPL/pgSQLの構造上の違いを説明できる

9.1 T-SQL とは

第1章で触れたとおり、SQL Server が使う SQL は T-SQL（Transact-SQL）という Microsoft の拡張方言です。第6〜8章までで使ってきた SELECT / WHERE / JOIN などは「宣言型」の標準SQLそのものですが、T-SQL はそこに変数・IF・WHILE・TRY...CATCH といった「手続き型」のプログラミング機能を足しています。

どんな場面で使うのでしょうか。代表的なのは次の2つです。

  • 複数のSQL文をまとめて実行し、条件によって処理を分ける「定型処理」（例: 月末に注文件数を集計してログに残す）
  • アプリケーション側ではなくデータベース側に業務ロジックを実装する（例: 「在庫が0未満にならないようにする」チェックをDB側で行う）

用語: 標準SQL と T-SQL

標準SQL（ANSI SQL）は「どんなRDBMSでもだいたい共通で使える」構文の集合です。T-SQL はその標準SQLに Microsoft 独自の関数・構文・手続き型機能を追加したものです。PostgreSQL にも同様の拡張として PL/pgSQL があり、この章の最後（9.7）で対比します。

9.2 変数とバッチ

T-SQL の変数は DECLARE @変数名 型 で宣言します。先頭に @ を付けるのが決まりです。値の代入には SET または SELECT を使います。

variable_basic.sql 
-- 変数の宣言と SET による代入
DECLARE @customerName NVARCHAR(50);
SET @customerName = N'鈴木商事';

-- SELECT でも代入できる（集計結果を1つの変数に入れるときに便利）
DECLARE @orderCount INT;
SELECT @orderCount = COUNT(*)
FROM Orders
WHERE CustomerId = 1;

SELECT @customerName AS 顧客名, @orderCount AS 注文件数;

もう1つ重要なのが GO です。GO は T-SQL の命令ではなく、SSMS や sqlcmd といったクライアントツールに「ここまでを1つのバッチとして送信して」と伝える区切りです。そして変数のスコープ（有効範囲）はバッチ内に閉じます。GO をまたぐと、それまで宣言した変数は消えてしまいます。

batch_scope.sql 
DECLARE @customerName NVARCHAR(50) = N'鈴木商事';
SELECT @customerName AS 顧客名;   -- ここまでは正常に動く
GO
-- ↑ここでバッチが区切られ、@customerName は破棄される

SELECT @customerName;  -- エラー: 変数 '@customerName' を宣言してください。

注意: GOの前後で変数は共有できない

SSMSのクエリウィンドウに何行も書いていると、離れた場所の GO の存在を見落としがちです。「宣言したはずの変数が見つからない」エラーが出たら、まず途中に GO が挟まっていないかを確認しましょう。

9.3 条件分岐と繰り返し

条件分岐は IF / ELSE で書きます。複数文をまとめるときは BEGIN...END で囲みます（他の言語の { } にあたります）。

if_else.sql 
DECLARE @stock INT = 5;

IF @stock < 10
BEGIN
    PRINT N'在庫が少なくなっています';
END
ELSE
BEGIN
    PRINT N'在庫は十分です';
END

繰り返しは WHILE です。ループの途中で抜けるには BREAK、その回だけスキップして次のループに進むには CONTINUE を使います。

while_loop.sql 
DECLARE @i INT = 0;
WHILE @i < 10
BEGIN
    SET @i = @i + 1;

    IF @i = 4
        CONTINUE;      -- 4のときだけ処理を飛ばして次のループへ

    IF @i > 6
        BREAK;         -- 6を超えたらループを抜ける

    PRINT CAST(@i AS NVARCHAR(5));
END

ヒント: カーソルは基本使わない

T-SQLには表の行を1行ずつ処理するカーソルという機能もありますが、初心者のうちは基本的に使いません。「1行ずつループで処理したい」と思ったときほど、実は SELECT や UPDATE の集合操作（第6〜8章の書き方）でまとめて処理できることが多く、そちらの方が高速です。

9.4 エラー処理

T-SQLでは TRY...CATCH でエラーを捕まえます。BEGIN TRY 〜 END TRY の中でエラーが起きると、続きは実行されずに BEGIN CATCH 〜 END CATCH にジャンプします。エラーの内容は ERROR_NUMBER()（エラー番号）や ERROR_MESSAGE()（メッセージ本文）といった組み込み関数で取得できます。

try_catch.sql 
BEGIN TRY
    -- わざと 0 で割ってエラーを発生させる
    SELECT 1 / 0 AS Result;
END TRY
BEGIN CATCH
    PRINT N'エラー番号: ' + CAST(ERROR_NUMBER() AS NVARCHAR(10));
    PRINT N'エラー内容: ' + ERROR_MESSAGE();
END CATCH

自分でエラーを発生させたい場合は THROW を使います。ストアドプロシージャの入力チェックなどでよく使われます。

throw_example.sql 
DECLARE @CustomerId INT = 9999;

BEGIN TRY
    IF NOT EXISTS (SELECT 1 FROM Customers WHERE CustomerId = @CustomerId)
        THROW 50001, N'指定した顧客が見つかりません。', 1;
END TRY
BEGIN CATCH
    PRINT N'処理を中断しました: ' + ERROR_MESSAGE();
END CATCH

重要ポイント

実務では TRY...CATCH をトランザクション（BEGIN TRAN / COMMIT / ROLLBACK）と組み合わせ、「エラーが起きたら更新を全部取り消す」という形でよく使います。この組み合わせは次の第10章で詳しく扱います。

9.5 ストアドプロシージャ

ストアドプロシージャは、複数のT-SQL文をひとまとまりの「部品」としてデータベースに保存しておき、名前を指定して呼び出せるようにしたものです。CREATE PROCEDURE（既存を変更するときは ALTER PROCEDURE、両方をまとめて安全に使える CREATE OR ALTER PROCEDURE が便利）で作成し、EXEC で実行します。

usp_GetCustomerOrderCount.sql 
CREATE OR ALTER PROCEDURE usp_GetCustomerOrderCount
    @CustomerId INT,
    @OrderCount INT OUTPUT      -- 結果を呼び出し元へ返す出力パラメータ
AS
BEGIN
    SELECT @OrderCount = COUNT(*)
    FROM Orders
    WHERE CustomerId = @CustomerId;
END
GO

DECLARE @cnt INT;
EXEC usp_GetCustomerOrderCount @CustomerId = 1, @OrderCount = @cnt OUTPUT;
PRINT N'注文件数: ' + CAST(@cnt AS NVARCHAR(10));

パラメータには既定値を設定できます。既定値があると、呼び出し側は値を省略できます。

usp_ListRecentOrders.sql 
CREATE OR ALTER PROCEDURE usp_ListRecentOrders
    @Days INT = 30              -- 既定値。省略時は過去30日分
AS
BEGIN
    SELECT OrderId, CustomerId, OrderDate
    FROM Orders
    WHERE OrderDate >= DATEADD(DAY, -@Days, GETDATE());
END
GO

EXEC usp_ListRecentOrders;            -- 既定値(30日)を使用
EXEC usp_ListRecentOrders @Days = 7;  -- 過去7日分を指定

再利用できる

同じ処理をアプリの複数箇所や複数のツールから呼び出せます。

権限管理がしやすい

テーブルへの直接アクセスを許可せず、プロシージャ経由だけ許可することができます。

通信回数を減らせる

複数のSQL文を1回の呼び出しにまとめられ、アプリとDB間のネットワーク往復が減ります。

9.6 ユーザー定義関数とビュー

ユーザー定義関数（UDF）には大きく2種類あります。スカラー関数は値を1つだけ返す関数、テーブル値関数は表（複数行・複数列）を返す関数です。プロシージャと違い、SELECT 文の中で呼び出せるのが特徴です。

ufn_GetCustomerRank.sql 
-- スカラー関数: 値を1つ返す
CREATE OR ALTER FUNCTION dbo.ufn_GetCustomerRank(@CustomerId INT)
RETURNS NVARCHAR(10)
AS
BEGIN
    DECLARE @totalAmount DECIMAL(12,2);
    SELECT @totalAmount = SUM(o.Quantity * p.UnitPrice)
    FROM Orders o
    JOIN Products p ON p.ProductId = o.ProductId
    WHERE o.CustomerId = @CustomerId;

    RETURN CASE WHEN @totalAmount >= 100000 THEN N'優良顧客' ELSE N'一般' END;
END
ufn_OrdersByCustomer.sql 
-- テーブル値関数: 表を返し、SELECTの対象として使える
CREATE OR ALTER FUNCTION dbo.ufn_OrdersByCustomer(@CustomerId INT)
RETURNS TABLE
AS
RETURN (
    SELECT OrderId, ProductId, Quantity, OrderDate
    FROM Orders
    WHERE CustomerId = @CustomerId
);
GO

SELECT * FROM dbo.ufn_OrdersByCustomer(1);

ビューは「よく使うSELECT文に名前を付けて保存したもの」です。テーブルのように SELECT できますが、実データは持たず、参照するたびに元のテーブルへ問い合わせます。

vw_CustomerOrderSummary.sql 
CREATE OR ALTER VIEW vw_CustomerOrderSummary
AS
SELECT c.CustomerId, c.CustomerName, COUNT(o.OrderId) AS OrderCount
FROM Customers c
LEFT JOIN Orders o ON o.CustomerId = c.CustomerId
GROUP BY c.CustomerId, c.CustomerName;
GO

SELECT * FROM vw_CustomerOrderSummary WHERE OrderCount > 0;

注意: WHERE の列側で関数を使わない

WHERE dbo.ufn_GetCustomerRank(CustomerId) = N'優良顧客' のように、列の側にユーザー定義関数を適用すると、SQL Server はインデックスを使えず全行をスキャンしてしまい、遅くなります。この「インデックスが効く書き方」については第11章で詳しく扱います。

9.7 PostgreSQLとの違い

T-SQL と PostgreSQL の PL/pgSQL は、どちらも「標準SQLに手続き型機能を足したもの」ですが、手続きをどこに書けるかという構造がはっきり異なります。

PostgreSQL との違い（T-SQL プログラミング）

観点 SQL Server（T-SQL） PostgreSQL（PL/pgSQL）
手続きの書き場所 バッチにIF/WHILEをそのまま書ける DO $$ ... $$ ブロックか、関数／プロシージャの中でのみ
変数宣言 DECLARE @x INT;（バッチ中どこでも） DECLARE x int;（先頭のDECLAREセクションのみ）
変数の接頭辞 @ を付ける（@x） 接頭辞なし（x）
プロシージャ本体 AS BEGIN ... END 本体全体を $$ ... $$ で囲む
実行方法 EXEC usp_Xxx CALL proc_xxx()
エラー処理 TRY...CATCH ＋ ERROR_MESSAGE() EXCEPTION WHEN ... THEN ブロック
結果セットを返す SELECT の実行結果がそのまま返る 関数なら RETURNS TABLE、プロシージャなら REFCURSOR 等が必要
文字列連結 + 演算子 || 演算子
NULLの既定値 ISNULL(x, 既定値) COALESCE(x, 既定値)（ANSI標準。SQL Serverでも使用可）

いちばんの違いは「バッチにそのままIF/WHILEを書けるか」です。T-SQLはバッチ全体が手続き型のキャンバスですが、PostgreSQLは関数やプロシージャの中だけが手続き型のキャンバスという考え方の違いだと捉えると整理しやすくなります。

ヒント: EXECとCALLを混同しない

PostgreSQLに慣れている方が最初につまずきやすいのが、この EXEC と CALL の違いです。SQL Serverで CALL usp_Xxx() と書いてもエラーになります。「SQL Serverは EXEC、PostgreSQLは CALL」とセットで覚えておきましょう。

やってみよう 9-1: 顧客の注文件数を返すストアドプロシージャを作る

SampleShop の Customers / Orders を使い、顧客IDを渡すとその顧客の注文件数を返すストアドプロシージャを自分で作成し、実行してみましょう。

手順

  1. 1 SSMS で SampleShop データベースに接続する（第4章の操作を思い出しましょう）。
  2. 2 @CustomerId INT を入力パラメータ、@OrderCount INT OUTPUT を出力パラメータとする usp_GetCustomerOrderCount プロシージャを CREATE OR ALTER PROCEDURE で作成する。
  3. 3 本体では Orders テーブルを WHERE CustomerId = @CustomerId で絞り込み、件数を @OrderCount に代入する。
  4. 4 実在する顧客ID（例: 1）で EXEC usp_GetCustomerOrderCount @CustomerId = 1, @OrderCount = @cnt OUTPUT; のように実行し、PRINT で結果を確認する。
  5. 5 余裕があれば、存在しない顧客IDを渡したときに THROW でエラーメッセージを返すよう改造してみる。

ねらい: 「入力パラメータを受け取り、OUTPUTパラメータで結果を返す」という、業務システムで最もよく使われるストアドプロシージャの型を手を動かして身につけることが目的です。

理解度確認クイズ

  1. Q1. T-SQLとは何ですか。標準SQLとの関係を含めて説明してください。

    回答を表示

    T-SQL（Transact-SQL）は、標準SQLに変数・IF・WHILE・TRY...CATCHなどの手続き型プログラミング機能を加えた、Microsoft独自のSQL方言です。SELECTなど宣言型の部分は標準SQLと共通ですが、手続き型の書き方はT-SQL独自のものです。

  2. Q2. ストアドプロシージャの OUTPUT パラメータは何のために使いますか。

    回答を表示

    プロシージャ内で計算した値を呼び出し元に返すために使います。パラメータ定義に OUTPUT を付け、呼び出し側も EXEC の引数に変数を渡して OUTPUT を指定することで、実行後にその変数へ結果が反映されます。

  3. Q3. ストアドプロシージャの実行構文と、手続きを書ける場所について、SQL ServerとPostgreSQLの違いを説明してください。

    回答を表示

    実行構文はSQL Serverが EXEC、PostgreSQLが CALL です。構造の違いとして、T-SQLはバッチにそのままIF/WHILEなどの手続きを書けますが、PostgreSQL（PL/pgSQL）は DO $$ ... $$ ブロックか、関数・プロシージャの本体（$$ ... $$ で囲む）の中でしか手続きを書けません。
