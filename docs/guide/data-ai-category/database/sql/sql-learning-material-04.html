ツールの基本操作とSQLの書き方

前章でインストールした pgAdmin 4 と A5:SQL Mk-2 を、実際に手を動かして操作します。この章ではまだテーブルは作りません。「SQLを入力して実行し、結果を見る」という一連の型を体に入れることが目的です。あわせて、SQL文の基本的な書き方のルールと、エラーメッセージの読み方も身につけます。

この章の学習目標

  • pgAdmin 4 のクエリツールを開き、SQLを実行して結果を確認できる
  • A5:SQL Mk-2 のSQLエディタを開き、SQLを実行して結果を確認できる
  • SQL文の基本ルール（大文字小文字・セミコロン・コメント・文字列）を説明できる
  • エラーメッセージを読んで、何が間違っているかの見当をつけられる

4.1 pgAdmin 4 の画面構成

pgAdmin 4 を起動すると、画面の左側にブラウザツリーというツリー構造の一覧が表示されます。これは「サーバーの中に何が入っているか」を階層的に表した地図です。前章で作成した接続をたどると、次のような並びになります。 

Servers
└── PostgreSQL 17
    └── Databases
        └── postgres
            └── Schemas
                └── public
                    └── Tables（まだ何も無い）

この章ではまだテーブルを作っていないので、Tables の下は空です。第5章で CREATE TABLE を実行すると、ここに表が増えていきます。まずは SQL を入力して実行する画面（クエリツール）を開きましょう。

クエリツールの開き方

ブラウザツリーで対象のデータベース（ここでは postgres）を左クリックで選択し、右クリックメニューから「Query Tool」を選びます。ツールバーのアイコンからも同じ画面を開けます。どのデータベースを選んだ状態で開いたかによって、SQLが実行される先が変わる点に注意してください。

クエリツールが開くと、画面が上下に分かれます。上側のSQL入力欄にSQLを書き、F5 キーまたはツールバーの▶（実行）ボタンを押すと実行されます。結果は下側に表示されます。

flowchart LR A["SQL入力欄にSQLを書く"] --> B["F5 または ▶ボタンで実行"] B --> C{"エラーなく実行できた？"} C -->|はい| D["Data Output タブに
結果の表が表示される"] C -->|いいえ| E["Messages タブに
エラー内容が表示される"]

下側にはいくつかタブがありますが、まず覚えるべきは次の2つです。

タブ名 表示される内容
Data Output SELECT の実行結果が表形式（結果グリッド）で表示される。行数・列名もここで確認できる
Messages 実行の成否・処理件数・実行時間（例: Query returned successfully in 12 msec.）や、エラー発生時の詳細メッセージが表示される

実行時間が表示されるのは地味に見えて重要です。今は数ミリ秒で終わる小さなSQLしか書きませんが、第9章以降で集計処理を扱うころには「速いSQLと遅いSQLの違い」を意識する材料になります。

4.2 A5:SQL Mk-2 の画面構成

A5:SQL Mk-2 も基本の考え方は同じです。起動して前章で設定した接続を開くと、左側にデータベースツリーが表示されます。pgAdmin 4 ほど階層は深くなく、シンプルに一覧できるのが特徴です。 

postgres（接続名）
└── public（スキーマ）
    └── テーブル（まだ何も無い）

SQLを書く画面はSQLエディタと呼ばれます。ツールバーの「SQL実行」アイコン、またはメニューから開けます。実行方法は pgAdmin 4 と同じくF5 キーです。加えて、A5:SQL Mk-2 には次のような便利な操作があります。

操作 キー・手順 用途
全文を実行 F5 エディタに書かれているSQLをすべて実行する
選択範囲だけ実行 実行したい文をマウスで選択してから「選択実行」（Ctrl+F5相当） 複数のSQLを1つのエディタに並べて書き、その一部だけを試したいときに使う
テーブルのデータを見る データベースツリーでテーブルを右クリック →「データを表示」 SELECT * FROM 表名; を自分で書かなくても中身を確認できる

「選択範囲だけ実行」は、慣れると非常によく使う操作です。第5章以降、1つのエディタに複数のSQL文を書きためて、そのつど気になる1文だけを選んで試す、という使い方をしていきます。

結果グリッドの見方はほぼ同じ

A5:SQL Mk-2 でも、実行結果は下側（または別タブ）の結果グリッドに表形式で表示されます。列名・行数・実行時間の見え方は pgAdmin 4 と多少レイアウトが異なりますが、「表で結果が返ってくる」という本質は同じです。

4.3 2つのツールの使い分け

第1章でも触れたとおり、実務では2つのツールを場面によって使い分けるのが一般的です。ここで改めて指針を整理しておきます。

やりたいこと 向いているツール 理由
サーバー全体の管理・設定確認 pgAdmin 4 PostgreSQL公式ツールで、サーバーの全機能に対応している
バックアップ・復元 pgAdmin 4 GUIから pg_dump 相当の操作ができる（第14章）
SQLを大量に書いて試す A5:SQL Mk-2 起動が速く動作が軽い。選択範囲実行で細かく試せる
テーブルの中身をさっと見る A5:SQL Mk-2 右クリック1つで「データを表示」できる

重要: どちらのツールでも本ガイドは完結します

上記はあくまで実務での目安です。本ガイドの第5章以降の学習は、pgAdmin 4だけでも、A5:SQL Mk-2だけでも、両方を併用しても、問題なく進められます。大事なのは「同じSQLを同じデータベースに送れば、返ってくるデータは同じ」という第1章で学んだ原則です（処理しているのはどちらのツールの背後にあるPostgreSQL本体だからです）。ただし、結果の表示書式や列幅、NULLの表示のしかたなどはツールによって多少異なります。自分が使いやすいと感じたほうを主軸にして構いません。

4.4 SQL文の書き方の基本ルール

SQLを実際に書き始める前に、文法以前の「お作法」を押さえておきましょう。ここを知らないと、些細な書き間違いで戸惑うことになります。

(a) キーワードの大文字・小文字は区別されない

SELECT と書いても select と書いても、PostgreSQLにとっては同じ意味です。これは SELECT / FROM / WHERE のようなSQLのキーワード（命令語）、およびクォートで囲まないテーブル名・列名について言えることです。PostgreSQLはクォートなしの識別子を内部的に小文字へ変換して扱うため、結果として大文字・小文字を区別しません（この折りたたみの挙動は製品によって異なります）。世界的な慣習として、キーワードは大文字、テーブル名や列名は小文字で書くのが読みやすいとされており、本ガイドもこの慣習に従います。

注意： 大文字・小文字が区別されないのは、キーワードと（クォートなしの）テーブル名・列名だけです。'東京都' のような文字列（値そのもの）や、"customerName" のようにダブルクォートで囲んだ識別子は、書かれた文字がそのまま比較されます。英字の文字列であれば 'Tokyo' と 'tokyo' は別の値として扱われますし、WHERE prefecture = 'とうきょうと' のようにひらがなで書いても、データが '東京都'（漢字）である限り一致しません。

case-example.sql 
-- どちらも同じ意味として実行できる
select customer_name from customers;
SELECT customer_name FROM customers;

-- 本ガイドで採用する書き方（キーワード大文字・名前は小文字）
SELECT customer_name FROM customers;

(b) 文の終わりはセミコロン

1つのSQL文の終わりには;（セミコロン）を付けます。1つのエディタに複数の文を書く場合、セミコロンが「ここで1文終わり」の目印になります。

(c) 空白・改行・インデントは自由

SQLは1行にまとめて書いても、単語ごとに改行しても、意味は変わりません。読みやすさのために、句（SELECT / FROM / WHERE など）ごとに改行してそろえるのが一般的です。

format-example.sql 
-- Before: 1行にまとめて書いても実行はできるが読みにくい
SELECT customer_name, prefecture FROM customers WHERE prefecture = '東京都';

-- After: 句ごとに改行すると、後から見返したときに読みやすい
SELECT customer_name, prefecture
FROM customers
WHERE prefecture = '東京都';

(d) コメントの書き方

SQLの実行に影響しないメモを残すには、コメントを使います。-- はその行の終わりまで、/* */ は複数行をまとめてコメントにできます。

comment-example.sql 
-- 1行コメント: この行はここから行末まで無視される
SELECT customer_name  -- 氏名だけ取り出す
FROM customers;

/*
  複数行コメント。
  動作確認用に一時的にSQLを無効化したいときにも便利。
*/
SELECT 1;

(e) 文字列はシングルクォート

'東京都' のように、文字列（テキストのデータ）はシングルクォート（'）で囲みます。ダブルクォート（"）は文字列ではなく、テーブル名や列名などの「識別子」を囲むために使われ、囲むと大文字・小文字が区別されるようになる特殊な意味を持ちます。初心者のうちはダブルクォートを使わず、文字列は必ずシングルクォートで書くと覚えておけば十分です。

注意: 全角スペースはエラーの原因になる

日本語入力モードのまま単語の区切りにスペースを入れると、見た目では区別できない全角スペース（　）が紛れ込むことがあります。SQLは全角スペースを単語の区切りとして認識できず、syntax error（構文エラー）になります。実行して原因不明のエラーが出たときは、まず日本語入力をオフにして単語間のスペースを一度打ち直してみてください。

4.5 エラーメッセージの読み方

SQLを学び始めると、エラーは避けて通れません。むしろエラーメッセージは「どこが間違っているか」を教えてくれる味方です。怖がらずに読み解く練習をしておきましょう。ここでは、わざと間違えたSQLを実行してみます。

まずは、命令語のつづりを間違えた例です。

error-example-1.sql 
-- SELECT のつづりをわざと間違えている
SELCT 1;

これを実行すると、Messages タブに次のようなメッセージが表示されます。

Messages 
ERROR:  syntax error at or near "SELCT"
LINE 1: SELCT 1;
        ^

読み解き方は次のとおりです。1行目の ERROR: syntax error at or near "SELCT" は「"SELCT" の付近で構文エラー」という意味、つまり PostgreSQL が知らない単語に出会って読めなくなったことを表します。2行目の LINE 1: は「何行目で起きたか」、その下の ^（キャレット）はだいたいの位置を指しています。

次に、存在しないテーブルを指定した例です。

error-example-2.sql 
-- nothing という名前のテーブルはまだ作っていない
SELECT * FROM nothing;
Messages 
ERROR:  relation "nothing" does not exist
LINE 1: SELECT * FROM nothing;
                      ^

今度は綴りの問題ではなく、relation "nothing" does not exist（nothing という relation は存在しない）というメッセージです。PostgreSQLではテーブルやビューをまとめて relation（リレーション）と呼びます。つまり「文法は正しいが、そのテーブルが無い」というエラーです。

メッセージの一部 意味
syntax error at or near "..." その単語の綴りやSQLの書き方そのものが間違っている（つづり間違い・カンマ忘れ・括弧の閉じ忘れなど）
relation "..." does not exist テーブル名・ビュー名の指定が間違っている、またはそのテーブルがまだ作られていない
column "..." does not exist 列名の指定が間違っている（第6章以降でよく遭遇する）

ヒント: エラーは怖くない

プロのエンジニアでも、エラーを一度も出さずにSQLを書くことはまずありません。大切なのは「ERROR: の後ろの一文」と「LINE の行番号」を落ち着いて読む習慣です。この章のうちに、エラーを見ても手が止まらないようにしておきましょう。

4.6 まず動かしてみる

テーブルが無くても実行できるSQLで、実行の型を練習しましょう。次のSQLを、pgAdmin 4のクエリツールまたはA5:SQL Mk-2のSQLエディタに入力し、1行ずつ選択して実行してみてください。

first-run.sql 
-- 1. PostgreSQLのバージョンを確認する
SELECT version();

-- 2. 計算結果を確認する（電卓代わりにも使える）
SELECT 1 + 2;

-- 3. 今日の日付を確認する
SELECT current_date;

-- 4. 好きな文字列を、任意の名前（別名）を付けて表示する
SELECT 'こんにちは' AS greeting;

SELECT version(); を実行すると、Data Output に導入したPostgreSQLのバージョン情報が1行1列で表示されます。SELECT 1 + 2; は計算結果の3、SELECT current_date; は今日の日付、最後のAS greeting を付けた文は「greeting」という見出しの列に文字列が1件だけ表示されます。

重要: SELECT はテーブルが無くても使える

SELECT は「テーブルから取り出す」命令として紹介しましたが、FROM を省略すれば、計算・日付取得・関数の動作確認など、テーブルに依存しない用途にも使えます。第8章で学ぶ関数の動作確認にも、この書き方をよく使います。

やってみよう 4-1: 同じSQLを2つのツールで実行して比べる

4.6で使った4つのSQLを、pgAdmin 4とA5:SQL Mk-2の両方で実行し、操作感を比べてメモに残しましょう（macOS / Linuxの方はpgAdmin 4だけで構いません）。

手順

  1. 1 pgAdmin 4でクエリツールを開き、4.6の4つのSQLを1文ずつ実行して結果を確認する。
  2. 2 A5:SQL Mk-2でSQLエディタを開き、同じ4つのSQLを1つのエディタにまとめて書き、「選択範囲を実行」で1文ずつ試す。
  3. 3 わざと SELCT 1; のように間違えたSQLも両方のツールで実行し、エラーメッセージの見え方（表示される場所・色・書式）の違いをメモする。
  4. 4 「結果が表示されるまでの体感速度」「画面のどこに目が行きやすいか」「自分はどちらが使いやすいと感じたか」を一言ずつ書き留める。

ねらい: 「同じSQLを同じデータベースに送れば、返ってくるデータは同じ（ただし表示の書式や列幅などは多少異なる）」ことを自分の手で確認し、次章以降どちらのツールを使っても迷わないようにするのが目的です。ここで感じた使いやすさで、以降の章の主軸ツールを決めて構いません。

理解度確認クイズ

  1. Q1. pgAdmin 4のクエリツールでSQLを実行したとき、「結果の表」と「実行時間やエラー」はそれぞれどのタブに表示されますか。

    回答を表示

    結果の表（SELECTの実行結果）は Data Output タブ、実行の成否・処理件数・実行時間やエラーメッセージは Messages タブに表示されます。

  2. Q2. select customer_name from customers; のようにすべて小文字で書いたSQLは正しく実行できますか。また、本ガイドではどのような書き方を推奨していますか。

    回答を表示

    実行できます。SQLのキーワードは大文字・小文字を区別しないためです。ただし読みやすさの慣習として、キーワードは大文字、テーブル名・列名は小文字で書くことを推奨しています。

  3. Q3. SELECT * FROM nothing; を実行すると relation "nothing" does not exist というエラーが出ました。これは何が原因だと考えられますか。

    回答を表示

    SQLの書き方（文法）自体は正しいものの、nothing という名前のテーブル（PostgreSQLでは relation と呼ぶ）が存在しないことが原因です。テーブル名の綴り間違い、または対象のテーブルをまだ作成していないことが考えられます。

  4. Q4. SQLを日本語入力モードのまま書いていたら原因不明の構文エラーになりました。まず疑うべき点は何ですか。

    回答を表示

    単語の区切りに全角スペースが紛れ込んでいないかを疑うべきです。全角スペースは見た目では半角スペースと区別しにくいですが、SQLの区切り文字としては認識されず syntax error の原因になります。日本語入力をオフにして、該当箇所のスペースを打ち直すことで解決できます。
