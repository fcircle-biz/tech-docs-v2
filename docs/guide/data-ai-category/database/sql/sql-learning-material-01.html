データベースとSQLの世界

SQL（エスキューエル）は、データベースに「こんなデータが欲しい」「このデータを書き換えて」と指示を出すための言語です。この章では「そもそもデータベースとは何か」という出発点から、SQL の役割、本ガイドで使う PostgreSQL・pgAdmin・A5:SQL Mk-2 という3つの道具の関係まで、全体像をつかみます。プログラミングの経験はまったく不要です。

この章の学習目標

  • データベース・DBMS・RDBMS という言葉の関係を説明できる
  • SQL が「データベースに指示を出す言語」であることを理解する
  • 代表的な RDBMS を知り、PostgreSQL の特徴を大づかみに言える
  • PostgreSQL・pgAdmin 4・A5:SQL Mk-2 それぞれの役割の違いが分かる

1.1 データベースとは何か

データベースとは、ひとことで言えば「たくさんのデータを整理して貯めておき、必要なときにすばやく取り出せるようにした保管庫」です。難しそうな響きですが、私たちは毎日その恩恵を受けています。コンビニのレジで商品のバーコードを読むと値段が出てくるのも、通販サイトで「注文履歴」を開くと過去の買い物が並ぶのも、その裏側にデータベースがあるからです。

では、そのデータはどんな形で貯まっているのでしょうか。答えは、みなさんが Excel で見慣れている「表」とほとんど同じ形です。たとえば通販サイトの顧客情報なら、次のような表になります。

顧客番号 氏名 都道府県 登録日
1 佐藤 花子 東京都 2024-04-01
2 鈴木 一郎 大阪府 2024-04-15
3 田中 美咲 北海道 2024-05-02

見た目は Excel のシートそのものです。それなら「Excel でいいのでは？」と思うのが自然でしょう。実際、少量のデータを1人で扱うだけなら Excel は十分に優秀です。しかし、大量のデータを、たくさんの人が同時に、安全に扱うという場面になると、事情が変わってきます。

観点 Excel などの表計算 データベース（RDBMS）
大量データの扱い 数万行くらいから、開くのも集計するのも重くなりやすいことが多い 数百万〜数億行のような規模になっても、必要な行だけを高速に取り出せる仕組みを持つ
複数人での同時更新 共同編集はできるが、多人数が同じ行を頻繁に書き換える用途には向かない 何百人規模が同時に読み書きしても、データの整合性が保たれるよう設計されている
処理をまとめて確定する仕組み 「複数の変更をまとめて確定／まとめて取り消し」する機能はない トランザクションとして扱い、途中で失敗すれば全体を取り消せる（第13章）
データの正しさの保証 数値欄に文字を入れてもそのまま保存できてしまうことが多い 型や制約を決めておけば、おかしなデータの登録を最初から拒否できる（第5章）
障害からの復旧 ファイルが壊れると復旧が難しい。誰がいつ壊したかも追いにくい バックアップとログを組み合わせて、特定の時点まで戻す手段がある（第14章）

補足： 上表の行数や人数はあくまで目安です。実際に快適に扱える範囲は、データ量だけでなくハードウェアの性能、SQL の書き方、インデックスの有無、テーブル設計などによって大きく変わります。

つまり Excel が劣っているのではなく、役割が違うということです。そして、こうした「大量・同時・安全」を実現するために作られた専用のソフトウェアを DBMS（データベース管理システム）と呼びます。さらにその中でも、上の例のようにデータを表の形で管理し、表と表を関係づけて扱うタイプを RDBMS（リレーショナルデータベース管理システム）と呼びます。本ガイドで学ぶ PostgreSQL は、この RDBMS の代表格のひとつです。

用語の整理: データベース／DBMS／RDBMS

データベースは「貯めてあるデータそのもの」、DBMSは「そのデータを管理するソフト」です。図書館にたとえるなら、蔵書がデータベースで、司書と貸出システムが DBMS にあたります。

日常会話では DBMS のことも「データベース」と呼んでしまうことが多いので、本ガイドでもそのつもりで読み進めて構いません。厳密に区別が必要な場面では、その都度お伝えします。

1.2 SQL とは — データベースに話しかける言葉

データベースにデータが貯まっていても、「東京都に住んでいる顧客の一覧が欲しい」と念じるだけでは出てきません。欲しいものを、決められた書き方で伝える必要があります。そのための言語が SQL（Structured Query Language）です。読み方は「エスキューエル」または「シークェル」。どちらでも通じます。

SQL の最大の特徴は、「どうやって取り出すか」ではなく「何が欲しいか」を書く点にあります。ファイルを1行ずつ読んで比較して…といった手順を書く必要はありません。実際に、先ほどの顧客の表から東京都の人を取り出す SQL はこれだけです。

first-select.sql 
-- customers（顧客）テーブルから、都道府県が「東京都」の行の
-- 氏名と登録日を取り出す
SELECT customer_name, registered_at
FROM customers
WHERE prefecture = '東京都';

まだ書き方を覚える必要はありません。ここで感じてほしいのは、ほとんど英語の文章のまま読めるということです。「SELECT（選ぶ）氏名と登録日を、FROM（〜から）customers を、WHERE（〜という条件で）都道府県が東京都」。これが SQL が長年使われ続けている理由のひとつです。

SQL の命令は、役割によって大きく4つのグループに分けられます。全部を今すぐ覚える必要はありませんが、「SQL にはこういう種類がある」と地図を持っておくと、以降の章で迷いにくくなります。

分類 役割 代表的な命令 学ぶ章
DDL
データ定義		 入れ物（データベース・テーブル）そのものを作る・変える・消す CREATE / ALTER / DROP 第5章
DML
データ操作		 中身のデータを取り出す・入れる・書き換える・消す SELECT / INSERT / UPDATE / DELETE 第6〜12章
TCL
トランザクション制御		 複数の変更をまとめて確定する・まとめて取り消す BEGIN / COMMIT / ROLLBACK 第13章
DCL
データ制御		 誰にどの操作を許すかという権限を管理する GRANT / REVOKE 第14章

本ガイドで最も時間をかけるのは DML の SELECT です。実務でも、書く SQL の大半は「データを取り出す」ためのものだからです。

重要: SQL は「一度覚えれば長く使える」技術

SQL は 1970年代に考案され、1986年に ANSI（米国規格協会）、翌1987年に ISO（国際標準化機構）で規格化されて以来、半世紀近く現役です。プログラミング言語やフレームワークの流行が入れ替わっても、業務システムの裏側ではほぼ必ず SQL が動いています。ここで学ぶ基本構文の多くは、PostgreSQL 以外の MySQL・Oracle・SQL Server でも共通して通用します。ただし、関数・データ型・DDL（テーブル定義の構文）などには製品ごとの差があるため、他製品で SQL を書く際はその違いを確認する習慣が大切です。

1.3 代表的な RDBMS と PostgreSQL の位置づけ

SQL は共通の言語ですが、それを受け付ける「製品」はいくつもあります。方言のように製品ごとの細かな違いはあるものの、基本文法は共通です。代表的な4製品を比べてみましょう。

製品 提供元・費用 よく使われる場面
PostgreSQL コミュニティ開発のオープンソース。ソフトウェアは無償 Web サービス、社内システム、クラウド上のアプリ。標準 SQL への準拠度が高く、学習の題材に向く
MySQL Oracle 社。無償版（コミュニティ版）あり Web サイト・CMS の定番。レンタルサーバーで採用されることが多い
Oracle Database Oracle 社の商用製品（無償の Express Edition あり） 金融・製造など大規模基幹システム。歴史が長く実績が豊富
SQL Server Microsoft の商用製品（無償の Developer / Express あり） Windows Server や .NET／C# で作られた業務システムとの組み合わせ

用語メモ：オープンソース — プログラムの設計図（ソースコード）が公開されており、誰でも無償で使用・改変できるソフトウェアの開発スタイルのことです。

本ガイドが PostgreSQL を選ぶ理由は3つあります。

完全に無償で始められる

ライセンス費用も利用者数の制限もありません。自宅の PC に入れて、好きなだけ試せます。

標準 SQL に忠実

標準 SQL を広くサポートしつつ、PostgreSQL 独自の拡張機能も備えています。基本的な書き方は他の RDBMS にも応用しやすい題材です。

実務での採用が伸びている

クラウド各社がマネージドサービスを提供しており、学んだ知識が仕事に直結します。

なお、本ガイドでは教材の画面や操作手順を統一するため、PostgreSQL 17 系を使用します。インストール方法は第3章で詳しく扱います。

ヒント: 「SQL」と「PostgreSQL」は別物

SQL は言語の名前、PostgreSQL はその言語を受け付ける製品の名前です。「日本語」と「日本語で話す相手」くらい違う、と考えてください。名前が似ているので最初は混乱しがちですが、この区別ができると技術記事がぐっと読みやすくなります。

1.4 本ガイドで使う3つの道具

本ガイドでは、PostgreSQL 本体に加えて2つの操作ツールを使います。「なぜ2つも？」と思うかもしれませんが、これには理由があります。まずは、それぞれの役割の違いを押さえましょう。

flowchart LR A["あなた"] --> B["pgAdmin 4
（ブラウザ型の管理ツール）"] A --> C["A5:SQL Mk-2
（軽快なWindows用クライアント）"] B -->|SQLを送る| D["PostgreSQL
（データベース本体）"] C -->|SQLを送る| D D -->|結果の表を返す| B D -->|結果の表を返す| C D --- E[("shop_db
顧客・商品・注文のデータ")]

重要なのは、データを実際に保管して SQL を処理しているのは PostgreSQL だけという点です。pgAdmin 4 も A5:SQL Mk-2 も、SQL を送って結果を受け取り、見やすく表示する「窓口」にすぎません。ですから、どちらのツールを使っても、同じ SQL を送れば同じデータが返ってきます。ただし ORDER BY を付けていない SELECT では行の並び順が保証されないため、画面に表示される順序が違って見えることがあります。

道具 正体 得意なこと 動作環境
PostgreSQL データベース本体（サーバー） データの保管、SQL の実行、整合性の保証。普段は画面を持たず裏で動き続ける Windows / macOS / Linux
pgAdmin 4 PostgreSQL 公式の GUI 管理ツール サーバー全体の管理、設定確認、バックアップ、ER 図的な構造の閲覧。PostgreSQL の全機能に対応 Windows / macOS / Linux
A5:SQL Mk-2 日本製のフリーな SQL クライアント 起動が速く、SQL をどんどん書いて試す作業に最適。ER 図作成機能も持つ Windows のみ

2つのツールを併用する理由は、実務でもこの使い分けが一般的だからです。データベースの構造を確認したり設定を変えたりする「管理作業」には公式ツールの pgAdmin 4 が向いています。いっぽう、日々の「SQL を書いて結果を見る」という作業では、起動が速く操作が軽い A5:SQL Mk-2 のようなクライアントが好まれます。1つのツールに閉じこもらないことで、SQL そのものの力が身につきます。

ヒント: macOS / Linux をお使いの方へ

A5:SQL Mk-2 は Windows 専用ソフトです。macOS / Linux をお使いの場合は pgAdmin 4 だけで全章を学習できます。A5:SQL Mk-2 の操作手順が出てきたら、pgAdmin 4 のクエリツールで同じ SQL を実行してください。取得されるデータの内容は同じです。

第5章では、以降のすべての章で使い続ける共通のサンプルデータベース shop_db を作ります。架空のオンラインショップ「みらい商店」の顧客・商品・注文・注文明細という4つの表です。同じ題材を使い続けることで、章が進んでも「データの中身を理解し直す」手間なく、SQL の書き方そのものに集中できます。

次の第2章では、その表がどんな部品でできているのか（行・列・主キー・外部キー）と、なぜ表を分けて関係づけるのかを学びます。ここを理解しておくと、第5章でテーブルを作るときに「なぜこの形にするのか」が腑に落ちます。

やってみよう 1-1: 身の回りのデータを「表」にしてみる

まだ何もインストールしていない今の段階では、紙やメモアプリで十分です。データベース的なものの見方に慣れることが目的です。

手順

  1. 1 今日使ったサービスを3つ書き出す（例: 交通系 IC カード、通販サイト、社内の勤怠システム）。
  2. 2 それぞれについて「どんなデータが保存されていそうか」を4項目ずつ挙げる（例: 勤怠なら 社員番号・日付・出勤時刻・退勤時刻）。
  3. 3 挙げた項目を「表の見出し（列名）」として、3行ぶんの架空データを埋めた表を書いてみる。
  4. 4 その表から「1行だけを確実に指し示せる列」はどれか考えてみる（例: 社員番号＋日付）。これが第2章で学ぶ主キーの考え方です。

ねらい: データベースは特別な世界のものではなく、「表を決めて、そこにデータを貯める」ことの延長線上にある、と体感するのが目的です。ここで書いた表は、第5章でそのまま CREATE TABLE の練習題材に使えます。

理解度確認クイズ

  1. Q1. 「SQL」と「PostgreSQL」はどう違いますか？

    回答を表示

    SQL はデータベースに指示を出すための「言語」の名前、PostgreSQL はその言語を受け付ける「製品（RDBMS）」の名前です。SQL は MySQL・Oracle・SQL Server でも使われる共通の言語で、製品ごとに細かな方言の違いがあります。

  2. Q2. 「顧客名簿を Excel で管理していたが、社員50人が同時に更新するようになって困っている」という相談に対し、RDBMS を勧める理由を2つ挙げてください。

    回答を表示

    (1) 多人数が同時に読み書きしてもデータの整合性が保たれるよう設計されている。(2) 型や制約を決めておくことで、おかしなデータの登録を防げる。ほかに「データ量が増えても高速に取り出せる」「バックアップとログで特定時点まで復旧できる」なども正解です。

  3. Q3. pgAdmin 4 と A5:SQL Mk-2 で同じ SQL を実行したとき、結果は変わりますか。理由も答えてください。

    回答を表示

    取得されるデータの内容は変わりません。データを保管し SQL を実際に処理しているのは PostgreSQL 本体だからです。2つのツールはどちらも「SQL を送って結果を受け取り、見やすく表示する窓口」であり、画面の見た目や操作性が違うだけです。ただし ORDER BY を付けていない SELECT では行の並び順が保証されないため、表示される順序が異なって見えることがある点には注意してください。

  4. Q4. CREATE TABLE と SELECT は、それぞれ SQL の4分類のどれに属しますか。

    回答を表示

    CREATE TABLE は入れ物そのものを作る命令なので DDL（データ定義言語）、SELECT は中身のデータを取り出す命令なので DML（データ操作言語）です。
