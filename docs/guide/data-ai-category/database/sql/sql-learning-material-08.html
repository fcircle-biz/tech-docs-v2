関数でデータを加工する

前章までで、欲しい行を WHERE で選び出せるようになりました。この章では、取り出した値そのものを加工するための道具、関数を学びます。文字を大文字にする、金額を丸める、日付から年齢を求める、NULL を見やすい表示に置き換える——こうした「ちょっとした加工」を SQL の中で完結させられるようになります。

この章の学習目標

  • 関数の「引数」と「戻り値」という考え方を説明できる
  • 文字列・数値・日付それぞれの代表的な関数を使って値を加工できる
  • CAST や :: を使ってデータ型を変換できる
  • COALESCE と NULLIF で NULL を安全に扱える

8.1 関数とは — 値を入れると、加工された値が返ってくる装置

関数とは、ひとことで言えば「値を入れると、決まったルールで加工して返してくれる装置」です。自動販売機に似ています。硬貨（材料）を入れてボタンを押すと、飲み物（結果）が出てきますが、途中の仕組みを知らなくても使えます。SQL の関数もまったく同じで、中でどう処理されているかを知らなくても、正しい材料を渡せば正しい結果が返ってくるものとして使えます。

関数に渡す材料のことを引数（ひきすう）、返ってくる結果のことを戻り値（もどりち）と呼びます。たとえば「文字数を数える」関数 length であれば、引数は「文字数を数えたい文字列」、戻り値は「その文字数（整数）」です。

flowchart LR A["引数
（材料となる値）"] --> B["関数
（加工のルール）"] B --> C["戻り値
（加工後の値）"]

本ガイドで扱う関数は、大きく2つの種類に分かれます。この章で学ぶのは「1行につき1つの値を返す」タイプ、次の第9章で学ぶのは「複数行をまとめて1つの値にする」タイプです。今は名前だけ覚えておけば十分です。

種類 入力と出力の関係 代表例 学ぶ章
スカラ関数 1行の値を受け取り、1行につき1つの値を返す upper / round / to_char 本章（第8章）
集約関数 複数行の値をまとめて受け取り、1つの値を返す count / sum / avg 第9章

ヒント: 関数はどこにでも書ける

SELECT の列指定だけでなく、WHERE 句・ORDER BY 句など、値を書ける場所ならどこにでも関数を書けます。列名を書くつもりで関数呼び出しを書く、と考えると理解しやすくなります。

8.2 文字列関数 — 文字を数える・変換する・つなげる

まずは文字列を加工する関数です。customers（顧客）テーブルの customer_name・email を材料に見ていきましょう。

string-functions.sql 
-- 顧客名の文字数、メールアドレスの大文字変換と先頭部分を確認する
SELECT
    customer_name,
    length(customer_name) AS 文字数,
    upper(email) AS メール大文字,
    substring(email FROM 1 FOR 5) AS メール先頭5文字
FROM customers
LIMIT 3;
customer_name 文字数 メール大文字 メール先頭5文字
佐藤 花子 5 SATO.HANAKO@EXAMPLE.COM sato.
鈴木 一郎 5 SUZUKI.ICHIRO@EXAMPLE.COM suzuk
田中 美咲 5 TANAKA.MISAKI@EXAMPLE.COM tanak

よく使う文字列関数を一覧にまとめます。lower は upper の逆（小文字化）、trim は前後の余分な空白を取り除く関数です。

関数 機能 記述例 結果
length 文字数を数える length('東京都') 3
replace 文字列を置き換える replace('東京都', '都', '') 東京
trim 前後の空白を除去する trim(' 東京都 ') 東京都
lpad 左側を指定文字で埋めて桁を揃える lpad('123', 5, '0') 00123

複数の文字列を1つにつなげる方法は2通りあります。演算子 ||（縦棒2つ）と、関数 concat です。

concat.sql 
-- 氏名とメールアドレスをまとめて1つの文字列にする
SELECT customer_name || '（' || email || '）' AS 連結演算子,
       concat(customer_name, '（', email, '）') AS concat関数
FROM customers
LIMIT 2;

注意: || と concat は NULL の扱いが違う

|| は、つなげる対象のうちどれか1つでも NULL があると、結果全体が NULL になります。prefecture が NULL の顧客に customer_name || ' - ' || prefecture を実行すると、結果は空欄（NULL）になってしまいます。

concat 関数は逆にNULL を「空文字列」として無視してつなげます。NULL を含む可能性がある列を連結表示するときは、意図に応じて使い分けるか、8.6節の COALESCE と組み合わせましょう。

8.3 数値関数 — 丸める・切り捨てる・切り上げる

次は数値を加工する関数です。order_items（注文明細）テーブルの unit_price を例に、代表的な関数を比べてみましょう。

numeric-functions.sql 
-- 単価を四捨五入・切り捨て・切り上げして比較する
SELECT
    unit_price,
    round(unit_price, -2) AS 百の位で四捨五入,
    trunc(unit_price, -2) AS 百の位で切り捨て,
    ceil(unit_price / 100) * 100 AS 百の位で切り上げ
FROM order_items
LIMIT 3;
unit_price 百の位で四捨五入 百の位で切り捨て 百の位で切り上げ
2800.00 2800 2800 2800
150.00 200 100 200
980.00 1000 900 1000

round(値, 桁数) は桁数を省略すると整数に丸められ、正の桁数は小数点以下、負の桁数は整数側（十の位・百の位）を指定できます。abs（絶対値）と mod（割り算の余り）もよく使います。

abs-mod.sql 
-- 在庫数を3個入りケースに詰めたときの端数（余り）を求める
SELECT product_name, stock_quantity,
       mod(stock_quantity, 3) AS 三個入りの余り
FROM products
LIMIT 3;

注意: 整数同士の割り算は小数点以下が消える

PostgreSQL では、integer 型どうしの割り算は結果も integer になり、小数点以下が切り捨てられます。5 / 2 の結果は 2.5 ではなく 2 です。「平均を求めたのに整数になってしまう」という初心者の定番のつまずきポイントです。

回避するには、片方だけでも小数（numeric）にします。

division.sql 
SELECT 5 / 2 AS 整数の割り算;           -- 結果: 2（切り捨て）
SELECT 5.0 / 2 AS 小数で割る;           -- 結果: 2.5
SELECT CAST(5 AS numeric) / 2 AS CASTで回避; -- 結果: 2.5

8.4 日付・時刻関数 — 今日の日付から年齢や期間を求める

current_date（今日の日付）と current_timestamp（現在の日時）は、引数を必要としない関数です。実行するたびに、そのときの日時が返ります。

current-datetime.sql 
-- 今日の日付と、現在の日時（時刻まで）を確認する
SELECT current_date AS 今日, current_timestamp AS 現在日時;

customers テーブルの birth_date（生年月日）から、現在の年齢を求めてみましょう。age 関数は2つの日付の差を「◯年◯か月◯日」という期間で返し、date_part（extract でも同じ）はその期間から「年」の部分だけを取り出します。current_date を使う関数のため、下の結果イメージは2026年8月時点で実行した場合の一例です。実行するタイミングによって値は変わります。

age-example.sql 
-- 生年月日から現在までの経過期間と、年齢（年数のみ）を求める
SELECT customer_name, birth_date,
       age(current_date, birth_date) AS 経過期間,
       date_part('year', age(current_date, birth_date)) AS 年齢
FROM customers
LIMIT 3;
customer_name birth_date 経過期間 年齢
佐藤 花子 1985-04-12 41年4か月17日 41
鈴木 一郎 1990-07-23 36年1か月6日 36
田中 美咲 1988-11-02 37年9か月27日 37

同じ date_part を使うと、registered_at（会員登録日時）から「登録月」だけを取り出すこともできます。

date-part-month.sql 
-- 会員登録した「月」だけを取り出す
SELECT customer_name, registered_at,
       date_part('month', registered_at) AS 登録月
FROM customers
LIMIT 3;

日付には数値を足したり、interval（期間）を足したりすることもできます。orders テーブルの order_date で確認しましょう。

date-arithmetic.sql 
-- 注文日の7日後と1か月後の日付を求める
SELECT order_date,
       order_date + 7 AS 七日後,
       order_date + interval '1 month' AS 一か月後
FROM orders
LIMIT 3;

最後に、日付を好きな書式の文字列に変換する to_char を紹介します。レポートや画面表示で「2024年04月01日」のような和風の表記にしたいとき、必ずと言っていいほど使われる関数です。

to-char.sql 
-- 注文日を「2024年04月01日」の形式で表示する
SELECT order_date,
       to_char(order_date, 'YYYY年MM月DD日') AS 表示用日付
FROM orders
LIMIT 3;

8.5 型変換 — CAST と :: で型を変える

データの型（文字列・数値・日付など）を別の型に変換することを型変換と呼びます。標準 SQL の書き方 CAST(値 AS 型) と、PostgreSQL 独自の省略記法 値::型 の2通りがあり、意味はまったく同じです。

cast-basic.sql 
-- 文字列 '100' を数値に変換してから計算する（2通りの書き方）
SELECT CAST('100' AS integer) + 50 AS CAST記法;   -- 150
SELECT '100'::integer + 50 AS コロン記法;         -- 150

逆に、数値を文字列に変換して他の文字列とつなげたり、文字列を日付に変換したりする場面もよくあります。

cast-more.sql 
-- 単価（数値）を文字列に変換し、「円」を付けて表示する
SELECT product_name, unit_price::varchar || '円' AS 価格表示
FROM products
LIMIT 3;

-- 文字列を日付に変換する
SELECT '2024-04-01'::date AS 変換成功;

ヒント: 変換できない形式はエラーになる

たとえば 'あいう'::date のように、日付として解釈できない文字列を変換しようとすると、PostgreSQL は invalid input syntax for type date というエラーを返し、実行を止めます。「とりあえず変換してみて、失敗したら別処理」という柔軟な変換ではなく、形式が合っていなければ確実に失敗するのが型変換の基本動作です。

8.6 NULL を扱う関数 — COALESCE と NULLIF

第7章で学んだとおり、NULL は「何も入っていない」という特別な状態です。COALESCE(値1, 値2, ...) は、左から順に見ていき最初に見つかった NULL でない値を返す関数です。「NULL だったら代わりにこの値を表示する」という用途で頻繁に使います。

本ガイドの共通サンプルデータには、prefecture（都道府県）が NULL の顧客がいます（未入力のまま登録された想定です）。そのまま表示すると空欄になってしまうので、COALESCE で「未設定」という文字列に置き換えてみましょう。

coalesce.sql 
-- prefectureがNULLの顧客は「未設定」と表示する
SELECT customer_name,
       COALESCE(prefecture, '未設定') AS 都道府県
FROM customers
ORDER BY customer_id;
customer_name 都道府県
佐藤 花子 東京都
鈴木 一郎 大阪府
田中 美咲 北海道
高橋 健太 東京都
伊藤 直美 愛知県
渡辺 大輔 福岡県
山本 恵子 未設定
中村 翔太 東京都
小林 麻衣 神奈川県
加藤 隆 大阪府

逆にNULLIF(値1, 値2) は、2つの値が等しければ NULL を返し、等しくなければ値1をそのまま返す関数です。用途は限られますが、「0除算エラーを避ける」という定番のパターンで威力を発揮します。

nullif.sql 
-- 在庫数が0の商品で割り算してもエラーにしない
-- stock_quantityが0ならNULLIFがNULLを返し、割り算の結果もNULLになる
SELECT product_name, stock_quantity,
       100 / NULLIF(stock_quantity, 0) AS 百個あたりの比率
FROM products;

stock_quantity が0の行では NULLIF(0, 0) が NULL を返すため、100 / NULL の結果も NULL になり、エラーで処理全体が止まる代わりに、その行だけが空欄になります。

8.7 関数を組み合わせる

関数は入れ子にして組み合わせられます。内側の関数の戻り値が、そのまま外側の関数の引数になる、という考え方です。たとえば、メールアドレスの「@」より後ろ（ドメイン部分）だけを取り出し、それを大文字にするには次のように書けます。

nested-functions.sql 
-- メールアドレスの「@」より後ろを取り出し、大文字にする
SELECT email,
       upper(substring(email FROM position('@' IN email) + 1)) AS ドメイン大文字
FROM customers
LIMIT 3;

読み方は内側から外側です。まず position('@' IN email) が「@」の位置（数値）を返し、その次の文字から substring が末尾までを取り出し、最後に upper がそれを大文字にします。1本の式の中で「位置を探す→切り出す→変換する」という3段階の加工を一気に行っているわけです。

ヒント: WHERE句で関数を使うときの注意

WHERE upper(customer_name) = 'サトウ ハナコ' のように、WHERE 句の中で列に関数をかけると、意図どおりに絞り込めます。ただし、列に関数をかけてしまうと、その列に張られた通常のインデックス（検索を高速化する仕組み）が効かなくなり、データ量が多いと検索が遅くなることがあります。この点は、インデックスを学ぶ第14章で詳しく扱います。今は「関数はWHERE句にも書けるが、速度面で注意が要る場合がある」とだけ覚えておいてください。

やってみよう 8-1: 関数を使ってデータを加工する

pgAdmin 4 または A5:SQL Mk-2 のクエリツールで、shop_db に対して次の4つの SQL を書いて実行し、期待どおりの結果になるか確認してください。

  1. 1 customers の customer_name をすべて大文字（半角英字部分のみ変化）にして表示してください。
    期待結果: upper 関数を使う。日本語部分は変化しないが、関数自体はエラーなく動作すること。
  2. 2 order_items の unit_price * quantity（明細の小計）を計算し、round で小数点以下を四捨五入して表示してください。
    期待結果: 小数点以下のない金額（例: 2560）が並ぶ。
  3. 3 orders の order_date から3か月後の日付を求めてください。
    期待結果: order_date + interval '3 month' で、元の日付より3か月先の日付が返る。
  4. 4 customers の prefecture が NULL の人を「未設定」と表示してください。
    期待結果: COALESCE(prefecture, '未設定') で、NULL の行だけ「未設定」と表示され、他の行は元の都道府県が表示される。

ねらい: 「どの関数がどのデータ型に対して使えるか」を体で覚えることが目的です。エラーが出た場合は、関数に渡している値の型（文字列・数値・日付）が合っているかを確認してみましょう。

理解度確認クイズ

  1. Q1. 関数における「引数」と「戻り値」とは、それぞれ何を指しますか。

    回答を表示

    引数は関数に渡す材料となる値（入力）、戻り値は関数が加工して返す結果の値（出力）です。自動販売機にたとえると、投入する硬貨が引数、出てくる飲み物が戻り値にあたります。

  2. Q2. 文字列を連結する || と concat 関数は、NULL の扱いがどう違いますか。

    回答を表示

    || は連結する値のどれか1つでも NULL があると、結果全体が NULL になります。一方 concat 関数は NULL を空文字列として無視し、残りの値だけをつなげて返します。

  3. Q3. 5 / 2 を実行すると結果が 2 になってしまうのはなぜですか。2.5 という結果を得るにはどうすればよいですか。

    回答を表示

    5 と 2 がどちらも整数（integer）型のため、結果も整数型となり小数点以下が切り捨てられるからです。5.0 / 2 のように片方を小数にするか、CAST(5 AS numeric) / 2 のように型変換をすれば、2.5 という小数の結果が得られます。

  4. Q4. CAST(値 AS 型) と 値::型 はどう違いますか。また COALESCE はどのようなときに使いますか。

    回答を表示

    CAST(値 AS 型) は標準 SQL の書き方、値::型 は PostgreSQL 独自の省略記法で、機能はまったく同じです。COALESCE は、複数の値の中から最初に見つかった NULL でない値を返す関数で、NULL を「未設定」などの分かりやすい表示に置き換えたいときに使います。
