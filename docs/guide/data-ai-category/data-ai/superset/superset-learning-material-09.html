チャート種別の使い分け

Superset には30種類以上のチャートが用意されていますが、すべてを暗記する必要はありません。この章では「何を伝えたいか」からチャートを選ぶ考え方を身につけ、まず覚えるべき6種類の使いどころ、円グラフを選ぶ前に立ち止まって考えるべきこと、そしてチャート選びでやりがちな失敗とその直し方を学びます。

この章で学ぶこと

  • 「推移・比較・内訳・分布・関係・単一値」という6つの観点から、伝えたいことに合うチャートを選べるようになる
  • 時系列折れ線グラフ・棒グラフ・テーブル・ピボットテーブル・Big Number・円グラフという基本6種類が、それぞれ何に向くか説明できる
  • 円グラフを選ぶ前に確認すべき条件（項目数・合計の意味・面積比較のしやすさ）を理解する
  • 系列の入れすぎや軸の誇張など、チャートでやりがちな失敗とその直し方を説明できる

9.1 チャートは「伝えたいこと」から選ぶ

Superset の Explore 画面でチャートタイプを選ぼうとすると、数十種類のアイコンが並んだ一覧が表示され、それだけで気後れしてしまうかもしれません。しかし実務では、この一覧を上から順に検討することはまずありません。最初に決めるべきは「どのチャートを使うか」ではなく、「このチャートで何を伝えたいか」です。

伝えたいことは、たいてい次の6つのどれかに当てはまります。

  • 推移 — 時間とともにどう変化したか
  • 比較 — 項目同士でどちらが大きい・多いか
  • 内訳 — 全体に対する構成比はどうなっているか
  • 分布 — 値がどのあたりに集中しているか
  • 関係 — 2つの指標に関連はあるか
  • 単一値 — 今の状態を1つの数字で知りたいか

9.2 まず覚える6種類

Superset には数多くのチャートがありますが、実務で使う頻度が高いのは次の6種類です。まずこの6つの使いどころを押さえれば、多くの分析要求に対応できます。

時系列折れ線グラフ
Time-series Line Chart

時間とともにどう推移したかを見せたいときの定番。売上や訪問者数の増減トレンドが一目でわかります。

棒グラフ
Bar Chart

カテゴリ同士の大小を比較したいときに強い。部門別・商品別の売上のように、項目を並べて比べる場面に向きます。

テーブル
Table

正確な数値そのものを見せたい、または多くの項目・複数指標を一覧にしたいときに最適です。

ピボットテーブル
Pivot Table

行×列で2軸のクロス集計をしたいときに使います（例: 月別×カテゴリ別の売上）。小計・合計もまとめて見せられます。

Big Number
（Trendline付きも含む）

「今月の売上」のように、単一値を大きく見せたいときに使います。Trendline付きなら背景に推移の折れ線も添えられます。

円グラフ
Pie Chart

全体に対する内訳（構成比）を示したいときの候補。ただし使いどころは限定的です（9.4で詳しく説明）。

作り方は第8章のまま使える

チャートの具体的な作り方（軸やメトリクスの指定）は第8章で学んだ Explore の操作がそのまま使えます。Visualization Type を切り替えるだけで、同じデータセットのまま作り直せます。この章では「どれを選ぶか」に集中しましょう。

「6種類は分かったが、結局どれを使えばいいのか」を素早く引けるように、目的別の早見表を用意しました。迷ったときは、まずこの表で当たりをつけてください。

9.4 円グラフを選ぶ前に考えること

円グラフ（Pie Chart）は「内訳を見せたいときの定番」と思われがちですが、実務では慎重に使うべきチャートです。理由は見た目の好みではなく、人間の目が面積や角度の差を正確に比較するのが苦手だからです。棒グラフのように「長さ」を比べるほうが、人はずっと正確に大小を読み取れます。

円グラフを検討する前に、次の条件を確認してみましょう。

円グラフが機能しやすい条件

  • 項目数が5つ程度以内に収まっている
  • 全体の合計が意味を持つ値である（構成比が100%になる）
  • 一番大きい項目・小さい項目が分かれば十分で、細かい差までは求められていない

円グラフが読みにくくなる条件

  • 項目数が6つ・7つ以上ある
  • 値の大きさが近い項目が複数あり、細かい差を見せたい
  • 見た人に正確な数値やランキングまで読み取ってほしい

迷ったら横棒グラフかテーブル

右側の条件に当てはまる場合は、横棒グラフかテーブルを検討してください。横棒グラフは項目数が増えてもラベルが読みやすく、大小の比較も正確に伝わります。正確な数値そのものが重要なら、素直にテーブルにする方が親切です。円グラフを使わないこと自体は失敗ではありません。

9.5 テーブルとピボットテーブルの実力

ここまで「チャートをどう選ぶか」を見てきましたが、実は最も見落とされがちな選択肢が「グラフにしない」ことです。テーブルやピボットテーブルは、地味に見えて次のような場面では他のどのチャートよりも優れています。

  • 正確な数値そのものを見せたい（概算ではなく実数を確認してほしい）
  • 項目数が多い（10件・20件を超えるような一覧）
  • 複数の指標を横に並べて比較したい（売上・件数・単価を同時に見たいなど）
  • 明細に近い粒度で確認したい

重要ポイント

テーブル・ピボットテーブルには、値の大きさに応じてセルに色を付ける条件付き書式や、合計行の表示といった機能も用意されています。数値を目立たせたいからといって無理にグラフ化する前に、テーブルの表現力も検討してください。

ピボットテーブルは、行と列の両方に軸を置ける点がテーブルと異なります。たとえば行に「月」、列に「カテゴリ」を置けば、月×カテゴリのクロス集計表が1枚でき、行・列それぞれの小計も表示できます。棒グラフを並べようとして複雑になってきたら、ピボットテーブルにできないか一度考えてみましょう。

設定名はバージョンにより異なる場合があります

条件付き書式や合計行の設定項目名・設定場所は、Superset のバージョンによって異なる場合があります。Explore 画面のチャート設定パネルを実際に開いて確認するのが確実です。

9.6 その他のチャート

6種類以外にも、Superset には目的が絞られたチャートが用意されています。使用頻度は高くありませんが、該当する場面に出会ったときのために概要を押さえておきましょう。

チャート 何に向くか 補足
面グラフ
Area Chart		 折れ線に加えて「量」の積み上がりを面で見せたいとき 系列が多いと面が重なって読みにくい
複合チャート
Mixed Chart（棒＋折れ線）		 単位が違う2つの指標（例: 売上と成約率）を1枚で見せたいとき 軸が2つになるため、読み手に軸の説明が必要
ヒートマップ
Heatmap		 2軸のマス目を色の濃淡で見せたいとき（例: 曜日×時間帯のアクセス数） 色の濃淡だけでは正確な数値は伝わらず、テーブルの併用が有効
散布図
Scatter Plot		 X軸に指定した列（時間・カテゴリ・数値）とY軸のメトリクスの関係を点で見せたいとき メトリクス同士の相関を見る用途ではない点に注意（指標×指標はBubble Chart）
バブルチャート
Bubble Chart		 2つの指標（メトリクス）の相関を見せたいとき。Entity・X・Y・Bubble sizeを指定し、3つ目の指標を円の大きさで表現できる 点が多いと重なって読みにくく、分析者向けの用途が中心
ヒストグラム

地図系チャート 都道府県別・国別など地理的な分布を見せたいとき 位置情報（緯度経度や地域コード）の準備が必要
ツリーマップ／
サンバースト		 階層を持つ内訳（カテゴリ→サブカテゴリなど）を面積や層で見せたいとき 初見の人には読み方の説明が要る。使用頻度は限定的
ゲージ

9.7 やりがちな失敗

チャート選びに慣れてきた頃によく出るのが、次の5つの失敗です。どれも「間違ったチャートを選んだ」のではなく、「詰め込みすぎた」ことが原因です。

失敗1: 系列を入れすぎて読めない

1枚のグラフに10系列も詰め込むと、色の見分けがつかず、結局どの線が何かを凡例と照合する作業になってしまいます。

どう直すか: 本当に比較したい3〜5系列に絞る。残りは「その他」にまとめるか、別のチャートに分ける。

失敗2: 色で意味を持たせすぎる

「なんとなく目立つから」で色を変えると、見る人は色の違いにも意味があると誤解し、かえって混乱します。

どう直すか: 色に意味を持たせるなら、1つのダッシュボード内で意味を1種類に統一する。装飾目的だけの色分けはやめる。

失敗3: 軸を0から始めないことによる誇張

棒グラフの数値軸の下限を実際のデータに近い値（例: 980〜1000）にすると、わずかな差が大きな差に見えてしまいます。棒グラフは長さで大小を比較するため、0を含まない軸は特に誤解を招きます。

どう直すか: 棒グラフの数値軸は0から始めるのが必須。折れ線グラフは変化の形を見せるのが目的のため0起点を強制しないのが一般的だが、0から始めない場合は軸の範囲をタイトルや注記で明示する。

失敗4: 時間粒度が細かすぎてノイズになる

月次の傾向を知りたいのに分単位・時間単位で描画すると、線がギザギザになり、本当に見たい傾向が埋もれてしまいます。

どう直すか: 見せたい変化の周期に合わせて、時間軸の粒度を週次・月次に粗くする。

失敗5: 1枚のチャートに複数の問いを詰め込む

「推移も比較も内訳も1枚で」と欲張ると、軸や凡例が増えすぎて、結局どの問いにも明快に答えられないチャートになります。

どう直すか: 「このチャートで答える問いは1つ」と決めてから作る。問いが複数あるなら、チャートを分けてダッシュボードに並べる。

共通しているのは、「1枚のチャートに詰め込みすぎない」という姿勢です。伝えたいことが複数あるなら、チャートも複数に分けて、ダッシュボード上に並べれば済みます。複数のチャートを1枚のダッシュボードにまとめる方法は第10章で扱います。

やってみよう 9-1: 「カテゴリ別売上」を3種類で作り比べる

第8章で作成した「カテゴリ別売上」のチャートを使って、同じデータを異なるチャートタイプで作り、見比べてみましょう。

手順

  1. 1 第8章で保存した「カテゴリ別売上」のチャートを Explore で開き、チャートタイプを棒グラフに変更して別名で保存する（例: 「カテゴリ別売上_棒」）。
  2. 2 同じ手順で、円グラフ版（「カテゴリ別売上_円」）とテーブル版（「カテゴリ別売上_表」）も作成する。対象期間や並び順などの条件は3つとも揃える。
  3. 3 3つのチャートを並べて見比べ、それぞれの「読み取りやすい点」「読み取りにくい点」をメモする。
  4. 4 売上高の合計を Big Number チャートとして1枚作成する。ディメンションは使わずメトリクスに「売上高」だけを設定し、「今月の売上高」のような名前で保存する（このチャートは第10章の実習でも使う）。
  5. 5 「上司への月次報告で使うならどれか」を1つ選び、理由を1〜2文で書く。

解答の目安

答えはカテゴリ数や、報告で何を重視するかによって変わります。カテゴリ数が4〜5程度で構成比を一目で伝えたいなら円グラフも選択肢になりますが、カテゴリが増えたり金額の正確さも併記したい場合は棒グラフやテーブルの方が安全です。判断に迷う場合は、大小を視覚的に見せる棒グラフと、正確な数値を確認できるテーブルを組み合わせるのが無難な選択です。

手順4のBig Numberは、ディメンションを使わずメトリクスに売上高（SUM）だけを設定すればよく、3種類の比較チャートより設定はシンプルです。次の第10章では、この「今月の売上高」をダッシュボードの上段に配置します。

理解度確認クイズ

  1. Q1. Superset のチャートを選ぶとき、種類の多さに迷ったら最初に何を決めるべきですか？

    回答を表示

    チャートの種類を先に決めるのではなく、まず「何を伝えたいか」（推移・比較・内訳・分布・関係・単一値のどれか）を決めます。伝えたいことが決まれば、候補となるチャートは自然に絞り込まれます。

  2. Q2. 円グラフを使う前に確認すべきことは何ですか？

    回答を表示

    項目数が少ないか（目安5つ以内）、合計が意味を持つ値か（構成比が100%になるか）を確認します。人間の目は面積や角度の差を正確に比較するのが苦手なため、条件に当てはまらない場合は横棒グラフやテーブルの方が正確に伝わります。

  3. Q3. 棒グラフと折れ線グラフでは、数値軸（Y軸）を0から始めるべきかというルールに違いはありますか？

    回答を表示

    棒グラフは0から始めることが必須です。長さで大小を比較するため、0を含まない軸にするとわずかな差が誇張されて伝わります。一方折れ線グラフは変化の形（トレンド）を見せるのが目的のため、0起点を強制しないのが一般的です。ただし0から始めない場合は、軸の範囲をタイトルや注記で明示する必要があります。

  4. Q4. チャートを作らず「グラフにしない」判断が有効なのはどんな場合ですか？

    回答を表示

    正確な数値そのものを見せたい場合、項目数が多い場合、複数の指標を並べて比較したい場合などです。こうした場合はテーブルやピボットテーブルの方が、グラフより正確に伝わります。
