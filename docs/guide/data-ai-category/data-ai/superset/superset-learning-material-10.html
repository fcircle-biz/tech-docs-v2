第10章 所要時間: 約70分

ダッシュボードを組み立てる

第8章・第9章で作った個々のチャートを、1枚の画面にまとめる工程がダッシュボードです。この章では、ダッシュボードの新規作成からチャートの配置、Tabs・Row・Columnによるレイアウト、Markdownでの説明の添え方までを一通り操作し、最後に「読み手に伝わる構成」とは何かを学びます。

この章で学ぶこと

  • ダッシュボードとチャートの関係（チャートは複数のダッシュボードで使い回せること）を説明できる
  • ダッシュボードを新規作成し、編集モードでチャートを配置・サイズ調整できる
  • Tabs・Row・Column・Header・Markdownなどのレイアウト要素を使い分けられる
  • 「結論を上、詳細を下」という構成の原則を理解し、Draft／Publishedを使い分けて共有できる

10.1 ダッシュボードとは

ダッシュボード（Dashboard）は、複数のチャートを1枚の画面にまとめ、URLで共有できるようにしたものです。第1〜9章で学んできたDB接続・データセット・チャートは、いわば材料と部品づくりでした。ダッシュボードは、その部品を並べて1つの「見る画面」に仕上げる工程にあたります。

ここで押さえておきたいのは、チャートの実体は1つのまま、複数のダッシュボードに配置できるということです。「置く」という言葉のとおり、ダッシュボードはチャートをコピーして持つのではなく、既存のチャートへの参照を並べています。そのため同じ「月次売上推移」というチャートを、経営会議用のダッシュボードと、営業チーム用のダッシュボードの両方に置く、といった使い回しが自然にできます。

flowchart LR C1["チャート
月次売上推移"] --> D1["ダッシュボード
経営会議"] C1 --> D2["ダッシュボード
営業チーム"] C2["チャート
カテゴリ別売上"] --> D1 C2 --> D3["ダッシュボード
商品部"]

この「実体は1つ」という性質は、便利である一方で注意も必要です。あるダッシュボードの中でチャートの見た目や集計方法を変更すると、そのチャートを使っている他のすべてのダッシュボードにも同じ変更が反映されます。

重要ポイント

ダッシュボードの編集で動かせるのは配置と大きさ、そしてMarkdownなどの文脈情報です。チャートそのものの色・集計方法・軸を変えたい場合は、そのチャートを直接編集する必要があります（第8章・第9章の操作）。「このダッシュボードだけ表示を変えたい」と思ったときは、まずチャートを複製して別名で保存するべきかどうかを考えましょう。

10.2 新規作成と編集モード

ダッシュボードを新しく作るには、ナビゲーションバーのDashboardsを開き、右上の+ Dashboardボタンをクリックします。新しい空のダッシュボードが開いたら、まずタイトルをクリックして分かりやすい名前を付けましょう（例:「月次売上ダッシュボード」）。タイトルは後からいつでも変更できるので、仮の名前で構いません。

Supersetのダッシュボードには、閲覧モード（View）と編集モード（Edit）の2つの状態があります。保存済みのダッシュボードを開くと、まず閲覧モードで表示されます。画面右上のEdit dashboardボタンを押すと編集モードに切り替わり、グリッドの枠線やチャートを探すための右側パネルが現れます。配置やレイアウトを直し終えたら、右上のSaveで保存します。保存するまでは変更が確定しないので、操作を間違えてもDiscard changes（変更の破棄）でいつでもやり直せます。

モード できること 主な利用者
閲覧モード（View） フィルタの操作、チャートの拡大表示、CSV／画像のダウンロード
（ダウンロードはロールの権限や管理者の設定に依存し、閲覧者に許可されていない場合もある）		 ダッシュボードを見るすべての利用者
編集モード（Edit） チャートの追加・削除・並べ替え、レイアウト変更、Markdown編集、プロパティ変更 ダッシュボードを作る・直す担当者

保存を忘れずに

編集モードでの変更は、Saveを押すまでは自分の画面にしか反映されません。配置を整えている途中でブラウザを閉じたり、他の画面に移動したりすると変更が失われることがあります。区切りのよいところでこまめにSaveする習慣をつけましょう。

10.3 チャートを配置する

第8章では、Exploreでチャートを保存する際のSaveダイアログにAdd to dashboardという項目があり、既存または新規のダッシュボードを指定できることに触れました。この方法は手早くチャートをダッシュボードに追加できますが、追加されるのは末尾の決まった位置で、どこに・どれくらいの大きさで置くかまでは指定できません。配置や大きさを整えるのは、結局この節で説明する編集モードでの作業になります。

編集モードに入ると、画面右側にChartsタブが現れます。ここには自分が保存したチャートが一覧表示され、名前で検索することもできます。目的のチャートのカードを、左側のグリッド上にドラッグ＆ドロップすると、その位置に配置されます。ドラッグ中は差し込まれる位置が枠線でプレビューされるので、狙った場所に落ち着かせてからマウスを離しましょう。

配置したチャートは、端にカーソルを合わせるとリサイズ用のハンドルが現れ、ドラッグして幅や高さを変えられます。画面は目に見えないグリッドで区切られており、サイズは細かいピクセル単位ではなく、一定の升目に沿ってスナップします。隣のチャートと高さを揃えたいときは、このスナップを頼りに調整すると綺麗に揃います。

配置し直すのも自由

すでに置いてあるチャートも、編集モード中はカードと同じようにドラッグして位置を移動できます。「まず全部並べてから、後で順番を整える」という進め方で問題ありません。並べ終わったら忘れずにSaveしてください。

10.4 レイアウト要素

右側のパネルには、チャートだけでなくLayout elements（レイアウト要素）も並んでいます。これらはチャートそのものではなく、画面を区切ったり文章を添えたりするための部品です。代表的な6つを整理します。

要素 役割
Tabs（タブ） 画面をページ切り替えのように分割する。「概要」「明細」など見る目的が違う内容を分けるのに使う
Row（行） チャートを横に並べる単位。ダッシュボードの基本的な骨組み
Column（列） Rowを横方向に分割してできる器で、その中に要素を縦に積める。同じ行の中で幅を細かく分けたいときに使う
Header（見出し） 大きな文字のセクション見出し。「売上」「在庫」のように話題の区切りを示す
Markdown 自由な文章を書ける部品。説明・注意書き・凡例などに使う（10.5で詳しく扱う）
Divider（区切り線） セクション間に1本の線を引き、見た目の区切りをつける

これらはDashboard → Tabs → Row → Column → Chartという入れ子の関係で組み合わさります。例えば「概要」タブと「明細」タブを作り、それぞれのタブの中にRowを並べ、Rowの中にChartやColumnを置く、という具合です。

flowchart TD Dash["ダッシュボード"] --> Tab1["Tab: 概要"] Dash --> Tab2["Tab: 明細"] Tab1 --> Row1["Row"] Tab1 --> Row2["Row"] Row1 --> Chart1["Big Number
今月の売上高"] Row1 --> Chart2["Big Number
今月の客数"] Row2 --> Col1["Column"] Row2 --> Col2["Column"] Col1 --> Chart3["折れ線
月次推移"] Col2 --> Chart4["棒グラフ
カテゴリ別売上"]

最初から全部の要素を使う必要はありません。まずはRowだけでチャートを並べてみて、画面が縦に長くなってきたらTabsで話題ごとに分ける、説明が必要な箇所にはHeaderやMarkdownを足す、という順番で少しずつ整えていくのがおすすめです。

10.5 Markdownで文脈を添える

チャートを並べただけのダッシュボードは、作った本人にしか意味が分からないことがよくあります。「この数字は税込か税抜か」「いつのデータか」「おかしいと思ったら誰に聞けばよいか」——こうした情報は、Markdown要素を使って画面の中に直接書き込んでおくのが一番確実です。

Markdown要素は、他のチャートと同じようにグリッド上に配置し、ドラッグでサイズを変えられます。編集モード中にMarkdown要素をクリックすると入力欄が開き、見出しや箇条書きを含む簡単な文章を書けます。最低限、次のような内容を書いておくとよいでしょう。

Markdown要素の記述例 
# 月次売上ダッシュボード

## このダッシュボードについて
店舗ごとの月次売上を、月次会議で確認するためのものです。

## 指標の定義
- 売上高 = 税抜金額の合計（返品分を除く）
- 客単価 = 売上高 ÷ 客数

## データの更新
毎日 AM6:00 に前日分までを反映します。

## 問い合わせ先
経営企画部 データチーム

Markdown要素は本文を書く場所としてだけでなく、Header代わりの大きな見出しや、チャートの色分けの凡例を書く場所としても使えます。「なぜこの色を使っているのか」を毎回口頭で説明せずに済むよう、画面の中に答えを置いておく、という意識で使うとよいでしょう。

10.6 読み手に伝わる構成の原則

部品（チャート・レイアウト要素・Markdown）が揃ったところで、それらをどう並べるかを考えます。Supersetの機能そのものではなく設計の話ですが、ダッシュボードの使いやすさはここでほぼ決まると言ってよいほど重要です。

  • 結論を上、詳細を下に — 最初に伝えたい数字（KPI・Big Number）を画面上段に置き、その数字を裏付ける推移グラフや内訳、明細テーブルを下段に続けます。
  • 左上から読まれる — 画面を開いた人の視線はおおむね左上から動き始めるといわれます。もっとも重要な数字ほど左上に近い位置に置きましょう。
  • 1画面1テーマ — 「売上」の画面に「勤怠」の数字を混ぜない、というように、1つのタブ・1つの画面では1つの話題に絞ります。話題が変わるならTabsで分けます。
  • スクロールを前提にしない — 開いた瞬間に見える範囲に、その画面でいちばん伝えたい結論が収まるようにします。詳細を見るためのスクロールは構いませんが、結論を見るために毎回スクロールさせる構成は避けます。
  • チャートを詰め込みすぎない — 作れるからといって全部並べると、どれが重要か分からなくなります。1画面あたり5〜9枚程度を目安に、迷ったら思い切って削りましょう。

良い例

  • 上段にBig Numberで結論となる数字を並べる
  • 中段に推移グラフを置き、変化の傾向を示す
  • 下段に内訳やテーブルなど、深掘り用の詳細を置く
  • 1つのテーマ（例: 月次売上）に絞って構成する
  • チャートの枚数を絞り、余白を残す

悪い例

  • 作れるチャートを思いつく限りすべて並べる
  • 売上と勤怠のように関連性の薄い話題を1画面に混在させる
  • 結論となる数字がどこにあるか分からない
  • 小さすぎるチャートを詰め込み、文字やラベルが読めない
  • いちばん伝えたい数字を見るのに毎回スクロールが必要

10.7 プロパティと見た目

タイトル以外の情報は、Edit properties（プロパティの編集）からまとめて設定できます。よく使われる項目には、タイトル・Owners（所有者。編集権限を持つユーザー）・Color scheme（このダッシュボードで使う配色）・CERTIFIED BY／CERTIFICATION DETAILS（証明バッジ。信頼できる公式ダッシュボードであることを示す印）などがあります。表示される項目や名称はバージョンによって多少異なる場合があるので、実際の画面で確認してください。

新しく作ったダッシュボードは、既定でDraft（下書き）という状態になっています。タイトルの近くにある表示を切り替えるとPublished（公開）にできます。Draftのままでも保存やURLでのアクセスはできますが、一覧画面では目立たなかったり、絞り込みの対象から外れたりすることがあります。チームに見てもらう準備ができたら、Publishedへの切り替えを忘れないようにしましょう。

Published は「誰でも見られる」ではない

Draft / Published は共有の準備状態を表す区分であり、アクセス制御そのものではありません。Published にしても、そのダッシュボードを開けるのは対象のデータセット（または当該ダッシュボード）への権限を持つユーザーだけです。逆に「URL を送ったのに相手が開けない」場合、原因は Draft のままではなく権限が足りていない可能性があります。「誰に何を見せるか」はロールと権限で決めるもので、第13章で扱います。

Draftのまま忘れがち

配置とMarkdownを整えたのに「誰にも見つけてもらえない」というときは、Publishedへの切り替えを忘れているケースが少なくありません。10-1の実習でも、最後にPublishedへの切り替えを手順に含めています。

10.8 共有する

Publishedにしたダッシュボードを共有するもっとも簡単な方法は、ブラウザのURLをそのままコピーして送ることです。10.1で触れたとおり、ダッシュボードの実体は1つで、全員が同じURLを開けば同じ最新の数字を見ることになります。Excelファイルをメールに添付して回す場合と違い、「どのバージョンが最新か分からない」という事故が起きません。

画面右上の…（その他）メニューからは、ダッシュボードの定義をZIPファイルとして書き出すエクスポートを実行できます（他の環境への移行手順は第14章で扱います）。また、同じメニューやツールバーからPDFや画像としてダウンロードできる場合もあります。この機能の有無や操作手順はSupersetのバージョンや管理者の設定によって異なるため、必要になったら実際の画面で確認してください。

「共有できる」と「見せてよい」は別の話

URLを知っていれば誰でも開けてしまうのか、それともログインとアクセス権限が必要なのかは、この章では扱いません。「誰に何を見せてよいか」を制御する仕組みは第13章で、ロールと行レベルセキュリティとあわせて学びます。この章ではまず、伝わる形にダッシュボードを組み立てることに集中しましょう。

次の第11章では、見る人が条件を変えられる「ネイティブフィルタ」と、チャート同士をクリックで連動させる「クロスフィルタ」を使って、ダッシュボードをより実用的に仕上げる方法を学びます。

やってみよう 10-1: 「月次売上ダッシュボード」を組み立てる

第8章・第9章で作成したチャートを使って、実際に1枚のダッシュボードへまとめてみましょう。個々のチャートを作る作業と、それらを並べて1つの画面に仕立てる作業とでは、必要な考え方がまったく違うことを体感してください。

手順

  1. 1 Dashboards画面で+ Dashboardから新規作成し、「月次売上ダッシュボード」という名前を付ける。
  2. 2 Edit dashboardで編集モードに入り、上段に第9章の実習で作成したBig Number（今月の売上高。まだ作っていなければ先に1枚作る）、中段に月次推移の折れ線、下段にカテゴリ別の棒グラフとテーブルを配置する。
  3. 3 Markdown要素を1つ追加し、指標の定義（売上高の集計範囲など）とデータの更新タイミングを記載する。
  4. 4 配置とMarkdownの内容を見直してからSaveし、プロパティ（またはタイトル付近の表示切り替え）でPublishedにする。

解答の目安

配置の意図: 上段のBig Numberで「結論」を最初に見せ、下段の推移・内訳・明細で「詳細」を続ける、10.6の結論→詳細の原則をそのまま形にしています。テーマは「月次売上」の1本に絞り、勤怠や在庫など別の話題は混ぜません。

Markdownに書くべき項目のチェックリスト:

  • 何についてのダッシュボードか
  • 指標（売上高・客単価など）の定義
  • データがいつ・どのくらいの頻度で更新されるか
  • 疑問点があったときの問い合わせ先

理解度確認クイズ

  1. Q1. 同じチャートを2つのダッシュボードに配置した場合、チャートの実体はいくつになりますか。また、一方のダッシュボードでそのチャートの色分けを変更すると何が起きますか。

    回答を表示

    実体は1つのままです。ダッシュボードはチャートをコピーして持つのではなく、既存のチャートへの参照を並べています。そのため一方で色分けなどチャート自体の設定を変更すると、そのチャートを使っている他のすべてのダッシュボードにも同じ変更が反映されます。

  2. Q2. チャートを狙った位置・大きさでダッシュボードに配置するには、どこで何をする必要がありますか。第8章のSaveダイアログでダッシュボードを指定する方法だけでは足りない理由もあわせて答えてください。

    回答を表示

    ダッシュボードをEdit dashboardで編集モードにし、右側のChartsタブから対象のチャートをグリッドへドラッグ＆ドロップし、端をドラッグしてサイズを調整します。第8章のSave時に指定する方法はチャートを末尾に追加してくれるだけで、位置や大きさまでは指定できないため、結局この編集モードでの調整が必要になります。

  3. Q3. 1つのダッシュボードの中で「概要」と「明細」のように見る目的が違う内容を分けたいとき、どのレイアウト要素を使いますか。RowやColumnではなくこの要素を使う理由も説明してください。

    回答を表示

    Tabs（タブ）を使います。RowやColumnは同じ画面の中でチャートを横や縦に並べるための要素であり、画面自体を切り替えるものではありません。目的の違う内容をページ切り替えのように分けたい場合はTabsが適しています。

  4. Q4. 「読み手に伝わる構成」の原則にしたがうと、KPIやBig Numberと、推移グラフ・明細テーブルは、それぞれ画面のどこに置くべきですか。またその理由も説明してください。

    回答を表示

    結論となるKPI・Big Numberは上段（画面の左上に近い位置）に、それを裏付ける推移グラフや明細テーブルなどの詳細は下段に置きます。人の視線はおおむね左上から動き始めるため、最初に見える位置に最も伝えたい結論を置くことで、スクロールしなくても要点が伝わる画面になります。
