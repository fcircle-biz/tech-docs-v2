Python SDKで組み込む

前章では curl で Jev の HTTP API を直接呼び出しました。本章では公式 Python SDK typesafe-sdk を使い、同じ処理を Python アプリケーションへ型安全に組み込みます。JSON を手作りする代わりに Choice・Score・Noul という Python クラスで Question を定義し、レスポンスもオブジェクトとして受け取ります。

この章で学ぶこと

  • Python SDK をインストールし、クライアントを初期化できる
  • Choice / Score / Noul を Python オブジェクトとして定義できる
  • response.answers から判断結果を型付きで取り出せる
  • 問い合わせを判定する Python CLI を自分で書ける

7.1 インストールと前提

第6章では、curl で POST /v1/systemone を直接呼び出し、リクエストとレスポンスの JSON 構造を確認しました。ここからは、その JSON の組み立て・送信・パースを肩代わりしてくれる公式 Python SDK typesafe-sdk を使い、Python アプリケーションへ組み込んでいきます。

SDK を使うと、認証ヘッダーの付与・JSON のシリアライズ／デシリアライズ・失敗時の例外化といった定型処理をSDKが肩代わりしてくれます。手で書くのは「どんな Question を送るか」という本質的な部分だけになります。

typesafe-sdk は Python 3.10 以上を前提としています。まずバージョンを確認し、プロジェクト専用の仮想環境を作ってからインストールしましょう。

ターミナル 
# Python 3.10 以上がインストールされているか確認する
python3 --version

# プロジェクト用の仮想環境を作成する
python3 -m venv .venv

# 仮想環境を有効化する（macOS / Linux）
source .venv/bin/activate

# 仮想環境を有効化する（Windows PowerShellの場合）
# .venv\Scripts\Activate.ps1

# Jevの公式Python SDKをインストールする
pip install typesafe-sdk

uv を使う場合

高速なパッケージマネージャ uv を使っているなら、pip install の代わりに uv add typesafe-sdk でも同じようにインストールできます。どちらも公式にサポートされています。

7.2 クライアントの初期化

第6章では curl -H "Authorization: Bearer $TYPESAFE_API_KEY" のように、リクエストのたびに認証ヘッダーを自分で組み立てました。SDK ではこの手順は不要です。TypeSafeClient を作成するだけで、環境変数から API キーを自動的に読み込んでくれます。

API キーは console.typesafe.ai/keys で発行したものを使います。まずターミナルで環境変数として設定します。

ターミナル 
# APIキーを環境変数として設定する（console.typesafe.ai/keys で発行）
export TYPESAFE_API_KEY="ここに発行されたAPIキーを貼り付ける"

Python 側では、TypeSafeClient() を呼び出すだけで初期化が完了します。

client.py 
from typesafe_sdk import TypeSafeClient

# 環境変数 TYPESAFE_API_KEY から自動的にAPIキーを読み込む
client = TypeSafeClient()

APIキーをソースコードに直書きしない

TypeSafeClient(api_key="sk-...") のようにキーを引数へ直接渡すことも技術的には可能ですが、そのままGitにコミットするとリポジトリの履歴からキーが漏洩します。第6章と同様に、環境変数 TYPESAFE_API_KEY から読み込む方法を徹底しましょう。

7.3 Question を Python オブジェクトで定義する

第6章で送ったリクエストの questions は、たとえば次のような JSON でした（department の部分だけ抜粋しています）。

第6章のリクエストJSON（抜粋） 
{
  "state": "（省略：問い合わせ本文）",
  "questions": {
    "department": {
      "type": "choice",
      "instructions": "この問い合わせはどの部署が対応すべきか",
      "criteria": {
        "technical": "バグや連携不具合に関する問題",
        "billing": "支払い・請求に関する問題",
        "sales": "料金やアカウントに関する質問"
      }
    }
  }
}

この questions の中身を、SDK では Choice・Score・Noul という3つの Python クラスでそのまま型付きに表現できます。書く内容は同じで、書き方だけが変わります。

questions.py（Choiceの定義） 
from typesafe_sdk import Choice, Score, Noul

# 担当部署をどの3択から選ぶかを定義する
department = Choice(
    instructions="この問い合わせはどの部署が対応すべきか",
    criteria={
        "technical": "バグや連携不具合に関する問題",
        "billing": "支払い・請求に関する問題",
        "sales": "料金やアカウントに関する質問",
    },
)

同じ要領で、frustration（不満度の段階評価）と is_urgent（緊急かどうかの真偽判定）も定義します。Score の criteria は選択肢の辞書ではなく、段階を表す配列になる点に注目してください。

questions.py（Score／Noulの定義） 
# 不満度を3段階のルーブリックで評価する
frustration = Score(
    instructions="顧客がどれくらい苛立っているか",
    criteria=[
        "落ち着いていて事実を述べているだけ",
        "苛立っているが礼儀正しい",
        "非常に怒っており、強い言葉を使っている",
    ],
)

# 至急対応が必要かを0〜1の確率で判定する
is_urgent = Noul(instructions="至急対応が必要な内容か（緊急性があるか）")

重要ポイント

instructions は「何を判断してほしいか」、criteria は「判断の材料となる選択肢や段階」を表します。JSON を手書きするより、Pythonオブジェクトの方が引数名の打ち間違いにエディタが気づいてくれるという利点もあります。この役割分担は第10章でさらに深く扱います。

7.4 結果を取り出す

3つの Question を辞書にまとめて client.system_one() に渡すと、1回のリクエストでまとめて評価されます（第11章で扱う「並列評価」の入り口です）。

main.py（結果の取得） 
state_text = "お客様からの問い合わせ本文をここに入れる"

# 3つのQuestionをまとめて送信する
response = client.system_one(
    state=state_text,
    questions={
        "department": department,
        "frustration": frustration,
        "is_urgent": is_urgent,
    },
)
# 型付きの結果を取り出す
print(response.answers["department"].choice)   # 例: "technical"
print(response.answers["frustration"].score)   # 例: 1.42（criteria の段階0〜2上の確率加重値）
print(response.answers["is_urgent"].noul)      # 例: 0.97

注意: .score は段階のラベル文字列ではなく数値

第4章で見たとおり、score は各段階の確率を段階番号で重み付け平均した確率加重値（数値）です。上の例のように criteria を3段階で定義した場合、返るのは 1.42 のような 0〜2 の小数であり、"苛立っているが礼儀正しい" というcriteria の文字列そのものは返りません。人が読むラベルを表示したい場合は、アプリ側で legend を参照して数値を表示用ラベルへ変換します。

response.answers は、questions に渡したのと同じキー名を持つ辞書です。第1章で見たレスポンス JSON の answers と対応しており、値の取り出し方は Primitive の種類によって決まります。

Primitive 定義に使うクラス 結果を読む属性
Choice Choice(...) .choice
Score Score(...) .score（数値）
Noul Noul(...) .noul

department のような Choice の結果と、frustration のような Score の結果には confidence や probabilities も付随し、response.answers["department"].confidence のように読み出せます。Noul にはこれらのフィールドはありません（noul の値自体が Yes である確率だからです）。これらの数値を使った設計は第9章で詳しく扱います。

補足: 型別のアクセサもある

公式ドキュメントには response.choices["..."]・response.scores["..."]・response.nouls["..."] という書き方も登場します。これはPrimitive の種類ごとに絞り込んだ辞書で、どちらも公式の API です。本教材では、どの Primitive でも同じ書き方で読める response.answers["..."] に統一します。

7.5 CLI を作る

ここまでの内容を1つの CLI スクリプト jev_triage.py にまとめます。コマンドライン引数があればそれを問い合わせ文として使い、無ければ標準入力から読み込みます。処理の流れは次のとおりです。

flowchart TD A["CLI起動"] --> B{"引数はあるか"} B -->|あり| C["コマンドライン引数を問い合わせ文にする"] B -->|なし| D["標準入力から問い合わせ文を読み込む"] C --> E["TypeSafeClientを初期化"] D --> E E --> F["3つのQuestionをsystem_oneに送信"] F --> G["department・frustration・is_urgentを表示"]

処理を3つの関数に分けて実装します。まずは問い合わせ文の受け取り部分です。

jev_triage.py（1/3: 入力の取得） 
import sys
from typesafe_sdk import TypeSafeClient, Choice, Score, Noul

def read_inquiry_text() -> str:
    # 引数があれば使い、無ければ標準入力から読む
    if len(sys.argv) > 1:
        return " ".join(sys.argv[1:])
    print("問い合わせ文を入力してください:")
    return input().strip()

次に、3つの Question を定義して system_one を呼び出す部分です。

jev_triage.py（2/3: Jevへの問い合わせ） 
def judge(text: str):
    # 3つのQuestionをまとめて送信し、結果を返す
    client = TypeSafeClient()
    department = Choice(
        instructions="この問い合わせはどの部署が対応すべきか",
        criteria={"technical": "連携不具合", "billing": "支払いの問題", "sales": "料金の質問"},
    )
    frustration = Score(
        instructions="顧客がどれくらい苛立っているか",
        criteria=["落ち着いている", "やや苛立っている", "非常に怒っている"],
    )
    is_urgent = Noul(instructions="至急対応が必要な内容か")
    questions = {"department": department, "frustration": frustration, "is_urgent": is_urgent}
    return client.system_one(state=text, questions=questions)

最後に、結果を表示するエントリーポイントです。

jev_triage.py（3/3: 結果表示） 
def main():
    text = read_inquiry_text()
    response = judge(text)
    answers = response.answers
    print(f"担当部署   : {answers['department'].choice}")
    print(f"不満度     : {answers['frustration'].score:.2f}")  # 0〜2の数値
    print(f"緊急度     : {answers['is_urgent'].noul:.2f}")

if __name__ == "__main__":
    main()

動作確認: CLIを実行してみる

引数に問い合わせ文を渡して実行すると、3つの判断がまとめて表示されます。

ターミナル 
$ python jev_triage.py "3日前からStripe連携が失敗しており、至急対応してほしい"
担当部署   : technical
不満度     : 1.42
緊急度     : 0.97

出力はすべて Python の値です（choice は文字列、score と noul は浮動小数点数）。if response.answers["is_urgent"].noul > 0.8: や if answers["frustration"].score >= 1.5: のように、そのままコードの条件分岐に使えます。「やや苛立っている」のような表示用ラベルが必要なら、legend を使ってアプリ側で変換します。

7.6 エラー処理と他言語SDK

実運用では、API キーが誤っている・レート制限に達した・ネットワークが不安定といった理由でリクエストが失敗することがあります。SDK はこうした失敗を TypeSafeAPIError という例外にまとめて通知します。

jev_triage.py（エラー処理を追加） 
from typesafe_sdk import TypeSafeAPIError

try:
    response = client.system_one(state=text, questions=questions)
except TypeSafeAPIError as error:
    # statusにHTTPステータスコードが入る（401=認証エラー、429=レート制限など）
    print(f"エラーが発生しました: status={error.status} request_id={error.request_id}")

error.status には HTTP ステータスコードが入ります。一般的な HTTP API の慣例に従えば、401系は認証情報（API キー）の問題、429はレート制限（送りすぎ）を意味します。error.request_id は、TypeSafe AI のサポートに問い合わせる際の手がかりになる識別子です。再試行そのものの考え方は、第6章で学んだ内容がそのまま活きます。

なお公式は、Python 以外に JavaScript / TypeScript 向けのクライアント SDK（npm install @typesafe-ai/sdk）も提供しています。Node.js のサーバーや Next.js の API Route から Jev を呼び出したい場合も、Python と同じように Choice・Score・Noul に相当する型付きの Question を定義できます。使用言語が Python でなくても、本章で学んだ「State と Question を渡し、型付きの answers を受け取る」という設計の考え方はそのまま応用できます。

やってみよう 7-1: CLIに自分の業務の判断を追加する

本章で作った jev_triage.py を、自分の業務に合わせて拡張してみましょう。

手順

  1. 1 自分の業務やアプリの中にある「Jevに向く判断」を1つ選ぶ（第1章の「やってみよう1-1」で書き出したものでもよい）。
  2. 2 その判断に合う Choice・Score・Noul のいずれかを選び、Pythonオブジェクトとして定義する。
  3. 3 judge() 内の questions 辞書に追加し、main() に response.answers[...] から結果を表示する1行を追加する。
  4. 4 実際に実行し、意図した通りの結果が返ってくるか確認する。

進め方のヒント

Noul は真偽（0〜1）、Choice は分類、Score は段階評価に向きます。判断の内容に応じて Primitive を選びましょう（第4章を復習）。

理解度確認クイズ

  1. Q1. pip install typesafe-sdk を実行する前に確認すべき前提条件は何ですか？

    回答を表示

    Python 3.10 以上がインストールされていることです。python3 --version で確認できます。プロジェクトごとに依存関係を分離するため、仮想環境（venv）の利用も推奨されます。

  2. Q2. TypeSafeClient() を初期化する際、APIキーはどこから読み込まれるのが推奨されますか。またその理由も答えてください。

    回答を表示

    環境変数 TYPESAFE_API_KEY から読み込まれるのが推奨です。api_key 引数でソースコードに直書きすると、Gitへのコミットなどでキーが漏洩する危険があるためです。

  3. Q3. Choice・Score・Noul のPythonオブジェクトと、第6章で送ったJSONの questions は、内容としてどのような関係にありますか？

    回答を表示

    同じ内容です。JSONで手書きしていた type・instructions・criteria の組を、SDKが用意した3つのクラスへの引数として型付きに表現したものが Choice・Score・Noul オブジェクトです。SDK内部で同じ形のJSONへ変換されてHTTPリクエストが送られます。

  4. Q4. client.system_one(...) の戻り値から、is_urgent の判定結果を取り出すコードを1行で書いてください。

    回答を表示

    response.answers["is_urgent"].noul です。キー名は questions 辞書で指定した名前と一致させる必要があります。
