16.1 CSV への保存と起動時の読み込み

第15章の kakeibo.py は、records というリストにデータを溜めているだけでした。プログラムを終了するとメモリ上のデータは消えてしまうため、次に起動したときには記録が空に戻ってしまいます。第12章で学んだ CSV ファイルへの読み書きを使って、この問題を解決しましょう。まず python-study/ch16 フォルダを作り、第15章の kakeibo.py をコピーして、その続きを書いていきます。保存先のファイル名は、あとで変更しやすいように定数としてまとめておきます（FILE_NAME のように全部大文字で書くのは「プログラムの途中で変更しない値」という目印の慣習です）。

kakeibo.py（ファイル冒頭の records = [] の上に追加） 
import csv

FILE_NAME = "kakeibo.csv"

def save_records():
    """記録一覧をCSVファイルに保存する"""
    with open(FILE_NAME, "w", encoding="utf-8", newline="") as f:
        fieldnames = ["date", "category", "amount", "memo"]
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(records)

csv.DictWriter は、辞書のリストをそのまま CSV の行として書き出せる便利なクラスです。records の要素（{"date": ..., "category": ..., "amount": ..., "memo": ...}）のキーと fieldnames を対応させることで、1件ずつ変換する手間が省けます。newline="" は、Windows で保存したときに空行が入るのを防ぐおまじないでした（第12章 12.3 を思い出しましょう）。

次に、起動時に CSV ファイルを読み込む load_records() を作ります。CSV から読み込んだ値はすべて文字列になるため、金額（amount）だけは int() で数値に戻す必要があります。また、初めてアプリを起動したときはファイルがまだ存在しないため、FileNotFoundError を except で受け止めて、記録が空のまま起動を続けます。except の中の pass は「何もしない」ことを表す文です。Python ではブロックの中身を空にできないため、何もしないときはこのように書きます。

kakeibo.py（続き） 
def load_records():
    """起動時にCSVファイルから記録を読み込む"""
    try:
        with open(FILE_NAME, "r", encoding="utf-8", newline="") as f:
            reader = csv.DictReader(f)
            for row in reader:
                row["amount"] = int(row["amount"])  # 文字列を数値に戻す
                records.append(row)
    except FileNotFoundError:
        pass  # ファイルがまだ無ければ空のまま始める

復習: global 宣言は要らない？

records はファイルの一番外側で定義されたグローバル変数でした（第10章 10.5）。load_records() の中では records.append(row) のように中身を変更するだけなので、第15章の add_record() と同じく global 宣言は不要です。もし関数内で records = [] のように代入し直す場合は global 宣言が必須になる点を覚えておきましょう。

作った2つの関数を、既存のコードにつなぎ込みます。add_record() は記録を追加した直後に保存し、main() は起動時に読み込み、終了時（メニュー「0」）にも念のため保存します。どちらも第15章のコードに「追加」とコメントした行を書き足すだけで、ほかの行はそのままです。

kakeibo.py（add_record を更新）

    amount = int(input("金額: "))  # 例外処理は16.3で追加する

    print("記録しました。")

16.2 カテゴリ別・月別集計

家計簿アプリの本来の目的は「何にいくら使ったか」を把握することです。第9章 9.4 で予告したとおり、辞書を使ってカテゴリごとの合計を集計します。キーにカテゴリ名、値に合計金額を持たせ、records を1件ずつ見ながら足し込んでいきます。

kakeibo.py（続き） 
def summarize_by_category():
    """カテゴリごとの支出合計を表示する"""
    totals = {}  # カテゴリ名をキーに合計金額を集計する辞書
    for record in records:
        category = record["category"]
        totals[category] = totals.get(category, 0) + record["amount"]

    print("--- カテゴリ別集計 ---")
    for category, total in totals.items():
        print(f"{category}: {total:,}円")

ポイントは totals.get(category, 0) です。第9章 9.1 で学んだとおり、辞書に無いキーを直接指定すると KeyError になりますが、get() はキーが無いときに指定した初期値（ここでは 0）を返してくれます。「まだ登場していないカテゴリなら 0 円から、既に登場していれば今までの合計から」金額を積み上げられるわけです。

同じ考え方で、月ごとの集計も作れます。date は "2026-04-01" のような文字列なので、スライス date[:7]（第5章 5.4）で先頭7文字を取り出せば "2026-04"（年月）だけを取り出せます。

kakeibo.py（続き） 
def summarize_by_month():
    """月ごとの支出合計を表示する"""
    totals = {}
    for record in records:
        month = record["date"][:7]  # "2026-04-01" -> "2026-04"
        totals[month] = totals.get(month, 0) + record["amount"]

    print("--- 月別集計 ---")
    for month, total in sorted(totals.items()):
        print(f"{month}: {total:,}円")

sorted(totals.items()) にしているのは、辞書の並び順が「データが登録された順」になるため、そのままでは月がバラバラに表示されることがあるからです。sorted()（第8章 8.3）でキー（年月の文字列）の昇順に並べ替えて表示します。最後に、2つの集計をまとめて呼び出す関数を用意し、第15章では「準備中です」と表示していたメニュー3番につなぎます。

kakeibo.py（続き・main を更新） 
def show_summary():
    """カテゴリ別・月別の集計をまとめて表示する"""
    summarize_by_category()
    print()
    summarize_by_month()

16.3 入力ミスへの対応

ここまでの add_record() は amount = int(input("金額: ")) と、単純に文字列を数値へ変換していました。しかし、利用者が誤って「千円」や空文字を入力すると、int() は変換できず ValueError が発生してアプリが強制終了してしまいます。第11章 11.4 で学んだ try・except を使い、正しい金額が入力されるまで聞き直す関数 input_amount() を作りましょう。

kakeibo.py（続き） 
def input_amount():
    """正しい金額が入力されるまで聞き直す"""
    while True:
        text = input("金額: ")
        try:
            amount = int(text)
            if amount <= 0:
                print("0より大きい金額を入力してください。")
                continue
            return amount
        except ValueError:
            print("数字で入力してください。")

while True のループの中で try を実行し、変換に成功して条件（0より大きい）も満たしたときだけ return でループを抜けます。数字に変換できなかった場合は except ValueError でメッセージを出してループの先頭に戻り、0 以下だった場合は continue で同じく聞き直します。add_record() の金額入力の1行を、この関数に置き換えましょう。

kakeibo.py（add_record を再更新） 
def add_record():
    """支出を1件入力してrecordsに追加し、CSVに保存する"""
    date = input("日付 (例: 2026-04-01): ")
    category = input("カテゴリ (例: 食費): ")
    amount = input_amount()  # 変更: 検査つきの入力関数に置き換え
    memo = input("メモ: ")
    record = {"date": date, "category": category, "amount": amount, "memo": memo}
    records.append(record)
    save_records()  # 記録を追加したらすぐ保存する

なお、日付はまだ入力されたとおりに保存しているため、abc・2026-99-99・4月1日 のような文字列も記録できてしまい、16.2 の月別集計（record["date"][:7]）でもおかしな「年月」として集計されてしまいます。日付のチェックは、章末の「やってみよう 16-1」で挑戦してみましょう。

注意: except は絞り込んで書く

ここでは except ValueError: のように、想定しているエラーの種類を明示しています。何でも受け止めてしまう except:（何も指定しない書き方）は、予期しないバグまで隠してしまうため避けましょう。第11章 11.3 の代表的なエラー一覧も見直しておくと安心です。

理解度確認クイズ

  1. Q1. totals[category] = totals.get(category, 0) + record["amount"] のように、辞書へ直接 totals[category] += ... と書かずに get() を使うのはなぜですか？

    回答を表示

    まだ一度も登場していないカテゴリの場合、辞書にそのキーが存在せず KeyError になってしまうからです。get(category, 0) は、キーが無いときに 0 を返してくれるため、「初回は0円から、2回目以降はこれまでの合計から」金額を安全に積み上げられます。

  2. Q2. input_amount() の中で except ValueError: はどんな場面で実行されますか？

    回答を表示

    int(text) が数値に変換できないとき（例: "千円" や空文字を入力したとき）に ValueError が発生し、except ValueError: の中の処理（メッセージを表示してループを続ける）が実行されます。try の中で例外が起きなければ except は実行されません。

  3. Q3. なぜ save_records() は「記録を追加したとき」と「アプリを終了するとき」の2か所から呼ばれているのですか？

    回答を表示

    記録を追加するたびに保存しておけば、途中でアプリが強制終了しても直前までのデータが残ります。終了時にもう一度保存するのは、その安全策に加えての「念のため」の保険です。どちらか1か所だけでもアプリは動きますが、両方あることでデータが消えるリスクをさらに減らせます。
