計算する - 四則演算とCOMPUTE

COBOL は「お金の計算」が得意な言語です。この章では、足し算・引き算・掛け算・割り算を行う命令と、数式で一度に計算できる COMPUTE を学びます。さらに、消費税の計算で欠かせない「端数の処理（切り捨てと四捨五入）」と、計算結果が入れ物に収まらない「桁あふれ」への備えを、実際の実行結果で確かめましょう。

この章で学ぶこと

  • ADD・SUBTRACT・MULTIPLY・DIVIDE を、TO / FROM / BY / INTO / GIVING の違いを意識して使い分けられる
  • COMPUTE で数式を書いて計算できる
  • ROUNDED による四捨五入と、既定の切り捨ての違いを説明できる
  • 桁あふれと 0 で割る失敗を、ON SIZE ERROR で検出して対処できる
  • COBOL の10進数計算が正確であることを、実行結果で確認できる

6.1 COBOLの計算命令の全体像

COBOL には、計算のための命令が5つあります。どれも英語の文のように読めます。まずは「どんな命令があるか」を、表で眺めてみましょう。

命令 意味 書き方の例
ADD 足す ADD 5 TO WS-A.
SUBTRACT 引く SUBTRACT 20 FROM WS-A.
MULTIPLY 掛ける MULTIPLY WS-PRICE BY WS-QTY GIVING WS-AMOUNT.
DIVIDE 割る DIVIDE 17 BY 5 GIVING WS-QUOT REMAINDER WS-REM.
COMPUTE 数式で計算する COMPUTE WS-R = (WS-A + WS-B) * WS-C.

「足し算だけなら ADD、複雑な式なら COMPUTE」と、おおまかに使い分けます。実際の現場では、単純な計算は ADD などの命令で、いくつもの演算が混ざる計算は COMPUTE で書くことが多くなります。

flowchart TD A{"どんな計算？"} -->|"足す・引くだけ"| B["ADD / SUBTRACT"] A -->|"掛ける・割るだけ"| C["MULTIPLY / DIVIDE"] A -->|"いくつもの演算が混ざる"| D["COMPUTE"] A -->|"あまりも知りたい"| E["DIVIDE ... REMAINDER"]

図の説明: 計算の種類に応じた命令の選び方の目安です。迷ったら、数式で書ける COMPUTE がいちばん読みやすくなります。

ヒント: 計算結果を入れる「箱」を先に用意する

第4章で学んだとおり、COBOL では計算に使う数字もすべて決まった桁数の箱（データ項目）に入れます。これから出てくる WS-A や WS-AMOUNT も、あらかじめ PIC 9(4) のように定義した項目です。計算結果がその箱に収まるかどうか（6.6 節）は、この章の大きなテーマです。

6.2 足し算と引き算 - ADD・SUBTRACT

ADD と SUBTRACT には、結果の置き場所が違う2つの形があります。違いは、元の値が書き換わるかどうかです。

TO / FROM の形

ADD 5 TO WS-A.

「A に 5 を足す」。結果は最後に書いた項目（A）を上書きします。貯金箱にお金を足すイメージです。

GIVING の形

ADD WS-A WS-B GIVING WS-C.

「A と B を足した結果を C に入れる」。A と B はそのまま残り、C だけが書き換わります。

実際に動かして確かめましょう。SUBTRACT も同じ考え方で、FROM の相手が書き換わり、GIVING を付けると別の項目に結果が入ります。

addsub.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. ADDSUB.
      * ADD と SUBTRACT の2つの形(TO/FROM と GIVING)を試す
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-A        PIC 9(4) VALUE 100.
       01  WS-B        PIC 9(4) VALUE 30.
       01  WS-C        PIC 9(4) VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PROC.
           ADD 5 TO WS-A.
           DISPLAY "ADD 5 TO A      : A=" WS-A.
           ADD WS-A WS-B GIVING WS-C.
           DISPLAY "ADD A B GIVING C: C=" WS-C.
           SUBTRACT 20 FROM WS-A.
           DISPLAY "SUBTRACT 20 FROM A: A=" WS-A.
           SUBTRACT WS-B FROM WS-A GIVING WS-C.
           DISPLAY "SUBTRACT B FROM A GIVING C: C=" WS-C.
           STOP RUN.

コンパイルして実行します。

ターミナル コマンド 
cobc -x addsub.cob
./addsub
実行結果 
ADD 5 TO A      : A=0105
ADD A B GIVING C: C=0135
SUBTRACT 20 FROM A: A=0085
SUBTRACT B FROM A GIVING C: C=0055

WS-A は 100 → 105 → 85 と TO / FROM の形で書き換わり、GIVING の形では WS-C にだけ結果が入っているのが分かります。PIC 9(4) の項目なので、表示は 4 桁（0105）です。

ヒント: SUBTRACT は「引かれる側」が後ろに来る

SUBTRACT WS-B FROM WS-A は「B を A から引く」と読みます。日本語の語順（A から B を引く）とは逆なので、FROM の後ろが引かれる側（結果が入る側）と覚えましょう。GIVING を付けた SUBTRACT WS-B FROM WS-A GIVING WS-C は、A - B の結果が C に入ります。

6.3 掛け算と割り算 - MULTIPLY・DIVIDE

MULTIPLY と DIVIDE は、BY・INTO・GIVING という言葉を組み合わせて書きます。特に DIVIDE は、BY と INTO で「どちらがどちらを割るのか」が逆になるので注意が必要です。

書き方 意味 書き換わる項目
MULTIPLY A BY B. B = A × B B
MULTIPLY A BY B GIVING C. C = A × B C
DIVIDE A INTO B. B = B ÷ A（A で B を割る） B
DIVIDE A BY B GIVING C. C = A ÷ B（A を B で割る） C
DIVIDE A BY B GIVING C REMAINDER D. C = 商、D = あまり C と D

注意: DIVIDE の BY の形は GIVING を省略できない

MULTIPLY は MULTIPLY A BY B. と GIVING を省略できますが、DIVIDE は同じ感覚で DIVIDE A BY B. と書くとコンパイルエラーになります。BY の形では必ず GIVING が必要です。結果を割られる側の項目に入れたいときは DIVIDE B INTO A. を使います。

flowchart LR A["DIVIDE 17 BY 5
GIVING QUOT
REMAINDER REM"] --> B["商 QUOT = 3"] A --> C["あまり REM = 2"]

図の説明: REMAINDER を付けると、割り算の商（割った答え）とあまりを別々の項目に受け取れます。「17 個のお菓子を 5 人で分けると 1 人 3 個で 2 個あまる」というイメージです。

muldiv.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. MULDIV.
      * MULTIPLY と DIVIDE の形と、あまり(REMAINDER)を試す
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-PRICE    PIC 9(5) VALUE 120.
       01  WS-QTY      PIC 9(3) VALUE 7.
       01  WS-AMOUNT   PIC 9(6) VALUE 0.
       01  WS-QUOT     PIC 9(4) VALUE 0.
       01  WS-REM      PIC 9(4) VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PROC.
           MULTIPLY WS-PRICE BY WS-QTY GIVING WS-AMOUNT.
           DISPLAY "120 x 7 = " WS-AMOUNT.
           MULTIPLY 2 BY WS-QTY.
           DISPLAY "QTY x 2 = " WS-QTY.
           DIVIDE 7 INTO WS-AMOUNT.
           DISPLAY "AMOUNT / 7 = " WS-AMOUNT.
           DIVIDE 17 BY 5 GIVING WS-QUOT REMAINDER WS-REM.
           DISPLAY "17 / 5 : QUOT=" WS-QUOT " REM=" WS-REM.
           STOP RUN.
実行結果 
120 x 7 = 000840
QTY x 2 = 014
AMOUNT / 7 = 000120
17 / 5 : QUOT=0003 REM=0002

実行結果のポイントを確認しましょう。

  • MULTIPLY WS-PRICE BY WS-QTY GIVING WS-AMOUNT で 120 × 7 = 840 が WS-AMOUNT に入ります。
  • MULTIPLY 2 BY WS-QTY は GIVING が無いので、WS-QTY 自身が 7 → 14 に書き換わります。
  • DIVIDE 7 INTO WS-AMOUNT は「840 を 7 で割る」ので 120 になります。
  • DIVIDE 17 BY 5 ... REMAINDER は商が 3、あまりが 2 です。

重要ポイント: 割り算の商は「入れ物の桁数」で決まる

17 ÷ 5 の本当の答えは 3.4 ですが、商を入れる項目が PIC 9(4)（整数だけ）なので、小数点以下は切り捨てられて 3 になります。小数を残したいときは、商の項目に PIC 9(4)V99 のように小数の桁を用意します（6.5 節で試します）。

6.4 数式で計算する - COMPUTE

COMPUTE は、算数や数学と同じように数式を書いて計算する命令です。COMPUTE 結果を入れる項目 = 数式. の形で書き、右辺の計算結果が左辺の項目に入ります。使える演算子は次のとおりです。

演算子 意味 計算の順番
( ) 括弧の中を先に計算 1番目（最優先）
** べき乗（B ** 2 は B の2乗） 2番目
*　/ 掛け算・割り算 3番目
+　- 足し算・引き算 4番目

算数と同じく「掛け算・割り算が先、足し算・引き算が後」で、括弧を使えば順番を変えられます。

compt.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. COMPT.
      * COMPUTE で数式を書く
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-A        PIC 9(4) VALUE 10.
       01  WS-B        PIC 9(4) VALUE 4.
       01  WS-C        PIC 9(4) VALUE 3.
       01  WS-R        PIC 9(6) VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PROC.
           COMPUTE WS-R = WS-A + WS-B * WS-C.
           DISPLAY "A + B * C     = " WS-R.
           COMPUTE WS-R = (WS-A + WS-B) * WS-C.
           DISPLAY "(A + B) * C   = " WS-R.
           COMPUTE WS-R = WS-B ** 2.
           DISPLAY "B ** 2        = " WS-R.
           COMPUTE WS-R = WS-A / WS-B.
           DISPLAY "A / B (10/4)  = " WS-R.
           STOP RUN.
実行結果 
A + B * C     = 000022
(A + B) * C   = 000042
B ** 2        = 000016
A / B (10/4)  = 000002

A + B * C は掛け算が先なので 10 + 4 × 3 = 22、括弧を付けた (A + B) * C は足し算が先なので (10 + 4) × 3 = 42 です。最後の 10 / 4 の本当の答えは 2.5 ですが、結果を入れる WS-R が整数の項目なので、小数点以下が切り捨てられて 2 になっています。

注意: 演算子の前後には半角スペースが必要

COBOL のデータ名にはハイフン（-）を使えるため、WS-A-WS-B のように詰めて書くと「1つの長い名前」と見なされてしまいます。+・-・*・/・** と = は、必ず前後を半角スペースで区切って書きましょう（括弧は例外で、内側にスペースを空けなくても構いません）。

6.5 端数の処理 - 切り捨てとROUNDED

消費税 10% の計算をすると、155 円 × 10% = 15.5 円 のように、円未満の端数が出ます。結果を入れる項目に小数の桁が無ければ、端数をどう扱うかを決めなければなりません。COBOL では次のようになります。

何も書かない（既定）

入りきらない小数点以下は切り捨てられます。15.5 → 15 になります。

ROUNDED を付ける

結果の項目の桁数で四捨五入されます。15.5 → 16 になります。

ROUNDED（ラウンデッド）は、結果を受け取る項目名の直後に書きます。切り捨てと四捨五入を並べて動かしてみましょう。

roundt.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. ROUNDT.
      * 端数処理: 切り捨て(既定)と ROUNDED(四捨五入)
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-PRICE    PIC 9(5) VALUE 155.
       01  WS-TAX1     PIC 9(5) VALUE 0.
       01  WS-TAX2     PIC 9(5) VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PROC.
           COMPUTE WS-TAX1 = WS-PRICE * 0.1.
           COMPUTE WS-TAX2 ROUNDED = WS-PRICE * 0.1.
           DISPLAY "155 * 10% 切り捨て : " WS-TAX1.
           DISPLAY "155 * 10% 四捨五入 : " WS-TAX2.
           STOP RUN.
実行結果 
155 * 10% 切り捨て : 00015
155 * 10% 四捨五入 : 00016

同じ計算式でも、ROUNDED の有無で消費税が 1 円違います。いくつかの価格で比べた結果が次の表です（COMPUTE 税 = 価格 * 0.1 を実際に動かした結果）。

価格 本当の答え 切り捨て（既定） ROUNDED（四捨五入）
154 円 15.4 15 15
155 円 15.5 15 16
159 円 15.9 15 16
flowchart LR A["計算の本当の答え
15.5"] --> B{"ROUNDED
を付けた？"} B -->|"付けない"| C["小数点以下を切り捨て
結果は 15"] B -->|"付ける"| D["結果の桁数で四捨五入
結果は 16"]

図の説明: ROUNDED の有無で、端数の扱いが「切り捨て」か「四捨五入」かに分かれます。

重要ポイント: 端数処理は「業務のルール」で決まる

消費税の端数を切り捨てにするか、四捨五入にするか、切り上げにするかは、会社や取引の決まりごとです。COBOL は書いたとおりに計算するだけなので、仕様書を確認してROUNDED を付けるかどうかを決めます。本ガイドでは、消費税は ROUNDED（四捨五入）で計算します。

小数の桁がある結果を受け取る

結果の項目に小数の桁（V99 など）があれば、その桁数に合わせて端数が処理されます。次のプログラムで、同じ 20 ÷ 3 を、切り捨て（既定）と四捨五入（ROUNDED）で小数第2位まで求めて比べます。

vdisp.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. VDISP.
      * 小数付き項目の表示と端数処理
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-X        PIC 9(3)V99 VALUE 0.
       01  WS-Y        PIC 9(3)V99 VALUE 0.
       01  WS-OUT      PIC ZZ9.99.
       PROCEDURE DIVISION.
       MAIN-PROC.
           COMPUTE WS-X = 20 / 3.
           DISPLAY "20 / 3 切り捨て    : " WS-X.
           COMPUTE WS-Y ROUNDED = 20 / 3.
           DISPLAY "20 / 3 四捨五入    : " WS-Y.
           MOVE WS-Y TO WS-OUT.
           DISPLAY "編集項目で表示     : " WS-OUT.
           STOP RUN.
実行結果 
20 / 3 切り捨て    : 006.66
20 / 3 四捨五入    : 006.67
編集項目で表示     :   6.67
  • 20 / 3 は 6.666... です。小数第2位までしか入らないので、既定では第3位以降が切り捨てられて 006.66。
  • 同じ 20 / 3 でも、ROUNDED を付けると小数第3位が四捨五入されて 006.67。
  • 同じ計算式でも、ROUNDED の有無で最後の桁が 1 違います。

ヒント: 小数付きの項目の DISPLAY と、人に見せる表示

GnuCOBOL では、PIC 9(3)V99 のような小数付きの数字項目を DISPLAY すると、003.33 のように小数点付きで表示されます。これは GnuCOBOL の動作で、メインフレームの COBOL では小数点は表示されず 00333 のようになります。また、上のとおり先頭の 0 も残ります。そこで、人に見せる表示は第5章で学んだ編集項目に MOVE してから DISPLAY するのが基本です。実行結果の3行目（[ 6.67]）は、PIC ZZ9.99 の編集項目を通したものです。

6.6 桁あふれへの備え - ON SIZE ERROR

計算結果が、受け取る項目の桁数に収まらないことがあります。これを桁あふれと呼びます。PIC 9(3)（3桁）の項目に 950 が入っているときに 100 を足すと、答えは 1050 の4桁になり、入れ物に収まりません。

桁あふれは整数部（上の桁）が足りない場合のことです。小数点以下が入りきらない場合（6.5 節の端数処理）は SIZE ERROR にはなりません。

まず、何も対策をしない場合と、ON SIZE ERROR（桁あふれが起きたときの処理）を書いた場合を比べます。

sizeerr.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. SIZEERR.
      * 桁あふれ: ON SIZE ERROR なしとありを比べる
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-N        PIC 9(3) VALUE 950.
       01  WS-M        PIC 9(3) VALUE 950.
       PROCEDURE DIVISION.
       MAIN-PROC.
           ADD 100 TO WS-N.
           DISPLAY "SIZE ERROR なし: " WS-N.
           ADD 100 TO WS-M
               ON SIZE ERROR
                   DISPLAY "桁あふれ。値は変更なし: " WS-M
               NOT ON SIZE ERROR
                   DISPLAY "加算できました: " WS-M
           END-ADD.
           STOP RUN.
実行結果 
SIZE ERROR なし: 050
桁あふれ。値は変更なし: 950
  • 対策なし: 1050 の上位の桁が切り捨てられ、050 が入ります（GnuCOBOL での結果。規格・処理系によっては動作が異なることがあります）。エラーにはならず、間違った値がそのまま残ってしまいます。
  • ON SIZE ERROR あり: 桁あふれが検出され、ON SIZE ERROR の処理が実行されます。そして項目の値は書き換えられず、元の 950 のままです。

注意: 桁あふれは黙って間違った値になる

COBOL は、ON SIZE ERROR を書かないと、桁あふれしてもエラーを知らせてくれません。売上金額や残高が、気づかないうちに桁が欠けた値になる危険があります。金額の計算では、桁あふれが起こりうる場所に ON SIZE ERROR を書き、起きたときの処理（メッセージの表示やプログラムの中止など）を用意します。

ON SIZE ERROR の書き方

ON SIZE ERROR は、ADD・SUBTRACT・MULTIPLY・DIVIDE・COMPUTE のどれにも付けられます。書く位置と、終わりの書き方が大切です。

flowchart TD A["計算を実行"] --> B{"結果が項目に
収まる？"} B -->|"収まる"| C["項目に結果を入れる
NOT ON SIZE ERROR の処理"] B -->|"収まらない"| D["項目は書き換えない
ON SIZE ERROR の処理"] C --> E["END-ADD などで終了"] D --> E

図の説明: ON SIZE ERROR を付けた計算の流れです。収まれば NOT ON SIZE ERROR 側、収まらなければ ON SIZE ERROR 側の処理が実行されます。

部分 役割
ON SIZE ERROR 桁あふれ（または 0 で割るなどの計算できない場合）に実行する処理。
NOT ON SIZE ERROR 正常に計算できたときに実行する処理（省略してよい）。
END-ADD など 「この計算命令はここまで」を示すスコープ終了符。END-ADD、END-SUBTRACT、END-MULTIPLY、END-DIVIDE、END-COMPUTE がある。

ON SIZE ERROR を書くときは、END-ADD などで命令の終わりをはっきり示し、END-xxx で閉じる文の内側（ON SIZE ERROR や NOT ON SIZE ERROR の中）にはピリオドを書かず、END-xxx の後ろに1つだけ置きます。内側の DISPLAY の後ろにピリオドを書くと、そこで文全体が終わってしまうためです（ピリオドの詳しい扱いは第7章で学びます）。0 で割る失敗は、同じ ON SIZE ERROR で検出できます。

divzero.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DIVZERO.
      * 0で割ると SIZE ERROR になる
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-TOTAL    PIC 9(5) VALUE 1000.
       01  WS-COUNT    PIC 9(3) VALUE 0.
       01  WS-AVG      PIC 9(5) VALUE 99999.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DIVIDE WS-TOTAL BY WS-COUNT GIVING WS-AVG
               ON SIZE ERROR
                   DISPLAY "0では割れません"
               NOT ON SIZE ERROR
                   DISPLAY "平均: " WS-AVG
           END-DIVIDE.
           DISPLAY "AVG は今も " WS-AVG.
           COMPUTE WS-AVG = WS-TOTAL * 1000
               ON SIZE ERROR
                   DISPLAY "COMPUTEも桁あふれ"
           END-COMPUTE.
           STOP RUN.
実行結果 
0では割れません
AVG は今も 99999
COMPUTEも桁あふれ

WS-COUNT が 0 なので割り算は実行されず、ON SIZE ERROR 側の「0では割れません」が表示されています。WS-AVG は書き換えられず 99999 のままです。最後の COMPUTE は 1000 × 1000 = 1000000 で5桁に収まらないため、こちらも桁あふれとして検出されました。

ヒント: 日本語メッセージは短めに

固定形式では1行が72桁まで、UTF-8 では日本語1文字が3バイトです。DISPLAY に長い日本語を書くと72桁を超えてコンパイルエラーになるので、1つのリテラルは日本語12文字程度までにし、長いときは DISPLAY を2つに分けましょう。

6.7 10進数計算の強み - 0.1を10回足す

第1章で「COBOL は計算が正確」と紹介しました。それを確かめましょう。0.1 を 10 回足せば、算数では 1.0 ちょうどになるはずです。

dect.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DECT.
      * 0.1 を10回足すと 1.0 ちょうどになる
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-SUM      PIC 9V9 VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PROC.
           ADD 0.1 TO WS-SUM.
           ADD 0.1 TO WS-SUM.
           ADD 0.1 TO WS-SUM.
           ADD 0.1 TO WS-SUM.
           ADD 0.1 TO WS-SUM.
           ADD 0.1 TO WS-SUM.
           ADD 0.1 TO WS-SUM.
           ADD 0.1 TO WS-SUM.
           ADD 0.1 TO WS-SUM.

実行結果 
0.1 を10回足した合計: 1.0

（繰り返しは第8章の PERFORM で学ぶので、ここでは ADD を10行並べています。）COBOL では、きっちり 1.0 になりました。COBOL は数値を、人間が使う10進数の桁のまま扱うからです。

COBOL（10進数）

「0.1」を「小数第1位の1」としてそのまま保持して計算するため、足し算を何回繰り返しても誤差がたまりません。

浮動小数点（2進数）

多くの言語が小数に使う方式です。0.1 は2進数で割り切れない数のため、わずかな誤差が生じ、足し続けると 1.0 とずれることがあります。

たとえば、1円未満の誤差が積み重なって、何万件もの請求の合計が1円合わなくなると、経理の現場では大問題です。COBOL が金融システムで信頼されてきた理由のひとつが、この正確さです。

重要ポイント: この章のまとめ

  • ・TO / FROM は最後の項目を上書き、GIVING は別の項目に結果を入れる。
  • ・DIVIDE は INTO（後ろを割る）と BY（前を割る）の向きに注意。あまりは REMAINDER。
  • ・複雑な計算は COMPUTE。演算子の前後に半角スペース。
  • ・端数は既定で切り捨て、ROUNDEDで四捨五入。
  • ・桁あふれは黙って起きる。ON SIZE ERROR ... END-xxx で備える。

やってみよう 6-1: 小計・消費税・税込合計を計算しよう

文房具店の売上計算です。単価 175 円のノートを 3 冊売ったときの、小計・消費税（10%、四捨五入）・税込合計を計算し、編集項目で見やすく表示するプログラム shoukei.cob を作りましょう。

手順

  • 1 単価（WS-PRICE）・数量（WS-QTY）・小計・消費税・税込合計の項目を定義し、単価と数量に VALUE で初期値を入れる。
  • 2 MULTIPLY で小計を求める。COMPUTE ... ROUNDED で消費税（小計の 10%）を求める。ADD ... GIVING で税込合計を求める。
  • 3 編集項目（PIC Z,ZZZ,ZZ9）に MOVE してから「円」を付けて表示する。
  • 4 ROUNDED を外して実行し、消費税が 1 円変わることを確かめる（小計 525 円の 10% は 52.5 円）。

解答例（コンパイル・実行して確認済み）

shoukei.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. SHOUKEI.
      * 小計・消費税(四捨五入)・税込合計を求める
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-PRICE    PIC 9(5) VALUE 175.
       01  WS-QTY      PIC 9(3) VALUE 3.
       01  WS-SUBTOTAL PIC 9(7) VALUE 0.
       01  WS-TAX      PIC 9(7) VALUE 0.
       01  WS-TOTAL    PIC 9(7) VALUE 0.
       01  WS-ED       PIC Z,ZZZ,ZZ9.
       PROCEDURE DIVISION.
       MAIN-PROC.
           MULTIPLY WS-PRICE BY WS-QTY GIVING WS-SUBTOTAL.
           COMPUTE WS-TAX ROUNDED = WS-SUBTOTAL * 0.1.
           ADD WS-SUBTOTAL WS-TAX GIVING WS-TOTAL.
           MOVE WS-SUBTOTAL TO WS-ED.
           DISPLAY "小計    : " WS-ED " 円".
           MOVE WS-TAX TO WS-ED.
           DISPLAY "消費税  : " WS-ED " 円".
           MOVE WS-TOTAL TO WS-ED.
           DISPLAY "税込合計: " WS-ED " 円".
           STOP RUN.
実行結果 
小計    :       525 円
消費税  :        53 円
税込合計:       578 円

ROUNDED を外すと消費税は 52 円、税込合計は 577 円になります。WS-ED は編集項目なので、計算には使わず表示専用にしている点に注目してください。

理解度確認クイズ

  • Q1. ADD WS-A TO WS-B. と ADD WS-A WS-B GIVING WS-C. では、計算後に値が変わる項目がそれぞれどれになりますか？

    回答を表示

    前者は TO の後ろの WS-B が上書きされます（WS-A は変わらない）。後者は GIVING の後ろの WS-C だけが書き換わり、WS-A と WS-B はそのまま残ります。

  • Q2. WS-A = 10、WS-B = 4、WS-C = 3 のとき、COMPUTE WS-R = (WS-A + WS-B) * WS-C. の結果はいくつですか？ 括弧を外した場合はどうなりますか？

    回答を表示

    括弧の中を先に計算して (10 + 4) × 3 = 42 です。括弧を外すと掛け算が先になり、10 + 4 × 3 = 22 になります。

  • Q3. 結果を PIC 9(5) の項目に入れるとき、COMPUTE WS-TAX = 155 * 0.1 と COMPUTE WS-TAX ROUNDED = 155 * 0.1 の結果はそれぞれいくつですか？

    回答を表示

    本当の答えは 15.5 です。ROUNDED が無いと小数点以下が切り捨てられて 15、ROUNDED を付けると四捨五入されて 16 になります。

  • Q4. PIC 9(3) の項目に 950 が入っているとき、ON SIZE ERROR を書かずに 100 を足すとどうなりますか？ ON SIZE ERROR を書くとどう変わりますか？

    回答を表示

    書かないと 1050 の上位桁が切り捨てられ、050 という誤った値が、エラーも出ずに入ってしまいます。ON SIZE ERROR を書くと桁あふれが検出されて ON SIZE ERROR 側の処理が実行され、項目の値は書き換わらず 950 のままです。0 で割る失敗も同じ仕組みで検出できます。
