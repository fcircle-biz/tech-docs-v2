COBOLの世界へようこそ - 業務システムを支える言語

COBOL（コボル）は、60年以上前に生まれ、今も銀行や保険会社、役所などの大切なシステムを動かし続けているプログラミング言語です。この章ではまだプログラムは書きません。「COBOLとはどんな言語で、どこで、なぜ使われているのか」を理解し、これから学ぶ全体の地図を手に入れましょう。

この章で学ぶこと

  • COBOLがどんな目的で生まれ、どんな特徴を持つ言語なのかを説明できる
  • COBOLが使われている業界・システムと、今も使われ続けている理由を説明できる
  • 「バッチ処理」と「オンライン処理」の違いを、身近な例で説明できる
  • 本ガイドで使う GnuCOBOL と、学習の進め方・コード例の読み方を把握する

このガイドのコード例の読み方

各コード例のヘッダーには、左にファイル名、その横に「コードを書く場所」を表すラベルを付けています。ラベルに出てくる言葉の細かい意味は、今は分からなくて大丈夫です。コンパイル（COBOL を実行できる形に変換すること）と cobc コマンドは第2章、DIVISION（部）は第3章で学びます。

  • 完全なプログラムそのまま .cob ファイルに保存し、cobc -x でコンパイルして実行できます。
  • DATA DIVISIONの抜粋データの定義（使うデータの入れ物を決める部分。WORKING-STORAGE SECTION など）に書く部分だけを示しています。
  • PROCEDURE DIVISIONの抜粋処理の手順（命令を順番に書く部分。PROCEDURE DIVISION）に書く部分だけを示しています。
  • コピーブック/データファイル共通のデータ定義（.cpy）や、プログラムが読み込むデータです。

COBOL のコードは行の先頭の空白（何桁目から書くか）に意味があります。コピーして使うときは、行頭の空白を消さないでください（理由は第3章で学びます）。

1.1 COBOLとは何か

COBOL（コボル）は、1959年に事務処理（ビジネス）のために作られたプログラミング言語です。名前は COmmon Business-Oriented Language の頭文字で、日本語にすると「共通の事務処理向け言語」という意味になります。

当時のコンピュータは、メーカーごとに命令の書き方がばらばらでした。そこでアメリカの政府機関やコンピュータメーカー、利用企業が集まった委員会が、「どのメーカーのコンピュータでも動き、技術者でない人にも読める事務処理用の言語」として COBOL を設計しました。給与計算、請求書の作成、在庫の集計といったお金とデータを正確に扱う仕事が、COBOL の得意分野です。

英語の文章のように読める

「ADD（足す）」「MOVE（移す）」など、英単語を並べて命令を書きます。記号が少なく、処理の意味を想像しやすい言語です。

お金の計算が正確

数値を10進数のまま扱えるため、金額の計算で小さな誤差が出にくく、銀行や保険の計算に向いています。

大量データの一括処理が得意

何十万件もの取引データを、決まった形式で1件ずつ確実に処理する仕事に強い言語です。

COBOLのコードをのぞいてみよう

まだ書き方を覚える必要はありません。COBOL がどれくらい「英語の文章っぽい」のか、雰囲気だけ見てみましょう。次のコードは、単価に数量を掛けて金額を求め、合計が1万円を超えたらメッセージを出す処理です。

売上の計算（イメージ） PROCEDURE DIVISIONの抜粋 
      * 単価に数量を掛けて金額を求め、合計に足す
           MULTIPLY WS-PRICE BY WS-QTY GIVING WS-AMOUNT.
           ADD WS-AMOUNT TO WS-TOTAL.
      * 合計が1万円を超えたらメッセージを表示する
           IF WS-TOTAL > 10000
               DISPLAY "合計が1万円を超えました"
           END-IF.

MULTIPLY WS-PRICE BY WS-QTY GIVING WS-AMOUNT は「単価（PRICE）に数量（QTY）を掛けて、金額（AMOUNT）に入れる」、ADD WS-AMOUNT TO WS-TOTAL は「金額を合計（TOTAL）に足す」と、英語の文章としてそのまま読めます。空白6個に続く7桁目に * がある行は、人間向けのメモ（コメント）です（桁のルールは第3章で学びます）。名前の先頭の WS- は「作業用のデータ」を表す目印です（第4章で学びます）。

用語: プログラミング言語とプログラム

コンピュータに「何を、どの順番でやってほしいか」を書いた指示書をプログラムと呼び、その指示書を書くための決まった言葉をプログラミング言語と呼びます。料理にたとえると、プログラムは「レシピ」、プログラミング言語は「レシピを書くときの決まった書き方」です。COBOL は、事務処理のレシピを書くのが得意な言語というわけです。

1.2 COBOLはどこで使われているのか

COBOL は、私たちの目にはふれないところで、社会の大切な仕組みを動かしています。特に多いのは、たくさんのお金とデータを、間違いなく処理しなければならない分野です。

分野 COBOLで動いているシステムの例
銀行 預金・振込・口座残高を管理する「勘定系システム」、利息の計算
保険・証券 保険料や保険金の計算、契約の管理、株式取引の精算
クレジットカード 利用明細の集計、毎月の請求金額の計算
官公庁・自治体 税金・年金・住民情報など、行政の基幹システム
一般企業 給与計算、販売管理、在庫管理、会計などの基幹システム

こうしたシステムの多くは、メインフレーム（大型汎用機）と呼ばれる、とても信頼性の高い大型コンピュータの上で動いています。とくに銀行の勘定系（預金や振込などのお金の出入りを記録する、中核のシステム）のように、止まることが許されない金融機関のシステムでは、今も COBOL のプログラムが使われ続けています。

用語: 基幹システムとメインフレーム

基幹システムとは、会社や組織の中心となる業務（お金・商品・人の管理など）を支えるシステムのことで、止まると業務そのものが止まってしまいます。メインフレームは、こうした基幹システムを長年にわたり止めずに動かすために作られた大型のコンピュータです。パソコンとは比べものにならないほど大量の処理を、安定して続けられるのが特長です。

1.3 なぜ今もCOBOLが使われ続けるのか

新しいプログラミング言語が次々に生まれているのに、なぜ60年以上前の言語が今も現役なのでしょうか。主な理由は次の4つです。

1. 計算が正確

COBOL は数値を10進数の桁のまま扱います。1円の誤差も許されない金額計算に、もともと向いた作りになっています（第6章で確かめます）。

2. 大量処理に強い

決まった形式のデータを1件ずつ順番に処理する仕事を、メインフレームと組み合わせて高速・確実にこなせます。

3. 長年の実績と信頼

何十年も問題なく動き、業務のルールが細かく作り込まれたプログラムは、それ自体が会社の大切な財産（資産）です。

4. 作り直しが難しい

巨大なシステムを別の言語で作り直すには、莫大な費用と時間がかかり、移行中のトラブルのリスクもあります。

一方で、課題もあります。COBOL のシステムを作ってきた技術者の多くが定年を迎え、COBOL を読める人が足りなくなっているのです。日本でも、経済産業省が2018年に公表した「DXレポート」で、古い基幹システムを放置すると2025年以降に大きな経済的損失が生じるおそれがある（いわゆる「2025年の崖」）と指摘されました。

現在も多くの企業が、COBOL のシステムを保守しながら、新しい仕組みへの移行（モダナイゼーション）を進めています。保守を続けるにも、別の言語へ移すにも、まず今動いている COBOL のプログラムを読んで理解できる人が必要です。COBOL を学ぶことは、こうした現場で頼りにされる力を身につけることにつながります。

重要ポイント

COBOL が使われ続けているのは「古いから仕方なく」だけではありません。正確な計算と大量データの確実な処理という、業務システムにとって最も大切な性質を持っているからです。そして、その COBOL を読み書きできる人材が不足しているからこそ、学ぶ価値があります。

1.4 バッチ処理とオンライン処理

業務システムの処理は、大きくバッチ処理とオンライン処理の2種類に分けられます。COBOL はどちらにも使われますが、特に得意なのがバッチ処理です。

項目 バッチ処理 オンライン処理
処理のしかた ためておいたデータを、決まった時刻にまとめて処理する 利用者の操作に合わせて、その場ですぐに処理する
身近な例 毎月の給与計算、電気料金の請求、1日の売上集計 ATM での引き出し、座席の予約、ネットショッピングの注文
たとえるなら 1日分の洗濯物をまとめて夜に洗う 汚れたらその場ですぐ拭く
flowchart TB subgraph batch["バッチ処理"] B1["日中に取引データをためる"] --> B2["夜間にまとめて処理"] B2 --> B3["翌朝に結果を確認"] end subgraph online["オンライン処理"] O1["ATMで引き出しを操作"] --> O2["その場で残高を更新"] O2 --> O3["すぐに結果を表示"] end

図の説明: バッチ処理はデータをためてからまとめて処理し、オンライン処理は操作のたびにすぐ処理します。

バッチ処理のプログラムは、多くの場合「ファイルを読む → 計算・集計する → ファイルや帳票に書き出す」という形をしています。本ガイドの最終章（第14章）でも、この形の「売上集計バッチ」を完成させます。

flowchart LR A["入力ファイル
1日分の売上データ"] --> B["COBOLプログラム
集計・計算"] B --> C["出力ファイル
集計結果"] B --> D["帳票
売上日報"]

図の説明: バッチ処理の基本形です。COBOL プログラムが入力ファイルのデータを1件ずつ読んで集計し、結果をファイルや帳票（紙や画面に出す一覧表）に書き出します。

用語: 帳票（ちょうひょう）

帳票とは、請求書・明細書・集計表など、業務で使う一覧表や書類のことです。決まった位置に決まった桁数で文字や数字を並べて出力するのが特徴で、COBOL はこうした帳票を作るのが得意です。

1.5 ほかのプログラミング言語との違い

Python や Java などの言語の名前を聞いたことがあるかもしれません。それらと比べると、COBOL には次のような違いがあります。ほかの言語を知らなくても大丈夫です。「COBOL はこういう考え方をする言語なんだ」とつかめれば十分です。

項目 COBOL Python・Java などの言語
書き方 英語の文章に近い（ADD A TO B.） 記号や数式が中心（b = b + a）
データの扱い 最初に「何桁の箱か」を決める（固定長） 必要に応じて大きさが変わることが多い
数値の計算 10進数のまま正確に計算できる 小数の計算で小さな誤差が出ることがある
得意な分野 大量データの一括処理・帳票作成 Web・スマホアプリ・AI など幅広い
主な動作環境 メインフレーム、業務用サーバー パソコン、サーバー、クラウド

なかでも大きな違いは、データの桁数を最初にきっちり決める点です。COBOL では「この項目は数字5桁」「この項目は文字10桁」というように、申込用紙のマス目を作るようにデータの入れ物を用意してから処理を書きます。少し窮屈に感じるかもしれませんが、そのおかげで「決まった形式のデータを大量に、正確に処理する」ことが得意なのです（第4章で詳しく学びます）。

1.6 COBOLの規格と処理系

COBOL は、どのコンピュータでも同じように書けるよう、規格（共通の文法のルール）が定められてきました。時代に合わせて少しずつ機能が追加されています。

flowchart LR A["1959年
COBOLの誕生"] --> B["1968年・1974年
標準規格の制定"] B --> C["1985年
COBOL 85
構造化の機能"] C --> D["2002年
オブジェクト指向"] D --> E["2023年
最新のISO規格"]

図の説明: COBOL の規格の主な歩みです。今の現場で動いているプログラムの多くは、COBOL 85 の書き方が基本になっています。

特に重要なのが COBOL 85 です。この規格で END-IF のような「処理の区切りを明示する書き方」が加わり、読みやすく整理されたプログラムを書けるようになりました。本ガイドも、この COBOL 85 の書き方を中心に学びます。

また、COBOL のプログラムをコンピュータが実行できる形に変換するソフトウェアを処理系（コンパイラ）と呼びます。COBOL には、次のような処理系があります。

処理系 提供元 主な用途
Enterprise COBOL for z/OS IBM IBM のメインフレーム（z/OS）上の基幹システム
Visual COBOL Rocket Software（2024年に Micro Focus の COBOL 事業を取得） Windows・Linux サーバーでの開発、メインフレームからの移行
NetCOBOL 富士通 国内の業務システム（Windows・Linux サーバーなど）
GnuCOBOL GNU プロジェクト（オープンソース） 無償で使え、パソコンで学習・開発できる（本ガイドで使用）

本ガイドでは、無償で誰でも使える GnuCOBOL（グニューコボル）を使います。メインフレームがなくても、自分のパソコンで COBOL のプログラムを書いて動かせます。処理系によって細かな違いはありますが、本ガイドで学ぶ基本の文法は、メインフレームの COBOL でもほぼそのまま通用します。違いがある箇所では、その都度お知らせします。

ヒント: 学習のコツ

プログラミングは、読むだけではなかなか身につきません。コード例は必ず自分の手で入力して動かしてみてください。わざと少し書き換えて、結果がどう変わるかを試すのもおすすめです。エラーが出ても心配はいりません。エラーを直す経験こそが、いちばんの上達の近道です。

やってみよう 1-1: 身の回りの「COBOLが動いていそうなシステム」を探そう

COBOL が使われていそうなシステムを考えることで、業務システムとバッチ処理のイメージをつかみます。紙やメモアプリに書き出してみましょう。

手順

  • 1 お金やたくさんのデータを扱う、身の回りのサービスやシステムを3つ挙げる（1.2 の表を参考にしてよい）。
  • 2 それぞれについて、処理が「バッチ処理」か「オンライン処理」か（または両方か）を考える。
  • 3 バッチ処理だと考えたものについて、「入力ファイル」「処理」「出力（ファイル・帳票）」が何にあたるかを書いてみる。

解答例

  • ・銀行の ATM: 引き出しはその場で残高を更新するオンライン処理。夜間の利息計算や取引の集計はバッチ処理。
  • ・電気料金の請求: 1か月分の使用量データ（入力）から料金を計算し（処理）、請求書（帳票）を作るバッチ処理。
  • ・クレジットカードの利用明細: 買い物の承認はオンライン処理、毎月の請求額の集計と明細の作成はバッチ処理。

理解度確認クイズ

  • Q1. COBOL という名前は何の頭文字ですか？ また、どんな目的で作られた言語ですか？

    回答を表示

    COmmon Business-Oriented Language（共通の事務処理向け言語）の頭文字です。給与計算や請求書の作成など、お金とデータを正確に扱う事務処理（ビジネス）のために、どのメーカーのコンピュータでも動く共通の言語として1959年に作られました。

  • Q2. COBOL が今も多くの基幹システムで使われ続けている理由を、2つ挙げてください。

    回答を表示

    次のうちから2つ挙げられれば正解です。(1) 10進数のまま扱えるため金額の計算が正確、(2) 大量データの一括処理が得意、(3) 長年動いてきた実績と信頼がある、(4) 巨大なシステムの作り直しには莫大な費用とリスクがかかる。

  • Q3. 「毎月の給与計算」と「ATM での引き出し」は、それぞれバッチ処理とオンライン処理のどちらですか？

    回答を表示

    毎月の給与計算は、1か月分の勤務データをまとめて処理するバッチ処理です。ATM での引き出しは、操作に合わせてその場で残高を更新するオンライン処理です。

  • Q4. 本ガイドで使う COBOL の処理系は何ですか？ また、それを使う理由は何ですか？

    回答を表示

    GnuCOBOL です。オープンソースで無償で使え、メインフレームがなくても自分のパソコンで COBOL を書いて動かせるからです。基本の文法はメインフレームの COBOL でもほぼそのまま通用します。
