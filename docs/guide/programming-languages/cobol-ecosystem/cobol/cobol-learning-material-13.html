プログラムを部品に分ける - CALLとCOPY

実際の業務システムは、1本の巨大なプログラムではなく、たくさんの小さなプログラム（部品）の組み合わせでできています。この章では、共通の処理を副プログラムとして切り出して CALL で呼び出す方法と、データ定義をコピーブックにまとめて COPY で共有する方法を学びます。

この章で学ぶこと

  • 処理を部品（副プログラム）に分ける理由を説明できる
  • 連絡節（LINKAGE SECTION）・USING・GOBACK を使って副プログラムを作り、CALL で呼び出せる
  • 引数が「名前ではなく順番」で対応することと、BY REFERENCE と BY CONTENT の違いを説明できる
  • COPY 文とコピーブックでデータ定義を共有し、-I 付きでコンパイルできる

13.1 なぜプログラムを部品に分けるのか

ここまでの章では、1つのプログラムの中にすべての処理を書いてきました。しかし、プログラムが大きくなると困ったことが起こります。たとえば「消費税を計算する処理」を、売上の集計プログラムにも、請求書の作成プログラムにも、見積書の作成プログラムにも書いていたらどうでしょう。税率が変わったときに、すべてのプログラムを探して直さなければなりません。直し忘れがあれば、プログラムごとに金額が食い違ってしまいます。

そこで、よく使う処理を別のプログラムとして切り出し、必要なときに呼び出すという方法を使います。切り出した小さなプログラムを副プログラム（サブプログラム）、呼び出す側を主プログラムと呼びます。

専門の係に仕事を頼む

会社には「経理係」「総務係」のような専門の係があります。副プログラムは、その専門の係です。主プログラムは「この金額の税金を計算してください」と仕事を頼み、結果だけを受け取ります。

同じ処理を何度も書かない

税計算は CALCTAX、日付のチェックは CHKDATE のように1か所にまとめます。どのプログラムからでも呼び出せるので、書き間違いも直し忘れも防げます。

分担して作れる

部品ごとに担当者を分けて同時に開発できます。部品は単独でテストできるため、不具合の場所も見つけやすくなります。

flowchart TD M["主プログラム
MAIN"] -->|CALL| T["副プログラム
CALCTAX 税計算"] M -->|CALL| D["副プログラム
CHKDATE 日付チェック"] M2["別の主プログラム
請求書作成"] -->|CALL| T M2 -->|CALL| D

図の説明: 複数の主プログラムが、同じ副プログラム（部品）を共有して使います。部品を直せば、呼び出すすべてのプログラムに反映されます。

もう1つの共有方法がコピーブックです。たとえば第12章で使った売上レコード SALES-REC の定義を、読み込みプログラムにも集計プログラムにも同じ内容で書く必要があります。コピーブックは、こうしたデータの定義を1つのファイルにまとめ、各プログラムに「コピーして貼り付ける」仕組みです。

仕組み何を共有するか使う命令たとえるなら
副プログラム処理（手順）CALL専門の係に仕事を頼む
コピーブックデータの定義（書式）COPY共通の申込用紙の様式をコピーして使う

13.2 副プログラムの作り方

まず、消費税を計算する副プログラム CALCTAX を作ってみましょう。税抜金額を受け取り、10%の消費税（四捨五入）を返すだけの小さなプログラムです。

calctax.cob 完全なプログラム（副プログラム） 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. CALCTAX.
      * 税抜金額から消費税10%を求める副プログラム
       DATA DIVISION.
       LINKAGE SECTION.
       01  LK-AMOUNT       PIC 9(7).
       01  LK-TAX          PIC 9(7).
       PROCEDURE DIVISION USING LK-AMOUNT LK-TAX.
       MAIN-PROC.
           COMPUTE LK-TAX ROUNDED = LK-AMOUNT * 0.1.
           GOBACK.

ヒント: 副プログラムは単独では実行できない

副プログラムは呼び出される側の部品なので、cobc -x calctax.cob のように単独で実行ファイルにしようとすると executable program requested but PROCEDURE/ENTRY has USING clause というエラーになります。13.3 で、呼び出す側の主プログラムと一緒にコンパイルします。

これまでのプログラムとの違いは、次の3点だけです。

場所書くもの役割
データ部LINKAGE SECTION.（連絡節）主プログラムから受け取る項目を定義する。作業場所節と違い、ここで定義した項目は自分の領域を持たず、呼び出し元のデータを指す
手続き部の見出しPROCEDURE DIVISION USING LK-AMOUNT LK-TAX.受け取る項目を、受け取る順に並べる
最後の文GOBACK.処理を終えて、呼び出し元に戻る

用語: 連絡節（LINKAGE SECTION）と引数

連絡節は、主プログラムとの「連絡用の窓口」です。主プログラムが頼むときに渡す書類（金額の記入用紙）を引数（ひきすう）と呼びます。副プログラムは、渡された用紙に書かれた金額を読み、計算結果を別の用紙に書き込んで返します。項目名は規約どおり LK- で始めます。

主プログラム副プログラム
終わりの文STOP RUN.（プログラム全体を終える）GOBACK.（呼び出し元へ戻る）
データの受け取りなしLINKAGE SECTION ＋ USING
PROGRAM-ID自由（例: MAIN）呼び出される名前（例: CALCTAX）

副プログラムで STOP RUN を書かない

副プログラムの最後に STOP RUN. を書くと、呼び出し元に戻らずプログラム全体が終了してしまいます。副プログラムは必ず GOBACK. で終えましょう（主プログラムの最後に GOBACK. を書いても動きますが、本ガイドでは主プログラムは STOP RUN. に統一します）。

13.3 CALLで副プログラムを呼び出す

副プログラムを呼び出すのは CALL 文です。呼び出す側の主プログラム main.cob を書いてみましょう。

main.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. MAIN.
      * 副プログラム CALCTAX を呼び出す主プログラム
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-AMT          PIC 9(7) VALUE 12345.
       01  WS-TAX          PIC 9(7) VALUE ZERO.
       01  WS-AMT-ED       PIC Z,ZZZ,ZZ9.
       01  WS-TAX-ED       PIC Z,ZZZ,ZZ9.
       PROCEDURE DIVISION.
       MAIN-PROC.
           CALL "CALCTAX" USING WS-AMT WS-TAX.
           MOVE WS-AMT TO WS-AMT-ED.
           MOVE WS-TAX TO WS-TAX-ED.
           DISPLAY "税抜金額: " WS-AMT-ED " 円".
           DISPLAY "消費税: " WS-TAX-ED " 円".
           STOP RUN.

CALL "CALCTAX" USING WS-AMT WS-TAX. は、「CALCTAX という係に、WS-AMT と WS-TAX を渡して仕事を頼む」という意味です。呼ばれた CALCTAX が GOBACK. に達すると、CALL の次の行に戻って処理が続きます。

flowchart LR A["主プログラム MAIN
CALL CALCTAX を実行"] --> B["副プログラム CALCTAX
税額を計算して LK-TAX に入れる"] B --> C["GOBACK で戻る"] C --> D["主プログラム MAIN
CALL の次の行から続きを実行"]

図の説明: CALL で副プログラムに処理を渡し、GOBACK で呼び出し元の次の行に戻ります。

2つのファイルをコンパイルする

プログラムが2つのファイルに分かれたので、コンパイルのしかたが変わります。主プログラム（先頭に書いたファイル）と副プログラムを、1つのコマンドでまとめて指定します。

作業フォルダの構成 

cobol-study/
├── main.cob        ← 主プログラム（PROGRAM-ID. MAIN）
└── calctax.cob     ← 副プログラム（PROGRAM-ID. CALCTAX）
ターミナル コマンド 
cobc -x main.cob calctax.cob
./main
実行結果 出力 
税抜金額:    12,345 円
消費税:     1,235 円

ヒント: 実行ファイルの名前

cobc -x は、先頭に書いたファイル名から実行ファイルの名前を決めます（main.cob なら main）。副プログラム calctax.cob は、その実行ファイルの中に一緒に組み込まれます。ファイル名ではなく PROGRAM-ID の名前（CALCTAX）で呼び出す点に注意してください。

引数は「名前」ではなく「順番」で対応する

CALL 側の WS-AMT WS-TAX と、副プログラム側の LK-AMOUNT LK-TAX は、名前がまったく違います。COBOL は名前で対応づけるのではなく、書いた順番で1番目どうし、2番目どうしを結びつけます。

flowchart LR subgraph caller["主プログラム 呼び出し側"] W1["1番目 WS-AMT 12345"] W2["2番目 WS-TAX 0"] end subgraph callee["副プログラム 受け取り側"] L1["1番目 LK-AMOUNT"] L2["2番目 LK-TAX"] end W1 --- L1 W2 --- L2

図の説明: 両側の項目は、名前ではなく並んだ順番で結びつきます。しかも「コピーを渡す」のではなく、同じ場所（同じデータ）を共有します。

順番を間違えると、どうなるでしょうか。わざと WS-TAX と WS-AMT の順に渡してみます。

main.cob（順番を間違えた例） 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. MAIN.
      * 引数の並び順をわざと間違えて呼び出す
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-AMT          PIC 9(7) VALUE 12345.
       01  WS-TAX          PIC 9(7) VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 正しくは USING WS-AMT WS-TAX の順
           CALL "CALCTAX" USING WS-TAX WS-AMT.
           DISPLAY "WS-AMT = " WS-AMT.
           DISPLAY "WS-TAX = " WS-TAX.
           STOP RUN.
実行結果 出力 
WS-AMT = 0000000
WS-TAX = 0000000

1番目に渡した WS-TAX（値は0）が LK-AMOUNT に、2番目の WS-AMT が LK-TAX に結びつきました。0の10%は0なので、税金の計算結果 0 が WS-AMT に書き込まれ、元の税抜金額 12345 が消えてしまいました。しかもエラーも出ません。

引数の順番と桁数は、自分で確かめる

コンパイラは、CALL 側と副プログラム側で引数の順番や型が合っているかを調べてくれません。順番の間違い、個数の違い、PIC の桁数の食い違いは、エラーにならないまま、おかしな結果になります。引数を変更するときは、呼び出す側と呼ばれる側の両方を必ず見直しましょう。

副プログラムが見つからないとき

コンパイルのときに calctax.cob を指定し忘れると、実行したときに次のエラーで止まります（GnuCOBOL では、副プログラムの有無は実行時に初めて調べられます。処理系によっては、組み立ての段階で調べるものもあります）。

実行結果 出力 
libcob: error: module 'CALCTAX' not found

このようなときのために、CALL には ON EXCEPTION（呼び出しに失敗したとき）を付けて、自分でメッセージを出す書き方もあります。

main.cob PROCEDURE DIVISIONの抜粋 
       MAIN-PROC.
      * 副プログラムが見つからないときの備え
           CALL "CALCTAX" USING WS-AMT WS-TAX
               ON EXCEPTION
                   DISPLAY "CALCTAX が見つかりません"
           END-CALL.
           DISPLAY "消費税 = " WS-TAX.

重要ポイント

副プログラムを使うときの約束は3つです。(1) 副プログラムは LINKAGE SECTION ＋ PROCEDURE DIVISION USING ＋ GOBACK で作る。(2) CALL "プログラム名" USING 引数… で呼ぶ。(3) 引数は名前ではなく順番で対応する。

13.4 BY REFERENCEとBY CONTENT - 原本を渡すか、コピーを渡すか

CALL で引数を渡すとき、渡し方が2種類あります。違いを、たとえ話から見てみましょう。

BY REFERENCE（参照渡し）

書類の原本を渡す方法です。受け取った係が原本に書き込めば、頼んだ側の書類も書き換わります。何も書かなければ、これが既定の渡し方です。

BY CONTENT（内容渡し）

書類のコピーを渡す方法です。受け取った係がコピーに何を書いても、手元の原本は変わりません。「渡したいだけで、書き換えられたくない」ときに使います。

実際に動かして比べましょう。まず、受け取った数に10を足すだけの副プログラム ADDTEN です。

addten.cob 完全なプログラム（副プログラム） 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. ADDTEN.
      * 受け取った数に10を足す副プログラム
       DATA DIVISION.
       LINKAGE SECTION.
       01  LK-NUM          PIC 9(3).
       PROCEDURE DIVISION USING LK-NUM.
       MAIN-PROC.
           ADD 10 TO LK-NUM.
           GOBACK.

次に、同じ初期値 5 の項目を、1つは BY REFERENCE、もう1つは BY CONTENT で渡します。

main.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. MAIN.
      * BY REFERENCE と BY CONTENT の違いを比べる
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-A            PIC 9(3) VALUE 5.
       01  WS-B            PIC 9(3) VALUE 5.
       PROCEDURE DIVISION.
       MAIN-PROC.
           CALL "ADDTEN" USING BY REFERENCE WS-A.
           CALL "ADDTEN" USING BY CONTENT WS-B.
           DISPLAY "BY REFERENCE: " WS-A.
           DISPLAY "BY CONTENT  : " WS-B.
           STOP RUN.
ターミナル コマンド 
cobc -x main.cob addten.cob
./main
実行結果 出力 
BY REFERENCE: 015
BY CONTENT  : 005
渡し方副プログラムが値を変えると向いている場面
BY REFERENCE（既定）呼び出し元の値も変わる（5 → 15）計算結果を受け取りたいとき（CALCTAX の税額など）
BY CONTENT呼び出し元の値は変わらない（5 のまま）値を渡すだけで、書き換えられたくないとき

USING の中では、BY REFERENCE と BY CONTENT を1つの CALL に混ぜて書くこともできます。たとえば「税抜金額は書き換えさせない（コピーを渡す）が、税額は結果を受け取る（原本を渡す）」なら、次のように書きます。

main.cob PROCEDURE DIVISIONの抜粋 
      * 金額はコピー、税額は原本を渡す
           CALL "CALCTAX" USING BY CONTENT WS-AMT
               BY REFERENCE WS-TAX.

BY CONTENT や BY REFERENCE の指定は、次の BY が出てくるまで、後ろに並ぶ引数すべてに効きます。たとえば USING BY CONTENT WS-AMT WS-TAX と書くと、WS-TAX もコピー渡しになり、税額が戻ってきません（実機では WS-TAX が 0000000 のままでした）。BY CONTENT の後ろで原本を渡したい引数には、BY REFERENCE をはっきり書きます。上の書き方なら、WS-AMT は 12345 のまま、WS-TAX には 1235 が戻ります。

ヒント: 迷ったときの選び方

結果を受け取りたい引数は BY REFERENCE（先頭で何も書かなければ既定。BY CONTENT の後ろでは BY REFERENCE と書く）、入力として渡すだけの引数は BY CONTENT、と覚えると失敗しません。13.3 の失敗例のように、うっかり原本を書き換えられる事故を防げます。

13.5 COPY文とコピーブック - データ定義を共有する

もう1つの部品化の仕組みが COPY 文です。第12章では売上レコード SALES-REC の定義をプログラムの中に書きました。しかし、売上を読む・集計する・帳票にするなど、複数のプログラムが同じレコードを扱う場合、同じ定義をあちこちに書くと、桁数を変えたときに直し忘れが起きます。

そこで、データの定義だけを別のファイル（コピーブック）に書き、各プログラムは COPY 文でそれを取り込みます。コンパイルのとき、COPY の行がコピーブックの中身に置き換えられる、と考えてください。

flowchart TD C["コピーブック
SALESREC.cpy
売上レコードの定義"] P1["読み込みプログラム
COPY SALESREC."] P2["集計プログラム
COPY SALESREC."] P3["帳票プログラム
COPY SALESREC."] C -->|コンパイル時に展開| P1 C -->|コンパイル時に展開| P2 C -->|コンパイル時に展開| P3

図の説明: コピーブックを1つ直せば、COPY しているすべてのプログラムが次のコンパイルで同じ定義になります。

コピーブックは、本ガイドでは copy というフォルダにまとめ、拡張子を .cpy にします。

作業フォルダの構成 

cobol-study/
├── main.cob              ← 主プログラム（COPY SALESREC. と書く）
└── copy/
    └── SALESREC.cpy      ← コピーブック（売上レコードの定義）
copy/SALESREC.cpy コピーブック 
      * 売上レコード（合計20バイト）
       01  SALES-REC.
           05  SR-DATE     PIC X(8).
           05  SR-ITEM     PIC X(4).
           05  SR-QTY      PIC 9(3).
           05  SR-PRICE    PIC 9(5).

コピーブックの中身は、データ部に書く内容そのままです（01 SALES-REC から始め、桁位置も本体のプログラムと同じ固定形式で書きます）。これを、取り込みたい場所に COPY で呼び出します。

main.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. MAIN.
      * コピーブックの売上レコードを取り込んで使う
       DATA DIVISION.
       WORKING-STORAGE SECTION.
           COPY SALESREC.
       01  WS-AMOUNT       PIC 9(8).
       01  WS-AMOUNT-ED    PIC Z,ZZZ,ZZ9.
       PROCEDURE DIVISION.
       MAIN-PROC.
           MOVE "20261001A00100300120" TO SALES-REC.
           COMPUTE WS-AMOUNT = SR-QTY * SR-PRICE.
           MOVE WS-AMOUNT TO WS-AMOUNT-ED.
           DISPLAY "日付: " SR-DATE " 商品: " SR-ITEM.
           DISPLAY "金額: " WS-AMOUNT-ED " 円".
           STOP RUN.

COPY SALESREC. は、名前のとおり SALESREC.cpy を探して、その内容をその場に取り込みます。文の最後のピリオドを忘れないようにしてください。コピーブックを探す場所は -I オプションで教えます。

ターミナル コマンド 
cobc -x -I copy main.cob
./main
実行結果 出力 
日付: 20261001 商品: A001
金額:       360 円

-I copy は「copy フォルダの中も探してください」という指定です。これを付け忘れると、次のようにコピーブックが見つからないエラーになります。

実行結果 出力 
main.cob:6: error: SALESREC: No such file or directory
main.cob: in paragraph 'MAIN-PROC':
main.cob:11: error: 'SALES-REC' is not defined
main.cob:12: error: 'SR-QTY' is not defined
main.cob:12: error: 'SR-PRICE' is not defined
main.cob:14: error: 'SR-DATE' is not defined
main.cob:14: error: 'SR-ITEM' is not defined

コピーブックが見つからず、そのため SALES-REC の定義が取り込まれなかったので、後ろの行でも「定義されていない」というエラーが続きます。最初の1行目のエラーを直せば、後ろのエラーは自然に消えることが多いので、エラーは上から順に直しましょう。

ファイル節の FD（第12章）の直下にも、同じように取り込めます。同じコピーブックを2つの FD に取り込むと、レコード名と項目名が二重に定義され、'SR-ITEM' is ambiguous; needs qualification というエラーになります。そのため、取り込むのは入力用の FD だけにします。出力側は第12章と同じく 01 OUT-REC PIC X(20). のような別名のレコードにして、WRITE OUT-REC FROM SALES-REC で書き出します（名前を置き換えて取り込む COPY ... REPLACING もありますが、本ガイドでは扱いません）。

ファイル節の部分 DATA DIVISIONの抜粋 
       FILE SECTION.
       FD  IN-FILE.
      * FD の直下にもコピーブックを取り込める
           COPY SALESREC.

コラム: 現場ではコピーブックが常識

メインフレームの開発現場では、レコードの定義はコピーブックにして共通化するのが当たり前です。ファイルのレイアウト（項目の並びと桁数）は、そのファイルを読み書きするすべてのプログラムで一致していなければならないからです。保守の仕事では「この項目はどのコピーブックで定義されているか」を探す場面がよくあります。また、COPY 文には、取り込むときに一部の文字列を置き換える REPLACING という機能もあります（本ガイドでは扱いません）。

13.6 RETURN-CODEと終了コード

副プログラムが仕事を終えたとき、「成功したか・失敗したか」を主プログラムに伝えたい場合があります。COBOL には、そのための特別な項目 RETURN-CODE が最初から用意されています。宣言は不要で、数値を入れて使います。

chkrc.cob 完全なプログラム（副プログラム） 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. CHKRC.
      * 数値が100を超えたら RETURN-CODE に8を入れる
       DATA DIVISION.
       LINKAGE SECTION.
       01  LK-NUM          PIC 9(3).
       PROCEDURE DIVISION USING LK-NUM.
       MAIN-PROC.
           IF LK-NUM > 100
               MOVE 8 TO RETURN-CODE
           ELSE
               MOVE 0 TO RETURN-CODE
           END-IF.
           GOBACK.
main.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. MAIN.
      * 副プログラムの終了コードを調べる
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-NUM          PIC 9(3) VALUE 150.
       PROCEDURE DIVISION.
       MAIN-PROC.
           CALL "CHKRC" USING WS-NUM.
           DISPLAY "RETURN-CODE = " RETURN-CODE.
           IF RETURN-CODE NOT = 0
               DISPLAY "異常です"
           END-IF.
           STOP RUN.
ターミナル コマンド 
cobc -x main.cob chkrc.cob
./main
echo $?
実行結果 出力 
RETURN-CODE = +000000008
異常です
8

RETURN-CODE の値は、副プログラムから主プログラムへ伝わり、さらに主プログラムが終わるときにはプログラム全体の終了コードになります。最後の echo $? が、その終了コード（8）を表示しています。

値慣習的な意味
0正常終了
4警告（処理は続けられるが、確認が必要）
8以上異常（エラー）

ヒント: 終了コードはジョブの流れを決める

メインフレームでは、複数のプログラムを順に実行する「ジョブ」の中で、前のプログラムの終了コード（リターンコード）を見て、後ろの処理を実行するか止めるかを決めます。「0なら次へ、8以上なら中止して担当者に連絡」のような運用です。そのため、プログラムは正常なら0、異常なら0以外を必ず返すように作ります。GnuCOBOL の DISPLAY では +000000008 のように符号と桁数付きで表示されますが、中身は数値の 8 です。

やってみよう 13-1: 日付チェックの副プログラム CHKDATE を作ろう

日付（YYYYMMDD）が実在する日付かどうかを調べる副プログラムを作り、主プログラムから呼び出して確かめます。

手順

  • 1 chkdate.cob を作る。LINKAGE SECTION に、日付 LK-DATE（年4桁・月2桁・日2桁の集団項目）と、結果 LK-RESULT（PIC X）を定義する。
  • 2 月が1〜12か、日が1〜その月の最終日か、を調べる。最終日は 4・6・9・11 月が30、2月が28（4で割り切れる年は29、簡易判定でよい）、それ以外が31。正しければ結果に "0"、誤りなら "1" を入れて GOBACK. する。
  • 3 main.cob から 20261001・20260231・20240229 の3つを CALL "CHKDATE" で調べ、「正しい日付です」「誤った日付です」と表示する。
  • 4 cobc -x main.cob chkdate.cob でコンパイルして動かす。余裕があれば、20260431 や 2026AB01 も試す。

解答例

副プログラムは、前半（IDENTIFICATION DIVISION から主な処理まで）と後半（月ごとの最終日を決める段落の中身）に分けて示します。それぞれ単独では動きません。順につなげて1つのファイル chkdate.cob に保存してください。前半の最後の MAXDAY-PROC. の行の直後に、後半をそのまま続けます（見出し行の追加は不要です）。なお副プログラムなので、完成した chkdate.cob だけを cobc -x しても実行ファイルにはなりません。

chkdate.cob（部品 1/2） プログラムの前半 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. CHKDATE.
      * 日付(YYYYMMDD)を調べる。LK-RESULT: 0=正しい 1=誤り
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-MAXDAY       PIC 99.
       LINKAGE SECTION.
       01  LK-DATE.
           05  LK-YEAR     PIC 9(4).
           05  LK-MONTH    PIC 9(2).
           05  LK-DAY      PIC 9(2).
       01  LK-RESULT       PIC X.
       PROCEDURE DIVISION USING LK-DATE LK-RESULT.
       MAIN-PROC.
           MOVE "1" TO LK-RESULT.
           IF LK-DATE IS NUMERIC
               IF LK-MONTH >= 1 AND LK-MONTH <= 12
                   PERFORM MAXDAY-PROC
                   IF LK-DAY >= 1 AND LK-DAY <= WS-MAXDAY
                       MOVE "0" TO LK-RESULT
                   END-IF
               END-IF
           END-IF.
           GOBACK.
       MAXDAY-PROC.
chkdate.cob（部品 2/2） PROCEDURE DIVISIONの抜粋 
      * 月ごとの最終日を決める。うるう年は簡易判定
           EVALUATE LK-MONTH
               WHEN 4 WHEN 6 WHEN 9 WHEN 11
                   MOVE 30 TO WS-MAXDAY
               WHEN 2
                   MOVE 28 TO WS-MAXDAY
                   IF FUNCTION MOD(LK-YEAR, 4) = 0
                       MOVE 29 TO WS-MAXDAY
                   END-IF
               WHEN OTHER
                   MOVE 31 TO WS-MAXDAY
           END-EVALUATE.
main.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. MAIN.
      * CHKDATE を3つの日付で試す
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-DATE         PIC X(8).
       01  WS-RESULT       PIC X.
       PROCEDURE DIVISION.
       MAIN-PROC.
           MOVE "20261001" TO WS-DATE.
           PERFORM CHECK-PROC.
           MOVE "20260231" TO WS-DATE.
           PERFORM CHECK-PROC.
           MOVE "20240229" TO WS-DATE.
           PERFORM CHECK-PROC.
           STOP RUN.
       CHECK-PROC.
           CALL "CHKDATE" USING WS-DATE WS-RESULT.
           IF WS-RESULT = "0"
               DISPLAY WS-DATE " は正しい日付です"
           ELSE
               DISPLAY WS-DATE " は誤った日付です"
           END-IF.
ターミナル コマンド 
cobc -x main.cob chkdate.cob
./main
実行結果 出力 
20261001 は正しい日付です
20260231 は誤った日付です
20240229 は正しい日付です
  • ・MAXDAY-PROC は、副プログラムの中の段落です。GOBACK. より後ろに置くことで、主な処理の流れの外に出しています。
  • ・LK-DATE IS NUMERIC で、数字以外が混じった日付（2026AB01 など）を先にはじいています（第7章のクラス条件）。
  • ・呼び出し側の WS-DATE は PIC X(8)、受け取り側 LK-DATE は4＋2＋2＝8桁の集団項目なので、全体の長さが同じであり、問題なく対応します。
  • ・FUNCTION MOD(LK-YEAR, 4) は、年を4で割った余りを返す組み込み関数です（第10章で少し登場。第6章の DIVIDE ... REMAINDER と同じ「余り」）。余りが0なら4で割り切れる＝うるう年です。
  • ・うるう年は「4で割り切れる年」の簡易判定です。実際には「100で割り切れる年は平年、ただし400で割り切れる年はうるう年」というルールがあり、実務ではそこまで判定します。

理解度確認クイズ

  • Q1. 副プログラムの最後には STOP RUN. と GOBACK. のどちらを書きますか？ 間違えるとどうなりますか？

    回答を表示

    GOBACK. を書きます。副プログラムで STOP RUN. を書くと、呼び出し元に戻らず、プログラム全体が終了してしまいます。

  • Q2. CALL "CALCTAX" USING WS-AMT WS-TAX. で、副プログラム側が USING LK-AMOUNT LK-TAX のとき、WS-TAX に対応するのはどの項目ですか？ また、その対応は何で決まりますか？

    回答を表示

    LK-TAX です。引数は項目の名前ではなく、USING に書いた順番で対応します（1番目どうし、2番目どうし）。順番を間違えてもコンパイルエラーにはならず、おかしな結果になるので注意が必要です。

  • Q3. BY REFERENCE と BY CONTENT の違いを説明してください。何も書かないときはどちらになりますか？

    回答を表示

    BY REFERENCE は呼び出し元のデータそのもの（原本）を渡すので、副プログラムが値を変えると呼び出し元の値も変わります。BY CONTENT はコピーを渡すので、副プログラムが値を変えても呼び出し元は変わりません。何も書かないときは BY REFERENCE です。

  • Q4. コピーブック SALESREC.cpy を copy フォルダに置いたとき、プログラムに書く文と、コンパイルのコマンドを答えてください。

    回答を表示

    プログラムのデータ部に COPY SALESREC. と書きます。コンパイルは cobc -x -I copy main.cob です。-I copy でコピーブックを探すフォルダを教えます。付け忘れると「SALESREC: No such file or directory」というエラーになります。
