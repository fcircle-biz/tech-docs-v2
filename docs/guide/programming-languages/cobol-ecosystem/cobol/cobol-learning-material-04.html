データを入れる箱 - データ項目とPICTURE句

プログラムは、金額・数量・商品コードなどの「データ」を扱って動きます。COBOL では、データを入れる箱（データ項目）を最初に「何の種類を、何桁まで入れるか」を決めて用意します。この章では、その箱の作り方（PICTURE句）と、箱に値を入れる方法（VALUE句と MOVE 文）を学びます。

この章で学ぶこと

  • データ項目とは何か、なぜ最初に桁数を決めるのかを説明できる
  • WORKING-STORAGE SECTION に、レベル番号と PICTURE 句でデータ項目を定義できる
  • 9・X・V・S の意味を理解し、小数や符号付きの項目を書ける
  • VALUE 句で初期値を設定し、MOVE 文で値を入れたときの右寄せ・左寄せ・桁あふれの動きを説明できる
  • PIC X の桁数は文字数ではなくバイト数であること（UTF-8 の日本語は多くの文字が1文字3バイト）と、初期化を忘れてはいけない理由を説明できる

4.1 データ項目とは - 桁数の決まった箱

ほかのプログラミング言語では「変数」と呼ばれる、データを一時的に置いておく入れ物のことを、COBOL ではデータ項目と呼びます。たとえば「商品コード」「単価」「数量」はどれも、プログラムの中ではデータ項目として用意します。

COBOL のデータ項目には、ほかの言語と大きく違う点があります。それは最初に「どんな種類のデータを、何桁分入れる箱か」をきっちり決めることです。申込用紙の記入欄を思い浮かべてください。「郵便番号は数字7マス」「氏名は文字10マス」のように、マス目の数が最初から決まっていますね。これを固定長といいます。

flowchart LR A["データ部
DATA DIVISION"] --> B["作業場所節
WORKING-STORAGE SECTION"] B --> C["WS-ITEM-CODE
文字4桁の箱"] B --> D["WS-QTY
数字3桁の箱"] B --> E["WS-PRICE
数字5桁の箱"]

図の説明: データ項目は、データ部の「作業場所節」の中に、名前と大きさを決めて用意します。

項目1桁目2桁目3桁目4桁目
商品コード（文字4桁）A001
数量（数字3桁）003　

申込用紙のマス目のように、箱の大きさは最初に決まっています。数量は3桁なので、4桁目はありません。

用語: 固定長と可変長

固定長は、入れ物の大きさが最初から決まっていて変わらないこと、可変長は入れるデータに合わせて大きさが変わることです。COBOL のデータ項目は固定長が基本です。大きさが決まっているおかげで、大量のデータを「何桁目から何桁目が商品コード」と機械的に、速く、確実に処理できます。

4.2 作業場所節とレベル番号 - 箱を用意する場所

データ項目は、データ部（DATA DIVISION）の作業場所節（WORKING-STORAGE SECTION）に書きます。作業場所節は、プログラムが処理の途中で使うデータを置いておく場所です。まず、いちばん簡単なプログラムを見てみましょう。

item.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. ITEM.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
      * 商品コード（英数字4桁）と数量（数字3桁）
       01  WS-ITEM-CODE    PIC X(4)  VALUE "A001".
       01  WS-QTY          PIC 9(3)  VALUE 3.
       77  WS-COUNTER      PIC 9(2)  VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "[" WS-ITEM-CODE "]".
           DISPLAY "[" WS-QTY "]".
           DISPLAY "[" WS-COUNTER "]".
           STOP RUN.

行ごとの意味は次のとおりです。

  • WORKING-STORAGE SECTION. ... ここからデータ項目を書く、という宣言です（A領域に書きます）。
  • 01・77 ... レベル番号です。項目の「格」を表し、箱を新しく用意するときの先頭に書きます。
  • WS-ITEM-CODE ... 項目の名前（データ名）です。作業場所節の項目には、慣習で WS- を付けます。
  • PIC X(4) ... 箱の種類と大きさ（PICTURE句）です。「文字（X）が4桁」の意味です。
  • VALUE "A001" ... 最初に入れておく値（初期値）です。

コンパイルして実行します。DISPLAY の前後に [ と ] を付けているのは、箱の中の空白や桁数が目で見えるようにするためです。

ターミナル 
cobc -x item.cob
./item
実行結果 
[A001]
[003]
[00]

WS-QTY に VALUE 3 と書いたのに、003 と3桁で表示されています。数字の箱は、桁数いっぱいまでゼロで埋められるからです。これは 4.6 の MOVE でもう一度出てきます。

レベル番号 01

もっとも一般的な、独立したデータ項目の宣言です。第9章で、01 の下に 05・10 を重ねて「項目の階層」を作る方法を学びます。現場では、単独の項目にも 01 を使うことが多くあります。

レベル番号 77

「ほかの項目とグループを作らない、単独の項目」を表す番号です。上のプログラムの WS-COUNTER のように使えます。ただし 77 の下には 05・10 などの下位項目を置けません。単独の項目なら 01 でも同じように書けるので、本ガイドでは基本的に 01 を使います。

ヒント: データ名の付け方

データ名は英大文字・数字・ハイフンで付けます（最初と最後の文字をハイフンにはできません）。WS-TOTAL-AMOUNT のように、中身が分かる名前にしましょう。A や X1 のような短い名前は、後から読む人が意味を推測できないので避けます。COBOL の予約語（DATE や TIME など）はデータ名に使えません。WS- を付ければ自然に避けられます。

4.3 PICTURE句の基本 - 9・X・A

箱の「種類」と「大きさ」を決めるのが PICTURE句（PIC句）です。PIC のあとに、入れるデータの種類を表す記号を、桁数の分だけ並べます。まず覚えるのは次の3つです。

記号入れられるデータ使いどころ
9数字（0〜9）だけ金額・数量・単価など、計算に使う数値
X文字ならなんでも（英字・数字・記号・空白）商品コード・名前・日付の文字列など
A英字（A〜Z、a〜z）と空白だけ英字だけの項目。実際の現場では X で済ませることが多い

同じ記号を何桁も書くのは大変なので、繰り返し表記が使えます。9(5) は 99999 と同じ意味です。

PICTURE句意味大きさ入れられる値の例
PIC 9(5)数字5桁5バイト00123、99999
PIC 9(3)数字3桁3バイト003、120
PIC X(10)文字10桁10バイトTANAKA（足りない分は空白）
PIC X(4)文字4桁4バイトA001
PIC A(6)英字6桁6バイトTANAKA
picdemo.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PICDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
      * 繰り返し表記: 9(5) は 99999 と同じ
       01  WS-A            PIC 99999   VALUE 123.
       01  WS-B            PIC 9(5)    VALUE 123.
       01  WS-NAME         PIC X(10)   VALUE "TANAKA".
       01  WS-ALPHA        PIC A(6)    VALUE "TANAKA".
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "[" WS-A "]".
           DISPLAY "[" WS-B "]".
           DISPLAY "[" WS-NAME "]".
           DISPLAY "[" WS-ALPHA "]".
           STOP RUN.
実行結果 
[00123]
[00123]
[TANAKA    ]
[TANAKA]

WS-A を PIC 99999、WS-B を PIC 9(5) と書いても、結果は同じです。WS-NAME は10桁の箱に TANAKA（6文字）を入れたので、残りの4桁は空白で埋められています（表示結果の ] の手前の空白）。

flowchart TD A{"箱に入れるデータは？"} A -->|"金額や数量など、計算に使う値"| B["PIC 9 を使う"] A -->|"商品コードや名前など、計算しない値"| C["PIC X を使う"] A -->|"英字だけの値"| D["PIC A も使えるが、通常は X で足りる"]

図の説明: PICTURE 句の記号の選び方です。迷ったら「その値を足したり掛けたりするか」で決めます。

重要ポイント: 計算しない数字は PIC X

商品コード A001 や電話番号、郵便番号のように、数字でも足し算や掛け算をしない値は PIC X にします。電話番号（03-1234-5678）のように、数字以外の文字が混ざることもあります。逆に、金額や数量のように計算する値は PIC 9 にします。

4.4 小数と符号 - V と S

金額には小数が付くことがあり、残高にはマイナスもあります。小数点と符号を表すための記号が、V と S です。

記号意味書き方の例説明
V小数点の位置（仮定小数点）PIC 9(5)V99整数5桁・小数2桁。V の位置に小数点があるものとして扱うだけで、V 自体は1桁を使わない（記憶領域には7桁分の数字だけが入る）
S符号（プラス・マイナス）PIC S9(3)項目の先頭に書く。S が無い数字の項目は、マイナスの値を持てない（符号無し）。S も V と同じく桁を使わない（符号は数字と一緒に記録される）。DISPLAY で - が付くのは、表示するときだけ
項目12345V67
PIC 9(5)V99 に 1234.5 を入れた状態01234↓50

V の位置は「ここで区切って読む」という印です。実際の記憶領域に「.」は入らず、整数5桁・小数2桁の合計7桁だけが入ります。

項目に入った数字　V の位置（小数点があるものとみなす位置。桁は使わない）

vsdemo.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. VSDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
      * V は小数点の位置、S は符号
       01  WS-PRICE        PIC 9(5)V99   VALUE 1234.5.
       01  WS-DIFF         PIC S9(3)     VALUE -5.
       01  WS-BAL          PIC S9(5)V99  VALUE -1234.5.
       01  WS-INT          PIC 9(5)V99   VALUE 1234.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "PRICE=[" WS-PRICE "]".
           DISPLAY "DIFF =[" WS-DIFF "]".
           DISPLAY "BAL  =[" WS-BAL "]".
           DISPLAY "INT  =[" WS-INT "]".
           STOP RUN.
実行結果 
PRICE=[01234.50]
DIFF =[-005]
BAL  =[-01234.50]
INT  =[01234.00]

DIFF は -005 のように、マイナス記号が付き、3桁ぶんのゼロ埋めになって表示されています。この - は表示するときに付くもので、記憶領域では S は桁を使いません。

注意: DISPLAY の小数点表示は処理系によって違う

GnuCOBOL では PIC 9(5)V99 の項目を DISPLAY すると 01234.50 のように小数点付きで表示されます。しかし規格やメインフレームの COBOL では、小数点は表示されず 0123450 のように数字だけが出ることがあります。符号付きの項目も同様で、メインフレームでは - 記号は付かず、最後の桁に符号が埋め込まれた形で表示されます。このため、人に見せる金額の表示には、第5章で学ぶ編集項目を使うのが正しいやり方です。

4.5 VALUE句で初期値を決める

データ項目の宣言に VALUE 句を付けると、プログラムが動き出すときの初期値を決められます。数字の箱には数字を、文字の箱には引用符（"）で囲んだ文字を書きます。

valdemo.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. VALDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
      * VALUE 句と表意定数
       01  WS-TOTAL        PIC 9(5)   VALUE ZERO.
       01  WS-MEMO         PIC X(6)   VALUE SPACE.
       01  WS-LINE         PIC X(6)   VALUE ALL "-".
       01  WS-CODE         PIC X(4)   VALUE "A001".
       01  WS-RATE         PIC 9V99   VALUE 0.10.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "TOTAL=[" WS-TOTAL "]".
           DISPLAY "MEMO =[" WS-MEMO "]".
           DISPLAY "LINE =[" WS-LINE "]".
           DISPLAY "CODE =[" WS-CODE "]".
           DISPLAY "RATE =[" WS-RATE "]".
           STOP RUN.
実行結果 
TOTAL=[00000]
MEMO =[      ]
LINE =[------]
CODE =[A001]
RATE =[0.10]

ZERO や SPACE のように、あらかじめ COBOL が用意している決まった値を表意定数と呼びます。よく使うものを整理します。

表意定数意味使い方の例
ZEROゼロ（ZEROS・ZEROES も同じ）数字の項目を0で初期化する。箱の桁数ぶん全部が0になる
SPACE空白（SPACES も同じ）文字の項目を空白で初期化する。箱の桁数ぶん全部が空白になる
ALL "-"指定した文字を箱いっぱいに並べる罫線や区切りの線を作る（上の例では6桁ぶんの ------）

ヒント: 小数の初期値

小数の項目には、小数点を書いて初期値を決められます（例: PIC 9V99 VALUE 0.10）。VALUE 句には項目の種類に合った値を書きます。数字の項目には数字を、文字の項目には文字を書くのが基本です。

4.6 MOVE文で値を入れる - 右寄せ・左寄せ・桁あふれ

箱の中身を後から入れ替えるのが MOVE文です。「MOVE 送り元 TO 送り先」と書くと、送り元の値が送り先の箱にコピーされます（送り元はそのまま残ります）。名前は「移動」ですが、実際は「コピー」です。

flowchart TD A["MOVE 送り元 TO 送り先"] --> B{"送り先の種類は？"} B -->|"数字項目"| C["小数点の位置をそろえる
右寄せ・左側はゼロ埋め
あふれたら上位の桁を切り捨て"] B -->|"英数字項目"| D["左寄せ・右側は空白埋め
あふれたら右側を切り捨て"]

図の説明: MOVE は、送り先の箱の種類によって「寄せる向き」が変わります。数字は右（小数点）にそろえ、文字は左にそろえます。

小さい値を入れたとき - 寄せる向きと埋め方

movedemo.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. MOVEDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-NUM          PIC 9(5)  VALUE ZERO.
       01  WS-TXT          PIC X(6)  VALUE SPACE.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 数字項目: 右寄せ、左側はゼロ埋め
           MOVE 42 TO WS-NUM.
           DISPLAY "NUM=[" WS-NUM "]".
      * 英数字項目: 左寄せ、右側は空白埋め
           MOVE "AB" TO WS-TXT.
           DISPLAY "TXT=[" WS-TXT "]".
           STOP RUN.
実行結果 
NUM=[00042]
TXT=[AB    ]
項目123456
MOVE 42 TO PIC 9(5)00042　
MOVE "AB" TO PIC X(6)AB・・・・

項目に入った文字・数字　自動で埋められた部分（ゼロまたは空白。「・」は空白）　その項目には無い桁

数字の項目は右にそろえて、左側をゼロで埋めます。文字の項目は左にそろえて、右側を空白で埋めます。数字は「桁（一の位）をそろえる」、文字は「文章を左から書き始める」と考えると覚えやすくなります。

大きすぎる値を入れたとき - 桁あふれ

箱より大きな値を入れようとすると、入りきらない部分が黙って切り捨てられます。エラーで止まることはありません。

overdemo.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. OVERDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-NUM          PIC 9(3)  VALUE ZERO.
       01  WS-TXT          PIC X(4)  VALUE SPACE.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 数字: あふれた上位の桁が切り捨てられる
           MOVE 12345 TO WS-NUM.
           DISPLAY "NUM=[" WS-NUM "]".
      * 英数字: あふれた右側が切り捨てられる
           MOVE "ABCDEFG" TO WS-TXT.
           DISPLAY "TXT=[" WS-TXT "]".
           STOP RUN.
実行結果 
NUM=[345]
TXT=[ABCD]
項目1234567
MOVE 12345 TO PIC 9(3)12345　　
MOVE "ABCDEFG" TO PIC X(4)ABCDEFG

項目に入った文字・数字　入りきらず切り捨てられた部分　その項目には無い桁

数字の項目では上位（左側）の桁が、文字の項目では右側が切り捨てられます。数字で上位の桁が消えると、12345 が 345 になってしまい、金額なら大事故です。

cobc に -Wall を付けてコンパイルすると、コンパイルの時点で分かる切り捨てを見つけて警告してくれます。

ターミナル 
cobc -x -Wall overdemo.cob
コンパイル時の警告 
overdemo.cob: in paragraph 'MAIN-PROC':
overdemo.cob:10: warning: value size exceeds data size [-Wtruncate]
overdemo.cob:10: note: value is 12345 [-Wtruncate]
overdemo.cob:5: note: 'WS-NUM' defined here as PIC 9(3) [-Wtruncate]
overdemo.cob:13: warning: value size exceeds data size [-Wtruncate]
overdemo.cob:13: note: value size is 7 [-Wtruncate]
overdemo.cob:6: note: 'WS-TXT' defined here as PIC X(4) [-Wtruncate]

ただし警告されるのは、上のように値を直接 MOVE するときなど、コンパイルの時点で分かる切り捨てだけです。項目から項目への MOVE（このあとの decdemo.cob の MOVE WS-A TO WS-B など）では警告されません。-Wall を付ければ安心、というわけではありません。

小数のある項目へ入れたとき

小数のある数字の項目では、小数点の位置をそろえて入ります。整数部・小数部それぞれ、あふれた桁は切り捨てられます。四捨五入はされません。MOVE には四捨五入の指定はありません。四捨五入したいときは、第6章で学ぶ COMPUTE などの計算命令に ROUNDED を付けます。

decdemo.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DECDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-A            PIC 9(3)V99  VALUE ZERO.
       01  WS-B            PIC 9(2)V9   VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 小数点をそろえて入り、あふれた桁は切り捨て
           MOVE 123.456 TO WS-A.
           DISPLAY "A=[" WS-A "]".
           MOVE WS-A TO WS-B.
           DISPLAY "B=[" WS-B "]".
           STOP RUN.
実行結果 
A=[123.45]
B=[23.4]
項目123V456
MOVE 123.456 TO PIC 9(3)V99123↓456
MOVE WS-A TO PIC 9(2)V9（WS-A は 123.45）123↓45　

項目に入った文字・数字　入りきらず切り捨てられた部分　その項目には無い桁　V の位置（小数点があるものとみなす位置。桁は使わない）

注意: 桁あふれは黙って起きる

実行時には、MOVE で桁があふれてもエラーメッセージも停止も起きません。「箱の大きさは、入りうる最大の値で決める」ことが大切です。金額なら「最大でいくらになるか」を考えて、余裕のある桁数にします。

4.7 注意したいこと - 日本語のバイト数と初期化

PIC X の箱には「文字ならなんでも」入ると説明しましたが、日本語を入れるときには落とし穴があります。

COBOL の PIC X の桁数は、文字数ではなくバイト数です。そして本ガイドで使う UTF-8 は、文字によって1〜4バイトを使い分ける文字コードです。半角英数字は1文字＝1バイトですが、ひらがな・カタカナ・漢字など多くの日本語の文字は1文字＝3バイトです（一部の漢字や絵文字のように4バイトの文字もあり、すべての日本語が3バイトとは限りません）。つまり PIC X(6) には、半角なら6文字、3バイトの日本語なら2文字までしか入りません。PIC でデータの長さを決めるときは、文字数とバイト数の違いに注意してください。

jpdemo.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. JPDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-NAME1        PIC X(6)  VALUE SPACE.
       01  WS-NAME2        PIC X(6)  VALUE SPACE.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 山田は2文字で6バイト。ちょうど入る
           MOVE "山田" TO WS-NAME1.
           DISPLAY "NAME1=[" WS-NAME1 "]".
      * 山田太郎は12バイトで、後半が切り捨てられる
           MOVE "山田太郎" TO WS-NAME2.
           DISPLAY "NAME2=[" WS-NAME2 "]".
           STOP RUN.
実行結果 
NAME1=[山田]
NAME2=[山田]
項目1〜34〜67〜910〜12
MOVE "山田" TO PIC X(6)山田　　
MOVE "山田太郎" TO PIC X(6)山田太郎

横軸は「何バイト目か」です。

項目に入った文字・数字　入りきらず切り捨てられた部分　その項目には無い桁

「山田」（6バイト）は PIC X(6) にちょうど入りますが、「山田太郎」（12バイト）は後半の「太郎」が切り捨てられ、「山田」になってしまいます。しかも、もし切れ目が文字の途中にあたると、次のように文字化けします。

jpcut.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. JPCUT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-NAME3        PIC X(4)  VALUE SPACE.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 山田は6バイト。4バイトでは田の途中で切れる
           MOVE "山田" TO WS-NAME3.
           DISPLAY "NAME3=[" WS-NAME3 "]".
           STOP RUN.
実行結果 
NAME3=[山�]

「�」は、文字として読めない半端なバイトの代わりに、端末が表示する記号です。箱には「山」の3バイトと、「田」の3バイトのうち先頭の1バイトが入っています。端末によっては ? や空白など、別の見え方になります。

注意: PIC X のデータ値は半角英数字にする

日本語を PIC X に入れると、桁数の計算が難しいうえに、上のような切り捨てや文字化けが起きます。そのため本ガイドでは、PIC X に入れるデータの値は半角英数字（ローマ字・英字・数字）にします（例: 顧客名は TANAKA、商品名は PEN）。画面に出す見出しやラベル（DISPLAY の文字列）には日本語を使ってかまいません。なお、日本語専用の PIC N という指定も存在しますが、本ガイドでは扱いません。

もうひとつ大切な注意があります。VALUE 句を書かないデータ項目の初期値は、保証されないということです。

initdemo.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INITDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
      * VALUE 句が無い項目の初期値は保証されない
       01  WS-NUM          PIC 9(3).
       01  WS-TXT          PIC X(3).
      * VALUE 句で初期化した項目
       01  WS-OK           PIC 9(3)  VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "NUM=[" WS-NUM "]".
           DISPLAY "TXT=[" WS-TXT "]".
           DISPLAY "OK =[" WS-OK "]".
      * 値を入れてから INITIALIZE で戻す
           MOVE 123 TO WS-NUM.
           MOVE "ABC" TO WS-TXT.
           INITIALIZE WS-NUM WS-TXT.
           DISPLAY "NUM=[" WS-NUM "] TXT=[" WS-TXT "]".
           STOP RUN.
実行結果 
NUM=[000]
TXT=[   ]
OK =[000]
NUM=[000] TXT=[   ]

上の1〜2行目のように、GnuCOBOL では VALUE 句の無い数字の項目は0、文字の項目は空白で初期化されます（3行目の WS-OK は VALUE 句で初期化した例です）。しかし規格では VALUE 句の無い項目の中身は保証されず、メインフレームなどでは前の処理の残りかすのような予期しない値が入っていることがあります。手元の GnuCOBOL で動いたからと安心せず、次のどちらかで必ず初期化する習慣をつけましょう。

  • 宣言のときに VALUE 句で初期値を書く（VALUE ZERO、VALUE SPACE）。
  • 処理の中で INITIALIZE 項目名 と書く（数字はゼロ、文字は空白になる）。上の例では、MOVE で 123 と ABC を入れたあと INITIALIZE WS-NUM WS-TXT で戻していて、4行目の表示で確かめられます。

重要ポイント: この章のまとめ

データ項目は種類（9 / X）と桁数を決めた固定長の箱。値は VALUE 句で最初に入れ、MOVE 文で入れ替える。MOVE では数字は右寄せ・ゼロ埋め、文字は左寄せ・空白埋めで、入りきらない部分は黙って切り捨てられる。PIC X の値は半角英数字にし、必ず初期化する。

やってみよう 4-1: 商品の情報を箱に入れて表示しよう

文房具店の商品1件分の情報を入れるデータ項目を定義し、MOVE で値を入れて表示します。

手順

  • 1 pract04.cob を作り、作業場所節に商品コード（文字4桁）・商品名（文字10桁）・単価（数字5桁）・数量（数字3桁）の4つのデータ項目を、それぞれ VALUE 句で初期化して定義する。
  • 2 手続き部で MOVE を使い、商品コード A001、商品名 PEN、単価 120、数量 3 を入れる。
  • 3 4つの項目を DISPLAY で、前後を [ ] で囲んで表示する。
  • 4 cobc -x pract04.cob でコンパイルして実行し、桁数どおりに表示されることを確認する。
解答例を表示
pract04.cob（解答例） 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PRACT04.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
      * 商品の情報を入れる箱を用意する
       01  WS-ITEM-CODE    PIC X(4)  VALUE SPACE.
       01  WS-ITEM-NAME    PIC X(10) VALUE SPACE.
       01  WS-PRICE        PIC 9(5)  VALUE ZERO.
       01  WS-QTY          PIC 9(3)  VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
           MOVE "A001"   TO WS-ITEM-CODE.
           MOVE "PEN"    TO WS-ITEM-NAME.
           MOVE 120      TO WS-PRICE.
           MOVE 3        TO WS-QTY.
           DISPLAY "CODE =[" WS-ITEM-CODE "]".
           DISPLAY "NAME =[" WS-ITEM-NAME "]".
           DISPLAY "PRICE=[" WS-PRICE "]".
           DISPLAY "QTY  =[" WS-QTY "]".
           STOP RUN.
実行結果 
CODE =[A001]
NAME =[PEN       ]
PRICE=[00120]
QTY  =[003]
  • ・商品コードは計算しない識別番号なので PIC X(4)、単価と数量は計算に使うので PIC 9 にしています。
  • ・単価の最大は99,999円、数量の最大は999個を想定して 5桁・3桁にしています。
  • ・商品名は PIC X(10) に PEN（3文字）を入れたので、残り7桁が空白で埋められています。
  • ・発展: MOVE 123456 TO WS-PRICE. と書くと、どう表示されるか試してみましょう（上位の桁が切り捨てられて 23456 になります）。

理解度確認クイズ

  • Q1. PIC 9(5) と PIC X(5) の違いを答えてください。商品コード A001 にはどちらを使いますか？

    回答を表示

    PIC 9(5) は数字だけが入る5桁の箱で、計算に使えます。PIC X(5) は英字・数字・記号など何でも入る5桁の文字の箱です。商品コードは英字を含み、計算にも使わないので PIC X を使います（A001 は4桁なので実際には PIC X(4)）。

  • Q2. PIC S9(5)V99 は、整数部・小数部がそれぞれ何桁で、符号を持てますか？ 記憶される桁数は合計で何桁ですか？

    回答を表示

    整数部5桁・小数部2桁で、S があるのでマイナスの値も持てます。V は小数点の位置を表すだけで1桁を使わず、S も桁を使わないので、記憶される数字は合計7桁です。

  • Q3. PIC 9(3) の項目に MOVE 12345 したときと、PIC X(4) の項目に MOVE "ABCDEFG" したときの結果は、それぞれどうなりますか？

    回答を表示

    数字の項目は上位の桁が切り捨てられ、345 になります。文字の項目は右側が切り捨てられ、ABCD になります。どちらもエラーにはならず、黙って切り捨てられます。

  • Q4. PIC X(6) に「山田太郎」を MOVE すると、どうなりますか？ また、本ガイドで PIC X に入れる値を半角英数字にする理由を答えてください。

    回答を表示

    UTF-8 では「山」「田」「太」「郎」はどれも1文字3バイトなので、「山田太郎」は12バイトです。6バイトの箱には「山田」の分だけが入り、「太郎」は切り捨てられます。切れ目が文字の途中だと文字化けもします。桁数がバイトで決まるため、日本語では桁の計算が難しくなるので、データ値は半角英数字にします。
