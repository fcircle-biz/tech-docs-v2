実践：売上集計バッチを作ろう - 総まとめと次のステップ

最終章では、これまでの知識を総動員して、順不同の売上データを並べ替え、商品ごとの小計と総合計を帳票にまとめる「売上集計バッチ」を完成させます。仕様 → 設計 → 部品ごとの実装 → 組み立て → 実行 → テストという、現場の開発と同じ流れで進めましょう。最後に、COBOL のさらに先にある学習の道すじも紹介します。

この章で学ぶこと

  • 作るものを仕様と入出力の例で整理し、段落構成に分けて設計できる
  • SORT文（SD・USING・GIVING）でデータを並べ替えられる
  • コントロールブレイク（キーが変わったら小計を出す）の仕組みを理解し、最後のグループの小計も出せる
  • 編集項目と FILLER で、桁のそろった帳票を出力できる
  • テストの観点（0件・1件・同じ商品だけ）を持ち、COBOL の次の学習ステップを把握する

14.1 作るもの（仕様）

いよいよ最終章です。ここまでの章で学んだ「データ項目」「計算」「判断」「繰り返し」「ファイル処理」を総動員して、文房具店の売上集計バッチを作ります。第1章で見た「入力ファイル → COBOLプログラム → 帳票」という、バッチ処理の基本形そのものです。

まず、「何を作るのか」を決めます。プログラムを書き始める前に入力と出力の例を紙に書くのは、現場でも使う基本の進め方です。

項目内容
入力sales.txt：売上レコード（第9章・第12章と同じ20バイト）を1行1件で並べたファイル。日付も商品もばらばら（順不同）

14.2 設計：段落に分けて考える

大きなプログラムを一度に書こうとすると混乱します。第8章で学んだとおり、「初期処理 → 主処理（繰り返し）→ 終了処理」の形にして、段落ごとに役割を決めてから書きましょう。

最初の1件を先読み"] M --> L{"ファイルの終わりまで繰り返す"} L --> D["DETAIL-PROC

図の説明: 段落の呼び出し関係です。BREAK-PROC（小計を出す段落）は、途中のキー変化と、最後の終了処理の2か所から呼ばれます。

段落役割主に使う知識
MAIN-PROC各段落を順に呼び出す。プログラム全体の流れ第8章 PERFORM
SORT-PROC入力ファイルを商品コード・日付の順に並べ替える14.3 SORT文

段落名は第8章からの規約どおり -PROC で終わる名前にしています。主プログラムの最後は STOP RUN. です。

14.3 SORT文：データを並べ替える

入力データは順不同ですが、商品ごとの集計は「同じ商品が連続して並んでいる」ことが前提です（理由は 14.4 で説明します）。そこで、まず SORT文で並べ替えます。COBOL には並べ替えの命令が最初から備わっているので、自分で並べ替えの手順を書く必要はありません。

SORT文の書き方 PROCEDURE DIVISIONの抜粋 
      * 商品コード→日付の順に並べ替える
       SORT-PROC.
           SORT WK-FILE
               ON ASCENDING KEY WK-ITEM WK-DATE
               USING IN-FILE
               GIVING SORTED-FILE.

SORT文の読み方は、英語の文章そのままです。

  • SORT WK-FILE：並べ替え作業に使うソート用ファイル（WK-FILE）を指定します。
  • ON ASCENDING KEY WK-ITEM WK-DATE：並べ替えのキー（基準）です。ASCENDING は昇順（小さい順）。最初に書いたキー（商品コード）が優先で、同じ商品の中では次のキー（日付）で並べます。
  • USING IN-FILE：並べ替える前のデータを読み込む入力ファイルです。
  • GIVING SORTED-FILE：並べ替えた結果を書き出すファイルです。

ソート用ファイルは、データ部のファイル節で SD（Sort Description）という見出しで定義します。FD の代わりに SD と書き、キーに使う項目（WK-DATE・WK-ITEM）を含むレコードを定義します。環境部の SELECT には、作業用の名前を書くだけで構いません（行順の指定は不要です）。

SORT文で注意すること

USING と GIVING に指定したファイルは、SORT文が自分で開いて閉じます。SORT文の前に OPEN してはいけません（規格で禁止されている書き方です。処理系によってはエラーになり、エラーにならない処理系でも結果は保証されません）。また、SD のレコードの長さと並び（項目の位置）は、入力ファイルのレコードと同じにしてください。

メインフレームでは

メインフレームでも SORT文の基本の書き方は同じです。ファイル名の対応づけ（ASSIGN の先）は JCL（ジョブ制御言語）で行います。

14.4 コントロールブレイク：キーが変わったら小計を出す

この章でいちばん大切な考え方がコントロールブレイク（キーブレイク）です。名前は難しそうですが、考え方は単純です。

コントロールブレイクの考え方

並べ替えたデータを上から順に読み、「キー（ここでは商品コード）が前の行から変わった」ことを見つけたら、直前のグループの小計を出す。変わらない間は、数量と金額を小計に足し続ける。

たとえるなら、仕分け済みの伝票の束を1枚ずつめくりながら電卓をたたく作業です。「A001の伝票が続く間は足し続ける。B002の伝票が出てきたら、いったんA001の合計を紙に書き、電卓をクリアしてB002を足し始める」。これをプログラムにするだけです。

そのために、前の行のキーを覚えておく項目（WS-PREV-ITEM）と、小計を貯めていく項目（WS-SUB-QTY・WS-SUB-AMT）を用意します。

具体的なデータで1行ずつ追ってみよう

並べ替え後の9件を上から読んでいくとき、プログラムは次のように動きます。表の「小計の貯め箱」は、その行を処理し終えた後の WS-SUB-AMT の値です。なお、最初の1件を読んだ直後に、そのキー（A001）を前のキーに入れておくので、1行目ではブレイクが起きません（14.6 の部品6）。

順読んだ行前のキー
(WS-PREV-ITEM)		比較の結果することと、処理後の貯め箱
1A001（金額 360）A001同じ明細を出力。貯め箱 = 360
2A001（金額 240）A001同じ明細を出力。貯め箱 = 600
3A001（金額 120）A001同じ明細を出力。貯め箱 = 720
4A001（金額 600）A001同じ明細を出力。貯め箱 = 1,320
5B002（金額 500）A001違う（ブレイク）A001の小計 1,320 を出力。貯め箱を0に戻し、前のキーを B002 に更新。明細を出力。貯め箱 = 500
6B002（金額 1,000）B002同じ明細を出力。貯め箱 = 1,500
7B002（金額 1,500）B002同じ明細を出力。貯め箱 = 3,000
8C003（金額 1,500）B002違う（ブレイク）B002の小計 3,000 を出力。貯め箱を0に戻し、前のキーを C003 に更新。明細を出力。貯め箱 = 1,500
9C003（金額 600）C003同じ明細を出力。貯め箱 = 2,100

ポイントは、キーの比較を「明細を出力する前」に行うことです。新しい商品の行を読んだ時点では、貯め箱にはまだ前の商品の合計が入っています。先に小計を出してから、新しい行を足し始めます。

図の説明: 1件ごとのキー比較と、最後のグループの小計の出力です。

最後のグループの小計を忘れない

キーが「変わった」ことをきっかけに小計を出す仕組みなので、最後のグループの次には「変わる相手」が存在せず、小計が出ません。ファイルの終わりに達したら、ループの外（終了処理）で最後のグループの小計を必ず出力してください。コントロールブレイクで最も多い間違いです。実際に忘れるとどうなるかは、14.6 で確かめます。

なぜ並べ替えが必要か

データが A001、B002、A001 のように行き来していると、「キーが変わるたび」に小計が出てしまい、同じ商品の小計が何か所にも分かれてしまいます。「同じキーが連続している」ことがコントロールブレイクの前提なので、先に SORT します。

14.5 帳票の編集：行の形を設計する

帳票は「決まった位置に決まった桁数」で並べるのが基本です。第9章で学んだ FILLER（名前のない項目）で項目の間にすき間を作り、第5章の編集項目（ZZ9・ZZ,ZZ9・Z,ZZZ,ZZ9）で数値を読みやすく整えます。

見出し行・明細行・小計行・合計行は、同じ位置に同じ種類の列が来るように設計します。1行は38桁で、列は次のように割り当てます。

列位置（桁）幅明細行小計行合計行
商品コード1〜44DL-ITEMSL-ITEM（TOTAL の文字）
日付／ラベル7〜148DL-DATESUBTOTAL の文字（TOTAL の文字）
数量17〜193DL-QTY（ZZ9）SL-QTY（ZZ9）TL-QTY（ZZ9）
単価22〜276DL-PRICE（ZZ,ZZ9）空白空白
金額30〜389DL-AMOUNT（Z,ZZZ,ZZ9）SL-AMOUNTTL-AMOUNT

行の定義は 14.6 のデータ部で見ます。ここで押さえるのは次の2点です。

  • 各列の開始位置（上の表の「位置」）がどの行でも同じになるように、FILLER の幅を決めます。結果として、どの行も合計38桁になります。
  • 金額は編集項目 Z,ZZZ,ZZ9 で桁区切りします。Z は「先頭のゼロを空白にする」記号なので、360 は [ 360] のように右寄せで表示されます（[ ] は項目の範囲で、中は9桁です）。

金額の計算は編集項目の前に

編集項目は計算の材料（足される側・式の右辺）にはできません（第5章）。COMPUTE の結果の受け取り先には指定できますが、本ガイドでは数字項目で計算してから MOVE する形にそろえます。そのため、金額は計算用の項目（WS-AMOUNT など数字だけの項目）で求めてから、書き出す直前に編集項目へ MOVE します。

14.6 完成プログラム：部品ごとに作って組み立てる

ここまでの設計を、環境部・データ部・手続き部の順に、8つの部品に分けて実装します。それぞれ単独では動きません。順につなげて1つのファイルに保存します。部品1から8までを順番につなげると、完全なプログラム salesrpt.cob になります。組み立てに必要な見出し行（IDENTIFICATION DIVISION.・PROGRAM-ID.・ENVIRONMENT DIVISION.・DATA DIVISION.・WORKING-STORAGE SECTION.・PROCEDURE DIVISION. など）は、すべて部品の中に含まれています（別に書き足す行はありません）。

部品1：見出し部と環境部（ファイルの指定）

4つのファイルを使います。入力 sales.txt、ソート用の作業ファイル、ソート済みの sorted.txt、帳票 report.txt です。

部品6：手続き部（MAIN-PROC と SORT-PROC）

MAIN-PROCが全体の流れを指揮します。先読み（ループに入る前に最初の1件を読む。第12章）をして、最初のレコードのキーを「前のキー」に入れておきます。こうすると、最初の行でブレイクが起きません。ファイルが空（0件）のときは、キーを設定せずにループも飛ばします。

salesrpt.cob（部品 6/8） PROCEDURE DIVISIONの抜粋 
       PROCEDURE DIVISION.
       MAIN-PROC.
           PERFORM SORT-PROC
           PERFORM INIT-PROC
           PERFORM READ-PROC
           IF NOT WS-EOF-YES
               MOVE SR-ITEM TO WS-PREV-ITEM
           END-IF
           PERFORM UNTIL WS-EOF-YES
               PERFORM DETAIL-PROC
               PERFORM READ-PROC
           END-PERFORM
           PERFORM TERM-PROC
           STOP RUN.
      * 商品コード→日付の順に並べ替える
       SORT-PROC.
           SORT WK-FILE
               ON ASCENDING KEY WK-ITEM WK-DATE
               USING IN-FILE
               GIVING SORTED-FILE.

部品7：手続き部（INIT-PROC・READ-PROC・DETAIL-PROC）

DETAIL-PROCが、14.4 の考え方をそのままコードにした段落です。IF の中でキーを比較して小計を出し、それから金額を足す順番になっています。本ガイドの規約どおり、IF・READ・インライン PERFORM のように END-xxx（スコープ終了符）で閉じる文は、内側にピリオドを書いていません。単純な命令文は、段落の最後の文にだけピリオドを置いています。

salesrpt.cob（部品 7/8） PROCEDURE DIVISIONの抜粋 
       INIT-PROC.
           OPEN INPUT SORTED-FILE
           OPEN OUTPUT REPORT-FILE
           WRITE REPORT-REC FROM WS-HEAD-LINE
           WRITE REPORT-REC FROM WS-RULE-LINE.
       READ-PROC.
           READ SORTED-FILE
               AT END SET WS-EOF-YES TO TRUE
           END-READ.
       DETAIL-PROC.
      * キーが変わったら先に小計を出す
           IF SR-ITEM NOT = WS-PREV-ITEM
               PERFORM BREAK-PROC
           END-IF
           COMPUTE WS-AMOUNT = SR-QTY * SR-PRICE
           ADD SR-QTY TO WS-SUB-QTY
           ADD WS-AMOUNT TO WS-SUB-AMT
           ADD 1 TO WS-COUNT
           MOVE SR-ITEM TO DL-ITEM
           MOVE SR-DATE TO DL-DATE
           MOVE SR-QTY TO DL-QTY
           MOVE SR-PRICE TO DL-PRICE
           MOVE WS-AMOUNT TO DL-AMOUNT
           WRITE REPORT-REC FROM WS-DETAIL-LINE.

部品8：手続き部（BREAK-PROC・TERM-PROC）

BREAK-PROCは「小計行を出す」ための段落で、小計を総合計に足し込み、貯め箱を0に戻し、前のキーを新しいキーに更新するまでを担当します。TERM-PROCは、ループが終わったあとに最後のグループの小計を出し、総合計を書いてファイルを閉じます。

salesrpt.cob（部品 8/8） PROCEDURE DIVISIONの抜粋 
      * 小計行を出し、次のグループの準備をする
       BREAK-PROC.
           MOVE WS-PREV-ITEM TO SL-ITEM
           MOVE WS-SUB-QTY TO SL-QTY
           MOVE WS-SUB-AMT TO SL-AMOUNT
           WRITE REPORT-REC FROM WS-SUB-LINE
           ADD WS-SUB-QTY TO WS-TOT-QTY
           ADD WS-SUB-AMT TO WS-TOT-AMT
           MOVE ZERO TO WS-SUB-QTY
           MOVE ZERO TO WS-SUB-AMT
           MOVE SR-ITEM TO WS-PREV-ITEM.
       TERM-PROC.
      * 最後のグループの小計はループの外で出す
           IF WS-COUNT > 0
               PERFORM BREAK-PROC
           END-IF
           MOVE WS-TOT-QTY TO TL-QTY
           MOVE WS-TOT-AMT TO TL-AMOUNT
           WRITE REPORT-REC FROM WS-RULE-LINE
           WRITE REPORT-REC FROM WS-TOTAL-LINE
           CLOSE SORTED-FILE REPORT-FILE
           DISPLAY "READ RECORDS: " WS-COUNT.

テストデータ確かめたいこと期待する結果

これで COBOL の基本文法を使って、実際に動くバッチプログラムを作れるようになりました。ここから先は、実際の現場で使われる環境と技術を少しずつ知っていくことになります。

図の説明: 本章の先に広がる学習の道すじです。

z/OS と JCL

z/OS は IBM のメインフレームの基本ソフト（OS）です。そこで COBOL プログラムを動かすには、JCL（ジョブ制御言語）で「どのプログラムを、どのファイルを使って実行するか」を書いたジョブを投入します。第12章のコラムで触れたとおり、ASSIGN で指定した名前と実際のファイルは JCL で結びつけられます。現場では、本章のような並べ替えを、COBOL の SORT 文ではなく JCL のソート専用ステップ（DFSORT などのユーティリティ）で行うことも多くあります。

CICS（オンライン処理）

CICS は、メインフレーム上でオンライン処理（第1章）を動かすための仕組みです。画面や端末からの操作に応じて、COBOL プログラムがその場で呼び出されます。バッチは「まとめて処理」、CICS は「その場で処理」という使い分けです。

Db2 と埋め込み SQL

本章ではテキストファイルを読み書きしましたが、現場ではデータベース（IBM Db2 など）を使うことも多くあります。COBOL のプログラムの中に EXEC SQL 〜 END-EXEC で SQL を埋め込み、データを検索・更新します。SQL の基礎を学んでおくと入りやすくなります。

VSAM・索引ファイル

本ガイドで扱った順ファイルは、先頭から順に読むファイルでした。メインフレームでは、キーを指定して目的のレコードを直接読み書きできる索引ファイルも使われます。代表が VSAM で、その中のキー順のファイル（KSDS）が索引ファイルにあたります。COBOL では ORGANIZATION IS INDEXED のように指定し、READ や WRITE にキーを使います。

学ぶ環境と進め方

  • IBM Z Xplore：IBM が提供している、メインフレーム（z/OS）を無償で体験できる学習環境です。自分でメインフレームを用意しなくても、インターネット経由で IBM の z/OS に接続し（VS Code と拡張機能などを使います）、JCL や COBOL の演習を試せます。本ガイドで学んだ基本文法をそのまま活かせます（提供内容や利用条件は変わることがあるので、最新の案内を確認してください）。
  • 既存プログラムを読む力：現場では、新規開発より既存プログラムの保守・改修のほうが多くなります。まず読むことが最重要です。見出し部で目的を確認し、データ部で何を扱うかをつかみ、手続き部の MAIN 段落から呼び出しをたどる、という読み方は、本ガイドで身につけた構造の理解そのものです。自分で書いたプログラムを数日後に読み直すのも良い練習になります。
  • モダナイゼーション：長年動いてきた COBOL の資産を、新しい環境や他の言語へ移行したり、新しいシステムと連携させたりする取り組みです（第1章）。移行するにも連携するにも、COBOL プログラムの仕様を正しく読み取れる人が必要です。業務ルールを COBOL から読み解いて、新しいシステムに引き継ぐ役割が求められます。

理解度確認クイズ

  • Q1. コントロールブレイクで小計を出す前に、入力データを SORT しておく必要があるのはなぜですか？

    回答を表示

    同じキー（商品コード）のデータが連続して並んでいることが、コントロールブレイクの前提だからです。順不同のままだと、同じ商品が離れた場所に何度も現れ、そのたびにキーが「変わった」と判断されて、同じ商品の小計が何か所にも分かれてしまいます。

  • Q2. コントロールブレイクの処理で、「最後のグループの小計」はなぜ特別に扱う必要がありますか？ 本章のプログラムではどこで出力していますか？

    回答を表示

    小計は「キーが変わった」ことをきっかけに出す仕組みですが、最後のグループの後にはキーが変わる相手の行がないため、ループの中では小計が出ません。そこで、ファイルの終わりを検出してループを抜けた後の終了処理（TERM-PROC）で、BREAK-PROC を呼んで最後の小計を出力しています。

  • Q3. SORT文の SORT WK-FILE ON ASCENDING KEY WK-ITEM USING IN-FILE GIVING SORTED-FILE で、WK-FILE・USING・GIVING はそれぞれ何を表していますか？

    回答を表示

    WK-FILE は並べ替えの作業に使うソート用ファイル（データ部で SD として定義）、USING は並べ替える前のデータを読み込む入力ファイル、GIVING は並べ替えた結果を書き出す出力ファイルです。USING・GIVING のファイルは、SORT文が自分で開いて閉じるので、SORT文の前に OPEN してはいけません。

  • Q4. メインフレームで COBOL のバッチプログラムを実行するとき、「どのプログラムを、どのファイルを使って動かすか」を指定するために書くものは何ですか？

    回答を表示

    JCL（ジョブ制御言語）です。プログラム内の SELECT 〜 ASSIGN で付けた名前と、実際のデータセット（ファイル）を JCL で結びつけます。本ガイドの GnuCOBOL では、ASSIGN にファイル名を直接書いていましたが、メインフレームではこの部分を JCL が担当します。

おわりに（ガイドのまとめ）

全14章、おつかれさまでした。ここまでで、次のことができるようになりました。

  • COBOL プログラムの骨組み（4つの部）と固定形式の桁のルールを理解して書ける（第2〜3章）
