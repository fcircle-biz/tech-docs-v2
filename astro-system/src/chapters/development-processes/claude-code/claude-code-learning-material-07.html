ホーム Claude Code 第7章
第7章 所要時間: 約50分

コンテキスト管理

Claude Code は、あなたが送るメッセージ・読み込むファイル・実行したコマンドの結果を、すべて「コンテキストウィンドウ」と呼ばれる作業用の記憶領域に積み上げながら動作します。この章では、コンテキストウィンドウの正体と、それをコントロールする/compact・/clear・/contextの使い分けを学びます。「コンテキストをどう扱うか」という本章のテーマは、第8章の CLAUDE.md・第9章のサブエージェント・第11章の MCP に共通する、本ガイド全体を貫く背骨です。

この章で学ぶこと

  • コンテキストウィンドウとは何か、Claude の「作業記憶」としてイメージできる
  • 何がコンテキストを消費するのか（プロンプト入力・ファイル読み込み・ツール実行・実行結果の受け取り）を説明できる
  • コンテキストが逼迫したときに起こる自動圧縮の仕組みと、そこに潜む注意点を理解する
  • /compact・/clear・/contextを目的に応じて使い分けられる
  • コンテキストを節約する3つのコツと、それぞれが後続の章とどうつながるかを説明できる

7.1 コンテキストウィンドウとは

「コンテキスト」とは、Claude の作業用の記憶領域のことです。プロンプトを入力したとき、Claude がファイルを読み込んだとき、ツールを実行したとき、ツールの実行結果を受け取ったとき――そのすべてが「コンテキストウィンドウ」と呼ばれる領域に積み上がっていきます。第1章で触れたとおり、コンテキストウィンドウの容量には限りがあります。この限りをどう扱うかが、Claude Code を使いこなせるかどうかを大きく左右します。

用語: 「トークン（token）」とは

Claude が文章を処理するときの最小単位です。日本語ではおおよそ1〜2文字が1トークンに相当します（英語ではおおよそ4文字で1トークン）。コンテキストウィンドウの容量は、このトークンの個数（例: 200,000トークン）で表されます。

容量が限られているからといって、コードベース全体を一度に読み込む必要はありません。Claude Code が「agentic」であることの強みはここにあります。必要なファイルだけを戦略的に探し出し、目的にたどり着けるように動くのです（第1章・第2章）。とはいえ、探索や会話が長く続けば続くほど、コンテキストウィンドウは着実に消費されていきます。次節では、具体的に何が容量を消費するのかを見ていきましょう。

7.2 何が消費するのか

コンテキストウィンドウは、主に次の4つのタイミングで少しずつ消費されていきます。

プロンプト入力時

あなたが送るメッセージそのものがコンテキストに加わります。

ファイル読み込み時

Claude がコードを理解するために読み込んだ内容が積み上がります。

ツール実行時

コマンドの実行やファイル編集そのものも記録として積み上がります。

実行結果の受け取り時

テストのログやコマンドの出力を受け取るたびに容量を使います。

実際にセッションを進めていくと、コンテキストウィンドウの中身は次のようなカテゴリに分かれます。/contextコマンドを実行すると、この内訳を実際に確認できます（7.4）。

コンテキストウィンドウの内訳（イメージ）

システムプロンプト 5%
CLAUDE.md 8%
MCPツール定義 12%
会話（履歴） 35%
ツール実行結果 25%
空き容量 15%
分類 内容 関連する章
システムプロンプト Claude Code 自体の基本的な振る舞いを定義する部分 ―
CLAUDE.md プロジェクトの記憶ファイルの内容 第8章
MCPツール定義 接続している MCP サーバーが提供するツールの一覧 第11章
会話（メッセージ履歴） これまでのプロンプトと Claude の応答 ―
ツール実行結果 ファイル読み込みやコマンド実行の出力 ―

7.3 いっぱいになるとどうなるか

コンテキストウィンドウの上限に近づくと、Claude Code は自動的に圧縮（compact）を行います。圧縮では、重要な情報を要約し、もう不要になったツールの実行結果を取り除くことで、空き容量を確保します。

注意: 自動圧縮では細かい情報が失われることがある

自動圧縮は要約によって重要な情報を残そうとしますが、要約である以上、ファイルの正確な内容や細かい判断の経緯といった情報が失われる可能性があります。あとで参照したい詳細があるなら、自動圧縮に任せきりにせず、次節で説明する/compactを自分のタイミングで使うほうが安全です。

7.4 3つのコマンド

コンテキストは自動圧縮に任せきりにする必要はありません。Claude Code には、コンテキストを自分の意思でコントロールするための3つのコマンドが用意されています。

コマンド 効果 使うタイミング
/compact その時点までの内容を要約し、手動で圧縮する 作業内容の記憶を保ちつつ空き容量を確保したいとき
/clear 会話履歴をすべて消去し、まっさらな状態に戻す 前のセッションの記憶を一切残さず、ゼロから始めたいとき
/context 現在のコンテキストの使用状況（容量・内訳）を確認する 何がどれだけ容量を占めているかを把握したいとき

実際の使用イメージは、次のとおりです。

terminal — /context と /compact の実行例 
> /context
◐ コンテキスト使用量: 170,000 / 200,000 トークン（85%）
  内訳: システムプロンプト 5%／CLAUDE.md 8%／MCPツール定義 12%
  　　　会話 35%／ツール実行結果 25%／空き容量 15%

> /compact
● 会話を圧縮しています…
● 重要な決定事項と変更したファイルを要約しました
● コンテキスト使用量: 85% → 20%（空き容量を確保しました）

※ 表示される数値やレイアウトは、利用しているモデルやバージョンによって異なります。

7.5 どちらを使うべきか

/compactと/clearは、どちらもコンテキストを整理するコマンドですが、向いている場面はまったく異なります。判断のポイントは「次に取り組むのが同じ機能の続きか、新しい機能か」です。

flowchart TD A["コンテキストが残り少なくなってきた"] --> B{"次に取り組むのは？"} B -->|"今の機能の続き"| C["/compact を使う"] B -->|"新しい機能に着手"| D["/clear を使う"] C --> E["要約された文脈を保ちながら継続する"] D --> F["前の会話のバイアスを持ち込まず、まっさらに始める"]
観点 /compact /clear
会話の記憶 要約として保持される 完全に消去される
適した場面 同じ機能の作業を続けたいとき 新しい機能に着手するとき
メリット 現在の文脈を保ったまま空き容量を確保できる 前の会話のバイアスを持ち込まず、まっさらに始められる
注意点 要約により細かい情報が失われる可能性がある（7.3） 覚えておいてほしいことは事前に CLAUDE.md へ（7.6）

7.6 セッションをまたぐ記憶は CLAUDE.md へ

/clearを使うと、会話の記憶は完全に消えます。ですが、「このプロジェクトでは pnpm を使う」「2スペースインデント」のように、セッションをまたいで毎回覚えておいてほしいことを、消えてしまう会話の記憶だけに頼るのは得策ではありません。そのために用意されているのが CLAUDE.md ファイルです。

次章の予告: CLAUDE.md

CLAUDE.md はプロジェクトのルートに置く Markdown ファイルで、セッション開始のたびに自動的に読み込まれます。/clearで会話をリセットしても、CLAUDE.md に書かれた内容は毎回思い出してもらえます。詳しくは第8章で学びます。

7.7 節約の3つのコツ

コンテキストは有限な資源です。ここでは、コンテキストを無駄遣いしないための3つのコツを紹介します。

1

具体的に指示する

曖昧なプロンプトは一見コンテキストの消費が少なく見えますが、実際には長い目で見るとより多くのコンテキストを消費します。指示が曖昧だと、Claude はコードベースをより広く探索し、自分で判断せざるを得なくなるからです。詳しく指示するほど、遠回りな探索を減らせます。

2

MCPサーバーを管理する

MCPサーバーは、使っていなくても既定ではすべてのツール定義をコンテキストに読み込みます。今取り組んでいるプロジェクトと関係のないサーバーはオフにしましょう。MCPサーバーの仕組みと管理方法は第11章で詳しく学びます。

3

サブエージェントを使う

サブエージェントはメインエージェントと並行して動作しますが、まったく別のコンテキストウィンドウを持ちます。「認証のエンドポイントはどこにあるか」のように結果さえ分かればよいタスクなら、サブエージェントに探索を任せ、要約だけを受け取ることでメインのコンテキストをきれいに保てます。作り方は第9章で学びます。

ここまで学んだコンテキスト管理は、実は本ガイドの背骨（バックボーン）です。この後に続く3つの章は、いずれも「コンテキストをどう扱うか」という本章のテーマを、それぞれ異なる角度から具体化した各論にすぎません。

手順

  1. 1 Claude Code を起動し、これまで通り何かひとつタスクを依頼する（前章までの続きでも、新しい簡単な質問でもかまいません）。
  2. 2 ある程度やり取りが進んだら /context を実行し、使用量とカテゴリ別の内訳（7.2）を確認する。
  3. 3 表示された内訳を見て、「同じ機能の続きなら /compact」「新しい機能に切り替えるなら /clear」のどちらが今の状況に合うかを7.5の表を見ながら考え、実際に実行してみる。

理解度確認クイズ

  1. Q1. コンテキストウィンドウとは何ですか。何が容量を消費しますか。

    回答を表示

    Claude の作業用の記憶領域（作業記憶）のことです。プロンプトの入力・ファイルの読み込み・ツールの実行・ツールの実行結果の受け取りのたびに容量が積み上がっていきます。容量には上限があり、上限に近づくと自動的に圧縮（compact）されます。

  2. Q2. /compact と /clear はそれぞれどのような場面で使うべきですか。

    回答を表示

    /compactは同じ機能の作業を続けたいときに使います。それまでの内容を要約して圧縮するため、現在の文脈を保ったまま空き容量を確保できます。/clearは新しい機能に着手するときに使います。会話履歴をすべて消去することで、前の会話が新しい作業にバイアスをかけるのを避けられます。セッションをまたいで覚えておいてほしいことは CLAUDE.md に書いておきます。

  3. Q3. コンテキストの容量を節約する3つのコツを挙げてください。

    回答を表示

    ①具体的に指示する（曖昧な指示はかえって探索範囲を広げ、長い目で見るとより多くのコンテキストを消費する）、②MCPサーバーを管理する（使っていないサーバーのツール定義はオフにする。第11章）、③サブエージェントを使う（別のコンテキストウィンドウに探索を任せ、要約だけを受け取る。第9章）の3つです。
