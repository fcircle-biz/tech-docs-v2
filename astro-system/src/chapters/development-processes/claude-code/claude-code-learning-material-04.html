最初のプロンプトと許可モード

第2章では許可モードの概要を、第3章ではセットアップを学びました。この章ではいよいよ Claude Code に実際に話しかけます。Shift + Tab で切り替わる3つの許可モードを理解し、ダークモードのトグル追加を題材にした実演を通して、安全に最初の依頼を出す感覚を身につけましょう。

この章で学ぶこと

  • Claude Code への話しかけ方の基本感覚をつかむ
  • Shift + Tab で3つの許可モードを切り替えられるようになる
  • 承認モード・自動承認モード・プランモードの違いと使いどころを説明できる
  • プランモードを使ってダークモード実装を安全に依頼する流れを体験する
  • 具体的なプロンプトの書き方と、覚えておきたい基本操作を身につける

4.1 まずは話しかけてみる

第3章でセットアップが完了したら、いよいよ Claude Code に話しかけてみましょう。Claude Code とのやり取りは、他のAIアシスタントに話しかけるのと同じ感覚で行えます。特別な構文を覚える必要はなく、自然な文章で「やってほしいこと」を伝えるだけです。

ただし、プロンプトを入力する際に知っておくと、安全性や作業のしやすさにつながるポイントがいくつかあります。それが、この章のテーマである許可モードです。Claude Code がファイルを編集したりコマンドを実行したりする前に、どこまで自分の確認を挟むかを自分でコントロールできます。

4.2 Shift + Tab によるモード切替

Claude Code には3つの許可モードがあり、入力欄で Shift + Tab キーを押すたびに、次のモードへと順番に切り替わります。今どのモードにいるかは、入力欄の下に表示されるラベル（例: プランモードなら「Plan mode on」など）で確認できます。

stateDiagram-v2 [*] --> 承認モード 承認モード --> 自動承認モード: Shift + Tab 自動承認モード --> プランモード: Shift + Tab プランモード --> 承認モード: Shift + Tab note right of 承認モード Claude Code起動直後の既定モード end note

どのモードを使うべきかという正解はありません。慣れないうちは承認モードで一つずつ確認しながら進め、Claude Code の動きが読めるようになってから、自動承認モードやプランモードを使い分けていくとよいでしょう。それぞれのモードを詳しく見ていきます。

4.3 各モードの詳細と使いどころ

3つのモードの違いを一覧にまとめました。

モード ファイルの編集 コマンドの実行 向いている場面
承認モード（既定） 都度、明示的な許可を求める 都度、明示的な許可を求める 初めて使うプロジェクト、変更を一つずつ把握したいとき
自動承認モード 確認なしで自動的に承認される 引き続き許可が必要 信頼できる小さな修正を素早く進めたいとき
プランモード 行わない（読み取り専用ツールのみ） ファイルを変更するコマンドは実行しない（ls や git log のような読み取り専用の確認コマンドは使われることがある） 複雑な変更の計画・安全なコードレビュー・複数ステップの実装

注意: 自動承認モードの使いどころ

自動承認モードは便利ですが、ファイルの編集が確認なしで進むため、意図と違う変更に気づきにくくなることがあります。まずは使い慣れたプロジェクト・小さな変更から試し、コマンド実行の許可を求められたときは内容をよく確認しましょう。

4.4 プランモード

プランモードでは、あなたのプロンプトを受け取った Claude が読み取り専用のツールを使ってコードベースを分析し、提案する実装方法を検討します。作業の途中で確認したい点があれば質問を挟みながら、最終的に実行可能な詳細なプランを提示します。

プランモードが特に力を発揮するのは、次のような場面です。

複雑な変更の計画

影響範囲が広い変更ほど、先にプランで全体像を把握できると安心です。

安全なコードレビュー

ファイルを変更せず、調査や分析だけをしてほしいときに活用できます。

複数ステップの実装

ある機能に向けた何段階もの実装が必要な場面でこそ真価を発揮します。

重要ポイント

プランモードの本質は、コードを1行も書く前に、Claude の理解と方針をすり合わせられることです。この「コードを書く前に軌道修正する」という考え方は、第5章で学ぶ Explore→Plan→Code→Commit ワークフローの土台になります。

4.5 実演: ダークモードのトグルを追加する

具体例を見ていきましょう。あなたのアプリケーションに、ダークモードのトグルを追加する必要があるとします。次の手順で進めます。

  1. 1 プロジェクトのルートディレクトリを開き、ターミナルで claude を実行してセッションを開始する。
  2. 2 Shift + Tab を数回押し、入力欄の下に「Plan mode on」と表示されるまでモードを切り替える。
  3. 3 下記のプロンプトを、原文のまま入力して送信する。
  4. 4 Claude が読み取り専用ツールでコードベースを調査し、実行可能な詳細プランを提示するのを待つ。
  5. 5 提示されたプランを読み、内容に問題がなければ承認する（気になる点があれば、その場で質問や修正依頼を挟む）。
  6. 6 承認後は実装フェーズに入る。各ステップを自動で進めさせるか、一つずつ確認しながら進めるかを選ぶ。
  7. 7 完了したら、Claude が何を行い、どのような判断でその結論に至ったのかを振り返って確認する。

実際の入力と Claude の応答は、次のようなイメージになります。

terminal — プランモードでの実演 
$ claude
（Shift + Tab を数回押し、入力欄の下に「Plan mode on」と表示されたことを確認）

> アプリ全体にダークモードを実装する必要があります。ヘッダーにライトモードとダークモードを切り替えられるトグルスイッチを作ってもらえますか？既存のライトテーマに合わせて、コントラストの良い色を見つけてほしいです。

● Plan mode onで動作しています（読み取り専用ツールのみを使用）
● src/components/Header 配下の構成とスタイル定義を調査しています…
● 既存のライトテーマのカラートークンを確認しました。
● コントラストを保った配色案とトグルの実装プランを作成しました。承認しますか？

Claude Codeを使う際は、できるだけ具体的にプロンプトを書くようにしましょう。すべてのステップを把握しておきたい場合は、そうすることもできます。実際にコードを実行する前に、達成したいことの詳細をClaudeに掘り下げてもらうために、プランモードを活用してください。

4.6 良いプロンプトの書き方

曖昧な指示は、一見手間が少なく見えても、実際には Claude が目的を推測するための余計な探索（関係ありそうなファイルの検索・読み込み）を発生させ、かえって遠回りになることがあります。できるだけ具体的に書くほど、Claude は迷わず正しい行動を選べます。

曖昧な指示の例

「ログイン画面、なんかおかしいので直しておいて」

→ 何が・どこが・どうおかしいのかが分からず、Claude が原因を推測するために広くファイルを探索することになる。

具体的な指示の例

「src/auth/login.ts で、トークン期限切れ後も画面遷移してしまう不具合があります。原因を調査して修正し、npm test が通ることを確認してください」

→ 対象ファイル・症状・完了条件が明確なので、Claude は迷わず調査に入れる。

先取り: コンテキストとの関係

曖昧な指示による「余計な探索」は、実はコンテキストウィンドウ（Claude の作業記憶）を余分に消費する原因にもなります。コンテキストの管理については第7章でじっくり学びます。

4.7 覚えておきたい基本操作

最後に、セッション中によく使う基本操作を4つ押さえておきましょう。

操作 説明
Esc 実行中の処理を中断する（割り込み）
/help 使えるスラッシュコマンドの一覧を表示する
/clear 会話の履歴をすべて消去し、まっさらな状態から始める（詳しくは第7章）
/exit Claude Code のセッションを終了する

やってみよう 4-1: 許可モードを切り替えて、実際に依頼してみる

実際に手を動かして、3つのモードの感触をつかみましょう。

手順

  1. 1 自分の手元にあるプロジェクト（無ければ、簡単なサンプルコードで構わない）のルートディレクトリで claude を起動する。
  2. 2 Shift + Tab を数回押し、承認モード→自動承認モード→プランモードと表示が切り替わることを確認する。
  3. 3 プランモードのまま、今すぐ着手したい小さな変更を1文で依頼してみる（例:「READMEに使い方セクションを追加してください」）。
  4. 4 提示されたプランを読み、「承認する」「修正を依頼する」「質問する」のいずれかで応答してみる。

理解度確認クイズ

  1. Q1. Shift + Tab を押すと、許可モードはどのように切り替わりますか？3つのモード名も挙げてください。

    回答を表示

    承認モード → 自動承認モード → プランモードの順に、Shift + Tab を押すたびに循環して切り替わります。①承認モード（既定・ファイル編集もコマンド実行も都度確認）、②自動承認モード（ファイル編集は自動承認、コマンド実行は要確認）、③プランモード（読み取り専用ツールのみで分析し、実行可能なプランを提示）の3つです。

  2. Q2. プランモードでは、Claude はどのようにコードベースを扱いますか？

    回答を表示

    読み取り専用のツールだけを使ってコードベースを分析し、必要に応じて途中で質問を挟みながら、最終的に実行可能な詳細なプランを提示します。この段階ではファイルの変更は行われず、ファイルを変更するコマンドの実行も行われません（ls のような読み取り専用の確認コマンドが使われることはあります）。

  3. Q3. 良いプロンプトを書くうえで大切なことは何ですか？また曖昧な指示にはどのようなデメリットがありますか？

    回答を表示

    できるだけ具体的に書くことが大切です。対象のファイルや症状、完了条件を明示すると、Claude は迷わず正しい行動を選べます。逆に曖昧な指示は、Claude が目的を推測するための余計な探索を発生させ、コンテキストウィンドウを余分に消費する原因になります（詳しくは第7章）。
