ホーム JMeter 第2章
第2章 所要時間: 約1時間

環境構築：JMeterと練習用サーバー

この章では、JMeter を動かすための Java（JDK）、JMeter 本体、そして負荷をかける相手となる練習用サーバー go-httpbin を、自分の PC に用意します。最後に JMeter を英語表示で起動して空のテスト計画を保存し、go-httpbin から応答が返ることまで確認すれば、次章以降の準備は完了です。

この章で学ぶこと

  • JDK 21 と JMeter 5.6.3 をインストールし、GUI を起動できる
  • JMeter の画面構成と、フォルダ構成（bin・lib・lib/ext など）の役割がわかる
  • user.properties で GUI を英語表示に統一できる
  • Docker で練習用サーバー go-httpbin を起動・停止・再開できる

2.1 準備するもの

JMeter は Java で作られたアプリケーションなので、動かすには Java の実行環境が必要です。また、負荷をかける相手として、練習用の Web サーバーを自分の PC 上に用意します。この章で準備するものは次の3つです。

準備するもの 本ガイドで使う版 役割
JDK（Java 開発キット） Eclipse Temurin 21（LTS） JMeter を動かす Java の実行環境
Apache JMeter 5.6.3 テスト計画を作り、負荷をかけるツール本体
Docker Desktop（または互換ツール） 最新版でよい 練習用サーバー go-httpbin を簡単に起動する

JMeter 5.6.3 自体は Java 8 以上で動作しますが、本ガイドでは JDK 21 を推奨します。今後の JMeter 6.x 系は Java 17 以上が必須になる予定で、長期サポート版（LTS）の 21 を入れておけば、バージョンが上がっても使い続けられるためです。

完成後の構成は次のとおりです。JMeter も go-httpbin も同じ PC の中で動き、JMeter が localhost:8080 に向けてリクエストを送ります。外部のサーバーには何も送りません。

flowchart LR subgraph PC["あなたのPC"] JDK["JDK 21
Javaの実行環境"] -.->|"JMeterを動かす"| J["JMeter 5.6.3
GUIで操作"] J -->|"HTTPリクエスト"| H["go-httpbin
localhost:8080"] D["Docker"] -.->|"コンテナとして起動"| H end

用語: <JMETER_HOME> と作業フォルダ

本ガイドでは、JMeter を展開したフォルダを <JMETER_HOME> と書きます。例えば Windows なら C:\tools\apache-jmeter-5.6.3、macOS なら ~/tools/apache-jmeter-5.6.3 です。また、各章で作るテスト計画の保存先として、任意の場所に jmeter-practice フォルダを作っておいてください。

2.2 JDK のインストールと確認

Eclipse Temurin 21 は、Adoptium プロジェクトが無料で配布している JDK の1つです。公式サイト（https://adoptium.net/）から、お使いの OS 用のインストーラー（Windows は .msi、macOS は .pkg）をダウンロードして実行します。Windows のインストーラーでは、「Add to PATH」にあたる項目が有効になっていることを確認してください。

インストール後は、新しくターミナル（Windows は PowerShell またはコマンドプロンプト、macOS は「ターミナル」）を開いて、次のコマンドでバージョンを確認します。

terminal 
# Java のバージョンを表示する
java -version

# 表示例（先頭が 21 で始まっていれば OK）
# openjdk version "21.0.x" ...
# OpenJDK Runtime Environment Temurin-21.0.x ...

JAVA_HOME という環境変数の設定は必須ではありません。大切なのは、ターミナルで java -version が動く（PATH が通っている）ことです。「コマンドが見つかりません」と出る場合は、いったんターミナルを閉じて開き直してください。それでも直らなければ、章末のトラブルシュート表を確認します。

2.3 JMeter のダウンロードと展開

JMeter には「インストーラー」はなく、ZIP などの圧縮ファイルを展開するだけで使えます。公式サイトのダウンロードページ（https://jmeter.apache.org/download_jmeter.cgi）を開き、Binaries の欄から次のファイルを選びます。

OS ダウンロードするファイル
Windows apache-jmeter-5.6.3.zip
macOS / Linux apache-jmeter-5.6.3.tgz

注意: Source ではなく Binaries を選ぶ

ダウンロードページには Source（ソースコード）の欄もありますが、これはプログラムを自分でビルドする人向けです。実行できる形になっているのは Binaries の方です。また、.sha512 や .asc はファイルの改ざんを確かめるための検証用ファイルで、起動には使いません。

ダウンロードしたファイルを、パスに日本語や空白を含まない場所へ展開します。パスに日本語や空白があると、起動スクリプトや後の章のファイル指定で思わぬエラーの原因になるためです。

terminal（Windows PowerShell） 
# 展開先フォルダを作る
mkdir C:\tools

# ダウンロードした zip を展開する（パスは自分の環境に合わせる）
Expand-Archive -Path "$HOME\Downloads\apache-jmeter-5.6.3.zip" -DestinationPath C:\tools
terminal（macOS / Linux） 
# 展開先フォルダを作る
mkdir -p ~/tools

# ダウンロードした tgz を展開する
tar -xzf ~/Downloads/apache-jmeter-5.6.3.tgz -C ~/tools

Tips: macOS の Homebrew について

macOS では brew install jmeter でも導入できますが、その時点の最新版が入るため、本ガイドの 5.6.3 と画面や挙動が異なる可能性があります。手順をそろえるため、本ガイドでは公式の Binaries を使う方法をおすすめします。

2.4 起動と画面の見方

展開したフォルダの bin にある起動スクリプトを実行します。Windows ではエクスプローラーから jmeter.bat をダブルクリックしてもかまいませんが、次の章以降で使う CLI（コマンドライン）に慣れるため、ターミナルから起動してみましょう。

terminal 
# Windows（PowerShell / コマンドプロンプト）
cd C:\tools\apache-jmeter-5.6.3\bin
.\jmeter.bat

# macOS / Linux
cd ~/tools/apache-jmeter-5.6.3/bin
./jmeter

数秒すると JMeter の GUI が開きます。同時に、起動したターミナルには次のような英語のメッセージが表示されます。

起動時のコンソール表示（抜粋） 
Don't use GUI mode for load testing !, only for Test creation and Test debugging.
For load testing, use CLI Mode (was NON GUI):
   jmeter -n -t [jmx file] -l [results file] -e -o [Path to web report folder]

これは、「負荷テストの本番実行には GUI モードを使わないでください。GUI はテスト計画の作成とデバッグ用です」という JMeter 自身からの注意です。GUI の描画や結果表示が JMeter のメモリと CPU を消費し、測定値を歪めてしまうためです。本番の負荷は CLI モードで実行します（第12章で学びます）。

起動した画面は、大きく3つの領域に分かれています。

領域 場所 役割
ツリー 左側 テスト計画（Test Plan）を構成する要素を、親子関係のツリーで表示する。要素の追加は右クリック → Add から行う
設定パネル 右側 ツリーで選んだ要素の設定項目を編集する
ツールバー 上部 保存・実行・停止・結果のクリアなどのボタンが並ぶ

ツールバーで特に使うのは、次のボタンです。実際の使い方は第4章で学びますが、場所だけ覚えておきましょう。

  • Start（緑の再生ボタン）: テスト計画を実行する
  • Stop・Shutdown: 実行を止める（Stop は即時、Shutdown は実行中のリクエストの完了を待って止める）
  • Clear・Clear All: 実行結果を消す（Clear は選んでいるリスナーだけ、Clear All はすべてのリスナーの結果を消す）

2.5 英語表示に統一する

JMeter 5.6.3 の起動スクリプトは、環境変数 JMETER_LANGUAGE の既定値によって、日本語環境の PC でも通常は英語表示で起動します。ただし Options → Choose Language で日本語を選ぶと日本語表示になります。JMeter の日本語訳は一部だけで、英語と混在しやすいうえ、Web 上の解説や公式マニュアルの名前とも一致しなくなるため、本ガイドでは GUI を英語表示に統一します。念のため次の設定を入れておきましょう。

設定は <JMETER_HOME>/bin/user.properties の末尾に1行追記するだけです。テキストエディタで開き、次の行を追加して保存し、JMeter を再起動してください。

bin/user.properties（末尾に追記） 
# GUI の表示言語を英語に固定する
language=en

Tips: 一時的に切り替えるだけなら

起動中の JMeter のメニュー Options → Choose Language → English でも言語を切り替えられます。ただしこの方法は、再起動すると元に戻ります。毎回英語で起動させたいので、user.properties への追記を行ってください。

なお、本ガイドでは要素名を「Thread Group（スレッドグループ）」のように、初出時に英語名＋日本語訳で書き、以降は英語名で表記します。メニュー操作は「Test Plan を右クリック → Add → Threads (Users) → Thread Group」の形式で示します。

2.6 ディレクトリ構成

展開した JMeter フォルダには、いくつかのサブフォルダがあります。すべてを覚える必要はありませんが、「設定ファイルはどこか」「プラグインはどこに置くか」は今後よく使います。

JMeter のフォルダ構成

apache-jmeter-5.6.3/        # = <JMETER_HOME>
├── bin/                    # 起動スクリプトと設定ファイル
│   ├── jmeter.bat          # Windows 用の起動スクリプト
│   ├── jmeter              # macOS / Linux 用の起動スクリプト
│   ├── jmeter.properties   # 既定の設定（直接編集しない）
│   ├── user.properties     # 自分の設定を書く場所
│   └── templates/          # File → Templates のひな形
├── lib/                    # JMeter が使う Java ライブラリ
│   └── ext/                # プラグインの置き場所
├── docs/                   # ドキュメント（API 仕様など）
└── extras/                 # 補助ファイル（Ant 用ビルドなど）

特に大切なのが jmeter.properties と user.properties の関係です。jmeter.properties には既定の設定がすべて書かれていますが、直接は編集しません。JMeter をバージョンアップしたときに上書きされたり、どこを変えたか分からなくなったりするためです。変更したい項目は、同じ名前で user.properties に書きます。user.properties の記述が優先され、変更点がそこに集まるので管理しやすくなります。

2.7 Plugins Manager の導入（任意）

JMeter はプラグインで機能を追加できます。Plugins Manager は、プラグインの検索・導入を GUI から行える便利な仕組みです。導入は次の手順です。

  1. 1 jmeter-plugins.org から jmeter-plugins-manager-<バージョン>.jar をダウンロードする。
  2. 2 jar ファイルを <JMETER_HOME>/lib/ext/ に置く。
  3. 3 JMeter を再起動し、メニューの Options → Plugins Manager が表示されることを確認する。

重要ポイント

この手順は任意です。本ガイドの本編は、プラグインなしの標準の JMeter だけで最後まで完結します。まずは標準機能をしっかり身につけ、必要になったときに導入すれば十分です。

2.8 練習用サーバー go-httpbin の起動

go-httpbin は、HTTP のテスト用に作られた小さな Web サーバーです。送ったリクエストの内容をそのまま返したり、指定した秒数だけ応答を遅らせたり、わざとエラーを返したりできます。本ガイドの実習はすべて、自分の PC で動かすこの go-httpbin に対して行います。

まず Docker Desktop をインストールして起動しておき、次のコマンドを実行します。初回はイメージのダウンロードが行われるため、少し時間がかかります。

terminal 
# go-httpbin をバックグラウンドで起動する
# -d: バックグラウンド実行 / --name: コンテナ名
# -p 127.0.0.1:8080:8080: 自分の PC の中（127.0.0.1）からの8080番だけを、コンテナの8080番へつなぐ
# :2.25.0: 使うイメージのバージョン（タグ）を固定する
docker run -d --name httpbin -p 127.0.0.1:8080:8080 ghcr.io/mccutchen/go-httpbin:2.25.0

# 起動しているか確認する（httpbin が表示され、PORTS が 127.0.0.1:8080->8080/tcp なら OK）
docker ps

補足: 127.0.0.1 とタグを付ける理由

  • 公開範囲を自分の PC に限る: -p 8080:8080 のように書くと、Docker の設定やネットワーク環境によっては、同じネットワークにいる他の PC からも go-httpbin に接続できる状態になることがあります。127.0.0.1: を前に付けると、自分の PC の中からの接続だけに限定できます。JMeter やブラウザからは、これまでどおり localhost:8080 で接続できます。
  • バージョンを固定する: タグ（:2.25.0）を省略すると、取得した時点の最新版（latest）が使われ、学習する時期によって動きが変わる可能性があります。実務でさらに厳密に固定したいときは、イメージのダイジェスト（@sha256:...）で指定します。
  • 以前にこの2つを付けずに httpbin コンテナを作っている場合は、docker stop httpbin と docker rm httpbin で削除してから、上のコマンドで作り直してください。

起動したら、ブラウザで http://localhost:8080 を開きます。使えるエンドポイント（URL の一覧）が表示されれば成功です。続けて http://localhost:8080/get?name=jmeter を開くと、送ったクエリやヘッダーが JSON で返ってきます。

/get?name=jmeter の応答（抜粋） 
{
  "args": {
    "name": ["jmeter"]
  },
  "method": "GET",
  "url": "http://localhost:8080/get?name=jmeter"
}

args の値が ["jmeter"] のように配列で返る点が、go-httpbin の特徴です。後の章で JSON の値を取り出すとき（$.args.name[0] のように書く）に使います。実際の応答には、ほかにも headers などの項目が含まれます。

止めたり再開したりするコマンドは次のとおりです。学習を終えるたびに止め、再開するたびに起動すれば、PC のリソースを無駄にしません。

terminal 
# 停止する
docker stop httpbin

# 再開する（コンテナは残っているので docker run は不要）
docker start httpbin

# 削除したいとき（停止してから）
docker rm httpbin

警告: 許可のないサーバーに負荷をかけない

本ガイドの実習は、すべて自分の PC 上の localhost（go-httpbin）に対して行います。許可なく他人・他社のサーバーに負荷をかけることは、サービスを妨害する攻撃（DoS 攻撃）と同じ行為であり、法的責任を問われる可能性があります。公開されている httpbin.org など、第三者のサーバーに JMeter を向けてはいけません。

2.9 トラブルシュート

環境構築でよくあるつまずきと対処法をまとめます。

症状 主な原因 対処法
java コマンドが見つからない JDK 未導入、または PATH が通っていない JDK を入れ直し（Windows は PATH に追加する項目を有効にする）、ターミナルを開き直して java -version を再確認する
JMeter がすぐ終了する・画面が出ない Java のバージョンが古い、または展開先パスに日本語・空白がある java -version を確認し、パスに日本語・空白を含まないフォルダへ展開し直す
docker run で「port is already allocated」などと出る ポート 8080 を別のプログラムが使用中 使うポートを変える。-p 127.0.0.1:18080:8080 で起動し、以降 localhost:18080 に読み替える（JMeter の Port Number も 18080 にする）
docker run で「name is already in use」と出る 同名のコンテナ httpbin が既に存在する docker start httpbin で再開するか、docker rm httpbin で削除してから作り直す
Cannot connect to the Docker daemon Docker Desktop が起動していない Docker Desktop を起動し、動作中の表示になってから再実行する
メニューや要素名が日本語と英語で混在する Options → Choose Language で日本語を選んだ、または環境変数 JMETER_LANGUAGE・JVM_ARGS で日本語ロケールを指定している Options → Choose Language → English で戻す。環境変数を設定している場合は外してから bin/jmeter.bat（macOS / Linux は bin/jmeter）で起動し直す（2.5 参照）
ファイルや画面の日本語が文字化けする ファイルの文字コード（Shift_JIS など）が JMeter 側の想定（UTF-8）と違う CSV や設定ファイルは UTF-8 で保存する（第8章の CSV Data Set Config では File encoding に UTF-8 を指定する）
画面の文字が小さい・潰れて見える 高解像度ディスプレイでの表示倍率の影響 メニューの Options → Zoom In で表示を拡大する

手順

  1. 1 Docker Desktop を起動する。

理解度確認クイズ

  1. Q1. JMeter 起動時のコンソールに「Don't use GUI mode for load testing」と表示されるのはなぜですか？

    回答を表示

    GUI の描画や結果表示が JMeter 自身のメモリや CPU を消費し、測定値を歪めてしまうためです。GUI はテスト計画の作成とデバッグ用に使い、本番の負荷実行は CLI モードで行います（第12章で学びます）。

  2. Q2. JMeter の設定を変更したいとき、jmeter.properties ではなく user.properties に書くのはなぜですか？

    回答を表示

    jmeter.properties は既定値を持つファイルで、バージョンアップ時に上書きされたり、どこを変更したか分からなくなったりするためです。user.properties に同名の項目を書けばそちらが優先され、自分の変更点を1か所にまとめて管理できます。

  3. Q3. ポート 8080 が別のプログラムに使われていて go-httpbin を起動できません。どうすればよいですか？ また、そのとき JMeter 側で変える設定は何ですか？

    回答を表示

    -p 127.0.0.1:18080:8080 のように、PC 側のポート番号を別の空いている番号に変えて起動します（コンテナの中は 8080 のままです）。JMeter 側では、接続先の Port Number を 18080 に読み替えます。ブラウザで確認するときも localhost:18080 を使います。
