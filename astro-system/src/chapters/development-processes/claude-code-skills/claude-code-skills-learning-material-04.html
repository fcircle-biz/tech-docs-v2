ホーム Claude Code Skills 第4章
第4章 所要時間: 約40分

スキルのテストと発見の仕組み

第3章で作成した pr-description スキルを実際に動かして確認します。あわせて、Claude Code が起動時にスキルをどうスキャンし、リクエストとどう照合し、いつ本文を読み込むのかという舞台裏の一連の流れを追います。

この章で学ぶこと

  • スキルを作成・更新・削除した後、なぜ Claude Code の再起動が必要なのかを説明できる
  • 利用可能なスキルの一覧を確認し、自作スキルが認識されているかを検証できる
  • pr-description スキルを実際に動かし、期待どおりの動作を確認できる
  • Claude Code がスキルを発見し、リクエストと照合し、本文を読み込む一連の流れを説明できる
  • 最初に name と description だけが読み込まれる設計の理由（コンテキストウィンドウの節約）を理解する

4.1 まず再起動する — スキルは起動時に読み込まれる

第3章では ~/.claude/skills/pr-description/SKILL.md を作成しました。ですが、ファイルを保存しただけでは、いま動いている Claude Code のセッションはまだそのスキルの存在を知りません。

Claude Code はスキルを起動時に読み込みます。そのため、スキルを新規作成したら、必ずセッションを再起動してください。いったん Claude Code を終了し、もう一度起動し直せば十分です。

なぜ「保存しただけ」では反映されないのか

Claude Code はスキルフォルダを毎回のメッセージ送信時にスキャンしているわけではありません。起動時に一度だけスキャンして、利用可能なスキルの一覧をメモリ上に保持します。ファイルを追加・変更しても、この一覧は再起動するまで更新されません。

再起動したら、まず利用可能なスキルの一覧を確認し、そのスキルが使える状態になっているかを確かめましょう。

terminal 
> 利用可能なスキルの一覧を教えて

  以下のスキルが利用可能です：
  - pr-description（パーソナル）
    プルリクエストの説明文を作成します。PRを作成するとき、
    PRを書くとき、あるいはユーザーがプルリクエストの変更内容
    の要約を求めたときに使用します。

一覧に pr-description が表示されていれば、Claude Code はこのスキルを認識しています。表示されない場合は、ディレクトリ名や SKILL.md の frontmatter に誤りがないか（第3章を参照）を見直し、再起動をやり直してください。

4.2 スキルを動かしてみる — pr-description をテストする

テスト方法はシンプルです。あるブランチでいくつか変更を加え、Claude Code に「変更内容のPR説明文を書いて」のように話しかけてみましょう。

Claude は PR 説明文スキルを使っていることを伝えたうえで、git diff main...HEAD などで差分を確認し、SKILL.md に書いたテンプレートに沿った説明文を——毎回同じフォーマットで——書いてくれます。

terminal 
> 変更内容のPR説明文を書いて

● pr-description スキルを使用しますか？
  プルリクエストの説明文を作成します。SKILL.md の内容を
  読み込んで指示に従います。
  > はい

● pr-description スキルを読み込みました
  git diff main...HEAD を実行しています...

  ## 概要
  ログイン画面のバリデーションエラー表示を改善します。
  ...

別のブランチで別の変更を加えて同じように依頼しても、返ってくる説明文は常に「概要・目的・変更点」という同じ見出し構成になります。これが、スキルによって「同じ指示を毎回繰り返す」状態から抜け出せたことの証拠です。

4.3 舞台裏の仕組み — スキルの発見とマッチング

いま体験した「スキルを使いますか？」というやり取りの裏側では、いくつかの段階を踏んだ処理が行われています。順番に見ていきましょう。

1

起動時に4つの場所をスキャン

Claude Code が起動すると、エンタープライズ・パーソナル・プロジェクト・プラグインという4つの場所をスキャンして、存在するスキルを探します（配置先の詳細は第2章）。

2

name と description だけを読み込む

見つけたスキルについて、SKILL.md の frontmatter にある name と description だけを読み込みます。指示本文（2つ目の --- より下）はこの時点では読み込みません。ここが最も重要なポイントです。

3

リクエストを説明文と照合（セマンティックマッチング）

あなたがメッセージを送ると、Claude はその内容を、利用可能なすべてのスキルの description と照らし合わせます。文字列が完全一致するかではなく、意図が重なっているかで判断します。

4

確認プロンプト → 本文を読み込んで実行

マッチするスキルが見つかると、Claude はそのスキルを読み込んでよいか確認を求めます。ここで承認すると、はじめて SKILL.md 全体がコンテキストに読み込まれ、その指示に従って作業が進みます。

たとえば「この関数が何をしているか説明して」というリクエストは、文言としては一致しなくても、「図を使ってコードを説明する」と説明されたスキルにマッチします。意図が重なっているためです。

flowchart TD A["Claude Code 起動"] --> B["4つの場所をスキャン
（エンタープライズ／パーソナル／プロジェクト／プラグイン）"] B --> C["各スキルの name と description だけ読み込む
（指示本文はまだ読み込まない）"] C --> D["ユーザーがリクエストを送信"] D --> E["リクエストと全スキルの description を照合
（セマンティックマッチング）"] E --> F{"意図が重なるスキルはあるか"} F -->|なし| G["通常どおり応答（スキル未使用）"] F -->|あり| H["このスキルを読み込んでよいか確認プロンプトを表示"] H --> I["ユーザーが確認する"] I --> J["SKILL.md の指示本文全体をコンテキストに読み込む"] J --> K["指示に従って作業を実行する"]

重要ポイント: 確認ステップの意味

マッチした瞬間に自動で本文が読み込まれるわけではありません。確認プロンプトを挟むことで、Claude がどのようなコンテキストを取り込もうとしているかを、あなたが常に把握できるようになっています。承認して初めて SKILL.md 全体が読み込まれます。

4.4 なぜ name と description だけを読み込むのか

第1章で触れたとおり、スキルの本文は使われるまでコンテキストを消費しません。この章で見た流れは、まさにその仕組みを実現するための設計です。

もし Claude Code が起動時にすべてのスキルの本文を読み込んでいたらどうなるでしょうか。スキルを10個、20個と増やしていくたびに、会話を始める前からコンテキストウィンドウがどんどん埋まっていきます。デバッグ中の会話に、無関係な PR レビューのチェックリストが紛れ込むことにもなりかねません。

name と description だけを先に読み込み、本文はマッチして確認が取れたときだけ読み込む——この二段構えによって、スキルの数をいくら増やしても、普段の会話のコンテキストは圧迫されません。

用語の整理: 何が「常に」読み込まれ、何が「オンデマンド」か

全スキルの name・description（軽量なメタデータ）は起動時に常に読み込まれます。一方、各スキルの指示本文は、そのスキルがマッチして確認された場合だけ読み込まれる「オンデマンド」な情報です。この2段階の粒度を意識しておくと、第7章の段階的開示（Progressive Disclosure）の理解もスムーズになります。

動作確認: スキルが読み込まれたことを確認する

次の3点が確認できれば、スキルは正しく機能しています。

  • スキル一覧に pr-description が表示されている（4.1）
  • 依頼した際に「pr-description スキルを使用します」というメッセージがターミナルに表示される
  • 出力される説明文が、毎回「概要・目的・変更点」という同じフォーマットになっている

4.5 スキルの更新と削除

作ったスキルは、育てていくものです。更新と削除の方法はどちらもシンプルです。

更新する

対象の SKILL.md を編集するだけです。description の言い回しを見直したり、指示本文にチェック項目を追加したりできます。

削除する

そのスキルのディレクトリごと削除します。SKILL.md だけを消しても、フォルダが残っていると管理上まぎらわしいので注意しましょう。

注意: 変更後も再起動を忘れずに

SKILL.md を更新した場合も、ディレクトリを削除した場合も、Claude Code は起動時にスキャンした一覧を保持し続けています。変更を反映させるには、必ず Claude Code を再起動してください。再起動せずにテストすると、「直したはずなのに動かない」という混乱の原因になります。

やってみよう 4-1: pr-description スキルの動作を確認する

第3章で作った pr-description スキルを、実際に一連の流れで動かしてみましょう。

手順

  1. 1 Claude Code をいったん終了し、再起動する。
  2. 2 「利用可能なスキルの一覧を教えて」と尋ね、pr-description が表示されることを確認する。
  3. 3 適当なファイルに小さな変更を加えたブランチで「変更内容のPR説明文を書いて」と依頼する。
  4. 4 ターミナルに「pr-description スキルを使用します」という表示が出ること、確認プロンプトが表示されること、そして出力が「概要・目的・変更点」のフォーマットになっていることを確認する。

ヒント: もしスキルが一覧に出てこない、または依頼してもスキルが使われない場合は、再起動を忘れていないか、SKILL.md の description が依頼内容と意図的に重なっているかを見直してみましょう。description の書き方は第5章で本格的に扱います。

理解度確認クイズ

  1. Q1. スキルを新規作成したり更新・削除したりしたあと、必ず行わなければならないことは何ですか？

    回答を表示

    Claude Code の再起動が必要です。Claude Code はスキルを起動時にスキャンした結果を保持しているため、ファイルを保存・変更・削除しただけでは、実行中のセッションには反映されません。

  2. Q2. Claude Code は起動時に、各スキルの何を読み込みますか。指示本文はいつ読み込まれますか？

    回答を表示

    起動時に読み込むのは、frontmatter の name と description だけです。指示本文（SKILL.md の --- より下）は、リクエストとマッチしてユーザーが確認プロンプトを承認したときにはじめて読み込まれます。

  3. Q3. Claude がリクエストとスキルの description をどのように照合しているか、簡単に説明してください。

    回答を表示

    文字列の完全一致ではなく、セマンティックマッチング（意図の重なり）によって照合します。たとえば「この関数が何をしているか説明して」というリクエストは、文言が違っても「図を使ってコードを説明する」と説明されたスキルにマッチします。

  4. Q4. マッチするスキルが見つかったとき、Claude はすぐに本文を読み込みますか。それとも別のステップを挟みますか？なぜそうなっていますか？

    回答を表示

    すぐには読み込まず、確認プロンプトを挟みます。これにより、Claude がどのようなコンテキストを取り込もうとしているかをユーザーが常に把握できます。確認して初めて SKILL.md 全体が読み込まれます。
