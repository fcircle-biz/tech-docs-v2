スキルの置き場所と優先順位

前章では、個人用とプロジェクト用という2つの置き場所を確認しました。実際にはスキルの配置先は4種類あり、それぞれ「誰に届くか」「いつ使うか」が異なります。この章では4つの配置先を整理し、名前が重複したときにどちらが優先されるのか、その順位づけの理由まで理解します。

この章で学ぶこと

  • スキルの4つの配置先（エンタープライズ・パーソナル・プロジェクト・プラグイン）を説明できる
  • 各配置先が「誰に届くか」「いつ使うべきか」を判断できる
  • skills/<スキル名>/SKILL.md というディレクトリ構成を再現できる
  • 名前が重複したときの優先順位（エンタープライズ→パーソナル→プロジェクト→プラグイン）を説明できる
  • 競合を避けるための命名の工夫と、置き場所の選び方を判断できる

2.1 スキルの4つの配置先

Claude Code は起動時に4つの場所をスキャンしてスキルを探します。どこに置くかによって、そのスキルが「誰の目に触れるか」「いつ使えるようになるか」が決まります。

① エンタープライズ

組織の管理設定（managed settings）を通じて配布されます。会社の IT 部門やプラットフォームチームが管理し、組織に所属する全員に強制的に適用されます。

例: セキュリティ上必須のレビュー基準、コンプライアンス関連のチェックリスト

② パーソナル

~/.claude/skills に置きます。すべてのプロジェクトであなたについて回ります。自分だけの好みやスタイルを反映するのに向いています。

例: コミットメッセージのスタイル、自分好みのコード説明の仕方

③ プロジェクト

リポジトリルートの .claude/skills に置きます。リポジトリをクローンした人全員に自動的に届きます。.claude にはエージェント・フック・スキル・設定がまとめて含まれます。

例: 会社のブランドガイドライン、そのリポジトリ固有のレビュー観点

④ プラグイン

インストールされたプラグインに同梱される形で提供されます。マーケットプレイス経由で配布されることが多く、第三者が作ったスキル一式をまとめて導入できます。

例: 特定フレームワーク向けの公式・コミュニティ製スキル集

Windows での置き場所

パーソナルスキルの置き場所は、Windows では C:/Users/<your-user>/.claude/skills になります。パスの区切りは Windows 上でもスラッシュ / を使うのが安全です（第12章で改めて扱います）。

2.2 ディレクトリ構成の実例

配置先が違っても、スキル1つあたりの構造は共通です。skills フォルダの下にスキル名と同じ名前のディレクトリを作り、その中に SKILL.md を置きます。

パーソナルスキルのディレクトリ構成（例） 

~/.claude/
└── skills/
    ├── pr-review/
    │   └── SKILL.md        ← ディレクトリ名 = スキル名
    ├── commit-message/
    │   └── SKILL.md
    └── frontend-review/
        └── SKILL.md

プロジェクト用スキルも考え方は同じで、リポジトリルートの .claude/skills/<スキル名>/SKILL.md という形になります。ディレクトリ名とスキル名を一致させることが重要です。Claude Code はこのディレクトリ名を手がかりにスキルを識別するため、ずれていると意図した通りに認識されません。

用語: スキル名（name）とは

SKILL.md の frontmatter に書く name フィールドの値のことです。この値と、スキルを収めたディレクトリの名前は一致させる必要があります。実際に手を動かして作る手順は、次の第3章で扱います。

2.3 名前が重複したときの優先順位

4つの配置先に、たまたま同じ名前のスキルが存在していたらどうなるでしょうか。たとえば、自分のパーソナルスキルと同じ名前のスキルを持つリポジトリをクローンした場合です。Claude Code はこの優先順位に従って、どちらを使うかを決めます。

flowchart TD Top["優先度 最高"] --> A["① エンタープライズ
（管理設定）"] A --> B["② パーソナル
（~/.claude/skills）"] B --> C["③ プロジェクト
（.claude/skills）"] C --> D["④ プラグイン
（インストール済みプラグイン）"] D --> Bottom["優先度 最低"]

優先順位はエンタープライズ → パーソナル → プロジェクト → プラグインの順です。同じ名前のスキルが複数の場所に存在する場合、より上位の配置先にあるものが採用され、下位のものは無視されます。

具体例: 会社に code-review という名前のエンタープライズスキルがあり、あなたも同じ名前で code-review というパーソナルスキルを作ったとします。この場合、エンタープライズ版が優先され、あなたのパーソナル版は使われません。

重要ポイント

この優先順位のおかげで、組織はエンタープライズスキルを通じて標準を強制しつつ、個人によるカスタマイズも許容できます。エンタープライズ側で明確に上書きしたいスキルだけ同名にし、それ以外は個人の裁量に委ねる、という設計が可能になります。

2.4 競合を避ける実践 — 説明的な名前を使う

優先順位があるとはいえ、意図せず上書きされてしまうのは避けたいものです。もっとも簡単な対策は、名前を短く曖昧にしすぎないことです。

避けたい名前

review のような一般的すぎる名前は、他の誰かが作った同名スキルと衝突しやすくなります。

望ましい名前

frontend-review・backend-review のように、対象を具体的に示す名前にすれば区別しやすくなります。

この工夫は、優先順位のルールを理解したうえで初めて意味を持ちます。「同じ名前なら上位が勝つ」と分かっているからこそ、意図せぬ上書きを避けたい場面では名前を分ける、逆に意図的に上書きしたい場面では同じ名前にする、という使い分けができるのです。

2.5 どこに置くか迷ったら

新しくスキルを作るとき、置き場所は「そのスキルを誰が必要としているか」で決まります。次のフローチャートを目安にしてください。

flowchart TD A["新しいスキルを作りたい"] --> B{"誰が使う？"} B -->|自分だけ| C["パーソナル
（~/.claude/skills）"] B -->|チーム全員| D["プロジェクト
（.claude/skills）"] B -->|組織全体に必須適用| E["エンタープライズ
（管理設定）"] B -->|広く配布したい| F["プラグイン
（マーケットプレイス配布）"]

迷ったときは、まずパーソナルかプロジェクトかの2択で考えるのがおすすめです。エンタープライズとプラグインは組織の運用や配布の仕組みが絡むため、第11章で改めて詳しく扱います。

やってみよう 2-1: 自分の環境で置き場所を確認する

実際にスキルを作る前に、自分の環境で「どこに置けるか」を確認しておきましょう。ディレクトリが存在していなくても問題ありません。

手順

  1. 1 ターミナルで ls ~/.claude/skills（Windows は ls C:/Users/<your-user>/.claude/skills）を実行し、パーソナルスキルの置き場所が存在するか確認する。
  2. 2 自分が普段作業しているリポジトリのルートで ls .claude/skills を実行し、プロジェクト用スキルが存在するか確認する。
  3. 3 第1章の実習で書き出した「スキル化したい繰り返し」を1つ選び、パーソナルとプロジェクトのどちらに置くべきかを、2.5のフローチャートに沿って判定する。

ヒント: ディレクトリが見つからなくても失敗ではありません。mkdir -p で作成する手順は、次の第3章で実際に体験します。

理解度確認クイズ

  1. Q1. スキルの4つの配置先を、優先順位が高い順にすべて挙げてください。

    回答を表示

    エンタープライズ（管理設定）→ パーソナル（~/.claude/skills）→ プロジェクト（.claude/skills）→ プラグイン（インストール済みプラグイン）の順です。

  2. Q2. 会社の code-review エンタープライズスキルと、自分が作った同名のパーソナルスキルが両方存在する場合、どちらが使われますか。またそれはなぜ望ましい設計と言えますか。

    回答を表示

    エンタープライズ版が優先されます。これにより組織は標準を強制しつつ、名前が衝突しない範囲では個人によるカスタマイズも許容できるためです。

  3. Q3. スキルのディレクトリ構成はどのような形になりますか。ディレクトリ名について注意すべき点も含めて説明してください。

    回答を表示

    skills/<スキル名>/SKILL.md という形です。ディレクトリ名は SKILL.md の frontmatter に書く name の値と一致させる必要があります。

  4. Q4. なぜ review ではなく frontend-review のような名前にするとよいのですか。

    回答を表示

    名前が重複すると優先順位の高い配置先のスキルに上書きされてしまいます。対象を具体的に示す説明的な名前にすることで、他の人が作ったスキルとの意図しない衝突を避けられます。
