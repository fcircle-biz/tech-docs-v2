ホーム Claude Code Skills 第8章
第8章 所要時間: 約45分

スクリプト・参照資料・アセットの活用

前章で学んだ段階的開示（Progressive Disclosure）を、実際のファイル構成として組み立てます。中心となるのはスクリプトです。スクリプトは中身をコンテキストに読み込まずに実行でき、消費するトークンは出力分だけ——この性質を理解すると、scripts/・references/・assets/ という3つのディレクトリの使い分けが自然に見えてきます。

この章で学ぶこと

  • スクリプトを「読ませる」場合と「実行させる」場合で、トークン消費がどう違うかを説明できる
  • スクリプトが特に役立つ3つの場面（環境検証・データ変換・信頼性の求められる操作）を挙げられる
  • SKILL.md からスクリプトを「実行させる」指示を書ける
  • references/ と assets/ の役割の違いを区別できる
  • 複数ファイル構成のスキルを、実際のディレクトリ構造として組み立てられる

8.1 段階的開示を「実装」する

第7章では、SKILL.md を500行以内に保ち、詳細を scripts/・references/・assets/ に切り出すという段階的開示の考え方を学びました。この章では、その3つのディレクトリを実際にどう使い分けるかを、特にコンテキスト消費が最も大きく変わるスクリプトを中心に見ていきます。

ポイントは1つだけです。スキルのディレクトリ内にあるスクリプトは、その中身をコンテキストに読み込まずに実行できます。この性質を知っているかどうかで、大規模なスキルの設計はまったく変わってきます。

スクリプトが実行され、消費するトークンは出力分だけです。1,000行のシェルスクリプトを読み込ませれば1,000行分のトークンを消費しますが、実行させれば、消費するのは数行の実行結果だけかもしれません。

8.2 「読ませる」と「実行させる」の違い

SKILL.md に含めるべき重要な指示は、Claude にスクリプトを「読ませる」のではなく「実行させる」ことです。同じスクリプトファイルでも、指示の書き方ひとつでコンテキストの使われ方がまったく変わります。

flowchart TD A["SKILL.md の指示"] --> B{"「読んで」か「実行して」か"} B -->|"読んで"| C["scripts/check-env.sh の全文をコンテキストへ"] B -->|"実行して"| D["scripts/check-env.sh を実行する"] D --> E["標準出力だけをコンテキストへ"] C --> F["トークン消費: スクリプトの行数に比例（大）"] E --> G["トークン消費: 出力の行数に比例（小）"]
観点 読ませる場合 実行させる場合
指示の例 check-env.sh の内容を確認してください check-env.sh を実行してください
コンテキストに入るもの スクリプトの全コード 実行結果（標準出力）のみ
トークン消費 スクリプトの行数に比例 出力の行数に比例（通常はるかに少ない）

ヒント: 「読ませる」が必要な場面もある

スクリプトの中身を Claude に理解させたうえで修正・拡張してほしい場合は、あえて「読ませる」指示が正しいこともあります。ここでの原則は「毎回同じ処理を確実に行いたいだけなら実行させる」という使い分けです。

8.3 スクリプトが特に役立つ3つの場面

すべての処理をスクリプト化すればよいわけではありません。スクリプトが本領を発揮するのは、次の3つの場面です。

① 環境の検証

必要なコマンドやバージョンが揃っているかの確認。毎回同じ手順で、判定結果だけが分かればよい。

② 一貫性が求められるデータ変換

フォーマット変換や集計など、毎回まったく同じロジックで処理してほしい作業。

③ 信頼性の求められる操作

生成されたコードよりも、テスト済みのコードのほうが信頼できる操作。

3つに共通するのは、「その場で Claude に考えて生成させる」よりも「あらかじめ用意した、検証済みの手順を再現する」ほうが適している、という点です。

8.4 SKILL.md からスクリプトを実行させる指示

実際に SKILL.md でどう書けばよいかを見てみましょう。ポイントは「実行すること」と明示し、「読む必要はない」と付け加えることです。

~/.claude/skills/env-check/SKILL.md 
---
name: env-check
description: 開発環境のセットアップ状況を確認します。環境構築や必要なコマンドの有無を確認するときに使用します。
---


環境を検証するには `scripts/check-env.sh` を実行すること。
（ファイルの内容を読む必要はない）

出力に「NG」と表示されたコマンドがあれば、
インストール手順を案内すること。

（ファイルの内容を読む必要はない） という一文が効いています。この一文がないと、Claude が念のためスクリプトの中身を読みにいってしまい、段階的開示のメリットが失われることがあります。

重要ポイント

指示は「〜を実行すること」のように動詞をはっきりさせるのがコツです。「〜を確認してください」だけだと、Claude が「読んで確認する」のか「実行して確認する」のか迷う余地が生まれます。

8.5 スクリプト例: 環境を検証する

先ほどの SKILL.md が指し示している scripts/check-env.sh の中身です。必要なコマンドがインストールされているかを、シンプルに判定します。

~/.claude/skills/env-check/scripts/check-env.sh 
#!/bin/bash
# 環境検証スクリプト: 必要なコマンドの有無を確認する
echo "=== 環境チェック ==="

# 確認したいコマンドの一覧
commands=("git" "node" "npm")

for cmd in "${commands[@]}"; do
  if command -v "$cmd" >/dev/null 2>&1; then
    echo "OK: $cmd はインストール済みです"
  else
    echo "NG: $cmd が見つかりません"
  fi
done

Claude はこのスクリプトを実行するだけで、上記14行を読み込む必要がありません。コンテキストに入るのは、たとえば OK: git はインストール済みです のような数行の出力だけです。

8.6 references/ と assets/ の使い分け

scripts/ が「実行させる」ためのディレクトリだとすれば、残る2つはどちらも「置いておいて必要なときだけ使う」ディレクトリです。ただし役割は異なります。

references/

追加のドキュメント。Claude に「読ませたい」情報を置きます。いつ読むべきかを SKILL.md 側で明示してリンクします。

例: 詳細な仕様書、フォーマットガイド、用語集

assets/

画像、テンプレート、その他のデータファイル。出力の素材として使うものを置きます。Claude が内容を読むというより、コピーしたり埋め込んだりして使います。

例: PRの説明文テンプレート、ロゴ画像、サンプルデータ

3つのディレクトリの使い分けを整理すると、次の表のようになります。

ディレクトリ 何を置くか Claude の扱い方 コンテキスト消費
scripts/ 検証・変換など実行可能なコード 「実行させる」。中身は読まない 出力分のみ（小）
references/ 追加のドキュメント・仕様 「読ませる」。必要なときだけ読み込む 読み込んだ分（中〜大）
assets/ 画像・テンプレート・データファイル 出力の素材として使用（コピー・埋め込み） 使用時のみ・内容次第

8.7 複数ファイル構成スキルの全体像

ここまでの内容を1つのスキルにまとめると、ディレクトリ構成は次のようになります。SKILL.md は目次のように短く保ち、実体は3つのディレクトリに分散させます。 

pr-description/
├── SKILL.md                 # 指示本文（500行以内・目次の役割）
├── scripts/
│   └── check-env.sh         # 「実行させる」検証スクリプト
├── references/
│   └── format-guide.md      # 必要なときだけ「読ませる」詳細資料
└── assets/
    └── pr-template.md       # 出力にそのまま使うテンプレート
flowchart TD A["SKILL.md を有効化"] --> B{"必要になったものは？"} B -->|"環境を検証したい"| C["scripts/check-env.sh を実行する"] B -->|"詳細な書式を確認したい"| D["references/format-guide.md を読む"] B -->|"出力にテンプレートを使いたい"| E["assets/pr-template.md を素材として使う"] C --> F["出力だけがコンテキストへ"] D --> G["文書全体がコンテキストへ"] E --> H["内容をそのまま出力へ反映"]

こうして分割しておくと、SKILL.md が有効化された直後にコンテキストへ入るのは短い指示本文だけで、実際に必要になったファイルだけが、必要になったタイミングで読み込まれる（またはスクリプトなら実行される）——という状態を作れます。

注意: スクリプトには実行権限が必要

scripts/ に置いたファイルは、そのままでは実行できないことがあります。chmod +x scripts/check-env.sh で実行権限を付与するのを忘れないようにしましょう。実行権限が無いために動かないケースの見分け方は、第12章のトラブルシューティングで詳しく扱います。

やってみよう 8-1: 環境検証スクリプト付きスキルを作る

本文で見た env-check スキルを実際に手元で作り、「読ませる」ではなく「実行させる」指示が意図どおりに働くことを確認します。

手順

  1. 1 mkdir -p ~/.claude/skills/env-check/scripts でディレクトリを作り、8.5のスクリプトを scripts/check-env.sh として保存する。
  2. 2 chmod +x ~/.claude/skills/env-check/scripts/check-env.sh で実行権限を付与する。
  3. 3 8.4の SKILL.md を作成する。「実行すること」「読む必要はない」の一文を必ず含める。
  4. 4 Claude Code を再起動し、「開発環境を確認して」のように依頼する。ターミナルの表示で、ファイルを読んでいるのか実行しているのかを見比べる。

ヒント: うまく実行されない場合は、まず実行権限（chmod +x）を疑ってください。次に多い原因は、SKILL.md の指示が「確認して」のように曖昧で、読むか実行するかが Claude に伝わっていないケースです。

理解度確認クイズ

  1. Q1. スキルのディレクトリ内のスクリプトを「実行」させた場合、コンテキストに読み込まれるのは何ですか？

    回答を表示

    スクリプトの中身ではなく、実行結果（標準出力）だけです。消費するトークンは出力分だけなので、「読ませる」場合よりもコンテキストを大きく節約できます。

  2. Q2. 本文で挙げられている、スクリプトが特に役立つ3つの場面は何ですか？

    回答を表示

    ①環境の検証、②一貫性が求められるデータ変換、③生成されたコードよりもテスト済みのコードのほうが信頼できる操作、の3つです。

  3. Q3. references/ と assets/ は、それぞれどのような用途に使いますか？

    回答を表示

    references/ は Claude に「読ませたい」追加のドキュメントを置く場所です。assets/ は画像・テンプレートなど、出力の素材としてそのまま使うファイルを置く場所です。

  4. Q4. SKILL.md でスクリプトを使ってもらうとき、どのように指示を書くのが適切ですか？

    回答を表示

    「scripts/check-env.sh を実行すること（ファイルの内容を読む必要はない）」のように、「実行すること」を明示し、読まなくてよいことも合わせて伝える書き方が適切です。
