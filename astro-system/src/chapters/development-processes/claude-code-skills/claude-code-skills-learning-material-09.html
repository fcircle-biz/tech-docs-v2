ホーム Claude Skills 第9章
第9章 所要時間: 約35分

CLAUDE.md・スラッシュコマンドとの使い分け

スキルは Claude Code のカスタマイズ手段の一つに過ぎません。この章では、常に読み込まれる CLAUDE.md とオンデマンドで読み込まれるスキル、明示的に呼び出すスラッシュコマンドの3つを比較し、「この知識はどこに書くべきか」を迷わず判断できるようになります。

この章で学ぶこと

  • CLAUDE.md が「あらゆる会話に常に読み込まれる」仕組みであることを説明できる
  • スキルが「リクエストと合致したときだけオンデマンドで読み込まれる」仕組みであることを説明できる
  • CLAUDE.md を使うべき場面を3つ挙げられる
  • スラッシュコマンドとスキルの違い（明示的な呼び出し vs 自動適用）を区別できる
  • 判断フローチャートを使って、書きたい内容をどの手段に振り分けるべきか判断できる

9.1 「どこに書けばいいのか」問題

第1章の「注意」カードで、常に守ってほしい制約は CLAUDE.md のほうが向いているという話に少し触れました。この章では、その判断をきちんと言葉にします。Claude Code には動作をカスタマイズする方法が複数あり、誤った場所に知識を置くと、余計な複雑さや使いにくさを招いてしまいます。

ここで比較するのは、CLAUDE.md・スキル・スラッシュコマンドの3つです。サブエージェント・フック・MCP サーバーとの比較は次の第10章で扱います。3者を分ける最大のポイントは、「いつコンテキストに読み込まれるか」です。

9.2 CLAUDE.md ― あらゆる会話に常に読み込まれる

CLAUDE.md は、あらゆる会話に常に読み込まれます。プロジェクトで TypeScript の strict モードを常に使わせたいなら、CLAUDE.md にそう書きます。会話の話題が何であっても、CLAUDE.md の内容は最初から Claude のコンテキストに入っています。

常に適用される標準

プロジェクト全体で常時守ってほしいコーディング標準やルール。

絶対的な制約

「データベーススキーマを絶対に変更しない」といった、例外なく守らせたい制約。

フレームワーク・スタイルの選好

使用するフレームワークの選好や、チームのコーディングスタイル全般。

CLAUDE.md を使うべきかどうかの目安はシンプルです。「どんな話題の会話でも、これは常に成り立っていてほしいか？」という問いに「はい」と答えられるなら、CLAUDE.md に書きます。

9.3 スキル ― マッチしたときだけオンデマンドで読み込まれる

一方でスキルはオンデマンドで読み込まれます。Claude がリクエストとスキルの description をマッチさせると、そのスキルの指示が会話に加わります。新しいコードを書いているときに PR レビューのチェックリストがコンテキストに含まれている必要はありません。レビューを依頼したときに初めて有効化される——これがスキルの本質です。

タスク固有の専門知識

特定の作業をするときだけ必要になる、専門的な手順やチェックリスト。

時々しか関係しない知識

毎回の会話には関係しないが、該当する場面では必要になる知識。

詳細な手順

毎回の会話に含めると煩雑になってしまう、細かい手順や書式の指定。

重要ポイント

第4章で学んだとおり、Claude が最初に読み込むのはスキルの name と description だけです。本文はマッチするまでコンテキストを消費しません。この「使われるまで読み込まれない」性質こそが、CLAUDE.md との一番の違いです。

9.4 スラッシュコマンドとの違い ― 「自動」か「明示」か

もう一つの手段がスラッシュコマンド（/command-name のように自分でタイプするコマンド）です。スラッシュコマンドは明示的にタイプする必要があります。一方でスキルにはそれが不要です。Claude は状況を認識すると、あなたが何も打たなくても自動的にスキルを適用します。

つまり両者は、「決まった処理をコード化しておく」という点では似ていますが、起動する主体が違います。スラッシュコマンドの起動者はあなた自身、スキルの起動者は Claude 自身です。

スラッシュコマンドが向く場面

「今この定型処理を実行したい」と自分ではっきり意識しているとき。呼び出しのタイミングを自分でコントロールしたい処理。

スキルが向く場面

「気づいたら関連知識が必要だった」というときに、言い忘れても Claude 側で気づいて適用してほしい知識。

9.6 判断フローチャート ― この知識はどこに書く？

頭で覚えるより、フローチャートに沿って自問してみるほうが確実です。次の2つの質問に答えるだけで、置き場所が決まります。

flowchart TD A["この知識はどこに置く？"] --> B{"常に守ってほしいか？"} B -->|"はい"| C["CLAUDE.md"] B -->|"いいえ"| D{"自分で明示的に呼び出したいか？"} D -->|"はい"| E["スラッシュコマンド"] D -->|"いいえ"| F["スキル"]

1つ目の質問「常に守ってほしいか？」に「はい」と即答できるものは、迷わず CLAUDE.md です。そうでない場合は2つ目の質問に進みます。「自分がタイプするタイミングをコントロールしたい」なら、スラッシュコマンド。「該当する場面になったら Claude 側で気づいて適用してほしい」なら、スキルです。

具体例で確認

「TypeScript の strict モードを常に使う」→ 常に守ってほしい → CLAUDE.md。「PR レビューのチェックリスト」→ レビュー時だけ必要 → 自分で呼び出したいわけではない → スキル。「週次レポートのひな形を出力する」→ 自分が意図したタイミングで呼びたい → スラッシュコマンド。

9.7 CLAUDE.md が肥大化してきたら

CLAUDE.md はあらゆる会話に常に読み込まれるため、内容が増えるほど、毎回のコンテキストを圧迫します。「本当に常時必要な内容だけを CLAUDE.md に残し、時々しか関係しない詳細手順はスキルへ移す」という見直しが有効です。

見直しの観点1: 頻度で問う

その項目は、会話のたびに関係していますか？特定の作業（特定フレームワークのデバッグ、特定ドキュメントのテンプレートなど）のときにしか関係しないなら、スキルへ移す候補です。

見直しの観点2: 分量で問う

手順が長く細かいものは、CLAUDE.md に置くと煩雑になります。第7章の段階的開示の考え方を使い、SKILL.md 本体は要点だけにして、詳細を references/ に切り出す構成にできないか検討します。

見直しの観点3: 例外の有無で問う

「絶対に」「必ず」といった例外を許さない制約は CLAUDE.md に残します。逆に「こういうときはこうする」という条件付きの手順は、スキルの description にその条件を書き込んだほうが自然に機能します。

CLAUDE.md とスキルは対立するものではありません。「常に」の部分を CLAUDE.md に、「時々」の部分をスキルに振り分けることで、どちらも身軽な状態を保てます。

やってみよう 9-1: 手元の CLAUDE.md を仕分ける

実際に手を動かして、9.6 の判断フローチャートを自分の CLAUDE.md に当てはめてみましょう。

手順

  1. 1 個人用または業務で使っているプロジェクトの CLAUDE.md を開く（無ければ、これから書きたい項目を思い浮かべても構いません）。
  2. 2 記載されている項目を1つずつ、①常時必要な標準・制約と②時々しか関係しない詳細手順のどちらかに仕分ける。
  3. 3 ②に仕分けた項目から1つ選び、それをスキル化する計画を書く。スキル名（kebab-case）、description の一文、そしてどんな場面（どんなリクエスト）でトリガーしてほしいかを具体的に書き出す。

ヒント: 迷ったら「これを削除したら、CLAUDE.md はどれだけ短くなるか」「削除しても、その場面が来たときにスキルが代わりに教えてくれるか」の2点を確認してください。両方の答えが良好なら、そのままスキル化を進めて大丈夫です。

理解度確認クイズ

  1. Q1. CLAUDE.md とスキルの、読み込まれるタイミングの違いは何ですか？

    回答を表示

    CLAUDE.md はあらゆる会話に常に読み込まれます。スキルはリクエストとdescriptionが合致したときだけオンデマンドで読み込まれます。新しいコードを書いているときに PR レビューのチェックリストがコンテキストに含まれる必要はなく、レビューを依頼したときに初めて有効化されるのがスキルです。

  2. Q2. 「データベーススキーマを絶対に変更しない」という制約は、CLAUDE.md とスキルのどちらに書くべきですか？また、その理由は？

    回答を表示

    CLAUDE.mdに書くべきです。「絶対に」という例外なく常に守ってほしい制約であり、特定のタスクのときだけ関係する知識ではないためです。スキルにしてしまうと、リクエストとマッチしなかった場合に制約が読み込まれず、守られない危険があります。

  3. Q3. スラッシュコマンドとスキルは、どちらも「決まった処理をコード化する」点で似ていますが、決定的に違う点は何ですか？

    回答を表示

    起動する主体が違います。スラッシュコマンドは自分で明示的にタイプする必要がありますが、スキルにはそれが不要で、Claude が状況を認識すると自動的に適用します。

  4. Q4. CLAUDE.md が肥大化してきたとき、見直すべき観点を1つ挙げてください。

    回答を表示

    例えば「その項目は会話のたびに関係しているか（頻度）」「手順が長く細かすぎないか（分量）」「例外を許さない制約か、条件付きの手順か（例外の有無）」のいずれかです。時々しか関係しない詳細手順は、スキルへ移すことで CLAUDE.md を身軽に保てます。
