クラスを受け継ぐ - 継承とポリモーフィズム

第8章・第9章でクラスとプロパティを学びました。この章では、既存のクラスを土台にして新しいクラスを作る「継承」と、同じ呼び出しでも相手によって違う動きをする「ポリモーフィズム」を学びます。オブジェクト指向の中核といえる考え方です。

この章で学ぶこと

  • 継承とは何か、なぜ共通部分を親クラスにまとめるのかを説明できる
  • Inherits で子クラスを作り、MyBase.New で親のコンストラクタを呼び出せる
  • Overridable / Overrides でメソッドを上書きし、抽象クラスとインターフェースの違いを理解している
  • ポリモーフィズムを使って、種類が違うオブジェクトを同じ処理でまとめて扱える

10.1 継承とは

第8章・第9章で作ったEmployee（社員）クラスに加えて、部下を持つ「管理職」を表すクラスが必要になったとします。氏名・給与・従業員番号といった項目は社員と同じで、そこに「部下の一覧」だけが追加されます。このとき、Manager クラスをゼロから書き直して氏名や給与のプロパティをもう一度書くのは無駄ですし、片方だけ修正して仕様がずれるバグの原因にもなります。

継承（けいしょう）は、この無駄を解消する仕組みです。共通部分を持つクラスを基底クラス（親クラス）として1つ定義し、そこに新しい機能を追加した特殊なクラスを派生クラス（子クラス）として作ります。子クラスは親クラスのメンバーをそのまま受け継ぐため、差分（追加・変更したい部分）だけを書けばよくなります。

身近な例で考えると分かりやすくなります。「動物」という大きなくくりの中に「犬」や「猫」がいます。動物はみな「名前を持つ」「鳴く」といった共通の性質を持ちますが、鳴き方は犬と猫で異なります。この関係を継承ツリーで表すと次のようになります。

flowchart TD A["Animal（動物）
名前・鳴く"] --> B["Dog（犬）
「ワン」と鳴く"] A --> C["Cat（猫）
「ニャー」と鳴く"]

図の説明: 親クラス Animal が「名前を持つ」「鳴く」という共通の性質を定義し、子クラスの Dog と Cat がそれぞれの鳴き方だけを独自に追加しています。共通部分は Animal に一度書けば、Dog と Cat の両方で使えます。

この関係は「Dog は Animal である」（is-a の関係）と言い表せます。「Manager は Employee である」も同じ関係です。逆に言えば、「〜は〜である」と自然に言えない関係を無理に継承で表すと、設計が破綻しやすくなります（詳しくは 10.5 のコラムで触れます）。

用語: 基底クラスと派生クラス

継承のもとになるクラスを基底クラス（親クラス・スーパークラスとも呼びます）、それを受け継いで作られるクラスを派生クラス（子クラス・サブクラスとも呼びます）と言います。本ガイドでは「親クラス」「子クラス」という呼び方で統一します。

10.2 Inherits による継承

VB.NET で継承を書くときは、子クラスの宣言の直後に Inherits 親クラス名 を1行書くだけです。まず第9章の Employee クラスを少し簡略化したものを親クラスとし、そこから Manager クラスを作ってみます。

Employee.vb クラスの定義 
' 親クラス: 社員
Public Class Employee
    Public Property Name As String
    Protected Salary As Decimal   ' 子クラスからも参照できる

    Public Sub New(name As String, salary As Decimal)
        Me.Name = name
        Me.Salary = salary
    End Sub

    Public Overridable Function GetInfo() As String
        Return $"{Name}さん（給与: {Salary:C0}）"
    End Function
End Class

ここで注目してほしいのが Salary の修飾子が Protected になっている点です。第9章で学んだ Private はクラス外からも子クラスからも見えませんが、Protected は「クラス外からは隠すが、子クラスからは見える」という中間の公開範囲です。継承を使う設計では、この Protected が重要な役割を果たします。

Manager.vb クラスの定義 
' 子クラス: 管理職（Employeeを継承）
Public Class Manager
    Inherits Employee   ' Employeeを土台にする

    Public MemberCount As Integer   ' 管理職だけが持つ追加メンバー

    Public Sub New(name As String, salary As Decimal, memberCount As Integer)
        MyBase.New(name, salary)   ' 親のコンストラクタを呼び出す
        Me.MemberCount = memberCount
    End Sub
End Class

Manager は自分で Name や GetInfo() を1行も書いていませんが、Inherits Employee のおかげで、それらをそのまま使えます。コンストラクタの1行目にある MyBase.New(name, salary) は「親クラスのコンストラクタを先に実行してください」という指示です。子クラスのコンストラクタでは、親の初期化を任せてから、自分の追加分（MemberCount）だけを初期化するのが基本の書き方です。

継承したメンバーを使う Sub Main内に記述 
Dim boss As New Manager("佐藤", 450000D, 5)

' GetInfoはManagerに書いていないが、Employeeから受け継いでいる
Console.WriteLine(boss.GetInfo())
Console.WriteLine($"部下の人数: {boss.MemberCount}人")
実行結果 
佐藤さん（給与: ￥450,000）
部下の人数: 5人

注意: MyBase.New は1行目に書く

MyBase.New(...) は、子クラスのコンストラクタの最初の行に書く必要があります（省略すると、親クラスに引数なしのコンストラクタがある場合は自動的に呼ばれます）。親のフィールドが初期化される前に子の処理を実行してしまうと、不正な状態のオブジェクトができてしまうためです。

10.3 メソッドの上書き（オーバーライド）

管理職の情報表示では、部下の人数もあわせて表示したいところです。子クラスで親と同じ名前のメソッドを定義し直し、動作を差し替えることをオーバーライド（上書き）と呼びます。オーバーライドを許可するには、親クラス側のメソッドに Overridable を付けておく必要があります（10.2 の GetInfo にはすでに付けてあります）。

Manager.vb（GetInfoを上書き） クラスの定義 
Public Class Manager
    Inherits Employee
    Public MemberCount As Integer

    Public Sub New(name As String, salary As Decimal, memberCount As Integer)
        MyBase.New(name, salary)
        Me.MemberCount = memberCount
    End Sub

    ' 親のGetInfoを上書きし、部下の人数を追加する
    Public Overrides Function GetInfo() As String
        Dim baseInfo As String = MyBase.GetInfo()   ' 親の処理結果を再利用
        Return $"{baseInfo}／部下{MemberCount}人を管理"
    End Function
End Class

子クラス側では Overrides を付けます。MyBase.GetInfo() と書くと、親クラスの元の実装を呼び出して、その結果に追記できます。ゼロから書き直すのではなく「親の処理 ＋ 差分」という発想で書けるのがオーバーライドの利点です。この状態で boss.GetInfo() を呼ぶと、Employee 版ではなく Manager 版が実行されます。

これ以上の上書きを禁止したい場合は NotOverridable Overrides、クラス自体をこれ以上継承させたくない場合はクラス宣言に NotInheritable を付けます。標準の String クラスなどは NotInheritable の代表例です。

オーバーロードとの違い

第7章で学んだオーバーロード（同じ名前で引数が違うメソッドを複数定義すること）と、今回のオーバーライド（親のメソッドを子で上書きすること）は、名前が似ているため混同されがちです。違いを表で整理します。

項目 オーバーロード（第7章） オーバーライド（本節）
関係するクラス 同じクラスの中 親クラスと子クラスの間
引数の並び 異なる（型・数を変える） 同じ（変えてはいけない）
必要なキーワード なし（自動的に区別） Overridable / Overrides
目的 呼び出し方のバリエーションを増やす 子クラスで動作をカスタマイズする

10.4 抽象クラスとインターフェース

図形（円・四角形）のように「共通の性質はあるが、共通の実装は書けない」場合があります。「面積を求める」という処理は円と四角形で必要ですが、計算方法はまったく違うため、親クラスに共通の計算式は書けません。このようなときに使うのが抽象クラスです。

Shape.vb（抽象クラス） クラスの定義 
' MustInherit: このクラス単体ではNewできない（土台専用）
Public MustInherit Class Shape
    Public Property Name As String

    ' MustOverride: 子クラスで必ず実装させる（中身は書けない）
    Public MustOverride Function GetArea() As Double
End Class

MustInherit を付けたクラスは「継承されるための土台」専用になり、New Shape() のように直接インスタンス化することはできません。さらに MustOverride を付けたメソッドは中身（処理内容）を書かず、宣言だけにします。このメソッドは、継承する子クラスで必ず Overrides して実装しなければなりません。実装を強制することで、「Shapeを継承したのに GetArea を書き忘れる」というミスをコンパイルの時点で防げます。

似た目的を持つもう1つの仕組みがインターフェースです。インターフェースは「これができることを約束する」という契約のようなもので、中身を持たず、メソッドの名前と形だけを定義します。

IShape.vb / Circle.vb クラスの定義 
' インターフェース: 「これができる」という約束事だけを定義
Public Interface IShape
    Function GetArea() As Double
End Interface

' Implementsで約束を実装するクラス
Public Class Circle
    Implements IShape

    Public Function GetArea() As Double Implements IShape.GetArea
        Return 3.14 * 5 * 5
    End Function
End Class

注意: この Circle は10.5の Circle とは別物

ここでの Circle は、インターフェース IShape の説明専用のサンプルです。10.5 で作る Circle（Shape を継承する版）とは定義が異なる別のクラスです。同じプロジェクトに同名の Circle クラスを2つ置くとコンパイルエラー（型の二重定義）になるため、実際に試すときはどちらか一方だけを使うか、片方の名前を CircleSample のように変更してください。

Implements IShape と書いたクラスは、IShape が約束したメソッドをすべて実装しなければコンパイルエラーになります。「このクラスは IShape の機能を持っています」ということを、コードの上で保証できるわけです。抽象クラスと違い、VB.NET では1つのクラスが複数のインターフェースを同時に実装できます。

使い分けの目安

観点 抽象クラス（MustInherit） インターフェース（Interface）
共通の実装 持てる（Name プロパティなど） 持てない（形だけ）
1クラスが継承できる数 1つだけ 複数OK
向いている場面 「〜は〜である」という強い親子関係 「〜ができる」という機能の約束

用語: 「できることの約束」

インターフェースは、部品の規格に似ています。「USBの規格を満たす機器」であれば、中身がマウスでもキーボードでも同じ差し込み口で使えます。IShape を実装したクラスであれば、円でも四角形でも「面積を聞けば答えてくれる」という同じ約束を守っている、というイメージです。

10.5 ポリモーフィズム

ポリモーフィズム（多態性）とは、「同じ呼び出し方をしても、実際のオブジェクトの種類によって異なる動きをする」という性質のことです。10.4 の Shape を継承して Circle と Rectangle を作り、両方を同じリストにまとめて扱ってみます。

Circle.vb / Rectangle.vb クラスの定義 
Public Class Circle
    Inherits Shape
    Public Property Radius As Double
    Public Overrides Function GetArea() As Double
        Return 3.14 * Radius * Radius
    End Function
End Class
Public Class Rectangle
    Inherits Shape
    Public Property Width As Double
    Public Property Height As Double
    Public Overrides Function GetArea() As Double
        Return Width * Height
    End Function
End Class
呼び出し側 Sub Main内に記述 
' 親クラス型のリストに、子クラスのオブジェクトを混在させて格納
Dim shapes As New List(Of Shape) From {
    New Circle With {.Name = "円", .Radius = 5},
    New Rectangle With {.Name = "四角形", .Width = 4, .Height = 6}
}

' 呼び出し方はGetArea()だけで同じだが、実行される中身は異なる
For Each s As Shape In shapes
    Console.WriteLine($"{s.Name}の面積: {s.GetArea():F2}")
Next
実行結果 
円の面積: 78.50
四角形の面積: 24.00

For Each の中では、どちらも同じ s.GetArea() という書き方をしているだけですが、実際に呼ばれるのは s の中身が円なら Circle 版、四角形なら Rectangle 版です。呼び出す側は「相手が何の図形か」を気にせず、「Shapeであれば GetArea が呼べる」ということだけを知っていればよいのです。図で流れを確認しましょう。

flowchart TD A["Shape（抽象クラス）
MustOverride GetArea()"] --> B["Circle
Overrides GetArea()"] A --> C["Rectangle
Overrides GetArea()"] D["s.GetArea() を呼び出す"] -->|sの中身がCircleなら| B D -->|sの中身がRectangleなら| C

図の説明: 呼び出し側は同じ「s.GetArea()」という命令を書くだけですが、実際に実行されるのは s の中身（実体）に応じて Circle の実装か Rectangle の実装かに振り分けられます。これがポリモーフィズムです。

オブジェクトの実際の型を確認したいときは TypeOf ... Is 演算子が使えます。また、親クラス型の変数を確実に子クラス型として扱いたい場合は CType や DirectCast でキャスト（型変換）します。

型判定とキャスト Sub Main内に記述 
For Each s As Shape In shapes
    ' TypeOf ... Is で実際の型を判定する
    If TypeOf s Is Circle Then
        ' DirectCastで安全にCircle型として扱う
        Dim c As Circle = DirectCast(s, Circle)
        Console.WriteLine($"半径{c.Radius}の円です")
    End If
Next

ポリモーフィズムの実務上の利点は、「新しい種類の図形（例: 三角形）を追加しても、For Each で回している呼び出し側のコードは1行も変更しなくてよい」ことです。Triangle クラスを Shape 継承で追加し、GetArea を実装してリストに加えるだけで、既存の処理がそのまま新しい図形にも対応します。これは規模の大きいプログラムほど効いてくる、保守性の高い設計の基本です。

注意: 継承の設計で気をつけること

親クラスのメソッドに Overridable を付け忘れると、子クラスで Overrides できずコンパイルエラーになります。また、継承の階層を「親 → 子 → 孫 → ひ孫…」と深くしすぎると、どこで何が定義されているか追いにくくなります。継承は浅く保ち、「〜は〜である」と自然に言えない関係には無理に使わないのが、実務での指針です。

重要ポイント

継承は「共通部分を1か所にまとめる」ための仕組みであり、ポリモーフィズムは「その共通の窓口を通じて、種類の違うオブジェクトをまとめて扱う」ための仕組みです。この2つはセットで使うことで、コードの重複を減らし、機能追加に強い設計を実現できます。

やってみよう 10-1: 図形の面積を一覧表示しよう

抽象クラス Shape を継承した Circle と Rectangle を使い、複数の図形をリストにまとめて面積を一覧表示するプログラムを作りましょう。

手順

  • 1 10.4・10.5 のコードを参考に、Shape（抽象クラス）・Circle・Rectangle を定義する。
  • 2 List(Of Shape) に円2つ・四角形2つを追加する。
  • 3 For Each で全図形の名前と面積を表示する。
  • 4 発展: すべての図形の面積の合計を、変数に加算しながら計算して表示する。

解答例

Dim shapes As New List(Of Shape) From {
    New Circle With {.Name = "円A", .Radius = 3},
    New Circle With {.Name = "円B", .Radius = 5},
    New Rectangle With {.Name = "四角形A", .Width = 4, .Height = 5},
    New Rectangle With {.Name = "四角形B", .Width = 2, .Height = 8}
}

Dim total As Double = 0
For Each s As Shape In shapes
    Console.WriteLine($"{s.Name}の面積: {s.GetArea():F2}")
    total += s.GetArea()   ' 発展: 合計を加算
Next
Console.WriteLine($"合計面積: {total:F2}")

理解度確認クイズ

  • Q1. 継承を使うと、なぜコードの重複を減らせるのですか？

    回答を表示

    複数のクラスに共通する部分を親クラスに1回だけ書き、子クラスは Inherits でそれを受け継いで、差分（追加・変更したい部分）だけを書けばよくなるためです。同じ内容を何度も書く必要がなくなり、修正も親クラス1か所で済みます。

  • Q2. 親クラスのメソッドを子クラスで上書きしたいとき、親側と子側にそれぞれ何というキーワードを付ける必要がありますか？

    回答を表示

    親クラス側には Overridable（上書きを許可する）、子クラス側には Overrides（実際に上書きする）を付けます。親に Overridable がないと、子で上書きしようとしてもコンパイルエラーになります。

  • Q3. 抽象クラス（MustInherit）とインターフェース（Interface）の大きな違いは何ですか？

    回答を表示

    抽象クラスは共通の実装（プロパティやメソッドの中身）を持てますが、1つのクラスは1つしか継承できません。インターフェースは実装を持たず「できることの約束」だけを定義しますが、1つのクラスが複数のインターフェースを同時に実装できます。

  • Q4. ポリモーフィズムとは、どのような性質のことですか。図形（Shape・Circle・Rectangle）の例で説明してください。

    回答を表示

    同じ呼び出し方（s.GetArea()）をしても、オブジェクトの実際の種類（Circle か Rectangle か）によって、実行される処理が異なる性質のことです。List(Of Shape) に円や四角形をまとめて入れ、同じ For Each で面積を求められるのはこの性質のおかげです。
