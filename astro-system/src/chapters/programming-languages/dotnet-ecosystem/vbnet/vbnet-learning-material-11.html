ホーム VB.NET入門 第11章
第11章 所要時間: 約90分

エラーに備える - 例外処理とデバッグ

どんなに注意して書いたプログラムでも、実行時には予想外のことが起こります。ファイルが見つからない、ユーザーが数字の代わりに文字を入力する、0で割り算をしてしまう――こうした「異常事態」でプログラムが突然落ちてしまうのを防ぐのが例外処理です。この章では、エラーの種類の見分け方から Try ... Catch ... Finally の使い方、そして Visual Studio でバグを見つけ出すデバッグの基本操作までを学びます。

この章で学ぶこと

  • 構文エラー・実行時エラー（例外）・論理エラーの違いを見分けられる
  • Try ... Catch ... Finally でプログラムが落ちるのを防げる
  • Throw で自ら例外を発生させ、事前チェックとの使い分けを説明できる
  • Visual Studio のブレークポイントとステップ実行でバグの原因を調べられる

11.1 エラーの3つの種類

プログラムを書いていると、さまざまな「うまくいかない」に出会います。原因を素早く突き止めるには、まずエラーが次の3つのどれに当たるかを見極めることが大切です。それぞれ発見できるタイミングと対処方法がまったく異なります。

種類 内容 見つかるタイミング 対処方法
構文エラー 文法違反（スペルミス・End Sub の書き忘れなど） 実行前（コンパイル時） エラー一覧を見て該当行を修正する
実行時エラー（例外） 文法は正しいが、実行中に異常事態が起きる（0除算・数値変換失敗など） 実行してみて初めて発生 本章で学ぶ Try ... Catch で備える
論理エラー 動作はするが、結果が意図と違う（計算式の間違いなど） 実行しても気づきにくい 11.5 で学ぶデバッグで変数の中身を確認する

構文エラーは Visual Studio がコードの下に赤い波線で教えてくれるため、比較的見つけやすいものです。厄介なのは残り2つです。実行時エラー（例外）はプログラムをクラッシュさせるため気づきやすい反面、いつどこで起きるか予測しづらく、本章の主役です。論理エラーはプログラムが正常終了してしまうため、結果を注意深く確認しないと見落とされます。

用語: バグとデバッグ

プログラムの不具合をバグ、それを取り除く作業をデバッグと呼びます。「虫（bug）を取り除く」が語源とされ、3種類のエラーすべてがバグの原因になり得ます。11.5 では Visual Studio を使った実践的なデバッグ手順を学びます。

11.2 例外とは

例外（Exception）とは、プログラムの実行中に起きる「想定外の異常事態」のことです。何も対策をしていないと、例外が発生した瞬間にその場で処理が中断され、呼び出し元へ呼び出し元へと伝わっていき、最終的にプログラム全体が異常終了（クラッシュ）します。

flowchart TD A["Main内でメソッドAを呼ぶ"] --> B["メソッドAの中でメソッドBを呼ぶ"] B --> C["メソッドBの中で例外が発生"] C --> D["メソッドBの処理を中断"] D --> E["呼び出し元のメソッドAへ伝わる"] E --> F{"メソッドAでCatchしている？"} F -->|いいえ| G["さらにMainへ伝わる"] G --> H{"Mainでも未対応"} H --> I["プログラムが異常終了"] F -->|はい| J["Catchで処理を継続"]

図の説明: 例外はそれを起こした場所で処理を止め、対応する Catch が見つかるまで呼び出し元へ次々と伝わっていきます。どこでも受け止められないと、最後にはプログラム全体が落ちてしまいます。

VB.NET（.NET）には、起きた異常の種類ごとに用意された例外クラスがあります。代表的なものを知っておくと、どんな原因で落ちたのかをメッセージから素早く判断できるようになります。

例外クラス 発生する原因
DivideByZeroException 整数の値を0で割ろうとした
FormatException 数値に変換できない文字列を Integer.Parse などに渡した
IndexOutOfRangeException 配列の存在しない要素番号（添字）にアクセスした
NullReferenceException 値が入っていない（Nothing）オブジェクトのメンバーを使おうとした
FileNotFoundException 指定したパスのファイルが存在しなかった（第12章で登場）
OverflowException データ型で表せる範囲を超えた計算結果になった

重要ポイント

これらの例外クラスはすべて、大元の System.Exception クラスを継承しています（第10章の継承を思い出してください）。そのため、11.3 で学ぶ Catch ex As Exception はどんな種類の例外でも受け止められる「最後の受け皿」になります。

11.3 Try ... Catch ... Finally

例外に備えるための基本構文が Try ... Catch ... Finally です。「例外が起きるかもしれない処理」を Try ブロックで囲み、「例外が起きたときの処理」を Catch ブロックに書きます。

Program.vb Sub Main内に記述 
Try
    ' 例外が起きるかもしれない処理
    Dim a As Integer = 10
    Dim b As Integer = 0
    Console.WriteLine(a \ b)   ' 0で割るためここで例外発生
Catch ex As Exception
    ' 例外が発生したときだけ実行される
    Console.WriteLine("エラーが発生しました: " & ex.Message)
Finally
    ' 例外の有無にかかわらず必ず実行される
    Console.WriteLine("計算処理を終了します")
End Try

Catch ex As Exception の ex は例外オブジェクトと呼ばれ、何が起きたかの詳細情報を持っています。特に ex.Message は「原因を説明する文章」で、画面表示やログに使う基本の情報です。

flowchart TD A["Tryブロック開始"] --> B["処理を実行"] B --> C{"例外が発生した？"} C -->|いいえ| D["Tryブロックを最後まで実行"] C -->|はい| E["該当するCatchブロックを実行"] D --> F["Finallyブロックを実行"] E --> F F --> G["Try文の後ろへ続行"]

図の説明: 例外が発生してもしなくても、最後には必ず Finally ブロックが実行されてから、プログラムは続きの処理に進みます。

複数のCatchを使い分ける

1つの Try に Catch を複数書き、例外の種類ごとに異なる対応をすることができます。このとき必ず具体的な例外クラスから順に書いてください。すべての例外を受け止める Exception を先に書いてしまうと、後ろの具体的な Catch には決して到達しません。

Program.vb Sub Main内に記述 
Console.Write("割る数を入力してください: ")
Dim input As String = Console.ReadLine()

Try
    Dim divisor As Integer = Integer.Parse(input)
    Dim result As Integer = 100 \ divisor
    Console.WriteLine("結果: " & result)
Catch ex As DivideByZeroException
    ' 具体的な例外を先に書く
    Console.WriteLine("0では割れません")
Catch ex As FormatException
    Console.WriteLine("数値を入力してください")
Catch ex As Exception
    ' どれにも当てはまらない例外はここで受け止める
    Console.WriteLine("予期しないエラー: " & ex.Message)
End Try

注意: Catchの中を空にしない

Catch ex As Exception の中身を何も書かずに End Try としてしまうと、エラーが起きたこと自体を「握りつぶして」しまいます。プログラムは動き続けますが、原因調査ができず、後で別の不具合として表面化する危険があります。最低でも Console.WriteLine(ex.Message) などでログに残しましょう。

11.4 例外を発生させる／使い分け

例外は .NET が自動的に発生させるものだけではありません。自分で作ったクラスやメソッドの中で「これは異常な状態だ」と判断したときは、Throw キーワードを使って自ら例外を発生させることができます。

Program.vb 完全なプログラム 
Module Program
    ' 年齢を検証し、不正な値なら例外を投げる
    Sub SetAge(age As Integer)
        If age < 0 OrElse age > 150 Then
            Throw New ArgumentException("年齢が不正です")
        End If
        Console.WriteLine("年齢を " & age & " に設定しました")
    End Sub

    Sub Main()
        Try
            SetAge(-5)
        Catch ex As ArgumentException
            Console.WriteLine("入力エラー: " & ex.Message)
        End Try
    End Sub
End Module

これは第9章で学んだプロパティの検証（バリデーション）でも同じ考え方が使えます。Set の中で不正な値を弾き、Throw New ArgumentException(...) で「この値は受け付けられません」と呼び出し元に知らせるのです。

Product.vb クラスの定義 
Public Class Product
    Private _price As Integer

    Public Property Price As Integer
        Get
            Return _price
        End Get
        Set(value As Integer)
            If value < 0 Then
                ' 価格が負の数なら異常事態として例外を投げる
                Throw New ArgumentException("価格は0以上にしてください")
            End If
            _price = value
        End Set
    End Property
End Class

事前チェックと例外の使い分け

「入力ミスはすべて例外で処理すればよい」と考えたくなりますが、それは効率的ではありません。起きることが最初から予測できる入力ミスは、第2章で学んだ TryParse のような事前チェックで防ぐのが基本です。一方、本来なら起きないはずの想定外の異常（ファイルが急に削除された、ネットワークが切れたなど）には例外処理で備えます。

状況 推奨する方法
ユーザーが数字の欄に文字を入力するかもしれない Integer.TryParse で事前チェック
プログラムの正常な使い方では起きないはずの不正な状態 Throw で例外を発生させる
ファイルアクセスなど外部要因で失敗しうる処理 Try ... Catch で備える

予告: Using によるリソース解放

ファイルやデータベース接続のように「使い終わったら必ず片付けるべきもの」を扱うときは、Using ... End Using という構文を使うと、例外が起きても自動的に後片付け（解放）が行われます。内部的には Finally と同じ考え方です。詳しくは第12章のファイル入出力で学びます。

11.5 Visual Studio でデバッグする

例外処理はエラーで落ちないようにする対策ですが、論理エラー（動くのに結果がおかしい）を見つけるには、プログラムの動きを1行ずつ確認するデバッグが欠かせません。Visual Studio には、その場でプログラムを一時停止し、変数の中身を覗ける強力なデバッグ機能が用意されています。

操作 キー できること
ブレークポイント設定 F9 コード左端をクリックし、その行の直前で実行を一時停止させる
デバッグ実行 F5 デバッガーを接続した状態でプログラムを実行する
ステップオーバー F10 現在の行を実行し、次の行へ進む（メソッドの中には入らない）
ステップイン F11 呼び出し先メソッドの中まで1行ずつ追いかける

F10 と F11 の違いは重要です。呼び出しているメソッドの中身まで確認したいときは F11（ステップイン）、すでに動作を信頼している部品（Console.WriteLine など）を素通りしたいときは F10（ステップオーバー）を使い分けます。

変数の中身を確認する

ブレークポイントで一時停止すると、画面下部に「ローカル」ウィンドウが表示され、現在有効な変数と値の一覧が確認できます。特定の変数だけを継続して見張りたい場合は、変数を右クリックして「ウォッチの追加」を選ぶとウォッチ式として常に監視できます。

ブレークポイントを置かずに一時的なログだけ確認したい場合は、コード中に Debug.WriteLine(...) を書くと、「出力」ウィンドウにメッセージが表示されます。Console.WriteLine と違い、実行画面には表示されずログだけを残せるのが特徴です。

Program.vb Sub Main内に記述 
' Debug.WriteLineを使うには、ファイルの先頭に
' 「Imports System.Diagnostics」の記述が必要
Dim total As Integer = 0
For i As Integer = 1 To 5
    total += i
    ' 出力ウィンドウにだけログを残す
    Debug.WriteLine("i = " & i & ", total = " & total)
Next
Console.WriteLine("合計: " & total)

バグを見つける基本手順

闇雲にコードを眺めても原因はなかなか見つかりません。次の手順で、疑わしい範囲を少しずつ絞り込んでいきましょう。

  • 1. 症状を再現する — どんな入力・操作をすると、どんな誤った結果になるかを特定する
  • 2. 該当箇所を絞り込む — 怪しい処理の手前にブレークポイントを置く
  • 3. 変数の値を確認する — ステップ実行しながら、想定と実際の値がどこでズレるかを見る
  • 4. 修正する — ズレの原因になったコードを直す
  • 5. 再確認する — もう一度実行し、症状が再現しないことを確かめる

注意: とりあえず Exception で済ませない

Catch ex As Exception だけですべてを受け止めると、コードは動きますが「何が原因だったか」を区別できなくなります。11.2 の表を参考に、まず起こりうる具体的な例外を考え、Exception は最後の受け皿として使いましょう。

やってみよう 11-1: 落ちない電卓を作ろう

ユーザーに2つの数値を入力してもらい割り算をする、シンプルな電卓プログラムを作ります。文字が入力されても、0で割られても、プログラムが落ちないように Try ... Catch ... Finally で保護しましょう。

手順

  • 1 Console.ReadLine() で「割られる数」と「割る数」を文字列として受け取る。
  • 2 Try ブロック内で Integer.Parse による変換と割り算を行う。
  • 3 Catch FormatException と Catch DivideByZeroException をこの順で用意し、それぞれ違うメッセージを表示する。
  • 4 Finally で「計算を終了しました」と必ず表示させ、わざと文字や0を入力して落ちないことを確認する。

解答例

Module Program
    Sub Main()
        Console.Write("割られる数: ")
        Dim numText As String = Console.ReadLine()
        Console.Write("割る数: ")
        Dim divText As String = Console.ReadLine()

        Try
            Dim num As Integer = Integer.Parse(numText)
            Dim div As Integer = Integer.Parse(divText)
            Console.WriteLine("結果: " & (num \ div))
        Catch ex As FormatException
            Console.WriteLine("数値を入力してください")
        Catch ex As DivideByZeroException
            Console.WriteLine("0では割れません")
        Finally
            Console.WriteLine("計算を終了しました")
        End Try
    End Sub
End Module

理解度確認クイズ

  • Q1. 「文法は正しいのに実行してみたらエラーになる」ものと「実行はできるが結果が間違っている」ものは、それぞれ何エラーと呼びますか？

    回答を表示

    前者は実行時エラー（例外）、後者は論理エラーです。実行時エラーは Try ... Catch で備え、論理エラーはデバッグで変数の中身を確認して見つけます。

  • Q2. 複数の Catch を書くとき、なぜ具体的な例外クラスを先に、Exception を最後に書く必要があるのですか？

    回答を表示

    Exception はすべての例外を受け止められるクラスのため、先に書いてしまうとそこですべての例外が処理されてしまい、後ろに書いた具体的な Catch（例: DivideByZeroException）には決して到達しません。

  • Q3. Finally ブロックは、どのようなタイミングで実行されますか？

    回答を表示

    例外が発生してもしなくても、必ず実行されます。後片付けやログ出力など、結果にかかわらず必ず行いたい処理を書くのに適しています。

  • Q4. Visual Studio で、実行中のプログラムをある行の直前で一時停止させる目印を何といい、どのキーで設定しますか？また、呼び出し先メソッドの中まで1行ずつ追いかけるキーは何ですか？

    回答を表示

    目印はブレークポイントで、F9 キーで設定します。呼び出し先メソッドの中まで追いかけるのはステップイン（F11）です（メソッドの中に入らず次の行へ進む場合はステップオーバー F10）。
