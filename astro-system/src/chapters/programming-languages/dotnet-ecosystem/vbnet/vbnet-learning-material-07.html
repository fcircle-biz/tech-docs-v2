ホーム VB.NET入門 第7章
第7章 所要時間: 約90分

処理を部品にする - SubプロシージャとFunction

ここまでの章では、処理はすべて Sub Main() の中に順番に書いてきました。この章では、まとまった処理に名前を付けて部品化する「プロシージャ」を学びます。戻り値のない Sub、戻り値のある Function、引数の渡し方の違い、そして良いプロシージャの作り方まで、段階的に理解していきましょう。

この章で学ぶこと

  • 処理を部品化する理由と、プロシージャの役割を説明できる
  • 戻り値のない Sub と戻り値のある Function を書き分けられる
  • ByVal と ByRef、Optional 引数の違いを理解し使い分けられる
  • 変数のスコープとオーバーロードを理解し、読みやすいプロシージャを設計できる

7.1 プロシージャとは

料理をするとき、毎回「だしの取り方」を最初から説明していたら、レシピはとても長く読みにくくなります。そこで「だしを取る」という手順だけを別のレシピカードに書いておき、必要なときに「あのレシピを見てね」と呼び出せば、本体のレシピはすっきりします。プログラミングにおけるこの「別カード」にあたるのがプロシージャです。

これまでの章では、消費税の計算や合計金額の計算のような処理を、必要になるたびに Sub Main() の中に同じようなコードとして書いてきました。同じ処理が2か所、3か所と増えていくと、次のような問題が起こります。

  • コードが長くなり、どこで何をしているのか読み取りにくくなる
  • 同じ処理を毎回コピー＆ペーストすることになり、無駄が多い
  • 仕様変更で計算方法を直すとき、コピーしたすべての箇所を書き換える必要があり、直し忘れが起きやすい

まとまった処理に名前を付けて部品化すれば、これらの問題を解決できます。部品化には主に3つの利点があります。

読みやすい

処理に意味の分かる名前が付くので、本体のコードが「何をしているか」を読み取りやすくなります。

再利用できる

一度作った部品は、名前を呼び出すだけで何度でも、どこからでも使い回せます。

修正が1か所で済む

処理をまとめた場所を直せば、それを呼び出しているすべての箇所に修正が反映されます。

実は使っていた「プロシージャ」

第1章から書き続けてきた Sub Main() も、実はプロシージャの一種です。VB.NET のコンソールアプリは「Sub Main という名前のプロシージャから実行が始まる」という約束事になっています。この章では、Main 以外にも自分でプロシージャを作れるようになります。

VB.NET には、部品化のための仕組みが2種類あります。Subプロシージャ（戻り値なし）とFunctionプロシージャ（戻り値あり）です。次の節から順番に見ていきましょう。

7.2 Subプロシージャ

Subプロシージャは、「何かの処理をするが、結果を呼び出し元に返さない」プロシージャです。画面にメッセージを表示する、値を書き換える、ファイルに書き込む、といった「実行すること自体が目的」の処理に向いています。定義は次の形です。

Sub プロシージャの基本形 
' 引数なしのSubプロシージャ
Sub 名前()
    ' ここに処理を書く
End Sub

実際に、区切り線を表示するだけのシンプルなプロシージャを作ってみましょう。Module の中に Sub Main と並べて書くことで、同じモジュール内から呼び出せます。

Program.vb 完全なプログラム 
Module Program
    Sub Main()
        Console.WriteLine("売上レポート")
        ShowLine()   ' 区切り線プロシージャを呼び出す
        Console.WriteLine("店舗A: 120000円")
        ShowLine()   ' 何度でも呼び出せる
    End Sub

    ' 区切り線を表示するだけのプロシージャ
    Sub ShowLine()
        Console.WriteLine("--------------------")
    End Sub
End Module
実行結果 
売上レポート
--------------------
店舗A: 120000円
--------------------

Subプロシージャには、呼び出し元から値を受け取るための引数（パラメータ）を持たせることもできます。引数は () の中に「引数名 As 型」の形で書きます。

Program.vb Sub Mainと並べて記述 
' 1つの引数を受け取るSub
Sub Greet(name As String)
    Console.WriteLine(name & "さん、こんにちは")
End Sub

' 呼び出し側
Greet("田中")
Greet("鈴木")

引数は ,（カンマ）で区切ることで複数指定できます。呼び出すときは、定義した順番どおりに値を渡します。

Program.vb Sub Mainと並べて記述 
' 複数の引数を受け取るSub
Sub ShowProfile(name As String, age As Integer)
    Console.WriteLine(name & "さん（" & age & "歳）")
End Sub

' 呼び出し側（順番どおりに値を渡す）
ShowProfile("佐藤", 28)

7.3 Functionプロシージャ

計算の結果や判定の結果など、「処理した結果を呼び出し元に返してほしい」場合にはFunctionプロシージャを使います。Sub との違いは、戻り値の型を As のあとに書く点と、処理の最後に Return で値を返す点です。

Function プロシージャの基本形 
' 2つの整数を受け取り、合計を返すFunction
Function Add(a As Integer, b As Integer) As Integer
    Return a + b   ' ここで処理が終わり、値が呼び出し元に返る
End Function

呼び出すときは、戻ってきた値を変数に代入したり、そのまま Console.WriteLine に渡したりできます。

Program.vb 完全なプログラム 
Module Program
    Sub Main()
        ' 戻り値を変数で受け取る
        Dim total As Integer = Add(120, 30)
        Console.WriteLine("合計: " & total)

        ' 戻り値をそのまま表示に使う
        Console.WriteLine("合計: " & Add(5, 7))
    End Sub

    Function Add(a As Integer, b As Integer) As Integer
        Return a + b
    End Function
End Module

重要なのは、Return に到達した時点でそのプロシージャの処理はそこで終わるという点です。Return より下に書いた行があっても実行されません。条件によって早めに結果を返したいときに、この性質を利用できます。

Program.vb Sub Mainと並べて記述 
' 割引後の価格を返す。0円以下ならその場で0を返す
Function GetDiscountPrice(price As Integer) As Integer
    If price <= 0 Then
        Return 0   ' ここで処理終了。以降の行は実行されない
    End If
    Return CInt(price * 0.9)
End Function

Sub と Function のどちらを使うべきか迷ったときは、次の表を目安にしてください。

観点 Sub Function
戻り値 なし あり（As 型 で指定）
目的 何かを「実行すること」自体 計算・判定などの「結果」を得ること
具体例 画面表示、ファイル出力、値の更新 合計計算、税込価格算出、真偽判定
終わり方 End Sub Return と End Function

7.4 引数の渡し方

プロシージャに変数を渡すとき、その渡し方には2種類あります。ByVal（値のコピーを渡す）とByRef（変数そのものを渡す）です。VB.NET では引数を何も指定しなければ、既定で ByVal として扱われます。

flowchart LR subgraph ByVal["ByVal（値のコピーを渡す）"] direction LR A1["呼び出し元の変数"] -->|コピーを渡す| B1["プロシージャ内の変数"] B1 -->|変更してもコピーだけ影響| C1["呼び出し元は変化しない"] end subgraph ByRef["ByRef（変数そのものを渡す）"] direction LR A2["呼び出し元の変数"] -->|同じ場所を渡す| B2["プロシージャ内の変数"] B2 -->|変更すると直接反映| C2["呼び出し元も変化する"] end

図の説明: ByVal では値のコピーが渡されるため、プロシージャ内で書き換えても呼び出し元の変数は影響を受けません。ByRef では変数そのものが渡されるため、プロシージャ内での書き換えが呼び出し元にも反映されます。

実際のコードと実行結果で違いを確認しましょう。

Program.vb 完全なプログラム 
Module Program
    Sub Main()
        Dim x As Integer = 10
        AddTenByVal(x)
        Console.WriteLine("ByVal後: " & x)   ' 10のまま

        Dim y As Integer = 10
        AddTenByRef(y)
        Console.WriteLine("ByRef後: " & y)   ' 20になる
    End Sub

    ' 既定はByVal（コピーが渡る）
    Sub AddTenByVal(ByVal num As Integer)
        num = num + 10
    End Sub

    ' ByRefは変数そのものが渡る
    Sub AddTenByRef(ByRef num As Integer)
        num = num + 10
    End Sub
End Module
実行結果 
ByVal後: 10
ByRef後: 20

次に、引数を省略できるOptional引数を紹介します。Optional を付けた引数には既定値を指定しておき、呼び出し側で値を渡さなければその既定値が使われます。Optional 引数は、必ず引数リストの最後に置く必要があります。

Program.vb Sub Mainと並べて記述 
' taxRateは省略可能。省略時は0.1（10%）を使う
Function GetTaxIncluded(price As Integer, Optional taxRate As Double = 0.1) As Integer
    Return CInt(price * (1 + taxRate))
End Function

' 呼び出し例
Console.WriteLine(GetTaxIncluded(1000))          ' 既定の10%が使われる
Console.WriteLine(GetTaxIncluded(1000, 0.08))    ' 8%を指定

また、引数の多いプロシージャを呼び出すときは、名前付き引数を使うと「どの値が何を表しているか」が読みやすくなります。引数名と := を使って値を指定します。

Program.vb Sub Main内に記述 
' 名前付き引数を使うと意味が分かりやすい
Console.WriteLine(GetTaxIncluded(price:=1000, taxRate:=0.08))

' 順番を入れ替えても名前で指定すれば正しく渡る
Console.WriteLine(GetTaxIncluded(taxRate:=0.08, price:=1000))

注意: ByRefの使いすぎに気をつける

ByRef は便利ですが、多用すると「どのプロシージャが変数をいつ書き換えたのか」が追いにくくなり、バグの原因になりがちです。値を返したいだけなら、素直に Function の戻り値を使うほうが分かりやすいコードになります。

7.5 スコープとオーバーロード

変数には「どこからその変数を使えるか」という有効範囲があり、これをスコープと呼びます。Subプロシージャや Functionプロシージャの中で Dim 宣言した変数はローカル変数と呼ばれ、そのプロシージャの中だけで使え、プロシージャの実行が終わると消えます。

一方、Module の直下（どの Sub/Function にも属さない場所）で宣言した変数はモジュールレベル変数と呼ばれ、同じモジュール内のすべてのプロシージャから読み書きできます。

Program.vb 完全なプログラム 
Module Program
    ' モジュールレベル変数：どのプロシージャからも見える
    Dim callCount As Integer = 0

    Sub Main()
        ShowMessage()
        ShowMessage()
        Console.WriteLine("呼び出し回数: " & callCount)
    End Sub

    Sub ShowMessage()
        ' ローカル変数：このSubの中だけで使える
        Dim message As String = "こんにちは"
        Console.WriteLine(message)
        callCount = callCount + 1   ' モジュールレベル変数を更新
    End Sub
End Module

VB.NET では、同じ名前のプロシージャを引数の型や数を変えて複数定義できます。これをオーバーロードと呼びます。呼び出すときに渡した引数の型・数に応じて、適切な定義が自動的に選ばれます。

Program.vb Sub Mainと並べて記述 
' 整数2つを足すFunction
Function Add(a As Integer, b As Integer) As Integer
    Return a + b
End Function

' 同じ名前で、文字列2つをつなげるFunction（オーバーロード）
Function Add(a As String, b As String) As String
    Return a & b
End Function

' 呼び出し側：渡した型に応じて選ばれる
Console.WriteLine(Add(3, 5))          ' 整数版が呼ばれる → 8
Console.WriteLine(Add("VB", ".NET")) ' 文字列版が呼ばれる → VB.NET

最後に、良いプロシージャを作るための2つの心がけを紹介します。

  • 1つの役割に絞る — 「税込価格を計算する」「名簿を表示する」など、1つのプロシージャは1つの仕事だけを行うようにする。役割を詰め込みすぎると再利用しにくくなる。
  • 意味の分かる名前を付ける — CalcTax、ShowMember のように動詞から始まる名前にすると、呼び出し元を読んだだけで処理内容が想像できる。

重要ポイント

プロシージャは「処理を部品にする」ための最初の一歩です。次の第8章で学ぶクラスは、この「処理の部品」に加えて「データの部品」も一緒にまとめる、さらに大きな部品化の仕組みです。ここでの考え方がそのまま土台になります。

やってみよう 7-1: 名簿表示と平均点計算プログラムを作ろう

Sub と Function の両方を使って、名簿の表示と点数の平均計算を行うプログラムを作りましょう。

手順

  • 1 名前と点数を受け取り、整形して表示する Sub ShowMember(name As String, score As Integer) を作る。
  • 2 3人分の点数（配列や個別の変数）を受け取り、平均点を返す Function GetAverage(a As Integer, b As Integer, c As Integer) As Double を作る。
  • 3 Sub Main から2つのプロシージャを呼び出し、3人の名簿と平均点を表示する。
  • 4 余裕があれば、消費税込みの価格を返す Function GetTaxIncluded（Optional引数つき）も追加して呼び出してみる。

解答例

Module Program
    Sub Main()
        ShowMember("田中", 80)
        ShowMember("鈴木", 75)
        ShowMember("佐藤", 90)

        Dim avg As Double = GetAverage(80, 75, 90)
        Console.WriteLine("平均点: " & avg)
    End Sub

    ' 名前と点数を整形して表示するSub
    Sub ShowMember(name As String, score As Integer)
        Console.WriteLine(name & "さん: " & score & "点")
    End Sub

    ' 3人分の平均点を返すFunction
    Function GetAverage(a As Integer, b As Integer, c As Integer) As Double
        Return (a + b + c) / 3.0
    End Function
End Module

理解度確認クイズ

  • Q1. Sub プロシージャと Function プロシージャの最大の違いは何ですか？

    回答を表示

    戻り値の有無です。Sub は処理を実行するだけで値を返しません。Function は Return によって計算結果などの値を呼び出し元に返します。

  • Q2. ByVal と ByRef の違いを説明してください。VB.NET の既定はどちらですか？

    回答を表示

    ByVal は値のコピーを渡すため、プロシージャ内で変更しても呼び出し元の変数には影響しません。ByRef は変数そのものを渡すため、プロシージャ内での変更が呼び出し元にも反映されます。VB.NET では、指定しない場合の既定は ByVal です。

  • Q3. Optional引数とは何ですか？ 定義するうえでの注意点も1つ挙げてください。

    回答を表示

    Optional は、呼び出し側が値を省略できる引数で、既定値をあらかじめ指定しておきます。省略された場合はその既定値が使われます。注意点として、Optional引数は必ず引数リストの最後に置く必要があります。

  • Q4. 同じ名前で引数の型や数が異なるプロシージャを複数定義できる仕組みを何と呼びますか？

    回答を表示

    オーバーロードと呼びます。呼び出し時に渡された引数の型・数に応じて、コンパイラが適切な定義を自動的に選んで実行します。
