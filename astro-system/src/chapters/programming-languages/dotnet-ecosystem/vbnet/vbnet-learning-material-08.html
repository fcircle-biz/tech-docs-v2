ホーム VB.NET入門 第8章
第8章 所要時間: 約90分

設計図からモノを作る - クラスとオブジェクト

これまで「データ（変数）」と「処理（プロシージャ）」を別々に扱ってきましたが、この章からはいよいよオブジェクト指向プログラミングの入口に立ちます。関連するデータと処理を1つにまとめる「クラス」という考え方を学び、そこから実際に動く「オブジェクト」を作って使えるようになりましょう。

この章で学ぶこと

  • クラス（設計図）とオブジェクト（実体）の関係を、身近な比喩で説明できる
  • Class でフィールドとメソッドを持つクラスを定義できる
  • New でオブジェクトを生成し、コンストラクタで初期値を設定できる
  • Me キーワードとクラスが参照型であることを理解している

8.1 オブジェクト指向の考え方

第7章までで、変数にデータを入れ、プロシージャで処理をまとめる方法を学びました。しかし、社員の情報（名前・年齢・部署）を扱うプログラムを想像してみてください。変数がバラバラのままだと、社員が10人になれば name1, age1, name2, age2... のように変数が増え続け、「この age3 は誰の年齢？」と管理が大変になります。データと、そのデータを扱う処理（自己紹介するなど）もバラバラなままでは、どのプロシージャがどのデータ用なのか分かりにくくなります。

オブジェクト指向プログラミング（OOP）は、この問題を解決する考え方です。関連するデータ（名前・年齢・部署）と、それを扱う処理（自己紹介するなど）を1つの「まとまり」にして管理します。この「まとまり」の設計図にあたるものがクラス、設計図から実際に作られたモノがオブジェクト（インスタンス）です。

身近な例で考えてみましょう。たい焼きの型は「クラス」にあたります。型そのものは食べられませんが、そこから何個でも同じ形のたい焼き（＝「オブジェクト」）を作れます。しかも、あんこ味・カスタード味のように、同じ型から作っても中身（データ）が違うたい焼きを作ることができます。

flowchart TD A["Employeeクラス
（設計図）"] -->|New| B["empオブジェクト1
名前: 佐藤
年齢: 30"] A -->|New| C["empオブジェクト2
名前: 鈴木
年齢: 25"]

図の説明: 1つのクラス（設計図）から、New によって複数のオブジェクトを作れます。それぞれのオブジェクトは同じ「型」を持ちますが、名前や年齢といった中身のデータは独立しています。

クラス＝設計図

どんなデータを持ち、どんな処理ができるかを定義したひな形です。

オブジェクト＝実体

設計図をもとに実際に作られたモノ。データを持ち、メソッドを呼び出せます。

まとめる利点

データと処理が1か所にまとまり、管理・再利用がしやすくなります。

用語: インスタンス

「オブジェクト」と「インスタンス」はほぼ同じ意味で使われます。厳密には「あるクラスから作られた実体」を指してインスタンスと呼び、「そのクラスをインスタンス化する」という言い方をします。本ガイドでも両方の言葉を使いますが、指しているものは同じです。

8.2 クラスを定義する

VB.NET では Class ... End Class でクラスを定義します。クラスの中には、そのクラスが持つデータであるフィールドと、そのクラスが持つ処理であるメソッド（第7章で学んだ Sub / Function）を書きます。社員を表す Employee クラスを例に見てみましょう。

Employee.vb クラスの定義 
' 社員を表すクラス（設計図）
Class Employee
    ' フィールド: このクラスが持つデータ
    Public Name As String
    Public Age As Integer
    Public Department As String

    ' メソッド: このクラスが持つ処理
    Public Sub Introduce()
        Console.WriteLine($"私は{Name}です。{Age}歳、{Department}に所属しています。")
    End Sub
End Class

Public Name As String のような行がフィールドです。書き方は変数宣言（Dim）とよく似ていますが、クラスの中に直接書くことでクラスが持つデータになります。Public は「クラスの外からもアクセスできる」ことを表すアクセス修飾子です（詳しくは第9章で学びます）。Introduce は社員が自己紹介するメソッドで、中身は今までどおり Sub として書けます。

  • フィールド — クラスが持つデータ。オブジェクトごとに独立した値を持ちます。
  • メソッド — クラスが持つ処理。中身は Sub / Function とまったく同じ書き方です。
  • メンバー — フィールドとメソッドをまとめて指す呼び方です。

用語: ファイル分割

これまでの章では Module Program の中にすべて書いてきましたが、実際の開発ではクラスは1つにつき1つの別ファイル（Employee.vb など）に分けて書くのが基本です。ファイルを分けることで、どこに何が書いてあるか探しやすくなり、複数人での開発もしやすくなります。本ガイドでは紙面の都合上まとめて示しますが、実務では分割することを意識してください。

8.3 オブジェクトを作って使う

クラス（設計図）を定義しただけでは、まだ何も動きません。設計図から実際に「モノ」を作る操作がインスタンス生成で、VB.NET では New キーワードを使います。作ったオブジェクトのメンバーには、ドット記法（.）でアクセスします。

Program.vb Sub Main内に記述 
' Employeeクラスからオブジェクトを1つ作る
Dim emp As New Employee()

' ドット記法でフィールドに値を設定する
emp.Name = "佐藤"
emp.Age = 30
emp.Department = "営業部"

' ドット記法でメソッドを呼び出す
emp.Introduce()
実行結果 
私は佐藤です。30歳、営業部に所属しています。

Dim emp As New Employee() は「emp という名前の変数を用意し、そこに新しい Employee オブジェクトを入れる」という意味です。As New Employee() の部分がインスタンス生成にあたります。ここで重要なのは、同じクラスから何個でもオブジェクトを作れることです。それぞれのオブジェクトは独立したデータを持ちます。

Program.vb Sub Main内に記述 
' 同じクラスから2つのオブジェクトを作る
Dim emp1 As New Employee()
emp1.Name = "佐藤"
emp1.Age = 30

Dim emp2 As New Employee()
emp2.Name = "鈴木"
emp2.Age = 25

' それぞれ独立した値を持っている
emp1.Introduce()
emp2.Introduce()

重要ポイント

emp1.Age = 30 と変更しても emp2.Age には一切影響しません。1つのクラス（設計図）から作られたオブジェクトどうしは、たとえ同じフィールド名を持っていても、それぞれが独立した「箱」にデータを保管しています。

8.4 コンストラクタ

前のセクションの書き方では、オブジェクトを作ったあとに emp.Name = "佐藤" のように1行ずつ値を設定していました。しかし、これでは値を設定し忘れるおそれがあります。設定し忘れたフィールドは初期値（String なら Nothing、Integer なら 0）のままになってしまいます。

この問題を防ぐのがコンストラクタです。コンストラクタは Sub New(...) という特別な名前のメソッドで、オブジェクトが生成される瞬間に自動的に呼び出されるという特徴があります。ここで初期値の設定を行えば、値の設定し忘れを防げます。

Employee.vb クラスの定義 
Class Employee
    Public Name As String
    Public Age As Integer

    ' コンストラクタ: New()という名前で作る
    Public Sub New(employeeName As String, employeeAge As Integer)
        ' 引数の値をフィールドに設定する
        Name = employeeName
        Age = employeeAge
    End Sub

    Public Sub Introduce()
        Console.WriteLine($"私は{Name}です。{Age}歳です。")
    End Sub
End Class

このクラスを使う側では、New Employee(...) の括弧の中に初期値を渡すだけで、フィールドが設定された状態のオブジェクトが手に入ります。

Program.vb Sub Main内に記述 
' コンストラクタに初期値を渡して生成する
Dim emp As New Employee("佐藤", 30)
emp.Introduce()

コンストラクタは、第7章で学んだメソッドのオーバーロードと同じ考え方で複数用意することができます。引数の数や型が違う Sub New を並べておけば、状況に応じて呼び分けられます。

Employee.vb（一部抜粋） 
' 名前・年齢を受け取るコンストラクタ
Public Sub New(employeeName As String, employeeAge As Integer)
    Name = employeeName
    Age = employeeAge
End Sub

' 名前のみを受け取るコンストラクタ（年齢は仮の値）
Public Sub New(employeeName As String)
    Name = employeeName
    Age = 20
End Sub

用語: 既定のコンストラクタ

8.2・8.3 で使った New Employee()（引数なし）が動いたのは、コンストラクタを1つも書かなかった場合に VB.NET が「引数なしの既定のコンストラクタ」を自動的に用意してくれるからです。Sub New を自分で1つでも書くと、この自動生成は行われなくなります。

8.5 Me キーワードと参照型

先ほどのコンストラクタでは、引数名を employeeName のようにフィールド名とわざと変えていました。もし引数名とフィールド名を同じ Name にしたい場合、区別のためにMeキーワードを使います。Me は「今動いている、このオブジェクト自身」を指します。

Employee.vb（一部抜粋） 
' 引数名とフィールド名を同じNameにする
Public Sub New(Name As String, Age As Integer)
    ' Me.Nameはフィールド、Nameは引数を指す
    Me.Name = Name
    Me.Age = Age
End Sub

Me.Name は「このオブジェクトが持つフィールドの Name」、右辺の Name は「受け取った引数の Name」を指し、両者は区別されます。Me を付けることで「どちらの Name を指しているか」がコードを読む人にもはっきり伝わります。

クラスは参照型

第2章で学んだ Integer や String は値型で、変数はデータそのものを持っていました。一方、クラスは参照型です。クラスの変数は、オブジェクトそのものではなく「オブジェクトが置かれている場所（参照）」を指すラベルのようなものです。

このため、1つのオブジェクトを2つの変数が指すことができます。片方の変数を使ってフィールドを書き換えると、もう片方の変数から見ても変わって見えます。同じ「実体」を見ているためです。

Program.vb Sub Main内に記述 
Dim emp1 As New Employee("佐藤", 30)
' emp2にemp1を代入すると、同じオブジェクトを指す
Dim emp2 As Employee = emp1

' emp2経由で変更すると…
emp2.Name = "田中"

' emp1から見ても変わっている（同じ実体を指すため）
emp1.Introduce()
実行結果 
私は田中です。30歳です。
flowchart LR A["変数 emp1"] --> C["Employeeオブジェクト
Name: 田中
Age: 30"] B["変数 emp2"] --> C

図の説明: emp1 と emp2 という2つの変数が、同じ1つのオブジェクトを指しています。どちらの変数を使って変更しても、同じ実体が書き換わるため、もう一方の変数から見ても変更が反映されます。

注意: Nothing と NullReferenceException

クラスの変数を Dim emp As Employee のようにNew せずに宣言すると、初期値は「何も指していない」ことを表す Nothing になります。この状態で emp.Name = "佐藤" のようにメンバーへアクセスすると、実行時に NullReferenceException（参照先が無い、というエラー）が発生します。クラス型の変数を使う前には、必ず New でオブジェクトを生成してあるかを確認しましょう。

Tips: クラス名の付け方

クラス名は単数形の名詞にするのが慣習です。「1つのモノ」を表す設計図なので、Employee（○）であって Employees（×、複数形）ではありません。複数の社員を扱いたいときは、第6章で学んだ List(Of Employee) のようにコレクションと組み合わせます。単語の先頭は大文字にするパスカルケース（Employee、ProductItem など）で書きます。

やってみよう 8-1: 商品クラスを作ろう

商品を表す Product クラスを作り、2つの商品オブジェクトを生成して操作してみましょう。

手順

  • 1 フィールド Name As String（商品名）、Price As Integer（単価）、Stock As Integer（在庫数）を持つ Product クラスを作る。
  • 2 商品名・単価・在庫数の3つを受け取るコンストラクタ（Sub New）を作る。
  • 3 税込価格（10%税）を返す Function GetTaxIncludedPrice() As Integer を作る。
  • 4 在庫を指定した数だけ減らす Sub SellStock(quantity As Integer) を作る。
  • 5 2つの商品オブジェクトを作り、それぞれ税込価格の表示と在庫を減らす操作をして、独立していることを確認する。

解答例（フィールドとコンストラクタ）

Class Product
    Public Name As String
    Public Price As Integer
    Public Stock As Integer

    ' コンストラクタで3つの初期値を受け取る
    Public Sub New(Name As String, Price As Integer, Stock As Integer)
        Me.Name = Name
        Me.Price = Price
        Me.Stock = Stock
    End Sub

続けて、税込価格を返すメソッドと在庫を減らすメソッドを同じ Product クラスに追加します。

解答例（Productクラスの続き）

    ' 税込価格を計算して返す
    Public Function GetTaxIncludedPrice() As Integer
        Return CInt(Price * 1.1)
    End Function

    ' 在庫を指定数だけ減らす
    Public Sub SellStock(quantity As Integer)
        Stock -= quantity
    End Sub
End Class

最後に、Module Program の Sub Main で2つの商品オブジェクトを作り、それぞれ独立していることを確認します。

解答例（動作確認）

Module Program
    Sub Main()
        Dim item1 As New Product("ノート", 150, 100)
        Dim item2 As New Product("ボールペン", 100, 50)

        Console.WriteLine($"{item1.Name}: 税込{item1.GetTaxIncludedPrice()}円")
        item1.SellStock(5)
        Console.WriteLine($"{item1.Name}の在庫: {item1.Stock}個")

        ' item2はitem1と独立している
        Console.WriteLine($"{item2.Name}: 税込{item2.GetTaxIncludedPrice()}円")
        Console.WriteLine($"{item2.Name}の在庫: {item2.Stock}個")
    End Sub
End Module

理解度確認クイズ

  • Q1. 「クラス」と「オブジェクト」の関係を、たい焼きの型にたとえて説明してください。

    回答を表示

    クラスは「たい焼きの型（設計図）」にあたり、それ自体は食べられません。オブジェクト（インスタンス）は、その型から実際に作られた「たい焼き」にあたり、同じ型からいくつでも作れます。あんこ味・カスタード味のように、同じ型から作っても中身（データ）が違うオブジェクトを作れます。

  • Q2. クラスに定義するデータのことを何と呼びますか？また、クラスに定義する処理のことを何と呼びますか？

    回答を表示

    データはフィールド、処理はメソッドと呼びます。両方をまとめてメンバーと呼ぶこともあります。

  • Q3. コンストラクタとは何ですか？ どのようなときに呼び出されますか？

    回答を表示

    コンストラクタは Sub New(...) という特別なメソッドで、オブジェクトが New で生成される瞬間に自動的に呼び出されます。ここで初期値を設定しておくことで、フィールドの設定し忘れを防げます。

  • Q4. Dim emp2 As Employee = emp1 と書いたあと、emp2.Name = "田中" と変更すると、emp1.Name はどうなりますか？ 理由も含めて答えてください。

    回答を表示

    emp1.Name も "田中" に変わります。クラスは参照型のため、emp1 と emp2 はどちらも同じ1つのオブジェクトを指しているからです。どちらの変数経由で変更しても、実体は1つしかないため、もう一方から見ても変更が反映されます。
