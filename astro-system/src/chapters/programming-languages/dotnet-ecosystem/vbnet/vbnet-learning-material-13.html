画面のあるアプリを作る - Windows Forms入門

ここまでは黒い画面（コンソール）でプログラムを動かしてきました。この章では、ボタンや入力欄のある「画面付きアプリ」の作り方を学びます。Windows Forms というしくみを使い、消費税を計算するミニアプリを実際に作りながら、GUIプログラミングの基本を身につけましょう。

この章で学ぶこと

  • コンソールアプリとGUIアプリの違いと、「イベント駆動」という考え方を説明できる
  • Visual Studio で Windows Forms プロジェクトを作成し、コントロールを配置できる
  • ボタンのクリックイベントにコードを書き、入力値を取得・計算・表示できる
  • 入力チェックと確認ダイアログを備えた、消費税計算アプリを完成させられる

13.1 GUIアプリとは

第1章から第12章まで、私たちはコンソールアプリ（CUI: キャラクターユーザーインターフェース）を作ってきました。黒い画面に文字を表示し、キーボードから文字を入力する、シンプルなアプリです。処理は Sub Main の中に書いたコードが、上から順番に実行されるだけでした。

一方、普段みなさんが使っている業務システムの多くは、ボタンや入力欄、一覧表があるGUIアプリ（グラフィカルユーザーインターフェース）です。VB.NET でこの種の画面付きアプリを作るための代表的なしくみが、Windows Forms（ウィンドウズ・フォームズ）です。2002年から存在する歴史あるしくみですが、今なお多くの業務システムの画面開発で使われています。

コンソールアプリ（CUI）

画面は黒地に文字だけ。処理は上から順番に1本道で実行される。学習・バッチ処理向き。

GUIアプリ（Windows Forms）

ボタン・入力欄・一覧表のある画面。ユーザーの操作をきっかけに処理が動く。業務システム向き。

GUIアプリで最も重要な考え方がイベント駆動（イベントドリブン）です。コンソールアプリは「上から下へ順番に実行して終わる」プログラムでしたが、GUIアプリには決まった実行順序がありません。かわりに、アプリは画面を表示したままユーザーが何か操作するのを待ち続け、「ボタンがクリックされた」「文字が入力された」といったイベント（出来事）が発生するたびに、それに対応する処理（イベントハンドラ）が実行されます。

flowchart TD A["アプリを起動"] --> B["画面を表示して待機"] B --> C{"ユーザーが操作"} C -->|ボタンをクリック| D["Clickイベント発生"] C -->|文字を入力| E["TextChangedイベント発生"] D --> F["対応するイベントハンドラが実行される"] E --> F F --> G["画面が更新される"] G --> B

図の説明: GUIアプリは起動後、画面を表示したままユーザーの操作を待ちます。ボタンのクリックなど「イベント」が発生するたびに対応する処理（イベントハンドラ）が実行され、画面が更新されてまた待機状態に戻ります。この繰り返しがGUIアプリの基本動作です。

用語: コントロール

Windows Forms では、ボタンや入力欄、ラベルといった画面の部品をコントロールと呼びます。フォーム（ウィンドウ）の上にコントロールを配置し、それぞれに動作（イベントハンドラ）を書いていくのがWindows Formsアプリ作成の基本の流れです。

13.2 プロジェクトを作る

Windows Forms アプリは、コンソールアプリとは別のプロジェクトの種類として作成します。Visual Studio を起動し、次の手順でプロジェクトを作りましょう。

  • スタート画面で「新しいプロジェクトの作成」をクリック
  • 言語のドロップダウンで「Visual Basic」を選び、一覧から「Windows フォーム アプリ」を選んで［次へ］
  • プロジェクト名に TaxCalcApp と入力して［次へ］
  • フレームワークで「.NET 8.0（長期的なサポート）」を選び［作成］

注意: テンプレートが見当たらないとき

「Windows フォーム アプリ」が一覧に出てこない場合、第1章でインストールした「.NET デスクトップ開発」ワークロードが入っていない可能性があります。Visual Studio Installer を起動し［変更］から追加してください。また、Windows Forms はWindows専用のしくみのため、macOSやLinuxでは利用できません。

プロジェクトを作成すると、コンソールアプリのときとは違うファイルが生成されます。それぞれの役割を確認しましょう。

ファイル 役割
Form1.vb 自分でコードを書くファイル。イベントハンドラなど、アプリの動作をここに記述します。
Form1.Designer.vb フォームデザイナーで配置したコントロールの情報が自動生成されるファイル。基本的に手で編集しません。
ApplicationEvents.vb アプリ全体の起動時・終了時などのイベントを書くファイル（「アプリケーション フレームワーク」のしくみの一部）。

起動時に最初に表示するフォームは、コードではなくプロジェクトのプロパティ画面で指定します。ソリューションエクスプローラーでプロジェクトを右クリックして「プロパティ」を開き、「アプリケーション」タブの「スタートアップフォーム」で選びます。新規作成直後は自動的に Form1 が設定されています。

用語: VBには Program.vb がない

C# の Windows フォーム アプリでは Program.cs に Application.Run(new Form1()) という起動コードが生成され、これがアプリの起動口になります。VB.NET では既定で「アプリケーション フレームワーク」というしくみがこの起動処理を肩代わりしてくれるため、Program.vb は生成されません。起動時にどのフォームを表示するかは、コードを書くのではなく上記のプロジェクトのプロパティ画面で指定します。

プロジェクトを作成すると、Visual Studio の画面に「フォームデザイナー」という真っ白なウィンドウの絵が表示されます。これが実際に作る画面のプレビューです。あわせて、次の3つの領域を確認しておきましょう。

フォームデザイナー

実際に作る画面そのもの。ここにコントロールをドラッグ＆ドロップして配置します。

ツールボックス

画面左に隠れているパネル。配置できるコントロールの部品一覧が並んでいます。

プロパティウィンドウ

画面右下。選んだコントロールのNameやTextなどの設定を変更します。

13.3 コントロールを配置する

ツールボックスから代表的なコントロールを確認しましょう。まずはよく使うものだけ覚えれば十分です。

コントロール 用途
Label 文字を表示するだけの部品。項目名や結果の表示に使う。
TextBox ユーザーが文字を入力できる欄。
Button クリックされると処理を実行するボタン。
ListBox 複数の項目を一覧で表示・選択できる箱。
ComboBox ドロップダウンで1つ選ぶ入力欄。
CheckBox オン／オフを選ぶチェック欄。複数選択が可能。
RadioButton 複数の選択肢から1つだけ選ぶボタン。
DataGridView 表形式で複数行のデータを一覧表示・編集できる部品。

コントロールはツールボックスからフォームデザイナー上へドラッグ＆ドロップして配置します。配置したら、プロパティウィンドウで少なくとも2つの項目を設定します。

  • Name — コードの中でそのコントロールを指す名前。あとから txtPrice.Text のように使います。
  • Text — 画面上に表示される文字。ボタンのラベルやラベルの文言はここで設定します。

Name は既定では Button1 のような連番になっており、コードから読んでも何のボタンか分かりません。次のような接頭辞（プレフィックス）付きの命名規則で分かりやすくするのが一般的です。

コントロール 接頭辞 命名例
Label lbl lblResult
TextBox txt txtPrice
Button btn btnCalc
ListBox lst lstHistory

Form1（フォームデザイナーのイメージ）

btnCalc（計算する）

13.4 イベントハンドラを書く

コントロールを配置しただけでは、ボタンを押しても何も起こりません。フォームデザイナー上でボタンをダブルクリックすると、Form1.vb が開き、次のようなコードが自動的に生成されます。

Form1.vb クラスの定義 
Private Sub btnCalc_Click(sender As Object, e As EventArgs) _
    Handles btnCalc.Click

    ' ここに処理を書く

End Sub

この1行の意味を分解して理解しましょう。

  • sender As Object — このイベントを発生させたコントロール自身（今回は btnCalc）が渡されてくる引数。
  • e As EventArgs — イベントに関する追加情報が入る引数。
  • Handles btnCalc.Click — 「このSubは btnCalc の Click イベントに対応する」という宣言。VB.NET 独自の書き方で、C#の += によるイベント登録と同じ役割を果たします。

次に、この中に処理を書きます。ポイントは、TextBox.Text が常に文字列（String型）であることです。計算に使うには、第2章で学んだ Integer.TryParse や Decimal.TryParse で数値に変換する必要があります。

Form1.vb クラスの定義 
Private Sub btnCalc_Click(sender As Object, e As EventArgs) _
    Handles btnCalc.Click

    Dim price As Decimal
    ' TextBox.Textは文字列なので数値に変換する
    If Decimal.TryParse(txtPrice.Text, price) Then
        Dim taxIncluded As Decimal = price * 1.1D
        ' 計算結果をLabelに表示する
        lblResult.Text = $"税込金額: {taxIncluded:C0}"
    Else
        MessageBox.Show("単価は数値で入力してください。")
    End If
End Sub

MessageBox.Show(...) は、ユーザーに知らせたいメッセージをポップアップの確認ダイアログで表示する命令です。入力ミスの警告や、処理完了の通知によく使います。

また、フォームが最初に表示されたときに一度だけ実行されるLoad イベントもよく使います。フォームの余白部分をダブルクリックすると生成され、初期表示（プレースホルダーの設定など）に利用します。

Form1.vb クラスの定義 
Private Sub Form1_Load(sender As Object, e As EventArgs) _
    Handles MyBase.Load

    ' フォーム表示時に結果欄を空にしておく
    lblResult.Text = ""
End Sub

用語: イベントハンドラ

特定のイベント（クリックや読み込みなど）が発生したときに実行されるSubプロシージャ（第7章）のことをイベントハンドラと呼びます。「〇〇イベントを処理する係」というイメージで捉えると分かりやすいです。

13.5 実践: 消費税計算アプリを作る

これまでの内容を組み合わせて、実用的な消費税計算アプリを完成させましょう。単価と個数を入力すると、税込金額を計算して表示します。入力チェック（未入力・数値以外）も加え、より丁寧なアプリにします。

配置するコントロール

  • txtPrice（TextBox）— 単価の入力欄
  • txtQuantity（TextBox）— 個数の入力欄
  • btnCalc（Button）— 計算ボタン（Textを「計算する」に設定）
  • lblResult（Label）— 結果を表示するラベル
Form1.vb 完全なプログラム 
Public Class Form1
    Private Sub btnCalc_Click(sender As Object, e As EventArgs) _
        Handles btnCalc.Click
        Dim price As Decimal
        Dim quantity As Integer
        ' 単価・個数のどちらかが不正なら中断する
        If Not Decimal.TryParse(txtPrice.Text, price) OrElse
           Not Integer.TryParse(txtQuantity.Text, quantity) Then
            MessageBox.Show("単価と個数を正しい数値で入力してください。")
            Return
        End If
        Dim total As Decimal = price * quantity * 1.1D
        lblResult.Text = $"税込金額: {total:C0}"
    End Sub
End Class

Return だけを書くと、それ以降の処理を行わずに Sub を終了できます（第7章参照）。チェックに失敗した時点で計算に進まないようにする、よく使うテクニックです。

発展: 計算履歴をListBoxに残す

lstHistory（ListBox）を追加すれば、計算するたびに履歴を積み上げて表示できます。Items.Add でリストに項目を1つ追加します。

Form1.vb 既存コードへの追記 
' lblResult.Text = ... の直後に追記する
lstHistory.Items.Add(
    $"単価{price:C0} × {quantity}個 → {total:C0}")

動作確認ポイント

  • 単価「100」・個数「3」で計算すると、税込金額が「￥330」と表示される
  • 単価を空欄のまま計算すると、警告のメッセージボックスが表示される
  • 単価に「abc」など文字を入れると、正しく警告されて計算が実行されない

注意: つまずきやすいポイント

  • プロパティウィンドウでコントロールの Name をあとから変更すると、すでに書いたイベントハンドラの Handles 句と名前がずれてしまい、コンパイルエラーになります。名前は配置直後に決めておきましょう。
  • TextBox.Text は必ず文字列型です。数値として使うときは毎回 TryParse などで変換する必要があります。
  • Windows Forms はWindows専用のしくみです。macOSやLinuxで動かすWebアプリを作る場合は、別のしくみ（ASP.NET Coreなど）を使います。

重要ポイント

Windows Forms アプリの基本は、「コントロールを配置する」「Nameを分かりやすく設定する」「イベントハンドラに処理を書く」の3ステップの繰り返しです。ここまで学んだ変数・条件分岐・プロシージャの知識がそのまま活きることに気づいたはずです。GUIは特別なものではなく、これまで学んだ文法をイベントというきっかけで動かすしくみなのです。

やってみよう 13-1: 名簿アプリを作ろう

名前を入力して ListBox に追加・削除できる、簡単な名簿アプリを作ってみましょう。第12章のファイル保存と組み合わせれば、名簿を .txt ファイルに残す発展課題にも挑戦できます。

手順

  • 1 フォームに txtName（TextBox）・btnAdd（「追加」ボタン）・btnRemove（「削除」ボタン）・lstNames（ListBox）を配置する。
  • 2 btnAdd をダブルクリックしてイベントハンドラを生成し、txtName.Text が空でなければ lstNames.Items.Add(...) で追加する。
  • 3 btnRemove では、lstNames.SelectedIndex が -1 でない（何か選ばれている）ことを確認してから lstNames.Items.RemoveAt(...) で削除する。
  • 4 発展: 第12章の File.WriteAllLines を使い、アプリ終了時に名簿を meibo.txt に保存する処理を追加してみる。

解答例（追加ボタン）

Private Sub btnAdd_Click(sender As Object, e As EventArgs) _
    Handles btnAdd.Click

    If String.IsNullOrWhiteSpace(txtName.Text) Then
        MessageBox.Show("名前を入力してください。")
        Return
    End If
    lstNames.Items.Add(txtName.Text)
    txtName.Text = ""
End Sub

解答例（削除ボタン）

Private Sub btnRemove_Click(sender As Object, e As EventArgs) _
    Handles btnRemove.Click

    If lstNames.SelectedIndex = -1 Then
        MessageBox.Show("削除する項目を選択してください。")
        Return
    End If
    lstNames.Items.RemoveAt(lstNames.SelectedIndex)
End Sub

理解度確認クイズ

  • Q1. コンソールアプリとGUIアプリでは、処理が実行されるタイミングの考え方がどう違いますか？

    回答を表示

    コンソールアプリは Sub Main の中身が上から順番に1本道で実行されます。一方GUIアプリは「イベント駆動」であり、画面を表示したままユーザーの操作（クリックなど）を待ち、イベントが発生するたびに対応するイベントハンドラが実行されます。決まった実行順序はありません。

  • Q2. Button をダブルクリックすると生成される Handles btnCalc.Click の役割は何ですか？

    回答を表示

    「このSubプロシージャは btnCalc の Click イベントに対応する処理である」ということを宣言しています。これにより、btnCalc がクリックされたときにこのSubが自動的に呼び出されます。

  • Q3. TextBox に入力された「100」という値を計算に使うとき、そのまま + や * で計算してはいけないのはなぜですか？

    回答を表示

    TextBox.Text は常に文字列（String型）だからです。数値として計算するには、Decimal.TryParse や Integer.TryParse であらかじめ数値型に変換する必要があります（変換できなければ入力ミスとして警告できます）。

  • Q4. コントロールの Name プロパティを配置後にうかつに変更すると、どのような問題が起こりますか？

    回答を表示

    すでに書いたイベントハンドラの Handles 句が、変更前の古い名前を参照したままになりコンパイルエラーになります。Name はコントロールを配置した直後、コードを書き始める前に決めておくのが安全です。
