データベースとつなぐ - ADO.NET入門と次のステップ

いよいよ最終章です。第12章ではファイルにデータを保存しましたが、業務システムではデータベースを使うのが基本です。この章では、データベースの基本用語とSQL、そしてVB.NETからデータベースを操作する仕組み「ADO.NET」を学びます。最後に全14章の学習を振り返り、次に進むべき道を案内します。

この章で学ぶこと

14.1 データベースとは

第12章では、データを .txt や .csv のファイルに保存する方法を学びました。しかし、業務システムのように複数の人が同時にデータを使う場面では、ファイル保存には次のような限界があります。

同時アクセスに弱い

複数人が同じファイルを同時に書き換えると、内容が壊れたり片方の更新が消えたりします。

検索・集計が遅い

データ件数が増えると、ファイルを全件読み込んで探す方法では処理に時間がかかります。

整合性を保ちにくい

在庫数のマイナス防止など、データのルールをファイル自体に持たせることができません。

こうした問題を解決するのがデータベース（DB）です。データベースは、大量のデータを整理して保存し、複数人からの同時アクセスや検索・集計を高速かつ安全に扱える専用の仕組みです。データベースを管理するソフトウェアをDBMS（データベース管理システム）と呼び、SQL Server・SQLite・MySQL・PostgreSQL などが代表例です。学習用には、無償で手軽に使える SQL Server Express または、ファイル1つで動く SQLite がおすすめです。

データベースの基本用語

リレーショナルデータベース（表形式のデータベース）では、Excelの表に似た形でデータを管理します。用語を対応づけて覚えておきましょう。

用語 意味 Excelでいうと
テーブル（表） 同じ種類のデータをまとめる入れ物 シート1枚
行（レコード） 1件分のデータ 1行
列（カラム） データの項目 1列（見出し）
主キー 行を一意に識別するための項目（重複・空を許さない） 連番のID列

たとえば「商品」テーブルは、次のようなイメージです。商品IDが主キーで、他の行と重複しない値になっています。

商品ID（主キー） 商品名 価格 在庫数
1 ノートPC 98000 12
2 マウス 1980 50

用語: リレーショナルデータベース（RDB）

複数のテーブルを主キーなどで関連づけて管理するデータベースをRDBと呼びます。SQL Server・MySQL・PostgreSQL・SQLite はすべてRDBです。テーブル同士の関連づけの詳細は本ガイドの範囲外ですが、業務システムでは「商品テーブル」と「注文テーブル」のように複数テーブルを組み合わせて使うのが一般的です。

14.2 SQLの基本

データベースに「データをちょうだい」「このデータを追加して」と命令するための、ほぼすべてのDBMSで共通に使える言語が SQL（エスキューエル）です。VB.NETからデータベースを操作するときも、最終的にはSQL文を組み立てて送信します。ここでは代表的な4つの命令を最小限の例で確認します。

以降の例で使う Products テーブルは、次のSQLで作成できます。お使いの環境で実際に試してみたい場合は、SQL Server Management Studio などでこのSQLを一度実行しておきましょう。

SQL — Productsテーブルの作成とサンプルデータ 
-- 商品テーブルを作成する
CREATE TABLE Products (
    ProductId INT IDENTITY(1,1) PRIMARY KEY,
    ProductName NVARCHAR(50) NOT NULL,
    Price INT NOT NULL,
    Stock INT NOT NULL
);

-- サンプルデータを3件投入する
INSERT INTO Products (ProductName, Price, Stock) VALUES
    (N'ノートPC', 98000, 12),
    (N'マウス', 1980, 50),
    (N'キーボード', 3500, 20);

SELECT: データを取り出す

SQL — 商品を検索する 
-- Products テーブルから全件を取得
SELECT * FROM Products;

-- 価格が2000円未満の商品だけを、価格の安い順に取得
SELECT ProductName, Price FROM Products
WHERE Price < 2000
ORDER BY Price ASC;

INSERT: データを追加する

SQL — 商品を1件追加する 
INSERT INTO Products (ProductName, Price, Stock)
VALUES ('キーボード', 3500, 20);

UPDATE: データを更新する

SQL — 在庫数を更新する 
UPDATE Products
SET Stock = 15
WHERE ProductId = 1;

DELETE: データを削除する

SQL — 商品を1件削除する 
DELETE FROM Products
WHERE ProductId = 2;

注意: WHERE を忘れずに

UPDATE や DELETE で WHERE を書き忘れると、テーブルの全行が更新・削除されてしまいます。特に DELETE FROM Products; のように条件なしで実行すると、全商品データが一瞬で消えます。実行前に必ず条件を確認する習慣をつけましょう。

14.3 ADO.NETの仕組み

VB.NETからデータベースを操作するための仕組みが ADO.NETです。SQLの命令文そのものは14.2で見た通りですが、それを「誰が」「どうやって」データベースに送るかを、次の3つの役割に分けて考えます。

役割 クラス名 やること
接続 SqlConnection データベースにつなぐ・切る
命令 SqlCommand 実行するSQL文を持たせて送る
結果の読み取り SqlDataReader SELECTの結果を1行ずつ読む
flowchart LR A["VB.NETアプリ"] --> B["Connection
（接続する）"] B --> C["Command
（SQLを送る）"] C --> D[("データベース")] D --> E["DataReader
（結果を1行ずつ読む）"] E --> A

図の説明: アプリはまず Connection でデータベースにつなぎ、Command にSQL文を持たせて送信します。データベースが処理した結果は DataReader で1行ずつ受け取り、アプリに戻ってきます。

SQL Serverを使う場合、コードの先頭で次の名前空間を読み込みます。

名前空間の読み込み 
' SQL Server用のADO.NETクラス群を読み込む
Imports Microsoft.Data.SqlClient

Microsoft.Data.SqlClient は標準では使えないため、あらかじめNuGet（VB.NETのライブラリ配布の仕組み）でパッケージを追加しておく必要があります。Visual Studio の「ソリューションエクスプローラー」からプロジェクトを右クリックし、「NuGetパッケージの管理」で Microsoft.Data.SqlClient を検索してインストールします（SQLiteを使う場合は Microsoft.Data.Sqlite を追加します）。

接続には、どのサーバーの・どのデータベースに・どんな方法でログインするかを1本の文字列にまとめた接続文字列を使います。

接続文字列の例（Windows認証） 
' サーバー名、対象データベース名、Windows認証を使うことを指定
Dim connectionString As String =
    "Server=localhost\SQLEXPRESS;Database=ShopDB;Trusted_Connection=True;TrustServerCertificate=True;"

注意: TrustServerCertificate=Trueは学習用の設定

近年の Microsoft.Data.SqlClient は既定で通信の暗号化が有効になっており、ローカルのSQL Server Expressが持つ自己署名証明書は正式な認証局が発行したものではないため、TrustServerCertificate=True を付けないと「証明書チェーンが信頼されていない機関により発行されました」というエラーで接続に必ず失敗します。TrustServerCertificate=True はサーバー証明書の検証を省略する設定であり、学習用のローカル環境に限って使うものです。本番環境では正式な証明書を用意し、この設定を省略しないようにしてください。

用語: Windows認証とSQL Server認証

Windows認証は、今Windowsにログインしているユーザーの権限でそのままデータベースに接続する方式です（Trusted_Connection=True）。一方SQL Server認証はユーザーIDとパスワードを別途指定する方式です。学習用途では、パスワード管理が不要なWindows認証が手軽です。

14.4 データを読み書きする

接続・命令・結果読み取りの3つを組み合わせて、実際にデータを読み書きしてみましょう。第12章で学んだ Using（自動的に後片付けをする構文）と、第11章の Try ... Catch（例外処理）を組み合わせて使います。

データを読み取る（SELECT）

Program.vb Sub Main内に記述 
Dim sql As String = "SELECT ProductName, Price FROM Products"

Try
    ' Using で Connection と Command を確実に後片付けする
    Using conn As New SqlConnection(connectionString)
        conn.Open()
        Using cmd As New SqlCommand(sql, conn)
            ' ExecuteReaderは1行ずつ結果を返すDataReaderを作る
            Using reader As SqlDataReader = cmd.ExecuteReader()
                While reader.Read()
                    Dim name As String = reader.GetString(0)
                    Dim price As Integer = reader.GetInt32(1)
                    Console.WriteLine($"{name}: {price}円")
                End While
            End Using
        End Using
    End Using
Catch ex As SqlException
    Console.WriteLine("データベースエラー: " & ex.Message)
End Try

処理の流れは、①conn.Open() で接続を開く → ②SqlCommand にSQL文と接続を渡す → ③ExecuteReader() を呼ぶと SqlDataReader が返る → ④reader.Read() をWhileループで呼ぶたびに1行ずつ読み進む、という順番です。reader.GetString(0) や GetInt32(1) は「何列目の値を、どの型として取り出すか」を指定しています。列の順番はSQL文の SELECT で書いた順です。

データを書き込む（INSERT / UPDATE / DELETE）

結果の行を返さない命令（追加・更新・削除）は ExecuteReader() ではなく ExecuteNonQuery() を使います。戻り値は「影響を受けた行数」です。

Program.vb Sub Main内に記述 
Dim sql As String =
    "UPDATE Products SET Stock = 15 WHERE ProductId = 1"

Using conn As New SqlConnection(connectionString)
    conn.Open()
    Using cmd As New SqlCommand(sql, conn)
        ' 戻り値は更新された行数
        Dim affected As Integer = cmd.ExecuteNonQuery()
        Console.WriteLine($"{affected}件を更新しました")
    End Using
End Using

用語: 型変換に注意

DataReader から値を取り出すときは、列の実際のデータ型に合わせて GetString／GetInt32／GetDateTime などを使い分けます。型が一致しないと実行時エラーになるため、テーブル設計（列の型）を事前に確認しておきましょう。NULL値が入る可能性がある列では reader.IsDBNull(列番号) で事前チェックするのが安全です。

14.5 安全なデータベース操作（重要）

画面から入力された文字列を、そのまま文字列連結でSQL文に組み込むのは絶対に避けてください。次の例を見てみましょう。

危険な書き方（悪い例） 
' 悪い例: テキストボックスの内容をそのまま連結している
Dim keyword As String = txtKeyword.Text
Dim sql As String = "SELECT * FROM Products WHERE ProductName = '" & keyword & "'"

この書き方では、txtKeyword.Text にSQLの一部として意味を持つ記号（シングルクォート ' など）を入力されると、組み立てられるSQL文の意味そのものが変わってしまう可能性があります。想定外の条件でデータが取得・変更されてしまう、この種の攻撃をSQLインジェクションと呼びます。業務システムの入力欄は不特定多数のユーザーが操作するため、この危険を必ず対策しなければなりません。

注意: 文字列連結でSQLを組み立てない

入力値をそのまま & でSQL文に連結する書き方は、初心者が最も陥りやすい落とし穴です。「動くから大丈夫」ではなく、「入力値は必ずパラメータとして渡す」というルールを最初から習慣にしましょう。

対策はパラメータ化クエリです。SQL文の中に値を直接書かず、@名前 というプレースホルダー（仮の場所）を置き、実際の値は Parameters 経由で別に渡します。こうすることで、渡した値は常に「ただのデータ」として扱われ、SQL文の意味を変えることができなくなります。

Program.vb Sub Main内に記述 
' 良い例: プレースホルダーとParametersを使う
Dim keyword As String = txtKeyword.Text
Dim sql As String = "SELECT * FROM Products WHERE ProductName = @name"

Using conn As New SqlConnection(connectionString)
    conn.Open()
    Using cmd As New SqlCommand(sql, conn)
        ' @name には常にただの「値」として渡される
        cmd.Parameters.AddWithValue("@name", keyword)
        Using reader As SqlDataReader = cmd.ExecuteReader()
            While reader.Read()
                Console.WriteLine(reader.GetString(0))
            End While
        End Using
    End Using
End Using

重要ポイント

データベース操作の3原則: ①入力値は必ずパラメータ化クエリで渡す、②接続は必ず Using で確実に閉じる、③ Try ... Catch で例外に備える。この3つを守れば、多くの実務的なデータベース操作は安全に書けます。

注意: 接続文字列にパスワードを直接書かない

コードの中に Password=... を直接書いてしまうと、ソースコードを見た人にパスワードが漏れます。可能な限りWindows認証を使うか、設定ファイル（appsettings.json など）や環境変数にパスワードを分離し、Gitなどのバージョン管理には含めないようにしましょう。

やってみよう 14-1: 商品検索プログラムを作ろう

Productsテーブルから、キーワードを含む商品名を検索して一覧表示するコンソールプログラムを作ってみましょう（データベース環境がない場合は、コードの読み方を確認するだけでも学習になります）。

手順

  • 1 NuGetで Microsoft.Data.SqlClient を追加し、接続文字列を用意する。
  • 2 Console.ReadLine() で検索キーワードを入力してもらう。
  • 3 LIKE 演算子とパラメータ化クエリを使って、部分一致検索のSQLを組み立てる。
  • 4 ヒットした商品名と価格を1行ずつ表示し、最後に「◯件見つかりました」と件数も表示する。

解答例

Console.Write("検索キーワード: ")
Dim keyword As String = Console.ReadLine()
Dim sql As String =
    "SELECT ProductName, Price FROM Products WHERE ProductName LIKE @kw"
Dim count As Integer = 0

Try
    Using conn As New SqlConnection(connectionString)
        conn.Open()
        Using cmd As New SqlCommand(sql, conn)
            ' 部分一致のため前後に%を付けてパラメータで渡す
            cmd.Parameters.AddWithValue("@kw", $"%{keyword}%")
            Using reader As SqlDataReader = cmd.ExecuteReader()
                While reader.Read()
                    Console.WriteLine($"{reader.GetString(0)}: {reader.GetInt32(1)}円")
                    count += 1
                End While
            End Using
        End Using
    End Using
    Console.WriteLine($"{count}件見つかりました")
Catch ex As SqlException
    Console.WriteLine("データベースエラー: " & ex.Message)
End Try

理解度確認クイズ

  • Q1. データベースのテーブルにおいて、行を一意に識別するための項目を何と呼びますか？

    回答を表示

    主キーです。テーブル内の行を一意に識別するための項目で、重複や空を許しません。

  • Q2. ADO.NETにおいて、SELECTの結果を1行ずつ読み取るためのクラスは何ですか？

    回答を表示

    SqlDataReader です。cmd.ExecuteReader() で取得し、reader.Read() をWhileループで呼ぶことで1行ずつ結果を読み進めます。

  • Q3. INSERT・UPDATE・DELETEのように結果の行を返さない命令を実行するメソッドは何ですか？

    回答を表示

    ExecuteNonQuery() です。戻り値として、更新・追加・削除された行数（Integer）が返されます。

  • Q4. 入力値を文字列連結でSQL文に組み込むことの危険性を何と呼びますか？ また、その対策として使うべき仕組みは何ですか？

    回答を表示

    SQLインジェクションと呼びます。対策としては、SQL文にプレースホルダー（@name など）を置き、cmd.Parameters.AddWithValue(...) で値を渡すパラメータ化クエリを必ず使います。
