エラーと上手に付き合おう（例外処理）

プログラムを書いていると、エラーは必ず出会います。この章では、エラーメッセージ（トレースバック）の読み方を身につけ、よく出会うエラーの種類を知り、try・except でエラーが起きても止まらないプログラムを作れるようになります。「エラーは敵ではなく、直し方を教えてくれるヒント」という見方に変えていきましょう。

この章で学ぶこと

  • 構文エラー（SyntaxError）と例外（実行時エラー）の違いを説明できる
  • トレースバックを下から読み、ファイル名・行番号・エラー種類を読み取れる
  • 代表的な例外の種類と、それぞれの典型的な原因が分かる
  • try・except・else・finally を使い、エラーが起きても止まらないプログラムを書ける

11.1 構文エラーと例外の違い

第3章で「わざとエラーを起こす」練習をしたことを覚えているでしょうか。Python のエラーは大きく2種類に分けられます。構文エラー（SyntaxError）は、Python の文法ルールに反した書き方をしたときに起こります。かっこの閉じ忘れやコロンの書き忘れなど、プログラムを実行する前の段階で見つかるエラーです。

もう1つが例外（Exception）です。文法としては正しく書けているのに、実行している途中で問題が起きて止まってしまうエラーです。たとえば「存在しないファイルを開こうとした」「文字列を数値として計算しようとした」「0で割り算しようとした」などは、文法上は問題がなくても実行時に失敗します。この章では主にこの「例外」の扱い方を学びます。

flowchart LR A["コードを書く"] --> B{"文法は正しい？"} B -->|いいえ| C["SyntaxError
実行前に停止"] B -->|はい| D["実行開始"] D --> E{"実行中に問題発生？"} E -->|はい| F["例外が発生
（NameError など）"] E -->|いいえ| G["最後まで実行できる"]

用語: 「エラー」と「例外」

日常会話では「エラー」とひとまとめに呼びますが、Python の用語では実行時に起きる問題を例外（Exception）と呼びます。本章のタイトルにある「例外処理」は、この実行時の問題に対処する方法のことです。

11.2 トレースバックの読み方

例外が発生してプログラムが止まると、Python はトレースバックと呼ばれるエラー情報をまとめて表示します。長い英文が出ると身構えてしまいますが、読む順番さえ知っていれば怖くありません。次のコードを実行してみましょう。

kakeibo_check.py 
# 支出記録を1件表示する
record = {"date": "2026-04-01", "category": "食費", "amount": 850}

# amonut は amount のタイプミス
print("金額:", record["amonut"])
実行結果 
Traceback (most recent call last):
  File "kakeibo_check.py", line 5, in <module>
    print("金額:", record["amonut"])
                   ~~~~~~^^^^^^^^^^
KeyError: 'amonut'

トレースバックは下から順番に読むのが基本です。一番下の行が「結論」、その上が「どこで起きたか」の詳細です。

読む順番 表示内容 この例での意味
① 最終行 エラー種類: メッセージ KeyError: 'amonut' — 「amonut というキーが無い」
② File 行 ファイル名と行番号 line 5 — 5行目で起きた
③ コード行 問題が起きた行そのもの どの式で失敗したかが分かる

つまりこのエラーは「5行目の record["amonut"] で、'amonut' というキーが辞書に無かった」ことを教えてくれています。実際には amount のタイプミスが原因でした。エラーが出たら、まず最終行のエラー種類を確認し、次に行番号を見て該当箇所を探す、という順番で読むと迷いません。

11.3 代表的なエラーの種類

これまでの章でも似たエラーに何度か出会ってきました。ここで代表的なものを一覧にして整理しておきましょう。エラー種類の名前を見た瞬間に「原因の見当がつく」ようになると、修正がぐっと速くなります。

エラー種類 分類 典型的な原因
SyntaxError 構文エラー かっこ・コロンの書き忘れ、スペルミス
IndentationError 構文エラー インデント（字下げ）のずれ・タブとスペースの混在
NameError 例外 変数名・関数名のタイプミス、定義前の使用
TypeError 例外 型の異なる値同士の演算（文字列と数値の足し算など）
ValueError 例外 int("abc") のように、型は合っているが値が変換できない
ZeroDivisionError 例外 0で割り算した
IndexError 例外 リストの範囲外のインデックスを指定した
KeyError 例外 辞書に存在しないキーを指定した
FileNotFoundError 例外 開こうとしたファイルが存在しない・パスが間違っている

SyntaxError と IndentationError は実行前に見つかる構文エラー、それ以外は実行中に発生する例外です。第12章で扱うファイル操作では FileNotFoundError に、第9章で扱った辞書では KeyError によく出会います。

重要ポイント

エラー種類の名前は、原因を探すための重要な手がかりです。エラーメッセージが出たら、まず種類の名前で「何が問題なのか」の見当をつけ、それから行番号を見て具体的な箇所を確認する、という2段階で考えると効率的です。

11.4 try・except・else・finally で例外に対処する

例外が起きてもプログラムを止めずに続けたいときは、try 文を使います。「try の中を試してみて、もし例外が起きたら except の中を実行する」という仕組みです。第4章で扱った input() と int() の組み合わせを、例外処理で安全にしてみましょう。

try_basic.py 
text = input("金額を入力してください: ")

try:
    # ここで例外が起きるかもしれない処理を試す
    amount = int(text)
except ValueError:
    # ValueError が起きたときだけここを実行する
    print("数値として認識できませんでした")
else:
    # 例外が起きなかったときだけここを実行する
    print("入力された金額:", amount)
finally:
    # 例外の有無にかかわらず必ず実行する
    print("入力の確認を終了します")

except ValueError: のように、対処したい例外の種類を指定できます。種類を指定しておくと、想定していた例外だけを捕まえて処理し、想定外の例外はそのままエラーとして表示できます。else は「例外が起きなかったときだけ」、finally は「結果にかかわらず必ず」実行される点を覚えておきましょう。

入力が正しくなるまで何度も聞き直したい場合は、while True（第7章）と組み合わせます。

retry_input.py 
def read_amount():
    """正しい数値が入力されるまで聞き直し、金額を返す"""
    while True:
        text = input("金額を入力してください: ")
        try:
            amount = int(text)
        except ValueError:
            print("数字だけで入力してください")
            continue  # 先頭に戻ってもう一度聞く
        return amount

最後に、自分で意図的に例外を発生させる raise も紹介します。関数の中で「この値は不正だ」と判断したときに使います。

raise_sample.py 
def set_amount(amount):
    # 支出の金額はマイナスにできない
    if amount < 0:
        raise ValueError("金額はマイナスにできません")
    print("金額を記録しました:", amount)

set_amount(-500)  # ここで ValueError が発生する

注意: except を広げすぎない

except: だけを書く（例外の種類を指定しない）と、想定していないエラーまで飲み込んでしまい、不具合に気づきにくくなります。except ValueError: のように、対処したい例外の種類を具体的に指定する習慣をつけましょう。

やってみよう 11-1: 正しい数値が入力されるまで聞き直す関数

python-study/ch11/kakeibo_input.py を作成し、支出金額を安全に受け取る関数を作りましょう。

手順

  1. 1 本文の read_amount() をベースに、0未満の数値が入力されたら「マイナスの金額は入力できません」と表示してもう一度聞き直す処理を追加する。
  2. 2 わざと数字以外（例: 「abc」）を入力し、ValueError が捕まってやり直しになることを確認する。
  3. 3 正しい金額（0以上の数値）を入力すると、return で関数から値が返ってくることを print() で確認する。

この「入力を検証してから受け取る」関数は、第15〜16章の家計簿アプリで金額を入力する場面にそのまま使えます。

理解度確認クイズ

  1. Q1. 構文エラー（SyntaxError）と例外（Exception）の違いを説明してください。

    回答を表示

    構文エラーは Python の文法ルールに反した書き方をしたときに、実行前の段階で見つかるエラーです。例外は文法は正しいのに、実行している途中で問題が起きて発生するエラーです。

  2. Q2. トレースバックを読むとき、まずどの行を確認すればよいですか。

    回答を表示

    一番下の行です。「エラー種類: メッセージ」の形で結論が書かれています。そこから上に向かって、File 行でファイル名と行番号を確認します。

  3. Q3. try 文の else と finally は、それぞれどんなときに実行されますか。

    回答を表示

    else は try の中で例外が起きなかったときだけ実行されます。finally は例外が起きたかどうかにかかわらず、必ず最後に実行されます。
