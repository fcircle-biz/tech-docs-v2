クラスとオブジェクトの基礎

これまで、データはリストや辞書にまとめてきました。この章では「データ」と「そのデータを操作する処理」をひとつにまとめるクラスという仕組みを学びます。クラスは、次の第15〜16章で作る家計簿アプリを、もっと整理された形で組み立てるための土台になります。

この章で学ぶこと

  • クラスとオブジェクトの関係を「設計図」と「実物」のたとえで説明できる
  • class と __init__ で属性を持つオブジェクトを作れる
  • メソッドを定義し、オブジェクトから呼び出せる
  • 複数のオブジェクトをリストで管理でき、辞書とクラスの使い分けを判断できる

14.1 クラスとオブジェクト

「たい焼き」を思い浮かべてください。たい焼きを焼くには、まず型（設計図）が必要です。同じ型からは、あんこ味やカスタード味など、中身が違う何個ものたい焼き（実物）を焼くことができます。プログラミングにおけるクラスはこの「型」にあたり、クラスから作られた実物をオブジェクト（またはインスタンス）と呼びます。

クラスには、オブジェクトが持つデータ（属性）と、そのデータを使って行う処理（メソッド）をまとめて定義します。第9章の辞書でも「データをまとめる」ことはできましたが、クラスは「データ」と「そのデータ専用の処理」を1か所にまとめられる点が異なります。

flowchart LR A["クラス
（設計図）"] -->|"インスタンス化"| B["オブジェクト1
account_a"] A -->|"インスタンス化"| C["オブジェクト2
account_b"] B --- D["属性: 残高など
メソッド: 入金・出金"] C --- E["属性: 残高など
メソッド: 入金・出金"]

実は、これまで使ってきた str や list も、すべてクラスです。文字列に .upper() や .split() を呼び出せたのは、これらのメソッドが str クラスに定義されているからです。

check_type.py 
# 見慣れた値の正体はすべてクラスのオブジェクト
name = "python-study"
prices = [120, 980, 450]

print(type(name))    # str クラスのオブジェクト
print(type(prices))  # list クラスのオブジェクト
実行結果 
<class 'str'>
<class 'list'>

用語: 属性とメソッド

オブジェクトが持つ「データ」を属性（アトリビュート）、オブジェクトが持つ「処理」をメソッドと呼びます。属性は名詞（残高・名前など）、メソッドは動詞（入金する・表示する など）でイメージすると区別しやすいです。

14.2 class と __init__、属性、self の意味

クラスは class キーワードで定義します。オブジェクトを作るときに自動で呼ばれる特別なメソッドが __init__（イニット）です。「初期化（initialize）」の略で、オブジェクトが生まれた瞬間に、最初の属性を設定する役割を持ちます。

bank_account.py 
# 銀行口座を表すクラス
class BankAccount:
    """1人分の銀行口座を表すクラス"""

    def __init__(self, owner, balance):
        # self. を付けた変数が「属性」になる
        self.owner = owner
        self.balance = balance


# クラスからオブジェクト（インスタンス）を作る
account = BankAccount("山田太郎", 1000)
print(account.owner)    # 属性は「.」でアクセスする
print(account.balance)
実行結果 
山田太郎
1000

self は「これから作られる（または作られた）オブジェクト自身」を指す特別な引数です。self.owner = owner は「このオブジェクト自身の owner 属性に、渡された owner の値を保存する」という意味になります。self という名前は慣習であり、Python が予約語として強制しているわけではありませんが、必ずこの名前を使います。

class BankAccount:

「口座」という種類のオブジェクトを作るための設計図を定義する。

account = BankAccount(...)

設計図から実物（オブジェクト）を1つ作る。account が変数名。

よくある間違い: self を書き忘れる

def __init__(owner, balance): のように self を書き忘れると、Python は最初の引数 owner をオブジェクト自身だと解釈してしまい、想定と違う動作やエラーになります。メソッドの第一引数には必ず self を書きましょう。

14.3 メソッドの定義と呼び出し

属性を操作する処理はメソッドとして定義します。メソッドの書き方は関数（第10章）とほぼ同じですが、クラスの中に置き、第一引数に self を書く点が異なります。self を通して、自分自身の属性を読み書きします。

bank_account.py 
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):  # 入金: 自分自身の balance を書き換える
        self.balance += amount

    def show_balance(self):  # 表示: 他のメソッドが更新した値を読む
        print(f"{self.owner}さんの残高: {self.balance}円")

account = BankAccount("山田太郎", 1000)
account.deposit(500)      # account 自身に対して入金する
account.show_balance()
実行結果 
山田太郎さんの残高: 1500円

メソッドを呼び出すときは account.deposit(500) のように「オブジェクト.メソッド名(引数)」と書きます。self は Python が自動で渡してくれるため、呼び出し側では書きません。deposit の中で書き換えた self.balance の値が、show_balance でもそのまま読み取れている点に注目してください。同じオブジェクトの属性は、どのメソッドからも共有されています。

sequenceDiagram participant U as 呼び出し側 participant A as account（オブジェクト） U->>A: deposit(500) A->>A: self.balance += 500 U->>A: show_balance() A-->>U: 画面に表示「山田太郎さんの残高: 1500円」

出金を防ぐ条件も書ける

出金のメソッドでは、第6章で学んだ if 文を使って「残高が足りない場合は出金しない」といった条件を入れられます。次の実習で実際に作ってみましょう。

14.4 複数のオブジェクトを作る、リストで管理する、辞書との比較

同じクラスから、何個でもオブジェクトを作れます。それぞれのオブジェクトは別々の属性の値を持ち、互いに影響しません。第8章で学んだリストと組み合わせれば、複数の口座をまとめて管理できます。

multi_accounts.py 
# 14.3 の BankAccount クラスの下に続けて書く
# 複数の口座オブジェクトをリストで管理する
accounts = [
    BankAccount("山田太郎", 1000),
    BankAccount("佐藤花子", 3000),
]

accounts[0].deposit(500)  # 山田さんの口座だけが変化する

for account in accounts:
    account.show_balance()
実行結果 
山田太郎さんの残高: 1500円
佐藤花子さんの残高: 3000円

ここで気になるのは「第9章の辞書のリスト（{"owner": "山田太郎", "balance": 1000} のような形）でも同じことができたのでは？」という点です。どちらも使えますが、向き・不向きがあります。

観点 辞書のリスト クラス（オブジェクトのリスト）
データだけを持つ 得意。表形式のデータの読み書きに向く できるが少し大げさ
専用の処理をまとめたい 処理は別の関数として外に書く必要がある 得意。メソッドとしてデータのそばに置ける
入力ミスへの強さ キー名の打ち間違いに気づきにくい（KeyError） 属性名の打ち間違いはエディタが指摘しやすい
CSV との相性 DictReader/DictWriter（第12章）とそのまま相性が良い オブジェクトと辞書を変換する処理が必要

重要ポイント

「データの出し入れが中心」なら辞書（やそのリスト）、「データと専用の処理をセットで扱いたい」ならクラスが向いています。次の第15〜16章の家計簿アプリでは、支出の記録そのものはCSVとの相性を優先して辞書のリストのまま扱い、集計や保存の処理は関数としてまとめます。クラスは、アプリの規模がさらに大きくなったときの次のステップとして覚えておきましょう。

やってみよう 14-1: 銀行口座クラスを作る

bank.py を作成し、入金・出金・残高表示ができる BankAccount クラスを完成させましょう。出金は残高不足のときに失敗するようにします。

手順

  1. 1 __init__(self, owner, balance) で owner と balance を属性として保存する。
  2. 2 deposit(self, amount) を定義し、self.balance に amount を加算する。
  3. 3 withdraw(self, amount) を定義し、if amount > self.balance: のとき「残高不足です」と表示して何もしない。足りていれば self.balance から amount を引く。
  4. 4 show_balance(self) で f"{self.owner}さんの残高: {self.balance}円" を表示する。
  5. 5 口座を2つ作り、片方だけ入金・出金し、両方の残高を表示して、互いに影響しないことを確認する。残高を超える金額の出金も試す。

エラーなく動いたら、出金額に0や負の数を渡すとどうなるか試してみましょう。次章のアプリ作りに向けて「入力チェックの大切さ」を再確認できます。

理解度確認クイズ

  1. Q1. クラスとオブジェクト（インスタンス）の関係を、たい焼きのたとえで説明してください。

    回答を表示

    クラスは「たい焼きの型（設計図）」にあたり、オブジェクトはその型から実際に焼かれた「たい焼き（実物）」にあたります。同じ型（クラス）から、あんこ味・カスタード味のように中身（属性の値）が異なる複数のたい焼き（オブジェクト）を作れます。

  2. Q2. 次のコードの空欄（?）に入れるべきものは何ですか。def __init__(?, name):

    回答を表示

    self です。self は「作られたオブジェクト自身」を指す特別な第一引数で、メソッドの定義には必ず書きます。self を書き忘れると、渡した引数がずれて解釈され、意図しない動作になります。

  3. Q3. データの出し入れが中心の処理には辞書、データと専用の処理をセットで扱いたい場合にはクラスが向くと学びました。家計簿アプリの「1件の支出記録」をCSVで保存・読み込みする場合、なぜ辞書（のリスト）のほうが扱いやすいのですか。

    回答を表示

    第12章で学んだ csv.DictReader／DictWriter は、CSVの1行を辞書として直接読み書きできるため、変換の手間がありません。オブジェクトで管理する場合は、CSVの行とオブジェクトを相互に変換する処理を別途書く必要があり、単純なデータの出し入れには手間が増えてしまいます。
