プログラムの骨組み - 4つの部と桁のルール

COBOL のプログラムには、決まった「骨組み」と、行の何桁目から書くかという独特の「桁のルール」があります。この章では、4つの部（DIVISION）の役割と、固定形式の桁のルールを、たとえ話と図でていねいに学びます。ここを乗り越えれば、COBOL のソースコードが「どこに何が書いてあるか」見通せるようになります。

この章で学ぶこと

  • COBOL プログラムを構成する4つの部（DIVISION）の役割と書く順番を説明できる
  • 部・節・段落・文・句という階層と、ピリオドが「文の終わり」を表すことを説明できる
  • 固定形式の桁のルール（1〜6桁・7桁・A領域・B領域・73桁以降）に従ってコードを書ける
  • コメントの書き方と、見出し部・段落の基本的な書き方を身につける
  • 桁ずれが原因のコンパイルエラーを読み取って直せる

3.1 4つの部（DIVISION）- プログラムの大きな区分け

COBOL のプログラムは、部（ブ、DIVISION）と呼ばれる最大4つの大きな区分けで構成されます。しかも、書く順番が決まっています。料理のレシピにたとえると分かりやすくなります。

部（英語名）役割レシピでいうと
見出し部（IDENTIFICATION DIVISION）プログラムの名前など、「このプログラムは何者か」を書く料理名
環境部（ENVIRONMENT DIVISION）プログラムが動く環境や、使うファイルを書く使う道具（鍋・オーブン）
データ部（DATA DIVISION）プログラムが扱うデータの入れ物を定義する材料と分量
手続き部（PROCEDURE DIVISION）実際の処理の手順を書く作り方（手順）
flowchart LR A["1. 見出し部
IDENTIFICATION"] --> B["2. 環境部
ENVIRONMENT"] B --> C["3. データ部
DATA"] C --> D["4. 手続き部
PROCEDURE"]

図の説明: 4つの部は、この順番で書きます。順番を入れ替えることはできません。

4つの部をすべて書いた完全なプログラムを見てみましょう。2行目からが本体で、1行目の * で始まる行は、人間向けのメモ（コメント）です。

fourdiv.cob 完全なプログラム 
      * 4つの部をすべて書いたプログラム
       IDENTIFICATION DIVISION.
       PROGRAM-ID. FOURDIV.
       ENVIRONMENT DIVISION.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-ITEM-NAME    PIC X(10) VALUE "PEN".
       01  WS-PRICE        PIC 9(4)  VALUE 120.
       PROCEDURE DIVISION.
           DISPLAY "商品: " WS-ITEM-NAME.
           DISPLAY "単価: " WS-PRICE " 円".
           STOP RUN.
ターミナル コマンド 
cobc -x fourdiv.cob
./fourdiv
実行結果 実行結果 
商品: PEN       
単価: 0120 円

各部の中身を見ていきましょう。

  • 見出し部: PROGRAM-ID. FOURDIV. でプログラムの名前を付けています（必須）。
  • 環境部: ここでは中身が空です。ファイルを使うときに活躍します（第12章）。
  • データ部: WORKING-STORAGE SECTION.（作業場所節）の中で、商品名 WS-ITEM-NAME と単価 WS-PRICE という2つのデータの入れ物を用意しています。詳しくは第4章で学びます。
  • 手続き部: 画面に表示する DISPLAY と、終了の STOP RUN. が処理の手順です。

ヒント: 環境部とデータ部は省略できる

処理に必要なければ、環境部とデータ部は省略できます（第2章の hello.cob にも書いていませんでした）。ただし、見出し部と手続き部は、ほぼ必ず必要です。実際の業務プログラムでは4つとも書かれるのが普通なので、4つの部の全体像を頭に入れておきましょう。

ヒント: 表示された「0120」と「PEN」の後ろの空白

単価が 120 ではなく 0120 と表示されるのは、PIC 9(4)（数字4桁）の入れ物に入れたからです。また、商品名の後ろに空白が付くのは、PIC X(10)（文字10桁）の残りが空白で埋まるためです。どちらも第4章で詳しく扱います。

3.2 部・節・段落・文・句 - 本のような階層構造

COBOL のプログラムは、本のように「大きな区分け」から「小さな区分け」へと階層になっています。

COBOL の単位本にたとえると例
部（DIVISION）部DATA DIVISION.
節（SECTION）章WORKING-STORAGE SECTION.
段落（パラグラフ、PARAGRAPH）段落MAIN-PROC.
文（SENTENCE）文最後にピリオド . が付く、ひとまとまりの命令
命令文（STATEMENT）文の中の動詞DISPLAY ... や MOVE ...
句（CLAUSE / PHRASE）単語のまとまりPIC X(10) や VALUE "PEN"
flowchart TD A["プログラム"] --> B["部 DIVISION"] B --> C["節 SECTION"] C --> D["段落 PARAGRAPH"] D --> E["文 SENTENCE
ピリオドで終わる"] E --> F["命令文 STATEMENT"] F --> G["句 CLAUSE ／ PHRASE"]

図の説明: 大きな単位ほど上にあります。手続き部では「段落 → 文 → 命令文」、データ部では「節 → データ項目 → 句」という形で使われます。

重要ポイント: ピリオドは「文の終わり」

COBOL では、ピリオド（.）が「ここで文が終わり」の合図です。他の言語の「改行」や「;（セミコロン）」にあたります。見た目は小さな点ですが、付け忘れると次の行とつながってしまい、思わぬエラーになります。この章から第6章までは、命令文1つごとにピリオドを付けて書きます。第7章で、IF などの END-xxx（スコープ終了符）で閉じる文の内側にはピリオドを書かない書き方を学びます。

ピリオドが文の区切りであることを、実際に確かめてみましょう。次のプログラムの DISPLAY "A" DISPLAY "B". は、1つの文の中に命令文が2つ入っています。

period1.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PERIOD1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-PRICE        PIC 9(4) VALUE 120.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 命令文2つを、ピリオド1つで1つの文にする
           DISPLAY "A" DISPLAY "B".
           DISPLAY "単価は " WS-PRICE.
           STOP RUN.
ターミナル コマンド 
cobc -x period1.cob
./period1
実行結果 実行結果 
A
B
単価は 0120

改行して書いても、ピリオドがなければ文は続いています。読みやすさのため、本ガイドでは原則として1行に1つの命令文を書き、ピリオドで終えます。

3.3 固定形式の桁のルール - 何桁目に書くかが大事

ここからが、COBOL の最も独特なルールです。COBOL の伝統的な書き方（固定形式）では、1行を80桁のマス目と考え、桁（左から何文字目か）ごとに役割が決まっています。これは、むかしパンチカード（80桁の穴あきカード）にプログラムを書いていた名残で、今のメインフレームの現場でもこの形式が使われています。

用語: 固定形式と自由形式

固定形式は桁の位置に意味がある書き方、自由形式は桁を気にせず書ける書き方です。GnuCOBOL の標準は固定形式で、本ガイドもすべて固定形式で書きます（自由形式は 3.7 で紹介します）。

桁名前本ガイドでの使い方
1〜6一連番号領域何も書かない（半角スペース6個）
7標識領域* を書くと、その行はコメント行。それ以外は半角スペース
8〜11A領域DIVISION・SECTION・段落名・レベル番号 01／77 を書き始める（レベル番号は、データの入れ物を定義する行の先頭に付ける番号。第4章で学びます）
12〜72B領域命令文（DISPLAY・MOVE など）や、05・10 など 01 より下の階層のレベル番号を書く
73〜80プログラム識別領域何も書かない（ここに書いた文字は無視される）

一連番号領域
空けておく"] --> B["7桁
標識領域
コメントは＊"] B --> C["8〜11桁
A領域

無視される"]

図の説明: 1行を左から右へ読むと、役割が5つに分かれています。命令文を書けるのは、72桁目までです。

実際のコードで、桁を確かめてみましょう。次の図は、プログラムの上に「桁の目盛り」を付けたものです。+ が5桁目、数字の 1 が10桁目、2 が20桁目を表します。2行目は各桁の領域を示しています（N=一連番号領域、*=標識領域、A=A領域、B=B領域）。目盛りの2行は説明用の図で、プログラムの一部ではありません（コピーボタンもありません）。

桁の目盛り付きの図 表示専用（保存しない） 
----+----1----+----2----+----3----+----4----+----5----+----6----+----7--
NNNNNN*AAAABBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB
      * 桁の位置を確かめるサンプル
       IDENTIFICATION DIVISION.
       PROGRAM-ID. COLPOS.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-NAME         PIC X(6) VALUE "TANAKA".
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "NAME: " WS-NAME.
           STOP RUN.

ファイルに保存して動かすのは、目盛りの2行を除いた次のプログラムです。

colpos.cob 完全なプログラム 
      * 桁の位置を確かめるサンプル
       IDENTIFICATION DIVISION.
       PROGRAM-ID. COLPOS.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-NAME         PIC X(6) VALUE "TANAKA".
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "NAME: " WS-NAME.
           STOP RUN.
ターミナル コマンド 
cobc -x colpos.cob
./colpos

NAME: TANAKA

このコードを桁に注目して読むと、次のことが分かります。

  • コメント行: 7桁目の *（先頭に半角スペース6個）。
  • A領域（8桁目から）: IDENTIFICATION DIVISION.、PROGRAM-ID.、WORKING-STORAGE SECTION.、レベル番号 01、段落名 MAIN-PROC. は、すべて先頭に半角スペース7個を置いて8桁目から始まっています。
  • B領域（12桁目から）: DISPLAY や STOP RUN. は、先頭に半角スペース11個を置いて12桁目から始まっています。
  • 01 の行の中: レベル番号 01 は8桁目から、データ名 WS-NAME は12桁目から始まります（01 の後ろに半角スペース2個）。

ヒント: 「7個」と「11個」だけ覚えればよい

桁の数え方で迷ったら、A領域＝行頭に半角スペース7個、B領域＝行頭に半角スペース11個と覚えましょう。コメント行だけは半角スペース6個＋* です。VS Code に桁の目印（ルーラー）を出す設定は、第2章で紹介しました。

次に、一連番号領域（1〜6桁）とプログラム識別領域（73〜80桁）は無視されることを確かめます。昔は、カードの順番を間違えないよう、ここに連番を書いていました。次のプログラムは、両方に文字を書いています。

seqnum.cob 完全なプログラム 
000100 IDENTIFICATION DIVISION.                                         SEQ00010
000200 PROGRAM-ID. SEQNUM.                                              SEQ00020
000300 PROCEDURE DIVISION.                                              SEQ00030
000400     DISPLAY "COL 1-6 AND 73-80 ARE IGNORED".                     SEQ00040
000500     STOP RUN.                                                    SEQ00050
000600* 1〜6桁と73〜80桁は無視される                         SEQ00060
ターミナル コマンド 
cobc -x seqnum.cob
./seqnum
実行結果 実行結果 
COL 1-6 AND 73-80 ARE IGNORED

エラーなく動きます。現場の古いプログラムを読むと、このような連番を見かけることがあります。本ガイドでは何も書きません。（最後のコメント行は日本語が1文字3バイトのため、画面上では SEQ の位置が左にずれて見えますが、ファイル上では73桁目から始まっています。）

警告: GnuCOBOL は桁のルールに甘い。でも守ること

GnuCOBOL は、命令文を A 領域から書いても、段落名をB領域から書いても、多くの場合そのままコンパイルしてしまいます。しかし、規格やメインフレームなどの処理系では、桁のルールに厳しく、警告やエラーになることがあります。現場で困らないよう、必ず上の表どおりの桁で書く習慣を付けましょう。

3.4 コメントの書き方 - 7桁目の「*」

コメントは、プログラムの動作には影響しない、人間向けのメモです。COBOL では、7桁目に * を書いた行がコメント行になります（先頭に半角スペース6個、その次に *）。日本語も書けます。

現場では、プログラムの先頭に「何のプログラムか」「誰がいつ作ったか」をコメントで書く習慣があります。数年後に別の人が保守するときの、大切な手がかりになるからです。

paras.cob 完全なプログラム 
      *****************************************************
      * プログラム名 : PARAS
      * 目的         : 段落の構成を確かめる
      * 作成者       : YAMADA
      * 作成日       : 2026-10-01
      *****************************************************
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PARAS.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 段落は上から順に実行される
           DISPLAY "MAIN-PROC です".
       END-PROC.
           DISPLAY "END-PROC です".
           STOP RUN.
ターミナル コマンド 
cobc -x paras.cob
./paras
実行結果 実行結果 
MAIN-PROC です
END-PROC です

ヒント: 区切り線のコメント

先頭の *****... の行は、見出しを目立たせる区切り線です。「枠」で囲むと、プログラムの先頭がひと目で分かります。7桁目さえ * なら、その後ろには何を書いてもかまいません。

警告: コメントの「*」を8桁目に書かない

* が7桁目ではなく8桁目以降にあると、コメントとして扱われず、命令文の一部と解釈されてエラーになります。3.8 の表と、やってみよう 3-1 で確かめます。また、本ガイドでは行の途中から始まるコメント（*>）は使いません。

3.5 見出し部の書き方 - PROGRAM-ID だけで十分

見出し部で必ず書かなければならないのは、PROGRAM-ID. だけです。ここに書くプログラム名は、本ガイドでは英大文字8文字以内にします（例: FOURDIV）。

見出し部の書き方 IDENTIFICATION DIVISIONの抜粋 
       IDENTIFICATION DIVISION.
      * プログラム名だけを書く（これで最小構成）
       PROGRAM-ID. HELLO.

昔のプログラムでは、見出し部に AUTHOR.（作成者）、DATE-WRITTEN.（作成日）などの段落を書くことがありました。現場の古いソースで見かけたら「作成者などのメモなのだな」と読めれば十分です。新しく書くときは、前の節で見たようにコメントに書くのが今の主流です。

author1.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. AUTHOR1.
       AUTHOR. YAMADA.
       PROCEDURE DIVISION.
      * 見出し部に作成者の段落を書いた例
           DISPLAY "AUTHOR PARAGRAPH IS OLD STYLE".
           STOP RUN.
ターミナル コマンド 
cobc -x -Wall author1.cob
./author1
コンパイルと実行の結果 警告つき 
author1.cob:3: warning: AUTHOR is obsolete in GnuCOBOL [-Wobsolete]
AUTHOR PARAGRAPH IS OLD STYLE

警告（warning）が出ましたが、コンパイルは成功し、実行もできます。「AUTHOR は古い書き方です」という知らせです。

ヒント: 警告（warning）とエラー（error）の違い

エラー（error）が出ると実行ファイルは作られません。警告（warning）は「動くけれど注意してね」という意味で、実行ファイルは作られます。-Wall を付けると、警告もすべて表示されます。

3.6 段落を使ってみる - 手続き部に名前を付ける

手続き部の中は、段落（パラグラフ）に区切って書くのが基本です。段落は、A領域（8桁目）から段落名を書き、最後にピリオドを付けて作ります。段落名は、本ガイドでは「英大文字＋-PROC」とします（例: MAIN-PROC）。

段落名は、料理でいう「下ごしらえ」「盛り付け」のような、手順の見出しです。3.4 の paras.cob の手続き部を、もう一度見てみましょう。

paras.cob の手続き部 PROCEDURE DIVISIONの抜粋 
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 段落は上から順に実行される
           DISPLAY "MAIN-PROC です".
       END-PROC.
           DISPLAY "END-PROC です".
           STOP RUN.
  • MAIN-PROC. と END-PROC. が段落名です。A領域（8桁目）から書き、ピリオドで終えます。
  • その下の命令文は B領域（12桁目）から書きます。
  • 段落は上から順に実行されます。MAIN-PROC の次に END-PROC が実行され、最後に STOP RUN. で終了します。
flowchart TD S["プログラム開始"] --> M["MAIN-PROC
MAIN-PROC です と表示"] M --> E["END-PROC
END-PROC です と表示"] E --> R["STOP RUN
プログラム終了"]

図の説明: 段落は上から順に実行されます。段落の呼び出し（PERFORM）で順番を変える方法は、第8章で学びます。

重要ポイント: STOP RUN を忘れない

STOP RUN. は「ここでプログラムを終える」命令です。GnuCOBOL では、書かなくても最後まで実行すれば終わります。それでも、どこで終わるかをはっきりさせるため、主プログラムの最後には必ず書きます。第8章で段落を呼び出す形にすると、STOP RUN が無いと、主処理の後ろの段落まで処理が流れ込んでしまいます。

3.7 コラム: 自由形式（-free）もある

GnuCOBOL や最近の COBOL には、桁を気にせず書ける自由形式もあります。コンパイルのときに -free を付けます。コメントは行内でも使える *> を使い、行頭の空白もいくつでもかまいません。

free1.cob（自由形式） 自由形式の例 
*> Free-format sample
IDENTIFICATION DIVISION.
PROGRAM-ID. FREE1.
PROCEDURE DIVISION.
    DISPLAY "自由形式でも動きます".
    STOP RUN.
ターミナル コマンド 
cobc -x -free free1.cob
./free1
実行結果 実行結果 
自由形式でも動きます

便利そうに見えますが、メインフレームの現場では今も固定形式が主流です。保守する既存のプログラムは固定形式で書かれているため、まずは固定形式をしっかり身につけることが近道です。本ガイドのコードは、すべて固定形式で書きます。

なお、自由形式のソースを、-free を付けずにコンパイルすると、7桁目に文字がある行が桁ルール違反として大量のエラーになります。

ターミナル コマンド 
cobc -x free1.cob
コンパイルの結果 コンパイル結果 
free1.cob:1: error: invalid indicator 'e' at column 7
free1.cob:2: error: invalid indicator 'F' at column 7
free1.cob:3: error: invalid indicator 'M' at column 7
（以下、同様のエラーが続く）

3.8 よくある桁ずれエラーを読む

桁のルールを守らないと、どんなエラーが出るのか、実際に見てみましょう。エラーの読み方は第2章でも学びました（ファイル名:行番号: 種類: 内容）。

ケース1: 7桁目に文字を書いてしまった

命令文の先頭が1桁左にずれて7桁目から始まると、標識領域に * や D など、決められた文字以外が入っていることになり、エラーになります。

badcol7.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. BADCOL7.
       PROCEDURE DIVISION.
           DISPLAY "HELLO".
      STOP RUN.
      * 5行目の STOP RUN が1桁左にずれている
ターミナル コマンド 
cobc -x badcol7.cob
コンパイルの結果 コンパイル結果 
badcol7.cob:5: error: invalid indicator 'S' at column 7

メッセージは「5行目の7桁目に、標識として正しくない文字 S がある」という意味です。5行目の STOP RUN. が1桁左にずれ、先頭の S が7桁目に来ています。命令文は12桁目から始めましょう。

ケース2: 72桁を超えてしまった

B領域は72桁目までです。73桁目以降の文字は無視されるので、長い文字列は途中で切れてしまいます。

long72.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. LONG72.
       PROCEDURE DIVISION.
           DISPLAY "ABCDEFGHIJKLMNOPQRSTUVWXYZ ABCDEFGHIJKLMNOPQRSTUVWXYZ".
           STOP RUN.
      * 4行目の文字列が72桁を超えている
ターミナル コマンド 
cobc -x long72.cob
コンパイルの結果 コンパイル結果 
long72.cob:5: error: continuation character expected
long72.cob:4: error: invalid literal: 'ABCDEFGHIJKLMNOPQRSTUVWXYZ ABCDEFG ...'
long72.cob:4: error: missing terminating " character
long72.cob:4: error: syntax error, unexpected end of file

4行目の文字列（リテラル）が72桁目で切られて終わりの " が消えたため、「文字列が閉じていない」というエラーが出ています。対策は、文字列を2つの DISPLAY に分けることです。日本語は1文字が3バイト（3桁分）を使うので、日本語の文字列はさらに早く72桁に届きます。

1つ目のメッセージが4行目ではなく5行目を指しているのは、4行目の文字列が閉じていないため、コンパイラが「次の行が続きの行（継続行）のはず」と5行目を調べたからです。continuation character expected が出たら、そのメッセージの1つ上の行を確かめましょう。

ヒント: エラーは最初の1つから直す

1つの間違いが、あとの行のエラーを連鎖的に引き起こすことがあります。エラーがたくさん出ても慌てず、いちばん上（最初）のエラーから順に直して、そのたびにコンパイルし直しましょう。ただし、メッセージが指す行の原因が、その1つ上の行にあることもあります（上の long72.cob がその例です）。行番号の前後の行も確かめましょう。

ケース3: エラーも出ないのに、表示されない

いちばん困るのは、エラーが出ないのに動作がおかしい場合です。次のプログラムでは、手続き部の DISPLAY が表示されません。

debuglin.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DEBUGLIN.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-A  PIC X(5) VALUE "ABCDE".
       PROCEDURE DIVISION.
      DISPLAY WS-A.
           STOP RUN.
      * 7行目の DISPLAY が7桁目から始まっている
ターミナル コマンド 
cobc -x debuglin.cob
./debuglin
実行結果 実行結果 
（何も表示されない）

原因は、DISPLAY の先頭の D が7桁目にあることです。COBOL では、7桁目の D は「デバッグ行（デバッグ用の命令）」を表し、通常のコンパイルでは行ごと無視されます。桁が1つずれただけで、命令が消えてしまうのです。

警告: 全角スペースとタブも桁ずれの原因

見た目では分からない桁ずれの代表が、全角スペースとタブ文字です。全角スペースは、入る位置によって、第2章で見た unknown statement や is not defined、行頭なら invalid indicator など、さまざまなエラーになります。タブは、エディタによって幅が変わり、桁がずれます。インデントは必ず半角スペースで書きましょう。

症状主な原因直し方
invalid indicator ... at column 77桁目に、決められた文字（* など）以外がある先頭の空白を増やし、命令文を12桁目から始める
continuation character expected や missing terminating "文字列が72桁を超えて切れた文字列を短くする、または DISPLAY を2つに分ける
エラーがないのに命令が実行されない7桁目に D がある命令文を12桁目から始める
syntax error, unexpected *コメントの * が8桁目以降にある* を7桁目に移す

やってみよう 3-1: 桁ずれのあるプログラムを直そう（間違い探し）

次の bug1.cob には、桁のルール違反が3か所あります。ファイルに保存してコンパイルし、3か所のうち2か所はエラーメッセージで見つかります。残る1か所は GnuCOBOL ではエラーにならない（3.3 の警告）ので、桁を目で確かめて見つけてください。直したら shop.cob として保存し、正しく動くことを確かめましょう。

           DISPLAY "いらっしゃいませ。本日は文房具の特売日です。".
       DISPLAY "ありがとうございました".

手順

  • 1 cobc -x bug1.cob を実行し、エラーメッセージの行番号を確認する。11行目に出る continuation character expected は、10行目の文字列が切れたことが原因です（3.8 のケース2と同じ）。
  • 2 8行目のコメント、10行目の長い文字列、11行目の命令文の位置を、桁のルールに合わせて直す。
  • 3 エラーが無くなるまでコンパイルし直す。11行目の桁ずれは GnuCOBOL がエラーにしないので、-Wall を付けても出ません。目で確かめて直す。

解答例

  • ・8行目: コメントの * が8桁目にある。先頭の空白を6個にして7桁目へ移す（「syntax error, unexpected *」）。
  • ・10行目: 文字列が長く72桁を超えている。DISPLAY を2つに分ける。
  • ・11行目: DISPLAY が8桁目（A領域）にある。先頭に半角スペース11個を置き、12桁目から書く（GnuCOBOL はエラーにしませんが、メインフレームなどでは警告・エラーになることがあります）。
  • ・ファイル名を shop.cob にするので、PROGRAM-ID も BUG1 から SHOP に変えます。

理解度確認クイズ

  • Q1. COBOL の4つの部を、書く順番に答えてください。また、データの入れ物を定義するのはどの部ですか？

    回答を表示

    見出し部（IDENTIFICATION）→ 環境部（ENVIRONMENT）→ データ部（DATA）→ 手続き部（PROCEDURE）の順です。データの入れ物を定義するのはデータ部、処理の手順を書くのは手続き部です。

  • Q2. 固定形式で、次の行は何桁目から書き始めますか？ (a) DATA DIVISION.　(b) DISPLAY "HELLO".　(c) コメント行の * 　(d) 段落名 MAIN-PROC.

    回答を表示

    (a) 8桁目（A領域、先頭に半角スペース7個）、(b) 12桁目（B領域、先頭に半角スペース11個）、(c) 7桁目（標識領域、先頭に半角スペース6個）、(d) 8桁目（A領域）です。

  • Q3. COBOL のコードの73桁目以降に書いた文字は、どのように扱われますか？ それが原因で起きる典型的なエラーは何ですか？

    回答を表示

    無視されます。長い文字列（リテラル）が72桁目で切れて、終わりの " が消えるため、「continuation character expected」や「missing terminating " character」といったエラーになります。

  • Q4. 7桁目の * と D は、それぞれどんな意味を持ちますか？ 命令文の先頭が誤って7桁目に来ると、どうなりますか？

    回答を表示

    * はコメント行、D はデバッグ行（通常のコンパイルでは行ごと無視される）を表します。決められた文字（*・D など）以外が7桁目にあると「invalid indicator」エラーになり、D の場合はエラーなしで命令が無視されることがあります。
