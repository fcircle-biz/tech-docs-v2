文字列を加工する - STRING・UNSTRING・INSPECT

業務データは「文字」の形で届くことがよくあります。日付 20261015 から月だけを取り出す、姓と名をつなげる、カンマ区切りの1行を項目に分ける、特定の文字を数えたり置き換えたりする。この章では、そうした文字列の加工に使う道具を一つずつ、実際の出力を確かめながら身につけます。

この章で学ぶこと

  • 部分参照 (開始位置:長さ) で、項目の一部を取り出したり書き換えたりできる
  • STRING で文字列を連結し、DELIMITED BY SIZE と SPACE の違いを説明できる
  • UNSTRING でカンマ区切りの1行を複数の項目に分割できる
  • INSPECT で文字を数え（TALLYING）、置換し（REPLACING）、変換できる（CONVERTING）
  • 組み込み関数（UPPER-CASE・TRIM・LENGTH・NUMVAL など）で、大文字小文字の変換や空白の除去ができる

この章の約束: 文字列データは半角英数字だけ

GnuCOBOL で UTF-8 のソースに書いた日本語は、文字数ではなくバイト数で扱われます（ひらがな・カタカナ・漢字の多くは1文字3バイト。第4章）。部分参照・STRING・UNSTRING・INSPECT はすべてバイト単位で動くため、日本語を含む文字列を扱うと、文字の途中で切れて文字化けしたり、桁数の計算が合わなくなったりします。実際、GnuCOBOL では FUNCTION LENGTH("山田") の結果が 2 ではなく 6 になります（処理系や文字コードの設定によって数え方は異なります）。そのため、この章の例題データはすべて半角英数字（TANAKA、20261015 など）にしています。画面に出す見出しの日本語（DISPLAY のリテラル）は問題ありません。

flowchart LR A["部分参照
一部を取り出す"] --> E["文字列の加工"] B["STRING
つなげる"] --> E C["UNSTRING
分ける"] --> E D["INSPECT
数える・置き換える"] --> E F["組み込み関数
大小文字・空白除去"] --> E

図の説明: この章で学ぶ5つの道具です。「取り出す・つなげる・分ける・数えて置き換える・整える」という、文字列加工の基本動作がひととおりそろいます。

11.1 項目の一部を取り出す - 部分参照

日付 20261015 から「月」だけを取り出したいとき、どうすればよいでしょうか。COBOL では、項目名の後ろに (開始位置:長さ) を付けるだけで、項目の一部分を指定できます。この書き方を部分参照（reference modification）と呼びます。

たとえるなら、横長の申込用紙のマス目の「左から5マス目から2マス分」を指さすイメージです。位置は1から数え始めます（第10章の添字と同じです）。

位置12345678
文字20261015
指定年（1:4）月（5:2）日（7:2）

表のとおり、年は「1文字目から4文字」で WS-DATE(1:4)、月は「5文字目から2文字」で WS-DATE(5:2)、日は WS-DATE(7:2) です。実際に動かしてみましょう。

substr.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. SUBSTR.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-DATE     PIC X(8) VALUE "20261015".
       01  WS-YEAR     PIC X(4).
       01  WS-MONTH    PIC X(2).
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 日付の一部だけを取り出す（開始位置:長さ）
           MOVE WS-DATE(1:4) TO WS-YEAR
           MOVE WS-DATE(5:2) TO WS-MONTH
           DISPLAY "DATE  : " WS-DATE
           DISPLAY "YEAR  : " WS-YEAR
           DISPLAY "MONTH : " WS-MONTH
           DISPLAY "DAY   : " WS-DATE(7:2)
           DISPLAY "FROM 5: " WS-DATE(5:)
      * 一部だけを書き換えることもできる
           MOVE "XX" TO WS-DATE(5:2)
           DISPLAY "CHANGED: " WS-DATE
           STOP RUN.
ターミナル コマンド 
cobc -x substr.cob
./substr
実行結果 出力 
DATE  : 20261015
YEAR  : 2026
MONTH : 10
DAY   : 15
FROM 5: 1015
CHANGED: 2026XX15

ポイントは3つです。

  • WS-DATE(1:4) は項目の代わりに、そのまま DISPLAY や MOVE に書けます。
  • 長さを省略した WS-DATE(5:) は「5文字目から最後まで」を意味します。
  • MOVE "XX" TO WS-DATE(5:2) のように、受け取る側に書けば、項目の一部だけを書き換えられます（結果は 2026XX15）。

ヒント: 開始位置と長さは変数でも指定できる

WS-DATE(WS-POS:2) のように、数字項目で位置を指定することもできます。第10章の表の添字と同じ感覚で、繰り返し処理と組み合わせて「1文字ずつ調べる」ような使い方もできます。

範囲外の指定には注意が必要です。WS-DATE(7:5)（8桁の項目の7文字目から5文字）のように、数値で直接書いた範囲外はコンパイル時にエラーになります。次は、前の substr.cob の DAY を表示する行を WS-DATE(7:5) に書き換えてコンパイルしたときのメッセージです。

コンパイルエラーの例 出力 
substr.cob: in paragraph 'MAIN-PROC':
substr.cob:16: error: length of 'WS-DATE' out of bounds: 5

一方、位置や長さを変数で指定すると、コンパイルでは検出できません。通常の実行では、項目の外側（隣のデータ）を黙って読んでしまいます。そこで、開発中は -debug を付けてコンパイルすると、実行時に範囲外を検出して止めてくれます。

oob.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. OOB.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-DATE     PIC X(8) VALUE "20261015".
       01  WS-POS      PIC 9(2) VALUE 7.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 位置が変数だとコンパイル時には検出されない
           DISPLAY "DAY: " WS-DATE(WS-POS:5)
           STOP RUN.
ターミナル コマンド 
cobc -x -debug oob.cob
./oob
実行結果 出力 
libcob: oob.cob:10: error: length of 'WS-DATE' out of bounds: 5, starting at: 7, maximum: 8

 Last statement of OOB was at line 10 of oob.cob

警告: 範囲外アクセスは見つけにくい不具合のもと

処理系やコンパイル時の設定によっては、範囲外の部分参照が検査されず、黙って隣のデータを読み書きして、原因の分かりにくい障害になることがあります。位置と長さを変数で指定するときは、「開始位置＋長さ−1」が項目の長さを超えないことを自分で確かめましょう。

11.2 文字列をつなげる - STRING

ここからは文字列をつなげる道具、STRING文です。複数の文字列を、1つの受け取り項目に順番に書き込んでいきます。

flowchart LR A["WS-LAST
TANAKA"] --> D["STRING"] B["リテラル
-"] --> D C["WS-FIRST
TARO"] --> D D --> E["INTO WS-OUT
TANAKA-TARO"]

図の説明: STRING の流れです。左の材料を順番に並べ、INTO で指定した受け取り項目へ書き込みます。

基本の形は「STRING 材料 DELIMITED BY 区切り ... INTO 受け取り項目 END-STRING」です。材料の後ろに DELIMITED BY（どこまでを使うか）を書きます。1つの DELIMITED BY は、その前に並べた材料にまとめて効きます（本章のプログラムでは、分かりやすさのため材料ごとに書いています）。最もよく使うのは次の2つです。

指定意味使いどころ
DELIMITED BY SIZE項目の全長をそのまま使う（後ろの空白も含む）リテラル（"-" など）、桁数が固定のデータ
DELIMITED BY SPACE最初の空白の手前までを使う名前など、後ろに空白が詰められた項目

違いを実機で比べます。WS-LAST は PIC X(10) に TANAKA を入れたので、後ろに空白が4つ付いています。結果を [ と ] で囲んで、空白が見えるようにしました。

string1.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. STRING1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-FIRST    PIC X(10) VALUE "TARO".
       01  WS-LAST     PIC X(10) VALUE "TANAKA".
       01  WS-OUT1     PIC X(30) VALUE SPACE.
       01  WS-OUT2     PIC X(30) VALUE SPACE.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * SIZE: 項目の全長（後ろの空白も）を連結する
           STRING WS-LAST DELIMITED BY SIZE
                  "-" DELIMITED BY SIZE
                  WS-FIRST DELIMITED BY SIZE
                  INTO WS-OUT1
           END-STRING
      * SPACE: 最初の空白の手前までを連結する
           STRING WS-LAST DELIMITED BY SPACE
                  "-" DELIMITED BY SIZE
                  WS-FIRST DELIMITED BY SPACE
                  INTO WS-OUT2
           END-STRING
           DISPLAY "SIZE : [" WS-OUT1 "]"
           DISPLAY "SPACE: [" WS-OUT2 "]"
           STOP RUN.
実行結果 出力 
SIZE : [TANAKA    -TARO               ]
SPACE: [TANAKA-TARO                   ]

SIZE では TANAKA の後ろの空白4つまで連結され、TANAKA -TARO と間が空いてしまいました。SPACE なら TANAKA-TARO と思いどおりにつながります。名前のような「後ろに空白が詰まった項目」は DELIMITED BY SPACE が基本です。

警告: SPACE 区切りは「値の途中の空白」でも切れる

TOKYO TOWER のように途中に空白がある値を DELIMITED BY SPACE で連結すると、最初の空白で終わってしまい、実際に [TOKYO ] になりました。途中に空白を含みうるデータは、11.5 で紹介する FUNCTION TRIM と DELIMITED BY SIZE の組み合わせを使います。

STRING は「書いた分だけ」上書きする

STRING には、初心者がつまずきやすい性質があります。受け取り項目の全体を空白で埋めてくれません。連結した文字数分だけを書き込み、残りは前の値のままです。次の例で確かめましょう。

strclr.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. STRCLR.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-OUT      PIC X(10) VALUE "XXXXXXXXXX".
       01  WS-SMALL    PIC X(5) VALUE SPACE.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * STRING は書いた分だけ上書き（残りは前の値）
           STRING "ABC" DELIMITED BY SIZE INTO WS-OUT
           END-STRING
           DISPLAY "BEFORE CLEAR: [" WS-OUT "]"
      * 先に空白で初期化してから使うのが定石
           MOVE SPACE TO WS-OUT
           STRING "ABC" DELIMITED BY SIZE INTO WS-OUT
           END-STRING
           DISPLAY "AFTER CLEAR : [" WS-OUT "]"
      * 入りきらないときは ON OVERFLOW で検出できる
           STRING "ABCDEFGH" DELIMITED BY SIZE INTO WS-SMALL
               ON OVERFLOW
                   DISPLAY "OVERFLOW: " WS-SMALL
               NOT ON OVERFLOW
                   DISPLAY "OK"
           END-STRING
           STOP RUN.
実行結果 出力 
BEFORE CLEAR: [ABCXXXXXXX]
AFTER CLEAR : [ABC       ]
OVERFLOW: ABCDE

1回目は受け取り項目が XXXXXXXXXX だったので ABCXXXXXXX と古い値が残りました。STRING の前に MOVE SPACE TO 受け取り項目 で空白にしておくのが定石です。

また、連結結果が受け取り項目に入りきらないときは、あふれた分が捨てられます。ON OVERFLOW（あふれたとき）と NOT ON OVERFLOW で検出でき、上の例では 5桁の項目に ABCDEFGH を入れようとして OVERFLOW: ABCDE と表示されました。

重要ポイント: STRING の前には必ず初期化する

STRING は書いた文字数分しか受け取り項目を更新しません。繰り返し処理で同じ項目に何度も STRING すると、前回の長い値の「しっぽ」が残ります。STRING の直前に MOVE SPACE TO を置く習慣をつけましょう。

POINTER: 書き込み位置を自分で管理する（紹介）

WITH POINTER を付けると、「受け取り項目の何文字目から書くか」を数字項目で指定でき、書いた後は次の位置に自動で進みます。何回かに分けて文字列を組み立てるときに使います。（次の2つの部品は、それぞれ単独では動きません。順につなげて1つのファイル ptr1.cob に保存します。部品1の前に IDENTIFICATION DIVISION.・PROGRAM-ID. PTR1.・DATA DIVISION.・WORKING-STORAGE SECTION. の4行を、部品1と部品2の間に PROCEDURE DIVISION.・MAIN-PROC. の2行を書き足してください。）

ptr1.cob（部品 1/2） DATA DIVISIONの抜粋 
      * 書き込み先（* で埋める）と書き込み位置
       01  WS-OUT3     PIC X(20) VALUE ALL "*".
       01  WS-PTR      PIC 9(2).
ptr1.cob（部品 2/2） PROCEDURE DIVISIONの抜粋 
      * WITH POINTER で書き込み位置を引き継ぐ
           MOVE 1 TO WS-PTR
           STRING "ABC" DELIMITED BY SIZE
                  INTO WS-OUT3 WITH POINTER WS-PTR
           END-STRING
           STRING "-DEF" DELIMITED BY SIZE
                  INTO WS-OUT3 WITH POINTER WS-PTR
           END-STRING
           DISPLAY "PTR  : [" WS-OUT3 "] NEXT=" WS-PTR
           STOP RUN.
実行結果 出力 
PTR  : [ABC-DEF*************] NEXT=08

1回目で ABC を書いた後、ポインタは 4 に進み、2回目の -DEF はその続きに書かれました。最後のポインタは 8（次に書く位置）です。※この例では、書かれなかった部分に初期値の * が残っていることも見て取れます。

11.3 文字列を分ける - UNSTRING

STRING の反対がUNSTRINGです。1つの文字列を、指定した区切り文字で分割して、複数の項目に入れます。他システムから届く、カンマ区切りのテキストの1行を項目に分けるときに使えます（ただし対象は単純なカンマ区切りデータです。詳しくはこの節の最後の注意を参照）。

flowchart LR A["WS-LINE
TANAKA,TARO,SALES"] --> B["UNSTRING
カンマで分割"] B --> C["WS-LAST
TANAKA"] B --> D["WS-FIRST
TARO"] B --> E["WS-DEPT
SALES"]

図の説明: UNSTRING の流れです。カンマの位置で1行を切り分け、INTO に並べた項目へ順番に入れていきます。

TANAKA,TARO,SALES（姓・名・部署）を3つの項目に分けてみましょう。TALLYING IN を付けると、実際に取り出せた項目の数を数字項目に数えてくれます。

unstr1.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. UNSTR1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-LINE     PIC X(30) VALUE "TANAKA,TARO,SALES".
       01  WS-LAST     PIC X(10).
       01  WS-FIRST    PIC X(10).
       01  WS-DEPT     PIC X(10).
       01  WS-CNT      PIC 9(2) VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * カンマで3つの項目に分割し、項目数も数える
           UNSTRING WS-LINE DELIMITED BY ","
               INTO WS-LAST WS-FIRST WS-DEPT
               TALLYING IN WS-CNT
           END-UNSTRING
           DISPLAY "LAST : [" WS-LAST "]"
           DISPLAY "FIRST: [" WS-FIRST "]"
           DISPLAY "DEPT : [" WS-DEPT "]"
           DISPLAY "COUNT: " WS-CNT
           STOP RUN.
実行結果 出力 
LAST : [TANAKA    ]
FIRST: [TARO      ]
DEPT : [SALES     ]
COUNT: 03

受け取り項目 PIC X(10) には、取り出した文字列が左寄せで入り、余りは空白で埋められます（[TANAKA ]）。COUNT: 03 は、3つの項目に取り出せたことを表します。

ヒント: TALLYING IN の項目は事前に 0 にしておく

TALLYING IN は、項目数を今の値に足し込みます。そのため、数字項目は VALUE 0 か MOVE 0 で先にゼロにしておく必要があります。使わない場合は省略して構いません。

分割の結果が、受け取り項目の数や長さと合わないときの動きも、押さえておきましょう（テスト用プログラムで確認した結果です）。

状況結果の例対処
区切りが足りず、項目が余る"A,B" を 3項目に分けると、3つ目は前の値のまま（テストでは受け取り項目の初期値を ??? にしておいたので、それが残った）、TALLYING は 2UNSTRING の前に受け取り項目を MOVE SPACE で初期化する
値が受け取り項目より長い"ABCDE,F" を PIC X(3) に取り出すと ABC に切り捨て受け取り項目の長さを十分に取る

UNSTRING だけで、あらゆる CSV は処理できない

このサンプルは、項目内にカンマや改行、引用符を含まない単純な区切り文字データを対象とします。一般的な CSV 形式を扱う場合は、引用符やエスケープの処理が別途必要です。たとえば 1001,"東京都,千代田区",5000 のように、引用符で囲んだ項目の中にカンマがある行を DELIMITED BY "," で分けると、引用符の中のカンマでも区切られてしまいます。

実際に試した結果です（unstr1.cob の WS-LINE を上の行に替え、3つの受け取り項目を PIC X(16) にして実行）。

実行結果 出力 
F1   : [1001            ]
F2   : ["東京都      ]
F3   : [千代田区"   ]
COUNT: 03

「東京都,千代田区」が2つに裂け、引用符も項目に残り、本来3つ目の 5000 は受け取り先がなくて捨てられています。それでもエラーにはならず、COUNT も 3 のままなので、気づきにくい点に注意してください。

取り出した長さを知る - COUNT IN と数字への変換

CSV では、数字も文字として届きます。たとえば A001,PEN,120（商品コード・商品名・単価）の「120」は、まだ文字です。COUNT IN で各項目の元の文字数を記録でき、数字にしたいときは 11.5 で詳しく学ぶ FUNCTION NUMVAL（数字の文字列を数値に変える関数）を使います。次の2つの部品は、それぞれ単独では動きません。順につなげて1つのファイル cntin.cob に保存します。部品1の前に IDENTIFICATION DIVISION.・PROGRAM-ID. CNTIN.・DATA DIVISION.・WORKING-STORAGE SECTION. の4行を、部品1と部品2の間に PROCEDURE DIVISION.・MAIN-PROC. の2行を書き足してください。

cntin.cob（部品 1/2） DATA DIVISIONの抜粋 
      * CSV の1行と、分割先の項目
       01  WS-LINE     PIC X(30) VALUE "A001,PEN,120".
       01  WS-CODE     PIC X(4).
       01  WS-NAME     PIC X(10).
       01  WS-PRICE-X  PIC X(5).
       01  WS-LEN      PIC 9(2).
       01  WS-PRICE    PIC 9(5).
cntin.cob（部品 2/2） PROCEDURE DIVISIONの抜粋 
      * NAME の文字数を COUNT IN で受け取る
           UNSTRING WS-LINE DELIMITED BY ","
               INTO WS-CODE
                    WS-NAME COUNT IN WS-LEN
                    WS-PRICE-X
           END-UNSTRING
           DISPLAY "NAME : [" WS-NAME "] LEN=" WS-LEN
           MOVE FUNCTION NUMVAL(WS-PRICE-X) TO WS-PRICE
           DISPLAY "PRICE: " WS-PRICE
           STOP RUN.
実行結果 出力 
NAME : [PEN       ] LEN=03
PRICE: 00120

WS-NAME の直後に書いた COUNT IN WS-LEN は、区切り文字までの元の文字数（PEN なら 3）を WS-LEN に入れます。受け取り項目より長くて切り捨てられた場合も元の長さ（例: ABCDE なら 5）が入るので、切り捨ての検出にも使えます。COUNT IN はその直前の受け取り項目に対応する点に注意してください。最後の NUMVAL で文字の「120」が数字の 00120 になりました。

11.4 数える・置き換える・変換する - INSPECT

INSPECTは、1つの項目の中身を「調べる」命令です。次の3つの使い方があります。

使い方できることたとえ
TALLYING特定の文字や文字列が何個あるかを数える文書の中の「A」の個数を数える
REPLACING特定の文字や文字列を別のものに置き換える検索と置換
CONVERTING文字を対応表に従って1文字ずつ変換する小文字を大文字に変える換字表

TALLYING - 数える

BANANA SPLIT を題材に、「A の個数」「AN の個数」「最初の空白より前の文字数」を数えます。数えた結果は、あらかじめ VALUE 0 にした数字項目に足し込まれます。

insp1.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INSP1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-TEXT     PIC X(12) VALUE "BANANA SPLIT".
       01  WS-CNT-A    PIC 9(2) VALUE 0.
       01  WS-CNT-ALL  PIC 9(2) VALUE 0.
       01  WS-CNT-LD   PIC 9(2) VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 数える: A の個数、AN の個数
           INSPECT WS-TEXT TALLYING WS-CNT-A FOR ALL "A"
           INSPECT WS-TEXT TALLYING WS-CNT-ALL FOR ALL "AN"
      * 最初の空白より前の文字数
           INSPECT WS-TEXT TALLYING WS-CNT-LD
               FOR CHARACTERS BEFORE INITIAL " "
           DISPLAY "TEXT  : [" WS-TEXT "]"
           DISPLAY "A     : " WS-CNT-A
           DISPLAY "AN    : " WS-CNT-ALL
           DISPLAY "BEFORE: " WS-CNT-LD
           STOP RUN.
実行結果 出力 
TEXT  : [BANANA SPLIT]
A     : 03
AN    : 02
BEFORE: 06

FOR ALL "A" は「すべての A」を数え、BANANA の A が3個あるので 03 です。FOR CHARACTERS BEFORE INITIAL " " は「最初の空白より前のすべての文字」を数えるという意味で、BANANA の6文字になります。BEFORE INITIAL は「最初に現れる〜より前」、AFTER INITIAL は「〜より後」と、範囲を絞る指定です。

REPLACING - 置き換える

置き換える範囲は、ALL（すべて）・FIRST（最初の1か所）・LEADING（先頭から連続する部分）の3種類から選びます。同じ BANANA SPLIT で違いを比べましょう。このあとの3つの部品は、それぞれ単独では動きません。順につなげて1つのファイル repl1.cob に保存します。部品1の前に IDENTIFICATION DIVISION.・PROGRAM-ID. REPL1.・DATA DIVISION.・WORKING-STORAGE SECTION. の4行を、部品1と部品2の間に PROCEDURE DIVISION.・MAIN-PROC. の2行を書き足してください（部品2と部品3はそのままつなげます）。

repl1.cob（部品 1/3） DATA DIVISIONの抜粋 
      * 置き換え・変換の対象になる項目
       01  WS-TEXT1    PIC X(12) VALUE "BANANA SPLIT".
       01  WS-TEXT2    PIC X(12) VALUE "BANANA SPLIT".
       01  WS-TEXT3    PIC X(12) VALUE "BANANA SPLIT".
       01  WS-PHONE    PIC X(12) VALUE "03-1234-5678".
       01  WS-CODE     PIC X(8)  VALUE "ab12cd34".
repl1.cob（部品 2/3） PROCEDURE DIVISIONの抜粋 
      * ALL: 一致するものをすべて置き換える
           INSPECT WS-TEXT1 REPLACING ALL "A" BY "*"
      * FIRST: 最初の1か所だけ置き換える
           INSPECT WS-TEXT2 REPLACING FIRST "A" BY "*"
      * LEADING: 先頭から連続する部分だけ置き換える
           INSPECT WS-TEXT3 REPLACING LEADING "B" BY "-"
      * ハイフンを空白に置き換える
           INSPECT WS-PHONE REPLACING ALL "-" BY " "

CONVERTING - 文字を変換する

CONVERTING 変換前の文字の並び TO 変換後の文字の並び と書くと、変換前の文字が出てくるたびに、同じ順番の位置にある変換後の文字へ置き換えます。小文字26文字と大文字26文字を対応させれば、小文字→大文字の変換になります。

repl1.cob（部品 3/3） PROCEDURE DIVISIONの抜粋 
      * 小文字を大文字へ1文字ずつ対応させて変換する
           INSPECT WS-CODE CONVERTING
               "abcdefghijklmnopqrstuvwxyz"
               TO "ABCDEFGHIJKLMNOPQRSTUVWXYZ"
      * 結果を [ ] で囲んで表示する
           DISPLAY "ALL    : [" WS-TEXT1 "]"
           DISPLAY "FIRST  : [" WS-TEXT2 "]"
           DISPLAY "LEADING: [" WS-TEXT3 "]"
           DISPLAY "PHONE  : [" WS-PHONE "]"
           DISPLAY "UPPER  : [" WS-CODE "]"
           STOP RUN.

部品3の最後の DISPLAY では、各項目を [ ] で囲んで表示しています。つなげた repl1.cob を cobc -x repl1.cob でコンパイルして実行した結果です。

実行結果 出力 
ALL    : [B*N*N* SPLIT]
FIRST  : [B*NANA SPLIT]
LEADING: [-ANANA SPLIT]
PHONE  : [03 1234 5678]
UPPER  : [AB12CD34]

ALL はすべての A が * に、FIRST は最初の A だけ、LEADING は先頭の B だけが変わっています。電話番号のハイフンは空白に、ab12cd34 は AB12CD34 になりました。

警告: REPLACING は同じ長さの置き換え専用

INSPECT REPLACING で置き換える文字列は、置き換え前と同じ長さでなければなりません（例: 1文字を1文字に、2文字を2文字に）。ハイフンを「消す」（詰める）ことはできず、上の電話番号のように空白に置き換える形になります。文字を詰めたいときは、UNSTRING で分けてから STRING でつなぎ直します。

11.5 便利な道具 - 組み込み関数（FUNCTION）

COBOL には、あらかじめ用意された便利な部品、組み込み関数（FUNCTION 関数名）があります。計算式の値のように、DISPLAY や MOVE の中にそのまま書けます。文字列加工でよく使うものを表にまとめます。

関数働き結果の例
FUNCTION UPPER-CASE(項目)英字をすべて大文字にするTanaka → TANAKA
FUNCTION LOWER-CASE(項目)英字をすべて小文字にするTanaka → tanaka
FUNCTION TRIM(項目)前後の空白を取り除く（LEADING で前だけ、TRAILING で後ろだけ）[ Tanaka ] → [Tanaka]
FUNCTION LENGTH(項目)項目の長さ（バイト数）を返すPIC X(10) なら 10
FUNCTION REVERSE(項目)文字の並びを逆にするABC → CBA
FUNCTION NUMVAL(項目)数字の文字列を数値にする（前後の空白・小数点を許す）" 1250" → 1250
FUNCTION CURRENT-DATE現在の日付と時刻を21桁の文字列で返す先頭8桁が年月日

空白の動きが見えるよう、先頭に空白を2つ付けた名前 " Tanaka"（PIC X(10)、後ろにも2つ空白が付く）で試します。次の2つの部品は、それぞれ単独では動きません。順につなげて1つのファイル func1.cob に保存します。部品1の前に IDENTIFICATION DIVISION.・PROGRAM-ID. FUNC1.・DATA DIVISION.・WORKING-STORAGE SECTION. の4行を、部品1と部品2の間に PROCEDURE DIVISION.・MAIN-PROC. の2行を書き足してください。

func1.cob（部品 1/2） DATA DIVISIONの抜粋 
      * 前後に空白が付いた名前（関数の動きを見る）
       01  WS-NAME     PIC X(10) VALUE "  Tanaka".
       01  WS-LEN      PIC 9(2).
       01  WS-NUM      PIC 9(5).
func1.cob（部品 2/2） PROCEDURE DIVISIONの抜粋 
      * 関数で大小文字・空白除去・長さ・数値化
           DISPLAY "RAW    : [" WS-NAME "]"
           DISPLAY "UPPER  : [" FUNCTION UPPER-CASE(WS-NAME) "]"
           DISPLAY "LOWER  : [" FUNCTION LOWER-CASE(WS-NAME) "]"
           DISPLAY "TRIM   : [" FUNCTION TRIM(WS-NAME) "]"
           DISPLAY "LEADING: [" FUNCTION TRIM(WS-NAME LEADING) "]"
           DISPLAY "TRAILING: [" FUNCTION TRIM(WS-NAME TRAILING) "]"
           DISPLAY "REVERSE: [" FUNCTION REVERSE(WS-NAME) "]"
           MOVE FUNCTION LENGTH(WS-NAME) TO WS-LEN
           DISPLAY "LENGTH : " WS-LEN
           MOVE FUNCTION LENGTH(FUNCTION TRIM(WS-NAME)) TO WS-LEN
           DISPLAY "TRIMLEN: " WS-LEN

           STOP RUN.
実行結果 出力

[ ] で囲んだおかげで、TRIM が前後の空白を取り除いていること、LEADING は前だけ、TRAILING は後ろだけを取り除くことがはっきり見えます。LENGTH は元の項目の 10 を、TRIM の結果に使うと実質の長さ 6 を返します。

ヒント: TRIM は STRING と組み合わせると強い

STRING FUNCTION TRIM(WS-LAST) DELIMITED BY SIZE " " DELIMITED BY SIZE FUNCTION TRIM(WS-FIRST) DELIMITED BY SIZE INTO WS-FULL のように、TRIM で前後の空白を取り除いた結果を DELIMITED BY SIZE で連結すれば、値の途中に空白があっても切れず、きれいにつながります。

現在の日付を取り出す - CURRENT-DATE

FUNCTION CURRENT-DATE は、年月日・時分秒などをまとめた21桁の文字列を返します。先頭の8桁が YYYYMMDD 形式の年月日なので、本章の部分参照で必要な部分を取り出せます。21桁の並びは次のとおりです。

位置内容部分参照の例
1〜8桁年月日（YYYYMMDD）WS-NOW(1:4) で年
9〜14桁時分秒（hhmmss）WS-NOW(9:2) で時
15〜16桁100分の1秒WS-NOW(15:2)
17〜21桁グリニッジ標準時との時差（符号と hhmm。日本なら +0900）WS-NOW(17:5)
cdate.cob 完全なプログラム

重要ポイント: 関数は結果を返すだけで、元の項目は変えない

FUNCTION UPPER-CASE(WS-NAME) は大文字にした結果の値を返すだけで、WS-NAME 自体は変わりません。結果を残したいときは MOVE FUNCTION UPPER-CASE(WS-NAME) TO WS-NAME2 のように、MOVE で別の項目（または同じ項目）に受け取ります。

やってみよう 11-1: 社員データの1行を分割して整形しよう

社員データの1行 TANAKA,TARO,SALES（姓・名・部署）を UNSTRING で分割し、「姓・名・部署」を整形して表示します。さらに姓と名を連結して、大文字と小文字の両方で表示してください。

手順

  • 1 namefmt.cob を作り、WORKING-STORAGE に WS-LINE（PIC X(30)、初期値は上の1行）と、WS-LAST・WS-FIRST・WS-DEPT（それぞれ PIC X(10)）、連結結果用の WS-FULL（PIC X(21)、VALUE SPACE で空白に初期化する）を定義する。
  • 2 UNSTRING で WS-LINE をカンマで3つに分割し、姓・名・部署を表示する。
  • 3 STRING で「姓 + 空白1つ + 名」を WS-FULL に連結する（姓と名は DELIMITED BY SPACE）。
  • 4 FUNCTION UPPER-CASE と FUNCTION LOWER-CASE で、連結した氏名を大文字と小文字で表示する。

解答例

次のプログラムです。コンパイルと実行の結果もあわせて示します。

namefmt.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. NAMEFMT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-LINE     PIC X(30) VALUE "TANAKA,TARO,SALES".
       01  WS-LAST     PIC X(10).
       01  WS-FIRST    PIC X(10).
       01  WS-DEPT     PIC X(10).
       01  WS-FULL     PIC X(21) VALUE SPACE.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * カンマで分割し、姓名を連結して表示する
           UNSTRING WS-LINE DELIMITED BY ","
               INTO WS-LAST WS-FIRST WS-DEPT
           END-UNSTRING
           DISPLAY "LAST : " WS-LAST
           DISPLAY "FIRST: " WS-FIRST
           DISPLAY "DEPT : " WS-DEPT
           STRING WS-LAST DELIMITED BY SPACE
                  " " DELIMITED BY SIZE
                  WS-FIRST DELIMITED BY SPACE INTO WS-FULL
           END-STRING
           DISPLAY "UPPER: " FUNCTION UPPER-CASE(WS-FULL)
           DISPLAY "LOWER: " FUNCTION LOWER-CASE(WS-FULL)
           STOP RUN.
ターミナル コマンド 
cobc -x namefmt.cob
./namefmt
実行結果 出力 
LAST : TANAKA    
FIRST: TARO      
DEPT : SALES     
UPPER: TANAKA TARO          
LOWER: tanaka taro
  • ・UNSTRING は DELIMITED BY "," でカンマ区切りの3項目に分割しています。
  • ・STRING の姓と名は DELIMITED BY SPACE、間の空白は " " DELIMITED BY SIZE です。WS-FULL は VALUE SPACE で空白にしてあるので、1回だけ使うここでは MOVE SPACE を省いています（繰り返して使うなら STRING の直前に MOVE SPACE が必要です）。
  • ・UPPER-CASE・LOWER-CASE は結果を返すだけなので、DISPLAY の中に直接書いています。

理解度確認クイズ

  • Q1. WS-DATE が PIC X(8) VALUE "20261015" のとき、WS-DATE(5:2) と WS-DATE(1:4) の値はそれぞれ何ですか？

    回答を表示

    WS-DATE(5:2) は 10、WS-DATE(1:4) は 2026 です。部分参照は (開始位置:長さ) で、位置は1から数えます。

  • Q2. WS-LAST（PIC X(10)）に TANAKA が入っているとき、STRING で DELIMITED BY SIZE と DELIMITED BY SPACE を指定すると結果はどう違いますか？

    回答を表示

    SIZE は項目の全長（10桁）を使うので、後ろの空白4つまで連結されます（TANAKA ）。SPACE は最初の空白の手前までなので TANAKA だけが連結されます。名前のように後ろに空白が詰まった項目には SPACE を使います。

  • Q3. UNSTRING に TALLYING IN WS-CNT を付けるときに、事前にやっておくべきことは何ですか？ また、STRING の前にやっておくべきことは何ですか？

    回答を表示

    TALLYING IN は項目数を今の値に足し込むので、WS-CNT を事前に 0 にしておく必要があります。STRING は書いた分しか受け取り項目を更新しないので、前の値が残らないよう事前に MOVE SPACE で受け取り項目を空白にしておくのが定石です。

  • Q4. WS-T が BANANA のとき、INSPECT WS-T TALLYING WS-N FOR ALL "A" の後で WS-N（初期値 0）はいくつになりますか？ また、小文字を大文字に変えたいときに使う INSPECT の指定は何ですか？

    回答を表示

    3 です（BANANA には A が3個あります）。小文字を大文字に変えるには、CONVERTING に小文字26文字と大文字26文字を対応させて指定します（INSPECT 項目 CONVERTING "abc...z" TO "ABC...Z"）。なお、FUNCTION UPPER-CASE でも同じことができます。
