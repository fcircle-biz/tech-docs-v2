ホーム COBOL入門 第2章
第2章 所要時間: 約90分

開発環境を準備する - GnuCOBOLで最初のプログラム

いよいよ手を動かします。この章では、無償の COBOL コンパイラ「GnuCOBOL」を自分のパソコンに入れ、「Hello, COBOL!」と表示する最初のプログラムを書いて動かします。さらに、わざと間違えてコンパイルエラーを出し、エラーメッセージの読み方にも慣れましょう。

この章で学ぶこと

  • COBOL のプログラムが「ソースファイル → コンパイル → 実行ファイル」の順で動くことを説明できる
  • 自分の OS（Windows・macOS・Linux）に GnuCOBOL をインストールし、cobc --version で確認できる
  • VS Code を COBOL 向けに設定し、hello.cob を作成・コンパイル・実行できる
  • コンパイルエラーのメッセージ（ファイル名:行番号: 種類: 内容）を読んで、原因を見つけて直せる

2.1 開発に必要なもの

COBOL のプログラムを作るのに必要なものは、たった2つです。

1. テキストエディタ

プログラムの文章（ソースコード）を書くためのソフトです。本ガイドでは無償で高機能な VS Code を使います。メモ帳でも書けますが、桁位置が見やすいエディタをおすすめします。

2. コンパイラ（GnuCOBOL）

書いたソースコードを、コンピュータが実行できる形に翻訳するソフトです。GnuCOBOL の翻訳コマンドの名前は cobc です。

コンパイルとは

人間が読み書きする COBOL の文章は、そのままではコンピュータが実行できません。コンピュータが実行できる形（実行ファイル）に変換する作業をコンパイルと呼びます。外国語の本を日本語に翻訳してから読むのと同じイメージです。

GnuCOBOL は、COBOL のソースをいったん C 言語のソースに変換し、さらに C コンパイラ（gcc）で実行ファイルにします。この流れは cobc が自動で行うので、私たちは意識する必要はありません。

flowchart LR A["COBOLソース
hello.cob"] --> B["cobc
GnuCOBOL"] B --> C["C言語のソース
自動で作られる"] C --> D["gcc
Cコンパイラ"] D --> E["実行ファイル
hello"] E --> F["実行して
画面に表示"]

図の説明: GnuCOBOL でプログラムが動くまでの流れです。私たちが書くのは左端の COBOL ソースだけで、途中の変換は cobc が自動で行います。

用語: ソースコードと実行ファイル

ソースコードは人間が書く「レシピ」、実行ファイルはそのレシピからできあがった「料理」にあたります。レシピ（hello.cob）を書き換えたら、もう一度コンパイルして料理（hello）を作り直す必要があります。

2.2 GnuCOBOLをインストールする

自分の OS に合わせて、次のいずれかの手順を進めてください。どの OS でも、最後の「確認」で cobc --version が表示されれば成功です。コマンドは、ターミナル（端末）と呼ばれる文字で命令を入力する画面に入力します。

お使いの OS 方法 主なコマンド
Windows WSL2 の Ubuntu を使う（推奨） sudo apt install gnucobol
macOS Homebrew を使う brew install gnucobol
Linux（Ubuntu） apt を使う sudo apt install gnucobol

Windows の場合（WSL2 の Ubuntu を使う）

WSL2（Windows Subsystem for Linux）は、Windows の中で Linux を動かす仕組みです。GnuCOBOL は Linux の環境がもっとも簡単に導入できるため、Windows ではこの方法をおすすめします。

  1. スタートメニューで「PowerShell」を右クリックし、管理者として実行する。
  2. 次のコマンドを入力して Enter キーを押し、画面の指示に従って Windows を再起動する。
PowerShell（管理者） 
wsl --install
  1. 再起動後、スタートメニューから「Ubuntu」を起動する。初回はユーザー名とパスワードの設定を求められるので、好きなものを入力する（パスワードは入力しても画面に表示されません）。
  2. Ubuntu の画面で、次の2つのコマンドを順に実行する。
Ubuntu のターミナル 
sudo apt update
sudo apt install gnucobol

パスワードを聞かれたら手順3で決めたものを入力します（画面には表示されません）。「続行しますか? [Y/n]」と出たら Y を入力して Enter キーを押します。

macOS の場合（Homebrew を使う）

Homebrewは、macOS 用のソフトウェア管理ツールです。まだ入れていない場合は、Homebrew の公式サイトの手順で先にインストールしてください。「ターミナル」アプリを開き、次のコマンドを実行します。

macOS のターミナル 
brew install gnucobol

Linux（Ubuntu）の場合

ターミナルを開き、Windows（WSL2）の場合と同じ2つのコマンドを実行します（パスワードを聞かれたら自分のログインパスワードを入力し、「続行しますか? [Y/n]」と出たら Y を入力して Enter キーを押します）。

Ubuntu のターミナル 
sudo apt update
sudo apt install gnucobol

インストールできたか確認する

次のコマンドでバージョンが表示されれば、インストール成功です。

バージョンの確認 
cobc --version
実行結果の例 実行結果 
cobc (GnuCOBOL) 3.1.2.0
Copyright (C) 2020 Free Software Foundation, Inc.
License GPLv3+: GNU GPL version 3 or later <https://gnu.org/licenses/gpl.html>
（以下、数行続きます）

ヒント: バージョンが少し違っても大丈夫

上の表示は Ubuntu 24.04 で確認したもの（3.1.2.0）です。macOS の Homebrew では 3.2 系が入ることがあります。3.x であればどれでも本ガイドのコードはそのまま動くので、数字が違っていても気にしないでください。ただし、エラーメッセージの文面や表示のしかたは版によって少し異なることがあります（ファイル名:行番号: の部分は共通です）。

注意: 「command not found」と出たら

cobc: command not found（コマンドが見つかりません）と表示された場合は、インストールが完了していないか、ターミナルを開き直す必要があります。いったんターミナルを閉じて開き直し、もう一度 cobc --version を試してください。それでも出る場合は、インストールのコマンドにエラーが出ていないかを見直します。Windows の場合は、PowerShell ではなく Ubuntu のターミナルで入力しているかも確認してください（GnuCOBOL は WSL の Ubuntu の中に入っているためです）。

2.3 エディタを準備する

第1章で見たとおり、COBOL は行の何桁目に書くかに意味がある言語です。そこで、桁の位置が一目で分かるようにエディタを設定しておきます。ここでは無償の Visual Studio Code（VS Code）を使います。公式サイトからダウンロードしてインストールしてください（Windows の場合は、Ubuntu の中ではなく Windows 側にインストールします）。

COBOL 用の拡張機能を入れる

VS Code の左端にある拡張機能のアイコン（四角が並んだマーク）を開き、「COBOL」で検索して、COBOL の色分け表示（シンタックスハイライト）を提供する拡張機能を入れます（例: Bitlang の「COBOL」）。予約語に色が付いて読みやすくなります。Bitlang の拡張機能を入れると COBOL ファイルでは同じ縦線が自動で表示されますが、入れない場合や確実にしたい場合に次の設定をします。

Windows（WSL2）の場合は、Ubuntu のターミナルで code . と入力すると、Windows 側の VS Code が WSL に接続された状態で開きます（初回は自動的に必要な部品が入ります。作業フォルダは 2.4 で作ります）。接続した画面で拡張機能を開き、COBOL 拡張の「WSL: Ubuntu にインストール」ボタンを押してください（ローカルに入れただけでは WSL 側で有効になりません）。

桁の目印と空白の設定

VS Code の設定ファイル（settings.json）に、次の3つを書いておくと便利です。VS Code で Ctrl + Shift + P（Mac は Cmd + Shift + P）を押し、「Open User Settings (JSON)」を選ぶと開けます。ファイルが {} だけなら丸ごと置き換え、すでに設定がある場合は { } の内側に3行を足し、前の行の末尾にカンマ（,）を付けてください。

settings.json 設定ファイル 
{
  "editor.rulers": [6, 7, 11, 72],
  "editor.insertSpaces": true,
  "files.encoding": "utf8"
}
設定 意味
editor.rulers 画面に縦線（ルーラー）を引く桁位置。6桁目（一連番号領域の終わり）・7桁目（標識領域）・11桁目（A領域の終わり）・72桁目（これより右の73桁目以降はコンパイラに無視される。文字列の途中で超えるとエラーになるが、それ以外は何も言われずに無視されるので要注意）の目印になる
editor.insertSpaces Tab キーを押したとき、タブ文字ではなく半角スペースを入力する（COBOL ではタブ文字は使わない）
files.encoding ファイルの文字コードを UTF-8 にする（日本語を画面に表示するため）

文字コードを確認する

文字コードは、文字をファイルに記録するときの約束事です。本ガイドは UTF-8 で統一します。保存形式が違うと、プログラムはコンパイルできても、日本語が画面で文字化けすることがあります（エラーは出ません）。次の方法で確認できます。

  • VS Code: ファイルを開いたとき、画面の右下（ステータスバー）に UTF-8 と表示されていれば問題ありません。
  • ターミナル（WSL・macOS・Linux）: file hello.cob と入力します。UTF-8 を含む表示（例: hello.cob: Unicode text, UTF-8 text）になれば UTF-8 で保存されています。
  • ターミナル側の設定: locale と入力したときの LANG= の行が UTF-8 で終わっていれば、ターミナルも UTF-8 です。

日本語だけがおかしく表示されるときは、まずソースファイルが UTF-8 で保存されているかを疑いましょう。

ヒント: 桁の意味は第3章で学びます

「6桁目」「7桁目」「A領域」といった言葉は、今はまだ分からなくて大丈夫です。この章では「コード例の行頭の空白を、そのまま写して入力する」ことだけ守れば動きます。縦線の意味は、第3章で一緒に確認しましょう。

2.4 最初のプログラムを動かす

準備ができたので、最初のプログラムを作ります。作業の流れは次の4ステップです。

flowchart LR A["1. 作業フォルダを作る
cobol-study"] --> B["2. hello.cob を書く"] B --> C["3. コンパイルする
cobc -x hello.cob"] C --> D["4. 実行する
./hello"]

図の説明: プログラムを動かすまでの4ステップです。以降の章でも、この流れを何度も繰り返します。

ステップ1: 作業フォルダを作る

本ガイドのプログラムを入れる専用のフォルダ cobol-study を作り、その中に移動します。ターミナル（Windows の場合は Ubuntu のターミナルで、PowerShell ではありません）で次のコマンドを実行してください（mkdir はフォルダを作る、cd はそのフォルダに移動する命令です）。

作業フォルダの作成 
mkdir cobol-study
cd cobol-study
code .

最後の code . は、このフォルダを VS Code で開く命令です（macOS・Linux の場合は、VS Code の「フォルダーを開く」メニューから開いても構いません。Windows は必ず Ubuntu のターミナルで code . を使ってください。Windows 側のフォルダを開くと、Ubuntu 内の cobol-study とは別の場所になってしまいます）。macOS で「command not found: code」と出る場合は、VS Code のコマンドパレットで「Shell Command: Install 'code' command in PATH」を実行するか、「フォルダーを開く」で cobol-study を開いてください。

ステップ2: hello.cob を書く

VS Code で新しいファイルを作り、hello.cob という名前で保存します。拡張子 .cob は COBOL のソースファイルであることを表します。次の内容を、行頭の空白も含めてそのまま入力してください。

hello.cob 完全なプログラム 
      * はじめてのCOBOLプログラム（挨拶を表示する）
       IDENTIFICATION DIVISION.
       PROGRAM-ID. HELLO.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "Hello, COBOL!".
           DISPLAY "はじめてのCOBOLです。".
           STOP RUN.

行頭の空白の数は、1行目のコメントが6個（そのあとに *）、IDENTIFICATION などの見出しが7個、DISPLAY と STOP RUN. が11個です。Tab キーを使うと設定によってはずれるので、半角スペースで入力しましょう。

ステップ3・4: コンパイルして実行する

ターミナルで hello.cob があるフォルダにいることを確認し、次のコマンドを順に実行します。-x は「実行ファイルを作る」という指定です。

コンパイルと実行 
cobc -x hello.cob
./hello
実行結果 実行結果 
Hello, COBOL!
はじめてのCOBOLです。

動作確認

  • ・コンパイルがうまくいくと、何も表示されずにコマンド入力待ちに戻ります（エラーが出なければ成功です）。
  • ・フォルダに hello という実行ファイルができています（ls で確認できます）。
  • ・./hello と入力すると、上の2行が表示されます。

ヒント: コンパイル時に出る2行の警告は無視してよい

Ubuntu 24.04（WSL の Ubuntu を含む）では、コンパイルのたびに次の2行が表示されることがあります。

<command-line>: warning: "_FORTIFY_SOURCE" redefined
<command-line>: note: this is the location of the previous definition

これは COBOL のプログラムの誤りではなく、裏で動く C コンパイラ（gcc）の設定が重なっているために出る表示です。実行ファイルは正常に作られ、動作にも影響しないので無視して構いません。見るべきなのは、hello.cob:6: のようにファイル名:行番号:で始まる行です。これが COBOL の警告やエラーです。

各行の役割

詳しい仕組みは第3章で学びます。ここでは「だいたいこういう意味」をつかんでおきましょう。

行 役割
* はじめての… 7桁目が * の行はコメント。人間向けのメモで、実行には影響しない
IDENTIFICATION DIVISION. 「ここからプログラムの名前などを書く部分（見出し部）です」という宣言
PROGRAM-ID. HELLO. プログラムの名前を HELLO にする
PROCEDURE DIVISION. 「ここから実際の処理の手順（手続き部）を書きます」という宣言
MAIN-PROC. 処理のまとまりに付けた名前（段落）。ここから処理が始まる
DISPLAY "…". ダブルクォートで囲んだ文字を画面に表示する
STOP RUN. プログラムを終了する

重要ポイント

COBOL の文はピリオド（.）で終わるのが基本です。また、ソースを書き換えたら必ず再コンパイルしてから実行します。「直したのに結果が変わらない」ときは、再コンパイルを忘れていないか確認しましょう。

ヒント: 中身の C 言語を見てみたい人へ

cobc -C hello.cob と実行すると、実行ファイルは作らず、変換後の C 言語のソース hello.c（と補助ファイル hello.c.h・hello.c.l.h）だけが作られます。2.1 の図で「自動で作られる」と説明した部分です。内容を理解する必要はありませんが、好奇心があればのぞいてみてください。

2.5 エラーに慣れよう

プログラムを書いていると、コンパイルが通らずにエラーが出ることがよくあります。これは失敗ではなく、「ここがおかしいですよ」とコンパイラが教えてくれているのです。エラーに慣れておくと、この先の学習がぐっと楽になります。

エラーメッセージの読み方

GnuCOBOL のエラーメッセージは、次の形をしています。

エラーメッセージの形式 
ファイル名:行番号: 種類: 内容
（例）hello.cob:6: error: unknown statement 'DISPLY'
部分 意味
hello.cob 問題があったファイル名
6 問題があった行番号（VS Code の左端に表示される番号と同じ）
error 種類。error は実行ファイルが作れない重大な問題、warning は作れるが注意が必要な点
unknown statement 'DISPLY' 内容（英語）。「知らない命令 DISPLY があります」という意味

まず行番号を見て、その行（と、その少し前の行）を確認するのが基本です。英語の内容が分からなくても、行番号だけで原因の場所を絞り込めます。

ヒント: 警告も見られるようにする

コンパイルのとき cobc -x -Wall hello.cob のように -Wall を付けると、「動くけれど怪しい書き方」の警告（warning）も主なものが表示されます。これから先、-Wall 付きでコンパイルする習慣をつけておくと、不具合を早く見つけられます。

わざと間違えてみよう

hello.cob を次のように1か所だけ書き換えて、コンパイルしてみましょう。確認が終わったら元に戻してください。なお、下の各抜粋の枠内で * で始まる1行目は説明用のコメントです。hello.cob では該当の1行だけを書き換えてください（コメント行を足すと行番号が1つずれます）。

失敗例1: 命令のスペルミス

6行目の DISPLAY を DISPLY（A が抜けた）に書き換えます。

hello.cob の6行目 PROCEDURE DIVISIONの抜粋 
      * DISPLAY が DISPLY になっている（誤り）
           DISPLY "Hello, COBOL!".
コンパイル結果 実行結果 
hello.cob: in paragraph 'MAIN-PROC':
hello.cob:6: error: unknown statement 'DISPLY'

1行目の「in paragraph 'MAIN-PROC'」は、「段落 MAIN-PROC の中で問題がありました」という場所の案内です。2行目で「6行目に、知らない命令 DISPLY がある」と教えてくれています。スペルを直せば解決です。

失敗例2: PROGRAM-ID のピリオド忘れ

3行目の PROGRAM-ID. HELLO. の最後のピリオドを消します。

hello.cob の3行目 IDENTIFICATION DIVISIONの抜粋 
      * 最後のピリオドが無い（誤り）
       PROGRAM-ID. HELLO
コンパイル結果 実行結果 
hello.cob:4: error: syntax error, unexpected PROCEDURE, expecting COMMON or EXTERNAL or RECURSIVE or INITIAL

問題があるのは3行目ですが、エラーは4行目と報告されています。コンパイラは「ピリオドがまだ来ない」と読み進め、次の行の PROCEDURE に出会って初めて「おかしい」と気づくためです。エラーの行番号は「問題に気づいた行」であり、原因は1つ前の行にあることも多い、と覚えておきましょう。メッセージの意味（「PROCEDURE が予想外です」）が難しいときも、前の行の書き終わり方を疑うのがコツです。

失敗例3: 桁ずれ（行の先頭から書いてしまう）

6行目の DISPLAY の行頭の空白をすべて消して、1桁目から書き始めてみます。

hello.cob の6行目 PROCEDURE DIVISIONの抜粋 
      * 1桁目から書いている（誤り）
DISPLAY "Hello, COBOL!".
コンパイル結果 実行結果 
hello.cob:6: error: invalid indicator 'Y' at column 7

「7桁目（標識領域）に Y という不正な文字があります」という意味です。DISPLAY の 7 文字目が Y で、ちょうど7桁目にあたるためです。7桁目に置ける文字は決まっています（本ガイドで使うのは * とスペースだけで、ほかに行の続きを表す - などがあります）。桁位置のルールは第3章で詳しく学びます。

失敗例4: 存在しない名前を使う

6行目を DISPLAY WS-MSG. に書き換えてみます（WS-MSG という入れ物はまだどこにも用意していません）。

コンパイル結果 実行結果 
hello.cob: in paragraph 'MAIN-PROC':
hello.cob:6: error: 'WS-MSG' is not defined

is not defined は「定義されていません」という意味です。データを入れる箱（データ項目）は、使う前に用意しなければなりません。第4章で学ぶ内容につながる、大切なエラーです。

失敗例5: ファイルが見つからない

ファイル名を打ち間違えたり、hello.cob がない場所でコンパイルしたりすると、プログラムの中身を読む前にこのエラーになります。ここでは cobc -x helo.cob（l が1つ足りない）と入力した例です。

コンパイル結果 実行結果 
cobc: helo.cob: No such file or directory

No such file or directory は「そのようなファイルはありません」という意味です。ls で今のフォルダにあるファイルを確認し、名前のつづりと、作業フォルダ（cobol-study）にいるかどうかを見直しましょう。

直す手順を習慣にしよう

flowchart TD A["ソースを書く・直す"] --> B["cobc -x -Wall で
コンパイル"] B --> C{"エラーが出た？"} C -->|はい| D["行番号と内容を読む"] D --> E["その行と
1つ前の行を確認"] E --> A C -->|いいえ| F["./実行ファイル名 で実行"] F --> G{"期待どおりの結果？"} G -->|いいえ| A G -->|はい| H["完成"]

図の説明: プログラミングの基本サイクルです。「書く → コンパイル → エラーを読んで直す」をぐるぐる回しながら完成に近づけます。

注意: 目に見えない原因に気をつけよう

次のような「見た目では分かりにくい」ミスが、エラーの原因になりやすいので注意してください。

  • ・全角スペースの混入: DISPLAY　"Hello" のように、命令と文字列（ダブルクォートで囲んだ部分）の間に全角スペースが入ると unknown statement 'DISPLAY　' というエラーになります。日本語入力をオンにしたまま入力しないようにしましょう。
  • ・全角の記号: ダブルクォート " やピリオド . を全角（” や ．）で入力しないこと。
  • ・タブ文字: 桁位置がずれます。必ず半角スペースで字下げします（2.3 の editor.insertSpaces 設定）。
  • ・72桁を超える行: 73桁目以降は無視されるため、長い文字列を書くと文字列の終わりが切れて、continuation character expected（継続文字＝文字列の続きを次の行に書くときの印が必要です。本ガイドでは使いません）や missing terminating " character などのエラーになります。行番号は超えた行の次の行で出ることもあります。日本語は1文字が3バイトなので、日本語を含む行は特に短く保ちましょう。

やってみよう 2-1: 自己紹介を3行表示しよう

プログラム名を JIKO、ファイル名を jiko.cob として、自己紹介を3行表示するプログラムを作ります。ローマ字の名前、趣味、目標を表示しましょう（内容は自由に変えて構いません）。

手順

  • 1 hello.cob をコピーして jiko.cob を作る（または新規作成する）。
  • 2 PROGRAM-ID を JIKO にし、DISPLAY の文を3つ並べる。
  • 3 cobc -x -Wall jiko.cob でコンパイルし、./jiko で実行する。

解答例

jiko.cob 完全なプログラム 
      * 自己紹介を3行表示するプログラム
       IDENTIFICATION DIVISION.
       PROGRAM-ID. JIKO.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "名前: TARO YAMADA".
           DISPLAY "趣味: 読書とランニング".
           DISPLAY "目標: COBOLをマスターする".
           STOP RUN.

実行結果

./jiko の実行結果 
名前: TARO YAMADA
趣味: 読書とランニング
目標: COBOLをマスターする

表示する文字列（"..." の中身）は、あなたの自己紹介に書き換えてください。日本語を入れる場合は、1行が72桁を超えないよう短めにします。

理解度確認クイズ

  • Q1. 「コンパイル」とは何をすることですか？ また、GnuCOBOL でコンパイルするコマンド名は何ですか？

    回答を表示

    人間が書いた COBOL のソースコードを、コンピュータが実行できる実行ファイルに変換（翻訳）することです。GnuCOBOL のコマンドは cobc で、cobc -x hello.cob のように実行します（-x は実行ファイルを作る指定）。

  • Q2. hello.cob を書き換えたのに、./hello の結果が変わりません。まず何を疑うべきですか？

    回答を表示

    再コンパイルを忘れていないかを疑います。実行されるのはソースではなく、コンパイルで作られた実行ファイル hello です。ソースを書き換えたら、もう一度 cobc -x hello.cob を実行して実行ファイルを作り直す必要があります。保存し忘れていないかも確認しましょう。

  • Q3. エラーメッセージ hello.cob:6: error: unknown statement 'DISPLY' から分かることを2つ挙げてください。

    回答を表示

    (1) 問題があるのは hello.cob の6行目（またはその直前）であること。(2) その行に知らない命令 DISPLY があること、つまり DISPLAY のスペルミスの可能性が高いこと。種類が error なので、実行ファイルは作られていません。

  • Q4. コンパイルエラーを避けるために、コードを入力するときに気をつけるべきことを3つ挙げてください。

    回答を表示

    次のうちから3つ挙げられれば正解です。(1) 行頭の空白の数（桁位置）をそろえる、(2) タブ文字を使わず半角スペースで字下げする、(3) 全角スペースや全角記号を混ぜない、(4) 1行を72桁以内に収める、(5) 文の終わりのピリオドを忘れない、(6) 命令のスペルを間違えない。
