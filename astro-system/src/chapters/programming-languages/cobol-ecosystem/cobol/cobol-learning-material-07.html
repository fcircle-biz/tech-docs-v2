第7章 所要時間: 約100分

プログラムに判断させる - IF・EVALUATEと条件名

ここまでのプログラムは、書いた順に上から下へ進むだけでした。この章では「60点以上なら合格、そうでなければ不合格」のように、条件によって処理を切り替える方法を学びます。IF と EVALUATE、条件に名前を付ける「条件名」、そして COBOL の最重要ルールのひとつであるピリオドとスコープ終了符の使い分けを身につけましょう。

この章で学ぶこと

  • IF〜ELSE〜END-IF と比較条件・AND/OR/NOT で、処理を分岐できる
  • IF の内側にピリオドを書くと何が起きるかを説明し、スコープ終了符（END-IF など）で正しく閉じられる
  • EVALUATE で多方向の分岐（WHEN・WHEN OTHER・THRU）を読みやすく書ける
  • 条件名（88レベル）とクラス条件（IS NUMERIC）で、読みやすい条件と入力チェックを書ける

7.1 IF〜ELSE〜END-IF - 「もし〜なら」で分かれ道を作る

プログラムの分岐とは、「条件が成り立つかどうか」で、実行する処理を切り替えることです。道の分かれ道で「雨なら電車、晴れなら自転車」と選ぶのと同じ考え方で、COBOL では IF 文を使います。

flowchart TD A["点数を受け取る"] --> B{"60点以上か？"} B -->|"はい"| C["合格です を表示"] B -->|"いいえ"| D["不合格です を表示"] C --> E["次の処理へ"] D --> E

図の説明: IF 文の流れです。ひし形の「条件」が成り立てば左の道、成り立たなければ右の道（ELSE）を進み、最後は合流して次の処理へ進みます。

この流れをそのままプログラムにしたものが次の例です。キーボードから点数を入力し、60点以上なら「合格です」、そうでなければ「不合格です」と表示します。

grade.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. GRADE.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-SCORE        PIC 9(3) VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 点数を入力して合格か不合格かを判定する
           DISPLAY "点数: " WITH NO ADVANCING
           ACCEPT WS-SCORE
           IF WS-SCORE >= 60
               DISPLAY "合格です"
           ELSE
               DISPLAY "不合格です"
           END-IF
           STOP RUN.

この章のプログラムは、手続き部のピリオドを段落の最後（STOP RUN.）にだけ置く書き方にしています。これまでの章のように命令文ごとにピリオドを付けても動きますが、IF などの内側にピリオドを書くと危険です。理由とルールは 7.4 で説明します。

保存して cobc -x grade.cob でコンパイルし、./grade で実行します。点数に 75 と 40 を入力して2回実行した結果は次のとおりです（点数の右側の数字は、キーボードから入力した値です）。

実行結果（75 を入力） 
点数: 75
合格です
実行結果（40 を入力） 
点数: 40
不合格です
書く部分 役割
IF 条件 分岐の始まり。条件が成り立つとき、次の行から ELSE（なければ END-IF）の手前までを実行する
ELSE 「そうでなければ」。条件が成り立たないときに実行する部分の始まり（不要なら省略できる）
END-IF IF 文の終わりを示す印（スコープ終了符）。7.4 で詳しく学ぶ

ヒント: 字下げ（インデント）は人間のために付ける

IF の中の命令を4桁ぶん右にずらしているのは、人間が「ここからここまでが IF の中」と見分けやすくするためです。命令を書き始める B 領域（12桁目以降）の中で、何桁右にずらすかはコンパイラは見ていません。IF がどこで終わるかを決めるのは、字下げではなく END-IF とピリオドです。この違いが 7.4 で重要になります。

7.2 比較条件 - 「等しい」「より大きい」をどう書くか

IF のあとに書く「条件」の基本は、2つの値を比べる比較条件です。記号でも、英語の言葉でも書けます。どちらを使っても意味は同じで、現場のプログラムでは両方が混在しています。

意味 記号 英語表記
等しい = EQUAL TO
等しくない NOT = NOT EQUAL TO
より大きい > GREATER THAN
より小さい（未満） < LESS THAN
以上 >= GREATER THAN OR EQUAL TO
以下 <= LESS THAN OR EQUAL TO

英語表記には IS を添えて IF WS-A IS LESS THAN 20 のように書くこともできます（IS は読みやすくするための言葉で、意味は変わりません）。次のコードを、WS-A が 10、WS-NAME が "TANAKA" の状態で実行してみます。データ部では 01 WS-A PIC 9(2) VALUE 10. と 01 WS-NAME PIC X(6) VALUE "TANAKA". を定義し、手続き部の先頭に PROCEDURE DIVISION. と MAIN-PROC.、末尾に STOP RUN. を補って1本のファイルにすると動かせます。

比較条件の例（cmp.cob（部品 1/1） PROCEDURE DIVISIONの抜粋 
      * いろいろな比較条件
           IF WS-A NOT = 5
               DISPLAY "A は 5 ではない"
           END-IF
           IF WS-A IS LESS THAN 20
               DISPLAY "A は 20 より小さい"
           END-IF
           IF WS-NAME = "TANAKA"
               DISPLAY "名前は TANAKA"
           END-IF
           IF WS-NAME = "TANAKA  "
               DISPLAY "短い側は空白で補って比べる"
           END-IF
実行結果 
A は 5 ではない
A は 20 より小さい
名前は TANAKA
短い側は空白で補って比べる

最後の例に注目してください。WS-NAME は6桁の英数字項目ですが、比べる相手が "TANAKA[ ]"（[ ] の中の末尾に空白2つ）と長さが違っても、短いほうの右側を空白で補って比べるため、等しいと判定されます。英数字の比較では、末尾の空白の有無だけが違う場合は等しいと判定される、と覚えておきましょう。

ヒント: 「以上」と「より大きい」を取り違えない

「60点以上」は >= 60、「60点より大きい」は > 60 です。ちょうど60点の人が合格になるかどうかが変わります。条件を書いたら、境目の値（この例では59・60・61）で動かして確かめる習慣をつけましょう。また、記号の前後には必ず半角スペースを入れます。COBOL の決まりでは比較記号の前後に空白が必要です。GnuCOBOL では WS-SCORE>=60 のようにくっつけても通ってしまうことがありますが、規格や他の処理系、現場の規約では問題になるため、半角スペースを入れる習慣をつけましょう。

7.3 複数条件 - AND・OR・NOT

「18歳以上で、かつ3,000円以上の購入」のように、条件を組み合わせたいときは AND・OR・NOT を使います。

書き方 意味 たとえるなら
条件1 AND 条件2 両方とも成り立つとき 入場条件が「チケットを持ち、かつ、受付を済ませた人」
条件1 OR 条件2 どちらか一方でも成り立つとき 割引の対象が「学生、または、65歳以上の人」
NOT 条件 成り立たないとき（反対） 「雨ではないとき」

次の例は、WS-AGE（年齢）が20、WS-AMOUNT（購入金額）が5000の状態で、条件を組み合わせて判定します。データ部では 01 WS-AGE PIC 9(3) VALUE 20. と 01 WS-AMOUNT PIC 9(6) VALUE 5000. を定義します。次の2つのコードは、それぞれ単独では動きません。順につなげ、先頭に IDENTIFICATION DIVISION.・PROGRAM-ID. LOGIC.・DATA DIVISION.・WORKING-STORAGE SECTION. とデータ定義、PROCEDURE DIVISION. と MAIN-PROC.、末尾に STOP RUN. を補って1つのファイルに保存します。

AND・OR・NOT（logic.cob（部品 1/2） PROCEDURE DIVISIONの抜粋 
      * AND・OR・NOT・英語表記の比較
           IF WS-AGE >= 18 AND WS-AMOUNT >= 3000
               DISPLAY "AND: 成人かつ3000円以上"
           END-IF
           IF WS-AGE < 18 OR WS-AMOUNT >= 3000
               DISPLAY "OR: 未成年または3000円以上"
           END-IF
           IF NOT WS-AMOUNT = 0
               DISPLAY "NOT: 金額は0円ではない"
           END-IF
英語表記と括弧（logic.cob（部品 2/2） PROCEDURE DIVISIONの抜粋 
      * 英語表記と括弧を使った条件
           IF WS-AMOUNT GREATER THAN OR EQUAL TO 5000
               DISPLAY "英語表記: 5000円以上"
           END-IF
           IF (WS-AGE < 18 OR WS-AGE >= 65) AND WS-AMOUNT >= 3000
               DISPLAY "括弧: 割引対象の年齢で3000円以上"
           END-IF
実行結果 
AND: 成人かつ3000円以上
OR: 未成年または3000円以上
NOT: 金額は0円ではない
英語表記: 5000円以上

最後の括弧つきの条件は、年齢が20歳で「18歳未満」にも「65歳以上」にも当てはまらないため成り立たず、何も表示されません。条件を組み合わせるときの注意点は2つあります。

計算の優先順位がある

AND と OR が混ざると、NOT → AND → OR の順に判定されます。算数で「足し算より掛け算が先」なのと同じです。

迷ったら括弧で明示する

AND と OR を混ぜるときは、先に判定したい部分を ( ) で囲みます。読む人も迷わず、意図しない判定も防げます。

7.4 ピリオドとスコープ終了符 - 最重要ルール

ここが本ガイドでいちばん大切な節です。COBOL の初心者が最もつまずき、現場でも古くから不具合の原因になってきたのがピリオド（.）の扱いです。

ピリオドは「文全体の終わり」

第3章で、ピリオドは「文の終わり」を表すと学びました。IF 文の場合、ピリオドは「開いているすべての IF を、ここで一気に閉じる」という強い意味を持ちます。つまり、IF の途中にピリオドを書くと、IF がそこで終わってしまうのです。

これに対し、END-IF のようなスコープ終了符は、「この IF だけを閉じる」印です。ピリオドと違って、ほかの文には影響しません。

誤った例1: IF の途中にピリオドを書いてしまった

「60点以上のとき、合格と表示し、合格者数に1を足す」つもりで書いたプログラムです。WS-SCORE の初期値は40点（不合格）にしてあります。字下げを見ると、ADD 1 TO WS-PASS-COUNT も IF の中に見えますが、どうなるでしょうか。

bad1.cob（誤り） 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. BAD1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-SCORE        PIC 9(3) VALUE 40.
       01  WS-PASS-COUNT   PIC 9(3) VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 誤り: IF の途中にピリオドを書いている
           IF WS-SCORE >= 60
               DISPLAY "合格です".
               ADD 1 TO WS-PASS-COUNT.
               DISPLAY "合格者数: " WS-PASS-COUNT
           STOP RUN.

cobc -x -Wall bad1.cob でコンパイルすると、エラーも警告も何も表示されずコンパイルできてしまいます。実行すると次のようになります。

実行結果（bad1 / 40点なのに合格者が1人になる） 
合格者数: 001

警告: エラーも警告も出ないまま、結果だけが間違う

40点は不合格なので「合格です」は表示されません。ところが 合格者数が 001 になっています。DISPLAY "合格です". の末尾のピリオドで IF が終わり、次の ADD 1 TO WS-PASS-COUNT. がIF の外に出て、点数に関係なく毎回実行されたからです。コンパイラは文法として正しいと判断するため、何も教えてくれません。

flowchart TD A{"60点以上か？"} -->|"はい"| B["合格です を表示"] B --> C["ピリオドで IF が終わる"] A -->|"いいえ"| C C --> D["合格者数に1を足す（常に実行）"] D --> E["合格者数を表示"]

図の説明: bad1.cob の本当の動きです。IF の中身は「合格です」の表示だけで、合格者数を足す処理は条件に関係なく必ず実行されます。

誤った例2: ピリオドと END-IF を混ぜた

では、END-IF も一緒に書いた場合はどうでしょうか。IF の内側にピリオドを残したまま、最後に END-IF を付けてみます。

bad2.cob（誤り） 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. BAD2.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-SCORE        PIC 9(3) VALUE 40.
       01  WS-PASS-COUNT   PIC 9(3) VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 誤り: ピリオドと END-IF を混ぜている
           IF WS-SCORE >= 60
               DISPLAY "合格です".
               ADD 1 TO WS-PASS-COUNT
           END-IF
           STOP RUN.

今度はコンパイルの段階でエラーになります。11行目のピリオドで IF がすでに終わっているのに、13行目に「閉じる相手のいない END-IF」が現れたためです。

コンパイル結果（bad2） 
bad2.cob: in paragraph 'MAIN-PROC':
bad2.cob:13: error: syntax error, unexpected END-IF

正しい例: END-IF で閉じ、内側にピリオドを書かない

正しくは、IF の内側の命令にはピリオドを付けず、END-IF で閉じます。同じ40点で実行してみましょう。

good1.cob（正しい） 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. GOOD1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-SCORE        PIC 9(3) VALUE 40.
       01  WS-PASS-COUNT   PIC 9(3) VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 正しい: END-IF で閉じ、内側にピリオド無し
           IF WS-SCORE >= 60
               DISPLAY "合格です"
               ADD 1 TO WS-PASS-COUNT
           END-IF
           DISPLAY "合格者数: " WS-PASS-COUNT
           STOP RUN.
実行結果（good1 / 40点なので合格者数は 0 のまま） 
合格者数: 000

今度は、合格者数が 0 のままです。ADD 1 TO WS-PASS-COUNT は IF の中にあるので、60点未満のときは実行されません。意図どおりの動きになりました。3つの例を並べて整理します。

プログラム 書き方 コンパイル 40点で実行した結果
bad1.cob IF の途中にピリオド（END-IF なし） 成功（警告なし） 合格者数 001（間違い）
bad2.cob IF の途中にピリオド＋END-IF 構文エラー 実行できない
good1.cob END-IF で閉じ、内側にピリオドなし 成功 合格者数 000（意図どおり）

重要ポイント: 本ガイドのピリオドのルール（この章以降ずっと守る）

  • 1. IF・EVALUATE・インライン PERFORM（END-PERFORM つき）・READ など、END-xxx（スコープ終了符）で閉じる文の内側には、絶対にピリオドを書かない。
  • 2. それ以外の単純な命令文（DISPLAY・MOVE・ADD など）は、これまでの章のように1文ごとにピリオドで終えてもよい。
  • 3. この章のプログラムのように、段落の最後の文（STOP RUN. など）にだけピリオドを置く書き方でもよい。どちらでも動く。
  • 4. 部・節の見出し、段落名（MAIN-PROC. など）、データ定義の末尾のピリオドは、常に必要。

この4つを守れば、ピリオドが原因の「条件が効かない」不具合はほとんど防げます。ピリオドが無くても、第3章で見たとおり1つの文の中に命令文を続けて書けるので、この章では段落の最後にだけ置く書き方にそろえています。第8章以降のプログラムには、単純な命令文の後ろにピリオドを置いたものもありますが、ルールは同じです。

ヒント: 古いプログラムを読むときの心構え

END-IF が使えるようになったのは COBOL 85 からです。それ以前に書かれたプログラムでは、ピリオドだけで IF を閉じる書き方が普通でした。現場で古いプログラムを保守するときは、「このピリオドはどこまでの IF を閉じているか」を意識して読むことが大切です。字下げではなく、ピリオドと END-IF を目印にしてください。

7.5 入れ子の IF とその読みにくさ

IF の中にさらに IF を書くことを入れ子（ネスト）と呼びます。「80点以上ならA、60点以上ならB、40点以上ならC、それ以外はD」と判定したいとき、IF だけで書くと次のようになります。点数は65点としています。

nest.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. NEST.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-SCORE        PIC 9(3) VALUE 65.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 入れ子のIF: 段が深くなって読みにくい
           IF WS-SCORE >= 80
               DISPLAY "評価: A"
           ELSE
               IF WS-SCORE >= 60
                   DISPLAY "評価: B"
               ELSE
                   IF WS-SCORE >= 40
                       DISPLAY "評価: C"
                   ELSE
                       DISPLAY "評価: D"
                   END-IF
               END-IF
           END-IF
           STOP RUN.
実行結果 
評価: B

正しく動きますが、分かれ道が増えるたびに字下げが右へ右へと深くなり、END-IF が3つも積み重なっています。どの ELSE がどの IF に対応するのか、読むだけで疲れてしまいます。このように「1つの値や条件で、いくつにも分かれる」場面のために用意されているのが、次の EVALUATE です。

ヒント: IF と EVALUATE の使い分け

「成り立つか成り立たないか」の二択なら IF、「3つ以上に分かれる」なら EVALUATE が読みやすくなります。IF の入れ子が2段を超えそうになったら、EVALUATE に書き換えられないか考えてみましょう。

7.6 EVALUATE - 多方向の分岐をすっきり書く

EVALUATE は、他の言語の switch 文や case 文にあたる命令です。「評価する」という名前のとおり、条件を上から順に調べ、最初に成り立った WHEN の処理だけを実行して、END-EVALUATE へ抜けます。

flowchart TD A["EVALUATE TRUE"] --> B{"WHEN 80点以上？"} B -->|"はい"| B1["評価A を表示"] B -->|"いいえ"| C{"WHEN 60点以上？"} C -->|"はい"| C1["評価B を表示"] C -->|"いいえ"| D{"WHEN 40点以上？"} D -->|"はい"| D1["評価C を表示"] D -->|"いいえ"| E["WHEN OTHER: 評価D を表示"] B1 --> Z["END-EVALUATE"] C1 --> Z D1 --> Z E --> Z

図の説明: EVALUATE は上の WHEN から順に調べ、最初に成り立ったところで処理を実行して終わります。どれにも当てはまらなければ WHEN OTHER（それ以外）が実行されます。

形1: EVALUATE TRUE - 条件を並べる

7.5 の入れ子の IF を EVALUATE に書き換えると、次のようにすっきりします。WHEN の後ろに条件を書くので、比較条件も AND/OR もそのまま使えます。EVALUATE TRUE は、WHEN に書いた条件のうち TRUE（真＝成り立つ）になるものを上から探す、という意味です。

eval1.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. EVAL1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-SCORE        PIC 9(3) VALUE 65.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 条件を上から順に調べる EVALUATE TRUE
           EVALUATE TRUE
               WHEN WS-SCORE >= 80
                   DISPLAY "評価: A"
               WHEN WS-SCORE >= 60
                   DISPLAY "評価: B"
               WHEN WS-SCORE >= 40
                   DISPLAY "評価: C"
               WHEN OTHER
                   DISPLAY "評価: D"
           END-EVALUATE
           STOP RUN.
実行結果 
評価: B

65点は「80点以上」には当てはまらず、次の「60点以上」で成り立つため、評価Bが表示されます。条件を書く順番が大切です。もし「40点以上」を先頭に書くと、65点も最初の WHEN で成り立ってしまい、評価Cになってしまいます。範囲の判定は、厳しい条件から順に並べましょう。

形2: EVALUATE 項目 - 値で振り分ける

1つの項目の値によって振り分けるときは、EVALUATE の後ろにその項目を書き、WHEN には比べる値だけを書きます。次の例は、会員ランクが "C" の状態で実行します。

eval3.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. EVAL3.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-RANK         PIC X    VALUE "C".
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 項目の値で振り分ける EVALUATE
           EVALUATE WS-RANK
               WHEN "A"
                   DISPLAY "ランクA: 特別会員"
               WHEN "B"
               WHEN "C"
                   DISPLAY "ランクB・C: 一般会員"
               WHEN OTHER
                   DISPLAY "ランク不明"
           END-EVALUATE
           STOP RUN.
実行結果 
ランクB・C: 一般会員

WHEN "B" の下に処理がなく、すぐ次の WHEN "C" が続いている点に注目してください。このように WHEN を続けて書くと、「B または C のとき」という意味になり、下の処理を共有できます。

範囲を指定する THRU

値の範囲は THRU（THROUGH でも同じ）で指定できます。1 THRU 3 は「1から3まで（1と3を含む）」です。月を四半期に振り分ける例を見てみましょう。

eval2.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. EVAL2.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-MONTH        PIC 9(2) VALUE 7.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * THRU で範囲を指定する
           EVALUATE WS-MONTH
               WHEN 1 THRU 3
                   DISPLAY "第1四半期"
               WHEN 4 THRU 6
                   DISPLAY "第2四半期"
               WHEN 7 THRU 9
                   DISPLAY "第3四半期"
               WHEN 10 THRU 12
                   DISPLAY "第4四半期"
               WHEN OTHER
                   DISPLAY "月が正しくありません"
           END-EVALUATE
           STOP RUN.
実行結果（WS-MONTH が 7 のとき） 
第3四半期

ヒント: WHEN OTHER は必ず書く習慣を

WHEN OTHER は「どの WHEN にも当てはまらなかったとき」の受け皿です。書かなくても文法エラーにはなりませんが、想定外の値（月が13など）が来たときに何も起きずに素通りしてしまうため、不具合に気づけません。「想定外の値のときはエラーを表示する」処理を置く習慣をつけましょう。

重要ポイント: EVALUATE も END-EVALUATE で閉じる

EVALUATE は END-EVALUATE で閉じます。WHEN の処理の内側にピリオドを書いてはいけません。書くと EVALUATE がそこで終わり、続く WHEN や END-EVALUATE が「閉じる相手のいない」構文エラーになります（誤った例2と同じです）。

7.7 条件名（88レベル）- 条件に名前を付ける

IF WS-MEMBER = "Y" と書いたとき、読む人は「"Y" って何だっけ？」と一瞬考えなければなりません。そこで COBOL には、「この値のとき」に名前を付ける仕組みがあります。これが条件名（88レベル）です。たとえるなら、「Y」という暗号に「会員である」というラベルを貼るようなものです。

データ部で、元になる項目の直後に、レベル番号 88 で条件名を定義します。条件名には VALUE で「どの値のときに真（成り立つ）になるか」を書きます。

flowchart LR A["WS-MEMBER
PIC X"] --> B["88 WS-MEMBER-YES
値が Y のとき真"] A --> C["88 WS-MEMBER-NO
値が N のとき真"]

図の説明: 88レベルの条件名は、直前の項目の「ある値」に名前を付けたものです。条件名自体は新しい箱ではなく、元の項目 WS-MEMBER を見ています。

cond88.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. COND88.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-MEMBER       PIC X VALUE "N".
           88  WS-MEMBER-YES   VALUE "Y".
           88  WS-MEMBER-NO    VALUE "N".
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 条件名で「会員かどうか」を読みやすく書く
           IF WS-MEMBER-YES
               DISPLAY "会員です"
           ELSE
               DISPLAY "会員ではありません"
           END-IF
      * SET で条件名を真にすると、元の項目に値が入る
           SET WS-MEMBER-YES TO TRUE
           DISPLAY "WS-MEMBER の中身: " WS-MEMBER
           IF WS-MEMBER-YES
               DISPLAY "会員になりました"
           END-IF
           STOP RUN.
実行結果 
会員ではありません
WS-MEMBER の中身: Y
会員になりました

ポイントは2つです。

条件として使う

IF WS-MEMBER-YES と、条件名だけを書きます。= "Y" は不要です。「会員なら」と読めるので、意味が一目で分かります。

SET で真にする

SET WS-MEMBER-YES TO TRUE と書くと、元の項目に "Y" が入ります。値そのものを書かなくてよいので、書き間違いを防げます。

ヒント: 条件名は EVALUATE でも使える

条件名は「成り立つか成り立たないか」を表すものなので、EVALUATE TRUE の WHEN WS-MEMBER-YES のようにも書けます（この章の実習で使います）。値の意味（"Y"・"N"・"1"・"2" など）はデータ部の1か所に集めておけば、手続き部は日本語のように読めて、値が変わったときの修正も1か所で済みます。

7.8 クラス条件 - 入力が数字かどうかを調べる

キーボードやファイルから受け取ったデータには、数字のはずの場所に文字が入っているなど、想定外の値が紛れ込むことがあります。そのまま計算に使うと、おかしな結果になったりプログラムが異常終了したりします。そこで、使う前にデータの種類を調べるのが クラス条件です。

書き方 真になる条件
IS NUMERIC すべての桁が数字（0〜9）である
IS ALPHABETIC 英字（A〜Z・a〜z）と空白だけである
IS NOT NUMERIC 数字以外が1文字でも含まれる

次のプログラムは、数量を4桁の英数字項目（PIC X(4)）で受け取って数字かどうかを確かめ、数字だけなら数字項目へ移して表示します。0012・AB12・12 と、3通りの入力で実行してみます。

numchk.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. NUMCHK.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-INPUT        PIC X(4) VALUE SPACE.
       01  WS-QTY          PIC 9(4) VALUE ZERO.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 数量を文字で受け取り、数字だけか確認する
           DISPLAY "数量: " WITH NO ADVANCING
           ACCEPT WS-INPUT
           IF WS-INPUT IS NUMERIC
               MOVE WS-INPUT TO WS-QTY
               DISPLAY "数量は " WS-QTY " です"
           ELSE
               DISPLAY "数字で入力してください"
           END-IF
           STOP RUN.
実行結果（0012 を入力） 
数量: 0012
数量は 0012 です
実行結果（AB12 を入力） 
数量: AB12
数字で入力してください
実行結果（12 だけを入力） 
数量: 12
数字で入力してください

警告: 「12」だけの入力は数字ではないと判定される

4桁の PIC X(4) に 12 と入力すると、残りの2桁は空白で埋められ、"12[ ]" になります。空白は数字ではないため、IS NUMERIC は偽になります。ゼロ埋めの 0012 のように桁数ぶん入力してもらうか、受け取り方を工夫する必要があります。数字項目（PIC 9(4)）へ直接 ACCEPT する方法は第5章で学んだとおりですが、数字以外を入力された場合の動作は処理系によって異なるため、現場では「英数字で受けて、調べてから数字へ移す」形がよく使われます。

実務例: 入力値の検証（数字か → 範囲内か → 計算）

実際の業務プログラムでは、受け取った値を「数字か」「決められた範囲内か」の順に確かめてから計算に使います。数字でないものに範囲の比較や掛け算を行うと、意味のない結果になったり異常終了したりするためです。次のプログラムは、数量（1〜100 が有効）を検証し、問題がなければ単価 250 円を掛けて合計金額を表示します。範囲は 88 レベルの条件名 QTY-OK で表し、検証の流れは IF を入れ子にして書いています。

valid.cob 完全なプログラム 
       IDENTIFICATION DIVISION.
       PROGRAM-ID. VALID.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-INPUT        PIC X(4) VALUE SPACE.
       01  WS-QTY          PIC 9(4) VALUE ZERO.
           88  QTY-OK      VALUE 1 THRU 100.
       01  WS-PRICE        PIC 9(4) VALUE 250.
       01  WS-TOTAL        PIC 9(6) VALUE ZERO.
       01  WS-OUT          PIC ZZZ,ZZ9.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 入力検証: 数字か → 範囲内か → 計算
           DISPLAY "数量(4桁): " WITH NO ADVANCING
           ACCEPT WS-INPUT
           IF WS-INPUT IS NOT NUMERIC
               DISPLAY "エラー: 数字以外が含まれています"
           ELSE
               MOVE WS-INPUT TO WS-QTY
               IF QTY-OK
                   COMPUTE WS-TOTAL = WS-QTY * WS-PRICE
                   MOVE WS-TOTAL TO WS-OUT
                   DISPLAY "合計金額: " WS-OUT
               ELSE
                   DISPLAY "エラー: 数量は1〜100です"
               END-IF
           END-IF
           STOP RUN.
実行結果（0012 を入力） 
数量(4桁): 0012
合計金額:   3,000
実行結果（AB12 を入力） 
数量(4桁): AB12
エラー: 数字以外が含まれています
実行結果（0150 を入力） 
数量(4桁): 0150
エラー: 数量は1〜100です
実行結果（0000 を入力） 
数量(4桁): 0000
エラー: 数量は1〜100です
入力数字か（IS NUMERIC）範囲内か（QTY-OK）結果
0012はいはい（12）合計 3,000 円を表示
AB12いいえ（調べない）数字以外のエラー
0150はいいいえ（150）範囲のエラー
0000はいいいえ（0）範囲のエラー

要点: 検証は「軽いものから順に」

先に IS NUMERIC で数字かどうかを確かめ、数字だと分かってから数字項目へ MOVE して範囲を調べます。順番を逆にすると、数字でない値を数として比較してしまいます。検証を通ったものだけを計算に回すのが、バッチ処理の基本形です。第14章の総合演習では、この検証に第6章の ON SIZE ERROR を組み合わせます。

やってみよう 7-1: 購入金額と会員区分から割引率を決めよう

文房具店のレジで、購入金額と会員区分から割引率を決め、お支払い金額を表示するプログラム disc.cob を作ります。EVALUATE と条件名（88レベル）を使いましょう。

割引のルール

会員区分 購入金額 割引率
会員10,000円以上10%
会員5,000円以上10,000円未満5%
会員5,000円未満2%
会員でない10,000円以上3%
会員でない10,000円未満0%

手順

  • 1 購入金額（PIC 9(6)）と会員区分（PIC X、"Y" なら会員）を ACCEPT で入力する。会員区分には条件名 WS-MEMBER-YES を定義する。
  • 2 EVALUATE TRUE で割引率（整数の%）を決める。条件は「厳しいほう（会員かつ高額）」から順に並べる。
  • 3 割引額を COMPUTE で求め、お支払い金額を編集項目 PIC ZZZ,ZZ9 で「お支払い: 10,800 円」のように表示する（Z で消えた先頭の桁が空白になるため、実際は お支払い:[ ]10,800 のように空白が2つ並びます）。
  • 4 「12000円・会員」「3000円・会員でない」など、境目の金額（4999・5000・10000）も含めて何通りか動かして確かめる。

解答例（データ部）

       WORKING-STORAGE SECTION.
      * 入力・割引率・支払額の項目
       01  WS-AMOUNT       PIC 9(6) VALUE ZERO.
       01  WS-MEMBER       PIC X    VALUE "N".
           88  WS-MEMBER-YES        VALUE "Y".
       01  WS-RATE         PIC 9(2) VALUE ZERO.
       01  WS-DISCOUNT     PIC 9(6) VALUE ZERO.
       01  WS-PAY          PIC 9(6) VALUE ZERO.
       01  WS-PAY-ED       PIC ZZZ,ZZ9.

解答例（手続き部 1/3: 入力）

disc.cob（部品 2/4） PROCEDURE DIVISIONの抜粋 
      * 購入金額と会員区分を入力する
           DISPLAY "購入金額: " WITH NO ADVANCING
           ACCEPT WS-AMOUNT
           DISPLAY "会員ですか(Y/N): " WITH NO ADVANCING
           ACCEPT WS-MEMBER

解答例（手続き部 2/3: 割引率の決定）

disc.cob（部品 3/4） PROCEDURE DIVISIONの抜粋 
      * 会員区分と金額から割引率(%)を決める
           EVALUATE TRUE
               WHEN WS-MEMBER-YES AND WS-AMOUNT >= 10000
                   MOVE 10 TO WS-RATE
               WHEN WS-MEMBER-YES AND WS-AMOUNT >= 5000
                   MOVE 5 TO WS-RATE
               WHEN WS-MEMBER-YES
                   MOVE 2 TO WS-RATE
               WHEN WS-AMOUNT >= 10000
                   MOVE 3 TO WS-RATE
               WHEN OTHER
                   MOVE 0 TO WS-RATE
           END-EVALUATE

解答例（手続き部 3/3: 計算と表示）

disc.cob（部品 4/4） PROCEDURE DIVISIONの抜粋 
      * 割引額と支払額を求めて表示する
           COMPUTE WS-DISCOUNT = WS-AMOUNT * WS-RATE / 100
           COMPUTE WS-PAY = WS-AMOUNT - WS-DISCOUNT
           MOVE WS-PAY TO WS-PAY-ED
           DISPLAY "割引率: " WS-RATE "%"
           DISPLAY "お支払い: " WS-PAY-ED " 円"

上の4つのコードは、それぞれ単独では動きません。順につなげて1つのファイルに保存します。先頭に IDENTIFICATION DIVISION. と PROGRAM-ID. DISC.、部品 1/4 の前に DATA DIVISION.、部品 2/4 の前に PROCEDURE DIVISION. と MAIN-PROC.、部品 4/4 の末尾に STOP RUN. を補って1本のファイルにまとめると、そのままコンパイルして動かせます。

理解度確認クイズ

  • Q1. 「点数が80点以上」を表す条件を、記号と英語表記の両方で書いてください。また、「80点より大きい」との違いは何ですか？

    回答を表示

    記号では WS-SCORE >= 80、英語表記では WS-SCORE GREATER THAN OR EQUAL TO 80 です。「以上（>=）」はちょうど80点を含み、「より大きい（>）」はちょうど80点を含みません。

  • Q2. 次のコードで、WS-SCORE が 40 のとき、「ADD 1 TO WS-PASS-COUNT」は実行されますか？ その理由も答えてください。
    IF WS-SCORE >= 60
        DISPLAY "合格です".
        ADD 1 TO WS-PASS-COUNT

    回答を表示

    実行されます。DISPLAY "合格です". の末尾のピリオドで IF 文がそこで終わってしまい、次の ADD 文は IF の外に出るためです。B 領域の中の字下げは見た目だけで、IF の終わりはピリオドと END-IF で決まります。正しくは、DISPLAY の後ろのピリオドを外し、IF を END-IF で閉じます。

  • Q3. EVALUATE TRUE で、WS-SCORE が 85 のとき「WHEN WS-SCORE >= 60」「WHEN WS-SCORE >= 80」の順に書くと、どうなりますか？

    回答を表示

    EVALUATE は上から順に調べ、最初に成り立った WHEN だけを実行します。85点は最初の「60点以上」で成り立つため、「80点以上」の処理には進みません。範囲を判定するときは、「80点以上」のように厳しい条件から先に書く必要があります。

  • Q4. 条件名（88レベル）の長所を1つ挙げてください。また、条件名を真にする命令は何ですか？

    回答を表示

    IF WS-MEMBER-YES のように、値の意味が名前で分かり、条件が日本語のように読めること（値の定義がデータ部の1か所に集まり、修正も1か所で済むことも長所です）。条件名を真にするには SET 条件名 TO TRUE を使い、元の項目にその値が入ります。
