ホーム COBOL入門 第9章
第9章 所要時間: 約90分

データをまとめて扱う - 集団項目とレベル番号

ここまでは、データ項目を1つずつ単独で定義してきました。しかし業務システムでは「日付・商品コード・数量・単価」のように、関連するデータを1つのかたまり（レコード）として扱うのが普通です。この章では、レベル番号で階層を持つレコードを定義する方法と、そのかたまりをまとめて操作する方法を学びます。第12章以降で使う「売上レコード」もここで登場します。

この章で学ぶこと

  • レベル番号（01・05・10）で階層を持つレコードを定義でき、集団項目と基本項目の違いを説明できる
  • 売上レコード SALES-REC（20バイト）を定義し、各項目の桁位置を説明できる
  • 集団項目への MOVE と INITIALIZE で、レコードをまとめて設定・初期化できる
  • FILLER で明細行を整形し、REDEFINES で同じ領域を別の見方で扱える

9.1 集団項目と基本項目

住所録のカードを思い浮かべてください。1枚のカードに「名前」「住所」「電話番号」が書かれていて、さらに「住所」は「都道府県」と「市区町村」に分けて書かれているかもしれません。COBOL のデータ定義も、これと同じように入れ物の中に入れ物を入れる形で書けます。

集団項目（グループ項目）

下にほかの項目をぶら下げている項目です。PIC 句を書きません。カード1枚、または「住所」のような小さなまとまりにあたります。

基本項目（エレメンタリ項目）

それ以上分けない、いちばん小さい項目です。PIC 句を書きます。「名前」「電話番号」のような記入欄1つ1つにあたります。

入れ物の上下関係は、レベル番号（項目の前に書く数字）で表します。数字が小さいほど「外側（親）」、大きいほど「内側（子）」です。

レベル番号 役割 書き始める桁
01 レコードや項目の最上位。02〜49 の項目は必ず 01 の下に入る（01 だけで PIC を持つ単独の項目にもできる。第4章） A領域（8桁目〜）
02〜49 01 の下の項目。数字が大きいほど内側。慣例として 05・10・15 のように飛ばして付ける B領域（12桁目〜）
77 単独の項目（第4章）。02〜49 の下位項目は持てない（88 の条件名は付けられる） A領域
88 条件名（第7章） B領域

たとえば住所録のカードは、次のように書けます。CUST-ADDR（住所）は PIC 句が無い集団項目で、その下に CUST-PREF（都道府県）と CUST-CITY（市区町村）がぶら下がっています。

住所録のカード DATA DIVISIONの抜粋 
      * 01が最上位。10は05の子、05は01の子
       01  CUSTOMER-REC.
           05  CUST-NAME     PIC X(10).
           05  CUST-ADDR.
               10  CUST-PREF PIC X(6).
               10  CUST-CITY PIC X(8).
           05  CUST-TEL      PIC X(11).
flowchart TD A["CUSTOMER-REC
レベル01・集団項目"] --> B["CUST-NAME
レベル05・基本項目"] A --> C["CUST-ADDR
レベル05・集団項目"] A --> D["CUST-TEL
レベル05・基本項目"] C --> E["CUST-PREF
レベル10・基本項目"] C --> F["CUST-CITY
レベル10・基本項目"]

図の説明: レコードを木の形で表した図です。枝の先にあたる基本項目だけが PIC 句を持ち、実際にデータが入ります。集団項目は「子を束ねる名前」です。

ヒント: レベル番号は連番でなくてよい

05 の次を 06 にせず、05・10・15 と飛ばして付けるのが慣例です。後から間に階層を足したくなったときに、番号を振り直さずに済みます。同じ親の下の兄弟は、同じレベル番号にそろえてください（上の例では CUST-PREF と CUST-CITY はどちらも 10）。

9.2 売上レコードを定義する

いよいよ、本ガイドの共通題材「文房具店の売上管理」の中心となる売上レコードを定義します。1件の売上を「日付・商品コード・数量・単価」の4つの項目で表します。この SALES-REC は、第12章（ファイル処理）・第13章（コピーブック）・第14章（売上集計バッチ）でも使うので、しっかり覚えておきましょう。

売上レコード DATA DIVISIONの抜粋 
      * 売上レコード（合計20バイト）
       01  SALES-REC.
           05  SR-DATE     PIC X(8).
           05  SR-ITEM     PIC X(4).
           05  SR-QTY      PIC 9(3).
           05  SR-PRICE    PIC 9(5).

集団項目の長さは、子の項目の長さを合計したものです。SALES-REC は 8 + 4 + 3 + 5 = 20バイト（20桁）になります。メモリ上では、4つの項目が隙間なく並んでいます。

項目 意味 桁位置 長さ 例（20261001A00100300120）
SR-DATE 売上日（YYYYMMDD） 1〜8 8 20261001
SR-ITEM 商品コード 9〜12 4 A001
SR-QTY 数量 13〜15 3 003
SR-PRICE 単価 16〜20 5 00120

つまり、20261001A00100300120 という20文字の並びは、「2026年10月1日に、商品 A001 が、3個、単価120円で売れた」という1件の売上を表しています。区切り記号は無く、決まった桁位置で切り分けるのが固定長レコードの特徴です。

重要ポイント: 集団項目のPICは「合成」される

集団項目には PIC 句を書きませんが、COBOL は子の項目を並べた全体を「長さ20の英数字」として扱います。この性質が、次の 9.3 の「まとめて MOVE」の鍵になります。なお、日付や商品コードのように計算に使わない項目は、数字だけの並びでも PIC X にするのが業務ではよく行われる定石です。

9.3 集団項目への MOVE

集団項目は、中身が数字項目であっても、全体をひとつの英数字の文字列として扱うというルールがあります。そのため、20桁の文字列を集団項目 SALES-REC に1回 MOVE するだけで、先頭から順に、8文字が SR-DATE、次の4文字が SR-ITEM、次の3文字が SR-QTY、残りの5文字が SR-PRICE に切り分けられて入ります。

salesrec.cob 完全なプログラム 
      * 売上レコードに20桁の文字列を一度に入れる
       IDENTIFICATION DIVISION.
       PROGRAM-ID. SALESREC.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  SALES-REC.
           05  SR-DATE     PIC X(8).
           05  SR-ITEM     PIC X(4).
           05  SR-QTY      PIC 9(3).
           05  SR-PRICE    PIC 9(5).
       PROCEDURE DIVISION.
       MAIN-PROC.
           MOVE "20261001A00100300120" TO SALES-REC.
           DISPLAY "レコード全体: " SALES-REC.
           DISPLAY "日付: " SR-DATE.
           DISPLAY "商品: " SR-ITEM.
           DISPLAY "数量: " SR-QTY.
           DISPLAY "単価: " SR-PRICE.
           STOP RUN.

動作確認

コンパイルと実行 
cobc -x salesrec.cob
./salesrec
実行結果 
レコード全体: 20261001A00100300120
日付: 20261001
商品: A001
数量: 003
単価: 00120

1回の MOVE で、20桁の文字列が桁位置どおりに4つの項目へ分かれました。これがファイルから1行読み込んだデータを項目ごとに使えるようになる仕組みの基本です（第12章）。

flowchart LR S["文字列
20261001A00100300120"] --> R["MOVE ... TO SALES-REC"] R --> D["SR-DATE
20261001"] R --> I["SR-ITEM
A001"] R --> Q["SR-QTY
003"] R --> P["SR-PRICE
00120"]

図の説明: 集団項目への MOVE は、文字列を先頭から子の項目の長さずつ順に切り分けて入れます。

同じ理屈で、親の集団項目と子の基本項目は同じ領域を重ねて共有しています。親を DISPLAY すれば全体が、子を DISPLAY すれば一部が表示されます。さらに階層を深くして、SR-DATE を年・月・日の集団項目にすることもできます。

salesrec.cob の DATA DIVISION を差し替え DATA DIVISIONの抜粋 
      * SR-DATEを年・月・日の集団項目にする
       01  SALES-REC.
           05  SR-DATE.
               10  SR-YYYY PIC X(4).
               10  SR-MM   PIC X(2).
               10  SR-DD   PIC X(2).
           05  SR-ITEM     PIC X(4).
           05  SR-QTY      PIC 9(3).
           05  SR-PRICE    PIC 9(5).

この定義で先ほどと同じ MOVE を実行して DISPLAY "日付(集団項目): " SR-DATE と DISPLAY "年: " SR-YYYY " 月: " SR-MM " 日: " SR-DD を表示すると、次のようになります。

実行結果 
日付(集団項目): 20261001
年: 2026 月: 10 日: 01

警告: 文字列が短いと、残りは空白で埋まる

集団項目への MOVE は英数字の MOVE なので、送り側が20桁より短いと右側が空白で埋められます。数字項目 SR-QTY にまで空白が入ってしまい、計算に使うと不正なデータになります。salesrec.cob の MOVE を MOVE "20261001A001" TO SALES-REC に変え、DISPLAY "レコード: [" SALES-REC "]" と DISPLAY "数量: [" SR-QTY "]" で表示すると次のようになります。

実行結果（12桁だけを MOVE した場合） 
レコード: [20261001A001        ]
数量: [   ]

レコードの長さ（桁数）とデータの長さはいつも一致させてください。

ヒント: 項目名の頭にレコードごとの接頭辞を付ける理由

COBOL では、親が違えば同じ項目名を使えますが、使うたびに「QTY OF OUT-REC」のように親を指定する必要が出て面倒です。そこで本ガイドでは SR-（売上）・IN-（入力）のようにレコードごとの接頭辞を付けて、項目名がレコード間で重ならないようにします。

9.4 FILLER: 名前の無い項目

FILLER（フィラー）は、「名前は付けないけれど、この桁数ぶんの場所を確保したい」ときに使う特別なデータ名です。表を作るときに、空欄の列を空けるイメージです。画面や帳票に出す行を作るとき、項目と項目の間の空白（区切り）や、固定の見出し文字を置くのにとても便利です。

見出し行と明細行を、同じ桁幅で作ってみましょう。見出し行の各項目の幅と、明細行の各項目の幅をそろえるのがコツです。

filldemo.cob 完全なプログラム 
      * FILLERで見出し行と明細行の列をそろえる
       IDENTIFICATION DIVISION.
       PROGRAM-ID. FILLDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-HEAD-LINE.
           05  FILLER       PIC X(6) VALUE "ITEM".
           05  FILLER       PIC X(5) VALUE "QTY".
           05  FILLER       PIC X(6) VALUE "PRICE".
       01  WS-DETAIL-LINE.
           05  WD-ITEM      PIC X(4).
           05  FILLER       PIC X(2) VALUE SPACE.
           05  WD-QTY       PIC ZZ9.
           05  FILLER       PIC X(2) VALUE SPACE.
           05  WD-PRICE     PIC ZZ,ZZ9.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY WS-HEAD-LINE.
           MOVE "A001" TO WD-ITEM.
           MOVE 3      TO WD-QTY.
           MOVE 1200   TO WD-PRICE.
           DISPLAY WS-DETAIL-LINE.
           STOP RUN.

動作確認

実行結果 
ITEM  QTY  PRICE
A001    3   1,200

見出しの「ITEM」「QTY」「PRICE」の位置と、明細の値の位置がそろって見えます。数量・単価は編集項目（ZZ9・ZZ,ZZ9）なので、右寄せで、上位のゼロが空白になり、桁区切りのカンマも付いています（編集項目は第5章）。

項目 見出し行（幅） 明細行（幅） 桁位置
商品コード FILLER X(6) WD-ITEM X(4) ＋ FILLER X(2) 1〜6
数量 FILLER X(5) WD-QTY ZZ9 ＋ FILLER X(2) 7〜11
単価 FILLER X(6) WD-PRICE ZZ,ZZ9 12〜17

ヒント: FILLER を使うときのポイント

  • ・FILLER は名前が無いので、名前を書いて値を参照・変更することはできません。値は VALUE 句で最初に決めます。ただし親の集団項目へ MOVE すると FILLER の部分も上書きされるので、見出し行などに MOVE SPACE しないようにしましょう。
  • ・区切りの空白は VALUE SPACE を付けておきます。付け忘れても GnuCOBOL では空白になります。規格・処理系によっては初期値が保証されないため、必ず VALUE を書く習慣をつけましょう。
  • ・COBOL 85 以降では、FILLER という語そのものを省略して、レベル番号と PIC だけを書くこともできます。本ガイドでは読みやすさのため FILLER を明記します。

9.5 INITIALIZE: まとめて初期化する

レコードを1件処理し終わったら、次の1件に備えて中身をきれいにしたくなります。項目が何十個もあるとき、1つずつ MOVE ZERO や MOVE SPACE を書くのは大変です。INITIALIZE は、集団項目の下にある基本項目を、型に応じてまとめて初期化してくれる命令です。

基本項目の種類 INITIALIZE した結果
数字項目（PIC 9 など） ゼロ
英数字項目（PIC X など） 空白
initdemo.cob 完全なプログラム 
      * INITIALIZEで集団項目をまとめて初期化する
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INITDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  SALES-REC.
           05  SR-DATE     PIC X(8).
           05  SR-ITEM     PIC X(4).
           05  SR-QTY      PIC 9(3).
           05  SR-PRICE    PIC 9(5).
       PROCEDURE DIVISION.
       MAIN-PROC.
           MOVE "20261001A00100300120" TO SALES-REC.
           DISPLAY "初期化前: [" SALES-REC "]".
           INITIALIZE SALES-REC.
           DISPLAY "初期化後: [" SALES-REC "]".
           DISPLAY "数量: " SR-QTY " 単価: " SR-PRICE.
           STOP RUN.

動作確認

実行結果 
初期化前: [20261001A00100300120]
初期化後: [            00000000]
数量: 000 単価: 00000

初期化後は、英数字の SR-DATE（8桁）と SR-ITEM（4桁）が空白12桁になり、数字の SR-QTY と SR-PRICE（合わせて8桁）がゼロになっています。

警告: レコード全体に MOVE SPACE してはいけない

「きれいにしたいから」と MOVE SPACE TO SALES-REC と書くと、数字項目にも空白が入ってしまい、あとで計算すると誤動作します。数字項目を含むレコードの初期化は、型に合わせて処理してくれる INITIALIZE を使いましょう。なお、FILLER は INITIALIZE の対象外なので、VALUE 句で決めた値がそのまま残ります。

9.6 REDEFINES: 同じ領域を別の見方で使う

20261001 という8桁の日付は、「ひとつの日付」として見ることも、「2026年・10月・01日」の3つに分けて見ることもできます。REDEFINES（リデファインズ）は、すでに定義した領域に別の名前と区切り方を付けて、同じ場所を別の見方で扱えるようにする句です。同じ1枚の紙に、「A4の1枚」と「上下2つの欄」の2通りの罫線を重ねて引くようなイメージです。

flowchart TB M["同じ8バイトの領域
20261001"] M --> V1["見方1: WS-DATE
8桁の数字"] M --> V2["見方2: WS-DATE-R
年4桁＋月2桁＋日2桁"] V2 --> Y["WS-YYYY
2026"] V2 --> MM["WS-MM
10"] V2 --> DD["WS-DD
01"]

図の説明: WS-DATE と WS-DATE-R は、メモリ上の同じ8バイトを指しています。新しい領域が増えるわけではありません。

redefdem.cob 完全なプログラム 
      * REDEFINESで日付を年・月・日に分けて見る
       IDENTIFICATION DIVISION.
       PROGRAM-ID. REDEFDEM.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-DATE         PIC 9(8) VALUE 20261001.
       01  WS-DATE-R REDEFINES WS-DATE.
           05  WS-YYYY     PIC 9(4).
           05  WS-MM       PIC 9(2).
           05  WS-DD       PIC 9(2).
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "日付: " WS-DATE.
           DISPLAY "年: " WS-YYYY.
           DISPLAY "月: " WS-MM.
           DISPLAY "日: " WS-DD.
           MOVE 12 TO WS-MM.
           DISPLAY "月だけ変更後: " WS-DATE.
           STOP RUN.

動作確認

実行結果 
日付: 20261001
年: 2026
月: 10
日: 01
月だけ変更後: 20261201

WS-MM（月）を 12 に変えると、同じ領域を共有している WS-DATE も 20261201 に変わりました。2つの名前は、同じものを指しているからです。

ヒント: REDEFINES の書き方のルール

  • ・REDEFINES は、再定義される項目（WS-DATE）の直後に書き、同じレベル番号にします（ここでは 01 と 01）。
  • ・再定義する側に VALUE 句は付けられません。初期値は元の項目に付けます。
  • ・再定義する側の長さは、元の長さと合わせます（ここでは 4 + 2 + 2 = 8桁）。

REDEFINES は、第10章で「初期値を持つ表」を作る定番テクニックとしても登場します。また、同じ領域に別の種類のデータが入りうる場合（たとえば、レコード種別によって後半の意味が変わるファイル）にもよく使われます。

9.7 MOVE CORRESPONDING（紹介）

2つの集団項目に同じ名前の項目があるとき、MOVE CORRESPONDING（略して MOVE CORR）を使うと、名前が一致する項目だけをまとめて移せます。順番や位置が違っていても、名前で対応づけられます。

corrdemo.cob 完全なプログラム 
      * MOVE CORRESPONDINGで同じ名前の項目だけ移す
       IDENTIFICATION DIVISION.
       PROGRAM-ID. CORRDEMO.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  IN-REC.
           05  ITEM-CODE   PIC X(4)  VALUE "A001".
           05  QTY         PIC 9(3)  VALUE 3.
           05  MEMO        PIC X(5)  VALUE "HELLO".
       01  OUT-REC.
           05  QTY         PIC 9(5)  VALUE ZERO.
           05  ITEM-CODE   PIC X(6)  VALUE SPACE.
       PROCEDURE DIVISION.
       MAIN-PROC.
           MOVE CORRESPONDING IN-REC TO OUT-REC.
           DISPLAY "[" ITEM-CODE OF OUT-REC "]".
           DISPLAY "[" QTY OF OUT-REC "]".
           STOP RUN.
実行結果 
[A001  ]
[00003]

名前が同じ ITEM-CODE と QTY だけが移り、OUT-REC に無い MEMO は無視されました。項目ごとの MOVE と同じルールで、英数字の ITEM-CODE は右側が空白で埋まり（4桁→6桁）、数字の QTY は左側がゼロで埋まっています（3桁→5桁）。ITEM-CODE と QTY は IN-REC と OUT-REC の両方にあるので、DISPLAY では OF OUT-REC と親の名前を付けて、どちらの項目かを指定しています（9.3 のヒントで触れた「修飾」）。

注意: 便利だが、現場では慎重に使う

どの項目が移るかが「名前の一致」という見えにくい条件で決まるため、項目を追加・名前変更したときに意図せず移る・移らなくなる事故が起きやすい命令です。現場のコーディング規約で禁止されている例もあります。本ガイドでは、項目ごとに MOVE を書く方法を基本にします。

やってみよう 9-1: 社員レコードを定義して明細行を表示しよう

次の仕様の社員レコードを定義し、1件のデータを1回の MOVE で入れ、FILLER で区切った明細行に整形して表示するプログラム empdemo.cob を作りましょう。

項目名 意味 PIC 桁位置
EM-NO 社員番号 X(5) 1〜5
EM-NAME 氏名（ローマ字） X(10) 6〜15
EM-DEPT 部署コード X(3) 16〜18
EM-SALARY 給与 9(6) 19〜24

手順

  • 1 上の表どおりに、01 レベルの EMP-REC と 05 レベルの4項目を定義する。
  • 2 表示用の EMP-LINE を作る。各項目の間に FILLER（空白2桁）を置き、給与は ZZZ,ZZ9 の編集項目にする。
  • 3 24桁の文字列 10001TANAKA SLS280000 を EMP-REC に MOVE する（TANAKA の後ろには半角スペースが4つ入る）。
  • 4 4つの項目を EMP-LINE の項目へ MOVE して、EMP-LINE を DISPLAY する。

解答例（2つの部品に分けて掲載します。それぞれ単独では動きません。順につなげて1つの empdemo.cob に保存します）

empdemo.cob（部品 1/2） DATA DIVISIONの抜粋

理解度確認クイズ

  • Q1. 集団項目と基本項目の違いは何ですか？ PIC 句を書くのはどちらですか？

    回答を表示

    集団項目は下にほかの項目をぶら下げている項目で、PIC 句は書きません。基本項目はそれ以上分けない最小の項目で、PIC 句を書きます。実際にデータの型と桁数を決めるのは基本項目です。

  • Q2. 売上レコード SALES-REC（SR-DATE X(8)、SR-ITEM X(4)、SR-QTY 9(3)、SR-PRICE 9(5)）の全体の長さは何バイトですか？ また SR-QTY は何桁目から何桁目ですか？

    回答を表示

    8 + 4 + 3 + 5 = 20バイトです。SR-DATE が1〜8桁、SR-ITEM が9〜12桁なので、SR-QTY は13〜15桁目になります。

  • Q3. MOVE "20261001A00100300120" TO SALES-REC を実行すると、SR-ITEM には何が入りますか？ なぜそうなりますか？

    回答を表示

    A001 が入ります。集団項目への MOVE は全体を英数字の文字列として扱い、先頭から子の項目の長さ（8桁、4桁、3桁、5桁）ずつ順に切り分けて入れるからです。9〜12文字目が SR-ITEM にあたります。

  • Q4. 数字項目を含むレコードを初期化したいとき、MOVE SPACE TO レコード名 ではなく INITIALIZE を使うべきなのはなぜですか？

    回答を表示

    MOVE SPACE だと数字項目にも空白が入り、計算に使うと不正なデータになるからです。INITIALIZE は基本項目の型に応じて、数字項目はゼロ、英数字項目は空白にしてくれます。
