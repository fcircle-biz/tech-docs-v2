SAMファイル - レコードと固定長・可変長を読み解く

第1章で見た12文字の売上明細レコードを、この章では一歩踏み込んで読み解きます。ファイル・レコード・項目の関係、SAMファイルと VSAM の違い、固定長と可変長（RECFM・LRECL・BLKSIZE）、そしてレコードレイアウトの読み方を学びます。最後に、PC 上で区切り文字のない固定長ファイルを実際に作り、中身を確かめます。この章で作るレコードレイアウト定義書は、修了成果物の①になります。

この章で学ぶこと

  • ファイル・レコード・項目の関係を、身近なたとえを使って説明できる
  • 固定長と可変長の違いと、RECFM・LRECL・BLKSIZE の意味を説明できる
  • レコードレイアウトから、項目の開始位置・終了位置・桁数を読み取れる
  • QSAM と VSAM の違いを説明できる
  • PC で固定長ファイルを作り、コマンドで中身を確かめられる

2.1 ファイル・レコード・項目 - 申込用紙のたとえ

データを扱うときに必ず出てくる言葉が、ファイル・レコード・項目の3つです。マス目のある申込用紙にたとえると分かりやすくなります。

申込用紙には、氏名欄・電話番号欄・住所欄といった記入欄があります。それぞれの欄は「何マス目から何マス目まで」と決まっています。用紙1枚がレコード、1つひとつの記入欄が項目、用紙を束ねたものがファイルにあたります。

データベースや表計算ソフトの「表・行・列」にたとえると、ファイルが表、レコードが行、項目が列にあたります。ただし、このガイドの売上明細のような固定長の SAMファイルには、列の名前（見出し）も区切り文字も入っていません。文字が並んでいるだけです。どこからどこまでが何の項目なのかは、別に決めておく「レコードレイアウト」（2.4）で読み取ります。

用語: バイト

バイトは、コンピュータがデータの大きさを数える単位です。半角の英字・数字・記号は、1文字が1バイトです。全角の日本語は、1文字が複数バイトになります（文字コードによって異なります）。このガイドのデータは半角の英数字だけなので、「1文字＝1バイト」として数えます。

2.2 SAM（順次アクセス方式）とデータセット

ファイルのレコードを、どんな順序や方法で読み書きするかを決めた仕組みをアクセス方式と呼びます。SAM（Sequential Access Method）は「順次アクセス方式」、つまり先頭のレコードから順番に読み書きする方式です。ベルトコンベアで流れてくる荷物を、流れてくる順に1つずつ検品するイメージです。

先頭から順に読む

3件目を読むには、1件目と2件目を先に読み進める必要があります。途中のレコードへ直接ジャンプして読むことはできません。

追加は末尾へ

新しいレコードは、ファイルの末尾にしか足せません。途中に差し込むことはできません。

全件処理に向く

日次売上集計のように、全件を最初から最後まで1回ずつ処理するバッチ処理と相性のよい方式です。

z/OS では、ファイルのことをデータセットと呼びます。データセットには、保存のしかた（編成）ごとにいくつかの種類があります。先頭から順に読み書きする順編成（PS: Physical Sequential、物理順次）のデータセットは、QSAM または BSAM という方式で処理します。このほかに、プログラムのソースを入れる区分データセットなどもあります（第6章 6.8 で出てきます）。

用語: ブロック化・バッファ・先読み・先書き

ブロック化は、複数のレコードを1つのまとまり（ブロック）にして読み書きすることです（2.3）。バッファは、読み書きするデータを一時的にためておく、メモリ上の場所です。先読みは、次に使うデータをあらかじめ読み込んでおくことです。先書きは、書き出すデータをいったんバッファにため、プログラムが次の処理を進めている間にまとめて書き出すことです。

COBOL の順ファイルは、QSAM（Queued Sequential Access Method）で読み書きされます。QSAM と BSAM（Basic Sequential Access Method）の違いは、ブロック化とバッファの管理をだれが行うかです。QSAM では、先読み・先書きも含めて、これらをシステムが受け持つので、プログラムはレコードを1件ずつ読み書きするだけで済みます。BSAM では、プログラム側が行います。このガイドで使うのは QSAM だけで、BSAM は扱いません。

なお、「SAMファイル」はこのガイドの便宜的な呼び方です（第1章の 1.3）。SAM は CSV のような「データの書き方（表現形式）」の名前ではなく、順次アクセス方式というアクセスのしかたを表す言葉です。

SAMファイルと VSAM の違い

z/OS には、もう一つ代表的なアクセス方式の VSAM（Virtual Storage Access Method）があります。VSAM は、キーなどを使って、探したいレコードを直接読み書きできるのが特徴です（順に読むこともできます）。VSAM のデータセットは、レコードの並び方と探し方によって、基本は次の4つの類型に分かれます。RRDS を固定長の RRDS と可変長の RRDS（VRRDS）に分けて、5つの区分として紹介されることもあります。

  • KSDS（Key-Sequenced Data Set）: キー（たとえば商品コード）の順に並び、キーを指定して読める
  • ESDS（Entry-Sequenced Data Set）: 書き込んだ（入力した）順に並ぶ
  • RRDS（Relative Record Data Set）: 相対レコード番号（先頭から何番目か）で読む。固定長の RRDS と、可変長の VRRDS（Variable-length RRDS）がある
  • LDS（Linear Data Set）: レコードの区切りを持たない

SAMファイル（QSAM）と VSAM の違いを、表で比べてみましょう。

全件を順番に処理するなら SAMファイル、キー（商品コードなど）で1件ずつ探して読むなら VSAM、と使い分けます。日次売上集計は、1日分の明細を全件処理するので、SAMファイルが向いています。このガイドでは SAMファイルだけを扱い、VSAM は第8章の「次のステップ」で、次に学ぶことの一つとして紹介します。

2.3 固定長レコードと可変長レコード

SAMファイルのレコードの長さには、固定長と可変長の2通りの決め方があります。

固定長

すべてのレコードが同じ長さです。売上明細は、どのレコードもちょうど12バイトです。項目の位置がどのレコードでも同じなので、読み取りが簡単です。桁数に足りない分は、0 や空白で埋めます。

可変長

レコードごとに長さが違います。長さが大きくばらつくデータでは、余白の無駄を省けます。そのかわり、各レコードの先頭に「このレコードは何バイトか」を示す管理情報（RDW）が付きます。

データセットの形を表す3つの値

データセットのレコードの形は、RECFM・LRECL・BLKSIZE の3つの値で表します。JCL では、データセットの形を指定する DCB というパラメータに、DCB=(RECFM=FB,LRECL=12) のように書きます（第5章で詳しく学びます）。

属性 英語名 意味 売上明細の例
RECFM Record Format（レコード形式） レコードが固定長か可変長か、ブロック化するかを表す文字 FB
LRECL Logical Record Length（論理レコード長） 1レコードの長さ（バイト）。可変長では最大の長さで、RDW の4バイトを含む（後述） 12
BLKSIZE Block Size（ブロックサイズ） 1ブロックの最大の長さ（バイト） 省略するか 0 を指定（システムに任せる）

RECFM の値は、F（固定長）・V（可変長）・U（不定長）に、ブロック化を表す B を組み合わせて表します。

RECFM 意味 ひとこと
F Fixed（固定長） 全レコードが同じ長さ。ブロック化しない（1ブロック＝1レコード）
FB Fixed Blocked（固定長・ブロック化） 固定長で、1ブロックに複数のレコードを入れる。このガイドの売上明細・売上集計結果はこの形式
V Variable（可変長） レコードごとに長さが違う。ブロック化しない
VB Variable Blocked（可変長・ブロック化） 可変長で、1ブロックに複数のレコードを入れる
U Undefined（不定長） 長さが決まっていない形式。このガイドでは扱わない

ブロック化 - まとめて読み書きする

ディスクなどとのデータのやり取り（入出力）は、レコードを1件ずつ行うより、複数件をまとめて行うほうが効率的です。そこで、複数のレコードを1つのブロックにまとめ、ブロック単位で読み書きします。1ブロックに入れるレコードの数をブロック化係数と呼びます。引っ越しで、本を1冊ずつ運ばずに、段ボール箱へまとめて入れて運ぶのと同じ考え方です。

固定長のブロック化（FB）では、BLKSIZE ＝ LRECL × ブロック化係数です。たとえば LRECL=12 で1ブロックに10件入れるなら、BLKSIZE は 12 × 10 ＝ 120 です（BLKSIZE は LRECL の倍数になります）。プログラムから見ると、読み書きはレコード1件ずつです。ブロックにまとめたり、ばらしたりする作業は、プログラムに代わって QSAM（システム）が行います。

BLKSIZE は、システムに決めさせるのが一般的

ブロックサイズを自分で計算せず、JCL に BLKSIZE=0 と書くか、BLKSIZE を省略すると、システムが最適な大きさを決めます（システム決定ブロックサイズ）。IBM も、多くのデータセットでこの方法を推奨しています。このガイドの JCL も、BLKSIZE は書かずにシステムに任せます。

可変長の仕組み - RDW と BDW

可変長（V・VB）では、レコードごとに長さが違うので、「このレコードは何バイトか」を示す情報が必要です。そのため、各レコードの先頭に4バイトの RDW（Record Descriptor Word）が付き、先頭の2バイトにレコードの長さ（RDW 自身の4バイトを含む）が入ります。

さらに、各ブロックの先頭にも4バイトの BDW（Block Descriptor Word）が付き、ブロックの長さ（BDW 自身の4バイトを含む）が入ります。次の図は、1ブロックの中身の例です。

ここで注意したいのは、LRECL が RDW の4バイトを含むことです。データ部分の最大の長さは、LRECL − 4 になります。たとえば LRECL=84 なら、1件に入れられるデータは最大80バイトです（上の図のレコード2が、ちょうど最大の長さです）。固定長（F・FB）には RDW も BDW も付かないので、LRECL がそのままデータの長さです。

2.4 レコードレイアウト（項目定義）を読む

区切り文字のないレコードから項目を取り出すには、「何バイト目から何バイト分が、何の項目か」を、先に決めておく必要があります。この約束事の一覧がレコードレイアウト（項目定義）です。実務では、レコードレイアウト定義書という文書にまとめ、データを送る側・受け取る側・プログラムを作る側が、同じものを見て作業します。

PIC と「ゾーン10進数」の読み方

COBOL のデータ名は第4章で作る売上集計プログラム（SALESSUM）で使う名前、PIC は第3章から学ぶ COBOL のデータの書き方です。今は「X(4) は英数字4文字、9(3) は数字3桁」と読めれば十分です。X は英数字、9 は数字、カッコの中は桁数を表します。

データ型の「ゾーン10進数」は、数字を1桁1バイトの文字で持つ方式です（2.6）。「符号なし」は、プラス・マイナスの区別がなく、0以上の数だけを扱う、という意味です。

開始位置・終了位置・桁数の関係

3つのルール

① 開始位置 ＝ 前の項目の開始位置 ＋ 前の項目の桁数（先頭の項目は 1）

② 終了位置 ＝ 開始位置 ＋ 桁数 − 1

③ 全項目の桁数の合計 ＝ レコード長（LRECL）

例（数量）: 開始位置は、商品コードの開始位置 1 ＋ 桁数 4 ＝ 5、終了位置は 5 ＋ 3 − 1 ＝ 7 です。単価も同じ式で求められます（上の表で答えを確かめましょう）。桁数の合計は 4 ＋ 3 ＋ 5 ＝ 12 で、LRECL と一致します。

実際のレコードを定規にあてはめてみましょう。次は、2件目のレコード 000200300250 です。

000200300250
商品コード（4文字） 数量（3桁） 単価（5桁）

上の数字は「何桁目か」です。商品コード 0002・数量 003（3個）・単価 00250（250円）と読めます。売上金額は 3 × 250 ＝ 750円です。

データ型と詰め方

項目の中身が桁数に満たないとき、余りの部分をどう埋めるかは、データ型で決まっています。

英数字（X）は左詰め

商品コード X(4) に A1 を入れると、左から詰めて、右側の余りが空白になります。「空白」と書いたマスには、半角スペース（1バイト）が入っています。

1234
A1空白空白
商品コード X(4)

数字（9）は右詰め

数量 9(3) に 7 を入れると、右から詰めて、左側の余りが 0 で埋まります。数字の項目は、先頭が 0 でも桁数分の文字が必ず入ります。

123
007
数量 9(3)

なぜ商品コードは「英数字」なのか

商品コードは「0001」のように数字で書かれていますが、計算には使わない識別番号です。そのため、英数字（X）で定義します。英字が混ざるコード（たとえば A001）にも対応でき、先頭の 0 も欠けずに残るからです。数量や単価のように、計算に使う項目は、数字（9）で定義します。

出力: 売上集計結果（RECFM=FB、LRECL=18）

集計対象日 20261020（2026年10月20日）と、合計金額 0000001070（1,070円）が、区切りも改行もなく18バイトにぴったり並んでいます。

レコードレイアウトは、データを作る側・読む側のすべてが守る約束事です。そのため、後から変えると影響する範囲が広がります。この影響は、やってみよう 2-2 で実際に考えます。

2.5 区切り文字のないデータ

データを表すしかたとして、よく見かけるのが CSV（カンマで区切ったテキスト）です。商品コード・数量・単価を CSV で書くと、0001,2,100 のようになります。固定長の 000100200100 と見比べてみましょう。なお、SAM と CSV は比べる軸が違うことは、2.2 で見たとおりです。ここでは、このガイドの SAMファイルに入っている固定長のデータと、CSV を比べます。

比べる点 CSV 固定長（このガイドの売上明細）
1件の例 0001,2,100 000100200100
項目の区切り カンマ 区切り文字なし。開始位置と桁数で決まる
レコードの区切り 改行 区切りなし。レコード長（12バイト）で数えて決まる
項目の長さ 値によって変わる（2 も 120 も書ける） 常に同じ。足りない分は 0 や空白で埋める
項目の意味の手がかり 先頭行に見出しを付けることがある データの中に見出しはない。レコードレイアウト定義書が必要
向いている場面 表計算ソフトとのやり取り、人が読む・編集するデータ 業務システム間の連携、COBOL のようにデータの形を決めて処理する場面

CSV では、カンマが項目の区切り、改行がレコードの区切りです。固定長には、どちらもありません。それでも項目を取り出せるのは、すべてのレコードが同じ長さで、各項目の開始位置と桁数が決まっているからです。先頭から12バイトまでが1件目、次の12バイトが2件目、というように、レコード長で数えて区切ります。

改行も1バイトのデータ

ここで大事なのは、改行も1バイトのデータだということです。テキストエディターで見ると、改行は見えない記号です。しかし、ファイルの中には、改行を表す1バイト（\n）が入っています。

z/OS の固定長データセット（FB）には、改行がありません。レコードの区切りは LRECL で決まるので、改行を入れる必要がないからです。1.5 で「見やすいように1件ずつ改行して表示している」と断ったのは、このためです。

改行の有無を取り違えると、項目の位置がずれる

改行入りのファイルを、改行なしの12バイト固定長として読むと、2件目以降が1バイトずつずれて読まれます。最後には、12バイトに足りない短いレコードが残ります。ずれた先の文字が数字として読めてしまうと、エラーにならないまま、誤った値で処理が進むこともあります。2.7 で実際に確かめ、第4章ではプログラムを動かして、どんなエラーになるかを見ます。

PC の GnuCOBOL には、改行で区切られたテキストファイルを読むための LINE SEQUENTIAL という指定もあります（第4章で紹介します）。ただし、このガイドの演習では使いません。メインフレームのデータセットと同じ「改行のない固定長」の読み書きを体験するためです。

2.6 文字コードと数値の持ち方

この節は、実務で出会ったときに慌てないための予備知識です。細かく覚える必要はありません。「こういう違いがある」と知っておけば十分です。

文字コード: EBCDIC と ASCII

コンピュータは、文字を数値（バイトの値）で記録します。どの文字にどの値を割り当てるかの約束が文字コードです。メインフレーム（z/OS）では、一般に EBCDIC（Extended Binary Coded Decimal Interchange Code）が使われます。PC では、ASCII（American Standard Code for Information Interchange）か、それを含む UTF-8 が使われます。同じ文字でも、文字コードが違えば、ファイルに記録されるバイトの値が違います。

文字 EBCDIC の値 ASCII の値
0 X'F0' X'30'
9 X'F9' X'39'
A X'C1' X'41'
空白（スペース） X'40' X'20'

用語: 16進数と X'F0'

16進数は、0〜9 と A〜F の16種類の文字で数を表す方法です。1バイトは、16進数2桁（00〜FF）で表せます。COBOL では、16進数で書いた値（16進数定数）を X'F0' のように書きます（F0 は10進数の 240 です）。

PC では、この章で printf を使って作るファイルも、第4章で GnuCOBOL が読み書きするファイルも、中身のバイトは ASCII 系の値になります（2.7 で確かめます）。同じ「12バイトのレコード」でも、メインフレームでは EBCDIC の値、PC では ASCII の値でバイトが並んでいる、という違いです。

数字の持ち方: ゾーン10進数とパック10進数

数字の項目の記録のしかたにも、いくつか種類があります。代表的な2つを紹介します。

持ち方 COBOL での書き方（例） 1桁あたり 1070 を5桁の項目に入れた例
ゾーン10進数 PIC 9(5) 1バイト（1桁を1文字として記録） 5バイト。EBCDIC なら X'F0F1F0F7F0'、ASCII なら X'3031303730'
パック10進数 PIC S9(5) COMP-3 約半バイト（1バイトに2桁を詰める） 3バイト。X'01070C'（末尾の半バイト（4ビット）の C は「プラス」を表す符号）

表の S は符号（プラス・マイナス）を持つこと、COMP-3 はパック10進数で持つことを表す指定です（このガイドのプログラムでは使いません）。

このガイドで使う数字の項目は、すべてゾーン10進数（符号なし）です。1桁が1文字なので、PC で od などを使えば、そのまま目で読めます。一方、パック10進数は、1バイトに2桁を詰めて持つため、画面にそのまま表示しても読めません。実務のデータでは、パック10進数の項目を含むファイルを見かけることもあります。

ファイルを転送するときの文字コード変換

メインフレームと PC の間でファイルをやり取りするときは、文字の項目を EBCDIC と ASCII の間で変換することが多くあります。数字や英字だけの項目は、変換しても同じ文字として読めます。ところが、パック10進数の項目を文字として変換すると、壊れてしまいます。パック10進数のバイトは「文字」ではなく数値そのものなので、文字コードの変換をかけると、別の値に変わってしまうからです。どの項目を変換し、どの項目を変換しないかは、項目のデータ型で決まります。レコードレイアウト定義書にデータ型を書いておくのは、このためでもあります。

数字の項目に、数字でない値が入っていたら

数量や単価のような数字の項目に、数字でない値（空白や英字など）が入っていることがあります。数字でないデータを計算に使うと、z/OS ではデータ例外（異常終了コード S0C7）で異常終了（ABEND）するのが典型です。ただし、データの中身やコンパイルの指定によっては、異常終了せずに誤った値のまま計算が進むこともあります。入力データの確かめ方は、第8章で扱います。

2.7 PC で固定長ファイルを作って読み解く

ここまでの内容を、PC で実際に確かめましょう。区切り文字のない固定長ファイル（売上明細3件）を作り、中身を調べます。作ったファイル data/sales.dat は、第4章以降の演習でも使います。

Windows の場合は WSL2 の Ubuntu で

Windows の場合は、WSL2 の Ubuntu のターミナルで実行します。環境の準備は、COBOL入門 第2章「開発環境を準備する」を見てください。macOS・Linux は、それぞれのターミナルで同じコマンドを実行できます。表示の空白の幅など、細かな表示は OS によって少し違うことがあります。

手順1: 作業フォルダと固定長ファイルを作る

まず、作業フォルダ（~/cobol-batch）と、データを置くフォルダを作ります。~ は自分のホームフォルダを表します。

続けて、売上明細3件を、改行を入れずに data/sales.dat へ書き出します。printf は書式を指定して文字を出力するコマンドで、'%s' は「引数を文字列のまま出力する」という指定です。改行を付けないので、3つの文字列が隙間なくつながります。> は、画面に出す代わりにファイルへ書き出す指定です（同じ名前のファイルがあると上書きされます）。

作業フォルダと売上明細の作成 PCで実行 
# 作業フォルダと、データ用のフォルダを作る（すでにあってもエラーにならない）
mkdir -p ~/cobol-batch/data
# 作業フォルダへ移動する（以降のコマンドは、ここで実行する）
cd ~/cobol-batch
# 売上明細3件を、改行なしで data/sales.dat に書き出す
printf '%s' 000100200100 000200300250 000300100120 > data/sales.dat
# ファイルのバイト数を数える（12バイト × 3件 ＝ 36 になるはず）
wc -c data/sales.dat
wc -c の結果 実行結果 
36 data/sales.dat

12バイトのレコードが3件で、ちょうど36バイトになりました。改行が入っていれば、36より大きくなります。

固定長ファイルは echo やエディターで作らない

echo 000100200100 > data/sales.dat のように echo で作ると、末尾に改行が1バイト付いてしまい、13バイトになります。固定長ファイルは、改行を付けない printf で作ってください。テキストエディターで保存したファイルも、末尾に改行が付く場合があります。Windows のテキストエディターで保存すると、改行が2バイト（CR と LF）になることもあります。

手順2: レコードを並べて、1バイトずつ見る

fold -w 12 は、表示を12バイトごとに折り返すコマンドです。表示を変えるだけで、ファイルの中身は変わりません。

12バイトごとに折り返して表示 PCで実行 
# 12バイトごとに折り返して表示する（ファイルは変わらない）
fold -w 12 data/sales.dat
fold の結果 実行結果 
000100200100
000200300250
000300100120

3件のレコードが1行ずつ表示されました。ファイルには改行がないので、最後の行のあとに、プロンプト（コマンドの入力待ちを表す記号）が同じ行で続いて表示されることがあります。これは、ファイルの最後に改行が入っていないことの現れです。

od は、ファイルの中身を1バイトずつ表示するコマンドです。-c を付けると1バイトを1文字として、-A d を付けると左端の位置を10進数で表示します。続けて実行する -t x1 は1バイトずつ16進数で表示する指定、-N 12 は先頭の12バイトだけを表示する指定です。

od で中身を見る PCで実行 
# 1バイトずつ、文字として表示する（-A d は左端の位置を10進数にする指定）
od -A d -c data/sales.dat
# 先頭の1件（12バイト）を、1バイトずつ16進数で表示する
od -A d -t x1 -N 12 data/sales.dat
実行結果（上から順に od -A d -c・od -A d -t x1 の出力） 実行結果 
0000000   0   0   0   1   0   0   2   0   0   1   0   0   0   0   0   2
0000016   0   0   3   0   0   2   5   0   0   0   0   3   0   0   1   0
0000032   0   1   2   0
0000036
0000000 30 30 30 31 30 30 32 30 30 31 30 30
0000012

od -A d -c: 左端の数字は、その行の先頭が、ファイルの先頭から何バイト目か（0から数えた位置）を表します。レコードレイアウトや cut -c の位置（1から数える）とは数え方が違います。たとえば 0000016 の行は、ファイルの17バイト目から始まります。1行に16バイトずつ並びます。最終行の 0000036 は、ファイル全体のバイト数（36）です。区切りも改行もなく、数字が36個並んでいることが分かります。なお、-A d を付けずに od -c だけを実行すると、左端の位置が8進数で表示されます（最終行は 0000044 で、8進数の 44 は10進数の 36 です）。

od -A d -t x1: 文字 0 は X'30'、1 は X'31' と、ASCII の値で並んでいます。2.6 の表のとおりです。メインフレーム（EBCDIC）なら、同じレコードは X'F0F0F0F1F0F0F2F0F0F1F0F0' になります。

手順3: 項目を切り出す

2.4 のレコードレイアウトのとおりに、項目を取り出してみましょう。cut -c5-7 は「各行の5〜7文字目だけを取り出す」コマンドで、レイアウト表の開始位置・終了位置がそのまま使えます。|（パイプ）は、左のコマンドの出力を、右のコマンドに渡す記号です。

数量だけを取り出す PCで実行 
# 12バイトごとに折り返し、5〜7文字目（数量）だけを取り出す
fold -w 12 data/sales.dat | cut -c5-7
cut の結果 実行結果 
002
003
001

cut -c1-4 なら商品コード（0001・0002・0003）、cut -c8-12 なら単価（00100・00250・00120）を取り出せます。区切り文字がなくても、位置と桁数が決まっていれば、項目を取り出せることを確かめられました。

手順4: 改行入りのファイルと比べる

次に、各レコードの後ろに改行を付けたファイルを作り、改行なしのファイルと比べます。printf の '%s\n' の \n は、改行を表します。

改行入りのファイルを作って調べる PCで実行 
# 各レコードの後ろに改行を付けて、比較用のファイルを作る
printf '%s\n' 000100200100 000200300250 000300100120 > data/sales-nl.dat
# バイト数を数える（改行が3つ増えて、36 + 3 ＝ 39 になるはず）
wc -c data/sales-nl.dat
# 画面に表示する（改行なしのファイルと見た目は同じ）
cat data/sales-nl.dat
# 1バイトずつ見る（\n が改行1バイトを表す）
od -A d -c data/sales-nl.dat

cat では3行に見えるだけで、改行なしのファイルとの違いは分かりません。ところが、wc -c は39バイトを表示し、od には \n（改行）が3つ現れます。見た目が同じでも、中身（バイト数）は違うことがあります。固定長ファイルを作ったら、wc -c でバイト数を確かめる習慣をつけましょう。

手順5: 12バイトずつ読むとどうなるか

やってみよう 2-2【直す】: 単価を6桁に広げよう

本社から、「高額な商品を扱うため、単価を6桁（最大 999,999円）に広げたい」という変更依頼が来ました。レコードレイアウトを変えると、どこに影響するかを考えます。

手順

  • 1 新しいレコードレイアウト（項目名・開始位置・終了位置・桁数）を書き、レコード長（LRECL）を求める。
  • 2 数量の最大（999）と、新しい単価の最大（999,999）をかけて、売上金額の最大値を求める。何桁の項目なら収まるかを考える。
  • 3 このレイアウト変更で見直しが必要になるものを、次の観点で書き出す: レイアウト定義書／既存のデータ／COBOL プログラム／JCL／データを作る側と読む側。

解答例

新しいレコードレイアウト（レコード長は13）

  • ・商品コード: 1〜4桁目（4桁）　・数量: 5〜7桁目（3桁）　・単価（円）: 8〜13桁目（6桁）
  • ・桁数の合計: 4 ＋ 3 ＋ 6 ＝ 13（LRECL=13）

売上金額の最大は 999 × 999,999 ＝ 998,999,001 で、9桁です（単価が5桁のときは、999 × 99,999 ＝ 99,899,001 で8桁に収まっていました）。

見直しが必要なもの

  • ・レイアウト定義書: 単価を6桁に、レコード長を13に書き換える。
  • ・既存のデータ: 12バイトのレコードを13バイトに作り直す（単価の左に 0 を1つ足す。000100200100 は 0001002000100 になる）。作り直さないと、読む位置がずれる。
  • ・COBOL プログラム: ファイルのレコード定義（第4章で学ぶ FD）の単価を6桁に、レコード長を13に変える。売上金額を入れる計算用の項目も、8桁では足りないので9桁以上に広げる。合計（10桁）の桁数も、見直しの対象になる。
  • ・JCL: データセットのレコード長を LRECL=12 から LRECL=13 に変える。
  • ・データを作る側・読む側: 前の工程のシステムは13バイトで出力するように、同じファイルを読むほかのプログラムも新しいレイアウトに合わせて直す。
  • ・テスト: 変更後のデータで、集計結果が正しいことを確かめ直す。

1か所でも古いレイアウトのまま残ると、項目の位置がずれて、誤った値で処理が進むおそれがあります。レコードレイアウト定義書で一元的に管理し、変更したときは影響範囲を洗い出す習慣が大切です。

やってみよう 2-3【作る】: レコードレイアウト定義書を作ろう（成果物①）

修了成果物の①「レコードレイアウト定義書」を、入力（売上明細）と出力（売上集計結果）の2ファイル分作ります。次の仕様メモから、項目の開始位置・終了位置・桁数を自分で求めて、表にまとめてください。表計算ソフトやメモ帳で作ってかまいません。この定義書は、第4章で COBOL のレコード定義を書くときの元になります。

仕様メモ（売上明細）: データセット名 TRAIN01.SALES.DETAIL、RECFM=FB。1件は、商品コード（4文字の英数字）、数量（3桁の数字）、単価（5桁の数字）の順に並ぶ。

仕様メモ（売上集計結果）: データセット名 TRAIN01.SALES.SUMMARY、RECFM=FB。1件は、集計対象日（8桁の数字。YYYYMMDD の形）、合計金額（10桁の数字）の順に並ぶ。

TRAIN01 は研修用ユーザー ID の例です。実際には、各自のユーザー ID や研修先で決められた名前に置き換えます。

手順

  • 1 見出し（項目名・開始位置・終了位置・桁数・データ型・PIC・備考）を持つ表を、ファイルごとに作る。
  • 2 仕様メモの項目を順に書き、2.4 のルール①②で開始位置と終了位置を求める。
  • 3 桁数の合計を求めて、レコード長（LRECL）として表の下に書く。表の上には、データセット名と RECFM・LRECL を書く。
  • 4 出力レコードの例 202610200000001070 を、作った定義書のとおりに切り分けて、読めることを確かめる。

解答例

売上明細（TRAIN01.SALES.DETAIL、RECFM=FB、LRECL=12）

項目名開始終了桁数データ型PIC備考
商品コード144英数字X(4)商品を識別する番号。計算には使わない。左詰め
数量573数字（符号なし・ゾーン10進数）9(3)販売した個数。右詰め、左を 0 で埋める
単価（円）8125数字（符号なし・ゾーン10進数）9(5)1個あたりの価格（円）。右詰め、左を 0 で埋める
レコード長12

売上集計結果（TRAIN01.SALES.SUMMARY、RECFM=FB、LRECL=18）

項目名開始終了桁数データ型PIC備考
集計対象日（YYYYMMDD）188数字（符号なし・ゾーン10進数）9(8)集計の対象にする日（業務日付）。実行した日とは限らない。例: 20261020
合計金額（円）91810数字（符号なし・ゾーン10進数）9(10)売上金額の合計。右詰め、左を 0 で埋める。最大 9,999,999,999

どちらのファイルも、桁数の合計がレコード長と一致し、開始位置・終了位置に隙間や重なりがありません（4＋3＋5＝12、8＋10＝18）。出力レコード 202610200000001070 は、1〜8桁目が 20261020（集計対象日）、9〜18桁目が 0000001070（合計金額1,070円）と読めます。

理解度確認クイズ

  • Q1. 売上明細には、区切り文字（カンマなど）がありません。それでも商品コード・数量・単価を取り出せるのは、なぜですか？

    回答を表示

    すべてのレコードが同じ長さ（12バイト）で、各項目の開始位置と桁数が、レコードレイアウトで決まっているからです。商品コードは1〜4桁目、数量は5〜7桁目、単価は8〜12桁目と、位置で切り出します。

  • Q2. 商品コードが4桁、数量が3桁、単価が5桁のレコードで、単価は何桁目から何桁目までですか？ 求め方も説明してください。

    回答を表示

    8〜12桁目です。開始位置は、前の項目（数量）の開始位置 5 ＋ 桁数 3 ＝ 8、終了位置は、開始位置 8 ＋ 桁数 5 − 1 ＝ 12 です。

  • Q3. RECFM=VB、LRECL=104 のデータセットで、1件のレコードに入れられるデータ部分の最大の長さは何バイトですか？

    回答を表示

    100バイトです。可変長では、各レコードの先頭に4バイトの RDW が付き、LRECL は RDW を含む長さです。そのため、データ部分の最大は LRECL − 4 ＝ 100バイトになります。

  • Q4. 商品コードをキーにして、特定の商品のレコードだけを直接読みたいとき、QSAM と VSAM のどちらが向いていますか？ 理由も答えてください。

    回答を表示

    VSAM（KSDS）です。QSAM（SAMファイル）は、先頭から順番に読む方式で、途中のレコードへ直接移動できません。VSAM の KSDS は、キーを指定して直接読めます。

  • Q5. 改行を含む39バイトのファイルを、12バイトの固定長として読むと、どうなりますか？

    回答を表示

    改行も1バイトのデータとして数えるので、2件目以降が1バイトずつずれて読まれます。2件目は先頭に改行が入り、項目が別の値になります。最後は3バイトしか残らず、12バイトに足りない短いレコードになります。
