JCLの基礎 - JOB・EXEC・DDでジョブを定義する

5.1 JCL とは - ジョブの実行を依頼する「指示書」

メインフレームでバッチ処理を動かすとき、プログラムを直接起動することはほとんどありません。代わりに、「どのプログラムを、どのデータセットを使って、結果をどこへ出力して動かすか」を書いた依頼書を z/OS に提出します。この依頼書が JCL（Job Control Language、ジョブ制御言語）です。JCL で依頼する仕事の単位が、第1章で学んだジョブです。

工場の作業指示書にたとえると分かりやすくなります。指示書には、「どの作業者に（プログラム）、どの材料を渡し（入力データセット）、できあがった製品をどこに置くか（出力データセット）」が書かれています。ただし、作業のやり方（計算や判断の手順）は書かれていません。それは作業者の腕、つまり COBOL プログラムが持っています。

観点COBOLJCL
書くこと処理の手順（計算・判断・繰り返し）実行の依頼（プログラム・データセット・出力先）
書き換えるのはどんなとき業務のルールが変わったとき（例: 売上金額の計算方法）動かす条件が変わったとき（例: 入力のデータセットを変える）
売上集計での例COMPUTE WS-AMOUNT = SALES-QTY * SALES-PRICE//SALESIN DD DSN=TRAIN01.SALES.DETAIL,DISP=SHR

プログラムの中には実際のデータセット名を書きません。そのため、JCL を書き換えるだけで、プログラムを作り直さずに入力データを差し替えられます。この仕組みは第6章で詳しく学びます。

5.2 JCL の書き方の基本ルール - 桁・名前・継続

JCL は COBOL と同じように、行のどの桁に何を書くかに決まりがあります。ただし、COBOL ほど細かくはありません。大事なのは、「行頭は // で始める」「名前は3桁目から書く」「オペランドの途中に空白を入れない」「71桁目までに収める（長いときは次の行に続ける）」の4つです。まず、JCL にはどんな種類の文があるかを見ておきましょう。

文の種類書き始め役割詳しい説明
JOB 文//ジョブ名 JOBジョブの始まり。ジョブの名前や、ジョブログの出力先などを指定する。ジョブの先頭に1つだけ書く5.3
EXEC 文//ステップ名 EXECジョブステップの始まり。実行するプログラムを指定する5.4
DD 文//DD名 DDステップで使うデータセットなどを指定する5.5
コメント文//*説明を書く。実行には影響しない。JOB 文より後に置く（1〜3桁目が //* の行）この節
区切り文/*DD * で書いたデータの終わりを示す（1〜2桁目が /* の行）5.5
ヌル文//ジョブの終わりを示す（1〜2桁目が // で、残りは空白の行）。省略してもよく、本ガイドの JCL では省略しているこの節

1行の形: 名前・操作・オペランド・コメント

JOB・EXEC・DD 文は、名前・操作・オペランド・コメントの4つのフィールドを、空白で区切って並べたものです。名前はその文の名前、操作は文の種類（JOB・EXEC・DD など）、オペランドは操作に対する指定、コメントはオペランドのあとに空白を空けて書く説明（実行には影響しません）です。第1章でも見た EXEC 文 //STEP020 EXEC PGM=SALESSUM を、1文字ずつマス目に入れて確かめてみましょう（この例にコメントはありません）。

12 3456789 1011 12131415 16 171819202122232425262728
// STEP020 EXEC PGM=SALESSUM
1〜2桁目名前（3桁目から）空白操作（12桁目）空白オペランド（17桁目から）

上の数字は「何桁目か」です。桁に意味があるのは、1〜2桁目の // と、3桁目から始まる名前です。操作とオペランドは、空白で区切れば何桁目に書いてもかまいません。本ガイドでは読みやすいように、操作を12桁目にそろえています。

名前の規則

ジョブ名・ステップ名・DD 名などの名前は、8文字以内で、英字（大文字）か # @ $ で始め、英数字と # @ $ だけで作ります（この3つの記号は、英語で national characters と呼ばれます。端末の言語の設定によっては別の文字コードになることがあるので、研修では英字で始まる名前を使うのが無難です）。JCL は基本的に大文字で書きます。

オペランドの中に空白が出てくると、そこでオペランドが終わり、その後ろはコメントとして扱われます（引用符で囲んだ文字列の中の空白は別です）。たとえば DISP=(NEW, CATLG,DELETE) と書くと、CATLG,DELETE) がコメントになり、括弧が閉じないため、JCL の構文エラーになります。

オペランドが長くなったときは、次の行へ続けて書けます。これを継続といいます。第1章で見た SUMOUT の DD 文は、実際のジョブ JSALSUM では3行に分けて書かれています（DISP 以降の意味は 5.6 で学びます）。次のコードの上の2行の数字は、桁位置を示す目盛りです（JCL を書ける71桁目までを示しています）。

//SUMOUT   DD DSN=TRAIN01.SALES.SUMMARY,

継続のルール 1

行末をカンマで終える

続けたい行は、オペランドの区切りのカンマ , で終えます（カンマは71桁目までに置きます）。カンマで終わった行の次は、前の行の続きとして読まれます。

継続のルール 2

次の行は // と空白で始める

続きの行は // で始め、そのあとに空白を入れます。この行には名前を書きません。

継続のルール 3

4〜16桁目から続ける

続きのオペランドは、4〜16桁目の間から書き始めます。本ガイドでは、前の行のオペランドの開始位置にそろえています（DD 文は15桁目、JOB 文は16桁目）。

カンマを忘れると、次の行が前の行の続きではなく新しい文として読まれ、JCL の構文エラーになります。また、名前・操作・オペランド・コメントを書けるのは71桁目までです。72桁目は継続のための特別な桁なので、空けておきます。73〜80桁目は z/OS に無視されます（連番を入れるための欄です）。なお、コメント文 //* だけは、80桁目まで書けます。長くなったら、71桁目までにあるカンマの位置で行を分けて続けます。

第1章でお願いしたとおり、JCL をコピーして使うときは、行頭の空白を消さないでください。続きの行の // のあとの空白を消すと、続きのオペランドが「名前」として読まれてしまい、JCL の構文エラーになります。

注意: JCL の日本語コメントについて

本ガイドでは、理解しやすいように日本語のコメント（//* の行）を入れています。ただし、実機の JCL で日本語を使うには、文字コード（EBCDIC の2バイト文字）の設定が必要です。日本語のコメントを書いてよいかどうかを含めて、現場の規約に従ってください。

5.3 JOB 文 - ジョブの名前と出力の扱いを決める

JOB 文は、ジョブの先頭に1つだけ書く文です。ジョブの名前と、ジョブの扱い方（どのクラスで実行するか、メッセージをどこへ出力するか）を指定します。売上集計ジョブ JSALSUM の JOB 文を見てみましょう。1行目の行末がカンマなので、2行目は1行目の続きです。3行目はコメント文です。コメント文は、JOB 文より後に置きます。

JSALSUM の JOB 文 z/OS JCLの抜粋 
//JSALSUM  JOB (ACCT),'SALES SUM',CLASS=A,MSGCLASS=X,
//             MSGLEVEL=(1,1),NOTIFY=&SYSUID
//* ジョブ JSALSUM の JOB 文（2行目は1行目の続き）
部分種類意味
JSALSUMジョブ名ジョブの名前（8文字以内）。ジョブログやジョブ管理製品（第7章）で、このジョブを見分けるのに使う
JOB操作「ここからジョブが始まる」を表す
(ACCT)会計情報（位置パラメータ）利用料金の集計などに使う情報。書き方は研修先・現場ごとに決められている。本ガイドでは仮の値 ACCT を書いている
'SALES SUM'プログラマー名（位置パラメータ）ジョブの持ち主や内容を示す名前。空白を含むので、アポストロフィー（'）で囲む
CLASS=Aジョブクラスジョブの種類を表す区分。どのイニシエーターが実行するかなどが、クラスごとに決められている
MSGCLASS=Xメッセージクラスジョブログ（ジョブ全体のメッセージなど）を出力する出力クラス
MSGLEVEL=(1,1)メッセージレベルジョブログに出力する情報の量。(1,1) は、JCL の文もシステムのメッセージも省略せずに出力する指定
NOTIFY=&SYSUID通知先ジョブが終わったときに知らせる相手。&SYSUID は、ジョブを投入したユーザー ID に置き換えられる

注意: JOB 文の値は研修先ごとに決まっています

会計情報・CLASS・MSGCLASS・MSGLEVEL・NOTIFY の値は、研修先や現場ごとに決められています。たとえば CLASS=A が、手元の環境で使えるクラスとは限りません。実機で動かすときは、指定された値に書き換えてください。

5.4 EXEC 文とジョブステップ - 実行するプログラムを決める

EXEC 文は、ジョブステップ（略してステップ）の先頭に書く文です。PGM= で実行するプログラムを指定すると、その EXEC 文が1つのステップになります（プロシージャを呼ぶ EXEC 文は、その中の複数のステップをまとめて実行します。第6章）。ジョブの中にステップが複数あるときは、上から順に1つずつ実行されます。

もう一つ大切なルールがあります。DD 文は、直前の EXEC 文のステップに属します。JSALSUM の構造を図にすると、JOB 文の下にステップが並び、各ステップの下に、そのステップが使う DD 文がぶら下がります。

flowchart TD JOB["JOB 文
JSALSUM"] --> S1["EXEC 文　STEP010
PGM=IEFBR14"] JOB --> S2["EXEC 文　STEP020
PGM=SALESSUM"] S1 --> D1["DD 文　DEL1"] S2 --> D2["DD 文　STEPLIB"] S2 --> D3["DD 文　SALESIN"] S2 --> D4["DD 文　SUMOUT"] S2 --> D5["DD 文　SYSIN"] S2 --> D6["DD 文　SYSOUT"]

図の説明: ジョブ JSALSUM は2つのステップを持ちます。STEP010 は DD 文を1つ、STEP020 は DD 文を5つ使います。STEP010 が終わってから STEP020 が始まります。

用語: プロシージャ と PARM

プロシージャは、よく使う EXEC 文と DD 文のまとまりに名前を付けて、あらかじめ登録しておいたものです。IGYWCL は、COBOL のコンパイルとリンクをまとめて行う、IBM 提供のプロシージャです（名前や使い方は研修先に従います）。

PARM= を付けると、プログラムに文字列を渡せます。本ガイドでは使いません。集計対象日は、SYSIN から渡します（第6章）。

ステップ名と、よく使うユーティリティ

ステップ名は STEP010、STEP020 のように、10刻みで付けることがよくあります（あとからステップを間に挟めるようにするためです）。決まりではないので、現場の命名規約に従います。JSALSUM の STEP020 が実行する SALESSUM は、第4章で作った COBOL の売上集計プログラムです。一方、STEP010 の IEFBR14 のように、IBM があらかじめ用意した便利なプログラムをユーティリティと呼びます。本ガイドでは、次の2つが登場します。

ユーティリティ何をするか使う場面
IEFBR14何もせずにすぐ終わる。DD 文の割り当てと、終了時の処置（DISP）だけが働くデータセットを作る・消す（JSALSUM の STEP010 は、前回の集計結果を削除する）

用語: 割り当てと処置

割り当ては、ステップが始まるときに、システムが DD 文に書かれたデータセットを探したり（既にあるもの）、新しく作ったり（出力用のもの）して、プログラムが使える状態にすることです。ステップが終わるときに、DISP の指定に従って、データセットを残す・消す・カタログに登録することを処置と呼びます（DISP は 5.6 で学びます）。

データセットの割り当てに失敗する（割り当てエラー）と、そのステップのプログラムは動きません。詳しくは第6章 6.3 で学びます。

プログラムの置き場所: STEPLIB と JOBLIB

z/OS は、プログラム名を見て、そのプログラムを探して実行します。実行できる形にしたプログラムをロードモジュール、それを入れておくデータセットをロードライブラリーと呼びます。IEFBR14 や IEBGENER は、システムに標準で用意された場所に入っているので、探す場所を教える必要はありません。一方、自分たちで作った SALESSUM は、研修用のロードライブラリー TRAIN01.LOAD に入っています。そこで、探す場所を DD 文で教えます。

STEPLIB に指定したライブラリーに目的のプログラムが入っていない（別のライブラリーを指定した、PGM= の名前を間違えた、STEPLIB を書き忘れた など）と、ステップは S806 という異常終了コードで ABEND（アベンド）します。ABEND とは、プログラムやシステムが処理を続けられず、強制的に終了することです（5.7 で詳しく説明します）。なお、STEPLIB に書いたデータセットそのものが存在しないときは、ABEND ではなく割り当てエラー（5.7）になり、ステップは実行されません。

5.5 DD 文とデータセット - プログラムが使うデータを指定する

DD 文（Data Definition、データ定義）は、ステップで使うデータセットなどを指定する文です。形は //DD名 DD オペランド です。DD 名は、プログラムがそのデータセットを呼ぶときの名前です。たとえば COBOL の SELECT SALES-FILE ASSIGN TO SALESIN の SALESIN が DD 名にあたります（第4章・第6章）。

DD 文の主なオペランド

データセット名は、ピリオドで区切った修飾子を並べて作ります。決まりは次の4つです。

  • 各修飾子の先頭は、英字か # @ $ にする
  • 2文字目以降は、英数字と # @ $ のほか、ハイフン（-）も使える（JOB・EXEC・DD の名前とは違います）

5.7 戻りコードとステップの実行制御

ステップが終わるとき、プログラムは戻りコード（Return Code、略して RC）という数値を z/OS に返します。「うまくいったか」を数字で伝える仕組みです。COBOL では、特殊レジスタ RETURN-CODE に値を入れてからプログラムを終えると、その値がステップの戻りコードになります（第6章）。

ジョブログでは、戻りコードが COND CODE（条件コード）という名前で表示されます。同じものです。本ガイドでは、以後「戻りコード」と呼びます。

戻りコードの慣習: 0・4・8・12・16

戻りコード意味（慣習）本ガイドの SALESSUM では

12重大なエラーファイルの OPEN・READ・WRITE の失敗（第4章の基本版から）
16回復不能なエラー（処理を打ち切る）使わない（慣習の説明だけ）

この使い分けは慣習で、意味は、プログラムや製品、プロジェクトごとに決めます。たとえば IBM の COBOL コンパイラ（Enterprise COBOL）は、メッセージの重大度（情報・警告・エラー・重大・回復不能）に応じて、0・4・8・12・16 を戻りコードにします。IDCAMS（データセットを管理する IBM のユーティリティ）も、0・4・8・12・16 を使います。なお、戻りコード 8 は「エラー」を表す数字であり、後で説明する ABEND とは別のものです。

COND でステップを飛ばす

同じことを、EXEC 文の COND パラメータで書くこともできます。既存の JCL でよく見かける書き方です。形は COND=(コード,演算子,ステップ名) で、「コード 演算子 ステップの戻りコード」が真なら、このステップを実行しません（飛ばします）。

COND の例 z/OS JCLの抜粋 
//* STEP020 の RC が 4 より大きければ STEP030 を飛ばす
//STEP030  EXEC PGM=IEBGENER,COND=(4,LT,STEP020)

COND=(4,LT,STEP020) は、「4 LT STEP020 の戻りコード」、つまり「4 が STEP020 の戻りコードより小さい」が真のときに STEP030 を飛ばす、という意味です。STEP020 の戻りコードごとに確かめると、次のようになります。

STEP020 の戻りコード「4 が戻りコードより小さいか」の判定（4 LT 戻りコード）STEP030
04 は 0 より小さくない → 偽実行する
44 は 4 より小さくない → 偽実行する
84 は 8 より小さい → 真飛ばす
124 は 12 より小さい → 真飛ばす

つまり、戻りコードが 5 以上のときに飛ばす指定です。先ほどの IF 文と、STEP020 が戻りコードを返して終わった場合は同じ結果になります。

注意: COND は「飛ばす条件」を書き、向きも逆です

  • ・IF は「実行する条件」、COND は「飛ばす条件」を書きます。
  • ・比較は「コード 演算子 戻りコード」の順です。LT は「コードが戻りコードより小さい」であり、「戻りコードが 4 未満」ではありません。
  • ・ステップ名を省略すると、それより前のすべてのステップが対象になり、どれか1つでも条件が真になると、このステップは飛ばされます。

COND の条件に当てはまって飛ばされたステップは、ジョブログに記録されます。たとえば、JSALSUM の末尾に STEP030 を付け足して COND=(4,LT,STEP020) を指定し、STEP020 の戻りコードが 8 だったとすると、次のような行が出ます（例）。

COND の条件でステップが飛ばされたとき（JESYSMSG の抜粋） ジョブログの例 
IEF202I JSALSUM STEP030 - STEP WAS NOT RUN BECAUSE OF CONDITION CODES

ABEND のあとのステップ

ステップが ABEND すると、通常は、それ以降のステップは実行されません。ABEND のあとでも実行したいステップには COND=EVEN、ABEND したときだけ実行したいステップには COND=ONLY を指定する方法があります（紹介のみ。本ガイドでは使いません）。

ここまでは、1つのジョブの中のステップの制御です。ジョブとジョブの間の制御（前のジョブが正常に終わったら次のジョブを動かす、など）は、ジョブ管理製品のジョブネットが受け持ちます（第7章）。

理解度確認クイズ

  • Q1. 次の2つの変更をするとき、直すのは COBOL（ソース）と JCL のどちらですか？ (a) 売上金額の計算方法を変える。 (b) 同じプログラムを、テスト用のデータセットで動かす。

    回答を表示

    (a) はCOBOLです。計算の手順は、プログラムに書いてあるからです。(b) はJCLです。SALESIN DD 文の DSN をテスト用のデータセット名に書き換えれば、プログラムを作り直す（再コンパイルする）必要はありません。ただし、本番の集計結果を壊さないよう、出力側のデータセット名（SUMOUT と、STEP010 の DEL1）もテスト用の名前にします（第6章 6-2）。

  • Q2. DISP=SHR と DISP=OLD の違いを説明してください。

    回答を表示

    どちらも、既にあるデータセットを使う指定です。SHR は他のジョブと共有して使うので、同時に何本ものジョブが読めます（入力を読むだけのときの基本）。OLD は専有して使うので、同じデータセットを使う他のジョブは、終わるまで待たされます（書き換えるとき向け）。

  • Q3. DISP=(NEW,CATLG,DELETE) の意味を説明してください。また、このデータセットを作るステップが、戻りコード 8 で終わった場合と、ABEND した場合で、データセットはそれぞれどうなりますか？

    回答を表示

    データセットを新しく作り、ステップが ABEND せずに終わったらカタログに登録して残し（第2パラメータ）、ABEND したら削除する（第3パラメータ）という意味です。戻りコード 8 で終わった場合は、ABEND していないので第2パラメータが使われ、データセットは残ります。ABEND した場合は、第3パラメータが使われ、データセットは削除されます。

  • Q4. 戻りコード 4 と 8 は、慣習上、それぞれどんな意味で使われますか？

    回答を表示

    4 は警告（処理は最後まで終わったが、注意が必要なことがあった）、8 はエラー（処理が正しく終わらなかった）を表すのが慣習です。ただし、これは慣習であって OS が決めた意味ではないので、プログラムやプロジェクトの規約で意味を決めて、関係者で共有しておく必要があります。

  • Q5. COND=(4,LT,STEP020) を付けたステップは、STEP020 の戻りコードが 0・4・8 のとき、それぞれ実行されますか？

    回答を表示

    COND は「4 が STEP020 の戻りコードより小さい」が真のときに、そのステップを飛ばす指定です。戻りコード 0 のときは「4 < 0」が偽、4 のときは「4 < 4」が偽なので、どちらも実行されます。8 のときは「4 < 8」が真なので、飛ばされます。つまり、戻りコードが 5 以上のときに飛ばされます。
