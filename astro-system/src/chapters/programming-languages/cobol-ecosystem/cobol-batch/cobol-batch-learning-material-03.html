ホーム COBOLバッチ処理入門 第3章
第3章 所要時間: 約3時間

COBOLの基礎 - DIVISION・PIC・MOVE・IF・PERFORM

この章から、いよいよ COBOL のプログラムを書きます。ファイルはまだ使いません。小さなプログラムを自分の PC で動かし、結果を確かめながら、プログラムの骨組み・データの定義（PIC）・MOVE・計算・IF・PERFORM という COBOL の基本の部品を身につけましょう。最後に、3件の売上明細から売上金額と合計を求める SALCALC を作ります。第4章では、これをファイルの入出力つきの売上集計プログラムへ発展させます。

この章で学ぶこと

  • 4つの DIVISION の役割と、固定形式の桁のルールを説明できる
  • PICTURE 句を使って、商品コード・数量・単価・金額などの業務データを定義できる
  • MOVE と算術演算の結果を予想できる（切り捨てや桁あふれを含む）
  • IF と PERFORM を使って、処理の流れを組み立てられる
  • 単純な集計プログラム（SALCALC）を作って、PC で実行できる

3.1 COBOL プログラムの骨組み

COBOL（コボル）は、事務処理（業務処理）のために作られたプログラミング言語です。英語に近い文でプログラムを書き、金額の計算やファイルの処理を、桁数まで決めて確実に書けるのが特徴です。銀行・保険・流通などのバッチ処理で、今も広く使われています。

この章のプログラムは、すべて PC の GnuCOBOL で動かします。まだ導入していない場合は、COBOL入門 第2章「開発環境を準備する - GnuCOBOLで最初のプログラム」の手順で準備してください（Windows の場合は WSL2 の Ubuntu を使います）。このガイドの実行結果は、GnuCOBOL 3.1.2 で確認したものです。この章で学ぶ基本の文法（部・PIC・MOVE・IF・PERFORM など）は、PC の GnuCOBOL でも、メインフレームの COBOL でも共通です。

プログラムは4つの部（DIVISION）でできている

COBOL のプログラムは、4つの部（DIVISION）でできています。部は、次の順番で書きます。

部 役割 日次売上処理での例 学ぶ場所
IDENTIFICATION DIVISION
見出し部		 プログラムの名前など、名札にあたるものを書く PROGRAM-ID. SALESSUM.（プログラム名） この節
ENVIRONMENT DIVISION
環境部		 プログラムが使うファイルなど、実行環境との結び付きを書く 入力ファイル・出力ファイルの宣言 第4章
DATA DIVISION
データ部		 プログラムが扱うデータ（ファイルのレコードや計算用の項目）の形を定義する 12バイトの売上明細レコード、合計金額を入れる項目 3.2
PROCEDURE DIVISION
手続き部		 処理の手順を書く 読む → 計算する → 書く 3.3〜3.6

使わない部は省略できます。この章のプログラムはファイルを使わないので、ENVIRONMENT DIVISION は書きません。部の中は、さらに細かく分かれています。大きい順に、部 → 節 → 段落 → 文です。SALCALC を例に、図にしてみましょう。

図の説明: SALCALC（3.7 で作るプログラム）を例にした、プログラムの階層です。部の中に節や段落があり、段落の中に文（命令）が並びます。点線の ENVIRONMENT DIVISION は、ファイルを使うプログラムだけに書く部です。

用語: 節・段落・文

節（SECTION）は部の中の区切りで、データ部の WORKING-STORAGE SECTION（作業場所節）のように名前が決まっています。段落は、手続き部の中で自分で名前を付けた処理のまとまりです（MAIN-PROC. や CALC-PROC.）。文は1つの命令（MOVE・ADD・DISPLAY など）です。段落名は、あとで PERFORM で呼び出すときに使います（3.6）。

書く位置のルール - 固定形式

COBOL では、1行のどの桁（左から何文字目）に書くかが決まっています。この書き方を固定形式と呼び、このガイドのプログラムはすべて固定形式で書きます。1行は、次の5つの領域に分かれています。80桁のカードに書いていた時代の名残です。

1〜6桁目 7桁目 8〜11桁目 12〜72桁目 73〜80桁目
一連番号領域
使わない。
空白6個を入れる		 標識領域
* を書くと
コメント行になる		 A領域
部・節・段落名・
01 レベルなど		 B領域
処理の文・
05 レベルなど		 プログラム識別領域
無視される。
何も書かない

実際の位置は、桁の定規と並べると分かりやすくなります。次の例では、IDENTIFICATION DIVISION. のように部・段落名は8桁目から、処理の文は12桁目から始まっています。

桁の定規（1〜72桁目）と、書く位置の例 

         1         2         3         4         5         6         7
123456789012345678901234567890123456789012345678901234567890123456789012
      * COMMENT                         ← 7桁目の * は、コメント行の目印
       IDENTIFICATION DIVISION.         ← 8桁目から書く（A領域）
       MAIN-PROC.                       ← 段落名も8桁目から（A領域）
           DISPLAY "HELLO, BATCH!"      ← 12桁目から書く（B領域）

コメント行は、プログラムの動きに影響しない説明です。このガイドでは、何をする処理かを日本語のコメントで書きます。コメントは、後から読む人（未来の自分を含む）への手紙です。なお、GnuCOBOL は命令文を8桁目から書いても動いてしまうことがありますが、他の環境でも動くように、決まりどおりの桁で書きましょう。

1行は72バイトまで（日本語は1文字が3バイト）

73桁目以降は、GnuCOBOL でも z/OS の Enterprise COBOL でも読み飛ばされます。PC ではソースファイルを UTF-8 で保存するため、日本語は1文字が3バイトです。日本語のコメントは短く書き、長くなるときは行を分けましょう。72バイトを超えた部分は、黙って無視されます。文の途中で切れると、コンパイルエラーになることもありますが、エラーにならずに意味が変わってしまうこともあります（例: COMPUTE WS-A = WS-B * 100 の最後の 0 が73桁目にあると、* 10 として計算され、WS-B が 7 なら 700 のはずが 70 になります。GnuCOBOL では、-Wall を付けても警告は出ません）。長すぎる行がないかは、次のコマンドで調べられます（何も表示されなければ問題ありません）。

行の長さの検査 PCで実行 
LC_ALL=C awk 'length($0)>72{print FILENAME": "NR": "length($0)}' hello.cob

最初のプログラム HELLO

骨組みが分かったところで、画面に「HELLO, BATCH!」と表示するだけのプログラムを作りましょう。作業フォルダ（第2章で作った ~/cobol-batch/）に、hello.cob という名前で、UTF-8 で保存します。

hello.cob 完全なプログラム 
      * HELLO: 最初のプログラム。画面に1行表示する
       IDENTIFICATION DIVISION.
       PROGRAM-ID. HELLO.
       PROCEDURE DIVISION.
       MAIN-PROC.
           DISPLAY "HELLO, BATCH!"
           STOP RUN.

プログラムを1行ずつ読んでみます。

  • IDENTIFICATION DIVISION. と PROGRAM-ID. HELLO.: 見出し部の始まりと、プログラム名（HELLO）です。
  • PROCEDURE DIVISION.: 手続き部の始まりです。データを使わないので、DATA DIVISION は省略しています。
  • MAIN-PROC.: 段落名です。「主処理（メインの処理）」の意味で付けた名前で、自分で決められます。
  • DISPLAY "HELLO, BATCH!": 画面に文字を表示します。"…" で囲んだ文字列をリテラル（プログラムに直接書いた定数）と呼びます。
  • STOP RUN.: プログラムを終了します。段落の最後の文なので、ピリオドを付けます。

ピリオド（.）は、そこまでに並べた文をまとめて区切る印です。手続き部では、文と文の間にピリオドは要りません。このガイドでは、ピリオドを段落名の後ろと、段落の最後の文にだけ書きます（見出し部やデータ部では、項目の定義など1つの記述の終わりに付けます）。条件で処理を分ける命令 IF の途中にピリオドを書くと、IF がそこで終わってしまい、思わぬ動きになるためです（3.5 で確かめます）。

コンパイルして実行する

COBOL で書いたプログラム（ソースプログラム）は、そのままでは動きません。コンピュータが実行できる形に翻訳するコンパイルを行い、できあがった実行ファイルを実行します。

ターミナル PCで実行 
cd ~/cobol-batch
cobc -x hello.cob
./hello
echo "RC=$?"
hello の実行結果 実行結果 
HELLO, BATCH!
RC=0
  • cobc -x hello.cob: cobc は GnuCOBOL のコンパイラです。-x を付けると、実行ファイル（ここでは hello）が作られます。
  • ./hello: できあがった実行ファイルを実行します（./ は「今いるフォルダの」という意味です）。
  • echo "RC=$?": 直前に実行したプログラムの戻りコードを表示します。

戻りコード（RC、Return Code）は、プログラムが終わるときに OS へ返す数値で、0 は正常を表します。バッチ処理では、この数値を見て「次のジョブを動かしてよいか」を判断します（第5章・第7章で学びます）。今は「プログラムは終了するときに数値を返す」と覚えておけば十分です。

なお、cobc -x -Wall hello.cob のように -Wall を付けると、コンパイラが気づいた怪しい書き方を警告（warning）として表示します。エラーと違って実行ファイルは作られますが、バグの手がかりになるので、警告が出たら必ず読みましょう。

コピーするときは、行頭の空白を消さない

固定形式では、行頭の空白にも意味があります。メモ帳やチャットを経由して行頭の空白が消えると、行が1桁目から始まり、各行の7文字目が7桁目（標識領域）に入ってしまうため、コンパイラは「7桁目の標識（インジケーター）が不正」というエラーを出します。次は、hello.cob の行頭の空白をすべて消してコンパイルしたときの表示です。エラーが出たら、行頭の空白が残っているか（8桁目・12桁目から書き始めているか）を確かめましょう。なお、エラーメッセージの文面は、GnuCOBOL のバージョンによって多少異なります。

行頭の空白を消した hello.cob のコンパイル結果 実行結果

hello.cob:2: error: invalid indicator 'F' at column 7
hello.cob:3: error: invalid indicator 'M' at column 7
hello.cob:4: error: invalid indicator 'U' at column 7
hello.cob:5: error: invalid indicator 'R' at column 7
hello.cob:6: error: invalid indicator 'Y' at column 7

hello.cob:8: error: PROGRAM-ID header missing

3.2 データの定義と PICTURE 句

プログラムが計算に使う数字や、ファイルから読んだ文字は、メモリ上の「データを入れる箱」に入れて扱います。COBOL では、箱を使う前に、名前・種類・大きさを定義しておく決まりです。この定義を書くのがデータ部です。計算や一時保存に使う箱は、データ部の中の作業場所節（WORKING-STORAGE SECTION）に書きます。ファイルのレコードを書くファイル節（FILE SECTION）は、第4章で扱います。

データ項目の書き方

箱1つ分の定義をデータ項目と呼びます。たとえば 01 WS-AMOUNT PIC 9(8) VALUE 0. は、「WS-AMOUNT という名前の、数字8桁の箱を用意し、最初は 0 を入れておく」という意味です。1つの項目は、次の部分でできています。

  • レベル番号（01）: 項目の階層を表す番号です。一番外側が 01 で、内側の項目ほど大きな番号（05 など）を付けます。
  • データ名（WS-AMOUNT）: 項目の名前です。処理の中では、この名前で箱を呼びます。
  • PIC 句（PIC 9(8)）: 箱に入れるデータの種類と桁数です。この節の後半で説明します。
  • VALUE 句（VALUE 0）: 最初に入れておく値（初期値）です。省略もできます。
  • ピリオド（.）: 項目定義の終わりです。

データ名は、英字・数字・ハイフン（-）で付けます。MOVE のような COBOL の予約語は使えません。COBOL は大文字と小文字を区別しませんが、慣習で大文字で書きます。このガイドでは、使い道が分かるように名前の頭に印を付けます。WS- は作業場所節（Working-Storage）の項目、SALES- は売上明細の入力レコード、SUM- は集計結果の出力レコードです（第4章で使います）。

集団項目と基本項目 - 第2章のレイアウトを COBOL で書く

第2章で、売上明細の1件（12バイト）は「商品コード4バイト・数量3バイト・単価5バイト」でできていることを学びました。COBOL では、このレイアウトを次のように書きます。

売上明細1件分のレイアウト DATA DIVISIONの抜粋 
      * 売上明細1件分（固定長12バイト）のレイアウト
       01  WS-SALES-REC.
           05  WS-CODE         PIC X(4).
           05  WS-QTY          PIC 9(3).
           05  WS-PRICE        PIC 9(5).
flowchart TD G["01 WS-SALES-REC
集団項目（12バイト）"] --> C["05 WS-CODE
PIC X(4)
商品コード（1〜4桁目）"] G --> Q["05 WS-QTY
PIC 9(3)
数量（5〜7桁目）"] G --> P["05 WS-PRICE
PIC 9(5)
単価（8〜12桁目）"]

図の説明: 12バイトのレコード全体を WS-SALES-REC（集団項目）と呼び、その中を4バイト・3バイト・5バイトの基本項目に区切っています。項目の位置と桁数は、第2章のレイアウト表のとおりです。

用語: 集団項目と基本項目

基本項目は、PIC 句を持ち、それ以上は分けない項目です（WS-CODE など）。集団項目は、PIC 句を持たず、下位の項目をまとめて1つの名前で呼べるようにした項目です（WS-SALES-REC）。レベル番号は 01〜49 が使え、05・10 のように間を空けて付けるのが慣習です。集団項目全体を指定すると12バイトを一度に扱え、基本項目を指定すると商品コードだけ・数量だけを扱えます。

第2章のレイアウト表は、そのまま PIC 句になります。「英数字・4桁」の商品コードは PIC X(4)、「数字・3桁」の数量は PIC 9(3)、「数字・5桁」の単価は PIC 9(5) です。開始位置と終了位置は COBOL には書きません。項目を上から順に並べれば、前の項目の続きに自然に決まるためです。

なお、第2章の表では、データ名を SALES-CODE・SALES-QTY・SALES-PRICE（レコード全体は SALES-REC）としました。この章ではファイルを使わず、作業場所節に置くので、頭に WS- を付けて WS-CODE・WS-QTY・WS-PRICE（レコード全体は WS-SALES-REC）とします。第4章でファイル節にレコードを書くときは、第2章の表どおり SALES- の名前を使います。

PICTURE 句 - 型と桁数を決める

PICTURE 句（PIC と略します）は、箱に入れるデータの型と桁数を決めます。使う記号は次のとおりです。V と S は、このガイドでは使わないので、紹介にとどめます。

記号 意味 例 入るもの・補足
X 英数字1文字（1バイト） X(4) 英字・数字・記号・空白などの文字。0001 や AB12 が入ります
9 数字1桁（0〜9） 9(5) 数字（0〜9）を入れる項目です。9(5) なら 00000〜99999 で、最大値は 99999 です。ただし、中身が本当に数字かどうかは自動では調べないため、英字が入ってしまうこともあります（3.3・3.5）
( ) 同じ記号の繰り返し回数 9(3) 9(3) は 999 と同じ意味です。桁数が多いときに数えやすくなります
V 小数点の位置（紹介） 9(3)V99 整数3桁・小数2桁です。小数点の文字そのものはデータに入らず、5バイトで表します
S 符号（正負）（紹介） S9(5) マイナスの値も持てます。S が無い項目にマイナスの値を入れると、符号が落ちて絶対値になります

9 の項目は、1桁が1バイトです（第2章で学んだ「ゾーン10進数」です）。そのため PIC 9(3) は3バイト、PIC X(4) は4バイトで、第2章のレイアウト表の桁数とそのまま一致します。

X と 9 の使い分け: 計算に使うかどうか

商品コードは 0001 のように数字だけに見えますが、足したり掛けたりしないので PIC X(4)（英数字）にします。コードは英字が混ざることもあり、先頭の 0 も大切な文字だからです。一方、数量・単価・金額のように計算に使う値は PIC 9（数字）にします。

VALUE 句と、箱の大きさの決め方

VALUE 句は、箱の初期値を決めます。合計や件数のように足していく項目は、必ず VALUE 0 を付けて 0 から始めます。VALUE 句を書かない項目の初期値は、処理系や設定によって異なり、0 や空白とは限りません。SALCALC の計算用の項目は、次のように定義しています。

計算に使う項目 DATA DIVISIONの抜粋 
      * 計算に使う項目
       01  WS-AMOUNT           PIC 9(8)  VALUE 0.
       01  WS-TOTAL            PIC 9(10) VALUE 0.
       01  WS-COUNT            PIC 9(3)  VALUE 0.

桁数は、入る可能性のある最大の値から決めます。

項目 PIC 桁数の根拠
WS-AMOUNT（1件の売上金額） 9(8) 数量は最大 999、単価は最大 99,999 なので、1件の売上金額は最大 999 × 99,999 = 99,899,001 で、8桁に収まります
WS-TOTAL（合計金額） 9(10) 出力する集計結果（第2章）の合計金額と同じ10桁です。最大 9,999,999,999円まで入ります
WS-COUNT（件数） 9(3) SALCALC は3件しか扱わないので3桁（999件まで）です。実際の業務では、データの件数に合わせて広げます

箱が小さいと、上の桁が黙って切れる

箱の桁数が足りないと、入りきらない上の桁は切り捨てられます。しかも、エラーにならず、プログラムは止まりません。この危険は 3.3 と 3.4 で実際に確かめます。「数量が3桁、単価が5桁だから、掛け算の結果は最大8桁」のように、最大値から逆算して桁数を決める習慣をつけましょう。

PICTURE 句をさらに詳しく知りたい方は、COBOL入門 第4章「データを入れる箱 - データ項目とPICTURE句」をご覧ください。

3.3 MOVE - データを項目に入れる

MOVE は、送り元の値を、送り先の項目にコピーする命令です。MOVE 送り元 TO 送り先 の順に書きます（送り元の値は変わりません）。コピーするとき、値は送り先の項目の型と大きさに合わせて整えられます。その整え方は、送り先が英数字項目・数字項目・集団項目のどれかで決まっています。

英数字項目（X）へ

左詰めで入り、余った右側は空白で埋まります。長すぎると、右側が切れます。

数字項目（9）へ

右詰めで入り、余った左側は 0 で埋まります。長すぎると、上の桁（左側）が切れます。

集団項目へ

文字をそのまま左から並べて入れます。12文字を MOVE すると、4・3・5文字に分かれて各項目に入ります。

実際に確かめてみましょう。MOVE した結果を表示する小さなプログラムです。次の2つのブロックを、上から順に続けて1つのファイル movetest.cob に保存します（長いプログラムは「部品 1/2」のように分けて示します）。

movetest.cob（部品 1/2） 完全なプログラム 
      * MOVETEST: MOVE の動きを確かめる
       IDENTIFICATION DIVISION.

3.4 算術演算 - 足す・引く・掛ける・割る

COBOL には、計算のための命令が5つあります。

命令 書き方の例 意味
ADD（足す） ADD WS-AMOUNT TO WS-TOTAL WS-TOTAL に WS-AMOUNT を足します（WS-TOTAL の値が変わります）
ADD（GIVING 付き） ADD WS-A WS-B GIVING WS-R WS-A と WS-B の和を WS-R に入れます（WS-A・WS-B は変わりません）
SUBTRACT（引く） SUBTRACT WS-B FROM WS-A GIVING WS-R WS-A から WS-B を引いた差を WS-R に入れます
MULTIPLY（掛ける） MULTIPLY WS-A BY WS-B GIVING WS-R WS-A × WS-B の積を WS-R に入れます
DIVIDE（割る） DIVIDE WS-A BY WS-B GIVING WS-R WS-A ÷ WS-B の商を WS-R に入れます
COMPUTE（数式で計算） COMPUTE WS-R = (WS-A + WS-B) * 10 数式で書きます。+ - * / とかっこが使えます（** はべき乗）

GIVING を付けると、結果は別の項目に入り、計算に使った項目の値は変わりません。ADD WS-AMOUNT TO WS-TOTAL のように GIVING を付けない書き方では、TO の後ろの項目が書き換わります。複数の演算を組み合わせる計算は、COMPUTE なら1行で書けます（掛け算が足し算より先に計算されるなど、ふつうの数式と同じ規則です）。なお、+ や - などの演算子の前後には、必ず空白を入れます。WS-A-WS-B と続けて書くと、ハイフンを含む1つのデータ名と見なされ、コンパイルエラーになります。

結果を入れる項目に小数点以下の桁が無いとき、割り算の小数点以下は切り捨てられます。四捨五入したいときは、ROUNDED を付けます。では、5つの命令の結果を、小さなプログラムで確かめましょう。最後の足し算は、結果の項目に入りきらない場合の動きを見るためのものです。

  • 7 ÷ 2 → 0003: 本当の答えは 3.5 ですが、小数点以下が切り捨てられました。
  • 7 ÷ 2（ROUNDED）→ 0004: ROUNDED を付けたので、四捨五入されて 4 になりました。
  • 9990 + 20 → 0010: 本当の答えは 10010 ですが、上の桁が切れて 0010 になりました。

桁あふれ: 計算結果の上の桁が、黙って切れる

最後の行を見てください。PIC 9(4) の項目に 9990 + 20 の結果 10010 は入りきらず、上の桁の 1 が切れて 0010 になりました。エラーメッセージは出ず、戻りコードも 0 のままです。合計金額がこれを起こすと、売上が突然小さくなって出力されます。

対策は2つあります。(1) 桁数を最大値から決める（3.2）。(2) ON SIZE ERROR を付けて検出する。たとえば ADD 20 TO WS-TOTAL に ON SIZE ERROR を付けると、桁があふれたときに指定した処理が実行され、WS-TOTAL は 9990 のまま変わりません。第8章で、合計の桁あふれを検出するために使います。

まとめ: データが黙って切れる3つの場面

(1) MOVE で、送り先より長い値を入れたとき（英数字は右側、数字は上の桁が切れる）。(2) 割り算などで、結果の項目に小数点以下の桁が無いとき（小数点以下が切り捨てられる）。(3) 計算結果が、結果の項目に入りきらないとき（上の桁が切れる）。どれもエラーにならず、戻りコードも 0 のままです。だから、桁数の設計と、結果の確認が欠かせません。

計算の命令をさらに詳しく知りたい方は、COBOL入門 第6章「計算する - 四則演算とCOMPUTE」をご覧ください。

3.5 IF - 条件で処理を分ける

IF は、条件が成り立つときだけ処理を実行する命令です。ELSE を付けると、成り立たないときの処理も書けます。このガイドでは、最後を必ず END-IF で閉じます（ピリオドでも IF は終わりますが、このあと確かめるとおり間違いのもとになるためです）。SALCALC（3.7）では、「売上金額が500円以上のときだけ、メッセージを追加で表示する」ために使っています。

flowchart TD A["売上金額 WS-AMOUNT を求めた"] --> B{"500円以上か？"} B -->|"はい"| C["「500円以上の売上です」を表示"] B -->|"いいえ"| D["何もしない"] C --> E["次の文へ進む"] D --> E

図の説明: SALCALC の IF の流れです。条件が成り立つとき（はい）だけメッセージを表示し、成り立たないとき（いいえ）は何もせず、どちらの場合も次の文に進みます。

条件には、次のような書き方があります。

種類 書き方の例 意味
比較 WS-AMOUNT >= 500 500以上かどうか。比較には =（等しい）・>・<・>=・<=・NOT =（等しくない）が使えます
両方成り立つ 条件1 AND 条件2 2つの条件が両方成り立つとき
どちらかが成り立つ 条件1 OR 条件2 2つの条件のどちらかが成り立つとき
中身が数字か WS-QTY IS NUMERIC 項目の中身がすべて数字か。クラス条件と呼びます

IS NUMERIC は、バッチ処理で重要な条件です。3.3 で見たように、MOVE は中身が正しいかを調べません。ファイルから読んだデータが壊れていないかは、IS NUMERIC で確かめます。IS の後ろに NOT を付けると、反対の意味になります（例: WS-QTY IS NOT NUMERIC は「数字だけでできていない」）。第8章の入力チェックでは、この NOT を付けた形を使います。IF の動きを、次のプログラムで確かめましょう。最後の部分では、数量の位置に英字 A が混じった壊れたレコードを、わざと使います。

IF の途中にピリオドを書くと、そこで IF が終わる

ピリオドは、そこまでの文をまとめて区切ります。IF の中の文の後ろに書くと、まだ END-IF で閉じていないIF 全体もそこで終わってしまい、後ろの文は条件に関係なく実行されます。次のプログラムは、金額が 200円（500円未満）なので、何も表示されないつもりで書いたものです。

       PROGRAM-ID. DOTTEST.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-AMOUNT           PIC 9(8) VALUE 200.

dottest の実行結果 実行結果 
割引の対象です

金額は 200円なのに、「割引の対象です」と表示されました。1つ目の DISPLAY の後ろのピリオドで IF が終わったため、2つ目の DISPLAY は IF とは無関係に、いつも実行されたのです。字下げされているので IF の中にあるように見えますが、COBOL では字下げに意味はありません。IF の範囲を決めるのは、END-IF とピリオドです。プログラムは止まらず、エラーも出ません。意図どおりに書くには、ピリオドを付けずに、END-IF で IF を閉じます。

正しい書き方 PROCEDURE DIVISIONの抜粋 
      * ピリオドを付けず、END-IF で閉じる
           IF WS-AMOUNT >= 500
               DISPLAY "500円以上です"
               DISPLAY "割引の対象です"
           END-IF

この形に直して実行すると、200円では何も表示されません。手続き部ではピリオドを段落名の後ろと段落の最後の文にだけ書き、IF は END-IF で閉じる。この書き方を習慣にしましょう。なお、古いプログラムには、END-IF を使わず、ピリオドで IF を終える書き方も残っています。読むときは、ピリオドの位置で IF の範囲を確かめましょう。IF をさらに詳しく知りたい方は、COBOL入門 第7章「プログラムに判断させる - IF・EVALUATEと条件名」をご覧ください。

3.6 PERFORM - 段落を呼び出す・繰り返す

手続き部の処理は、段落に分けて名前を付けます。段落を呼び出す命令が PERFORM です。呼び出された段落の処理が終わると、呼び出した文の次に戻ります。処理を段落に分けると、プログラムが読みやすくなり、同じ処理を何度でも使い回せます。次の図は、3.7 で作る SALCALC の呼び出しの流れです。

sequenceDiagram participant M as MAIN-PROC（主処理） participant C as CALC-PROC（1件分の計算） M->>M: 1件目のレコードを MOVE M->>C: PERFORM CALC-PROC C-->>M: 計算が終わったら、呼び出した次の文へ戻る M->>M: 2件目のレコードを MOVE M->>C: PERFORM CALC-PROC C-->>M: 戻る M->>M: 3件目のレコードを MOVE M->>C: PERFORM CALC-PROC C-->>M: 戻る M->>M: 件数と合計を表示して STOP RUN

図の説明: 主処理（MAIN-PROC）が、レコードを MOVE しては CALC-PROC を呼び出します。CALC-PROC は、1件分の計算を終えると、呼び出された場所の次の文に戻ります。同じ段落を3回使い回しています。

PERFORM には、回数や条件を指定して繰り返す書き方もあります。

書き方 意味 使う場面
PERFORM CALC-PROC 段落を1回実行する 1件ごとの計算（3.7）
PERFORM SHOW-PROC 3 TIMES 段落を3回続けて実行する 回数が決まっている繰り返し
PERFORM CALC-PROC UNTIL WS-EOF = "Y" 条件が成り立つまで、段落を繰り返し実行する ファイルの終わりまで、1件ずつ処理する（第4章）
PERFORM 2 TIMES ～ END-PERFORM 段落に分けず、PERFORM と END-PERFORM の間に処理を書く（インライン PERFORM） 短い繰り返し
PERFORM UNTIL 条件 ～ END-PERFORM インライン形式で、条件が成り立つまで繰り返す 短い繰り返し

UNTIL の条件は、繰り返す処理を実行する前に、毎回判定されます。最初から条件が成り立っていれば、繰り返す処理は1回も実行されません。

flowchart TD S(["PERFORM UNTIL 条件"]) --> C{"条件は成り立っているか？
（実行する前に、毎回判定）"} C -->|"いいえ"| B["繰り返す処理を1回実行"] B --> C C -->|"はい"| E(["次の文へ進む"])

図の説明: UNTIL の繰り返しの流れです。処理を実行する前に条件を判定し、成り立っていなければ処理を1回実行して、また判定に戻ります。成り立ったら繰り返しを終えます。

このうち3つの書き方（回数指定・UNTIL・インライン）を、1つのプログラムで確かめます。2つのブロックを続けて、looptest.cob に保存してください。

looptest.cob（部品 1/2） 完全なプログラム

       IDENTIFICATION DIVISION.
       PROGRAM-ID. LOOPTEST.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-I                PIC 9(2) VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PROC.
      * 段落を3回呼ぶ
           PERFORM SHOW-PROC 3 TIMES
      * WS-I が3になるまで、段落を繰り返し呼ぶ
           PERFORM COUNT-PROC UNTIL WS-I >= 3
      * 条件を満たし済みなので、1回も呼ばれない
           PERFORM COUNT-PROC UNTIL WS-I >= 3

           PERFORM 2 TIMES
               DISPLAY "INLINE"
           END-PERFORM
           STOP RUN.

  • SHOW-PROC が3回表示されたのは、PERFORM SHOW-PROC 3 TIMES のためです。
  • COUNT-PROC は、WS-I が3になるまで3回実行されました。段落の中で WS-I に 1 を足しているので、3回目で条件が成り立ちます。
  • 2つ目の PERFORM COUNT-PROC UNTIL WS-I >= 3 は、実行する前の時点で WS-I がすでに 3 なので、1回も実行されませんでした。
  • INLINE が2回表示されたのは、段落に分けない PERFORM 2 TIMES ～ END-PERFORM のためです。

繰り返しと段落のつまずきやすい点

条件がいつか成り立つように書く: 繰り返しの条件に使う項目を、繰り返しの中で変えないと、条件がいつまでも成り立たず、プログラムが終わらなくなります（無限ループ）。LOOPTEST の COUNT-PROC が WS-I に 1 を足しているのは、そのためです。夜間のバッチで無限ループが起きると、ジョブが朝まで終わらず、業務に影響します。PC で動かしていて止まらなくなったら、ターミナルで Ctrl+C を押して止めます。

主処理の最後に STOP RUN を書く: 段落は上から順に実行されます。主処理の最後に STOP RUN を書き忘れると、実行がそのまま下の段落へ流れ込み、呼び出されていない段落まで実行されてしまいます。

ここで示した以外に、カウンターを自動で増やしながら繰り返す PERFORM VARYING もあります。詳しく知りたい方は、COBOL入門 第8章「同じ処理を繰り返す - PERFORMと構造化」をご覧ください。

3.7 単純な集計処理を作る - SALCALC

ここまでの部品を組み合わせて、売上集計の核になる計算を作りましょう。SALCALC は、ファイルを使わずに、売上明細3件の売上金額（数量 × 単価）を求め、件数と合計を数えるプログラムです。ファイルから読む代わりに、第1章 1.5 のテストデータ3件を、MOVE で売上明細のレコード領域（WS-SALES-REC）に入れて処理します。3.1〜3.6 で学んだ部品を、すべて使います。

プログラムは2つのブロックに分けて示します。上から順に続けて、salcalc.cob に保存してください（行頭の空白を消さないように注意します）。

salcalc.cob（部品 1/2） 完全なプログラム 
      *================================================================
      * SALCALC: 売上明細3件の売上金額と合計を求める
      *================================================================
       IDENTIFICATION DIVISION.
       PROGRAM-ID. SALCALC.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
      * 売上明細1件分（固定長12バイト）のレイアウト
       01  WS-SALES-REC.
           05  WS-CODE         PIC X(4).
           05  WS-QTY          PIC 9(3).
           05  WS-PRICE        PIC 9(5).
      * 計算に使う項目
       01  WS-AMOUNT           PIC 9(8)  VALUE 0.
       01  WS-TOTAL            PIC 9(10) VALUE 0.
       01  WS-COUNT            PIC 9(3)  VALUE 0.
salcalc.cob（部品 2/2） 完全なプログラム 
       PROCEDURE DIVISION.
      * 主処理: 1件ずつレコードに入れて計算する
       MAIN-PROC.
           MOVE "000100200100" TO WS-SALES-REC
           PERFORM CALC-PROC
           MOVE "000200300250" TO WS-SALES-REC
           PERFORM CALC-PROC
           MOVE "000300100120" TO WS-SALES-REC
           PERFORM CALC-PROC
           DISPLAY "COUNT=" WS-COUNT " TOTAL=" WS-TOTAL
           STOP RUN.
      * 1件分の売上金額を求めて合計に足す
       CALC-PROC.
           COMPUTE WS-AMOUNT = WS-QTY * WS-PRICE
           ADD WS-AMOUNT TO WS-TOTAL
           ADD 1 TO WS-COUNT
           DISPLAY WS-CODE " " WS-QTY " X " WS-PRICE " = " WS-AMOUNT
           IF WS-AMOUNT >= 500
               DISPLAY "  500円以上の売上です"
           END-IF.

プログラムを読む

  • 部品 1/2（データを用意する）: WS-SALES-REC は、1件分のレコードを入れる12バイトの領域です（3.2）。WS-AMOUNT（1件の売上金額）・WS-TOTAL（合計）・WS-COUNT（件数）は、VALUE 0 で 0 から始めます。
  • MAIN-PROC（主処理）: MOVE で1件分のデータをレコード領域に入れ、PERFORM CALC-PROC で計算します。これを3件分繰り返したあと、件数と合計を表示し、STOP RUN. で終わります。
  • CALC-PROC（1件分の計算）: COMPUTE で売上金額（数量 × 単価）を求め、ADD で合計に足し、件数に 1 を足します。DISPLAY で明細を1行表示し、売上金額が500以上のときだけ、IF で追加のメッセージを表示します。段落の最後の END-IF. にだけ、ピリオドが付いています。
  • DISPLAY: 項目と文字列を続けて並べて表示できます。数字の項目は、先頭の 0 も含めて桁数どおりに表示されます（売上金額 200 は 00000200）。1,070 のように見やすく整えるには編集項目を使います（COBOL入門 第5章）。

SALCALC は、売上集計プログラムの骨格

第4章の売上集計プログラム SALESSUM は、SALCALC の骨組みをそのまま引き継ぎます。違いは、レコードを MOVE で入れる代わりにファイルから READ し、PERFORM ... UNTIL でファイルの終わりまで繰り返し、集計結果をファイルに WRITE して、ファイル操作の異常を調べることです。売上金額を求めて合計に足す計算（CALC-PROC の COMPUTE と ADD）は、そのまま使えます（データ名は、第2章の表どおり SALES-QTY・SALES-PRICE に変わります）。

やってみよう 3-3【作る】: 合計数量と平均売上金額を表示しよう

3件版の SALCALC（salcalc.cob）に、合計数量と1件あたりの平均売上金額を表示する処理を追加します。平均は「合計金額 ÷ 件数」で、小数点以下は四捨五入します。

手順

  • 1 cp salcalc.cob salcalc3.cob でコピーし、salcalc3.cob を直す（3-2 で直した版ではなく、3件版を使います）。
  • 2 作業場所節に、合計数量を入れる WS-QTY-TOTAL（PIC 9(6)）と、平均を入れる WS-AVG（PIC 9(8)）を、どちらも VALUE 0 で追加する。
  • 3 CALC-PROC で、WS-QTY を WS-QTY-TOTAL に足す。
  • 4 MAIN-PROC の最後で、DIVIDE ... GIVING ... ROUNDED を使って「合計金額 ÷ 件数」を WS-AVG に求め、合計数量と平均を表示する。
  • 5 コンパイルして実行し、合計数量が 6、平均が 357 になることを確認する（1,070 ÷ 3 = 356.66… を四捨五入した値）。

解答例

salcalc3.cob の変更箇所 変更箇所の抜粋 
      * 作業場所節に追加
       01  WS-QTY-TOTAL        PIC 9(6)  VALUE 0.
       01  WS-AVG              PIC 9(8)  VALUE 0.
      * CALC-PROC に追加（合計に足す文の後ろ）
           ADD WS-QTY TO WS-QTY-TOTAL
      * MAIN-PROC の最後の DISPLAY の後ろに追加
           IF WS-COUNT > 0
               DIVIDE WS-TOTAL BY WS-COUNT GIVING WS-AVG ROUNDED
           END-IF
           DISPLAY "合計数量=" WS-QTY-TOTAL " 平均金額=" WS-AVG
salcalc3 の実行結果 実行結果 
0001 002 X 00100 = 00000200
0002 003 X 00250 = 00000750
  500円以上の売上です
0003 001 X 00120 = 00000120

  • ・合計数量は 2 + 3 + 1 = 6、平均は 1,070 ÷ 3 = 356.66… を四捨五入して 357 です。ROUNDED を付けないと、小数点以下が切り捨てられて 356 になります。
  • ・件数が 0 のときは 0 で割れないため、IF WS-COUNT > 0 で、件数があるときだけ割っています。入力が0件のときの扱いは、第8章でも考えます。
  • ・桁数は最大値から決めています（3.2）。WS-QTY-TOTAL は、件数が最大 999 件（WS-COUNT は 3桁）、1件の数量が最大 999 なので、合計は最大 999 × 999 = 998,001 で、6桁に収まります。WS-AVG は、平均が1件の売上金額の最大（99,899,001）を超えることはないので、WS-AMOUNT と同じ8桁にしています。

理解度確認クイズ

  • Q1. COBOL プログラムを構成する4つの DIVISION を、書く順に挙げ、それぞれの役割を答えてください。

    回答を表示

    IDENTIFICATION DIVISION（見出し部: プログラム名など）→ ENVIRONMENT DIVISION（環境部: 使うファイルなど、実行環境との結び付き）→ DATA DIVISION（データ部: 扱うデータの形の定義）→ PROCEDURE DIVISION（手続き部: 処理の手順）の順です。ファイルやデータを使わないプログラムでは、ENVIRONMENT DIVISION と DATA DIVISION を省略できます。

  • Q2. PIC 9(5) の項目に入れられる最大の値はいくつですか。また、この項目は何バイトですか？

    回答を表示

    最大値は99999、大きさは5バイトです。9 は数字1桁を表し、9(5) は 99999 と同じ意味です。このガイドで使う形式では、1桁が1バイトです。

  • Q3. 項目 WS-NUM が PIC 9(5) のとき、MOVE 123456 TO WS-NUM を実行すると、WS-NUM の値はいくつになりますか？

    回答を表示

    23456 になります。数字項目に入りきらない上の桁（左端の 1）が切れるためです。エラーにはならず、プログラムは止まりません。なお、英数字項目は左詰めで入るので、PIC X(4) の項目に MOVE "AB" すると、AB の後ろに空白が2つ付いた4文字になります。

  • Q4. 項目 WS-I が 3 のときに PERFORM COUNT-PROC UNTIL WS-I >= 3 を実行すると、COUNT-PROC は何回実行されますか？

    回答を表示

    0回です。UNTIL の条件は、処理を実行する前に毎回判定されます。最初から条件が成り立っているので、1回も実行されません（3.6 の LOOPTEST の2つ目の PERFORM）。

  • Q5. IF の中の文の後ろにピリオドを書くと、何が起きますか？ 意図どおりに動かすには、どう書けばよいですか？

    回答を表示

    ピリオドはそこまでの文をまとめて区切るので、まだ閉じていないIF 全体もそこで終わります。後ろに書いた文は IF の条件と無関係に、いつも実行されてしまいます。意図どおりにするには、ピリオドを付けずに END-IF で IF を閉じ、手続き部のピリオドは、段落名の後ろと段落の最後の文にだけ書きます。
