ホーム Power BI 第3章
第3章 所要時間: 約60分

データを取得する

第2章では、あらかじめ用意された Excel ファイルを読み込んでグラフを作りました。この章では一歩戻って、その「読み込む」という操作そのものを掘り下げます。Power BI がデータを取り込める場所は Excel だけではありません。CSV・データベース・Web ページなど、代表的な4種類の接続先の使い方と、データの取り込み方には大きく2つの方式があることを学びます。ここで判断の基準を持っておくと、実際の現場でデータソースを渡されたときに迷わず選べるようになります。

この章で学ぶこと

  • 「データを取得」の全体的な流れ（コネクタ選択 → ナビゲーターで確認 → 読み込む）を説明できる
  • Excel／CSV・SQL Server・Web という代表的な接続先ごとの手順と注意点を理解する
  • Import と DirectQuery の違いを、データの置き場所・速度・更新の観点から説明できる
  • 実際に CSV ファイルを読み込み、ナビゲーターで列と行数を確認する手順を実行できる

3.1 「データを取得」の全体像

Power BI Desktop の画面左上、ホーム リボンにある データを取得 というボタンが、あらゆるデータ取り込みの入り口です。クリックすると、接続できるデータソースの一覧が表示されます。この一覧に並ぶ1つ1つの接続方法をコネクタと呼びます。

Power BI には100種類を超えるコネクタが用意されていますが、新人SEがまず押さえておくべきなのは次の4種類です。本章ではこの4つを順番に見ていきます。

接続先 どんなときに使うか 本章の節
Excel ブック 手元にある Excel ファイルをそのまま取り込む、もっとも身近な入り口 3.2
テキスト/CSV 基幹システムなどから書き出された CSV ファイルを取り込む 3.2
SQL Server 社内のデータベースに直接つないでテーブルを取り込む 3.3
Web インターネット上に公開されているページの表を取り込む 3.4

どのコネクタを選んでも、その後の流れはほぼ共通しています。接続先を選ぶと、そのデータの中身を一覧できるナビゲーターという画面が開きます。ここでシートやテーブルを選ぶとプレビューが表示され、最後に 読み込む と データの変換 のどちらかを選んではじめてデータが取り込まれます。

flowchart LR A["ホーム"] --> B["データを取得"] B --> C["コネクタを選ぶ
Excel・CSV・SQL Server・Web"] C --> D["ナビゲーター
プレビューで確認"] D -->|そのまま取り込む| E["読み込む"] D -->|整形してから取り込む| F["データの変換
（Power Query エディター）"] E --> G["データモデルへ"] F --> G

最後に選ぶ 読み込む と データの変換 の違いは、次の章以降を理解するうえで重要です。

選択肢 何が起きるか 向いている場面
読み込む プレビューで見えている状態のまま、そのままデータモデルに取り込む 列名やデータ型がすでに整っている場合
データの変換 取り込む前に Power Query エディターが開き、列の削除や型変換などの下ごしらえができる 不要な列がある、型がずれているなど整形が必要な場合（第4章で本格的に扱う）

迷ったら「データの変換」を選んでも大丈夫

「読み込む」を選んだ後でも、後から データの変換 ボタンで Power Query エディターを開き直せます。取り込みをやり直す必要はないので、迷ったときにどちらを選んでも致命的な失敗にはなりません。

3.2 Excel／CSV から取り込む

Excel と CSV は、新人SEが最初に扱うことになるデータソースです。手順はよく似ていますが、確認すべき落とし穴が少し違います。まずは基本の手順を確認しましょう。

  1. ホーム → データを取得 → Excel ブック（または テキスト/CSV）を選ぶ。
  2. 取り込みたいファイルをファイル選択ダイアログで指定する。
  3. ナビゲーターに表示されたシート／テーブルの一覧からプレビューを確認する。
  4. 列が正しく分かれているか、先頭行が見出しになっているかを確認する。
  5. 問題がなければ 読み込む、整形が必要なら データの変換 を選ぶ。

手順は共通していますが、Excel と CSV では確認すべき落とし穴が異なります。表にまとめます。

確認ポイント Excel ブック テキスト/CSV
シートとテーブルの違い ワークシート全体か、名前を付けた「テーブル」単位かを選べる。テーブルは範囲が明確でずれにくい 1ファイル＝1つの表として扱われるため、この区別はない
先頭行の扱い 先頭行を見出しとして使うかどうかをプレビューで確認する 同様に「先頭行をヘッダーとして使用する」設定を確認する
文字コード 通常は問題になりにくい Shift-JIS のファイルを既定のまま読み込むと文字化けすることがある。作成元のシステムを確認する
区切り記号 該当しない カンマ区切りが基本だが、タブやセミコロン区切りのファイルもある。プレビューで列が分かれているか必ず確認する

注意: 「1列にまとまって見える」ときは区切り記号を疑う

CSV を取り込んだ直後のプレビューで、本来複数あるはずの列が1列にまとまって表示されることがあります。多くの場合、区切り記号がカンマではなくタブやセミコロンになっているのが原因です。読み込む前に必ずプレビューで列数を数え、Sales テーブルなら7列あるかを確認する習慣をつけましょう。

3.3 SQL Server から取り込む

みらい商事のような会社では、売上データは Excel ではなく基幹システムのデータベースに入っていることも多くあります。ここでは代表例として SQL Server への接続方法を見ていきます。

  1. ホーム → データを取得 → データベース → SQL Server データベース を選ぶ。
  2. サーバー名（必要であればデータベース名も）を入力する。
  3. 認証方式を選び、必要な資格情報を入力する。
  4. ナビゲーターで必要なテーブル（例: Sales や Customers）にチェックを入れる。
  5. 読み込む または データの変換 を選ぶ。

サーバー名の書き方は環境によってさまざまです。社内の担当者から伝えられた名前をそのまま入力するのが基本ですが、代表的な書き方を知っておくと戸惑いません。

サーバー名の入力例 
// 社内サーバー名がそのまま名前解決できる場合
sales-db.miraishoji.local

// 名前付きインスタンスを使っている場合（サーバー名\インスタンス名）
192.168.10.25\SQLEXPRESS

// 既定と異なるポート番号を使っている場合（サーバー名,ポート番号）
sales-db.miraishoji.local,1433

認証方式は主に3種類あります。どれを選ぶべきかは、社内の情報システム部門やデータベース管理者に確認してください。

認証方式 説明 使う場面
Windows 今ログインしている Windows アカウントの権限で接続する 社内ドメインに参加した PC から接続する場合の基本
データベース SQL Server 側で発行されたユーザー名とパスワードを使う ドメインに参加していない環境や、外部からの接続
Microsoft アカウント 組織のクラウドアカウントでサインインする Azure SQL Database など、クラウド上のデータベースに接続する場合

なお、この接続画面には SQL 文を直接入力できる欄も用意されています。しかし新人SEのうちは、次のポイントを基本方針にしてください。

重要ポイント: SQL は自分で書かず、テーブル選択＋Power Query で絞る

SQL を直接書く方法は使わないことを基本方針にしてください。ナビゲーターでテーブルをそのまま選び、絞り込みや列の削除は次の章で学ぶ Power Query で行う方が、後から見た人にも「何をしたか」が分かりやすく、修正もしやすいためです。SQL を直接書く方法は、Power Query の操作に十分慣れてから検討しましょう。

もう1つ、この接続画面で意識してほしいのが「Import」と「DirectQuery」のどちらでデータを取り込むかという選択です。SQL Server のようなデータベース系のコネクタでは、この選択画面が表示されます。この2つの方式の違いは3.5でじっくり扱います。

3.4 Web から取り込む

官公庁の統計ページや業界団体の公開情報など、インターネット上のページに表として載っているデータを取り込みたい場面もあります。たとえば、みらい商事の企画部門が「業界団体が公開している市場統計の表を自社のレポートに取り込みたい」と依頼してきた、という場面を想像してみてください。Power BI は、ページの中から表を自動的に見つけてくれる Web コネクタを持っています。

  1. ホーム → データを取得 → Web を選ぶ。
  2. 取り込みたい表が載っている URL を入力する。
  3. Power BI がページ内の表を自動検出し、ナビゲーターに候補として一覧表示する。
  4. プレビューを見て、狙った表と一致しているかを確認する。
  5. 読み込む または データの変換 を選ぶ。

注意: ページの構造が変わると取り込みが壊れる

Web コネクタは、あくまで「今そのページに表示されている構造」をもとに列を認識します。運営元がページのデザインや列構成を変更すると、更新のたびに取り込みが失敗したり、列の並びがずれたりすることがあります。継続的に使う重要な指標を、自分たちで管理していない外部ページだけに依存させるのは避け、可能であれば正式なデータ提供（API やダウンロード用のファイル）がないかも確認しましょう。

3.5 Import と DirectQuery

3.3 で触れたとおり、SQL Server のようなデータベース系のコネクタでは、接続の設定画面で「Import（インポート）」と「DirectQuery（ダイレクトクエリ）」のどちらでデータを取り込むかを選ぶことになります（Excel・CSV・Web はこの選択肢がなく、常に Import 方式になります）。この違いを理解しておくことは、本章でもっとも重要なポイントです。

Import は、データソースの中身をコピーして Power BI 側に取り込む方式です。第2章で Excel を読み込んだときも、この Import 方式が使われていました。DirectQuery は、データをコピーせず元の場所に置いたまま、レポートを見るたびに問い合わせを送る方式です。図で見比べてみましょう。

Import の場合

flowchart TD A["データソース
SQL Server など"] -->|コピーして取り込む| B["Power BI モデル
（メモリ内に保持）"] B -->|高速に集計| C["レポート"] C -.->|手動またはスケジュールで更新| A

DirectQuery の場合

flowchart TD D["レポート"] -->|見るたびに問い合わせ| E["データソース
SQL Server など"] E -->|最新の結果を返す| D

図から分かるとおり、Import は「あらかじめ取り込んでおいて、後から高速に見る」方式、DirectQuery は「取り込まずに、その都度確認しに行く」方式です。それぞれの特徴を比較表で整理します。

比較する点 Import DirectQuery
データの置き場所 Power BI のモデル内にコピーを圧縮して保持する 元のデータソースに置いたまま。Power BI 側にはコピーを持たない
速度 非常に高速（メモリ内の圧縮データを集計するため） データソース側の性能に依存し、遅くなることがある
データ量 メモリを消費するため、扱える量に上限を意識する必要がある データソース側の容量が上限になるため、非常に大きなデータも扱いやすい
更新 手動またはスケジュールで更新した瞬間だけ最新化される 見るたびに問い合わせるため、ほぼリアルタイムに最新の状態になる
使える機能 DAX のほぼすべての関数を制限なく使える 一部の DAX 関数や複雑な計算に制限がある
向いているケース 過去データの分析など、多くのケースで第一候補になる リアルタイム性が必須、またはデータ量が膨大でメモリに載せきれない場合

名前だけ覚えておきたい2つの言葉

このほかに、Live 接続（Analysis Services や別の Power BI セマンティックモデルに、DirectQuery に近い形でつなぐ方式）と、複合モデル（Import で取り込んだテーブルと DirectQuery のテーブルを1つのモデルの中に混在させる方式）という用語もあります。入門段階では「そういう選択肢もある」と名前を知っておくだけで十分です。

本ガイドでは第4章以降、基本的にImport 方式を前提にデータの整形・モデリング・計算を進めます。DirectQuery が必要になるのは、データ量やリアルタイム性の要件が明確になってからで十分です。迷ったら、まず Import から始めましょう。

やってみよう 3-1: CSV を読み込んでナビゲーターで確認する

みらい商事の売上明細を月次で書き出した CSV ファイル（例: sales_202401.csv）を読み込み、取り込む前にナビゲーターで中身を確認する練習をします。

手順

  1. 1 ホーム → データを取得 → テキスト/CSV を選び、学習用の売上 CSV ファイルを指定する。
  2. 2 プレビュー画面が開いたら、まず列の数を数える。Sales テーブルの7列（SalesID OrderDate ProductID CustomerID StoreID Quantity Amount）ときちんと分かれているかを確認する。
  3. 3 画面下部に表示されている行数を確認し、想定していた件数とおおむね合っているかをチェックする。文字化けしている列名がないかも見ておく。
  4. 4 列と行数に問題がなければ 読み込む を選ぶ。もし列が1つにまとまっていたら区切り記号を疑い、一度キャンセルして3.2を読み直す。
  5. 5 左端のビュー切替アイコンからテーブルビューに切り替え、読み込んだ Sales テーブルの中身が想定どおりであることを確認する。

理解度確認クイズ

  1. Q1. Import と DirectQuery の違いを、データの置き場所という観点から説明してください。

    回答を表示

    Import はデータソースの中身をコピーして Power BI のモデル内（メモリ上）に保持する方式です。一方 DirectQuery はコピーを持たず、元のデータソースに置いたままにして、レポートを見るたびに問い合わせを送ります。この違いにより、Import は高速だが更新のタイミングでしかデータが変わらず、DirectQuery は常に最新だが速度がデータソースの性能に依存する、という特徴の差が生まれます。

  2. Q2. ナビゲーターに表示される「読み込む」と「データの変換」は、それぞれ何をする選択肢ですか？

    回答を表示

    「読み込む」は、プレビューに表示されている状態のまま、そのままデータモデルに取り込みます。「データの変換」は、取り込む前に Power Query エディターを開き、不要な列の削除やデータ型の変更などの整形を行ってから取り込みます。整形が必要なデータには「データの変換」を選びます。

  3. Q3. Web コネクタでデータを取り込むときに、特に注意すべき点は何ですか？

    回答を表示

    Web コネクタは、取り込んだ時点のページの構造（列の並びや表の位置）をもとにデータを認識しています。ページの運営元がデザインや構成を変更すると、次回以降の更新で取り込みが失敗したり、列がずれてしまったりするリスクがあります。継続的に使う重要な指標を、自分たちで管理していない外部ページだけに頼りすぎないよう注意が必要です。
