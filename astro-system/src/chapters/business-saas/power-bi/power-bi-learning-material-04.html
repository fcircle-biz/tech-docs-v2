Power Query入門

Power Query は、取り込んだばかりの生データを「分析できる形」に整えるための編集画面です。列の削除・型の変換・行の絞り込み・テーブルの結合といった下ごしらえを、Power BI Desktop の中でボタン操作だけで行えます。この章でもっとも大切なのは、その操作がすべて「適用したステップ」として記録され、データが更新されるたびに同じ手順で自動的に再実行される、という再現性の仕組みです。ここが腹落ちすると、Excel の手作業と Power BI が根本的に何が違うのかが分かります。

この章で学ぶこと

  • Power Query エディターの画面構成と、「適用したステップ」が持つ再現性の意味を説明できる
  • 列の整形（不要な列の削除・列名の変更・データ型の変更）を行い、型を最初に直す理由を説明できる
  • 行の整形（フィルター・重複の削除・null の扱い）と、列を増やす・分ける操作を実行できる
  • マージ（Merge）と追加（Append）の違いを理解し、目的に応じて正しく使い分けられる

4.1 Power Query エディターの画面と「適用したステップ」

第3章では、Excel や CSV、SQL Server からデータを Power BI に取り込みました。しかし現実のデータは、そのままレポートに使える状態であることはほとんどありません。列名が分かりにくかったり、数値のはずの列が文字として読み込まれていたり、空欄の行が混ざっていたりします。この「取り込んだ後の下ごしらえ」を専門に行う画面がPower Query エディターです。

Power Query エディターは、データ取得の途中で選べる データの変換 から開きます。すでに読み込んだテーブルを後から編集したい場合は、ホーム → データの変換 でいつでも呼び出せます（バージョンにより名称が異なる場合があります）。

画面の場所 役割
左側「クエリ」ペイン 取り込んだテーブル（クエリ）の一覧。Sales や Products がここに並ぶ
中央のデータプレビュー 選んだクエリの中身を表形式で確認できる領域
数式バー 今選んでいるステップの中身を M 言語の式として表示する（4.6 で扱う）
右側「適用したステップ」ペイン これまでに行った操作が、実行した順番でリストになっている

この章でもっとも大切なのが、右側の「適用したステップ」です。Power Query では、列を削除する・型を変える・行を絞り込むといった操作を1つ行うたびに、その操作が自動的に「ステップ」として記録されていきます。ステップは上から順に実行され、途中のステップをクリックすれば、そこまで処理が終わった時点のデータを確認できます。

flowchart TD A["生データ
今月のSales CSV"] --> B["適用したステップ
記録済みの操作を上から順に再実行"] B --> C["整形済みデータ
そのままレポートに使える形"] D["翌月、新しいCSVに差し替える"] -.->|同じステップを自動で再実行| B

ここが Excel の手作業と決定的に違う点です。Excel で「不要な列を消して、日付を並べ替えて、合計を出す」という作業をした場合、残るのは結果だけで、手順そのものは残りません。翌月また同じ作業を一からやり直すことになります。Power Query では手順そのものが「適用したステップ」として保存されるため、データが新しくなっても更新ボタンを押すだけで同じ整形が自動的に繰り返されます。この性質を再現性と呼びます。

重要ポイント: ステップは編集・削除・並べ替えができる

「適用したステップ」は一度作って終わりではありません。歯車アイコンから設定を変更したり、右クリックで削除したりできます。ただし、後の手順が前の手順の結果を前提にしていることが多いため、途中のステップを削除・並べ替えすると、それより後のステップがエラーになることがあります。まずは上から積み増していく使い方に慣れましょう。

4.2 列の整形 ── データ型の変更が最重要

列に対する整形は3つあります。不要な列を消す、列名を分かりやすくする、そしてデータ型を正しく直すことです。このうち、初心者がもっとも軽視しがちで、かつ後々もっとも影響が大きいのがデータ型の変更です。

操作 やり方 目的
列の削除 消したい列を右クリック → 削除 分析に使わない列（社内メモなど）を減らし、モデルを軽くする
列名の変更 列ヘッダーをダブルクリックして入力し直す Amt のような略称を Amount のように分かりやすくする
データ型の変更 列ヘッダー左端の型アイコンをクリック → 正しい型を選ぶ 後続の集計・並べ替え・リレーションを正しく機能させる

なぜデータ型がそこまで重要なのでしょうか。ソースが Excel や CSV の場合、Power Query は列の中身を見て型を推測しますが、この自動判定はしばしば外れます。たとえば Sales テーブルの OrderDate 列が「テキスト」のまま読み込まれたり、Amount 列が「テキスト」として扱われたりすることがあります。

列の例 正しい型 型を直さないと起きること
Sales[Amount] 10進数 合計しても 0 になったり、文字列として連結されたりする
Sales[Quantity] 整数 平均・合計などの数値関数が使えない、または誤った結果になる
Sales[OrderDate] 日付 DateTable と正しくリレーションを組めず、年月での絞り込みができない
Products[ProductName] テキスト （本来テキストのままでよいが）数値と誤認識されると並び順や検索がおかしくなる

注意: 型の変更は整形の一番最初に行う

データ型の変更を後回しにすると、その後に組み立てたフィルターやカスタム列が「文字列としての比較」になり、想定と違う結果になることがあります。列の削除・列名の変更が終わったら、他の整形に進む前に必ず型を確認するのが安全な順番です。

なお、型を変更するたびに「変更された型」というステップが「適用したステップ」に追加されます。列を1つずつ変えると型変更のステップが何個も並んでしまうため、複数列をまとめて選択してから型を変更すると、ステップが1つにまとまりすっきりします。

4.3 行の整形 ── フィルター・重複・null の扱い

列を整えたら、次は行です。分析に不要な行、同じ内容が重複している行、値が入っていない行を取り除いたり適切に処理したりします。

フィルターは、列ヘッダー右端の下向き矢印をクリックし、条件を指定して不要な行を除く操作です。たとえば「テスト用に入力した架空の注文」や「金額が空欄の行」を除外するのに使います。重複の削除は、ホーム → 行の削除 → 重複の削除 から行い、選んだ列の値が完全に一致する行を1行だけ残します。

もっとも判断に迷うのがnull（空白）の扱いです。null とは「値が何も入っていない」状態を指し、0 や空文字列（長さ0の文字列）とは区別されます。null をどう扱うかは、その列が何を表しているかによって変わります。

方針 こういうときに選ぶ みらい商事の例
削除する その行自体が集計に不要、または不正なデータである Sales[Amount] が空欄の行（入力ミス・欠損した取引記録）
置換する 欠損に代わる意味のある既定値がある Customers[Industry] が空欄なら「未分類」に置き換える
残す 集計の性質上、null のままでも問題が起きない 一部の店舗にだけ設定された備考欄など、集計に使わない列

用語: null と 0 と空文字列は別物

Amount が null（未入力）の行と、0（金額ゼロの取引）の行は意味が違います。前者は「データが取れなかった」、後者は「取引はあったが金額が0円だった」ことを表します。この違いを意識せずに一律で除外・置換すると、集計結果の意味が変わってしまうので注意しましょう。

4.4 列を増やす・分ける

整形は「消す・直す」だけでなく、「増やす・分ける」ことも含みます。ここでは代表的な3つの方法を紹介します。

列の分割

1つの列を区切り記号や文字数で複数の列に分ける。「東京都渋谷区」を都道府県と市区町村に分ける、など。

例からの列

欲しい結果を数行入力すると、Power Query がパターンを推測して残りの行に自動適用する。

カスタム列

数式を自分で書いて新しい列を作る。既存の列どうしの計算などに使う。

もっとも使う機会が多いのがカスタム列です。列の追加 → カスタム列 を選び、列名と計算式を入力します。たとえば Sales テーブルに、金額と数量から1個あたりの実売単価を求める列を追加してみましょう。

  1. 列の追加 → カスタム列 をクリックする
  2. 新しい列名に 実売単価 と入力する
  3. 数式欄に [Amount] / [Quantity] のように、同じテーブルにある列名を角括弧で囲んで計算式を書く
  4. OK を押すと、行ごとに計算された新しい列が末尾に追加される

たとえば Amount が 3,600円、Quantity が 3 の行では、実売単価は 1,200円 になります。なお、この式で参照できるのは同じテーブルにある列だけです。Products の UnitPrice と比べたい場合は、次の 4.5 で学ぶマージで UnitPrice を取り込んでから計算します。

カスタム列と DAX の計算列は何が違う？

似たような計算は、第7章で学ぶ DAX の「計算列」でも作れます。Power Query のカスタム列はデータを取り込む段階で計算して固定するのに対し、DAX の計算列はモデルに読み込んだ後で計算します。迷ったら「取り込み時に一度決めてよい値はカスタム列、後から条件で変わりうる値は DAX」と覚えておきましょう。

4.5 テーブルを合わせる ── マージと追加

複数のテーブルを扱う Power BI では、テーブルどうしを組み合わせる場面が必ず出てきます。Power Query には、その組み合わせ方が2種類あります。マージ（Merge）と追加（Append）です。名前が似ているうえに結果も表に見えるため混同しやすいですが、やっていることはまったく違います。

操作 結合の向き 何が増えるか 必要な条件
マージ（Merge） 横に結合 列 共通のキー列（例: ProductID）
追加（Append） 縦に積む 行 同じ列構成のテーブルどうし

たとえば Sales に Products の商品名を付け加えたいならマージ、1月分と2月分に分かれた売上ファイルを1つにまとめたいなら追加を使います。図で比べてみましょう。

マージ（Merge）＝横に結合

flowchart TD A["Sales
ProductID・Amount"] -->|ProductIDで結合| C["結合後のSales
ProductID・Amount・ProductName"] B["Products
ProductID・ProductName"] -->|ProductIDで結合| C

追加（Append）＝縦に積む

flowchart TD A["1月のSales
120行"] --> C["積み上げ後のSales
120行 + 110行 = 230行"] B["2月のSales
110行"] --> C

マージを行うと、ホーム → クエリのマージ から結合するテーブルとキー列を選び、最後に結合の種類を指定します。入門段階でまず覚えておきたいのは次の2つだけです。

結合の種類 残る行 使いどころ
左外部（Left Outer） 左のテーブル（Sales）は全行残り、一致する Products の情報があれば付け足す 売上明細に商品名を付けたいなど、主役の表を1行も減らしたくない場合
内部（Inner） 両方のテーブルでキーが一致した行だけが残る 両方に存在するデータだけを厳密に突き合わせたい場合

注意: マージ直後は列が「テーブル」として折りたたまれている

マージを実行すると、新しい列に Table という値が入った状態で追加されます。これは Products テーブルまるごとがその行に紐づいていることを示すもので、まだ使える状態ではありません。列ヘッダーの展開ボタン（左右矢印アイコン）をクリックし、ProductName など必要な列だけにチェックを入れて展開する操作を忘れないようにしましょう。

最後に、テーブルの形そのものを変えるピボット解除を紹介します。Excel からもらうデータには、月ごとの実績が横一列に並んだ「列持ち」の表がよくあります。このままでは Power BI で年月を軸に集計しにくいため、月を1つの列にまとめる「行持ち」の形に直します。

ピボット解除前（列持ち） ピボット解除後（行持ち）
StoreName / 1月 / 2月 / 3月
渋谷店・120,000円・135,000円・128,000円 		StoreName / 属性(月) / 値(金額)
渋谷店・1月・120,000円
渋谷店・2月・135,000円
渋谷店・3月・128,000円

操作は、月の列（1月 2月 3月）をまとめて選択し、右クリックから 列のピボット解除 を選ぶだけです。選んだ列名が「属性」列に、元の値が「値」列にまとまり、DAX での集計やスライサーでの絞り込みがしやすい形になります。

4.6 Power Query と M 言語の関係

ここまでの操作はすべてマウスとボタンだけで行ってきました。しかし裏側では、ボタンを押すたびにM 言語と呼ばれるプログラミング言語のコードが自動的に生成されています。「適用したステップ」の各行は、実は M 言語の式が積み重なったものです。

ステップを1つクリックして数式バーを見ると、そのステップに対応する M の式が表示されます。さらに 表示 → 詳細エディター を開くと、クエリ全体の M コードを一度にまとめて確認できます。試しに、この章の実習でマージを行った後の詳細エディターを覗くと、次のようなコードが見えるはずです。

詳細エディター（M コードの抜粋。コメントは解説用に追記したもの） 
let
    // ...（読み込みと型変更のステップは省略。直前のステップ名が「変更された型」）
    // Products テーブルと ProductID で左外部結合する
    マージされたクエリ = Table.NestedJoin(
        変更された型, {"ProductID"},
        Products, {"ProductID"},
        "Products", JoinKind.LeftOuter
    ),
    // 結合結果から ProductName 列だけを取り出して展開する
    展開されたProducts = Table.ExpandTableColumn(
        マージされたクエリ, "Products", {"ProductName"}
    )
in
    展開されたProducts

let から in までの間に、これまでのステップが上から順番に並んでいるのが分かります。Table.NestedJoin がマージ操作、Table.ExpandTableColumn が列の展開操作に対応しており、GUI で行った操作名がそのままステップ名（マージされたクエリ など）になっています。

入門段階では M を書けなくてよい

M 言語を自分で書けると、GUI にないような細かい条件分岐や繰り返し処理も表現できるようになります。ただし本ガイドの範囲では、GUI の操作で組み立てられれば十分です。まずは「ボタン操作の裏で M が生成されている」「詳細エディターを見れば何が起きているか確認できる」ということだけ知っておけば、この先の章に困ることはありません。必要になったときに数式バーを読めることの方が、最初から M を書けることより重要です。

やってみよう 4-1: 売上データを整形して商品名を付ける

みらい商事の売上 CSV（Sales）を Power Query で整形し、Products をマージして商品名まで表示できるようにします。

手順

  1. 1 Sales の CSV を読み込み、データの変換 で Power Query エディターを開く。
  2. 2 分析に使わない列（社内用の備考列など）を右クリックから削除する。
  3. 3 OrderDate を日付型、Quantity を整数、Amount を10進数に変更する。
  4. 4 Amount が空欄（null）の行をフィルターで除外する。
  5. 5 ホーム → クエリのマージ で Products を ProductID で左外部結合し、ProductName 列を展開する。
  6. 6 「適用したステップ」に6つ前後のステップが積み上がっていることを確認し、閉じて適用 する。

理解度確認クイズ

  1. Q1. 「適用したステップ」とは何ですか。Excel の手作業と比べて何が優れていますか？

    回答を表示

    「適用したステップ」は、列の削除や型の変更などの操作を行った順番どおりに自動で記録する仕組みです。Excel の手作業は結果だけが残り手順は残りませんが、Power Query は手順そのものが保存されるため、データが更新されても更新ボタン1つで同じ整形を自動的に再現できます。この性質を再現性と呼びます。

  2. Q2. マージ（Merge）と追加（Append）は、それぞれ何を増やす操作ですか。具体例とあわせて説明してください。

    回答を表示

    マージは共通のキー列（例: ProductID）で2つのテーブルを横に結合し、列を増やす操作です。Sales に Products の商品名を付け加える場合に使います。追加は列構成が同じテーブルを縦に積み、行を増やす操作です。1月分と2月分の売上テーブルを1つにまとめる場合に使います。

  3. Q3. 整形の中で、データ型の変更をまっさきに行うべき理由は何ですか？

    回答を表示

    型が違ったままだと、数値のはずの列が合計できなかったり、日付のはずの列が DateTable と正しくリレーションを組めなかったりと、後工程の集計・モデリングが失敗する原因になるためです。また型を直す前に組んだフィルターやカスタム列は「文字列としての比較」になり、意図しない結果になることがあります。だからこそ、列の削除・列名の変更のあとにまず型を確認するのが安全な順番です。
