ホーム Excel VBA 第4章

VBAの基本文法

第3章では、操作を記録するとVBAのコードが自動的に書かれることを確認しました。この章からは、そのコードを自分の手でゼロから書いていきます。VBAのコードは「Sub」と「End Sub」という2つの言葉に挟まれた小さな入れ物の中に、命令を1行ずつ並べていくだけの、驚くほどシンプルな仕組みでできています。この章では入れ物の作り方、読みやすく書くためのルール、そしてVBAの命令に共通する「オブジェクト・プロパティ・メソッド」という考え方を身につけ、次章以降で本格的にコードを書くための土台を作ります。

この章で学ぶこと

  • Sub 〜 End Sub の構造を説明し、自分でゼロからマクロを書ける
  • コメント・インデント・行継続など、読みやすいコードの書き方を実践できる
  • 「オブジェクト・プロパティ・メソッド」というVBAの基本的な考え方を説明できる
  • イミディエイトウィンドウと Debug.Print を使って、処理の途中経過を確認できる

前章までのふりかえり

第3章では、操作を記録すると VBA のコードが自動的に書かれることを確認しました。生成されたコードを開くと、必ず Sub から End Sub までのまとまりと、ドット（.）でつながった命令が並んでいたはずです。この章では、その同じ構造を「文法」として整理し、記録に頼らず自分の手でゼロからマクロを書けるようにします。

4.1 Subプロシージャ — マクロ1つ分の入れ物

VBAでは、マクロ1つ分の手順をまとめる入れ物のことを Subプロシージャ と呼びます。Sub は「Subroutine（小さな処理のまとまり）」の略で、Sub マクロ名() という行から始まり、End Sub という行で終わります。この2行に挟まれた部分に、実行させたい命令を1行ずつ書いていきます。まずは、これ以上削れないくらい小さなマクロを見てみましょう。

SayHello — 最小のマクロ 
Sub SayHello()
    ' この行はコメント。実行されず、説明を書くために使う
    MsgBox "こんにちは、VBA！"
End Sub

1行目の Sub SayHello() が「ここから SayHello という名前のマクロが始まる」という宣言、4行目の End Sub が「ここで終わる」という宣言です。名前のうしろにある () は、マクロに渡す追加情報である引数（ひきすう）を書く場所ですが、今の段階では空のままで問題ありません。引数の使い方は第10章で扱います。2〜3行目が実際に実行される命令で、'（シングルクォート）で始まる行はコメントとしてExcelに無視されます。

注意: End Sub を消してしまうとエラーになります

VBE で Sub SayHello() と入力して Enter を押すと、End Sub は自動的に生成されます。この行をうっかり消してしまうと、実行時や別のプロシージャを書こうとしたときに「プロシージャの外では無効です」「End Sub が必要です」といったエラーが出ます。エラーが出たら、まず Sub と End Sub の対応が崩れていないかを確認してください。

プロシージャ名の付け方

マクロの名前（プロシージャ名）は自由に決められますが、いくつかの規則があります。

  • 先頭は文字にする — 数字やアンダースコアから始めることはできない
  • スペースや記号は使えない — - や / などは使えず、区切りたい場合はアンダースコア _ を使う
  • 日本語も使えるが、英数字を推奨 — 「合計欄を作る」のような日本語名も動作するが、本章以降は半角英数字のプロシージャ名で統一する
  • 予約語や既存の機能名は避ける — Sub・Dim・End などの予約語は使えない。Range・MsgBox のように Excel／VBA が既に持っている名前も、動作はするが混乱のもとなので避ける

注意: 名前の付け方でもエラーになります

1月集計（数字始まり）や 売上 集計（スペースを含む）といった名前は入力した時点で構文エラーになります。

また、同じ標準モジュールの中に同じ名前の Sub を2つ作ってしまうと、実行しようとした時点で「あいまいな名前を検出しました」というコンパイルエラーが出ます。名前が重複していないか、迷ったら VBE のプロジェクトエクスプローラーで確認しましょう。

VBAのコードは、Sub の直後の行から End Sub の直前の行まで、原則として上から下へ1行ずつ順番に実行されます。この章の後半（4.4）で学ぶ Call を使うと、途中で別のマクロに処理を任せて、終わったら元の位置に戻ってくることもできます。全体の流れを図にすると次のようになります。

flowchart TD A["Sub 開始"] --> B["1行目の処理"] B --> C["2行目: Call 別のマクロ"] C --> D["3行目の処理"] D --> E["End Sub 終了"] C -. 呼び出す .-> X["呼び出された別のSub
（処理を実行して戻る）"] X -. 戻る .-> D

図の説明: コードは Sub から End Sub まで、原則として上から下へ1行ずつ実行されます。途中に Call があると、そこで別のSubプロシージャへ処理が移り、その処理が終わると呼び出し元の続きの行に戻ってきます。Callの詳しい書き方は4.4で説明します。

4.2 読みやすいコードの書き方

コードは一度書いたら終わりではなく、後で自分や他の人が読み返し、直し、機能を追加していくものです。「後から読む自分への手紙」だと考えて、次の4つの習慣を最初から身につけておきましょう。

1行1命令が原則

1つの行には、1つの命令だけを書きます。複数の処理を無理に1行へ詰め込まないことで、どこで何をしているかが一目で分かります。この方針は第14章の完成コードまで一貫して守ります。

コメントで意図を残す

'（シングルクォート）から行末までは、実行されないコメントになります。「何をしているか」だけでなく「なぜそうしているか」を書いておくと、後で読んだときに理解が速くなります。

インデントで段を揃える

Tab キーで、Sub の中身を1段右にずらします。まとまりが目で分かるようになり、第7章以降で学ぶ分岐や繰り返しの入れ子でも迷わなくなります。

長い行は折り返す

行末に半角スペース＋アンダースコア（_）を置くと、そこで行を折り返して次の行に続けて書けます。1行が長くなりすぎるのを防げます。

4つの習慣を1つのコードにまとめると、次のようになります。4.1の SayHello を少し発展させ、コメント・インデント・行継続をあわせて使ってみましょう。

ShowSheetName — コメントと行の折り返し 
Sub ShowSheetName()
    ' 「売上明細」シートの名前をメッセージで表示する

    ' 長い行は行末に半角スペース＋アンダースコアを置くと
    ' 次の行に折り返して書ける
    MsgBox "対象シートの名前は " & _
           Worksheets("売上明細").Name & " です"
End Sub

MsgBox に渡す文字列が長くなったため、&（文字列をつなげる記号）の直後で行を折り返しています。折り返した2行目も、続きであることが分かるように同じ深さのインデントを揃えると読みやすくなります。

注意: 全角スペース・全角記号が混ざると構文エラーになります

日本語入力（IME）がオンのまま " や ( を打つと、見た目はそっくりでも全角文字として入力されてしまい、その行が赤字になってエラーになります。

コードを入力するときは半角英数モードに切り替える習慣をつけましょう。入力後に行が赤くなったら、まず全角のスペース・カッコ・引用符が紛れ込んでいないかを疑ってください。日本語の文章として書くのは、コメントと文字列（" で囲んだ部分）の中だけです。

4.3 オブジェクト・プロパティ・メソッドという考え方

第1章で「ブック → シート → セル」という入れ子の話をしましたが、VBAの命令はほぼすべて、次の3つの言葉の組み合わせでできています。この3つを区別できるようになると、初めて見る命令でも意味を推測できるようになります。

オブジェクト ＝ もの

操作する対象そのもの。「ブック」「シート」「セル」など、Excelの中に存在する“もの”を指します。例: Range、Worksheet

プロパティ ＝ 状態や値

オブジェクトが持っている「状態や値」のこと。セルの値、文字の太さ、背景の色など、「〜の◯◯」で言い表せるものはプロパティです。多くは = を使って読み取ったり、値を代入して変えたりします。例: Value、Font.Bold

メソッド ＝ させる操作

オブジェクトに行わせる「操作」のこと。コピーする、削除する、幅を自動調整するなど、動詞にあたるものはメソッドです。多くは = を使いません。例: Copy、Delete、AutoFit

日本語の文に対応させると分かりやすくなります。「A1セルの／文字の太さを／太字にする」という文は「A1セル（オブジェクト）の／文字の太さ（プロパティ）を／太字にする（値の代入）」という意味です。一方「A1セルを／コピーする」は「A1セル（オブジェクト）を／コピーする（メソッド）」という意味になります。VBAでは、この「〜の」にあたる部分を .（ドット）でつなぎます。住所を「都道府県 → 市区町村 → 番地」とたどるのと同じ考え方です。

実際のコードで、プロパティとメソッドの書き方の違いを確認してみましょう。「売上明細」シートを開いた状態で実行すると、A1セルの見出しである「日付」をあらためて設定する例になります（どのシートを操作するかをコードで明示する書き方は第6章で学びます）。

ObjectSample — プロパティとメソッドの違い 
Sub ObjectSample()
    ' プロパティ＝性質を変える（= を使って値を代入する）
    Range("A1").Value = "日付"
    Range("A1").Font.Bold = True
    ' メソッド＝動作をさせる（= を使わない）
    Range("A1").EntireColumn.AutoFit   ' A列の幅を内容に合わせて自動調整する
End Sub

Range("A1").Value = "日付" は「A1セルの／値を／"日付"にする」というプロパティの書き換え、Range("A1").Font.Bold = True は「A1セルの／文字の／太さを／太字にする」というプロパティの書き換えです。どちらも = の右側に値を書いています。これに対して最後の Range("A1").EntireColumn.AutoFit は「A1セルを含む列を／自動調整する」という動作の指示なので、= は登場しません。

flowchart TD A["VBAの命令"] --> B["オブジェクト＝もの"] A --> C["プロパティ＝性質"] A --> D["メソッド＝動作"] B --> B1["Range、Worksheet"] C --> C1["Value、Font.Bold"] D --> D1["Copy、Delete、AutoFit"]

図の説明: VBAの命令は、操作対象である「オブジェクト」に対して、「プロパティ」で性質を確認・変更するか、「メソッド」で動作をさせるかのどちらかに分類できます。迷ったときは、この3つのどれに当てはまるかを考えると命令の意味をつかみやすくなります。

ヒント: 見分けの目安（あくまで簡易的な手がかり）

初めて見る命令が出てきたら、まず = があるかどうかを確認すると、大まかな見分けの助けになります。= があれば性質を読み書きするプロパティ、無ければ何かの動作を実行させるメソッドである可能性が高いです。

ただしこれは書き方の見た目からの当てずっぽうにすぎません。Range("A1").Copy のように = が無くてもメソッド、ws.Cells(1,1).Value = 10 のように = があってもプロパティ、というだけで、見た目だけでは決まらない例外もあります。迷ったら「これは状態や値か、それともさせる操作か」で考えてください。判断の主軸は、あくまで先に説明した本質的な違い（プロパティ＝状態や値、メソッド＝させる操作）です。

4.4 マクロを実行する・止める

コードを書いたら、実際に動かして確認します。VBE上での実行・停止の操作は、キーボードから行うものがほとんどです。特に F8によるステップ実行は、コードが1行ずつどう動くかを目で追える、初心者にとって最も心強い機能です。

操作 キー操作 できること
実行 F5 カーソルがあるマクロを、最初から最後まで一気に実行する
ステップ実行 F8 1行ずつ実行し、今どこを実行しているかを黄色いハイライトで確認できる
強制中断 Ctrl + Break 実行中のマクロを途中で止める（意図しない繰り返しで固まったときに使う）
リセット ツールバーの ■ ボタン 中断・実行中の状態を解除し、最初からやり直せるようにする

4.1の図で予告したとおり、マクロの中から別のマクロを呼び出すには Call を使います。処理をいくつかのSubプロシージャに分けて、それぞれを組み合わせて実行できるようになると、1つ1つのマクロが短く、目的がはっきりしたものになります。この考え方は第10章で「関数化」として本格的に扱いますが、ここでは呼び出し方の基本だけをつかんでおきましょう。

Main — 別のマクロを呼び出す 
Sub Main()
    ' Call を付けても付けなくても呼び出せる（Call は省略可）
    Call SayHello
    PrintSalesInfo
End Sub

Call SayHello は「SayHelloという名前のマクロを実行して、終わったらここに戻ってくる」という意味です。Call は省略でき、PrintSalesInfo のようにマクロ名だけを書いても同じように呼び出せます（PrintSalesInfo は次の4.5で作成します）。Main を実行すると、上から順に SayHello → PrintSalesInfo の順で処理が進みます。

4.5 イミディエイトウィンドウとDebug.Print

処理の途中経過を確認する方法として、ここまで MsgBox を使ってきました。分かりやすい反面、MsgBox は表示されるたびに手でダイアログを閉じる必要があり、第8章で学ぶ「繰り返し処理」の中に置くと、100回繰り返せば100回閉じることになってしまいます。そこで登場するのが Debug.Print です。

MsgBox

画面にダイアログを表示し、閉じるまで処理を止めます。ユーザーに知らせたい・確認してほしい場面に向いています。

Debug.Print

処理を止めずに、イミディエイトウィンドウという専用の画面へ値を書き出します。動作確認・デバッグ用として優れています。

PrintSalesInfo — Debug.Printで途中経過を確認する 
Sub PrintSalesInfo()
    ' イミディエイトウィンドウ（Ctrl + G）に出力する。画面を邪魔しない
    Debug.Print "処理を開始します"
    Debug.Print "対象シート: " & Worksheets("売上明細").Name
    Debug.Print "A1セルの値: " & Worksheets("売上明細").Range("A1").Value
    Debug.Print "処理を終了しました"
End Sub

このマクロを実行すると、画面には何も表示されず、代わりにイミディエイトウィンドウへ次のように書き出されます。イミディエイトウィンドウが見当たらないときは Ctrl + G で表示できます。

イミディエイトウィンドウの表示例 
処理を開始します
対象シート: 売上明細
A1セルの値: 日付
処理を終了しました

実行するたびに前回の内容の下へ追加されていくため、画面が見づらくなってきたら、イミディエイトウィンドウの中で右クリックして「すべてクリア」を選ぶと消去できます。

ヒント: 繰り返し処理の相棒はDebug.Print

第8章で学ぶ「繰り返し処理」を書くようになると、Debug.Print の便利さを実感する場面が増えます。「今、何行目を処理しているか」「変数に何が入っているか」を止めずに確認できるため、意図どおりに動かないときの原因調査（第12章のデバッグ）にも欠かせない道具になります。

ここまでで、Subプロシージャの作り方、読みやすいコードの書き方、オブジェクト・プロパティ・メソッドという考え方、マクロの実行・停止方法、そしてDebug.Printによる確認方法を学びました。知識としては理解できても、実際に自分の指でコードを打ち込んでみるまでは体に馴染みません。ここからは、実習で手を動かしてみましょう。

やってみよう 4-1: 3つのSubプロシージャを自分の手で入力する

標準モジュール「M_Main」に、次の3つの Sub をコピーせず、自分の手で入力してみましょう。手で打つことで、Sub・End Sub・引用符・ドットの位置が体で覚えられます。

手順

  1. 1 VBEで標準モジュール「M_Main」を挿入する（第2章の手順を思い出しましょう）。
  2. 2 ShowMyName という名前の Sub を作り、MsgBox で自分の名前と今日の日付を表示するコードを入力する。
  3. 3 PrintHeaders という名前の Sub を作り、「売上明細」シートのA1〜E1の値を Debug.Print で1行ずつ出力するコードを入力する。
  4. 4 RunAll という名前の Sub を作り、上の2つのマクロを Call で順番に呼び出すコードを入力する。
  5. 5 カーソルを RunAll の中に置き、F8 キーで1行ずつステップ実行し、黄色いハイライトがどのように動くか、呼び出し先のマクロにも移動することを観察する。

実行前 ―「売上明細」シートの状態

この演習は、下の状態から始めます。特にA1セルの値が「日付」になっていることを確認してください。

    A列        B列    C列            D列   E列
 1  日付        支店   商品名         単価 数量
 2  2026/04/01  東京   A4コピー用紙    480   12
 3  2026/04/01  横浜   付箋セット      320   50
 …（11行目まで、合計10件）

実行するコード

4.5で作成した PrintSalesInfo を実行して、環境が確定サンプルデータと一致しているかを先に確認しておきましょう（ShowMyName・PrintHeaders・RunAll の作成は、この確認のあとで行います）。

PrintSalesInfo — 実行結果を確認する 
Sub PrintSalesInfo()
    ' イミディエイトウィンドウ（Ctrl + G）に出力する。画面を邪魔しない
    Debug.Print "処理を開始します"
    Debug.Print "対象シート: " & Worksheets("売上明細").Name
    Debug.Print "A1セルの値: " & Worksheets("売上明細").Range("A1").Value
    Debug.Print "処理を終了しました"
End Sub

期待される実行結果

VBEの「表示」→「イミディエイトウィンドウ」（Ctrl + G）に、次の4行が表示されます。

理解度確認クイズ

  1. Q1. コードにコメント（説明文）を書くための記号は何ですか。

    回答を表示

    シングルクォート（'）です。VBAでは ' から行末までがコメントとして扱われ、実行されません。Rem という書き方もありますが行頭専用で、実務ではほとんど使われません。

  2. Q2. MsgBox と Debug.Print の違いを説明してください。

    回答を表示

    MsgBox は画面にダイアログを表示し、閉じるまで処理を止めます。Debug.Print は処理を止めずに、イミディエイトウィンドウへ値を書き出します。100回の繰り返しの中に MsgBox を入れると100回閉じる必要がありますが、Debug.Print ならその心配がないため、動作確認には Debug.Print が向いています。

この章のまとめ

  • マクロ1つ分の入れ物は Sub マクロ名() から End Sub までで、中の命令は原則として上から下へ1行ずつ実行される。
  • 読みやすいコードの4原則は「1行1命令」「コメント」「インデント」「行継続（_）」である。
  • VBAの命令はオブジェクト（もの）に対してプロパティ（性質、= を使う）を変えるか、メソッド（動作、= を使わない）を実行させるかのどちらかである。
  • 実行は F5、1行ずつの確認は F8、強制停止は Ctrl + Break。Call で別のマクロを呼び出せる。
  • 処理を止めずに途中経過を確認するには、MsgBox より Debug.Print（イミディエイトウィンドウ、Ctrl + G）が適している。

次の第5章では、これまで "日付" や 100 のように直接書いていた値を、変数という名前の付いた箱に入れて扱う方法を学びます。変数を使えるようになると、同じコードでも異なる商品・異なる支店に対して使い回せるようになり、これから先の章で扱う分岐や繰り返しの土台になります。
