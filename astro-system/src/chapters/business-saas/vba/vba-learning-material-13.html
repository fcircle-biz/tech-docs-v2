ユーザーとのやり取り

第12章までで、狙いどおりに動き、エラーが起きても止まらないマクロを書けるようになりました。しかし、そのマクロを動かせるのが「VBEを開いてF5キーを押せる人」だけでは、日々の業務でチームに使ってもらうことはできません。この章では、確認や入力を求める会話型のダイアログ（MsgBox・InputBox）、シート上に置くだけで押せるボタン、操作をきっかけに自動で動くイベントプロシージャ、そして自前の入力画面であるUserFormを学びます。第7章で学んだ条件分岐が、ここでは利用者の選択を受けて処理を切り替える場面で活躍します。ここまでの内容を「VBEを知らない同僚でも迷わず使える」マクロへ仕上げる、最後の土台作りです。

13.1 MsgBoxを使いこなす — 情報を表示し、選択をうながす

ここまでの章でも、処理の完了を知らせるために MsgBox を何度か使ってきました。この章では、その MsgBox を体系的に理解し、単なる通知だけでなく「利用者に選ばせて処理を分ける」道具として使いこなせるようにします。基本の書式は次のとおりです。

MsgBoxの書式 
MsgBox メッセージ, ボタンの種類, タイトル
  • 第1引数（メッセージ） — ダイアログに表示する文章。改行したいときは vbCrLf という定数を文字列の間にはさむ。
  • 第2引数（ボタンの種類） — 表示するボタンの組み合わせと、アイコンの種類を表す定数を + でつないで指定する（省略時は OK のみのボタンになる）。
  • 第3引数（タイトル） — ダイアログのタイトルバーに表示する文字（省略時は「Microsoft Excel」などになる）。

ボタンの種類は、押されたボタンに応じて戻り値が変わります。「どのボタンを押したか」をコードで判定するために、この対応関係を覚えておく必要があります。

ボタンの種類定数 表示されるボタン 押したときの戻り値
vbOKOnly（既定値） OK のみ vbOK
vbOKCancel OK ／ キャンセル vbOK または vbCancel
vbYesNo はい ／ いいえ vbYes または vbNo
vbYesNoCancel はい ／ いいえ ／ キャンセル vbYes・vbNo・vbCancel のいずれか

アイコンは見た目を分かりやすくするための添え物で、戻り値には影響しません。ボタンの定数と + でつなげて指定します。

  • vbInformation — 「情報」を表すアイコンを表示する
  • vbExclamation — 「注意」を表すアイコンを表示する
  • vbCritical — 「エラー」を表すアイコンを表示する
  • vbQuestion — 「質問」を表すアイコンを表示する

たとえば vbYesNo + vbQuestion と書くと、「はい／いいえ」ボタンと「？」アイコンを同時に指定できます。これらの定数は内部的には数値として管理されているため、+ で足し合わせて1つの引数にまとめられるのです。実際に、確認ダイアログでよく使う形を見てみましょう。

ConfirmRebuild — MsgBoxの戻り値で処理を分ける 
Sub ConfirmRebuild()
    Dim answer As VbMsgBoxResult
    ' 戻り値を受け取るときは、引数全体を括弧で囲む
    answer = MsgBox("集計シートを作り直しますか？" & vbCrLf & _
                    "現在の内容は消えます。", vbYesNo + vbQuestion, "確認")
    If answer = vbYes Then
        Call PrepareSummarySheet      ' 第9章で作ったマクロを呼び出す
        MsgBox "作り直しました", vbInformation
    Else
        MsgBox "処理を中止しました"
    End If
End Sub

注意: 戻り値を受け取るかどうかで括弧の要・不要が変わります

上のコードをよく見ると、戻り値を変数に受け取る1行目（answer = MsgBox(...)）だけ引数全体が括弧で囲まれ、それ以外の行（MsgBox "作り直しました", vbInformation など）には括弧がありません。

VBAでは、戻り値を代入するときだけ引数を括弧で囲み、代入しないときは括弧を付けないというルールがあります。逆にすると「構文エラー」や「引数は省略できません」といったコンパイルエラーになるので、書くときはどちらの形か意識しましょう。

上のコードの流れを図にすると、次のようになります。戻り値によって処理が2つに分かれる様子を確認してください。

flowchart TD A["MsgBoxで確認
「作り直しますか？」"] --> B{"戻り値は vbYes か"} B -->|はい| C["集計シートを作り直す"] C --> D["完了メッセージを表示"] B -->|いいえ| E["何もせず終了メッセージを表示"]

図の説明: MsgBoxで確認を取り、利用者が「はい」を選んだ場合だけ実際の処理（集計シートの作り直し）を行います。「いいえ」を選んだ場合は何もせず、中止したことだけを伝えて終了します。利用者の選択が、そのままコードの分岐先を決めています。

13.2 InputBoxで入力を受け取る

MsgBoxがあらかじめ用意した選択肢から選ばせる道具だとすれば、InputBox は利用者に自由に文字や数値を入力してもらうための関数です。書式は次のとおりです。

InputBoxの書式 
InputBox(メッセージ, タイトル, 既定値)

第3引数の「既定値」は、入力欄にあらかじめ表示しておく文字です。利用者がよく入力する値を既定値にしておくと、毎回すべて打ち込まずに済みます。実際の使用例を見てみましょう。

AskBranch — InputBoxで支店名を受け取る 
Sub AskBranch()
    Dim branch As String
    ' 第3引数は入力欄にあらかじめ表示しておく既定値
    branch = InputBox("集計する支店名を入力してください", "支店の指定", "東京")
    ' キャンセルまたは空欄のまま OK した場合は "" が返る
    If branch = "" Then
        MsgBox "処理を中止しました"
        Exit Sub
    End If
    MsgBox branch & " 支店を集計します", vbInformation
End Sub

InputBoxの戻り値は常に文字列型です。利用者が「キャンセル」を押した場合も、何も入力せずに「OK」を押した場合も、どちらも長さ0の文字列 "" が返ります。上のコードの If branch = "" Then のように判定し、処理を中断させるのが基本形です。

数値の入力を期待する場面では注意が必要です。InputBoxが返すのはあくまで文字列なので、利用者が「abc」のような数字以外の文字を打ち込むこともできてしまいます。第7章で学んだ IsNumeric 関数を使い、If IsNumeric(inputText) Then のように検証してから CDbl などで数値に変換する習慣をつけましょう（input はVBAの予約語なので、変数名には inputText のような別の名前を使います）。

より高度な入力を求めたいときは、Application.InputBox メソッドを使います。たとえば Set rng = Application.InputBox("集計する範囲を選択してください", Type:=8) のように第4引数の Type:=8 を指定すると、利用者はキーボードで文字を打つ代わりに、マウスでセル範囲をクリック（またはドラッグ）して選べるようになります。戻り値はRange型のオブジェクトになるため、Dim rng As Range と宣言したうえで Set を付けて受け取ります。キャンセルされたときは真偽値の False が返るため、そのまま Set で受け取ろうとすると実行時エラー424になります。キャンセルにも備えるには、第12章で学んだ On Error Resume Next で囲んでから If rng Is Nothing Then で判定します。

項目 InputBox 関数 Application.InputBox メソッド
戻り値の型 常に文字列型 Type引数で指定した型（セル範囲も可）
セル範囲の選択 できない（手入力のみ） Type:=8 でマウス選択できる
キャンセル時の戻り値 長さ0の文字列 "" False（真偽値）
主な用途 文字列や数値を1つ入力してもらう セル範囲や条件を選ばせる

13.3 シート上にボタンを置いてマクロを実行する

ここまでのマクロは、VBEを開いてF5キーを押すか、マクロ一覧（Alt + F8）から選んで実行してきました。しかし、Excelの操作に慣れていない同僚にVBEを操作してもらうのは現実的ではありません。シート上にボタンを置き、クリックひとつでマクロを実行できるようにしましょう。

フォームコントロールのボタンを配置する手順

  1. 1 リボンの「開発」タブを開く。表示されていない場合は「ファイル」→「オプション」→「リボンのユーザー設定」で「開発」にチェックを入れる。
  2. 2 「開発」タブ →「挿入」→「フォームコントロール」の一覧から、左上のボタンのアイコンを選ぶ。
  3. 3 マウスカーソルが十字に変わるので、シート上でドラッグしてボタンの大きさを決める。マウスを離すと「マクロの登録」ダイアログが自動的に開く。
  4. 4 登録したいマクロ名（例: ConfirmRebuild）を一覧から選び、「OK」をクリックする。
  5. 5 ボタンの上で右クリック →「テキストの編集」を選び、表示文字を分かりやすい名前（例: 「集計をやり直す」）に書き換える。
  6. 6 ボタン以外の場所をクリックして編集を終了し、実際にボタンをクリックしてマクロが動くことを確認する。
  7. 7 登録するマクロを後から変更したい場合は、ボタンを右クリック →「マクロの登録」を選び直せばよい。

① フォームコントロールのボタン

灰色の専用ボタン部品です。配置から登録まで数クリックで完結し、誰が見ても「押せるボタン」だと分かる素朴な見た目が長所です。

② 図形（オートシェイプ）に登録

四角形や角丸四角形などの図形を描き、右クリック →「マクロの登録」で同じように紐づけられます。色や文字を自由に変えられ、社内ツールらしい見た目に仕上げられます。

重要: 「VBEを知らない人でも使える」が最終ゴールです

ここまで学んできた文法やオブジェクト操作は、あくまで「正しく動くコード」を書くための土台でした。実際に業務でマクロを使ってもらうには、コードを書けない人でも迷わず操作できる入り口が欠かせません。ボタンや、この後に学ぶイベント・UserFormは、その入り口を作るための道具です。

ボタンにMsgBoxによる確認を組み合わせると、利用者の操作から完了までの一連の流れができあがります。13.1で作った ConfirmRebuild をボタンに登録した場合の流れを、時系列で見てみましょう。

図の説明: 利用者がシート上のボタンを押すと、そのボタンに登録されたマクロが実行されます。マクロはまずMsgBoxで確認を取り、利用者の選択に応じて処理を進めるか中止するかを決め、最後に結果をMsgBoxで知らせます。VBEを一度も開かずに、この一連のやり取りが完結する点が重要です。

13.4 イベントプロシージャ — 何かが起きたら自動で動く

ボタンは「利用者が押す」という能動的なきっかけでマクロを実行する方法でした。一方で、「ブックを開いたら」「セルの値が変わったら」というように、Excel側で何かが起きたタイミングで自動的にマクロを実行したい場面もあります。これを実現するのがイベントプロシージャです。

イベントプロシージャを書く場所

これまでの標準モジュール（Module1など）とは異なり、イベントプロシージャは対応するオブジェクトのモジュールに書きます。ブック全体に関わるイベントは ThisWorkbook モジュールへ、特定のシートだけに関わるイベントはそのシートのモジュールへ書きます。

ThisWorkbook モジュール

ブック全体に関わるイベントを書く場所です。Workbook_Open（ブックを開いたとき）や Workbook_BeforeClose（閉じる直前）などがあります。

シートモジュール

そのシート固有のイベントを書く場所です。Worksheet_Change（セルの値が変わったとき）や Worksheet_SelectionChange（選択セルが変わったとき）などがあります。

VBEのプロジェクトエクスプローラーで対象のモジュール（ThisWorkbookや各シート名）をダブルクリックしてコードウィンドウを開くと、上部に2つのドロップダウンがあります。左側で対象（WorkbookやWorksheet）を選び、右側でイベント名（OpenやChange）を選ぶと、Private Sub 〜 End Sub の雛形が自動的に挿入されます。この雛形の中に処理を書き足していきます。

ヒント: イベントプロシージャは標準モジュールに書いても動きません

標準モジュール（Module1など）に Private Sub Workbook_Open() と書いても、ただの実行されないSubが1つ増えるだけで、ブックを開いても何も起こりません。イベントプロシージャは、対応するオブジェクトのモジュール（ThisWorkbookまたは各シートモジュール）に書いて初めて、Excel側から自動的に呼び出されます。

まずは、ブックを開いたときに自動実行される例です。このコードは ThisWorkbook モジュールに書きます。

ThisWorkbookモジュール — Workbook_Openイベント 
' ★このコードは標準モジュールではなく ThisWorkbook モジュールに書く
Private Sub Workbook_Open()
    ' ブックを開いたら「売上明細」シートを表示して、A2 セルを選択する
    ThisWorkbook.Worksheets("売上明細").Activate
    ThisWorkbook.Worksheets("売上明細").Range("A2").Select
    MsgBox "売上管理ブックを開きました", vbInformation, "ようこそ"
End Sub

次は、セルの値が変わったときに自動計算する例です。多くのイベントプロシージャには、何が起きたかを表す引数が自動的に渡されます。ここでは Target が「変更されたセル」を表します。このコードは「売上明細」シートのシートモジュールに書きます。

売上明細のシートモジュール — Worksheet_Changeイベント 
' ★このコードは「売上明細」シートのシートモジュールに書く
Private Sub Worksheet_Change(ByVal Target As Range)
    ' 複数セルを一度に貼り付けた場合は処理しない（エラー防止）
    If Target.Cells.Count > 1 Then Exit Sub
    ' 変更されたのが D列（単価）か E列（数量）で、2行目以降のときだけ計算する
    If (Target.Column = 4 Or Target.Column = 5) And Target.Row >= 2 Then
        Cells(Target.Row, 6).Value = Cells(Target.Row, 4).Value * _
                                     Cells(Target.Row, 5).Value
    End If
End Sub

注意: Worksheet_Change は暴走しやすいイベントです

複数セルをまとめてコピー＆ペーストすると、Targetがそのセル範囲全体を指すため、単一セルを前提にした計算はエラーになります。上のコードの1行目にある If Target.Cells.Count > 1 Then Exit Sub は、この事故を防ぐための定番の書き方です。

また、Worksheet_Changeの中で自分自身がセルに書き込むと、その書き込みが新たな変更として扱われ、再びWorksheet_Changeが呼び出されてしまうことがあります（無限ループの原因）。込み入った処理を書くときは、書き込みの前に Application.EnableEvents = False でイベントの発生を一時的に止め、処理の最後に必ず Application.EnableEvents = True で元に戻してください。

さらに、D列やE列に数値以外の文字が入力されると掛け算がエラー13（型が一致しません）になります。実務で使うときは、乗算の前に If IsNumeric(Cells(Target.Row, 4).Value) And IsNumeric(Cells(Target.Row, 5).Value) Then のような確認を挟むと安全です。

13.5 UserForm入門 — 自分だけの入力画面を作る

InputBoxは1回に1項目しか入力できません。支店名・商品名・単価・数量のように複数の項目をまとめて入力してもらいたい場合は、UserFormという自前のダイアログ画面を作ります。

注意: UserFormはWindows版Excel専用の機能です

UserFormはWindows版Excelを前提とした機能です。Mac版ExcelのVBEにはUserFormを作るためのデザイン画面（ツールボックス）が無く、新しく作成することができません（Windowsで作成したフォームが表示できる場合もありますが、使えないコントロールがあるなど動作は保証されません）。またWeb版Excel（ブラウザ版）はマクロの実行そのものに対応していないため、UserFormを含め本章で学ぶ機能はすべて動作しません。

本ガイドは第2章の前提のとおりWindows版Excelでの学習を想定しています。会社でMac版やWeb版しか使えない場合、この節は読み物として理解にとどめ、無理に手を動かす必要はありません。

フォームを作る手順

  1. 1 VBEのメニューで「挿入」→「ユーザーフォーム」を選ぶと、白紙のフォームと「ツールボックス」が表示される。
  2. 2 ツールボックスから配置したい部品をクリックし、フォーム上でドラッグして配置する。
  3. 3 配置した部品を選んだ状態で「プロパティウィンドウ」を開き、Name（コードから参照する名前）と Caption（画面に表示する文字）を設定する。
  4. 4 ボタンをダブルクリックすると、そのボタンをクリックしたときの処理を書くコードウィンドウが自動的に開く。
  5. 5 標準モジュールなどからフォームを表示するには UserForm1.Show、表示中のフォームを閉じるには Unload Me と書く。

よく使う代表的な部品は次の3つです。まずはこの3つの組み合わせだけで、多くの入力フォームが作れます。

TextBox

利用者が自由に文字を入力する欄です。商品名や数量のように、決まった選択肢がない項目に使います。

ComboBox

あらかじめ用意した候補から選ばせる欄です。支店名のように選択肢が決まっている項目に向き、入力ミスも防げます。

CommandButton

クリックされたときに処理を実行させるボタンです。「登録」や「閉じる」など、フォームの締めくくりに使います。

本ガイドでは、「売上明細」に1件だけデータを追加する最小限のフォームを、次の「やってみよう」で実際に作ります。TextBoxを4つとComboBoxやCommandButtonを組み合わせるだけでも、実務で十分に使える入力画面になります。

やってみよう 13-1: ボタンとイベントで「使えるツール」に仕上げる

これまでに作ったマクロを、VBEを開かなくても使える形に仕上げていきましょう。

手順

  1. 1 「売上明細」シートにフォームコントロールのボタンを2つ配置し、それぞれ RunFast（第11章で作成）と ConfirmRebuild を登録する。ボタンの表示文字をそれぞれ「金額とランクを更新」「集計シートを作り直す」に変更する。
  2. 2 Workbook_Open を ThisWorkbook モジュールに書き、ブックを一度閉じてから開き直し、メッセージが自動的に表示されることを確認する。
  3. 3 Worksheet_Change を「売上明細」のシートモジュールに書き、D列（単価）またはE列（数量）の値を書き換えると、F列（金額）が自動的に再計算されることを確認する。
  4. 4 発展: UserForm1 を作り、TextBox1（支店）・TextBox2（商品名）・TextBox3（単価）・TextBox4（数量）・CommandButton1（登録）を配置し、下のコードで「売上明細」の末尾に1件追加できるようにする。
UserForm1のCommandButton1 — クリック時に売上明細へ1件追加 
Private Sub CommandButton1_Click()
    Dim ws As Worksheet, newRow As Long
    If Not IsNumeric(TextBox3.Value) Or Not IsNumeric(TextBox4.Value) Then  ' 数値か確認
        MsgBox "単価と数量には数値を入力してください", vbExclamation
        Exit Sub
    End If
    Set ws = Worksheets("売上明細")
    newRow = ws.Cells(ws.Rows.Count, "A").End(xlUp).Row + 1   ' 追加する行
    ws.Cells(newRow, "A").Value = Date          ' 日付は今日の日付
    ws.Cells(newRow, "B").Value = TextBox1.Value ' 支店
    ws.Cells(newRow, "C").Value = TextBox2.Value ' 商品名
    ws.Cells(newRow, "D").Value = CDbl(TextBox3.Value) ' 単価（数値に変換）
    ws.Cells(newRow, "E").Value = CDbl(TextBox4.Value) ' 数量（数値に変換）
    Unload Me                                    ' フォームを閉じる
End Sub

理解度確認クイズ

  1. Q1. MsgBoxで「はい」ボタンが押されたことを判定するために比較する定数はどれか。

    ア. vbOK　　イ. vbYes　　ウ. vbTrue

    回答を表示

    正解: イ（vbYes）。vbYesNo で表示したダイアログの戻り値は vbYes または vbNo です。vbOK は vbOKCancel で表示した場合の戻り値になります。なお戻り値を受け取るには answer = MsgBox("...", vbYesNo) のように、引数全体を括弧で囲む必要があります。

  2. Q2. InputBoxでキャンセルボタンが押されたときの戻り値はどれか。

    ア. False　　イ. 長さ0の文字列 ""　　ウ. Empty

    回答を表示

    正解: イ（長さ0の文字列 ""）。VBAの InputBox 関数は、キャンセル時も空欄のまま OK した時も "" を返すため、この2つを区別できません。区別が必要な場合は Application.InputBox を使います（キャンセル時は False を返します）。

この章のまとめ

  • MsgBox は「メッセージ・ボタンの種類・タイトル」の3引数で情報表示や確認ができ、戻り値を受け取るときは引数全体を括弧で囲む。
  • InputBox は利用者からの入力を受け取れるが、キャンセル時と空欄OK時はどちらも "" を返すため区別できない。区別が必要なら Application.InputBox を使う。
  • シート上にフォームコントロールのボタンを配置してマクロを登録すると、VBEを開かずにマクロを実行できる。
  • イベントプロシージャは標準モジュールではなく、ThisWorkbookモジュール（Workbook_Openなど）やシートモジュール（Worksheet_Changeなど）に書く。
  • Worksheet_Changeでは、複数セル貼り付けやイベントの連鎖に注意し、Target.Cells.Count や Application.EnableEvents で制御する。
  • UserFormを使うと複数項目をまとめて入力する自前の画面を作れるが、Mac版Excelでは新規作成できず、Web版Excelではマクロ自体が動作しない。

これで、マクロを「動くコード」から「他の人が使えるツール」へ仕上げるための道具がそろいました。次の第14章では、これまで14章を通じて作ってきたマクロを1つにまとめ、ボタン1つで「金額とランクの更新」から「帳票の作成・保存」までを実行できる、さくら文具株式会社の業務自動化ミニアプリを完成させます。
