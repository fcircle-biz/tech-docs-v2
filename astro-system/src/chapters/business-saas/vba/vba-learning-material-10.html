ホーム Excel VBA 第10章
第10章 所要時間: 約90分

プロシージャと関数

第6章から第9章にかけて、「売上明細」を集計し、整え、転記し、複数シートを扱うマクロを書いてきました。機能を追加するたびにコードの行数は増え、気づけば1つのマクロが100行を超えていた——という人も多いはずです。この章では、そうした長いマクロを意味のある単位に分割する方法を学びます。呼び出すたびに違う値を渡せるSub、計算結果を値として返すFunction、そしてワークシートの数式からも呼び出せるユーザー定義関数——この3つの道具を身につけると、これまで書いてきたコードが驚くほどすっきりと整理できます。

重要: この章でいちばん大事なのは「Sub と Function の違い」

この章でいちばん大事なのは、Sub（実行して終わる処理）とFunction（答えを返す処理）の違いが分かることです。10.1〜10.3節をしっかり理解すれば、この章の目的は達成です。後半に出てくるByVal / ByRefやPublic / Privateは、慣れてから読み返せばよい発展的な内容です。無理に一度で覚えようとしなくて大丈夫です。

この章で学ぶこと

  • SubとFunctionの違いを説明し、目的に応じて使い分けられる
  • 引数を渡して処理を汎用化し、戻り値を受け取るプロシージャを書ける
  • ByVal（値のコピーを渡す）とByRef（変数そのものを貸す）の違いを理解し、意図して指定できる（発展）
  • Public / Privateによるスコープ（その名前がどこまで通用するかの範囲）を理解し、モジュールを役割ごとに分割できる（発展）
  • ワークシート上で使えるユーザー定義関数（UDF）を作れる（発展）

10.1 長いマクロの問題と、処理を分ける発想 基本

第9章までに書いたマクロを思い出してみましょう。最初は数行だった処理も、条件分岐やループを足していくうちに、気づけば50行、100行と伸びていませんでしたか。1つのプロシージャがどんどん長くなっていくと、次の3つの問題が起こります。

読めない

100行のコードを開いても、どこで何をしているのか一目では分からず、内容を思い出すだけで時間がかかります。

直せない

1か所を修正しようとしても、どこまで影響が及ぶか分からず、直したつもりが別の場所で不具合を起こすことがあります。

使い回せない

「最終行を求める」処理のように他のマクロでも使いたい部分があっても、コピー＆ペーストで増やすしかありません。

解決の発想はシンプルです。料理のレシピを「下ごしらえ」「炒める」「盛り付け」という工程に分けて書くように、マクロも意味のあるまとまりごとに分けて名前を付ければよいのです。分けた1つひとつの処理をプロシージャと呼びます。VBAのプロシージャには、これまで使ってきたSubと、この章で新しく学ぶFunctionの2種類があります。

プロシージャを分けるときの原則はただ1つ、「1つのプロシージャは1つの仕事に絞る」ことです。「売上明細を読み込んで、集計して、書式を整えて、保存する」という1本のマクロではなく、「読み込む」「集計する」「整える」「保存する」という4つのプロシージャに分け、それぞれに分かりやすい名前を付けます。名前を見るだけで何をする処理か分かるようになれば、それは適切に分割できているサインです。

この章では、処理を部品化するための4つの道具を順番に学びます。

道具 できること 学ぶ節
引数を受け取るSub 呼び出すたびに違う値で同じ処理を実行する 10.2
値を返すFunction 処理結果を値として呼び出し元に返す 10.3〜10.4
Public / Private 呼び出せる範囲を制御し、モジュールを役割ごとに分ける 10.5
ユーザー定義関数（UDF） ワークシートの数式からVBAの処理を呼び出す 10.6

10.2 Subに引数を渡して汎用化する 基本

第2章〜第9章で書いたSubは、いずれも括弧の中が空でした。Subの括弧の中には、呼び出すときに渡す値——引数（ひきすう）——を書くことができます。引数を使うと、1つのSubを「毎回違う値」で呼び出して使い回せるようになります。

引数を受け取るSub — 同じ処理をいろいろな文言で使い回す 
' 括弧の中の message が「受け取る値（引数）」
Sub WriteLog(ByVal message As String)
    ' 現在時刻を付けてイミディエイトウィンドウに記録する
    Debug.Print Format(Now, "hh:nn:ss") & "  " & message
End Sub

Sub MainProcess()
    WriteLog "処理を開始しました"       ' 括弧なしで呼び出す
    Call WriteLog("処理を終了しました") ' Call を付けるときは括弧が必要
End Sub

Sub WriteLog(ByVal message As String)の括弧の中にあるmessageが引数です。message As Stringは「messageという名前で文字列を受け取る」という意味で、第5章で学んだ変数宣言とほぼ同じ書き方です。呼び出す側で渡した値が、そのままSubの中でmessageとして使えるようになります。MainProcessを実行すると、イミディエイトウィンドウ（Ctrl+G で表示）に次のように記録されます。

イミディエイトウィンドウの表示例 
10:15:30  処理を開始しました
10:15:31  処理を終了しました

引数を持つSubの呼び出し方には2通りあります。WriteLog "開始"のようにSub名の後にスペースで値を並べる書き方と、Call WriteLog("開始")のようにCallを付けて括弧で囲む書き方です。どちらも動作は同じですが、括弧の付け方がCallの有無と対応している点に注意してください。

注意: Callと括弧の組み合わせを間違えるとエラーになる

Call WriteLog "開始"（Callありで括弧なし）や引数を2つ取るSubを MySub("A", "B") のように書く形（Callなしで引数2つを括弧付き）は、どちらも構文エラーになります。

覚え方はシンプルです。「Callを付けるなら括弧あり、付けないなら括弧なし」。迷ったら括弧なしで統一するとエラーが起きにくくなります。

もう1つ、引数を持つSubには特徴があります。Excelの「マクロ」ダイアログ（Alt+F8）の一覧には表示されなくなるのです。これは、Excelが「どんな値を渡せばよいか」を自動では判断できないためです。引数を持つSubは、ボタンや別のプロシージャから呼び出す部品として使うと考えてください。

10.3 Functionと戻り値 基本

Subは処理を実行するだけで、結果を呼び出し元に返しません。一方、計算結果や判定結果を「値」として呼び出し元に返したい場面もよくあります。そのためのプロシージャがFunctionです。

SubとFunctionの違いは、「やってもらう」か「答えをもらう」かの違いだと考えると分かりやすいでしょう。Subに頼むのは「ログを記録して」「シートを整えて」といった作業そのものです。Functionに頼むのは「税込価格はいくら？」「このシートの最終行は何行目？」といった質問で、返ってくるのは実行結果ではなく答えの値です。

Functionの宣言はFunction 名前(引数) As 戻り値の型という形で、Subの宣言に「戻り値の型」が付いただけです。そしてFunctionの中で関数名そのものに値を代入すると、それが呼び出し元への戻り値（もどりち＝処理結果として返ってくる値）になります。

値を返すFunction — 税込金額を計算する 
' As Double は「戻り値の型」。Optional は省略できる引数
Function TaxIncluded(ByVal price As Double, Optional ByVal taxRate As Double = 0.1) As Double
    ' 関数名に代入すると、それが戻り値になる
    TaxIncluded = Int(price * (1 + taxRate))
End Function

Sub UseTaxIncluded()
    MsgBox "税込（10%）: " & TaxIncluded(10000) & " 円" & vbCrLf & _
           "税込（8%）: " & TaxIncluded(10000, 0.08) & " 円"
End Sub

TaxIncluded = Int(price * (1 + taxRate))の行で、関数名TaxIncluded自身に計算結果を代入しています。これが戻り値です。引数のうちOptional ByVal taxRate As Double = 0.1のOptionalは「省略できる引数」を表すキーワードで、詳しくは次の10.4節で扱います。UseTaxIncludedを実行すると、次のようなメッセージが表示されます。

MsgBoxの表示例 
税込（10%）: 11000 円
税込（8%）: 10800 円

注意: 戻り値を設定し忘れると静かに間違える

TaxIncluded = ...の行を書き忘れると、Functionはエラーを出さずに、常に0（数値型の場合）や空文字（文字列型の場合）を返します。

エラーにならないぶん気づきにくいバグです。Functionを書いたら、必ず「関数名への代入があるか」を見直す習慣をつけましょう。

呼び出し元とFunction・Subのやり取りを図にすると、次のようになります。

sequenceDiagram participant M as 呼び出し元 participant F as Function TaxIncluded participant S as Sub WriteLog M->>F: 引数10000を渡して呼び出す F-->>M: 戻り値11000を返す M->>S: 引数「開始」を渡して呼び出す Note over M,S: Subは値を返さない（戻りの矢印がない）

図の説明: Functionを呼び出すと、実線の矢印で引数が渡り、破線の矢印で戻り値が返ってきます。Subを呼び出す場合は引数を渡すだけで、戻ってくる矢印は描かれません。この「戻りの矢印があるかどうか」が、SubとFunctionの一番の違いです。

ここまでの内容を踏まえて、「Subで作るべきか、Functionで作るべきか」を判断する目安を図にまとめます。ワークシートの数式から使いたい場合の考え方（10.6節で扱うユーザー定義関数）も含めています。

ユーザー定義関数として使う"] D -->|いいえ| F["VBAコードの中だけで呼び出す"]

図の説明: 迷ったらまず「値を返す必要があるか」を自問してください。返す必要がなければSub、返す必要があればFunctionです。さらにFunctionの場合は、ワークシートの数式でも使いたいかどうかで、10.6節のユーザー定義関数にするかどうかが決まります。

10.4 ByVal / ByRef と省略可能な引数 発展

発展: ここは今は読み飛ばしても先に進めます

ByValとByRefの違いは、慣れてから読み返せばよい発展的な内容です。今の時点では「引数を渡せる」ことが分かっていれば十分です。第14章で実際に使う場面が出てきたら、ここに戻ってきてください。

10.2節・10.3節のコード例では、引数の前にByValというキーワードを付けていました。これは引数の渡し方を指定するキーワードで、VBAにはByVal（値渡し）とByRef（参照渡し）の2種類があります。

ByRefは、変数そのものへの参照を渡します。呼び出された側でその引数の値を変更すると、呼び出し元の変数の値も一緒に変わります。ByValは、値のコピーを渡します。呼び出された側でいくら変更しても、コピーが変わるだけで呼び出し元の変数には影響しません。VBAでは、ByValもByRefも書かなかった場合、既定でByRefとして扱われる点に注意してください。

ByRefとByValの違いを1つの変数で確認する 
' ByRefとByValの違いを、同じ「2倍にする」処理で見比べる
Sub DoubleByRef(ByRef num As Long)
    num = num * 2      ' 呼び出し元の変数も書き換わる
End Sub

Sub DoubleByVal(ByVal num As Long)
    num = num * 2      ' コピーを書き換えるだけ。呼び出し元は変わらない
End Sub

Sub CompareRefAndVal()
    Dim a As Long, b As Long
    a = 10
    b = 10
    DoubleByRef a
    DoubleByVal b
    Debug.Print a      ' 20（ByRefなので書き換わった）
    Debug.Print b      ' 10（ByValなので元のまま）
End Sub

CompareRefAndValを実行すると、DoubleByRefに渡したaは呼び出し後に20へ書き換わっているのに対し、DoubleByValに渡したbは呼び出し後も10のままです。同じ「2倍にする」処理でも、渡し方によって呼び出し元への影響が変わることが分かります。

観点 ByRef（既定） ByVal
渡すもの 変数そのものへの参照 値のコピー
呼び出し先での変更 呼び出し元の変数にも反映される 呼び出し元の変数は変わらない
書き方 省略可（何も書かなければこちら） 必ずByValと明記する
実務での推奨 意図して使う場合だけ選ぶ 原則こちらを明示する

呼び出し元の変数をうっかり書き換えてしまうと、原因の分かりにくいバグにつながります。実務では、変更するつもりがない引数には明示的にByValを書く習慣をつけましょう。「既定のByRefに任せる」のではなく「ByValと書いて安全を宣言する」という考え方です。

もう1つ、10.3節のコード例に出てきたOptionalについても説明します。Optional 引数名 As 型 = 既定値と書くと、その引数は呼び出し時に省略できるようになります。省略した場合は= 既定値で指定した値が使われます。TaxIncluded(10000)のようにtaxRateを省略すれば10%（既定値0.1）、TaxIncluded(10000, 0.08)のように指定すれば8%として計算されます。

ヒント: Optionalな引数は最後にまとめる

Optionalを付けた引数は、付けていない引数（必須の引数）より後ろに書く必要があります。Function TaxIncluded(ByVal price As Double, Optional ByVal taxRate As Double = 0.1)のように、必須のpriceを先に、省略可能なtaxRateを後に置きます。

10.5 スコープとモジュール構成 発展

発展: ここは今は読み飛ばしても先に進めます

Public / Privateによるスコープの制御は、慣れてから読み返せばよい発展的な内容です。第14章で実際にモジュールを分割する場面が出てきたら、ここに戻ってきてください。

プロシージャが増えてくると、「どこからでも呼べるようにするか」「このモジュールの中だけで使うか」を意図的に決める必要が出てきます。この「どこから呼び出せるか」という範囲をスコープと呼びます。

用語: スコープ

変数や部品の名前が「どこまで通用するか」という有効範囲のことを スコープ と呼びます。社内だけで通じる呼び名か、社外にも通じる正式名か、の違いだと考えてください。

VBAでは、プロシージャの前にPublicまたはPrivateを付けることでスコープを指定します。Publicは他のモジュールからも呼び出せる公開の部品、Privateはそのモジュールの中だけで使う非公開の下請け処理です。何も書かなかった場合はPublicとして扱われます。

観点 Public（既定） Private
呼び出せる範囲 他のモジュールからも呼べる 同じモジュール内だけ
省略時の扱い 何も書かなければPublic相当になる 明示的にPrivateと書く必要がある
使いどころ 複数モジュールで共有する部品（例: GetLastRow） そのモジュール内だけで使う下請け処理

変数にも同じ考え方が当てはまります。プロシージャの中でDimした変数はそのプロシージャの中だけで使えるプロシージャレベル変数ですが、モジュールの先頭（プロシージャの外）で宣言した変数は、そのモジュール内のすべてのプロシージャから使えるモジュールレベル変数になります。多用すると影響範囲が分かりにくくなるため、本ガイドでは基本的にプロシージャレベル変数と引数の受け渡しで処理をつなげる方針を取ります。

スコープの考え方を使って、本ガイドではこれ以降、1つの標準モジュールにすべてを書くのではなく、役割ごとに4つのモジュールへ分けていきます。

M_Main — 実行の入口

ボタンなどから呼ばれる、処理全体の入口となるプロシージャを置きます。

M_Aggregate — 集計処理

支店別・商品別の集計ロジックをまとめて置きます。

M_Report — 帳票出力

集計結果を整形して出力する処理をまとめて置きます。

M_Common — 共通の部品

GetLastRow・BranchAreaなど、どのモジュールからも呼ばれる汎用処理を置きます。

呼び出す・呼び出されるの関係を図にすると、次のようになります。実行の入口であるM_Mainが集計と帳票出力のモジュールを呼び出し、どちらのモジュールも共通部品であるM_Commonを利用する、という構成です。

flowchart TD A["M_Main
（実行の入口）"] --> B["M_Aggregate
（集計処理）"] A --> C["M_Report
（帳票出力）"] B --> D["M_Common
（共通の部品）"] C --> D

図の説明: M_Mainが起点となり、M_AggregateとM_Reportをそれぞれ呼び出します。両方のモジュールが最下段のM_Commonにある共通処理（GetLastRowなど）を呼び出すことで、同じコードを2重に書かずに済みます。

この4分割の構成は、第14章の総合演習でそのまま使います。今の時点では「新しい機能を追加するときは、どのモジュールに書くべきかを考える」という意識を持てれば十分です。

10.6 ユーザー定義関数をワークシートで使う 発展

発展: ここは今は読み飛ばしても先に進めます

ユーザー定義関数（UDF）は、慣れてから読み返せばよい発展的な内容です。第14章で実際に使う場面が出てきたら、ここに戻ってきてください。

標準モジュールに書いたFunctionには、もう1つ便利な使い道があります。VBAのコードからではなく、ワークシートの数式から直接呼び出すことができるのです。自分で作って、ワークシートのセルに=関数名(…)と書いて使える関数のことをユーザー定義関数（UDF ＝ User Defined Function）と呼びます。SUMやIFの“自作版”です。

M_Common — 最終行を求める処理を部品にする 
' M_Common モジュールに置く共通部品
Function GetLastRow(ByVal ws As Worksheet, ByVal colName As String) As Long
    ' 指定したシートの、指定した列の最終行番号を返す
    GetLastRow = ws.Cells(ws.Rows.Count, colName).End(xlUp).Row
End Function

Sub ShowLastRow()
    ' 第6章・第8章で毎回書いていた1行が、これだけで済むようになる
    MsgBox "売上明細の最終行: " & GetLastRow(ThisWorkbook.Worksheets("売上明細"), "A")
End Sub

このGetLastRowは、第6章・第8章で毎回書いていた「Cells(Rows.Count, "A").End(xlUp).Row」という1行を部品化したものです。どのシートの、どの列の最終行が知りたいかを引数wsとcolNameで指定できるようにしたことで、「売上明細」シート以外でも、A列以外でもそのまま使い回せるようになりました。

ワークシートでも使えるユーザー定義関数 — 支店名からエリアを返す 
' シート上で =BranchArea(B2) のように使える
Function BranchArea(ByVal branch As String) As String
    Select Case Trim(branch)
        Case "東京", "横浜"
            BranchArea = "関東"
        Case "大阪", "京都"
            BranchArea = "関西"
        Case "名古屋"
            BranchArea = "中部"
        Case Else
            BranchArea = "その他"
    End Select
End Function

BranchAreaのようなFunctionは、標準モジュールに書くだけで、セルに=BranchArea(B2)と入力すればそのまま使えます。SUMやVLOOKUPと同じ感覚で、自分で作った関数をワークシートの数式に組み込めるということです。「売上明細」シートのH列（エリア）に入力した場合、結果は次のようになります。※「京都」は本ガイドのサンプルデータには含まれていませんが、Caseは1つの行に複数の値をカンマで並べられることを示すために入れてあります。

B列（支店） H列に入力する数式 表示される値
東京（B2） =BranchArea(B2) 関東
横浜（B3） =BranchArea(B3) 関東
大阪（B4） =BranchArea(B4) 関西
名古屋（B6） =BranchArea(B6) 中部
福岡（未登録の支店を試しに入力した場合） =BranchArea("福岡") その他

注意: ユーザー定義関数はセルの書式を変えられない

=BranchArea(A1)のように数式として呼び出されたFunctionの中で、セルの色を変えたり他のセルに書き込んだりしても反映されません（Excelの仕様です）。ユーザー定義関数は「値を返すだけ」と割り切り、書式変更や他セルへの書き込みが必要な処理はSubとしてマクロで実行してください。

ユーザー定義関数は、参照しているセルの値が変わったときに自動的に再計算されます。ただし、シートの再計算そのものに関わらない情報（現在時刻など）を返す関数を作りたい場合は、Application.Volatileという指定が必要になる場面もあります。これは応用的な内容なので、今は「そういう仕組みがある」と知っておく程度で十分です。

やってみよう 10-1: 共通処理をモジュールに切り出す

これまでのマクロに繰り返し登場していた処理を、名前の付いた部品として切り出してみましょう。

手順

理解度確認クイズ

  1. Q1. 処理の結果を「値」として呼び出し元に返せるのはどちらですか。ア. Sub　イ. Function　ウ. どちらも返せる

    回答を表示

    正解: イ
    Functionは関数名 = 値の形で戻り値を設定します。Subは処理を実行するだけで値を返しません（引数をByRefで書き換える方法はありますが、分かりにくいため推奨しません）。

  2. Q2. 引数をByRefで渡し、呼び出された側でその値を変更するとどうなりますか。ア. 呼び出し元の変数の値も変わる　イ. 呼び出し元の変数は変わらない　ウ. コンパイルエラーになる

    回答を表示

    正解: ア
    ByRefは変数そのものへの参照を渡すため、呼び出し先の変更が呼び出し元に反映されます。VBAの既定がByRefである点が事故のもとなので、意図しない限りByValを明示しましょう。

  3. Q3. ユーザー定義関数の中でセルの色を変えたり、他のセルに書き込んだりするとどうなりますか。

    回答を表示

    反映されません（Excelの仕様です）。ワークシートの数式から呼び出されるユーザー定義関数は値を返すことしかできず、セルの書式変更や他セルへの書き込みは行えません。そうした処理が必要な場合は、Subとして作成しマクロとして実行します。

この章のまとめ

  • 長い処理は意味のある単位に分けることで、読みやすく・直しやすく・使い回しやすくなる。
  • Subは「やってもらう」処理、Functionは「値を返してもらう」処理という使い分け。戻り値は関数名への代入で設定する。
  • 引数の既定はByRef（参照渡し）。意図しない書き換えを防ぐにはByValを明示する。Optionalで省略可能な引数も作れる。
  • Public / Privateでスコープを制御し、役割ごとにモジュールを分ける（M_Main / M_Aggregate / M_Report / M_Common）。
  • 標準モジュールのFunctionは、ワークシート上でユーザー定義関数として使える（ただし値を返すのみ）。
