ホーム Excel VBA 第14章
第14章 所要時間: 約120分

実践：業務自動化ミニアプリ

第1章で、本ガイドは「ボタン1つで支店別帳票が出るツールを作る」ことを最終ゴールに掲げました。第2章から第13章にかけて、VBAの文法・セル操作・条件分岐・繰り返し・シート操作・処理の部品化・配列とDictionary・エラー処理・ボタンとメッセージという道具を、1つずつ手に入れてきました。この最終章では、それらすべてを実際に組み合わせ、さくら文具株式会社の月次業務――売上明細から支店別の売上合計を出し、帳票を作って提出する――を、ボタン1つで完了するミニアプリとして完成させます。コードを書く前に要件を言葉にする設計の手順から、他の人にも安心して渡せる形に仕上げるところまで、実務での自動化ツール作りの一連の流れを体験しましょう。

この章で学ぶこと

  • やりたいことを要件として整理し、処理手順（設計）に分解できる
  • 複数のデータを集計して帳票シートへ出力する、一連のマクロを完成させられる
  • 第5章から第13章までに学んだ機能を、目的に応じて選び組み合わせて設計できる
  • 作ったマクロを、他の人が安心して使える形（ボタン・確認・エラー処理・完了通知）に仕上げられる

この章の位置づけ ― 全14章の集大成

本章は新しい文法を学ぶ章ではありません。第10章で作った最終行を求める関数、第11章で学んだ配列とDictionaryによる集計、第12章のエラー処理、第13章のMsgBoxとボタンを、1つの実用マクロとして組み合わせます。コードのコメントには「（第◯章）」という形で、その部品を学んだ章を添えていますので、記憶があいまいな部分があれば該当章に戻って読み返しながら進めてください。

14.1 作るものを決める ― 要件を言葉にする

新しいマクロを作るとき、いきなりVBEを開いてコードを書き始めたくなりますが、実務ではまず「何を作るか」を言葉にしておくことが近道です。要件があいまいなまま書き始めると、途中で「支店の並び順はどうするんだっけ」「データが無いときはどうする」といった迷いが生まれ、書いては直しの繰り返しになりがちです。今回作るのは、担当者が毎月手作業で行っている「売上明細から支店別の合計を出し、帳票を作って提出する」という業務です。これを、次の5つの観点で言葉にしておきましょう。

観点 今回作るツールの要件
① 入力 「売上明細」シートのA列（日付）〜F列（金額）
② 処理 利用者が指定した対象年月のデータだけを、支店ごとに金額（F列）を合計する
③ 出力 「帳票」シートに対象年月・支店別の一覧表と合計行を作る
④ 操作方法 「売上明細」シートに配置した「帳票を作成」ボタンを押し、対象年月を入力するだけ
⑤ 異常時の動き ①データが0件、②年月の入力を中止・書式ミス、③対象年月のデータが0件、のときは案内して中止する。不正な行は読み飛ばして件数を知らせる。「帳票」シートが無ければ自動作成する。エラーが起きても画面設定は必ず元に戻す

この5つの要件を満たすために、これまでの章で作った部品をどう割り当てるかを整理すると、次のようになります。「学んだ章」の列を見て記憶があいまいな部分があれば、先にその章を読み返しておくと後の節がスムーズに読めます。

部品 本章での役割 学んだ章
変数と型 支店名や金額を入れる箱を用意する 第5章
セルへの読み書き 「売上明細」の値を読み、「帳票」へ書く 第6章
条件分岐（If） データが0件かどうかを判定する 第7章
繰り返し（For / For Each） 支店の一覧・データ行を順番に処理する 第8章
複数シートの操作 「売上明細」と「帳票」の2枚を行き来する 第9章
処理の関数化・GetLastRow 集計・出力を部品ごとのプロシージャに分ける 第10章
配列とDictionary 大量データを高速に読み込み、キーごとに集計する 第11章
On Error によるエラー処理 エラーで処理が止まらないようにする 第12章
MsgBox・InputBox・ボタン 対象年月の受け取り、利用者への確認・完了通知、ワンクリック実行 第13章

重要: 要件は「入力・処理・出力」だけで終わらせない

動くコードを書けても、使う人がどう起動するか、データが無いときにどうなるかを決めていないツールは、結局作った本人しか使えません。上の表の④操作方法・⑤異常時の動きまで含めて要件と呼ぶ、という意識を持ちましょう。

14.2 処理を分けて設計する ― モジュール構成

要件が決まったら、次は「どのプロシージャが何を担当するか」に分解します。第10章では、1つの標準モジュールに処理を詰め込みすぎず、役割ごとにモジュールを分ける設計を学びました。今回も同じ考え方で、次のプロシージャに分けます。

モジュール プロシージャ 種類 役割
M_Main RunSalesReport Sub 実行の入口。全体の流れと後片付けを担当
M_Main AskTargetMonth Function 対象年月を利用者から受け取り、"yyyy/mm" 形式で返す
M_Aggregate AggregateByBranch Function 対象年月のデータだけを支店別に集計し、結果を返す
M_Report PrepareReportSheet Function 「帳票」シートを用意する（無ければ作る／あれば消す）

「1つのプロシージャは1つの仕事だけをする」という第10章の原則を、ここでも徹底します。RunSalesReport はデータの中身を1行も読みません。集計は AggregateByBranch に任せ、その結果（Dictionary）だけを受け取って次に渡す――という役割分担にすることで、後から「集計方法だけ変えたい」「出力先を変えたい」となったときに、直す場所が1つのプロシージャに絞り込めます。

値の受け渡し方

AggregateByBranch は Function として作り、集計結果のDictionaryを戻り値として返します。WriteReport は Sub として作り、そのDictionaryを引数で受け取ります。「集計する部品」と「出力する部品」の間を、シートの値ではなくDictionaryというデータそのものでつなぐことで、途中経過をシートに書き出す手間や、シートを読み間違えるリスクを減らせます。この「FunctionとSubを組み合わせ、戻り値と引数でデータを受け渡す」という考え方は第10章で学んだ内容そのものです。

14.3 データを読み込んで集計する

集計処理を作る前に、まず2つの小さな部品を用意します。1つは第10章で作った「最終行を求める関数」の復習、もう1つは本章で新しく追加する「データの有無を確認する関数」です。

M_Common モジュール ― GetLastRow（第10章の復習） 
' 指定した列の最終行番号を求める（第10章で作成済み）
Function GetLastRow(ByVal ws As Worksheet, ByVal col As String) As Long
    GetLastRow = ws.Cells(ws.Rows.Count, col).End(xlUp).Row
End Function

次に、集計を始める前の「ガード」を用意します。売上明細に1件もデータが無い状態でいきなり集計に入ると、見出し行だけを読み込んでしまい、支店名の代わりに「支店」という見出し文字がDictionaryに登録される、といった気づきにくい不具合につながります。そこで、条件分岐（第7章）とエラー処理の考え方（第12章）を組み合わせ、データが無ければその場でメッセージを出して処理を止める関数を作ります。

M_Common モジュール ― HasSalesData（本章で追加） 
' 「売上明細」に1件以上データがあるか確認する
Function HasSalesData() As Boolean
    Dim ws As Worksheet
    Set ws = ThisWorkbook.Worksheets("売上明細")
    If GetLastRow(ws, "A") < 2 Then
        MsgBox "売上明細にデータがありません", vbExclamation   ' 0件を知らせる
        HasSalesData = False
    Else
        HasSalesData = True
    End If
End Function

見出し行（1行目）しか無ければ GetLastRow は 1 を返すため、2 未満かどうかで「データ行が1行も無い」ことを判定できます。この関数の呼び出し方は14.5節で扱います。

もう1つ、本章で新しく用意する部品が「シートの有無を調べる関数」です。次の節で作る「帳票」シートの自動作成（PrepareReportSheet）で使うので、先にここで用意しておきます。考え方は第9章の演習で作った「シートの存在確認」と同じで、ブック内のすべてのシートを For Each（第8章）で順に見ていき、名前が一致するものがあるかどうかを返します。

M_Common モジュール ― SheetExists（第9章の応用） 
' 指定した名前のシートがこのブックにあるかどうかを返す（第9章の応用）
Function SheetExists(ByVal sheetName As String) As Boolean
    Dim ws As Worksheet
    For Each ws In ThisWorkbook.Worksheets
        If ws.Name = sheetName Then
            SheetExists = True
            Exit Function          ' 見つかった時点で調べ終わる
        End If
    Next ws
    SheetExists = False
End Function

GetLastRow・HasSalesData・SheetExists の3つは、いずれも「売上明細」や「帳票」といった特定のシートに依存しない、汎用的な小部品です。このように、複数の機能から呼ばれる共通処理を M_Common モジュールへまとめておくのが、第10章で学んだ「役割ごとにモジュールを分ける」考え方の実践です。

対象年月を受け取る

帳票のタイトルは「2026年4月 支店別売上レポート」のように、特定の年月を表します。したがって集計も、その年月のデータだけを対象にしなければ、タイトルと中身が食い違ってしまいます。そこで、集計に入る前に InputBox（第13章）で対象年月を尋ねる関数を用意します。入力された文字列が本当に年月として読めるかどうかは、IsDate 関数（第7章の条件分岐と組み合わせ）でチェックします。

M_Main モジュール ― AskTargetMonth（本章で追加） 
' 対象年月を利用者に尋ね、"yyyy/mm" の形にそろえて返す
' キャンセル・空欄・書式ミスのときは "" を返す（呼び出し側はそれを見て中止する）
Function AskTargetMonth() As String
    Dim answer As String
    Dim defaultValue As String

    ' 入力欄には今月をあらかじめ表示しておく
    defaultValue = Format(Date, "yyyy/mm")

    answer = InputBox("集計する年月を入力してください。" & vbCrLf & _
                      "例: 2026/04（年4桁 / 月2桁）", _
                      "対象年月の指定", defaultValue)

    ' ［キャンセル］または空欄のまま［OK］を押した場合
    If answer = "" Then
        AskTargetMonth = ""
        Exit Function
    End If

    ' 「2026/04」に「/01」を足して日付として読めるかどうかで正しさを判定する
    If Not IsDate(answer & "/01") Then
        MsgBox "年月の形式が正しくありません。" & vbCrLf & _
               "「2026/04」のように、年4桁と月を「/」で区切って入力してください。", _
               vbExclamation, "帳票を作成"
        AskTargetMonth = ""
        Exit Function
    End If

    ' 「2026/4」のような入力も「2026/04」にそろえてから返す
    AskTargetMonth = Format(CDate(answer & "/01"), "yyyy/mm")
End Function

戻り値が空文字列 "" のときは「中止すべき状態」を表す、という約束にしています。呼び出し側（RunSalesReport）は、この関数の戻り値が空かどうかを見るだけで、キャンセル・未入力・書式ミスの3パターンをまとめて判定できます。

配列とDictionaryで集計する

対象年月を受け取れたら、いよいよ集計です。第11章で学んだとおり、セルを1つずつ読みに行くより、範囲をまとめて配列に読み込んでからループで処理する方が高速です。読み込んだ行を支店ごとに束ねるには、同じく第11章の Dictionary を使います。存在しないキーに加算しようとすると自動的に 0 から始まる、という性質を利用して、1行のコードで「新しい支店なら追加、既にある支店なら足し込む」を同時に行えます。あわせて、日付が読めない・支店名が空欄・金額が数値でない、といった不正なデータの行は集計から除き、読み飛ばした件数を呼び出し元に伝えるようにします。

M_Aggregate モジュール ― AggregateByBranch 
Option Explicit

' 対象年月（"yyyy/mm"）のデータだけを支店別に集計し、結果をDictionaryで返す
' skippedCount には、内容が正しくないため読み飛ばした行数を返す
Function AggregateByBranch(ByVal targetMonth As String, _
                           ByRef skippedCount As Long) As Object
    ' 配列の列番号をハードコーディングせず、Constで名前を付ける（第5章）
    Const COL_DATE As Long = 1     ' 1列目＝A列（日付）
    Const COL_BRANCH As Long = 2   ' 2列目＝B列（支店）
    Const COL_AMOUNT As Long = 6   ' 6列目＝F列（金額）

    Dim dic As Object
    Dim ws As Worksheet
    Dim data As Variant
    Dim i As Long
    Dim branchName As String

    Set dic = CreateObject("Scripting.Dictionary")
    Set ws = ThisWorkbook.Worksheets("売上明細")

    ' A列（日付）からF列（金額）までを1回のやり取りでまとめて読み込む（第11章）
    data = ws.Range("A2:F" & GetLastRow(ws, "A")).Value

    skippedCount = 0

    For i = 1 To UBound(data, 1)
        If Not IsDate(data(i, COL_DATE)) Then
            ' 日付として読めない行は集計しない
            skippedCount = skippedCount + 1
        ElseIf Trim(CStr(data(i, COL_BRANCH))) = "" Then
            ' 支店名が空欄の行は集計しない
            skippedCount = skippedCount + 1
        ElseIf IsError(data(i, COL_AMOUNT)) Then
            ' 単価や数量に文字が入っていて金額が #VALUE! になっている行
            skippedCount = skippedCount + 1
        ElseIf Not IsNumeric(data(i, COL_AMOUNT)) Then
            ' 金額が空欄、または数値として読めない行
            skippedCount = skippedCount + 1
        ElseIf Format(data(i, COL_DATE), "yyyy/mm") = targetMonth Then
            ' ここまで通った行のうち、対象年月と一致するものだけを足し込む
            branchName = Trim(CStr(data(i, COL_BRANCH)))    ' 表記ゆれ対策（14.6）
            dic(branchName) = dic(branchName) + data(i, COL_AMOUNT)
        End If
        ' 対象年月以外の行は、不正ではないので skippedCount には数えない
    Next i

    Set AggregateByBranch = dic
End Function

読み込む範囲を、支店から始まる B2:F... ではなく A2:F... へ1列広げているため、配列の列番号もシートの列番号から1つずつずれます。ここが今回いちばん間違えやすいポイントです。行番号や列番号を数値のまま書くと、後で読む人には「6って何の6？」としか分かりません。このように意味の分からない数値をコードの中に直接書き込んでしまうことをハードコーディングと呼び、その中でも特に説明なく置かれた数値はマジックナンバーと呼ばれます（第5章）。上のコードでは Const COL_DATE = 1 のように名前を付けることで、列番号がハードコーディングにならないようにしています。

ElseIf（第7章）は上から順に判定され、最初に成立した条件だけが実行されます。そのため「まず日付・支店名・金額が正しく読めるかを順にふるい落とし、最後に対象年月かどうかを見る」という順番になっている点に注目してください。ByRef skippedCount As Long（第10章）は、戻り値（Dictionary）とは別の情報を、呼び出し元の変数へ直接書き戻すための引数です。

ヒント: なぜSubではなくFunctionにするのか

AggregateByBranch を Function にしておくと、「集計する」と「出力する」を分離できます。集計結果はDictionaryとして手元に残るので、帳票への出力だけでなく、将来グラフ用のデータや、メール本文への差し込みなど、別の用途にもそのまま再利用できます。

14.4 帳票シートへ出力する

集計結果のDictionaryができたら、次は「帳票」シートへの書き出しです。ここで1つ考えておきたいのが、「帳票」シートが最初から存在するとは限らないという点です。第9章では「集計」シートを対象に「あれば内容を消す・無ければ作る」という自動作成の処理を学びました。今回も同じ考え方を PrepareReportSheet として部品化し、利用者に「シートを手で作ってください」と求めずに済むようにします。何度実行しても同じ結果になる（冪等な）ツールになるうえ、要件④「ボタンを押すだけ」にも合致します。

M_Report モジュール ― PrepareReportSheet（本章で追加） 
' 「帳票」シートを用意する。無ければ作り、あれば内容を消して返す（第9章の応用）
Function PrepareReportSheet() As Worksheet
    Dim ws As Worksheet
    If SheetExists("帳票") Then
        Set ws = ThisWorkbook.Worksheets("帳票")
        ws.Cells.Clear                     ' 前回の内容と書式を消す
    Else
        ' 一番右に新しいシートを追加する
        Set ws = ThisWorkbook.Worksheets.Add( _
            After:=ThisWorkbook.Worksheets(ThisWorkbook.Worksheets.Count))
        ws.Name = "帳票"
    End If
    Set PrepareReportSheet = ws
End Function

戻り値の型を Worksheet にしているのがポイントです（第5章）。呼び出し元は「帳票シートが無ければどう用意するか」を一切気にせず、戻ってきた ws をそのまま使えます。次の WriteReport では、タイトル・見出し・明細行・合計行の順に書き込みます。行番号は変数 r で管理し、For Each（第8章）でDictionaryのキーを1つずつ取り出します。

M_Report モジュール ― WriteReport 
' 集計結果を「帳票」シートへ書き出す
Sub WriteReport(ByVal dic As Object, ByVal targetMonth As String)
    Dim ws As Worksheet
    Dim k As Variant
    Dim r As Long

    Set ws = PrepareReportSheet()          ' 無ければ作り、あれば消してから使う

    ' タイトルは「集計した月」を表す（実行した日ではない）
    ws.Range("A1").Value = Format(CDate(targetMonth & "/01"), "yyyy年m月") & " 支店別売上レポート"
    ws.Range("A2").Value = "支店"
    ws.Range("B2").Value = "売上金額"

    r = 3
    For Each k In dic.Keys                 ' 支店を1つずつ書き出す
        ws.Cells(r, "A").Value = k
        ws.Cells(r, "B").Value = dic(k)
        r = r + 1
    Next k

    ' 合計行。数式で入れておくと、あとで明細を直しても自動で再計算される
    ws.Cells(r, "A").Value = "合計"
    ws.Cells(r, "B").Formula = "=SUM(B3:B" & r - 1 & ")"

    Call FormatReport(ws, r)               ' 書式を整える
End Sub

ws.Range("A2").Value = "支店" と ws.Range("B2").Value = "売上金額"、ws.Cells(r, "A").Value = "合計" と ws.Cells(r, "B").Formula = "..." は、それぞれ別の行に分けて書いています。第4章で学んだ「1行1命令」を、この完成コードでも守っています。コロン（:）で複数の命令を1行に詰め込むと短くは書けますが、どこで何をしているかが読みにくくなるため、本ガイドでは最後まで使いません。

最後の行にあたる合計行は、Formula プロパティにExcelの数式文字列を書き込む方法を採用しています。合計を出す方法はほかにも考えられるので、違いを比べておきましょう。

方法 書き方 特徴
数式を書き込む（採用） .Formula = "=SUM(...)" セルに数式が残り、後で明細行を編集しても自動で再計算される
WorksheetFunctionで計算 .Value = WorksheetFunction.Sum(範囲) VBA側で計算した数値だけが入り、数式は残らない
集計中に合計を持っておく 合計 = 合計 + dic(k) ループの中で加算するため、書き出した後にシートを読み返す必要が無い

書き出しの最後で FormatReport を呼び出し、見た目を整えます。データを入れる部分と、見た目を整える部分をプロシージャごと分けておくと、「文字は合っているのに罫線だけ直したい」というときに触る場所を絞り込めます。

M_Report モジュール ― FormatReport 
' 帳票の書式を整える
Sub FormatReport(ByVal ws As Worksheet, ByVal lastRow As Long)
    ws.Range("A1").Font.Size = 14                  ' タイトルを大きく
    ws.Range("A1").Font.Bold = True
    With ws.Range("A2:B2")                         ' 見出し行
        .Font.Bold = True
        .Interior.Color = RGB(221, 235, 247)       ' 薄い青
        .HorizontalAlignment = xlCenter
    End With
    ws.Range("A" & lastRow & ":B" & lastRow).Font.Bold = True  ' 合計行
    ws.Range("B3:B" & lastRow).NumberFormatLocal = "#,##0"     ' 桁区切り
    ws.Range("A2:B" & lastRow).Borders.LineStyle = xlContinuous
    ws.Columns("A:B").AutoFit                      ' 列幅を自動調整
End Sub

M_Main モジュール ― RunSalesReport（実行の入口） 
' ボタンから呼び出す実行の入口
Sub RunSalesReport()
    Dim dic As Object
    Dim targetMonth As String
    Dim skippedCount As Long
    Dim savedScreenUpdating As Boolean
    Dim resultMessage As String
    Dim resultIcon As Long

    ' 変更する前の設定を控えておく（後片付けで必ずこの値に戻す。第12章の原則②）
    savedScreenUpdating = Application.ScreenUpdating

    On Error GoTo ErrHandler

    ' ① 前提条件の確認（第12章の原則①）
    If HasSalesData() Then

        ' ② 対象年月を利用者から受け取る（第13章）
        targetMonth = AskTargetMonth()
        If targetMonth <> "" Then

            ' ③ 対象年月のデータだけを支店別に集計する（第11章）
            Application.ScreenUpdating = False
            Set dic = AggregateByBranch(targetMonth, skippedCount)

            If dic.Count = 0 Then
                resultMessage = targetMonth & " の売上データが1件も見つかりませんでした。" & vbCrLf & _
                                "対象年月を確かめて、もう一度実行してください。"
                resultIcon = vbExclamation
            Else
                ' ④ 帳票シートへ書き出す
                Call WriteReport(dic, targetMonth)
                resultMessage = targetMonth & " の帳票を作成しました。" & vbCrLf & _
                                "集計した支店: " & dic.Count & " 件" & vbCrLf & _
                                "読み飛ばした不正データ: " & skippedCount & " 件"
                resultIcon = vbInformation
            End If
        End If
    End If

Cleanup:
    ' 正常時も中止時もここを通る。変更した設定を必ず元の値に戻す（第12章の原則②）
    Application.ScreenUpdating = savedScreenUpdating
    ' 中止した場合は呼び出し先が案内済みなので、ここでは何も表示しない
    If resultMessage <> "" Then
        MsgBox resultMessage, resultIcon, "帳票を作成"
    End If
    Exit Sub                       ' 正常時はここで終了する（重要）

ErrHandler:
    ' 想定外のエラーでも、設定を戻したうえで内容を利用者に伝える（第12章の原則②③）
    Application.ScreenUpdating = savedScreenUpdating
    MsgBox "処理を中断しました。" & vbCrLf & _
           "エラー " & Err.Number & ": " & Err.Description, _
           vbExclamation, "帳票を作成"
End Sub

上から順に読むと、それぞれの行がどの章の学習内容かが見えてきます。On Error GoTo ErrHandler（第12章）でエラーの受け皿を用意し、HasSalesData（本章）で0件を弾き、AskTargetMonth（本章）で対象年月を受け取り、ScreenUpdating（第11章）で画面のちらつきを止めてから集計・出力を行い、最後に MsgBox（第13章）で完了を知らせます。Cleanup: は「エラーが起きても起きなくても必ず通る後片付けの置き場」です。If の入れ子を抜けた処理は自然にこのラベルへ流れ落ちるので、ここへ来るためだけの GoTo は使っていません。Exit Sub を Cleanup: の直後に置いて、正常時に ErrHandler: へ流れ込まないようにする点は、第12章で学んだとおりです。

もう1つ注目してほしいのが savedScreenUpdating です。Application.ScreenUpdating を変更する前の値を控えておき、正常終了・中止・エラーのどの経路をたどっても、必ずこの変数の値へ戻します。True を決め打ちで代入しないのがポイントで、もし他のマクロから呼ばれて ScreenUpdating が最初から False だった場合でも、勝手に True にしてしまいません。「変更した設定は必ず元に戻す」という第11章・第12章の原則を、そのまま踏襲しています。

14.6 初心者がつまずきやすいポイント

今回のように複数のプロシージャを組み合わせると、単体では起きなかった問題が顔を出すことがあります。実際によく起きる3つのつまずきを、先に知っておきましょう。

つまずき①: 「帳票」シートの名前を変えてしまうと別シートが増える

本章の PrepareReportSheet は「帳票」という名前のシートが無ければ自動で作成するため、シートを削除しただけならボタンを押し直すだけで復旧します。注意したいのは、シート名が「帳票 」（末尾に半角スペース）や「帳票2」のように少しでも変わってしまった場合です。SheetExists("帳票") は完全一致でしか判定しないため、元の名前の「帳票」が見つからず、新しいシートがもう1枚追加されてしまいます。

シート名はできるだけ変更せず、「帳票」で統一しておきましょう。それでも想定外のエラー（ブックの保護など）が起きた場合は、On Error GoTo によって画面が壊れることはなく、分かりやすいメッセージが表示されて処理が中止されます。

つまずき②: 画面が固まったように見える

ScreenUpdating = False にしたまま処理が異常終了すると、画面の再描画が止まったままになり、セルを操作しても表示が変わらないため「Excelが壊れた」と誤解しやすくなります。今回のコードは Cleanup: でも ErrHandler: でも必ず savedScreenUpdating（変更前の値）に戻しているため通常は心配ありませんが、開発中にコードを実行の途中で強制終了（Escキーなど）した場合は、この復元処理自体が実行されずに固まって見えることがあります。

その場合は、VBEのイミディエイトウィンドウ（表示 → イミディエイトウィンドウ）に Application.ScreenUpdating = True と入力してEnterキーを押せば、その場で復旧できます。

つまずき③: Dictionaryのキーの表記ゆれで同じ支店が2行に分かれる

「東京」と「東京 」（末尾に半角スペース）のように、見た目はほぼ同じでも1文字でも違えばDictionaryでは別のキーとして扱われ、帳票に同じ支店が2行に分かれて出てしまいます。帳票の行数が想定と違うときは、まずこの表記ゆれを疑いましょう。

対策は、キーを登録する前に Trim で余分な空白を取り除いておくことです。本章の AggregateByBranch（14.3節）では、branchName = Trim(CStr(data(i, COL_BRANCH))) として、このTrimをあらかじめ組み込んであります。なお、VBAの Trim が取り除けるのは半角スペースだけです。全角スペースも想定される場合は Replace(キー, "　", "") を併用してください。

理解度確認クイズ

  1. Q1. RunSalesReport から Exit Sub の行を削除すると、正常終了したときに何が起きますか。

    回答を表示

    完了メッセージの後、そのままエラーハンドラのラベル（ErrHandler:）へ処理が流れ込み、エラーハンドラのメッセージまで表示されてしまいます。Err.Number は正常時には 0 のままなので、「エラー 0」という不可解なメッセージが出ます。第12章で学んだとおり、Exit Sub は正常時にエラーハンドラへ流れ込むのを防ぐための行です。

  2. Q2. 集計処理を Sub ではなく Function（AggregateByBranch）として作った利点は何ですか。

    回答を表示

    「集計する部品」と「出力する部品」を分離できることです。集計結果をDictionaryとして戻り値で返しておけば、出力方法を変えたいときも集計部分をそのまま使い回せますし、グラフ用データやメール本文への差し込みなど、帳票以外の用途にも再利用できます。不具合が起きたときも、集計側と出力側のどちらの問題かを切り分けやすくなります。

14.8 次のステップ ― この先の学び方

全14章で、VBAの基本文法から実用ツールの完成まで一通り体験しました。ここから先は、目的に応じて次の4つの方向に学習を広げていくと、できることがさらに増えていきます。

① ファイル操作を広げる

複数ブックの一括処理（フォルダ内の全ファイルを開いて集計する等）や、CSVファイルの読み書きを学ぶと、Excel単体では完結しない業務も自動化できます。

② 他のOfficeアプリと連携する

VBAはOffice製品に共通の言語です（第1章）。OutlookからExcelのデータを使ってメールを一括送信したり、Wordで差し込み文書を作成したりできます。

③ Power QueryやOffice Scriptsとの使い分け

データの取り込み・整形が中心ならPower Query、Web版Excelでも動く自動化ならOffice Scriptsが向いていることもあります。VBAと使い分ける視点を持つと選択肢が広がります。

④ コードの共有と保守を学ぶ

他の人が読めるコメントの書き方、変更履歴の残し方（バージョン管理）、複数のブックで同じマクロを使い回せる .xlam アドイン化など、「作って終わり」にしないための知識です。

学習を続けるための情報源

  • Microsoft Learn の VBA リファレンス ― オブジェクトやメソッドの正式な仕様を調べたいときの一次情報源です。
  • マクロの記録で調べる ― 第3章で学んだ記録機能は、学習が進んだ後も「この操作をVBAでどう書くか分からない」ときの調べ方として現役で使えます。
  • オブジェクトブラウザー（F2キー） ― VBE上でF2キーを押すと、使えるオブジェクト・プロパティ・メソッドの一覧を検索できます。知らない命令に出会ったときの調べ方として覚えておくと便利です。

この章のまとめ

  • コードを書く前に、入力・処理・出力・操作方法・異常時の動きの5点を言葉にして要件を固めることが、遠回りに見えて一番の近道である。
  • 要件は RunSalesReport（入口）・AskTargetMonth（年月受け取り）・AggregateByBranch（集計）・PrepareReportSheet（シート準備）・WriteReport（出力）・FormatReport（書式）という、役割の異なるプロシージャに分解して実装する。
  • 第10章のGetLastRow、第11章の配列とDictionary、第12章のOn Error、第13章のMsgBox・InputBox・ボタンを組み合わせると、実務で使えるツールになる。列番号は Const（第5章）で名前を付け、コードは最後まで1行1命令（第4章）を守る。
  • データが0件の場合のガード、対象年月の入力チェック、不正データの読み飛ばしと件数通知、「帳票」シートの自動作成、ScreenUpdating の変更前の値への復元など、単体のコードでは見えにくい配慮は、組み合わせて初めて表面化する。
  • 完成したツールは、検算による受け入れテストを行ってから人に渡す。

第1章で「毎月おなじ手順でExcelの表を集計し、別のシートに転記し、決まった形の表を作る――そんな作業を自分の代わりにExcelにやらせる」と説明したVBAの目的を、覚えているでしょうか。ここまで全14章、お疲れ様でした。皆さんは今、まさにその「代わりにやらせる」ツールを、自分の手で最初から最後まで組み上げました。マクロの記録も分からなかった第1章から、Dictionaryやエラー処理を使いこなして総合演習を完成させるところまで、着実に積み上げてきた成果です。

この先大切なのは、命令をすべて暗記することではなく、自分の業務を「入力・処理・出力」に分解して考えられることです。次に「これ、自動化できないかな」と思う作業に出会ったら、まずはこの章のように要件を紙に書き出すところから始めてみてください。本ガイドで身につけた考え方は、そのまま実務の自動化に持ち込めます。皆さんの日々の業務が、少しでも軽やかになることを願っています。
