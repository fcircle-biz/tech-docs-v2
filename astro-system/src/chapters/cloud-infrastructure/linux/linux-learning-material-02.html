ホーム Linux 第2章
第2章 所要時間: 約60分

学習環境を準備する

この章では、手元のパソコンの中に「もう1台のUbuntu」を用意します。Windowsの方はWSL2、Macの方はMultipassを使ってUbuntu 24.04 LTSを起動し、ターミナルからコマンドを打てる状態にします。自分のOSに合った節（2.2または2.3）に沿って、実際に手を動かしながら進めてください。

この章で学ぶこと

  • ホストOSの中でUbuntuが動く仕組み（WSL2／Multipass）を説明できる
  • Windowsで WSL2 を使い、Ubuntu 24.04 を導入できる
  • Macで Multipass を使い、Ubuntu 24.04 の仮想マシンを作成できる
  • 起動したUbuntuのバージョン・ユーザー名・ホスト名を確認できる
  • ターミナルの終了・再開の操作と、よくあるトラブルの対処法を知る

2.1 環境の全体像（ホストOSの中でUbuntuを動かす）

第1章で触れたとおり、本ガイドは Ubuntu 24.04 LTS というディストリビューションを使います。とはいえ、Ubuntu専用のパソコンを新しく買う必要はありません。いま使っているWindowsやMacのホストOS（土台となるOS）はそのまま残し、その中で「もう1台のUbuntu」を動かします。

Windowsでは WSL2（Windows Subsystem for Linux 2）というWindows標準搭載の機能を使います。Macには同等の機能が無いため、Ubuntuの開発元 Canonical 社が提供する Multipass という仮想マシン作成ツールを別途インストールして使います。どちらの方法でも、たどり着く先は同じです。Ubuntu 24.04 が起動し、その中で bash が入力を待っている状態になります。

図1: ホストOSの中でUbuntuが動く仕組み

flowchart TB subgraph W["Windowsのパソコン"] WIN["Windows"] -->|組み込み機能| WSL2["WSL2"] WSL2 --> UB1["Ubuntu 24.04 LTS
（仮想環境）"] end subgraph M["Mac"] MAC["macOS"] -->|追加インストール| MULTI["Multipass"] MULTI --> UB2["Ubuntu 24.04 LTS
（仮想マシン）"] end UB1 --> BASH["シェル: bash"] UB2 --> BASH BASH --> CMD["あなたが打つコマンド
（ls・cd など）"]

図のように、WindowsとMacで入口となる仕組み（WSL2かMultipassか）は違いますが、どちらも「ホストOSの中にUbuntu 24.04を用意し、その中でbashが命令を受け付ける」という最終形は同じです。ホストOS側のウィンドウとUbuntu側のウィンドウは共存できるので、普段どおりWindowsやMacを使いながら、必要なときだけUbuntuのターミナルを開く、という使い方になります。

この表は、これから2.2節・2.3節で行う作業の見取り図です。細かい違いは後で実際に手を動かしながら確認していくので、今は「WindowsとMacで手順が違う」ことだけ頭に入れておけば十分です。Windowsをお使いの方は2.2節へ、Macをお使いの方は2.3節へ進んでください。

2.2 Windows: WSL2でUbuntuを入れる

この節はWindowsをお使いの方向けの手順です。Macをお使いの方は読み飛ばして2.3節に進んでください。WSL2の導入は、管理者権限でのコマンド実行 →（求められたら）再起動して同じコマンドをもう一度実行 → 初回ユーザー設定、という流れで進みます（Windows 11、または Windows 10 が必要です。Windows 10 は 22H2 を推奨し、少なくともバージョン 2004 以降が必要です）。

1 PowerShellを管理者として開く

スタートメニューのアイコンを右クリック（または Windowsキー + X）し、表示されたメニューから「ターミナル（管理者）」または「Windows PowerShell（管理者）」を選びます。ユーザーアカウント制御の確認画面が出たら「はい」を選んでください。WSLのインストールはWindowsの機能を有効にする操作を伴うため、管理者権限が必要です。

すでにWSLを使ったことがある場合

別のディストリビューションなどでWSLをすでに導入済みの場合は、まず最新化してからバージョンを確認しましょう。

PowerShell（管理者） 
# WSL本体を更新する
wsl --update
# 導入済みディストリビューションとバージョンを一覧表示する
wsl --list --verbose

VERSION の列が 2 になっていれば、WSL2として動いています（1 の場合は互換性の低い旧方式のため、本ガイドでは想定しません。1 の場合は wsl --set-version Ubuntu-24.04 2 で WSL2 に変換できます）。

先頭の * は、wsl とだけ打ったときに起動する既定のディストリビューションの印です。Ubuntu-24.04 に * が無い場合は、wsl -d Ubuntu-24.04 で起動するか、wsl --set-default Ubuntu-24.04 で既定に変更します。

出力結果（例） 
  NAME            STATE           VERSION
* Ubuntu-24.04    Running         2

2 Ubuntu 24.04をインストールする

管理者権限のPowerShellで、次のコマンドを実行します。-d オプションでディストリビューション名を指定しないと別のバージョン（2026年時点では Ubuntu 26.04 LTS）が入るため、Ubuntu-24.04 を必ず指定してください。

PowerShell（管理者） 
# Ubuntu 24.04 を指定してインストールする
wsl --install -d Ubuntu-24.04

実行するとWSL本体とUbuntuのイメージのダウンロードが始まります。回線速度にもよりますが、数分かかることがあります。

3 パソコンを再起動する

初めてWSLを使う場合は、WSL2 に必要な Windows の機能（「仮想マシン プラットフォーム」など）が有効になり、最後に再起動が必要だというメッセージが表示されます。この時点ではまだ Ubuntu 本体はインストールされていません。作業中のファイルを保存して再起動し、再起動後にもう一度、管理者の PowerShell で手順2と同じ wsl --install -d Ubuntu-24.04 を実行してください。今度は Ubuntu のダウンロードとインストールが行われます。再起動を求められなかった場合は、そのまま手順4に進みます。

4 初回起動でユーザー名とパスワードを設定する

Ubuntu のインストールが終わると、同じ PowerShell のウィンドウでそのまま Ubuntu が起動し、初回セットアップとしてUbuntu内で使う専用のユーザーアカウントの作成を求められます。Windowsのユーザー名と一致させる必要はありません。ユーザー名は英小文字で始まる、英小文字と数字で、たとえば student のように短い名前にしておくと、以降の入力が楽になります。ユーザー名の入力欄には、Windows のユーザー名があらかじめ入っていることがあります。そのまま使うなら Enter を、別の名前にするなら Backspace キーで消してから入力します（消さずに入力すると、後ろにつながった名前になります）。

出力結果（例） 
Provisioning the new WSL instance Ubuntu-24.04
This might take a while...
Create a default Unix user account: student
New password:
Retype new password:
passwd: password updated successfully

パスワードを入力する2行では、キーを押しても画面には何も表示されません。これは壊れているのではなく正常な動作です（2.4節でもう一度説明します）。そのまま入力してEnterを押してください。このパスワードは、後で管理者の権限で操作するとき（sudo）に使うので、忘れないようにメモしておきましょう。設定が終わると、student@DESKTOP-XXXXXXX:~$ のようなプロンプトが表示され、いつでもコマンドを打てる状態になります（PowerShell から起動したため、~ の部分が /mnt/c/… と表示されることがあります。その場合は exit で抜け、スタートメニューから Ubuntu を開き直すと ~ から始まります）。

2回目以降は、スタートメニューのUbuntu 24.04の項目（Ubuntu-24.04などの名前）から起動できます。Windows Terminalを使っている場合は、タブの追加メニューにUbuntu 24.04の項目（Ubuntu-24.04などの名前）が候補として表示されるので、そこから開くこともできます。

2.3 Mac: MultipassでUbuntuを入れる

この節はMacをお使いの方向けの手順です。Windowsをお使いの方は2.2節をご覧ください。Multipassの導入は、アプリのインストール → 仮想マシンの起動 → シェルへのログイン、という3段階で進みます（macOS 13 Ventura 以降が必要です）。

1 Multipassをインストールする

まず Mac の「ターミナル」アプリを開きます。Spotlight（⌘+スペース）で「ターミナル」と入力して Enter を押すか、Finder の「アプリケーション」→「ユーティリティ」→「ターミナル」で開けます。見出しが「ターミナル（Mac）」のブロックは、Ubuntu の中ではなく、この Mac のターミナルで実行するコマンドです。

すでにパッケージ管理ツール Homebrew を使っている場合は、ターミナル（Mac標準の「ターミナル」アプリ）で次のコマンドを実行します。

ターミナル（Mac） 
# Homebrew で Multipass をインストールする
brew install --cask multipass

途中で Password: と表示されたら、Mac にログインするときのパスワードを入力して Enter を押します。入力中は何も表示されませんが、それで正常です。

Homebrewを使っていない場合は、公式サイト https://canonical.com/multipass からmacOS用インストーラ（.pkg ファイル）をダウンロードし、ダブルクリックして画面の指示に従ってください。インストール作業自体はターミナルを使いません（次の手順2からはターミナルを使います）。

2 Ubuntu仮想マシンを起動する

インストールが終わったら、ターミナルで次のコマンドを実行し、Ubuntu 24.04の仮想マシンを起動します。--cpus・--memory・--disk を省略すると既定値（1CPU・1GBメモリ・5GBディスク）になり、この後の章の作業には手狭なため、必ず指定してください。

ターミナル（Mac） 
# Ubuntu 24.04 を ubuntu という名前で、2CPU・2GBメモリ・10GBディスクで起動する
multipass launch 24.04 --name ubuntu --cpus 2 --memory 2G --disk 10G
出力結果（例） 
Launched: ubuntu

初回はUbuntuのイメージをダウンロードするため、1〜2分ほどかかります。Launched: ubuntu と表示されれば起動完了です。

3 仮想マシンの中に入る

次のコマンドで、起動した ubuntu という名前の仮想マシンの中にログインします。

ターミナル（Mac） 
# ubuntu という名前の仮想マシンのシェルに入る
multipass shell ubuntu

実行すると、Macのターミナルのプロンプトが ubuntu@ubuntu:~$ に変わります。これでUbuntuの中に入り、コマンドを打てる状態になりました。

Multipassのユーザー名は固定です

Multipassで作った仮想マシンのユーザー名は、常に ubuntu（ホームディレクトリは /home/ubuntu）です。WSLのように自分で名前を決めることはできません。また、既定の設定では sudo を実行してもパスワードを聞かれません。この点はWindows側（WSL）と異なるので、本ガイドの出力例（student@ubuntu）を読むときは、自分の環境ではubuntu@ubuntuに読み替えてください。

2回目以降にUbuntuへ入りたいときも、ターミナルを開いて multipass shell ubuntu を実行するだけです（起動・停止の詳しい操作は2.5節で扱います）。

やってみよう 2-1: 自分のパソコンにUbuntu環境を作る

2.2節または2.3節の手順に沿って、実際に自分のパソコンにUbuntu 24.04を導入してみましょう。

手順

  1. 1 自分のパソコンがWindowsかMacかを確認する（第1章のやってみようで確認済みならそれを使う）。
  2. 2 Windowsの場合は2.2節、Macの場合は2.3節の手順を上から順に実行する。
  3. 3 ターミナルに ユーザー名@ホスト名:~$ の形のプロンプトが表示されることを確認する。
  4. 4 うまくいかない場合はあわてずに、2.5節の「トラブル対処」を確認する。

2.4 起動確認と初回アップデート

WSLのUbuntuウィンドウ、または multipass shell ubuntu 実行後の画面、どちらの方法でも、ここから先は同じUbuntuの中での作業です。ここで打つコマンドの意味を、今は深く理解する必要はありません。「このコマンドを打つと、こういう情報が見える」という感覚だけ掴んでおきましょう。詳しい読み方は第3章以降で学びます。

1つ目は、OSの詳しい情報が書かれたファイルの中身を表示するコマンドです。

ターミナル 
# OSの詳しい情報が書かれたファイルの中身を表示する
cat /etc/os-release
出力結果（例） 
PRETTY_NAME="Ubuntu 24.04.x LTS"
NAME="Ubuntu"
VERSION_ID="24.04"
VERSION="24.04.x LTS (Noble Numbat)"
VERSION_CODENAME=noble
ID=ubuntu
ID_LIKE=debian
（以下略）

PRETTY_NAME の x の部分には、更新のたびに増える具体的な数字（1、2…）が入ります。VERSION_CODENAME=noble は、Ubuntu 24.04のコードネームが「noble」であることを示しています。ID_LIKE=debian は、第1章1.2節の図2で見たとおり、Ubuntu が Debian 系のディストリビューションであることを示しています。

2つ目は、カーネルやCPUアーキテクチャなど、システム全体の情報を表示するコマンドです。

ターミナル 
# カーネルのバージョンやCPUアーキテクチャなどを表示する
uname -a

WSL（Windows）での出力例です（日時などは省略しています）。末尾近くに microsoft-standard-WSL2 という文字列が入るのが目印です。

出力結果（例） 
Linux DESKTOP-XXXXXXX 6.6.x-microsoft-standard-WSL2 #1 SMP PREEMPT_DYNAMIC x86_64 x86_64 x86_64 GNU/Linux

Multipass（Apple SiliconのMac）での出力例です（日時などは省略しています）。CPUアーキテクチャの部分が aarch64 になります（Intel Macや大半のWindows PCでは x86_64）。

出力結果（例） 
Linux ubuntu 6.8.0-xxx-generic #xxx-Ubuntu SMP PREEMPT_DYNAMIC aarch64 aarch64 aarch64 GNU/Linux

3つ目・4つ目は、自分のユーザー名とこのUbuntuのホスト名（コンピューター名）を確認するコマンドです（第3章で詳しく学びます）。

ターミナル 
# 自分のユーザー名を表示する
whoami
# このUbuntuのホスト名を表示する
hostname

WSL でユーザー名を student にした場合の出力例です。

出力結果（例） 
student@DESKTOP-XXXXXXX:~$ whoami
student
student@DESKTOP-XXXXXXX:~$ hostname
DESKTOP-XXXXXXX

WSLでは、hostname の結果がWindows側のコンピューター名（例: DESKTOP-XXXXXXX）になります。Multipassでは、ユーザー名・ホスト名とも ubuntu が表示されます。本ガイドの出力例は student@ubuntu という架空の名前で統一していますが、実際の画面には自分の環境の名前が表示されるので、その都度読み替えてください。

最後に、Ubuntu内のソフトウェア（パッケージ）を最新の状態にしておきます。次のコマンドの意味は今は分からなくて大丈夫です。パッケージ管理の仕組みと apt コマンドの使い方は第11章、先頭の sudo（管理者の権限で実行する）は第9章、2つのコマンドを続けて実行する && は第8章で詳しく学びます。ここでは「セットアップの最後にお決まりで打つ呪文」として実行しておきましょう。

ターミナル 
# パッケージ一覧を最新化してから、更新可能なソフトをすべて更新する（第11章で詳しく学ぶ）
sudo apt update && sudo apt upgrade -y

パスワードを入力しても画面に何も表示されないのは正常です

sudo の実行時にパスワードを求められることがあります（WSLでは求められます。一度入力すると、同じウィンドウではしばらく（約15分）聞かれません。Multipassでは既定では求められません）。このとき、キーを押しても文字はおろか * すら表示されません。他人に画面をのぞかれても文字数さえ分からないようにする、Linuxのセキュリティ上の仕様です。壊れたのではないので、そのまま正しく入力してEnterキーを押してください。

実行後は、次のような更新状況のメッセージが流れます（先頭部分の抜粋です。パッケージの数や内容、取得先のURLは環境により異なります）。WSLの場合、先頭に [sudo] password for student: の行が表示されます（Multipassでは表示されません）。

出力結果（例） 
[sudo] password for student:
Hit:1 http://archive.ubuntu.com/ubuntu noble InRelease
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
N packages can be upgraded. Run 'apt list --upgradable' to see them.

この後、apt upgrade による更新の表示が続きます。最後にプロンプト（ユーザー名@ホスト名:~$）が戻れば完了です。

やってみよう 2-2: 自分の環境の情報を確認して記録する

2.4節のコマンドを自分のUbuntuで実行し、結果をメモに残しておきましょう。今後の章でエラーが起きたとき、自分の環境の情報がすぐ分かると助かります。

手順

  1. 1 cat /etc/os-release、uname -a、whoami、hostname を順番に実行する。
  2. 2 表示されたVERSION_CODENAME・ユーザー名・ホスト名を、メモ帳などに書き留める。
  3. 3 自分の環境（WSLかMultipassか）によって、本ガイドの表記例 student@ubuntu とユーザー名・ホスト名がどう違うか比べてみる。
  4. 4 （未実行なら）sudo apt update && sudo apt upgrade -y を実行する。WSL ではパスワードを求められるので、入力しても何も表示されないことを確かめる（Multipassではパスワードを聞かれずにそのまま進みます）。

2.5 ターミナルの終了・再開とトラブル対処

最後に、Ubuntuの終了方法と、次にパソコンを開いたときの再開方法を確認しておきましょう。

終了する

Ubuntuのシェルから抜けてホストOS側に戻るには、exit と入力します。ウィンドウを直接閉じても終了はできますが、exit のほうが行儀の良い終了方法です。

ターミナル 
# Ubuntuのシェルを終了してホストOS側に戻る
exit

再開する（Windows / WSL）

スタートメニューで「Ubuntu」と検索し、Ubuntu 24.04 の項目（Ubuntu-24.04 などの名前）を選ぶと、ホームディレクトリ（~）で新しいシェルが始まります（作ったファイルはそのまま残っています）。PowerShell や Windows Terminal から入る場合は、次のコマンドを使います（単に wsl と打つと、既定のディストリビューションが、Windows 側の今いるフォルダーで起動します）。

PowerShell（管理者） 
# Ubuntu 24.04 をホームディレクトリから起動する
wsl -d Ubuntu-24.04 --cd ~

WSLを完全に停止させたい場合（動作が重いと感じたときなど）は、次のコマンドを使います。

PowerShell（管理者） 
# 起動中のすべてのWSLディストリビューションを停止する
wsl --shutdown

再開する（Mac / Multipass）

Multipassの仮想マシンは、使わないときは停止しておくのが基本です。状態の確認や起動・停止には次のコマンドを使います。

ターミナル（Mac） 
# 仮想マシンの一覧と状態（Running / Stopped）を確認する
multipass list
# 停止していたら起動する
multipass start ubuntu
# 中に入る
multipass shell ubuntu
ターミナル（Mac） 
# 作業が終わったら停止する
multipass stop ubuntu

トラブル対処

導入時によくあるつまずきと対処法をまとめました。

症状 主な原因 対処
WSLの起動時に「仮想化が有効になっていないため、WSL2を開始できません」などのエラー（旧版では 0x80370102）が出る BIOS/UEFIで仮想化機能（Intel VT-xやAMD-V）が無効になっている タスクマネージャーの［パフォーマンス］→［CPU］で「仮想化: 無効」なら、パソコンを再起動してBIOS/UEFI設定画面に入り、仮想化機能を有効にする
再起動したのに Ubuntu が起動しない・スタートメニューに無い 再起動が必要だった場合、Ubuntu 本体はまだインストールされていない 管理者の PowerShell で wsl --install -d Ubuntu-24.04 をもう一度実行する
インストールやパッケージ更新が途中で失敗する ディスクの空き容量が不足している 不要なファイルを削除して空き容量を確保してからやり直す
Multipassの起動がなかなか終わらない 初回はUbuntuイメージのダウンロードが走る／ネットワークが不安定 しばらく待つ。別のターミナルで multipass list を実行して状態を確認する
パスワードを入力しても画面に何も表示されない 正常動作（Linuxのセキュリティ上の仕様） 気にせずそのまま入力してEnterキーを押す
sudoのパスワードを忘れた（WSL） — PowerShell で wsl -d Ubuntu-24.04 -u root を実行し、passwd ユーザー名 で再設定する

BIOS/UEFIの設定画面はメーカーによって異なります

操作方法や項目名はパソコンのメーカー・機種によってさまざまです。分からない場合は「（パソコンのメーカー名） 仮想化 有効化」で検索すると、多くの場合、手順が見つかります。不安な場合は無理に自分で進めず、詳しい人に確認してから作業してください。

この章のまとめ

  • ホストOS（Windows/Mac）の中で、WSL2またはMultipassを通してUbuntu 24.04が動き、その中でbashがコマンドを受け付ける。
  • Windows: 管理者のPowerShellで wsl --install -d Ubuntu-24.04 →（再起動を求められたら、再起動後に同じコマンドをもう一度実行）→ 初回セットアップでユーザー名・パスワードを設定する。
  • Mac: Multipassをインストール後、multipass launch 24.04 --name ubuntu --cpus 2 --memory 2G --disk 10G → multipass shell ubuntu。ユーザー名はubuntu固定、sudoにパスワード不要。
  • cat /etc/os-release・uname -a・whoami・hostname で自分の環境を確認できる。パスワード入力中に何も表示されないのは正常。
  • 終了は exit。完全停止はWSLが wsl --shutdown、Multipassが multipass stop ubuntu。

確認問題

  1. Q1. WindowsでUbuntu 24.04を導入する際、どのような権限で開いたPowerShellで、何というコマンドを実行しますか。

    回答を表示

    管理者として実行したPowerShell（またはWindows Terminal）で、wsl --install -d Ubuntu-24.04 を実行します。

  2. Q2. Macで multipass launch を実行するとき、既定の設定（1CPU・1GBメモリ・5GBディスク）をそのまま使わず、オプションを指定したほうがよいのはなぜですか。

    回答を表示

    既定のスペックは本ガイドの実習を進めるには手狭なためです。--cpus・--memory・--disk オプションで、たとえば multipass launch 24.04 --name ubuntu --cpus 2 --memory 2G --disk 10G のように指定します。

  3. Q3. uname -a の出力を見て、自分の環境がWSLかMultipass（Apple Silicon Mac）かを見分けるには、それぞれ何という文字列に注目すればよいですか。

    回答を表示

    WSLでは microsoft-standard-WSL2 という文字列が含まれます。Apple SiliconのMac上のMultipassでは、CPUアーキテクチャを示す aarch64 が表示されます。

  4. Q4. sudo apt update の実行中にパスワードを求められ、入力してもキーを押した文字が画面に一切表示されません。これは異常事態ですか。

    回答を表示

    異常ではなく正常な動作です。Linuxではセキュリティ上、パスワード入力中は文字も * のような伏せ字も表示されない仕様になっています。そのまま正しく入力してEnterキーを押せば問題ありません。
