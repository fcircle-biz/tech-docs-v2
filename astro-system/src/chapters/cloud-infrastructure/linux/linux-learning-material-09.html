ホーム Linux 第9章
第9章 所要時間: 約80分

ユーザーとパーミッション

ここまでの章では、ファイルやコマンドを自由に読み書き・実行できる前提で進めてきました。しかし実際のLinuxは、「誰が」「何を」できるかをユーザーとパーミッション（権限）で厳密に管理しています。この章では、ユーザー・グループの確認方法、rootとsudoの仕組み、ls -lで目にする-rwxr-xr--の読み方、そしてchmod・chownによる変更方法を学びます。

この章で学ぶこと

  • whoami・id・groups・/etc/passwdでユーザーとグループの情報を確認できる
  • rootと一般ユーザーの違い、sudoの仕組みを説明できる
  • ls -lのパーミッション表記-rwxr-xr--を所有者・グループ・その他に分解して読める
  • rwxと数値表記（755・644・600）を相互に変換できる
  • chmodで権限を、chown／chgrpで所有者・グループを変更できる
  • chmod 777やsudoの乱用がなぜ危険かを説明できる

9.1 ユーザーとグループ

Linuxは、複数の人が同時に使うことを前提に設計されたマルチユーザーOSです。あなたがログインしている間も、システム内部では裏方の処理を行う専用ユーザー（daemon など）の権限で、いくつものプログラムが動いています。ファイルやコマンドには必ず「誰が所有しているか」「誰が実行できるか」という情報が紐づいており、これから学ぶパーミッションはすべてユーザーとグループという単位の上に成り立っています。まずは、自分が今どのユーザーとして操作しているのかを確認する方法から始めましょう。

ターミナル 
# この章の作業ディレクトリを作って移動する
mkdir -p ~/linux-practice/ch09
cd ~/linux-practice/ch09

まず whoami（今の自分のユーザー名）、id（ユーザーID・グループID・所属グループ）、groups（所属グループ名の一覧）の3つを実行してみます。

ターミナル 
# 自分のユーザー名を表示する
whoami
# ユーザーID・グループID・所属グループを表示する
id
# 所属グループ名だけを表示する
groups
出力結果（例） 
student@ubuntu:~/linux-practice/ch09$ whoami
student
student@ubuntu:~/linux-practice/ch09$ id
uid=1000(student) gid=1000(student) groups=1000(student),4(adm),27(sudo),...
student@ubuntu:~/linux-practice/ch09$ groups
student adm sudo ...

id の出力は「自分のUID（ユーザーID）とGID（主グループID）」に続けて、所属しているすべてのグループが グループID(グループ名) の形式で並びます。1人のユーザーは1つの主グループのほかに、複数の副グループに同時に所属できます。sudo グループへの所属は9.2節で扱う管理者権限に関わる重要な項目です。

所属グループは環境によって異なります

上の出力例の ... の部分や、具体的なグループの種類・数はディストリビューションやインストール状況によって変わります。大事なのは個々のグループ名ではなく、「1人のユーザーが複数のグループに同時に所属できる」という仕組みです。自分の環境で実行したときは、表示された内容をそのまま読めば大丈夫です。

こうしたユーザーの情報は、/etc/passwd という設定ファイルにまとめて登録されています。名前に「password」とありますが、実際のパスワードは入っていません（理由はすぐ後で説明します）。ためしに中身を覗いてみましょう。

ターミナル 
# /etc/passwd の先頭3行を表示する
head -n 3 /etc/passwd
# 自分の行だけを取り出す（student は自分のユーザー名に置き換える。Multipass なら ubuntu）
grep student /etc/passwd
出力結果（例） 
student@ubuntu:~/linux-practice/ch09$ head -n 3 /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
student@ubuntu:~/linux-practice/ch09$ grep student /etc/passwd
student:x:1000:1000:,,,:/home/student:/bin/bash

1行が1人のユーザーに対応し、:（コロン）区切りで7つのフィールドが並んでいます。

# フィールド 内容 studentの例
1 ユーザー名 ログインに使う名前 student
2 パスワード欄 常に x。実体は下記のとおり別ファイル x
3 UID ユーザーID。0はroot、一般ユーザーは1000以降 1000
4 GID 主グループのID 1000
5 GECOS フルネームなどのコメント欄。空のことも多い ,,,
6 ホームディレクトリ ログイン直後にいる場所 /home/student
7 ログインシェル ログイン時に起動するシェル /bin/bash

パスワード欄が x なのはなぜ？

/etc/passwd は、どのユーザーでも中身を読めるファイルです。もし暗号化されたパスワードがここに書かれていたら、全ユーザーに解析のヒントを与えてしまいます。そこで実際の（ハッシュ化された）パスワード情報は /etc/shadow という別ファイルに分けて保存されており、こちらはroot以外は読み取れません。「誰がいるか」の情報と「パスワードの実体」を分離するのが、Linuxの伝統的な安全設計です。

9.2 rootと一般ユーザー、sudoの仕組み

先ほどの /etc/passwd の1行目にいた root（UID 0）は特別なユーザーで、あらゆるファイルにあらゆる操作ができる、権限チェックを一切受けない管理者です。一方、student のような一般ユーザーは、この章で学ぶパーミッションの制限を受けます。システムの設定変更やソフトウェアのインストールにはroot権限が必要ですが、普段からrootとしてログインして作業するのは危険です。誤って重要なファイルを消してしまっても、それを止める仕組みが働かないからです。

そこで使うのが sudo（superuser do）です。sudo グループに所属しているユーザーは、rootのパスワードではなく自分自身のパスワードを入力することで、そのコマンド1つだけを一時的にroot権限で実行できます。しかも一度認証すると、その後しばらく（既定では約15分間）はパスワードの再入力なしで sudo を使い続けられます。「普段は制限された一般ユーザー、必要な瞬間だけ管理者権限を借りる」というのが、Linuxにおける安全な運用の基本です。

図1: sudo でコマンドを実行するときの流れ

flowchart TD A["一般ユーザーが実行
sudo whoami"] --> B{"sudoグループに
所属している？"} B -->|いいえ| C["拒否される

※ 実際には、sudo グループに入っていないユーザーもまずパスワードを聞かれ、入力した後に「… is not in the sudoers file.」と表示されて拒否されます。

実際に whoami を sudo 付きで実行し、一瞬だけrootになっていることを確認してみましょう。

ターミナル 
# 自分のパスワードを入力し、root権限でwhoamiを実行する
sudo whoami
出力結果（例） 
student@ubuntu:~/linux-practice/ch09$ sudo whoami
[sudo] password for student:
root

whoami 単体では student と表示されるのに、sudo を付けると root に変わります。このコマンドだけがrootとして実行され、終わればまた student の権限に戻ります。パスワード入力時は、第2章で触れたとおり画面には文字が表示されず、カーソルも動きませんが、これが正常な挙動です。

Multipass（Mac）ではパスワードを聞かれません

Multipassで作成したUbuntu環境の既定ユーザー ubuntu は、パスワードなしで sudo を使えるように設定されています。そのため sudo whoami を実行しても [sudo] password for ... の行は表示されず、すぐに root と出力されます。WSL（Windows）では、第2章で設定した自分のパスワードを入力してください。自分の環境の表示に読み替えて進めましょう。

9.3 パーミッション表記を読む

第4章で ls -l の出力に触れたとき、先頭にある -rwxr-xr-- のような10文字の並びは「後で詳しく学ぶ」として通り過ぎました。ここがその「後」です。この10文字には、「誰が」「何を」できるかという情報がすべて詰まっています。次のような出力行があったとして、1文字ずつ分解してみましょう（このファイルは説明用の例で、まだ作る必要はありません）。

出力結果（例） 
student@ubuntu:~/linux-practice/ch09$ ls -l app.sh
-rwxr-xr-- 1 student student 220 Apr  1 10:00 app.sh

図2: パーミッション文字列 -rwxr-xr-- の分解

-
r

x

-

1文字目: 種類

-=ファイル
d=ディレクトリ
l=シンボリックリンク

2〜4文字目: 所有者(u)

rwx = 読み書き実行すべて可能

5〜7文字目: グループ(g)

r-x = 読み取りと実行のみ

8〜10文字目: その他(o)

r-- = 読み取りのみ

つまり -rwxr-xr-- は、「所有者（このファイルを持つユーザー、= u）は読み書き実行すべて可能、グループ（このファイルが属するグループのメンバー、= g）は読み取りと実行のみ、その他（それ以外の全員、= o）は読み取りのみ」という意味になります。ls -l の出力では、この10文字の直後にある所有者名・グループ名の欄（先ほどの例では student student）が、まさに「誰が所有者で」「どのグループに属すか」を表しています。

r・w・xが「読む」「書く」「実行する」という意味なのは共通ですが、実はファイルとディレクトリでは意味が少し異なります。特にディレクトリの x は見落とされがちですが、非常に重要です。

権限 ファイルでの意味 ディレクトリでの意味
r（読み取り） 中身を読める（cat など） 中にあるファイル名の一覧を見られる（ls）
w（書き込み） 中身を変更・上書きできる 中でファイルの作成・削除・名前変更ができる
x（実行） プログラム・スクリプトとして実行できる そのディレクトリに入れる（cd）・中のファイルにアクセスできる

ディレクトリの x が無いと「通れない」

ディレクトリの x は「通行権限」のようなものです。r があっても x が無いディレクトリは、ls で名前の一覧は見えても、cd で中に入ったり、中のファイルをファイル名指定で開いたりすることはできません。逆に x だけあって r が無いと、ファイル名を知っていればアクセスできるが一覧表示はできない、という状態になります。

9.4 パーミッションを変更する（chmod）

パーミッションを変更するコマンドが chmod（change mode）です。指定方法には記号による指定と数値による指定の2通りがあり、どちらもよく使われます。まずは数値表記の仕組みから見ていきましょう。r・w・xにはそれぞれ 4・2・1 という重みが割り当てられていて、この3つの数字を足し算することで、1つのカテゴリ（所有者・グループ・その他）が持つ権限を1桁の数字で表せます。（各桁が0〜7に収まるこの表記は「8進数」表記と呼ばれます）

図3: rwx を数値に変換する

r

読み取り = 4

w

書き込み = 2

x

実行 = 1

数値 内訳 rwx表記
74+2+1rwx
64+2rw-
54+1r-x
44r--
0（なし）---

この数字を「所有者・グループ・その他」の順に3つ並べたものが、よく見る3桁の数値表記です。

755 = rwxr-xr-x

所有者7・グループ5・その他5。スクリプトやディレクトリの標準的な権限。

644 = rw-r--r--

所有者6・グループ4・その他4。一般的なテキストファイルの標準的な権限。

600 = rw-------

所有者6・グループ0・その他0。自分だけが読み書きできる秘密のファイル用（第12章のSSH鍵など）。

もう1つの記号による指定は、「誰の（u=所有者・g=グループ・o=その他・a=全員）」「どうする（+=付与・-=削除・==設定）」「何を（r/w/x）」を組み合わせる方式です。既存の権限の一部だけをピンポイントで変えたいときに便利です。たとえば u+x は「所有者に実行権限を追加」、go-w は「グループとその他から書き込み権限を削除」という意味です。「誰の」を省略して +x のように書くと a+x とほぼ同じ意味になり、所有者・グループ・その他の全員に実行権限が付きます（umask で禁止されている権限は付きません）。数値指定はすべての権限を一度に置き換えるのに対して、記号指定は今ある権限に対する差分を表せる点が異なります。

やってみよう 9-1: 実行権限とPermission deniedを体験する

1行だけのスクリプトを作り、実行権限の有無で挙動がどう変わるかを実際に確認します。

手順

  1. 1
    echo を1行だけ書いた hello.sh を作成する（中身の書き方は第13章で詳しく学ぶ）。
    ターミナル 
    # hello.sh を1行だけの内容で作成する
cat > hello.sh <<'EOF'
echo "Hello, Linux!"
EOF
  2. 2
    作成直後の権限を確認してから、実行権限を付与してもう一度確認する。
    ターミナル 
    # 現在の権限を確認する（rw-r--r-- または rw-rw-r--。9.5節で説明）
ls -l hello.sh
# 実行権限を追加する（u/g/o を省略すると全員に付く）
chmod +x hello.sh
# 権限が変わったことを確認する（rwxr-xr-x または rwxrwxr-x）
ls -l hello.sh
    出力結果（例） 
    student@ubuntu:~/linux-practice/ch09$ ls -l hello.sh
-rw-r--r-- 1 student student 21 Apr  1 10:00 hello.sh
student@ubuntu:~/linux-practice/ch09$ chmod +x hello.sh
student@ubuntu:~/linux-practice/ch09$ ls -l hello.sh
-rwxr-xr-x 1 student student 21 Apr  1 10:00 hello.sh
  3. 3
    ./hello.sh で実行する（先頭の ./ は「カレントディレクトリの」という意味。第4章で学んだ相対パスです）。
    ターミナル 
    # カレントディレクトリの hello.sh を実行する
./hello.sh
    出力結果（例） 
    student@ubuntu:~/linux-practice/ch09$ ./hello.sh
Hello, Linux!
  4. 4
    読み取り権限を全員から外し、cat で中身を見ようとして拒否される様子を確認する。
    ターミナル 
    # 全員（a）から読み取り権限を外す
chmod a-r hello.sh
# 中身を見ようとする
cat hello.sh
    出力結果（例） 
    student@ubuntu:~/linux-practice/ch09$ chmod a-r hello.sh
student@ubuntu:~/linux-practice/ch09$ cat hello.sh
cat: hello.sh: Permission denied
  5. 5
    数値指定で元の実行可能な状態（755）に戻し、読めることを確認する。
    ターミナル 
    # 数値指定で rwxr-xr-x に戻す
chmod 755 hello.sh
cat hello.sh

chmod 777 は「誰でも何でもできる」状態にする危険な設定です

エラーが出て困ったときに、原因を調べずとりあえず chmod 777 file や chmod -R 777 . を実行して「直った」で終わらせるのは絶対にやめましょう。777は所有者・グループ・その他の全員が読み書き実行できる状態で、他のユーザーやプロセスがファイルを書き換えたり、悪意あるスクリプトを置かれて実行されたりする入り口になります。サーバー上では特に、公開設定の事故や不正アクセスの温床になりやすい設定です。権限エラーが出たときは、まず ls -l で今の権限と所有者を確認し、必要最小限の権限だけを追加しましょう。

9.5 所有者の変更とumask

chmod が「何ができるか」を変えるのに対し、chown（change owner）と chgrp（change group）は「誰のものか」を変えるコマンドです。所有者を変える chown は他人にファイルを譲り渡す操作にあたるため sudo が必要です。chgrp は、自分のファイルを自分が所属するグループに変えるだけなら sudo なしでも実行できますが、それ以外は sudo が必要です。

ターミナル 
# student の部分は自分のユーザー名（whoami の結果。Multipass なら ubuntu）に置き換える
# 所有者とグループを同時に変更する（所有者:グループ）
sudo chown student:student hello.sh
# グループだけを変更する
sudo chgrp student hello.sh

上の例はすでに student が所有しているファイルに同じ所有者を設定し直すだけなので見た目の変化はありませんが、構文の確認として実行できます（student は自分のユーザー名に読み替えてください）。chown が実際に役立つのは、次の警告で説明する「sudo で作ったファイルの所有者を自分に戻す」ような場面です。

sudo で作ったファイルはrootの所有物になる

自分のホームディレクトリの中であっても、sudo touch note.txt や sudo nano note.txt のように sudo を付けて新規ファイルを作ると、そのファイルの所有者はrootになります。後で sudo を付けずに編集・保存しようとすると Permission denied になり、「自分のディレクトリなのに自分のファイルを編集できない」という状態に陥ります。直すには sudo chown student:student note.txt（student は自分のユーザー名に読み替える）で所有者を自分に戻します。「本当にroot権限が必要な操作か」を都度考え、不要な場面では sudo を付けないのが、この落とし穴を避ける一番の対策です。

最後に、新しくファイルやディレクトリを作ったときに最初から適用される権限がどう決まるかを見ておきましょう。これを制御しているのが umask です。umask は「新規作成時に、基本の権限から差し引く権限」を4桁の数値で表したもので、Ubuntu の一般ユーザーでは 0022 か 0002 のどちらかになっていることが多く、環境によって異なります（WSL では 0022、Multipass では 0002 になることが多いです。以下は 0022 の場合の例です）。

ターミナル 
# 現在のumaskを確認する
umask
出力結果（例） 
student@ubuntu:~/linux-practice/ch09$ umask
0022

ファイルの基本権限は 666（rw-rw-rw-、実行権限は自動では付かない）、ディレクトリの基本権限は 777 です。ここから umask の下3桁（022）を、所有者・グループ・その他それぞれについて差し引きます（正確には算数の引き算ではなく「umask に含まれる権限を取り除く」計算です。022 なら引き算と同じ結果になりますが、たとえば umask 027 では新規ファイルは 640（rw-r-----）、新規ディレクトリは 750（rwxr-x---）になります）。

新規ファイル

666 − 022 = 644（rw-r--r--）

新規ディレクトリ

777 − 022 = 755（rwxr-xr-x）

umask が 0002 と表示された場合

新規ファイルは 666−002＝664（rw-rw-r--）、新規ディレクトリは 775（rwxrwxr-x）になります。9-1 の hello.sh も作成直後は -rw-rw-r--、chmod +x の後は -rwxrwxr-x と表示されます。

実際、9-1で hello.sh を作った直後の権限が rw-r--r--（644）だったのは、この計算の結果です。umask の値は umask 027 のように一時的に変更することもできますが、通常は既定値のままで問題ありません。「なぜ新しく作ったファイルが644から始まるのか」の理由として覚えておけば十分です。

sudo は「一時的に借りる」もの。乱用しない

root権限では、通常なら止めてくれる安全装置（確認、権限チェック）がすべて働きません。特に sudo rm -rf / のようなコマンドは、システム全体を破壊しかねない最も危険な例としてよく知られています。「エラーが出たらとりあえずsudoを付ける」を習慣にせず、今から実行するコマンドが何をするか理解してから sudo を使いましょう。パッケージのインストール（第11章）やシステム設定ファイルの編集など、本当に管理者権限が必要な操作に限定するのが安全です。

この章のまとめ

  • ユーザーは whoami・id・groups で確認でき、/etc/passwd に7つのフィールドで登録される（パスワードの実体は /etc/shadow）。
  • rootは制限のない特別なユーザー。sudo グループのユーザーは、自分のパスワードで一時的にroot権限を借りられる（既定で約15分キャッシュ）。
  • ls -l の -rwxr-xr-- は「種類＋所有者／グループ／その他のr/w/x」。ディレクトリの x は「入れるか」を意味し、ファイルの実行権限とは意味が異なる。
  • 権限は記号（chmod u+x）と数値（chmod 755、r=4・w=2・x=1）の2通りで変更できる。
  • chown／chgrp（chown は sudo 必須）で所有者・グループを変更でき、umask が新規作成時の権限を決める（0022ならファイル644・ディレクトリ755）。
  • chmod 777・sudo の乱用・sudoで作ったファイルの所有権に注意する。

確認問題

  1. Q1. /etc/passwd のパスワード欄が x になっているのはなぜですか。実際のパスワード情報はどこに保存されていますか。

    回答を表示

    /etc/passwd は誰でも読めるファイルなので、暗号化されたパスワードをそのまま書くと解析のヒントを与えてしまうためです。実際の（ハッシュ化された）パスワード情報は、root以外読み取れない /etc/shadow に分けて保存されています。

  2. Q2. -rwxr-xr-- というパーミッション文字列を、所有者・グループ・その他がそれぞれ持つ権限に分けて説明してください。

    回答を表示

    所有者（u）は rwx で読み取り・書き込み・実行すべて可能、グループ（g）は r-x で読み取りと実行のみ、その他（o）は r-- で読み取りのみです。先頭の - はファイルの種類（通常ファイル）を表します。

  3. Q3. chmod 644 file.txt を実行すると、権限はどう変わりますか。数値の意味も含めて説明してください。

    回答を表示

    r=4・w=2・x=1として、所有者は6（4+2＝rw-）、グループは4（r--）、その他は4（r--）になります。つまり権限は rw-r--r-- になり、所有者だけが書き込みでき、グループとその他は読み取りのみ可能になります。

  4. Q4. chmod 777 がなぜ危険とされるのか、理由を説明してください。

    回答を表示

    所有者・グループ・その他の全員が読み取り・書き込み・実行のすべてを行える状態になるためです。自分以外の第三者やプロセスがファイルを自由に書き換えたり、悪意あるスクリプトを置いて実行されたりする可能性が生まれ、特にサーバー上では不正アクセスや情報漏えいの原因になりやすいため危険とされています。
