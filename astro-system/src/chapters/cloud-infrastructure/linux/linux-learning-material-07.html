第7章 所要時間: 約80分

検索とテキスト処理

ここまでの章で、ファイルを作ったり中身を表示したりする方法を学びました。実務では、それだけでなく「たくさんのファイルの中から目的のファイルを見つける」「ログの中から必要な行だけを取り出す」「同じ値がいくつあるか数える」といった作業が頻繁に発生します。この章では、ファイルを探す find、文字列を探す grep、そして wc・sort・uniq・cut・tr によるテキスト処理を学びます。次の第8章で学ぶ「パイプ」を使うと、これらのコマンドをつなげてさらに強力な集計ができるようになります。

この章で学ぶこと

  • ヒアドキュメントを使って、複数行のファイルを一気に作成できる
  • find でファイルを名前・種類・更新日時・サイズから検索できる
  • grep で文字列を含む行の検索・除外・件数表示ができ、簡単な正規表現を読める
  • wc でファイルの行数・単語数を数えられる
  • sort と uniq -c を組み合わせて、同じ値の出現回数を集計する仕組みを理解する
  • cut で列を取り出し、tr で文字を変換できる

7.1 練習用データをヒアドキュメントで作る

検索や集計を練習するには、ある程度まとまった量のデータが必要です。この章では、架空の売上データ（sales.csv）とWebサーバーのアクセスログ（access.log）を使います。どちらも複数行あるので、nano で1行ずつ打つのは大変です。そこで、ヒアドキュメント（here document）という「ファイルの中身をターミナルに貼り付けるだけで一気に作る」書き方を使います。

まず、この章専用の作業ディレクトリを作って移動しましょう。

ターミナル 
# 第7章の作業ディレクトリを作って移動する
mkdir -p ~/linux-practice/ch07
cd ~/linux-practice/ch07

次に、下の1ブロックをそのままコピーしてターミナルに貼り付けてください。1行目の cat > sales.csv <<'EOF' は「これから入力する内容を、EOF とだけ書かれた行が出てくるまで sales.csv というファイルに書き込む」という意味です。仕組みを厳密に理解する必要はなく、今は「複数行のファイルをまとめて作るための書き方」として使い方だけ覚えれば十分です。

ターミナル 
# sales.csv をヒアドキュメントで一気に作成する
cat > sales.csv <<'EOF'
date,store,item,qty,price
2026-04-01,Tokyo,apple,3,120
2026-04-01,Osaka,banana,5,80
2026-04-02,Tokyo,orange,2,150
2026-04-02,Nagoya,apple,4,120
2026-04-03,Osaka,apple,1,120
2026-04-03,Tokyo,banana,6,80
2026-04-04,Nagoya,orange,3,150
2026-04-04,Tokyo,apple,2,120
EOF

続けて、Webサーバーのアクセスログを模した access.log も同じ要領で作成します。1列目がアクセス元のIPアドレス、7列目がリクエストされたパス、9列目がステータスコード（200=成功、404=見つからない、500=サーバーエラー）、10列目がバイト数です（スペース区切り）。

ターミナル 
# access.log をヒアドキュメントで一気に作成する
cat > access.log <<'EOF'
192.168.1.10 - - [01/Apr/2026:10:00:01 +0900] "GET /index.html HTTP/1.1" 200 1024
192.168.1.11 - - [01/Apr/2026:10:00:05 +0900] "GET /about.html HTTP/1.1" 200 2048
192.168.1.10 - - [01/Apr/2026:10:01:12 +0900] "GET /missing.html HTTP/1.1" 404 512
192.168.1.12 - - [01/Apr/2026:10:02:30 +0900] "POST /login HTTP/1.1" 500 128
192.168.1.10 - - [01/Apr/2026:10:03:45 +0900] "GET /index.html HTTP/1.1" 200 1024
192.168.1.11 - - [01/Apr/2026:10:04:10 +0900] "GET /contact.html HTTP/1.1" 200 1536
192.168.1.11 - - [01/Apr/2026:10:05:22 +0900] "GET /old-page.html HTTP/1.1" 404 512
192.168.1.10 - - [01/Apr/2026:10:06:00 +0900] "GET /about.html HTTP/1.1" 200 2048
EOF

ls で2つのファイルができたか確認しておきましょう。

ターミナル 
# 作成したファイルを確認する
ls
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ ls
access.log  sales.csv
student@ubuntu:~/linux-practice/ch07$

この2つのファイルは第8章でも使います

次の第8章では、この access.log を使ってリダイレクトやパイプを学びます。~/linux-practice/ch07 は削除せずに残しておいてください（もし無くなっていても、第8章に同じ作成手順があります）。

7.2 find でファイルを探す

ls は「今いる場所」の中身しか見せてくれません。ディレクトリが何階層にも分かれてくると、目的のファイルがどこにあるか探すのは大変です。find は、指定した場所から下の階層すべてを再帰的に探し、名前・種類・更新日時・サイズなどの条件に合うファイルを一覧表示します。基本の書式は次のとおりです。

find 検索開始位置 条件...

まずはファイル名で探す -name と、ディレクトリだけに絞る -type d（ファイルだけなら -type f）を試してみましょう。

ターミナル 
# ファイル名の末尾が .csv のファイルを探す
find ~/linux-practice -name "*.csv"
# ディレクトリだけを探す
find ~/linux-practice -type d
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ find ~/linux-practice -name "*.csv"
/home/student/linux-practice/ch07/sales.csv
student@ubuntu:~/linux-practice/ch07$ find ~/linux-practice -type d
/home/student/linux-practice
/home/student/linux-practice/ch05
/home/student/linux-practice/ch05/myproject
/home/student/linux-practice/ch05/myproject/docs
/home/student/linux-practice/ch05/myproject/src
/home/student/linux-practice/ch05/myproject/backup
/home/student/linux-practice/ch06
/home/student/linux-practice/ch07
student@ubuntu:~/linux-practice/ch07$

（-type d の結果は、これまでの章で自分が作ったディレクトリによって変わります。上は一例です。）

なぜ "*.csv" を引用符で囲むのか

* はシェル自身が「今いる場所にあるファイル名」に展開しようとする特殊な文字です。引用符を付けずに find ~/linux-practice -name *.csv と打つと、シェルが先に *.csv をカレントディレクトリのファイル名に展開してから find に渡してしまい、意図と違う結果になることがあります。引用符で囲むと、*.csv という文字どおりの文字列が find にそのまま渡り、find 自身がディレクトリを探しながら1つずつ名前を照合してくれます。

更新日時やサイズで絞り込むこともできます。-mtime -1 は「更新日時が1日以内（直近24時間）」、-size +1M は「サイズが1MBより大きい」という意味です。+ は「より大きい」、- は「より小さい」を表し、サイズの単位は k（KB）・M（MB）・G（GB）を付けます。（サイズは単位ごとに切り上げて比べるため、-size -1M は空のファイルにしか一致しません。小さいファイルを探すときは -size -100k のように小さい単位で指定します）

ターミナル 
# 過去1日以内に更新されたファイルを探す
find ~/linux-practice -mtime -1
# 1MBより大きいファイルを練習用ディレクトリから探す
find ~/linux-practice -size +1M
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ find ~/linux-practice -mtime -1
/home/student/linux-practice
/home/student/linux-practice/ch07
/home/student/linux-practice/ch07/sales.csv
/home/student/linux-practice/ch07/access.log
...
student@ubuntu:~/linux-practice/ch07$ find ~/linux-practice -size +1M
student@ubuntu:~/linux-practice/ch07$

1つ目は、7.1節で作ったばかりの ch07 とその中の2つのファイル、そして ch07 を作ったことで更新日時が変わった linux-practice 自身が表示されます。前の章の実習を24時間以内に行っていれば、そのファイルも並びます（... は続きがある印です）。2つ目は何も表示されません。これはエラーではなく、「条件に合うファイルが見つからなかった」という正常な結果です。find はヒットが無くても黙って終了します。

最後に、権限の壁にぶつかる例も見ておきましょう。/etc の中には一般ユーザーが読めないディレクトリもあります。

ターミナル 
# /etc の中から設定ファイル（.conf）を探す
find /etc -name "*.conf"
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ find /etc -name "*.conf"
/etc/wsl.conf
find: ‘/etc/ssl/private’: Permission denied
/etc/systemd/resolved.conf
...
student@ubuntu:~/linux-practice/ch07$

Permission denied が混ざっても慌てない

一般ユーザーには読む権限が無いディレクトリに find が入ろうとすると、結果の一覧に Permission denied という行が混ざります（正確な表記は環境によって多少異なることがあります）。探したい結果自体は問題なく表示されているので無視して構いません。このようなエラーメッセージだけを画面から消す方法（2>/dev/null）は、次の第8章で学びます。

やってみよう 7-1: find でファイルを探す

自分の環境で実際に find を実行し、結果を確認しましょう。

手順

  1. 1 find ~/linux-practice -name "*.log" を実行し、access.log が見つかることを確認する。
  2. 2 find ~/linux-practice -type f を実行し、これまでの章で作ったファイルが一覧できることを確認する。
  3. 3 find /etc -name "*.conf" を実行し、Permission denied の行が混ざっていても結果自体は表示されることを確認する。

7.3 grep で行を検索する

find が「ファイルそのもの」を探すのに対し、grep は「ファイルの中身」から、指定した文字列を含む行を探して表示します。ログから特定のエラーだけを抜き出したり、設定ファイルから特定の項目だけを確認したりと、非常によく使うコマンドです。

ターミナル 
# sales.csv から Tokyo を含む行だけを表示する
grep Tokyo sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ grep Tokyo sales.csv
2026-04-01,Tokyo,apple,3,120
2026-04-02,Tokyo,orange,2,150
2026-04-03,Tokyo,banana,6,80
2026-04-04,Tokyo,apple,2,120
student@ubuntu:~/linux-practice/ch07$

9行あった sales.csv のうち、Tokyo を含む4行だけが表示されました。よく使うオプションを組み合わせてみましょう。-i は大文字小文字を区別しない、-c は該当した行数だけを表示します。

ターミナル 
# 大文字小文字を区別せずに検索する
grep -i tokyo sales.csv
# 該当する行数だけを表示する
grep -c Tokyo sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ grep -i tokyo sales.csv
2026-04-01,Tokyo,apple,3,120
2026-04-02,Tokyo,orange,2,150
2026-04-03,Tokyo,banana,6,80
2026-04-04,Tokyo,apple,2,120
student@ubuntu:~/linux-practice/ch07$ grep -c Tokyo sales.csv
4
student@ubuntu:~/linux-practice/ch07$

検索する文字列を tokyo（小文字）にしても、-i のおかげで Tokyo を含む同じ4行がヒットしています。次は、行番号を表示する -n と、条件に一致しない行を表示する -v（反転検索）です。

ターミナル 
# 行番号を付けて apple を含む行を表示する
grep -n apple sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ grep -n apple sales.csv
2:2026-04-01,Tokyo,apple,3,120
5:2026-04-02,Nagoya,apple,4,120
6:2026-04-03,Osaka,apple,1,120
9:2026-04-04,Tokyo,apple,2,120
student@ubuntu:~/linux-practice/ch07$
ターミナル 
# Tokyo を含まない行だけを表示する（反転検索）
grep -v Tokyo sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ grep -v Tokyo sales.csv
date,store,item,qty,price
2026-04-01,Osaka,banana,5,80
2026-04-02,Nagoya,apple,4,120
2026-04-03,Osaka,apple,1,120
2026-04-04,Nagoya,orange,3,150
student@ubuntu:~/linux-practice/ch07$

-v の結果にはヘッダー行も含まれる点に注目してください。ヘッダー行にも Tokyo という文字列は含まれていないので、「一致しない行」として表示されます。grep はCSVの構造（どこがヘッダーか）を理解しているわけではなく、あくまで1行ずつの文字列として照合していることが分かります。

ここまではファイルを1つだけ指定してきましたが、-r を付けるとファイルの代わりにディレクトリを指定でき、その下の全ファイルをまとめて検索できます。

ターミナル 
# ~/linux-practice の下の全ファイルから Nagoya を含む行を探す
grep -r Nagoya ~/linux-practice
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ grep -r Nagoya ~/linux-practice
/home/student/linux-practice/ch07/sales.csv:2026-04-02,Nagoya,apple,4,120
/home/student/linux-practice/ch07/sales.csv:2026-04-04,Nagoya,orange,3,150
student@ubuntu:~/linux-practice/ch07$

結果は ファイル名:該当行 の形で表示され、~/linux-practice の下にある全ファイルの中から Nagoya を含む行を見つけ出してくれます。

grep は簡単な正規表現（パターンで文字列を表す書き方）も使えます。まずは3つの基本記号だけ覚えましょう。^ は行の先頭、$ は行の末尾、. は任意の1文字を表します。

ターミナル 
# 行の先頭が 2026-04-02 の行だけを表示する（^ = 行頭）
grep '^2026-04-02' sales.csv
# 行の末尾が 120 の行だけを表示する（$ = 行末）
grep '120$' sales.csv
# b と nana の間に任意の1文字がある行を表示する（. = 任意の1文字）
grep 'b.nana' sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ grep '^2026-04-02' sales.csv
2026-04-02,Tokyo,orange,2,150
2026-04-02,Nagoya,apple,4,120
student@ubuntu:~/linux-practice/ch07$ grep '120$' sales.csv
2026-04-01,Tokyo,apple,3,120
2026-04-02,Nagoya,apple,4,120
2026-04-03,Osaka,apple,1,120
2026-04-04,Tokyo,apple,2,120
student@ubuntu:~/linux-practice/ch07$ grep 'b.nana' sales.csv
2026-04-01,Osaka,banana,5,80
2026-04-03,Tokyo,banana,6,80
student@ubuntu:~/linux-practice/ch07$

2つ目の 120$ でヒットした4行は、実はすべて apple の行と一致します（このデータでは apple の価格が常に120円のため）。正規表現とデータの規則性を組み合わせると、こういう探し方もできるという一例です。

最後に access.log でも試してみます。スペースを含めて ' 404 ' のように検索すると、ステータスコードの列だけを狙い撃ちできます（前後のスペースが無いと、日時やパスの中の数字にも誤ってヒットする可能性があるためです）。

ターミナル 
# ステータスコードが 404 の行を探す
grep ' 404 ' access.log
# 404 の行が何件あるか数える
grep -c ' 404 ' access.log
# 拡張正規表現（-E）で 400番台と500番台をまとめて探す
grep -E ' (4|5)[0-9]{2} ' access.log
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ grep ' 404 ' access.log
192.168.1.10 - - [01/Apr/2026:10:01:12 +0900] "GET /missing.html HTTP/1.1" 404 512
192.168.1.11 - - [01/Apr/2026:10:05:22 +0900] "GET /old-page.html HTTP/1.1" 404 512
student@ubuntu:~/linux-practice/ch07$ grep -c ' 404 ' access.log
2
student@ubuntu:~/linux-practice/ch07$ grep -E ' (4|5)[0-9]{2} ' access.log
192.168.1.10 - - [01/Apr/2026:10:01:12 +0900] "GET /missing.html HTTP/1.1" 404 512
192.168.1.12 - - [01/Apr/2026:10:02:30 +0900] "POST /login HTTP/1.1" 500 128
192.168.1.11 - - [01/Apr/2026:10:05:22 +0900] "GET /old-page.html HTTP/1.1" 404 512
student@ubuntu:~/linux-practice/ch07$

-E を付けた拡張正規表現では、(4|5)（4か5のどちらか）や [0-9]{2}（0〜9のどれかを2回）のような、より柔軟なパターンが書けます。ここでは「こういうこともできる」と紹介する程度にとどめ、実際に手を動かして慣れる機会は第14章の総合演習で用意しています。

7.4 cut と tr で列を取り出す・変換する

grep が行を選ぶコマンドだとすれば、cut は列を選ぶコマンドです。区切り文字（-d）とフィールド番号（-f）を指定して、CSVやログの特定の列だけを取り出せます。名前のとおり「はさみで切り取る」イメージです。

図1: grep（行を選ぶ）と cut（列を選ぶ）の違い

flowchart TD IN["sales.csvの一部
2026-04-01,Tokyo,apple,3,120
2026-04-01,Osaka,banana,5,80
2026-04-02,Tokyo,orange,2,150"] IN -->|"grep Tokyo sales.csv
（横方向 = 行を選ぶ）"| G["Tokyoを含む行だけが残る
2026-04-01,Tokyo,apple,3,120
2026-04-02,Tokyo,orange,2,150"] IN -->|"cut -d, -f2 sales.csv
（縦方向 = 列を選ぶ）"| C["2番目の列（store）だけが残る
Tokyo
Osaka
Tokyo"]
ターミナル 
# 区切り文字はコンマ、2番目の列（store）だけを取り出す
cut -d, -f2 sales.csv
# 3番目の列（item）だけを取り出す（7.5節の集計で使う）
cut -d, -f3 sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ cut -d, -f2 sales.csv

Tokyo
Osaka
Tokyo
Nagoya
Osaka
Tokyo
Nagoya

student@ubuntu:~/linux-practice/ch07$ cut -d, -f3 sales.csv

banana

apple
banana
orange

student@ubuntu:~/linux-practice/ch07$

ターミナル 
# IPアドレス（1列目）だけを取り出す
cut -d' ' -f1 access.log
# ステータスコード（9列目）だけを取り出す
cut -d' ' -f9 access.log
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ cut -d' ' -f1 access.log

192.168.1.12

192.168.1.10
student@ubuntu:~/linux-practice/ch07$ cut -d' ' -f9 access.log

200
404

200

student@ubuntu:~/linux-practice/ch07$

こうして取り出した列を「同じ値が何回出てきたか」集計する方法は、次の7.5節で学びます。

次は tr です。tr 変換前 変換後 の形で、文字を1つずつ置き換えます。a-z のように範囲指定もできます。

ターミナル 
# 小文字のアルファベットをすべて大文字に変換する
tr a-z A-Z < sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ tr a-z A-Z < sales.csv
DATE,STORE,ITEM,QTY,PRICE
2026-04-01,TOKYO,APPLE,3,120
2026-04-01,OSAKA,BANANA,5,80
2026-04-02,TOKYO,ORANGE,2,150
2026-04-02,NAGOYA,APPLE,4,120
2026-04-03,OSAKA,APPLE,1,120
2026-04-03,TOKYO,BANANA,6,80
2026-04-04,NAGOYA,ORANGE,3,150
2026-04-04,TOKYO,APPLE,2,120
student@ubuntu:~/linux-practice/ch07$

なぜ tr < sales.csv という形になるのか

tr は、これまで見てきた grep Tokyo sales.csv や cut -d, -f2 sales.csv と違い、ファイル名を引数として受け取れません。tr は標準入力（キーボードなどからの入力）しか読まないため、< という記号を使って「sales.csv の中身を標準入力として送り込む」必要があります。この <（リダイレクト）の仕組みは、次の第8章で詳しく学びます。今は「tr を使うときはお決まりの形」として覚えておけば十分です。

区切り文字を変換する使い方も便利です。たとえばコンマをタブに置き換えると、表計算ソフトなどが扱いやすいTSV形式に近づきます。

ターミナル 
# コンマをタブに置き換える
tr ',' '\t' < sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ tr ',' '\t' < sales.csv
date	store	item	qty	price
2026-04-01	Tokyo	apple	3	120
2026-04-01	Osaka	banana	5	80
...
student@ubuntu:~/linux-practice/ch07$

元のファイルを上書きしないよう注意

ここで作った sales.csv と access.log は第8章でも使います。tr ... < sales.csv > sales.csv のように変換結果を元の同じファイル名へ書き戻すと、tr が読み込む前にシェルが sales.csv を空にしてしまうため、中身がすべて消えてしまいます（上書きの仕組みと危険性は次の第8章で詳しく学びます）。この章では、変換結果は画面に表示するだけにしておきましょう。

7.5 wc・sort・uniq で数える・並べ替える・集計する

まずは基本の wc（word count）です。-l は行数、-w は単語数、-c はバイト数（改行も1バイトとして数える）を表示します。

ターミナル 
# 2つのファイルの行数を確認する
wc -l sales.csv
wc -l access.log
# sales.csv の「単語」の数も見てみる
wc -w sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ wc -l sales.csv
9 sales.csv
student@ubuntu:~/linux-practice/ch07$ wc -l access.log
8 access.log
student@ubuntu:~/linux-practice/ch07$ wc -w sales.csv
9 sales.csv
student@ubuntu:~/linux-practice/ch07$

-w は空白（スペースやタブ）で区切られたかたまりを1単語として数えます。sales.csv は区切り文字がコンマでスペースを含まないため、1行がそのまま1単語として数えられ、結果的に行数と同じ9になっています。

次は sort です。何もオプションを付けないと、行全体を文字コード順（先頭の文字から1文字ずつ比較）に並べ替えます。

ターミナル 
# sales.csv を既定の並べ替え（行全体を文字コード順）で表示する
sort sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ sort sales.csv
2026-04-01,Osaka,banana,5,80
2026-04-01,Tokyo,apple,3,120
2026-04-02,Nagoya,apple,4,120
2026-04-02,Tokyo,orange,2,150
2026-04-03,Osaka,apple,1,120
2026-04-03,Tokyo,banana,6,80
2026-04-04,Nagoya,orange,3,150
2026-04-04,Tokyo,apple,2,120
date,store,item,qty,price
student@ubuntu:~/linux-practice/ch07$

ヘッダー行（date,store,...）が最後に来ているのは、先頭の文字 d が数字の 2 より文字コード上で後ろにあるためです。このように、数値を「数値として」並べ替えたい場合は -n、逆順（降順）にしたい場合は -r を付けます（-n を付けないと、数値の 10 が 9 より先頭に来てしまうことがあります。1 の方が 9 より文字コードで小さいためです）。

CSVのように列が分かれているデータでは、-t で区切り文字、-k でどの列を基準に並べ替えるかを指定できます。-k4,4 は「4列目から4列目まで」、つまり4列目だけを基準にするという意味です（終わりの列番号を省略すると「4列目から行末まで」を基準にしてしまうため、1列だけを対象にしたいときは -k4,4 のように終わりも指定するのが安全です）。

ターミナル 
# qty（4列目）を数値として昇順に並べ替える
sort -t, -k4,4 -n sales.csv
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ sort -t, -k4,4 -n sales.csv
date,store,item,qty,price
2026-04-03,Osaka,apple,1,120
2026-04-02,Tokyo,orange,2,150
2026-04-04,Tokyo,apple,2,120
2026-04-01,Tokyo,apple,3,120
2026-04-04,Nagoya,orange,3,150
2026-04-02,Nagoya,apple,4,120
2026-04-01,Osaka,banana,5,80
2026-04-03,Tokyo,banana,6,80
student@ubuntu:~/linux-practice/ch07$

今度はヘッダー行が先頭に来ました。理由は単純で、4列目の値が qty という文字列であり、数値として解釈できないため -n はこれを 0 扱いにするからです。0はどの数量よりも小さいので先頭に来ます。同じオプションに -r を追加した sort -t, -k4,4 -rn sales.csv を実行すると、この並びがそのまま逆になり、qty=6の行が先頭、ヘッダー行が最後に来ます。

最後に uniq -c です。uniq は重複した行をまとめ、-c を付けると出現回数も表示します。ただし、重要な制約があります。uniq は隣り合っている同じ行しかまとめません。データがバラバラの順序で並んでいると、同じ値が離れた場所に出てきてしまい、正しく数えられないのです。だからこそ、uniq -c の前には必ず sort を行い、同じ値を隣どうしに集めておく必要があります。

uniq -c は「隣り合う」重複しかまとめない

並べ替えずに uniq -c だけを実行すると、離れた場所にある同じ値が別々に数えられてしまい、集計結果が正しくなりません。「集計する前にまず sort」を合言葉にしておきましょう。

ここまでは1つずつコマンドを実行して結果を確かめてきましたが、実は「あるコマンドの出力を、そのまま次のコマンドの入力として渡す」パイプ（|）という仕組みを使うと、複数のコマンドを1行につなげられます。パイプは本格的には次の第8章で学びますが、この章で学んだ cut・sort・uniq -c を早速1行につなげて、組み合わせの威力を先取りしてみましょう。

ターミナル 
# item列を取り出し→並べ替え→出現回数を数える、を1行でつなげる
cut -d, -f3 sales.csv | sort | uniq -c
出力結果（例） 
student@ubuntu:~/linux-practice/ch07$ cut -d, -f3 sales.csv | sort | uniq -c
      4 apple
      2 banana
      1 item
      2 orange
student@ubuntu:~/linux-practice/ch07$

たった1行で「商品ごとの件数」が集計できました。1 item という行が混ざっているのは、ヘッダー行の3列目の文字列がそのまま item であり、これも1件のデータとして数えられてしまったためです。ヘッダー行を除きたいときは、7.3節で学んだ -v と ^ を使って grep -v '^date' sales.csv とすれば、ヘッダー以外の行だけを取り出せます（その結果を集計へ渡すつなぎ方は第8章で学びます）。今は「ヘッダー行も等しく1行として処理される」ということを覚えておきましょう。

やってみよう 7-2: 検索とテキスト処理を組み合わせる

この章で学んだコマンドを、~/linux-practice/ch07 で実際に動かして確認しましょう。

手順

  1. 1 grep -c ' 200 ' access.log を実行し、ステータス200の件数が5件であることを確認する。
  2. 2 sort -t, -k4,4 -n sales.csv を実行し、qtyが一番少ない行（qty=1）が先頭近くに来ることを確認する。
  3. 3 cut -d, -f1 sales.csv で日付の列だけを取り出す。
  4. 4 tr a-z A-Z < access.log を実行し、Apr や /index.html などの小文字が大文字に変わり、もともと大文字の GET・POST は変わらないことを確認する。
  5. 5 grep -c 192.168.1.10 access.log を実行し、IPアドレス 192.168.1.10 からのアクセスが4件あることを確認する（IPアドレスごとの件数をまとめて数える方法は、第8章でパイプを使って学びます）。

この章のまとめ

  • cat > ファイル <<'EOF' のヒアドキュメントを使うと、複数行のファイルを一気に作成できる。
  • find は -name・-type・-mtime・-size でファイルそのものを検索する。ワイルドカードは引用符で囲む。
  • grep は文字列を含む行を検索する。-i・-n・-v・-c・-r と、^ $ . の簡単な正規表現が使える。
  • cut -d 区切り文字 -f 列番号 で列を取り出す。tr 変換前 変換後 は標準入力しか読めないため < でファイルを渡す。
  • wc -l/-w で行数・単語数を数え、sort で並べ替え、uniq -c で出現回数を数える。uniq -c の前には必ず sort（隣り合う重複しかまとめないため）。
  • パイプ（|）を使うと複数のコマンドを1行でつなげられる。本格的な使い方は次の第8章で学ぶ。

確認問題

  1. Q1. uniq -c を実行する前に sort が必要なのはなぜですか。

    回答を表示

    uniq -c は隣り合っている同じ行しかまとめて数えられないためです。データが並べ替えられていないと、同じ値が離れた位置に出てきてしまい正しく集計できません。sort で同じ値を隣どうしに集めてから uniq -c を実行する必要があります。

  2. Q2. find ~/linux-practice -name "*.txt" のように、ワイルドカードを引用符で囲む理由は何ですか。

    回答を表示

    引用符が無いと、* が find に渡る前にシェル自身がカレントディレクトリのファイル名に展開してしまい、意図と違う結果になることがあります。引用符で囲むことで *.txt という文字どおりの文字列が find に渡り、find 自身が各ディレクトリを探しながら照合してくれます。

  3. Q3. grep -v Tokyo sales.csv はどんな行を表示しますか。

    回答を表示

    -v は反転検索のオプションで、指定した文字列を含まない行だけを表示します。grep -v Tokyo sales.csv は、Tokyo を含まない行（ヘッダー行と、Osaka・Nagoyaの行）を表示します。

  4. Q4. tr コマンドが、tr a-z A-Z sales.csv ではなく tr a-z A-Z < sales.csv という形で使われるのはなぜですか。

    回答を表示

    tr は grep や cut と違い、ファイル名を引数として受け取れず、標準入力しか読み取れません。そのため、< を使ってファイルの中身を標準入力として送り込む必要があります。
