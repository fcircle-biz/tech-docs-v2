ホーム Linux 第6章
第6章 所要時間: 約70分

ファイルの中身を見る・編集する

第5章では、ファイルやディレクトリを作成・コピー・移動・削除する方法を学びました。ファイルの「中身」を見る方法は、第2章で cat /etc/os-release を一度使っただけで、まだきちんと学んでいません。この章では cat・less・head・tail でファイルの中身を確認し、nano と vim という2つのテキストエディタで実際にファイルを編集します。あわせて、文字コードと改行コードという「見た目には分かりにくいがトラブルの元になる」注意点も押さえます。

この章で学ぶこと

  • cat・less・head・tail を目的に応じて使い分け、ファイルの中身を確認できる
  • file コマンドでファイルの種類・文字コード・改行コードを調べられる
  • nanoで新規・既存のテキストファイルを作成・編集・保存できる
  • vimの最低限の操作（ノーマルモード・挿入モード・保存終了）を理解し、迷わず抜けられる
  • 文字コード（UTF-8）と改行コード（LF/CRLF）の違いと注意点を説明できる

6.1 ファイルの中身を見る — cat・less・head・tail

GUIであればファイルをダブルクリックすればメモ帳やテキストエディタが開きますが、CLIでは「見るだけ」のコマンドと「編集する」ためのエディタが分かれています。まずは中身を見るための4つのコマンド、cat・less・head・tail を使い分けられるようになりましょう。まずはこの章専用の練習用ディレクトリを作ります。

ターミナル 
# 練習用ディレクトリを作り、移動する
mkdir -p ~/linux-practice/ch06
cd ~/linux-practice/ch06

最初は cat（concatenateの略）です。指定したファイルの中身を、先頭から末尾まで一気に画面へ出力します。第2章で見た /etc/os-release を練習用ディレクトリにコピーして使ってみましょう。

ターミナル 
# システム情報ファイルを練習用ディレクトリへコピーする
cp /etc/os-release .
# ファイルの中身を一気に表示する
cat os-release
出力結果（例） 
PRETTY_NAME="Ubuntu 24.04.x LTS"
NAME="Ubuntu"
VERSION_ID="24.04"
VERSION="24.04.x LTS (Noble Numbat)"
VERSION_CODENAME=noble
ID=ubuntu
ID_LIKE=debian
HOME_URL="https://www.ubuntu.com/"
SUPPORT_URL="https://help.ubuntu.com/"
BUG_REPORT_URL="https://bugs.launchpad.net/ubuntu/"
PRIVACY_POLICY_URL="https://www.ubuntu.com/legal/terms-and-policies/privacy-policy"
UBUNTU_CODENAME=noble
LOGO=ubuntu-logo

行番号が欲しいときは -n オプションを付けます。あとで説明するファイル検索やエディタで「何行目」を指すときに役立ちます。

ターミナル 
# 行番号を付けて表示する
cat -n os-release
出力結果（例） 
     1	PRETTY_NAME="Ubuntu 24.04.x LTS"
     2	NAME="Ubuntu"
     3	VERSION_ID="24.04"
     4	VERSION="24.04.x LTS (Noble Numbat)"
     5	VERSION_CODENAME=noble
     6	ID=ubuntu
     7	ID_LIKE=debian
     8	HOME_URL="https://www.ubuntu.com/"
     9	SUPPORT_URL="https://help.ubuntu.com/"
    10	BUG_REPORT_URL="https://bugs.launchpad.net/ubuntu/"
    11	PRIVACY_POLICY_URL="https://www.ubuntu.com/legal/terms-and-policies/privacy-policy"
    12	UBUNTU_CODENAME=noble
    13	LOGO=ubuntu-logo

cat には弱点があります。何百行もある大きなファイルに使うと、文字がものすごい速さで画面を流れていき、大事な部分が読めないまま消えてしまいます。このようなときは、1画面ずつ表示して自分のペースで読める less を使います。

たとえ話: 早口の朗読 と 自分のペースで読む本

cat は、誰かが本を最初のページから最後まで休まず一気に読み上げるようなものです。読み終わるまで待つしかなく、途中で「もう一度」とは言えません。一方 less は、自分の手でページをめくりながら好きな速さで読み、気になった単語を探し、飽きたらすぐ本を閉じられます。長いログファイルを読むときは less の出番です。

less ファイル名 で開くと、画面全体がファイルの中身で占有され、次の入力を待つ状態になります（画面に収まる短いファイルなら画面左下（いちばん下の行）に (END)、「これ以上続きが無い」印が出ます）。この状態で使う主なキー操作は次のとおりです。

キー操作 動作
Space 次の1画面へ進む
b 前の1画面へ戻る（backの意味）
/文字列 → Enter 下方向にその文字列を検索する
n 同じ文字列で、次に一致する箇所へ進む（nextの意味）
g ファイルの先頭へ移動する
G ファイルの末尾へ移動する
q less を終了する（quitの意味）

実際に、もっと長い実在のファイルで練習してみましょう。第2章で sudo apt upgrade を実行したとき、Ubuntuは操作の記録を自動でログファイルに残しています。代表的なのが次の2つで、どちらも一般ユーザーの権限で読めます。

  • /var/log/dpkg.log — パッケージ1つ1つのインストール・更新の詳細な記録
  • /var/log/apt/history.log — apt install・apt upgrade などコマンド単位の記録
ターミナル 
# dpkgの詳細な操作ログをページャーで開く
less /var/log/dpkg.log

開いたら、次の順で操作してみましょう。

  1. /upgrade と入力して Enter — 「upgrade」を含む最初の行へジャンプ
  2. n — 次に一致する行へ
  3. G → g — 末尾・先頭への移動を確認
  4. q — less を終了してシェルへ戻る
ターミナル 
# コマンド単位の操作記録のうち、末尾の20行を表示する
tail -n 20 /var/log/apt/history.log
出力結果（例） 
Start-Date: 2026-09-10  09:32:10
Commandline: apt upgrade -y
Requested-By: student (1000)
Upgrade: libc6:amd64 (2.39-0ubuntu8, 2.39-0ubuntu8.2), tzdata:amd64 (2024a-1, 2024b-0ubuntu1)
End-Date: 2026-09-10  09:33:47

読めないログファイルもある

ログの中には、root や特定のグループのユーザーしか読めないものもあります。読む権限の無いファイルを開くと、/var/log/ファイル名: Permission denied（アクセス拒否）のようなエラーになります。その場合は sudo less ファイル名 のように sudo を付けると読めます。この仕組み（パーミッション）は第9章で詳しく学びます。今回使った dpkg.log と apt/history.log は、誰でも読めるログです。

ログの続きを見る前に、less と役割が近いもう2つのコマンド、head と tail を紹介します。head はファイルの先頭、tail は末尾だけを表示します。既定では10行ですが、-n オプションで行数を指定できます。

ターミナル 
# 先頭5行だけを表示する
head -n 5 os-release
# 末尾5行だけを表示する
tail -n 5 os-release
出力結果（例） 
student@ubuntu:~/linux-practice/ch06$ head -n 5 os-release
PRETTY_NAME="Ubuntu 24.04.x LTS"
NAME="Ubuntu"
VERSION_ID="24.04"
VERSION="24.04.x LTS (Noble Numbat)"
VERSION_CODENAME=noble
student@ubuntu:~/linux-practice/ch06$ tail -n 5 os-release
SUPPORT_URL="https://help.ubuntu.com/"
BUG_REPORT_URL="https://bugs.launchpad.net/ubuntu/"
PRIVACY_POLICY_URL="https://www.ubuntu.com/legal/terms-and-policies/privacy-policy"
UBUNTU_CODENAME=noble
LOGO=ubuntu-logo

tail には、ファイルへの追記をリアルタイムで監視し続ける -f（followの意味）オプションもあります。サーバーのログをリアルタイムで見守るときによく使う、実務でも重要な使い方です。

ターミナル 
# 監視用の空ファイルを作る
touch watch.log
# 更新され続ける様子を監視する（Ctrlキー＋Cで止めるまで戻らない）
tail -f watch.log

この状態のターミナルは新しい行が来るまで動き続け、次のコマンド入力を受け付けません。別のターミナルウィンドウ（またはタブ）をもう1つ開き、第2章 2.5 と同じ方法で Ubuntu に入ってから（WSL はスタートメニューの「Ubuntu 24.04 LTS」、Mac は新しいターミナルで multipass shell ubuntu）、次のコマンドで watch.log に1行追記してみましょう。

ターミナル（別ウィンドウ） 
# watch.log の末尾に1行追記する
# （>> は「追記」の記号。詳しくは第8章で学ぶ）
echo "新しい行が追加されました" >> ~/linux-practice/ch06/watch.log

最初のターミナルに戻ると、追記した行が自動的に表示されます。監視を終えるには Ctrl+C を押します（実行中の処理を強制的に中断する、第3章で紹介したものと同じショートカットです）。

出力結果（例） 
student@ubuntu:~/linux-practice/ch06$ tail -f watch.log
新しい行が追加されました
^C
student@ubuntu:~/linux-practice/ch06$

もう1つ、ファイルの行数を数える wc というコマンドもあります。使い方は第7章で検索・集計コマンドと合わせて詳しく学ぶので、ここでは名前だけ覚えておいてください。

4つのコマンドの使い分けは、次の表のとおりです。

コマンド 何をする 向いている場面
cat ファイル全体を一気に表示 短いファイルの中身をさっと確認する
less 1画面ずつ表示。検索・スクロールができる 長いファイル・ログをじっくり読む
head 先頭のN行だけを表示 ファイルの先頭（見出しなど）だけ見たい
tail 末尾のN行だけを表示（-fで追記を監視） 直近の記録、ログの最新状況を見たい

6.2 ファイルの種類を調べる — file

Linuxではファイル名に拡張子を付けなくても動作します（.txt を付けなくてもテキストファイルとして扱えますし、逆に拡張子だけ書き換えても中身は変わりません）。つまりファイル名だけでは、本当の中身は分かりません。実際の中身を判定してくれるのが file コマンドです。

ターミナル 
# ファイルの種類を調べる
file os-release
出力結果（例） 
os-release: ASCII text

os-release は半角英数字と記号だけでできているため、ASCII text（アスキーテキスト）と判定されました。ASCIIは、半角英数字と基本的な記号だけを表現できる、もっとも基本的な文字コードです。

> は上書き注意

これから使う echo "文字列" > ファイル名 は、指定したファイルが既に存在する場合、確認なしに中身をすべて消して上書きします。間違ったファイル名を指定すると、大切なデータを一瞬で失います。>（上書き）と >>（追記）の詳しい使い方は第8章で学びます。今は「> は上書き」とだけ覚えておきましょう。

では、1行だけの新しいテキストファイルを作って確かめてみましょう。

ターミナル 
# 1行だけのテキストファイルを作る
echo "Hello, Linux!" > memo.txt
file memo.txt
出力結果（例） 
memo.txt: ASCII text

次に、日本語を含むファイルではどう表示されるか比べてみましょう。

ターミナル 
# 日本語を含むファイルを作る
echo "こんにちは、Linux" > japanese.txt
file japanese.txt
出力結果（例） 
japanese.txt: Unicode text, UTF-8 text

日本語はASCIIで表現できる範囲を超えるため、より多くの文字を表せるUTF-8という文字コードで保存され、file もそれを見抜いて Unicode text, UTF-8 text と表示します。文字コードの詳しい説明は6.5節で行います。また、Windowsで作られたファイルを file で調べると、改行コードの違いを示す情報が追加で表示されることがあります。これも6.5節で扱います。

6.3 nanoでテキストファイルを編集する

cat や less は中身を見るだけで、編集はできません。ファイルを作成・編集するにはテキストエディタを使います。最初に紹介するのは nano です。画面の下部に使えるショートカットが常に表示されるため、初めてでも迷いにくいのが特徴です。

ターミナル 
# nanoでmemo.txtを開く
nano memo.txt

起動すると、画面全体がエディタになります。上部にファイル名、下部に主なショートカットが並びます（実際の表示はnanoのバージョンによって多少異なるため、これは一例です）。

画面表示（例） 
  GNU nano 7.2                    memo.txt
Hello, Linux!


^G Help      ^O Write Out ^W Where Is  ^K Cut       ^T Execute
^X Exit      ^R Read File ^\ Replace   ^U Paste     ^J Justify

下部の ^ はCtrlキーを表す記号です。つまり ^O は Ctrl+O、^X は Ctrl+X を意味します。nanoには特別な「モード切り替え」は無く、矢印キーでカーソルを動かしながら、そのまま文字を入力できます。

試しに2行目を追加してみましょう。矢印キーで最後の行の行末にカーソルを移動し、Enter キーで改行してから、好きな文字列を入力してください。

入力できたら保存します。Ctrl+O（Write Out＝書き出す、の意味）を押すと、画面下部に File Name to Write: memo.txt のように保存するファイル名の確認が表示されるので、そのまま Enter を押すと同じファイル名で保存されます。保存できたら Ctrl+X で nano を終了します。もし保存し忘れた変更があると、終了前に次のような確認が表示されます。

画面表示（例） 
Save modified buffer?
 Y Yes
 N No           ^C Cancel

Y を押すと保存するファイル名の確認（File Name to Write: memo.txt）が出るので、Enter を押すと保存して終了、N で変更を捨てて終了、Ctrl+C でnanoの編集画面に戻ります（キャンセル）。今回はすでに保存済みなので、この確認は表示されないはずです。中身を確認してみましょう。

ターミナル 
# 保存された内容を確認する
cat memo.txt
出力結果（例） 
Hello, Linux!
nanoで2行目を追加しました

やってみよう 6-1: nanoでメモファイルを作り、4つの表示コマンドで確認する

nanoで新しいメモファイルを作成し、この章で学んだ cat・less・head・tail で表示を確認します。

手順

  1. 1 ~/linux-practice/ch06 で nano diary.txt を開く。
  2. 2 今日学んだことを3〜4行、自由に入力する。
  3. 3 Ctrl+O → Enter で保存し、Ctrl+X で終了する。
  4. 4 cat diary.txt で全体を、cat -n diary.txt で行番号付きで確認する。
  5. 5 head -n 2 diary.txt と tail -n 2 diary.txt で先頭・末尾だけを確認する。
  6. 6 less diary.txt で開き、内容を確認してから q で終了する。

6.4 vimの最低限の操作

サーバーや最小構成のコンテナでは、nanoが入っておらずvim（またはその前身のvi）しか使えないことがあります。環境によっては vim コマンドが無く command not found になることもありますが、その場合はより軽量な前身の vi memo.txt を試してください。操作方法はこの章で学ぶ範囲では同じです（フル機能版のvimは、第11章で学ぶ apt で sudo apt install vim のように導入できます）。vimを使いこなす必要はありませんが、「開いて」「少し直して」「安全に抜ける」という最低限の操作だけは、この章で身につけておきましょう。

nanoと違い、vimはモードを切り替えながら操作するモーダルエディタです。起動した直後はキーを押しても文字は入力されず、キーそのものが「カーソルを動かす」「文字を消す」などのコマンドとして扱われます。この状態をノーマルモードと呼びます。文字を入力したいときは、i キーを押して挿入モードに切り替えてから入力します。

たとえ話: オートマ車とマニュアル車

nanoは、キーを押せばそのまま文字が入る「オートマ車」に近い操作感です。vimは操作を切り替える「マニュアル車」に近く、慣れるまでは戸惑うかもしれません。しかしモードの意味さえ分かれば、あとは決まった手順を踏むだけです。まずは「ノーマル」「挿入」の2つだけ覚えれば十分です。

ターミナル 
# vimでmemo.txtを開く（無ければ vi memo.txt を試す）
vim memo.txt

ノーマルモード・挿入モード・コマンドラインモードという3つのモードの関係を図にすると、次のようになります。

図1: vimのモード遷移 — ノーマル・挿入・コマンドラインの3つのモード

stateDiagram-v2 [*] --> N state "ノーマルモード" as N state "挿入モード" as I state "コマンドラインモード" as C N --> I: iキーを押す I --> N: Escキーを押す N --> C: コロンキーを押す C --> N: Escキー、またはw（保存のみ）などの実行後 C --> [*]: wqで保存終了、またはq!で破棄終了

編集が終わったら、Esc キーでノーマルモードに戻り、コロンキー（:）を押してコマンドラインモードに入ります。画面左下にカーソルが移り、入力した文字がそのまま表示されるようになります。ここに wq と入力して Enter を押すと、保存（write）してから終了（quit）します。まとめて :wq と書き表すのが一般的です。

逆に、編集した内容を保存せずに終了したいときは、コマンドラインモードで q! と入力して Enter を押します（:q!）。! は「確認せず強制的に実行する」という意味の記号です。

vimから抜けられないときは

「vimを開いたら文字が思うように入力できず、ビープ音が鳴るだけで困った」というのは、多くの人が一度は経験する事態です。多くの場合、ノーマルモードのままキーを連打してしまい、意図しないコマンドが積み重なっている状態です。落ち着いて Esc キーを2〜3回押し、確実にノーマルモードへ戻してください。そのうえでコロンキーを押して q! と入力し、Enter を押せば、編集内容を保存せずに必ず抜け出せます。

やってみよう 6-2: vimで1行追記して保存する

vimで memo.txt を開き、1行追記して保存する一連の流れを練習します。あわせて「保存せず抜ける」練習もしておきましょう。

手順

  1. 1 vim memo.txt で開く（ノーマルモードで始まる）。
  2. 2 i キーを押して挿入モードにする。
  3. 3 矢印キーで最後の行の行末へ移動し、Enter で改行してから新しい行を入力する（例: vimの練習です）。
  4. 4 Esc キーを押してノーマルモードに戻る。
  5. 5 コロンキーを押して wq と入力し、Enter を押して保存終了する（:wq）。
  6. 6 cat memo.txt で追記されたか確認する。
  7. 7 （発展）もう一度 vim memo.txt を開き、i で適当な文字を入力したあと、Esc → コロンキー → q! → Enter で「保存せず抜ける」練習をする。cat memo.txt で内容が変わっていないことを確認できれば成功。

6.5 文字コードと改行コードの注意

コンピュータの内部では、文字も結局は数字として保存されています。「どの数字をどの文字に対応させるか」という対応表を文字コード（エンコーディング）と呼びます。もっとも基本的なASCIIは、半角英数字と基本記号の128種類しか定義していません。日本語や絵文字を表すには足りないため、現在は世界中のほぼすべての文字を表現できるUTF-8が標準的に使われています。

Ubuntu（本ガイドの環境）はロケールが既定で C.UTF-8 になっており、ターミナルから入力した日本語も、nanoやvimで保存したファイルも、UTF-8で書き込まれます。6.2節で echo で作った日本語ファイルが Unicode text, UTF-8 text と判定されたのは、このためです。

普段は文字コードを意識しなくてよい

Ubuntuは既定でUTF-8のため、日本語ファイルを作るときに特別な設定は不要です。意識すべきなのは「Windowsから持ち込んだファイルの改行コードが違うことがある」という次の点だけです。

もう1つ注意したいのが改行コードです。「行の終わり」を表す記号にも種類があります。

種類 記号 主なOS
LF（改行のみ） \n Linux・Mac
CRLF（復帰＋改行） \r\n Windows

Windowsのメモ帳などで作成したファイルはCRLFになります。WSL環境で、Windows側のフォルダ（/mnt/c/...）からファイルをコピーしてきた場合や、メールやチャットで受け取ったテキストファイルをUbuntuに持ち込んだ場合は、CRLFのまま混ざっていることがあります。見分け方は、6.2節で学んだ file コマンドです。

ターミナル 
# （練習用）Windows と同じ CRLF 改行のファイルを作る（printf は \r\n を CRLF として書き出す）
printf 'Hello\r\nLinux\r\n' > windows-note.txt
# 改行コードを調べる
file windows-note.txt
出力結果（例） 
windows-note.txt: ASCII text, with CRLF line terminators

「with CRLF line terminators」という一文が追加されていれば、そのファイルはCRLF改行だと分かります。

改行コードが原因のトラブル

第13章で作るシェルスクリプトのファイルにCRLFが紛れ込むと、見た目は正常なのに実行時だけ原因の分かりにくいエラーになることがあります。もし遭遇したら、file で改行コードを疑ってみましょう。変換には dos2unix というコマンドが便利で、第11章で学ぶ apt で導入できます。

この章のまとめ

  • cat（全体を一気に表示、-nで行番号）・less（1画面ずつ、検索可）・head/tail（先頭・末尾のN行、-fで追記監視）を目的に応じて使い分ける。
  • file コマンドでファイルの種類・文字コード・改行コードを判定できる（ASCII text / UTF-8 text / CRLF line terminators など）。
  • nanoは画面下部のショートカット表示を見ながら直感的に編集できる。保存はCtrl+O→Enter、終了はCtrl+X。
  • vimはノーマルモード（既定）と挿入モード（iで入る）を切り替えて使う。保存終了は:wq、破棄終了は:q!。迷ったらEscを押してからこれらを試す。
  • Ubuntuは既定でUTF-8。Windowsで作られたファイルはCRLF改行になっていることがあり、fileで確認できる。

確認問題

  1. Q1. 数百行ある大きなログファイルの、末尾20行だけをさっと見たいときは、cat・less・head・tailのどれを使うのが適切ですか。理由もあわせて説明してください。

    回答を表示

    tail（tail -n 20 ファイル名）が適切です。catは全体を一気に出力するため長いファイルでは目的の部分を探しにくく、headは先頭から表示するので末尾を見るのには向きません。tail -nは末尾から指定行数だけを直接表示できるため、目的に最も合っています。

  2. Q2. nanoで編集内容を保存してから終了する操作を、キー操作の順番どおりに説明してください。

    回答を表示

    まずCtrl+O（Write Out）を押して保存を開始し、ファイル名の確認画面でEnterを押して保存を確定します。続けてCtrl+Xを押すとnanoが終了します。

  3. Q3. vimを開いてしまい、キーを押しても文字が入力されずビープ音が鳴るだけで操作に困っています。編集内容を保存せずに抜け出す手順を説明してください。

    回答を表示

    Escキーを2〜3回押して確実にノーマルモードへ戻り、コロンキーを押してコマンドラインモードに入ったらq!と入力してEnterを押します（:q!）。これで編集内容を保存せずにvimを終了できます。

  4. Q4. fileコマンドの結果が「ASCII text」ではなく「UTF-8 text」と表示されるのはどのような場合ですか。また、Windowsで作成したファイルをUbuntuに持ち込んだとき、fileの結果に追加で表示されることがある情報は何ですか。

    回答を表示

    ファイルの中身が半角英数字と基本記号だけの場合は「ASCII text」と表示されます。日本語など、ASCIIの範囲を超える文字が含まれると「Unicode text, UTF-8 text」と表示されます。また、Windowsで作られたファイル（改行がCRLF）をUbuntuに持ち込むと、「with CRLF line terminators」という情報が結果に追加で表示されることがあります。
