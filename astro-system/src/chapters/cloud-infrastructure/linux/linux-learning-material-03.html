ホーム Linux 第3章
第3章 所要時間: 約60分

はじめてのコマンドとシェルの基本

第2章でUbuntu環境が整いました。この章では、いよいよターミナルに実際にコマンドを打ち込んでいきます。プロンプトの読み方から始めて、簡単なコマンドを何個か実行し、「コマンド＋オプション＋引数」という共通の書式を理解します。さらに、入力を楽にするTab補完・履歴・ショートカットキー、そして困ったときに自分で調べる方法（man・--help・type）まで、この先すべての章で使う土台を身につけます。

この章で学ぶこと

  • プロンプト student@ubuntu:~$ の各部分が何を表しているか説明できる
  • echo・date・whoami・hostname・clear を実行できる
  • 「コマンド＋オプション＋引数」というコマンドラインの書式を理解し、空白や大文字小文字の違いに注意して打てる
  • Tab補完・コマンド履歴・Ctrlショートカットを使って入力を効率化できる
  • man・--help・type を使って、コマンドの使い方を自分で調べられる

3.1 プロンプトを読む

ターミナルを開くと、まず次のような文字列が表示され、カーソルが点滅して入力を待っています。これをプロンプト（prompt、「促す」の意味）と呼びます。プロンプトは「今からコマンドを受け付けます」という合図であり、同時に今誰が・どこで作業しているかを教えてくれる、シェルからの重要なメッセージでもあります。

図1: プロンプト student@ubuntu:~$ の構造

student@ubuntu:~$
student — 今ログインしているユーザー名
ubuntu — 今使っているコンピューターのホスト名
~ — 今いる場所（カレントディレクトリ）。~はホームディレクトリの略記号（第4章で詳しく学ぶ）
$ — 一般ユーザーとして入力待ちであることを示す記号

まとめると、プロンプトは 「ユーザー名＠ホスト名：カレントディレクトリ＄」 という形になっています。この形式はUbuntuの標準設定によるもので、ディストリビューションや設定次第で見た目は変わりますが、「今の自分の状態」を表すという役割は共通です。

末尾が # なら root（管理者）

末尾の記号が $ ではなく # になっていたら、それはroot（管理者）ユーザーとして操作している合図です。# の状態では、システムを壊しかねない操作も確認なしで実行できてしまうため、見慣れない # を見たら一呼吸置く習慣をつけましょう。root と sudo については第9章で詳しく学びます。

自分の画面では表示が少し違います

Multipass（Mac）では、ユーザー名が ubuntu 固定のため、プロンプトは ubuntu@ubuntu:~$ のようにユーザー名とホスト名が同じ単語になります。WSL（Windows）では、ホスト名の部分が自分のパソコンのコンピューター名（例: DESKTOP-XXXXXXX）になります。本ガイドの出力例はすべて student@ubuntu:~$ の表記で統一していますが、実際の画面では自分の環境の名前に読み替えてください。

3.2 最初のコマンドを打ってみる

それでは、実際にコマンドを打ってみましょう。ここで紹介するのは、画面に何かを表示したり、今の状態を確認したりするだけの、失敗しても安全なコマンドばかりです。気軽に試してください。

echo — 文字を画面に表示する

echo は、引数に渡した文字をそのまま画面に表示するコマンドです。「シェルがちゃんと動いているか」を確認する、いちばん単純な一歩になります。

ターミナル 
# 渡した文字をそのまま表示する
echo Hello, Linux!
出力結果（例） 
student@ubuntu:~$ echo Hello, Linux!
Hello, Linux!
student@ubuntu:~$

whoami・hostname — 自分の状態を確認する

whoami（who am I）は今ログインしているユーザー名を、hostname は今操作しているコンピューターのホスト名を表示します。どちらも、プロンプトに表示されている内容を1つずつ確認できるコマンドです。

ターミナル 
# 今ログインしているユーザー名を表示する
whoami
# 今操作しているコンピューターのホスト名を表示する
hostname
出力結果（例） 
student@ubuntu:~$ whoami
student
student@ubuntu:~$ hostname
ubuntu
student@ubuntu:~$

Multipassなら whoami は ubuntu、WSLなら hostname は自分のパソコンのコンピューター名を表示します。3.1節で触れた内容が、実際のコマンドで裏付けられたことになります。

date — 今の日時を表示する

date は現在の日時を表示します。

ターミナル 
# 現在の日時を表示する
date
出力結果（例） 
student@ubuntu:~$ date
Wed Apr  1 10:00:00 UTC 2026
student@ubuntu:~$

「曜日 月 日 時:分:秒 タイムゾーン 年」の順で表示されます。上の出力例をよく見ると、Apr と 1 の間に空白が2つ入っています。日が1桁のときに桁をそろえるための仕様で、故障ではありません。タイムゾーンの表示は UTC（協定世界時）のこともあれば、環境の設定によって JST（日本時間）のこともあります。自分の画面の時刻がずれているように見えても、まずはタイムゾーンの違いを疑ってみましょう。

clear — 画面をきれいにする

コマンドを打つほど、画面はどんどん文字で埋まっていきます。clear を実行すると、画面の表示だけがまっさらになり、新しいプロンプトが一番上に表示されます。それまで実行したコマンドが消えるわけではありません。次の3.4節で学ぶ履歴にはちゃんと残っています。

ターミナル 
# 画面の表示をきれいにする（履歴は消えない）
clear

cal を試すとエラーになる — エラーメッセージを読む練習

カレンダーを表示する cal というコマンドもありますが、Ubuntu 24.04では標準で入っていないことが多く、実行すると次のようなメッセージが出ます。

出力結果（例） 
student@ubuntu:~$ cal
Command 'cal' not found, but can be installed with:
sudo apt install ncal
student@ubuntu:~$

これは失敗ではなく、読めば分かるヒントです

1行目は「cal というコマンドは見つからないが、こうすれば入れられる」という意味、2行目はその具体的な方法です。Ubuntuはこのように、コマンドが無いときに導入方法まで教えてくれる親切な仕組みを持っています。今の段階ではまだ sudo apt install は実行しません（ソフトの追加は第11章で学びます）。ここで大事なのは、エラーが出ても慌てず、表示された文章を最後まで落ち着いて読むという習慣です。この先の章でも、エラーメッセージは何度も出てきます。

やってみよう 3-1: 基本コマンドを一通り試す

自分のターミナルで、この節に出てきたコマンドを実際に打ってみましょう。

手順

  1. 1 echo の後ろに好きな文字（まずは英数字や日本語。' や ! などの記号は特別な意味を持つので避ける）を続けて実行し、そのまま表示されることを確認する。行頭に > が出て止まったら Ctrl+C（3.4節）で抜ける。
  2. 2 whoami・hostname を実行し、結果がプロンプトの表示と一致することを確認する。
  3. 3 date を実行し、表示されたタイムゾーンが UTC か JST かを確認する。
  4. 4 画面が見づらくなってきたら clear で片付ける。
  5. 5 最後に cal を実行し、出てきたメッセージを実際に自分の目で読んでみる。

3.3 コマンドの書式（オプションと引数）

ここまでのコマンドは単語1つだけでしたが、実際のコマンドはもっと細かく動作を指定できます。Linuxのコマンドラインには、ほぼすべてのコマンドに共通する書式があります。

コマンド ［オプション］ ［引数］

それぞれ「何をするか」（コマンド）、「どう動作を変えるか」（オプション）、「何に対して行うか」（引数）を表します。第4章で詳しく学ぶ ls（一覧表示コマンド）を例に、実際に分解してみましょう。

図2: コマンドラインの分解 — ls -l /etc の場合

flowchart LR A["ls"] -->|空白で区切る| B["-l"] -->|空白で区切る| C["/etc"] A -.-> A2["コマンド本体
実行するプログラムの名前"] B -.-> B2["オプション
動作を変える指定
ハイフンで始まる"] C -.-> C2["引数
操作の対象
ファイルやディレクトリなど"]

ls は「一覧表示する」というコマンド本体、-l は「詳しい形式で」というオプション、/etc は「対象は /etc ディレクトリ」という引数です。実際に打ってみましょう（/etc は設定ファイルが集まる場所で、詳しくは第4章で学びます）。

ターミナル 
# /etc の中身を詳しい形式（-lオプション）で一覧表示する
ls -l /etc
出力結果（例） 
student@ubuntu:~$ ls -l /etc
total 1428
-rw-r--r--   1 root root    3028 Apr  1 09:40 adduser.conf
drwxr-xr-x   8 root root    4096 Apr  1 09:40 apt
drwxr-xr-x   2 root root    4096 Apr  1 09:40 cron.d
-rw-r--r--   1 root root       7 Apr  1 09:40 hostname
-rw-r--r--   1 root root     177 Apr  1 09:40 hosts
（以下省略）
student@ubuntu:~$

左端の -rw-r--r-- のような文字列はファイルの種類とアクセス権限（パーミッション）で、詳しい読み方は第9章で学びます。今はいちばん右のファイル・ディレクトリ名だけ確認できれば十分です。表示される行数やファイル名、日時、サイズは環境によって変わります。

オプションはまとめて書ける

1文字のオプション（短いオプション）は、ハイフン1つの後ろにまとめて書けます。たとえば「詳しい形式で」（-l）と「隠しファイルも含めて」（-a、第4章で扱います）を同時に使いたいときは、次の2通りはまったく同じ意味になります。

ターミナル 
# この2つの書き方は同じ意味になる
ls -l -a
ls -la

一方、--all や --help のように単語のつづりで指定するものは長いオプションと呼ばれ、ハイフン2つで始まります（ただし第7章で学ぶ find の -name のように、ハイフン1つで単語を書くコマンドも一部あります。その場合は1文字ずつのオプションに分解されません）。-a と --all は同じ意味を持つコマンドが多く、短いオプションは打ちやすく、長いオプションは意味が分かりやすいという特徴があります。まとめられるのは短いオプションだけで、--all --help のような長いオプション同士は --allhelp のようにまとめて書くことはできません。

空白と大文字小文字は厳密に区別される

コマンドラインでは、区切りの空白がとても重要な意味を持ちます。コマンドとオプションの間の空白を消してしまうと、シェルはそれを1つの別のコマンド名として解釈しようとし、見つからずにエラーになります。

出力結果（例） 
student@ubuntu:~$ ls-l
ls-l: command not found
student@ubuntu:~$

シェルは ls-l という名前のコマンドを探しに行き、見つからないので「command not found」（コマンドが見つかりません）と返してきます。同じように、Linuxのコマンドは大文字と小文字も厳密に区別します。ls を大文字にした LS は、別物として扱われて見つかりません。

出力結果（例） 
student@ubuntu:~$ LS
LS: command not found
student@ubuntu:~$

「command not found」が出たら、まずこの2つを疑う

この先の章で入力ミスをして固まってしまったら、①空白の位置が正しいか、②大文字小文字を間違えていないかをまず確認しましょう。この2つだけで、command not found エラーの多くは解決します。

3.4 入力を楽にする（Tab補完・履歴・ショートカット）

コマンド名は長いものも多く、すべて手入力するのは大変です。bashには、入力の手間を大きく減らしてくれる仕組みが標準で備わっています。

Tab補完 — 最後まで打たなくていい

コマンド名の先頭だけを入力して Tabキーを押すと、bashが続きを自動的に補ってくれます。候補が1つに絞れる場合は、その場で最後まで補完されます。

出力結果（例） 
student@ubuntu:~$ whoa
（ここでTabキーを1回押す）
student@ubuntu:~$ whoami

whoa で始まるコマンドは whoami しかないため、Tabキー1回で whoami まで補完されます。あとはEnterを押すだけです。一方、候補が複数あって1つに絞れないときは、Tabキーを2回押すと候補の一覧が表示されます。

出力結果（例） 
student@ubuntu:~$ who
（Tabキーを1回押しても反応がない。もう1回押すと…）
who      whoami
student@ubuntu:~$ who

who で始まるコマンドには who 自身と whoami の2つがあるため、1回目のTabではどちらか決められず反応しません。2回目のTabで候補が一覧表示され、入力していた who がそのままプロンプトに戻ってくるので、続きを自分で打ちます。Tab補完はコマンド名だけでなく、第4章以降で学ぶファイル名やディレクトリ名でも同じように使え、打ち間違いも防いでくれるため積極的に使う価値があります。

コマンド履歴 — 同じコマンドを打ち直さない

bashは実行したコマンドを記憶しています。↑（上矢印）キーを押すと直前に実行したコマンドが、さらに押すともっと前のコマンドが呼び出されます。↓（下矢印）キーで逆方向にたどれます。呼び出したコマンドはそのまま実行してもよいですし、一部を書き換えてから実行しても構いません。記憶されている履歴全体は history コマンドで確認できます。

ターミナル 
# これまで実行したコマンドの一覧を番号付きで表示する
history
出力結果（例） 
student@ubuntu:~$ history
    1  echo Hello, Linux!
    2  whoami
    3  hostname
    4  date
    5  clear
    6  history
student@ubuntu:~$

番号を使って !4 のように打つと、その番号のコマンド（この例では4番の date）をもう一度実行できます。番号は人によって違います（第2章で打ったコマンドも残っているため）。!番号 を使うときは、直前に history で自分の番号を確認してください。ただし打ち間違えると別の番号を再実行してしまう危険もあるため、まずは↑↓キーで履歴をたどる方法に慣れておけば十分です。!番号 はこういう機能もあると知っておく程度で構いません。

よく使うショートカットキー

キーボードだけでカーソルを動かしたり、操作を中断したりできるショートカットもあります。マウスに手を伸ばさず入力し続けられるので、覚えておくと作業が速くなります。

キー操作 名称 効果
↑ / ↓ 履歴の呼び出し 実行したコマンドを1つずつ前後にたどる
Tab 入力補完 コマンド名・ファイル名を補完する（候補複数なら2回押しで一覧）
Ctrl + C 中断 実行中のコマンドや、入力中の行を取り消す
Ctrl + L 画面クリア clear コマンドと同じ効果（履歴は消えない）
Ctrl + A 行頭へ移動 カーソルを入力行の先頭に移動する
Ctrl + E 行末へ移動 カーソルを入力行の末尾に移動する

特に Ctrl+C は重要です。長い処理を間違えて実行してしまったときや、コマンドが固まって戻ってこないように見えるときに、慌てず押せば安全に中断できます。この先の章で「何か様子がおかしい」と感じたら、まず Ctrl+C を試す習慣をつけておきましょう。

やってみよう 3-2: Tab補完と履歴で入力を楽にする

Tab補完・履歴・ショートカットを、実際に手で試して体に覚え込ませましょう。

手順

  1. 1 whoa まで打ってTabキーを1回押し、whoami まで補完されることを確認してEnterを押す。
  2. 2 who まで打ってTabキーを2回押し、候補が一覧表示されることを確認する。
  3. 3 ↑キーを数回押して、これまで打ったコマンドが順番に呼び出されることを確認する。
  4. 4 history を実行し、番号付きの一覧を確認する。
  5. 5 何か文字を入力した状態で Ctrl+A → Ctrl+E の順に押し、カーソルが行頭・行末に飛ぶことを確認してから Ctrl+C で入力を取り消す。

3.5 困ったときはマニュアル（man・--help・type）

これから何十個ものコマンドを学びますが、すべてのオプションを暗記する必要はありません。Linuxには、コマンドの使い方をコマンド自身に聞く方法が用意されています。まずは調べ方を覚えてしまいましょう。

man — 詳しいマニュアルを読む

man（manual）は、コマンドの正式なマニュアルを表示します。man ls のように「man 調べたいコマンド名」の形で使います。

ターミナル 
# lsコマンドのマニュアルを表示する
man ls

マニュアルは画面いっぱいに表示され、「NAME（名前）」「SYNOPSIS（書式）」「DESCRIPTION（説明）」といった見出しの下に、コマンドの目的とオプションの一覧が続きます。この表示中は次のキー操作でページ内を移動できます。

キー 効果
スペースキー 1画面分、先へ進む
b 1画面分、前に戻る
/検索したい語 文中をキーワードで検索する（続けてEnter）
q マニュアルを終了し、プロンプトに戻る（quit）

マニュアルを開いたまま操作が分からなくなっても、慌てず q を押せば必ず戻ってこられます。これだけ覚えておけば安心です。

環境によっては man が使えないことがある

Docker コンテナなど、最小構成に軽量化されたUbuntu環境では、man を実行すると次のような案内が表示され、マニュアル本文が出てこないことがあります。

出力結果（例） 
student@ubuntu:~$ man ls
This system has been minimized by removing packages and content that
are not required on a system that users do not log into.

To restore this content, including manpages, run the 'unminimize'
command.

これは「マニュアルなどを省いた軽量構成になっている」というお知らせで、故障ではありません。このような環境では、次に紹介する --help を代わりに使えば、たいていの用は足ります。

--help — 手早く使い方だけ見る

多くのコマンドは、--help という長いオプションを付けて実行すると、マニュアルより短い使い方の要約をその場に表示してくれます。ページをめくる操作が要らないので、ちょっと確認したいだけのときに手早く済みます。

ターミナル 
# lsコマンドの使い方を手早く確認する
ls --help

先頭に Usage: ls [OPTION]... [FILE]... のような1行（書式の要約）が表示され、その下にオプションの一覧が続きます。man は「じっくり読む」、--help は「さっと見る」と使い分けるとよいでしょう。

type — その名前の正体を調べる

コマンドだと思って打っている名前が、実はシェル自身に組み込まれた機能だったり、別のコマンドの別名（エイリアス）だったりすることがあります。type を使うと、その名前の正体を確認できます。

ターミナル 
# cd・ls・date の正体をそれぞれ調べる
type cd
type ls
type date
出力結果（例） 
student@ubuntu:~$ type cd
cd is a shell builtin
student@ubuntu:~$ type ls
ls is aliased to `ls --color=auto'
student@ubuntu:~$ type date
date is hashed (/usr/bin/date)
student@ubuntu:~$

結果は3パターンに分かれます。cd は「shell builtin（シェル組み込み機能）」で、独立したプログラムではなくbash自身が処理します（第4章で学びます）。ls は「aliased to（〜の別名）」で、実は ls --color=auto（ファイルの種類を色分けする）の短縮名として登録されています（エイリアスは第11章で学びます）。date は /usr/bin/date という実体のあるプログラムファイルだと分かります。一度実行したコマンドには hashed（bash が場所を覚えている、という意味）と付きます。新しく開いたターミナルで最初に調べると date is /usr/bin/date と表示されますが、正体は同じです。同じ「コマンド」という言葉で呼んでいても、裏側の正体はさまざまです。

シェルを終了する

今の作業を終えるときは exit と打てば、今使っているシェルを終了できます。WSLならそのままターミナルのウィンドウが閉じるか元のコマンドプロンプトに戻り、Multipassなら multipass shell で入ったUbuntu環境から抜けて、Mac側のターミナルに戻ります（Ubuntu環境自体が終了するわけではありません）。この章では、次のやってみよう 3-3 を終えてから実行しましょう。再開するときは、第2章 2.5節の方法でもう一度 Ubuntu に入ります。

ターミナル 
# 今のシェルを終了する
exit

やってみよう 3-3: man で date のオプションを調べる

自分でマニュアルを検索し、見つけたオプションを実際に試してみましょう。

手順

  1. 1 man date を実行する（表示されない場合は date --help でもよい。その場合は手順2・3を飛ばし、表示された一覧から %Y・%m・%d を探す）。
  2. 2 / を押してから format と入力しEnterを押し、書式指定に関する説明を検索する。
  3. 3 q でマニュアルを閉じる。
  4. 4 見つけた書式指定を使って date +%Y-%m-%d を実行し、日付だけが表示されることを確認する。
  5. 5 最後に type date を実行し、/usr/bin/date が表示されることを確認する（直前に date を実行したので date is hashed (/usr/bin/date) と表示される）。

この章のまとめ

  • プロンプト ユーザー名@ホスト名:カレントディレクトリ$ は「今の自分の状態」を表す。# はrootユーザーの合図。
  • echo・date・whoami・hostname・clear で状態確認や画面整理ができる。「command not found」は落ち着いて読めば対処できる。
  • コマンドラインの書式はコマンド＋オプション＋引数。短いオプションはまとめられる（-la）が、長いオプションは -- で始まる。空白と大文字小文字は厳密に区別される。
  • Tab補完（1回で補完、複数候補は2回で一覧）・↑↓キーの履歴・history・Ctrl+C／Ctrl+L／Ctrl+A／Ctrl+E で入力を効率化できる。
  • man コマンド名（qで終了）・コマンド名 --help・type コマンド名 で、自分でコマンドの使い方を調べられる。作業を終えるときは exit。

確認問題

  1. Q1. プロンプト student@ubuntu:~$ の4つの部分（student・ubuntu・~・$）は、それぞれ何を表しますか。rootユーザーで操作しているときは、どこがどう変わりますか。

    回答を表示

    student はログイン中のユーザー名、ubuntu はホスト名、~ はカレントディレクトリ（ここではホームディレクトリ）、$ は一般ユーザーとして入力待ちであることを示します。rootユーザーで操作しているときは、末尾の記号が $ から # に変わります。

  2. Q2. cal を実行すると Command 'cal' not found, but can be installed with: sudo apt install ncal と表示されました。これはどのような意味で、今の段階ではどう対処すればよいですか。

    回答を表示

    「cal というコマンドは今インストールされていないが、sudo apt install ncal を実行すれば追加できる」という案内です。コマンドが見つからないというエラーですが、導入方法まで教えてくれるUbuntuの親切なヒントでもあります。ソフトウェアの追加（apt）は第11章で学ぶため、この章ではまだインストールを実行せず、メッセージを読んで意味を理解できれば十分です。

  3. Q3. ls -l /etc と、ハイフンの前にスペースを入れずに打った ls-l /etc とでは、結果がどう違いますか。理由も含めて説明してください。

    回答を表示

    ls -l /etc は「ls コマンドを -l オプション付きで /etc に対して実行する」と正しく解釈され、詳しい形式の一覧が表示されます。一方 ls-l はスペースが無いため、シェルはこれを1つの単語（コマンド名）として認識してしまい、そのようなコマンドは存在しないため ls-l: command not found というエラーになります。

  4. Q4. Tab補完で候補が1つに絞れないとき、候補の一覧を見るにはどうすればよいですか。また type ls を実行すると何が表示され、それはどういう意味ですか。

    回答を表示

    Tabキーを2回押すと、候補に当てはまるコマンド名（またはファイル名）が一覧表示されます。type ls を実行すると ls is aliased to `ls --color=auto' と表示され、これは ls という名前が独立したプログラムではなく、ls --color=auto（ファイルを種類ごとに色分けして表示する）のエイリアス（別名）として登録されていることを意味します。
