シェルスクリプト入門

ここまでの章では、コマンドを1つずつターミナルに入力して実行してきました。この章では、複数のコマンドをテキストファイルにまとめておき、まとめて実行できる「シェルスクリプト」の書き方を学びます。変数（第11章で少しだけ触れました）・引数・条件分岐（if）・繰り返し（for／while）といった、プログラミングの基本的な考え方を、ここで本格的に学びます。ここで身につける引数チェック・終了ステータス・コマンド置換などの書き方は、第14章の総合演習でそのまま使います。

この章で学ぶこと

  • シェルスクリプトの役割と、シバン・実行権限（chmod +x）・./script.sh での実行方法を説明できる
  • 変数を定義・参照でき、ダブルクォートとシングルクォートの違いを説明できる
  • 引数（$1・$#）や read -p を使って、外部からの入力を受け取るスクリプトを書ける
  • if文と比較演算子（-f・-d・-eq など）を使って、条件によって処理を分岐できる
  • for文・while文を使って、同じ処理を繰り返し実行できる
  • 終了ステータス（$?）・標準エラー出力（>&2）・set -eu を使って、エラーに気づきやすい安全なスクリプトを書ける

13.1 シェルスクリプトとは

シェルスクリプトとは、ターミナルに打ち込むコマンドを順番に並べて保存した、ただのテキストファイルです。第1章の1.4節で「for f in *.jpg; do mv "$f" "trip_$f"; done のような1行で何百回分もの作業を片づけられる」と予告したのを覚えているでしょうか。この章では、そうした1行や複数行の処理をファイルにまとめ、名前を付けて何度でも呼び出せるようにする方法を学びます。

たとえ話: 料理のレシピ

シェルスクリプトは、料理のレシピに似ています。毎回「まず野菜を切って、次に炒めて……」と口頭で説明する代わりに、手順を紙に書いておけば、誰が読んでも（自分自身が後で読み返しても）同じ手順を正確に再現できます。シェルスクリプトも同じで、コマンドの手順を1つのファイルに書いておけば、1週間後の自分や同僚が、まったく同じ処理を寸分違わず繰り返せます。

シェルスクリプトのファイルは、先頭の1行にシバン（shebang）と呼ばれる特別な行を書くのが決まりです。

書式 
#!/bin/bash

#! の部分は「シバン」と読み、そのあとに続くパス（ここでは /bin/bash）が「このファイルの中身は bash に読ませて実行してください」という宣言になります。このファイルを実行しようとすると、シバンを見て bash 本体が呼び出され、2行目以降が bash のコマンドとして1行ずつ実行されます。

① シバンを書く

1行目に #!/bin/bash。第6章の nano でファイルを作成する。

② 実行権限を付ける

第9章の chmod +x ファイル名 で実行(x)権限を付与する。

③ 実行する

./ファイル名 のように、先頭に ./ を付けて実行する。

実際に手を動かして確認しましょう。まず、この章専用の実習ディレクトリを作ります。

ターミナル 
# 実習用ディレクトリを作成して移動する
mkdir -p ~/linux-practice/ch13
cd ~/linux-practice/ch13

# nanoで最初のスクリプトファイルを新規作成する
nano first.sh

nano が開いたら、次の3行を入力して Ctrl+O → Enter で保存し、Ctrl+X で終了します（第6章の操作）。

first.sh 
#!/bin/bash
# first.sh: 最初のシェルスクリプト
echo "Hello, Shell Script!"

保存しただけの状態で、いきなり実行してみましょう。

ターミナル 
# 実行権限を付ける前に、そのまま実行してみる
./first.sh
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ ./first.sh
bash: ./first.sh: Permission denied

「権限が無い（Permission denied）」と拒否されました。nano で新規作成したファイルには、まだ実行権限（x）が付いていないためです。第9章の chmod で権限を付けます。今度は ./ を付けずに実行してみましょう。

ターミナル 
# 実行権限(x)を付与する
chmod +x first.sh

# ./を付けずに実行してみる
first.sh
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ chmod +x first.sh
student@ubuntu:~/linux-practice/ch13$ first.sh
first.sh: command not found

実行権限を付けたのに、今度は「見つからない（command not found）」と言われてしまいました。これは第11章で学んだPATHが原因です。コマンド名だけを打つと、シェルは PATH に登録されたディレクトリだけを順番に探します。カレントディレクトリ（~/linux-practice/ch13 のような「今いる場所」）は、基本的に PATH に含まれていません。そこで ./（「カレントディレクトリの」という意味の相対パス、第4章）を付けて、「今いる場所にあるこのファイル」だと明示的に指定する必要があります。

ターミナル 
# ./ を付けて「今いる場所のファイル」だと明示して実行する
./first.sh
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ ./first.sh
Hello, Shell Script!

重要ポイント

「実行権限が無い（Permission denied）」と「PATHに見つからない（command not found）」は、原因がまったく別のエラーです。chmod +x で権限を付け、./で場所を明示するという2つがそろって、はじめてスクリプトを実行できます。

なお、実行権限が無くても動かす方法もあります。bash ファイル名 のように、bash コマンドの引数としてスクリプトを渡す方法です。この場合は「bash にこのファイルを読ませて実行する」という指定になるため、実行権限(x)は不要です。

ターミナル 
# bash にスクリプトを渡して実行する（実行権限は不要）
bash first.sh
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ bash first.sh
Hello, Shell Script!

本ガイドでは、配布しても単独のコマンドのように使える chmod +x ＋ ./script.sh の形を基本にします。

知らないスクリプトをいきなり実行しない

chmod +x と ./ の仕組みは、裏を返せば「実行権限さえ付ければどんなファイルでも実行できてしまう」ということでもあります。インターネットからダウンロードしたスクリプトや、中身を書いた人が分からないスクリプトは、chmod +x する前に cat や less（第6章）で中身を確認する習慣をつけましょう。

13.2 変数・引数・入力

スクリプトの中で値を一時的に覚えておく箱が変数です。変数名=値 で代入し、$変数名（または ${変数名}）で参照します。

= の前後にスペースを入れない

シェル変数への代入は、= の前後にスペースを1つも入れてはいけません。スペースを入れると、シェルは「name というコマンドを = と "Linux" という2つの引数付きで実行する」という意味だと解釈してしまいます。

ターミナル 
# 間違い: = の前後にスペースがある
name = "Linux"

# 正しい: = の前後にスペースを入れない
name="Linux"
echo "$name"
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ name = "Linux"
name: command not found
student@ubuntu:~/linux-practice/ch13$ name="Linux"
student@ubuntu:~/linux-practice/ch13$ echo "$name"
Linux

変数を参照するときは、"$name" のようにダブルクォートで囲むのが基本です。値にスペースが含まれていても1つの値として扱われ、意図しない分割を防げます。一方シングルクォートで囲むと、中身が一切展開されずそのままの文字列になります。

ダブルクォート "..."

中の $変数名 は値に展開される。値の中のスペースも保持されるので、基本はこちらを使う。

シングルクォート '...'

中身がそのまま文字列になる。$ も展開されない。設定ファイルの雛形など「展開させたくない」ときに使う。

クォート無しだとどう困るか、ファイル名で確認してみましょう（touch は第5章）。

ターミナル 
filename="my report.txt"

# クォート無し: スペースで2つの単語に分割されてしまう
touch $filename
ls

# ダブルクォートあり: 1つのファイル名として扱われる
touch "$filename"
ls
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ touch $filename
student@ubuntu:~/linux-practice/ch13$ ls
first.sh  my  report.txt
student@ubuntu:~/linux-practice/ch13$ touch "$filename"
student@ubuntu:~/linux-practice/ch13$ ls
 first.sh   my  'my report.txt'   report.txt

クォート無しの1回目は、my と report.txt という別々の2つのファイルができてしまいました。ダブルクォートで囲んだ2回目は、意図どおり my report.txt という1つのファイルになっています（ls はスペースを含む名前を引用符付きで表示し、ほかの名前の前には桁をそろえるための空白を1つ入れます）。シングルクォートとの違いも確認しておきましょう。

ターミナル 
# ダブルクォートとシングルクォートの違いを比べる
echo "$name"
echo '$name'
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ echo "$name"
Linux
student@ubuntu:~/linux-practice/ch13$ echo '$name'
$name

次に、スクリプトの外から値を受け取る方法です。./script.sh apple banana のように実行すると、スクリプトの中では次の特別な変数で参照できます。

変数 意味
$0 実行したときのスクリプト自身の名前（./script.sh と打てば ./script.sh）
$1 $2 … 1番目、2番目…の引数（このような引数を「位置パラメータ」と呼ぶ）
$# 渡された引数の個数
$@ すべての引数（1つずつの並びとして）

nano show_args.sh で次の内容を入力して保存し、実行権限を付けて引数を2つ渡してみましょう。

show_args.sh 
#!/bin/bash
# show_args.sh: 渡された引数を表示する
echo "スクリプト名: $0"
echo "1番目の引数: $1"
echo "2番目の引数: $2"
echo "引数の数: $#"
echo "すべての引数: $@"
ターミナル 
# 実行権限を付けて、引数を2つ渡して実行する
chmod +x show_args.sh
./show_args.sh apple banana
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ ./show_args.sh apple banana
スクリプト名: ./show_args.sh
1番目の引数: apple
2番目の引数: banana
引数の数: 2
すべての引数: apple banana

引数を付けずに実行された場合など、その場で利用者に入力してもらいたいこともあります。そのときは read -p "表示する文字列: " 変数名 を使います。プロンプトを表示したあと、Enterキーが押されるまで入力を待ち、入力された文字列を変数へ代入します。

ターミナル 
# 入力を受け取って変数 lang に代入し、表示する
read -p "好きな言語を入力してください: " lang
echo "あなたの好きな言語は ${lang} ですね。"
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ read -p "好きな言語を入力してください: " lang
好きな言語を入力してください: Bash
student@ubuntu:~/linux-practice/ch13$ echo "あなたの好きな言語は ${lang} ですね。"
あなたの好きな言語は Bash ですね。

最後に、コマンドの実行結果を変数に取り込むコマンド置換 $(コマンド) です。カッコの中のコマンドが実行され、その標準出力の文字列が、その場に埋め込まれます。

ターミナル 
# date の実行結果を変数 today に代入する（コマンド置換）
today=$(date +%Y-%m-%d)
echo "今日の日付: ${today}"
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ today=$(date +%Y-%m-%d)
student@ubuntu:~/linux-practice/ch13$ echo "今日の日付: ${today}"
今日の日付: 2026-09-23

日付の書式はお好みで指定できる

date コマンドに続ける +書式 を変えると、出力される形が変わります。たとえば区切りの無い $(date +%Y%m%d) なら 20260923 のように出力され、ファイル名に使いやすい形になります。第14章のバックアップスクリプトでこの形を使います。

やってみよう 13-1: あいさつスクリプトを作る

名前を引数で受け取り、無ければ read で尋ねて、あいさつと今日の日付を表示する hello.sh を作りましょう。

手順

  1. 1 ~/linux-practice/ch13 にいることを確認し、nano hello.sh で下記の内容を入力して保存する。
  2. 2 chmod +x hello.sh で実行権限を付与する。
  3. 3 ./hello.sh 太郎 のように引数を付けて実行し、結果を確認する。
  4. 4 今度は引数なしで ./hello.sh を実行し、名前を尋ねられたら入力して確認する。
hello.sh 
#!/bin/bash
# hello.sh: 名前を受け取ってあいさつする

if [ $# -ge 1 ]; then
    name="$1"
else
    read -p "お名前を入力してください: " name
fi

today=$(date +%Y-%m-%d)
echo "こんにちは、${name}さん！"
echo "今日は ${today} です。"
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ chmod +x hello.sh
student@ubuntu:~/linux-practice/ch13$ ./hello.sh 太郎
こんにちは、太郎さん！
今日は 2026-09-23 です。
student@ubuntu:~/linux-practice/ch13$ ./hello.sh
お名前を入力してください: 花子
こんにちは、花子さん！
今日は 2026-09-23 です。

$# -ge 1（引数が1個以上）という条件で分岐しています。if の詳しい書き方は次の13.3で学びます。

13.3 条件分岐（if文）

条件によって処理を分けたいときは if 文を使います。基本の形は次のとおりです。

書式 
if [ 条件1 ]; then
    条件1が真のときの処理
elif [ 条件2 ]; then
    条件2が真のときの処理
else
    どちらでもないときの処理
fi

elif・else は無くてもよく、必ず fi（if を逆から書いたもの）で締めます。

[ ] の内側は前後に半角スペースが必須

実は [ は記号に見えて独立したコマンド（test コマンドの別名）です。ls や grep と同じように、前後をスペースで区切って引数を渡す必要があります。詰めて書くと構文エラーになります。

ターミナル 
# 間違い: ] の前にスペースが無い
[ 1 -eq 1]

Ubuntu 24.04（bash 5.2）では、次のようなエラーになります。

出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ [ 1 -eq 1]
bash: [: missing `]'

[ の直後にスペースを入れ忘れた場合も同様に、独立した単語として認識されずエラーになります。[ の前後・] の前後、条件式の間はすべて半角スペースで区切る、と覚えておきましょう。

[ ] の中でよく使う判定はファイルの種類、数値の比較、文字列の比較の3系統です。

分類 演算子 意味
ファイル判定 -f パス 通常のファイルとして存在する
-d パス ディレクトリとして存在する
-e パス 種類を問わず、とにかく存在する
数値比較 -eq 等しい（equal）
-ne 等しくない（not equal）
-lt より小さい（less than）
-gt より大きい（greater than）
-le 以下（less or equal）
-ge 以上（greater or equal）
文字列比較 = 等しい
!= 等しくない
-z 文字列 文字列の長さが0（空）である

数値には -eq の系統、文字列には =・!= を使い分けます。数値のつもりが文字列を渡すと、次のようにエラーになります。

ターミナル 
# 数値比較 -eq に文字列を渡し、終了ステータスも確認する
[ "abc" -eq 1 ]
echo $?
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ [ "abc" -eq 1 ]
bash: [: abc: integer expression expected
student@ubuntu:~/linux-practice/ch13$ echo $?
2

$? の意味は13.4で説明します。ここでは「数値比較に文字列を渡すとエラーになる」ことだけ押さえておけば十分です。

13.4 終了ステータスとエラー処理

コマンドやスクリプトは、実行を終えるたびに終了ステータスという0〜255の数値を返します。0 は「成功」、0以外 は「何らかの失敗」を表す約束です。直前に実行したコマンドの終了ステータスは、特別な変数 $? で確認できます。

ターミナル 
# 成功するコマンドと失敗するコマンドの終了ステータスを比べる
ls /etc/hosts
echo $?
ls /nonexistent
echo $?
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ ls /etc/hosts
/etc/hosts
student@ubuntu:~/linux-practice/ch13$ echo $?
0
student@ubuntu:~/linux-practice/ch13$ ls /nonexistent
ls: cannot access '/nonexistent': No such file or directory
student@ubuntu:~/linux-practice/ch13$ echo $?
2

成功したときは 0、失敗したときは0以外（ls では通常 2）になっています。$? は「直前の1回」しか保持しないので、確認するコマンドの直後に echo $? を打つ必要がある点に注意してください。

自分で書いたスクリプトも、終了ステータスを明示的に指定できます。exit 数値 と書くと、その時点でスクリプトを終了し、指定した数値を終了ステータスとして返します（exit を省略すると、最後に実行したコマンドの終了ステータスがそのまま使われます）。慣習として、正常終了は 0、異常終了は 1 を使うことが多いです。

エラーメッセージは、通常の echo の代わりに echo "メッセージ" >&2 のように書き、標準エラー出力（第8章の 2> で扱ったストリーム番号2）へ出すのがマナーです。2> は「2番の出力をファイルへ逃がす」リダイレクトでしたが、>&2 は逆に「この出力を2番（標準エラー出力）に送る」という指定です。こうしておくと、スクリプトの結果を ./script.sh > result.txt のようにファイルへリダイレクトしたときも、エラーメッセージだけは画面に表示され、見逃しにくくなります。

やってみよう 13-2: ファイル存在確認スクリプトを作る

図1のフローどおりに、引数の数をチェックし、指定したパスがファイルかディレクトリかを判定する check_file.sh を作りましょう。

手順

  1. 1 nano check_file.sh で下記の内容を入力して保存する。
  2. 2 chmod +x check_file.sh で実行権限を付与する。
  3. 3 ./check_file.sh hello.sh を実行し、ファイルと判定されることを確認する。
  4. 4 ./check_file.sh .（カレントディレクトリ）と ./check_file.sh nofile.txt（存在しないパス）も試し、echo $? で終了ステータスの違いを確認する。
  5. 5 引数を付けずに ./check_file.sh を実行し、使い方メッセージが表示されることを確認する。
check_file.sh 
#!/bin/bash
# check_file.sh: 指定したパスがファイルかディレクトリかを調べる
if [ $# -ne 1 ]; then
    echo "使い方: $0 パス" >&2
    exit 1
fi
target="$1"
if [ -f "$target" ]; then
    echo "${target} はファイルです。"
elif [ -d "$target" ]; then
    echo "${target} はディレクトリです。"
else
    echo "${target} は存在しません。" >&2
    exit 1
fi
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ chmod +x check_file.sh
student@ubuntu:~/linux-practice/ch13$ ./check_file.sh hello.sh
hello.sh はファイルです。
student@ubuntu:~/linux-practice/ch13$ ./check_file.sh .
. はディレクトリです。
student@ubuntu:~/linux-practice/ch13$ echo $?
0
student@ubuntu:~/linux-practice/ch13$ ./check_file.sh nofile.txt
nofile.txt は存在しません。
student@ubuntu:~/linux-practice/ch13$ echo $?
1
student@ubuntu:~/linux-practice/ch13$ ./check_file.sh
使い方: ./check_file.sh パス
student@ubuntu:~/linux-practice/ch13$ echo $?
1

使い方メッセージの $0 が、実際に打った ./check_file.sh という文字列そのものになっている点にも注目してください。

13.5 繰り返し処理（for・while）

同じ処理を何度も行いたいときは for 文・while 文を使います。for 文にはよく使う3つの書き方があります。まずは値を直接並べる形です。

ターミナル 
# リストを直接並べる
for i in 1 2 3; do
    echo "カウント: $i"
done
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ for i in 1 2 3; do echo "カウント: $i"; done
カウント: 1
カウント: 2
カウント: 3

出力例では、同じループを ; で区切って1行で入力した形で示しています（第1章の1行と同じ書き方）。複数行のまま貼り付けて実行しても結果は同じです。

2つ目は、第5章のワイルドカードと組み合わせて、条件に合うファイルを1つずつ処理する形です。

ターミナル 
# 練習用に.txtファイルを3つ用意する
touch note1.txt note2.txt note3.txt

# *.txt に一致するファイルを1つずつ処理する
for f in *.txt; do
    echo "テキストファイル: $f"
done
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ for f in *.txt; do echo "テキストファイル: $f"; done
テキストファイル: my report.txt
テキストファイル: note1.txt
テキストファイル: note2.txt
テキストファイル: note3.txt
テキストファイル: report.txt

13.2 で作った my report.txt と report.txt も *.txt に一致するので一緒に表示されます。"$f" とダブルクォートで囲んでいるので、スペースを含む名前も1つのファイルとして扱われています。

3つ目は、第5章のブレース展開 {開始..終了} で連番を作る形です。次の実習で使います。

ターミナル 
# ブレース展開で1〜5の連番を作って繰り返す
for i in {1..5}; do
    echo "report_${i}.txt"
done
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ for i in {1..5}; do echo "report_${i}.txt"; done
report_1.txt
report_2.txt
report_3.txt
report_4.txt
report_5.txt

while 文は「条件が真の間、繰り返す」形です。for のようにリストを使わないため、カウンタ用の変数を自分で用意し、ループの中で1ずつ増やします。i=$((i + 1)) の $((...)) は算術展開と呼ばれる書き方で、カッコの中を計算した結果に置き換えます。「i に1を足した値を、もう一度 i に代入する」という意味です。

ターミナル 
# i が5以下の間、繰り返す
i=1
while [ $i -le 5 ]; do
    echo "${i}回目"
    i=$((i + 1))
done
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ i=1; while [ $i -le 5 ]; do echo "${i}回目"; i=$((i + 1)); done
1回目
2回目
3回目
4回目
5回目

i=$((i + 1)) を書き忘れると…

カウンタを増やす行を忘れると i がずっと1のままになり、[ $i -le 5 ] が永遠に真のままになってしまいます（無限ループ）。止まらなくなったら Ctrl+C（第3章）で強制終了できます。

やってみよう 13-3: 連番ファイルを一括作成する

for と touch を組み合わせて、report_1.txt から report_5.txt までをまとめて作る make_files.sh を作りましょう。

手順

  1. 1 nano make_files.sh で下記の内容を入力して保存する。
  2. 2 chmod +x make_files.sh で実行権限を付与する。
  3. 3 ./make_files.sh を実行する。
  4. 4 ls report_*.txt で作成されたファイルを確認する。
make_files.sh 
#!/bin/bash
# make_files.sh: report_1.txt ~ report_5.txt を作成する

for i in {1..5}; do
    touch "report_${i}.txt"
    echo "作成しました: report_${i}.txt"
done

echo "合計 $(ls report_*.txt | wc -l) 件のファイルを作成しました。"
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ chmod +x make_files.sh
student@ubuntu:~/linux-practice/ch13$ ./make_files.sh
作成しました: report_1.txt
作成しました: report_2.txt
作成しました: report_3.txt
作成しました: report_4.txt
作成しました: report_5.txt
合計 5 件のファイルを作成しました。
student@ubuntu:~/linux-practice/ch13$ ls report_*.txt
report_1.txt  report_2.txt  report_3.txt  report_4.txt  report_5.txt

13.6 スクリプトを安全に書く

ここまでのスクリプトで使ってきた # から始まる行はコメントです。シェルは # 以降を無視するため、処理の意図や注意点を書き残すのに使います。行の途中から書くこともできます（例: i=$((i + 1)) # カウンタを1増やす）。

bash は既定では、途中のコマンドが失敗しても、それを無視して次の行に進んでしまいます。nano で次の risky.sh を作成して確認してみましょう。

risky.sh 
#!/bin/bash
# risky.sh: エラーが起きても止まらない例
echo "開始"
ls /nonexistent-file
echo "ここまで到達してしまう"
ターミナル 
# 実行権限を付けて risky.sh を実行する
chmod +x risky.sh
./risky.sh
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ chmod +x risky.sh
student@ubuntu:~/linux-practice/ch13$ ./risky.sh
開始
ls: cannot access '/nonexistent-file': No such file or directory
ここまで到達してしまう

ls がエラーになったのに、最後の echo まで実行されてしまいました。想定外の状態のまま処理が進むと、後工程で誤ったファイルを消したり上書きしたりする事故につながりかねません。この対策が、スクリプトの冒頭（シバンの次の行）に書く set -eu です。

オプション 効果
-e いずれかのコマンドが失敗（終了ステータスが0以外）した時点で、スクリプトを即座に中断する
-u 定義されていない変数を参照した時点でエラーにし、中断する（打ち間違いに気づきやすくなる）

risky.sh のシバン（1行目）とコメント行の次に set -eu を1行加えた safe.sh で、動きの違いを確認しましょう。

safe.sh 
#!/bin/bash
# safe.sh: set -eu でエラー時にすぐ止める
set -eu
echo "開始"
ls /nonexistent-file
echo "ここには到達しない"
ターミナル 
# safe.sh を実行し、終了ステータスも確認する
chmod +x safe.sh
./safe.sh
echo $?
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ chmod +x safe.sh
student@ubuntu:~/linux-practice/ch13$ ./safe.sh
開始
ls: cannot access '/nonexistent-file': No such file or directory
student@ubuntu:~/linux-practice/ch13$ echo $?
2

今度は ls のエラーでスクリプトが止まり、最後の echo は実行されませんでした。-u の効果も、既存のスクリプトを汚さないよう bash -c（新しいbashをその場で1回だけ起動する方法）で試してみましょう。

ターミナル 
# set -u を有効にした bash で、打ち間違えた変数を参照してみる
bash -c 'set -u; echo "${nmae}"'
出力結果（例） 
student@ubuntu:~/linux-practice/ch13$ bash -c 'set -u; echo "${nmae}"'
bash: line 1: nmae: unbound variable

line 1 は bash -c に渡した文字列の1行目という意味です。name を nmae と打ち間違えていても、set -u が無ければ空文字列として静かに処理が進んでしまい、誤りに気づきにくくなります。

重要ポイント

本ガイドでは、これから書くスクリプトの冒頭に #!/bin/bash の次の行として set -eu を書く習慣をおすすめします。第14章の log_report.sh・backup.sh では、この章で学んだ $# のチェック・>&2・exit 1・set -eu・$(date +%Y%m%d) のすべてを組み合わせます。

この章のまとめ

  • シェルスクリプトはコマンドを並べたテキストファイル。1行目にシバン（#!/bin/bash）を書き、chmod +x で実行権限を付け、./script.sh（または実行権限が無くても動く bash script.sh）で実行する。
  • 変数は name=値（= の前後にスペース無し）で代入し、"$name" のようにダブルクォートで参照する。引数は $1 $2…、個数は $#、read -p でその場の入力も受け取れる。
  • if [ 条件 ]; then ... fi で条件分岐する。[ ] の内側は前後にスペース必須。-f/-d でファイル判定、-eq 等で数値比較、= で文字列比較する。
  • for i in リスト; do ... done、while [ 条件 ]; do ... done で繰り返す。カウンタは i=$((i + 1))（算術展開）で増やす。
  • 終了ステータスは $? で確認でき、0 が成功。exit 1 で異常終了を明示し、エラーメッセージは >&2 で標準エラー出力へ。set -eu でエラーと未定義変数を早期に検知できる。

確認問題

  1. Q1. シェルスクリプトを作ってから実行するまでの3つのステップを説明してください。実行時に ./script.sh のように ./ を付ける理由も含めてください。

    回答を表示

    ① nano などで1行目にシバン（#!/bin/bash）から始まるファイルを作成する。② chmod +x ファイル名 で実行権限を付与する。③ ./script.sh のように実行する。./ が必要なのは、シェルが自動的にコマンドを探すPATH（第11章）に、通常カレントディレクトリが含まれていないため。./ を付けることで「今いる場所のこのファイル」だと明示的に指定する。

  2. Q2. 変数への代入で name = "Linux" と書くとエラーになります。正しい書き方と、エラーになる理由を説明してください。

    回答を表示

    正しくは name="Linux" のように = の前後にスペースを入れない。スペースを入れると、シェルは「name という名前のコマンドを、= と "Linux" という2つの引数付きで実行しようとする」と解釈するため、name: command not found のようなエラーになる。

  3. Q3. if [ $# -eq 0]; then のように ] の前のスペースを忘れると何が起きますか。また -f と -d の違いは何ですか。

    回答を表示

    [ は実際には test コマンドの別名で、最後の引数として独立した ] を必要とする。スペースを詰めて書くと 0] のように1つの単語になってしまい、構文エラー（missing `]' など）になる。-f は「通常のファイルとして存在するか」、-d は「ディレクトリとして存在するか」を判定する。

  4. Q4. スクリプトの冒頭に set -eu と書くと何が変わりますか。また、エラーメッセージを echo "..." >&2 のように書くのはなぜですか。

    回答を表示

    -e はコマンドが失敗（終了ステータスが0以外）した時点でスクリプトを即座に中断させ、-u は定義されていない変数を参照した時点でエラーにして中断させる設定。想定外の状態のまま処理が進んでしまう事故を防げる。>&2 は出力先を標準エラー出力（第8章の 2> で扱ったストリーム番号2）に切り替えるためで、通常の出力をファイルにリダイレクトしても、エラーメッセージだけは画面に表示されるようにできる。
