インターネットとURL・DNS

第1章では「クライアントがサーバーにリクエストを送る」という大まかな流れを見ました。しかし、そもそもクライアントはどうやって相手のサーバーを見つけているのでしょうか。この章では、通信相手を特定する仕組み（IPアドレス・DNS・URL・ポート）を掘り下げ、HTTP が通信の階層の中でどこに位置するのかを確認します。

この章で学ぶこと

  • IPアドレスとドメイン名の関係を説明できる
  • DNS がドメイン名をIPアドレスに変換する流れを説明できる
  • URLを構成要素（スキーム・ホスト・ポート・パス・クエリ・フラグメント）に分解できる
  • ポート番号の役割と、TCP/IPの階層の中でHTTPがどこに位置するかが分かる

2.1 IPアドレス

インターネットで通信する機器には、IPアドレスという数字の住所が割り当てられます（1台が Wi-Fi 用と有線用など複数のIPアドレスを持つこともあります）。手紙を送るときに「〇〇県〇〇市〇〇番地」という住所が必要なように、通信を届けるにも相手の住所が必要です。よく使われる形式（IPv4）は 93.184.215.14 のように、0〜255の数字を4つ、ピリオドで区切って書きます。

IPv4

32ビットの数字を4組で表記（例: 203.0.113.10）。表現できる住所の数に限りがあり、世界的に不足が進んでいます。

IPv6

128ビットで表記（例: 2001:db8::1）。IPv4の不足を解消するために作られた新しい形式で、対応が広がっています。

IPアドレスには、インターネット上で他者と重複しないグローバルIPアドレスと、家庭や社内のネットワーク内だけで使うプライベートIPアドレスがあります。プライベートIPアドレスは 192.168.x.x や 10.x.x.x のような範囲が予約されており、自宅ルーターの管理画面などでよく見かけます。家庭や社内のパソコン・スマホには多くの場合プライベートIPアドレスが割り当てられ、インターネットへ出るときは、ルーターなどが持つグローバルIPアドレスに変換して通信します（この変換を NAT と呼びます）。そのため、1つのグローバルIPアドレスを複数の機器で共有していることも珍しくありません。

用語: localhost（127.0.0.1 / ::1）

IPv4 の 127.0.0.1 と IPv6 の ::1 は、どちらも「自分自身」を指す特別なIPアドレス（ループバックアドレス）で、localhost という名前でも参照できます。環境によっては localhost が ::1 のほうに解決されることもあります。手元のパソコンでWebサーバーを動かして動作確認するときによく登場します。

2.2 ドメイン名とDNS

93.184.215.14 のような数字の並びは、人間には覚えにくく入力もしにくいものです。そこで使われるのが example.com のようなドメイン名です。ドメイン名とIPアドレスを対応付け、名前から住所を調べる仕組みが DNS（Domain Name System）で、電話帳にたとえられます。

DNSの問い合わせは、いきなり1か所に聞くのではなく、階層をたどって答えにたどり着きます。

sequenceDiagram participant B as ブラウザ participant R as キャッシュサーバー participant Root as ルートサーバー participant TLD as .com TLDサーバー participant Auth as example.com 権威サーバー B->>R: example.com のIPは？ R->>Root: .com はどこ？ Root-->>R: .com TLDサーバーの場所 R->>TLD: example.com はどこ？ TLD-->>R: 権威サーバーの場所 R->>Auth: example.com のIPは？ Auth-->>R: 93.184.215.14 です R-->>B: 93.184.215.14 です（結果をキャッシュ）

毎回この長い経路をたどっていては時間がかかるため、一度調べた結果は一定時間キャッシュ（一時保存）され、次回以降は速やかに答えが返ります。また、パソコンには hosts ファイルという設定ファイルがあり、ここにドメイン名とIPアドレスの対応を直接書いておくと、DNSより先にその内容が使われます（開発時に特定のドメインを手元のサーバーへ向けたいときなどに使われます）。

重要ポイント

DNSの名前解決は、HTTPの通信が始まる前に行われる下準備です。「ページが表示されない」というトラブルでは、DNSの問題（名前が引けない）なのか、HTTPの問題（サーバーがエラーを返す）なのかを切り分けて考えることが大切です。

2.3 URLの構造

普段何気なく入力している URL（Uniform Resource Locator）は、実はいくつかの部品の組み合わせでできています。次の例を見てみましょう。

URLの例 
https://api.example.com:443/v1/users?page=2#top
部品 値 意味
スキーム https 通信に使う約束事（プロトコル）の種類。http は暗号化なし、https は暗号化あり（第8章）。
ホスト api.example.com 通信相手のドメイン名（またはIPアドレス）。
ポート 443 サーバー内の「窓口番号」。省略時は既定値が使われる（2.4で解説）。
パス /v1/users サーバー内のどのリソース（資源）を指すか。
クエリ ?page=2 key=value 形式の追加情報。複数ある場合は & でつなぐ。
フラグメント #top ページ内の特定位置を示す。ブラウザ内だけで使われ、サーバーには送られない。

クエリやパスに日本語や記号を含めたい場合は、URLエンコードという変換が必要です。たとえば半角スペースは %20 に、日本語の文字も %E3%81%82 のような形に変換されます。ブラウザやプログラムのライブラリが自動でやってくれることがほとんどなので、「URLに使える文字は限られていて、はみ出す文字は %記号 に変換される」ということだけ覚えておけば十分です。

パスとクエリの使い分け

「どのリソースか」はパスで、「その中の絞り込みや並び替え」はクエリで表すのが一般的です。この考え方は第11〜13章のREST API設計でも重要になります。

2.4 ポート番号

1台のサーバーには、Webサーバー・メールサーバー・データベースなど、複数のプログラムが同時に動いていることがあります。ポート番号は、IPアドレスという「建物の住所」に加えて、「何号室（どのプログラム）宛てか」を示す番号です。マンションにたとえると、IPアドレスがマンションの住所、ポート番号が部屋番号にあたります。

ポート番号 主な用途
80 HTTP の既定ポート（http:// で省略時に使われる）
443 HTTPS の既定ポート（https:// で省略時に使われる）
3000 / 8080 開発中のWebアプリでよく使われる（決まりではなく慣習）

URLでポート番号が既定値（http なら80、https なら443）のときは省略できます。開発中に自分のパソコンで動かすアプリを見るとき、http://localhost:3000/ のようにポート番号付きのURLをよく目にするはずです。これは「localhost という宛先の、3000号室にあるアプリ」を指しています。

2.5 TCP/IPの4階層とHTTPの位置

ここまで見てきたIPアドレス・DNS・ポートは、実はそれぞれ役割の異なる「層」に分かれています。インターネットの通信は、次のような4つの階層が積み重なって成り立っており、これを TCP/IPの階層モデルと呼びます。

flowchart TD A["アプリケーション層
HTTP・DNS・SMTP など"] --> B["トランスポート層
TCP・UDP（ポート番号）"] B --> C["インターネット層
IP（IPアドレス）"] C --> D["ネットワークインターフェース層
Wi-Fi・Ethernet など"]

HTTPはいちばん上の「アプリケーション層」に位置します。ここまで学んだ IPアドレス（インターネット層）とポート番号（トランスポート層）は、いわばHTTPの通信を届けるための「土台」であり、HTTP自身はその土台の上で「何をしてほしいか」という中身のやり取りに専念しています。

トランスポート層には TCP と UDP という2つの方式があります。TCPは「送った順番どおりに、抜け漏れなく届ける」ことを保証する方式で、HTTPはこのTCPの信頼性を利用しています（HTTP/3ではUDPを土台にした新しい方式QUICが使われますが、詳細は第3章で概要のみ触れます）。UDPは信頼性より速さを優先する方式で、動画配信やオンラインゲームなどで使われます。

よくある勘違い

「HTTPとTCP/IPは別々の技術」と思われがちですが、正確にはHTTPはTCP/IPという土台の上で動く、より上位の約束事です。この章で学んだDNS・IPアドレス・ポートはすべて「相手を見つけて接続する」ための準備であり、次の第3章からは、その先にある「HTTPそのものの中身」を見ていきます。

やってみよう 2-1: nslookupでドメイン名からIPアドレスを調べる／URLを分解する

nslookup はWindows・macOSどちらにも標準で入っているコマンドで、DNSの名前解決を自分の手で試せます。

  2. 2 次のコマンドを入力して実行する。

理解度確認クイズ

  1. Q1. DNSはどのような役割を果たしていますか。

    回答を表示

    人間が読みやすいドメイン名（例: example.com）を、通信に必要な数字のIPアドレスに変換（名前解決）する仕組みです。電話帳のように名前から住所を調べます。

  2. Q2. URL https://api.example.com:443/v1/users?page=2#top のうち、「パス」と「クエリ」はそれぞれどの部分ですか。

    回答を表示

    パスは /v1/users（サーバー内のどのリソースかを示す部分）、クエリは page=2（? の後ろに続く追加情報）です。

  3. Q3. ポート番号はどのような目的で使われますか。80番と443番はそれぞれ何のための既定ポートですか。

    回答を表示

    1台のサーバー内で動く複数のプログラムのうち、どのプログラム宛ての通信かを区別するための番号です。80番はHTTPの既定ポート、443番はHTTPSの既定ポートです。

  4. Q4. TCP/IPの4階層のうち、HTTPはどの層に位置しますか。またIPアドレスとポート番号はそれぞれどの層に関係しますか。

    回答を表示

    HTTPはいちばん上の「アプリケーション層」に位置します。IPアドレスは「インターネット層」、ポート番号は「トランスポート層」（TCP）に関係し、どちらもHTTP通信を届けるための土台にあたります。
