JSONを読み書きする

前章では JSON の構文ルールを学びました。この章では、実際の API が返すような入れ子になった JSONを読み解き、目的の値までたどり着く練習をします。あわせて JavaScript の JSON.parse / JSON.stringify、よくあるエラーの読み方、注意しておきたい落とし穴、そして JSON Schema の入口までを扱います。

この章で学ぶこと

  • 入れ子になった JSON から、目的の値までの経路をたどれる
  • JSON.parse と JSON.stringify の使い分けが分かる
  • よくある JSON の構文エラーを読み、原因を特定できる
  • 数値・日付・文字コードにまつわる JSON の注意点を説明できる

10.1 入れ子のJSONを読む

前章の /users/1 をもう一度見てみましょう。オブジェクトの中にオブジェクトが入り、その中にさらにオブジェクトが入る——という入れ子（ネスト）の構造になっています。

GET https://jsonplaceholder.typicode.com/users/1 のレスポンス（一部） 
{
  "id": 1,
  "name": "Leanne Graham",
  "address": {
    "city": "Gwenborough",
    "geo": {
      "lat": "-37.3159",
      "lng": "81.1496"
    }
  }
}

「緯度（lat）を取り出したい」場合、いきなり lat にはたどり着けません。キーを1段ずつ下って、対象のオブジェクトの中に入っていく必要があります。

flowchart LR A["ルート
（users/1全体）"] -->|"address"| B["address
オブジェクト"] B -->|"geo"| C["geo
オブジェクト"] C -->|"lat"| D["'-37.3159'
（求める値）"]

この経路をそのまま言葉にすると「ルートの address の中の geo の中の lat」となります。JavaScript では、この JSON を変換したオブジェクトを入れた変数（次の節では user）から出発して、user.address.geo.lat というドット区切りで表します。次の節で実際にコードで取り出してみます。

配列が混ざる場合

たとえば /users/1/posts のように結果が配列で返る場合は、「何番目の要素か」という添字（インデックス）も経路に加わります。配列は 0 番目から数えるので、1件目は [0] です。

10.2 JavaScriptで扱う

サーバーから届く JSON は、通信の間はただの文字列です。JavaScript でその中の値を扱うには、いったん文字列を「オブジェクト」に変換する必要があります。これを行うのが JSON.parse です。

ブラウザの開発者ツールを開き、Console タブに次のコードを1行ずつ貼り付けて試してみましょう。

console：JSON.parse で文字列をオブジェクトに変換 
// サーバーから届いた「文字列」を想定
const text = '{"name":"Leanne Graham","address":{"geo":{"lat":"-37.3159"}}}';

// 文字列 → オブジェクトに変換する
const user = JSON.parse(text);

// ドット記法で1段ずつ下る
console.log(user.address.geo.lat); // "-37.3159"

キー名がハイフンを含む・変数で指定したいなど、ドット記法が使えない場合はブラケット記法（角括弧）を使います。配列の要素も同じ書き方で取り出せます。

console：ブラケット記法と配列の添字 
// ブラケット記法（ドット記法と結果は同じ）
console.log(user["address"]["geo"]["lat"]);

// キー名を変数で指定したいときはブラケット記法が必須
const key = "lat";
console.log(user.address.geo[key]);

// 配列は 0 番目から数える添字でアクセスする
const posts = [{ id: 1, title: "最初の投稿" }];
console.log(posts[0].title); // "最初の投稿"

逆に、オブジェクトを JSON 文字列に戻したいときは JSON.stringify を使います。第2引数と第3引数を指定すると、見やすく整形（インデント）して出力できます。

console：JSON.stringify でオブジェクトを文字列に戻す 
// オブジェクト → JSON文字列（そのままだと1行）
JSON.stringify(user.address);
// => '{"geo":{"lat":"-37.3159"}}'

// 第2引数 null・第3引数 2 でインデント2つ分の整形出力にする
console.log(JSON.stringify(user.address, null, 2));

重要ポイント

fetch で API を呼ぶ場合、実は response.json() というメソッドが内部で JSON.parse を行ってくれます。そのため自分で JSON.parse を書く場面は少ないですが、「文字列とオブジェクトは別物」という仕組みを理解しておくと、エラーの原因を見抜きやすくなります。fetch は第14章で扱います。

10.3 よくあるエラー

前章で学んだ「末尾カンマ禁止」「キーはダブルクォート必須」などのルールを破ると、JSON.parse は例外（エラー）を投げて処理を止めます。エラーメッセージの読み方を知っておきましょう。

console：末尾カンマがあるJSONを解析してみる 
// name の後ろに余計なカンマがある（前章のルール違反）
JSON.parse('{"name":"Leanne",}');
// Uncaught SyntaxError: Expected double-quoted property name
//   in JSON at position 17 (line 1 column 18)

SyntaxError は「文法の間違い」を意味するエラーの種類です。Expected double-quoted property name（ダブルクォートで囲んだキー名が来るはずだった）は、カンマの後ろに次のキーを期待していたのに } が来た、という意味です。このように、多くの場合はエラー位置の直前の文字（今回はカンマ）が原因です。なお、メッセージの文言はブラウザやそのバージョンによって異なります（下の表は Chrome・Edge の例）。

エラーメッセージの特徴 よくある原因
Expected double-quoted property name ／ Unexpected token ']' 直前に余計な末尾カンマがある（前者はオブジェクト、後者は配列の場合）
Expected property name or '}' キーがダブルクォートで囲まれていない（シングルクォート・無しなど）
Unexpected end of JSON input 閉じ括弧が足りない、文字列が途中で切れている
Unexpected token 'u' undefined のようなJSONに存在しない値が紛れ込んでいる

エラーメッセージだけで原因が分からないときは、専用の検証ツールが助けになります。JSONLint のようなサイトに JSON を貼り付けると、間違っている位置を教えてくれます。Visual Studio Code で .json ファイルを開いた場合も、間違った箇所に赤い波線が表示されます。

よくある勘違い

エラーメッセージに出てくる行番号・列番号は「エラーに気づいた位置」であって、必ずしも「間違えた位置そのもの」ではありません。特に末尾カンマの場合、実際の原因は表示位置の少し手前にあることが多いです。

10.4 注意点

JSON を扱ううえで、初心者がつまずきやすい細かな注意点を4つ押さえておきましょう。

数値の精度

JavaScript で JSON を解析すると、数値は JavaScript の数値型（浮動小数点）になります。非常に大きな整数（例: データベースの巨大なID）は、桁が丸められてしまうことがあります。そのようなIDは、あえて文字列として返す API 設計もよく見られます。

日付は文字列

前章のとおり JSON に日付型はありません。"2024-04-01T09:00:00Z" のような ISO 8601 形式の文字列として届くので、日付として計算したい場合はプログラム側で Date オブジェクトなどに変換します。

文字コードはUTF-8

JSON のテキストは基本的にUTF-8でやり取りされます。日本語がそのまま入っていても問題ありませんが、まれに \u3042 のようなエスケープ表現（「あ」の意味）で届くこともあります。

JSと「JSONもどき」の違い

JavaScript のオブジェクトリテラルは JSON に似ていますが別物です。キーにクォート無しを書ける・末尾カンマOK・undefined や関数を値にできる、といった点は JSON にはありません。「動くコード」と「正しいJSON」を混同しないようにしましょう。

言い換えると、JavaScript オブジェクトはプログラムの中でだけ通用する自由な形、JSON は言語をまたいでやり取りするための厳密な形です。 JSON.stringify は、この自由な形を厳密な形に変換するときに、undefined や関数を含むプロパティを黙って取り除く、という動きをします。

10.5 JSON Schemaの入口

API を使う側は「このAPIはどんな形のJSONを返すのか」「必ず入っている項目は何か」を事前に知りたいものです。それをJSON自体で約束事として定義する仕組みが JSON Schema です。

user-schema.json（ユーザーの形を約束する簡単な例） 
{
  "type": "object",
  "properties": {
    "id": { "type": "integer" },
    "name": { "type": "string" },
    "email": { "type": "string" }
  },
  "required": ["id", "name", "email"]
}

この定義は「id は整数、name と email は文字列で、この3つは必ず存在する」という約束を表しています。専用のツールを使うと、実際に届いたJSONがこの約束を守っているかを機械的にチェックできます。

今の段階では「JSON Schema という、JSONの形を約束するための別のJSONがある」ということだけ覚えておけば十分です。API を設計する側の視点は、第13章でもう一度扱います。

TypeScriptとの関係

TypeScript を使ったことがある人は、interface や type による型定義を思い浮かべたかもしれません。役割はよく似ていますが、JSON Schema は言語に依存せず、通信の相手（サーバー・クライアント）双方が同じ約束を参照できる点が特徴です。

やってみよう 10-1: コンソールでJSONから値を取り出そう

開発者ツールの Console で、10.2 と同じ要領で今度は自分で経路をたどってみましょう。

手順

  1. 1 ブラウザで https://jsonplaceholder.typicode.com/users/1 を開いて全体をコピーする（第9章の実習と同じ）。
  2. 2 開発者ツールの Console で const user = コピーした内容; のように貼り付けて変数に代入する（すでにオブジェクトの形なので JSON.parse は不要）。
  3. 3 次の3つの値をそれぞれ取り出すコードを書いて実行する：会社名（user.company.name）、住所の郵便番号（user.address.zipcode）、経度（user.address.geo.lng）。
  4. 4 最後に console.log(JSON.stringify(user.company, null, 2)); を実行し、整形された出力を確認する。

行き詰まったら、10.1 のツリー図のように「ルートから何を経由するか」を紙に書き出してみると経路が見えやすくなります。

理解度確認クイズ

  1. Q1. JSON文字列をJavaScriptのオブジェクトに変換するメソッドは何ですか。また、その逆を行うメソッドは何ですか。

    回答を表示

    文字列 → オブジェクトは JSON.parse、オブジェクト → 文字列は JSON.stringify です。

  2. Q2. オブジェクト user の address の中の city を、ドット記法とブラケット記法のそれぞれで書いてください。

    回答を表示

    ドット記法は user.address.city、ブラケット記法は user["address"]["city"] です。

  3. Q3. {"name":"Leanne",} をJSON.parseすると SyntaxError: Expected double-quoted property name になります（Chrome の場合）。原因は何ですか。

    回答を表示

    "Leanne" の後ろに、JSONでは許されない末尾カンマが付いているためです。JSONでは最後の値の後ろにカンマを付けられません。

  4. Q4. JSONに日付型が無いのに、APIのレスポンスにはどのように日付が表現されていますか。

    回答を表示

    "2024-04-01T09:00:00Z" のような ISO 8601 形式の文字列として表現されます。日付として扱いたい場合はプログラム側で変換します。

  5. Q5. JSON Schemaは何をするための仕組みですか。

    回答を表示

    JSONの「型」や「必須項目」といった形を、JSON自体で約束事として定義し、届いたデータがその約束を守っているかを機械的にチェックできるようにする仕組みです。
