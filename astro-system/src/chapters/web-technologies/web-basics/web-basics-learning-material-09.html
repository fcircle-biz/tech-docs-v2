JSONの基本

第1章の1.5で見たように、Web API のレスポンスの多くは JSON という形式で書かれています。この章では、JSON がどんな書き方のルールを持つ「データの表現方法」なのかを、実際のAPIの中身を見ながら学びます。ルールはシンプルですが、細かいところで間違えやすいので、落とし穴もあわせて確認しましょう。

この章で学ぶこと

  • JSON とは何か、なぜ Web API でよく使われるのかを説明できる
  • オブジェクトと配列を使って、データの形を読み書きできる
  • JSON で使える6種類の値を挙げられる
  • JSON の厳密な構文ルールを知り、よくある書き間違いに気づける
  • 同じデータを XML・CSV で表した場合との違いを説明できる

9.1 JSONとは

JSON（ジェイソン）は JavaScript Object Notation の略で、名前のとおり JavaScript のオブジェクトの書き方をもとに作られた、データを表現するための軽量な形式です。もともと JavaScript から生まれましたが、今では特定の言語に縛られない言語非依存のデータ形式として、Python・Java・PHP・Go など、ほとんどのプログラミング言語から読み書きできます。

第6章で学んだ Content-Type ヘッダーを思い出してください。JSON をボディに含むレスポンスやリクエストには、通常 Content-Type: application/json が付きます。これにより、受け取った側は「中身はテキストではなく JSON として解釈すればよい」と判断できます。

flowchart LR S["サーバー
（データを保持）"] -- "JSON文字列に変換" --> R["HTTPレスポンス
Content-Type: application/json"] R -- "受信して解析" --> C["クライアント
（プログラム内のデータへ）"]

JSON が広く使われる理由は、人が読んでも構造がつかみやすく、かつプログラムが機械的に解析しやすいという、両方のバランスが良いからです。同じ目的の形式には XML や CSV もありますが（9.5 で比較します）、現在の Web API では JSON が事実上の標準になっています。

9.2 オブジェクトと配列

JSON の中心となる部品は2つ、オブジェクトと配列です。オブジェクトは { } で囲み、「キー」と「値」の組を並べます。配列は [ ] で囲み、値を順番に並べます。

オブジェクトの例（1件のユーザー） 
{
  "id": 1,
  "name": "山田太郎",
  "email": "taro@example.com"
}

上の例では、キー "name" に対して値 "山田太郎" が対応しています。複数のキーと値の組は、カンマ , で区切ります。

配列の例（ユーザーの一覧） 
[
  { "id": 1, "name": "山田太郎" },
  { "id": 2, "name": "鈴木花子" }
]

オブジェクトの中に配列を入れたり、配列の中にオブジェクトを入れたりと、入れ子（ネスト）にすることもできます。この入れ子構造の読み方は、次の第10章でじっくり練習します。

オブジェクトのキーの順序

JSON の仕様上、オブジェクトのキーの並び順には意味がありません（順序が保証されません）。一方、配列の要素の順序には意味があり、並び替えるとデータの意味が変わってしまいます。「一覧」や「順位」を表したいときは配列を使いましょう。

9.3 値の6種類

JSON でキーに対応させられる「値」は、次の6種類だけです。逆に言えば、これ以外の値は JSON では直接表せません。

種類 書き方 例
文字列 必ずダブルクォートで囲む "東京"
数値 クォートなし、整数・小数・負数OK 28、-3.5
真偽値 小文字のみ true、false
null 「値が無い」ことを表す null
オブジェクト キーと値の組の集まり {"a": 1}
配列 値を順番に並べたもの [1, 2, 3]

JSON には「日付型」が無い

JSON にはプログラミング言語にあるような日付・時刻専用の型がありません。そのため日付は、"2026-09-23T10:00:00Z" のような ISO 8601 形式の文字列で表すのが一般的な慣習です。GitHub の API など多くの API が、この形式で日付を返します。

9.4 書き方のルールと落とし穴

JSON は見た目こそ JavaScript のオブジェクトによく似ていますが、構文はかなり厳密です。1文字でも規則から外れると、JSON 全体が読み込めなくなります（第10章でエラーの見つけ方を学びます）。ここでは特に間違えやすい5つのルールを押さえましょう。

  • キーは必ずダブルクォートで囲む（'name' のようなシングルクォートは不可）
  • 末尾のカンマは不可（最後の要素の後ろにカンマを付けるとエラーになる）
  • コメントは書けない（// や /* */ は使えない）
  • undefined は書けない（値が無いことは null で表す）
  • NaN・Infinity も書けない（数値は常に有効な数でなければならない）

誤り: 次の JSON には、上のルール違反が複数含まれています。

誤りの例 
{
  'name': "山田太郎",
  "age": undefined,
  "score": NaN,
  "tags": ["A", "B",],
}

2行目はキーがシングルクォート、3行目は undefined、4行目は NaN、5行目には配列の末尾カンマ（"B",）と、オブジェクトの最後の要素の後ろのカンマ（行末の ,）の2つが残っています。すべて JSON では無効です。

また、文字列の中でダブルクォートや改行そのものを表現したいときは、エスケープという書き方を使います。

エスケープの例 
{
  "comment": "彼は \"OK\" と言った",
  "memo": "1行目\n2行目"
}

\" は文字列中のダブルクォート、\n は改行を表します。バックスラッシュ \ 自体を書きたい場合は \\ と2つ重ねます。

9.5 XML・CSVとの比較

データをやり取りする形式は JSON だけではありません。同じ「ユーザー一覧」のデータを、JSON・XML・CSV の3形式で書き比べてみましょう。

JSON

users.json 
[
  { "id": 1, "name": "山田" },
  { "id": 2, "name": "鈴木" }
]

XML

users.xml 
<users>
  <user>
    <id>1</id>
    <name>山田</name>
  </user>
  <user>
    <id>2</id>
    <name>鈴木</name>
  </user>
</users>

CSV

users.csv 
id,name
1,山田
2,鈴木
観点 JSON XML CSV
入れ子構造 得意 得意 苦手（表形式のみ）
データ量（冗長さ） 少ない 多い（開始/終了タグ） とても少ない
人が読みやすいか 読みやすい やや読みにくい 表計算ソフトで読みやすい
主な用途 現在のWeb API全般 SOAP、設定ファイル、文書 表計算ソフトとの連携、集計データ

重要ポイント

どの形式にも向き不向きがありますが、入れ子構造を表現しやすく、かつ冗長になりすぎないという中間的なバランスの良さから、現在の Web API では JSON が最も広く使われています。次の第10章では、この JSON を実際にプログラムから読み書きする方法を学びます。

やってみよう 9-1: 本物のAPIのJSONを読んでみよう＋間違い探し

練習用API「JSONPlaceholder」が返す本物の JSON を眺めて、9.2〜9.3 で学んだオブジェクト・配列・値の種類を確認します。あわせて、自分で JSON の間違い探しにも挑戦しましょう。

手順

  1. 1 ブラウザで https://jsonplaceholder.typicode.com/users/1 を開く（書き込み系は保存されない練習用APIですが、この GET は実データを返します）。
  2. 2 表示された JSON の中から、文字列・数値・オブジェクト・配列を1つずつ指さして確認する（address はオブジェクト、geo はさらにその中のオブジェクトです）。
  3. 3 9.4 の「誤りの例」を見直し、4種類・5か所の違反（シングルクォート・undefined・NaN・末尾カンマ2か所）をすべて挙げられるか確認する。
  4. 4 正しい JSON に書き直してみる（紙やメモ帳で構いません）。

実在するAPIのJSONは、思ったより長く入れ子も深いことに気づくはずです。全体を一度に理解しようとせず、「これはオブジェクトか配列か」「このキーの値は何種類目か」と1つずつたどるのがコツです。

理解度確認クイズ

  1. Q1. JSON とは何の略で、どのような特徴を持つデータ形式ですか。

    回答を表示

    JavaScript Object Notation の略で、JavaScript のオブジェクトの書き方をもとにした、言語非依存の軽量なデータ表現形式です。多くのプログラミング言語から読み書きできます。

  2. Q2. JSON で使える6種類の値をすべて挙げてください。

    回答を表示

    文字列・数値・真偽値・null・オブジェクト・配列の6種類です。

  3. Q3. 次のうち、JSON の構文として誤っているものをすべて指摘してください。
    ①キーをシングルクォートで囲む　②配列の最後の要素の後ろにカンマを付ける　③値に null を使う

    回答を表示

    ①と②が誤りです。キーは必ずダブルクォートで囲む必要があり、末尾のカンマも許されません。③の null は正しい書き方です。

  4. Q4. JSON には日付専用の型がありません。日付はどのように表すのが一般的ですか。

    回答を表示

    "2026-09-23T10:00:00Z" のような ISO 8601 形式の文字列として表すのが一般的な慣習です。

  5. Q5. JSON・XML・CSV を比較したとき、JSON が現在のWeb APIで最も広く使われている理由は何ですか。

    回答を表示

    CSV と違って入れ子構造を表現でき、XML ほど開始・終了タグで冗長にならないという、表現力とデータ量のバランスの良さが理由です。
