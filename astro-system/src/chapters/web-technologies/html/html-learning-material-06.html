リンク

「ハイパーテキスト」の名の由来でもあるリンクは、ページとページをつなぎ、Webを「一枚の巨大な網」にする最も重要な仕組みです。この章では <a> タグの基本から、パスの指定方法、ページ内ジャンプ、別タブでの表示、メール・電話リンク、そしてアクセシビリティに配慮したリンクの書き方まで、実務でも通用する知識を身につけます。

この章で学ぶこと

  • <a href="..."> を使ってリンクを作成できる
  • 絶対パスと相対パス（./・../・ルート相対）の違いを説明できる
  • id 属性を使った同一ページ内リンクを作成できる
  • target="_blank" と rel="noopener" を安全に併記できる
  • メールリンク（mailto:）・電話リンク（tel:）を作成できる
  • 「こちら」を避けるなど、アクセシビリティに配慮したリンクテキストを書ける

6.1 アンカータグ（<a>）の基本

リンクを作るタグは <a>（アンカー）です。「anchor（錨・いかり）」という名前のとおり、文書のどこかに錨を下ろすように、飛び先を指定します。基本の書き方は次の1行だけです。

link.html 
<a href="https://www.example.com/">サンプルサイト</a>

構造はシンプルです。href 属性（hypertext reference の略）に飛び先の URL やファイルパスを指定し、開始タグと終了タグの間の文字がリンクテキスト（クリックできる部分）になります。

href 属性

リンクとして機能させるために事実上必ず指定する属性。URLでも、同じサイト内のファイルパスでも指定できます。

リンクテキスト

開始タグと終了タグに挟まれた部分。クリックできる範囲であり、内容も画面に表示されます。

画像もリンクにできる

<a> は文字だけでなく <img> なども囲めます（<a> で <img> を囲めば画像リンクになります）。

外部サイトへは https:// を忘れずに

外部サイトへのリンクは https://（または http://）から書き始めます。これを省略して href="www.example.com" のように書くと、ブラウザは「自分のサイト内にある www.example.com というファイル」だと誤解してしまいます。

6.2 絶対パスと相対パスの違い

自分のサイト内の別ページへリンクする場合、パス（飛び先の場所）の書き方には絶対パスと相対パスの2種類があります。この違いを理解しておくと、フォルダ構成が変わってもリンクが壊れにくいページを作れるようになります。

種類 書き方 意味
絶対パス https://example.com/about.html サーバーやドメインを含む、世界に1つだけの完全な住所
相対パス（同じ階層） ./about.html または about.html 今いるファイルと同じフォルダにあるファイル
相対パス（下の階層） images/photo.jpg 今いるフォルダの中の、さらに下のフォルダにあるファイル
相対パス（上の階層） ../index.html 今いるフォルダの1つ上のフォルダにあるファイル
ルート相対パス /about.html サイトの一番上（ルート）のフォルダを起点にした場所

ルート相対パスは Web サーバー上でのみ正しく動きます。ファイルをダブルクリックして開いた状態（file://）では使えないため、学習中は相対パスを使いましょう。

ポイントは「今いるファイルからの位置関係」で考えることです。次の図のようなフォルダ構成を例に、profile.html から他のファイルへどうパスを書くか見てみましょう。 

プロジェクトフォルダ/
├── index.html            → "index.html"（同じ階層）
├── profile.html         ← このファイルから見た相対パス
├── images/
│   └── icon.png          → "images/icon.png"
└── pages/
    └── contact.html       → "pages/contact.html"
flowchart TD Root["プロジェクトフォルダ"] --> Index["index.html"] Root --> Profile["profile.html（今このファイルにいる）"] Root --> ImagesDir["imagesフォルダ"] Root --> PagesDir["pagesフォルダ"] ImagesDir --> Icon["icon.png"] PagesDir --> Contact["contact.html"] Profile -.->|"index.html（同じ階層）"| Index Profile -.->|"images/icon.png（下の階層へ）"| Icon Profile -.->|"pages/contact.html（下の階層へ）"| Contact

逆に pages/contact.html から profile.html に戻りたい場合は、1つ上のフォルダへ移動する ../ を使い、../profile.html と書きます。../ は「1つ上へ」、../../ なら「2つ上へ」を意味します。

重要ポイント: 使い分けの基本方針

同じサイト内のページ同士をつなぐときは相対パスを使うのが基本です。フォルダごとサーバーの引っ越しをしても、ファイル同士の位置関係さえ変わらなければリンクが壊れません。一方、他人のサイトへのリンクは必ず絶対パス（https://...）で書きます。

6.3 同一ページ内リンク（id 属性とページ内ジャンプ）

長いページでは、「目次をクリックすると該当の見出しまで一気にジャンプする」機能をよく見かけます。これは同一ページ内リンクと呼ばれ、飛び先の要素に id 属性を付け、リンク側の href にその #id名 を指定することで実現します。

toc.html 
<!-- 目次側：#の後にid名を書く -->
<nav>
  <a href="#profile">自己紹介</a>
  <a href="#hobby">趣味</a>
</nav>

<!-- 飛び先側：見出しなどにidを付ける -->
<h2 id="profile">自己紹介</h2>
<p>...</p>

<h2 id="hobby">趣味</h2>
<p>...</p>

リンク側では # を先頭に付けますが、id 属性の値そのものには # を付けない点に注意してください。ページの一番上に戻る「トップへ戻る」ボタンも、同じ仕組みで作れます。

back-to-top.html 
<body id="top">
  ...
  <a href="#top">トップへ戻る</a>
</body>

id はページ内で重複禁止

id 属性の値は、1つのページの中で唯一でなければなりません（同じ id を持つ要素が2つあってはいけません）。何度も繰り返し使いたい印には、第10章で学ぶ class 属性を使います。

6.4 別タブで開くリンク（target="_blank"）

外部サイトへのリンクをクリックしたときに、元のページを残したまま新しいタブで開かせたい場合は、target="_blank" 属性を追加します。

external-link.html 
<a href="https://www.example.com/" target="_blank" rel="noopener">
  外部サイト（別タブで開く）
</a>

ここで欠かせないのが rel="noopener" の併記です。かつては target="_blank" だけを指定すると、新しく開いたタブ（リンク先のページ）が JavaScript を通じて元のタブの内容を操作できてしまうという、セキュリティ上の弱点がありました。現在の主要ブラウザは target="_blank" に自動で同等の保護をかけますが、古い環境への対応と意図の明示のため、rel="noopener" を書くのが安全です。

target="_blank" は必ず rel="noopener" とセットで

target="_blank" を書くときは、常に rel="noopener" を一緒に書く習慣を付けましょう。参照元情報（どのページから来たか）をリンク先に伝えたくない場合は rel="noopener noreferrer" のように空白区切りで複数指定します。なお、多用は禁物です。ユーザーが望んでいないのにタブがどんどん増えると、かえって使いにくいページになります。

6.5 メール・電話リンク（mailto: と tel:）

href にはWebページ以外の飛び先も指定できます。代表例が、クリックするとメールソフトが起動する mailto: と、スマートフォンで電話アプリが起動する tel: です。

contact.html 
<!-- メールリンク：メールソフトが起動し、宛先が自動入力される -->
<a href="mailto:info@example.com">メールを送る</a>

<!-- 電話リンク：スマホでは電話アプリが起動する -->
<a href="tel:0312345678">03-1234-5678 に電話する</a>

mailto: は ?subject=件名&amp;body=本文 を続けることで、件名や本文をあらかじめ入力した状態にすることもできます。属性値の中でパラメータをつなぐ & は &amp; と書きます（日本語やスペースはエンコードが必要な場合があります）。tel: の番号にはハイフンを入れても問題ありませんが、ハイフンなしの数字だけで書くのが最もトラブルが少ない書き方です。国際的に確実に動かすなら tel:+81312345678 のように国番号付きで書きます。

PC で tel: リンクを踏むとどうなる？

スマートフォンでは電話アプリが起動しますが、電話機能のないPCでは何も起きないか、連携している通話アプリが起動する程度です。それでも、モバイル利用者が多いサイトでは tel: リンクを用意しておくと親切です。

6.6 良いリンクテキストと、リンク切れを防ぐ考え方

リンクは「見た目」だけでなく「アクセシビリティ（誰にとっての使いやすさ）」にも直結します。特に、視覚に障害のある方が使うスクリーンリーダー（画面の内容を音声で読み上げるソフト）は、リンクだけを一覧にして読み上げる機能を持っています。そのとき、リンクテキストが「こちら」ばかりだと、どこへ飛ぶリンクなのか判別できません。

リンク先の内容がリンクテキストだけでは分からない。一覧表示すると「こちら」「こちら」「こちら」…と並んでしまう。

望ましい書き方

送料についてのご案内ページをご覧ください。

リンクテキストだけで飛び先の内容が推測できる。スクリーンリーダーの利用者にも親切。

もう1つ大切なのがリンク切れ（リンク先が見つからないエラー）を防ぐ考え方です。よくある原因は、ファイル名の変更・移動や、相対パスの書き間違いです。次の点を意識すると、リンク切れを大きく減らせます。

  • ファイル名・フォルダ名は半角英数字とハイフンで統一し、後から変更しない
  • 大文字・小文字の違いに注意する（サーバーによっては区別される）
  • フォルダを移動したら、そこにリンクしている全ページのパスも見直す
  • 公開前に、すべてのリンクをクリックして確認する習慣を付ける

重要ポイント

良いリンクテキストは「クリックする前に、どこへ飛ぶか分かる文章」です。「こちら」「ここ」「詳細」のような単独では意味を持たない言葉ではなく、飛び先の内容が伝わる言葉を選びましょう。

やってみよう 6-1: リンク集ページを作ろう

これまで学んだ複数種類のリンクを1つのページにまとめて、動作を確認してみましょう。

手順

  1. 1 links.html という名前のファイルを新規作成する。
  2. 2 ページ上部に目次（<h2 id="..."> への同一ページ内リンク）を3つ作る。
  3. 3 外部サイトへのリンクを1つ、target="_blank" と rel="noopener" を付けて作る。
  4. 4 自分宛の mailto: リンクと tel: リンクを1つずつ作る。
  5. 5 ページ最下部に「トップへ戻る」リンクを付け、クリックで先頭に戻ることを確認する。

すべてのリンクテキストを「こちら」にせず、飛び先が分かる言葉にできているか、書き終えたら見直してみましょう。

理解度確認クイズ

  1. Q1. ../ はパス指定において何を意味しますか？

    回答を表示

    今いるファイルから見て「1つ上のフォルダへ移動する」という意味です。2つ上のフォルダへ移動したい場合は ../../ のように重ねて書きます。

  2. Q2. 同一ページ内リンクを作るには、飛び先の要素と href にそれぞれ何を指定しますか？

    回答を表示

    飛び先の要素には id 属性で一意の名前を付けます。リンク側の href には、その id 名の先頭に # を付けた値（例: href="#profile"）を指定します。

  3. Q3. target="_blank" と一緒に書くべき属性は何で、それはなぜ必要ですか？

    回答を表示

    rel="noopener" です。かつては target="_blank" だけでは、新しく開いたリンク先のページが JavaScript を通じて元のタブを操作できてしまうというセキュリティ上の弱点がありました。現在の主要ブラウザは自動で同等の保護をかけますが、古い環境への対応と意図の明示のため rel="noopener" を書くのが安全です。

  4. Q4. リンクテキストに「こちら」ばかり使うと、なぜアクセシビリティ上望ましくないのですか？

    回答を表示

    スクリーンリーダーはリンクだけを一覧にして読み上げる機能を持っており、その際「こちら」ばかりだと飛び先の内容が判別できないためです。リンクテキストだけで飛び先の内容が分かる文章にすることが望ましいとされています。
