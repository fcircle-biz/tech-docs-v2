ホーム HTML 第8章
第8章 所要時間: 約35分

表（テーブル）

料金表・スペック表・時刻表など、行と列で整理されたデータを表現するのが表（テーブル）です。この章では <table> の基本構造から、見出しセルとデータセルの違い、セルの結合、そして「表はデータのために使い、レイアウトには使わない」という現在の原則まで、順を追って学びます。

この章で学ぶこと

  • <table>・<tr>・<th>・<td> で表の基本構造を組み立てられる
  • <thead>・<tbody>・<tfoot> で表をグループ化し、<caption> で表題を付けられる
  • colspan・rowspan でセルを結合できる
  • 表をレイアウトに使わない理由と、scope 属性によるアクセシビリティ配慮を説明できる

8.1 表の基本構造 — table・tr・th・td

料金プラン、商品一覧、時刻表、スペック比較 — 世の中には「行と列」で整理すると分かりやすい情報がたくさんあります。HTML ではこうした表形式のデータを、専用のタグを組み合わせて表現します。使うタグは主に4種類です。

<table> — 表全体

表全体を囲む要素。この中に見出しや行をすべて入れます。

<tr> — 行（table row）

表の「1行分」を表します。この中に <th> や <td> を横に並べます。

<th> — 見出しセル（table header）

その行・列の「見出し」を表すセル。既定で太字・中央寄せで表示されます。

<td> — データセル（table data）

実際の値を入れる普通のセル。既定で通常の太さ・左寄せで表示されます。

つまり table > tr > th／td という入れ子構造が基本です。実際に、コーヒーと紅茶の価格表を書いてみましょう。

書いた HTML

menu.html 
<!-- 商品と価格の一覧表 -->
<table>
  <tr>
    <th>商品名</th>
    <th>価格</th>
  </tr>
  <tr>
    <td>コーヒー</td>
    <td>450円</td>
  </tr>
  <tr>
    <td>紅茶</td>
    <td>400円</td>
  </tr>
</table>

ブラウザでの表示イメージ

商品名 価格
コーヒー 450円
紅茶 400円

素の <table> には枠線が付かず、<th> は中央寄せで表示されます。ここでは見やすさのため枠線と背景を付けています（見た目の付け方は第11章の CSS で学びます）。

用語: tr・th・td の由来

tr は table row（表の行）、th は table header（表の見出し）、td は table data（表のデータ）の略です。名前の意味を知っておくと、どのタグを使うべきか迷ったときに思い出しやすくなります。

8.2 見出しセルとデータセルの違い、行と列の対応

<th> と <td> は見た目（太字か普通か）だけの違いではありません。<th> は「この列（または行）はこういうデータですよ」という見出しであることを意味的に宣言するタグです。スクリーンリーダー（画面を読み上げる支援技術）はこの違いを利用し、あるデータセルを読み上げるときに「対応する見出しは○○です」とあわせて伝えてくれます。

表の見出しには2つの向きがあります。列見出し（表の一番上の行で、各列が何のデータかを示す）と、行見出し（表の一番左の列で、各行が何のデータかを示す）です。両方を使うと、どのセルがどの行・どの列に属するデータなのかが一目で分かります。

＼ 月曜 火曜
午前 数学 英語
午後 理科 体育

上の表では、灰色の背景（thead の行）が列見出し（月曜・火曜）、薄い primary 色の行の左端（午前・午後）が行見出しです。「理科」というデータセルは、行方向に見ると「午後」、列方向に見ると「火曜」の見出しと対応しています。この行と列の交差点にデータが置かれるという考え方が、表を組み立てるときの基本です。

重要ポイント

<th> は「太字で目立たせるためのタグ」ではなく、「このセルは見出しであるという意味の宣言」です。結果として太字・中央寄せで表示されるだけ、という順番で理解しておきましょう。第4章で学んだ <strong> と同じ考え方です。

8.3 thead・tbody・tfoot によるグループ化

行数が多い表になると、「見出しの行」「データ本体の行」「合計などのまとめの行」を区別したくなります。HTML には、そのための3つのグループ化タグが用意されています。

  • <thead> — 表の見出し行をまとめる（table head）
  • <tbody> — 本体のデータ行をまとめる（table body）
  • <tfoot> — 合計・注記などの締めの行をまとめる（table foot）

いずれも省略可能ですが、行数の多い表では入れておくと構造が明確になり、長い表を印刷したときに各ページの先頭へ見出し行を自動で繰り返す、といったブラウザの機能も働きやすくなります。書く順番は <thead> → <tbody> → <tfoot> です（古い解説では <tfoot> を先に書く例がありますが、現在の仕様では末尾に置きます）。<tbody> を省略しても、ブラウザは内部的に補って解釈します。開発者ツールで確認すると、書いていないはずの <tbody> が表示されることがありますが、これが理由です。

書いた HTML

order.html 
<!-- 見出し・本体・合計行を分けて構成 -->
<table>
  <thead>
    <tr><th>商品</th><th>数量</th><th>金額</th></tr>
  </thead>
  <tbody>
    <tr><td>ノート</td><td>2</td><td>300円</td></tr>
    <tr><td>消しゴム</td><td>1</td><td>100円</td></tr>
  </tbody>
  <tfoot>
    <tr><th>合計</th><td>3</td><td>400円</td></tr>
  </tfoot>
</table>

ブラウザでの表示イメージ

商品 数量 金額
ノート 2 300円
消しゴム 1 100円
合計 3 400円

8.4 caption で表にタイトルをつける

表が何を表しているのかを明示したいときは、<caption> タグを使います。<table> の直後（最初の子要素）に書くのがルールで、既定では表の上部中央にタイトルとして表示されます。

見た目の効果だけでなく、スクリーンリーダーは表に出会うと caption の内容を真っ先に読み上げます。「これから読み上げるのは何の表なのか」を利用者に伝える、アクセシビリティ上とても重要なタグです。

書いた HTML

plan.html 
<table>
  <caption>2024年度 料金プラン一覧</caption>
  <thead>
    <tr><th>プラン</th><th>月額</th></tr>
  </thead>
  <tbody>
    <tr><td>ライト</td><td>500円</td></tr>
    <tr><td>スタンダード</td><td>1200円</td></tr>
  </tbody>
</table>

ブラウザでの表示イメージ

2024年度 料金プラン一覧
プラン 月額
ライト 500円
スタンダード 1200円

8.5 セルを結合する — colspan・rowspan

「この行だけ2列分をまとめて表示したい」「このセルを2行分の高さで表示したい」ということがあります。そんなときは <th> や <td> に属性を追加して、セルを結合します。

  • colspan="2" — 横方向（列）に2列分結合する（column span）
  • rowspan="2" — 縦方向（行）に2行分結合する（row span）

書いた HTML

timetable.html 
<!-- rowspanで縦結合、colspanで横結合 -->
<table>
  <tr><th></th><th>月曜</th><th>火曜</th></tr>
  <tr>
    <th>1限</th>
    <td rowspan="2">体育（合同）</td>
    <td>数学</td>
  </tr>
  <tr><th>2限</th><td>英語</td></tr>
  <tr><th>3限</th><td colspan="2">昼休み</td></tr>
</table>

ブラウザでの表示イメージ

月曜 火曜
1限 体育（合同） 数学
2限 英語
3限 昼休み

よくあるミス: 列数が合わなくなる

セルを結合すると、その行に書く <th>／<td> の個数が他の行より減ります。上の例では2行目が「1限・体育（合同）・数学」の3セル、3行目は結合セルを引き継ぐため「2限・英語」の2セルしか書きません。列の合計数（今回は3列）を意識しながら組み立てると、表が崩れにくくなります。

8.6 表の使い方の原則 — レイアウトには使わない・scope属性

CSS がまだ発展途上だった1990年代〜2000年代前半、Web制作者たちは<table> を使ってページ全体を「見えない格子」で区切り、ヘッダー・サイドバー・本文をマス目に配置するという方法（テーブルレイアウト）を多用していました。しかし、CSS の Flexbox や Grid（本ガイドの範囲外・第12章「次のステップ」で紹介）が普及した現在は、この方法は推奨されていません。

用途 使うべきもの 理由
表形式のデータを示す <table> 本来の意味どおりの使い方
ページ全体の配置を組む CSS（Flexbox・Grid） 意味と見た目を分離できる・レスポンシブにしやすい

レイアウト目的で表を使うと、意味的には「表ではない」ものに<table>というラベルが付いてしまい、スクリーンリーダーの利用者が「表が始まりました」と誤って案内されたり、スマートフォンなど画面の狭い端末でレイアウトが崩れやすくなったりします。表はあくまで「行と列を持つデータ」を表現するためのタグと覚えておきましょう。

本来の用途で表を使う場合も、アクセシビリティをもう一歩高める方法があります。それが scope 属性です。見出しセル（<th>）に付けることで、「この見出しは列の見出しなのか、行の見出しなのか」をスクリーンリーダーに明示できます。次の例では、8.1 で <td> だった「商品名」のセルを、行見出しとして <th scope="row"> に変えています。

accessible-table.html 
<!-- scope属性でヘッダーとデータの対応を明示 -->
<table>
  <tr>
    <th scope="col">商品</th>
    <th scope="col">価格</th>
  </tr>
  <tr>
    <th scope="row">コーヒー</th>
    <td>450円</td>
  </tr>
</table>
  • scope="col" — この見出しは同じ列のデータセルの見出しである
  • scope="row" — この見出しは同じ行のデータセルの見出しである

豆知識: シンプルな表なら scope はなくても伝わる

列見出しの行が1つだけの単純な表であれば、ブラウザや多くのスクリーンリーダーは scope がなくても構造を推測してくれます。ただし、8.2 で見たような「行見出しと列見出しの両方がある表」では、scope を付けることで対応関係が確実に伝わります。迷ったら付けておくと安全です。

やってみよう 8-1: 商品価格表を作ってみよう

この章で学んだタグをすべて使い、自分だけの価格表ページを作ってみましょう。第2章で作った学習用フォルダに table.html という名前で保存してください。

手順

  1. 1 <table> の直後に <caption> を書き、「〇〇カフェ メニュー」のような表題を付ける。
  2. 2 <thead> に「商品名」「価格」の見出し行を scope="col" 付きの <th> で作る。
  3. 3 <tbody> に商品を3〜4行、<td> で追加する。
  4. 4 <tfoot> に合計行（<th>合計</th><td>◯◯円</td>）を追加し、さらにもう1行、<td colspan="2">送料は別途</td> だけの注記行を作って2列分を1セルにまとめてみる。
  5. 5 保存してブラウザで開き、見出し行が太字・中央寄せになっていること、キャプションが表の上に表示されていることを確認する。

うまく崩れる場合は、タグの閉じ忘れ（</td> や </tr>）がないか、各行のセル数が結合の分だけ正しく合っているかを確認しましょう。

理解度確認クイズ

  1. Q1. <table>・<tr>・<th>・<td> はそれぞれ何を表すタグですか。

    回答を表示

    <table> は表全体、<tr> は表の1行（table row）、<th> は見出しセル（table header・太字中央寄せ）、<td> はデータセル（table data・通常表示）です。

  2. Q2. <thead>・<tbody>・<tfoot> はそれぞれどんな行をまとめるためのタグですか。

    回答を表示

    <thead> は見出し行、<tbody> は本体のデータ行、<tfoot> は合計や注記などの締めの行をまとめます。構造が明確になり、長い表の扱いやすさが向上します。

  3. Q3. colspan と rowspan の違いを説明してください。

    回答を表示

    colspan はセルを横方向（列）に結合し、rowspan はセルを縦方向（行）に結合します。結合したセルの分だけ、その行に書く <th>／<td> の個数が減ることに注意が必要です。

  4. Q4. 表をページ全体のレイアウトに使うことが推奨されないのはなぜですか。また scope 属性は何のためにありますか。

    回答を表示

    表形式ではないものに <table> を使うと、スクリーンリーダー利用者を誤って案内したり、スマートフォンなどでレイアウトが崩れやすくなったりするためです。現在はCSSの Flexbox・Grid でレイアウトを組みます。scope="col"／scope="row" は、見出しセルが列と行のどちらに対応するかを明示し、読み上げの正確さを高めるための属性です。
