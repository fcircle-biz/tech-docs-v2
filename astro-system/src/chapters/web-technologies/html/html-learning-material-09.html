ホーム HTML 第9章
第9章 所要時間: 約40分

フォーム

ここまでは「情報を見せる」HTMLを学んできましたが、Webサイトにはユーザーから情報を受け取るページもたくさんあります。お問い合わせ・会員登録・検索窓 — これらの入口になるのがフォームです。この章では <form> の仕組みと、代表的な入力部品、<label> による結び付け、そして入力補助のための属性を学び、問い合わせフォームを組み立てられるようになります。

この章で学ぶこと

  • フォームの「入力 → 送信 → サーバー処理」という流れを説明できる
  • action・method（GET と POST）の違いを理解し使い分けられる
  • text・password・email・number・date・radio・checkbox など主要な入力部品を使い分けられる
  • label と for/id の結び付け、name 属性の役割を説明できる
  • placeholder・required・maxlength で入力補助と簡易バリデーションができる

9.1 フォームの仕組み（入力 → 送信 → サーバー処理）

フォームとは、ユーザーが文字を入力したり選択肢を選んだりできる部品をひとまとめにし、その内容をWebサーバーへ送るための仕組みです。お問い合わせページの「お名前」「メールアドレス」「お問い合わせ内容」の欄を思い浮かべてください。あれらすべてがフォームの部品です。

フォーム全体は <form> というタグで囲みます。この中に、これから学ぶ入力部品（<input> など）を配置し、最後に「送信」ボタンを置くのが基本形です。ユーザーが送信ボタンを押すと、フォーム内のすべての入力内容がまとめてサーバーへ送られます。

flowchart TD A["ユーザーが入力欄に
文字を入力・選択する"] --> B["送信ボタンをクリックする"] B --> C["ブラウザが入力内容を
まとめて送信データを作る"] C --> D["Webサーバーに送信データが届く"] D --> E["サーバー側のプログラムが
データを処理する（保存・返信など）"] E --> F["結果のページが
ブラウザに返される"]

ここで大切なのは役割分担です。HTMLの仕事は「入力欄と送信ボタンを画面に用意すること」までです。送られてきたデータをどう処理するか（メールを送る・データベースに保存するなど）は、サーバー側のプログラム（PHP・Python・Node.js など）の仕事になります。この教材では HTML の範囲、つまり「入力欄を正しく作る」ところまでを学びます。

このページの入力欄は「見た目の確認用」です

この章ではサーバーを用意していないため、実際に送信できるフォームは設置していません。以降に出てくる入力欄のイメージは見た目を再現した表示です。コードは実際に動作するものなので、第2章で作った自分の環境にそのままコピーして試してみましょう。

9.2 form の action・method（GET と POST の違い）

<form> タグには、送信先やデータの送り方を指定する2つの重要な属性があります。

form.html 
<form action="/contact" method="post">
  <!-- ここに入力部品を配置する -->
</form>
  • action — 入力内容をどこに送るか（送信先のURL）を指定する
  • method — 入力内容をどうやって送るか（送信方法）を指定する。値は主に get か post

GET と POST は、データの送り方が根本的に異なります。それぞれの特徴を比較してみましょう。

項目 GET POST
データの送り方 URLの末尾に付け足す（クエリ文字列） 本文（リクエストボディ）に載せて送る（URLには現れない）
主な用途 検索・絞り込みなど「情報を取得する」場面 お問い合わせ・会員登録など「情報を送信・変更する」場面
URLへの表示 入力内容がURLに残るためブックマーク可能 入力内容はURLに表示されない
機微な情報 パスワードなどには不向き（URLに残るため） 比較的向いている（それでも通信の暗号化＝HTTPSは必須）

迷ったときの目安はシンプルです。「検索窓のように結果を見るだけ」なら GET、「お問い合わせや登録のようにサーバー側の状態を変える」なら POST を選びます。

よくある勘違い

GET と POST は「どちらが安全か」という単純な優劣の話ではありません。GETは入力内容がURLに残るため、パスワードのような情報を扱うのに不向きというだけで、検索フォームなどではむしろ GET が適切です。用途に応じて選ぶ、という考え方を押さえておきましょう。

9.3 代表的な入力部品

フォームの中身を作る主役が <input> タグです。type 属性の値を変えるだけで、まったく違う見た目・動作の入力欄に変身する、とても汎用的なタグです。

type の値 見た目・動作 主な用途
text 1行のテキスト入力欄 氏名、件名など自由記述
password 入力文字が ●●● で隠れる パスワードの入力
email メール形式かをブラウザが簡易チェック 連絡先メールアドレス
number 数値のみ、増減ボタン付き 数量、年齢、価格など
date カレンダーから日付を選択 予約日、生年月日など
radio 複数の選択肢から1つだけ選ぶ お問い合わせ種別、性別など
checkbox 選択肢を複数選べる／オンオフ 興味のある項目の複数選択、規約への同意

コードと見た目のイメージを見比べてみましょう。

書いた HTML

input.html 
<input type="text" placeholder="山田 太郎">
<input type="email" placeholder="taro@example.com">
<input type="radio" name="type" value="soudan" checked> 相談
<input type="radio" name="type" value="mitsumori"> 見積依頼
<input type="checkbox" value="agree"> 規約に同意する

ブラウザでの表示イメージ

山田 太郎
taro@example.com
相談
見積依頼
規約に同意する

上のコード例に登場する checked 属性は、最初から選択された状態にしておくための属性です。なお、ここでは説明のため文字をそのまま並べていますが、入力欄の説明には本来 <label> タグを使います（<label> の付け方は次の9.4で学びます）。

<input> は空要素（第3章参照）なので終了タグがありません。一方で、複数行の文章を入力させたいときは <textarea>、あらかじめ決まった選択肢から選ばせたいときは <select> を使います。どちらも開始タグ・終了タグを持つ通常の要素です。

textarea-select.html 
<textarea rows="4" placeholder="お問い合わせ内容をご記入ください"></textarea>

<select>
  <option value="general">一般的なご質問</option>
  <option value="quote">お見積りのご相談</option>
</select>

<button type="submit">送信する</button>

最後に登場した <button> は送信ボタンです。type="submit" を指定したボタンをクリックすると、フォーム内の入力内容がまとめて送信されます。

9.4 label と for/id の結び付け

入力欄の横に添える「お名前」「メールアドレス」といった説明文には、ただのテキストではなく <label> タグを使います。<label> の for 属性と、対応する入力欄の id 属性に同じ値を指定すると、両者が結び付きます。

label.html 
<label for="name">お名前</label>
<input type="text" id="name" name="name">

この結び付けには2つの大きなメリットがあります。

クリック範囲が広がる

ラベルの文字部分をクリック・タップするだけで、対応する入力欄にカーソルが移動します（チェックボックスなら選択状態が切り替わります）。スマホでは特に効果を実感できます。

読み上げソフトに伝わる

視覚障害のある方が使うスクリーンリーダーが「これは何を入力する欄か」を正しく読み上げられるようになります。アクセシビリティの基本です。

よくある失敗

<label> を使わずに、ただの <p>お名前</p> のような文章で済ませてしまうケースをよく見かけます。見た目は同じでも、クリックしても入力欄にフォーカスが移らず、読み上げソフトにも伝わりません。「入力欄の説明」には必ず <label> を使いましょう。

9.5 name 属性 — 送信データの「キー」になる

入力部品には id のほかに name という属性も付けます。この2つは役割がまったく異なります。id は label との結び付けなどページ内で使うための目印、name は送信データの名前（キー）になります。

フォームが送信されると、ブラウザは「name属性の値＝入力された値」という組を、部品の数だけ作ってサーバーに送ります。name を付け忘れた入力欄は、たとえ画面上に文字を入力していても送信データに含まれません。

ただし radio・checkbox は自由に文字を入力するものではないため、「入力された値」がありません。その代わりに、value 属性に書いた値が送信されます。value を省略すると既定値の "on" が送られてしまい、どの選択肢が選ばれたか区別できなくなるため注意しましょう。

書いた HTML と入力内容

name.html 
<input type="text" name="username">
<!-- 「山田太郎」と入力 -->

<input type="email" name="email">
<!-- 「taro@example.com」と入力 -->

GETで送られるURLのイメージ

https://example.com/contact?

username=山田太郎&email=taro@example.com

（実際は日本語はエンコードされて送られます）

右側の例からも分かるとおり、URLに現れているのは name属性の値 であり、id属性の値 ではありません。POSTで送信した場合は、これと同じ組がURLではなくリクエストの本文に隠れて送られます。

重要ポイント

id は「ページ内でこの要素を指し示すための名前」、name は「サーバーに送るデータの名前」。役割が違うので、入力部品には両方を付けるのが基本です。

9.6 入力補助の属性と簡易バリデーション

HTMLには、サーバーに送る前に入力ミスを防ぐための便利な属性が用意されています。これらはブラウザが自動でチェックしてくれるため、少ないコードで入力の質を高められます。

属性 効果
placeholder 未入力時に薄く表示される入力例。入力された値ではない点に注意
required 未入力のまま送信しようとすると、ブラウザが警告を出して送信を止める（必須項目）
maxlength 入力できる文字数の上限を指定する（text・search・url・tel・email・passwordのみに有効。numberやdateには効かない）
validation.html 
<label for="name">お名前（必須）</label>
<input type="text" id="name" name="name"
       placeholder="山田 太郎" required maxlength="30">

<label for="email">メールアドレス（必須）</label>
<input type="email" id="email" name="email"
       placeholder="taro@example.com" required>

type="email" や required によるチェックは「簡易」バリデーションである点を必ず覚えておいてください。ブラウザ側のチェックは、開発者ツールで属性を書き換えられたり、ブラウザを介さず（プログラムから）直接サーバーへリクエストを送られたりすると、簡単にすり抜けられてしまいます。

重要: クライアント側チェックだけでは不十分

required や type="email" は、あくまで入力の手間を減らす・親切な誘導をするためのものです。実際のシステムでは、送られてきたデータをサーバー側のプログラムでも必ずチェックする「サーバーサイドバリデーション」が不可欠です。この教材ではHTML側の入力補助までを扱います。

やってみよう 9-1: 問い合わせフォームを組み立てよう

これまでに学んだ部品を組み合わせて、実際に動く問い合わせフォームを作ってみましょう。第2章で作った学習用フォルダに contact.html を新規作成してください。

手順

  1. 1 <form action="#" method="post"> を書き、その中にこれから作る部品をすべて入れる。
  2. 2 「お名前」欄を <label> と <input type="text"> で作る。for/id を結び付け、required を付ける。
  3. 3 「メールアドレス」欄を type="email" で、「お問い合わせ種別」を radio 2つ以上で作る（同じ name と、選択肢ごとに異なる value を指定するのを忘れずに）。
  4. 4 「お問い合わせ内容」を <textarea> で、「規約への同意」を checkbox で作る。最後に <button type="submit">送信する</button> を置く。
  5. 5 ブラウザで開き、名前欄を空のまま送信ボタンを押して required の警告が出ることを確認する。ラベルの文字をクリックして入力欄にカーソルが移ることも確かめる。

action="#" のままなら実際にどこかへデータが送られることはないので、安心して何度でも送信ボタンを試せます。うまく動いたら、maxlength や placeholder も追加してみましょう。

理解度確認クイズ

  1. Q1. フォームの「入力 → 送信 → サーバー処理」という流れの中で、HTMLが担当するのはどこまでですか。

    回答を表示

    HTMLが担当するのは「入力欄と送信ボタンを画面に用意すること」までです。送られてきたデータをどう処理するか（保存・返信など）は、サーバー側のプログラムの仕事になります。

  2. Q2. GETとPOSTの違いを、データの送り方の観点から説明してください。

    回答を表示

    GETは入力内容をURLの末尾（クエリ文字列）に付け足して送るのに対し、POSTはリクエストの本文に隠して送ります。GETは検索など「情報を取得する」場面、POSTはお問い合わせや登録など「情報を送信・変更する」場面に向いています。

  3. Q3. label と input を for/id で結び付けると、どのようなメリットがありますか。2つ挙げてください。

    回答を表示

    (1) ラベルの文字をクリック・タップするだけで対応する入力欄にカーソルが移動し操作しやすくなる、(2) スクリーンリーダーなどの読み上げソフトに「これは何を入力する欄か」が正しく伝わり、アクセシビリティが向上する、という2点です。

  4. Q4. name属性の役割と、required属性の限界について説明してください。

    回答を表示

    name属性は送信データの「キー（名前）」になり、name属性を付け忘れた入力欄の値は送信データに含まれません。required属性は未入力のまま送信しようとするとブラウザが警告を出す便利な機能ですが、あくまでブラウザ側（クライアント側）のチェックであり、すり抜けられる可能性があるため、実際のシステムではサーバー側でのチェックも必須です。
