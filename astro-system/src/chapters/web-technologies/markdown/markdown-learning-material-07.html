コードブロックと引用

この章では、技術文書に欠かせない2つの記法「コードブロック」と「引用」を学びます。コマンドやプログラムのコードをそのままの見た目で見せる方法と、他の文章や注意書きを本文と区別して示す方法を身につけ、伝わりやすい文書を書けるようになりましょう。

この章で学ぶこと

  • インラインコードとフェンス付きコードブロックの違いを説明できる
  • バッククォート3つ（```）でコードブロックを書き、言語名を指定してシンタックスハイライトできる
  • 引用（>）の書き方と、入れ子（>>）にする方法が分かる
  • コードブロックと引用を、それぞれふさわしい場面で使い分けられる

7.1 インラインコードと「コードブロック」の違い

第4章では、文中で短いコードやコマンド名を目立たせるインラインコード（バッククォート1つで囲む書き方。例: `npm install`）を学びました。文章の途中に埋め込んで使うのにぴったりの記法です。

しかし、複数行にわたるプログラムのコードや、設定ファイルの中身をまとめて見せたいときはどうでしょうか。インラインコードは「1行の中に埋め込む」ための記法なので、無理に使うと改行やインデント（字下げ）が失われてしまい、正しく表示できません。

そこで使うのが、コードの前後を区切って独立した領域として表示するフェンス付きコードブロック（fenced code block）です。「フェンス（fence）」は「柵」という意味で、その名のとおりコードを柵で囲うように区切ります。

比較項目 インラインコード コードブロック
書き方 バッククォート1つで囲む（`code`） バッククォート3つで前後を囲む（```）
向いている用途 文中の短いコマンド名・ファイル名・変数名 複数行のコード・設定ファイル・実行結果
改行・インデント 保持されない（1行の中に埋め込まれる） そのまま保持される

7.2 フェンス付きコードブロックの書き方

書き方はとてもシンプルです。コードの前後をバッククォート3つ（```）だけの行で挟むだけで、その内側がまとめてコードブロックとして扱われます。たとえば、Gitのコマンドを3つまとめて紹介したいときは、次のように書きます。

note.md 
変更内容を確認してから、コミットします。

```
git status
git add .
git commit -m "更新内容を記録"
```

フェンスの内側に書いた改行やスペースは、そのままの見た目で表示されます。ただし、この書き方では言語を指定していないため、色は付かずプレーンな表示になります（色を付ける方法は次の7.3で学びます）。

書くときのポイント

開始と終了のフェンス（```）は、それぞれ独立した行に単独で書きます。同じ行にコードを続けて書かないよう注意しましょう。また、コードブロックの中に書いた * や # などの記号は、Markdownの記法として解釈されずそのまま文字として表示されます。

7.3 言語名を指定してシンタックスハイライトする

開始のフェンス（```）の直後に、スペースを空けずに言語名を書くと、その言語に合わせて色分け表示（シンタックスハイライト＝構文強調表示）が行われます。キーワードや文字列、コメントなどが色分けされ、コードがぐっと読みやすくなります。

書いたテキスト（Markdown）

example.md 
```python
def greet(name):
    print(f"Hello, {name}!")

greet("World")
```

表示イメージ

def greet(name):
    print(f"Hello, {name}!")

greet("World")

キーワード（def など）や文字列、数値などが自動的に色分けされているのが分かるでしょうか。よく使う言語名の一部を紹介します。

言語 指定する名前 主な用途
Python python Pythonのスクリプト
JavaScript javascript Web・Node.jsのコード
シェルコマンド bash ターミナルで実行するコマンド
JSON json 設定ファイル・データ形式
YAML yaml 設定ファイル（GitHub Actionsなど）

言語名を書かなくてもエラーにはならない

言語名を省略しても、コードブロックとしては正しく機能します（色が付かず、プレーン表示になるだけです）。対応していない言語名を書いてしまった場合も同様で、エラーにはなりません。まずは気軽に python や bash から試してみましょう。

7.4 引用（>）の書き方

他の人の発言や、外部の文章をそのまま紹介したいときは、行の先頭に半角の大なり記号（>）と半角スペースを付けます。これを引用（blockquote）と呼びます。表示すると左側に縦線の入った箱になり、本文と視覚的に区別できます。

書いたテキスト（Markdown）

notice.md 
プロジェクトのREADMEには、こう書かれていました。

> このツールはまだベータ版です。
> 本番環境での利用は推奨しません。

上記の注意点を踏まえて使いましょう。

表示イメージ

プロジェクトのREADMEには、こう書かれていました。

このツールはまだベータ版です。
本番環境での利用は推奨しません。

上記の注意点を踏まえて使いましょう。

複数行を引用する場合は、上の例のようにそれぞれの行の先頭に > を付けます。1行だけに付けて改行すると、続きが引用として扱われるかどうかはツールによって挙動が異なるため、慣れるまでは各行に付けるのが安全です。

重要ポイント

引用を終えて通常の文章に戻るときは、間に空行を1つ入れましょう。空行がないと、どこまでが引用でどこからが本文なのか、意図しない表示になってしまうことがあります。

7.5 引用の入れ子と、引用の中で使える記法

引用の中にさらに引用を入れたい場合（例えば、チャットの返信を重ねて表示したいとき）は、> を重ねて書きます。2重の引用なら >>、3重なら >>> です。

chat.md 
チャットのやり取りを引用してまとめます。

> Aさん: 今日のミーティングは何時からですか？
>
>> Bさん: 14時からです。会議室Aで行います。

これは次のように表示されます。引用の中に、さらに枠がひとつ深く入っているのが分かります。

Aさん: 今日のミーティングは何時からですか？

Bさん: 14時からです。会議室Aで行います。

引用の中でも、これまでの章で学んだ太字・斜体・インラインコード・リンクなどの記法がそのまま使えます。注意書きを目立たせたいときによく使われる組み合わせを見てみましょう。

warning.md 
> **注意:** このコマンドは `rm -rf` を含むため、実行前によく確認してください。

注意: このコマンドは rm -rf を含むため、実行前によく確認してください。

7.6 使い分けの整理：コードブロックと引用

コードブロックと引用は、どちらも「本文と見た目を変えて区別する」記法ですが、使うべき場面はまったく異なります。最後に整理しておきましょう。

コードブロックが向いている場面

  • ターミナルで実行するコマンドの例
  • プログラムのソースコード
  • 実行結果やエラーメッセージの貼り付け
  • JSON・YAMLなどの設定ファイルの中身

引用が向いている場面

  • 他人の発言や外部の文章の紹介
  • 本文とは違う注意書き・補足の強調
  • メールやチャットの返信内容の引用
  • 参考にした引用元の明示

判断に迷ったときは、次の流れで考えてみましょう。

flowchart TD A["書きたい内容は？"] --> B{"内容の種類"} B -->|"コマンド・エラーメッセージ・設定ファイル"| C["コードブロックを使う"] B -->|"他人の文章・注意書き・補足コメント"| D["引用を使う"] C --> E["三連バッククォートで前後を囲む"] D --> F["行頭に引用記号を付ける"]

重要ポイント

「そのままコピーして実行・保存してほしい情報」はコードブロック、「本文とは出どころや立場が違う情報」は引用、と覚えておけば迷いません。

やってみよう 7-1: コードブロックと引用を書いてみよう

第2章で使ったVS Codeを開き、コードブロックと引用を実際に書いて、プレビューでどう表示されるかを確認しましょう。

手順

  1. 1 新しいファイル practice.md を作成する。
  2. 2 言語名付きのフェンス（```bash）で、git status などお好みのコマンドを2〜3行書く。
  3. 3 コードブロックの下に空行を入れ、> を使って「実行前によく確認しましょう。」のような注意書きを引用として書く。
  4. 4 プレビュー（Ctrl+Shift+V）を開き、コードが色付きの枠で、引用が左に線の入ったボックスで表示されることを確認する。
  5. 5 余裕があれば >> を使って引用を入れ子にし、表示がどう変わるか試してみる。

理解度確認クイズ

  1. Q1. インラインコード（バッククォート1つ）ではなく、フェンス付きコードブロック（バッククォート3つ）を使うべきなのはどんなときですか？

    回答を表示

    複数行にわたるコードや、改行・インデントを正確に保持したい場合です。設定ファイルの中身やコマンドの実行結果など、まとまった内容を見せたいときに使います。インラインコードは文中の短い単語やコマンド名に向いています。

  2. Q2. コードブロックにPythonのシンタックスハイライトを適用したいとき、開始のバッククォート3つの直後に何と書きますか？

    回答を表示

    スペースを空けずに言語名 python を続けて書きます（```python）。対応するエディタやサービスが、キーワードや文字列を自動で色分けして表示してくれます。

  3. Q3. 引用を入れ子にして、引用の中にさらに引用を入れたいときはどう書きますか？また、コマンドの実行例と他人の発言、それぞれどちらの記法を使うべきですか？

    回答を表示

    >> のように大なり記号を重ねて書きます（3重なら >>>）。コマンドの実行例やエラーメッセージ、設定ファイルの中身はコードブロックを、他人の発言や注意書きなど「本文とは異なる情報」を示したいときは引用を使います。
