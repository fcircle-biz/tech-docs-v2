ホーム Markdown 第3章
第3章 所要時間: 約30分

見出しと段落

見出しと段落は、文章に骨組みを与える一番基本の要素です。この章では、# を使った見出しの書き方と正しい階層の作り方、そして段落・改行のルールを学び、読みやすい文書の土台を組み立てられるようになります。

この章で学ぶこと

  • 見出し記法（# 〜 ###### の6レベル）の書き方と、必ず守るべきルールが分かる
  • 見出しレベルを飛ばさずに使い、文書に正しい階層構造を作れる
  • 段落の正しい作り方（空行で区切る）が分かる
  • 改行の2つの方法と、ツールによって挙動が違うことを理解する

3.1 見出しの書き方（# 〜 ######）

見出し（heading）とは、Wordでいう「見出し1」「見出し2」のような、文章の区切りを示すタイトル部分です。Markdown では、行の先頭に #（シャープ、ハッシュ記号）を1〜6個書くことで、6段階の見出しを表現します。# の数が少ないほど大きな見出し、多いほど小さな見出しになります。

レベル 記法 目安となる使いどころ
1 # 見出し 文書全体のタイトル（1つの文書で基本1回だけ）
2 ## 見出し 大きな章・セクションの見出し
3 ### 見出し 章の中の小見出し（この教材でもよく使う階層）
4 #### 見出し さらに細かい項目分け
5 ##### 見出し 5階層目の見出し（実務ではあまり使わない）
6 ###### 見出し 最も小さい見出し（めったに使わない）

書いたテキスト（Markdown）

headings.md 
# メインタイトル

## セクション見出し

### 小見出し

表示イメージ

メインタイトル

セクション見出し

小見出し

重要: # の直後には半角スペースが必須

#見出し のようにスペースを詰めて書くと見出しとして認識されず、そのまま記号付きの文字列として表示されてしまいます。# 見出し のように、# の後に半角スペースを1つ入れましょう（全角スペースも不可です）。

3.2 見出しレベルの使い分け

見出しは、本の目次のように文書全体の階層構造を作る役割も持っています。GitHub などの多くのツールは、見出しの並びから自動で目次（アウトライン）を生成します。この仕組みを正しく働かせるために守っておきたいルールが1つあります。それは見出しレベルを飛ばさないことです。

たとえば ##（レベル2）の次に、いきなり ####（レベル4）を使うのは避けましょう。フォントサイズの見た目だけで見出しレベルを選ぶのではなく、「章の中の節、節の中の項」というように1段階ずつ深くするのが正しい使い方です。

flowchart TD A["見出し1（文書のタイトル）"] --> B["見出し2（第1章）"] A --> C["見出し2（第2章）"] B --> D["見出し3（1-1節）"] B --> E["見出し3（1-2節）"] C --> F["見出し3（2-1節）"]

悪い例（レベルを飛ばしている）

bad-example.md 
## 第1章 準備

#### インストール手順

良い例（1段階ずつ深くする）

good-example.md 
## 第1章 準備

### インストール手順

重要ポイント

見出しは目次の骨組みそのものです。フォントサイズの見た目だけで選ばず、「## の次は ###」というように1段階ずつ順番に深くすることを意識しましょう。

3.3 段落の作り方

段落（paragraph）とは、ひとまとまりの文章のかたまりです。Markdown では、空行（何も書いていない行）によって段落の区切りを判断します。エディタの画面上で行を変えて書いても、間に空行がなければ、Markdown 的には同じ1つの段落として扱われてしまう点に注意しましょう。

paragraphs.md 
これは1つ目の段落です。
この行も1つ目の段落の続きとして扱われます。

これは2つ目の段落です。空行で区切られています。

表示イメージ

これは1つ目の段落です。 この行も1つ目の段落の続きとして扱われます。

これは2つ目の段落です。空行で区切られています。

Word の「Enter」とは違います

Word などの文書ソフトでは、Enter キーを押すたびに見た目どおりに段落が変わります。しかし Markdown では、1回改行しただけ（空行なし）では段落は変わりません。段落を分けたいときは、必ず空行を1行はさむと覚えておきましょう。

3.4 改行のルール

段落は変えずに、1行だけ改行したいということもあります（住所や短い詩のような文章など）。ところが3.3で見たとおり、ふつうに改行しただけでは段落の中では無視されてしまいます。Markdown で確実に改行するには、次の2つの方法のどちらかを使います。

方法 書き方 特徴
半角スペース2つ 行の末尾に半角スペースを2つ入力してから改行する 見た目に何も残らないため分かりにくい。エディタの設定によっては、保存時に行末の空白が自動的に削除されてしまうことがある
<br> タグ 行の末尾に <br> と書く HTML のタグを直接書く方法。目に見えるので分かりやすく、消えにくい

書いたテキスト（Markdown）

line-break.md 
お知らせ：<br>
本日は休業いたします。

表示イメージ

お知らせ：
本日は休業いたします。

半角スペース2つの方法でも同じ結果になります。1行目「お知らせ：」の行末に半角スペースを2つ入力してから改行し、2行目に「本日は休業いたします。」と続けて書けば、<br> タグを使ったときと同じように改行されます（スペースは目に見えないため、見た目だけでは気づきにくい点に注意してください）。

ツールによって挙動が違う

GitHub など多くのツールは両方の方法に対応していますが、簡易的な Markdown しか処理できないチャットツールやメモアプリの中には、半角スペース2つによる改行が効かないものもあります。迷ったときは、目に見えて分かりやすい <br> タグを使うのが無難です。

3.5 よくある間違いに注意

最後に、初心者がとくにつまずきやすい2つのポイントをおさらいしておきましょう。どちらも「一見それらしく書けているのに、なぜか思ったとおりに表示されない」という定番のつまずきポイントです。

間違い1: # の後のスペースを忘れる

#見出し のようにスペースなしで書くと見出しにならず、そのまま「#見出し」という文字列が表示されます。

正しくは # 見出し（# の直後に半角スペース1つ）です。

間違い2: 空行を入れずに改行したつもりになる

エディタの画面では行が変わって見えても、間に空行がなければ Markdown 上は同じ1つの段落として扱われ、表示のときにつながってしまいます。

段落を分けたいときは空行を1行、段落の中で1行だけ改行したいときは行末に半角スペース2つ、または <br> タグを使いましょう。

やってみよう 3-1: 見出しと段落を書いてみよう

第2章で準備した VS Code を使って、実際に見出しと段落を書き、プレビューでどう表示されるかを確認しましょう。

手順

  1. 1 VS Code で新しいファイル chapter3.md を作成する。
  2. 2 # から ###### まで6段階の見出しを書き、Ctrl+Shift+V でプレビューを開いて、大きさの違いを見比べる。
  3. 3 見出しの下に2つの文章を空行を入れずに並べて書き、1つの段落につながることを確認する。次に間に空行を入れて、2つの段落に分かれることを確認する。
  4. 4 1つの段落の中で、行末に半角スペースを2つ、または <br> タグを使って改行を試し、表示の違いを確認する。

理解度確認クイズ

  1. Q1. 見出し記法を書くとき、# の後に必ずしなければならないことは何ですか？

    回答を表示

    # の後に半角スペースを1つ入れる必要があります。スペースがないと見出しとして認識されず、記号付きのただの文字列として表示されてしまいます。

  2. Q2. 見出しレベルを使うときに避けるべきことは何ですか？理由もあわせて説明してください。

    回答を表示

    見出しレベルを飛ばすこと（例: ## の次にいきなり #### を使う）は避けるべきです。見出しは文書の階層構造（目次）を作る土台なので、1段階ずつ順番に深くしないと、読み手やツールが文書の構造を正しく理解できなくなります。

  3. Q3. 段落を分けたいときと、段落の中で1行だけ改行したいときでは、それぞれどのように書けばよいですか？

    回答を表示

    段落を分けたいときは、間に空行（何も書いていない行）を1行入れます。段落を変えずに1行だけ改行したいときは、行末に半角スペースを2つ入れるか、<br> タグを使います。
