10.1 GitHub Flavored Markdown（GFM）とは

第9章の最後で少し触れたとおり、Markdown にはいくつかの「方言（フレーバー）」があります。その中でも最も広く使われているのが、GitHub が独自に拡張したGFM（GitHub Flavored Markdown）です。土台となる標準仕様CommonMark（曖昧さの少ない Markdown の共通ルールをまとめた仕様）に、GitHub が実務でよく使う機能を追加したものだと考えてください。

実は、この教材でこれまで学んできた記法の中にも、GFM による拡張機能がいくつも含まれています。README.md は GitHub 上で表示されることが前提のファイルなので、GFM の機能を遠慮なく使って大丈夫です。

用語: 自動リンクの範囲

第6章で学んだ <https://example.com>（山括弧で囲む書き方）は CommonMark の標準機能です。GFM ではさらに一歩進んで、https://example.com のようにURLをそのまま書くだけでも自動的にリンクになります。README ではこの「拡張オートリンク」が特によく使われます。

まとめると、GFM ＝ CommonMark（標準）＋ GitHub の便利な拡張機能という関係です。次の節からは、この GFM も活用しながら README を組み立てていきます。

10.2 README の役割と定番構成

README（リードミー）は、GitHub でリポジトリ（プロジェクトの保存場所）を開いたときに、ファイル一覧の下に自動的に表示される案内ドキュメントです。多くの人にとって、そのプロジェクトについて最初に読む文章になります。分かりやすい README があるだけで「どんなツールか」「どう使えばいいか」が一瞬で伝わり、使ってもらえる可能性も大きく上がります。

書く内容に厳密な決まりはありませんが、多くのプロジェクトで採用されている定番の6構成があります。まずはこの型に沿って書くことを意識しましょう。

  1. 1 タイトル — プロジェクト名を # の大見出しで示す
  2. 2 概要 — 「何をするものか」を1〜数行で説明する
  3. 3 特徴 — 主な機能やメリットを箇条書きで並べる
  4. 4 インストール方法 — 導入コマンドをコードブロックで示す
  5. 5 使い方 — 基本的なコマンドや操作例を示す（表が便利）
  6. 6 ライセンス — 利用・改変・再配布の条件を明記する

重要ポイント

6つすべてを毎回完璧に書く必要はありません。特に概要・インストール方法・使い方の3つは、初めて訪れた人が最初に知りたい情報なので、優先して書くようにしましょう。

10.3 総合演習：todo-cli の README を完成させよう

ここからは総仕上げです。架空のコマンドラインツール「todo-cli」（ターミナルで使うシンプルな ToDo 管理ツール、という設定です）を題材に、これまで学んだ記法を総動員して README.md を段階的に組み立てていきます。一気に書こうとせず、下図の4つの流れに沿って、STEP1〜STEP6 の順で少しずつ組み立てていきましょう。

flowchart LR A["①骨組みを作る
（見出しだけ）"] --> B["②各セクションを書く
（概要・特徴など）"] B --> C["③表・コードを足す
（使い方・インストール）"] C --> D["④見直して公開
（プレビューで確認）"]

それでは、実際に手を動かす気持ちで1つずつ見ていきましょう。すべて同じ README.md というファイルを、少しずつ育てていくイメージです。

1 骨組みを作る（見出しだけ）

README.md 
# todo-cli

## 概要

## 特徴

## インストール方法

## 使い方

## ライセンス

まずは見出しだけを並べて、全体の設計図を作ります。10.2 で見た6構成をそのまま ## の見出しにしただけです。中身は空でも、これだけで「何が書かれる予定か」が一目で分かります。

2 タイトルと概要を書く

README.md 
# todo-cli

> ターミナルから使えるシンプルな ToDo 管理ツール

## 概要

`todo-cli` は、コマンド1つでタスクの追加・完了・削除ができる
軽量な ToDo 管理ツールです。難しい設定は不要で、
インストール後すぐに使い始められます。

タイトルの下に引用（第7章）で一言キャッチコピーを添え、「概要」にはインラインコード（第4章）でツール名を、通常の文章で内容を説明しています。文章を空行で段落に分けている点にも注目してください（第3章）。

3 特徴をタスクリストで書く

README.md 
## 特徴

- [x] タスクの追加・完了・削除
- [x] 期限（締切日）の設定
- [x] JSON ファイルへの自動保存
- [ ] クラウド同期（今後追加予定）

**対応OS**: Windows / macOS / Linux

普通の箇条書きの代わりにタスクリスト（第5章・GFM）を使うと、「実装済みの機能」と「予定の機能」を視覚的に区別できます。README ならではの、GFM が活きる書き方です。

4 インストール方法を書く

README.md 
## インストール方法

```bash
npm install -g todo-cli
```

インストール後、`todo` コマンドが使えるようになります。

コマンドはフェンス付きコードブロック（第7章）に bash を指定して表示します。読んだ人がそのままコピーして実行できるのが、コードブロックを使う一番のメリットです。

5 使い方を表で書く

README.md 
## 使い方

| コマンド | 説明 |
| --- | --- |
| `todo add "牛乳を買う"` | タスクを追加する |
| `todo done 1` | 1番のタスクを完了にする |
| `todo list` | 未完了のタスク一覧を表示する |

複数のコマンド例を並べるときは、文章よりも表（第8章）の方が圧倒的に見やすくなります。セル内ではインラインコードでコマンド名を強調しています。

6 ライセンスを書いて仕上げる

README.md 
## ライセンス

このプロジェクトは [MIT License](LICENSE) の下で公開されています。
自由に利用・改変・再配布していただけます。

---

*Made with :coffee: by todo-cli チーム*

最後はリンク（第6章）でライセンス条件を、水平線と絵文字コード（どちらも第9章）でちょっとした遊び心を添えて締めくくります。これで6要素がすべて揃いました。

すべてをつなげると、GitHub 上では次のように表示されます。

10.4 全記法チートシート（早見表）

最後に、第3章から第9章まで学んできた記法を1つの表にまとめました。書き方を忘れてしまったときは、このチートシート（早見表）にいつでも戻ってきてください。

記法 書き方・意味 学んだ章
#〜###### 見出し（#の数がレベル、後ろに半角スペース必須） 第3章
（空行） 空行を1行はさんで段落を分ける 第3章
**太字** 文字を太く強調する 第4章
*斜体* 文字を斜体にする 第4章
~~打ち消し~~ 文字に取り消し線を引く（GFM） 第4章
`code` 文中にコードを表示する（インラインコード） 第4章
- 項目 順序のない箇条書きリスト 第5章
1. 項目 自動で連番が振られる番号付きリスト 第5章
- [ ] / - [x] チェックボックス付きのタスクリスト（GFM） 第5章
[テキスト](URL) 文字列にリンクを付ける 第6章
![alt](パス) 画像を埋め込む（先頭の ! に注意） 第6章
``` 〜 ``` 複数行のコードをそのまま表示する（フェンス） 第7章
> 他の文章の引用を表す 第7章
| 列 | 情報を表（テーブル）形式で整理する（GFM） 第8章
--- 水平線（区切り線）を引く 第9章
\ 直後の記号をそのまま文字として表示する（エスケープ） 第9章
<br> 改行など、Markdown にない表現を HTML タグで補う 第9章
<details> クリックで開閉する折りたたみブロックを作る 第9章
<!-- --> 表示されないコメント（メモ）を書く 第9章
[^1] 補足説明を文末にまとめる脚注 第9章
:smile: 環境によって絵文字を表示する（GFM等） 第9章

こうして並べてみると、Markdown の記法は決して多くないことが分かります。覚えるというより、必要なときにこの表を見返せば十分です。

10.5 次のステップ

全10章、お疲れ様でした。Markdown の考え方から、見出し・装飾・リスト・リンク・画像・コードブロック・引用・表、そして GFM や README の書き方まで、一通り身につけることができました。ここで学んだことは、そのままいろいろな場面で使い回せます。次は、以下のような形でさらにステップアップしてみましょう。

HTML / CSS を学ぶ

Markdown の変換先である HTML を学ぶと、「見出しは実は h1〜h6 タグだった」など、理解がさらに深まります。

Git / GitHub を学ぶ

この章で作った README を実際に活かすには、バージョン管理と公開の知識が役立ちます。Git / GitHub 入門学習ガイドへどうぞ。

技術記事を書いてみる

Qiita や Zenn などのサービスで、学んだ記法を使って実際に記事を書いて公開してみましょう。

お疲れ様でした

Markdown は、一度覚えれば一生使える基礎スキルです。最初は表やタスクリストの書き方をこの章のチートシートで確認しながらで構いません。使いながら覚えていくのが、一番の近道です。

やってみよう 10-1: 自分の手で todo-cli の README.md を完成させよう

10.3 で見た6つのステップは、読むだけでなく実際に自分の手で入力してこそ身につきます。VS Code を開いて、じっくり体を動かしながら進めてみましょう。仕上げに、自分だけのオリジナル README にも挑戦します。

手順

  1. 1 第2章の復習として、新しいフォルダ（例: todo-cli-practice）を作り、その中に README.md という空ファイルを作成する。
  2. 2 STEP1の骨組みをそのまま入力し、プレビュー（Ctrl+Shift+V）で6つの見出しが表示されることを確認する。
  3. 3 STEP2〜STEP6の内容を上から順番に入力し、そのつどプレビューと見比べながら「どの記法がどう変わって見えるか」を確認する。
  4. 4 「特徴」のタスクリストを書き換えて、チェックの数を増減させてみる。プレビューでチェックボックスの見た目がどう変わるか観察する。
  5. 5 「使い方」の表に、自分で考えたコマンドの行を1行追加してみる（区切り行の --- は増やさなくてよいことも確認する）。
  6. 6 【発展】todo-cli の代わりに、自分の好きな架空のアプリを1つ考え、同じ6構成（タイトル・概要・特徴・インストール方法・使い方・ライセンス）でオリジナルの README.md を、何も見ずに書いてみる。

このファイルを実際に GitHub リポジトリのルート（一番上の階層）に置くと、リポジトリのトップページに自動的に表示されます。

理解度確認クイズ

  1. Q1. GFM（GitHub Flavored Markdown）とは何か、土台となる標準仕様との関係も含めて説明してください。

    回答を表示

    GFM は、標準仕様である CommonMark に、GitHub がタスクリスト・表・打ち消し線・自動リンクなどの便利な機能を追加した拡張版の Markdown です。GitHub の README や Issue、プルリクエストなどで使えます。

  2. Q2. README の定番構成として学んだ6つの要素をすべて挙げてください。

    回答を表示

    「タイトル」「概要」「特徴」「インストール方法」「使い方」「ライセンス」の6つです。この順番で書くと、初めて訪れた人でもプロジェクトの内容をスムーズに理解できます。

  3. Q3. 総合演習で「特徴」セクションに使った、GFM ならではのリスト記法は何ですか？また、それは第何章で学びましたか？

    回答を表示

    タスクリスト（- [ ] / - [x]）です。チェックボックス付きのリストとして表示され、第5章で学びました。
