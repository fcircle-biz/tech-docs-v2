レスポンシブデザイン

今や多くの人が、スマートフォンでWebページを見ています。この章では、1つのHTML/CSSだけで、スマホからタブレット・PCまで見やすく表示する「レスポンシブデザイン」を学びます。viewportの設定、単位の使い分け、メディアクエリ、モバイルファーストという考え方を順に押さえ、最後に第10章で学んだ Grid と組み合わせて、画面幅でカードの列数が切り替わる実例を作ります。

この章で学ぶこと

  • レスポンシブデザインとviewportメタタグの役割を理解し、なぜ必要か説明できる
  • px・%・em・rem・vw・vh の違いを理解し、使い分けられる
  • メディアクエリを使って、画面幅ごとにスタイルを切り替えられる
  • モバイルファーストという考え方でCSSを書ける

11.1 レスポンシブデザインとは

レスポンシブデザイン（Responsive Web Design）とは、1つのHTML/CSSファイルだけで、スマートフォン・タブレット・PCなど、あらゆる画面サイズに合わせて見た目を最適化する設計手法です。「レスポンシブ（responsive）」は英語で「反応する」という意味で、画面の幅という変化に「反応」してレイアウトが形を変えることからこの名前が付いています。かつては「PC用サイト」と「スマホ用サイト」を別々に作ることもありましたが、現在ではスマートフォンからのアクセスがPCを上回るサイトが多くなっており、最初から「どの画面幅でも見やすい」ことを前提にページを作るのが標準です。第7〜10章で学んだボックスモデル・Flexbox・Gridは、このレスポンシブデザインを実現するための土台になります。

保守がラク

HTML/CSSが1つなので、修正するときも1箇所を直すだけで済みます。PC版・スマホ版を別々に管理する手間がありません。

SEOに有利

URLが1つにまとまるため、検索エンジンにとっても分かりやすい構成になります。Googleもレスポンシブデザインを推奨しています。

どの端末でも快適

同じページなのに、スマホでは縦積み・PCでは横並びといった最適な見た目に自動で切り替わります。

用語: 「ブレークポイント」とは

レイアウトの切り替え地点となる画面幅のことをブレークポイント（breakpoint）と呼びます。「この幅を境に、CSSの指定を変える」という区切り線のようなものです。11.4で詳しく扱います。

11.2 viewport の設定

レスポンシブデザインを始める前に、絶対に欠かせない前提設定があります。それが viewport（ビューポート＝表示領域）の指定です。スマートフォンのブラウザは、何も指定しないと「PC向けの980px幅のページ」を前提にページを描画し、それを画面に収まるよう縮小して表示してしまいます。結果として、文字が豆粒のように小さくなってしまうのです。

これを防ぐために、HTMLの <head> 内に次のメタタグを記述します。

index.html 
<!-- head内に必ず記述する -->
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>ページタイトル</title>
</head>

content の中身は2つの意味を持っています。width=device-width は「表示領域の幅を、端末が実際に持つ画面幅に合わせる」、initial-scale=1.0 は「最初の表示倍率（拡大率）を100%にする」という指定です。

viewportはCSSの前提となる必須設定

このメタタグが無いと、スマホは「PC向けの980px幅を前提にしたページ」を縮小して表示しようとするため、文字が豆粒のように小さくなってしまいます。この先学ぶメディアクエリなどのレスポンシブ用CSSも正しく機能しません。HTMLを書くときは、最初から必ずセットで入れると覚えておきましょう（このページ自体にも、共通のレイアウトとして最初から設定されています）。

11.3 単位の使い分け

CSSで大きさを指定するとき、これまでは主に px（ピクセル）を使ってきました。しかしレスポンシブデザインでは、画面サイズに応じて自動で変化する相対単位も組み合わせて使います。まずは代表的な単位を一覧で見比べてみましょう。

単位 基準 特徴 主な用途
px なし（絶対値・固定） 画面サイズに関係なく常に同じ大きさ 枠線の太さなど、細かい固定値
% 親要素のサイズ 親要素に対する割合で決まる 幅を親いっぱいに広げたいときなど
em 親要素の文字サイズ 入れ子になるほど計算が積み重なり複雑 文字サイズに連動させたい余白
rem ルート（html要素）の文字サイズ 入れ子の深さに関係なく常に安定 文字サイズ・余白全般（推奨）
vw 画面（ビューポート）幅の1% 画面の横幅に応じて値が変化する 画面幅に連動させたい大見出しなど
vh 画面（ビューポート）高さの1% 画面の高さに応じて値が変化する 画面いっぱいに広げたい領域の高さ

この中で特に押さえておきたいのが rem です。em は「親要素の文字サイズ」が基準になるため、要素が入れ子になるたびに掛け算が積み重なり、意図しない大きさになってしまうことがあります。一方 rem の「r」は root（ルート）の意味で、常に一番の親である <html> 要素の文字サイズだけを基準にするため、どれだけ深く入れ子になっても計算が安定します。これが rem が使いやすいとされる理由です。多くのブラウザは <html> の既定の文字サイズを16pxとしているため、特に指定を変えていなければ 1rem = 16px と考えて差し支えありません。

style.css 
/* emは親要素の文字サイズが基準。入れ子で計算が積み重なる */
.parent { font-size: 20px; }
.child { font-size: 1.5em; }        /* 20px × 1.5 = 30px */
.grandchild { font-size: 1.5em; }   /* 30px × 1.5 = 45px（意図せず拡大）*/

/* remは常にhtml要素の文字サイズが基準。入れ子でも安定する */
.child2 { font-size: 1.5rem; }      /* 16px × 1.5 = 24px */
.grandchild2 { font-size: 1.5rem; } /* 深さに関係なく同じ24px */

11.4 メディアクエリ

メディアクエリ（Media Query）は、「画面幅がこの条件のときだけ、このCSSを適用する」という条件分岐の仕組みです。@media というキーワードを使い、min-width（この幅以上）や max-width（この幅以下）で条件を指定します。この2つを組み合わせれば、「特定の範囲のときだけ」という指定も可能です。

style.css 
/* 画面幅が768px以上のときだけ適用されるスタイル */
@media (min-width: 768px) {
  .container { width: 750px; }
}

/* タブレットの範囲だけに適用（768px以上 かつ 1024px未満） */
@media (min-width: 768px) and (max-width: 1023px) {
  .sidebar { display: none; } /* この範囲だけ非表示にする */
}

では、何pxを境目（ブレークポイント）にすればよいのでしょうか。厳密な決まりはありませんが、次の3段階が広く使われている目安です。

  • スマートフォン — 〜480px程度（縦持ちのスマートフォン）
  • タブレット — 768px前後〜（iPadなどのタブレット端末）
  • PC — 1024px前後〜（ノートPC・デスクトップ）

ただし、これらは代表的な目安にすぎません。実際の現場では「このスマホ機種は何pxだから」ではなく、自分のページのレイアウトが崩れ始める幅を開発者ツールで確認しながらブレークポイントを決めるのが基本です（この章末の実習で試します）。

11.5 モバイルファースト

メディアクエリを書く順番には、推奨されるスタイルがあります。それがモバイルファースト（Mobile First）です。「まずスマートフォン向けの基本スタイルを書き、min-width のメディアクエリで、画面が広くなるにつれてスタイルを追加・上書きしていく」という考え方です。次の図は、画面幅が広がるにつれてどのCSSが積み重なって適用されていくかを表したものです。基本スタイルの上に、条件を満たすたびにスタイルが追加されていくイメージをつかんでください。

flowchart TD A["基本スタイル（min-widthの指定なし）
＝スマホ向けレイアウト"] --> B{"画面幅は768px以上？"} B -->|いいえ| C["基本スタイルのみ適用
（1列表示）"] B -->|はい| D["min-width: 768px の指定を追加適用
（2列表示）"] D --> E{"画面幅は1024px以上？"} E -->|いいえ| F["ここまでの指定が有効
（タブレット向け・2列）"] E -->|はい| G["min-width: 1024px の指定もさらに追加適用
（3列表示・PC向け）"]

コードにすると、次のように「基本形」→「min-width による上書き」という順で書きます。

style.css 
/* 1. まず基本スタイル（スマホ向け）を書く */
.card-list {
  display: grid;
  grid-template-columns: 1fr; /* 1列で縦に並べる */
  gap: 16px;
}

/* 2. 画面が広くなったらmin-widthで上書きする */
@media (min-width: 768px) {
  .card-list {
    grid-template-columns: repeat(2, 1fr); /* 2列にする */
  }
}

モバイルファーストが推奨される理由は、主に次の3つです。メディアクエリは基本的に min-width だけを使い、画面が広くなる方向にスタイルを追加していくのが基本形です（逆にPC向けを基本にして max-width で打ち消していく「デスクトップファースト」は、指定の取り消しが増えて複雑になりがちです）。

  • アクセスの主流に合っている — スマートフォンからの閲覧が中心になっている以上、その環境を基準に考えるのが自然です
  • 「足し算」で考えられる — シンプルな1列レイアウトから始め、画面が広がるごとに要素を「足していく」ほうが、複雑なPC向けレイアウトから要素を「引いていく」よりも考えやすい
  • 無駄なCSSを読み込ませない — スマホでは基本スタイルだけで済み、PC向けの複雑な指定を余分に処理させずに済みます

11.6 画像とメディアの可変対応

文字は画面幅に合わせて折り返されますが、<img> タグの画像は、何も指定しないと元の大きさのまま表示されます。画像が親要素より大きいと、画面からはみ出してレイアウトが崩れる原因になります。

style.css 
/* 画像や動画が親要素の幅からはみ出さないようにする */
img, video {
  max-width: 100%; /* 親の幅を超えて表示しない */
  height: auto;    /* 縦横比を保ったまま高さを自動調整する */
}

max-width: 100% は「親要素の幅を超えない範囲で、できるだけ大きく表示する」という指定です。height: auto を必ずセットで指定することで、幅が縮んでも縦横比が保たれ、画像が潰れたり伸びたりするのを防げます。この指定は、多くのCSSリセット（初期化用スタイルシート）にあらかじめ含まれているほどの定番です。特別な理由がない限り、プロジェクトの最初のCSSに書いておくとよいでしょう。

11.7 実践: カードの列数を画面幅で切り替える

ここまで学んだ知識を使って、第10章の CSS Grid と組み合わせた実例を作ってみましょう。商品一覧やブログ記事一覧などでよく見る「PCでは3列・タブレットでは2列・スマホでは1列」に切り替わるカードレイアウトです。モバイルファーストの考え方どおり、基本形（1列）から書き始めます。

style.css 
/* 基本（モバイル向け）：1列で縦に並べる */
.card-grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}
/* タブレット以上（768px〜）：2列にする */
@media (min-width: 768px) {
  .card-grid { grid-template-columns: repeat(2, 1fr); }
}

/* PC（1024px〜）：3列にする */
@media (min-width: 1024px) {
  .card-grid { grid-template-columns: repeat(3, 1fr); }
}

ポイントは、grid-template-columns の値だけを画面幅ごとに書き換えている点です。HTML側は列数が変わっても一切変更する必要がありません。display: grid と repeat() の書き方は第10章で学んだとおりです。

開発者ツールの「デバイスモード」を使うと、実機を持っていなくてもスマホやタブレットの画面幅を再現できます。このページ（第11章）を使って、ブレークポイントの切り替わりを実際に観察してみましょう。

手順

  1. 1 キーボードの F12 キーを押して開発者ツールを開く（Macは Option+Command+I）。
  2. 2 パネル左上にある、スマホとタブレットが重なったようなアイコン（デバイスツールバーの切り替え）をクリックする（ショートカットは Ctrl+Shift+M、Macは Cmd+Shift+M）。
  3. 3 画面上部に表示される幅の数値（例: 375px）を確認しながら、端のバーをドラッグして幅を少しずつ広げていく。
  4. 4 幅がおよそ768px・1024pxを超えたタイミングで、11.7の「動作確認」カードの列数が 1列 → 2列 → 3列 に切り替わることを確認する。あわせて「Elements」パネルの「Styles」欄を見ると、今どのメディアクエリの指定が有効か（無効なものは取り消し線で表示）も分かる。

実務でも、この手順で「どの幅からレイアウトが崩れるか」を確認しながらブレークポイントを決めます。ぴったり768pxや1024pxである必要はなく、自分のデザインが崩れ始める瞬間を見つけることが大切です。

理解度確認クイズ

  1. Q1. 「レスポンシブデザイン」とはどのような設計手法か、説明してください。

    回答を表示

    1つのHTML/CSSだけで、スマートフォン・タブレット・PCなど、あらゆる画面サイズに合わせて見た目を最適化する設計手法です。画面幅の変化に「反応」してレイアウトが形を変えることから、この名前が付いています。

  2. Q2. viewportメタタグを設定しないと、スマートフォンでページはどのように表示されてしまいますか。

    回答を表示

    PC向けの980px幅を前提にページが描画され、それが画面に収まるよう縮小表示されてしまいます。結果として文字が非常に小さくなり、読みにくくなります。<meta name="viewport" content="width=device-width, initial-scale=1.0"> を設定することでこれを防げます。

  3. Q3. remとemの違いを説明し、remが使いやすいとされる理由を述べてください。

    回答を表示

    emは「親要素の文字サイズ」を基準にするため、要素が入れ子になるほど計算が積み重なり、意図しない大きさになりやすい単位です。remは常に「ルート（html要素）の文字サイズ」だけを基準にするため、入れ子の深さに関係なく計算が安定し、扱いやすいとされています。

  4. Q4. 「モバイルファースト」とはどのような考え方で書くCSSか、なぜ推奨されるのかも含めて説明してください。

    回答を表示

    まずスマートフォン向けの基本スタイルを書き、min-width のメディアクエリを使って画面が広くなるにつれてスタイルを追加・上書きしていく考え方です。スマホからのアクセスが主流である現状に合っている、シンプルな状態から「足し算」で考えられる、モバイル環境に不要なCSSを読み込ませずに済む、といった理由から推奨されています。
