カスケード・継承・詳細度

「色を変えたはずなのに変わらない」「余白を指定したのに反映されない」——CSSを書き始めた人が必ず一度は通る道です。この章では、複数のスタイル指定がぶつかったときにブラウザがどう決着をつけるのか、その裏側にある3つの仕組み（カスケード・継承・詳細度）を理解し、「書いたのに効かない」を自分の力で切り分けられるようになります。

この章で学ぶこと

  • カスケードの仕組み（同じ強さのルールが競合したときは、後に書いたほうが勝つこと）を説明できる
  • 継承されるプロパティと継承されないプロパティを区別できる
  • 詳細度（Specificity）を計算し、どちらのルールが勝つか判断できる
  • !important を安易に使うべきでない理由と、効かないときの調べ方が分かる

4.1 なぜスタイルが効かないことがあるのか

第3章までで、セレクタを使って「どこに」スタイルを当てるかを指定できるようになりました。ところが実際に書き進めていくと、「文字色を指定したのに変わらない」「別の場所に書いたスタイルのほうが、なぜか優先されてしまう」「親に指定した設定が子にまで伝わっていて驚く」といった「なぜか効かない」現象に必ず出会います。

これらはCSSが壊れているわけではありません。ブラウザは「複数のスタイル指定がぶつかったとき、どちらを採用するか」を決めるための、明確なルールに従って動いています。そのルールを知らないまま「効かない」に遭遇すると、ただ困惑するだけになってしまいます。この章では、そのルールを症状別に整理しながら学んでいきます。

症状 疑うべき原因 参照
複数のルールが競合し、意図と違うほうが勝っている カスケードの記述順・詳細度 4.2 / 4.4
親には効くのに子に効かない、または効かせたくないのに伝わる 継承の有無 4.3
詳細度を上げても、どうしても他のルールに負ける 相手が !important を使っている 4.5
セレクタもCSSも合っているはずなのに無反応 つづり間違い・ファイルの読み込み失敗 4.6

4.2〜4.4で「どちらが勝つか」を決める3つのルール（カスケード・継承・詳細度）を順番に学び、4.5で反則技である !important の扱いを確認し、最後の4.6で実際に原因を調べる手順を身につけます。

4.2 カスケード（重ね塗り）

第1章で触れたとおり、CSSのCは Cascading（カスケーディング）、つまり「滝のように流れ落ちて重なる」という意味でした。1つの要素には、ブラウザ標準のスタイル・外部CSSファイル・複数のルールなど、いくつもの指定が同時に降り注いでいます。カスケードとは、それらが重なったときに最終的な値を1つに決めるための仕組み全体を指す言葉です。

カスケードにはいくつかの判定材料がありますが、初心者がまず覚えるべき基本ルールはこれだけです。詳細度（4.4で学びます）が同じ強さのルール同士がぶつかったときは、後に書かれたほうが勝つ。次の例を見てください。

style.css 
/* 2つとも要素セレクタなので詳細度は同じ */
p {
  color: blue;
}

p {
  color: red; /* 後に書かれているのでこちらが採用される */
}

どちらも p という同じ強さのセレクタなので、詳細度では決着がつきません。こういうときにブラウザは「ファイルの下のほうに書かれている＝より新しい指定」とみなし、後のルールを採用します。

この「後に書かれたほうが勝つ」という考え方は、CSSファイルの読み込み順にも当てはまります。<link> タグで複数の外部CSSファイルを読み込んでいる場合、同じ強さのルール同士なら、あとから読み込んだファイルの指定のほうが優先されます。

ただし「順序」が意味を持つのは、あくまで詳細度が同じ場合の最終判定としてです。詳細度そのものに差があれば、書いた順番に関係なく点数の高いほうが常に勝ちます。詳細度の計算方法は4.4で学びます。

4.3 継承

継承とは、親要素に指定したスタイルの一部が、何も指定していない子要素にも自動的に受け継がれる仕組みです。すべてのプロパティが継承されるわけではなく、性質によって「継承されるもの」と「継承されないもの」に分かれています。

継承される（主に文字まわり） 継承されない（主にレイアウトまわり）
color margin
font-family padding
font-size border
line-height background

感覚的には「文字の見た目に関するものは継承されやすく、箱の形やレイアウトに関するものは継承されない」と覚えておくとよいでしょう。もし継承されないプロパティを明示的に親から受け継ぎたい場合は、inherit というキーワードを値に指定します。

style.css 
/* color・font-family・line-height は自動で子要素に伝わる */
body {
  color: #333333;
  font-family: "Noto Sans JP", sans-serif;
  line-height: 1.7;
}

/* border は継承しないプロパティなので、明示的にinheritを指定する */
.child-box {
  border: inherit;
}

この性質を利用すると、文字色やフォントを1つずつの要素に指定する手間が省けます。ページ全体の土台となる body に、まとめて基本の文字スタイルを指定してしまうのが定石です。

重要ポイント: body にまとめると楽になる

見出しや段落1つ1つに font-family や color を書く必要はありません。body に一度指定しておけば、継承によってページ内のほとんどのテキスト要素へ自動的に行き渡ります。あとから個別に上書きしたい要素だけ、別途セレクタを書けば十分です。

4.4 詳細度（Specificity）

詳細度とは、セレクタの「狙いの絞り込み方」がどれだけ強いかを点数化したものです。詳細度に差がある場合は、CSSファイルのどこに書いたかに関係なく、点数が高いルールが常に勝ちます。まずは点数の数え方を押さえましょう。

セレクタの種類 点数 例
IDセレクタ 100点 #header
クラス・擬似クラス・属性セレクタ 10点 .card・:hover
要素セレクタ・擬似要素 1点 div・::before

1つのセレクタに複数の種類が含まれる場合は、その点数を単純に合計します。実際に計算してみましょう。

セレクタ 内訳 合計
p 要素1個 = 1点 1点
.card クラス1個 = 10点 10点
#header ID1個 = 100点 100点
#sidebar .widget h3 ID1個100点 + クラス1個10点 + 要素1個1点 111点

点数の差がはっきりしていれば、あとに書いたかどうかは関係ありません。次の例では、#page-title（100点）を先に書き、.title（10点）を後に書いています。それでも点数の高い #page-title が勝ち、文字色は navy になります。

style.css 
/* 詳細度100点。先に書かれていても、点数が高いので勝つ */
#page-title {
  color: navy;
}

/* 詳細度10点。あとに書いてあるが、点数が低いので負ける */
.title {
  color: seagreen;
}

逆に言えば、4.2で学んだ「後に書いたほうが勝つ」というルールが働くのは、詳細度がまったく同点のときだけです。詳細度と記述順は対等な関係ではなく、詳細度のほうが優先される、という上下関係を覚えておいてください。

4.5 !important

値の末尾に !important を付けると、そのルールは詳細度の計算を無視して強制的に勝つようになります。まさに反則技です。

style.css 
p {
  color: blue !important; /* 詳細度1点でも、importantが付くと最優先になる */
}

#main p {
  color: red; /* 詳細度101点でも、importantには勝てない */
}

便利そうに見えますが、!important は原則として使うべきではありません。理由は次のとおりです。

  • この章で学んだ「カスケード・詳細度」という積み上げのルールを、まるごと無視してしまう
  • あとから上書きしたい人が、さらに強い !important を重ねるしかなくなり、収拾がつかなくなる（!important の潰し合い）
  • 「なぜ効かないのか」の原因調査（4.6）が、詳細度では説明がつかなくなり、格段に難しくなる

基本方針: 原則として使わない

「効かないから !important を付ける」は応急処置であり、根本解決ではありません。まずはセレクタの詳細度を見直し、素直に勝てる書き方を探すことを優先してください。

とはいえ、実務では例外的に許容される場面もあります。JavaScriptでクラスを付け外しして「必ず非表示にする」ユーティリティクラス（.hidden など）や、自分では編集できない外部ライブラリのCSSを、やむを得ず上書きする場合などに限り、チーム内で合意のうえ使われることがあります。「困ったらとりあえず付ける」用途では使わないようにしましょう。

ここまでの4.2〜4.5の内容を1つにまとめると、ブラウザがスタイルを決定するまでの判定は、次の順番で行われています。

flowchart TD A["同じ要素に複数のルールが競合している"] --> B{"importantキーワードが付いたルールがあるか？"} B -->|ある| C["importantキーワードのルールが最優先で勝つ"] B -->|ない| D["各ルールの詳細度を点数で比較する"] D --> E{"点数に差があるか？"} E -->|差がある| F["詳細度が高いルールが勝つ"] E -->|同点| G["CSSファイル内で後に書かれた（後に読み込まれた）ルールが勝つ"]

4.6 効かないときの調べ方

ルールを覚えても、実際のページで「どのルールが勝っているか」を目視で追うのは大変です。ここでブラウザの開発者ツールが力を発揮します。第1章・第2章で開いた開発者ツールを、今度は「効かない原因」を調べる目的で使ってみましょう。

  1. 1 スタイルが効いていない要素の上で右クリックし、「検証」（Inspect）を選んで開発者ツールを開く。
  2. 2 Elementsパネルで対象の要素が選択された状態で、右側の Styles パネルを確認する。
  3. 3 競合して採用されなかったルールには取り消し線（打ち消し線）が表示される。線が付いていない、一番上に表示されているルールが実際に採用されている。
  4. 4 意図したルール自体が一覧に表示されていない場合は、カスケードの問題ではなく、そもそもスタイルが適用されていない可能性が高い。

目当てのルールが Styles パネルにまったく表示されない場合は、カスケード・継承・詳細度以前の問題です。よくある原因は次のとおりです。

よくある見落とし

セレクタのつづり間違い — 例えば HTML側は class="btn-pimary" なのに、CSS側は .btn-primary と書いてしまっている。大文字・小文字の違いやハイフン抜けも同様に一致しなくなります。

ファイルの読み込み失敗 — <link> タグの href のパスが間違っている、ファイル名の拡張子が違う、など。コンソールに404エラーが出ていないか確認しましょう。

ブラウザのキャッシュ — CSSファイルを編集して保存しても、古い内容がキャッシュに残ったままのことがあります。強制再読み込み（Windowsは Ctrl+Shift+R、Macは Cmd+Shift+R）で解決することが多いです。

やってみよう 4-1: 「勝つのはどれ？」を予想してから確認する

同じ要素に対して強さの違う3つのルールを書き、開発者ツールで実際にどれが採用されているかを確認します。予想してから答え合わせをすることが、この実習の一番のポイントです。

手順

  1. 1 練習用のHTMLファイルに <p id="target" class="box">この文字の色は？</p> を1つ用意する。
  2. 2 同じCSSファイルに、下のコードのように要素セレクタ・クラスセレクタ・IDセレクタで、それぞれ違う color を指定する3つのルールを書く。保存してブラウザで開く前に、紙やメモ帳に「何色になると思うか」を予想として書いておく。
  3. 3 ブラウザで実際の色を確認し、予想が当たっていたか答え合わせをする。
  4. 4 開発者ツールの Styles パネルを開き、負けた2つのルールに取り消し線が付いていることを確認する。
style.css 
/* 3つとも同じ p#target.box に効くルール */
p {
  color: green;
}

.box {
  color: blue;
}

#target {
  color: red;
}

予想が外れても問題ありません。むしろ「なぜその結果になったのか」を4.4の点数計算で説明できるようになることが、この実習のゴールです。慣れてきたら、セレクタの組み合わせを変えて何度か試してみましょう。

理解度確認クイズ

  1. Q1. 詳細度がまったく同じ2つのルールが競合したとき、どちらが優先されますか。

    回答を表示

    後に書かれたほうのルールが優先されます。同じCSSファイル内なら下に書かれているルール、複数の外部CSSファイルを読み込んでいる場合は、あとから読み込んだファイルのルールが勝ちます。ただしこれは、あくまで詳細度が同点のときの決着方法です。

  2. Q2. margin は継承されるプロパティですか。理由も含めて説明してください。

    回答を表示

    継承されません。margin や padding・border・background など、要素の箱の形やレイアウトに関わるプロパティは継承されない設計になっており、要素ごとに指定する必要があります。継承されるのは color や font-family など、主に文字の見た目に関するプロパティです。

  3. Q3. 【計算問題】セレクタ #page .btn.primary:hover の詳細度を計算してください。

    回答を表示

    合計130点です。内訳は、IDセレクタ #page が100点、クラスセレクタ .btn と .primary がそれぞれ10点ずつで合計20点、擬似クラス :hover が10点です。100 + 20 + 10 = 130点となります。

  4. Q4. !important を安易に使うべきでない理由を1つ説明してください。

    回答を表示

    詳細度の力関係を無視して強制的に勝ってしまうため、あとから上書きしたい人がさらに強い !important を重ねるしかなくなり、収拾がつかなくなるためです。また、カスケードや詳細度という通常のルールでは説明がつかなくなるので、「効かない」原因の調査も難しくなります。
