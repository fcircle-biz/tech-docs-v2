14.1 完成イメージと今回の題材

今回作るのは、自己紹介ページ（プロフィールページ）です。構成はシンプルで、「ヘッダー（アイコン・名前・肩書き）」「自己紹介文」「スキル一覧」「作品カード」「フッター」の5つのブロックからなる、1枚の縦長ページです。難しい機能は使いません。これまでの章で学んだCSSだけで、ここまで仕上げられることを体感するのが目的です。

先に完成後の雰囲気をつかんでおきましょう。以下は、この教材のスタイルで再現した「完成イメージ」の見本です（実際に手を動かして作るのは、この下にある素のHTML・CSSです）。

山田 太郎

フロントエンドエンジニア

HTML CSS JavaScript

ポートフォリオサイト

タスク管理アプリ

出発点となる素のHTMLは、class属性まですでに書き終えています。CSSがまだ1行も無いので、見た目はかなり素っ気ない状態です。ヘッダーとスキル一覧の部分は、次のようになっています（抜粋）。

index.html（抜粋・ヘッダー＋スキル） 
<header class="profile-header">
  <img src="avatar.jpg" alt="山田太郎" class="avatar">
  <h1 class="name">山田 太郎</h1>
  <p class="tagline">フロントエンドエンジニア／猫と旅が好きです</p>
</header>

<section class="skills">
  <h2>スキル</h2>
  <ul class="skill-list">
    <li class="skill-tag">HTML</li>
    <li class="skill-tag">CSS</li>
    <li class="skill-tag">JavaScript</li>
  </ul>
</section>

続く作品カードの部分は次のとおりです。このあとにコピーライトだけを表示する<footer>が続きますが、中身は<p>1つだけなので、ここでは省略します。

index.html（抜粋・作品カード） 
<section class="works">
  <h2>作品</h2>
  <div class="work-list">
    <article class="work-card">
      <h3>ポートフォリオサイト</h3>

    </article>
    <article class="work-card">
      <h3>タスク管理アプリ</h3>
      <p>日々のToDoを管理するアプリです。</p>

  </div>

ここから先は、次の6つのSTEPで少しずつCSSを重ねていきます。実務でも「土台 → 目立つ部分 → 細部のレイアウト → レスポンシブ → 仕上げ」の順で進めることが多く、行き当たりばったりに書くよりずっと迷いにくくなります。

14.2 STEP1: 下地を作る

いきなりヘッダーを装飾したくなりますが、まずはページ全体の土台を整えます。第13章で学んだCSS変数（カスタムプロパティ）で色やサイズをひとまとめにし、第7章のボックスモデルで登場したbox-sizing: border-boxをすべての要素に適用します。ここを先に決めておくと、この先のSTEPで数値がぶれません。

style.css（STEP1・その1） 
/* テーマカラーと共通の余白をCSS変数にまとめておく */
:root {
  --main-color: #6366f1;
  --text-color: #1e293b;
  --bg-color: #f8fafc;
  --spacing: 16px;
  --radius: 12px;
}

/* すべての要素でpadding・borderをwidthに含める */
*, *::before, *::after {
  box-sizing: border-box;
}

続けて、ページ全体の基本スタイルをbodyに指定します。フォント・行の高さ・文字色・背景色という「読みやすさの土台」を、最初に一度だけ決めてしまう考え方です（第5・6章の復習です）。

style.css（STEP1・その2） 
/* ページ全体の基本スタイル（読みやすさの土台） */
body {
  font-family: "Noto Sans JP", sans-serif;
  line-height: 1.7;
  color: var(--text-color);
  background-color: var(--bg-color);
  margin: 0;
}

なぜ最初にCSS変数を決めるのか

この先のSTEPでは、色を指定するたびにvar(--main-color)のように変数を呼び出します。こうしておけば、最後に「テーマ色を変えたい」と思ったとき、:rootの1行を直すだけでページ全体の色が変わります（第13章の内容そのものです）。

14.3 STEP2: ヘッダーを整える

次はページの「顔」であるヘッダーです。text-align: centerで中身を中央寄せにし、アイコン画像はborder-radius: 50%で正方形から円形に切り抜きます。正方形の画像を丸くするのは、プロフィールページの定番テクニックです。

style.css（STEP2・その1） 
/* ヘッダー全体を中央寄せにする */
.profile-header {
  text-align: center;
  padding: 48px 16px;
  background-color: #eef1ff;
}

/* 正方形の画像を円形に切り抜く */
.avatar {
  width: 120px;
  height: 120px;
  border-radius: 50%;
  object-fit: cover;
}

object-fit: coverは、画像の縦横比を保ったまま指定した枠いっぱいに敷き詰めるプロパティです。これを付けないと、正方形でない画像を使ったときに丸が楕円につぶれてしまいます。最後に、名前と肩書きの文字スタイルを整えましょう（第5章の復習です）。

style.css（STEP2・その2） 
/* 名前を大きく、肩書きは控えめな色にする */
.name {
  font-size: 1.75rem;
  margin: 8px 0 4px;
}

.tagline {
  color: #64748b;
  font-size: 0.95rem;
}

ここまでで、ヘッダー部分だけはひとまず完成した見た目になります。imgタグのalt属性（HTML側で設定済み）は、画像が読み込めなかったときの代替テキストであると同時に、スクリーンリーダーが読み上げる内容でもあります。CSSで見た目を整えるときも、HTML側のこうした配慮を消さないようにしましょう。

14.4 STEP3: スキル一覧をFlexboxで

スキル一覧は「横に並べて、入りきらなければ折り返す」タグの集まりです。これはまさに第9章で学んだFlexboxの出番です。display: flexとflex-wrap: wrapを組み合わせ、gapでタグ同士の間隔を空けます。

style.css（STEP3・その1） 
/* タグを横並びにし、幅が足りなければ折り返す */
.skill-list {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
  list-style: none;
  padding: 0;
  justify-content: center;
}

list-style: noneで箇条書きの黒丸を消し、padding: 0でブラウザ標準の字下げをリセットしています。これで<ul>を「見た目はタグの集合」として使えるようになります。あとは1つ1つのタグをピル型に整えるだけです。

style.css（STEP3・その2） 
/* 個々のタグをピル型のボタン風にする */
.skill-tag {
  background-color: var(--main-color);
  color: #fff;
  padding: 6px 14px;
  border-radius: 9999px;
  font-size: 0.85rem;
}

border-radius: 9999pxのように、高さより大きい数値を指定すると、四隅が最大限に丸まって「ピル（カプセル）型」になります。角丸を扱う小技として覚えておくと便利です。

14.5 STEP4: 作品カードをGridで

作品カードは「行」と「列」の両方を意識したい並びなので、第10章で学んだCSS Gridの出番です。特にrepeat(auto-fit, minmax(240px, 1fr))は、カードの並ぶ数を画面幅に応じて自動で増減させてくれる、実務でも頻出の書き方です。

style.css（STEP4） 
/* カードを自動で折り返すグリッドに並べる */
.work-list {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: var(--spacing);
  padding: 0 16px 48px;
}

/* カード自体の見た目 */
.work-card {
  background-color: #fff;
  border: 1px solid #e2e8f0;
  border-radius: var(--radius);
  padding: 20px;
}

minmax(240px, 1fr)は「1枚あたり最低240px、余ったスペースは均等に広げる」という意味です。auto-fitと組み合わせることで、画面が広ければ3〜4列、狭ければ1〜2列と、メディアクエリを書かなくても自動で列数が変わります。次のSTEP5では、この仕組みだけではカバーしきれない部分（文字サイズや余白）をメディアクエリで調整します。

14.6 STEP5: レスポンシブ対応

第11章で学んだモバイルファーストの考え方を適用します。まず何も指定しない状態（＝スマートフォンなど小さい画面）を基準に控えめなサイズを指定し、@media (min-width: ...)で「画面が広いときだけ」大きく調整します。STEP2で決めた.nameの文字サイズを、この考え方で整理し直しましょう。

style.css（STEP5） 
/* 基本（スマホなど小さい画面）は控えめなサイズ */
.name {
  font-size: 1.4rem;
}

/* 画面幅が600px以上ならPC向けに拡大する */
@media (min-width: 600px) {
  .name {
    font-size: 1.75rem;
  }
  .profile-header {
    padding: 64px 16px;
  }
}

viewportの指定を忘れずに

メディアクエリを書いても、HTMLの<head>に<meta name="viewport" content="width=device-width, initial-scale=1.0">が無いと、スマートフォンでは縮小表示されてレスポンシブが効いているように見えません（第11章の復習）。自分のファイルを作るときは、必ずこの1行を入れましょう。

14.7 STEP6: 仕上げの装飾

最後の一手間です。第12章で学んだbox-shadowで作品カードに軽い影を付け、マウスを乗せたときにtransformでふわっと持ち上がる動きをtransitionで滑らかにします。

style.css（STEP6） 
/* カードに影を付けて浮かび上がらせる（STEP4の.work-cardに追記）*/
.work-card {
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.08);
  transition: transform 0.2s, box-shadow 0.2s;
}

/* マウスを乗せたときに少し持ち上げる */
.work-card:hover {
  transform: translateY(-4px);
  box-shadow: 0 8px 20px rgba(0, 0, 0, 0.12);
}

transitionを付けているのは.work-card側であることに注意してください。「変化のきっかけ」である:hover側ではなく、「通常時の状態」にtransitionを書くのが基本の型でした（第12章の復習）。0.2秒程度の短い時間にとどめ、動きを付けすぎないこともアクセシビリティの観点から大切です。

14.8 完成とチェックリスト

STEP6まで終えたら、プロフィールページの完成です。ここで終わりにせず、開発者ツール（F12）を開いて最終確認をする習慣を付けましょう。プロの現場でも、書いて終わりではなく「確認して終わり」が基本です。

最終チェックリスト

  • 余白・枠線 — 要素を選択し「ボックスモデル」パネルで、余白や枠線が意図どおりか確認した（第7章）
  • レスポンシブ — デバイスツールバーでスマホ幅・タブレット幅・PC幅それぞれの見た目を確認した（第11章）
  • コントラスト — 文字色と背景色の組み合わせが薄すぎず、読みやすいか確認した（第6章）
  • hoverの動き — 作品カードにマウスを乗せたとき、動きが唐突すぎないか確認した（第12章）
  • コンソール — 「Console」タブに赤いエラーが出ていないか確認した

14.9 これからの学習ステップ

素のCSSでページを組み立てられるようになったあなたなら、次の4つのどれに進んでも、きっとスムーズに理解できます。焦らず、興味を持てそうなものから触れてみてください。

JavaScript（動きを付ける）

クリックでメニューを開閉する、入力内容をその場でチェックするなど、CSSだけでは実現できない「動き」を付けられるようになります。

CSSフレームワーク

この教材のページ自体にも使われているTailwind CSSや、コンポーネント指向のBootstrapを学ぶと、素のCSSの知識を土台にぐっと効率よく開発できます。

CSS設計・Sass

BEMのようなクラス命名ルールや、変数・入れ子記法が使えるSassを学ぶと、ページ数が増えても崩れにくく保守しやすいCSSを書けます（第13章の発展です）。

自分のサイトを公開する

GitHub Pagesなどの無料サービスを使えば、今日作ったプロフィールページをそのままインターネットに公開できます。人に見てもらうと、学習のモチベーションがぐっと上がります。

やってみよう 14-1: オリジナルのプロフィールページにしよう

完成したページは、あくまで「山田太郎さん」のサンプルです。すべて自分の情報に差し替えて、世界に1つだけのページに仕上げましょう。

手順

  1. 1 名前・肩書き・自己紹介文・スキル・作品を、自分自身の情報にすべて書き換える。
  2. 2 アイコン画像を自分の写真やイラストに差し替える（用意できない場合は、仮の画像でも構いません）。
  3. 3 :rootの--main-colorを好きな色に変更し、テーマ全体の印象を変える。
  4. 4 作品カードの数を増やしたり減らしたりして、Gridの自動折り返しがどう変化するか観察する。

色を変えるだけで印象がガラッと変わることに驚くはずです。うまくいかない箇所があれば、対応する章に戻って読み返してみましょう。それも立派な学習です。

理解度確認クイズ

  1. Q1. 今回のプロフィールページ制作は、「下地」「ヘッダー」「スキル一覧」「作品カード」「レスポンシブ」「仕上げ」という順番で進めました。この順番にはどのような利点がありますか。

    回答を表示

    土台（変数・リセット・基本スタイル）を先に決めてから、目立つ部分、細部のレイアウト、画面サイズ対応、装飾という順に進めることで、後戻りが少なく迷いにくくなります。先に細部を装飾すると、後で土台を直したときに全体が崩れやすくなってしまいます。

  2. Q2. STEP1でbox-sizing: border-boxを全要素に指定しました。これを指定しておくと、あとの余白調整がなぜ楽になるのでしょうか（第7章の復習）。

    回答を表示

    border-boxでは、paddingとborderの分がwidth・heightの中に含まれます。指定していないと「幅を100pxにしたのに、paddingを足したら想定より大きくなった」という事故が起きますが、border-boxならその心配がなく、要素の外側サイズを一定に保ったまま安心して余白を調整できます。

  3. Q3. スキル一覧にはFlexbox、作品カードにはCSS Gridを使いました。それぞれをどのような基準で使い分けましたか（第9・10章の復習）。

    回答を表示

    Flexboxは「1列（1方向）に並べて、入りきらなければ折り返す」ような1次元的な配置に向いているため、タグの一覧に使いました。CSS Gridは「行と列の両方」を意識して敷き詰める2次元的な配置に向いているため、repeat(auto-fit, minmax(...))で自動的に列数が変わるカード一覧に使いました。

  4. Q4. このガイドを終えたあと、次に学んでみたいテーマを1つ挙げ、それを学ぶとどんなことができるようになるか説明してください。

    回答を表示

    例: JavaScriptを学ぶと、クリックでメニューを開閉するなど「動き」を付けられるようになります。CSS設計手法（BEM）やSassを学ぶと、ページ数が増えても崩れにくく保守しやすいCSSを書けるようになります。CSSフレームワークを学ぶと、効率よくデザインを組み立てられるようになります（この設問に決まった正解はありません。自分の言葉で書けていれば十分です）。
