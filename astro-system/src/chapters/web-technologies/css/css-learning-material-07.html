ボックスモデル

ボックスモデルは、CSS の中でももっとも重要な概念です。すべての HTML 要素は、内容（content）・パディング・ボーダー・マージンという4層の「箱」として扱われています。「余白が思いどおりにならない」「幅がなぜかずれる」といった CSS のつまずきの9割は、実はこのボックスモデルの理解不足が原因です。図解と実習で、しっかり体に染み込ませていきましょう。

この章で学ぶこと

  • すべての HTML 要素が四角い「箱」であることを理解し、開発者ツールで確認できる
  • ボックスモデルの4層（content・padding・border・margin）をそれぞれ説明できる
  • padding・margin・border の値の書き方（1〜4値指定、個別指定）を使い分けられる
  • box-sizing: border-box を使う理由と、width が実際の幅に与える影響を計算できる
  • マージンの相殺と margin: 0 auto による中央寄せの仕組みを理解する

7.1 すべての要素は「箱」でできている

CSS でレイアウトを組んでいくと、「なぜ思った位置に配置できないのか」「余白がなぜかズレる」と悩む場面が必ず出てきます。その答えのほとんどは、この章で学ぶボックスモデルという考え方の中にあります。まずは大原則を確認しましょう。ブラウザは、HTML のすべての要素を四角形の「箱」として扱います。

見出し・段落・画像・ボタン・丸いアイコン — 見た目がどんな形であっても、CSS の計算上はすべて長方形の箱として位置とサイズが決まります。たとえば border-radius で角を丸めても、それは「見た目」が丸くなるだけで、要素が実際に占有するスペースは角丸になる前の四角形のままです。

開発者ツールで箱を確認する

要素を選択した状態で開発者ツール（F12）の「Computed（算出済みスタイル）」タブを開くと、その要素の content・padding・border・margin の実際の数値が、入れ子になった図として表示されます。この図こそ、この章で解説する「ボックスモデル」そのものです。迷ったら、まずこの図を見る習慣をつけましょう。

それでは、この「箱」がどんな4つの層でできているのか、順番に見ていきましょう。

7.2 ボックスモデルの4層

1つの要素の「箱」は、内側から外側に向かって次の4つの層が重なってできています。役割がまったく違うので、しっかり区別しましょう。

層 役割 背景色
content（内容） テキストや画像など、実際の中身が入る領域 表示される
padding（パディング） 内容とボーダーの間の「内側の余白」 表示される（content と同じ背景が続く）
border（ボーダー） 箱を囲む枠線そのもの 線自体に色を付けられる
margin（マージン） 箱の外側、他の要素との間隔 常に透明

次のようなお知らせカードを例に考えてみましょう。

card.html 
<div class="card">
  <h3>お知らせ</h3>
  <p>明日 10:00 よりメンテナンスを行います。</p>
</div>

この .card にスタイルを当てていくと、外側から順に margin → border → padding → content という入れ子構造になります。図にすると、次のようなイメージです。

margin（外側の余白・常に透明）

border（枠線）

padding（内側の余白）

content（内容）

重要ポイント

背景色が見えるのは content と padding です。margin は常に透明で、他の要素との間隔をあけるためだけに存在します。border は枠線そのものに独立した色を付けられます。この違いを覚えておくと、次章以降の配置調整がぐっと楽になります。

7.3 padding と margin の書き方

padding と margin は、どちらも上下左右の4方向をまとめて指定できます。指定する値の数によって、どの辺に適用されるかが変わるので、パターンを覚えてしまいましょう。

値の数 適用される順序 例
1つ 上下左右すべて同じ padding: 10px;
2つ 上下 / 左右 padding: 10px 20px;
3つ 上 / 左右 / 下 padding: 10px 20px 15px;
4つ 上 → 右 → 下 → 左（時計回り） padding: 10px 20px 15px 20px;
spacing.css 
/* 4値：上 右 下 左（時計回り） */
.box-a { padding: 10px 20px 15px 20px; }

/* 2値：上下 左右 */
.box-b { padding: 10px 20px; }

/* 1値：上下左右すべて同じ */
.box-c { margin: 16px; }

/* 個別指定：上だけ変えたいとき */
.box-d { margin-top: 32px; }

4方向まとめて書けるほか、padding-top・padding-right・margin-bottom のように、1辺だけを個別に指定するプロパティも用意されています。「他は変えず、上だけ広げたい」といったときはこちらが便利です。

padding と margin は書き方こそ似ていますが、使いどころは正反対です。padding は「箱の内側」の余白なので、背景色やボーダーの内側に空間を作りたいとき（文字が枠線にくっつかないようにするなど）に使います。margin は「箱の外側」の余白なので、要素どうしの間隔をあけたいとき（カードとカードの間を空けるなど）に使います。

7.4 border（ボーダー）

border は、箱の周囲を囲む枠線です。padding と content の外側、margin の内側に位置します。よく使うのは、太さ・線種・色をまとめて指定するショートハンド記法です。

border.css 
/* ショートハンド：太さ → 線種 → 色 の順 */
.card {
  border: 1px solid #cccccc;
}

/* 上だけ強調したいときは個別指定 */
.card-highlight {
  border-top: 4px solid #f97316;
  border-right: 1px solid #cccccc;
  border-bottom: 1px solid #cccccc;
  border-left: 1px solid #cccccc;
}

border: 1px solid #ccc; は「太さ 1px・線種 solid（実線）・色 #ccc」の3つをスペース区切りで指定しています。線種にはほかに dashed（破線）・dotted（点線）・none（線なし・初期値）などがあります。padding や margin と同様に、border-top のように1辺だけを個別に指定することもできます。

7.5 width / height と実際の見た目の幅

ここが、ボックスモデルで一番つまずきやすいポイントです。次の CSS を見てください。

content-box.css（box-sizing 未指定＝初期値） 
.card {
  width: 200px;
  padding: 10px;
  border: 5px solid #333333;
}
/* 実際の見た目の幅 = 200 + (10×2) + (5×2) = 230px */

width: 200px と指定したのに、実際にブラウザ上で占める幅は 200px ではありません。初期値の box-sizing: content-box では、width はあくまで「content の幅」であり、padding と border はそこに追加して計算されるからです。計算すると 200(content) + 10×2(padding左右) + 5×2(border左右) = 230px になります。

デザインどおりの幅にするたびにこの計算をするのは大変です。そこで使うのが box-sizing プロパティです。これは「width に何を含めて計算するか」というルールそのものを切り替える指定です。

border-box.css 
.card {
  box-sizing: border-box;
  width: 200px;
  padding: 10px;
  border: 5px solid #333333;
}
/* 実際の見た目の幅 = 200px のまま */

box-sizing: border-box にすると、padding と border が width の内側に含まれるようになります。つまり width: 200px と書けば、padding や border を足しても常に 200px のまま。非常に直感的なので、多くの実務サイトが最初に次の1行を書いて、全要素の計算方法を統一しています。

reset.css 
/* サイトの最初に書く定番のリセット */
*,
*::before,
*::after {
  box-sizing: border-box;
}

迷ったら border-box

多くの CSS フレームワークやリセット CSS は、この *, *::before, *::after { box-sizing: border-box; } を最初に書きます。この教材でも、この後の章からはこの前提で説明を進めます。

7.6 マージンの相殺

margin には、他の CSS プロパティにはない不思議な性質があります。上下方向に隣り合う margin どうしが重なり合い、大きいほうの値だけが適用されるという現象で、マージンの相殺（マージンの結合）と呼ばれます。

margin-collapse.css 
h2 {
  margin-bottom: 30px;
}
p {
  margin-top: 20px;
}
/* 隣り合う間隔は 30+20=50px ではなく、大きい方の 30px */

この例では h2 の margin-bottom（30px）と、直後の p の margin-top（20px）が隣り合っています。合計の 50px ではなく、大きいほうの 30px だけが実際の間隔になります。

相殺が起きるのは上下方向のみで、左右の margin では起きません。また、間に padding や border がある場合や、Flexbox・Grid のアイテムどうしでは相殺は起こりません（第9章・第10章で学ぶレイアウトでは、この現象自体をあまり意識しなくて済みます）。

覚えておくコツ

縦方向の間隔調整で「思ったより狭い」と感じたら、まず相殺を疑いましょう。上下どちらか一方（たとえば margin-bottom だけ）に指定を統一すると、相殺で悩むことがぐっと減ります。

7.7 margin: 0 auto による中央寄せ

margin は、ブロックレベル要素を横方向の中央に寄せる定番テクニックにも使われます。それが margin: 0 auto です。

center.css 
/* 幅を指定してから、左右マージンを auto にする */
.container {
  width: 800px;
  margin: 0 auto;
}

auto は「余ったスペースを自動計算して埋める」という指定です。左右の margin を両方 auto にすると、ブラウザが余白を左右均等に配分するため、結果として要素が中央に寄って見えます。

中央寄せに必要な2つの条件

① 要素がブロックレベル要素であること（display: block など）。② width に具体的な値（px や % など）が指定されていて、左右に余るスペースが生まれること。width を指定せず margin: 0 auto だけを書いても、要素が横幅いっぱいに広がってしまい、中央寄せの効果は現れません。

やってみよう 7-1: box-sizing で幅がどう変わるか確認しよう

エディタとブラウザを使い、padding・border・margin を付けたカードが、box-sizing の有無で実際の幅がどう変わるかを開発者ツールの数値で確認します。

手順

  1. 1 HTML に div を1つ用意し、CSS で width: 200px・padding: 20px・border: 5px solid #333 を指定する（box-sizing はまだ指定しない）。
  2. 2 ブラウザで開いて F12 で開発者ツールを開く。要素を選択し「Computed（算出済みスタイル）」タブでボックスモデルの図を確認する。実際の幅が 200px より大きくなっていることを確かめよう。
  3. 3 その div に box-sizing: border-box; を追加する。Computed タブのボックスモデル図を見て、幅がどう変わったか確認しよう。
  4. 4 さらに margin: 20px; を追加し、隣に置いたもう1つの div との間隔がどう変わるかも観察してみよう。

Computed タブのボックスモデル図は、この章で学んだ4層の図そのものです。数値を実際に見比べることで、content-box と border-box の違いが体に入ります。

理解度確認クイズ

  1. Q1. ボックスモデルの4層を、内側（中心）から外側に向かって正しい順に並べてください。

    回答を表示

    content（内容）→ padding（パディング）→ border（ボーダー）→ margin（マージン）の順です。中心にあるのが実際の中身（content）で、そこから外側に向かって内側の余白・枠線・外側の余白が層になっています。

  2. Q2. 次の CSS が指定された要素があります（box-sizing 未指定＝初期値の content-box）。この要素が実際にブラウザ上で占める横幅は何 px になるでしょうか。
    width: 300px／padding: 15px／border: 5px solid

    回答を表示

    340px です。content-box（初期値）では width はあくまで content の幅を表し、padding と border はその外側に追加されます。300（content）＋ 15×2（padding左右）＋ 5×2（border左右）＝ 340px となります。もし box-sizing: border-box を指定していれば、300px のままになります。

  3. Q3. 「マージンの相殺」とはどのような現象で、どの方向で起こりますか。

    回答を表示

    上下方向に隣り合う margin どうしが重なり合い、合計ではなく大きいほうの値だけが実際の間隔として適用される現象です。左右方向の margin では発生しません。

  4. Q4. margin: 0 auto で要素を中央寄せするには、どんな条件が必要ですか。

    回答を表示

    ①要素がブロックレベル要素であること、②width に具体的な値（px や % など）が指定されていて、左右に余るスペースがあることの2つが必要です。width を指定しないまま margin: 0 auto だけを書いても、要素が横幅いっぱいに広がるため中央寄せの効果は現れません。
