ホーム Apache Superset 第8章
第8章 所要時間: 約70分

チャートを作る（Explore入門）

前章までで、データセットに列とメトリクスという土台を整えました。この章では、その土台を使って実際に1枚のチャートを作る画面「Explore」を操作します。ディメンション（分ける軸）とメトリクス（測る値）を組み合わせてグラフを描き、フィルタや件数制限で見やすく絞り込み、最後は保存してダッシュボードに追加するところまでを一通り体験します。

この章で学ぶこと

  • Explore画面の3つの領域（データパネル・設定パネル・プレビュー）の役割を理解し、Create chart で再描画できる
  • ディメンション（分ける軸）とメトリクス（測る値）の違いを、SQLのGROUP BYと集計関数に結び付けて説明できる
  • 時間の粒度・時間範囲・フィルタ・並び替え・件数制限を設定し、意図した集計結果を得られる
  • View query で生成されたSQLを確認する習慣を身に付け、チャートを保存してダッシュボードに追加できる

8.1 Explore とは

Explore は、1つのデータセットを対象にチャートを1枚作るための画面です。第1章で確認した「Database接続 → Dataset → Chart → Dashboard」という積み上げの中で、ちょうど Dataset と Chart をつなぐ役割を担います。開き方は主に2通りあります。

  • データセット一覧から開く — Datasets 画面でデータセット名をクリックすると、そのデータセットを対象にした Explore がそのまま開きます。
  • チャート一覧から開く — Charts 画面の + Chart ボタンから、対象のデータセットとチャート種別（Visualization Type）を選んで開きます。

どちらの入口から開いても、たどり着く画面は同じです。違うのは「データセットを先に決めるか、チャートを作る意図を先に持つか」という順番だけだと考えてください。

前の章とのつながり

Exploreで選べる列やメトリクスは、第6章でデータセットに設定した列と、第7章で定義したメトリクスがそのまま候補として並びます。土台を丁寧に作っておくほど、この画面での作業は迷いなく進みます。もし欲しい列やメトリクスが見当たらない場合は、Exploreを疑う前にデータセットの設定に戻って確認しましょう。

8.2 画面の3つの領域

Explore の画面は、どの入口から開いても同じ3つの領域で構成されています。左右中央の役割を先に押さえておくと、後の節で迷わなくなります。

左: データパネル

対象データセットの列とメトリクスの一覧。検索して探し、ドラッグや選択で中央の設定欄に配置します。

中央: 設定パネル

Data タブと Customize タブがあり、チャートの中身と見た目を設定します。

右: プレビュー

実際に描画されたチャート。設定を変えても、ここは自動更新されません。

中央の設定パネルはさらに2つのタブに分かれます。Data タブでは「何を描くか」（チャート種別・時間設定・ディメンション・メトリクス・フィルタなど）を、Customize タブでは「どう見せるか」（凡例・配色・ラベルなど）を設定します。Customizeタブは8.7で扱います。

flowchart LR A["Dataタブで設定
（ディメンション・メトリクス・フィルタ等）"] --> B["Create chart を押す"] B --> C["Supersetが SQL を生成・発行"] C --> D["接続先DBが集計"] D --> E["結果をプレビューに描画"] E -.->|"設定を変更したら"| B

設定は自動反映されない

ディメンションやフィルタを変えただけでは、右のプレビューは更新されません。変更のたびに Create chart（既存のチャートを編集している場合は Update chart と表示されます）を押して、あらためて実行する必要があります。

8.3 ディメンションとメトリクス

Explore で設定する項目の大半は、ディメンション（分ける軸）とメトリクス（測る値）という2つの役割のどちらかに分類できます。ディメンションは「何ごとに分けて見るか」、メトリクスは「その中で何を数字として測るか」です。同じデータでも、ディメンションを変えるだけでまったく違う問いに答えられます。

ディメンション（軸） メトリクス（値） 答えられる問い
注文月 売上高（SUM） 売上は月ごとにどう推移しているか
商品カテゴリ 売上高（SUM） どのカテゴリの売上が大きいか
都道府県 注文件数（COUNT） どの地域からの注文が多いか

「メトリクスは固定して、ディメンションだけ差し替える」という発想を持てると、Exploreでの試行錯誤がぐっと速くなります。同じ「売上高」というメトリクスでも、軸を月にすれば推移が、カテゴリにすれば内訳が見えてきます。

SQLで言うと

ディメンションは GROUP BY に並ぶ列、メトリクスは SUM や COUNT のような集計関数に対応します。第7章で「メトリクスは集計式」と学んだことを思い出すと、Exploreの画面構成がそのままSQLの構造を表していることが分かります。

8.4 時系列チャートを作る

最初に作る1枚として定番なのが、時間の推移を見る折れ線グラフです。ここでは「時間軸となる列」を指定する必要がある点が、8.3までのディメンション・メトリクスの話に加わります。

  1. 1 + Chart からデータセットを選び、チャート種別に折れ線グラフ（Line Chart）を選ぶ。
  2. 2 X-AXIS に、時間軸に使う列（第6章でデータセットの時間カラムとして設定した列）を指定する。
  3. 3 X-AXISに時間列を指定するとTime grain（時間の粒度）が選べるようになる。日ごとの動きを見たいなら「日」、全体の傾向をつかみたいなら「月」を選ぶ。
  4. 4 Filters セクションの時間フィルタで、対象期間を設定する。「直近1年」のような相対指定と、開始日・終了日を直接指定する方法がある（詳しくは8.5で扱う）。
  5. 5 METRICS に、測定したい値（例: 第7章で定義した「売上高」）を追加する。
  6. 6 Create chart を押して描画する。粒度や範囲を変えるたびに、この操作が必要になる。

同じデータでも、Time grainを変えると見え方は大きく変わります。日次にすると曜日や日ごとの細かい増減（ノイズ）が目立ち、月次にすると全体の傾向（伸びているか、縮んでいるか）が見えやすくなります。まずは大きい単位で傾向をつかみ、気になる時期があれば粒度を細かくして原因を探る、という順番がおすすめです。

8.5 絞り込み・並び替え・件数制限

ディメンションとメトリクスを置いただけでは、対象範囲が広すぎたり、順序が意図と違ったりすることがあります。Data タブの残り4つの設定で、チャートを見やすい形に絞り込みます。

設定項目 何を制御するか 未設定・大きすぎるとどうなるか
Filters 対象行の絞り込み（列＋演算子＋値） 関係ないデータまで集計に混ざり、数字がぼやける
Sort by 結果の並び順 上位・下位が探しにくく、読み手が自分で並べ替える手間が生じる
Row limit クエリが返す行数の上限 データ量が多いと表示が遅くなったり、途中で切れたりする
Series limit チャートに表示する系列（線・棒など）の本数上限 カテゴリ数が多いと凡例が埋まり、グラフ自体が読めなくなる

8.4 で設定した時間範囲も、実はこの Filters の一部です。時間の絞り込みと、それ以外の列に対する絞り込みは、どちらも同じ Filters セクションにまとまっている、と理解しておくと画面を探すときに迷いません。

Filters でよく使う演算子には、次のようなものがあります。

  • Equal to（=） — 指定した1つの値に一致する行だけを対象にする（例: ステータスが「完了」）。
  • IN — 複数の値のいずれかに一致する行を対象にする（例: カテゴリが「家電」または「食品」）。
  • Greater than or equal（以上） — しきい値以上の行を対象にする（例: 注文金額が1000円以上）。
  • LIKE — 部分一致で絞り込む（例: 商品名に「Pro」を含む）。

8.6 生成されたSQLを確認する

第1章で確認したとおり、Superset はチャートを描画するたびに接続先データベースへ SQL を発行します。つまり Explore で設定した内容は、必ず1本の SQL に翻訳されています。発行された SQL やクエリ結果は、次の3つの方法で確認できます。

  • View query（チャート右上の ... メニュー内）— 実際に発行された SQL 文そのものを表示する。
  • Results（チャート下端の折りたたみデータパネル内のタブ）— そのクエリを実行した結果（集計後の行）を表形式で確認する。
  • Samples（チャート下端の折りたたみデータパネル内のタブ）— 集計前の元データを数行だけ抜き出して確認する。データセットの中身を素の状態で見たいときに使う。

例えば「月次の売上高」を時間範囲とRow limitを添えて集計すると、Supersetはおおよそ次のようなSQLを組み立てます。

生成されるSQLのイメージ 
-- Exploreが生成するSQLのイメージ（月次の売上高、期間・件数を絞り込み）
SELECT
    DATE_TRUNC('month', order_date) AS "注文月",  -- ディメンション（Time grain=月で丸めた時間列）
    SUM(amount) AS "売上高"                        -- メトリクス（集計関数）
FROM sales
WHERE order_date >= '2024-01-01'                   -- Time rangeによる絞り込み
  AND order_date < '2025-01-01'
GROUP BY DATE_TRUNC('month', order_date)            -- ディメンションがそのままGROUP BYに
ORDER BY "注文月" ASC
LIMIT 10000;                                        -- Row limit

列名やテーブル名は例です。実際に生成されるSQLの書き方は、接続先データベースの種類（時間の丸め方の関数など）やSupersetのバージョンによって異なる場合があります。ここでは「ExploreでのGUI操作が、どのようにSQLへ翻訳されるか」という考え方のイメージとして示しています。また、実際の Superset は時間軸の列を __timestamp という内部的な名前でエイリアスして生成することが多く、View query で見るSQLでは列名がこの例より事務的な表記になります。

思った数字と違うときは、必ずSQLを見る

チャートの数字が想定と合わないとき、最初に開くべきは設定パネルではなくView queryです。フィルタの条件を書き間違えている、GROUP BYの列が意図と違う、期間の指定がずれている——こうした原因の多くは、SQLを一目見れば分かります。「Supersetは都度SQLを発行する」という第1章の性質を、ここで実際の操作習慣に変えましょう。

8.7 Customizeタブで見た目を整える

データが正しく集計できていることを確認できたら、Customize タブで見た目を整えます。ここは「正しさ」ではなく「伝わりやすさ」を調整する場所です。

設定 効果 使いどころ
凡例（Legend） 系列名の一覧を表示・位置を調整 系列（線や棒の種類）が2つ以上あるとき
カラースキーム 系列ごとの配色を切り替え ダッシュボード内の他のチャートと統一したいとき
軸ラベル X軸・Y軸に説明文を表示 列名だけでは単位や意味が伝わりにくいとき
数値フォーマット 桁区切り・小数の桁数・％表示などを指定 大きな金額や比率を読みやすくしたいとき
データラベル 棒や点のすぐ上に値そのものを表示 系列や項目数が少なく、正確な値まで見せたいとき

装飾より読みやすさ

Customizeタブには多くの設定項目がありますが、すべてを使う必要はありません。優先すべきは、桁区切りや単位を正しく表示する数値フォーマットと、系列が何を表すか一目で分かる凡例です。色を凝りすぎたりデータラベルを詰め込みすぎたりすると、かえって読みにくくなります。

8.8 保存とダッシュボードへの追加

SQLの内容と見た目の両方に納得できたら、チャートを保存します。画面右上の Save ボタンを押すと、チャート名を入力するダイアログが開きます。

  • チャート名を付けて保存 — 後から一覧で探しやすいよう、「何を・どの軸で見ているか」が分かる名前を付ける（例: 「月次売上推移」）。
  • ダッシュボードへの同時追加 — 保存ダイアログの Add to dashboard 欄で既存のダッシュボードを指定するか、新規ダッシュボード名を入力すれば、保存と同時にそのダッシュボードへ追加できる（画面構成はバージョンによって異なる場合がある）。
  • Save as で複製 — 既存のチャートを開いた状態で Save as を使うと、元のチャートを残したまま別名で複製できる。「同じデータをチャート種別だけ変えて比べたい」ときに便利。

次の第9章では、今回使った折れ線・棒グラフ以外のチャート種別を、目的に応じてどう選べばよいかを整理します。

やってみよう 8-1: 月次売上とカテゴリ別売上のチャートを作る

第7章で定義したメトリクスを使って、実際に2枚のチャートを作成・保存します。作った後は必ずSQLを確認し、Exploreでの設定がSQLのどこに現れているかを自分の目で確かめましょう。

手順

  1. 1 Explore を開き、折れ線グラフ（Line Chart）を選ぶ。X-AXISに時間列を指定し、Time grainを「月」に設定して、メトリクスに「売上高」を追加してから Create chart を実行する。
  2. 2 Save で「月次売上推移」のような名前を付けて保存する。既存または新規のダッシュボードを指定して同時に追加する。
  3. 3 もう一度 + Chart から棒グラフ（Bar Chart）を選び、ディメンションに「カテゴリ」、メトリクスに「売上高」を設定する。Row limitをカテゴリ数に見合った値に絞り、実行する。
  4. 4 こちらも「カテゴリ別売上」のような名前を付けて保存する。
  5. 5 2枚それぞれの ... メニューから View query を開き、生成されたSQLの GROUP BY に何が入っているかを確認する。

解答の目安

① 月次売上の時系列チャート — 時間列: 第6章で設定した時間カラム／Time grain: 月／ディメンション: なし（時間軸のみ）／メトリクス: 売上高（SUM）／Row limit: 既定値のままで十分（月数はどれだけ長くても数十行程度）。

② カテゴリ別売上の棒グラフ — 時間列: 使わない、または全期間を対象にする／ディメンション: カテゴリ列／メトリクス: 売上高（SUM）／Row limit: カテゴリの種類数に応じて20〜50件程度に絞る。

View query を開くと、①では時間列を丸めた式が、②ではカテゴリ列が GROUP BY に入っているはずです。もし売上高（メトリクス側）が GROUP BY に混ざっていたら、ディメンションとメトリクスの設定を取り違えています。

理解度確認クイズ

  1. Q1. Explore画面の3つの領域を挙げ、それぞれ何を扱うか説明してください。

    回答を表示

    左（データパネル）はデータセットの列とメトリクスの一覧、中央（設定パネル）はData／Customizeタブでの設定、右（プレビュー）は描画結果です。設定を変えても右は自動更新されないため、Create chartを押して再実行する必要があります。

  2. Q2. ディメンションとメトリクスの違いを、SQLの用語を使って説明してください。

    回答を表示

    ディメンションは「分ける軸」で、SQLのGROUP BYに並ぶ列に対応します。メトリクスは「測る値」で、SUMやCOUNTなどの集計関数に対応します。同じメトリクスでも、ディメンションを変えると答えられる問いが変わります。

  3. Q3. Row limitとSeries limitは、それぞれ何を制限するものですか？

    回答を表示

    Row limitはクエリが返す行数の上限、Series limitはチャートに表示する系列（線や棒の本数）の上限です。どちらも絞り込まないと、表示が遅くなったり、凡例やグラフが読みにくくなったりします。

  4. Q4. チャートの数字が想定と違うとき、最初に確認すべきことは何ですか？

    回答を表示

    チャート右上の...メニューからView queryを開き、実際に発行されたSQLを確認します。フィルタ条件の誤りや集計単位のズレなど、原因の多くはSQLを見れば分かります。これは第1章で学んだ「Supersetは都度SQLを発行する」という性質に基づく習慣です。
