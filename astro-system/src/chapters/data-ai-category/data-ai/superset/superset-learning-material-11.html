ホーム Apache Superset 第11章
第11章 所要時間: 約60分

フィルタとインタラクション

前章まででダッシュボードは完成しましたが、まだ「作った人が決めた1つの見方」しかできません。この章では、見る人が自分で条件を変えられるネイティブフィルタと、チャート同士がクリックで連動するクロスフィルタを使って、ダッシュボードを「眺めるもの」から「触って調べられるもの」に変えていきます。

この章で学ぶこと

  • ダッシュボードのネイティブフィルタと、第8章で扱ったチャート単体のフィルタの違いを説明できる
  • ネイティブフィルタを追加し、対象のデータセット・列・スコープを設定できる
  • クロスフィルタとドリルダウンを使って、ダッシュボードを探索的に調べられる
  • フィルタ設計でつまずきやすい落とし穴（スコープ設定漏れなど）を避けられる

11.1 なぜフィルタが要るのか

「部署ごとに数字を見たい」「先月だけの実績を見たい」——こうした要望が出たとき、最も手軽に見える解決策は同じ構成のダッシュボードを部署の数だけ複製することです。しかし複製で対応すると、チャートの定義を1つ直すたびに全コピーへ同じ修正を繰り返すことになり、直し忘れでコピーごとに数字がずれていく事故が起きやすくなります。

フィルタが解決するのはこの問題です。ダッシュボードの実体を1枚だけ用意し、見る人がその場で条件を変えられるようにすれば、複製もメンテナンスの手間も発生しません。「見る人が自分で条件を変えられる」ことこそが、この章で扱うフィルタの価値です。

ありがちな回避策: ダッシュボードの複製

「東京支店用」「大阪支店用」のように、同じ構成のダッシュボードを部署の数だけ複製して運用しているケースをよく見かけます。すぐに用意できる反面、チャートを1つ改善するたびに全コピーへ同じ作業を繰り返すことになり、更新漏れが起きやすい構成です。フィルタは、この複製をやめるための機能だと考えてください。

ここで、すでに第8章で扱ったチャート単体のフィルタと、この章で扱うダッシュボードのフィルタ（ネイティブフィルタ）の違いを整理しておきましょう。名前は似ていますが、「誰が」「いつ」変えられるかがまったく異なります。ネイティブフィルタについては、フィルタそのものを用意するのは編集者、その値を選ぶのは閲覧者という二段構えになっている点に注意してください。

用語: フィルタバー

ダッシュボード画面の左側に表示される縦長のパネルをフィルタバーと呼びます。ここに追加したネイティブフィルタが並び、閲覧者はチャートを編集する権限がなくても、フィルタバーの値だけは自由に変更できます。

11.2 ネイティブフィルタを追加する

フィルタバーの上部にある + Add/Edit Filters から、新しいフィルタを追加できます。開いた設定画面で、フィルタの種類・名前・対象のデータセットと列を指定していきます。

  • Filter Type（フィルタ種別） — 値で絞るのか、期間で絞るのかなど、フィルタの種類を選びます。
  • Filter Name（フィルタ名） — フィルタバーに表示される見出しです。「対象期間」「カテゴリ」のように、閲覧者が見て分かる名前を付けます。
  • Dataset（データセット） — どのデータセットの列を対象にするかを選びます。
  • Column（列） — 選んだデータセットの中で、実際に絞り込みに使う列を指定します。

フィルタ種別は用途に応じて使い分けます。よく使う5種類を整理しておきましょう。

フィルタ種別 何を選ぶか 主な用途
Value（値） 列に含まれる値を1つ、または複数選択 カテゴリ・部署名・ステータスなどでの絞り込み
Numerical range（数値範囲） 数値列の下限〜上限をスライダーで指定 金額・数量など数値の範囲で絞り込む
Time range（時間範囲） 開始日〜終了日の期間 「直近12か月」「今四半期」など期間の指定
Time column（時間列） 時間軸として使う日付列そのもの データセットに複数の日付列がある場合の切り替え
Time grain（時間粒度） 集計の単位（日／週／月／四半期／年 など） 折れ線グラフなどの集計粒度をまとめて切り替える

画面表記はバージョンによって異なる場合があります

ボタンの名前や設定画面のタブ構成は、Superset のバージョンによって多少変わることがあります。本章では代表的な構成で説明しますが、実際の画面と表記が違う場合は、近い意味の項目を探してみてください。

11.3 スコープを設定する

フィルタを追加すると、そのフィルタをどのチャートに効かせるかを決める「スコープ」の設定が必ず付いてきます。選択肢は大きく2つです。

  • ダッシュボード全体に適用（Apply to all panels）— ダッシュボード上のすべてのチャートに効かせます。迷ったらまずこちらを選んで構いません。
  • 特定のチャートだけに適用（Apply to specific panels）— チャートを個別に選んで、効かせる範囲を絞ります。「このフィルタは、このタブのチャートだけに関係する」というときに使います。
flowchart TD F["フィルタ: 対象期間
直近12か月"] --> C1["月次売上（棒グラフ）
データセット: 売上明細"] F --> C2["カテゴリ別内訳（円グラフ）
データセット: 売上明細"] F -.->|スコープ対象外| C3["在庫サマリ（Big Number）
データセット: 在庫スナップショット"]

注意したいのは、スコープに含めても、異なるデータセットを使うチャートには効かないことがある点です。上の図の「在庫サマリ」は別のデータセット（在庫スナップショット）を参照しているため、「対象期間」フィルタが期待する列と対応が取れず、スコープの対象からは自然に外れます。

異なるデータセットが混在するダッシュボード

1枚のダッシュボードに複数のデータセットのチャートを混在させることはよくあります。この場合、フィルタの設定画面でチャートごとにどの列を対応させるかを追加で指定できる場合があります。列名が違う、あるいは対応する列自体が無いデータセットのチャートには、スコープに含めていてもフィルタは効きません。

11.4 使い勝手を上げる設定

フィルタは追加しただけでは使いにくいことがあります。次の設定を組み合わせて、閲覧者にとって迷わないフィルタバーに仕上げましょう。

設定 内容 使いどころ
既定値（デフォルト選択） フィルタを開いたときに最初から選ばれている値 最もよく見られる条件をあらかじめ選んでおく
必須（Filter value is required） 値が選ばれるまでチャートを描画しない 条件を選ばずに集計値だけが独り歩きするのを防ぎたい場合
複数選択（Can select multiple values） 1つのフィルタで複数の値を同時に選べるかどうか カテゴリを2つ以上まとめて見比べたい場合に有効化
検索（Dynamically search all filter values） 選択肢が多いときに絞り込み検索を表示する 値の種類が数十〜数百ある列
並び順（Sort filter values） 選択肢の表示順（昇順・降順・件数順 など） よく使う値を上のほうに出しておきたい場合
他フィルタへの依存（Values are dependent on other filters） 別のフィルタで選んだ値に応じて、選択肢を絞り込む 「地域」を選んだら「都道府県」の選択肢が連動して変わる、など

重要ポイント: 初期表示を軽くする

ダッシュボードを開いた瞬間、フィルタバーの既定値を条件として全チャートのクエリが一斉に実行されます。時間範囲フィルタの既定値を「全期間」のように広く設定していると、開くたびに大量のデータを集計することになり、初回表示が遅くなります。特別な理由がなければ、既定値は「直近12か月」のように実務で普段見る範囲に絞っておくと、開いた瞬間の体感速度が変わります。

11.5 クロスフィルタ

クロスフィルタは、あるチャートの要素（棒グラフの1本、円グラフの1切れなど）をクリックすると、その値を条件として他のチャートが一時的に絞り込まれる機能です。フィルタバーを操作しなくても、チャートそのものをきっかけに他のチャートを掘り下げられます。

解除は、同じ要素をもう一度クリックするだけです。複数のクロスフィルタを適用した場合も、フィルタバー側に適用中の条件が表示され、そこから個別に、またはまとめて解除できます。クロスフィルタは既定で有効になっている機能です（機能フラグ DASHBOARD_CROSS_FILTERS 自体が非推奨化されており、常時有効という扱いになっています）。定型レポートなどで動きを止めたい場合だけ、ダッシュボードのプロパティから無効化を検討してください。

クロスフィルタが向く場面

  • 特定の商品や部門を選び、原因を掘り下げて調べたいとき
  • 全体の傾向から気になる箇所を見つけ、詳細を辿りたいとき
  • 分析担当者が自由に切り口を変えながら探索するとき

クロスフィルタが向かない場面

  • 毎回同じ数字・同じ見た目を保証したい定型レポート
  • スケジュール配信やPDF出力など、決まった状態を配りたいとき
  • 操作に不慣れな閲覧者が誤クリックで混乱しそうなとき

クロスフィルタは既定で有効

クロスフィルタは有効化の手順を踏まなくても、はじめから使える状態になっています。誤クリックによる混乱を避けたい定型レポート用のダッシュボードなど、動きを止めたい場合だけ、ダッシュボードのプロパティ（Edit properties）から無効化してください。

11.6 ドリルダウンと明細の確認

フィルタとクロスフィルタは「絞り込む」操作でしたが、もう一歩踏み込んで「この1つの数字は、どの行から計算されたのか」を確かめたい場面もあります。この確認に使う Drill to detail には入り口が2つあり、それぞれ表示されるデータの範囲が異なるので区別して覚えてください。

  • チャート上のデータ点を右クリック → Drill to detail by <ディメンション名> — クリックした点を構成する元データの行だけを一覧表示します。棒グラフの1本、表の1セルなど、着目した部分に絞り込まれます。
  • チャートヘッダーの ... メニュー → Drill to detail — 特定の点に絞らず、フィルタなしでそのチャート全体の元データを表示します。

これとは別に、「年→四半期→月」のように軸の粒度を1段階ずつ細かくしながら見ていく Drill by（ドリルバイ）という機能もあります。本教材の検証バージョン（6.1.0）では、機能フラグ DRILL_BY・DRILL_TO_DETAIL はいずれも既定で有効なので、対応するチャートであれば追加設定なしに使えます。ただし DRILL_TO_DETAIL は公式の機能フラグ一覧で deprecated（非推奨）扱いとなっており、将来のメジャーバージョンでフラグ自体が廃止される見込みです（機能が使えなくなるという意味ではなく、フラグでの切り替えができなくなるという意味です）。

操作 確認できること
データ点を右クリック → Drill to detail by <ディメンション名> クリックした点（棒グラフの1本、表の1セルなど）を構成する元データの行だけ
チャートヘッダーの ... メニュー → Drill to detail フィルタなし、そのチャート全体の元データ
Drill by（ドリルバイ） 軸を1段階細かい粒度に替えた内訳（年→四半期→月 など）

「元の行を見られる」ことの価値

「この数字、本当に合っているの？」と聞かれたとき、SQL Lab まで戻って条件を書き直さなくても、その場で元データの行を提示できるのは大きな安心材料になります。数字への疑問に「見せながら答えられる」動線があること自体が、ダッシュボードへの信頼につながります。

11.7 フィルタ設計の落とし穴

フィルタは便利な反面、増やしすぎたり設定を誤ったりすると、かえってダッシュボードを使いにくくします。公開する前に、次のチェックリストで見直しておきましょう。

公開前チェックリスト

  • 増やしすぎていないか — 付けられるだけフィルタを並べると、誰にも使われないまま画面だけが複雑になります。実際に聞かれる問いに対応する最小限にとどめましょう。
  • 必須フィルタを付けすぎていないか — 「値が選ばれるまで描画しない」を多用すると、開いた瞬間は何も表示されない画面になります。既定値で代用できないか、先に検討してください。
  • スコープの設定漏れがないか（最も多い事故） — フィルタの値を変えても、1つのチャートだけ数字が動かない場合は、そのチャートがスコープに含まれていないか、データセットの列が対応付けられていない可能性が高いです。
  • URL共有でフィルタの状態が伝わるか — 見ている状態をそのまま他の人に渡したいときは、URLをそのままコピーするだけでなく、今の状態を固定して共有する機能（パーマリンクなど。名称はバージョンにより異なる場合があります）を使うと確実です。
  • キャッシュとの関係を理解しているか — フィルタの値を変えるたびに実質的に別のクエリとして扱われ、キャッシュのヒット率に影響します。「直近1時間」のように既定値が頻繁に変わるフィルタは、キャッシュが効きにくい点を覚えておいてください。なおフィルタの選択状態そのもののキャッシュ（FILTER_STATE_CACHE_CONFIG）とチャートのデータのキャッシュ（DATA_CACHE_CONFIG）は別物です（第14章で扱います）。

スコープ設定漏れの見つけ方

複数のチャートを並べたダッシュボードで、フィルタを変えても特定の1つのチャートだけ数字が動かないときは、まずそのフィルタの設定を開き、スコープの対象チャート一覧にそのチャートが含まれているかを確認してください。含まれているのに動かない場合は、そのチャートのデータセットに対応する列が無い、または列名が食い違っている可能性があります。

やってみよう 11-1: 月次売上ダッシュボードにフィルタとクロスフィルタを追加する

第10章で作った月次売上ダッシュボードを使って、実際にフィルタとクロスフィルタを追加してみましょう。

手順

  1. 1 フィルタバーから + Add/Edit Filters を開き、Time range 型のフィルタを追加する。フィルタ名は「対象期間」、既定値は「直近12か月」に設定する。
  2. 2 続けて Value 型のフィルタを追加する。フィルタ名は「カテゴリ」、対象列はカテゴリの列を指定し、複数選択を有効にする。
  3. 3 2つのフィルタそれぞれのスコープを開き、「ダッシュボード全体に適用」（全チャート対象）になっていることを確認する。
  4. 4 カテゴリフィルタで値を1〜2個選び、ダッシュボード上のすべてのチャートの数字が連動して変わることを確認する。
  5. 5 クロスフィルタは既定で有効になっているので、そのまま月次売上の棒グラフの1本をクリックする。他のチャートがその月に絞り込まれることを確認したら、同じ棒をもう一度クリックして解除する。

解答の目安

スコープを正しく設定できていれば、カテゴリフィルタを変えたときにダッシュボード上のすべての数値が一斉に動きます。もし1つのチャートだけ数字が変わらない場合は、そのチャートがフィルタのスコープに含まれていないか、そのチャートのデータセットにカテゴリ列が対応付けられていない可能性が高いです。該当フィルタの設定画面を開き、スコープの対象チャート一覧にそのチャートが入っているかをまず確認してください。なお、クロスフィルタは棒をクリックした瞬間だけ他のチャートに一時的な絞り込みがかかる点が、開いている間ずっと効き続けるネイティブフィルタとの違いです。

理解度確認クイズ

  1. Q1. ダッシュボードのネイティブフィルタは、第8章で学んだチャート単体のフィルタと何が違いますか？

    回答を表示

    チャート単体のフィルタは Explore 画面でチャートの作成者が設定し、そのチャートだけに固定的に効きます。一方ネイティブフィルタは、ダッシュボードの編集者が対象の列・スコープ・既定値を定義しておき、閲覧者がフィルタバーから値をその場で選べるものです。スコープで指定した複数のチャートに同時に影響を与えます。

  2. Q2. フィルタの値を変えても、ダッシュボード上の1つのチャートだけ数字が変わりません。まず何を疑うべきですか？

    回答を表示

    そのフィルタのスコープ設定を疑います。対象チャートの一覧にそのチャートが含まれていない、またはチャートが参照するデータセットに対応する列がマッピングされていないと、フィルタは効きません。フィルタ設計の中で最も起きやすい事故です。

  3. Q3. クロスフィルタが向いている場面と、向いていない場面をそれぞれ挙げてください。

    回答を表示

    分析担当者が数値を掘り下げながら原因を探る探索的な使い方に向いています。一方、スケジュール配信やレポートのように「常に同じ見た目」を保証したい定型的な用途には、誤クリックで表示が変わってしまう可能性があるため向きません。

  4. Q4. データ点を右クリックする Drill to detail と、チャートヘッダーの...メニューから開く Drill to detail は、それぞれ何を表示しますか？

    回答を表示

    データ点を右クリックするDrill to detail by <ディメンション名>は、クリックした点を構成する元データの行だけに絞って表示します。一方、チャートヘッダーの...メニューから開くDrill to detailは、フィルタをかけずそのチャート全体の元データを表示します。どちらもSQL Lab まで戻って同じ条件のクエリを書き直す必要がなく、表示されている数字が正しく集計された結果かどうかをその場で検証できます。
