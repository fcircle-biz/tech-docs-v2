第1章 所要時間: 約45分

Jevとは

Jev は TypeSafe AI が提供する「文章を書かないAI」です。この章では、Jev が何を返すモデルなのか、ChatGPT や Claude のような LLM とどう違うのか、そしてどんな処理に向いているのかという全体像をつかみます。

この章で学ぶこと

  • Jev とは何か、誰が提供しているのかを理解する
  • Jev と一般的な LLM の違いを説明できる
  • State ＋ Question から構造化された判断が返る流れをつかむ
  • ある処理に LLM と Jev のどちらが適しているかを見分けられる

1.1 Jev とは何か

Jev（ジェブ）は、AI 企業 TypeSafe AI が提供するモデルで、System One モデルと呼ばれる新しい種類の AI です。最大の特徴は、文章を生成しないことにあります。

ChatGPT や Claude のような LLM（大規模言語モデル）に「この問い合わせは緊急ですか？」と尋ねると、返ってくるのは「はい、この問い合わせは3日間も決済連携が失敗しており、売上の損失も発生しているため緊急度が高いと考えられます」といった文章です。プログラムでこれを使うには、文章を読み取って「緊急かどうか」を取り出す処理（パース）が必要になります。

Jev は、この「文章を書いて、それを読み取る」というステップそのものを取り除きます。同じ問いを Jev に投げると、返ってくるのは 1.0 という数値です。プログラムが if 文でそのまま使える形で、判断結果が返ってきます。

判断を返す

文章ではなく、選択肢・点数・確率という型付きの判断結果を返します。

速い

長い思考を挟まないため高速です。1回のリクエストで複数の判断を並列に評価できます。

確信度が分かる

「どう判断したか」に加えて「どれくらい自信があるか」も一緒に返ります。

用語: 「System One」という名前について

心理学では、人間の思考を「直感的で高速な判断」と「じっくり考える論理的な推論」の2種類に分けて説明することがあります。Jev が担うのは前者、つまり熟練者が一瞬で下すような判断です。文章を書いたり、段階を追って推論したりする役割は、これまでどおり LLM が担います。本教材では、この役割分担を設計に落とし込む方法を学びます。

1.2 LLM との違い

両者の処理の流れを並べると、違いがはっきりします。LLM は「入力から文章を作る」モデル、Jev は「情報と問いから判断を返す」モデルです。

flowchart LR subgraph LLM["一般的なLLM"] A1["入力（プロンプト）"] --> A2["文章を生成"] A2 --> A3["テキスト出力"] A3 --> A4["コードで文章を解析"] end subgraph JEV["Jev（System One）"] B1["State（判断対象の情報）"] --> B3["Jev"] B2["Question（判断してほしい内容）"] --> B3 B3 --> B4["構造化された判断"] end

Jev への入力は必ず State と Question の2つに分かれます。State は「判断の材料となる情報」（問い合わせ本文など）、Question は「判断してほしい内容」（緊急か？ どの部署か？ など）です。この分離が、Jev の設計の出発点になります。

観点 一般的な LLM Jev
主な役割 テキスト生成 判断
対話 会話を続けられる 非会話型（1問1答）
出力の形 自由形式のテキスト 型付きの値（選択肢・数値・確率）
JSON で受け取る方法 「JSON で出力して」と指示する 構造化結果をそのまま返す
思考のしかた 段階を追った推論（Reasoning） 高速な判断（Fast Judgment）
設計の中心 プロンプト State ＋ Question

Jev にできないこと

公式ドキュメントは、System One モデルが「返信を書く・コードを生成する・説明文を作る」ことをしないと明記しています。また入力はテキストのみで、画像・音声・動画には対応していません。文章生成が必要な場面では、これまでどおり LLM を使います。Jev は LLM の置き換えではなく、役割の違う別の道具です。

1.3 Jev が返す「構造化された判断」

Jev の Question には3つの種類（Primitive）があります。詳しくは第4章で扱いますが、ここでは「どんな形の答えが返るのか」だけ先に見ておきましょう。

  • Choice — 用意した選択肢から1つ選ぶ（例: どの部署が担当すべきか）
  • Score — 段階の尺度のどこに当たるかを評価する（例: 顧客の不満度）
  • Noul — 真偽を 0〜1 の確率で返す（例: 返金を要求しているか）

実際のレスポンスは、次のような JSON です。choice や score をそのままプログラムで使えます。

Jev のレスポンス例（抜粋） 
{
  "model": "jev-1.13.0",
  "answers": {
    "department": {
      "type": "choice",
      "choice": "technical",
      "confidence": 0.78,
      "probabilities": { "technical": 0.85, "billing": 0.15, "sales": 0.0 }
    },
    "is_urgent": {
      "type": "noul",
      "noul": 1.0
    }
  }
}

注目してほしいのは、probabilities と confidence が一緒に返ってくる点です。「technical だと判断した」だけでなく「その確率は 0.85 で、確信度は 0.78」まで分かります。これにより、自信のある判断は自動処理し、自信のない判断は人間に回すという設計が可能になります（第9章・第12章）。

重要ポイント

Jev が返すのは個々の判断であって、最終的な結論ではありません。「返金要求である」「緊急である」という部品を Jev から受け取り、それを組み合わせて「では返金処理を自動実行する」と決めるのはコードの役割です。この責務分担が本教材の中心テーマになります。

1.4 Jev が向く処理・向かない処理

公式ドキュメントは Jev の適用範囲を、「その分野をよく知る人が、必要な情報を見て数秒で判断できること」と説明しています。この基準はとても実用的です。迷ったときは「熟練の担当者なら一瞥して答えられるか？」と自問してみてください。

Jev が向く

  • 問い合わせのカテゴリ分類・担当部署の振り分け
  • 緊急度・重大度・不満度の段階評価
  • 返金要求か／クレームかといった真偽判定
  • 個人情報や不正な内容が含まれるかの検知
  • ユーザー入力の意図（Intent）分類

Jev が向かない

  • メール本文や FAQ 回答の作成（文章生成）
  • プログラムコードの生成
  • 正確な数値計算・件数の集計
  • 日付の前後比較などの厳密な計算
  • 「分析して整理して対応方法まで決める」複合的な依頼

右側の「向かない」項目は、Jev の欠陥ではなく設計上の役割分担です。文章生成は LLM に、正確な計算はコードに任せます。この3者の切り分けは、システム全体の設計方針として次のように整理できます。

flowchart TD A["やりたい処理"] --> B{"どんな種類の仕事か"} B -->|人が数秒で下せる判断| C["Jev に任せる"] B -->|正確な計算・ルール適用| D["コードで書く"] B -->|文章生成・複雑な推論| E["LLM に任せる"]

関連: Coding Agent との関係

Jev は Claude Code や Codex のような Coding Agent の置き換えでもありません。関係はむしろ逆で、Coding Agent を使って「Jev を利用するアプリケーション」を開発するという位置づけになります（第15章）。

やってみよう 1-1: LLM と Jev のどちらが適しているか考える

API キーの取得はまだ不要です。まずは「どちらの道具を使う場面か」を見分ける目を養いましょう。この判断ができるかどうかが、そのまま設計の質につながります。

手順

  1. 1 次の6つの処理を、「LLM 向き」と「Jev 向き」に分類してみる。
    (a) メール本文の生成　(b) 問い合わせカテゴリ分類　(c) プログラムコード生成　(d) 問い合わせ緊急度判定　(e) FAQ 回答文の生成　(f) 不正メッセージ判定
  2. 2 分類の理由を「熟練者が数秒で判断できるか？」「文章を作る必要があるか？」の2つの観点で説明してみる。
  3. 3 自分の業務やアプリの中に「Jev 向き」の判断がないか、1つ以上書き出してみる。第16章の実践課題で使えます。

解答の目安

Jev 向きは (b)(d)(f) の3つ。いずれも「分類」「段階評価」「真偽判定」であり、出力は選択肢・数値・確率で表せます。LLM 向きは (a)(c)(e) の3つで、いずれも文章やコードを書く必要があります。

理解度確認クイズ

  1. Q1. Jev が一般的な LLM と最も異なる点は何ですか？

    回答を表示

    文章を生成せず、型付きの判断結果（選択肢・数値・確率）を直接返す点です。LLM の出力は自由形式のテキストなので、プログラムで使うには解析が必要ですが、Jev の出力はそのままコードで扱えます。

  2. Q2. Jev へ与える2つの入力を挙げ、それぞれ何を表すか説明してください。

    回答を表示

    State（判断対象となる情報。問い合わせ本文など）と Question（判断してほしい内容。緊急か？ どの部署か？ など）です。この2つを分けて設計するのが Jev の出発点です。

  3. Q3. 「この問い合わせを分析して、問題点を整理して、対応方法を決めてください」という依頼は Jev に向いていますか？

    回答を表示

    向いていません。複数の作業が1つに混ざった複合的な依頼だからです。Jev では「緊急か？」「返金要求か？」「どの部署か？」のように小さな判断へ分解し、それらを組み合わせて対応方法を決めるのはコードが担います（第8章で詳しく学びます）。

  4. Q4. Jev の返却値に confidence が含まれていると、どんな設計ができますか？

    回答を表示

    確信度が高い判断だけを自動処理し、低い判断は人間のレビューへ回すという振り分けができます。つまり「判断しない」という選択肢を設計に組み込めます（第9章・第12章）。
