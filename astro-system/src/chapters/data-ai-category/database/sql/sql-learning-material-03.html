ホーム SQL入門 第3章
第3章 所要時間: 約90分

環境構築（PostgreSQL・pgAdmin・A5:SQL Mk-2）

前の章までで「なぜ表を分けるのか」という理屈を学びました。この章からはいよいよ手を動かします。Windows パソコンに PostgreSQL 17 を実際にインストールし、同梱の pgAdmin 4 と、別途ダウンロードする A5:SQL Mk-2 の2つのツールから接続できる状態を作ります。画面の流れに沿って一つずつ進めれば、迷うことはありません。

この章の学習目標

  • Windows に PostgreSQL 17 をインストールし、スーパーユーザーのパスワードを正しく設定できる
  • Windows サービスと psql を使って、インストールが正しく完了したことを確認できる
  • pgAdmin 4 を初回起動し、PostgreSQL サーバーへ接続できる
  • A5:SQL Mk-2 を導入して接続設定を行い、pgAdmin 4 と同じ結果が得られることを確認できる

3.2 Windows への PostgreSQL 17 インストール

PostgreSQL 公式サイトのダウンロードページから、EDB 社が提供する Windows 用インストーラをダウンロードします。「Download the installer」のリンクをクリックし、バージョン一覧から 17系の最新版（Windows x86-64）を選んでください。

ダウンロードした postgresql-17.x-x-windows-x64.exe をダブルクリックすると、セットアップウィザードが起動します。以降、画面に沿って次の順に進めます。

  1. Installation Directory: インストール先フォルダ。特別な事情がなければ既定値（C:\Program Files\PostgreSQL\17）のまま進めます。
  2. Select Components: インストールするコンポーネントを選ぶ画面。PostgreSQL Server・pgAdmin 4・Command Line Tools の3つにチェックが入っていることを確認します（Stack Builder は任意ですが、外しても構いません）。
  3. Data Directory: 実データを保存するフォルダ。既定値のままで問題ありません。
  4. Password: データベース全体を管理するスーパーユーザー postgres のパスワードを設定します。下の警告を必ず読んでください。
  5. Port: PostgreSQL が待ち受けるポート番号。既定の 5432 のまま進めます。
  6. Advanced Options（Locale）: 文字の並び順や日付表記に関するロケール設定。Default locale、または Japanese, Japan のどちらを選んでも本ガイドの学習には支障ありません。迷ったら Default locale で構いません。
  7. Pre Installation Summary: これまでの設定内容の確認画面。内容を確認して「Next」を押すとインストールが始まります。

警告: postgres のパスワードは必ずメモしておく

ここで設定するパスワードは、この後の pgAdmin 4・A5:SQL Mk-2 の接続設定、そして今後すべての章で繰り返し入力することになります。忘れると復旧に手間がかかります。パスワード管理アプリやメモ帳など、あとで必ず見返せる場所に控えてから次へ進んでください。本ガイドでは以降、このパスワードを単に「postgres のパスワード」と呼びます。

インストールが完了すると、最後に Stack Builder（追加ツールをダウンロードするためのオプション画面）を起動するかどうかを聞かれます。本ガイドでは追加ツールを使わないため、チェックを外して「Finish」を押し、スキップして問題ありません。

3.3 インストールの確認

インストールが終わったら、PostgreSQL が実際に動いているかを2つの方法で確認します。

(1) Windows サービスで動作を確認する

スタートメニューの検索欄に「サービス」と入力し、「サービス」アプリ（services.msc）を開きます。一覧を下にスクロールして postgresql-x64-17 という項目を探し、状態の欄が「実行中」になっていれば、PostgreSQL はバックグラウンドで正常に動作しています。

(2) psql でバージョンを確認する

スタートメニューから「SQL Shell (psql)」を起動します。Server・Database・Port・Username はすべて既定値のまま Enter キーを押して進み、Password for user postgres: と聞かれたら、先ほど設定した postgres のパスワードを入力します（入力中は画面に何も表示されませんが、正常な動作です）。

postgres=# というプロンプトが表示されたら接続成功です。試しに、PostgreSQL のバージョンを確認する SQL を実行してみましょう。

psql 
-- インストールされたPostgreSQLのバージョンを確認する
SELECT version();

PostgreSQL 17.x on x86_64-windows... のような文字列が表示されれば成功です。確認できたら \q と入力して psql を終了します。

3.4 pgAdmin 4 の初回起動

スタートメニューから「pgAdmin 4」を起動します。既定のブラウザが自動的に開き、pgAdmin 4 の画面が表示されます（インターネットには接続せず、自分のパソコンの中だけで動くローカル画面です）。

  1. 初回起動時はマスターパスワードの設定を求められます。これは pgAdmin 4 が接続情報を保存する際に使う、pgAdmin 4 専用のパスワードです。postgres のパスワードとは別物なので、混同しないよう注意してください。
  2. 画面左側のツリーから Servers（サーバー群） を展開し、あらかじめ登録されている PostgreSQL 17 をクリックします。
  3. 接続用のパスワード入力が求められるので、postgres のパスワード（3.2節でメモしたもの）を入力します。「Save Password」にチェックを入れると、次回以降の入力を省略できます。
  4. 接続に成功すると、ツリーが展開されて Databases の下に postgres データベースが見えるようになります。これで pgAdmin 4 からの接続は完了です。

ヒント: 「マスターパスワード」と「postgres のパスワード」の違い

マスターパスワードは pgAdmin 4 というアプリ自体を開くための鍵（保存済みの接続情報を守るためのもの）、postgres のパスワードは PostgreSQL サーバー本体に接続するための鍵です。役割が異なる2つのパスワードがある、と覚えておいてください。

3.5 A5:SQL Mk-2 の導入

A5:SQL Mk-2 は公式サイトから ZIP ファイルをダウンロードし、任意のフォルダ（例: C:\A5SQL）に展開するだけで使えます。インストール作業は不要で、Windows の管理者権限がなくても導入できるのが特長です。展開したフォルダの中にある A5Mk2.exe をダブルクリックすると起動します。

初回起動時は自動的に「データベースの追加と削除」ダイアログが開きます（開かない場合は、ツールバーの「データベースの追加と削除」アイコンをクリックします）。次の手順で PostgreSQL への接続を登録しましょう。

  1. 「追加」ボタンをクリックします。
  2. 接続方式の一覧から 「PostgreSQL（直接接続）」 を選択します。
  3. 下の表の内容に沿って、サーバー名・ポート番号・データベース名・ユーザーID・パスワードを入力します。
  4. 「テスト接続」ボタンを押し、接続に成功するメッセージが表示されることを確認します。
  5. 「OK」を押して登録を完了します。
設定項目 入力する値
サーバー名（ホスト名） localhost
ポート番号 5432
データベース名 postgres
ユーザーID postgres
パスワード 3.2節でメモした postgres のパスワード

登録した接続をダブルクリックすると、SQL エディタが開きます。使い方の詳細は次の第4章で扱いますので、ここでは接続できることが確認できれば十分です。

3.6 macOS / Linux の場合

A5:SQL Mk-2 は Windows 専用ソフトのため、macOS / Linux をお使いの場合はpgAdmin 4 だけで全章を学習できます。以降の章で A5:SQL Mk-2 の操作手順が出てきたら、pgAdmin 4 のクエリツールで同じ SQL を実行してください。結果はまったく同じです。

macOS の場合

Homebrew を使うのが簡単です。ターミナルで次のコマンドを実行します。

terminal 
# PostgreSQL 17をHomebrewでインストールする
brew install postgresql@17

# バックグラウンドサービスとして起動する
brew services start postgresql@17

コマンド操作をせずに GUI で完結させたい場合は、Postgres.app という選択肢もあります。アプリをダウンロードして起動するだけで PostgreSQL が使えるようになります。

Linux（Ubuntu 系）の場合

apt パッケージマネージャーからインストールします。

terminal 
# パッケージ一覧を更新してPostgreSQL 17を導入する
sudo apt update
sudo apt install postgresql-17

Docker を使う場合（OS共通）

Docker がすでに使える環境であれば、インストール不要で試すこともできます。

terminal 
# PostgreSQL 17のコンテナを起動する（ポート5432を公開）
docker run --name shop-postgres \
  -e POSTGRES_PASSWORD=your_password \
  -p 5432:5432 \
  -d postgres:17

いずれの方法でも、接続先は localhost・ポート 5432・ユーザー postgres となり、pgAdmin 4 からの接続手順は 3.4 節と同じです。

3.7 よくあるトラブルと対処

環境構築でつまずくのはよくあることです。代表的な症状と対処法を一覧にしました。似た症状が出たら、まずここを確認してください。

症状 主な原因 対処
「接続が拒否されました」
could not connect to server		 PostgreSQL のサービスが停止している 「サービス」アプリで postgresql-x64-17 を右クリックし「開始」を選ぶ
「password authentication failed」 postgres のパスワードを間違えて入力している 3.2節でメモしたパスワードを再確認し、大文字・小文字や全角入力になっていないか確かめて入力し直す
ポート 5432 が使用中 以前に別の PostgreSQL をインストール済みで競合している 「サービス」アプリで他の postgresql-x64-* を停止するか、片方のポート番号をインストール時に変更する
pgAdmin 4 の画面が真っ白になる ブラウザのキャッシュが影響している ブラウザのキャッシュを削除して再読み込みするか、別のブラウザで開き直す
日本語が文字化けする クライアント側の文字コード設定が合っていない A5:SQL Mk-2 の接続設定で文字コードを UTF-8 に指定する（既定値のままであれば通常は発生しません）
postgres のパスワードを忘れた メモを取らずに設定を進めてしまった 学習用途であれば PostgreSQL をアンインストールしてデータディレクトリごと削除し、3.2節から入れ直すのが最も簡単。既存データを残したまま再設定する方法もあるが本ガイドの範囲を超えるため、必要になったら別途調べる

動作確認チェックリスト

次の項目がすべて確認できていれば、環境構築は完了です。

  • Windows サービスで postgresql-x64-17 が「実行中」になっている
  • psql から接続し、SELECT version(); が実行できた
  • pgAdmin 4 から PostgreSQL 17 サーバーに接続し、Databases が見える
  • A5:SQL Mk-2（またはmacOS/Linuxではこの項目は省略）でテスト接続が成功した
  • postgres のパスワードを、あとで見返せる場所に控えてある

やってみよう 3-1: 両方のツールから同じ結果を確認する

pgAdmin 4 と A5:SQL Mk-2（macOS/Linuxの場合は pgAdmin 4 のみ）の両方から、同じ SQL を実行して同じ結果が返ることを確かめます。1.4節で学んだ「どちらのツールも窓口に過ぎない」を、自分の目で確認するのが目的です。

手順

  1. 1 pgAdmin 4 で PostgreSQL 17 サーバーに接続し、ツールバーの「Query Tool」を開く。
  2. 2 SELECT version(); と入力して実行し、結果に表示されるバージョン文字列をメモする。
  3. 3 A5:SQL Mk-2 で 3.5節の接続を開き、SQL エディタに同じ SELECT version(); を入力して実行する（macOS/Linuxの場合はpgAdmin 4のクエリツールをもう一度開いて同様に実行する）。
  4. 4 両方の結果を見比べ、まったく同じ文字列が返ってきていることを確認する。

ねらい: どちらのツールで実行しても結果が変わらないのは、SQL を実際に処理しているのが PostgreSQL 本体だからです。次の第4章では、この2つのツールそれぞれの画面構成と操作方法を詳しく学んでいきます。

理解度確認クイズ

  1. Q1. PostgreSQL のインストール中に設定する「postgres のパスワード」は、なぜ必ずメモしておく必要がありますか。

    回答を表示

    このパスワードは、この後の pgAdmin 4・A5:SQL Mk-2 への接続設定や、以降すべての章で PostgreSQL に接続するたびに必要になるためです。忘れてしまうと、学習用途であれば PostgreSQL を入れ直すなど復旧に手間がかかります。

  2. Q2. pgAdmin 4 の「マスターパスワード」と、PostgreSQL の「postgres のパスワード」はどう違いますか。

    回答を表示

    マスターパスワードは pgAdmin 4 というアプリが保存済みの接続情報を守るための鍵です。postgres のパスワードは PostgreSQL サーバー本体に接続するための鍵で、役割がまったく異なります。

  3. Q3. Windows サービスの一覧で postgresql-x64-17 の状態が「実行中」になっていない場合、何が起きますか。またどう対処しますか。

    回答を表示

    サービスが停止していると、pgAdmin 4 や A5:SQL Mk-2、psql から接続しようとしても「接続が拒否されました（could not connect to server）」というエラーになります。「サービス」アプリで該当サービスを右クリックし「開始」を選ぶことで解決できます。

  4. Q4. macOS / Linux を使っている場合、A5:SQL Mk-2 が使えないことは学習の支障になりますか。理由も答えてください。

    回答を表示

    支障にはなりません。A5:SQL Mk-2 も pgAdmin 4 も、SQL を送って結果を受け取る「窓口」に過ぎず、データを実際に処理しているのは PostgreSQL 本体だからです。A5:SQL Mk-2 の手順が出てきたら、pgAdmin 4 のクエリツールで同じ SQL を実行すれば同じ結果が得られます。
