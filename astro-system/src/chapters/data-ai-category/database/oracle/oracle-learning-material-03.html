ホーム Oracle 第3章
第3章 所要時間: 約1.5時間

環境構築とインストール

第2章では、PDB（プラガブルデータベース）やリスナー、ポート1521といった接続の仕組みを言葉で学びました。本章では、いよいよそれを自分のPC上で実際に動かします。Oracle AI Database 26ai Freeを導入して起動し、SQL*Plusで接続を確認し、学習用ユーザーhrを作成し、SQL Developerの接続設定まで済ませます。この章を終えると、次の第4章から実際にSQLを打ち始められる状態になります。

この章で学ぶこと

  • Oracle AI Database 26ai Free を自分のPCに導入し、起動できる
  • SQL*Plus で FREEPDB1 に接続し、接続できたことを確認できる
  • 学習用ユーザー hr を作成し、学習に必要な権限を与えられる
  • 接続に失敗したときに、代表的なORAエラーから原因を切り分けられる

3.1 導入方法を選ぶ：コンテナかインストーラか

Oracle AI Database 26ai Free をPCに用意する方法は、大きく2通りあります。1つはコンテナ（アプリケーションと、それが動くために必要な環境一式をひとまとめにして、すぐ使える状態で配布・実行する仕組み）を使う方法。もう1つは、OSごとに用意されたインストーラ（PCに直接インストールする専用プログラム）を使う方法です。

たとえるなら、コンテナは「家具付きの賃貸物件」です。必要なものが最初からそろっていて、契約（起動）すればすぐ生活（作業）を始められ、退去（削除）も身軽です。一方インストーラは「更地に家を建てる」方法で、自分のPCの環境に直接組み込まれるぶん、作り直しがやや手間になります。

本章では、macOS・LinuxはDocker／Podmanを使ったコンテナ起動、Windowsは公式インストーラを使う手順をそれぞれ説明します。どちらの方法で導入しても、この先の章で学ぶSQLやPL/SQLの内容に違いはありません。自分の環境に合う方を読み進めてください。

26ai Free の前提と制限（第1章のおさらい）

第1章で触れたとおり、Free版はユーザーデータ12GB・メモリ2GB・CPU 2コアまでという上限があります（この上限値は前身のOracle Database 23ai Freeから変更されていません）。学習用のサンプルデータ程度であれば全く問題になりません。Dockerを使う場合は、Docker Desktop側の設定でコンテナに割り当てるメモリが2GB以上になっているかを確認しておきましょう。

いずれの方法でも、まずはOracle公式サイト（oracle.com）の「Oracle AI Database Free」のページ、または公式ドキュメント「Installing Oracle AI Database Free」から入手します。ドキュメント上のエディション名は「Oracle AI Database Free」（バージョン注記として26ai）ですが、旧称「Oracle Database Free」「Oracle Database XE」で紹介されている記事もまだ多く見つかります。インストーラやコンテナイメージの正式な取得先は公式サイトの案内に従ってください（配布形態は更新されることがあるため、本書では具体的なファイル名までは指定しません）。

3.2 Windows へのインストール

Windows環境では、公式インストーラを使ってOracle AI Database 26ai Freeを導入します。手順は次のとおりです。1ステップずつ、慌てずに進めましょう。

  1. Oracle公式サイト（oracle.com）の「Oracle AI Database Free」ダウンロードページ（旧称: Oracle Database Free）を開き、Windows用のインストーラを入手する。
  2. ダウンロードしたインストーラを、右クリックから「管理者として実行」する（管理者権限が必要）。
  3. インストールウィザードの案内に従って進める。インストール先フォルダなどは、迷ったら既定値のままでよい。
  4. 途中で管理者パスワードの設定画面が表示される。これはSYS・SYSTEM・PDBADMINという3つの管理者アカウント共通の初期パスワードになる。必ずメモして忘れないようにする。
  5. インストールが完了するまで待つ。裏側でデータベースの作成が行われるため、PCの性能にもよるが数分〜十数分かかる。
  6. 完了画面が表示されたら、コマンドプロンプトから動作確認する（次の手順参照）。

管理者パスワードは絶対に忘れないこと

インストール時に設定する管理者パスワードを忘れると、systemユーザーで接続できず、この後の作業がすべて止まってしまいます。パスワードマネージャーやメモに残しておきましょう。また、単純すぎるパスワード（例: ユーザー名と同じ、桁数が短すぎる）はORA-28003で拒否されることがあります。英大文字・英小文字・数字を組み合わせた8文字以上にしておくと安全です（3.7節で詳しく扱います）。

インストールが完了したら、コマンドプロンプトでリスナー（第2章で学んだ、接続要求を受け付ける受付係）が動いているかを確認できます。表示されるメッセージの細かな文言は、OSやバージョン、インストール時の設定によって多少異なる場合があります。

コマンドプロンプト（Windows） 
# リスナーが起動しているかを確認する
# 「READY」状態のサービスが表示されれば正常
lsnrctl status

# サービス "freepdb1" のインスタンス "FREE" が
# 一覧に見えていれば、インストールは成功している
# （表示内容は環境によって多少前後することがあります）

3.3 macOS・Linux: Docker／Podman でコンテナを起動する

macOSやLinuxでは、Docker（コンテナを動かすための代表的なソフトウェア）またはPodman（Dockerとほぼ同じ使い方ができる、コンテナを動かす別のソフトウェア）を使うのが手軽です。あらかじめDocker Desktopなどで、Docker（またはPodman）自体が使える状態になっていることを確認してください。

Oracleは公式のコンテナレジストリ（コンテナの雛形である「イメージ」を配布する保管庫）でOracle AI Database 26ai Freeのイメージを配布しています。次の手順でイメージを取得し、コンテナを起動します。

ターミナル（macOS／Linux） 
# Oracle公式のコンテナイメージを取得する（本書執筆時点のlatestタグは
# バージョン23.26.3.0 = Oracle AI Database 26ai Freeを指しています）
docker pull container-registry.oracle.com/database/free:latest

# コンテナを起動する。ORACLE_PWDはSYS/SYSTEM/PDBADMINの初期パスワード
# -p 1521:1521 でホストのポート1521をコンテナへ転送する
# ※Free版のコンテナイメージが公開するポートは1521のみです（5500/EM Expressは使えません）
docker run -d --name oracle-free -p 1521:1521 \
  -e ORACLE_PWD=MyOraclePw1 \
  container-registry.oracle.com/database/free:latest

# 初回はデータベース作成に数分かかる。準備完了のログが出るまで待つ
docker logs -f oracle-free

latestタグは将来更新される

:latestタグは、新しいリリースアップデートが出るたびに指し示す中身が変わります。本書執筆時点（2026年8月）のlatestは23.26.3.0（Oracle AI Database 26ai Free）でしたが、今後さらに新しいバージョンに置き換わります。手順の再現性を保ちたい場合は、container-registry.oracle.com/database/free:23.26.3.0のように具体的なバージョンタグを指定してください。

学習環境専用 -e ORACLE_PWD をコマンドラインに書くことについて

docker runの-e ORACLE_PWD=...のように環境変数へ直接パスワードを書く方法は、シェルのコマンド履歴やdocker inspect・プロセス一覧から他人に見られてしまう可能性があります。学習環境では簡便さのためにやむを得ず使いますが、本番環境では避けるべき方法です。Oracle AI Database 26aiのコンテナイメージからは、Podmanのsecret機能を使ってパスワードを暗号化して渡す方式もサポートされています。興味があれば公式ドキュメントを確認してみてください。

コマンドの中の-e ORACLE_PWD=MyOraclePw1は、環境変数（プログラムの動作を外から設定するための値）でパスワードを渡しています。ここで指定した値が、Windows版と同じくSYS・SYSTEM・PDBADMIN共通の初期パスワードになります。

docker logs -f oracle-freeを実行すると、コンテナの起動ログがリアルタイムで流れ続けます。初回起動時はデータベースの作成処理が走るため、環境によっては数分かかります。ログに準備完了のメッセージが出るまでは、接続を試みずに待ってください。準備が整う前に接続すると、次の3.7節で紹介するORA-12541などのエラーになります。

動作確認: この行が出たら起動成功

ログの最後の方に、次のような1行が表示されればデータベースの準備は完了です。

DATABASE IS READY TO USE!

このメッセージを確認したら、Ctrl + Cでログ表示を終了して構いません（コンテナ自体は動き続けます）。

Podmanを使う場合

Podmanでもコマンドの書き方はほぼ同じです。上のコマンドのdockerをpodmanに置き換えるだけで、同じようにpull・run・logsが使えます。

3.4 SQL*Plusで初回接続する：CDBとPDB、どちらに繋ぐか

起動が終わったら、いよいよSQL*Plus（Oracleに標準で付属する、文字だけで操作するコマンドラインツール）から接続してみます。第2章で学んだとおり、接続時にはリスナー（既定ポート1521で待ち構える受付係）に対して、どのサービス名（つなぎたいデータベースの名前）につなぐかを伝えます。

ここで思い出してほしいのが、第2章のCDB／PDBの関係です。Oracle AI Database 26ai Freeでは、CDB（コンテナ全体）のサービス名がFREE、既定で用意されているPDB（業務データを置く部屋）のサービス名がFREEPDB1でした。

重要ポイント: 迷ったら FREEPDB1

本ガイドで表やデータを作る作業は、すべてFREEPDB1に接続した状態で行います。FREE（CDBのルート）にはユーザーの表を作りません。「サービス名はFREEPDB1」と覚えておけば、この先ほぼ迷いません。

接続文字列の形は、第2章で学んだEasy Connect記法（ユーザー名/パスワード@ホスト名:ポート番号/サービス名）のままです。ただし、ここから先の手順ではパスワードをコマンドラインに書きません。理由は次のコラムのとおりです。

なぜパスワードをコマンドラインに直接書かないのか

sqlplus ユーザー名/パスワード@接続先のようにパスワードを平文で入力すると、そのコマンドはシェルのコマンド履歴に残ったり、同じPC上の別のユーザーがpsコマンド（実行中のプロセス一覧を表示するOSコマンド）で覗き見できたりする場合があります。Oracle公式ドキュメント（SQL*Plus User's Guide）も「パスワードを平文で書くのはセキュリティ上のリスクであり、省略してプロンプト入力にすることでこのリスクを避けられる」と明記しています。そのため本書では、ユーザー名だけを指定してSQL*Plusを起動し、表示されるPassword:プロンプトでパスワードを入力する方式を基本にします。

まずは管理者ユーザーsystemで、FREEPDB1に接続してみましょう。次の1行目のsqlplusコマンドはOSのターミナル／コマンドプロンプトで実行するコマンドです。実行するとパスワードを尋ねられるので入力してください。その後に続くSHOW CON_NAMEやSELECT文は、SQL*Plusが起動したあとのSQL>プロンプトに入力するSQL*Plusコマンド／SQL文です。

ターミナル／コマンドプロンプト 
# 管理者ユーザーsystemでPDB(FREEPDB1)に接続する（パスワードは省略）
# 接続先を "..." で囲むのは、/ がパスワードの区切りと誤解されるのを防ぐため
sqlplus system@"localhost:1521/FREEPDB1"

# → Password: と表示されるので、インストール時に設定したパスワードを入力する
SQL*Plus（SQL> プロンプト） 
-- 今どのコンテナ(PDB)にいるかを確認する（FREEPDB1と出れば成功）
SHOW CON_NAME

-- Oracleのバージョンを確認する（接続できたことの最終確認）
SELECT banner_full FROM v$version;

system@"localhost:1521/FREEPDB1"のように、パスワードを省略したEasy Connect形式の接続先はダブルクォート（"）で囲みます。省略すると、@の後ろのlocalhost:1521/FREEPDB1に含まれる/が、パスワードの区切り文字と誤解されて接続に失敗することがあるためです（bashなどのシェルでは'localhost:1521/FREEPDB1'のようにシングルクォートでも構いません）。

SHOW CON_NAMEの結果がFREEPDB1と表示され、v$versionへの問い合わせでOracleのバージョン情報が返ってくれば、インストールと起動は成功です。banner_fullの内容には実際に取得したパッチレベル（例: 23.26.3.0など）が含まれます。本書の記述と手元のバージョン表記が完全に一致しなくても、23.26系であれば同じ手順で問題ありません。

クライアントから実際のデータにたどり着くまでの道のりを図にすると、次のようになります。途中でつまずくと、それぞれ決まったORAエラーが出ます（詳しくは3.7節）。

flowchart LR A["SQL*Plus／SQL Developer"] -->|"ポート1521
失敗するとORA-12541"| B["リスナー"] B -->|"サービス名 FREEPDB1
誤るとORA-12514"| C["PDB: FREEPDB1"] C -->|"ユーザー名／パスワード
誤るとORA-01017"| D["hrユーザーのスキーマ"]

サービス名を「FREE」と書くと別の場所につながる

接続文字列のサービス名をFREEにすると、PDBではなくCDBのルート（CDB$ROOT）に接続されます。表を作るつもりが作れなかったり、この後のユーザー作成でORA-65096が出たりする原因になります。接続後は必ずSHOW CON_NAMEで確認する習慣をつけましょう。

3.5 学習用ユーザー hr を作成する

systemのような管理者ユーザーで作業を続けるのは避け、本ガイド専用の学習用ユーザーを1つ作ります。名前はhr（Human Resources／人事部の略。第5章で作る社員名簿のサンプルにちなんだ名前）とします。このhrユーザーは、第5章以降ずっと使い続けます。

作業の前に、必ずSHOW CON_NAMEでFREEPDB1に接続していることを確認してください。次の3つの文を、systemで接続した状態のまま実行します。

学習環境専用 まず、本書を最短で進めるための簡略版を示します。RESOURCEロールとQUOTA UNLIMITEDをまとめて与える方法で、権限の管理が最小限で済む代わりに、必要以上の権限も一緒に渡してしまいます。本番環境の最小権限設計ではなく、あくまで学習環境向けの簡略設定である点に注意してください。

SQL*Plus — hrユーザーの作成（簡略版・学習環境専用） 
-- ※必ずFREEPDB1に接続した状態で実行すること
-- 学習用ユーザーを作る（PDB内のローカルユーザーなのでC##は不要）
CREATE USER hr IDENTIFIED BY MyHrPw1;

-- 接続と、表・シーケンスなどを作るための権限を与える（学習環境専用の簡略設定）
GRANT CONNECT, RESOURCE TO hr;

-- USERS表領域にデータを書き込めるように容量の割当を与える（学習環境専用の簡略設定）
ALTER USER hr QUOTA UNLIMITED ON USERS;

CONNECTロール（接続に必要な最小限の権限のまとまり）とRESOURCEロール（表やシーケンスなどを作る権限のまとまり）を与えることで、hrは「ログインして自分の表を作る」という学習に必要な権限を手に入れます。QUOTA UNLIMITED ON USERSは、既定のUSERS表領域（第2章で学んだ、表の実データを保管する場所）にどれだけデータを書き込んでよいかの割当です。UNLIMITED（無制限）は手軽ですが、実務では使う分だけを見積もって割り当てるのが基本です。

次に、本番環境に近い考え方で、本ガイド（第5〜13章）が実際に使う機能だけに絞って権限を個別付与する例を示します。どちらか一方を実行すれば十分です（両方は不要です）。

SQL*Plus — hrユーザーの作成（個別付与版） 
-- ※必ずFREEPDB1に接続した状態で実行すること
CREATE USER hr IDENTIFIED BY MyHrPw1;

-- 本番環境に近い、必要な権限だけを個別に付与する例
GRANT CREATE SESSION TO hr;    -- ログインするための権限
GRANT CREATE TABLE TO hr;      -- 表を作る権限（自分のスキーマ内の索引もこれで作れる）
GRANT CREATE SEQUENCE TO hr;   -- シーケンス（連番採番）を作る権限
GRANT CREATE VIEW TO hr;       -- ビューを作る権限
GRANT CREATE PROCEDURE TO hr;  -- プロシージャ・ファンクション・パッケージを作る権限
GRANT CREATE TRIGGER TO hr;    -- トリガーを作る権限

-- 必要な分だけ表領域の使用量を許可する
ALTER USER hr QUOTA 100M ON USERS;

CREATE TABLE権限があれば、自分のスキーマ内に限り索引（検索を高速化するためのデータ構造）も作成できるため、個別にCREATE INDEXを付与する必要はありません。CREATE PROCEDURE権限は、プロシージャだけでなくファンクションやパッケージの作成もまとめて許可します。QUOTA 100Mは、本ガイドのサンプルデータ規模であれば十分な容量です。

参考 DB_DEVELOPER_ROLE というロールもある

Oracle Database 23aiで追加され、26aiでも引き続き利用できるロールにDB_DEVELOPER_ROLEがあります。アプリケーション開発者に必要な権限一式（CREATE SESSIONやCREATE VIEW、デバッグ用の権限など）をひとまとめにしたロールで、Oracleは開発者にDBAロールや個別権限をばらばらに与えるよりDB_DEVELOPER_ROLEの付与を推奨しています。RESOURCEロールと違いCREATE SESSIONやCREATE VIEWも含まれるため、これ一つでログインから開発作業まで始められます。使い方はGRANT DB_DEVELOPER_ROLE TO hr;の1文です。本書では学習の見通しをよくするため上記の個別付与を採用していますが、実務でアプリケーション開発用のユーザーを作る際は選択肢として覚えておくとよいでしょう。含まれる権限は次のSQLで確認できます。

SELECT privilege FROM role_sys_privs WHERE role = 'DB_DEVELOPER_ROLE' ORDER BY 1;

どちらの方法でhrを作成した場合も、作成後の確認手順は同じです。実際にhrで接続し直して確認しましょう。1つ目のコマンドはOSのターミナル／コマンドプロンプトで実行します。

ターミナル／コマンドプロンプト 
# SQL*Plusをいったん終了してから、hrで接続し直す場合（パスワードは省略）
sqlplus hr@"localhost:1521/FREEPDB1"

# → Password: と表示されるので、hr作成時に設定したパスワードを入力する
SQL*Plus（SQL> プロンプト） 
-- 今の自分が誰かを確認する（HRと表示されれば成功）
SHOW USER

systemで接続したSQL*Plusを終了せずに接続を切り替えたい場合は、SQL>プロンプトでCONNECT hr@"localhost:1521/FREEPDB1"のようにユーザー名のみを指定します（このときもパスワードは書かず、表示されるPassword:プロンプトで入力します）。

重要ポイント: C##接頭辞が要るのは「CDBの共通ユーザー」だけ

PDB（FREEPDB1）の中で作るユーザーはローカルユーザーなので、名前にC##を付ける必要はありません。もしCDB$ROOTに接続したままCREATE USER hr ...を実行すると、共通ユーザー名の規則に反するとしてORA-65096が発生します（3.7節で扱います）。

3.6 SQL Developer の導入と接続設定

SQL Developerは、Oracleが無償で提供しているGUI（画面とマウスで操作するツール）のクライアントソフトです。文字だけのSQL*Plusと違い、結果を表形式で見たり、表の構造をツリーで確認したりできます（詳しい使い方は第4章で扱います）。Oracle公式サイトからダウンロードして展開する（または案内に従ってインストールする）だけで準備は完了します。

起動したら、新規接続を作成します。入力する項目は、これまで使ってきたEasy Connect記法の各パーツと、そのまま対応しています。

接続ダイアログの項目 入力する値 Easy Connect記法での対応箇所
接続名 自由な名前（例: hr_freepdb1） （接続情報の保存名。自分がわかればよい）
ユーザー名 hr ユーザー名/パスワード@ホスト:ポート/サービス名
パスワード MyHrPw1（3.5節で設定した値） ユーザー名/パスワード@ホスト:ポート/サービス名
ホスト名 localhost ユーザー名/パスワード@ホスト:ポート/サービス名

パスワードは保存してもよい

学習用の環境であれば、接続ダイアログの「パスワードの保存」にチェックを入れておくと、毎回入力する手間が省けます。実務の共有PCなどでは、パスワードを保存しない運用が一般的です。

3.7 つながらないときの切り分け

接続がうまくいかないとき、OracleはORA-番号という形式のエラーメッセージを返します。初心者のうちは意味を覚えていなくて当然です。大切なのは「エラー番号をそのまま読み、まず何を疑うべきかを知っている」ことです。代表的な5つを表にまとめます。

エラー 意味 まず疑うこと
ORA-12541 TNS: no listener（リスナーがいない） データベース（コンテナ）が起動しているか、ポート番号が1521で合っているか
ORA-12514 リスナーがそのサービス名を知らない サービス名の綴り（FREEPDB1になっているか）、PDBがOPEN状態か
ORA-01017 invalid username/password（ユーザー名またはパスワードが無効） 綴り、パスワードの大文字・小文字。パスワードをコマンドラインに直接指定している場合は、記号がシェルに解釈されていないかも確認する
ORA-65096 共通ユーザー名またはロール名が不正 CDB$ROOTに接続している。FREEPDB1に接続し直す
ORA-28003 パスワードの検証に失敗した パスワードが単純すぎないか（英大文字・小文字・数字を組み合わせ8文字以上にする）

起動直後のORA-12541は「まだ準備中」のサイン

初回起動時はデータベースの作成処理が走るため、数分間はリスナーそのものが応答できません。3.3節のDATABASE IS READY TO USE!（Windowsの場合はインストール完了画面）が出るまでは、ORA-12541が出ても異常ではありません。焦らず待ちましょう。

パスワードに記号を使うときの注意

本書のようにPassword:プロンプトでパスワードを入力する方式であれば、シェルによる記号の誤解釈はほぼ気にせずに済みます。ただし、もしパスワードをコマンドラインの引数として直接打ち込む機会があれば、!や$などの記号は、シェル（macOS／Linuxのターミナルなど）にとって特別な意味を持つ文字として解釈されてしまうことがあります。学習中は英字と数字だけの単純なパスワード（例: MyHrPw1）にしておくと、この種のトラブルを避けられます。

やってみよう 3-1: 自分の環境を用意し、hrで接続する

ここまでの内容を、実際に自分の手で最後まで通してみましょう。すべて完了できれば、第4章からのSQL学習にそのまま入れます。

  1. 自分の環境（Docker／Podmanのコンテナ、またはWindowsインストーラ）でOracle AI Database 26ai Freeを起動する。
  2. SQL*Plusでsystem接続し、SHOW CON_NAMEでFREEPDB1にいることを確認する。
  3. 学習用ユーザーhrを作成し、3.5節の簡略版（CONNECT・RESOURCEロール）または個別付与版のどちらかで権限を与える。
  4. hrで接続し直し、SHOW USERでHRと表示されることを確認する。
  5. SQL Developerに同じ接続情報を設定し、「テスト」で成功と表示されることを確認する。

ヒント: 途中でORA-番号のエラーが出たら、まず3.7節の表を見て「まず疑うこと」を1つずつ確認してください。多くの場合、起動待ちの不足か、サービス名の指定ミス（FREEになっていないか）が原因です。

理解度確認クイズ

  1. Q1. sqlplus hr@"localhost:1521/FREEPDB1"を実行したらORA-12541（TNS: no listener）が出ました。まず何を確認すべきですか。

    回答を表示

    データベース（コンテナやインストール済みのサービス）が起動しているか、ポート1521が正しく公開・待ち受けされているかです。リスナーそのものに届いていない段階のエラーなので、ユーザー名やパスワードの問題ではありません。

  2. Q2. CREATE USER hr IDENTIFIED BY pw;を実行したらORA-65096で失敗しました。原因と対処を答えてください。

    回答を表示

    CDB$ROOT（CDBのルート）に接続したままユーザーを作ろうとしたことが原因です。ルートで作れるのはC##で始まる共通ユーザーだけなので、いったん切断してFREEPDB1に接続し直してから、あらためてCREATE USERを実行します。

  3. Q3. Oracle AI Database 26ai Freeで、学習用の表を作るために接続すべきサービス名はどれですか。(a) FREE (b) FREEPDB1 (c) PDB$SEED

    回答を表示

    (b) FREEPDB1。FREEはCDBのルート、PDB$SEEDは新しいPDBを作るための雛形なので、どちらにも業務データ（学習用の表）は作りません。
