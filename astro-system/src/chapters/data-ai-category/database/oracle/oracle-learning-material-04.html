SQL*PlusとSQL Developerの基本操作

第3章で Oracle AI Database 26ai Free につながる環境ができました。この章では、SQL を打ち込むための2つの道具「SQL*Plus」と「SQL Developer」の使い方に集中します。ここで覚える操作は、第5章以降のすべての章で毎回使う「基本の型」です。まだ自分の表は作りませんが、道具の扱いに慣れることが今回のゴールです。

この章で学ぶこと

4.1 SQL*Plus と SQL Developer、2つの道具

Oracle に SQL を送る方法はひとつではありません。本ガイドでは、性格の異なる2つのツールを使い分けます。SQL*Plus（エスキューエル・プラス）は、Oracle に標準で付属するCUI（Character User Interface / 文字だけで操作する画面のこと。黒い画面に文字を打ち込むイメージ）のツールです。もう一方の SQL Developer は、Oracle が無償で配布しているGUI（Graphical User Interface / ボタンやウィンドウを絵として表示し、マウスで操作できる画面のこと）のツールです。

たとえるなら、SQL*Plus は「文字だけの電卓」です。ボタンの絵はありませんが、キー入力だけで正確に、しかも連続して計算できます。一方、SQL Developer は「ボタンの付いた表計算ソフト」です。メニューやアイコンをクリックしながら、結果を表の形で眺めて試行錯誤できます。どちらが優れているという話ではなく、場面によって向き不向きがあります。

flowchart LR A{"何をしたい？"} -->|"手順を再現したい／自動実行したい／サーバー上で作業したい"| B["SQL*Plus"] A -->|"結果を表で眺めたい／構造をツリーで見たい／実行計画を見たい"| C["SQL Developer"] B --> D["同じ FREEPDB1 につながる"] C --> D

実務では、動作確認や調査は SQL Developer で試行錯誤し、決まった手順は SQL*Plus のスクリプトにして誰が実行しても同じ結果になるようにする、という使い方がよくあります。両方を使えることが、現場での強みになります。本章では両方の基本操作を身につけます。

初心者向け注記: 「SQL文」と「SQL*Plusコマンド」は別物です

この章にはこれから SET・COLUMN・SHOW・DESC といった単語がたくさん出てきますが、これらは SELECT のようなSQL 文ではありません。SQL*Plus コマンド（SQL*Plus という道具そのものを操作するための命令）と呼ばれる別の種類のものです。Oracle 本体（データベース）には送られず、SQL*Plus の中だけで完結します。混同すると「SQL Developer に貼り付けたのに動かない」といった原因不明のつまずきにつながるため、ここで一度整理しておきましょう。

4.2 SQL*Plus の基本操作 — 起動・接続・終了

まずは SQL*Plus を起動して Oracle につないでみましょう。ターミナル（コマンドを打ち込む黒い画面）で、次のように入力します。第2章で学んだ Easy Connect 記法（ユーザー名＠ホスト：ポート／サービス名）を思い出してください。パスワードはこのあと別途プロンプトで入力します。

ターミナル 
-- hrユーザーでFREEPDB1に接続する（第3章で作成したユーザー）
-- 書式: sqlplus ユーザー名@"ホスト:ポート/サービス名"   ← @の後ろはダブルクォートで囲む
sqlplus hr@"localhost:1521/FREEPDB1"

-- Password: プロンプトが表示されたら、hrユーザーのパスワードを入力してEnter
-- （入力した文字は画面に表示されません）
Password: ********

-- 接続に成功すると、SQL> というプロンプトが表示される
SQL>

なぜパスワードをコマンドに直接書かないのか

sqlplus hr/パスワード@... のように、コマンドラインにパスワードをそのまま書く方法もあります。しかし、この書き方はシェルのコマンド履歴に残ったり、同じマシンの他の利用者が ps コマンドなどで実行中のプロセスを見たときにパスワードが見えてしまったりする場合があります。パスワードは Password: プロンプトが表示されてから入力する方法を、本ガイドでは一貫して使います。なお、パスワードを省略するときは @ の後ろ全体をダブルクォートで囲む点に注意してください。囲まないと、接続文字列に含まれる / がパスワードの区切りと解釈されてしまうことがあります（Oracle 公式ドキュメントの例も引用符付きです）。

SQL> というプロンプト（入力を待っている合図）が出れば接続成功です。ここに SQL 文を打ち込んでいきます。作業の途中で接続ユーザーを変えたいときは、SQL*Plus を終了せずに CONNECT コマンドで切り替えられます。

SQL*Plus 
-- SQL*Plusコマンド: SQL*Plusを終了せずに、接続ユーザーを切り替える
CONNECT hr@"localhost:1521/FREEPDB1"
-- Password: プロンプトが表示されたら、hrユーザーのパスワードを入力してEnter

-- SQL*Plusコマンド: 今の自分が誰かを確認する（第3章で学んだコマンド）
SHOW USER

-- SQL*Plusコマンド: SQL*Plusを終了する
EXIT

EXIT（QUIT でも同じ）で SQL*Plus を終了します。なお、確定していない変更（COMMIT していない INSERT や UPDATE）がある状態で EXIT すると、SQL*Plus は自動的に確定してから終了します。この挙動の詳細は第7章で扱います。

EXITでの自動確定はSQL*Plus固有の既定動作

EXIT／QUIT で正常に終了した場合のみ、既定で未確定の変更が自動的に確定されます（この動作は SET EXITCOMMIT で変更可能です）。ウィンドウを閉じる・接続が切れるといった異常終了ではロールバックされますし、SQL Developer など他のツールでは挙動が異なります。どのツールを使うときも確実なのは、自分で COMMIT を実行しておくことです（第7章で詳しく学びます）。

4.3 セミコロン（;）とスラッシュ（/）の使い分け【重要】

SQL*Plus を初めて使う人が、最初につまずくのがこの使い分けです。ここは焦らず、じっくり読んでください。

通常の SQL 文（SELECT・INSERT など）は、行の最後にセミコロン「;」を付けて Enter を押すと実行されます。試しに次を入力してみましょう。

SQL*Plus 
-- セミコロンで終わっているので、Enterを押すとすぐ実行される
SELECT SYSDATE FROM dual;

-- 直前に実行した文をもう一度実行したいときは、スラッシュだけの行を入力する
/

ここで、もしセミコロンを付け忘れて Enter を押すとどうなるでしょうか。次のような表示になります。

実行結果 
SQL> SELECT SYSDATE FROM dual
  2

SQL> ではなく2 という行番号が表示されたら、それは「文がまだ終わっていないので続きを待っている」というサインです。ここで慌てる必要はありません。セミコロンだけを入力して Enter を押せば実行されます。

つまずきポイント: 行番号 2 が出て固まったように見える

セミコロンの付け忘れは初心者の定番ミスです。パニックになって強制終了する必要はありません。; とだけ入力して Enter を押すか、これから説明する単独の / を入力すれば、そのまま実行されます。

一方、PL/SQL ブロック（複数の SQL 文や条件分岐をひとまとまりにした処理。第10章で学びます）のように、複数行にまたがり内部にすでにセミコロンを含むものは、セミコロンでは実行できません。その代わり、ブロックの最後に単独の行としてスラッシュ「/」を書くことで実行します。「ここまでをひとつの塊として送信する」という合図です。

記号 使う場面 意味
;（セミコロン） SELECT・INSERT・UPDATE・DELETE などの1文の末尾 「この1文はここで終わり、実行してよい」という合図
/（スラッシュ単独行） PL/SQLブロックの直後、または直前の文の再実行 「今たまっている内容をまとめて送信する」という合図

SQL*Plus は、直前に入力した1文をバッファ（一時的に記憶しておく場所）に保持しています。単独の / は「バッファの内容をもう一度実行する」という意味でもあるため、SQL の末尾でもブロックの末尾でも使える、と覚えておくとよいでしょう。

4.4 表示を整える SET コマンド

SQL*Plus は初期設定のままだと1行の表示幅が狭く、日本語を含む表を表示すると列がずれて折り返され、とても読みにくくなります。これを直すのが SET コマンドです。

SQL*Plus 
-- SQL*Plusコマンド: 1行の表示幅を200文字に広げる（既定は狭く、折り返されやすい）
SET LINESIZE 200

-- SQL*Plusコマンド: 50行ごとに列見出しを再表示する（既定は画面が流れて見出しが消えやすい）
SET PAGESIZE 50

-- SQL*Plusコマンド: 文字列列の表示幅を半角20文字ぶんに固定する（第5章以降の表で使う）
COLUMN last_name FORMAT A20

参考 COLUMN last_name FORMAT A20 のように列ごとの表示幅を細かく調整する書式設定は、今すぐ覚える必要はありません。last_name 列は、第5章で作る employees 表の列です。今の時点ではまだ表が存在しないため見た目の効果は確認できませんが、コマンド自体はエラーにならず登録されます。第5章で表を作ったあとにもう一度試すと、列の幅がそろって見やすくなります。

SET は SQL ではなく「道具への指示」

ここが第4章で最も混同しやすい点です。SET LINESIZE や COLUMN はSQL*Plus という道具に対する設定であり、Oracle 本体（データベース）には一切送られません。SQL Developer にこれらのコマンドをそのまま貼り付けても、一部は無視されるか期待どおりに効かないことがあります。「これはデータベースへの命令」「これは道具への指示」を区別する習慣を、ここで身につけましょう。

この違いを図にすると、次のようになります。SET コマンドは SQL*Plus の中だけで完結し、Oracle 側へは届きません。

sequenceDiagram participant U as 利用者 participant P as SQL*Plus participant O as Oracle（FREEPDB1） U->>P: SET LINESIZE 200 と入力 Note over P: SQL*Plusの中だけで設定を記憶する U->>P: SELECT SYSDATE FROM dual; と入力 P->>O: SQL文だけをデータベースへ送信 O-->>P: 実行結果を返す P-->>U: 設定に沿って画面に整形表示

4.5 オブジェクトを調べるコマンド

作業中に「この表にはどんな列があったか」「今どのユーザーで接続しているか」が分からなくなることがあります。そんなときに使う3つのコマンドを紹介します。

1つ目は DESCRIBE（略して DESC）です。表の「設計図」、つまり列名・データ型・NOT NULL 制約の有無を一覧表示します。まだ自分の表がないので、Oracle に最初から用意されている DUAL（1行1列だけのダミー表。詳しくは第6章で扱います）で試してみましょう。

SQL*Plus 
-- SQL*Plusコマンド: DUAL表の構造を確認する（DESCの略記が便利）
DESC dual
実行結果 
名前                                      NULL?    型
----------------------------------------- -------- ----------------
DUMMY                                              VARCHAR2(1)

2つ目は SHOW USER と SHOW CON_NAME（いずれも第3章で使用済み）です。「今の自分が誰で、どの PDB にいるか」を確認できます。3つ目は、データディクショナリ（Oracle 自身が管理する、表やユーザーの情報を記録した特別な表群）の一つ USER_TABLES です。自分が持っている表の一覧を取得できます。

SQL*Plus 
-- SQL文: 今の自分が持っている表の一覧を見る（こちらはSQL、DESCとは違う）
SELECT table_name FROM user_tables ORDER BY table_name;

-- 第5章より前の今の時点では、まだ表を作っていないので0件になる
-- 「レコードが選択されませんでした」と表示されれば正常

重要ポイント: 迷子になったらこの3つ

SHOW USER（今の自分は誰か）、SHOW CON_NAME（今どの PDB にいるか）、DESC 表名（その表はどんな形か）。この3つを覚えておけば、作業中に迷っても現在地を取り戻せます。第5章で表を作ったら、DESC employees を実際に試してみましょう。

4.6 スクリプトファイルの実行と SPOOL によるログ保存

SQL 文を1行ずつ手で入力するのは、毎回同じ作業をするときには非効率です。SQL をテキストファイルに保存しておき、まとめて実行する方法を覚えましょう。第5章で表を作る作業も、スクリプト化しておけば「作り直し」がボタン1つで済むようになります。

SQL*Plus 
-- SQL*Plusコマンド: 保存しておいたSQLファイルをまとめて実行する（@は「アットマーク」と読む）
@C:\work\create_tables.sql

-- Linux/macOSの場合の例（パスの区切りはスラッシュ）
@/home/user/work/create_tables.sql

逆に、画面に表示された内容をファイルへ記録したいときは SPOOL（「巻き取る」という意味の英単語から。画面出力をテープに記録するイメージ）を使います。SPOOL ファイル名 で記録を開始し、SPOOL OFF で終了します。

SQL*Plus 
-- SQL*Plusコマンド: 画面に出る内容をファイルへ記録し始める
SPOOL C:\work\result.txt

-- SQL文: この間に実行したSQLと結果が、すべてファイルにも書き込まれる
SELECT SYSDATE FROM dual;

-- SQL*Plusコマンド: 記録を終了する（OFFを忘れるとファイルが閉じられないので注意）
SPOOL OFF

@ファイル名 と SPOOL を組み合わせると、「スクリプトを流し、その一部始終を記録として残す」という、現場でもよく使う手順が完成します。第14章のバックアップ確認作業でも同じ考え方を使います。

4.7 SQL Developer の基本操作

続いて SQL Developer を見てみましょう。第3章で作成した接続を開くと、画面は大きく3つの領域に分かれています。

接続ペイン（左側）

登録した接続の一覧と、表・ビューなどをツリー状に表示する場所です。表をダブルクリックすると「データ」タブでレコードを見られます。

ワークシート（中央上）

SQL 文を入力する場所です。SQL*Plus の入力画面に相当し、複数のタブを開いて並行作業もできます。

結果グリッド（中央下）

実行結果が表の形で表示される場所です。列見出しをクリックして並べ替えたり、セルをコピーしたりできます。

ワークシートでの実行方法には、大きく分けて2種類あります。この違いは、SQL*Plus の「セミコロン」と「スラッシュ単独行」の違いに通じるものです。

4.8 SERVEROUTPUTと自動コミットの設定を確認する

最後にもう2つだけ、今は効果が見えなくても先の章で必ず必要になる設定を確認しておきます。今すぐ覚え込む必要はありません。「そういう設定があった」と思い出せれば十分です。

1つ目は SET SERVEROUTPUT ON です。第10章で学ぶ PL/SQL では、DBMS_OUTPUT.PUT_LINE という命令で画面に文字を表示します。ところがこの出力機能は既定でOFFになっており、先に SET SERVEROUTPUT ON を実行しておかないと、エラーにもならないまま何も表示されません。現在の設定値は SHOW SERVEROUTPUT で確認できます。

SQL*Plus 
-- SQL*Plusコマンド: 現在の設定を確認する（既定はOFF）
SHOW SERVEROUTPUT

-- SQL*Plusコマンド: 画面出力を有効にする（第10章のDBMS_OUTPUTで使用する）
SET SERVEROUTPUT ON

SQL Developer には SET SERVEROUTPUT ON というコマンドはありません。代わりにメニューの「表示（View）」→「DBMS出力（DBMS Output）」からDBMS_OUTPUTビューを開き、緑色の「＋」ボタンで対象の接続を追加すると、同じように画面出力が有効になります（詳しい操作は第10章で扱います）。

2つ目は自動コミット設定の確認です。SQL*Plus では SHOW AUTOCOMMIT で確認でき、既定はOFFです。SQL Developer にも、環境設定（Preferences）の「データベース」内に同じ意味を持つ「Autocommit（自動コミット）」のチェックボックスがあり、こちらも既定ではオフになっています。

SQL*Plus 
-- SQL*Plusコマンド: 自動コミットの設定状況を確認する（既定はOFF）
SHOW AUTOCOMMIT

既定では自動コミットされない（第7章で詳しく学びます）

AUTOCOMMIT がOFFということは、INSERT・UPDATE・DELETE を実行しただけでは確定されず、自分で COMMIT を打つ必要があるということです。SET AUTOCOMMIT ON にすれば1文ごとに自動確定させることもできますが、確定のタイミングを自分でコントロールする感覚を身につけるため、学習中はOFFのままにしておくことをおすすめします。

この2つの設定は、今の時点で無理に使いこなす必要はありません。SET SERVEROUTPUT ON は第10章、自動コミットの考え方は第7章で、実際に手を動かしながらあらためて登場します。困ったときは、この節に戻ってきてください。

やってみよう 4-1: SQL*Plus と SQL Developer の両方を動かす

第3章で作った hr ユーザーを使って、実際に手を動かしてみましょう。まだ自分の表が無いので、DUAL 表と現在時刻を題材にします。

  1. ターミナルから sqlplus hr@"localhost:1521/FREEPDB1" と入力し、Password: プロンプトが出たら hr ユーザーのパスワードを入力して接続する。
  2. SELECT SYSDATE FROM dual とセミコロンを付けずに Enter を押し、行番号 2 が出ることを確認する。続けて ; だけを入力して実行する。
  3. 単独の / を入力し、直前の文がもう一度実行されることを確認する。
  4. SET LINESIZE 200 と DESC dual を実行し、表示が整うことを確認する。
  5. EXIT で SQL*Plus を終了し、今度は SQL Developer で同じ接続を開き、ワークシートで同じ SELECT 文を Ctrl + Enter で実行する。

ヒント: 手順2〜3で「行番号が出て固まった」と感じても、それはエラーではありません。SQL*Plus が続きを待っているだけです。落ち着いて ; を入力しましょう。

理解度確認クイズ

  1. Q1. SQL*Plus で SELECT * FROM employees と入力して Enter を押したが、結果が出ずに 2 という行番号が表示された。何が起きているか。

    回答を表示

    セミコロンを付けていないため、SQL*Plus が文の続きを待っている状態です。; を入力して Enter を押せば実行されます。

  2. Q2. DESC employees と SELECT * FROM employees; は何が違うか。

    回答を表示

    DESC は表の「設計図」（列名・データ型・NULL 可否）を見る SQL*Plus のコマンドで、SELECT は表の「中身（データ）」を取り出す SQL です。前者は道具へのコマンド、後者はデータベースへ送る命令という違いもあります。

  3. Q3. SQL Developer のワークシートに CREATE TABLE と INSERT を続けて書いた。まとめて実行するにはどうすればよいか。

    回答を表示

    実行したい範囲を選択し、F5（スクリプトとして実行）を使います。Ctrl + Enter はカーソル位置の1文しか実行しないため、複数文をまとめて流したいときには使いません。
