ホーム SQL Server 第3章
第3章 所要時間: 約75分

環境構築とインストール

前章までで SQL Server の仕組みが分かったところで、いよいよ手を動かします。この章では、自分の PC に SQL Server を導入し、SSMS などのクライアントツールから接続して、実際に SQL を実行できる状態を作ります。Windows・macOS/Linux（Docker）のどちらでも学習を始められるように解説します。

この章で学ぶこと

  • 自分の OS に合った学習環境（Windows直接／Docker／クラウド）を選べる
  • Windows へ SQL Server 2022 Developer Edition をインストールできる
  • macOS/Linux では Docker コンテナで SQL Server を起動できる
  • SSMS などのクライアントツールを導入し、接続確認ができる
  • よくある接続トラブルの原因を切り分け、自力で解決できる

3.1 学習環境の選び方

SQL Server を学ぶための環境は、お使いの OS によって選び方が変わります。大きく分けると「Windows へ直接インストール」「macOS/Linux では Docker コンテナで起動」「クラウド（Azure SQL）を使う」の3択です。まずは全体像を比較しておきましょう。

本ガイドの推奨

Windows を使っている方は 3.2 の手順で SQL Server 2022 Developer Edition を直接インストールしてください。macOS・Linux の方は 3.3 の Docker を使う方法が最短です。どちらも無償で、学習に必要な機能はすべて使えます。

3.2 Windowsへのインストール

Windows では、Microsoft の公式サイトから SQL Server 2022 Developer Edition のインストーラを無償で入手できます。インストーラ自体は小さなプログラムで、実際のセットアップファイルはこのあとダウンロードされます。

  1. 1 Microsoft の SQL Server ダウンロードページから「Developer」版のインストーラを入手し、実行する。
  2. 2 インストールの種類を選ぶ画面で 「基本」を選択する（既定構成で最短にインストールされる）。インスタンス名・認証モード・照合順序を自分で選びたい場合は「カスタム」を選ぶ。
  3. 3 ライセンス条項に同意し、インストール先フォルダを確認してそのまま進める。
  4. 4 インストール完了後に表示される画面で、接続に使うインスタンス名・サーバー名を控えておく（設定内容の詳細は下記）。

「基本」インストールでは細かい選択肢は省略され、次の3つはすべて既定値に固定されます。値を選びたい場合は「カスタム」インストールが必要です。初心者のうちは意味だけ押さえておけば十分です。

設定項目 内容
インスタンス名 「基本」では MSSQLSERVER（既定インスタンス）に固定。学習用に別名を付けたい場合は「カスタム」で名前付きインスタンスを選べる（第2章参照）。
認証モード Windows認証（Windowsのログインアカウントで接続）と混合モード（Windows認証＋ID/パスワードのSQL Server認証）の2種類。「基本」では Windows 認証に固定されるため、混合モード（sa）を使いたい場合は「カスタム」インストールを選ぶ。
照合順序（Collation） 文字の並び順・大文字小文字の扱いを決める設定。日本語環境の既定は Japanese_CI_AS など。特別な理由がなければ既定のままでよい。

混合モードを選んだら sa パスワードを必ず設定

カスタムインストールで混合モードを選ぶと、SQL Server 標準の管理者アカウント sa（system administrator）のパスワードを設定する画面が出ます。8文字以上で、大文字・小文字・数字・記号のうち3種類以上を含むパスワードにしてください。単純なパスワードはインストーラ自体に拒否されます。忘れると sa でのログインができなくなるので、必ずメモしておきましょう。

3.3 macOS/Linux（Docker）での起動

macOS や Linux では、Microsoft が公式に配布している Dockerイメージを使うのが最も手軽です。事前に Docker Desktop（macOS/Windows）や Docker Engine（Linux）がインストールされている必要があります。

terminal 
# SQL Server 2022 のイメージでコンテナをバックグラウンド起動する
docker run -e "ACCEPT_EULA=Y" \
  -e "MSSQL_SA_PASSWORD=P@ssw0rd2022!" \
  -p 1433:1433 \
  --name sqlserver2022 \
  -d mcr.microsoft.com/mssql/server:2022-latest

各オプションの意味は、ACCEPT_EULA=Y がライセンス条項への同意、MSSQL_SA_PASSWORD が sa アカウントのパスワード、-p 1433:1433 がコンテナの1433番ポートをホストの1433番へつなぐ設定、--name がコンテナ名、-d がバックグラウンド実行です。

terminal 
# コンテナが起動しているか確認する（STATUS が Up ならOK）
docker ps

# 停止する
docker stop sqlserver2022

# 再度起動する（初回インストールはしない、既存コンテナの再開）
docker start sqlserver2022

パスワードの複雑さ要件に注意

MSSQL_SA_PASSWORD は Windows 版と同じ複雑さ要件（8文字以上で、大文字・小文字・数字・記号のうち3種類以上を含む）を満たさないと、コンテナが起動直後に停止してしまいます。docker ps で STATUS が Exited になっていたら、まずパスワードを疑いましょう。

3.4 クライアントツールの導入

SQL Server 本体（サーバー側）を起動しただけでは、まだ SQL を実行できません。サーバーに接続して操作するためのクライアントツールを導入します。本ガイドでは Windows での標準ツール SSMS（SQL Server Management Studio）を中心に扱います。

  1. 1 Microsoft の公式ページから SSMS のインストーラをダウンロードし、実行する（無償）。
  2. 2 インストール完了後に SSMS を起動すると「サーバーへの接続」ダイアログが表示される。
  3. 3 サーバー名を入力する。既定インスタンスなら localhost、名前付きインスタンスなら localhost\SQLEXPRESS、ポート指定なら localhost,1433 のように書く。
  4. 4 認証を選ぶ。Windows認証でインストールした場合は「Windows認証」のまま、混合モードなら「SQL Server認証」を選び sa とパスワードを入力する。
  5. 5 Docker 環境など証明書が未設定の場合、「サーバー証明書を信頼する」オプションにチェックが必要になることがある。学習環境では有効にして問題ない。

SSMS は Windows 専用のため、macOS / Linux では別の選択肢が必要です。現在の推奨は Visual Studio Code ＋ MSSQL 拡張機能です。VS Code に拡張機能を追加するだけで、接続・クエリ実行・結果表示ができます。なお、かつてクロスプラットフォームの標準ツールだった Azure Data Studio は 2026年2月にサポートが終了し、後継は VS Code の MSSQL 拡張機能とされています。これから学ぶ方が新たに導入する必要はありません。

SSMS

Windows専用。高機能な GUI で管理・開発の両方に対応。本ガイドの標準ツール（第4章）。

sqlcmd

コマンドラインツール。OS を問わず使え、自動化スクリプトにも組み込める（第4章）。

VS Code + MSSQL拡張

Windows/macOS/Linux で動く。macOS・Linux ユーザーの標準的な選択肢。

3.5 接続できたか確認する

SSMS などで接続できたら、まずはバージョン情報を取得する SQL を実行して、正しく通信できているか確かめましょう。SSMS の「新しいクエリ」からクエリエディタを開き、次の1文を実行します（F5 キーで実行、詳細は第4章）。

query.sql 
-- サーバーのエディション・バージョン・OSの情報を確認する
SELECT @@VERSION;

GUI を使わず、コマンドラインの sqlcmd から接続することもできます。Docker コンテナの場合は、コンテナ内に同梱されている sqlcmd を使うのが手軽です。

terminal 
# コンテナ内のsqlcmdでSQL Serverへ接続する
docker exec -it sqlserver2022 /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U sa -P "P@ssw0rd2022!" -C

# 接続後、プロンプトにSQLを入力してGOで実行する
1> SELECT @@VERSION;
2> GO

動作確認

実行結果に Microsoft SQL Server 2022 ... のような文字列が表示されれば接続成功です。ここまで来れば環境構築は完了、第4章から実際に SSMS を使ったデータベース操作へ進みます。

3.6 よくあるトラブルと対処

接続作業でつまずくポイントはある程度決まっています。エラーメッセージを見て焦る前に、次の表で切り分けましょう。

接続エラーが出たら、まず「サービスが動いているか」を疑う

接続系トラブルの大半は、SQL Server のサービス自体が起動していない・止まっていることが原因です。焦らずサービスの状態から確認しましょう。

症状 主な原因 対処
サーバーが見つからない SQL Server のサービスが停止している 「サービス」アプリ（services.msc）で SQL Server (MSSQLSERVER) を起動する
名前付きインスタンスに繋がらない SQL Server Browser サービスが停止している、または TCP/IP プロトコルが無効 「サービス」アプリで SQL Server Browser を開始し、SQL Server Configuration Manager でTCP/IPを有効化してサービスを再起動する
別PC・Dockerホスト外から繋がらない ファイアウォールが1433番ポートを遮断している Windowsファイアウォールで1433番の受信を許可する
サーバー名のエラー サーバー名の書式間違い（. と \ の位置など） localhost・.\インスタンス名・localhost,ポート番号 の書式を確認する
ログインに失敗する sa のパスワードを間違えている、または大文字小文字を誤入力 インストール時にメモしたパスワードを再確認する。忘れた場合は、Windows 認証で接続できる管理者から ALTER LOGIN sa WITH PASSWORD = ... で再設定できる

3.7 PostgreSQLとの違い

環境構築の手順そのものも、SQL Server と PostgreSQL では考え方が異なります。PostgreSQL の経験がある方は、次の対応表で頭を整理しておきましょう。

PostgreSQL との違い（環境構築編）

観点 SQL Server PostgreSQL
既定ポート 1433 5432
初期化の手順 インストーラがGUIで一括セットアップ initdb コマンドでクラスタを明示的に初期化
サービス名 SQL Server (インスタンス名) postgresql
既定の管理者 sa（SQL Server認証時） postgres
接続CLI sqlcmd psql
公式Dockerイメージ mcr.microsoft.com/mssql/server postgres
認証設定の場所 インストーラのGUI／T-SQLで設定 設定ファイル pg_hba.conf を編集

PostgreSQL はコマンドラインでの初期化・設定ファイル編集が中心なのに対し、SQL Server はインストーラや GUI ツールで完結する場面が多いのが特徴です。どちらも「サーバーを起動し、ポートを開け、認証を設定する」という流れ自体は同じです。

やってみよう 3-1: 自分の環境にSQL Serverを構築する

実際に手を動かして、自分の PC で SQL Server に接続できる状態を作りましょう。

手順

  1. 1 お使いの OS に応じて、3.2（Windows）または 3.3（macOS/Linux・Docker）の手順で SQL Server をインストール・起動する。
  2. 2 3.4 の手順で SSMS（Windows）または VS Code の MSSQL 拡張機能（macOS/Linux）を導入し、サーバーへ接続する。
  3. 3 SELECT @@VERSION; を実行し、表示されたバージョン文字列をメモに残す。

ねらい: 「インストール手順を読む」だけでなく実際に完走することで、第4章以降のハンズオンにスムーズに入れるようにします。エラーが出たら3.6の表で原因を切り分けてみましょう。

理解度確認クイズ

  1. Q1. Windows へのインストール時に「混合モード」を選んだ場合、追加で設定が必要になるアカウントは何ですか。

    回答を表示

    sa（system administrator）アカウントです。混合モードでは、Windows認証に加えて sa のパスワードを複雑さ要件を満たす形で設定する必要があります。

  2. Q2. macOS で SQL Server 2022 のコンテナを起動する docker run コマンドに、必ず指定しなければならない環境変数を2つ挙げてください。

    回答を表示

    ACCEPT_EULA=Y（ライセンス条項への同意）と MSSQL_SA_PASSWORD（sa パスワード）です。どちらか一方でも欠けるとコンテナは正常に起動しません。

  3. Q3. SSMS で接続できず「サーバーが見つからない」というエラーが出た場合、最初に確認すべきことは何ですか。

    回答を表示

    SQL Server のサービスが起動しているかどうかです。接続系トラブルの多くはサービス停止が原因のため、「サービス」アプリ（services.msc）や Docker の場合は docker ps で稼働状況を確認します。
