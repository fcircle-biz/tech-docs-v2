ホーム SQL Server 第6章
第6章 所要時間: 約75分

SELECT文でデータを取り出す

第5章で作成した学習用データベース SampleShop（Customers・Products・Orders）を使って、SQL の中心である SELECT 文を学びます。列の絞り込みから条件検索、並べ替え、件数制限、条件分岐、関数まで、データを「取り出す」ための一通りの武器をそろえます。

この章で学ぶこと

  • SELECT 文で列を選び、別名や計算列を付けて取り出せる
  • WHERE 句で条件を組み合わせて絞り込め、NULL を正しく扱える
  • ORDER BY・DISTINCT・TOP・OFFSET/FETCH で並べ替えと件数制限ができる
  • CASE 式とよく使う組み込み関数を使い、PostgreSQL との違いも説明できる

6.1 SELECT の基本形

SELECT 文は「どの表の、どの列を、どんな条件で取り出すか」を指示する SQL の中心構文です。まずは第5章で作った SampleShop データベースの Customers テーブルを例に、基本の形を確認しましょう。

select-basic.sql 
-- 全列を取り出す（* はアスタリスク）
SELECT * FROM Customers;

-- 列を指定して取り出す
SELECT CustomerName, Email FROM Customers;

-- 列に別名（AS）を付ける
SELECT CustomerName AS 顧客名, Email AS メールアドレス
FROM Customers;

-- 計算列（単価に消費税10%を加算）
SELECT ProductName, UnitPrice, UnitPrice * 1.1 AS 税込価格
FROM Products;

AS は省略もできますが（CustomerName 顧客名）、読みやすさのために明示するのがおすすめです。計算列のように元のテーブルに存在しない値も、式を書くだけでその場で作れるのが SQL の便利なところです。

注意: 業務では SELECT * を避ける

SELECT * は動作確認には便利ですが、業務のコードでは避けるのが基本です。理由は3つあります。①テーブルに列が追加・削除されると結果の列構成が予告なく変わる、②不要な列まで転送されて性能が落ちる、③アプリ側で「どの列を使っているか」が読み取れずコードの見通しが悪くなる。必要な列だけを明示的に指定する習慣をつけましょう。

6.2 WHERE で絞り込む

WHERE 句は「条件に合う行だけ」を取り出すための仕組みです。まずは比較演算子を確認しましょう。

演算子 意味 例
= 等しい Quantity = 1
<> 等しくない（!= も使用可） Quantity <> 1
> / >= より大きい／以上 UnitPrice >= 1000
< / <= より小さい／以下 UnitPrice < 1000

複数の条件を組み合わせるには AND（かつ）・OR（または）・NOT（否定）を使います。AND は OR より先に評価されるため、意図した優先順位にしたいときは括弧で明示しましょう。

where-and-or.sql 
-- 1000円以上、かつ販売中の商品
SELECT ProductName, UnitPrice
FROM Products
WHERE UnitPrice >= 1000 AND IsActive = 1;

-- 括弧で優先順位を明示（誤解を防ぐ）
SELECT ProductName, UnitPrice
FROM Products
WHERE IsActive = 1 AND (UnitPrice < 500 OR UnitPrice > 5000);

範囲や候補を指定するときは BETWEEN・IN・LIKE が便利です。

where-between-in-like.sql 
-- BETWEEN: 500円〜2000円の範囲（両端を含む）
SELECT ProductName, UnitPrice FROM Products
WHERE UnitPrice BETWEEN 500 AND 2000;

-- IN: 特定の注文数量に絞り込む
SELECT OrderId, Quantity FROM Orders
WHERE Quantity IN (1, 5, 10);

-- LIKE: 「田」を含む顧客名（% は0文字以上、_ は任意の1文字）
SELECT CustomerName FROM Customers
WHERE CustomerName LIKE N'%田%';

-- LIKE: 任意の2文字のあとが「様」で終わる名前（_ は任意の1文字）
SELECT CustomerName FROM Customers
WHERE CustomerName LIKE N'山%';

日本語を含む文字列リテラルには N'...' のように先頭に N を付けます。これは列の型が nvarchar（Unicode 文字列）であることを明示し、文字化けを防ぐための書き方です（第5章で学んだ nvarchar 型に対応します）。

重要ポイント: NULL は「= NULL」では見つからない

NULL は「値が無い（未入力・不明）」という特殊な状態であり、「0」や「空文字」とは異なります。SQL では「NULL と何かを比較した結果」は真でも偽でもなく「不明（UNKNOWN）」になるため、WHERE Email = NULL は常に1件もヒットしません。NULL かどうかを調べるには専用の IS NULL / IS NOT NULL を使います。

where-is-null.sql 
-- 誤り: これは常に0件（NULLとの比較は常に「不明」）
SELECT * FROM Customers WHERE Email = NULL;

-- 正しい: メールアドレス未登録の顧客を探す
SELECT CustomerName FROM Customers WHERE Email IS NULL;

-- 正しい: メールアドレスが登録済みの顧客を探す
SELECT CustomerName FROM Customers WHERE Email IS NOT NULL;

6.3 並べ替えと重複除去

ORDER BY は結果の並び順を指定します。ASC（昇順・既定値）と DESC（降順）が選べ、複数の列をカンマで並べると「1つ目の列が同じ値のときに2つ目の列で並べ替える」という優先順位が付きます。

order-by.sql 
-- 単価が高い順（降順）
SELECT ProductName, UnitPrice FROM Products
ORDER BY UnitPrice DESC;

-- 複数キー: 顧客IDの昇順、同じ顧客の中では注文日の降順
SELECT CustomerId, OrderDate, Quantity FROM Orders
ORDER BY CustomerId ASC, OrderDate DESC;

DISTINCT は、結果に含まれる重複した行を1つにまとめるキーワードです。「注文のあった顧客IDの一覧（重複なし）」のように、値の種類だけを知りたいときに使います。

distinct.sql 
-- 注文した顧客IDの一覧（重複を除去）
SELECT DISTINCT CustomerId FROM Orders;

6.4 件数を絞る

SQL Server では、上位から指定した件数だけを取り出すのに TOP 句を使います。件数は括弧付きの TOP (10) という書き方が推奨形です（括弧なしの TOP 10 も動きますが、UPDATE/DELETE と組み合わせる場合など括弧が必須になる場面があるため、常に括弧を付ける習慣が安全です）。

top.sql 
-- 単価が高い上位10件の商品
SELECT TOP (10) ProductName, UnitPrice
FROM Products
ORDER BY UnitPrice DESC;

-- 全体の上位10パーセントの商品（件数ではなく割合）
SELECT TOP (10) PERCENT ProductName, UnitPrice
FROM Products
ORDER BY UnitPrice DESC;

TOP は必ず先頭から件数を切るだけですが、「11件目から20件目だけ欲しい」といったページング（一覧の2ページ目、3ページ目…）には ORDER BY ... OFFSET ... FETCH NEXT ... ROWS ONLY を使います。OFFSET は「何件読み飛ばすか」、FETCH NEXT は「その後何件取るか」を表します。

offset-fetch.sql 
-- 単価の安い順に並べ、11件目〜20件目を取得（2ページ目相当）
SELECT ProductName, UnitPrice
FROM Products
ORDER BY UnitPrice ASC
OFFSET 10 ROWS FETCH NEXT 10 ROWS ONLY;

ヒント: OFFSET/FETCH には ORDER BY が必須

OFFSET ... FETCH NEXT ... は「何番目から何件」を切り出す構文なので、並び順が決まっていないと意味を持ちません。そのため ORDER BY を省略するとエラーになります。一覧画面のページングを実装するときの定番パターンとして覚えておきましょう。

6.5 CASE 式で条件分岐

CASE 式は、条件によって値を出し分ける「SQL の中の if 文」です。書き方には、値を1つずつ比較する単純CASEと、任意の条件式を書ける検索CASEの2種類があります。

case-simple.sql 
-- 単純CASE: 値そのものを比較する
SELECT OrderId, Quantity,
    CASE Quantity
        WHEN 1 THEN N'単品'
        WHEN 2 THEN N'2個セット'
        ELSE N'まとめ買い'
    END AS 購入区分
FROM Orders;

実務でよく使うのは、範囲や複数条件を扱える検索CASEです。例えば商品の価格帯を「安い・普通・高い」に区分けする場合はこう書きます。

case-searched.sql 
-- 検索CASE: 任意の条件式（範囲判定など）を書ける
SELECT ProductName, UnitPrice,
    CASE
        WHEN UnitPrice < 1000 THEN N'安い'
        WHEN UnitPrice BETWEEN 1000 AND 4999 THEN N'普通'
        ELSE N'高い'
    END AS 価格帯
FROM Products
ORDER BY UnitPrice;

ELSE を省略すると、どの条件にも当てはまらない行は自動的に NULL になります。意図しない NULL を避けるため、基本は ELSE を書くようにしましょう。

6.6 よく使う組み込み関数

SELECT の中では、日付・文字列・数値を加工する組み込み関数が使えます。まずはよく使うものを一覧で押さえましょう。

関数 分類 説明
GETDATE() / SYSDATETIME() 日付 現在の日時を返す。SYSDATETIME() はより高精度
LEN(文字列) 文字列 文字数を返す（末尾の空白は数えない）
SUBSTRING(文字列, 開始, 長さ) 文字列 指定位置から指定長さを切り出す
UPPER() / LOWER() 文字列 大文字／小文字に変換
CONCAT(値1, 値2, ...) 文字列 文字列を連結する（NULL は空文字として扱う）
ISNULL(式, 代替値) NULL処理 式が NULL のとき代替値を返す（SQL Server 独自）
COALESCE(式1, 式2, ...) NULL処理 最初に NULL でない値を返す（標準SQL・複数指定可）
CAST(式 AS 型) / CONVERT(型, 式) 型変換 型を変換する。CONVERT は日付の書式指定も可能
FORMAT(式, 書式) 書式変換 日付や数値を指定の書式文字列で整形する
ROUND(数値, 桁数) 数値 指定した桁数で四捨五入する
functions.sql 
SELECT
    CustomerName,
    -- 文字列連結は + 演算子（片方でもNULLだと結果はNULL）
    CustomerName + N'様' AS 敬称付き氏名,
    -- メール未登録なら「未登録」と表示
    ISNULL(Email, N'未登録') AS メール表示,
    -- 登録日を「2026年08月28日」の形式に整形
    FORMAT(CreatedAt, N'yyyy年MM月dd日') AS 登録日表示
FROM Customers;

用語: 文字列連結は「+」

SQL Server では文字列の連結に + 演算子を使います。ただし + は片方でも NULL があると結果全体が NULLになる点に注意が必要です。NULL を空文字として扱いたい場合は CONCAT() 関数、または ISNULL() と組み合わせて使いましょう。

6.7 PostgreSQLとの違い

SELECT 文の骨格そのものは標準 SQL に沿っているため SQL Server と PostgreSQL でほぼ共通ですが、件数制限・文字列連結・NULL 処理・関数名まわりには方言の違いがあります。移行やマルチDB開発で戸惑いやすいポイントをまとめます。

PostgreSQL との違い（SELECT編）

観点 SQL Server PostgreSQL
件数の絞り込み SELECT TOP (10) ... SELECT ... LIMIT 10
ページング構文 OFFSET ... FETCH NEXT ...（両対応） LIMIT ... OFFSET ...（両対応）
文字列連結 +（NULL混在は結果もNULL） ||（NULLの扱いは同様に注意）
NULL の代替値 ISNULL(式, 代替値)（独自・2引数） COALESCE(式1, 式2, ...)（標準・可変長）
文字数取得 LEN()（末尾空白を含まない） LENGTH()（末尾空白も含む）
現在日時 GETDATE() NOW() / CURRENT_TIMESTAMP
文字列比較の大小文字 既定の照合順序では区別しない 既定で区別する（大文字小文字は別物）
日付の書式変換 CONVERT() / FORMAT() TO_CHAR()
真偽値の扱い WHERE IsActive = 1（bit型は0/1） WHERE is_active（真のboolean型）

とくに注意したいのは大文字小文字の扱いです。文字の比較・並び順・大文字小文字の区別などを決めるルールのことを照合順序（Collation）と呼びます。SQL Server はデータベースや列ごとに照合順序を設定でき、多くの日本語環境で使われる既定の照合順序では「大文字小文字を区別しない」設定になっているため、WHERE CustomerName = N'yamada' でも「Yamada」がヒットします。この挙動は照合順序の設定に依存するため、区別する照合順序が選ばれている環境では結果が変わります。PostgreSQL は既定で区別するため、同じ検索条件でも結果が変わることがあります。

ヒント: LEN() と DATALENGTH() は別物

LEN() は「文字数」を返しますが、DATALENGTH() は「バイト数」を返します。nvarchar（Unicode）は目安として1文字あたり2バイトを使うため、日本語の文字列では両者の値が一致しません（正確には文字によって使用バイト数が異なります。詳しくは下記の発展を参照）。バイト数ではなく文字数を数えたいときは LEN() を使いましょう。

発展: nvarchar は本当に「1文字2バイト」なのか

nvarchar は、Unicode の文字をビット列に変換して保存するための方式のひとつ（正式名称: UTF-16）を使って文字を格納します。ひらがな・カタカナ・大半の漢字・英数字などほとんどの文字は2バイト（1コード単位）で表現できますが、絵文字や一部の非常に珍しい漢字のように、2コード単位（4バイト）を組にして初めて1文字を表せる文字（サロゲートペア）もあります。そのため「1文字2バイト」はあくまで目安であり、正確には文字の種類によって使用バイト数が異なります。また nvarchar(50) のように型に付ける数値も、バイト数ではなく文字数（正確にはUTF-16のコード単位の個数）を表している点に注意しましょう。業務でよく使う日本語・英数字の範囲では「2バイト目安」で困ることはほとんどありませんが、絵文字などを扱う可能性がある場合は正確な挙動を意識しておくと安心です。

やってみよう 6-1: SampleShop を検索してみる

第5章で作った SampleShop の各テーブルに、SSMS の新しいクエリで数件ずつデータを INSERT してから（第7章で詳しく学びますが、今は動作確認用に自由に数行入れて構いません）、以下の SELECT 文を自分で書いて実行してみましょう。

手順

  1. 1 条件付き検索: Products から、単価が 1,000円以上 かつ 販売中（IsActive = 1）の商品だけを、商品名と単価の2列で取り出す SELECT 文を書く。
  2. 2 並べ替え: 手順1の結果に ORDER BY を追加し、単価の高い順に並び替える。
  3. 3 上位N件: 手順2の結果の先頭3件だけを TOP を使って取得する（=最も高い商品トップ3）。

ねらい: 「絞り込み → 並べ替え → 件数制限」という一連の流れを自分の手で組み立てることで、実務のレポート抽出クエリの土台が作れることを体感します。

理解度確認クイズ

  1. Q1. WHERE Email = NULL という条件を書くと、なぜメールアドレスが未登録の行を取得できないのですか。正しい書き方も答えてください。

    回答を表示

    NULL は「値が無い」という特殊な状態で、NULL を含む比較の結果は真でも偽でもなく「不明」になるため、= NULL はどの行にも一致しません。未登録の行を探すには WHERE Email IS NULL を使います。

  2. Q2. SQL Server の TOP 句と PostgreSQL の LIMIT 句の違いを説明してください。また、両方の製品で使えるページング構文の名前も挙げてください。

    回答を表示

    件数を絞る構文名が違うだけで役割は同じです。SQL Server は SELECT TOP (10) ...、PostgreSQL は SELECT ... LIMIT 10 と書きます。ページングには両方とも ORDER BY ... OFFSET ... FETCH NEXT ...（PostgreSQLは LIMIT ... OFFSET ...も使用可）が使えます。

  3. Q3. ISNULL() と COALESCE() はどちらも NULL を別の値に置き換える関数ですが、何が違いますか。

    回答を表示

    ISNULL(式, 代替値) は SQL Server 独自の関数で、引数は常に2つです。COALESCE(式1, 式2, ...) は標準SQLに含まれる関数で、3つ以上の値を渡して「最初にNULLでないもの」を選べます。PostgreSQLなど他のRDBMSへの移植性を考えるなら COALESCE を使うのが安全です。
