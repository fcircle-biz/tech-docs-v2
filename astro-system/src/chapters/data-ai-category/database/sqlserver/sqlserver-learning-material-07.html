ホーム SQL Server 第7章
第7章 所要時間: 約60分

データの追加・更新・削除

前章では SELECT でデータを取り出す方法を学びました。この章では、データを追加（INSERT）・更新（UPDATE）・削除（DELETE）する方法を学びます。あわせて、実務で最も恐れられている「WHERE句の付け忘れ事故」を防ぐ手順や、結果を確認しながら操作できる OUTPUT 句、MERGE 文までを扱います。

この章で学ぶこと

  • INSERT 文で1行・複数行のデータを追加できる
  • UPDATE / DELETE を安全に使い、WHERE 句の付け忘れ事故を防ぐ手順を実践できる
  • DELETE と TRUNCATE TABLE の違いを理解し、使い分けられる
  • OUTPUT 句と MERGE 文の基本を理解する

7.1 INSERT でデータを追加する

この章では、学習用データベース SampleShop の Customers（顧客）・Products（商品）・Orders（注文）の3テーブルを使います。いずれも先頭列（CustomerId / ProductId / OrderId）が IDENTITY（自動連番）です。

INSERT 文は「どの列に」「どんな値を」入れるかを指定してデータを追加します。列名は省略せず明示するのが基本です。テーブルの列順に依存すると、あとで列が追加されたときに事故が起きるためです。

insert_basic.sql 
-- 列を指定して1行追加する（IDENTITY列 CustomerId は指定しない）
INSERT INTO dbo.Customers (CustomerName, Email, CreatedAt)
VALUES (N'山田太郎', N'yamada@example.com', GETDATE());

日本語などの全角文字を含む文字列リテラルの前には、N を付けます。N'山田太郎' のように書くことで、SQL Server に「これは nvarchar（Unicode文字列）として扱ってほしい」と伝えられます。N を省略すると、環境によっては日本語が文字化けすることがあるため、日本語を含む文字列には必ず付ける習慣をつけましょう。

VALUES はカンマで区切って複数行まとめて書けます。1回のINSERT文で何行も追加でき、1行ずつ実行するより高速です。

insert_multi_rows.sql 
-- 複数行をまとめて追加する
INSERT INTO dbo.Products (ProductName, UnitPrice, IsActive)
VALUES
    (N'ノートパソコン', 128000, 1),
    (N'ワイヤレスマウス', 2980, 1),
    (N'USBメモリ 64GB', 1580, 1);

別のテーブル（や同じテーブル）の SELECT 結果をそのまま追加したい場合は INSERT ... SELECT を使います。VALUES の代わりに SELECT 文を書くだけです。

insert_select.sql 
-- CustomersArchive（別途用意したアーカイブ用テーブル）の結果を Customers へ追加する
INSERT INTO dbo.Customers (CustomerName, Email, CreatedAt)
SELECT CustomerName, Email, GETDATE()
FROM dbo.CustomersArchive
WHERE CreatedAt >= '2026-01-01';

ヒント: IDENTITY列にどうしても値を指定したいとき

通常 CustomerId のような IDENTITY 列には値を指定できません（自動採番されるため）。データ移行などでどうしても特定の値を入れたい場合だけ、SET IDENTITY_INSERT dbo.Customers ON; を実行してから CustomerId を含めて INSERT し、終わったら SET IDENTITY_INSERT dbo.Customers OFF; に戻します。日常の業務ではほとんど使わない特殊な操作です。

7.2 UPDATE でデータを更新する

UPDATE 文は、既存の行の値を書き換えます。基本形は「どのテーブルの」「どの列を」「どんな条件の行だけ」書き換えるかを指定する形です。

update_basic.sql 
-- ProductId が 2 の商品の単価だけを更新する
UPDATE dbo.Products
SET UnitPrice = 2680
WHERE ProductId = 2;

複数の列を同時に更新したい場合は、SET の後にカンマ区切りで列を並べます。

update_multi_columns.sql 
-- メールアドレスと登録日時をまとめて更新する
UPDATE dbo.Customers
SET Email = N'yamada.new@example.com',
    CreatedAt = GETDATE()
WHERE CustomerId = 1;

SQL Server には UPDATE ... FROM という独自の構文があり、別のテーブルの値を条件や更新値に使うことができます。以下は「2020年より前の注文がある商品」をまとめて非公開（IsActive = 0）にする例です。

update_from_join.sql 
-- Ordersと結合し、2020年より前の注文がある商品を非公開にする
UPDATE p
SET p.IsActive = 0
FROM dbo.Products AS p
INNER JOIN dbo.Orders AS o ON o.ProductId = p.ProductId
WHERE o.OrderDate < '2020-01-01';

UPDATE p SET ... のように、FROM で付けたエイリアス（別名）に対して SET できるのがポイントです。JOIN の書き方自体は次章で詳しく学びます。

7.3 DELETE でデータを削除する

DELETE 文は行そのものを削除します。UPDATE と同じく WHERE で対象を絞り込みます。

delete_basic.sql 
-- OrderId が 10 の注文を1件だけ削除する
DELETE FROM dbo.Orders
WHERE OrderId = 10;

第5章で学んだとおり、Orders.CustomerId は Customers.CustomerId を参照する外部キーです。注文履歴が残っている顧客を削除しようとすると、参照整合性が壊れてしまうため SQL Server はエラーを返して削除を拒否します。

delete_fk_error.sql 
-- Ordersにこの顧客の注文が残っている場合、エラーになる
DELETE FROM dbo.Customers
WHERE CustomerId = 1;
-- メッセージ 547: DELETE ステートメントが REFERENCE 制約 "FK__Orders__Customer__..." と競合しました。
-- （第5章のように名前を付けずに外部キーを作ると、制約名は自動生成される）

このエラーはデータベースが壊れたデータを防いでくれている状態です。「注文履歴がある顧客のIDが、注文からは参照できるのに顧客テーブルには存在しない」という矛盾を未然に防いでいます。削除したい場合は、先に該当する Orders を削除するか、顧客を無効化するフラグを立てる設計に変えるのが一般的です。

7.4 【重要】WHERE の付け忘れ事故を防ぐ

UPDATE・DELETE で WHERE を書き忘れると、テーブルの全行が更新・削除されてしまいます。これは実務データベース事故の代表例で、「WHERE句なしのDELETEで本番データが全消去された」という話は決して珍しくありません。

危険: WHEREなしのUPDATE / DELETEは全行が対象になる

次の文はどちらも「1件だけ」のつもりで書いても、WHERE がなければ Products テーブルの全行が対象になります。実行前に必ず落ち着いて確認しましょう。

UPDATE dbo.Products SET UnitPrice = 0; -- 全行の単価が0円に！ DELETE FROM dbo.Products; -- 全行が削除される！

事故を防ぐ2つの習慣

  1. 1 UPDATE / DELETE を書く前に、同じWHERE条件でSELECTを実行し、対象件数と内容を目で確認する。
  2. 2 BEGIN TRAN で囲んでから実行し、結果を確認してから COMMIT（確定）するか ROLLBACK（取り消し）するかを選ぶ。

実際の手順をコードで見てみましょう。まず対象件数を確認します。

step1_check_before.sql 
-- 手順1: UPDATE/DELETEと同じWHEREでSELECTし対象を確認する
SELECT * FROM dbo.Products
WHERE ProductId = 2;
-- → 1件だけヒットすることを目で確認してから次へ進む

次に、トランザクションで囲んでから実行し、結果を見て確定・取り消しを判断します（トランザクションの詳細は第10章で学びます）。

step2_tran_then_confirm.sql 
-- 手順2: トランザクションで囲んで実行し、結果を見てから確定する
BEGIN TRAN;

UPDATE dbo.Products
SET UnitPrice = 2680
WHERE ProductId = 2;

SELECT * FROM dbo.Products WHERE ProductId = 2;
-- 結果が正しければCOMMIT、想定と違えばROLLBACK
COMMIT TRAN;
-- おかしいと思ったら代わりに ROLLBACK TRAN; を実行する

重要ポイント

トランザクションを開いたまま長時間放置すると、他の利用者の処理をブロックしてしまいます。BEGIN TRAN は「確認してすぐ COMMIT か ROLLBACK する」ための一時的な安全策として使い、確認が終わったら速やかに閉じましょう。

7.5 DELETE と TRUNCATE TABLE の違い

テーブルの中身をすべて空にしたいとき、DELETE FROM テーブル名;（WHEREなし）と TRUNCATE TABLE の2つの方法があります。結果は「全行が消える」で同じに見えますが、内部的な動きはまったく異なります。

観点 DELETE（WHEREなし） TRUNCATE TABLE
WHERE指定 できる（一部だけ削除可能） できない（常に全行）
ログの記録量 1行ずつログに記録（多い） ページ単位で記録（少ない）
実行速度 行数に比例して遅くなる 大量データでも高速
IDENTITYの再シード されない（採番は続きから） される（次回挿入はシード値から。既定のIDENTITY(1,1)なら1から）
外部キー参照がある場合 参照している行があるとエラー 参照されているテーブルには実行不可
トランザクションでの取り消し ROLLBACK可能 ROLLBACK可能
truncate_example.sql 
-- OrdersArchive（別途用意した練習用のコピーテーブル）を空にし、IDENTITYをシード値（既定のIDENTITY(1,1)なら1）に戻す
TRUNCATE TABLE dbo.OrdersArchive;

使い分けの目安: 一部の行だけ消したい、または他テーブルから参照されている可能性があるなら DELETE。テーブルを完全に空にしてIDENTITYもシード値から振り直したい（既定のIDENTITY(1,1)なら1から。例: テスト用データの初期化）なら TRUNCATE TABLE が適しています。

7.6 OUTPUT句 — 変更した行をその場で確認する

OUTPUT 句を付けると、INSERT・UPDATE・DELETE が変更した行の内容を、その場で結果として受け取ることができます。SQL Server は変更の前後の値を inserted（挿入後の値）と deleted（削除前・更新前の値）という2つの疑似テーブルで参照できるようにしています。

output_insert.sql 
-- 追加した行のIDENTITY値（採番結果）をその場で確認する
INSERT INTO dbo.Customers (CustomerName, Email, CreatedAt)
OUTPUT inserted.CustomerId, inserted.CustomerName
VALUES (N'鈴木一郎', N'suzuki@example.com', GETDATE());
output_update.sql 
-- 更新前後の単価を両方確認する
UPDATE dbo.Products
SET UnitPrice = UnitPrice * 1.1
OUTPUT deleted.UnitPrice AS 変更前, inserted.UnitPrice AS 変更後
WHERE ProductId = 1;
output_delete.sql 
-- 削除した行の内容を確認しながら削除する
DELETE FROM dbo.Orders
OUTPUT deleted.OrderId, deleted.ProductId, deleted.Quantity
WHERE OrderDate < '2020-01-01';

UPDATE では deleted が「更新前の値」、inserted が「更新後の値」を表す点に注意しましょう。「消えた（deleted）＝古い値」「入った（inserted）＝新しい値」と覚えると理解しやすいです。

7.7 MERGE文の紹介 — あれば更新、なければ挿入

「対象データがすでにあれば更新、なければ挿入」という処理（一般に UPSERT と呼ばれます）を1文で書けるのが MERGE 文です。

merge_upsert.sql 
-- メールアドレスが一致する顧客がいれば名前を更新、いなければ新規登録
MERGE dbo.Customers AS target
USING (VALUES (N'田中次郎', N'tanaka@example.com')) AS src (CustomerName, Email)
ON target.Email = src.Email
WHEN MATCHED THEN
    UPDATE SET target.CustomerName = src.CustomerName
WHEN NOT MATCHED THEN
    INSERT (CustomerName, Email, CreatedAt)
    VALUES (src.CustomerName, src.Email, GETDATE());

USING 句が「照合したいデータ」、ON が「一致条件」、WHEN MATCHED が「一致した場合の処理」、WHEN NOT MATCHED が「一致しなかった場合の処理」です。

注意: MERGEを無条件におすすめはしない

MERGEは「あれば更新・なければ挿入」を1文で書ける便利な構文ですが、複数の処理が同時に同じデータへアクセスするような、同時実行性の高いシステムでは競合や複雑な問題が発生する場合があることが知られています。Microsoft自身も、MERGEを本番環境で使う前には十分なテストを行うことを推奨しています。初心者のうちは「こういう構文がある」と知っておくだけで十分です。実務でMERGEを使うかどうかは、設計者や先輩エンジニアに相談してから判断しましょう。

ヒント: まずはIF文でも十分だが、これも万能ではない

MERGE文は複数の条件分岐を組み合わせると読みにくくなりがちで、条件次第では意図しない挙動を招くこともある構文です。学習を始めたばかりの段階では、まず「存在確認のSELECTをして、あればUPDATE・なければINSERT」という素朴な2文（第9章のIF文で自動化できます）で書いてみるとよいでしょう。ただし、この2文の組み合わせも常に安全というわけではありません。複数の処理が同時に動く環境では、SELECTで「無い」と確認した直後に別の処理が同じ行をINSERTしてしまい、重複エラーや更新の取りこぼしといった競合が起こり得ます。MERGEでもSELECT＋IFでも、同時実行を正しく扱うにはトランザクションと、一意制約などの適切なロック・制約の設計が別途必要になる点は変わりません。まずは書き方に慣れることを優先し、同時実行を意識した設計は経験を積んでから取り組めば十分です。

7.8 PostgreSQLとの違い

データ操作（DML）の基本的な考え方は SQL Server と PostgreSQL で共通ですが、変更行を確認する構文や UPSERT のやり方には明確な違いがあります。

PostgreSQL との違い（データ操作編）

観点 SQL Server PostgreSQL
変更行の確認 OUTPUT inserted.列名 RETURNING 列名
UPSERT（あれば更新、なければ挿入） MERGE 文 INSERT ... ON CONFLICT DO UPDATE
他テーブルを使ったUPDATE UPDATE ... FROM ... JOIN UPDATE ... FROM（JOINなしで結合条件をWHEREに書く）
TRUNCATEとIDENTITY 既定でIDENTITYがシード値（IDENTITY(1,1)なら1）に戻る RESTART IDENTITY を明示しないと連番は戻らない
TRUNCATEのロールバック トランザクション内ならROLLBACK可能 同様にトランザクション内ならROLLBACK可能
自動コミット SSMSは既定で自動コミット。明示的にはBEGIN TRAN psqlも既定は自動コミット。明示的にはBEGIN
文字列リテラルのエスケープ 日本語などはN'...'推奨、単一引用符は''で二重化 N'...'は不要（既定でUTF-8）、単一引用符は同様に''で二重化

とくに UPSERT の書き方（MERGE と ON CONFLICT）は構文がまったく異なるので、PostgreSQL の経験がある方は書き換えのタイミングで戸惑いやすいポイントです。

やってみよう 7-1: トランザクションで安全に更新を試す

サンプルデータを追加し、トランザクションで囲んでUPDATEし、確認したうえで元に戻す一連の流れを体験しましょう。

手順

  1. 1 練習用のサンプル商品を INSERT する。INSERT INTO dbo.Products (ProductName, UnitPrice, IsActive) VALUES (N'練習用キーボード', 4500, 1);
  2. 2 SELECT * FROM dbo.Products WHERE ProductName = N'練習用キーボード'; で対象が1件だけであることを確認する。
  3. 3 BEGIN TRAN; を実行し、同じ条件で UPDATE dbo.Products SET UnitPrice = 3980 WHERE ProductName = N'練習用キーボード'; を実行する。
  4. 4 再度 SELECT して単価が 3980 に変わっていることを確認したら、ROLLBACK TRAN; を実行して元の 4500 に戻す。
  5. 5 最後にもう一度 SELECT し、ROLLBACK によって単価が 4500 のまま変わっていないことを確認する。

ねらい: 「確認してから確定する」という安全な操作の型を、実際に手を動かして体に覚え込ませることが目的です。ROLLBACKで元に戻せることを体験しておくと、本番作業での安心感が変わります。

理解度確認クイズ

  1. Q1. UPDATE や DELETE で WHERE を書き忘れると何が起きますか。事故を防ぐために実行前にすべき2つのことも答えてください。

    回答を表示

    WHEREがないとテーブルの全行が更新・削除の対象になります。防ぐには、（1）同じWHERE条件でSELECTを先に実行して対象件数と内容を確認する、（2）BEGIN TRANで囲んで実行し、結果を見てからCOMMITかROLLBACKを判断する、の2つを習慣にします。

  2. Q2. DELETE と TRUNCATE TABLE の違いを、WHERE指定の可否とIDENTITYの扱いの観点から説明してください。

    回答を表示

    DELETEはWHEREで一部の行だけを削除でき、IDENTITYの採番は続きから振られます。TRUNCATE TABLEはWHEREを指定できず常に全行が対象になりますが、ログ量が少なく高速で、実行するとIDENTITYがシード値（既定のIDENTITY(1,1)なら1）に再シードされます。

  3. Q3. 変更した行の内容をその場で確認したいとき、SQL Server と PostgreSQL ではそれぞれ何という句を使いますか。

    回答を表示

    SQL Serverは OUTPUT 句（inserted / deleted 疑似テーブルを参照）、PostgreSQLは RETURNING 句を使います。どちらもINSERT・UPDATE・DELETEの直後に付けて、変更した行の値をその場で取得できます。
