プロジェクトを使いこなす

Projects（プロジェクト）は、専用のメモリ・チャット履歴・ナレッジベース・カスタム指示を持つ独立したワークスペースです。この章では、プロジェクトを使うべきタイミングの見極め方から、作成・指示・ナレッジベース構築の3ステップ、そしてチームでの共有方法までを順を追って学びます。

この章で学ぶこと

  • プロジェクトとは何かを説明し、使うべきタイミングを判断できる
  • 名前・説明・公開設定を指定して新しいプロジェクトを作成できる
  • ナレッジベースにドキュメントを追加し、効果的なプロジェクト指示を書ける
  • チームメンバーとプロジェクトを共有し、3つの権限レベルを使い分けられる

7.1 プロジェクトとは何か

Projects（プロジェクト）は、それぞれが専用のメモリ・チャット履歴・ナレッジベース・カスタム指示を持つ、独立したワークスペースです。特定の業務の流れごとに用意された専用の作業部屋だとイメージしてください。プロジェクト内のどの会話からも、同じナレッジと指示にアクセスできます。

用語: ワークスペースとは

1つの目的・テーマに紐づいた「作業場所」のことです。通常の Claude.ai の会話は毎回まっさらな状態から始まりますが、プロジェクト内の会話は、あらかじめ登録したナレッジや指示を最初から踏まえた状態で始まります。

（背景・プロセス・トーン・要件）"] P --> K["ナレッジベース
（PDF・DOCX・CSV等）"] P --> M["専用メモリ"] P --> C1["チャット1"] P --> C2["チャット2"] P --> C3["チャット3"] I --> C1 I --> C2 I --> C3 K --> C1 K --> C2 K --> C3

プロジェクトを使うタイミングの3条件

プロジェクトは、単発の質問ではなく継続的に取り組んでいる案件がある場合に特に役立ちます。次の3つのいずれかに当てはまるなら、プロジェクトの作成を検討しましょう。

繰り返し使う参考資料がある

議事録・アンケート結果・レポート・過去データなどを、毎回アップロードし直さずに使い回したい。

応答方法に一貫した要件がある

常にフォーマルな言葉遣いを使う、常に出典を明記する、常に自社テンプレートに従う、など。

チーム協働が必要

複数のメンバーが、同じ文脈・指示・蓄積されたナレッジという同じ土台の上で作業すべき場合。

重要ポイント

プロジェクトは自動的にスケールします。ナレッジベースがコンテキストの上限に近づくと、Claude はシームレスに RAG（検索拡張生成）モードを有効にし、回答品質を保ちながら容量を最大10倍まで拡張します（詳しくは 7.4 で解説します）。

7.2 ステップ1: プロジェクトを作成する

プロジェクトのセットアップはほんの数分で完了します。まずは器（うつわ）を用意するところから始めましょう。

  1. 1 左側のサイドバーにカーソルを合わせて「Projects（プロジェクト）」をクリックするか、claude.ai/projects に直接アクセスする。
  2. 2 右上の「+ New Project（新規プロジェクト）」をクリックする。
  3. 3 プロジェクトに分かりやすい名前を付ける（例:「Q4マーケティングキャンペーン」「製品ドキュメント」）。
  4. 4 取り組んでいる内容についての簡単な説明を追加する。
  5. 5 公開設定を選ぶ。非公開のままにするか、組織内で共有するか（Claude for Work 利用者の場合）を選択する。

注意: 説明文は「人のため」のもの

ステップ3で入力する説明文は、Claude が直接参照するわけではありません。あなたやチームメンバーが、あとから見てもプロジェクトの目的をすぐ思い出せるようにするためのメモだと考えてください。Claude の振る舞いを実際に導くのは、次のステップの「プロジェクト指示」です。

7.3 ステップ2: プロジェクト指示を書く

プロジェクト指示（project instructions）は、このプロジェクト内のすべての会話で Claude がどう振る舞うべきかを伝えるものです。プロジェクトページの「Instructions（指示）」をクリックすると、指示パネルが開きます。書き終えたら「Save instructions（指示を保存）」をクリックすれば、以降のすべてのチャットに自動的に適用されます。

良いプロジェクト指示には、通常次の4つの要素が含まれます。

構成要素 指示の例
背景情報 「このプロジェクトは、自社のB2Bソフトウェア製品向けのマーケティングコンテンツを作成するためのものです」
プロセスの指示 「まずこの読者層を引きつけるブログの構成を検討してから、草稿を書いてください」
トーン・スタイルの好み 「プロフェッショナルでありながら会話調のトーンを使ってください。専門用語はできるだけ避けてください」
具体的な要件 「マーケティングコピーの最後には必ず行動喚起（CTA）を含めてください」

重要ポイント

プロジェクト指示は、このプロジェクトにおける Claude の振る舞いをプログラミングするものだと考えてください。「会議の書き起こしをアップロードしたら、このテンプレートを使って構造化された要約を作成してください」のように、ワークフローの自動化にも活用できます。

7.4 ステップ3: ナレッジベースを構築する

ナレッジベースは、Claude に参照してほしいドキュメントをアップロードする場所です。プロジェクトのメインページの右側にあるファイルメニューの「+」ボタンをクリックしてコンテンツを追加します。PDF・DOCX・CSV・TXT・HTML など、さまざまな種類のファイルをアップロードできるほか、Google Drive と連携してドキュメントを直接リンクすることもできます。

アップロードすべきものは、大きく次の4分類に整理できます。

分類 具体例
参考資料 ブランドガイドライン、スタイルガイド、テンプレート
背景資料 リサーチレポート、議事録、要件定義書
真似してほしい成果物の例 Claude に模倣してほしい、過去の質の高い成果物
技術ドキュメント・仕様書 API仕様書、設計資料、業務マニュアルなど

大きなナレッジベースをどう扱うか（RAG）

大量のコンテンツをアップロードするとどうなるのでしょうか。プロジェクトはRAG（Retrieval Augmented Generation、検索拡張生成）という仕組みで、大量のデータを自動的にスケールして扱います。プロジェクトのナレッジがコンテキストウィンドウの上限に近づくと、Claude はシームレスに RAG モードを有効にし、プロジェクトの内容をすべて一度にメモリへ読み込む代わりに、質問に答えるために最も関連性の高い部分だけを検索・取得します。これにより、回答品質を保ちながらプロジェクトの容量を最大10倍まで拡張できます。

flowchart LR A["ナレッジ少量
全文をそのまま参照"] --> B["ナレッジ増加
コンテキスト上限に接近"] B --> C["RAGモードが
シームレスに有効化"] C --> D["質問に関連する
部分のみを検索・取得"] D --> E["回答品質を保ちつつ
容量を最大10倍に拡張"]

たとえ話: 図書館の司書

RAG は、大量の資料を持つ司書のような仕組みです。棚にある本をすべて丸暗記するのではなく、質問を受けてから「必要なページだけ探して読み、答える」という動き方をします。プロジェクトが RAG 対応になると視覚的な表示が出ますが、使い勝手自体はこれまでと変わりません。

プロのコツ: ファイル名は内容が分かるように付けましょう。Claude はファイル名を手がかりに情報を理解・検索するため、「document1.pdf」よりも「Q4-2024-Brand-Guidelines.pdf」のような名前の方が役立ちます。

7.5 チームで共有する

プロジェクト共有・コラボレーションは Claude for Work（Team および Enterprise プラン）で利用できます。チームメンバーとプロジェクトを共有すれば、全員が同じ文脈・指示・蓄積されたナレッジの恩恵を受けられます。共有時は、次の3つの権限レベルから選べます。

権限レベル できること
Can view（閲覧のみ） プロジェクトの内容を見たり、ナレッジにアクセスしたり、チャットしたりできる。変更は不可
Can edit（編集可） 指示の変更、ナレッジの更新、他のメンバーの管理など、協働に必要なあらゆる操作ができる
Owner（オーナー） プロジェクト作成者。公開範囲を含め、誰がプロジェクトを見られるかまで含めた全権を持つ

共有の手順

  1. 1 共有したいプロジェクトを開く。
  2. 2 プロジェクト名の右にある「Share project（プロジェクトを共有）」をクリックする。
  3. 3 名前やメールアドレスで個別にメンバーを追加するか、メールアドレスのリストを一括貼り付けする（相手の「Shared with you」＝共有されたもの、に表示される）。
  4. 4 あるいは「Everyone at [組織名]」を選び、組織内の Team タブでプロジェクトを見つけられるように公開する。

補足

プロジェクトを共有すると、チームメンバーにはメール通知が届きます。

プロジェクト活用のベストプラクティス

  • まずは絞って始め、徐々に広げる。すべてを1つのプロジェクトにまとめようとせず、具体的なユースケースから始める。
  • ナレッジベースを最新の状態に保つ。古いドキュメントは古い回答につながる。
  • 明確な指示を書く。望むことを具体的に書く。曖昧な指示は一貫性のない結果につながる。
  • 内容が分かるファイル名を付ける。「report.pdf」ではなく「Q4-2025-Sales-Report.pdf」のように。
  • 質問時にドキュメント名を指定する。「Q3レポートによると、顧客からの主な懸念事項は何でしたか？」のように検索範囲を絞る。

プロジェクト例 アップロードする内容

やってみよう 7-1: 自分の最初のプロジェクトを作る

7.1〜7.4 で学んだ手順を、実際に自分の業務に当てはめて実践してみましょう。

手順

  1. 1 継続的に取り組んでいる業務を1つ選び、「+ New Project」から新規プロジェクトを作成する。分かりやすい名前と、目的が伝わる説明文を設定する。
  2. 2 「Instructions」を開き、背景情報・プロセスの指示・トーン＆スタイル・具体的要件の4要素を含むプロジェクト指示を書いて「Save instructions」で保存する。
  3. 3 「+」ボタンから、内容が分かるファイル名を付けたドキュメントを2〜3件アップロードする。
  4. 4 アップロードしたドキュメント名を指定して、プロジェクト内で質問を投げてみる。

ヒント: 迷ったら 7.5 の「参考になるプロジェクトの例」から近いものを選んで真似してみましょう。まずは1つの用途に絞り、うまく回り出してから範囲を広げるのがコツです。

理解度確認クイズ

  1. Q1. プロジェクトの作成を検討すべき3つの条件を挙げてください。

    回答を表示

    「繰り返し使う参考資料がある」「応答方法に一貫した要件がある」「チーム協働が必要」の3つです。いずれかに当てはまる継続的な業務があるなら、プロジェクトの作成を検討する価値があります。

  2. Q2. プロジェクト作成時に入力する「説明」は、Claude の振る舞いにどう影響しますか。

    回答を表示

    この説明は Claude が直接参照するわけではありません。あなたやチームメンバーがプロジェクトの目的を理解するためのメモです。Claude の振る舞いを実際に導くのは「Instructions（プロジェクト指示）」のほうです。

  3. Q3. プロジェクトの権限レベル3種（Can view / Can edit / Owner）の違いを説明してください。

    回答を表示

    Can view は閲覧とチャットのみ可能で変更は不可、Can edit は指示変更・ナレッジ更新・メンバー管理など協働に必要な操作ができ、Owner は作成者として公開範囲を含む全権を持ちます。
