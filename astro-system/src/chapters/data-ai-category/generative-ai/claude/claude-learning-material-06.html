デスクトップアプリの3モード

Claude デスクトップアプリには、Chat・Cowork・Code という3つのモードがあります。ちょっとした質問から複雑なリサーチ、ソフトウェア開発まで、作業の性質に応じて使い分けます。この章では、それぞれの設計意図と固有機能を理解し、状況に応じて最適なモードを選べるようになることを目指します。

この章で学ぶこと

  • Chat・Cowork・Code の3モードを識別し、それぞれの設計意図を説明できる
  • Quick entry、スケジュールタスク、Local と Remote の違いなど各モード固有の機能を説明できる
  • 取り組む作業の種類に応じて適切なモードを選択できる
  • Cowork の保護された環境と Code のフルアクセスの違いを説明できる

6.1 3つのモードという考え方

Claude デスクトップアプリには、Claude と連携する3つの方法があります。Chat・Cowork・Code です。ちょっとした質問から複雑なリサーチ、ソフトウェア開発まで対応できるよう、それぞれが担う作業内容に合わせて設計されています。

Chat は claude.ai でおなじみの Claude に、Quick entry・スクリーンショット・Dictation・コネクタといった、コンピュータ上でネイティブに動作するからこそ使える機能が加わったものです。Cowork はエージェント型のツールで、目標を伝えツールやリソースに接続すれば、あとは Claude が作業を進めてくれます。より広い範囲でより多くのことをこなせるため、入念なリサーチや分析、複雑なドキュメントや成果物の作成に向いています。Code はソフトウェア開発のためのモードで、コードの記述・テストからデプロイまでを担います。

重要: Cowork と Code は同じエンジン

Cowork と Code は同じエンジン上で動作します。どちらも内部的には Claude Code であり、お使いのマシン上でローカルに動作し、自律的に作業を進める能力を持ち、サブエージェントを立ち上げて長時間のタスクをこなすことができます。この仕組みにより、Claude はリサーチや文章作成、ソフトウェア開発といった大規模なタスクを自力でやり遂げられます。

3モードは互いに排他的なものではありません。同じ日に、簡単な確認は Chat、資料横断のリサーチは Cowork、コード修正は Code というように、作業の性質に応じて切り替えて使うのが基本の考え方です。

6.2 Chat — 素早いやり取り

Chat は、質問をしたり、アイデアを出し合ったり、下書きを作成したり、やり取りを重ねながら問題に取り組んだりする場面で真価を発揮します。claude.ai を使ったことがあれば、基本的な操作感はそのままです。それに加えて、コンピュータ上でネイティブに動作するからこその機能がいくつか備わっています。

機能 内容
Quick entry（クイックエントリー） Mac で Option キーを素早く2回押すと、作業中の画面の上に Claude を呼び出せる。アプリを切り替えても最前面に表示され続けるコンパクトなウィンドウで応答する
スクリーンショットとウィンドウ共有 スクリーンショットの撮影やウィンドウ共有で、今見ている画面をそのまま Claude に見せられる
Dictation（音声入力） 入力する代わりに話しかけて問題を伝えられる。考えを声に出しながら整理したいときに便利
Desktop connectors（デスクトップコネクタ） コネクタを通じてローカルのツールやサービスと接続し、マシン上の他のツールと連携して作業できる

注意: Mac 限定の機能があります

Quick entry・スクリーンショットとウィンドウ共有・Dictation は Mac 限定の機能です。Windows をお使いの場合、これらは利用できません。なお、次節以降で扱う Cowork の Computer use も現在は macOS のみの対応です（6.3 参照）。

たとえば、見慣れないダッシュボードに戸惑ったときは、Quick entry でウィンドウをスクリーンショットに収めて「これらの指標は何を意味しているの？」と尋ねられます。会議の合間にプレゼンの構成を考えたいときは、Dictation に切り替えて話しながら考えを整理し、Claude にアウトラインを作らせることもできます。

6.3 Cowork — 複雑・長時間の作業

Cowork は、本格的な労力を要する作業のために作られています。多くの情報源からデータを集め、それを整理して意味を見出し、完成した成果物を作り上げる、といった作業です。入念なリサーチブリーフ、複数情報源を横断した分析、あちこちに散らばった資料から仕上げる資料作成などに向いています。

作業を始める前、Claude は範囲・形式・制約といった要件を明確にするため、簡単な質問を投げかけることがよくあります。そのうえで計画を立て、サイドバーで確認できるようにします。作業が進むにつれて、参照している情報源・形になっていくファイル・計画の進捗状況を見ることができ、複数のタスクをそれぞれ別の会話として同時に実行し、サイドバーから切り替えることも可能です。

範囲・形式・制約を質問"] --> B["計画立案
サイドバーに提示"] B --> C["サブエージェント
並列実行"] C --> D["成果物統合"] D --> E["共有フォルダへ保存"]

Cowork 固有の機能

機能 内容
Folder access（フォルダアクセス） フォルダを指定すると、Claude が中身を読み取り、完成した成果物を同じ場所に保存する
Scheduled tasks（スケジュールタスク） 繰り返し発生する作業をスケジュールに沿って処理する。実行予定時刻にアプリが閉じていた場合は、次に開いたときにまとめて処理する
Subagents（サブエージェント） 複雑な依頼をサブタスクに分割し、それぞれを独自のコンテキストを持つサブエージェントに割り当てて並行処理し、結果を1つの成果物として統合する
Dispatch（ディスパッチ） Cowork での会話をスマートフォンから続けられる機能。デスクトップとモバイルの両方が必要で、PC がスリープせずデスクトップアプリが開いている状態である必要がある
Projects 関連タスクを専用ワークスペースにまとめる。Claude.ai の Projects と似ているが、Cowork の Projects はデスクトップ上にローカルに存在する
Browser use（ブラウザ操作） Claude in Chrome を接続すると、ウェブサイトを操作し、見つけた情報を作業中のタスクに取り込める
Computer use（コンピュータ操作） 対応するコネクタやプラグインがない場合、コンピュータを直接操作する。Claude はコネクタ → Chrome → 画面操作の順に優先する
Plugins（プラグイン） リアルタイムの財務データ取得や社内ナレッジベース検索など、Claude 単体では持っていない機能を追加する
Protected environment（保護された環境） コンピュータ上の隔離された空間で動作する。共有したフォルダ内のファイルは読み取り・作成・編集できるが、それ以外の場所にはアクセスできない

用語: Computer use は現在プレビュー段階

Computer use は Pro・Max プランでリサーチプレビュー中で、現在は macOS のみの対応です（Windows 対応は準備中）。Claude が各アプリにアクセスする前には許可の確認が表示され、アクセスさせたくないものについてはブロックリストを設定できます。

6.4 Code — ソフトウェア開発向けモード

Code は開発者向けの機能です。Codeタブでは、デスクトップアプリの中で直接動作する Claude Code の機能を利用でき、コードの記述・修正・コマンド実行までを行うフル機能の開発環境が手に入ります。プログラミングを日常業務にしない読者は、「こういうモードもある」という位置づけを押さえるだけで十分です。

Code では、Claude がコードベース上で直接作業します。既存のコードを読み込み、コードを記述・修正し、コマンドを実行します。ビジュアル差分表示で変更内容を確認でき、組み込みのターミナルで実行中のコマンドを確認でき、git がすべてのバージョンを記録するため、いつでもロールバックできます。

作業する環境を選ぶ

環境 内容
Local コンピュータ上のフォルダを選択すると、Claude がそれらのファイルを直接操作する。マシン上で動作するため、開発サーバーを起動してブラウザでプレビューすることもできる
Remote GitHub リポジトリを接続すると、Claude はクラウド環境上で作業する。アプリを閉じてもセッションは継続するため、大規模なリファクタリングを開始してあとから結果を確認するといった使い方ができる

3つの操作モード

Claude にどこまで自律的に作業させるかは、3つの操作モードでコントロールします。

Ask

すべての変更を提案し、利用者の承認を待つ。変更前にビジュアル差分を確認し、承認または却下する。

Code

ファイルの変更は自動的に適用するが、ターミナルコマンドを実行する前には確認を取る。

Plan

何かに着手する前にアプローチの全体像を提示する。専用のプランビューアーで戦略を確認・見直しできる。

複数のプロジェクトにまたがって複数のセッションを実行でき、サイドバーからステータス（Active／Archived）や環境（Local／Cloud）で絞り込むことができます。

重要ポイント: 保護された環境 vs フルアクセス

Cowork が共有したフォルダに限定された保護された環境で動作するのに対し、Code はファイルシステム・ターミナル・開発ツールにフルアクセスできる状態で、プロジェクト上で直接動作します。同じエンジンでも、アクセス範囲の設計思想がまったく異なる点を押さえておきましょう。

やってみよう 6-1: 業務に最適なモードを選ぶ

3モードの違いを頭で理解するだけでなく、自分の実際の業務に当てはめて考えてみましょう。

手順

  1. 1 最近の業務から、次の3種類に当てはまる作業をそれぞれ1件ずつ思い浮かべる。①簡単な質問／②複数の情報源から資料を作成する作業／③コードの変更や定型作業の自動化。
  2. 2 それぞれについて、6.5 の比較表を見ながら Chat・Cowork・Code のどれが最適かを選ぶ。
  3. 3 なぜそのモードを選んだのか、根拠となる特徴（機能・アクセス範囲・作業時間の想定など）を1〜2文で書く。
  4. 4 プログラミングに関わらない方は、③についても「もし自分がコードを扱う立場だったら」という想定で考えて構いません。

ヒント: 「一度きりの質問か、繰り返す作業か」「1つの情報源で足りるか、複数を横断する必要があるか」という2つの軸で考えると、モードを選びやすくなります。

理解度確認クイズ

  1. Q1. Cowork と Code に共通する特徴を挙げてください。

    回答を表示

    Cowork と Code は同じエンジン上で動作し、どちらも内部的には Claude Code です。お使いのマシン上でローカルに動作し、自律的に作業を進め、サブエージェントを立ち上げて長時間のタスクをこなすことができる点が共通しています。

  2. Q2. Chat の固有機能のうち、Windows では利用できないものを挙げてください。

    回答を表示

    Quick entry、スクリーンショットとウィンドウ共有、Dictation は Mac 限定の機能です。Windows では利用できません。一方、Desktop connectors は OS を問わず利用できます。

  3. Q3. Cowork と Code のアクセス範囲の違いを説明してください。

    回答を表示

    Cowork は共有したフォルダ内のみ読み書きできる保護された環境で動作します。一方 Code は、ファイルシステム・ターミナル・開発ツールにフルアクセスできる状態でプロジェクト上で直接動作します。
