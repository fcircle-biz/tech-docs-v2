コネクタと MCP

この章では、Claude を Google Drive・Slack・Notion といった普段使っている業務ツールとつなぐコネクタと、その基盤となるModel Context Protocol（MCP）について学びます。ツールを連携すると、Claude は会話の外にある実際のデータに直接アクセスできるようになります。

この章で学ぶこと

  • コネクタとは何か、なぜ Claude での作業にとって重要かを説明できる
  • Model Context Protocol（MCP）がコネクタの基盤であることを説明できる
  • コネクタディレクトリから Web コネクタを設定し、動作をテストできる
  • コネクタの権限とセキュリティ上の原則を説明し、連携を解除できる

10.1 コネクタとは何か

これまでの章で扱ってきた Claude は、あなたが送ったテキストやアップロードしたファイルの範囲でしか会話の材料を持てませんでした。コネクタは、この会話の外側にあるあなたの実際のツール・データにも Claude がアクセスできるようにする仕組みです。コネクタは、Claude を「毎回ゼロから状況を説明しないといけないアシスタント」から、「あなたの状況をすでに理解している協働者」へと変えてくれます。

コネクタの種類や、あなたが付与した権限次第で、Claude は次のようなことができるようになります。

  • 連携先サービス内のファイルを検索する
  • ドキュメントを取得して内容を読む
  • データを分析する
  • 新しいコンテンツを作成する
  • レコードを更新する
  • 連携済みアプリケーション上でタスクを実行する

これらはすべて、いつもの会話の中から行えます。別のアプリを開いて情報をコピー＆ペーストする必要はありません。

10.2 コネクタを支える Model Context Protocol（MCP）

コネクタを技術的に支えているのが Model Context Protocol（MCP）です。Anthropic はこれを「AI 版の USB-C」だと説明しています。この比喩を少し掘り下げてみましょう。

たとえ話: なぜ「USB-C」なのか

USB-C が登場する前は、機器ごと・メーカーごとに違う形のケーブルや端子が必要でした。USB-C は、1つの共通規格の端子で、充電器からディスプレイ、外付けストレージまで幅広い機器をつなげるようにした標準規格です。MCP も同じ役割を果たします。個々のアプリごとに Claude 専用のバラバラな組み込み方をするのではなく、単一の一貫したインターフェースを通じて、Claude が多様なアプリケーションに接続できるようにします。

MCP はオープンな標準規格です。誰でも仕様を参照できるため、開発者は自分たちのツール向けに独自のコネクタを構築できます。そうして作られたコネクタは、共通の規格に沿っているので Claude とシームレスに連携します。あなたが Google Drive・Notion・Slack・Asana など、性質の異なる複数のサービスを違和感なく同じ Claude の会話から使えるのは、この共通インターフェースのおかげです。

重要ポイント

MCP を覚えていなくても、コネクタは問題なく使えます。ここで押さえておきたいのは、「Claude をいろいろなアプリにつなぐための、共通の仕組みが存在する」という事実だけで十分だということです。

10.3 コネクタを見つけて連携する

コネクタには大きく分けて2種類あります。それぞれ動作する場所とアクセスできる対象が異なります。

種類 動作する場所 アクセスできる対象・例
Webコネクタ クラウド上（Claude.ai から利用） Google Drive、Notion、Slack、Asana などのクラウドサービス
デスクトップ拡張機能 自分のパソコン上（Claude Desktop アプリ経由） ローカルファイル、ブラウザ操作、Figma などのネイティブアプリ

Anthropic は、おすすめのコネクタをまとめたディレクトリを claude.ai/directory で公開しています。ディレクトリは「Web」タブと「デスクトップ拡張機能」タブの2つで構成されています。チャットウィンドウ左下の + ボタン → Connectors からも同じ一覧を閲覧できます。

Webコネクタを設定する（5ステップ）

クラウドサービスを連携する手順は次のとおりです。

  1. 1 コネクタを見つける — claude.ai/directory にアクセスするか、チャットで + → Connectors をクリック
  2. 2 Connect をクリック — 追加したいコネクタを選択する
  3. 3 認証する — サービスのログインページにリダイレクトされるので、既存の資格情報でサインインする
  4. 4 権限を付与する — Claude が要求している具体的な権限を確認し、アクセスを許可する
  5. 5 連携をテストする — Claude に戻り、「[ツール名]にアクセスできますか？」のような簡単なリクエストを試す

連携が完了すると、付与した権限に応じて、Claude はそのサービス内で検索や閲覧を行ったり、場合によっては操作を実行したりできるようになります。

デスクトップ拡張機能の導入

デスクトップ拡張機能を使うには、ブラウザ版ではなく Claude Desktop アプリが必要です。これらの拡張機能により、Claude はローカルアプリケーション・ファイルシステム・OS のネイティブ機能とやり取りできるようになります。例としては、ドキュメントの読み取り・整理のためのローカルファイルアクセス、Web作業を自動化するブラウザ操作、Figma のようなネイティブアプリケーションとの連携などがあります。

  1. 1 Claude Desktop アプリをダウンロードしてインストールする
  2. 2 アプリを開き、Settings（設定）> Extensions（拡張機能）に移動する
  3. 3 利用可能な拡張機能を閲覧し、Install をクリックする
  4. 4 その拡張機能固有の追加セットアップ手順があれば、それに従う

10.5 セキュリティと権限

Claude を外部サービスと連携すると、そのサービス内のデータを読み取る（場合によっては変更する）権限を Claude に与えることになります。連携の前に、次の3つの原則を理解しておきましょう。

sequenceDiagram participant U as ユーザー participant C as Claude participant S as 連携先サービス U->>C: コネクタを選び「Connect」をクリック C->>S: 認証をリクエスト S->>U: ログインページを表示 U->>S: 既存の資格情報でサインイン S->>U: 要求する権限を提示 U->>S: 権限を確認して許可 S->>C: 連携を確立 U->>C: 「アクセスできますか？」とテスト C->>S: 許可された範囲でデータ取得 S->>C: 結果を返す C->>U: 取得内容をもとに回答

範囲が限定された権限

権限はそのコネクタが必要とするものに限定されており、各アプリケーションのメニューから個々の権限のオン・オフを切り替えられる。

見えるのはあなたが見えるものだけ

Claude がアクセスできるのは、あなた自身がアクセス権を持つデータだけ。仕事用メールを連携しても、Claude が見られるのはあなた自身の受信箱で、CEOの受信箱にはアクセスできない。

いつでも解除可能

サービスとの連携は、Claude の設定画面から、またはサードパーティサービス側のセキュリティ設定からいつでも解除できる。

注意: カスタムコネクタの見極め

Skills と同様に、カスタムコネクタを見つけたり自分で作成したりすることもできます。その場合も Skills と同じ注意が必要です。信頼できる提供元のコネクタのみをインストールしてください。

やってみよう 10-1: 業務ツールを1つ連携してテストする

実際にコネクタを1つ設定し、動作を確認してみましょう。

手順

  1. 1 自分が最も頻繁に使う業務ツールを1つ選び、claude.ai/directory または + → Connectors から連携する（10.3 の5ステップに沿う）。
  2. 2 「[ツール名]にアクセスできますか？」とテストし、Claude が正しく応答するか確認する。
  3. 3 続けて、そのツールに関する実務的な質問（例: 「直近のタスク一覧を見せて」）を1つ投げてみる。
  4. 4 設定画面で、そのコネクタに付与した権限の一覧を確認する。

ヒント: どの業務ツールを連携すると最も価値がありそうか、現在コピー＆ペーストで行っている作業のうちコネクタが自動化できそうなものは何か、を考えながら選ぶと効果を実感しやすくなります。

理解度確認クイズ

  1. Q1. Model Context Protocol（MCP）とは何ですか。よく使われるたとえで説明してください。

    回答を表示

    MCP は、単一の一貫したインターフェースを通じて Claude を多様なアプリケーションに接続できるようにするオープンな標準規格です。「AI版のUSB-C」とたとえられ、機器ごとに違う端子が必要だった時代に代わって共通の端子で多くの機器をつなげる USB-C のように、アプリごとにバラバラな組み込み方をせず、開発者が任意のツール向けにコネクタを構築できるようにします。

  2. Q2. コネクタの2種類とその違いを説明してください。

    回答を表示

    Webコネクタとデスクトップ拡張機能の2種類です。Webコネクタは Google Drive・Notion・Slack・Asana などのクラウドサービスと Claude.ai から連携します。デスクトップ拡張機能は Claude Desktop アプリを通じてパソコン上でローカルに動作し、ローカルファイルやネイティブアプリケーションへのアクセスを Claude に与えます。

  3. Q3. コネクタのセキュリティに関する3つの原則を挙げてください。

    回答を表示

    ①範囲が限定された権限（アプリごとのメニューで個別にオン/オフ切替可能）、②Claude が見えるのはあなたが見えるものだけ（自分の受信箱にはアクセスできても CEO の受信箱にはアクセスできない）、③いつでも解除可能（Claude の設定画面またはサードパーティ側のセキュリティ設定から）、の3つです。
